js-031: Safe browser rendering and security boundaries#

Use the browser fixture and record predictions before inspecting solutions.

Exercises#

  1. Render a markup-looking title as literal text. Save the snippet and inspect the resulting DOM and visible title. Expected: the angle-bracket text is visible; no img element is created. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Validate a URL before creating a link. Use a same-origin relative link and reject a javascript URL under the shown policy. Expected: local help is accepted; javascript: is rejected. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Install the complete fixture CSP. Inspect the reference HTML and load its external script and stylesheet under the meta policy. Expected: local resources load; no inline handlers or eval are needed. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Reject origin and credential tricks. Try a different port, an external origin, a data URL and embedded credentials. Expected: every candidate is rejected by the local-link policy. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Inspect dynamic text without changing policy. Enter strong-tag-looking text, render it, then inspect child element count. Expected: text remains literal and child element count stays zero. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Explain the actual policy boundary. Record what the meta policy proves and what needs headers or server authorization. Expected: no claim that CSP authenticates callers, CORS authorizes actions, or meta implements frame-ancestors. Verify: Record the observed value, exception or browser state and compare it with that expectation.
