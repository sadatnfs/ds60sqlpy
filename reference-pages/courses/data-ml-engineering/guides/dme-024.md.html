dme-024: Checkpoints, replay and state-schema evolution#

Level: Intermediate | Prepared runtime: python-core

Direct prerequisites: dme-015, dme-020, dme-021, dme-023.

Outcome: Restore a versioned checkpoint and compare with a full replay oracle.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

A checkpoint must describe a consistent cut of work#

A checkpoint records enough information to resume a computation without forgetting accepted work or applying it twice. For a finite source tape, that includes a position in the tape and the derived state produced by all accepted positions before it. Saving only a cursor is dangerous: it may skip effects that were never committed. Saving only effects is also dangerous: replay may apply them again unless the effect identities are recognized.

The source in this chapter is an ordered list of identified integer events: A with two, B with three, A with two again, and C with one. The repeated A is a replay of the same event, not a second business event. There are four source positions but three unique accepted effects. A correct final projection totals six. Adding every tape position would produce eight, which confuses transport repetition with new information.

The example uses actual SQLite files to commit the cursor and effects in one transaction. It also binds the checkpoint to the exact source tape, reviewed program bytes and state-schema version. This is a local checkpoint mechanism, not a claim that a distributed engine, external queue or remote sink has been coordinated. Those systems need their own checkpoint and commit protocols. The local transaction makes the essential invariant concrete enough to inspect and test.

Define the prefix invariant#

Let the cursor kkk mean that source positions 000 through k−1k-1k−1 have committed. Let PkP_kPk​ be that source prefix. The accepted effect table must equal the unique identified events in PkP_kPk​, provided repeated identities agree on content:

The cursor must satisfy 0≤k≤n0\leq k\leq n0≤k≤n, where nnn is the bound source length. A repeated identity with a different value is rejected, because deduplication cannot resolve contradictory events by itself. This invariant is stronger than checking only that a database opens or that its cursor is an integer.

connect validates the finite event schema, opens the database and checks metadata. The source hash includes ordered tape content, because changing arrival order changes the meaning of the cursor. The program hash identifies the transformation implementation. Metadata schema 1 describes this checkpoint layout. On reopen, the function reconstructs the expected unique effects from the committed prefix and compares them with the actual effects table. This bounded oracle catches missing or altered state even when a cursor remains within range.

resume verifies that its supplied tape still matches the checkpoint's source hash. It reads the current cursor inside BEGIN IMMEDIATE, applies or recognizes the next identified effect, advances the cursor and commits. The immediate transaction protects the cursor-read and state update as one write operation. The program uses a finite tape of at most 100 positions so that replay checks and output remain appropriate for a teaching pad.

Worked case 1: close, reopen and resume#

example_one() starts processing the four-position tape and deliberately interrupts after two committed positions. At that point the cursor is two, and the effect table contains A: two and B: three. The connection is closed. Reopening the same file verifies the source and program identities, state schema and prefix invariant before returning a usable connection.

Resumption reads position two, the repeated A. Its stored value matches, so the effect table does not change, but the source cursor advances because that tape position has now been processed. Position three inserts C with one. The final cursor is four and the effects are A: two, B: three, C: one. Their sum is six. Invoking resume again at the end returns the same snapshot without additional effects.

This case makes two kinds of progress visible. Source progress counts four positions, while business-effect progress counts three unique identities. Neither should be silently substituted for the other in monitoring. A high replay rate may indicate upstream retries even when the accepted business state is stable. Conversely, a cursor that advances rapidly while useful effects remain empty can indicate filtering or validation problems requiring investigation.

Worked case 2: reject inconsistent or incompatible continuation#

The second case injects an exception after inserting an effect but before updating the cursor. Both operations belong to the same transaction, so the exception rolls them back together. The observed cursor remains zero and the effects table remains empty. A subsequent normal resume produces the accepted baseline. This is an actual SQLite rollback around the dangerous effect-versus-position boundary.

Next, the case tries to reopen that checkpoint with an extra source event and then with a different program identity. Both attempts are rejected. Appending a new event might seem harmless, but this fixture deliberately binds a finite source tape. A real appendable log needs a different identity contract, such as source partition identity plus stable offsets and retention guarantees. Silently accepting changed input would weaken the meaning of the recorded checkpoint.

Finally, the program changes the stored state-schema version to an unsupported value and verifies that reopening rejects it. The demonstration is an intentional compatibility drill, not an automatic migration. A schema version is a promise about how stored state is interpreted. Loading unknown state and hoping the fields still mean the same thing can turn a recoverable incompatibility into silent corruption.

Complete worked program#

Run in Python Core. All database files belong to one temporary directory per case. The program obtains its source identity from its actual source file, so editing the implementation changes the identity deliberately.

"""Actual SQLite checkpoint transactions bound to a finite source and reviewed program."""

import hashlib
import json
import sqlite3
import tempfile
from pathlib import Path


def identity(events):
    return hashlib.sha256(json.dumps(events, separators=(",", ":")).encode()).hexdigest()


def connect(path, events, program_identity):
    if not isinstance(program_identity, str) or len(program_identity) != 64:
        raise ValueError("Declare the exact reviewed transformation SHA-256")
    if not isinstance(events, list) or len(events) > 100:
        raise ValueError("Use a bounded source tape")
    for event in events:
        if (
            not isinstance(event, list)
            or len(event) != 2
            or not isinstance(event[0], str)
            or not event[0].strip()
            or type(event[1]) is not int
        ):
            raise ValueError("Each source position needs a string identity and integer value")
    connection = sqlite3.connect(path)
    try:
        with connection:
            connection.execute(
                "create table if not exists metadata(key text primary key,value text not null)"
            )
            connection.execute(
                "create table if not exists cursor(id integer primary key,"
                "next_offset integer not null)"
            )
            connection.execute(
                "create table if not exists effects(event_id text primary key,"
                "value integer not null)"
            )
            expected = {
                "schema": "1",
                "source_sha": identity(events),
                "program_sha": program_identity,
            }
            stored = dict(connection.execute("select key,value from metadata"))
            if stored:
                if stored != expected:
                    raise ValueError("Checkpoint schema, source or transformation identity changed")
            else:
                connection.executemany("insert into metadata values(?,?)", expected.items())
                connection.execute("insert into cursor values(1,0)")
            offset = connection.execute("select next_offset from cursor where id=1").fetchone()
            if offset is None or type(offset[0]) is not int or not 0 <= offset[0] <= len(events):
                raise ValueError("Checkpoint offset is outside its bound source")
        expected_effects = {}
        for key, value in events[: offset[0]]:
            if key in expected_effects and expected_effects[key] != value:
                raise ValueError("Committed source prefix contains a conflicting replay")
            expected_effects[key] = value
        actual_effects = dict(connection.execute("select event_id,value from effects"))
        if actual_effects != expected_effects:
            raise ValueError("Checkpoint effects do not match the committed source prefix")
        return connection
    except BaseException:
        connection.close()
        raise


def resume(connection, events, interrupt_after=None, fail_after_effect=False):
    if connection.execute("select value from metadata where key='source_sha'").fetchone() != (
        identity(events),
    ):
        raise ValueError("Resume tape differs from the checkpoint source")
    commits = 0
    while True:
        with connection:
            connection.execute("begin immediate")
            offset = connection.execute("select next_offset from cursor where id=1").fetchone()[0]
            if offset == len(events):
                break
            key, value = events[offset]
            previous = connection.execute(
                "select value from effects where event_id=?", (key,)
            ).fetchone()
            if previous is not None and previous != (value,):
                raise ValueError("Repeated event identity has conflicting value")
            connection.execute("insert or ignore into effects values(?,?)", (key, value))
            if fail_after_effect:
                raise RuntimeError("Interrupted before offset and effect could commit together")
            connection.execute("update cursor set next_offset=? where id=1", (offset + 1,))
        commits += 1
        if interrupt_after == commits:
            raise RuntimeError("Controlled interruption after committed source position")
    return snapshot(connection)


def snapshot(connection):
    return {
        "next_offset": connection.execute("select next_offset from cursor").fetchone()[0],
        "effects": dict(connection.execute("select event_id,value from effects order by event_id")),
    }


def fixture():
    return [["A", 2], ["B", 3], ["A", 2], ["C", 1]]


def example_one():
    events = fixture()
    program = hashlib.sha256(Path(__file__).read_bytes()).hexdigest()
    with tempfile.TemporaryDirectory() as directory:
        path = Path(directory) / "checkpoint.db"
        connection = connect(path, events, program)
        try:
            resume(connection, events, interrupt_after=2)
        except RuntimeError:
            assert snapshot(connection) == {"next_offset": 2, "effects": {"A": 2, "B": 3}}
        finally:
            connection.close()
        connection = connect(path, events, program)
        try:
            final = resume(connection, events)
            assert final == {"next_offset": 4, "effects": {"A": 2, "B": 3, "C": 1}}
            assert resume(connection, events) == final
            assert sum(final["effects"].values()) == 6
            return {"resumed": final, "unique_total": 6, "raw_tape_total": 8}
        finally:
            connection.close()


def example_two():
    events = fixture()
    program = hashlib.sha256(Path(__file__).read_bytes()).hexdigest()
    with tempfile.TemporaryDirectory() as directory:
        path = Path(directory) / "checkpoint.db"
        connection = connect(path, events, program)
        try:
            try:
                resume(connection, events, fail_after_effect=True)
            except RuntimeError:
                pass
            else:
                raise AssertionError("Expected injected transaction failure")
            assert snapshot(connection) == {"next_offset": 0, "effects": {}}
            baseline = resume(connection, events)
        finally:
            connection.close()
        failures = []
        for candidate, transform in [(events + [["D", 4]], program), (events, "0" * 64)]:
            try:
                connect(path, candidate, transform)
            except ValueError:
                failures.append("identity-rejected")
            else:
                raise AssertionError("An incompatible checkpoint was admitted")
        connection = connect(path, events, program)
        try:
            assert snapshot(connection) == baseline
            with connection:
                connection.execute("update metadata set value='2' where key='schema'")
        finally:
            connection.close()
        try:
            connect(path, events, program)
        except ValueError:
            failures.append("schema-rejected")
        else:
            raise AssertionError("Unknown state schema was admitted")
        return {
            "rolled_back_effect_and_offset": True,
            "incompatible_resumes": failures,
            "baseline_preserved_before_schema_drill": baseline,
        }


def main():
    print("Durable restart with identified effects:", example_one())
    print("Atomic failure and incompatible state rejection:", example_two())


if __name__ == "__main__":
    main()

State migration needs evidence#

A new application version may need to add a field, change an aggregation or split one state table into several. Decide whether old state can be transformed safely, whether it should be rebuilt from retained source, or whether both readers must coexist during a transition. The decision depends on semantics, not merely whether a SQL ALTER TABLE statement succeeds.

For example, changing from a sum to a mean requires both sum and count. If the old state stored only a sum and the source is no longer retained, the count cannot generally be reconstructed. No schema migration can invent the missing information. If the source remains available, rebuild under a new checkpoint identity and compare with an independent oracle before switching consumers. Keep the old accepted version until the new one is qualified and rollback requirements are understood.

The prefix reconstruction in this program is intentionally affordable because the source has at most 100 positions. A large production stream cannot rescan its entire history on every restart. It may instead rely on engine-maintained state snapshots, checksums, manifests, changelogs and transactional commit metadata. Those mechanisms reduce recovery cost but still need corruption detection, identity checks and tested restore procedures. A faster restart is not useful if it resumes the wrong computation.

Recovery limits and failure diagnosis#

A successful local transaction does not coordinate an external HTTP effect. If the computation calls another service between reading and committing its cursor, a crash can leave an uncertain remote outcome. Use the previous chapter's identified effect and reconciliation reasoning at that boundary. Likewise, a checkpoint file on a failed disk is not available merely because it was once committed; backup, replication and restore are separate operational concerns.

If the restored total is eight instead of six, inspect duplicate-event handling. If it is five, inspect whether C was skipped by a cursor saved ahead of its effect. If the cursor is valid but an effect value was modified, the prefix comparison should reject the checkpoint. If every code edit makes old checkpoints incompatible, that is the conservative contract of this teaching implementation; a production system may distinguish a stable transformation version from nonsemantic packaging changes through a reviewed migration policy.

Do not fix a mismatch by resetting the cursor to zero while retaining non-idempotent effects. Do not delete the effects while retaining a cursor at the end. Both shortcuts destroy the consistent cut of work. Preserve evidence, identify the last accepted state and choose a deliberate restore or rebuild path.

Applications and answered interview discussion#

These principles apply to stream processors, batch resumptions, import tools and model-feature computations. In an interview, “Where should the offset be committed?” is incomplete without asking where the effect is committed and what happens between them. Explain the atomic boundary or the reconciliation mechanism that connects the two.

If asked whether checksums prove a checkpoint is trustworthy, distinguish integrity from authorization and semantic correctness. A matching hash shows agreement with a declared identity; it does not prove the source was approved or the computation was right. If asked how to evolve state, discuss retained source, reversible migration, independent reconciliation and a controlled accepted-version switch. A migration plan should specify the failure and rollback path before changing the only copy of valuable state.
