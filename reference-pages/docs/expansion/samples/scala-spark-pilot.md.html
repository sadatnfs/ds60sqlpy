spark-013: One row, one event#

A NULL-aware aggregate lesson in Scala, PySpark and Spark SQL.

Status: planned pilot. This document is a complete teaching sample for the Scala/Spark design, not an activated course lesson. The current application has no Scala/Spark adapter. Do not run this code through the ordinary Python runner or install a JVM as a side effect of opening it. The proposed spark-local-scala and spark-local-python profiles require their own implementation and acceptance tests. The solutions are separate so you can predict and attempt the work first.

Level and prerequisites#

Beginner, about 90 minutes after a local profile is available. Complete planned spark-012 and demonstrate either the Scala foundations through spark-010, or the PySpark bridge spark-011 with existing python-10 skills. Neither path requires the historical SQL course: the small amount of SQL below is explained here. Existing sql-02 offers optional extra aggregate practice.

The proposed tuple is Spark 4.2.0, Scala 2.13.18, JDK 21 and Python 3.12. It is a compatibility-informed design, not a tested image. Apache documents the supported language/runtime lines, and its tagged build identifies the Scala patch. Spark environments, tagged build.

Learning objectives#

  • State the grain of a table and preserve distinct events with equal values.
  • Distinguish retained rows, observed amounts, zero amounts and missing amounts.
  • Predict the behavior of grouping, count, sum and NULL comparisons.
  • Separate a result's logical content from its physical partition layout.
  • Compare Scala, PySpark and SQL against an independent, ordered golden result.

Vocabulary and concepts#

  • Grain means what one row represents. Here one row is one event identified by event_id; it is not one unique (team, amount_cents) combination.
  • A bag, also called a multiset, permits equal-valued rows to occur more than once. Distinct event IDs can carry the same amount and team.
  • A schema states field names, types and nullability. Explicit schemas avoid guessing the type of a column whose current values are all missing.
  • NULL is an unknown or absent value at the SQL boundary. A zero amount is an observed number. A missing team is a grouping key with unknown identity.
  • A Column expression describes work Spark will evaluate. It is not a Python Boolean or an already computed Scala value.
  • A transformation constructs another query; an action, such as count or collect, requests a result. Collecting these seven rows is bounded; collecting an unknown production table is a different decision.
  • A canonical result is a deliberately normalized representation for comparison, including the requested column order and a complete row order. It is not proof that Spark's underlying storage has a permanent order.

count(*) counts all retained rows. In the APIs, count(lit(1)) has that effect because the literal is non-null for every retained row. count(amount_cents) counts rows with an observed amount. sum(amount_cents) adds observed amounts; if a group has no observed amounts, its sum remains NULL. Replacing that NULL with zero is a business rule that the report must name, not an automatic repair.

An ordinary comparison with NULL produces an unknown condition, so it does not pass a filter that keeps only TRUE. Use isNull for missingness. Use eqNullSafe in PySpark, <=> in Scala, or <=> in Spark SQL when you intend NULL-safe equality. GROUP BY collects NULL keys into a group. Finally, specify NULLS LAST when that is the desired presentation policy. These are Spark SQL semantics shared by the DataFrame expressions. Spark NULL semantics.

Runtime boundary and setup#

This pilot uses only inline rows, has no database connection, writes no dataset and needs no network dataset. A future accepted profile should create a fresh owned SparkSession with local[2], UTC time zone, two shuffle partitions and Spark UI disabled. Its process controller must bound memory/time and bind local Spark communication to loopback. It must stop only the session it created. The snippets below assume that owned session is called spark; the learner scaffolds and solution scripts show its lifecycle explicitly.

Scala uses Long values such as 100L; PySpark's explicit LongType receives Python integers. Money is integer cents to keep arithmetic exact. In the schema, false/False means the field cannot be missing in this fixture, and true/True permits missing values. Scala null and Python None become SQL NULL inside nullable fields. Scala's Option is useful in local code, but a raw Row with this schema uses null at the boundary.

Worked example / walkthrough#

Example 1: one missing amount is not an extra zero#

This smaller fixture contains amounts 10, NULL and 0. First count the rows on paper: there are three. Then count the observed amounts: there are two. Finally add the observed numbers: the sum is 10. Group x has two rows but only one observed amount; group y has one observed zero.

In an owned Scala Spark session:

import org.apache.spark.sql.Row
import org.apache.spark.sql.functions._
import org.apache.spark.sql.types._

val exampleSchema = StructType(Seq(
  StructField("team", StringType, true),
  StructField("amount_cents", LongType, true)
))
val exampleRows = Seq(Row("x", 10L), Row("x", null), Row("y", 0L))
val example = spark.createDataFrame(
  spark.sparkContext.parallelize(exampleRows, 2), exampleSchema
)
val metrics = example.agg(
  count(lit(1)).as("rows"),
  count(col("amount_cents")).as("valued"),
  sum(col("amount_cents")).as("total_cents")
).first()
assert(metrics.getLong(0) == 3L)
assert(metrics.getLong(1) == 2L)
assert(metrics.getLong(2) == 10L)
example.groupBy("team").agg(
  count(lit(1)).as("rows"),
  count(col("amount_cents")).as("valued"),
  sum(col("amount_cents")).as("total_cents")
).orderBy(col("team").asc_nulls_last).show()

The equivalent PySpark expressions:

from pyspark.sql import functions as F
from pyspark.sql.types import LongType, StringType, StructField, StructType

example_schema = StructType([
    StructField("team", StringType(), True),
    StructField("amount_cents", LongType(), True),
])
example = spark.createDataFrame(
    [("x", 10), ("x", None), ("y", 0)], schema=example_schema
)
metrics = example.agg(
    F.count(F.lit(1)).alias("rows"),
    F.count("amount_cents").alias("valued"),
    F.sum("amount_cents").alias("total_cents"),
).first()
assert tuple(metrics) == (3, 2, 10)
example.groupBy("team").agg(
    F.count(F.lit(1)).alias("rows"),
    F.count("amount_cents").alias("valued"),
    F.sum("amount_cents").alias("total_cents"),
).orderBy(F.col("team").asc_nulls_last()).show()

Expected rows, in order:

team rows valued total_cents
x 2 1 10
y 1 1 0

The argument to count determines what is counted. The alias only names the result. Changing the alias to rows does not turn a count of a nullable field into a count of every row.

Example 2: all missing and observed zero remain distinct#

Use a new three-row fixture: two missing amounts for m and one observed zero for n. Reuse exampleSchema/example_schema from the first example.

val missingExample = spark.createDataFrame(
  spark.sparkContext.parallelize(
    Seq(Row("m", null), Row("m", null), Row("n", 0L)), 2
  ), exampleSchema
)
val missingSummary = missingExample.groupBy("team").agg(
  count(lit(1)).as("rows"),
  count(col("amount_cents")).as("valued"),
  sum(col("amount_cents")).as("total_cents")
).orderBy(col("team").asc_nulls_last).collect()
assert(missingSummary(0).getString(0) == "m")
assert(missingSummary(0).getLong(1) == 2L)
assert(missingSummary(0).getLong(2) == 0L)
assert(missingSummary(0).isNullAt(3))
assert(missingSummary(1).getLong(3) == 0L)
missing_example = spark.createDataFrame(
    [("m", None), ("m", None), ("n", 0)], schema=example_schema
)
missing_summary = missing_example.groupBy("team").agg(
    F.count(F.lit(1)).alias("rows"),
    F.count("amount_cents").alias("valued"),
    F.sum("amount_cents").alias("total_cents"),
).orderBy(F.col("team").asc_nulls_last()).collect()
assert [tuple(row) for row in missing_summary] == [
    ("m", 2, 0, None),
    ("n", 1, 1, 0),
]

Check the Scala NULL with isNullAt before reading a primitive value. Do not let an unsafe conversion of NULL to a primitive number erase the distinction you are trying to teach. If a consumer wants a display value of zero, keep the original observed-count field and document that display policy separately.

Main fixture and learner scaffolds#

The row grain is one event per event_id.

event_id team amount_cents status
1 A 100 paid
2 A NULL paid
3 B 0 paid
4 NULL 50 paid
5 B 150 void
6 A 100 paid
7 C NULL paid

void means excluded from this report; it does not delete the input event. IDs 1 and 6 deliberately carry the same team and amount. They are different paid events. The missing team at ID 4 does not make its observed amount missing.

import org.apache.spark.sql.{Row, SparkSession}
import org.apache.spark.sql.functions._
import org.apache.spark.sql.types._

object Spark013Attempt {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder().appName("ds60-spark-013-attempt")
      .master("local[2]")
      .config("spark.ui.enabled", "false")
      .config("spark.driver.host", "127.0.0.1")
      .config("spark.driver.bindAddress", "127.0.0.1")
      .config("spark.sql.shuffle.partitions", "2")
      .config("spark.sql.session.timeZone", "UTC").getOrCreate()
    try {
      require(spark.sparkContext.master == "local[2]")
      val schema = StructType(Seq(
        StructField("event_id", LongType, false),
        StructField("team", StringType, true),
        StructField("amount_cents", LongType, true),
        StructField("status", StringType, false)
      ))
      val rows = Seq(
        Row(1L, "A", 100L, "paid"), Row(2L, "A", null, "paid"),
        Row(3L, "B", 0L, "paid"), Row(4L, null, 50L, "paid"),
        Row(5L, "B", 150L, "void"), Row(6L, "A", 100L, "paid"),
        Row(7L, "C", null, "paid")
      )
      val raw = spark.createDataFrame(
        spark.sparkContext.parallelize(rows, 2), schema
      )
      println(raw.schema.simpleString)
      // Exercise 1: retain event identity and filter status.
      // Exercise 2: inspect row count, observed count and sum.
      // Exercise 3: aggregate by team and order NULL keys last.
      // Exercise 4: distinguish NULL predicates and observed zero.
      // Exercise 5: expose projected-distinct loss; repartition safely.
      // Exercise 6: compare both APIs and SQL to the golden fixture.
    } finally {
      spark.stop()
    }
  }
}

Progressive hints#

  1. Keep a ledger of event IDs before comparing values. Equal values do not tell you whether two records are the same event.
  2. Count a non-null literal and the amount field separately. Inspect team C before considering any coalesce business rule.
  3. Normalize the final summary with an explicit NULL-last order, compare it to a literal golden list, and inspect which columns existed immediately before distinct.

Rubric#

Score each criterion 0, 1 or 2: 0 means absent or incorrect, 1 means a correct result with incomplete evidence/explanation, and 2 means exact evidence plus a correct explanation. There are six criteria: grain/filter, count/sum distinction, NULL/zero/group behavior, predicates, bag/partition invariance, and independent cross-language/SQL parity. Mastery requires 2 on each criterion and a correct transfer prediction. A successful process exit alone earns no criterion.

Common pitfalls#

Using a set to compare rows can hide duplicate loss. Comparing printed show tables can hide a type mismatch. Filling NULL with zero before thinking about meaning can erase missingness. Sorting within partitions can leave the overall result unordered. Scala primitive getters need a NULL guard. PySpark Columns need &/| with parentheses rather than Python and/or. Both implementations can repeat the same bad assumption, so a hand-written oracle remains necessary.
