# go-047: Controller tests from pure functions to owned clusters

## Level and prerequisites

Advanced. Allow about 120 minutes, then revisit the transfer case later. Prerequisites: go-046

## Learning objectives

By the end, explain fake client, integration evidence, fault injection; implement the six investigations below; and defend the expected result of a changed input before running it. A passing reference is evidence about that program, not a certification of your independent understanding.

## Why this mechanism matters

A controller needs several evidence layers. Pure tests check decision rules quickly. Fake-client tests check requested API interactions and local error handling but may omit server defaulting, validation, resourceVersion conflicts and admission behavior. API-server integration tests add those server contracts. An owned disposable cluster adds controllers, scheduling, networking and real cleanup behavior. Passing a fake test is not interchangeable with a successful rollout. Design fault injection around a specific uncertainty: conflict, cancellation, stale cache, forbidden access or unknown outcome. Keep source hashes, exact object identity and cleanup receipts so the evidence can be traced to the program that actually ran.

## Vocabulary and concepts

- **Fake client:** An in-process substitute with deliberately limited server semantics.
- **Integration evidence:** Observed behavior across real component boundaries.
- **Fault injection:** Deliberately producing a specified failure to test recovery.

## Syntax anatomy and reasoning

Use a narrow interface at the application boundary and inject a fake with explicit outcomes. Assert both the result and which calls were made. A forbidden error should not trigger an endless retry loop; a cancellation should stop new calls. For live tests, create a unique owned namespace, retain UIDs, bound all waits and verify cleanup without deleting resources identified only by a reusable name. Do not use production contexts as convenient fixtures.

## Worked example / walkthrough

### Worked example 1: Verify one successful API call

Run a fake client configured to return a value.

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

var ErrForbidden = errors.New("forbidden")

type FakeReader struct {
	Value, Calls int
	Err          error
}

func (f *FakeReader) Read(ctx context.Context) (int, error) { f.Calls++; return f.Value, f.Err }

type Reader interface {
	Read(context.Context) (int, error)
}

func readOnce(ctx context.Context, r Reader) (int, error) {
	if err := ctx.Err(); err != nil {
		return 0, err
	}
	v, err := r.Read(ctx)
	if err != nil {
		return 0, fmt.Errorf("read object: %w", err)
	}
	return v, nil
}

func main() {
	// Verify one successful API call
	{
		f := &FakeReader{Value: 3}
		v, err := readOnce(context.Background(), f)
		check(err == nil && v == 3 && f.Calls == 1, "success")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The result is retained and exactly one call occurs.

Call count is evidence about adapter behavior, while the returned value checks the consuming contract.

### Worked example 2: Preserve a forbidden error

Make the fake return ErrForbidden.

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

var ErrForbidden = errors.New("forbidden")

type FakeReader struct {
	Value, Calls int
	Err          error
}

func (f *FakeReader) Read(ctx context.Context) (int, error) { f.Calls++; return f.Value, f.Err }

type Reader interface {
	Read(context.Context) (int, error)
}

func readOnce(ctx context.Context, r Reader) (int, error) {
	if err := ctx.Err(); err != nil {
		return 0, err
	}
	v, err := r.Read(ctx)
	if err != nil {
		return 0, fmt.Errorf("read object: %w", err)
	}
	return v, nil
}

func main() {
	// Verify one successful API call
	{
		f := &FakeReader{Value: 3}
		v, err := readOnce(context.Background(), f)
		check(err == nil && v == 3 && f.Calls == 1, "success")
	}

	// Preserve a forbidden error
	{
		f := &FakeReader{Err: ErrForbidden}
		_, err := readOnce(context.Background(), f)
		check(errors.Is(err, ErrForbidden) && f.Calls == 1, "forbidden")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The exact cause is visible and only one call occurs.

Authorization failure is not repaired by repeating the same request. Surface the required permission or configuration diagnosis.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
