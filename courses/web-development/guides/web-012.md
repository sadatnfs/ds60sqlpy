# web-012: Typography, units and readable content

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-011`

## Learning objectives

Build a reading page with bounded measure and scalable headings. Explain why ch is a useful approximation rather than a word-count guarantee. Use rem, em and line-height accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Typography controls the effort required to read. A font stack lists preferred fonts followed by a generic fallback, so text remains usable when a particular font is absent. This course uses system fonts and makes no external font request. Relative units allow the design to respond to user settings. A rem is relative to the root font size; em often depends on the current element's font size, with property-specific details.

Line length, line height and spacing interact. Very long lines make it difficult to find the next line; very short lines create constant interruptions. A max-width expressed in ch can approximate a readable character measure, though it is based on the zero glyph width rather than an exact count of all characters. A unitless line-height scales naturally with the element's font size.

### Key terms

- **Rem:** A length unit equal to the root element's font size, so text sized in rem follows the reader's browser font setting.
- **Em:** A length unit relative to the element's own font size, or the parent's when setting `font-size`, so it compounds when nested.
- **Line-height:** The property that sets the height of each line box; a unitless value such as 1.5 scales with the font size.
- **Measure:** The length of a line of text, often limited with a `ch` based maximum inline size so lines stay readable.
- **Font stack:** A comma-separated `font-family` list that the browser tries in order, ending with a generic family such as `sans-serif`.

## Syntax anatomy and mechanism

Use `font: 1rem/1.6 system-ui, sans-serif` to set size, unitless line-height and family. Avoid fixing the root to a tiny pixel size to make arithmetic convenient. Preserve user zoom. Headings can use a bounded fluid size with clamp, while body text should remain comfortable and predictable. Give the preferred value a rem term, as in `1.25rem + 2vw`: a pure viewport unit such as `4vw` ignores the reader's default font size and text zoom between the bounds. Text alignment is content-sensitive; full justification can create distracting gaps in narrow columns.

## Worked example / walkthrough

### Worked example 1: A reading column

The column stays bounded even on a large monitor.

```css
.prose {
  max-inline-size: 65ch;
  font-size: 1rem;
  line-height: 1.6;
}
```

**Expected observation:** The heading grows with width within the given bounds, and the rem term keeps it responsive to the reader's font-size setting and zoom.

### Worked example 2: A bounded heading

Clamp supplies a minimum, preferred fluid size and maximum.

```css
h1 {
  font-size: clamp(1.75rem, 1.25rem + 2vw, 3rem);
}
```

**Expected observation:** The heading grows with width within the given bounds.

## Contrast case: a heading sized only by the viewport

Both rules produce a similar heading at a typical laptop width. Change the browser's default font size and compare them.

```css
/* viewport only */
h1.a {
  font-size: 4vw;
}
/* bounded and zoom-aware */
h1.b {
  font-size: clamp(1.75rem, 1.25rem + 2vw, 3rem);
}
```

`h1.a` depends only on viewport width. At a 400px viewport it computes to 16px, smaller than many body texts, and at 2000px it reaches 80px. Changing the default font size from 16px to 24px leaves it untouched, so a reader who needs larger text gets no help. `h1.b` stays between 1.75rem and 3rem, and both its bounds and its rem term grow with the reader's setting. The Computed panel shows the resolved pixel value for each rule after you resize.

## Debugging and common mistakes

Do not disable pinch zoom or set user-scalable=no. A brand font is optional; readable content is not. Test actual enlargement because a screenshot at one size cannot expose clipping.

When text overlaps after zooming, look for a fixed line height in pixels or a container with a fixed height. When headings stop growing with the reader's font setting, check whether the size uses only viewport units; adding a rem term to clamp restores the user's control.
