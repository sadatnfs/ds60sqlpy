# web-014: Normal flow, display and positioning

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-013`

## Learning objectives

Build a card with an intentional positioned badge and flowing content. Explain the containing block used by an absolute element. Use normal flow, block and inline accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Normal flow is the browser's default arrangement of content. Block boxes generally stack in the block direction and inline content flows within lines. Understanding this default prevents unnecessary positioning. Display changes how an element participates in layout; it does not change its underlying HTML meaning. A paragraph made display:flex remains a paragraph semantically.

Positioning modifies placement relative to a containing block or scroll container. Relative positioning keeps the element's original space while offsetting its painted position. Absolute positioning removes it from ordinary flow and uses a containing block, often the nearest positioned ancestor. Fixed positioning is often tied to the viewport but transformed ancestors can affect that behavior. Sticky positioning depends on a scroll container and an inset threshold.

### Key terms

- **Normal flow:** The default layout, in which block boxes stack in the block direction and inline content wraps along lines.
- **Block box:** A box that starts on a new line and, by default, fills the available inline size of its container.
- **Inline content:** Text and inline-level boxes that flow within lines and wrap with them instead of stacking.
- **Position:** The property with values `static`, `relative`, `absolute`, `fixed` and `sticky` that decides how offsets move a box and whether it leaves normal flow.
- **Containing block:** The rectangle that percentages and offsets refer to; for an absolutely positioned box it is usually the nearest positioned ancestor.

## Syntax anatomy and mechanism

Use `position: relative` on a card only when it intentionally establishes the containing block for an absolute badge. Keep the main article content in flow. A sticky section label needs an inset such as `top: 0` and sufficient scroll space. Avoid putting every element at exact pixel coordinates; content length and viewport width will change.

## Worked example / walkthrough

### Worked example 1: Ordinary flow

Blocks stack without special positioning.

```html
<p>First paragraph.</p><p>Second paragraph.</p>
```

**Expected observation:** The second paragraph follows the first in normal flow.

### Worked example 2: A contained badge

Only the badge is taken out of flow.

```css
.card {
  position: relative;
  padding: 2rem;
}
.badge {
  position: absolute;
  inset-block-start: 0.5rem;
  inset-inline-end: 0.5rem;
}
```

**Expected observation:** The badge is positioned relative to the card.

## Contrast case: an absolute badge without a positioned ancestor

The badge rule from worked example 2 is kept, but the card's `position: relative` is deleted.

```html
<style>
  .card { padding: 2rem; }
  .badge {
    position: absolute;
    inset-block-start: 0.5rem;
    inset-inline-end: 0.5rem;
  }
</style>
<article class="card">
  <span class="badge">New</span>
  <p>Card text.</p>
</article>
```

Without a positioned ancestor, the badge's containing block is the initial containing block, so New jumps to the top right corner of the page instead of the card. Every card on the page would stack its badge in that same corner. Restoring `position: relative` on `.card` makes the card the containing block again, and the inset values are measured from its padding edge. The card's own text never moved in either case, because an absolutely positioned element is removed from flow and does not push siblings.

## Six progressive exercises

Exercises that ask you to predict, explain, compare or diagnose keep their answers in the solutions file. The others show the evidence to look for.

### Exercise 1: Predict whether relative positioning frees the original space.

**Progressive hint:** Compare where the element was laid out with where it is painted.

### Exercise 2: Turn a group of inline links into a block navigation list.

**Expected evidence:** Display changes the arrangement without changing navigation semantics.

**Progressive hint:** Change display on the list or links, not the markup.

### Exercise 3: Build a card with an intentional positioned badge and flowing content.

**Expected evidence:** Long body text expands the card while the badge stays in its reserved corner.

**Progressive hint:** Make the card position: relative and reserve padding where the badge will sit.

### Exercise 4: Diagnose an absolute label overlapping enlarged text.

**Progressive hint:** Increase the text size and check whether the reserved space grows with it.

### Exercise 5: Add a long paragraph and narrow the preview.

**Expected evidence:** Content remains readable and the badge does not obscure it.

**Progressive hint:** Make the paragraph much longer and shrink the preview to a phone width.

### Exercise 6: Explain the containing block used by an absolute element.

**Progressive hint:** Walk up the ancestors to the first one whose position is not static.

## Debugging and common mistakes

Sticky positioning can fail because an ancestor creates an unexpected scroll container. Z-index does not repair an incorrect containing block. Keep the reading order in the source meaningful.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
