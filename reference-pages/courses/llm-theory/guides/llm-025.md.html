llm-025: Memory and compute without a GPU#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: llm-024. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Estimate attention and cache costs before choosing a context size. The central investigation is concrete: Count score elements and KV-cache bytes for declared T,H,dtype; compare T=16T=16T=16 and 32 while model width stays fixed. The finish condition is Doubling context quadruples the T-by-T score count and doubles KV storage. State exclusions such as allocator overhead and batching. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Turn tensor shapes into an execution budget#

The cached decoder in the previous chapter made an important promise: recomputing a prefix and extending its cache should represent the same computation. This chapter asks what that promise costs. A cache saves repeated work by retaining state, so it exchanges computation for storage. An attention implementation may avoid storing an entire score matrix while still evaluating the same pairs. Understanding these tradeoffs begins by naming the arrays, their dimensions, and the interval during which they remain alive.

Use B for batch size, T for sequence length, L for the number of layers, Hq for the number of query heads, Hkv for the number of key/value heads, d for the width of one head, and s for bytes per stored element. In ordinary multi-head attention, Hq=Hkv=HH_q=H_{kv}=HHq​=Hkv​=H and model width D=H⋅dD=H\cdot dD=H⋅d. Keep D distinct from d: a head is a partition of the model's feature width, not another copy of that entire width. We will count raw tensor storage first, then explain why process memory and runtime require additional evidence.

Begin with a named array and its lifetime#

For one layer, a materialized score array has shape(B,Hq,T,T). The first T indexes the token asking a question; the second indexes candidate keys. Its element count is B⋅Hq⋅T2B\cdot H_q\cdot {T}^{2}B⋅Hq​⋅T2, and its raw bytes are B⋅Hq⋅T2⋅sB\cdot H_q\cdot {T}^{2}\cdot sB⋅Hq​⋅T2⋅s. Doubling T changes both position axes, so it quadruples that array. A causal triangle does not automatically halve the allocated tensor: an implementation can store a full square and mask half its entries. Sparse mathematical support and sparse physical storage are different properties.

The K/V cache has a different shape and purpose. Each layer retains one key and one value for every cached token. When keys and values have the same head width, raw cache bytes are 2⋅L⋅B⋅Hkv⋅T⋅d⋅s2\cdot L\cdot B\cdot H_{kv}\cdot T\cdot d\cdot s2⋅L⋅B⋅Hkv​⋅T⋅d⋅s. The leading 2 counts the two tensors. This grows linearly in cached length because a new token adds one key and one value per KV head. Query vectors are needed to process the current step but are not another persistent history tensor in this cache design.

A lifetime diagram prevents a common accounting mistake. During sequential inference, a temporary score array for layer 1 can be released before layer 2's score array is created. The cache for every layer must remain available for the next generated token. Summing every temporary array ever created overestimates simultaneous live storage; counting only one layer's persistent cache underestimates it. During training, intermediates retained for backward can overlap across layers and change the memory picture again.

Work through a budget with consistent units#

Consider an analytical model with L=12L=12L=12 layers, B=1B=1B=1, Hq=Hkv=8H_q=H_{kv}=8Hq​=Hkv​=8 and d=64d=64d=64, so D=512D=512D=512. Assume float32 materialized scores, using 4 bytes per element, and a two-byte cache representation. These are chosen counting assumptions, not a claim about an installed kernel or measured model.

A MiB is 1,048,576 bytes. A decimal MB is 1,000,000 bytes. Report the unit instead of using the same label for both. At T=2048T=2048T=2048, it would be misleading to call 128 MiB the model's memory requirement: it describes only one score tensor. It would also be misleading to multiply that value by 12 without stating whether all layer scores coexist. The 48 MiB cache count, by contrast, explicitly includes all 12 layers.

Now increase batch size from 1 to 4. Both raw quantities multiply by 4 if every request has the same padded/cached length. If the actual request lengths are[256,512,1024,2048], a tightly packed cache could count the sum 3840 positions, while a rectangular allocation padded to 2048 for all four requests reserves 8192 positions. The data layout, padding policy and allocator determine which physical count applies. A batch size is not enough information to predict memory.

Count work separately from stored values#

A dot product of width d uses d multiplications and roughly d additions. Under the convention that one multiply and one add count as two floating-point operations, forming QKTQK^{\mathsf T}QKT costs about 2⋅B⋅Hq⋅T2⋅d2\cdot B\cdot H_q\cdot {T}^{2}\cdot d2⋅B⋅Hq​⋅T2⋅d. Multiplying the attention weights by values of the same width costs a similar amount. Ordinary dense attention therefore has a leading pairwise term of approximately 4⋅B⋅T2⋅D4\cdot B\cdot {T}^{2}\cdot D4⋅B⋅T2⋅D. This ignores normalization, masking, projections and implementation details, but it explains why the two position axes matter even if a clever algorithm avoids storing their full matrix.

The Q/K/V projections and output projection also cost work. For ordinary MHA with width D, four D-by-D projections contribute approximately 8⋅B⋅T⋅D28\cdot B\cdot T\cdot {D}^{2}8⋅B⋅T⋅D2 operations under the same convention. A two-matrix feed-forward block with hidden width h contributes approximately 4⋅B⋅T⋅D⋅h4\cdot B\cdot T\cdot D\cdot h4⋅B⋅T⋅D⋅h. These terms are linear in T but quadratic in feature width when h is proportional to D. At modest context lengths, projections and feed-forward work can dominate a tiny model even though attention has the more alarming asymptotic growth. Big-O describes scaling, not which measured operation currently takes the most time.

Incremental decoding changes the query length. With one newly generated token and T cached keys, the score shape per head is(1,T), so the new attention comparison is linear in existing context length. The cache avoids recomputing past projections and representations. It does not make generating an arbitrary number of tokens constant-cost: the retained context grows, cache reads grow, and each new token still passes through model layers. Prompt prefill and one-token decode are different workloads and should be timed separately.

Training requires another set of state accounts#

A parameter tensor may coexist with its gradient and optimizer states. For example, a simple float32 parameter/gradient/two-moment accounting for an Adam-style optimizer is roughly four float32 arrays per parameter, or 16 bytes per parameter, before activations and temporary work. Mixed-precision training may also retain master weights or use different optimizer-state formats, so this is an illustrative accounting identity rather than a universal rule. Freezing a parameter can remove some training state, but the forward operation may still need its value and may still need activations to backpropagate into other trainable components.

Activation checkpointing trades extra recomputation for retaining fewer forward intermediates. Gradient accumulation trades multiple smaller forward/backward passes for a desired effective batch, but does not automatically make optimizer state smaller. Quantizing stored weights changes another component of the budget and can add scale metadata. These techniques operate on different allocations. A useful report names which component is reduced and what additional work or numerical change is introduced.

This is why a full training-memory claim cannot be obtained by multiplying parameter count by one dtype size. The claim also needs optimizer choice, batch and sequence shapes, activation policy, precision, retained graphs and temporary workspace behavior. On CPU, process memory includes Python/framework objects; an allocator may keep released storage for reuse. On an accelerator, reserved device memory and actively used tensor memory can differ. Neither measure can be inferred from a small static table alone.

Turn the estimate into a diagnostic hypothesis#

Suppose doubling context makes a run fail. First check whether the failed allocation has two position axes, one position axis, a vocabulary axis or an optimizer-state role. A full logits tensor shaped(B,T,V) can be important when vocabulary V is large, even if it is tiny in this lesson. A serving path returning only the final token's logits has a different allocation contract. If memory rises across repeated calls at a fixed shape, retained references or graphs may be a better hypothesis than the T² formula.

The arithmetic here gives predictions to test: doubling T should quadruple a particular materialized score array and double a fixed-layout cache; doubling B should multiply each by two; halving element width should halve the raw array bytes. If a measured process peak does something else, that does not invalidate arithmetic. It means another allocation or lifetime rule is involved. Keep the estimate, the measured observation and the explanation separate until the discrepancy is understood.

Vocabulary and concepts#

Quadratic growth: Doubling a dimension multiplies a quantity by four.

KV bytes: Raw storage of keys and values under declared shapes and dtype.

Peak memory: Maximum observed runtime memory, including more than raw tensor sizes.

Syntax anatomy and reasoning sequence#

For batch B, heads H, sequence length T, head width d and s bytes per element, scores contain B⋅H⋅T⋅TB\cdot H\cdot T\cdot TB⋅H⋅T⋅T elements. Full multi-head K/V storage contains 2⋅L⋅B⋅H⋅T⋅d⋅s2\cdot L\cdot B\cdot H\cdot T\cdot d\cdot s2⋅L⋅B⋅H⋅T⋅d⋅s bytes across L layers. Model width is D=H⋅dD=H\cdot dD=H⋅d; using D in place of d would count the heads twice. Convert bytes to KiB by dividing by 1024, not 1000. Change one dimension at a time to expose scaling.

Derive score and cache storage separately#

Materialized attention scores for one layer have B⋅H⋅T⋅TB\cdot H\cdot T\cdot TB⋅H⋅T⋅T entries. With B=1B=1B=1, H=2H=2H=2, increasing T from 16 to 32 changes the count from 512 to 2, 048, a factor of four. At four bytes per element, those individual score arrays occupy 2 KiB and 8 KiB. This is a tensor-size calculation; an implementation may also materialize probabilities, masks or backward intermediates, or use an algorithm that avoids storing the full score matrix.

K/V cache data for L layers has 2⋅L⋅B⋅Hkv⋅T⋅Dh2\cdot L\cdot B\cdot H_{kv}\cdot T\cdot D_h2⋅L⋅B⋅Hkv​⋅T⋅Dh​ elements. The leading two counts keys and values. For one layer, batch one, two KV heads, head width sixteen and float32, T=16T=16T=16 gives 4, 096 bytes and T=32T=32T=32 gives 8, 192 bytes. Doubling context doubles this cache data rather than quadrupling it. The score and cache sizes happen to coincide at one chosen small shape; that coincidence is not a general identity.

Changing element size from four bytes to two halves the raw cache-byte arithmetic. It does not prove that the runtime supports a desired low-precision kernel or that numerical behavior remains acceptable. Increasing batch from one to three triples cache data. Redistributing a fixed model width between ordinary MHA head count and head width preserves H⋅DhH\cdot D_hH⋅Dh​, so that particular cache count stays the same. MQA/GQA instead change the number of distinct KV heads, which the expert head-sharing chapter treats separately.

Raw tensor bytes are not measured peak memory#

Parameters, temporary buffers, framework state, Python objects, allocator caching and retained activations can all contribute to process memory. During training, storing intermediates for backward differs from inference with detached caches. A peak measurement also depends on the lifetime overlap of tensors, not only the sum of every tensor that ever exists. An allocator may retain released memory for reuse rather than returning it immediately to the operating system.

Vocabulary logits are another potential allocation: a full [B, T, V] output can be substantial for a large V, while an inference interface that requests only the last position has a different output contract. Do not infer the dominant cost from the tiny sixteen-token fixture. Likewise, CPU tensor arithmetic does not establish GPU kernel throughput or memory-traffic savings. The honest result here is an exact layout-based estimate with explicit exclusions, ready to be compared with a separate measured runtime experiment.

Worked example / walkthrough#

Example A: Count attention scores#

Both the query and key axes double, producing four times as many scores. The number of heads remains fixed.

import numpy as np

b, h = 1, 2
counts = [b * h * t * t for t in [16, 32]]
assert counts == [512, 2048]

Expected: 512 and2048 score elements.

Example B: Count raw cache bytes#

The factor two counts keys and values. Each past position adds a fixed number of features, so doubling context doubles this raw storage.

import numpy as np

b, h = 1, 2
counts = [b * h * t * t for t in [16, 32]]
assert counts == [512, 2048]
cache = [2 * 1 * 1 * 2 * t * 16 * 4 for t in [16, 32]]
assert cache == [4096, 8192]

Expected: 4096 and8192 bytes.

Common pitfalls and diagnosis#

Write every factor and unit in the byte formula: keys/values, layers, batch, KV heads, time, head width and element size. Separate score materialization from cache storage and raw data bytes from measured process peak. A fixed-width MHA head repartition is not the same change as reducing KV heads with GQA or MQA.
