# web-019: Pseudo-classes, pseudo-elements and stateful styling

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-018`

## Learning objectives

Build a preferences list whose selected state is visible and semantic. Explain why CSS state cannot authorize a server action. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

A pseudo-class selects an element based on a condition such as focus, checked state or its position among siblings. A pseudo-element represents a stylable part associated with an element, such as before or after. Generated decorative content can enrich presentation, but essential instructions should exist as real document content because generated content has inconsistent accessibility implications.

State should remain grounded in a real control or application contract. Styling a checkbox's checked state makes use of built-in behavior. A decorative class named active does not prove that a control is selected, and CSS cannot perform server authorization. Use native state first and add custom state only with a clear interaction model.

## Syntax anatomy and mechanism

`:focus-within` matches a container while one of its descendants has focus. `input:checked + span` selects a neighboring label fragment after a checked input. Attribute selectors can target a declared state, but the application is responsible for keeping that state accurate. Hover must be an enhancement because touch and keyboard interactions may not provide the same hover behavior.

## Classroom execution and offline inputs

Choose **HTML browser preview** in the classroom. The pad is one complete HTML document with embedded CSS and, where taught, embedded JavaScript. Its preview is isolated from the classroom and recreated on each run. It does not contact a server, submit real forms, read cookies, fetch assets or load a CDN. All fixtures are inline and synthetic. The browser uses its native HTML parser, so classic-script ordering, shared lexical bindings, inline modules and real DOMContentLoaded/load events keep their browser semantics. External module imports remain blocked. Navigation metadata such as base and meta http-equiv is rejected explicitly. On any supported host, the browser renders the document while Docker serves the classroom. No host compiler is needed.

Run your own source after implementing the task. A reference's checks inspect only the named initial conditions. Its success message is not a full accessibility audit, proof of responsive behavior at every size, or evidence that you implemented the solution yourself. Inspect actual output after keyboard input, resizing and changes. Save your source before comparing with a reference. The document and its CSS share one saved pad; HTML and CSS remain different languages within that artifact.

## Worked example / walkthrough

### Worked example 1: A focused group

The container helps the user locate the current task.

```css
.field:focus-within { border-color: #0753a4; }
```

**Expected observation:** The field group changes while its descendant is focused.

### Worked example 2: A native checked state

The checkbox remains the actual control.

```css
input:checked + span { font-weight: 700; }
```

**Expected observation:** The adjacent label becomes bold when checked.

## Six progressive exercises

### Exercise 1: Distinguish a condition selector from generated content.

**Expected evidence:** A pseudo-class selects an existing state; a pseudo-element styles a represented part.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Add focus-within feedback around a labeled input.

**Expected evidence:** The group is highlighted while the control has focus.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Build a preferences list whose selected state is visible and semantic.

**Expected evidence:** Native checkboxes carry the state and text styling reinforces it.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Remove an essential instruction placed only in ::before and restore it as HTML.

**Expected evidence:** The instruction becomes real document content available independently of generated decoration.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Operate the controls without hover.

**Expected evidence:** All actions and state information remain usable by keyboard and touch.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Explain why CSS state cannot authorize a server action.

**Expected evidence:** Presentation can be changed by the client; the server must enforce permission using trusted context.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

A hover-only menu can exclude keyboard users. Generated text can be skipped or announced unexpectedly. Keep meaningful text in the document and let CSS reinforce it.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation.
