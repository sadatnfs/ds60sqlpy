## Learn from a comparison without confusing preference with truth

Supervised instruction tuning provides a desired response to imitate. Preference data instead compares responses under a stated criterion: for the same prompt, one response is labeled chosen and another rejected. A preference objective turns that comparison into a learning signal. The criterion might concern usefulness, format, completeness or another property, and the label collection process determines what it actually means. A chosen label is not automatically an independently verified factual answer.

Let x be a prompt, y_w the chosen response and y_l the rejected response. Write pi_theta(y|x) for the current policy's sequence probability and pi_ref(y|x) for a fixed reference policy. A sequence log probability is a sum of conditional token log probabilities under the declared tokenization and termination policy. The lesson uses those log probabilities as supplied scalar values so the objective can be inspected without sampling or training a model.

### Form the comparison in two stages

First compute the policy's preference difference: delta_theta=log pi_theta(y_w|x)-log pi_theta(y_l|x). Compute the analogous reference difference delta_ref. The adjusted margin is m=beta*(delta_theta-delta_ref), where beta is positive. The logistic loss is L=-log sigmoid(m)=log(1+exp(-m)). A positive margin means the current policy favors the chosen answer more strongly than the reference does under this scoring convention.

In the first worked case, current log probabilities-2 and-3 give delta_theta=1. Reference log probabilities-4 and-5 also give delta_ref=1. Their difference is zero, so m=0 and loss log(2)≈.693147. Both policies assign a higher probability to the chosen response, but there has been no relative-preference improvement against the reference. Absolute sequence probabilities can differ while this adjusted margin remains unchanged.

In the second case, the supplied differences are 2 and 0 and beta=.5, giving m=1. The loss is log(1+exp(-1))≈.313262. Reversing the chosen/rejected labels negates the margin and gives log(1+exp(1))≈1.313262. The difference in losses reflects agreement with the supplied ordering. It does not evaluate whether either response's claims are supported by an external source.

### Understand where the reference correction comes from

One motivation considers a policy optimized for expected reward while penalizing divergence from a reference distribution. Under the relevant fixed-prompt, support and normalization assumptions, the optimum has the form pi_star(y|x) proportional to pi_ref(y|x)*exp(r(x,y)/beta). Rearranging expresses reward as beta*log[pi_star(y|x)/pi_ref(y|x)] plus a prompt-dependent normalization term.

If pairwise preferences are modeled through a logistic function of reward differences, that prompt-only normalization term cancels between two responses to the same prompt. This yields the relative log-probability comparison used by the DPO-style objective. The derivation relies on the preference model and regularized-policy assumptions; it is not a statement that arbitrary human choices reveal an exact universal reward function. The [DPO paper](https://arxiv.org/abs/2305.18290) develops this connection in full, while the course isolates the resulting scalar objective.

The reference policy is normally fixed for the stated comparison. If its parameters or scoring convention change, the same current-policy scores can produce a different margin. Store the reference identity alongside the data and objective configuration. Using a variable called `reference` does not establish that it remained frozen or that its tokenization matched the current policy.

### Follow the gradient to see what is rewarded

The derivative dL/dm is-sigmoid(-m). Applying the chain rule gives derivative-beta*sigmoid(-m) with respect to the chosen response's current log probability and+beta*sigmoid(-m) with respect to the rejected response's. Gradient descent therefore pushes the chosen log probability upward relative to the rejected one through the model's parameterization. At beta=.5 and m=1, the magnitudes are approximately .13447.

For a very positive margin, the gradient becomes small because the pair is already strongly ordered as desired. For a very negative margin, its magnitude with respect to m approaches 1. The stable implementation uses `logaddexp(0,-m)` rather than forming exp(-m) directly. At m=-1000, direct exponentiation can overflow even though the loss is approximately 1000 and can be represented. Numerical stability preserves the intended objective; it does not correct bad labels or a mismatched reference.

An improved margin need not mean that the chosen response's absolute probability increased. Suppose the current difference changes from(-2)-(-3)=1 to(-3)-(-5)=2. The chosen response became less probable, but the rejected response declined even more, so the relative preference improved. This counterexample explains why a margin alone is not a complete description of the policy change. Inspect sequence probabilities, task outcomes and reference divergence when those quantities matter to the experiment.

### Token and response conventions change the event being compared

A sequence log probability is usually a sum over response tokens conditioned on the prompt and previous response tokens. Prompt tokens can be context without belonging to the response score. Including an EOS token, masking formatting tokens or normalizing by response length changes the comparison. A mean token log probability is not algebraically interchangeable with the sequence log probability in the stated objective.

Length can affect sums because a longer response contains more factors below one. The reference correction can account for aspects of baseline preference, but it does not make every length-related data bias disappear. If annotators consistently prefer verbose answers or the rejected responses are systematically shorter, the dataset may teach a style preference alongside the intended quality criterion. Preserve response lengths and annotation rationale so that a gain can be interpreted.

The prompt must also be the same contextual event for the pair. Comparing one response generated with extra retrieval evidence to another generated without it can mix evidence availability with response quality. Such a comparison may be meaningful for a system-level study, but it is a different experimental question from changing only the policy under fixed context. Record the actual input artifacts used to produce each candidate.

### Preference data is a measurement process

A label can be inconsistent, ambiguous or affected by presentation order, domain knowledge and the rubric. Multiple annotators may disagree for substantive reasons. A dataset should retain the prompt family, candidate identities, rubric, available evidence and relevant collection conditions. Pair counts alone do not establish independent coverage if many comparisons are variations of the same underlying task.

Train/development/test separation must follow the intended unit of generalization. If the same source answer or prompt template appears in both adaptation and assessment, a favorable score may reflect familiarity with that family. Choosing beta or a stopping point after repeatedly examining final assessment preferences similarly converts that set into development data. The presence of a reference policy does not solve data leakage.

A useful application evaluation separates the behavior rewarded by preference labels from other required properties. Better preferred-response rate can coexist with worse citation support, more unsupported detail or a regression on a small but important task family. Those outcomes need their own checks. This does not make preference learning useless; it makes its objective precise enough to combine with other evidence.

### Know what the local exercise actually executes

The reference computes fixed margins, stable losses and controlled changes. It does not fit a reward model, sample a rollout, run an online reinforcement-learning loop or train a production assistant. Describing it as a full RLHF pipeline would attribute work to the code that it never performs. Its contribution is the ability to derive and debug a preference objective before using one in a larger adaptation experiment.
