Docker: from the first container to a recoverable application#

Run ./classroom from the repository root and choose Docker in the unified subject directory. All 42 lessons include a detailed guide, two worked examples, six progressive evidence tasks, an answer-free worksheet and separate solutions. The classroom saves reading notes and progress. It does not execute Docker engine commands or receive a Docker socket.

Start with containers, images and processes. Follow the beginner sequence through a visible local build, loopback browser request and volume-preserving replacement. Continue into BuildKit, multi-stage and multi-platform builds, networking, permissions, backup/restore, resource limits, security, registries, supply-chain evidence, CI, operations and architecture.

The maintained compose-lab project is a small standard-library Python app with health, public message and persistent counter endpoints. Copy it into a new learner directory before optional host practice. Its README gives exact commands, expected observations, a peer-network check, independent restore experiment and cleanup scoped to that disposable project. The first build needs the base image; prepared runs stay local and never push. Use Bash on Linux/macOS or Ubuntu inside WSL 2 on Windows.

Evidence and authoring#

A parsed Compose file, a successful image build, an actual HTTP response and a verified restore are different observations. Record what you actually performed. The fixture inventory lists intended cases and does not manufacture runtime acceptance. Its process-local counter lock is intentionally not a replicated database design; the scaling chapter explains that limit.

Authoring instructions describe regeneration from the original chapter specifications. Preserve stable IDs, host ownership and named volumes. The course never uses a global prune as routine learner cleanup.
