llm-019: Overfit one batch to diagnose the loop#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: llm-018. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Use a deliberately tiny overfit experiment to separate implementation failure from generalization. The central investigation is concrete: Repeat one fixed batch with dropout off; compare a no-update control and a functioning loop under the same declared step cap. The finish condition is The no-update control leaves weights identical. Record the observed loss curve and first failed invariant; do not interpret memorizing this batch as held-out quality. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Use deliberate memorization to isolate the learning path#

Generalization is the eventual objective of most model development, but it is difficult to diagnose a broken training system from a complicated held-out score. A smaller question comes first: can the implementation fit a tiny batch that it sees repeatedly? This deliberately easy experiment removes many sources of variation. If it fails, we can inspect the computation and update path before spending more time on data or scale.

The batch contains one input sequence [1,2,3] and targets [2,3,4]. The decoder has enough flexible parameters to memorize these three cases. The task does not require discovering a transferable grammar. Token and position representations can help distinguish the training positions, so success on this batch is intentionally weaker than language understanding. That weakness is useful because it makes failure suspicious and the expected direction of change straightforward.

Construct two independent models, then copy the first model's state into the second. They should begin with identical numerical parameters, not simply with constructors that happened to receive similar settings. One model will train; the other will remain a control. Independence matters: assigning control=trained would create two names for the same object, so both would change together and the comparison would be meaningless.

The no-update control runs the same batch five times and preserves a cloned state dictionary. In this dropout-free decoder, with no running batch statistics, the predictions and losses remain identical. That establishes the behavior expected when no learning intervention occurs. In a different architecture, training-mode dropout could change outputs without changing weights, and running statistics could change state without an optimizer step. The control must account for the particular model's stochastic and stateful components rather than assuming no_grad makes everything fixed.

The trained model receives thirty Adam updates. Its loss curve is finite and the last recorded training loss is lower than the first. That is evidence that the implemented parameters, objective and optimizer can fit the exposed mapping. It is not evidence that every internal component is necessary: a simpler route through the parameter space may already solve three cases. It also does not show that the final post-update loss equals the last pre-update curve point, a distinction introduced in the previous chapter.

If the trained curve does not improve while the control behaves correctly, inspect the first missing link. Are targets shifted rather than copied? Does the vocabulary axis contain sixteen scores? Do expected parameters receive gradients? Does the optimizer own those parameter objects? Are gradients cleared before, rather than after, backward? Does step actually run? These questions locate a mechanism failure more directly than repeatedly changing random seeds.

Once the diagnostic passes, restore a clean experimental setup for any generalization study. The repeatedly exposed batch is training data, and the report correctly records zero held-out examples. Reusing a model already tuned on a supposed test case would compromise the next comparison. The diagnostic earns confidence in the learning path, while held-out evaluation must earn confidence in transfer.

Syntax anatomy and reasoning sequence#

Create two independent models from the same state_dict. Use dropout-free evaluation-compatible architecture so repeated control predictions are deterministic. The control calculates loss under no_grad without optimizer.step. The training loop zeros gradients and updates. Compare loss trajectories and weight snapshots, keeping the first failed invariant rather than only the final scalar.

Why overfitting one batch is a diagnostic#

The fixture uses one sequence of three input positions with targets [2, 3, 4]. A sufficiently flexible model can memorize that tiny mapping. Failing to reduce its loss is a reason to inspect target alignment, gradients, optimizer membership and the forward computation before spending resources on a large corpus. Succeeding does not demonstrate that the model learned a transferable language rule, since a position table or token lookup can help memorize three cases.

The trained model and no-update control begin with identical parameter values. Copying state into a separately constructed model preserves isolation; keeping two references to one model would not. The control snapshot clones every state tensor, so later mutation cannot silently alter the recorded before-state. The trained model takes thirty updates while the control takes none.

The current TinyDecoder has no dropout or running batch statistics, making repeated control passes deterministic under its fixed input. In a model with stochastic or stateful components, unchanged weights alone would not imply identical outputs. Set the intended evaluation mode, control randomness and inspect non-parameter state before interpreting a changing control curve. no_grad disables gradient recording but does not itself switch dropout or BatchNorm into evaluation behavior.

What a lower training loss establishes#

A finite decreasing curve and changed parameters support the claim that this optimization path can fit the repeated batch. Uniform logits over sixteen vocabulary items would give loss log⁡(16)\log(16)log(16), but the actual random model is not constrained to uniform logits, so its initial loss must be measured rather than replaced with that theoretical baseline. The loss axis must remain vocabulary, with logits [1, 3, 16] and three aligned targets.

The experiment has zero held-out examples. It cannot estimate generalization error, calibration, robustness to a new document family or useful generation behavior. A training curve and a held-out evaluation are different evidence sources. Keep the memorization experiment as a debugging fixture, then restore a clean initialization and a frozen split for the actual model comparison. Reusing a model already tuned on a supposed evaluation fixture would compromise that next experiment.

Worked example / walkthrough#

Example A: Clone the initial state#

Independent model objects avoid shared mutation. Copying the state establishes a fair starting point for the update intervention.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
torch.manual_seed(9); trained=TinyDecoder(); control=TinyDecoder(); control.load_state_dict(trained.state_dict())
assert all(torch.equal(a,b) for a,b in zip(trained.parameters(),control.parameters()))
x=torch.tensor([[1,2,3]]); y=torch.tensor([[2,3,4]])

Expected: all parameter tensors initially equal.

Example B: Run a no-update control#

Repeated execution is not training. The control demonstrates the difference without relying on log messages or an optimizer object merely existing.

import torch
from torch import nn
from torch.nn import functional as F

        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)

assert all(torch.equal(a,b) for a,b in zip(trained.parameters(),control.parameters()))
x=torch.tensor([[1,2,3]]); y=torch.tensor([[2,3,4]])
before={k:v.clone() for k,v in control.state_dict().items()}; values=[]
with torch.no_grad():
    for _ in range(5):
        z,_=control(x); values.append(F.cross_entropy(z.reshape(-1,16),y.reshape(-1)).item())
assert len(set(values))==1 and all(torch.equal(v,before[k]) for k,v in control.state_dict().items())

Expected: all losses equal; weights unchanged.

Common pitfalls and diagnosis#

Verify that control and trained models have equal initial values but independent storage. If the no-update control changes output, inspect stochastic mode and non-parameter state. If the trained path cannot memorize the tiny batch, reduce the pipeline before scaling it. If it can, retain the narrow conclusion: repeated-batch fitting without held-out evidence.
