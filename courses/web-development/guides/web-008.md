# web-008: Forms: labels, controls and successful values

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-007`

## Learning objectives

Build a study-preferences form with three native control types. Explain why form appearance cannot establish server validation. Use form, label and name accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

A form collects values for an action. A label names a control; a placeholder offers a short example and disappears during entry, so it cannot replace a label. A control's id connects it to a label. Its name identifies the value when a browser constructs form data. These are different responsibilities, and a visible input without a name may not be submitted.

Choose the native control that matches the task. A select presents a bounded choice, a textarea accepts multiline text, and checkboxes represent independent choices. A radio group represents one choice among alternatives and shares a name. A fieldset and legend describe a related group. Native controls provide interaction and accessibility behavior that a custom drawing would need to recreate.

## Syntax anatomy and mechanism

Connect `label for="topic"` with `input id="topic" name="topic"`. A button inside a form defaults to submission, so specify its type. Disabled controls are not included in submitted form data; readonly text controls can still contribute values. This offline preview prevents real submission. Inspect control values and labels without contacting a backend.

## Worked example / walkthrough

### Worked example 1: A labeled field

Identifier and submitted name have separate jobs.

```html
<label for="topic">Study topic</label><input id="topic" name="topic" value="HTML" />
```

**Expected observation:** Selecting the label focuses its associated input.

### Worked example 2: Related choices

A legend provides a group-level question.

```html
<fieldset>
  <legend>Reminder</legend>
  <label><input type="checkbox" name="reminder" />Show a reminder</label>
</fieldset>
```

**Expected observation:** The checkbox has a label and a group context.

## Six progressive exercises

Exercises that ask you to predict, explain, compare or diagnose keep their answers in the solutions file. The others show the evidence to look for.

### Exercise 1: Predict the different roles of id and name.

**Progressive hint:** Ask which attribute a label's for points to and which one becomes a key in the submitted data.

### Exercise 2: Add a textarea with a persistent label.

**Expected evidence:** The label remains available while the user types.

**Progressive hint:** Use a label element linked by for and id instead of relying on placeholder text.

### Exercise 3: Build a study-preferences form with three native control types.

**Expected evidence:** Every control has a useful label, stable name and suitable type.

**Progressive hint:** Choose one text control, one choice control and one yes-or-no control, and give each a label, name and type.

### Exercise 4: Diagnose a field missing from submitted values.

**Progressive hint:** Check the name attribute, whether the field is disabled and, for a checkbox, whether it is checked.

### Exercise 5: Navigate the form using only Tab and Space.

**Expected evidence:** Each enabled control is reachable and can be operated without a pointer.

**Progressive hint:** Put the pointer device away and operate every control in order.

### Exercise 6: Explain why form appearance cannot establish server validation.

**Progressive hint:** Imagine sending the same request from a command-line client without the form.

## Debugging and common mistakes

Do not use only placeholder text or a nearby unconnected paragraph as a label. Avoid nested forms. A control's visible value can differ from the value a server ultimately trusts.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
