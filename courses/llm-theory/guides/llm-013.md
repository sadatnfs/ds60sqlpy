# llm-013: A leakage audit before a model score

## Level and prerequisites

Beginner; approximately 105 minutes. Direct prerequisites: `llm-012`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Identify target leakage, duplicate documents and test-set reuse independently of mask correctness. The central investigation is concrete: Split a fixed corpus by source document; compare shifted labels with copying the input as its own target and introduce one duplicate document. The finish condition is Inputs [2,5,7] pair with labels [5,7,3]; document sets are disjoint and the injected duplicate is detected. Prefix invariance alone does not establish these conditions. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

### Define the prediction before judging the predictor

An experiment can be computationally correct while measuring the wrong task. A network may produce finite logits, a loss may decrease and a causal-mask test may pass, yet the labels may ask it to copy the token already visible at the same position. That is why this chapter audits the construction of prediction events before introducing a trainable decoder. The target is part of the model's scientific specification, not merely an array needed by a loss function.

Lay out the sequence [2,5,7,3] on paper. There are three next-token questions: after 2, predict 5; after [2,5], predict 7; after [2,5,7], predict 3. The batched inputs are [2,5,7] and the aligned targets are [5,7,3]. Input and target arrays have the same length, but each target is shifted one place ahead. Under this arrangement, including the attention diagonal is correct because the current input token is part of the prefix for the next token being predicted.

Now copy the input array into the targets. Every target in this fixture changes, becoming [2,5,7]. A model can solve that new task by preserving token identity instead of predicting a continuation. A triangular mask does not forbid reading the current input, so it cannot detect the objective substitution. This gives two separate checks: verify which inputs may influence a representation, and verify which event that representation is scored against.

The second boundary separates information used to fit or choose a system from information reserved to evaluate it. In the literal hash example, differently named records contain the same text alpha beta. Comparing filenames would miss the duplication; comparing hashes of the encoded text finds it. The family example catches another relationship: two different records may belong to the same known source family even if their bytes differ. Neither check subsumes the other. A hash tests equality under its input representation, while family metadata records a broader relationship supplied by the dataset design.

A vocabulary is also fitted state. If training contains alpha and beta but validation introduces gamma, evaluation should follow the declared unknown-token policy. Adding gamma to the fitted mapping during assessment changes the system being assessed. The same logic applies when using held-out answers to revise prompts, choose a confidence threshold or select a retrieval configuration. These can be useful development activities, but the reused data is no longer an untouched final assessment of the selected system.

Document boundaries determine which next-token questions exist. The two documents of lengths four and two contain three plus one internal transitions. Concatenating them creates an additional transition from the first document's last token 3 to the second document's first token 8. A separator could make such concatenation a deliberate corpus design, but silently introducing the pair changes the task. Count the expected prediction events independently of the code that builds them.

These controls are useful because they localize different failure classes. A failed shift check needs a batching repair. A family overlap needs a split or claim repair. A changed vocabulary needs a fitting-boundary repair. Improving the optimizer does not address any of them.

**Contamination:** Assessment information entering training or selection.

## Syntax anatomy and reasoning sequence

For token sequence ids, use ids[:-1] as inputs and ids[1:] as targets. Hash raw or explicitly normalized text according to a declared policy. Compare both exact hashes and known family IDs across partitions; exact hashing cannot detect paraphrases on its own. Validate disjoint groups before fitting any vocabulary or count model.

## Two different information boundaries

A causal mask constrains which input positions can influence a representation. The training objective separately specifies which target that representation must predict. For [2, 5, 7, 3], inputs [2, 5, 7] pair with targets [5, 7, 3], giving three next-token events. Copying inputs into labels creates targets [2, 5, 7] instead. The current token is visible under an ordinary causal mask, so an identity objective can appear easy while answering a different question. Mask correctness does not establish objective correctness.

Document boundaries are another part of the objective. Documents of lengths four and two contribute three plus one adjacent transitions. Concatenating them without an explicit boundary policy adds a fifth transition from the final token of the first document to the first token of the second. Whether that transition is meaningful depends on how the corpus is defined. A separator or end-of-document token is a deliberate modeling choice, not a repair that can be silently added after observing a score.

## Trace where evaluation information can enter

Exact text hashes catch byte-identical duplicates across files. They do not identify every paraphrase, translated copy, templated document or later revision. Family IDs can keep related records together when those relationships are known. The family grouping rule should reflect the deployment question: predicting another paragraph from the same document is different from generalizing to a new document source or organization.

Representation fitting also belongs to training. If a vocabulary is fitted on training words alpha and beta, the validation-only word gamma should follow the declared unknown-token policy. Adding gamma while evaluating changes the fitted representation. The same reasoning applies to learned normalization, prompt selection, deduplication thresholds and retrieval-index choices when their tuning uses held-out outcomes.

Keep a manifest of document identities, families, split assignments, normalization rules and fitted-artifact versions. Freezing that manifest before evaluation makes later changes visible. It does not prove the source data has no unknown relationship, so report the detection limits of exact hashes and available family metadata. An honest leakage audit combines known relationships and reproducible checks rather than treating one empty hash intersection as universal independence.


## Worked example / walkthrough

### Example A: Construct next-token pairs

There are three target events in a four-token sequence. The final token has no next token unless an explicit end marker is included in the original sequence.

```python
import numpy as np

ids=np.array([2,5,7,3]); inputs=ids[:-1]; labels=ids[1:]
np.testing.assert_array_equal(inputs,[2,5,7]); np.testing.assert_array_equal(labels,[5,7,3])
```

**Expected:** inputs[2,5,7],labels[5,7,3].

### Example B: Expose identity labels

A model trained to reproduce its current token is not being tested on next-token prediction. A causal mask allows the current input, so it cannot detect this objective error.

```python
import numpy as np

ids=np.array([2,5,7,3]); inputs=ids[:-1]; labels=ids[1:]
np.testing.assert_array_equal(inputs,[2,5,7]); np.testing.assert_array_equal(labels,[5,7,3])
copied=inputs.copy(); assert np.count_nonzero(copied!=labels)==3
```

**Expected:** all three copied labels differ from the target fixture.

## Common pitfalls and diagnosis

Check the objective shift before inspecting the attention mask. Then audit document boundaries, exact duplicate hashes, known family overlap and fitted preprocessing artifacts separately. A passing causal test cannot detect a target copied from its current input or a tokenizer fitted using evaluation records. Preserve the manifest that made the assessment interpretable.
