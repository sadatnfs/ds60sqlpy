# js-053: Grouped and stacked bars: totals, composition and denominators

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-052`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Build a two-series stacked chart. Choose grouped or stacked bars for subgroup comparison. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

Grouped bars support comparison of categories within several groups using a shared baseline for each bar. Stacked bars emphasize totals and composition, but interior segments do not share a common baseline. The choice depends on whether the reader needs precise subgroup comparisons or an overview of parts and whole.

A stack layout computes interval endpoints for each series in each row. The rectangle represents the distance between the lower and upper endpoints, not the upper endpoint alone. A normalized stack transforms each row to shares, which can hide differences in total magnitude.

A zero total has no meaningful fraction composition unless a policy is stated. Missing components also differ from known zeros. Preserve the original totals alongside a 100% chart so the reader can see whether a large-looking share represents two observations or two million.

## Syntax anatomy and mechanism

`d3.stack().keys(['a','b'])` reads the named components from each record and returns one series for each key. A point is `[lower, upper]` and retains its original row in `.data`. Use y(lower)-y(upper) for positive vertical height.

`stackOffsetExpand` normalizes each row to unit total when appropriate. Validate finite nonnegative components for this introductory positive stack. Signed values need a different design, such as a diverging stack with explicit positive and negative baselines.

## Worked example / walkthrough

### Worked example 1: Read stack endpoints

The second component begins where the first ends.

```javascript
const series = d3.stack().keys(["a", "b"])([{ group: "X", a: 2, b: 3 }]);
console.log(series[0][0].slice(), series[1][0].slice());
```

**Expected observation:** [0, 2] and [2, 5].

### Worked example 2: Compare counts and shares

The same share can represent different totals.

```javascript
const rows = [
  { a: 2, b: 3 },
  { a: 20, b: 30 },
];
console.log(rows.map((d) => d.a / (d.a + d.b)));
```

**Expected observation:** 0.4 and 0.4 despite totals 5 and 50.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose using upper endpoint as segment height. Its distinguishing evidence is Later segments are exaggerated because the lower endpoint was ignored. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
