# c-021: Linked lists and mutation-safe traversal

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-020`

## Learning objectives

Implement the six investigations, from the "insert at the head" case to the "transfer double-reversal reasoning" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A linked list stores each element in a node that points to the next node. It can insert at the head without moving all existing elements, but each allocation and pointer chase has a cost. The head pointer is part of the mutable structure, so a function changing it often receives a pointer to that pointer. Every node has one release responsibility. When deleting during traversal, save the next pointer before freeing the current node; reading current->next afterward would use an expired object. Lists are useful when their mutation pattern fits the problem, not simply because pointers make them possible.

## Vocabulary and concepts

- **Node:** An element plus linkage to another element.
- **Head pointer:** The entry point to a linked structure.
- **Mutation invariant:** A structural property preserved while links are changed.

## Syntax anatomy and execution trace

struct Node contains a value and next pointer. push_front allocates first and changes the head only after success. A Node **head lets the helper update the caller head. Iterative destruction retains next before free and resets the head afterward. Reverse uses previous, current and next pointers, maintaining a processed-prefix invariant without new allocations.

## Worked example / walkthrough

### Worked example 1: Insert at the head

Push 1 and then 2.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Node {
  int value;
  struct Node *next;
};
bool push_front(struct Node **head, int value) {
  struct Node *node = malloc(sizeof *node);
  if (node == NULL)
    return false;
  node->value = value;
  node->next = *head;
  *head = node;
  return true;
}
size_t list_length(const struct Node *head) {
  size_t n = 0;
  for (const struct Node *p = head; p != NULL; p = p->next)
    n++;
  return n;
}
void destroy_list(struct Node **head) {
  struct Node *p = *head;
  while (p != NULL) {
    struct Node *next = p->next;
    free(p);
    p = next;
  }
  *head = NULL;
}
void reverse_list(struct Node **head) {
  struct Node *previous = NULL, *current = *head;
  while (current != NULL) {
    struct Node *next = current->next;
    current->next = previous;
    previous = current;
    current = next;
  }
  *head = previous;
}

int main(void) {
  /* Insert at the head */
  {
    struct Node *head = NULL;
    CHECK(push_front(&head, 1) && push_front(&head, 2));
    CHECK(head->value == 2 && head->next->value == 1);
    destroy_list(&head);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The list order is 2 then 1.

Head insertion reverses arrival order. If FIFO order is required, a tail pointer or different structure is needed.

### Worked example 2: Count a constructed list

Push three values and count nodes.

```c

#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

    n++;
  return n;
}

  while (p != NULL) {

    free(p);
    p = next;
  }

  struct Node *previous = NULL, *current = *head;

    struct Node *next = current->next;
    current->next = previous;
    previous = current;

  }

int main(void) {
  /* Insert at the head */
  {
    struct Node *head = NULL;
    CHECK(push_front(&head, 1) && push_front(&head, 2));
    CHECK(head->value == 2 && head->next->value == 1);
    destroy_list(&head);
  }

  /* Count a constructed list */
  {
    struct Node *head = NULL;
    for (int i = 0; i < 3; i++)
      CHECK(push_front(&head, i));
    CHECK(list_length(head) == 3);
    destroy_list(&head);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The length is 3.

The traversal stops at NULL and does not assume nodes occupy adjacent addresses.

### Exercise 3: Handle an empty list

Measure and destroy a null head.

**Expected:** Length is zero and head stays NULL.

**Verify:** Keep a CHECK equivalent to `head == NULL`. Control edit: `CHECK(head != NULL);` must fail; then restore it.

**Progressive hints:** First trace `head` from initialization. Then recall: An empty structure should have natural operations without a fabricated sentinel payload.

### Exercise 4: Reverse without reallocating

Build 3, 2, 1 and reverse it.

**Expected:** The order becomes 1, 2, 3.

**Verify:** Keep a CHECK equivalent to `head->value == 1 && head->next->value == 2 && head->next->next->value == 3`. Control edit: `CHECK(push_front(&head, 2) && push_front(&head, 2) && push_front(&head, 3));` must fail; then restore it.

**Progressive hints:** First trace `head` from initialization. Then recall: Saving next before rewiring preserves access to the unprocessed suffix.

### Exercise 5: Reverse a singleton

Reverse a one-node list.

**Expected:** Its value and terminating link are preserved.

**Verify:** Keep a CHECK equivalent to `head->value == 7 && head->next == NULL`. Control edit: `CHECK(push_front(&head, 8));` must fail; then restore it.

**Progressive hints:** First trace `head` from initialization. Then recall: The smallest nonempty structure checks the initial and final link conditions.

### Exercise 6: Transfer double-reversal reasoning

Reverse a two-node list twice.

**Expected:** Its original order is restored.

**Verify:** Keep a CHECK equivalent to `head->value == 2 && head->next->value == 1`. Control edit: `CHECK(push_front(&head, 2) && push_front(&head, 2));` must fail; then restore it.

**Progressive hints:** First trace `head` from initialization. Then recall: This involution property complements exact order tests.

## Common pitfalls and diagnosis

Advancing with `node = node->next` after `free(node)` reads freed memory; save `next` first. Losing the head pointer partway through a reversal leaks the rest of the list, so publish the new head only at the end.
