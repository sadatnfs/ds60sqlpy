# clp-002: Reduction and weight contracts

Tutorial mode. Stage: beginner. Direct prerequisites: `clp-001`.

## A reduction is part of the model contract

Parallel computation often changes a correct formula accidentally. One worker returns the average loss for two observations, another returns the average for two thousand, and a driver averages those two numbers. The resulting objective gives equal influence to workers instead of observations. More machines cannot correct that mistake. We therefore carry a numerator and a denominator explicitly and state what each weight represents.

Let \(\ell_i(\theta)\) be a row NLL and \(w_i\geq0\) a fixed weight. Three distinct objectives are

\[
S(\theta)=\sum_i w_i\ell_i(\theta),\qquad
\overline L_w(\theta)=\frac{S(\theta)}{\sum_iw_i},\qquad
\overline L_n(\theta)=\frac{S(\theta)}{n}.
\]

The last two denominators answer different questions. If weights are fixed and positive total mass is guaranteed, multiplying the whole unpenalized objective by a constant leaves its optimizer unchanged. It changes gradient magnitudes, stopping criteria, learning-rate behavior and Hessian-based uncertainty calculations. Once a penalty is added, rescaling only the data term can also change the optimum.

Frequency weights represent replication. Reliability or sampling weights do not automatically have that interpretation. A weighted estimating equation can be useful without the weighted sum being the log-likelihood of the actual sampling experiment. In particular, inverse-probability weighting usually requires a sampling-aware variance calculation, not a mechanical inverse weighted Hessian.

## Worked case 1: a denominator with an independently calculable answer

The program uses a fixed-scale Gaussian residual loss with constants omitted:

\[
\ell_i(\mu)=\tfrac12(y_i-\mu)^2,\quad
\frac{\partial\overline L_w}{\partial\mu}=
\frac{\sum_iw_i(\mu-y_i)}{\sum_iw_i}.
\]

For \(y=(0,2,4,8,10)\), \(w=(1,1,2,1,3)\) and \(\mu=3\), the weighted numerator is 92 and the weight mass is 8. The weighted mean loss is 11.5 and its derivative is -3. These numbers can be calculated with pencil and paper, so they serve as an oracle independent of Torch's reduction implementation. The loss retains parameter-dependent terms only because the fixed Gaussian scale is not estimated in this chapter.

Split after the second row. The first shard has numerator 5 and mass 2, while the second has numerator 87 and mass 6. Averaging their means gives \((2.5+14.5)/2=8.5\), which is wrong for the declared observation-weighted objective. Adding numerators and masses first gives \((5+87)/(2+6)=11.5\), regardless of this partitioning choice.

## Worked case 2: replicate the weighting measure

Multiply all weights by seven. The weighted mean and its gradient remain unchanged because both numerator and denominator scale by seven. The weighted sum becomes seven times larger. If integer weights mean independent replicated observations, the sum represents more information and its curvature increases accordingly. If weights are merely normalized importance weights, multiplying them by seven has not collected new data. The same arithmetic operation therefore has different inferential consequences depending on the meaning of the weights.

For partition \(p\), return \((S_p,M_p)\), where \(M_p=\sum_{i\in p}w_i\). A globally normalized gradient is \(\sum_p\nabla S_p/\sum_pM_p\). Never average already normalized local gradients without their masses. An empty shard can contribute zero numerator and zero mass, but a globally empty or zero-weight dataset must fail explicitly before division.

## Debugging and uncertainty

Check that weights and outcomes have identical shape, finite values and nonnegative weights, with at least one positive weight. Do not rely on broadcasting to repair a missing dimension: an \((n,1)\) residual times an \((n,)\) weight can silently become an \((n,n)\) matrix. Keep weights independent of parameters in this derivation. If weights depend on \(\theta\), differentiating only the numerator is incomplete because the denominator may also depend on \(\theta\).

Floating-point summation is not associative. A different partition order can change the last few bits even when the mathematics is correct. Compare with a tolerance appropriate to scale and precision, and distinguish tiny summation differences from the large denominator error above. This program does serial shard arithmetic and provides no distributed throughput measurement.

## Answered review questions

**Can I use a mean loss during optimization and a sum Hessian afterward?** Yes, if both represent the same declared likelihood and you rescale consistently. For \(n\) independent rows, the sum Hessian is \(n\) times the mean Hessian. Inverting the mean Hessian without that correction overstates variance by a factor of \(n\).

**Does equal weighting of groups ever make sense?** Yes, if the estimand deliberately weights groups equally. That is a different objective and must be named. Unequal group sizes alone do not justify changing the target silently.

**What must a reusable distributed likelihood interface return?** Loss numerator, gradient numerator, weight or observation mass, and diagnostics about rejected rows and complete independent units. A bare scalar named `loss` is too ambiguous for safe aggregation.

## Complete reproducible program

Run this complete source in the separately prepared `llm-torch-cpu` pad. It uses float64 CPU tensors and tiny original offline fixtures. Each execution starts fresh. Save edited source and notes with classroom controls. There is no exam or hidden solution, and execution is not scientific model acceptance. Runtime: `llm-torch-cpu`.

```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def weighted_loss(mu, observations, weights):
    y, w, mu = tensor(observations), tensor(weights), tensor(mu)
    if y.ndim != 1 or not len(y) or y.shape != w.shape:
        raise ValueError("One weight is required for each observation")
    if (
        not bool(torch.isfinite(y).all() & torch.isfinite(w).all())
        or bool((w < 0).any())
        or float(w.sum()) <= 0
    ):
        raise ValueError("Use finite observations and nonnegative positive-mass weights")
    numerator = (w * (y - mu).square() / 2).sum()
    return numerator, w.sum()


def run_cases():
    y, weights = tensor([0, 2, 4, 8, 10]), tensor([1, 1, 2, 1, 3])
    mu = tensor(3.0).requires_grad_()
    total, mass = weighted_loss(mu, y, weights)
    mean = total / mass
    a, wa = weighted_loss(mu, y[:2], weights[:2])
    b, wb = weighted_loss(mu, y[2:], weights[2:])
    wrong = (a / wa + b / wb) / 2
    right = (a + b) / (wa + wb)
    gradient = torch.autograd.grad(mean, mu)[0]
    assert float(total.detach()) == 92 and float(mass) == 8
    assert float(mean.detach()) == 11.5 and float(wrong.detach()) == 8.5
    assert torch.allclose(mean, right) and float(gradient) == -3
    scaled, scaled_mass = weighted_loss(mu, y, 7 * weights)
    assert torch.allclose(scaled / scaled_mass, mean)
    assert torch.allclose(scaled, 7 * total)
    return {
        "weighted_sum": float(total.detach()),
        "weight_mass": float(mass),
        "weighted_mean": float(mean.detach()),
        "wrong_equal_partition_mean": float(wrong.detach()),
        "global_mean_gradient": float(gradient),
        "frequency_weight_sum_changes_with_replication": True,
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
