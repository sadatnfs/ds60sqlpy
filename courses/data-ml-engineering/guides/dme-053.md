## Preserve meaning while changing representation

A migration changes how a system stores or serves information while preserving an explicitly chosen contract. Moving CSV to Parquet can improve typed access and analytical interoperability, but the format change does not automatically preserve identifiers, units, missing values or consumer behavior. The migration needs a canonical comparison and an acceptance boundary before consumers switch.

This capstone converts an actual CSV file into actual Parquet. The old representation stores an order identity and a decimal USD amount as text. The new representation stores the identity as a string, an integer amount in minor currency units and an explicit currency field. Both readers produce the same canonical records for comparison. The accepted pointer changes only after those records agree exactly.

The fixture is small enough that every value can be checked independently. Order `001` has USD 1.99 and order `010` has USD 2.50. The canonical total is 449 cents. Leading zeros belong to the identifier contract, so `001` is not interchangeable with `1`. The source field name `amount_usd` establishes the old currency meaning; adding `currency: USD` in the new representation makes existing knowledge explicit rather than inventing missing business information.

## Define a canonical comparison

A canonical representation is a reviewed form used to compare old and new interpretations. It should preserve all information relevant to the contract, not merely make two outputs look similar. Here each row has `order_id`, `amount_minor` and `currency`, sorted by order identity for deterministic comparison. Sorting changes presentation order without changing the logical relation.

The old reader uses `Decimal` to parse currency text and multiplies by 100:

\[
\mathrm{amount}_{\mathrm{minor}}=100\times\mathrm{amount}_{\mathrm{USD}}.
\]

It requires a finite, nonnegative, integral result in minor units. This rejects values that cannot be represented under the declared cent contract rather than silently rounding them. The reader also checks the exact source fields, nonblank identities and unique order grain. A numeric-looking identity remains text throughout.

The Parquet writer uses an explicit Arrow schema with string identity, 64-bit integer minor amount and string currency. The new reader verifies that physical schema and rejects duplicate identities. Activation compares the full canonical record lists, then records the candidate's content digest, source digest and row count in the accepted manifest. Equality of one aggregate does not replace equality of the declared records.

## Worked case 1: compatible readers before and after cutover

`example_one()` creates the old CSV and an accepted pointer naming that file and its digest. The old reader returns order 001 with 199 cents and order 010 with 250 cents, both in USD. The program writes those canonical rows into a new Parquet candidate, reads it back and compares the complete records with the old source interpretation.

After the comparison succeeds, activation atomically replaces the local pointer with a manifest for the Parquet candidate. Reading through the accepted pointer now uses the new reader, but its canonical result still equals the old reader's result. The original CSV remains present and readable. This permits coexistence and gives the learner concrete evidence that changing representation did not change the reviewed business records.

The program verifies the exact identifier list and total 449. Both checks matter. The record-level equality includes currency and values, while the total is an additional easily explained diagnostic. A migration report should show enough detail to distinguish a missing row, duplicated row, changed identity and changed unit, rather than reducing every discrepancy to one number.

## Worked case 2: equal totals conceal damaged identifiers

The second case creates a candidate that converts each identifier to an integer and then back to text. The resulting IDs are `1` and `10`, while the monetary values remain 199 and 250. The candidate's total is still 449, and its Parquet schema is valid. A checksum of that candidate would also be internally consistent with its own bytes.

Activation rejects the candidate because the canonical records differ from the source. The accepted pointer remains byte-for-byte unchanged and continues to serve the original identifiers. This is a semantic migration failure even though serialization, parsing and aggregation all succeeded. A downstream join expecting `001` could fail or match a different namespace if the damaged candidate were accepted.

The changed condition is intentionally subtle. Many data tools infer numeric types from identifier-like columns unless the author declares the schema. Treat identifiers as values in a namespace with explicit formatting rules, not as arithmetic quantities merely because their characters are digits. A migration should preserve that namespace unless a separate reviewed identity-mapping change is part of its scope.

## Complete worked program

Use data-engineering. CSV parsing, Decimal conversion, Arrow schema validation and Parquet readback all execute locally. The program changes only an owned temporary accepted pointer and retains the old source file during the demonstration.

```python
"""Actual CSV-to-Parquet migration reconciles identities and minor currency units before cutover."""

import csv
import hashlib
import json
import tempfile
from decimal import Decimal
from pathlib import Path

import pyarrow as pa
import pyarrow.parquet as pq

SCHEMA = pa.schema(
    [("order_id", pa.string()), ("amount_minor", pa.int64()), ("currency", pa.string())]
)


def old_reader(path):
    with path.open(newline="") as handle:
        reader = csv.DictReader(handle)
        if (
            reader.fieldnames is None
            or set(reader.fieldnames) != {"order_id", "amount_usd"}
            or len(reader.fieldnames) != 2
        ):
            raise ValueError("Old CSV schema differs from its reviewed contract")
        rows = list(reader)
    canonical = []
    for row in rows:
        if (
            set(row) != {"order_id", "amount_usd"}
            or not row["order_id"]
            or row["order_id"] != row["order_id"].strip()
        ):
            raise ValueError("Old record identity or field population is invalid")
        amount = Decimal(row["amount_usd"]) * 100
        if not amount.is_finite() or amount != amount.to_integral_value() or amount < 0:
            raise ValueError("Old contract requires nonnegative exact USD cents")
        canonical.append(
            {"order_id": row["order_id"], "amount_minor": int(amount), "currency": "USD"}
        )
    if len({row["order_id"] for row in canonical}) != len(canonical):
        raise ValueError("Old table has duplicated order identity")
    return sorted(canonical, key=lambda row: row["order_id"])


def candidate(root, name, rows):
    if not name.isalnum():
        raise ValueError("Candidate name must be a simple owned identifier")
    path = root / (name + ".parquet")
    if path.exists():
        raise ValueError("Candidate files are immutable")
    pq.write_table(pa.Table.from_pylist(rows, schema=SCHEMA), path)
    return path


def new_reader(path):
    table = pq.read_table(path)
    if table.schema != SCHEMA:
        raise ValueError("New physical schema differs from the reviewed contract")
    result = sorted(table.to_pylist(), key=lambda row: row["order_id"])
    if len({row["order_id"] for row in result}) != len(result):
        raise ValueError("New table has duplicated order identity")
    return result


def activate(root, source, candidate_path):
    original, proposed = old_reader(source), new_reader(candidate_path)
    if original != proposed:
        raise ValueError("Candidate differs in row identity, value or currency")
    manifest = {
        "kind": "parquet",
        "file": candidate_path.name,
        "sha256": hashlib.sha256(candidate_path.read_bytes()).hexdigest(),
        "source_sha256": hashlib.sha256(source.read_bytes()).hexdigest(),
        "rows": len(proposed),
    }
    pending = root / "current.pending"
    pending.write_text(json.dumps(manifest, sort_keys=True))
    pending.replace(root / "current.json")
    return proposed


def fixture(root):
    path = root / "orders.csv"
    path.write_text("order_id,amount_usd\n001,1.99\n010,2.50\n")
    (root / "current.json").write_text(
        json.dumps(
            {
                "kind": "csv",
                "file": path.name,
                "sha256": hashlib.sha256(path.read_bytes()).hexdigest(),
            }
        )
    )
    return path


def accepted(root):
    manifest = json.loads((root / "current.json").read_text())
    if Path(manifest["file"]).name != manifest["file"]:
        raise ValueError("Accepted file must be an owned basename")
    path = root / manifest["file"]
    if hashlib.sha256(path.read_bytes()).hexdigest() != manifest["sha256"]:
        raise ValueError("Accepted artifact changed")
    if manifest["kind"] == "csv":
        return old_reader(path)
    if manifest["kind"] == "parquet":
        return new_reader(path)
    raise ValueError("Unknown reader contract")


def example_one():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        source = fixture(root)
        original = accepted(root)
        path = candidate(root, "reviewed", original)
        activate(root, source, path)
        assert accepted(root) == old_reader(source) == original
        assert [row["order_id"] for row in original] == ["001", "010"]
        assert sum(row["amount_minor"] for row in original) == 449
        return {
            "old_and_new_canonical_rows": original,
            "exact_total_minor_units": 449,
            "leading_zero_identities_preserved": True,
            "accepted_format": "parquet",
        }


def example_two():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        source = fixture(root)
        original = accepted(root)
        before = (root / "current.json").read_bytes()
        wrong = [{**row, "order_id": str(int(row["order_id"]))} for row in original]
        path = candidate(root, "lostidentity", wrong)
        assert sum(row["amount_minor"] for row in new_reader(path)) == 449
        try:
            activate(root, source, path)
        except ValueError:
            pass
        else:
            raise AssertionError("Equal totals hid changed order identities")
        assert (root / "current.json").read_bytes() == before and accepted(root) == original
        return {
            "candidate_total_still_449": True,
            "candidate_ids": [row["order_id"] for row in wrong],
            "accepted_ids": [row["order_id"] for row in original],
            "cutover_rejected": True,
        }


def main():
    print("Compatible dual readers with exact currency units:", example_one())
    print("Aggregate equality does not establish migration correctness:", example_two())


if __name__ == "__main__":
    main()
```

## Compare more than the happy-path sample

A real migration needs representative edge cases: nulls, empty strings, maximum values, non-ASCII text, time zones, duplicate keys, unusual identifiers and values near precision limits. The selected canonical representation should make those differences visible. Converting every value to a string may make display comparison easier while hiding type changes that matter to consumers.

For timestamps, specify whether the contract preserves an instant, a local wall time, a timezone label or a calendar date. For decimals, specify scale, rounding and currency. For arrays and nested records, define ordering and missing-field behavior. For floating-point computations, decide where numeric tolerance is justified; do not apply a broad tolerance to identifiers, row counts or exact monetary units.

The previous schema-evolution chapter covers additive and required-field compatibility. This capstone adds controlled cutover between two actual storage representations. A larger migration may require both concerns at once, but changing several meanings simultaneously makes reconciliation harder. Separate independent changes where practical so a discrepancy has a smaller set of possible causes.

## Plan coexistence and rollback

During coexistence, identify which writer is authoritative and how updates reach both representations. A one-time conversion is insufficient if the old system continues to accept new data while the candidate is being validated. A production cutover may need a captured source position, incremental catch-up or a bounded write pause. The exact mechanism depends on the source and target systems.

The program's source is a fixed complete file, so no concurrent catch-up is needed. Its single-publisher local pointer is not a distributed catalog transaction. The full data-product project and actual table-format workshops provide richer publication boundaries. Preserve the distinction rather than describing a temporary-file replacement as a complete enterprise migration procedure.

Rollback should preserve a compatible accepted version and its source interpretation. Deleting the old files immediately after one successful read removes a useful recovery option. Conversely, retaining old copies indefinitely can conflict with retention policy. Define the support window, consumer transition evidence and cleanup process explicitly.

## Failure diagnosis and answered interview discussion

If totals match but consumers break, compare identities, types, units and response shape. If only some rows fail, inspect edge-case parsing and null conventions. If repeated migration runs duplicate records, inspect output file inventory and publication identity. If old and new readers disagree only after cutover, inspect whether they actually read the same source version or whether updates continued during preparation.

An interviewer may ask, “How do you validate a format migration?” Explain canonical record comparison, independent population checks, representative edge cases and consumer readback. If asked why not compare checksums of CSV and Parquet, explain that different representations have different bytes even when their meaning is equivalent. If asked why a matching total is insufficient, use the leading-zero identity failure from this case.

For an answered extension, change the new candidate's currency to EUR while leaving its integer values and total unchanged. Canonical equality must reject it because 449 minor units in one currency is not the same contract as 449 in another. A type-compatible value can still be semantically incompatible.
