c-014: Parsing numbers with complete error evidence#

Level and prerequisites#

Beginner, approximately 90 minutes plus a later retrieval session. Direct prerequisites: c-013

Learning objectives#

Explain end pointer, range error, whole-string contract. Implement the six investigations with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

Purpose and mental model#

External text must be parsed under an explicit grammar and range policy. atoi cannot report all useful failure distinctions, so robust code often uses strtol with an end pointer and errno. Parsing can consume no digits, stop before trailing garbage, or overflow the target type. A long result may still fail to fit an int even when strtol itself succeeded. Reset errno before the call and inspect it afterward. Define whitespace and sign rules deliberately. Preserve the output on failure so a caller cannot mistake a partial or stale result for a successful parse.

Vocabulary and concepts#

  • End pointer: The location immediately after the parsed numeric prefix.
  • Range error: A value outside the representation accepted by the parser or target type.
  • Whole-string contract: A rule requiring all input text to belong to one valid value.

Syntax anatomy and execution trace#

strtol(text,&end,10) parses base-ten text and stores where parsing stopped. end==text means no digits were consumed. errno==ERANGE reports range failure for long. Require *end=='\0' for this lesson's whole-string contract, then compare against INT_MIN and INT_MAX before converting. This helper accepts strtol leading whitespace and signs, but rejects trailing whitespace or other trailing text; a different user-facing policy should normalize explicitly before parsing.

Worked example / walkthrough#

Worked example 1: Parse a complete integer#

Parse 42 into an output integer.

#include <assert.h>
#include <errno.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

bool parse_int(const char *text, int *out) {
  if (text == NULL || out == NULL)
    return false;
  errno = 0;
  char *end = NULL;
  long value = strtol(text, &end, 10);
  if (end == text || *end != '\0' || errno == ERANGE || value < INT_MIN ||
      value > INT_MAX)
    return false;
  *out = (int)value;
  return true;
}

int main(void) {
  /* Parse a complete integer */
  {
    int out = 0;
    CHECK(parse_int("42", &out) && out == 42);
  }
  puts("Worked example checks passed.");
  return 0;
}

Observe: Success is true and output is 42.

The parser validates complete consumption and final target range before assignment.

Worked example 2: Reject trailing garbage#

Parse 42x with an existing output of 7.

  if (text == NULL || out == NULL)
    return false;

  long value = strtol(text, &end, 10);
  if (end == text || *end != '\0' || errno == ERANGE || value < INT_MIN ||
      value > INT_MAX)

int main(void) {
  /* Parse a complete integer */
  {
    int out = 0;
    CHECK(parse_int("42", &out) && out == 42);
  }

  /* Reject trailing garbage */
  {
    int out = 7;
    CHECK(!parse_int("42x", &out) && out == 7);
  }
  puts("Worked example checks passed.");
  return 0;
}

Observe: The call fails and output remains 7.

A valid prefix is not a valid complete input under this contract.

Common pitfalls and diagnosis#

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
