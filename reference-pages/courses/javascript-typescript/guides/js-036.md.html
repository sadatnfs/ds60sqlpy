js-036: Package design and reproducible toolchains#

Level and prerequisites#

Advanced, approximately 120 minutes. Direct prerequisites: js-035

Learning objectives#

Explain exports map, dependency lock, engine declaration, content identity with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. The first investigation is: Create a package with exports pointing at index.mjs and import its version value. The final task tests preserve a versioned behavior contract.

Purpose and mental model#

A package is a public interface plus the files and metadata needed to implement it. The exports map declares supported entry points. Consumers importing an undeclared internal path receive a loader error, even if a file exists on disk. This helps maintain an API boundary but is not filesystem access control for a hostile process with direct disk access.

A package version and an engine declaration communicate compatibility expectations. They do not prove the implementation obeys semantic-versioning conventions, and Node's module loader does not automatically enforce every package engines field. A tested runtime contract must check the actual executable and supported behavior. A breaking change can be behavioral even if TypeScript signatures or exported function names remain unchanged.

Reproducible preparation needs more than a top-level version range. Lockfiles record resolved dependency versions and integrity information; the package manager version, platform-specific dependencies, runtime, installation flags and build inputs can still matter. npm ci is the usual strict lockfile installation route, but this default lesson does not install dependencies or run lifecycle scripts. Its fixtures are small authored packages under an owned temporary node_modules directory so resolution can be observed offline.

The examples create a public entry, an explicit subpath and a private implementation file, then run real Node imports. A SHA-256 manifest demonstrates content identity and detects an intentional local modification. A hash proves equality to an expected byte sequence, not trustworthiness, licensing or correctness. Keep source identity, dependency resolution and runtime behavior as separate pieces of release evidence.

Vocabulary and concepts#

Exports map: The declared package entry and subpath interface.

Dependency lock: A record of resolved dependency artifacts and metadata.

Engine declaration: Package metadata describing an intended runtime requirement.

Content identity: A digest tying evidence to exact file bytes.

How to run this lesson#

Use the prepared Node 24.22.1 profile. The classroom saves an ES module as main.mjs and executes it with Node. Only built-in Node or ECMAScript APIs are used. For a prepared native environment, node main.mjs is the same command on PowerShell and POSIX. Browser APIs have separate host requirements.

Save your own learner copy under ignored .learning/expansion/js-036/ or use a saved classroom pad. Record predictions before execution. Each worked program includes its helper definitions. The reference puts the six exercises in separate scopes, so a task cannot silently rely on a variable from a previous task. A successful assertion is silent; the final JSON receipt reports how many exercise blocks completed. A failing assertion must produce a failed process, not a generic success message.

Optional project preparation#

In a real learner-owned package, review package.json and the lockfile together, record the intended Node and npm versions, and run the documented locked installation during explicit connected setup. npm ci --ignore-scripts --no-audit --no-fund is a useful starting policy when lifecycle scripts are unnecessary; some packages require reviewed build steps, so skipping scripts is not a universal guarantee that installation is complete. Offline reuse needs a complete compatible cache or prepared image. This chapter performs no npm install or npm ci and does not claim those optional project steps were executed.

Syntax anatomy and execution trace#

package.json type:module selects ESM for .js files in its package scope, while .mjs is explicit independently. exports maps package entry and subpath names to intended files. Bare package imports resolve from the importing module's location. A child main.mjs in the temporary project imports the authored package through node_modules, exercising the real loader. The helper captures exit status and stderr, cleans up its directory and never runs a shell or package installation.

Worked example / walkthrough#

Example A: Import the public package entry#

The import uses normal package-name resolution from the temporary main module. It does not bypass the exports map with an absolute file URL.

import { strict as assert } from 'node:assert';
import { mkdtemp, mkdir, writeFile, readFile, rm } from 'node:fs/promises';
import { writeFileSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { spawnSync } from 'node:child_process';
import { createHash } from 'node:crypto';

async function withPackage(use) {
  const directory = await mkdtemp(join(tmpdir(), 'course-package-'));
  try {
    const folder = join(directory, 'node_modules/course-fixture');
    await mkdir(folder, { recursive: true });
    await writeFile(join(folder, 'package.json'), JSON.stringify({ name: 'course-fixture', version: '1.0.0', type: 'module', engines: { node: '>=99' }, exports: { '.': './index.mjs', './math': './math.mjs' } }));
    await writeFile(join(folder, 'index.mjs'), 'export const version = 1;');
    await writeFile(join(folder, 'math.mjs'), 'export const twice = value => value * 2;');
    await writeFile(join(folder, 'private.mjs'), 'export const internal = true;');
    return await use(directory);
  } finally { await rm(directory, { recursive: true, force: true }); }
}
function runImport(directory, source) {
  const path = join(directory, 'main.mjs');
  writeFileSync(path, source);
  const result = spawnSync(process.execPath, [path], { encoding: 'utf8', timeout: 10000, maxBuffer: 1024 * 1024 });
  if (result.error) throw result.error;
  if (result.signal) throw new Error(`child terminated by ${result.signal}`);
  return result;
}
function digest(bytes) { return createHash('sha256').update(bytes).digest('hex'); }

export async function verify() {
  // Worked example
  {
    await withPackage(async directory => {
      const result = runImport(directory, 'import { version } from \'course-fixture\'; console.log(version);');
      assert.equal(result.status, 0, result.stderr);
      assert.equal(result.stdout.trim(), '1');
    });
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));

Expected: actual child prints 1.

Prediction before your attempt#

Trace the entry point and identify the values that exist before each operation. Distinguish a value from a reference to an object, a returned Promise from its eventual result, and a compile-time type from a runtime check. Write down the first observation that would disprove your explanation. A useful prediction includes an expected value or failure category, not merely a claim that the program should work.

For a loop, write the state before and after one iteration. For a callback, identify the caller and the arguments it supplies. For an asynchronous operation, identify who starts it, who awaits it, and who owns cleanup. These small traces make failures local: you can compare the first incorrect state instead of guessing from a much later symptom.

Exercises#

  1. Import the public package entry. Create a package with exports pointing at index.mjs and import its version value. Expected: actual child prints 1. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Use an explicitly exported subpath. Import twice from course-fixture/math. Expected: actual child prints 6. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Reject an undeclared private path. Attempt a package-name import of private.mjs even though the file exists. Expected: nonzero child status with ERR_PACKAGE_PATH_NOT_EXPORTED. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Observe that engines is metadata rather than a loader gate. Read the fixture engine declaration requiring Node99, then import its entry with the actual runtime. Expected: metadata says >=99; ordinary import still succeeds. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Detect exact source tampering through a digest. Hash the public source, change only that owned file, and compare hashes. Expected: digest changes after modification. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Preserve a versioned behavior contract. Import the arithmetic subpath and assert both a normal and a boundary input in the child. Expected: child exits successfully for twice(0)=0 and twice(-2)=-4. Verify: Record the observed value, exception or browser state and compare it with that expectation.

Common pitfalls and diagnosis#

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.

Progressive hints#

Start by comparing the actual value with the literal expected result. Next, isolate the expression that transforms it or the boundary where its type or ownership changes. If the discrepancy involves scheduling, replace unrelated work with a small trace array and await the exact completion you intend to observe. Finally, ask for one hint about the first incorrect assumption before opening the reference. Keep one controlled failure that would catch the same mistake returning.
