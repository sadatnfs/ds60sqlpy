## The question and the mechanism

Align actuals with a monthly category budget without copying a whole-month target into a daily metric.

Budget is recorded at month/category grain, while Sales is recorded at order-line grain. A daily product-level query does not automatically have a comparable target. Relating a monthly budget to an arbitrary date key can make it appear only on one day; copying the entire monthly value into every day can multiply it. The model must state the intended temporal and category mapping.

The analytical fixture leaves Budget disconnected and transfers selected MonthKey and Category values explicitly with TREATAS. For January Paper, actual revenue is 47 and budget is 60, so the variance is-13. The reference permits that comparison only when the selected Date population is the complete single calendar month.

On January 2 alone, actual Paper revenue is 27. The monthly budget 60 is not a daily target, so the guarded measure returns BLANK rather than an invented variance. A genuine daily allocation needs an explicit weighting policy whose allocated values reconcile to the original monthly amount. Uniform, working-day and forecast-weighted allocation are different business choices.

## Vocabulary and expression anatomy

HASONEVALUE and the date-row count form this fixture's single-complete-month guard. DAY(EOMONTH(...)) gives the calendar month length. TREATAS maps the retained month and category sets to the disconnected Budget columns. The guard is a documented comparison policy, not a universal pattern for every fiscal calendar.

Concepts to explain in your own words: **monthly budget**, **grain mismatch**, **TREATAS**, **full-period guard**, **allocation**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: A comparable full-month category

**Starting context:** FullJanuary 2025 and Paper category; Budget is monthly/category-grained and disconnected.

```dax
EVALUATE CALCULATETABLE ( VAR FullMonth = HASONEVALUE ( 'Date'[MonthKey] ) && COUNTROWS ( VALUES ( 'Date'[Date] ) ) = DAY ( EOMONTH ( MAX ( 'Date'[Date] ), 0 ) ) VAR Target = IF ( FullMonth, CALCULATE ( SUM ( Budget[Amount] ), TREATAS ( VALUES ( 'Date'[MonthKey] ), Budget[MonthKey] ), TREATAS ( VALUES ( Product[Category] ), Budget[Category] ) ) ) RETURN ROW ( "Actual", [NetRevenue], "ComparableBudget", Target, "Variance", IF ( NOT ISBLANK ( Target ), [NetRevenue] - Target ) ), 'Date'[Year] = 2025, 'Date'[MonthNumber] = 1, Product[Category] = "Paper" )
```

**Context trace:**

1. January has 31 selected dates, satisfying the complete single-month guard.
2. Paper actuals are S 4 and S 5:27 +20 =47.
3. The mapped budget is 60, so actual minus budget is-13.

**Hand-derived worked-reference result:**

| Actual | ComparableBudget | Variance |
| --- | --- | --- |
| 47 | 60 | -13 |

The sign convention is part of the metric: here negative means below the revenue target, not necessarily a generic unfavorable variance for every account type.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: A daily selection is not assigned the monthly target

**Starting context:** One observed day in January 2025; no daily budget allocation policy exists.

```dax
EVALUATE CALCULATETABLE ( VAR FullMonth = HASONEVALUE ( 'Date'[MonthKey] ) && COUNTROWS ( VALUES ( 'Date'[Date] ) ) = DAY ( EOMONTH ( MAX ( 'Date'[Date] ), 0 ) ) VAR Target = IF ( FullMonth, CALCULATE ( SUM ( Budget[Amount] ), TREATAS ( VALUES ( 'Date'[MonthKey] ), Budget[MonthKey] ), TREATAS ( VALUES ( Product[Category] ), Budget[Category] ) ) ) RETURN ROW ( "Actual", [NetRevenue], "ComparableBudget", Target ), 'Date'[Date] = DATE ( 2025, 1, 2 ), Product[Category] = "Paper" )
```

**Context trace:**

1. The selected date count is 1 rather than January's31.
2. Actual revenue on the day is 27.
3. The guard refuses to present the whole-month 60 as a comparable daily budget.

**Hand-derived worked-reference result:**

| Actual | ComparableBudget |
| --- | --- |
| 27 | BLANK |

BLANK protects an undefined comparison. If a daily target is required, add and explain an allocation policy rather than removing the guard without replacement.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Use S8 and the matching monthly budget row.
2. Add compatible monthly targets and actuals once each.
3. Allocated daily weights must sum to one over the intended month.
4. The monthly budget is being repeated at a lower grain.
5. Missing target is not necessarily a zero target.
6. Plans and events often have different time and organizational grains.
