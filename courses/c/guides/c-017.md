# c-017: Ownership APIs, borrowing and independent clones

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-016`

## Learning objectives

Design owning and borrowing APIs, clone independent storage and make cleanup safe to call twice. Along the way, explain borrow, owned result and clone. Implement the six investigations, from the "create an owned string" case to the "transfer a deliberate move" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A reusable C component needs an ownership vocabulary. A borrowed pointer grants temporary access without transferring release responsibility. An owned result makes the caller responsible for destruction. A clone creates independent owned storage; a shallow struct copy usually does not. Document whether a function consumes its input on success, on failure, both or neither. Ambiguity produces leaks, double-free and use-after-free defects that can be difficult to diagnose after components are combined. The small text owner here has one destructor and an explicit clone operation. It never represents a shallow copy as a second independent owner.

## Vocabulary and concepts

- **Borrow:** Temporary access without taking release responsibility.
- **Owned result:** A value whose recipient must release its resources.
- **Clone:** An independent allocation containing equivalent data.

## Syntax anatomy and execution trace

The owner struct contains a char pointer and length. create allocates length plus one, copies bytes and writes a terminator. clone calls the same creation policy on a borrowed source. destroy releases and resets the owner. Use a const pointer for borrowed read access. Returning a struct by value can transfer ownership, but subsequent copies must obey the documented move-or-clone policy because C does not enforce it automatically.

## Worked example / walkthrough

### Worked example 1: Create an owned string

Create an owner for alpha.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Text {
  char *data;
  size_t len;
};
bool text_create(struct Text *out, const char *source) {
  if (out == NULL || source == NULL || out->data != NULL)
    return false;
  size_t n = strlen(source);
  if (n == SIZE_MAX)
    return false;
  char *data = malloc(n + 1);
  if (data == NULL)
    return false;
  memcpy(data, source, n + 1);
  out->data = data;
  out->len = n;
  return true;
}
void text_destroy(struct Text *t) {
  free(t->data);
  t->data = NULL;
  t->len = 0;
}

int main(void) {
  /* Create an owned string */
  {
    struct Text t = {0};
    CHECK(text_create(&t, "alpha"));
    CHECK(t.len == 5 && strcmp(t.data, "alpha") == 0);
    text_destroy(&t);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Length is 5 and content is alpha.

The owner contains both storage and logical length. The terminator is additional storage, not part of len.

### Worked example 2: Clone independent storage

Clone cat and mutate the clone to bat.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Text {
  char *data;
  size_t len;
};
bool text_create(struct Text *out, const char *source) {
  if (out == NULL || source == NULL || out->data != NULL)
    return false;
  size_t n = strlen(source);
  if (n == SIZE_MAX)
    return false;
  char *data = malloc(n + 1);
  if (data == NULL)
    return false;
  memcpy(data, source, n + 1);
  out->data = data;
  out->len = n;
  return true;
}
void text_destroy(struct Text *t) {
  free(t->data);
  t->data = NULL;
  t->len = 0;
}

int main(void) {
  /* Create an owned string */
  {
    struct Text t = {0};
    CHECK(text_create(&t, "alpha"));
    CHECK(t.len == 5 && strcmp(t.data, "alpha") == 0);
    text_destroy(&t);
  }

  /* Clone independent storage */
  {
    struct Text a = {0}, b = {0};
    CHECK(text_create(&a, "cat") && text_create(&b, a.data));
    b.data[0] = 'b';
    CHECK(strcmp(a.data, "cat") == 0 && strcmp(b.data, "bat") == 0);
    text_destroy(&a);
    text_destroy(&b);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The original remains cat.

Two independently allocated owners can be destroyed separately. A plain struct assignment would share the pointer and make that unsafe.

### Exercise 1: Create an owned string: predict an edited check

In worked example 1, change `CHECK(text_create(&t, "alpha"));` to `CHECK(text_create(&t, "alpha!"));`. Predict whether the CHECK still holds and why, then run and restore.

**Expected:** `Check failed`: `CHECK(text_create(&t, "alpha!"));` is false, although length is 5 and content is alpha.

**Verify:** Explain which claim `CHECK(text_create(&t, "alpha!"));` makes that the state fails; restoring `CHECK(text_create(&t, "alpha"));` passes again.

**Progressive hints:** First trace `t` from initialization. Then compute what the CHECK sees with `CHECK(text_create(&t, "alpha!"));` in place.

**Expected:** `Check failed` at `strcmp(a.data, "cat") == 0 && strcmp(b.data, "bat") == 0` until the line reads `b.data[0] = 'b';` again.

**Verify:** Explain how `b.data[1] = 'b';` changes the value `strcmp(a.data, "cat") == 0 && strcmp(b.data, "bat") == 0` tests, using your failing and repaired runs.

**Progressive hints:** First trace `a` and `b` from initialization. Then compare `b.data[1] = 'b';` with worked example 2's original line.

### Exercise 3: Borrow without releasing

Read through a const pointer borrowed from an owner.

**Expected:** The borrowed content is ready.

**Verify:** Keep a CHECK equivalent to `strcmp(view, "ready") == 0`. Control edit: `CHECK(text_create(&t, "ready!"));` must fail; then restore it.

**Progressive hints:** First trace `view` from initialization. Then recall: The view must not be used after destruction.

### Exercise 4: Represent an owned empty string

Create an owner for empty text.

**Expected:** Length is zero but a valid terminator exists.

**Verify:** Keep a CHECK equivalent to `t.len == 0 && t.data != NULL && t.data[0] == '\0'`. Control edit: `CHECK(t.len != 0 && t.data != NULL && t.data[0] == '\0');` must fail; then restore it.

**Progressive hints:** First trace `t` from initialization. Then recall: An empty string still needs one byte under this contract.

### Exercise 5: Make cleanup idempotent

Destroy the same reset owner twice.

**Expected:** The owner stays empty.

**Verify:** Keep a CHECK equivalent to `t.data == NULL && t.len == 0`. Control edit: `CHECK(t.data != NULL && t.len == 0);` must fail; then restore it.

**Progressive hints:** First trace `t` from initialization. Then recall: Resetting the owning fields makes this API safe for repeated cleanup.

### Exercise 6: Transfer a deliberate move

Move ownership by assigning the struct and clearing the source.

**Expected:** Only the destination retains the allocation.

**Verify:** Keep a CHECK equivalent to `source.data == NULL && strcmp(destination.data, "move") == 0`. Control edit: `CHECK(text_create(&source, "move!"));` must fail; then restore it.

**Progressive hints:** First trace `source` and `destination` from initialization. Then recall: The explicit source reset is the manual move protocol.

## Common pitfalls and diagnosis

Copying an owning struct with `=` creates two apparent owners of one allocation, and destroying both frees it twice. Destroying the owner while a borrowed `const char *` view is still in use leaves that view dangling.

General diagnosis order and the pointer checklist: [Diagnose failures](../STUDY-GUIDE.md#diagnose-failures).
