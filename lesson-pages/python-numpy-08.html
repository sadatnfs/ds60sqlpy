Vocabulary and concepts: view, correlation, convolution and boundary#

Sliding window: Groups successive samples into overlapping rows. For a length-nnn vector and width kkk, the valid window matrix has shape (n−k+1,k)(n-k+1,k)(n−k+1,k). A view can describe this matrix without copying every repeated sample. Its logical element count is larger than the original buffer, and several entries can refer to the same storage location.

For real inputs, this is a correlation-style operation.

Convolution: In a window representation, uses the reversed kernel. Symmetric weights produce the same result after reversal, so they are a poor diagnostic fixture. An asymmetric derivative-like kernel reveals the difference immediately.

Boundary condition: Specifies unobserved values outside the signal. Zero extension assumes zeros; reflection borrows nearby interior values; periodic extension wraps to the other end. These are modeling decisions, not cosmetic choices. Valid output uses only complete observed windows. Same output preserves the signal length under an explicit centering policy. Full convolution includes the entire finite support, including partial overlap at both ends.

Syntax anatomy and memory ownership#

Import sliding_window_view from numpy.lib.stride_tricks, then use sliding_window_view(x, width). The default result is read-only. np.shares_memory(x, windows) checks the storage relationship; it does not mean windows.base is x must hold through every internal view wrapper.

Read-only access prevents assignment through that view, but the original array can still change. This distinction matters when a window matrix is passed to another function while the source remains mutable. Copy it if an independent snapshot is required. Do not force overlapping windows writable merely to silence an assignment error, because one write can affect several visible positions.

The view saves storage allocation, but a naive reduction across all windows still examines roughly nknknk logical elements. Specialized convolution or cumulative-sum methods may reduce work for particular operations. This unit teaches correctness and semantics before performance selection; it does not claim that every stride trick is a faster algorithm.

Worked example: asymmetric weights expose reversal#

Predict the signs of both result arrays. This complete program compares the same two numbers interpreted as left-to-right weights and as a convolution kernel.

import numpy as np
from numpy.lib.stride_tricks import sliding_window_view

source = np.array([2.0, 5.0, 9.0, 14.0])
windows = sliding_window_view(source, 2)
weights = np.array([1.0, -1.0])
left_to_right = windows @ weights
convolution = np.convolve(source, weights, mode="valid")
assert np.allclose(left_to_right, [-3, -4, -5])
assert np.allclose(convolution, [3, 4, 5])
assert np.shares_memory(source, windows) and not windows.flags.writeable
print("weighted windows:", left_to_right.tolist(), "convolution:", convolution.tolist())

The left-to-right difference subtracts the later sample, producing negative differences for this increasing signal. Convolution reverses the weights in the local window, producing the opposite sign. With weights [0.5, 0.5], both operations would agree, concealing an orientation bug.

Change source[1] after constructing the windows and inspect both windows that include that sample. The view updates in both positions. Previously calculated dot-product outputs do not update, because they are new result arrays. Keeping this ownership distinction explicit prevents a misleading expectation that every downstream calculation remains linked to the source.

Boundary models change edge values#

For an odd kernel of width kkk, use (k−1)/2(k-1)/2(k−1)/2 padding values on each side to define a centered same-length result. This lesson rejects even kernels because choosing left or right alignment would otherwise remain unstated. The reflect mode excludes the endpoint itself, unlike a symmetric mode that repeats it.

For [1, 2, 4], one reflected sample on each side produces [2, 1, 2, 4, 2], whereas zero extension gives [0, 1, 2, 4, 0]. Compute a boundary result by hand before calling any convenience function. The center result can be correct under both modes while the edge result answers a different physical question.

Reflection can be reasonable for a locally smooth image edge, while zero padding may represent a finite impulse surrounded by silence. Neither is universally correct. For a streaming sensor, reflecting future observations at the right edge would also violate causality if those observations were not actually available. A numerical padding choice is not permission to invent unavailable data.

Worked example: an FFT product has a circular boundary#

Predict where the final value goes when the transform is too short. This complete program compares full linear support with a length-three circular calculation.

import numpy as np

signal = np.array([1.0, 3.0, 2.0])
kernel = np.array([1.0, 2.0])
length = signal.size + kernel.size - 1
linear = np.fft.irfft(np.fft.rfft(signal, n=length) * np.fft.rfft(kernel, n=length), n=length)
circular = np.fft.irfft(np.fft.rfft(signal, n=3) * np.fft.rfft(kernel, n=3), n=3)
assert np.allclose(linear, [1, 5, 8, 4])
assert np.allclose(circular, [5, 5, 8])
assert np.allclose(np.fft.irfft(np.fft.rfft(signal), n=3), signal)
print("linear:", linear.tolist(), "circular:", circular.tolist())

The full result has length four. The shorter transform folds its final contribution of 4 into the first position, changing 1 to 5. Zero-padding to at least n+m−1n+m-1n+m−1 prevents that overlap for vectors of lengths nnn and mmm. Padding beyond that length is also possible, but the requested full output still needs to be cropped deliberately.

The inverse transform already applies its normalization under the default backward convention. Dividing linear again by the transform length would introduce an extra scale error. Change one operand to an impulse and verify that the other is reproduced in the expected position; this is a useful independent test of orientation, support and amplitude.

Real transforms, length and normalization#

For length NNN, the forward discrete Fourier transform uses

With norm="backward", the inverse includes the factor 1/N1/N1/N, so forward followed by inverse reconstructs the input within numerical tolerance. Real input has conjugate-symmetric frequency coefficients. rfft stores only ⌊N/2⌋+1\lfloor N/2\rfloor+1⌊N/2⌋+1 bins, and irfft reconstructs real observations.

The stored bin count does not uniquely encode whether every original length was odd or even. Always preserve the original N and pass it to irfft. An odd-length signal can otherwise return a different output shape. This is a metadata failure as much as a numerical one: a spectrum without its sampling interval and original length is incomplete evidence.

Amplitude scaling and the acquisition assumptions#

rfftfreq(N, d=sample_spacing) returns frequencies in inverse units of the spacing. If spacing is seconds, frequencies are cycles per second. For a bin-centered real sinusoid away from DC and the even-length Nyquist frequency, its one-sided amplitude is twice the FFT magnitude divided by NNN. DC represents the mean and has no separate negative-frequency partner. The even-length Nyquist bin also has no separate partner, so neither is doubled.

For odd lengths, the final stored bin is still an interior positive frequency and must be doubled. This is why testing only even lengths is insufficient. The contract reports magnitude, losing phase and the sign of a DC value. It is not a power spectral density and does not automatically provide physical energy units.

Uniform sampling is required for these frequency labels. Frequencies above half the sampling rate can alias into lower bins; post-processing cannot generally recover what the acquisition failed to distinguish. A real system needs an appropriate sampling rate and anti-alias filtering before downsampling. A frequency between FFT bins also leaks across bins because a finite rectangular observation window need not join smoothly under periodic extension. The lesson does not detrend or apply a taper, so do not interpret its largest bin as an unbiased amplitude estimate for arbitrary signals.

Common pitfalls and diagnosis#

If a derivative changes sign, inspect kernel orientation. If only the edges differ, inspect padding and alignment. If an FFT result wraps into the beginning, inspect transform length. If every value has an extra scale factor, inspect the normalization pair before changing the data. If a real inverse produces one fewer sample, restore the original odd length explicitly.

These mechanisms appear in time-series smoothing, finite impulse-response filters, image neighborhoods and spectral monitoring. Explain which assumptions are appropriate before selecting an API. Reproduce one boundary calculation by hand, explain why a read-only view can change, and identify a signal that would violate the amplitude interpretation. A correct transform implementation and a scientifically meaningful signal analysis are separate achievements.

    x = _vector(values)
    if (
        isinstance(width, (bool, np.bool_))
        or not isinstance(width, (int, np.integer))
        or not 1 <= width <= x.size

        raise ValueError("Window width must be an integer from one through signal length")

Adjacent rows refer to overlapping regions of the original storage. The view avoids allocating a full window matrix, but applying a width-k reduction still performs work across those logical elements. Preserving the source dtype avoids secretly replacing the array with a floating copy and then claiming shared ownership. Default read-only access reduces accidental conflicting writes; it cannot freeze the source.

A row [x_i, x_(i+1)] dotted with [1, 3] is x_i + 3*x_(i+1). Discrete convolution reverses the kernel in a window interpretation, so it is a different operation for asymmetric weights. def convolve_same(values: np.ndarray, kernel: np.ndarray, boundary: str) -> np.ndarray:
    x, h = _vector(values).astype(np.float64), _vector(kernel).astype(np.float64)
    if h.size % 2 != 1 or boundary not in {"zero", "reflect"}:
        raise ValueError("Expected an odd kernel and a zero or reflect boundary")
    if boundary == "reflect" and x.size < 2:
        raise ValueError("Reflect mode needs at least two samples")
    pad = h.size // 2
    padded = np.pad(x, (pad, pad), mode="constant" if boundary == "zero" else "reflect")
    with np.errstate(over="ignore", invalid="ignore"):
        return _finite_result(sliding_window_view(padded, h.size) @ h[::-1])

The interior computation cannot decide which values exist outside the observation interval. Zero padding imposes zero extension; reflection uses nearby interior samples and excludes repeated endpoints under NumPy reflect semantics. Reversal handles convolution orientation separately from padding. Restricting kernels to odd length supplies an unambiguous center, while still permitting kernels wider than the signal.

Exercise 4: Preserve real-transform length and normalization#

Contract: fft_roundtrip. Return irfft(rfft(values, norm="backward"), n=len(values), norm="backward") for a nonempty finite real vector, converted to float64. Reject invalid inputs or nonfinite results with ValueError. Preserve input and original length for both odd and even signals. Verify with numerical tolerance, not exact equality.

Expected: Signals of length 5 and 6 each return their own shape and original values within tolerance. Omitting n for a length-5 input would ordinarily reconstruct length 4.

def fft_roundtrip(values: np.ndarray) -> np.ndarray:
    x = _vector(values).astype(np.float64)
    with np.errstate(over="ignore", invalid="ignore"):
        transformed = np.fft.rfft(x, norm="backward")
        result = np.fft.irfft(transformed, n=x.size, norm="backward")
    return _finite_result(result)

The default backward convention leaves the forward transform unscaled and divides the inverse by the transform length. Real-input transforms store only the nonredundant half-spectrum, whose size alone does not distinguish every odd/even original length. Passing n is therefore part of the data contract. Approximate roundtrip identity checks implementation consistency, not the suitability of a spectral model.

Exercise 5: Scale DC, interior and Nyquist bins correctly#

Contract: one_sided_amplitude. Return (frequency, amplitude) for at least two uniformly sampled finite real observations and finite positive sample_spacing excluding bool. Use rfftfreq and abs(rfft(values))/n; double positive-frequency interior bins only, leaving DC and the even-length Nyquist bin undoubled. For odd length, double every non-DC bin. Reject invalid inputs or nonfinite outputs with ValueError. Do not detrend or window.

Expected: Eight samples of 2 + 3cos(2pij/8) + 4(-1)**j with spacing 1/8 give bins [0, 1, 2, 3, 4] and amplitudes [2, 3, 0, 0, 4] within tolerance. Frequency uses inverse units of spacing.

def one_sided_amplitude(values: np.ndarray, sample_spacing: float) -> tuple[np.ndarray, np.ndarray]:
    x = _vector(values).astype(np.float64)
    if (
        isinstance(sample_spacing, (bool, np.bool_))
        or not isinstance(sample_spacing, (int, float, np.integer, np.floating))
        or not np.isfinite(sample_spacing)
        or sample_spacing <= 0
        or x.size < 2
    ):
        raise ValueError("Expected at least two samples and finite positive sample spacing")
    with np.errstate(over="ignore", invalid="ignore", divide="ignore"):
        frequency = np.fft.rfftfreq(x.size, d=sample_spacing)
        amplitude = np.abs(np.fft.rfft(x, norm="backward")) / x.size
    stop = -1 if x.size % 2 == 0 else None
    amplitude[1:stop] *= 2
    return _finite_result(frequency), _finite_result(amplitude)

Real signals have conjugate frequency pairs. Interior positive bins represent a pair, so doubling their magnitude recovers an isolated bin-centered sinusoid amplitude. DC and an even-length Nyquist bin have no distinct partner. Off-bin tones leak energy; this amplitude convention is neither a general unbiased estimator nor a power spectral density. Uniform sampling and anti-aliasing remain acquisition assumptions.

Exercise 6: Separate linear from circular convolution#

Contract: fft_convolve_full. Return full linear convolution of two nonempty finite real vectors using rfft products and irfft with transform length len(values) + len(kernel) - 1. Convert to float64 before arithmetic, preserve inputs and reject invalid or nonfinite results with ValueError. Return exactly that full output length; no circular wraparound or unexplained extra scale factor.

Expected: [1, 2] convolved with [3, 4] yields [3, 10, 8] within tolerance. A transform length of 2 would alias the last value into the first output position.

def fft_convolve_full(values: np.ndarray, kernel: np.ndarray) -> np.ndarray:
    x, h = _vector(values).astype(np.float64), _vector(kernel).astype(np.float64)
    length = x.size + h.size - 1
    with np.errstate(over="ignore", invalid="ignore"):
        transformed = np.fft.rfft(x, n=length) * np.fft.rfft(h, n=length)
        result = np.fft.irfft(transformed, n=length)
    return _finite_result(result)

Multiplication of finite-length DFTs naturally corresponds to circular convolution. Padding to at least the full linear support prevents overlapping tails from wrapping into the beginning. The default inverse already applies the reciprocal length, so dividing again would under-scale the result. FFT methods are not always faster for tiny kernels; this exercise proves the boundary identity rather than making a performance claim.

from collections.abc import Callable

import numpy as np
from numpy.lib.stride_tricks import sliding_window_view


def _vector(values: np.ndarray) -> np.ndarray:
    x = np.asarray(values)
    if x.ndim != 1 or x.size == 0 or x.dtype.kind not in "iuf" or not np.isfinite(x).all():
        raise ValueError("Expected a nonempty finite real numeric vector, excluding bool")
    return x


def _finite_result(values: np.ndarray) -> np.ndarray:
    if not np.isfinite(values).all():
        raise ValueError("Result exceeds finite floating range")
    return values


def window_view(values: np.ndarray, width: int) -> np.ndarray:
    x = _vector(values)
    if (
        isinstance(width, (bool, np.bool_))
        or not isinstance(width, (int, np.integer))
        or not 1 <= width <= x.size
    ):
        raise ValueError("Window width must be an integer from one through signal length")
    return sliding_window_view(x, int(width))


def weighted_valid(values: np.ndarray, weights: np.ndarray) -> np.ndarray:
    x, w = _vector(values).astype(np.float64), _vector(weights).astype(np.float64)
    windows = window_view(x, w.size)
    with np.errstate(over="ignore", invalid="ignore"):
        return _finite_result(windows @ w)


def convolve_same(values: np.ndarray, kernel: np.ndarray, boundary: str) -> np.ndarray:
    x, h = _vector(values).astype(np.float64), _vector(kernel).astype(np.float64)
    if h.size % 2 != 1 or boundary not in {"zero", "reflect"}:
        raise ValueError("Expected an odd kernel and a zero or reflect boundary")
    if boundary == "reflect" and x.size < 2:

    padded = np.pad(x, (pad, pad), mode="constant" if boundary == "zero" else "reflect")

def expect_value_error(call: Callable[[], object]) -> None:
    try:
        call()
    except ValueError:
        return
    raise AssertionError("Expected ValueError")


def main() -> None:
    source = np.arange(6, dtype=float)
    windows = window_view(source, 3)
    assert windows.shape == (4, 3) and np.shares_memory(source, windows)
    assert not windows.flags.writeable
    source[2] = 17
    assert windows[0, 2] == windows[1, 1] == windows[2, 0] == 17
    expect_value_error(lambda: window_view(source, 0))
    np.testing.assert_allclose(weighted_valid(np.array([1, 2, 4]), np.array([1, 3])), [7, 14])
