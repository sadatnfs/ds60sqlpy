Data and ML Engineering#

A complete tutorial from engineering foundations through data systems, dependable ML workflows and the LLM serving lifecycle.

The 72 tutorial chapters connect engineering foundations, data systems, ML lifecycle decisions and LLM serving. Every chapter provides original theory, two complete explained cases, failure diagnosis, answered interview discussion and a maintained executable reference. There are no forced exams or hidden answers. Start at dme-001 or follow a selected chapter's direct prerequisites.

Open the book#

Follow the main Docker setup, then open the printed address ending in /classroom and select Data and ML Engineering. A lightweight ./classroom --starter session can read the entire book and run Core chapters. To select the complete set of ordinary runtimes used by this book from the repository root:

BUILDKIT_PROGRESS=plain ./classroom \
  --profile data-engineering --profile spark-local-python --profile llm-torch-cpu

Core is included automatically. Explicit profile flags replace the saved profile selection, so include any additional language profiles you want to retain in that selection. Later ./classroom reuses the saved selection; ./classroom stop retains learner state, and ./classroom resume starts without building or pulling. See the launcher guide for the full contract.

The host needs a Linux-container Docker engine and the documented Bash launcher; Windows uses WSL 2. Compilers, Python packages and Spark's JVM belong inside the prepared images. Use images matching the native engine architecture. No GPU, cloud account, downloaded model weights or host language installation is needed for the ordinary worked programs.

Read the changed-condition cases before editing the reference. Compare actual output with the chapter's independent oracle, and inspect rejected conditions as well as successful ones. Saved drafts, notes and results belong to their lesson and runtime. A read marker or successful reference execution records activity; it does not certify mastery or production readiness.

Use the complete projects separately#

Ordinary pads create bounded temporary state and do not start long-lived servers. For persistent service work, copy the maintained project source into a new learner-owned folder and follow that project's instructions:

  • Data-product service: real HTTP snapshot ingestion, SQLite, Polars/DuckDB, immutable Parquet, failure recovery and rollback.
  • Inference service: actual CPU model execution, bounded requests, SSE, cancellation and durable operation receipts.
  • Focused ML service: retained feature/model state, explicit activation, prediction and monitoring.
  • Apache and open-data workshops: separately prepared actual services for the mechanisms discussed in this book.

A Python mechanism model is identified as a model. It is never presented as an executed Kafka, Flink, Cassandra, Pinot, cloud object store or table-format service. Native program execution, application tests, actual HTTP service checks and architecture/hardware qualification remain separate evidence.
