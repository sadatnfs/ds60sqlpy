# dme-064: Autoregressive decoding, sampling and stopping rules

**Level:** Advanced | **Prepared runtime:** `python-core`

**Direct prerequisites:** `dme-063`.

**Outcome:** Derive sampling distributions and enforce stop strings across output boundaries.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

The model produces logits: real-valued scores for vocabulary entries at a position. A decoding policy converts those scores into a selected next token. The server then feeds that token back into the model, updating the cache, until a declared stopping condition holds. The model weights and the decoding policy together determine the behavior a user observes.

This chapter assumes the prefill and cache mechanism. Its NumPy examples use tiny exact distributions so the effect of temperature and top-k truncation can be checked by hand. A separate text example handles a stop string split across chunks. The live workshop implements greedy or seeded top-k sampling, EOS, maximum new-token count and bounded stop strings.

## Logits are not probabilities

Let \(z_j\) be the logit for vocabulary entry \(j\). For temperature \(\tau>0\), softmax defines

\[
p_j=\frac{\exp(z_j/\tau)}{\sum_k\exp(z_k/\tau)}.
\]

Subtracting the maximum scaled logit before exponentiation preserves the distribution and improves numerical stability. It avoids overflow from large positive scores. The denominator normalizes over the allowed vocabulary entries, which may exclude special tokens such as BOS during continuation.

Greedy decoding selects the largest allowed logit. The workshop represents this with temperature zero as a separate branch; it does not divide logits by zero. A small positive temperature sharpens a distribution but still permits sampling. In a tie, selection behavior depends on the implementation's ordering convention and should not be assumed identical across every backend.

Top-k retains the k highest allowed logits and renormalizes within that subset. Nucleus, or top-p, decoding instead selects a probability-mass threshold. The workshop does not implement top-p merely because this chapter discusses it. Adding a policy requires a precise order of operations, validation and tests, including how it interacts with forbidden tokens and temperature.

Sampling uses a request-local random generator. Sharing one global generator across concurrent requests makes outputs depend on execution interleaving. A seed helps reproduce a specific implementation's random choices; it is not a promise of bit-identical output across device types, dependency releases, changed kernels or changed model/tokenizer assets.

## The autoregressive loop

The final prompt position predicts the first continuation token. After selecting it, the server appends it to the conceptual sequence and performs a cached decode step to predict the next token. It does not sample all future tokens independently from the first distribution. Each selection changes the subsequent prefix.

A simplified loop has five stages: check cancellation, compute logits for the current position, apply the decoding policy, decode and retain the selected token's bytes, then evaluate termination. Per-step compute measurements should identify whether they include sampling and device synchronization. The workshop includes its actual model operation and token selection, while event persistence and optional pacing are measured outside compute.

Invalid or nonfinite logits must not silently become a probability vector. They indicate a numerical or contract failure that needs a terminal error and resource cleanup. Similarly, a top-k value beyond the available vocabulary is invalid. Input validation should catch ordinary configuration mistakes before a request owns a compute slot.

## Three stopping mechanisms

EOS is a particular token ID learned during training. Sampling it ends the sequence under the model's vocabulary convention. A maximum new-token count is a server-enforced budget even when the model never emits EOS. A stop string is a decoded-text condition chosen by the caller. These reasons should be recorded separately because they imply different interpretations of the output.

A stop string can cross token boundaries, UTF-8 boundaries and transport-event boundaries. Searching each independently displayed delta is insufficient. The decoder must retain any suffix that could be the beginning of a stop string and release it only when later text disambiguates it. Once a stop matches, the matched string and subsequent text are omitted from the visible continuation under this workshop's contract.

This holdback may delay visible text even after a model token is available. Therefore “time to first token” and “time to first displayed character” need not be identical. A token can represent an incomplete UTF-8 prefix or part of a possible stop string. Retain token-level evidence and define the latency metric explicitly.

## Worked case 1: full, truncated and colder distributions

The first case uses logits `[0, log(2), log(3)]`. At temperature one with all three entries, probabilities are `[1/6,2/6,3/6]`. Top-k with k equal to two removes the first entry and renormalizes the others to `[0,0.4,0.6]`. Temperature one-half with the full vocabulary squares the unnormalized masses, producing `[1/14,4/14,9/14]`.

These expected values follow directly from exponent rules, independently of the implementation. The case checks them with numerical assertions. It also uses two separately initialized NumPy generators with the same seed and distribution and verifies that their sampled sequences match in this prepared environment.

The changed conditions illustrate two different operations. Temperature changes relative mass among retained candidates; top-k removes candidates entirely. A token assigned zero mass by truncation cannot be recovered by lowering or raising temperature afterward unless the policy changes the retained set. Document operation order when comparing decoding configurations.

## Worked case 2: a stop marker split across deliveries

The second case receives `answer <E` followed by `ND> hidden`, with stop string `<END>`. After the first delivery, it exposes `answer ` and retains `<E` because that suffix could complete the marker. After the second, the marker matches and neither it nor ` hidden` becomes visible. The final visible text is exactly `answer `.

A naive implementation that prints the entire first chunk would leak part of the marker and then need to retract text. One that searches only the second chunk would miss the match. The holdback rule avoids both errors. A production policy must also define behavior for overlapping stop strings, duplicate markers, empty strings and end-of-stream flushing; the workshop bounds and validates these cases.

```python
"""Sampling changes a conditional distribution; stopping changes an output contract."""

import numpy as np


def distribution(logits, temperature, top_k):
    values = np.asarray(logits, dtype=float)
    if temperature <= 0 or not 1 <= top_k <= len(values):
        raise ValueError("positive temperature and bounded k required")
    retained = np.argsort(-values, kind="stable")[:top_k]
    scores = values[retained] / temperature
    probabilities = np.exp(scores - scores.max())
    probabilities /= probabilities.sum()
    result = np.zeros_like(values)
    result[retained] = probabilities
    return result


def example_one():
    p = distribution([0.0, np.log(2), np.log(3)], 1.0, 3)
    np.testing.assert_allclose(p, [1 / 6, 2 / 6, 3 / 6])
    truncated = distribution([0.0, np.log(2), np.log(3)], 1.0, 2)
    np.testing.assert_allclose(truncated, [0.0, 0.4, 0.6])
    cold = distribution([0.0, np.log(2), np.log(3)], 0.5, 3)
    np.testing.assert_allclose(cold, [1 / 14, 4 / 14, 9 / 14])
    print("full", p, "top-2", truncated, "colder", cold)
    a = np.random.default_rng(17).choice(3, size=12, p=p)
    b = np.random.default_rng(17).choice(3, size=12, p=p)
    np.testing.assert_array_equal(a, b)


def example_two():
    stop = "<END>"
    chunks = ["answer <E", "ND> hidden"]
    pending = ""
    visible = ""
    for chunk in chunks:
        pending += chunk
        found = pending.find(stop)
        if found >= 0:
            visible += pending[:found]
            break
        hold = max([0] + [size for size in range(1, len(stop)) if pending.endswith(stop[:size])])
        visible += pending[:-hold] if hold else pending
        pending = pending[-hold:] if hold else ""
    assert visible == "answer "
    print("Stop string omitted across token/event boundaries:", repr(visible))
    print("EOS identity, string match and output-token budget are separate finish reasons.")


def main():
    example_one()
    example_two()


if __name__ == "__main__":
    main()
```

## Reproducibility and honest interpretation

A generated continuation is not guaranteed factual or grammatical because the server handles it correctly. The tiny workshop model learns from a small synthetic corpus and can produce fragments. Treat that as a property of the trained model, not a transport bug, unless token IDs, cache comparisons or decoded bytes violate their contracts.

For a reproducible result, retain prompt source, model/tokenizer hashes, generation settings, selected token IDs, finish reason and relevant runtime identity. Output text alone loses evidence about byte replacement and hidden stop prefixes. A completed record should be inspectable without sampling again.

When evaluating a decoding change, distinguish model selection from sampling variation. Use fixed prompts and a declared set of seeds, compare relevant outcome metrics and retain failure examples. Cherry-picking one fluent continuation is not a quality evaluation. The existing LLM evaluation route develops paired comparisons and uncertainty more fully.

## Interview discussion

**Is temperature a confidence estimate?** No. It is a decoding transformation of logits. A sharper distribution is not necessarily more factually calibrated or more correct.

**Why might the first text appear later than the first selected token?** UTF-8 decoding or stop-prefix holdback can delay text. The network and browser add further boundaries. Specify whether a metric measures model selection, server emission or client-visible text.

**Why store finish reasons separately?** Reaching a budget, matching a caller marker and sampling EOS represent different behavior. They affect truncation analysis, user interpretation and comparisons between releases.
