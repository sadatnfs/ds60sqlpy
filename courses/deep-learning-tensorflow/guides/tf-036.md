# tf-036: Capstone: release a small, reproducible model

## Level and prerequisites

Advanced; approximately 240 minutes. Direct prerequisites: `tf-035`.

## Learning objectives

Defend a local model release with reproducibility, inference and rollback evidence. The central investigation is concrete: Package the tiny trained model, preprocessing schema, split hashes and next-step checkpoint proof; run a fresh-process prediction contract and a deliberately failing release check. The finish condition is Acceptance requires all deterministic contract checks, frozen-test evidence, limitations and a rollback artifact. A failed schema or hash blocks the release recommendation.

## Purpose and mental model

A model release is a decision backed by a bundle of evidence. It needs a prediction contract, frozen preprocessing, the identity of fitting and assessment records, and a recoverable artifact. A hash can detect accidental changes to bytes, but cannot establish that those bytes contain a good model or honest data split. A release gate combines independent checks and blocks when a required one fails. The tiny linear model is intentionally transparent so the lesson can concentrate on packaging and decision logic. A no-go is a valid capstone result. Production rollout, privacy guarantees and broad reliability remain outside this offline teaching exercise.

## Vocabulary and concepts

**Release gate:** A conjunction of required checks that permits or blocks a decision.

**Lineage:** The identities of data, preprocessing and artifacts used.

**Rollback artifact:** A retained previous version that can restore a known state.

## Syntax anatomy and reasoning sequence

Serialize metadata with sorted keys and fixed separators before hashing. Keep schema, weights and split IDs in separate fields so a reviewer can identify what changed. Run prediction parity on fixed probes and reject a schema mismatch before inference. The checkpoint parity proof from tf-028 and export proof from tf-032 are distinct evidence items; neither should be replaced by a boolean invented without execution.

## Make a release decision reconstructible

The capstone's weight vector [2, -1] and ordered input [3, 4] produce 2.
Swapping those inputs produces 5. Both arrays have the same shape and dtype,
so the fixed probe connects feature order to behavior in a way that a file
existence check cannot. A release bundle needs the schema and preprocessing
contract as well as model bytes.

Canonical serialization gives a stable byte representation for the split
manifest. A SHA256 digest then changes when a recorded ID changes. This
detects an identity change relative to an expected digest; it does not prove
that the split was independent or that its author is trusted. Keep the
actual disjointness check, grouping rule and provenance beside the digest.

Required gates have three meaningful states: passed, failed and unexecuted.
The fixture accepts only literal True for each required gate, so an unknown
restart proof does not become an implicit pass. A recorded boolean should
point to the observation that supports it. Prediction parity, a fresh-process
restart and a schema check are separate pieces of evidence, not interchangeable
labels for one successful run.

Retain the previous artifact and the input contract needed to use it when
recording a rollback path. An artifact name without recoverable bytes and
compatible preprocessing is not a demonstrated rollback. The final record
also preserves the two-row holdout count and synthetic-fixture limitation.
A no-go decision is a successful application of the lesson when required
evidence is absent or a gate fails. The next step is to obtain the missing
evidence or repair the failed contract, then reassess the complete bundle.

## Worked example / walkthrough

### Example A: Build a literal model bundle

A known probe connects the serialized feature order to numerical behavior. Swapping features would change the prediction even if the model file remained readable.

```python
import numpy as np
import tensorflow as tf

weights = np.array([[2.0], [-1.0]], dtype="float32")
schema = {"features": ["a", "b"], "dtype": "float32", "width": 2}
model = tf.keras.Sequential([tf.keras.Input(shape=(2,)), tf.keras.layers.Dense(1, use_bias=False)])
model.layers[0].set_weights([weights])
np.testing.assert_array_equal(model(np.array([[3, 4]], dtype="float32")).numpy(), [[2]])
```

**Expected:** probe [3, 4] predicts 2.

### Example B: Freeze and hash a split manifest

The canonical representation avoids a digest change caused only by dictionary key order. The explicit intersection check verifies a property that a hash alone cannot establish.

```python
import numpy as np
import tensorflow as tf

weights = np.array([[2.0], [-1.0]], dtype="float32")
schema = {"features": ["a", "b"], "dtype": "float32", "width": 2}
model = tf.keras.Sequential([tf.keras.Input(shape=(2,)), tf.keras.layers.Dense(1, use_bias=False)])
model.layers[0].set_weights([weights])
np.testing.assert_array_equal(model(np.array([[3, 4]], dtype="float32")).numpy(), [[2]])
import hashlib, json

split = {"train": ["a", "b"], "test": ["c", "d"]}
payload = json.dumps(split, sort_keys=True, separators=(",", ":")).encode()
digest = hashlib.sha256(payload).hexdigest()
assert not set(split["train"]) & set(split["test"]) and len(digest) == 64
```

**Expected:** disjoint IDs and a 64-character SHA256.

## Common pitfalls and diagnosis

If all gates appear green, check that each has an actual receipt
for the candidate bytes. If a schema-valid request predicts incorrectly,
inspect feature order and units. If rollback is claimed, identify the retained
artifact and compatible transformation. Keep unknown evidence distinct from
failure, while letting either block a required release gate.
