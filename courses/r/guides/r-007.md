## Outcome and mechanism

Explain why ordinary vector updates differ from mutations of reference objects and why attributes matter.

An R object can carry attributes in addition to its underlying values. Names attach labels, dim gives an array shape, and class influences methods. Two vectors with the same numerical entries can differ as complete objects if their names or other attributes differ. Use unname only when the labels are genuinely irrelevant to the question.

For ordinary vectors, a second assignment such as y <- x creates another binding whose value initially agrees with x. Updating y should not be interpreted as changing x by reference. R's implementation can share storage internally until modification, but the observable ordinary-vector behavior preserves x. Avoid claiming that every assignment immediately copies all bytes; allocation strategy is different from language semantics.

Environments are an important exception. Two bindings can refer to the same environment, and assigning a field through one binding is visible through the other. Later R6 objects use related reference semantics. This distinction affects testing, caching and configuration: an apparent local update may modify shared state when the object is reference-based.

Attributes are also part of an interface. A function intended to return an unnamed numeric vector should deliberately document and test that choice. A function intended to preserve labels should not drop them by accident. Numeric equality alone cannot validate either contract. Inspect structure and use exact assertions for names, dimensions and class where those properties carry meaning.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Attribute | Metadata attached to an object, such as names or dimensions. |
| Copy-on-modify behavior | Ordinary vector modification preserves another binding to the prior value. |
| Identity | Exact comparison of value, type and attributes. |
| Reference object | An object such as an environment whose mutations can be shared. |

## Read the syntax

names(x) reads labels and names(x) <- value assigns them. attributes(x) exposes metadata. identical compares the full object. new.env creates a reference object; e$value <- ... changes its binding rather than an ordinary numeric vector copy.

## Worked examples

### Example 1: An ordinary vector remains independently editable

```r
x <- c(A = 1, B = 2)
y <- x
y[[1]] <- 99
stopifnot(x[[1]] == 1, y[[1]] == 99)
stopifnot(!identical(x, unname(x)))
print(list(original = x, edited = y))
```

**Expected observation:** Original A is one; edited A is 99.

The updated binding has a different vector value. The original labels and values remain intact.

### Example 2: An environment is shared state

```r
first <- new.env(parent = emptyenv())
first$count <- 1
second <- first
second$count <- 2
stopifnot(first$count == 2, identical(first, second))
print(first$count)
```

**Expected observation:** 2.

Both names point to the same environment. This is a reference object, so the mutation is visible through either binding.
