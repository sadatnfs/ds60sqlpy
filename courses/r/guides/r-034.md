## Outcome and mechanism

Reshape repeated measurements only after validating the observation key and deciding how missing cells are represented.

Long and wide tables organize the same measurements differently. In a long table, each row might identify one person, one visit and one observed value. In a wide table, visits become columns and each row describes a person. Neither representation is inherently more correct; the intended operation determines which shape is easier to use.

A reshape requires a unique cell key. If two records share person and visit, they cannot both occupy one ordinary scalar wide cell without an additional rule. Summing or taking the first value is an aggregation decision, not a neutral reshape. Diagnose duplicates before conversion and decide whether they are repeated events, data errors or measurements requiring a declared summary.

An absent person-visit combination differs from a present row whose value is missing. A wide table can represent both as NA unless additional observation-status information is retained. If that distinction matters, preserve a presence indicator or keep the original long records. Do not claim a lossy wide representation can reconstruct information it never stored.

Verify a round trip under the declared uniqueness and missingness assumptions. Order may change during reshaping, so compare sorted keys and aligned values rather than raw row order. Preserve identifier types and state the resulting column names explicitly. A successful round trip on one complete table does not validate a later table with duplicated keys or structurally absent measurements.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Long representation | Rows encode repeated measurement identifiers as values. |
| Wide representation | Repeated measurement identifiers become separate columns. |
| Cell key | The fields identifying one intended wide-table cell. |
| Round-trip invariant | A property preserved after conversion and reversal. |

## Read the syntax

Base reshape uses idvar for the entity key, timevar for repeated measurement labels, v.names for measured values and direction for the target shape. Supply varying columns explicitly on a reverse conversion rather than relying on accidental naming inference.

## Worked examples

### Example 1: Two visits become two columns

```r
long <- data.frame(id = c("A", "A", "B", "B"), visit = c(1, 2, 1, 2), value = c(10, 12, 20, 23))
stopifnot(!anyDuplicated(long[c("id", "visit")]))
wide <- reshape(long, idvar = "id", timevar = "visit", direction = "wide")
wide <- wide[order(wide$id), , drop = FALSE]
stopifnot(identical(wide$value.1, c(10, 20)), identical(wide$value.2, c(12, 23)))
print(wide)
```

**Expected observation:** A10/12;B20/23.

The unique id/visit key determines one value per output cell. No aggregation is necessary.

### Example 2: An absent visit becomes an explicit missing cell

```r
long <- data.frame(id = c("A", "A", "B"), visit = c(1, 2, 1), value = c(10, 12, 20))
wide <- reshape(long, idvar = "id", timevar = "visit", direction = "wide")
stopifnot(is.na(wide$value.2[wide$id == "B"]))
present <- transform(long, present = TRUE)
stopifnot(nrow(present) == 3L)
print(wide)
```

**Expected observation:** B visit 2 isNA.

The missing B visit 2 cell means no supplied record here. Keeping the original long rows or a separate presence table preserves that distinction.
