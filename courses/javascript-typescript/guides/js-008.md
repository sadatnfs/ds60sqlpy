# js-008: Strings, Unicode and regular expressions

## Level and prerequisites

Beginner, approximately 90 minutes. Direct prerequisites: `js-007`

## Learning objectives

Count and compare Unicode text correctly and write bounded, Unicode-aware regular expressions without hidden cursor state.

By the end you can count code units and codepoints, compare canonical spellings, match a literal regex fragment, observe global regex cursor state, use Unicode-aware dot matching, and bound a text-validation input.

## Purpose and mental model

JavaScript strings are sequences of UTF-16 code units. length and indexing count those units, which do not always correspond to complete Unicode codepoints. A supplementary emoji occupies a surrogate pair, and a visible letter can combine several codepoints. Iteration with for...of or spread uses codepoints, while grapheme segmentation requires an additional text policy. Normalization can map canonically equivalent spellings to one representation, but should not be applied silently to every identifier or secret.

Regular expressions are programs over text, not literal string containers. User text containing dots, brackets or quantifiers can change a pattern if inserted without escaping. The prepared Node 24 runtime supports RegExp.escape for literal pattern construction. Bound pattern and input size when regex work is exposed externally; not every complex pattern has predictable linear cost.

## Vocabulary and concepts

**UTF-16 code unit:** The storage/indexing unit used by JavaScript String.

**Code point:** A Unicode identity represented by one or two code units.

**Normalization:** A declared mapping between equivalent Unicode sequences.

**Pattern escaping:** Treating input text as literal characters rather than regex syntax.

## Syntax anatomy and execution trace

Use codePointAt and string iteration to inspect codepoints. normalize('NFC') applies a declared canonical normalization. The u flag enables Unicode-aware regex semantics for codepoints, but does not turn codepoints into grapheme clusters. RegExp.escape converts a literal string into a safe pattern fragment. A global regex carries lastIndex state across calls, so reuse requires understanding or resetting that cursor.

## Worked example / walkthrough

### Example A: Count code units and codepoints

The emoji uses two code units. Taking a one-unit substring from its middle would not produce a complete codepoint.

```javascript
import { strict as assert } from 'node:assert';

function identifier(value) {
  if (typeof value !== 'string' || value.length > 20 || !/^[A-Za-z_][A-Za-z0-9_]*$/u.test(value))
    throw new TypeError('bounded ASCII identifier required');
  return value;
}

export async function verify() {
  // Worked example
  {
    const text = 'A🙂';
    assert.equal(text.length, 3);
    assert.equal([...text].length, 2);
    assert.equal(text.codePointAt(1), 0x1f642);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** length 3; spread count 2.
### Example B: Compare canonical spellings

Canonical normalization changes representation identity under an explicit policy. It does not solve every homoglyph or language-specific comparison problem.

```javascript
import { strict as assert } from 'node:assert';

function identifier(value) {
  if (typeof value !== 'string' || value.length > 20 || !/^[A-Za-z_][A-Za-z0-9_]*$/u.test(value))
    throw new TypeError('bounded ASCII identifier required');
  return value;
}

export async function verify() {
  // Worked example
  {
    const composed = 'é';
    const decomposed = 'é';
    assert.notEqual(composed, decomposed);
    assert.equal(decomposed.normalize('NFC'), composed);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** raw strings differ; normalized strings equal.

## Exercises

1. **Count code units and codepoints: predict an edited check.** In a scratch copy of Example A, change `assert.equal(text.codePointAt(1), 0x1f642);` to `assert.equal(text.codePointAt(2), 0x1f642);` inside its check. Does the check still pass?
   **Expected:** The edited run fails with an `AssertionError` at `assert.equal(text.codePointAt(2), 0x1f642);`. Restoring `assert.equal(text.codePointAt(1), 0x1f642);` brings back: length 3; spread count 2.
   **Verify:** The emoji uses two code units. Use that rule to account for the actual and expected values in the `AssertionError`.

2. **Compare canonical spellings: debug a regression.** A regression made one Example B line read `const composed = 'é!';`. Locate and repair it without editing the check.
   **Expected:** Before the repair the run fails with an `AssertionError` at `assert.equal(decomposed.normalize('NFC'), composed)`. Restoring `const composed = 'é';` brings back: raw strings differ; normalized strings equal.
   **Verify:** Canonical normalization changes representation identity under an explicit policy. Keep the failing and repaired runs and compare the values each one reports.

3. **Match a literal regex fragment.** Escape a.b+ and match it exactly rather than interpreting dot and plus.
   **Expected:** literal accepted; axbb rejected.
   **Verify:** Keep `assert.equal(pattern.test('a.b+'), true)`. Control: changing `const literal = 'a.b+';` to `const literal = 'a.b+!';` must make that check fail; then restore it.

4. **Observe global regex cursor state.** Call /a/g repeatedly on aa and inspect lastIndex.
   **Expected:** matches at 0 then 1; third call false resets cursor 0.
   **Verify:** Keep `assert.equal(pattern.lastIndex, 0)`. Control: editing it to `assert.equal(pattern.lastIndex, 1);` must make the check fail; then restore it.

5. **Use Unicode-aware dot matching.** Compare `/^.$/` and `/^.$/u` on one emoji.
   **Expected:** without u false; with u true.
   **Verify:** Keep `assert.equal(/^.$/u.test('🙂'), true)`. Control: editing it to `assert.equal(/^.$/u.test('🙂!'), true);` must make the check fail; then restore it.

6. **Bound a text-validation input.** Reject a string longer than 20 code units before applying an anchored ASCII identifier pattern.
   **Expected:** item_1 accepted; oversized input rejected.
   **Verify:** Keep `assert.equal(identifier('item_1'), 'item_1')`. Control: editing it to `assert.equal(identifier('item_2'), 'item_1');` must make the check fail; then restore it.

## Common pitfalls and diagnosis

A regular expression with the `g` flag remembers `lastIndex`, so repeated `test` calls on one pattern alternate between true and false. Reversing text with `split('')` also breaks surrogate pairs. When text results look random, inspect `lastIndex` and the code-unit counts. ([Diagnosing a failure](../STUDY-GUIDE.md#diagnosing-a-failure).)
