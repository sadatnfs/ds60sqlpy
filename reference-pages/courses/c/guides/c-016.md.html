c-016: Reallocation and a checked dynamic vector#

Level and prerequisites#

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: c-015

Learning objectives#

Implement a growable vector whose reallocation preserves contents and leaves the vector unchanged when growth fails. Along the way, explain length, capacity and reallocation. Implement the six investigations, from the "push into an empty vector" case to the "transfer reserve failure atomicity" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

Purpose and mental model#

A dynamic vector separates logical length from allocated capacity. Growth may move the allocation, invalidating prior element pointers. realloc returns a new pointer on success; on failure for a nonzero requested size, the original allocation remains owned and unchanged. Assigning realloc directly to the only owning pointer can therefore lose the original allocation on failure. Keep the result in a temporary, validate it, then update the vector. Growth arithmetic needs overflow checks and a resource policy. The vector here owns ints and preserves its old state when a reserve request is rejected.

Vocabulary and concepts#

  • Length: The number of initialized logical elements.
  • Capacity: The number of elements fitting in allocated storage.
  • Reallocation: Resizing storage, potentially changing its address.

Syntax anatomy and execution trace#

A vector stores data, len and cap. reserve ensures capacity without changing length. push reserves before writing data[len], then increments length. pop checks nonempty before decrementing. destroy frees storage and resets all fields, making repeated cleanup harmless under this local ownership contract. Never retain an element pointer across a call that may grow the vector.

Worked example / walkthrough#

Worked example 1: Push into an empty vector#

Push 3 and 5 into a zero-initialized vector.

#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Vector {
  int *data;
  size_t len, cap;
};
bool vector_reserve(struct Vector *v, size_t cap) {
  if (cap <= v->cap)
    return true;
  if (cap > SIZE_MAX / sizeof *v->data)
    return false;
  int *next = realloc(v->data, cap * sizeof *v->data);
  if (next == NULL)
    return false;
  v->data = next;
  v->cap = cap;
  return true;
}
bool vector_push(struct Vector *v, int value) {
  if (v->len == v->cap) {
    size_t next = v->cap ? v->cap * 2 : 4;
    if (next < v->cap || !vector_reserve(v, next))
      return false;
  }
  v->data[v->len++] = value;
  return true;
}
bool vector_pop(struct Vector *v, int *out) {
  if (v->len == 0 || out == NULL)
    return false;
  *out = v->data[--v->len];
  return true;
}
void vector_destroy(struct Vector *v) {
  free(v->data);
  v->data = NULL;
  v->len = 0;
  v->cap = 0;
}

int main(void) {
  /* Push into an empty vector */
  {
    struct Vector v = {0};
    CHECK(vector_push(&v, 3) && vector_push(&v, 5));
    CHECK(v.len == 2 && v.data[0] == 3 && v.data[1] == 5);
    vector_destroy(&v);
  }
  puts("Worked example checks passed.");
  return 0;
}

Observe: Length is 2 and values are retained.

The zero state is a usable empty vector. Growth happens before the first write.

Worked example 2: Reserve without adding elements#

Reserve capacity eight.

#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Vector {
  int *data;
  size_t len, cap;
};
bool vector_reserve(struct Vector *v, size_t cap) {
  if (cap <= v->cap)
    return true;
  if (cap > SIZE_MAX / sizeof *v->data)
    return false;
  int *next = realloc(v->data, cap * sizeof *v->data);
  if (next == NULL)
    return false;
  v->data = next;
  v->cap = cap;
  return true;
}
bool vector_push(struct Vector *v, int value) {
  if (v->len == v->cap) {
    size_t next = v->cap ? v->cap * 2 : 4;
    if (next < v->cap || !vector_reserve(v, next))
      return false;
  }
  v->data[v->len++] = value;
  return true;
}
bool vector_pop(struct Vector *v, int *out) {
  if (v->len == 0 || out == NULL)
    return false;
  *out = v->data[--v->len];
  return true;
}
void vector_destroy(struct Vector *v) {
  free(v->data);
  v->data = NULL;
  v->len = 0;
  v->cap = 0;
}

int main(void) {
  /* Push into an empty vector */
  {
    struct Vector v = {0};
    CHECK(vector_push(&v, 3) && vector_push(&v, 5));
    CHECK(v.len == 2 && v.data[0] == 3 && v.data[1] == 5);
    vector_destroy(&v);
  }

  /* Reserve without adding elements */
  {
    struct Vector v = {0};
    CHECK(vector_reserve(&v, 8));
    CHECK(v.cap >= 8 && v.len == 0);
    vector_destroy(&v);
  }
  puts("Worked example checks passed.");
  return 0;
}

Observe: Capacity is at least eight while length stays zero.

Reservation is storage preparation, not logical insertion. Treating capacity as length would expose uninitialized elements.

Common pitfalls and diagnosis#

Fix diagnostics in the "push into an empty vector" case and the "reserve without adding elements" case one cause at a time, starting with the first warning for reallocation and a checked dynamic vector; a declaration mismatch in vector_reserve or vector_push or vector_pop cascades. If the CHECK on v.cap >= 8 && v.len == 0 in the "reserve without adding elements" case fails, compare the actual value with the claim that capacity is at least eight while length stays zero and find the earliest departing transition. A clean compile, or a run of the "grow while preserving contents" case that did not crash, does not rule out undefined behavior.

In the "pop from a nonempty vector" case and the "reject an empty pop" case, give every pointer and index a target, bounds, alignment, lifetime and mutability under the length, capacity and reallocation rules. Check each library result before use and release each owned resource once per path. The "transfer reserve failure atomicity" case transfers the mechanism; keep its distinction from the "push into an empty vector" case instead of replacing a rejected input with a plausible default.
