llm-046: MHA, MQA, GQA and blockwise exact attention#

Level and prerequisites#

Advanced; approximately 210 minutes. Direct prerequisites: llm-045. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Attention architecture and attention execution are separate design dimensions. The central investigation is concrete: Use batch 1, time 5, query heads4, head width 2, float32, and compare KV heads 4, 2, 1. The finish condition is raw KV bytes 320, 160, 80; projection weights 256, 192, 160 for model width 8 without biases. both raise ValueError; no output NaNs are accepted. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Separate the attention function from the way it is executed#

There are two broad ways to reduce attention-related costs. One changes the model's structure, such as sharing key/value heads across multiple query heads. The other computes a chosen attention operation using a different storage and scheduling strategy. These changes can be combined, but they should not be described as the same optimization. The first can change the represented function; the second aims to preserve that function while changing execution costs.

The chapter's grouped-head example and online-softmax example isolate these two ideas. Both use small NumPy arrays and exact comparison oracles. They do not implement a GPU FlashAttention kernel or demonstrate a serving throughput improvement. Their value is that the algebra and array ownership can be inspected before a performance claim is attempted.

Read the head dimensions before counting a cache#

Multi-head attention gives each query head its own key/value head. Multi-query attention shares one key/value head across all query heads. Grouped-query attention uses an intermediate number of KV heads. In the fixture, four query heads share two KV heads in contiguous groups: query heads 0 and 1 use KV head 0, while query heads 2 and 3 use KV head 1.

The query projections remain distinct, so two query heads sharing the same keys can still assign different attention weights. Sharing K/V does not make all head outputs identical. The reference verifies this mapping by constructing an expanded oracle that repeats each shared KV head twice. Agreement with that intentionally equivalent oracle checks grouping logic, not the quality of converting an arbitrary independently trained MHA checkpoint.

With cache length T, batch B, KV head count Hkv, head width d and bytes per element s, raw K/V storage is 2BTHkvd*s per layer. Query-head count does not multiply that storage again. If a system accidentally materializes repeated K/V copies for each query head, it can lose the intended storage saving even though the mathematical grouping is correct. The physical layout must match the resource claim.

Count what head sharing leaves unchanged#

For model width D and Hq query heads, the Q projection has DHqd entries. K and V together have 2DHkvd, and the output projection has Hqd*D. Reducing Hkv changes only the K/V term in this count. It does not shrink the query projection, output projection, feed-forward blocks or every activation by the same factor.

The fixture D=8,Hq=4,d=2 gives projection totals 256,192,160 for Hkv=4,2,1. Raw cache bytes at T=5,B=1,float32 are 320,160,80. The cache shrinks by four from MHA to MQA in this example, while these projection weights shrink from 256 to 160, a different ratio. A single "four times smaller" slogan would hide which quantity was counted.

Changing Hkv also constrains the learned representation. Repeating shared heads creates a special MHA configuration with tied values, but averaging unrelated trained heads does not generally preserve outputs. Any conversion needs a model-specific adaptation and evaluation plan. The equality oracle in this lesson deliberately avoids claiming otherwise.

Derive online attention as a mergeable weighted average#

For one query, ordinary attention produces output O=sum_j exp(s_j)V_j / sum_j exp(s_j). To avoid unstable exponentials, choose a reference maximum m and store ell=sum_j exp(s_j-m) and n=sum_j exp(s_j-m)V_j. The output is n/ell, so the common factor exp(m) cancels. This summary can be updated block by block without retaining every score.

Suppose block A has summary(m_A,ell_A,n_A) and block B has(m_B,ell_B,n_B). Let m=max(m_A,m_B). Rescale A by exp(m_A-m), rescale B by exp(m_B-m), then add their denominators and numerators. Both accumulated quantities must use the same reference maximum. In exact arithmetic, combining blocks this way gives the same weighted average regardless of grouping; floating-point summation order can still produce small differences.

A block with no allowed keys contributes no mass and can be skipped. A complete query with no allowed key is different: it has no defined probability distribution under the lesson contract. The implementation refuses it instead of returning a fabricated zero vector. A neutral intermediate state is bookkeeping, not permission to divide 0 by 0 at the end.

Work through a two-block example#

Use scores[0,log(2),log(4)] and scalar values[1,3,5]. The dense masses are[1,2,4], so the output is(1+6+20)/7=27/7≈3.857143. Process the first two entries as block A. Its maximum is log(2), shifted masses are[.5,1], ell_A=1.5 and n_A=.51+13=3.5.

The final entry is block B with maximum log(4), ell_B=1 and n_B=5. The combined maximum rises from log(2) to log(4), so A is rescaled by exp(log(2)-log(4))=.5. The new denominator is .51.5+1=1.75, and the new numerator is .53.5+5=6.75. Their ratio is 6.75/1.75=27/7, matching the dense calculation.

If the old numerator were left unscaled, the output would be(3.5+5)/1.75≈4.857143. If only the numerator were rescaled and the denominator remained unscaled, the output would be 6.75/2.5=2.7. Both errors can produce finite, plausible-looking numbers. A case where the maximum arrives in a later block is therefore essential for testing the recurrence.

Exact arithmetic does not mean identical resource behavior#

The online routine avoids holding a full query-key score matrix inside that operation. It still computes the relevant dot products. For dense self-attention, the number of query-key pairs remains quadratic in sequence length. Reducing memory traffic and temporary storage is different from changing that pair count.

The independent dense oracle intentionally allocates a full score matrix. As a result, the entire test process cannot be advertised as having only the online routine's temporary footprint. The returned peak count records the largest local score block, not peak process or device memory. A resource report should separate those measurements instead of borrowing the strongest-sounding label.

A production IO-aware kernel also manages device memory hierarchy, parallel execution, synchronization, layout and backward computation. The mathematical recurrence is one ingredient, not the whole implementation. Python-loop timing on tiny CPU arrays cannot establish the throughput of that kernel. The FlashAttention paper supplies the broader implementation context.

Numerical guards define the supported domain#

Positive head width is required before division by sqrt(d). Finite input elements do not guarantee a finite dot product because multiplication and summation can overflow. The repaired helper controls warning behavior around score formation and rejects nonfinite computed scores with ValueError. This keeps an undefined intermediate from becoming accepted NaN output.

The unnormalized weighted-value numerator can also overflow even when all scores and values are finite. Two equal masses multiplying values of 1e308 can sum to infinity before division by the denominator, although the final dense average is representable. This teaching implementation explicitly rejects nonfinite accumulated numerators, denominators or outputs with ValueError. It therefore has a narrower numerical domain than every finite-input attention problem; it does not promise to recover all representable averages. A later maximum cannot safely repair an already overflowed numerator through zero times infinity.

Stable softmax addresses exponentiation after valid scores exist. It cannot repair a dot product that has already overflowed. This ordering is important: validate the inputs and dimensions, compute under a controlled numeric policy, validate the resulting scores, then normalize. A nonuniform finite oracle should still pass so that rejection tests do not reward a function that simply refuses all inputs.

Design decisions and when to use this method#

Use MQA or GQA when the architecture and training evidence support sharing keys/values to reduce incremental cache costs. Treat converting existing weights as a model-change problem requiring adaptation/evaluation, not a pure storage-format rewrite. Use IO-aware exact-attention kernels when the prepared hardware/backend supports them and their correctness and performance are measured on representative shapes.

Do not conflate fewer KV heads with FlashAttention. One changes model structure and cache dimensions; the other changes execution of an attention computation. Do not claim that this reference measures peak memory or GPU throughput. Its dense oracle intentionally allocates the full score matrix to check the blockwise result, and Python loops are not a proxy for an optimized kernel.

Derivation and shape trace#

Let B be batch size, L cached token count, Hkv key/value head count, d head width and s bytes per entry. Raw key/value storage is 2BLHkvds. Query heads do not multiply that storage a second time. With model width D and Hq query heads, the bias-free projection count is D(Hqd)+2D(Hkvd)+(Hqd)*D.

For one query, maintain a running maximum m, denominator ell=sum exp(score-m), and numerator n=sum exp(score-m)*value. When a new score block b arrives, define m_new=max(m,max(b)) and alpha=exp(m-m_new). Update both accumulated quantities:

\[ \ell_{new}=\alpha\ell+\sum_j\exp(b_j-m_{new}),\quad n_{new}=\alpha n+\sum_j\exp(b_j-m_{new})v_j. \]

The final output is n/ell. Both quantities now use the same reference maximum, so their ratio matches dense softmax attention up to floating-point rounding. Skipping a fully masked block is valid; accepting a query with no legal key is not valid under this lesson contract.

This recurrence supports tiled execution without retaining the whole score matrix. A fast GPU implementation additionally manages memory layout, synchronization, parallelism and backward recomputation. Those implementation and hardware properties are not measured by this NumPy reference.

Separate model sharing from execution efficiency#

Query heads decide how many distinct query projections are available. KV heads decide how many distinct key/value projections are stored and shared. In the fixture Hq=4 and Hkv=2, query heads0 and 1 read KV head 0, while query heads2 and 3 read KV head 1. The mapping h//(Hq/Hkv) assumes contiguous equal groups and divisibility. A different head layout requires a corresponding mapping; repeating or reshaping tensors until shapes match is not enough to establish equivalence.

The repeated-head oracle deliberately constructs equivalent inputs. It duplicates each of the two existing KV heads twice and then executes four ordinary head computations. Agreement establishes that the grouping code applies the intended sharing. It does not prove that four independently trained KV heads can be replaced by two without changing outputs. Averaging arbitrary trained head weights would define a new model, even if it reduced cache storage. The GQA work treats conversion and training as part of the model study, rather than a lossless file-format rewrite.

For one layer with batch B, cached length L, Hkv KV heads, key/value width d and s bytes per entry, raw cache bytes are 2BLHkvds. The2 counts K and V. With B=1,L=5,d=2,s=4, using4,2,1 KV heads gives 320,160,80 bytes. A stack with N layers multiplies this raw count by N if each layer has the same dimensions. Real allocation also includes paging, alignment, metadata and any unequal K/V widths. Query-head count does not multiply cached K/V storage again after Hkv has already been counted.

The projection-weight count tells a related but different story. For model width D and query output width Hqd, W_Q contains DHqd entries, W_K and W_V together contain2DHkvd, and the output projection contains Hqd*D. With D=8,Hq=4,d=2, the total is 256,192,160 for Hkv=4,2,1. This excludes biases and other blocks. Reducing KV heads by four changes raw cache bytes by four, but does not reduce Q/output projections or the rest of the model by that factor.

Online softmax solves a numerical aggregation problem. For a processed set of keys, store a maximum m, mass ell=sum exp(s_j-m), and weighted numerator n=sum exp(s_j-m)v_j. The final output is n/ell. The absolute scale exp(m) is never needed because it cancels. To combine summaries from two blocks with maxima m_a,m_b, choose m=max(m_a,m_b), scale each block by exp(m_block-m), and add both its denominator and numerator. In exact arithmetic this merging is associative; floating-point operation order can still create small differences.

Trace a changing maximum with scores[0,log 2] and scalar values[2,5], processed one key at a time. The first state is m=0,ell=1,n=2. The second score raises the reference maximum to log 2, so the old state is scaled by exp(-log 2)=1/2. The new state is ell=.5+1=1.5 and n=1+5=6, giving output 4. A dense calculation uses weights[1/3,2/3] and also gives 4. If only the denominator were rescaled, the numerator would be2+5=7 and the output 14/3, which is wrong. If only the numerator were rescaled, the denominator would2 and the output 3, also wrong.

A fully masked block contributes no legal key and can be skipped. A query whose entire allowed set is empty cannot be normalized. Keeping an initial m=-infinity and ell=0 is useful state bookkeeping, but it does not make0/0 a valid output. The helper validates the row-level allowed set before accumulation. It also requires positive head width and rejects nonfinite computed dot products, since finite elements alone do not prevent multiplication/summation overflow.

Exact blockwise attention avoids retaining the full score matrix in that routine, but still evaluates the relevant query-key pairs. For dense self-attention, the pair count remains quadratic in sequence length. The local peak counter reports the largest score block in this implementation; it is not a process peak-memory measurement. The independent dense oracle intentionally allocates a dense score matrix, so the whole verification process cannot be advertised as having the online routine's memory footprint.

FlashAttention combines exact attention algebra with hardware-aware tiling and memory traffic reduction. The NumPy loops here teach one mathematical ingredient, not a GPU implementation or speedup. Performance evaluation must separate prompt prefill, incremental decode, batch size, cache lengths, precision, warmup and synchronization. A faster small CPU loop would not establish the bandwidth or scheduling behavior of a device kernel.

Interview reasoning: "Does GQA make FlashAttention unnecessary?" They address different dimensions. GQA changes which heads share learned keys and values, while an IO-aware kernel changes how the selected attention operation is executed. A model can use both. Validate the model's output contract separately from measuring the implementation's memory and latency under representative workloads.

Vocabulary and concepts#

MHA: Attention with one key/value head per query head.

MQA: Attention sharing one key/value head across all query heads.

GQA: Attention sharing key/value heads within groups of query heads.

Online softmax state: A running maximum,normalizer and weighted-value numerator.

IO-aware kernel: An implementation designed around memory hierarchy and traffic,not only arithmetic count.

Syntax anatomy and reasoning sequence#

For the single-batch reference, Q has shape(Hq, T, d), K shape(Hkv, T, d), and V shape(Hkv, T, dv), with Hq divisible by Hkv. Query head h uses key/value head h//(Hq/Hkv). The dense helper normalizes allowed keys per query. The online helper processes legal key blocks, skips blocks with no allowed keys, and rescales old accumulated state whenever a larger score appears. It rejects an entirely masked row rather than returning an invented distribution.

The online implementation checks its weighted-value numerator and denominator after every block, then checks the divided output. It raises ValueError when these intermediates exceed finite floating-point range, even if another evaluation order could produce a representable final average. Finite inputs and scores alone do not guarantee a finite unnormalized numerator.

Worked example / walkthrough#

Example A: Count cache and projection dimensions#

The cache factor2 counts keys and values. These are raw tensor/weight counts excluding allocator, activation, quantization-metadata and communication overhead.

import numpy as np
def scaled_scores(q,k):
    if q.ndim!=2 or k.ndim!=2 or q.shape[1]==0 or q.shape[1]!=k.shape[1]: raise ValueError('positive matching head width required')
    with np.errstate(over='ignore',invalid='ignore',divide='ignore'):
        scores=q@k.T/np.sqrt(q.shape[1])
    if not np.isfinite(scores).all(): raise ValueError('finite computed attention scores required')
    return scores
def dense(q,k,v,allowed):
    scores=scaled_scores(q,k); masked=np.where(allowed,scores,-np.inf)
    if not allowed.any(1).all(): raise ValueError('each query requires a legal key')
    mass=np.exp(masked-masked.max(1,keepdims=True)); return mass/mass.sum(1,keepdims=True)@v
def gqa(q,k,v):
    q,k,v=(np.asarray(value,dtype=float) for value in (q,k,v))
    if any(value.ndim!=3 for value in (q,k,v)) or not len(q) or not len(k) or q.shape[1]==0 or q.shape[2]==0 or v.shape[2]==0 or not all(np.isfinite(value).all() for value in (q,k,v)) or len(q)%len(k) or k.shape[:2]!=v.shape[:2] or q.shape[1:]!=k.shape[1:]: raise ValueError('self-attention grouped head contract')
    group=len(q)//len(k); allowed=np.tri(q.shape[1],dtype=bool)
    return np.stack([dense(q[head],k[head//group],v[head//group],allowed) for head in range(len(q))])
def online_row(scores,values,block_size):
    scores=np.asarray(scores,dtype=float); values=np.asarray(values,dtype=float)
    if scores.ndim!=1 or not len(scores) or values.ndim!=2 or len(values)!=len(scores) or type(block_size) is not int or block_size<=0 or not np.isfinite(scores).all() or not np.isfinite(values).all(): raise ValueError('finite nonempty online row and positive block required')
    maximum=-np.inf; denominator=0.; numerator=np.zeros(values.shape[1]); peak=0
    for start in range(0,len(scores),block_size):
        block=scores[start:start+block_size]; local_values=values[start:start+block_size]; peak=max(peak,len(block))
        new_maximum=max(maximum,float(block.max()))
        with np.errstate(over='ignore',invalid='ignore',divide='ignore',under='ignore'):
            scale=0. if maximum==-np.inf else np.exp(maximum-new_maximum)
            mass=np.exp(block-new_maximum)
            numerator=scale*numerator+mass@local_values
            denominator=scale*denominator+mass.sum()
        if not np.isfinite(numerator).all() or not np.isfinite(denominator) or denominator<=0:
            raise ValueError('finite online attention accumulators required')
        maximum=new_maximum
    with np.errstate(over='ignore',invalid='ignore',divide='ignore'):
        output=numerator/denominator
    if not np.isfinite(output).all(): raise ValueError('finite online attention output required')
    return output,peak
def online_attention(q,k,v,allowed,block_size):
    q,k,v=(np.asarray(value,dtype=float) for value in (q,k,v)); allowed=np.asarray(allowed)
    if any(value.ndim!=2 for value in (q,k,v)) or not len(q) or q.shape[1]==0 or q.shape[1]!=k.shape[1] or len(k)!=len(v) or allowed.shape!=(len(q),len(k)) or allowed.dtype!=np.bool_: raise ValueError('attention shapes and boolean mask required')
    if not allowed.any(1).all() or not all(np.isfinite(value).all() for value in (q,k,v)) or type(block_size) is not int or block_size<=0: raise ValueError('finite legal attention rows and positive block required')
    outputs=[]; peak=0
    for row in range(len(q)):
        maximum=-np.inf; denominator=0.; numerator=np.zeros(v.shape[1])
        for start in range(0,len(k),block_size):
            mask=allowed[row,start:start+block_size]
            if not mask.any(): continue
            keys=k[start:start+block_size][mask]; values=v[start:start+block_size][mask]; scores=scaled_scores(q[row:row+1],keys)[0]; peak=max(peak,len(scores))
            new_maximum=max(maximum,float(scores.max()))
            with np.errstate(over='ignore',invalid='ignore',divide='ignore',under='ignore'):
                scale=0. if maximum==-np.inf else np.exp(maximum-new_maximum)
                mass=np.exp(scores-new_maximum)
                numerator=scale*numerator+mass@values
                denominator=scale*denominator+mass.sum()
            if not np.isfinite(numerator).all() or not np.isfinite(denominator) or denominator<=0:
                raise ValueError('finite online attention accumulators required')
            maximum=new_maximum
        with np.errstate(over='ignore',invalid='ignore',divide='ignore'):
            output=numerator/denominator
        if not np.isfinite(output).all(): raise ValueError('finite online attention output required')
        outputs.append(output)
    return np.stack(outputs),peak
query_heads=4; head_width=2; width=8; time=5
cache_bytes=[2*1*time*kv_heads*head_width*4 for kv_heads in [4,2,1]]
parameters=[width*(query_heads*head_width)+2*width*(kv_heads*head_width)+(query_heads*head_width)*width for kv_heads in [4,2,1]]
assert cache_bytes==[320,160,80] and parameters==[256,192,160]

Expected: raw KV bytes 320, 160, 80; projection weights 256, 192, 160 for model width 8 without biases.

Example B: Verify grouped heads against an equivalent repeated-head oracle#

The comparison manufactures identical shared heads, so parity is expected. It does not say that an arbitrary trained four-KV-head model can be compressed to two heads without changing behavior.

q=np.arange(24,dtype=float).reshape(4,3,2)/10
k=np.arange(12,dtype=float).reshape(2,3,2)/7
v=np.array([[[1.,0.],[0.,2.],[3.,1.]],[[2.,1.],[1.,4.],[5.,2.]]])
grouped=gqa(q,k,v)
expanded_k=np.repeat(k,2,axis=0); expanded_v=np.repeat(v,2,axis=0)
oracle=np.stack([dense(q[h],expanded_k[h],expanded_v[h],np.tri(3,dtype=bool)) for h in range(4)])
assert grouped.shape==(4,3,2); np.testing.assert_allclose(grouped,oracle,atol=1e-12,rtol=0)

Expected: outputs agree within 1e-12; shape(4, 3, 2).

Example C: Trace online softmax at extreme scores#

When the running maximum changes, the old numerator and denominator must both be rescaled. Updating only one produces a plausible butincorrect weighted average.

scores=np.array([1000.,999.,998.]); values=np.array([[1.],[3.],[5.]])
online,peak=online_row(scores,values,2)
mass=np.exp(np.array([0.,-1.,-2.])); expected=(mass@values)/mass.sum()
np.testing.assert_allclose(online,expected,atol=1e-12,rtol=0); assert peak==2 and np.isfinite(online).all()

Expected: finite output equals a maximum-shifted dense calculation.

Controlled case study#

A serving team reduces KV heads from eight to two and observes a fourfold reduction in raw cache bytes. That does not imply a fourfold end-to-end speedup: weight reads, other layers, batching and communication remain. Separately, a blockwise implementation fails after a block with a much larger score because it rescales the denominator but not the numerator. The extreme-score fixture exposes that algebraic error before a GPU benchmark is meaningful.

Common pitfalls and diagnosis#

When grouped outputs disagree with the oracle, inspect group membership and the head axis before changing tolerances. When an online result diverges after a larger score arrives, print the old/new maxima and both rescaled accumulators; rescaling only one is a characteristic error. Use multiple block sizes and a case where the maximum arrives in a later block.

The positive head-width check prevents division by zero, and controlled score calculation rejects overflowed or NaN scores with ValueError. Finite original arrays are not sufficient evidence of finite products. Distinguish raw cache entries, the local largest score block, process peak memory and end-to-end latency. This NumPy program establishes algebraic parity and local storage counts, not a FlashAttention kernel benchmark.
