# Plan 10-01: publish and verify release 1.4.4

## Objective

Publish DS60 1.4.4 only after its source, tests, images, scans, registry
target and tags are verified, then pull and smoke-test the published artifact
(REL-01).

## Tasks

1. Bump every `1.4.3` release reference to `1.4.4`, following the 1.4.3
   release commit `c46e6ad4` (pyproject, `src/ds60sqlpy/__init__.py`,
   `uv.lock` project entry, Dockerfiles, compose files, launchers, project
   READMEs and scripts, docs). Do not touch third-party versions that happen to
   read `1.4.3` (for example the Julia Manifest) or test fixtures that model
   older tags. Run `make generate` so the reference pages follow.
2. Rerun the Phase 9 repository gate on the bumped tree.
3. Commit `Release DS60 1.4.4 [publish-docker]`, push to `main`, then dispatch
   `verify-torch-package.yml` for that exact commit.
4. Watch `Publish images`: qualification, the Phase 8 scan gate, staging and
   promotion. On a transient failure use Re-run failed jobs; never bypass the
   scan gate.
5. After promotion, confirm the native AMD64 and ARM64 pull jobs passed, then
   pull `sadatnfs/ds60sqlpy:1.4.4` locally into a disposable project
   `ds60-p10-smoke`, start App and Core, open a lesson, run Python and SQL, and
   tear it down with `down -v`.
6. Update `docs/dockerhub.md` and the README with the 1.4.4 evidence in a
   follow-up commit without release markers.

## Verification

- Publish run green with 1.4.4 version indexes and latest aliases; pull jobs
  green; local smoke receipt recorded in `10-VERIFICATION.md`.
