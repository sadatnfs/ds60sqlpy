# dbt-005: Source freshness and clock assumptions

## Level and prerequisites

Beginner. Direct prerequisites: `dbt-002`, `dbt-003`

**Outcome:** Define and test a source freshness policy with an explicit clock and response.

## Question and mechanism

Freshness asks whether a source has been updated within a permitted age. It is different from completeness, correctness and event-time coverage. A source can contain a recent timestamp while missing many records, and an old historical dataset can be complete for its intended purpose. Choose the freshness clock and threshold from the consumer's requirement.

The example uses the actual DuckDB clock and constructs a fresh record or a record two days old. A one-hour error threshold distinguishes those cases. The timestamp is explicitly timezone-aware. This is a bounded local check of dbt's freshness behavior, not an observation about an external ingestion service.

The meaning of loaded_at matters. It might represent ingestion completion, upstream publication or a field supplied by the source. If future timestamps, partial loads or clock skew are possible, max(loaded_at) alone can produce a misleading pass. A production contract should combine freshness with coverage, batch identity and relevant consistency checks.

## Syntax and data contract

A source declaration names a schema and table identifier independently of a model. Its loaded_at_field and freshness thresholds define the check. source freshness writes target/sources.json. The program checks its actual pass/error status and uses source() in the model to declare the dependency. Do not confuse this artifact with ordinary model run_results.

## Worked case 1: Check a fresh local source

The first case writes a timestamp near the current UTC time, loads the seed and runs the real freshness command. Its small timing margin is well inside the declared one-hour threshold.

**Expected evidence:** The source freshness status is pass.

```python
import json
import os
import tempfile
from datetime import UTC, datetime, timedelta
from pathlib import Path

import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def freshness_case(stale):
    with tempfile.TemporaryDirectory() as d:
        stamp = datetime.now(UTC) - timedelta(days=2 if stale else 0)
        schema = {
            "sources": [
                {
                    "name": "landing",
                    "schema": "main",
                    "tables": [
                        {
                            "name": "events",
                            "identifier": "raw_events",
                            "config": {
                                "loaded_at_field": "loaded_at",
                                "freshness": {"error_after": {"count": 1, "period": "hour"}},
                            },
                        }
                    ],
                }
            ]
        }
        p = project(
            d,
            models={"events": "select * from {{ source('landing', 'events') }}"},
            seeds={"raw_events": f"id,loaded_at\n1,{stamp.isoformat()}\n"},
            schema=schema,
        )
        invoke(p, "seed")
        invoke(p, "source", "freshness", succeeds=not stale)
        status = artifact(p, "sources.json")["results"][0]["status"]
        assert status == ("error" if stale else "pass"), status
        return {"stale": stale, "status": status}


def example_one():
    return freshness_case(False)


if __name__ == "__main__":
    print(example_one())
```

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Change the threshold

Allow three days for the deliberately old source.

**Check:** A two-day-old source can pass that revised policy.

**Hint:** Thresholds encode a requirement.


### 2. Use a future timestamp

Describe how a future loaded_at value can mislead an age check.

**Check:** The answer calls for a separate future-time validation.

**Hint:** A recent maximum can hide bad clocks.


### 3. Separate event and load time

Give an old event a recent ingestion timestamp.

**Check:** Fresh ingestion does not imply recent event coverage.

**Hint:** There are two different clocks.


### 4. Inspect the artifact

Read sources.json and identify the tested source.

**Check:** The source identifier and status are retained.

**Hint:** This command has a distinct artifact.


### 5. Test partial ingestion

Explain why one recent row cannot prove a complete batch.

**Check:** The answer names a coverage or batch-integrity check.

**Hint:** max alone ignores missing rows.


### 6. Define an action

Specify what happens when freshness fails.

**Check:** The action distinguishes blocking, fallback and investigation.

**Hint:** A diagnostic needs an operational response.


## Diagnose errors and misleading results

A stale-source error can be correct behavior under the declared threshold. Check timestamp parsing, timezone, clock skew and the meaning of loaded_at before increasing the limit. If the source passes but users see missing data, investigate completeness rather than claiming freshness proved everything.
