# c-008: Pointers, addresses and explicit mutation

## Level and prerequisites

Beginner, approximately 90 minutes plus a later retrieval session. Direct prerequisites: `c-007`

## Learning objectives

## Purpose and mental model

A pointer identifies an object or function, or holds a null value. Dereferencing a pointer requires a live target with appropriate type, alignment and access permissions. C does not keep an object alive merely because a pointer still refers to it. A pointer to an automatic local object becomes invalid when that object lifetime ends. Passing a pointer copies the pointer value, while mutation through it can affect the caller-owned target. Prefer an explicit pointer contract over hidden global state. A null check is necessary for optional pointers, but it cannot prove that a non-null pointer still refers to valid storage.

## Vocabulary and concepts

- **Pointer target:** The object a pointer designates.
- **Dereference:** Accessing the target through its pointer.
- **Lifetime:** The interval during which an object exists and may be accessed.

## Syntax anatomy and execution trace

&object obtains an address and *pointer accesses its target. int *p declares a pointer to int. Parentheses matter: *p += 1 changes the target, while p += 1 changes the pointer position. NULL is a null pointer constant. A function can return a pointer to caller-owned or static storage if its lifetime is documented, but must not return a pointer to an expired automatic local.

## Worked example / walkthrough

### Worked example 1: Change a caller-owned value

Increment integer 4 through its address.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

void increment(int *p) { *p += 1; }
bool set_if_present(int *p, int value) {
  if (p == NULL)
    return false;
  *p = value;
  return true;
}
void swap_ints(int *a, int *b) {
  int saved = *a;
  *a = *b;
  *b = saved;
}

int main(void) {
  /* Change a caller-owned value */
  {
    int n = 4;
    increment(&n);
    CHECK(n == 5);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The caller value becomes 5.

The helper receives a pointer copy, but that copy still designates the original integer.

### Worked example 2: Read a target copy

Copy the integer behind a pointer, then change the target.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

void increment(int *p) { *p += 1; }
bool set_if_present(int *p, int value) {
  if (p == NULL)
    return false;
  *p = value;
  return true;
}
void swap_ints(int *a, int *b) {
  int saved = *a;
  *a = *b;
  *b = saved;
}

int main(void) {
  /* Change a caller-owned value */
  {
    int n = 4;
    increment(&n);
    CHECK(n == 5);
  }

  /* Read a target copy */
  {
    int n = 3;
    int *p = &n;
    int copy = *p;
    *p = 9;
    CHECK(copy == 3 && n == 9);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The copied value stays 3 and the target becomes 9.

Dereferencing to obtain an int copies that scalar value. Retaining the pointer would retain access to future target changes.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
