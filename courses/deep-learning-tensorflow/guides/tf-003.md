## Purpose and mental model

A linear neuron combines input features with weights. An affine neuron also adds a bias, a fixed offset shared across observations. Rather than hiding this calculation inside a neural-network layer, we will perform it directly as a matrix product. The row axis will represent observations, the middle dimension will represent input features, and the final axis will represent output coordinates.

The expression X @ W + b is compact but carries several contracts. The number of columns in X must match the number of rows in W. The bias must describe output coordinates rather than input features or observation IDs. A result with a convenient shape is not enough: the first output should be recoverable from its individual multiplications and addition.

This is also a model interface. A caller who changes feature order or units has changed the meaning of X without necessarily changing its shape. We will use fixed numeric fixtures so you can diagnose the difference between a dimension error that raises immediately and a semantic error that quietly returns numbers. No TensorFlow layer, optimizer or training dataset is required yet.

## Vocabulary and concepts

**Feature matrix:** a two-dimensional array with one observation per row and one measured feature per column.

**Weight matrix:** a map from input-feature coordinates to output coordinates, with one row per input feature.

**Bias:** an offset per output coordinate that is added to every observation; it is not one free value per input record.

**Affine map:** a matrix product plus a bias, in contrast to a purely linear map with zero offset.

**Batch:** the observations processed together; changing batch size does not create new feature coordinates.

## Syntax or reasoning anatomy

For X shaped (batch,features) and W shaped (features,outputs), the @ operator sums products over the shared features axis. The resulting shape is (batch,outputs). A scalar bias is suitable for one shared scalar offset. A vector bias of length outputs adds the corresponding offset to each output column. A feature-length vector is generally not the right bias.

For this helper, require two nonempty matrices, matching input widths, a scalar or output-length bias, and finite values. These checks do not establish feature order or units; keep those as a separate declared schema. In a one-output model, the (batch,1) result is intentionally a column. Do not confuse that correct layer layout with the paired rank-one residual policy from the previous lesson. Each function must state its own boundary.

## Worked example / walkthrough

### Example A: Recover a scalar output by hand

Use the fixed two-record feature matrix and one-output weight. Calculate the first row before executing.

```python
import numpy as np

X = np.array([[1, 2, 3], [0, 1, 0]], dtype=np.float64)
W = np.array([[1], [0], [-1]], dtype=np.float64)
result = X @ W + 2
np.testing.assert_array_equal(result, [[0], [2]])
print(result)
```

**Expected:** The first row is 1*1 + 2*0 + 3*(-1) + 2 = 0. The second is 0*1 + 1*0 + 0*(-1) + 2 = 2. Two observations produce two rows, each with one output.

### Example B: A bias can create a plausible wrong shape

Change only the bias to an input-feature-length vector. Observe what plain broadcasting permits.

```python
wrong = X @ W + np.array([2, 3, 4])
assert wrong.shape == (2, 3)
np.testing.assert_array_equal(wrong, [[0, 1, 2], [2, 3, 4]])
print(wrong)
```

**Expected:** The matrix product is still (2,1), but adding (3,) broadcasts into three output columns. A declared one-output interface should reject this bias before addition.

## Exercises

1. **Trace the product.** Write all multiply/add terms for both rows of the first example, then execute it.
   **Expected:** Result [[0],[2]] with shape (2,1).
   **Verify:** Assert both output values and recover the first zero from four written terms.

2. **Add an observation.** Append row [3,0,0] to X without changing W or the bias.
   **Expected:** The result is [[0],[2],[5]] with shape (3,1).
   **Verify:** Compare the original two output rows unchanged and assert the new scalar is 5.

3. **Reject incompatible features.** Implement affine(X,W,bias), then pass a (2,3) X with a (2,1) W.
   **Expected:** A ValueError explains the input-feature mismatch before a matrix product is attempted.
   **Verify:** Capture the mismatch exception and inspect the accepted (2,3) @ (3,1) result afterward.

4. **Guard the bias axis.** Reject bias [2,3,4] for the one-output model while accepting scalar 2 and output vector [2].
   **Expected:** Scalar and length-one vector biases give the same [[0],[2]]; feature-length bias raises ValueError.
   **Verify:** Assert equality of the two accepted outputs and capture the rejected bias case independently.

5. **Extend to two outputs.** Use W=[[1,0],[0,1],[-1,1]] and bias [2,-1] on the original X.
   **Expected:** The result is [[0,4],[2,0]] with shape (2,2).
   **Verify:** Check each output column by hand and assert the complete matrix, not just its shape.

6. **Preserve a prediction under unit conversion.** For X=[[100],[200]] centimeters, W=[[0.02]] and bias 1, convert X to meters and choose the corresponding new W.
   **Expected:** The centimeter model and meter model with W=[[2]] both predict [[3],[5]].
   **Verify:** Assert both predictions agree and explain why changing X alone while retaining 0.02 would alter the model.

## Progressive hints

- **Hint 1:** Write batch, features and outputs beside the three axes before using @.
- **Hint 2:** Calculate one output as a dot product plus one bias; this catches mistakes a shape-only test cannot.
- **Hint 3:** Bias length follows outputs, while a unit conversion may require an inverse change in the corresponding weight.

## Common pitfalls

If @ raises a dimension mismatch, write the two shape tuples and circle the shared feature dimension before transposing anything. Blind transposes can make dimensions compatible while moving the observation axis. If an addition unexpectedly creates extra columns, print the bias shape and compare it with the output width. If the shape is correct but a prediction changes after a data export, inspect feature order and units.

A single number called bias is shared across records, not fitted separately to each held-out target. Adding one target-specific offset per record would leak the answer into the prediction. Reject empty and nonfinite requests explicitly; the absence of an exception from NumPy does not establish the model's domain contract.
