## Outcome and mechanism

Use exported namespace-qualified functions and inspect a local package source layout without confusing sourced definitions with an installed package.

A package namespace separates names that belong to one package from names in the current workspace. stats::median selects an exported function even when another function called median is present in the global environment. library attaches exported names to the search path for convenience; it does not make every unqualified name immune to masking. Namespace qualification is useful when the originating dependency is part of the analytical contract.

The double-colon operator accesses exported objects. Triple-colon access reaches implementation details that the package author has not offered as a stable public interface. A function being reachable is not a reason to depend on it. getNamespaceExports and getExportedValue provide inspectable public interfaces without guessing internal names. Use the exact prepared package and record versions when behavior matters.

A minimal package source tree has DESCRIPTION metadata, a NAMESPACE declaration and R source files beneath R/. DESCRIPTION lists dependencies, while NAMESPACE controls exports and method registrations. Listing a package in Imports records a dependency; it does not by itself attach that package or make every function available without qualification. Names prefixed with a dot are conventional internal names, not access-control guarantees.

The worked tree exports observed_mean while keeping its helper out of NAMESPACE. The script writes only to its own temporary directory, parses the source and evaluates its own authored definitions in a new environment. This is a local source-layout demonstration. It does not install a package, create an actual package namespace, test lazy loading or run R CMD check. The cleanup handler deletes that temporary tree when the demonstration returns.

For a real reusable package, continue in a separately prepared multi-file contributor workspace: maintain DESCRIPTION and NAMESPACE, document public functions, add tests, build and install locally, then run R CMD check. Those steps need their own file/project workflow. The classroom pad runs one main.R and does not turn a temporary demonstration directory into a permanent downloadable package.

Choose dependencies because they supply a needed public behavior. A small mean function uses base code; a statistical density can call stats::dnorm explicitly. Avoid installing packages inside analytical lesson code. The classroom dependencies are prepared separately, and source execution remains offline. Tests should establish numerical outputs, dependency resolution and public-interface boundaries without treating a package scaffold as installation evidence.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Namespace | A package-specific environment and name-resolution boundary. |
| Export | A name the package exposes through its public interface. |
| Imports | A DESCRIPTION dependency field, distinct from attaching a package to the search path. |
| NAMESPACE | The package file declaring exports, imports and method registrations. |

## Read the syntax

stats::median resolves an exported name regardless of a global median binding. getExportedValue("stats","median") retrieves that public function. read.dcf reads DESCRIPTION metadata; parse validates R syntax. sys.source here evaluates only the script's own local definitions in a chosen environment and does not emulate package installation.

## Worked examples

### Example 1: Qualification survives a masked name

```r
median <- function(x, ...) -999
x <- c(1, 4, 9)
stopifnot(median(x) == -999, stats::median(x) == 4)
public <- getExportedValue("stats", "median")
stopifnot(public(x) == 4, "median" %in% getNamespaceExports("stats"))
print(c(masked = median(x), qualified = stats::median(x)))
```

**Expected observation:** Masked result -999; exported stats result 4.

The deliberately masked global name shows why dependency-qualified calls carry useful information. The exported function remains available through the namespace without depending on the search-path ordering.

### Example 2: Inspect a bounded package-shaped source tree

```r
inspect_local_package <- function() {
  root <- tempfile("measurekit-")
  dir.create(root)
  on.exit(unlink(root, recursive = TRUE), add = TRUE)
  dir.create(file.path(root, "R"))
  writeLines(c(
    "Package: measurekit", "Version: 0.0.1", "Title: Local Contract Example",
    "Description: Demonstrates a bounded package source layout.",
    "License: MIT", "Authors@R: person('Example', 'Author', role=c('aut','cre'), email='example@example.invalid')",
    "Imports: stats"
  ), file.path(root, "DESCRIPTION"))
  writeLines("export(observed_mean)", file.path(root, "NAMESPACE"))
  definition <- c(
    ".validate <- function(x) {",
    "  if (!is.numeric(x) || any(!is.finite(x))) stop('finite numeric values required')",
    "  x", "}",
    "observed_mean <- function(x) {",
    "  x <- .validate(x)",
    "  if (!length(x)) return(NA_real_)",
    "  mean(x)", "}"
  )
  writeLines(definition, file.path(root, "R", "summary.R"))
  metadata <- read.dcf(file.path(root, "DESCRIPTION"))
  stopifnot(metadata[1, "Package"] == "measurekit")
  stopifnot(identical(readLines(file.path(root, "NAMESPACE")), "export(observed_mean)"))
  parsed <- parse(file.path(root, "R", "summary.R"), keep.source = FALSE)
  stopifnot(length(parsed) == 2L)
  environment <- new.env(parent = baseenv())
  sys.source(file.path(root, "R", "summary.R"), envir = environment)
  stopifnot(environment$observed_mean(c(2, 4)) == 3)
  list(files = sort(list.files(root, recursive = TRUE)), mean = environment$observed_mean(c(2, 4)))
}

result <- inspect_local_package()
stopifnot(identical(result$files, c("DESCRIPTION", "NAMESPACE", "R/summary.R")), result$mean == 3)
print(result)
```

**Expected observation:** Three expected source files and mean 3; the temporary directory is removed.

The temporary files demonstrate metadata, exports and source placement. Evaluating the known definitions proves their local behavior, while the guide explicitly separates that from installation and package-check evidence.
