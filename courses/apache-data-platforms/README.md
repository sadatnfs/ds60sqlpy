# Apache and open data platforms

An original 88-unit tutorial route from storage/transport/execution contracts to
columnar interchange, embedded/distributed query, orchestration, streaming,
stateful databases, analytical serving, catalogs, governance and open sharing.
Each chapter explains vocabulary/mechanisms, two changed-condition worked cases,
plausible mistakes and an answered interview discussion. Complete worked source
is visible; there are no compulsory exams or hidden answer gates.

## Choose a supported execution path

Ordinary Python examples use actual Arrow 23.0.1, DataFusion 55 and PyIceberg 0.12
in the prepared data-platforms-python image. Distributed/service chapters open
editable Markdown command notebooks. The classroom does not execute Docker
commands from those pads and does not mount an engine socket into workers.

Each project is copied into a learner-owned work directory and has explicit
preparation/lifecycle boundaries. Read its qualification file before asserting
that a feature ran. Component acceptance does not establish an unexecuted combined
Kafka/Flink/Pinot or Hive/Atlas topology. Native ARM64 and native AMD64 are separate
acceptance gates; no local AMD64 emulation is used.

The maintained [qualification ledger](authoring/ENVIRONMENTS.md) distinguishes
actual native runs, prepared source and omitted local-server routes. Atlas's
Java 8/backing-stack boundary and current Sharing native-wrapper availability
are explicit. Their portable plan actions do not contact or simulate a server.

## Maintained source

Read [authoring guidance](authoring/README.md), the [design](DESIGN.md), and
[project instructions](AGENTS.md). Durable sources are authoring/chapters,
authoring/programs and authoring/units. Generated guides/examples are refreshed
by authoring/build.py; shared HTML is generated by the repository tools.
The complete route must pass explicit admission before track/lessons registration.

Use the existing Rust, Java, Scala/Spark, Python and SQL foundations when a project
needs them. A programming language, an ordinary worker profile and a distributed
service are different capabilities. The final capstone selects one coherent
actual supported path and records source, result, failure and recovery evidence.
