# web-004: Links, paths, navigation and usable destinations

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-003`

## Learning objectives

Build a contents list that navigates to three local sections. Explain the difference between absolute, root-relative and document-relative paths. Use URL, relative path and fragment accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

A URL identifies a resource and can contain a scheme, host, path, query and fragment. A relative path is resolved against a base URL; it is not resolved against the author's mental picture of a folder. A fragment such as #methods identifies a location within the current document and does not require another document to exist. An anchor with href provides navigation semantics and keyboard behavior automatically.

Good link text tells a reader the destination or action. A page full of links named click here loses meaning when links are read as a list. A link navigates; a button changes application state or submits an action. Styling a paragraph blue does not create link behavior, and adding a click listener does not automatically provide keyboard support.

### Key terms

- **URL:** The address of a resource, made of parts such as the scheme, host, path, query and fragment.
- **Relative path:** A link target such as `../about.html` that the browser resolves against the current document's location.
- **Fragment:** The part of a URL after `#` that identifies a location inside a document, usually an element with a matching `id`.
- **Link text:** The visible words of a link, which should describe its destination so the link still makes sense out of context.

## Syntax anatomy and mechanism

Use `href="#details"` with a unique `id="details"` for this offline lesson. A leading slash means a path from the origin root, while `../` moves one directory upward relative to the base path. Production external links may need a new-window notice and suitable rel values; do not open new tabs by default merely to keep a user on your site.

## Worked example / walkthrough

### Worked example 1: Within-page navigation

A fragment is enough for a self-contained document.

```html
<a href="#methods">Read the methods</a>
<section id="methods"><h2>Methods</h2></section>
```

**Expected observation:** The navigation target is the methods section.

### Worked example 2: Link versus button

Choose the element before its styling.

```html
<a href="#results">View results</a>
<button type="button">Toggle details</button>
```

**Expected observation:** The link navigates; the button requires an implemented action.

## Contrast case: a fragment link that misses its target by one character

The starter fixture contains this kind of defect, so practice spotting it from the source and from the URL bar.

```html
<nav aria-label="Contents">
  <a href="#method">Methods</a>
  <a href="#results">Results</a>
</nav>
<section id="methods"><h2>Methods</h2></section>
<section id="results"><h2>Results</h2></section>
```

Activating Results scrolls to its section because `#results` equals the `id`. Activating Methods changes the URL fragment to `#method`, but no element has that `id`, so nothing scrolls and the page stays where it was. Fragment matching is exact, including case, so `#Results` would also miss. The fix is to make the `href` and the `id` identical, which `document.getElementById('method')` returning null confirms before and after the repair.

## Six progressive exercises

Exercises that ask you to predict, explain, compare or diagnose keep their answers in the solutions file. The others show the evidence to look for.

### Exercise 1: Resolve ../images/plot.svg from /notes/week1/page.html.

**Progressive hint:** Remove the file name first, then let each .. remove one directory.

### Exercise 2: Replace vague link text with destination-specific wording.

**Expected evidence:** The link makes sense outside its surrounding sentence.

**Progressive hint:** Read only the link text aloud, as a screen-reader list of links would.

### Exercise 3: Build a contents list that navigates to three local sections.

**Expected evidence:** Every fragment matches one unique section id and works with keyboard activation.

**Progressive hint:** Give each section a unique id first, then write one href with a matching fragment for each.

### Exercise 4: Diagnose a link whose fragment has no matching id.

**Progressive hint:** Copy the fragment from the href and search the document for exactly that id, including letter case.

### Exercise 5: Distinguish a disabled action from an unavailable destination.

**Progressive hint:** Ask whether the item performs an action, which is a button, or navigates, which is a link.

### Exercise 6: Explain the difference between absolute, root-relative and document-relative paths.

**Progressive hint:** Resolve one example of each kind from the same page, then imagine moving the page to another directory.

## Debugging and common mistakes

Do not test relative paths only from an editor preview with a special base. Avoid `href="#"` as a fake action. The classroom sandbox blocks external network behavior deliberately; use local fragments here.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
