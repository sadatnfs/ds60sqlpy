## Read the decoder as a sequence of transformations

A decoder can look intimidating when its components arrive as one class definition. Start instead with the question it must answer: for every supplied prefix position, produce scores for the next token. The input is therefore an integer array of token IDs, while the output is a floating-point array with one vocabulary score vector per input position. The internal layers repeatedly transform a representation of each token occurrence while respecting the causal information boundary.

Use B for batch size, T for the number of input positions, V for vocabulary size and D for feature width. In the lesson's model, \(V=16\) and \(D=32\). A one-sequence, four-token input has shape [1,4]. Token lookup produces [1,4,32]. A position table supplies a 32-feature vector for each of those four locations, which is added to the token vectors. The addition keeps the shape but changes the information represented: two identical token IDs at different positions can now start with different vectors.

The first sublayer normalizes each token's features, then projects them into queries, keys and values. The combined projection has output width 3D=96, later split into three width-32 arrays. Two heads reorganize each into [1,2,4,16]. Query/key comparisons produce scores [1,2,4,4], whose last axis enumerates candidate key positions. The causal mask removes future keys separately for every query. The weighted values return [1,2,4,16], then rejoining heads restores [1,4,32]. A learned projection and residual addition produce the next token representation.

The feed-forward sublayer takes each width-32 token vector through a width-64 hidden transformation and back to width 32, with a nonlinearity between the two linear maps. It does not mix token positions. A second residual addition keeps an input path alongside that learned update. Finally, the output projection maps each 32-feature representation to 16 vocabulary logits, producing [1,4,16]. Softmax is not needed inside the model if the loss function expects logits and performs its own stable normalization.

This shape trace explains why the model is a decoder rather than simply a collection of matrix multiplications. Each output row is tied to a position and a prediction event. The first row may depend only on the first input token and its position; the last row may use the complete supplied prefix. If a future input changes an earlier output, some path violated that contract. The literal prefix tests below rerun the model rather than merely slicing its output, so they challenge the entire forward computation.

The model has 10,464 learned scalars under the exact layer definitions below. That count includes embeddings, projections, feed-forward biases and normalization parameters; it is not the number of values in one input batch. Training changes those shared scalars. Longer inputs create more activation values and attention scores without creating new copies of the parameters. The subsequent ledger distinguishes these quantities explicitly.

At this stage the decoder is initialized, not trained into a competent language model. Correct shapes, causal behavior and cache parity establish its mechanics. Learning useful probability assignments requires a valid target batch, a loss, an optimizer and evidence from held-out data. That progression is the purpose of the next chapters.
