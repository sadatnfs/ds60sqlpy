llm-047: Sparse experts, routing capacity and load balancing#

Level and prerequisites#

Advanced; approximately 210 minutes. Direct prerequisites: llm-046. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

A mixture-of-experts layer routes each token to a subset of specialized transformations. The central investigation is concrete: Use experts I, 2I, -I and three token/router rows with selected probabilities 3/4 and 1/4. The finish condition is outputs[1.25, 0], [0, 1.75], [-.25, -.25]. invalid policies raise ValueError; top-2 tie indices 0, 1. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Let a router choose computation, then account for every consequence#

A mixture-of-experts layer gives a token several possible transformations and uses a router to select a subset. The intended benefit is conditional computation: a model can store many expert parameters while evaluating only some of them for each token. That description leaves several important questions open. How are selected outputs weighted? What happens at a tie? How many tokens can one expert accept? Which paths receive gradients? The answers define the actual model.

The fixture uses literal linear experts rather than trained semantic specialists. With matrices I,2I and-I, the experts preserve, double or negate an input vector. Calling them experts describes their architectural role, not a demonstrated domain skill. Their simple transformations let us see exactly how routing changes the output without attributing learned knowledge to the toy model.

Separate scores, assignments and gates#

For token t, the router produces E scores z_t1,...,z_tE. A top-k rule selects a set S_t of expert indices. A gate rule then assigns weights to the selected outputs. This lesson computes a softmax over all scores and renormalizes the selected mass, which is equivalent to a softmax restricted to the selected scores while the selection remains fixed.

With selected probabilities 3/4 and 1/4 and expert outputs x and 2x, the mixture is(3/4)x+(1/4)2x=1.25x. If the selected experts instead produce-x and 2x with the same weights, the result is-.25x. The gate weights are nonnegative and sum to one, but the output features can be negative because the expert outputs are vectors, not probabilities.

Retaining the original selected probabilities without renormalization would define a different scale, especially if substantial mass lies on unselected experts. Using a unit-weight top-1 delta inside a residual branch defines another policy. These are not interchangeable implementation details. State the formula before comparing gradients or quality.

Understand the piecewise-smooth function#

Within a fixed selected set, the normalized gate g_i is exp(z_i)/sum_(j in S)exp(z_j). For scalar expert outputs e_i, mixture y=sum_i g_i e_i has derivative dy/dz_j=g_j(e_j-y). The derivative is smooth as long as the selected identities do not change. A common shift of all selected scores cancels, so the derivatives over those scores sum to zero.

At a top-k boundary, selection can change discontinuously. The reference uses a stable sorting policy so equal scores choose lower indices deterministically. That makes the discrete result reproducible but does not make the boundary differentiable. A finite-difference check near a tie can compare two different selected sets rather than the intended smooth local derivative.

Top-1 with selected-mass renormalization illustrates an important limit. The single selected gate becomes 1, so its local derivative with respect to the router score is zero while assignment remains unchanged. Main-task loss through that normalized gate alone cannot supply the same router signal as a policy retaining the selected full-softmax probability. An auxiliary objective or another routing/training choice may therefore matter. The word top-1 does not specify the entire learning mechanism.

Capacity can be exhausted unevenly#

Capacity limits the number of assignments an expert accepts in a batch. A common planning form is C=ceil(ckT/E), where T is token count, k assignments per token, E experts and c a capacity factor. This formula describes a nominal per-expert allocation under a balanced-load expectation. It does not ensure that actual routing is balanced or that every token will be admitted.

For T=4,E=2,k=1,c=1, capacity is 2 per expert. The fixture assigns tokens to experts[0,0,1,0], producing counts[3,1]. Expert 0 overflows by one while expert 1 has an unused slot. Total nominal capacity equals total assignments, yet one token still cannot use its chosen expert. This is a concrete reason that average utilization can hide a bottleneck.

The reference admits assignments in input order and preserves the overflowing token's residual input while dropping its expert delta. The token remains in the sequence and in any later loss denominator. Reordering the batch can change which token overflows even when assigned counts remain[3,1]. Record token identities, accepted assignments and drop flags, not just the histogram.

Other systems may reroute, use a different priority policy, increase capacity or apply another fallback. Each changes behavior and resource use. Increasing capacity can reduce drops but requires more activation buffers and may change worst-case work. A capacity-factor name alone does not establish which policy was executed.

Read the balancing objective under its stated approximation#

For the top-1-style auxiliary calculation, f_i is the fraction of hard token assignments to expert i and P_i is mean router probability for that expert. The term alphaEsum_i f_i P_i encourages a relationship between hard load and probability mass. In a local gradient calculation, f is treated as fixed while gradients flow through the soft probabilities.

With f=[.75,.25],P=[.7,.3],E=2 and alpha=.01, the value is .012(.75.7+.25.3)=.012. The balanced fixture f=P=[.5,.5] yields .01. This comparison illustrates the formula on two states; it does not establish a universal lower bound or prove that lowering the auxiliary term always improves task accuracy or eliminates capacity overflow.

For one token among T, the local derivative with respect to score j is alpha*E/T times p_j[f_j-sum_i f_i p_i]. If a token gives substantial probability to an already heavily assigned expert, the derivative can push that score down under gradient descent. But the hard assignment counts can change at a routing boundary, and the main task objective can prefer a different tradeoff. Monitor both objectives and actual dispatch outcomes.

Count stored and activated parameters separately#

For E experts each containing bias-free matrices D-by-H and H-by-D, total expert weights are 2EDH. A token selecting k experts activates k of those transformations, corresponding to 2kDH expert weights in this simple count. With E=8,D=64,H=128,k=2, the totals are 131072 stored expert weights and 32768 selected expert weights per token, excluding the router and other model components.

The selected-weight count is not a complete compute or memory bill. Expert weights must be stored somewhere, routing has overhead, and activation dispatch can require communication between devices. Small batches may underutilize large matrices; skewed assignments can make one expert the critical path. A model with sparse activation is not automatically as cheap to serve as a dense model with the same active-parameter count.

A distributed expert-parallel system additionally needs to preserve token identity during dispatch and recombination. Outputs must return to the correct original positions with the correct gates. Network failures, stragglers and padded capacity slots introduce operational concerns absent from this local NumPy fixture. The Switch Transformer study provides a broader learned-system example; this chapter exposes the smaller contracts that such a system must implement.

Diagnose whether the problem is routing, capacity or the task#

If output values disagree, inspect selected indices, gate normalization and expert matrices before interpreting task quality. If local gradients disagree, check whether top-k membership changed during the perturbation. If capacity drops occur, preserve which tokens were affected and whether their errors differ from admitted tokens. A balanced load plot cannot prove that the experts learned useful transformations.

A meaningful model study compares held-out task behavior, resource use and routing statistics under a fixed data and evaluation contract. It may find that more balanced routing improves throughput while changing accuracy, or that a higher capacity reduces drops at an unacceptable memory cost. These are measured tradeoffs, not consequences that follow from the sparse architecture's name.

Design decisions and when to use this method#

Use sparse experts when the architecture, training and serving stack can support conditional computation and its routing overhead. Measure token load distributions and tail behavior, not just mean expert utilization. Keep capacity, tie handling, gate normalization and overflow policy in the artifact contract.

Do not claim that a model with many total parameters has the compute cost of a small dense model without accounting for router work, expert shapes, communication and batching. This CPU reference executes small matrices locally and does not verify distributed dispatch, network bandwidth or hardware throughput. A real expert-parallel acceptance test needs those measurements and failure/straggler behavior separately.

Derivation and shape trace#

For token x_t, let router probabilities p_t=softmax(z_t), and let S_t be its selected top-k expert set. This reference uses g_ti=p_ti/sum_(j in S_t)p_tj for selected experts and zero otherwise. The output is y_t=sum_i g_ti E_i(x_t). Retaining the original selected probabilities instead would define a different gate policy.

Within a fixed selected set, a scalar mixture has derivative dy/dz_j=g_j(e_j-y). With expert outputs 1 and 2 and gates 3/4 and 1/4, y=5/4 and the first-logit derivative is (3/4)(1-5/4)=-3/16. A change in top-k membership introduces a hard selection boundary, so this local derivative must not be described as differentiating every routing decision.

A Switch-style auxiliary term is L_aux=alphaNsum_i f_i P_i. Here f_i is the fraction of hard assignments to expert i, and P_i is the mean router probability. The hard fraction vector is not differentiable; the probability vector is. For T tokens and fixed f, the derivative for one logit is alphaN/T p_tj * (f_j-sum_i f_i p_ti). The coefficient .01 is a declared fixture setting.

For E experts with two bias-free matrices D-by-H and H-by-D, total expert weights are 2EDH. Top-k activates k experts per token, but storage and communication still depend on placement and serving of all E experts.

Routing has a smooth interior and a discrete boundary#

A mixture-of-experts block first computes router scores z_ti for token t and expert i. A top-k operation selects a set S_t, and a gate rule combines selected expert outputs. Within one fixed selected set, this lesson renormalizes the selected probabilities. Since the full-softmax denominator cancels, selected gate g_i equals exp(z_i)/sum_(j in S) exp(z_j). Scores of unselected experts have no effect on that normalized mixture until they cross the selection boundary. This local statement is essential when interpreting a finite-difference router gradient.

For selected scalar expert outputs e_1=1,e_2=2 and gates[3/4,1/4], the mixture y is 5/4. Differentiating with the selected set held fixed gives dy/dz_j=g_j(e_j-y). Thus the first derivative is(3/4)(1-5/4)=-3/16 and the second is+3/16. Raising the score of the smaller-output expert lowers this scalar output. The derivatives sum to zero because a common shift of selected scores leaves their softmax unchanged. The fixture's finite difference verifies this smooth local behavior, not a derivative through every top-k identity change.

At a routing tie, a small perturbation can change which expert is selected. The reference makes ties deterministic by stable descending sorting, so a lower index wins an equal score. Deterministic does not mean differentiable. Finite-difference checks should stay away from membership boundaries when testing the smooth formula, then test the boundary behavior separately as a discrete policy. If a gradient estimate changes dramatically with step size near a tie, the first question is whether the selected expert set changed.

For top1 with renormalization among selected experts, the only selected gate is exactly1. Within a fixed assignment, the main expert-mixture output has zero derivative with respect to the router score through that gate. Training the router then requires another mechanism, such as a different gating convention or an auxiliary signal. Retaining the selected probability from the full softmax would produce a different gradient and output scale. The capacity example deliberately uses a unit-weight top1 expert delta in a residual path, so it must not be presented as every sparse-transformer implementation's training rule.

Capacity adds an admission policy after assignment. The example assigns counts[3,1] to two experts, each with capacity 2. Only two of expert 0's three tokens are admitted, leaving accepted counts[2,1] and one overflow. The dropped token is not removed from the sequence or loss denominator; its output keeps the residual input while omitting the expert delta. With input[2,1], that fallback remains[2,1]. Silently dropping its entire output row would change sequence alignment and the evaluation unit.

The implementation admits tokens in input order. Reordering a batch with the same assigned counts can therefore change which token overflows and which task predictions are affected. Load counts alone cannot reveal that fairness or quality effect. A production policy could select by gate confidence, reserve capacity or use another dispatch scheme, but each choice defines different behavior and needs an explicit acceptance test. Increasing capacity reduces some drops while increasing activation buffers and potentially changing worst-case work.

For T tokens and N experts, let f_i be the fraction of hard assignments and P_i the mean router probability. The auxiliary term is alphaNsum_i f_i P_i. In a local derivative that treats the hard f as fixed, one token's score derivative is alpha*N/T times p_tj[f_j-sum_i f_i p_ti]. This reveals what can receive a gradient: the probability path, not the discrete counts. For f=[.75,.25],p_t=[.7,.3],N=2,T=4,alpha=.01, the derivatives are+.000525 and-.000525. Gradient descent pushes this token's probabilities away from the more heavily assigned expert under the fixed-count local approximation.

Balanced f=P=[.5,.5] gives the stated .01 fixture value, while f=[.75,.25],P=[.7,.3] gives.012. These two calculations do not prove that .01 is a universal lower bound over every feasible collection of routing distributions, nor that reducing the auxiliary term necessarily improves task loss. Monitor assigned counts, accepted counts, dropped tokens, per-family errors and the main objective together. The auxiliary coefficient trades off objectives and must not be interpreted as a stand-alone quality metric.

Sparse activation also differs from storage. With E experts each containing two bias-free matrices D-by-H and H-by-D, stored expert weights total 2EDH even if only k experts execute per token. Distributed dispatch requires transporting activations to selected experts and combining their outputs. Uneven loads, synchronization, communication and padding can dominate wall-clock cost. The local linear experts do not measure these effects or reproduce the Switch Transformer training system.

Interview reasoning: "Does activating only two experts make an enormous model as cheap as a small dense one?" It reduces one category of active expert computation under the stated shapes. Total weight storage, routing, dispatch, memory traffic and latency remain. State the counted operations first, then measure the actual system rather than converting an active-parameter count directly into a speed claim.

Vocabulary and concepts#

Sparse expert activation: Evaluating only selected experts for each token.

Router: A function producing expert-selection scores for each token.

Capacity: A bound on tokens admitted to an expert in one batch.

Load-balancing loss: An auxiliary objective encouraging a less concentrated routing distribution.

Expert parallelism: Placing different experts on different devices and moving activations between them.

Syntax anatomy and reasoning sequence#

Inputs have shape(tokens, model_width), router logits(tokens, experts), and expert matrices(experts, model_width, output_width). Stable descending argsort declares a lowest-index tie policy. The selected gates are normalized before combining expert outputs. The capacity helper tracks assigned counts, accepted counts and dropped-token flags separately. A Switch-style auxiliary term uses hard assignment fractions f and mean router probabilities P, with the hard fractions held fixed for a local gradient calculation.

Worked example / walkthrough#

Example A: Calculate a top2 expert mixture#

The third token combines a negative expert with a positive expert, so routing can change the function ratherthan merely selecting a faster implementation of the same computation.

import numpy as np
def softmax_rows(logits):
    logits=np.asarray(logits,dtype=float)
    if logits.ndim!=2 or not logits.shape[1] or not np.isfinite(logits).all(): raise ValueError('finite router matrix required')
    mass=np.exp(logits-logits.max(1,keepdims=True)); return mass/mass.sum(1,keepdims=True)
def mixture(x,logits,experts,k):
    x,logits,experts=(np.asarray(value,dtype=float) for value in (x,logits,experts))
    if x.ndim!=2 or logits.ndim!=2 or experts.ndim!=3 or len(x)!=len(logits) or logits.shape[1]!=len(experts) or x.shape[1]!=experts.shape[1] or type(k) is not int or not 1<=k<=len(experts): raise ValueError('expert shapes and top-k required')
    probabilities=softmax_rows(logits); indices=np.argsort(-logits,axis=1,kind='stable')[:,:k]; selected=np.take_along_axis(probabilities,indices,axis=1); gates=selected/selected.sum(1,keepdims=True)
    output=np.zeros((len(x),experts.shape[2]))
    for row in range(len(x)):
        for slot,expert in enumerate(indices[row]): output[row]+=gates[row,slot]*(x[row]@experts[expert])
    return output,indices,gates
def capacity_route(x,logits,experts,capacity):
    x,logits,experts=(np.asarray(value,dtype=float) for value in (x,logits,experts))
    if type(capacity) is not int or capacity<=0 or experts.shape[1:]!=(x.shape[1],x.shape[1]) or logits.shape!=(len(x),len(experts)): raise ValueError('positive capacity and square expert shapes required')
    chosen=np.argmax(logits,axis=1); assigned=np.bincount(chosen,minlength=len(experts)); accepted=np.zeros(len(experts),dtype=int); dropped=np.zeros(len(x),dtype=bool); output=x.copy()
    for row,expert in enumerate(chosen):
        if accepted[expert]>=capacity: dropped[row]=True; continue
        output[row]+=x[row]@experts[expert]; accepted[expert]+=1
    return output,dropped,assigned,accepted
x=np.array([[1.,0.],[0.,1.],[1.,1.]])
experts=np.stack([np.eye(2),2*np.eye(2),-np.eye(2)])
logits=np.array([[np.log(3),0.,-100.],[0.,np.log(3),-100.],[-100.,0.,np.log(3)]])
output,indices,gates=mixture(x,logits,experts,2)
np.testing.assert_allclose(output,[[1.25,0],[0,1.75],[-.25,-.25]],atol=1e-12,rtol=0)
np.testing.assert_allclose(gates.sum(1),1,atol=1e-12,rtol=0)

Expected: outputs[1.25, 0], [0, 1.75], [-.25, -.25].

Example B: Enforce expert capacity with residual fallback#

The dropped token is not deleted from the sequence or loss denominator. Its residual path is explicit, and the drop count remains available for quality and load analysis.

tokens=np.array([[1.,0.],[0.,1.],[1.,1.],[2.,1.]])
route_logits=np.array([[5.,0.],[4.,0.],[0.,4.],[3.,0.]])
residual,dropped,assigned,accepted=capacity_route(tokens,route_logits,experts[:2],2)
assert assigned.tolist()==[3,1] and accepted.tolist()==[2,1] and dropped.tolist()==[False,False,False,True]
np.testing.assert_allclose(residual,[[2,0],[0,2],[3,3],[2,1]],atol=1e-12,rtol=0)

Expected: assigned counts 3, 1; accepted 2, 1; last token drops its expert delta and keeps its input.

Example C: Compute a load-balancing term#

The term measures a routing-related objective under the declared formula. A lower auxiliary value is not itself evidence that task loss, capacity drops or distributed utilization improved.

fractions=np.array([.75,.25]); mean_probability=np.array([.7,.3]); coefficient=.01
loss=coefficient*2*np.dot(fractions,mean_probability)
np.testing.assert_allclose(loss,.012,atol=1e-12,rtol=0)
np.testing.assert_allclose(coefficient*2*np.dot([.5,.5],[.5,.5]),.01,atol=1e-12,rtol=0)

Expected: auxiliary loss .012; balanced fixture .01.

Controlled case study#

A batch routes75 percent of its tokens to one of two experts, but capacity allows only half the batch per expert. Some expert deltas are dropped despite low average device utilization. Record assigned counts, accepted counts, drops and task errors for affected tokens. Increasing capacity may reduce drops while increasing activation memory. Router regularization may improve balance while changing task quality. These are measured tradeoffs, not consequences of parameter counts alone.

Common pitfalls and diagnosis#

When router gradients disagree, check the selected expert identities before comparing numbers. Verify whether the implementation renormalizes selected mass, retains full-softmax gates or uses a unit residual delta. For capacity failures, retain token identities as well as assigned/accepted counts; the same histogram can hide a different dropped token after reordering.

A lower auxiliary loss does not prove fewer drops or better task quality. The reference fixes tiny linear experts and uses a local router derivative away from selection boundaries. It neither trains a large sparse model nor executes distributed expert dispatch. Report those boundaries alongside any exact parameter or gate calculation.
