# js-044: Selections and data joins: enter, update and exit

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-043`.

## Learning objectives

Render with data joins so repeated draws add, update and remove exactly the marks the current data needs. The central exercise is: Write a render function using a data join.

## Purpose, vocabulary and mental model

A selection is a group of DOM nodes, not a copy of their HTML. A data join relates an array of records to selected nodes. Records without corresponding nodes enter; nodes with corresponding records update; surplus nodes exit. This makes repeated rendering a reconciliation operation rather than an instruction to append duplicates forever.

The selector describes the nodes you intend to manage. `selectAll('circle')` can begin empty; the subsequent data join creates the required nodes. `join('circle')` handles the common enter/update/exit case. Attribute callbacks then assign geometry from each bound record.

A render function should produce the intended state when called again. Calling append for every record on every update leaves stale marks and inflates counts. Start with a small sequence, such as three values followed by two, and verify both node count and attributes after the second render.

### Key terms

- **Data join:** The operation `selection.data(values)` that pairs an array of records with selected nodes so each node can be created, updated or removed to match the data.
- **Enter:** The part of a join holding records that have no matching node yet; `join` creates one new element for each of them.
- **Update:** The part of a join holding existing nodes that matched a record; they keep their element and receive the new bound datum.
- **Exit:** The part of a join holding existing nodes with no matching record; the default `join` removes them so stale marks do not accumulate.
- **Bound datum:** The record attached to a node by a join, passed as `d` to attribute callbacks along with the group index `i`.

## Syntax anatomy and mechanism

`selection.data(values).join('circle')` binds the current values and returns the merged entered/updated selection. Without a key, matching is by index within a group. This can be correct when positions are identities, but the next lesson shows why stable entity IDs often need keys.

An attribute callback `(d, i) => ...` receives the record as d and its current group index as i. Returning undefined for a required coordinate can remove or invalidate the intended attribute. Inspect the derived values before blaming SVG rendering.

## Worked example / walkthrough

### Worked example 1: Reconcile a changing count

This complete snippet creates its own SVG and draws twice.

```javascript
const svg = d3.select("#chart").append("svg").attr("viewBox", "0 0 640 360");
function draw(values) {
  svg
    .selectAll("circle")
    .data(values)
    .join("circle")
    .attr("cx", (d, i) => 80 + i * 120)
    .attr("cy", 180)
    .attr("r", (d) => d);
}
draw([5, 10, 15]);
draw([8, 12]);
console.log(
  svg
    .selectAll("circle")
    .nodes()
    .map((node) => node.getAttribute("r")),
);
```

**Expected observation:** Two circles remain; their radii are 8 and 12.

### Worked example 2: Contrast unconditional append

The top row appends on every call; the bottom row uses a join. Both are drawn twice with the same values.

```javascript
// js-044 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Selections and data joins: enter, update and exit")
  .style("width", "100%")
  .style("max-width", "640px");
const appendAll = (values) => {
  for (const value of values) {
    svg
      .append("circle")
      .attr("class", "appended")
      .attr("cx", 80 + value * 30)
      .attr("cy", 110)
      .attr("r", value * 2)
      .attr("fill", "#dc2626")
      .attr("fill-opacity", 0.4);
  }
};
const draw = (values) =>
  svg
    .selectAll("circle.joined")
    .data(values)
    .join("circle")
    .attr("class", "joined")
    .attr("cx", (d) => 80 + d * 30)
    .attr("cy", 250)
    .attr("r", (d) => d * 2)
    .attr("fill", "#2563eb")
    .attr("fill-opacity", 0.4);
appendAll([5, 10]);
appendAll([5, 10]);
draw([5, 10]);
draw([5, 10]);
check(svg.selectAll("circle.appended").size() === 4, "Unconditional append duplicates marks");
check(svg.selectAll("circle.joined").size() === 2, "A join keeps one mark per value");
output.textContent = "js-044 worked example 2 complete";
```

**Expected observation:** The top row looks like two darker circles but holds four nodes, two drawn over two; the joined bottom row holds exactly two.

## Six progressive exercises

### Exercise 1: Predict the node count after two draws.

**Expected evidence:** Two circles after changing three records to two.

**Progressive hint:** The exit selection is removed by the standard join.

### Exercise 2: Change the second input to an empty array.

**Expected evidence:** No managed circles remain.

**Progressive hint:** An empty dataset is a valid state.

### Exercise 3: Write a render function using a data join.

**Expected evidence:** Repeated calls produce exactly one mark per current record.

**Progressive hint:** Separate creation policy from attributes so the function can update existing nodes instead of appending duplicates.

### Exercise 4: Diagnose a chart that doubles its nodes on every click.

**Expected evidence:** It uses unconditional append or selects the wrong managed nodes.

**Progressive hint:** Check the selector and join boundary first.

### Exercise 5: Add an explicit invalid-value rejection.

**Expected evidence:** A negative radius input is refused before drawing.

**Progressive hint:** Geometry has a domain contract.

### Exercise 6: Apply the same pattern to an HTML list.

**Expected evidence:** Current records reconcile to current list items.

**Progressive hint:** The mechanism is about data-to-node relationships, not SVG alone.

## Debugging and common mistakes

If the node count grows on every draw, check whether the code appends unconditionally or selects a different selector from the one it creates. Print `selectAll('circle').size()` after each call: with a working `join` it equals the current data length, three, then two, then zero, because an empty array removes every managed node through exit. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a chart that doubles its nodes on every click. Distinguishing evidence: It uses unconditional append or selects the wrong managed nodes.

## Accessibility and interpretation

A redraw that removes and recreates nodes can also discard focus or announced text. Keep a short summary such as "2 circles: radii 8 and 12" that updates on each draw, and confirm that a screen reader hears the new count rather than a stale one from the previous dataset. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Without a key, a join matches records to nodes by index, so the first node takes whatever record is first in the new array. That is acceptable for this lesson's anonymous radii but wrong when marks stand for named entities, which is the problem the keyed joins in the next lesson solve. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
