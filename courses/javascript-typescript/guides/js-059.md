# js-059: Hierarchies and tree layouts

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-058`.

## Learning objectives

Turn nested data into a hierarchy and render a labeled tree layout with correct node and link counts. The central exercise is: Render a labeled left-to-right tree.

## Purpose, vocabulary and mental model

A hierarchy represents parent-child relationships without cycles. A tree has one root and a unique path from that root to each node. This differs from a general network, where nodes can have several relationships and cycles. Choosing a tree layout for data that is not a tree can hide important structure.

`d3.hierarchy` wraps nested input in nodes with parent, children, depth and traversal methods. Layout algorithms add geometry to these wrapper nodes. The original data remains available as node.data. A tree layout uses topology, not a numeric magnitude, to position nodes.

The reference visualizes a small learning taxonomy. Labels explain the nodes, and links show parent-child relationships. A hierarchy can be deep or broad, so a reusable view must address label collisions, collapse state and keyboard navigation rather than assuming every tree fits one screen.

### Key terms

- **Hierarchy:** Data with parent-child relationships and no cycles. `d3.hierarchy` wraps nested objects as nodes with `parent`, `children`, `depth` and the original `data`.
- **Parent:** The single node directly above a node in a hierarchy. Every node except the root has exactly one parent.
- **Tree layout:** The `d3.tree().size(...)` layout that assigns x and y coordinates from topology alone. For a left-to-right tree, the layout y becomes the horizontal position.
- **Link:** A source-target pair from `root.links()`, one per parent-child edge, so a connected tree with n nodes has n - 1 links.

## Syntax anatomy and mechanism

Construct the hierarchy from an object whose children field contains nested objects. Apply `d3.tree().size([height,width])` to compute coordinates. For a left-to-right tree, use the layout y coordinate as horizontal position and x as vertical position.

`root.links()` returns source-target pairs; `d3.linkHorizontal` converts each pair into a path. Check node and edge counts: a connected tree with n nodes has n-1 parent edges. This is a structural invariant, not a visual preference.

## Worked example / walkthrough

### Worked example 1: Count a tiny hierarchy

The wrapper exposes descendants and links.

```javascript
const root = d3.hierarchy({ name: "Root", children: [{ name: "A" }, { name: "B" }] });
console.log(root.descendants().length, root.links().length);
```

**Expected observation:** 3 nodes and 2 parent links.

### Worked example 2: Distinguish topology from magnitude

A tree layout positions nodes by structure alone; this one is drawn top-down.

```javascript
// js-059 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Hierarchies and tree layouts")
  .style("width", "100%")
  .style("max-width", "640px");
const root = d3.hierarchy({ name: "Root", children: [{ name: "A" }, { name: "B" }] });
d3.tree().size([400, 200])(root);
const g = svg.append("g").attr("transform", "translate(120,60)");
g.selectAll("line")
  .data(root.links())
  .join("line")
  .attr("x1", (d) => d.source.x)
  .attr("y1", (d) => d.source.y)
  .attr("x2", (d) => d.target.x)
  .attr("y2", (d) => d.target.y)
  .attr("stroke", "#9ca3af");
g.selectAll("circle")
  .data(root.descendants())
  .join("circle")
  .attr("cx", (d) => d.x)
  .attr("cy", (d) => d.y)
  .attr("r", 8)
  .attr("fill", "#0f766e");
g.selectAll("text")
  .data(root.descendants())
  .join("text")
  .attr("x", (d) => d.x + 12)
  .attr("y", (d) => d.y + 4)
  .text((d) => d.data.name);
check(
  root.children.every((d) => d.depth === 1),
  "Children of the root have depth 1",
);
check(
  root.descendants().every((d) => d.value === undefined),
  "No size value was needed",
);
output.textContent = "js-059 worked example 2 complete";
```

**Expected observation:** A top-down tree with Root above A and B, both at depth 1, laid out without any size value.

## Six progressive exercises

### Exercise 1: Predict node and edge counts.

**Expected evidence:** Three nodes and two links in the small example.

**Progressive hint:** Each non-root node has one parent edge.

### Exercise 2: Add a grandchild under A.

**Expected evidence:** Depth 2 appears and counts become 4 nodes, 3 links.

**Progressive hint:** The new relationship changes topology.

### Exercise 3: Render a labeled left-to-right tree.

**Expected evidence:** Links connect the matching source and target nodes.

**Progressive hint:** Use the same layout coordinates for both marks and links.

### Exercise 4: Diagnose using a tree for a cyclic relationship graph.

**Expected evidence:** The data model does not satisfy tree assumptions.

**Progressive hint:** A general network needs a different representation or an explicitly chosen spanning tree whose omissions are disclosed.

### Exercise 5: Handle long labels in a narrow view.

**Expected evidence:** Labels remain readable or an alternate list exposes full names.

**Progressive hint:** Truncation needs a discoverable full value.

### Exercise 6: Design a collapsible taxonomy state model.

**Expected evidence:** Stable node IDs and explicit collapsed sets preserve identity.

**Progressive hint:** Do not encode collapse only by deleting data permanently.

## Debugging and common mistakes

Count before drawing: `root.descendants().length` and `root.links().length` should be 3 and 2 for the small example, and a tree always has one fewer link than nodes. `d3.stratify` refuses a table with a cycle or several roots, with errors such as `no root`, which signals that the data form a graph, not a tree. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose using a tree for a cyclic relationship graph. Distinguishing evidence: The data model does not satisfy tree assumptions.

## Accessibility and interpretation

A tree layout uses position to show parent and child, which a screen reader cannot see. Provide a nested list that mirrors the hierarchy, and shorten long labels visually only when the full name remains in that list or as the node's accessible name. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

A tree layout shows topology, such as which unit reports to which, not magnitude; node spacing carries no quantity. If the relationships contain cycles or shared children, a tree drawing invents a single parent and misstates the structure. Choose the layout from the data model, not from how the picture looks. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
