Outcome and mechanism#

Normalize and parse small text records with explicit patterns while preserving identifiers and Unicode meaning.

Text often carries identifiers, labels and encoded values in one field. Parsing should distinguish these roles. An ID such as "0017" is not automatically a number, and trimming surrounding whitespace should not silently remove meaningful internal characters. Preserve the original field when normalization needs to be audited.

Regular expressions describe patterns rather than literal strings. In an anchored pattern, ^ and $ constrain the match to the beginning and end. A dot in regex syntax usually matches any character, so grepl(".", x) is not a test for a literal decimal point. Use fixed=TRUE for literal matching or escape the regex metacharacter deliberately.

R source strings add another escaping layer. A backslash needed by the regular-expression engine may itself need escaping inside the source string. Keep a small input/output table beside a complicated pattern and test a near-miss case, not only a valid example. A pattern that extracts a plausible substring from an invalid whole record can admit malformed data if it lacks anchors.

Characters and bytes are different units. A Unicode string can contain a character represented by several UTF-8 bytes. nchar(type="chars") and nchar(type="bytes") can therefore disagree. Neither automatically counts user-perceived grapheme clusters. Declare the unit used by a limit or slicing operation, and avoid assuming every visible symbol occupies one byte.

Read the syntax#

trimws removes selected surrounding whitespace, paste combines strings, strsplit returns a list of split pieces, and grepl returns a logical match mask. Use anchors for a whole-field contract and fixed=TRUE when the input is a literal delimiter.

Worked examples#

Example 1: Whole-field IDs retain leading zeros#

raw <- c(" 0017 ", "A17", "17x")
clean <- trimws(raw)
valid <- grepl("^[0-9]{4}$", clean)
stopifnot(identical(clean[[1]], "0017"), identical(valid, c(TRUE, FALSE, FALSE)))
print(data.frame(raw = raw, clean = clean, valid = valid))

Expected observation: Only 0017 is valid.

Normalization removes only surrounding whitespace. The four-digit contract rejects partial or mixed matches without converting the ID to a number.

Example 2: Literal dots and Unicode byte counts#

x <- c("a.b", "axb")
stopifnot(identical(grepl(".", x, fixed = TRUE), c(TRUE, FALSE)))
text <- enc2utf8("café")
stopifnot(nchar(text, type = "chars") == 4L, nchar(text, type = "bytes") == 5L)
print(c(characters = nchar(text), bytes = nchar(text, type = "bytes")))

Expected observation: Four characters and five bytes.

Literal matching avoids regex wildcard semantics. The accented character uses multiple UTF-8 bytes while the string has four code-point characters.

Progressive hints#

  1. Fixed matching treats the dot literally.
  2. Change the anchored repetition count.
  3. The regex pipe has another meaning unless fixed matching is selected.
  4. Finding digits is weaker than validating the whole field.
  5. Check the split function boundary behavior before assuming field counts.
  6. Visible characters need not occupy one byte.
