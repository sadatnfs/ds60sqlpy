# asm-002: The additive likelihood theorem

Tutorial mode. Stage: beginner. Direct prerequisites: `asm-001`, `clp-002`.

## Starting point and result

A distributed optimizer needs a mathematical reason to combine partition results. “The table is large” is not that reason. This chapter proves the additive likelihood contract and then breaks it with a shared latent variable. You should understand the driver/executor boundaries from the preceding chapter and the difference between a probability density and a numerical loss.

The first example evaluates a Gaussian negative log likelihood at a fixed mean and known scale. Spark and an independent serial formula agree for several partitions. The second example calculates a two-observation marginal likelihood with a shared random intercept and shows that treating the observations as independent changes the value. Both are tiny, fully specified models, so the difference can be traced algebraically.

## Mechanism: the decomposition is conditional

Suppose the modeled observations are conditionally independent given parameters \(\theta\) and observed design \(X\). Then their joint density is

\[
p(y\mid X,\theta)=\prod_{i=1}^{n}p(y_i\mid x_i,\theta),
\qquad
L(\theta)=-\log p(y\mid X,\theta)=\sum_i\ell_i(\theta).
\]

For disjoint index sets \(I_1,\ldots,I_P\) whose union is the dataset, define \(L_p(\theta)=\sum_{i\in I_p}\ell_i(\theta)\). It follows that \(L=\sum_pL_p\). If each contribution is differentiable, the finite-sum rule gives \(\nabla L=\sum_p\nabla L_p\). This is an algebraic equality, not an approximation caused by the cluster.

The prerequisites matter. Every observation must appear in exactly one logical contribution. All partitions must evaluate the same parameter vector and feature ordering. Constants that depend on estimated parameters must remain in the objective. An independently chosen partition average is not the same object as a partition sum.

A model penalty belongs outside the data reduction unless the implementation deliberately divides it across partitions. Writing \(L(\theta)+\lambda R(\theta)\) means one penalty. Adding \(\lambda R\) to every partition and then summing multiplies its strength by \(P\). The parallel API cannot detect that modeling error.

## Worked case 1: normalized Gaussian contributions

For \(y_i\sim N(\mu,\sigma^2)\) with known \(\sigma>0\),

\[
\ell_i(\mu)=\tfrac12\log(2\pi\sigma^2)+
            \frac{(y_i-\mu)^2}{2\sigma^2}.
\]

The program uses four values, \(\mu=1.5\), and \(\sigma=2\). It computes each term in Spark SQL, then returns one count and one sum. The serial oracle uses math.fsum, which is a more careful summation than a naive loop for small floating inputs. Spark is checked against that independent value within a small absolute tolerance.

Now change the number of physical partitions. The parameter and data population remain fixed, so the mathematical objective is unchanged. The count confirms that the partition union still contains the four intended observations. The tolerance accommodates numerical summation without hiding a large modeling discrepancy.

The Gaussian normalization is retained even though \(\sigma\) is fixed in this first case. If a later model estimates \(\sigma\), dropping \(n\log\sigma\) would reward arbitrarily large scales and produce the wrong optimization problem. Teaching the complete normalized likelihood prevents a shortcut from silently surviving into a different model.

## Worked case 2: integrate one shared random intercept

Let \(y_i=b+\epsilon_i\), where \(b\sim N(0,\tau^2)\) is shared and the \(\epsilon_i\) are independent \(N(0,\sigma^2)\). Conditional on a fixed \(b\), the row likelihood is additive. After integrating over \(b\), the observations have covariance

\[
\Sigma=
\begin{pmatrix}
\sigma^2+\tau^2 & \tau^2\\
\tau^2 & \sigma^2+\tau^2
\end{pmatrix}.
\]

With \(\sigma=\tau=1\), the diagonal is \(2\), the off-diagonal is \(1\), and the determinant is \(3\). The joint Gaussian NLL contains \(\tfrac12\log 3\) and a quadratic form involving \(y_1y_2\). Multiplying the two marginal \(N(0,2)\) densities uses determinant \(4\) and omits that cross term. The resulting likelihood is different even though each one-dimensional marginal is correct.

For the observations \(y=(1,1)\), the program computes both values explicitly. Setting \(\tau=0\) makes the covariance diagonal, and the same calculation then agrees with the independent sum. Changing one modeling condition therefore restores the decomposition for a reason you can verify.

This is the first warning for Spark/TMB integration: a shared latent effect cannot be integrated independently in each arbitrary partition. Later chapters derive when independent latent *groups* do permit a sum of groupwise integrated likelihoods.

## Failure diagnosis

If independent row terms match but the global objective does not, inspect the observation count, partition coverage and normalization. If a random effect is present, ask whether the likelihood is conditional on it or marginal over it. Those are different objectives.

A numerical match at one parameter is weak evidence. A wrong objective can coincide accidentally at \(\theta=0\). Check changed parameters, changed partitioning and a dependence counterexample. Gradient agreement should be checked in addition to loss agreement before optimization.

Do not use an executor accumulator as the authoritative objective. Task retries and execution semantics are not a substitute for returning and aggregating pure numerical values.

## Interview discussion

**When can Spark optimize a custom likelihood?** When you can evaluate a useful bounded partition summary and reconstruct the intended objective and derivatives from those summaries. Additivity is common, but it must be proved for the actual observation and latent structure.

**Does conditional independence imply marginal independence?** No. Sharing a random variable can induce marginal dependence even when observations are conditionally independent given that variable. The random-intercept example makes the distinction explicit.

**Can the normalization constant be dropped?** Only a term constant with respect to every estimated parameter can be dropped without changing an optimizer. Retain it when comparing likelihoods or changing which parameters are estimated, and explain any omission.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-python`.

```python
from __future__ import annotations

import json
import math


def session(name):
    from pyspark.sql import SparkSession

    spark = (
        SparkSession.builder.master("local[2]")
        .appName(name)
        .config("spark.ui.enabled", "false")
        .config("spark.driver.host", "127.0.0.1")
        .config("spark.driver.bindAddress", "127.0.0.1")
        .config("spark.sql.shuffle.partitions", "2")
        .config("spark.sql.adaptive.enabled", "false")
        .config("spark.sql.ansi.enabled", "true")
        .config("spark.sql.session.timeZone", "UTC")
        .getOrCreate()
    )
    if spark.version != "4.0.1":
        spark.stop()
        raise RuntimeError("This worked reference is qualified for Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    return spark


def normal_nll(values, mean, scale):
    if not scale > 0:
        raise ValueError("positive Gaussian scale required")
    constant = 0.5 * math.log(2 * math.pi * scale * scale)
    return math.fsum(constant + (y - mean) ** 2 / (2 * scale * scale) for y in values)


def shared_intercept_nll(first, second, noise_variance, intercept_variance):
    diagonal = noise_variance + intercept_variance
    covariance = intercept_variance
    determinant = diagonal * diagonal - covariance * covariance
    if noise_variance <= 0 or intercept_variance < 0 or determinant <= 0:
        raise ValueError("positive-definite covariance required")
    quadratic = (
        diagonal * (first * first + second * second) - 2 * covariance * first * second
    ) / determinant
    return math.log(2 * math.pi) + 0.5 * math.log(determinant) + 0.5 * quadratic


def run(spark):
    from pyspark.sql import functions as F

    values = [-1.0, 0.5, 2.0, 4.0]
    mean, scale = 1.5, 2.0
    oracle = normal_nll(values, mean, scale)
    frame = spark.createDataFrame([(y,) for y in values], "y double")
    reports = []
    for partitions in (1, 2, 3):
        contribution = F.lit(0.5 * math.log(2 * math.pi * scale * scale)) + (
            (F.col("y") - mean) ** 2 / (2 * scale * scale)
        )
        row = (
            frame.repartition(partitions)
            .agg(F.count("*").alias("n"), F.sum(contribution).alias("loss"))
            .first()
        )
        assert row.n == len(values) and math.isclose(row.loss, oracle, abs_tol=1e-10)
        reports.append({"partitions": partitions, "n": row.n, "loss": row.loss})
    shared = shared_intercept_nll(1.0, 1.0, 1.0, 1.0)
    false_independent = normal_nll([1.0, 1.0], 0.0, math.sqrt(2.0))
    independent = shared_intercept_nll(1.0, 1.0, 1.0, 0.0)
    assert not math.isclose(shared, false_independent, abs_tol=1e-6)
    assert math.isclose(independent, normal_nll([1.0, 1.0], 0.0, 1.0), abs_tol=1e-12)
    print(
        json.dumps(
            {
                "additive": reports,
                "shared_latent_joint": shared,
                "wrong_product_of_marginals": false_independent,
            }
        )
    )


if __name__ == "__main__":
    spark = session("asm-002")
    try:
        run(spark)
    finally:
        spark.stop()
```
