dme-069: SSE, UTF-8, backpressure and explicit event readback#

Level: Advanced | Prepared runtime: python-core

Direct prerequisites: dme-068.

Outcome: Parse exact SSE across arbitrary network chunks and read retained event suffixes without generation.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

Generating a token is not the same as delivering text to a browser. The server must convert the selected ID into bytes, decode complete text where appropriate, frame an application event, write it through the HTTP stack, and let the client parse arbitrary network deliveries. A reliable streaming interface gives each layer its own boundary and handles partial delivery explicitly.

This chapter uses exact Server-Sent Events, or SSE, framing with a small incremental UTF-8 parser. The full project serves real SSE from the tiny Transformer. It uses authenticated fetch streaming rather than native EventSource, because the workshop API requires a request header and deliberately avoids automatic reconnect-and-replay behavior.

Three different boundaries#

A model token is a vocabulary ID. Its byte piece may be empty for a special token, contain several characters or end in the middle of a UTF-8 character. An SSE event is an application message delimited by an empty line. A network chunk is whatever portion of bytes the transport and browser happen to deliver on a particular read.

One network read can contain several SSE events. One SSE event can span many reads. A multi-byte character can also span reads, so decoding each chunk independently is unsafe. The client first uses an incremental UTF-8 decoder, then accumulates text until complete SSE frame boundaries exist, then parses the JSON data carried by those frames.

The workshop's token event contains a sequential event ID, a token index, token ID, byte hex, visible text delta and measured compute duration. The visible delta may be empty while a Unicode character or stop marker is incomplete. Event count therefore differs from token count, and token count differs from displayed character count.

Framing and identity#

An SSE frame may contain id, event and one or more data lines, ending with a blank line. The project emits one JSON data line per event, escaping embedded newline characters inside JSON. It does not concatenate untrusted prompt text into raw SSE field names. Its event types are fixed: admission, start, token and terminal categories.

Event IDs are sequential within one request. They are not global model-token IDs, timestamps or byte offsets. A retained cursor ccc means the client has observed events through ccc; a readback returns events with IDs greater than that cursor. A cursor beyond the retained event count is invalid, because silently skipping unknown positions would hide a possible mismatch.

A terminal event records completion, cancellation or error. A closed connection without a terminal event is an unknown transport outcome, not successful generation. The client should reconcile through retained request state. It must not create a new generation merely because a socket closed.

Backpressure is a resource policy#

A producer can generate output faster than a consumer reads it. Without a bound, pending text or events can accumulate indefinitely. Backpressure makes the producer wait or applies an explicit failure policy. It must account for every buffering layer: application queues, framework transport buffers, kernel socket buffers and the browser.

The workshop has a four-event application queue for the active subscriber. If it cannot enqueue another event within the declared timeout, it requests cancellation with a backpressure reason. This bounds application event buffering. It does not mean every slow browser immediately fills that queue: the HTTP and kernel buffers may absorb a tiny demonstration response first.

Consequently, the independent scheduler test deliberately stops consuming an event iterator and verifies the bounded timeout and reservation release. Actual browser tests verify framing, streaming, cancellation and exact downloads. Those are complementary evidence. A small successful browser request is not a large-scale network saturation benchmark.

Optional pedagogical pacing makes events easier to observe but is not computation. It is separately configured and measured. Never claim a token took 20 milliseconds of model time because a demonstration intentionally waited 20 milliseconds before the next step.

Worked case 1: every possible two-chunk split#

The first case frames two events carrying é and 🙂. It parses the combined byte stream as one delivery, then as one byte per delivery, then at every possible two-chunk split. All parses must produce exactly the same two event IDs and text values.

This tests splits inside UTF-8 encodings, field names, JSON strings and the blank-line terminator. A parser that assumes one read equals one event will fail many of those splits. A parser that decodes every chunk independently will fail when a Unicode encoding is divided. The expected semantic events remain unchanged regardless of transport segmentation.

The example is intentionally a bounded parser for the exact frame subset emitted by the project. A general-purpose SSE client must implement the full standard, including its line handling and field rules. Do not advertise a narrowly tested fixture parser as a complete standards implementation.

Worked case 2: cursor readback and truncated framing#

The second case retains four events: queued, started, token and completed. Reading after cursor two returns only events three and four. Repeating that read leaves the modeled generation-call count unchanged. It is data retrieval, not a continuation request.

The case also removes the final byte from an encoded frame. The parser rejects the incomplete frame rather than treating a partial message as success. In the live UI, a stream that ends before a terminal event reports the unknown outcome and directs the learner to retained history. A new request requires an explicit user action and a separate identity.

"""SSE framing survives arbitrary network chunks and explicit cursor readback."""

import codecs
import json


def encode(identity, text):
    payload = json.dumps({"text": text}, ensure_ascii=False)
    return f"id: {identity}\nevent: token\ndata: {payload}\n\n".encode()


def parse(chunks):
    decoder = codecs.getincrementaldecoder("utf-8")(errors="strict")
    buffer = ""
    records = []
    for chunk in chunks:
        buffer += decoder.decode(chunk, final=False)
        while "\n\n" in buffer:
            frame, buffer = buffer.split("\n\n", 1)
            fields = dict(line.split(": ", 1) for line in frame.splitlines())
            records.append((int(fields["id"]), json.loads(fields["data"])["text"]))
    buffer += decoder.decode(b"", final=True)
    if buffer:
        raise ValueError("Incomplete SSE frame")
    return records


def example_one():
    raw = encode(1, "é") + encode(2, "🙂")
    expected = [(1, "é"), (2, "🙂")]
    assert parse([raw]) == expected
    assert parse([bytes([value]) for value in raw]) == expected
    for boundary in range(1, len(raw)):
        assert parse([raw[:boundary], raw[boundary:]]) == expected
    print("All", len(raw) - 1, "two-chunk splits preserve the same two SSE events.")


def example_two():
    retained = [(1, "queued"), (2, "started"), (3, "token"), (4, "completed")]
    cursor = 2
    suffix = [item for item in retained if item[0] > cursor]
    assert suffix == [(3, "token"), (4, "completed")]
    calls = 1
    for _ in range(3):
        assert [item for item in retained if item[0] > cursor] == suffix
    assert calls == 1
    try:
        parse([encode(1, "x")[:-1]])
    except ValueError:
        print("A truncated network response is not successful completion.")
    print("Explicit completed readback returns data without model execution.")


def main():
    example_one()
    example_two()


if __name__ == "__main__":
    main()

Persistence and replacement#

The project stores bounded, source-bound request snapshots atomically in its dedicated state directory. Completed records are immutable. After container replacement, the new process loads those records and can serve the same completed event stream without invoking the model. The API checker compares exact downloaded bytes and verifies that generation-call counts do not change during readback.

An unfinished snapshot is different. Startup recovery records an explicit interruption and does not reconstruct the missing continuation by sampling again. Even the same prompt and seed could produce different results after a runtime change; more importantly, a saved request is not authorization for an automatic new execution.

The UI's JSON download uses response bytes directly. It does not parse and reserialize the record before downloading it. That preserves the exact retained representation and avoids unnecessary changes to numeric formatting or key order. Model and source hashes remain available for comparison.

Disconnects, security and observability#

The workshop's documented policy cancels an active request when its only stream subscriber disconnects. Reconnecting reads the retained partial and terminal events; it does not resume generation. Other products may deliberately continue jobs after disconnect, but then need a bounded durable-output policy and an explicit contract for later attachment.

Do not put authentication tokens in event URLs. URLs can reach browser history, logs and referrers. The local client sends a private header over the loopback connection, and the server checks Host and origin. Output is inserted as text, never interpreted as HTML. A generated string containing markup must remain literal content.

For debugging, record request ID, event cursor and terminal reason. Avoid treating a network read count as token throughput. If events arrive in a burst after generation finishes, inspect proxy buffering, framework flush behavior and client parsing before concluding that the model generated all tokens simultaneously.

Interview discussion#

Why can a correct model stream appear broken in a browser? Transport buffering, UTF-8 chunk handling, SSE framing or client rendering can fail independently of token selection. Trace the boundaries separately.

Does Last-Event-ID authorize more inference? No. It identifies a readback cursor under this contract. Generation requires an explicit creation operation; reading retained events never samples again.

How do you test backpressure honestly with a tiny model? Use a bounded controlled consumer that stops reading at the application boundary, then separately test real network/browser behavior. State that this demonstrates the policy, not arbitrary Internet-scale congestion.
