## Starting point and result

A shared or correlated latent structure can prevent independent group integration. A covariance matrix that connects groups has off-diagonal blocks, and its determinant generally does not equal the product of the diagonal-block determinants. This chapter supplies a concrete counterexample so the Spark/TMB integration is not oversold as a universal distributed Laplace solver.

## Mechanism: integration and partitioning do not commute generally

For two latent variables with Hessian \(H=\begin{bmatrix}a&c\\c&b\end{bmatrix}\), the determinant is \(ab-c^2\). Summing separate log determinants would use \(\log a+\log b=\log(ab)\), omitting the coupling. Positive definiteness requires positive diagonal structure and \(ab-c^2>0\).

At a coupled mode, the optimum of one latent block also depends on the other. Solving each block independently changes both the mode and curvature term in the Laplace approximation. Increasing Spark partitions cannot make the off-diagonal entries vanish. A correct method may use a sparse factorization, message passing, state-space recursion or a distributed linear-algebra algorithm, but it must account for the coupling explicitly.

A complete independent connected component can be a valid unit of work. If the latent dependency graph separates into components, each component can be evaluated independently. Storage groups and business labels do not necessarily coincide with those components.

## Worked case: a two-by-two determinant

Set a=b=2 and c=1. The correct determinant is three; the independent-block approximation uses four. The Laplace curvature term differs by \(\tfrac12\log(4/3)\), about 0.14384. This discrepancy exists before considering any difference in the latent mode. It is not a floating-point tolerance issue.

At c=0, both determinants are four and the block factorization becomes valid. That limiting case provides a useful test: a coupled implementation should recover the independent result when the coupling is exactly removed. Testing only c=0 would fail to expose an implementation that always discards off-diagonal structure.

## Worked case: a spatial field crossing partitions

Imagine neighboring locations assigned to different Spark partitions while their latent effects follow a spatial precision matrix. Edges crossing partitions contribute off-diagonal terms. Fitting each partition with boundary edges removed changes the prior and therefore the marginal likelihood. A good fit to each isolated partition is not evidence that the original spatial model was fitted.

Possible designs include assigning entire connected components to workers, preparing sparse matrices in Spark and solving centrally within memory limits, or implementing a specialized distributed solver. Each has different scale limits. The honest fallback is a bounded exact or well-characterized approximation with clear limitations, not an unsupported claim that TMB cannot ever be used with Spark.

## Failure diagnosis

If the result changes when a group is split while the model is supposedly unchanged, inspect lost covariance edges and initial-state terms. A “distributed Laplace” implementation that never exchanges information about coupled blocks needs a convincing mathematical factorization. An optimizer's convergence flag cannot establish that factorization.

## Interview discussion

**Is this a limitation of automatic differentiation?** The derivative engine can differentiate the computation it is given. The issue is that an incorrect partitioned computation represents a different probability model.

**Can an approximation still be useful?** Yes, if its altered assumptions, error behavior and validation are explicit. Compare against a small joint model and study sensitivity rather than presenting the approximation as exact.
