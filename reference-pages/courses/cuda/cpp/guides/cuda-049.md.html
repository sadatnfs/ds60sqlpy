Purpose, vocabulary and mental model#

A linear solver seeks x such that A*x approximates b. Factorization usually avoids the unnecessary work and numerical costs of explicitly constructing an inverse. Library status tells whether the requested procedure completed; a residual checks how well the returned vector satisfies the equation. A small residual does not guarantee a small error in x when A is ill-conditioned, meaning small input changes can greatly change the solution. Report both the residual and a conditioning interpretation. Workspace, matrix layout, pivoting and rank assumptions belong to the solver contract rather than being incidental implementation details.

Mathematical contract#

r=b−Ax^r=b-A\widehat x

The residual r measures equation satisfaction by the computed x-hat. Small residual alone does not imply small forward error for an ill-conditioned matrix.

Worked example 1: trace the mechanism#

For A=[[3,1],[1,2]][[3,1],[1,2]] and b=[9,8][9,8], x=[2,3][2,3] gives A*x=[9,8][9,8], so residual is zero in this exact fixture. This is a good first layout and status test, but it does not exercise singular or poorly conditioned problems.

The complete CPU model below intentionally models only the named arithmetic, layout, dependency or capability decision. It does not model GPU scheduling, caches, instruction timing or device memory visibility.

A, b, x = [[3, 1], [1, 2]], [9, 8], [2, 3]
product = [sum(a * v for a, v in zip(row, x)) for row in A]
residual = [rhs - value for rhs, value in zip(b, product)]
assert residual == [0, 0]
wrong = [sum(a * v for a, v in zip(row, [2, 2])) for row in A]
assert [rhs - value for rhs, value in zip(b, wrong)] == [1, 2]
print({"solution": x, "residual": residual})

Expected observation: Every assertion succeeds. A representative CPU output is:

{'solution': [2, 3], 'residual': [0, 0]}

Tiny floating-point display differences across platforms are acceptable only where the explicit assertions use a tolerance; integers, shapes and ordering must still satisfy their exact contracts. A printed hypothetical duration is a model output, not a measured GPU benchmark.

Worked example 2: change a meaningful condition#

For A=[[1,1],[1,1.000001]][[1,1],[1,1.000001]], small changes in the second component of b can produce large changes in the two components of x. The nearly dependent rows provide little independent information. A solver returning numbers cannot remove that uncertainty; inspect conditioning and the problem specification.

Before applying this example to your own program, write down which inputs are read, which result is produced, and the condition that makes the comparison valid. Keep the original case as a regression check when changing a boundary.
