# Parallel accumulators and OpenMP

Start with: tmb-006, r-027.

Outcome: Parallelize an independent sum while preserving the objective and its derivatives.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

OpenMP runs multiple native threads inside one process. Spark distributes tasks across processes and potentially machines. These are different parallel layers. TMB's `parallel_accumulator<Type>` supports suitable independent objective contributions inside a compiled template; it does not turn an arbitrary model into a distributed Spark computation.

An independent normal NLL is a sum over observations. Each term depends on the same fixed mean and scale but can be evaluated separately. The original `parallel_gaussian.cpp` accumulates the complete normalized contribution. Its compiler explicitly enables OpenMP, and runtime acceptance compares actual one-thread and two-thread evaluations.

### Worked case A: partitioning a sum correctly

The base-R companion splits a vector into unequal chunks, evaluates each chunk's total NLL at the same parameters, and verifies the sum equals the serial total. It also shows that averaging chunk means equally changes the result when chunk sizes differ. The companion is an algebraic model; the prepared C++ acceptance supplies the actual OpenMP evidence.

```r
TMB::openmp(1, DLL = "parallel_gaussian")
one <- evaluate_objective(obj, obj$par)
TMB::openmp(2, DLL = "parallel_gaussian")
two <- evaluate_objective(obj, obj$par)
```

Check gradients as well as objective values. Floating-point summation order can produce small differences even for a correct decomposition. Choose tolerances based on scale and conditioning, and avoid claiming bitwise identity unless it was actually observed.

### Worked case B: nested parallelism oversubscribes a machine

If four Spark tasks each launch eight TMB threads and each thread calls a threaded BLAS, the requested concurrency can greatly exceed available cores. The companion computes a simple budget table. In an executor-based design, begin with one native thread per task, then benchmark a deliberate allocation. Record Spark task count, TMB/OpenMP count and BLAS settings together.

Compilation, tape construction, gradient evaluation and sparse factorization have different costs. A short vector can run slower with threads because startup and coordination dominate arithmetic. Time repeated evaluations after warmup, while also reporting cold-start preparation separately. A speedup on one synthetic case does not establish a benefit for every likelihood.

### Diagnostics and answered discussion

**Can I parallelize any loop over latent states?** Not blindly. Contributions may share mutable state or require structured sparse operations. Use the documented accumulator contract and compare a serial reference. **Does `openmp(2)` guarantee two cores were busy?** It configures the runtime; actual scheduling and workload determine utilization. **Does passing local parity prove cluster scalability?** No. Cluster transport, task scheduling, skew and fault behavior need separate measurements.

See [TMB's parallel accumulator reference](https://kaskr.github.io/adcomp/structparallel__accumulator.html). Compiler and thread receipts belong beside numerical evidence, not in a claim that an ordinary R-only companion used native threads.

### Complete R companion

```r
y <- c(1, 2, 4, 7, 9); chunks <- list(y[1:2], y[3:5])
loss <- function(z) -sum(dnorm(z, 3, 2, log = TRUE))
print(c(serial = loss(y), partition_sum = sum(vapply(chunks, loss, numeric(1)))))
stopifnot(abs(loss(y) - sum(vapply(chunks, loss, numeric(1)))) < 1e-12)
print(c(correct_mean = loss(y) / length(y), wrong_equal_chunk_mean = mean(vapply(chunks, function(z) loss(z) / length(z), numeric(1)))))
print(data.frame(tasks = c(1, 4, 4), threads_per_task = c(2, 1, 8), requested_threads = c(2, 4, 32)))
```
