# js-056: Pointer interaction, keyboard access and safe tooltips

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-055`.

## Learning objectives

Add pointer and keyboard interaction that share one action and render tooltip text safely. The central exercise is: Build an accessible selection list beside the chart.

## Purpose, vocabulary and mental model

An interaction connects a user action to application state. D3 event handlers receive the event and the datum associated with the selected node. Pointer position is measured in a coordinate space; using page coordinates as SVG data values mixes two spaces and often produces misplaced tooltips or selections.

A tooltip is supplemental information, not the only place essential values should exist. A pointer-only tooltip excludes keyboard and some touch users. Provide focusable controls or an alternative data list, and keep a visible summary. Use text insertion so a data label containing markup characters remains text.

Native HTML buttons provide keyboard activation behavior. Making every SVG circle act like a button requires deliberate semantics, focus and key handling. For a small chart, a parallel list of native buttons can offer a simpler accessible route to selecting each datum.

### Key terms

- **Event handler:** A listener registered with `selection.on(type, listener)`. D3 calls it with the DOM event and the datum bound to the node.
- **Pointer coordinates:** The `[x, y]` pair returned by `d3.pointer(event, node)`, measured in the given node's coordinate system so SVG scaling is accounted for, unlike page coordinates.
- **Tooltip:** A small supplemental label shown near a mark on hover or focus. Essential values must also be available without it.
- **Keyboard focus:** The element that currently receives key presses. Native buttons are focusable and activate with Enter or Space without extra code.
- **Text insertion:** Setting content with `.text()` or `textContent`, so markup characters in a data label appear literally instead of being parsed as HTML.

## Syntax anatomy and mechanism

`d3.pointer(event, node)` returns coordinates relative to the chosen node. A handler can update a selected ID and a text summary. Do not retain the event object as long-term application state; retain the meaningful data selection instead.

The reference draws circles and creates native buttons beneath the SVG. Both pointer and keyboard activation reach the same select function. It programmatically activates one button for a deterministic check, while the learner must still perform the real keyboard navigation.

## Worked example / walkthrough

### Worked example 1: Insert a label as text

This preserves literal characters rather than parsing markup.

```javascript
d3.select("#chart").append("p").text("<strong>sample</strong>");
console.log(document.querySelector("#chart strong") === null);
```

**Expected observation:** true: the angle-bracket text appears literally and no strong element is created.

### Worked example 2: Share one action between input methods

Native buttons handle keyboard activation; pointer entry on a circle calls the same action.

```javascript
// js-056 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Pointer interaction, keyboard access and safe tooltips")
  .style("width", "100%")
  .style("max-width", "640px");
const rows = [
  { id: "A", value: 3 },
  { id: "B", value: 5 },
];
let selected = null;
const summary = d3.select(host).append("p").attr("role", "status");
const marks = svg
  .selectAll("circle")
  .data(rows)
  .join("circle")
  .attr("cx", (d, i) => 180 + i * 260)
  .attr("cy", 180)
  .attr("r", (d) => d.value * 10)
  .attr("fill", "#2563eb")
  .attr("stroke-width", 4)
  .on("pointerenter", (event, d) => selectRow(d));
function selectRow(row) {
  selected = row.id;
  summary.text(`Selected ${row.id}: ${row.value}`);
  marks.attr("stroke", (d) => (d.id === selected ? "#111827" : "none"));
}
const buttons = d3
  .select(host)
  .append("div")
  .selectAll("button")
  .data(rows)
  .join("button")
  .attr("type", "button")
  .text((d) => `Select ${d.id}`)
  .on("click", (event, d) => selectRow(d));
buttons.nodes()[1].click();
check(
  selected === "B" && summary.text() === "Selected B: 5",
  "A button click uses the shared action",
);
marks.nodes()[0].dispatchEvent(new PointerEvent("pointerenter"));
check(selected === "A", "Pointer entry uses the same action");
output.textContent = "js-056 worked example 2 complete";
```

**Expected observation:** Two circles and two native buttons; activating Select B or moving the pointer onto a circle updates the same status text and outline.

## Six progressive exercises

### Exercise 1: Predict literal markup in a text label.

**Expected evidence:** It remains text instead of becoming executable HTML.

**Progressive hint:** Text insertion is the appropriate default for data labels.

### Exercise 2: Activate the same record by pointer and keyboard.

**Expected evidence:** Both produce the same selection summary.

**Progressive hint:** Input methods should converge on application state, not implement subtly different data transformations.

### Exercise 3: Build an accessible selection list beside the chart.

**Expected evidence:** Native buttons are reachable and reveal exact record values.

**Progressive hint:** A chart can have a rich visual layer while retaining a simple semantic interaction route.

### Exercise 4: Diagnose a tooltip offset after SVG scaling.

**Expected evidence:** Coordinates were measured in the wrong space.

**Progressive hint:** Choose the target coordinate system and use the corresponding conversion.

### Exercise 5: Keep essential values available without hover.

**Expected evidence:** A summary or data list remains visible and usable.

**Progressive hint:** Hover is not universal.

### Exercise 6: Review focus and announcement behavior.

**Expected evidence:** Focus stays predictable and the live summary is concise.

**Progressive hint:** Avoid moving focus on every hover or announcing a large changing DOM.

## Debugging and common mistakes

If a tooltip appears offset after the SVG scales, check the coordinate space: `d3.pointer(event, svgNode)` returns coordinates in the SVG's user space, while `event.clientX` is in page pixels. Insert labels with `.text()` so markup such as `<strong>` stays literal, and check that the pointer and keyboard paths call the same update function. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a tooltip offset after SVG scaling. Distinguishing evidence: Coordinates were measured in the wrong space.

## Accessibility and interpretation

Hover is unavailable to keyboard and many touch users, so every value revealed on hover must also be reachable another way. Native `button` elements receive focus and Enter and Space activation without extra code. Keep a visible focus outline and a short live summary that announces the selected record once. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

A tooltip that shows rounded or partial values misleads when it is the only place exact numbers appear. Interaction should help a reader inspect the claim the static chart makes, not reveal a different one, so keep the selected record's exact values and units in visible text. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
