## The question and the mechanism

Explain why a mean over observed sale days differs from revenue per eligible calendar day.

A rolling window requires an anchor, direction, interval size and boundary convention. For the three-day window ending February 3,2025, the included dates are February 1,2 and 3. DATESINPERIOD with a negative day count describes that backward interval. The interval token DAY is an enumeration, not a quoted text value.

The window contains revenue 56 on two sale dates, but three eligible calendar dates. Revenue per calendar day is 56/3. AVERAGEX over the date set with a revenue measure excludes a blank day and instead averages 20 and 36, giving 28. Replacing each known empty day's measure with zero changes that average back to 56/3.

Zero-filling is justified here only because the entire window is inside the fixture's declared observation coverage. An unavailable future date is not an observed zero. This population rule should be part of a metric contract, especially when dashboards compare windows with different coverage or event intensity.

## Vocabulary and expression anatomy

The reference binds the window table once, then uses it as a CALCULATE filter. The second case iterates that same date set to contrast blank-excluding and zero-filled averages. Context transition occurs when [NetRevenue] is invoked for each date row.

Concepts to explain in your own words: **DATESINPERIOD**, **rolling window**, **calendar weighting**, **zero versus blank**.

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: A three-calendar-day denominator

**Starting context:** AnchorFebruary 3,2025; included calendar days February 1,2,3; all observed.

```dax
EVALUATE CALCULATETABLE ( VAR WindowDates = DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -3, DAY ) VAR RevenueInWindow = CALCULATE ( [NetRevenue], WindowDates ) RETURN ROW ( "Days", COUNTROWS ( WindowDates ), "Revenue", RevenueInWindow, "RevenuePerCalendarDay", DIVIDE ( RevenueInWindow, COUNTROWS ( WindowDates ) ) ), 'Date'[Date] = DATE ( 2025, 2, 3 ) )
```

**Context trace:**

1. February 1 has no order, February 2 contributes 20 and February 3 contributes 36.
2. Window revenue is 56 and the Date table supplies three eligible dates.
3. The calendar-day ratio is 56/3.

**Hand-derived worked-reference result:**

| Days | Revenue | RevenuePerCalendarDay |
| --- | --- | --- |
| 3 | 56 | 18.66666667 |

The denominator is independent of whether a sale happened on a given included date. That is what makes it a calendar-day rate.

### Case B: Two different averages over the same window

**Starting context:** Same three observed calendar dates; contrast exclusion of BLANK with an explicit zero policy.

```dax
EVALUATE CALCULATETABLE ( VAR WindowDates = DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -3, DAY ) RETURN ROW ( "SaleDayAverage", AVERAGEX ( WindowDates, [NetRevenue] ), "ObservedCalendarAverage", AVERAGEX ( WindowDates, COALESCE ( [NetRevenue], 0 ) ) ), 'Date'[Date] = DATE ( 2025, 2, 3 ) )
```

**Context trace:**

1. The unfilled values are BLANK,20,36.
2. The blank-excluding average is 56/2 =28.
3. The zero-filled observed-calendar values 0,20,36 average 56/3.

**Hand-derived worked-reference result:**

| SaleDayAverage | ObservedCalendarAverage |
| --- | --- |
| 28 | 18.66666667 |

Neither name should be shortened to average daily revenue without identifying the denominator. A small blank-handling change can alter the business meaning.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Only February 2 and 3 are included.
2. The dates are January 2,3,4.
3. Include time role, boundary, coverage and weighting unit.
4. The display may have removed eligible denominator rows.
5. The model's calendar extends beyond its observation watermark.
6. Choose whether all scheduled intervals or only recorded observations count.
