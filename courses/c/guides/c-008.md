# c-008: Pointers, addresses and explicit mutation

## Level and prerequisites

Beginner, approximately 90 minutes plus a later retrieval session. Direct prerequisites: `c-007`

## Learning objectives

Use pointers to read or update a caller-owned object and reject a null target before dereferencing it. Along the way, explain pointer target, dereference and lifetime. Implement the six investigations, from the "change a caller-owned value" case to the "transfer a swap contract" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A pointer identifies an object or function, or holds a null value. Dereferencing a pointer requires a live target with appropriate type, alignment and access permissions. C does not keep an object alive merely because a pointer still refers to it. A pointer to an automatic local object becomes invalid when that object lifetime ends. Passing a pointer copies the pointer value, while mutation through it can affect the caller-owned target. Prefer an explicit pointer contract over hidden global state. A null check is necessary for optional pointers, but it cannot prove that a non-null pointer still refers to valid storage.

## Vocabulary and concepts

- **Pointer target:** The object a pointer designates.
- **Dereference:** Accessing the target through its pointer.
- **Lifetime:** The interval during which an object exists and may be accessed.

## Syntax anatomy and execution trace

&object obtains an address and *pointer accesses its target. int *p declares a pointer to int. Parentheses matter: *p += 1 changes the target, while p += 1 changes the pointer position. NULL is a null pointer constant. A function can return a pointer to caller-owned or static storage if its lifetime is documented, but must not return a pointer to an expired automatic local.

## Worked example / walkthrough

### Worked example 1: Change a caller-owned value

Increment integer 4 through its address.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

void increment(int *p) { *p += 1; }
bool set_if_present(int *p, int value) {
  if (p == NULL)
    return false;
  *p = value;
  return true;
}
void swap_ints(int *a, int *b) {
  int saved = *a;
  *a = *b;
  *b = saved;
}

int main(void) {
  /* Change a caller-owned value */
  {
    int n = 4;
    increment(&n);
    CHECK(n == 5);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The caller value becomes 5.

The helper receives a pointer copy, but that copy still designates the original integer.

### Worked example 2: Read a target copy

Copy the integer behind a pointer, then change the target.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

void increment(int *p) { *p += 1; }
bool set_if_present(int *p, int value) {
  if (p == NULL)
    return false;
  *p = value;
  return true;
}
void swap_ints(int *a, int *b) {
  int saved = *a;
  *a = *b;
  *b = saved;
}

int main(void) {
  /* Change a caller-owned value */
  {
    int n = 4;
    increment(&n);
    CHECK(n == 5);
  }

  /* Read a target copy */
  {
    int n = 3;
    int *p = &n;
    int copy = *p;
    *p = 9;
    CHECK(copy == 3 && n == 9);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The copied value stays 3 and the target becomes 9.

Dereferencing to obtain an int copies that scalar value. Retaining the pointer would retain access to future target changes.

### Exercise 1: Change a caller-owned value: change one input

In worked example 1, change `int n = 4;` to `int n = 5;`. Predict which value the CHECK on `n == 5` sees, then run and restore.

**Expected:** `Check failed` at `n == 5`; restoring `int n = 4;` passes again.

**Verify:** Name the value that made `n == 5` false, where worked example 1 showed that the caller value becomes 5.

**Progressive hints:** First trace `n` from initialization. Then compute what the CHECK sees with `int n = 5;` in place.

### Exercise 2: Read a target copy: debug a regression

In worked example 2, `int n = 3;` now reads `int n = 4;`. Repair it so that the copied value stays 3 and the target becomes 9 again.

**Expected:** `Check failed` at `copy == 3 && n == 9` until the line reads `int n = 3;` again.

**Verify:** Explain how `int n = 4;` changes the value `copy == 3 && n == 9` tests, using your failing and repaired runs.

**Progressive hints:** First trace `copy` and `n` from initialization. Then compare `int n = 4;` with worked example 2's original line.

### Exercise 3: Reject an absent target

Pass NULL to an optional update helper.

**Expected:** The helper returns false without an access.

**Verify:** Keep a CHECK equivalent to `!set_if_present(NULL, 8)`. Control edit: `CHECK(set_if_present(NULL, 8));` must fail; then restore it.

**Progressive hints:** First work out what `set_if_present` returns here. Then recall: Null is a valid absence representation under this helper contract.

### Exercise 4: Update a present target

Pass an integer address to the same helper.

**Expected:** The helper returns true and stores 8.

**Verify:** Keep a CHECK equivalent to `set_if_present(&n, 8) && n == 8`. Control edit: `CHECK(set_if_present(&n, 9) && n == 8);` must fail; then restore it.

**Progressive hints:** First trace `n` from initialization. Then recall: The caller owns the object and keeps it alive throughout the call.

### Exercise 5: Distinguish pointer and target change

Point p at a, then reassign p to b.

**Expected:** Neither integer changes merely because p changes.

**Verify:** Keep a CHECK equivalent to `a == 2 && b == 7 && *p == 7`. Control edit: changing `int a = 2, b = 7;` to `int a = 3, b = 7;` must fail it; then restore it.

**Progressive hints:** First trace each value in `a == 2 && b == 7 && *p == 7` from initialization. Then recall: Pointer assignment changes which object is designated.

### Exercise 6: Transfer a swap contract

Swap two caller-owned integers through pointers.

**Expected:** The values exchange positions.

**Verify:** Keep a CHECK equivalent to `a == 7 && b == 2`. Control edit: changing `int a = 2, b = 7;` to `int a = 3, b = 7;` must fail it; then restore it.

**Progressive hints:** First trace `a` and `b` from initialization. Then recall: A temporary preserves the first value before overwriting it.

## Common pitfalls and diagnosis

Returning the address of a local variable: the pointer outlives its target, so any later read is undefined. Confusing `p = q`, which retargets the pointer, with `*p = *q`, which changes the target's value, is the other common slip.
