## Bound both the candidate set and the generation process

A language model may assign a small amount of probability to many possible continuations. Sampling from the entire distribution can select unlikely alternatives, while always taking the maximum removes variation. Nucleus sampling offers a different policy: retain enough of the highest-probability candidates to cover a chosen amount of the original mass, then sample within that set. Its support size adapts to how concentrated the current distribution is.

The example distribution is [0.5,0.3,0.2], already in descending order. With threshold 0.6, the first candidate alone covers only 0.5, so it is insufficient. Adding the second reaches 0.8, which crosses the threshold. The smallest qualifying prefix contains two candidates. The threshold is a minimum covered mass, not a requirement that the retained mass equal exactly 0.6. Discrete candidate probabilities generally prevent exact equality.

After selection, divide the retained masses by 0.8 to obtain [0.625,0.375]. The omitted candidate gets probability zero under this policy. The sampling distribution has changed deliberately; it is not the original model distribution with an unused row hidden from display. Top-k would keep a fixed number of candidates even if their probabilities changed, while top-p chooses the count from the mass. If a single candidate had probability 0.9, threshold 0.6 could retain only that candidate.

The order of policy operations matters. Temperature changes probabilities, which can change which candidates are needed to cross a top-p threshold even when their ranking stays the same. Stable tie handling also matters when equally probable candidates straddle a boundary. Preserve the original vocabulary IDs when sorting: a sampled position in the retained array must be mapped back to the token it represents. In this fixture, the retained positions happen to be IDs zero and one, which makes the mapping easy to overlook.

A generation loop needs a stopping contract independently of its sampler. The literal token stream [2,3,9,4] stops at EOS token 9, leaving stored output [2,3,9]. The next token 4 is never appended. Another loop with no EOS stops after three generated tokens because of its explicit cap. The first outcome means the designated termination token was observed; the second means the budget was exhausted. A caller may need to distinguish them, especially if truncated JSON or an incomplete calculation is not an acceptable answer.

The cap counts newly generated tokens, while the model's total context also includes the prompt and any retained history. Hitting neither the output cap nor EOS does not make an arbitrarily long context valid. Position limits and cache capacity remain separate constraints. Likewise, hiding EOS from displayed text does not change whether it was stored or counted by the generation process.

Two local generators seeded identically produce the same draws in the tested runtime because they use the same support and call sequence. Changing earlier calls or the policy can alter later outputs. Treat a generation result as the product of model state, prefix, sampling configuration, random state and stopping rules. None of these mechanisms independently establishes that the resulting answer is supported by evidence.
