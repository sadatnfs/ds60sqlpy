# asm-013: Typed Scala aggregation and merge laws

Tutorial mode. Stage: intermediate. Direct prerequisites: `asm-006`, `spark-007`.

## Starting point and result

A typed `Aggregator[IN, BUF, OUT]` separates observations, intermediate summaries and final results. This makes the algebra of a distributed summary explicit. Our input is a double, our buffer stores a long count and double total, and our output preserves both. Retaining count avoids prematurely replacing a sufficient summary with a partition mean.

## Key terms

- **Aggregator:** A typed Spark interface with input, buffer and output types and the zero, reduce, merge and finish methods.
- **Monoid:** A collection with an associative combine operation and an identity element, which lets partial results merge in any tree shape.
- **Merge law:** The rule that merging buffers (n1, s1) and (n2, s2) yields (n1 + n2, s1 + s2) regardless of partition boundaries.
- **Encoder:** The description of how JVM objects become Spark's internal representation for buffers and outputs.
- **Empty-input policy:** The declared output when no observations arrive, which the identity buffer must support without dividing by zero.

## Mechanism: define the identity and merge law

The buffer is \(b=(n,s)\), with identity \(e=(0,0)\). Adding observation x produces \((n+1,s+x)\); merging two buffers produces \((n_1+n_2,s_1+s_2)\). A monoid is a collection with an associative operation and an identity. These properties let the engine combine partial results in different tree shapes without changing the exact-arithmetic meaning.

Spark calls `zero` for the initial buffer, `reduce` for observations, `merge` for partial buffers and `finish` for the output. Encoders describe how JVM objects become Spark's internal representation. They are part of execution, not a substitute for validating the statistical contract. Our immutable case class keeps aliasing simple. A mutable buffer may reduce allocation, but reusing a shared mutable identity or accidentally mutating both merge inputs can corrupt results.

The merge law is mathematically associative over exact sums. Double addition is only approximately associative. The chapter's small integers are exactly represented, so fixture equality is appropriate. General likelihood summaries need the precision and tolerance policy from asm-008. A declaration of “monoid” does not repeal floating-point arithmetic.

## Worked case: merge unequal partitions correctly

Four observations, 1, 3, 3 and 3, are converted to a typed Dataset. The program evaluates the aggregator after repartitioning to one and then three partitions. Both outputs must be `Summary(4, 10)`, and the final mean is 2.5. No task divides by its local count. A mean is formed only after global merging.

The direct merge checks combine three buffers in two parenthesizations and verify the identity on a nonempty buffer. These are focused fixtures rather than a proof for every possible value. The algebra above supplies the proof in exact arithmetic; property tests and numerical stress cases extend implementation evidence.

## Worked case: empty input has a valid summary

An empty typed Dataset returns the identity summary. This is useful: count zero and sum zero are well-defined. The corresponding mean is not defined, so a caller must check the denominator before dividing. Returning zero as the mean of no observations would confuse absence with a measured value.

The choice to return a summary instead of a double therefore preserves information needed by downstream validation. For weighted data, retain accepted row count and total weight separately. A zero weight sum may occur even when rows were present.

## Worked example: exhaustive merge checks for the count and sum buffer

```python
from itertools import combinations

values = [1.0, 3.0, 3.0, 3.0]
zero = (0, 0.0)


def reduce_rows(rows):
    return (len(rows), sum(rows))


def merge(a, b):
    return (a[0] + b[0], a[1] + b[1])


def merge_means(a, b):
    means = [s / n for n, s in (a, b) if n]
    return (a[0] + b[0], sum(means) / len(means) * (a[0] + b[0]) if means else 0.0)


results = {"merge": set(), "merge_means": set()}
for cut1, cut2 in combinations(range(len(values) + 1), 2):
    parts = [values[:cut1], values[cut1:cut2], values[cut2:]]
    for name, fn in (("merge", merge), ("merge_means", merge_means)):
        acc = zero
        for part in parts:
            acc = fn(acc, reduce_rows(part))
        results[name].add(acc)
print({name: sorted(found) for name, found in results.items()})
print("identity:", merge(zero, (4, 10.0)) == (4, 10.0), "empty:", reduce_rows([]))
```

Output from running the block above:

```text
{'merge': [(4, 10.0)], 'merge_means': [(4, 8.0), (4, 10.0), (4, 10.666666666666668), (4, 11.0)]}
identity: True empty: (0, 0)
```

This Python model of the typed buffer enumerates every way to cut the four observations 1, 3, 3, 3 into three ordered chunks, including empty ones, and folds the reduced chunks with each merge function. The correct merge of counts and sums reaches the same buffer, (4, 10.0), for all ten splits, so the final mean is 2.5 wherever the partition boundaries fall. The faulty merge, which averages chunk means and rescales, produces four different totals between 8 and 11 depending on the split. A single Dataset run would show only one of those values, which is the reason the chapter tests merge directly. The last line checks that the zero buffer is a true identity and that an empty chunk reduces to (0, 0) without dividing.

## Failure diagnosis

A result that changes substantially with partition count suggests a broken merge law or an aliased buffer. A missing encoder is a serialization/schema problem, not an optimizer failure. A result that is correct on one partition but wrong on two often indicates that `reduce` works while `merge` discards a field or applies normalization twice.

## Interview discussion

**Why test merge directly when the Dataset example passes?** A single physical execution may not exercise every merge shape or empty-buffer combination. Direct tests isolate the contract on which all distributed plans depend.

**Could an aggregate fit an entire optimizer?** A mergeable sufficient-statistic model may permit a closed-form fit at `finish`. A general iterative likelihood usually needs repeated evaluations at shared parameters, not arbitrary optimizers hidden in each buffer.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-scala`.

```scala
import org.apache.spark.sql.{SparkSession, DataFrame, Dataset, Encoder, Encoders}
import org.apache.spark.sql.functions._

import org.apache.spark.sql.expressions.Aggregator

case class Summary(n: Long, total: Double)
class SumCount extends Aggregator[Double, Summary, Summary] {
  def zero: Summary = Summary(0L, 0.0)
  def reduce(b: Summary, x: Double): Summary = Summary(b.n + 1L, b.total + x)
  def merge(a: Summary, b: Summary): Summary = Summary(a.n + b.n, a.total + b.total)
  def finish(b: Summary): Summary = b
  def bufferEncoder: Encoder[Summary] = Encoders.product[Summary]
  def outputEncoder: Encoder[Summary] = Encoders.product[Summary]
}
object Main {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder
      .master("local[2]")
      .appName("advanced-spark-modeling")
      .config("spark.ui.enabled", "false")
      .config("spark.driver.host", "127.0.0.1")
      .config("spark.driver.bindAddress", "127.0.0.1")
      .config("spark.sql.shuffle.partitions", "2")
      .config("spark.sql.adaptive.enabled", "false")
      .config("spark.sql.ansi.enabled", "true")
      .getOrCreate()
    require(spark.version == "4.3.0", "This example targets Spark 4.3.0")
    spark.sparkContext.setLogLevel("ERROR")
    import spark.implicits._
    try {
      val aggregate = new SumCount
      val values = Seq(1.0, 3.0, 3.0, 3.0).toDS()
      for (partitions <- Seq(1, 3)) {
        val result = values.repartition(partitions).select(aggregate.toColumn).head()
        require(result == Summary(4L, 10.0))
        println(
          s"partitions=$partitions count=${result.n} sum=${result.total} mean=${result.total / result.n}"
        )
      }
      val a = Summary(1L, 1.0); val b = Summary(2L, 6.0); val c = Summary(1L, 3.0)
      require(aggregate.merge(aggregate.zero, a) == a)
      require(
        aggregate.merge(aggregate.merge(a, b), c) == aggregate.merge(a, aggregate.merge(b, c))
      )
      val empty = Seq.empty[Double].toDS().select(aggregate.toColumn).head()
      require(empty == aggregate.zero)
      println("identity, associative fixture and empty input passed; arbitrary doubles still round")
    } finally { spark.stop() }
  }
}
```
