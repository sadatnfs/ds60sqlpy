## Outcome and mechanism

Combine chunk-level sufficient statistics correctly and distinguish a memory strategy from a performance claim.

A table may be larger than a convenient in-memory intermediate. Processing it in chunks can reduce the peak size of some operations, but only when the output state can be combined correctly. A sum and count are straightforward mergeable state for an observed-value mean. An unweighted mean of chunk means is generally wrong when chunk sizes differ.

Define the state before the loop. Each chunk can return observed count, missing count and observed sum. Combining those fields by addition preserves enough information for the final mean. The final all-missing policy still matters: zero total count should produce the declared missing result rather than an accidental division by zero.

Not every operation is equally mergeable. An exact median requires more distribution information than one number per chunk. A distinct count requires the union of keys or a deliberately chosen approximate sketch with an error contract. A join may require partitioning by keys, external storage or an indexed lookup. Chunking syntax alone does not solve those algorithmic requirements.

Floating-point addition is not perfectly associative. Two mathematically equivalent reduction orders can differ slightly when magnitudes vary greatly. Tests should distinguish harmless representation error from a changed population or weighting rule. These tiny examples establish semantic equivalence and bounded state size; they do not claim measured speed, memory savings on a large production workload or automatic parallel execution.

## Read the syntax

Represent state as a named numeric vector or list, update it per chunk, and compute the final statistic once. Test uneven chunk sizes and all-missing input. Use an explicit tolerance when reduction order can change floating-point rounding.

## Worked examples

### Example 1: Combine sums and counts, not means

```r
chunks <- list(c(10), c(20, 30, 40))
state <- c(count = 0, total = 0)
for (chunk in chunks) {
  state <- state + c(count = length(chunk), total = sum(chunk))
}
mean_from_state <- state[["total"]] / state[["count"]]
stopifnot(mean_from_state == 25, mean(vapply(chunks, mean, numeric(1))) == 20)
print(state)
```

**Expected observation:** Count 4, total 100, mean 25.

The two chunks have unequal sizes. Sufficient totals reconstruct the observation mean while averaging the two chunk means changes the weighting.

### Example 2: A chunked missingness ledger

```r
chunks <- list(c(1, NA_real_), c(3, 5), c(NA_real_))
state <- c(observed = 0, missing = 0, total = 0)
for (chunk in chunks) {
  valid <- !is.na(chunk)
  state <- state + c(observed = sum(valid), missing = sum(!valid), total = sum(chunk[valid]))
}
stopifnot(state[["observed"]] == 3, state[["missing"]] == 2, state[["total"]] == 9)
print(state)
```

**Expected observation:** Observed 3, missing 2, total 9.

Each input entry contributes to either observed or missing count. The total uses only observed measurements under the declared policy.
