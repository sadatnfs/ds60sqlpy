# Template types and the objective contract

Start with: tmb-001, cpp-020.

Outcome: Separate data shapes from optimized parameters and detect a malformed design.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

The signature `template<class Type> Type objective_function<Type>::operator()()` defines a function object that returns one scalar of type `Type`. During ordinary evaluation, that type can represent a numerical value; during derivative recording, it carries the information needed for chain-rule calculations. Replacing model intermediates with `double` can detach them from differentiation or fail compilation. Use `Type` for parameter-dependent scalars and `vector<Type>` or `matrix<Type>` for their arrays.

`DATA_VECTOR(y)` reads a named numeric vector from the R data list. `PARAMETER(mu)` reads a scalar from the parameter list. `PARAMETER_VECTOR(beta)` declares several optimized coefficients. These macros are interface declarations, not estimates. Their spelling must match list names exactly. The flattened parameter order follows template declarations, not a guessed alphabetical order.

### Worked case A: a two-column regression

For \(\mu=X\beta\), let \(X\) have four rows and two columns and let \(\beta=(\beta_0,\beta_1)^T\). The first column is one, representing an intercept. The second contains the predictor. Matrix multiplication combines each row with the same parameter vector. A vector of two coefficients is necessary because there are two columns, regardless of the number of observations.

```cpp
DATA_MATRIX(X);
PARAMETER_VECTOR(beta);
vector<Type> mean = X * beta;
```

The companion shows the four fitted means and checks the dimensions. R uses one-based indexing; C++ and the `group` contract in our project use zero-based indexing. Convert group labels once at the boundary and retain the original labels outside the numerical model.

### Worked case B: a plausible shape error

Removing the intercept from `X` while leaving two coefficients is a shape mismatch. More subtly, reordering columns while keeping coefficient names creates a numerically valid but scientifically wrong model. Validate both dimensions and the meaning/order of columns. The companion deliberately checks and reports a rejected shape without relying on a compiler crash. Our R API rejects missing, non-finite or mismatched arrays before entering C++.

Some quantities could be data or parameters depending on the question. A calibrated sensor standard deviation can be fixed data. An unknown standard deviation is a parameter, usually represented by its logarithm. Moving it into `DATA_SCALAR` stops optimization and derivative propagation with respect to that quantity. Conversely, declaring a covariate as a parameter asks the optimizer to change the data-generating explanation in a different model.

### Diagnostics and answered discussion

**Can I optimize a different number of groups with the same objective?** Changing latent dimensions requires a newly constructed objective with matching parameter shapes. Do not mutate the old flat vector and hope the tape adapts. **Why keep identifiers out of numeric matrices?** Labels are keys, not measurements. Turning a long identifier into a floating-point value can lose exact identity. **Why does `Type(0)` appear?** It constructs a constant in the same arithmetic type as the objective. Compile-time integers used for loop indices remain ordinary integers.

Consult the [TMB manual](https://cran.r-project.org/web/packages/TMB/TMB.pdf), particularly `MakeADFun` and `map`. This course's `R/api.R` is a deliberately small fixed-model interface; more general model authoring still needs explicit shape and domain checks.

### Complete R companion

```r
x <- c(-1, 0, 1, 2)
X <- cbind(intercept = 1, x = x)
beta <- c(intercept = 2, x = .5)
print(drop(X %*% beta))
stopifnot(nrow(X) == length(x), ncol(X) == length(beta))
wrong <- matrix(x, ncol = 1)
shape_ok <- function(design, parameter) ncol(design) == length(parameter)
print(list(valid = shape_ok(X, beta), rejected = !shape_ok(wrong, beta)))
stopifnot(!shape_ok(wrong, beta))
```
