## Treat a tiny training run as a complete experiment

The earlier chapters built the pieces of a decoder and explained how to inspect their shapes, losses and cache behavior. This capstone puts those pieces into one bounded experiment. Its purpose is to make a whole training-and-evaluation workflow understandable, including the possibility that the neural model does not beat a simple baseline. A completed optimizer loop is an observation about computation; an improvement on a frozen holdout is an observation about that particular prediction problem.

The authored training documents are[1,2,3,4] and[1,2,4,3]. The held-out document is[1,3,2,4]. Token IDs come from a fixed vocabulary of size 16. Each length-four document supplies three next-token targets, so the training batch contains six target events and the holdout contains three. There is no implicit EOS target in this fixture. These counts define the loss denominator and the count model's transition observations.

### Follow the forward path from IDs to logits

The training input batch has shape(2,3): the first three IDs from each document. Labels are the last three IDs, also shaped(2,3). A token embedding and learned position embedding each contribute width 32 features, producing a hidden array shaped(2,3,32). Adding them combines lexical identity and position at the same token coordinates; it does not concatenate them into width 64.

The first LayerNorm acts over each token's 32 features. A single bias-free QKV projection maps width 32 to width 96, then splits into three width 32 arrays. With two heads, each head has width 16. Reshaping and transposing gives Q,K,V shapes(2,2,3,16): batch, head, token, head-feature. The score array is(2,2,3,3), and its lower-triangular access rule prevents a query from using later input positions.

The weighted values return to shape(2,3,32), pass through an output projection and join the first residual path. A second LayerNorm and a feed-forward transformation 32→64→32 form the second residual branch. The final vocabulary projection produces logits shaped(2,3,16). These are unnormalized scores for each next-token target. Flattening to(6,16) and flattening labels to(6,) merely presents the same six events to cross entropy; it does not create six independent documents.

This shape trace also gives a parameter audit. Token embeddings contribute \(16\cdot 32=512\) entries and position embeddings \(32\cdot 32=1024\). Two LayerNorms each have 32 gains and 32 biases, totaling 128. QKV contributes \(32\cdot 96=3072\) and its output projection \(32\cdot 32=1024\). The feed-forward layers contribute \(32\cdot 64+64\) plus \(64\cdot 32+32\), totaling 4192. The vocabulary projection contributes \(32\cdot 16=512\). Altogether the model has 10,464 parameters under the exact bias choices in the reference, comfortably below the declared 50,000 cap. The count is a structural fact, not a claim that the model has enough data to estimate all those parameters reliably.

### Understand what one optimizer step changes

Every update clears previous gradients, computes logits on the same six training targets, forms mean cross entropy, differentiates that scalar, and applies an Adam update. The loop performs 20 such updates. Because the dataset is tiny, these updates repeatedly revisit the same authored transitions. Repeated exposure can reduce training loss without adding new information about unseen document families.

The loss stored in `curve` is computed before that iteration's parameter update. The final recorded curve point therefore describes the parameters entering the twentieth step, while a later evaluation uses parameters after it. This distinction matters when reproducing an exact training trace. The test requires 20 finite values and the parameter bound; it does not require a particular monotonic curve or claim that every update improves the loss.

The seed fixes initialization for this runtime's random-number sequence. It helps reproduce the small experiment, but one seed does not establish robustness across initializations or implementations. Optimizer version, dtype, operation order and platform can matter to exact numeric output. For the lesson's conclusion, retain the runtime and source identity with the measured losses rather than turning a seed into a universal reproducibility guarantee.

### Reconstruct the count baseline independently

The count model observes transitions within each training document. Token 1 is followed by 2 twice. Token 2 is followed by 3 once and 4 once. Token 3 is followed by 4 once, and token 4 is followed by 3 once. These six observations match the target count. No transition is invented between the end of one document and the start of another.

Add-one smoothing over 16 candidates gives \(\Pr(v\mid u)=\frac{C_{uv}+1}{C_{u}+16}\). The held-out path contains 1→3,3→2 and 2→4. Their probabilities are 1/18,1/17 and \(\frac{2}{18}=\frac{1}{9}\). The baseline's held-out mean negative log likelihood is therefore \(\frac{\log18+\log17+\log9}{3}=\frac{\log2754}{3}\), approximately 2.6403 nats per target. This number can be derived without training a neural network, making it a useful independent oracle for the evaluation pipeline.

Why can a uniform predictor over 16 candidates have loss \(\log(16)\)≈2.7726 while this smoothed model is slightly better on the holdout despite missing two transitions? The known 2→4 transition receives probability \(\frac{1}{9}\), above the uniform \(\frac{1}{16}\). That improvement partly compensates for the two unseen transitions receiving smaller probabilities. This is a concrete example of an aggregate log score combining benefits and failures rather than simply counting how many transitions were previously observed.

### Score the same target events under both models

The neural model receives[1,3,2] as context positions and predicts[3,2,4]. Evaluation mode and no-grad prevent the scoring call from intentionally performing a training update or retaining a backward graph. The mean is over exactly three targets. The count baseline scores the same transitions. This alignment matters more than the fact that both results are called "loss."

A fair comparison also keeps preprocessing, vocabulary, target inclusion and holdout identity fixed. If the baseline were allowed to fit the held-out transitions, or the neural model were scored only on an easy subset, the resulting numbers would answer different questions. Likewise, choosing the 20-update budget after repeatedly viewing this final holdout would use it for model selection. In the authored demonstration, the budget is fixed beforehand.

The reference asserts that both held-out losses are finite. It deliberately does not assert that the neural loss is lower. A model with more parameters and a more expressive architecture can overfit, optimize poorly, or fail to generalize from two tiny documents. Reporting that outcome accurately is a successful experiment, not an error to repair by adding the holdout to training.

### Retest the information boundary after fitting

Parameter updates should change learned preferences while preserving the causal access rule. The capstone recomputes the first two positions separately and compares their logits with the corresponding prefix of the full input. Agreement within the stated tolerance supports prefix invariance for the trained model and checked sequence. It is different evidence from the holdout loss.

A model can pass this causal test and still have seen the evaluation answers during data construction. It can also have a valid split but an incorrect loss denominator. Use independent checks for independent failure modes: transition counts and label shifting for the scoring contract, family identities for the split, prefix recomputation for information flow, and actual held-out losses for the measured comparison. One passing assertion should not stand in for all four.

### Read hashes as identities, not endorsements

The split hash records the serialized partition mapping. The model hash records parameter bytes under the known code and ordering used by this fixture. A matching hash helps identify which artifact was evaluated. It does not authenticate a publisher, prove that the split is independent, or show that a metric was computed correctly. A reusable production artifact would also need architecture, tokenizer, names, shapes, dtypes and relevant version/configuration information bound into its identity.
