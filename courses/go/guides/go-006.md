## Why this mechanism matters

A map associates keys with values. Reading an absent key returns the value type's zero value, which can be indistinguishable from a present key whose value is zero. The comma-ok form retains the presence information. Map iteration order is deliberately unspecified; reproducible reports must extract and sort keys rather than rely on an observed order. Maps share mutable storage when assigned, and ordinary maps are not safe for concurrent mutation without synchronization. A nil map can be read but cannot accept an assignment. Treat these properties as part of the data model when building counters, caches and configuration overlays.

## Vocabulary and concepts

- **Key:** A comparable value identifying a map entry.
- **Presence bit:** The boolean distinguishing an existing entry from absence.
- **Deterministic order:** An explicitly chosen ordering independent of map iteration.

## Syntax anatomy and reasoning

map[string]int declares string keys and integer values. value, ok := counts[key] distinguishes absence from zero. make initializes writable map storage. delete removes a key and is harmless if the key is absent. range gives key/value pairs in an unspecified order. Use sort.Strings on extracted keys before producing ordered output.

## Worked example / walkthrough

### Worked example 1: Distinguish zero from missing

Read present key zero and absent key missing with comma-ok.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Distinguish zero from missing
	{
		m := map[string]int{"zero": 0}
		a, okA := m["zero"]
		b, okB := m["missing"]
		check(a == b && okA && !okB, "presence")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** Both values are 0, but only zero is present.

A numeric value alone cannot represent both absence and an intentional zero without losing information.

### Worked example 2: Build a frequency table

Count red, blue and red.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Distinguish zero from missing
	{
		m := map[string]int{"zero": 0}
		a, okA := m["zero"]
		b, okB := m["missing"]
		check(a == b && okA && !okB, "presence")
	}

	// Build a frequency table
	{
		m := map[string]int{}
		for _, v := range []string{"red", "blue", "red"} {
			m[v]++
		}
		check(m["red"] == 2 && m["blue"] == 1, "counts")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** red has count 2 and blue has count 1.

Missing counts start at the zero value, which is useful here because zero is the correct additive identity.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
