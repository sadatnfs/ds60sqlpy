## Purpose and mental model

### Translate the mathematical contract before translating the API

Two frameworks can implement the same mathematical operation while storing weights differently, arranging axes differently or assigning opposite meanings to a boolean mask. A successful import or matching tensor shape therefore does not establish parity. Begin with an equation, explicit dimensions and a small literal fixture whose expected values can be calculated independently. Then map that contract to each API.

This chapter is a reading comparison. It does not require installing a second framework or running TensorFlow to continue the course. The executable lessons elsewhere provide actual runtime evidence for their own profiles. Here the goal is to understand what must be matched before a cross-framework result can be interpreted as the same computation.

#### Use a rectangular projection to expose orientation

In row-vector notation, let X have shape(N,d_in) and W have shape(d_in,d_out). The projection is \(Y=XW+b\). NumPy multiplication and a Keras Dense kernel use this orientation directly. PyTorch Linear stores its weight with shape(d_out,d_in) and applies the corresponding transposed multiplication. The stored array must therefore be transposed when translating this particular equation.

The fixture uses \(X=[1,2]\) and \(W=[[1,2,3],[4,5,6]]\), so the output is[9,12,15]. The PyTorch-style stored weight is[[1,4],[2,5],[3,6]], shaped(3,2). A square symmetric matrix would be a poor translation test because transposing it could leave its values unchanged. The rectangular dimensions and distinct entries make the error visible.

The backward contract should match too. If the upstream derivative is \(G=[1,-1,2]\), then \(\frac{\partial L}{\partial X}=G\) \({W}^{T}=[5,11]\). The gradient for the NumPy/Keras-oriented W is \({X}^{T}\) \(G=[[1,-1,2],[2,-2,4]]\). The corresponding PyTorch stored-weight gradient is its transpose. Agreement only on one forward output would not detect every gradient-layout or parameter-update mistake.

Bias handling is another independent field. A bias may be enabled by default in one layer and deliberately absent in the mathematical fixture. If one implementation adds a bias and the other does not, transposing weights cannot repair the mismatch. Match bias presence, values and broadcasting before moving to a larger network.

#### Write mask meaning as a sentence

For causal self-attention with shifted next-token labels, query row i may use keys j<=i. The three-token allowed matrix is rows 100,110,111. A forbidden matrix is its boolean complement, rows 011,001,000. The two matrices represent the same boundary only when the receiving API's boolean convention is known.

PyTorch functional scaled-dot-product attention uses a boolean attention mask whose True entries participate. PyTorch MultiheadAttention uses True in a boolean attention mask to prohibit that position, and True in its key-padding mask to ignore a key. Keras MultiHeadAttention describes its attention mask as allowed positions. These conventions should be checked against the exact versioned API documentation, not inferred from the shared word "mask."

The shape identifies another part of the meaning. A key-padding mask typically names unavailable source keys per batch item. A query-dependent causal mask has both query and key axes. A padding mask cannot express "query 0 cannot see key 1, but query 1 may see key 1" without the query dimension. Combining padding and causality requires a deliberate rule, such as allowing a key only when both its source-validity condition and its causal-position condition hold.

Boolean and floating masks are also different interfaces. A floating attention mask can be an additive score bias rather than a boolean inclusion array. Passing 0/1 values where a library expects additive biases can add preferences instead of blocking positions. State whether a mask is a boolean access rule or a numeric score adjustment and test a forbidden extreme-score case to distinguish the interpretations.

#### Cached and cross-attention shapes need separate checks

Self-attention over a complete sequence often uses a square score matrix. Cross-attention can have Tq target queries and Tk source keys, yielding shape(Tq,Tk). A single cached decode query can have \(\mathrm{Tq}=1\) while attending to many prior keys. Code that assumes a square triangle can accidentally allow only the first key because its local query-row index is 0 rather than the query's absolute sequence position.

A correct translation must preserve position offsets and cache layout as well as masks. One library may store batch before head, another may expose a different packed representation. Reshaping is not a substitute for a semantically correct transpose. Use distinct values for each batch, head and position so an axis permutation cannot pass by coincidence.

The same principle applies to returned attention weights. Some APIs average across heads by default or omit weights entirely when using an optimized path. Comparing an averaged tensor with an unaveraged head tensor can produce a misleading mismatch or an accidental broadcast. Specify exactly which intermediate is being compared.

#### Match numerical and mode conventions

Normalization needs the same axes, epsilon, gain/bias configuration and variance convention. A LayerNorm formula based on mean squared centered deviations is not automatically reproduced by a standalone variance function whose default uses a different correction. A small nonconstant vector and a common-shift test can expose the difference before it is buried in a full decoder.

Dtype and tolerance belong in the experiment. Float64 arithmetic in a tiny oracle can support a much tighter tolerance than a mixed-precision device kernel. The correct response to a mismatch is to locate the first divergent intermediate and understand its source, not immediately widen every tolerance. Relative tolerance matters for large-magnitude values, while absolute tolerance matters near zero; choose them according to the quantity and numeric contract.

Training/evaluation mode and gradient recording are separate controls. Evaluation mode can change dropout or normalization behavior in modules, while a no-grad context controls whether operations are recorded for differentiation. PyTorch's functional scaled-dot-product attention applies the explicitly supplied `dropout_p`; callers must pass 0 when they intend no dropout. A surrounding model's evaluation flag does not automatically rewrite that function argument. See the [versioned SDPA documentation](https://docs.pytorch.org/docs/2.9/generated/torch.nn.functional.scaled_dot_product_attention.html).

Equal seeds across frameworks do not imply equal initialized weights or identical random masks. Random-number algorithms, draw order and initialization formulas can differ. For a parity study, copy literal weights and inputs first and disable stochastic behavior. Only after deterministic parity is understood should random training behavior be compared under an appropriate statistical design.

#### Build a ladder of independent parity checks

Start with the rectangular linear layer and its gradients. Add normalization with explicit epsilon and axes. Add a single attention head with nonuniform scores, a forbidden key and a rectangular case. Then compare a residual block, followed by full-prefix and cached execution. At each level, preserve the earlier oracles so a later failure can be localized.

A model-level output that happens to match on one input is weak evidence if the input is symmetric or all zeros. Nonuniform literal fixtures are often more informative than large random arrays because their expected values can be traced by hand. Randomized tests can add coverage, but they should supplement rather than replace a few carefully chosen counterexamples.

API parity is not a claim that two different architectures or training recipes have equal quality. Even a mathematically equivalent operation can use different kernels and resource behavior. Report numerical agreement, gradient agreement, runtime performance and task generalization as separate results. The primary API references for [MultiheadAttention](https://docs.pytorch.org/docs/2.9/generated/torch.nn.MultiheadAttention.html) and [Keras MultiHeadAttention](https://keras.io/api/layers/attention_layers/multi_head_attention/) support the interface translation; actual execution remains specific to the tested environment.

## Match a mathematical map before matching framework names

For row input x=[1, 2] and W=[[1, 2, 3], [4, 5, 6]], x*W=[9, 12, 15]. A Keras Dense kernel for this map has shape[2, 3]. PyTorch Linear stores its weight as[out_features, in_features], so the same map uses W transposed with shape[3, 2], because its forward operation multiplies by the stored weight's transpose. Comparing equal-shaped square matrices can conceal this orientation error, which is why the worksheet uses a rectangular example.

A meaningful parity experiment explicitly assigns weights and biases, fixes dtype, uses the same epsilon and reduction rules, and selects equivalent training/evaluation modes. Matching a seed across two frameworks does not assign identical parameter arrays, since initialization algorithms and random streams can differ. Equal layer names are also insufficient when defaults, layouts or state updates differ.

## Boolean masks do not share one universal polarity

In [PyTorch functional scaled-dot-product attention](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html), a Boolean true entry permits attention. In [MultiheadAttention](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html), true in its Boolean attention mask means disallowed, and true in its key-padding mask marks an ignored key. A key-padding mask has a different shape and purpose from a causal attention matrix: a batch-by-key array cannot encode a distinct triangular restriction for every query position. Translate semantic intent, shape and polarity together.

[Keras MultiHeadAttention](https://keras.io/api/layers/attention_layers/multi_head_attention/) uses a Boolean attention mask that uses true for an allowed query/key relationship. This makes it similar to functional SDPA's polarity, but it does not make every broadcasting or call contract interchangeable. Draw a small allowed-relation table, then translate it into each API and verify which output changes when a future token changes. A passing output shape alone cannot detect reversed mask meaning.

Functional SDPA applies the dropout probability passed to the function. A surrounding module's eval mode does not automatically rewrite that numeric argument to zero. A wrapper should pass zero when evaluation requires deterministic attention and the configured probability only during training. This is a call-site policy, distinct from disabling autograd. The worksheet explains these contracts without claiming a new cross-framework runtime comparison; the dedicated framework routes provide their actual qualified examples.


## Worked example / walkthrough

### Example A: Translate linear weights

A square symmetric matrix would hide a transpose error. The rectangular fixture makes the orientation and output feature count explicit.

```text
X shape(1,2)
NumPy/Keras W shape(2,3): [[1,2,3],[4,5,6]]
```

**Expected:** PyTorch weight[[1,4],[2,5],[3,6]];all outputs[9,12,15].

### Example B: Translate a causal mask

The diagonal is allowed because inputs are paired with shifted next-token labels. Excluding it would remove the current token from its own prediction context.

```text
Allowed:
1 0 0
1 1 0
1 1 1
Forbidden:
0 1 1
0 0 1
0 0 0
```

**Expected:** allowedrows100,110,111;forbiddenrows011,001,000.

## Common pitfalls and diagnosis

Use rectangular literal weights to expose transposition errors. Check mask shape, meaning and polarity for the exact API, and do not use a padding mask as if it were a query-dependent causal mask. Match dtype, epsilon, modes and dropout arguments explicitly rather than assuming equal seeds or names imply parity.
