## Learning objectives

Prevent mixing semantically different values with the same representation.

## Vocabulary and concepts

A strong type wraps a representation in a domain name so unrelated values cannot be mixed accidentally. An explicit constructor blocks implicit conversions. A value API should obey simple laws, such as addition identity and equality symmetry. Domain restrictions must be enforced at construction or operation boundaries.

## Syntax and mechanism

`struct Cents { long long value; };` distinguishes money from a raw count. Define only meaningful operations. Cents+Cents can yield Cents, while adding a count should require a deliberate conversion. Avoid exposing unchecked arithmetic as a blanket promise for all long long values.

**Expected:** Zero is the addition identity for this bounded domain.
