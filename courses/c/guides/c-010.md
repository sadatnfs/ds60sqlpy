# c-010: Structs, enums and tagged domain values

## Level and prerequisites

Beginner, approximately 90 minutes plus a later retrieval session. Direct prerequisites: `c-009`

## Learning objectives

Explain struct, discriminator, padding. Implement the six investigations with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A struct groups named fields into one object. An enum gives meaningful names to integer constants, but it does not automatically prevent every other integer value from appearing in the representation. A tagged union pairs a discriminator with a union whose active interpretation depends on that tag. This can model alternatives without allocating a class hierarchy, but every reader must check the tag before interpreting the stored payload. Struct assignment copies fields, including pointer values rather than their targets. Struct padding and representation are implementation details, so bytewise comparison or raw struct serialization is not a general semantic equality policy.

## Vocabulary and concepts

- **Struct:** A value composed of named fields.
- **Discriminator:** A tag identifying which alternative a value represents.
- **Padding:** Implementation-inserted storage between or after fields.

## Syntax anatomy and execution trace

struct Point names a type unless a typedef adds a shorter alias. A designated initializer uses .field=value. The dot operator accesses a struct value; -> accesses through a struct pointer. A union shares storage among alternatives. Switch on an enum tag and handle unexpected values explicitly. Compare meaningful fields rather than relying on memcmp over padding bytes.

## Worked example / walkthrough

### Worked example 1: Use named fields

Construct Point with x 2 and y 3.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Point {
  int x, y;
};
enum ValueTag { VALUE_INT, VALUE_TEXT };
struct Value {
  enum ValueTag tag;
  union {
    int integer;
    const char *text;
  } data;
};
bool valid_tag(enum ValueTag tag) {
  return tag == VALUE_INT || tag == VALUE_TEXT;
}

int main(void) {
  /* Use named fields */
  {
    struct Point p = {.x = 2, .y = 3};
    CHECK(p.x + p.y == 5);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The field sum is 5.

Designated initialization preserves field meaning even if declaration order changes.

### Worked example 2: Copy scalar fields

Copy a Point and change the copied x.

```c
#include <assert.h>

    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Point {
  int x, y;
};
enum ValueTag { VALUE_INT, VALUE_TEXT };
struct Value {
  enum ValueTag tag;
  union {
    int integer;
    const char *text;
  } data;
};
bool valid_tag(enum ValueTag tag) {
  return tag == VALUE_INT || tag == VALUE_TEXT;
}

int main(void) {
  /* Use named fields */
  {
    struct Point p = {.x = 2, .y = 3};
    CHECK(p.x + p.y == 5);
  }

  /* Copy scalar fields */
  {
    struct Point a = {2, 3};
    struct Point b = a;
    b.x = 9;
    CHECK(a.x == 2 && b.x == 9);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The original x stays 2.

Scalar fields are copied into independent struct storage. Pointer fields would still designate their original targets.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
