# c-002: Integer ranges, signedness and floating approximation

Implement the six investigations, from the "compare integer and floating division" case to the "transfer negative division" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. ## Purpose and mental model

An integer type has a finite range. C guarantees minimum ranges for fundamental integer types, not that int has one universal size. Fixed-width types from stdint.h exist when the implementation supports exactly those widths. Unsigned arithmetic is defined modulo one more than its maximum value; signed overflow is undefined behavior. That difference is a semantic rule, not an invitation to guess CPU wraparound. Floating-point types approximate many real numbers and need deliberate comparison policies. Conversion can lose information even when the source program compiles without an error.

## Vocabulary and concepts

- **Range:** The set of values a type can represent.
- **Unsigned modular arithmetic:** Arithmetic reduced modulo the unsigned type range.
- **Undefined behavior:** An operation for which the C standard imposes no behavioral requirements.

## Syntax anatomy and execution trace

sizeof reports a size in char units, and sizeof(char) is always one; CHAR_BIT gives bits per char. INT_MAX and UINT_MAX expose implementation limits. A U suffix creates an unsigned integer constant. Integer division truncates toward zero. Convert an operand before division when a fractional result is required. fabs computes an absolute floating difference; a tolerance is specific to the numerical problem.

Compute 7/2 and 7/2.0.

    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int main(void) {
  /* Compare integer and floating division */
  {
    int whole = 7 / 2;
    double fraction = 7 / 2.0;

**Observe:** The results are 3 and 3.5.

Converting the already truncated integer result afterward cannot restore the missing fraction.

### Worked example 2: Observe defined unsigned wrap

Add one to UINT_MAX in unsigned arithmetic.

```c
#include <assert.h>
#include <limits.h>
#include <math.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int main(void) {
  /* Compare integer and floating division */
  {
    int whole = 7 / 2;
    double fraction = 7 / 2.0;
    CHECK(whole == 3 && fraction == 3.5);
  }

  /* Observe defined unsigned wrap */
  {
    unsigned int n = UINT_MAX;
    n += 1U;
    CHECK(n == 0U);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result is zero.

This result is guaranteed for unsigned arithmetic. Repeating the experiment with INT_MAX would invoke undefined behavior and is not an acceptable runnable example.

### Exercise 3: Inspect representation facts

Check sizeof(char) and minimum CHAR_BIT.

**Expected:** A char occupies one char unit and has at least eight bits.

**Verify:** Keep a CHECK equivalent to `CHAR_BIT >= 8`. Control edit: `CHECK(CHAR_BIT > 8);` must fail; then restore it.

**Progressive hints:** First evaluate `CHAR_BIT >= 8` by hand. Then recall: A C byte is defined in char units.

### Exercise 4: Widen before multiplication

Multiply two int64_t values of 50000.

**Expected:** The product is 2500000000.

**Verify:** Keep a CHECK equivalent to `a *b == INT64_C(2500000000)`. Control edit: `CHECK(a +b == INT64_C(2500000000));` must fail; then restore it.

**Progressive hints:** First trace `a` and `b` from initialization. Then recall: The operand type determines the arithmetic.

### Exercise 5: Check a tiny floating calculation

Add 0.1 and 0.2 and compare to 0.3.

**Expected:** The absolute error is below 1e-15.

**Verify:** Keep a CHECK equivalent to `fabs((a + b) - 0.3) < 1e-15`. Control edit: `CHECK(fabs((a - b) - 0.3) < 1e-15);` must fail; then restore it.

**Progressive hints:** First trace `a` and `b` from initialization. Then recall: The tolerance is appropriate only for this tiny example.

### Exercise 6: Transfer negative division

Divide -7 by 2 and inspect its remainder.

**Expected:** The quotient is -3 and remainder -1.

**Verify:** Keep a CHECK equivalent to `q == -3 && r == -1 && q * 2 + r == -7`. Control edit: `CHECK(q == -3 && r == -1 && q + 2 + r == -7);` must fail; then restore it.

**Progressive hints:** First trace `q` and `r` from initialization. Then recall: Truncation toward zero differs from floor division.

## Common pitfalls and diagnosis

Assuming signed overflow wraps like unsigned arithmetic: `INT_MAX + 1` is undefined, while `UINT_MAX + 1u` is defined to be 0. Testing `0.1 + 0.2 == 0.3` is the floating trap; compare with a stated tolerance instead.
