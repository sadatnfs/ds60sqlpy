tf-015: A reproducible tf.data pipeline#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: tf-014. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Keep preprocessing, cardinality and order visible in a bounded dataset pipeline. The central investigation is concrete: Construct a Dataset from fixed arrays; normalize using only training statistics; batch with a remainder and prefetch 1. The finish condition is For five records batched by 2, batch sizes are [2,2,1]. Normalization statistics and IDs are identical after a fresh run; no download/map side effect occurs. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

A data pipeline is part of the statistical experiment. It determines which records arrive, in what order, under which transformation and how many times. tf.data represents that sequence lazily. Constructing a Dataset is not evidence that its elements were visited. Carry record IDs through transformations so cardinality and pairing remain inspectable. A training-derived mean can be applied during mapping, but validation records must not participate in estimating it. Batching creates a new leading axis, and prefetch overlaps preparation with consumption without changing the desired order. This tiny pipeline uses literal arrays and no file or network side effects.

Vocabulary and concepts#

Cardinality: Number of dataset elements at a specific pipeline stage.

Map: A transformation applied to each element.

Prefetch: Bounded preparation of upcoming elements before consumption.

Syntax anatomy and reasoning sequence#

from_tensor_slices slices the leading axis of each tuple component together. map receives one ID and one value; arithmetic can use a frozen scalar mean. batch(2,drop_remainder=False) retains the final singleton. as_numpy_iterator materializes values for small teaching assertions, not an approach for collecting an unbounded production dataset. prefetch(1) limits the look-ahead buffer.

Treat the input pipeline as part of the model's experiment#

A pipeline describes a traversal, not just a collection of arrays. Mapping, shuffling, batching, caching and repeating have different effects depending on their order. Batching five records by two gives sizes 2,2,1. Adding an explicit drop-remainder policy changes the observed sample to four records. The absent record should remain visible in the ID ledger.

Shuffle whole records before separating their components. Shuffling feature and target datasets independently is unsafe even if their lengths match. An equal seed is not a robust pairing mechanism once one branch filters, maps, repeats or consumes randomness differently. Keep the ID, feature and target together through transformations, then unpack them at the model boundary.

Cache placement affects what is repeated. Caching after a random augmentation can preserve the first materialized augmented values across later traversals. Caching the deterministic source before augmentation allows later augmentation calls to produce different values. Neither policy is universally required; state which behavior the experiment intends and test it on a small fixture.

Prefetch overlaps production of later elements with consumption of current ones. It is not a justification for changing labels or evaluation order. Reproducibility also depends on deterministic transformation behavior, seeds, parallel execution choices and the sequence of iterations. A repeatable five-row traversal checks this local contract, not every possible production input. Fit preprocessing statistics only on the training partition before placing the frozen transform in validation or test pipelines.

Worked example / walkthrough#

Example A: Observe batches#

The input cardinality is five records but the batched cardinality is three elements. Naming the stage prevents a batch count from being mistaken for a dataset size.

import numpy as np
import tensorflow as tf

ds = tf.data.Dataset.from_tensor_slices((np.arange(5), np.arange(1, 6, dtype="float32")))
batches = list(ds.batch(2).as_numpy_iterator())
assert [len(ids) for ids, values in batches] == [2, 2, 1]

Expected: batch sizes[2,2,1].

Example B: Apply training statistics#

The held-out values4 and5 are transformed with the same mean. Their transformed average is not zero, which is expected when a frozen training transformation meets a different subset.

import numpy as np
import tensorflow as tf

ds = tf.data.Dataset.from_tensor_slices((np.arange(5), np.arange(1, 6, dtype="float32")))
batches = list(ds.batch(2).as_numpy_iterator())
assert [len(ids) for ids, values in batches] == [2, 2, 1]
mean = np.mean([1.0, 2.0, 3.0])
centered = ds.map(lambda i, v: (i, v - tf.cast(mean, tf.float32)))
values = np.array([float(v) for i, v in centered.as_numpy_iterator()])
np.testing.assert_array_equal(values, [-1, 0, 1, 2, 3])

Expected: centered values[-1,0,1,2,3].

Common pitfalls and diagnosis#

When observations vanish, inspect filtering and remainder policy before blaming training. When labels drift, compare IDs before and after mapping. When augmentations unexpectedly repeat, inspect cache placement. When timing changes, preserve output equality and the traversal contract before interpreting a prefetch or parallel-map optimization.
