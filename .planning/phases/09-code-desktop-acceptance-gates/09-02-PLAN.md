# Plan 09-02: desktop browser acceptance

## Objective

Prove the changed lesson and operation flows in a real desktop browser,
including errors and recovery, on a disposable stack built from the candidate
commit (QUAL-02, ROADMAP Phase 9 success criterion 2).

## Tasks

1. Build the candidate images through `./classroom` into a disposable project
   `ds60-phase9-browser` (never `ds60-classroom*`).
2. Run the combined Classroom browser gate
   (`~/.cache/ds60sqlpy/run-browser.sh ds60-phase9-browser
   work/phase9-browser-receipts.json`) at the 1440 by 900 desktop viewport. It
   covers: the operating manual page and its links, lesson switching from the
   palette and the lesson list, the workspace mode strip, Python and SQL
   walkthroughs (open, step, leave), a non-Python/SQL track walkthrough, run,
   save, history, the SQL practice reset, keyboard-only flow, focus cues, axe
   scan in both themes, and draft preservation across reload and restart.
3. Exercise error and recovery flows: a Python run that raises, an invalid SQL
   statement, a stopped worker reported and recovered, and a walkthrough whose
   reference no longer matches being hidden rather than shown stale.
4. Tear the stack down with `down -v`; confirm protected containers and
   learner volumes are untouched.
5. Record results and receipt digests in `09-VERIFICATION.md`.

## Verification

- The receipt reports every stage passed; no serious or critical axe
  findings; the stack and its volumes are gone afterwards.
