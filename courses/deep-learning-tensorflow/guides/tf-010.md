# tf-010: A split is part of the experiment

## Level and prerequisites

Beginner; approximately 105 minutes. Direct prerequisites: `tf-009`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Detect duplicate/group leakage before reporting held-out performance. The central investigation is concrete: Assign a fixed eight-record fixture with four account IDs to train/validation by account; fit a mean only on train. The finish condition is No account ID occurs in both sets. A validation-only extreme changes the all-data mean but not the recorded training normalization. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

A split defines what is unseen. If two rows belong to one account, putting one in training and one in validation exposes part of the validation entity during fitting. Grouped splitting assigns the entity once, then carries all of its rows together. Preprocessing is also fitting: a mean inferred from validation values has already consumed validation information even if no label was used. Store the training statistic and apply it unchanged to validation. This lesson uses literal account records so every crossing can be enumerated. The tiny fixture teaches isolation and does not establish that an account model will generalize to a future deployment.

## Vocabulary and concepts

**Split unit:** Entity assigned wholly to one partition.

**Leakage:** Assessment information influencing fitting or selection.

**Fit statistic:** A quantity estimated from training inputs and then frozen.

## Syntax anatomy and reasoning sequence

Use a mapping from account to split before selecting values. Set intersection tests group isolation. NumPy mean reduces only the selected training values, and subtraction then broadcasts the scalar to both partitions. A validation perturbation should change transformed validation values while leaving the saved fit statistic unchanged. Hash canonical record IDs only after freezing the selection, and never refit merely because a held-out point looks extreme.

## A split determines what the experiment can claim

Training and validation are roles assigned to observations. Preprocessing
must respect those roles too. In the supplied fixture the training mean is 4,
so validation values 20,22,30 and 32 become 16,18,26 and 28. A future value 1000
becomes 996. Its extremeness does not authorize refitting the mean: doing so
would make the supposedly frozen transformation depend on evaluation data.

An account-level split answers a different question from a row-level split.
When several rows describe the same account, a row split may put near copies
or stable account characteristics on both sides. A high score then measures
performance partly on familiar accounts. An account-disjoint split measures
transfer to different accounts under the remaining sampling assumptions.
Neither automatically proves transfer to a later time period or a new region.

Write the intended prediction moment before choosing the split. A feature
computed after the outcome is unavailable at that moment even if its column
is present in both files. A split can be disjoint by ID and still leak through
future aggregates, duplicate documents or feature-selection decisions made
using held-out labels.

A split hash makes one particular assignment identifiable. It does not prove
independence, good sampling or absence of leakage. Retain the IDs, grouping
rule, time boundary and preprocessing-fit partition with the hash. If a
validation score drives model choice, it is no longer a fresh final test of
the selected model; keep that last assessment separate.

## Worked example / walkthrough

### Example A: Partition accounts

The boolean mask has one position per record. Its values come from group identity, not a target-dependent ranking. Training has four values and validation has four, but equal counts are incidental to the group-isolation contract.

```python
import numpy as np

groups=np.array(list('AABBCCDD')); x=np.array([1.,3.,5.,7.,20.,22.,30.,32.])
train=np.isin(groups,['A','B']); valid=~train; mean=x[train].mean()
assert mean==4 and set(groups[valid])=={'C','D'}
```

**Expected:** train mean4 and validation IDs C,D.

### Example B: Expose global fitting

A perturbation restricted to validation cannot influence a training-only mean. This controlled counterexample detects leakage more directly than inspecting the name of a preprocessing object.

```python
import numpy as np

groups=np.array(list('AABBCCDD')); x=np.array([1.,3.,5.,7.,20.,22.,30.,32.])
train=np.isin(groups,['A','B']); valid=~train; mean=x[train].mean()
assert mean==4 and set(groups[valid])=={'C','D'}
changed=x.copy(); changed[-1]=3200
assert changed[train].mean()==mean
assert changed.mean()!=x.mean()
```

**Expected:** training mean stays4; global mean changes.

## Common pitfalls and diagnosis

If an extreme validation record changes a fitted training statistic,
the preprocessing boundary is broken. If account IDs cross the split, first
decide whether the intended use involves new or already observed accounts.
Inspect feature timestamps and duplicate families even when the explicit ID
intersection is empty. A new split hash documents a change; it does not
explain or justify the change.
