# clp-016: Gradient and curvature audits

Tutorial mode. Stage: advanced. Direct prerequisites: `clp-015`, `torch-026`.

## Audit the derivative implementation separately

Higher-order derivatives support uncertainty approximations and curvature-aware optimization, but they also amplify mistakes in graph construction and scaling. A Hessian produced without an exception is not automatically the Hessian of the intended scientific objective. We therefore use a quadratic model with a handwritten matrix oracle and deliberately broken alternatives whose failure should be detected.

For design \(X\), response \(y\) and a declared quadratic penalty,

\[
Q(\theta)=\frac12\|X\theta-y\|^2+0.1\theta^\top\theta,
\quad \nabla Q=X^\top(X\theta-y)+0.2\theta,
\quad H=X^\top X+0.2I.
\]

The Hessian does not depend on \(\theta\) or \(y\), making it an especially transparent test. This penalty supplies additional curvature; the Hessian here is the curvature of the penalized objective, not automatically a frequentist covariance calculation for an unpenalized MLE.

## Worked case 1: analytic matrix and numerical gradient check

Set \(X\) to rows \((1,0),(1,1),(1,2)\), responses to \((0.5,1.5,2.2)\) and parameters to \((0.2,0.7)\). The expected Hessian is

\[
H=\begin{pmatrix}3.2&3\\3&5.2\end{pmatrix}.
\]

The program obtains it using `torch.autograd.functional.hessian` and compares against the direct matrix expression. It also computes the smallest eigenvalue, approximately 1.03772, which is positive. On this particular quadratic objective that confirms strict convexity and a unique minimizer. For a nonlinear objective, positivity at one point is only a local statement.

`torch.autograd.gradcheck` compares AD with numerical perturbations. The input uses float64 and avoids nondifferentiable locations, which are important conditions for meaningful comparisons. The program performs gradcheck in addition to the Hessian oracle. These checks validate different aspects: one tests local first derivatives numerically, while the other tests the complete analytic second-derivative structure.

## Worked case 2: a forward value with the wrong gradient

The deliberately broken objective detaches \(X\theta\) before constructing residuals and adds a zero-valued parameter term so that a derivative path technically exists. Its forward values look plausible, but the meaningful parameter dependence has been removed from the AD graph. Gradcheck returns false because finite differences still observe changing values while AD sees the detached path.

This is a realistic class of error when moving data through Python numbers, NumPy arrays or external libraries inside a custom objective. Copying the resulting value into a new tensor with `requires_grad=True` does not reconnect the lost graph. If an external compiled function is necessary, it needs a correct custom derivative contract or an interface that preserves differentiability.

The program also attempts an in-place update on a leaf parameter that requires gradients and confirms that Torch rejects it. Optimizers manage parameter updates under appropriate gradient-mode rules; arbitrary in-place mutation inside a differentiable objective can invalidate saved values required by backward. Catching the resulting error is preferable to suppressing it through unsafe state manipulation.

## Numerical and scientific boundaries

Finite differences have truncation and cancellation error, so step size and tolerances need to match parameter scale and floating precision. A failure near a kink may reflect nondifferentiability rather than a wrong implementation. Tensor views with overlapping storage can also invalidate the assumption that perturbing one element changes only one mathematical coordinate. Use independent, well-scaled test inputs before diagnosing more complex failures.

A dense Hessian requires quadratic parameter storage and can be prohibitively expensive for a neural network. Hessian-vector products or structured approximations may be more appropriate at scale, but they answer a different computational question from printing a small full Hessian. This chapter validates a two-parameter CPU case and makes no claim about a billion-parameter model.

## Answered review questions

**Does passing gradcheck establish that the likelihood is correct?** No. It establishes local derivative consistency for the implemented function under the test conditions. A consistently differentiated wrong density can pass. Probability construction needs independent model checks.

**Should a failed Hessian inverse be repaired by adding a diagonal?** First investigate identification, constraints, scale and objective sign. A diagonal adjustment may be a declared regularizer or numerical approximation, but it cannot silently turn absent information into genuine precision.

**How should derivative evidence be reported?** Record the objective, parameters tested, precision, maximum errors, tolerance, software version and source identity. A bare boolean `gradient checked` omits information needed to interpret or reproduce the claim.

## Complete reproducible program

Run this complete source in the separately prepared `llm-torch-cpu` pad. It uses float64 CPU tensors and tiny original offline fixtures. Each execution starts fresh.
```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def audited_loss(theta, design, y):
    if theta.shape != (design.shape[1],) or not bool(torch.isfinite(theta).all()):
        raise ValueError("Use one finite coefficient per design column")
    return (design @ theta - y).square().sum() / 2 + 0.1 * theta.square().sum()


def run_cases():
    design = tensor([[1, 0], [1, 1], [1, 2]])
    y = tensor([0.5, 1.5, 2.2])
    theta = tensor([0.2, 0.7]).requires_grad_()

    def f(value):
        return audited_loss(value, design, y)

    hessian = torch.autograd.functional.hessian(f, theta)
    expected = design.T @ design + 0.2 * torch.eye(2, dtype=DTYPE)
    assert torch.allclose(hessian, expected, atol=1e-12, rtol=0)
    passed = torch.autograd.gradcheck(f, (theta,), eps=1e-6, atol=1e-5, rtol=1e-3)

    def detached(value):
        return ((design @ value).detach() - y).square().sum() / 2 + 0 * value.sum()

    bad = torch.autograd.gradcheck(detached, (theta,), raise_exception=False)
    assert passed and not bad
    inplace_rejected = False
    try:
        theta.add_(1)
    except RuntimeError:
        inplace_rejected = True
    assert inplace_rejected
    return {
        "hessian": hessian.tolist(),
        "minimum_information_eigenvalue": float(torch.linalg.eigvalsh(hessian)[0]),
        "correct_gradcheck": passed,
        "detached_gradcheck": bad,
        "leaf_inplace_operation_rejected": inplace_rejected,
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
