# web-017: Responsive layouts and content-driven breakpoints

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-016`

## Learning objectives

Build a responsive course outline with a readable article. Explain why responsive design is more than media queries. Use responsive design, media query and viewport accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Responsive design lets one document work across available sizes and user settings. A breakpoint is a condition where a layout needs to change, not a permanent name for a device. A phone can have a wide landscape viewport; a desktop window can be narrow. Start with content that works in a small space and add more complex arrangements only when enough room exists.

The viewport metadata tells mobile browsers to use the device's layout width rather than a historical wide page assumption. Flexible widths, wrapping and content-driven heights solve many problems before a media query is necessary. A responsive page must also survive enlarged text, translations and long values, not merely a list of screen widths.

### Key terms

- **Responsive design:** Building one page that adapts its layout to the available space instead of making separate pages for each device.
- **Viewport meta element:** The `meta name="viewport"` element that tells mobile browsers to lay out at the device width rather than a wide virtual page.
- **Media query:** An `@media` condition, such as a minimum width, that applies rules only when the environment matches.
- **Breakpoint:** A width at which the layout changes, chosen where the content starts to break rather than to match a particular device.
- **Mobile first:** Writing the narrow layout as the default and adding minimum-width media queries for wider screens.

## Syntax anatomy and mechanism

Use a base single-column layout and a min-width media query for a wider arrangement. Relative units in queries support a design tied to text scale. Inspect where the content becomes cramped and choose the breakpoint from that evidence. Keep the navigation visible or provide a fully accessible disclosure rather than simply hiding it on small screens.

## Worked example / walkthrough

### Worked example 1: A small-space baseline

The ordinary layout works without a query.

```css
.layout {
  display: grid;
  gap: 1rem;
}
```

**Expected observation:** Sections stack in one column.

### Worked example 2: An evidence-based enhancement

Add a second column only when content has room.

```css
@media (min-width: 48rem) {
  .layout {
    grid-template-columns: 15rem minmax(0, 1fr);
  }
}
```

**Expected observation:** The wider layout gives navigation a bounded column.

## Contrast case: a missing viewport meta tag

The responsive CSS from both worked examples is identical in these two documents. Only the head differs.

```html
<!-- A: no viewport metadata -->
<head>
  <meta charset="utf-8" />
  <title>Outline</title>
</head>

<!-- B: layout viewport follows the device -->
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Outline</title>
</head>
```

Mobile browsers render document A as if the screen were roughly 980 CSS pixels wide and then scale it down, so the `min-width: 48rem` query matches and readers see a tiny two-column desktop page. Document B sets the layout viewport to the device width, so a phone stays below 48rem and gets the single-column base layout. A desktop preview resized by hand may not show this difference, so use a device emulation preset when you test it.

## Debugging and common mistakes

Do not hide essential actions just because space is limited. Avoid fixed viewport-height panels that trap content behind mobile browser chrome. Test actual text growth and settled layout.

When a phone view looks like a shrunken desktop page, the viewport meta element is missing, so the browser lays out at a wide default width. When a breakpoint triggers at an awkward width, resize slowly and move it to where the content actually breaks.
