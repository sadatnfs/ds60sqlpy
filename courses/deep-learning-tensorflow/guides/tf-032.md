A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

Saving has two distinct purposes: preserving a trainable Keras model and exporting an inference interface. The .keras format preserves a Keras model configuration and state; model.export creates an inference artifact that can be loaded through SavedModel. Keras3 does not use model.save(directory) as the export workflow. Prediction parity must be checked after reconstruction, ideally in a fresh process. Matching predictions says nothing about whether optimizer state can resume the same next update, which is the separate checkpoint lesson. This fixture has one fixed weight and a known signature, so failures can be attributed to persistence and interface behavior rather than training randomness.

## Vocabulary and concepts

**Serialization:** Encoding model configuration and state into a recoverable artifact.

**Export:** Publishing a fixed inference interface and its state.

**Parity:** Agreement of outputs under declared inputs and tolerance.

## Syntax anatomy and reasoning sequence

Save the built model to a path ending.keras. Load it with tf.keras.models.load_model. Export to a different owned directory and load it with tf.saved_model.load; call its serve endpoint. TemporaryDirectory owns both outputs. The child process accepts only the two local artifact paths created by the parent and prints predictions as JSON. Compare using float32 tolerance1e-6.

## Save the object needed by the next consumer

A .keras archive is intended to reconstruct a Keras model with its saved
configuration and state. A SavedModel inference export exposes a callable
endpoint with an input/output contract. These are different consumers and
different restoration paths. Loading an inference endpoint does not by itself
reconstruct the optimizer and full training workflow.

In the fixture, retain the object returned by tf.saved_model.load while
using its serve endpoint. Treating the endpoint as an unrelated function
and discarding its owning module can lose the lifetime of captured variables.
The fresh-process comparison checks that the reconstructed owner and callable
actually produce the expected values without relying on the original model
remaining in memory.

A dynamic batch dimension means the endpoint can accept different numbers
of rows under its signature. It does not make the feature width arbitrary.
The one-feature model must still receive width one and the declared dtype.
For a larger model, feature order and units are semantic parts of the contract
too: swapping two columns of the same shape can change predictions without
producing a shape error. Keep that schema beside the model artifact.

Check parity on several deliberately different inputs, including more than
one batch size, and reject incompatible inputs explicitly. A content hash
identifies bytes; a parity check examines behavior on its probes. Neither
alone establishes generalization or compatibility with an untested runtime.
See the [Keras saving guide](https://keras.io/guides/serialization_and_saving/)
and [inference export contract](https://keras.io/api/models/model_saving_apis/export/)
for the separate APIs used by these consumers.

## Worked example / walkthrough

### Example A: Create a fixed inference model

A known fixed weight avoids making serialization success depend on a stochastic training result. The input shape and dtype are part of the inference contract.

```python
import numpy as np
import tensorflow as tf
import tempfile,json,subprocess,sys,textwrap
from pathlib import Path

model=tf.keras.Sequential([tf.keras.Input(shape=(1,)),tf.keras.layers.Dense(1,use_bias=False,kernel_initializer=tf.keras.initializers.Constant(2.))])
x=np.array([[1.],[3.]],dtype='float32'); expected=model(x).numpy()
np.testing.assert_array_equal(expected,[[2],[6]])
```

**Expected:** predictions2,6.

### Example B: Round-trip .keras

Reconstruction must use the saved artifact rather than another reference to the original model object. File existence alone does not establish that deserialization works.

```python
import numpy as np
import tensorflow as tf
import tempfile,json,subprocess,sys,textwrap
from pathlib import Path

model=tf.keras.Sequential([tf.keras.Input(shape=(1,)),tf.keras.layers.Dense(1,use_bias=False,kernel_initializer=tf.keras.initializers.Constant(2.))])
x=np.array([[1.],[3.]],dtype='float32'); expected=model(x).numpy()
np.testing.assert_array_equal(expected,[[2],[6]])
temporary=tempfile.TemporaryDirectory(); folder=Path(temporary.name); keras_path=folder/'model.keras'; model.save(keras_path)
loaded=tf.keras.models.load_model(keras_path)
np.testing.assert_allclose(loaded(x).numpy(),expected,atol=1e-6,rtol=0)
```

**Expected:** reloaded predictions match within 1e-6.

## Common pitfalls and diagnosis

If reloading succeeds but calling the endpoint fails, retain the
loaded module and inspect its actual signature. If numerical parity fails,
check feature order, dtype, preprocessing and training mode. Do not infer
training-resume support from a successful inference export, or accept a
different feature width merely because batch length is dynamic.
