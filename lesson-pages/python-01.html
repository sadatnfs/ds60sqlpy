Day 1: Setup and REPL in the Docker Classroom#

How to run this lesson#

From the repository root, start the prepared Docker classroom with ./classroom. Open /classroom, choose Python and data science, and select Day 1. Read the Python capability notice and open the coding pad. Windows uses the same launcher inside WSL 2. Follow the one-command setup guide if Docker preparation is still needed. Ordinary study requires the Docker classroom and a browser; host Python, virtual environments, VS Code, pip, and Jupyter are not prerequisites.

The pad contains Python source from this notebook, with # %% comments marking cells. Run submits the current program to a new worker process. With the prepared notebook capability, cells share names inside that one submission and display a cell's final expression. An ordinary program without cell markers uses normal script behavior. Use print when output must be explicit in either form.

Read the examples here, then predict, Run, and inspect the output/result area. Save edited source and notes in your Day 1 pad. Source and result records are stored by the classroom; variables disappear when the process ends. Navigate back to Day 1 to inspect saved text. The classroom guide explains results and saved work. Reading an old result does not execute it or prove that your current source matches it.

The ten tasks use tiny offline standard-library programs and supplied reasoning records. A reference run can verify values and exceptions. Only your own browser observations can verify that you saved, navigated, and inspected your actual pad. Keep those evidence types separate. Initial engine/image preparation can need a connection; opening or running these already prepared examples needs no download.

Level and prerequisites#

Level: Beginner. Stable ID: python-01. Direct prerequisites: None. You need no previous programming or terminal administration. You should be able to open the prepared classroom and type into its pad. The supported Python examples use 3.11-compatible syntax; inspect the capability notice for the selected prepared runtime. Historical Day 1 is an ordering label, not a deadline.

  • Learner: Day 1 notebook.
  • Reference explanations: worked answers.
  • Reference notebook: complete local examples.

Learning objectives#

Identify the interpreter that is executing your source, read a small program in order, distinguish an explicit print from interactive display, and preserve a recoverable source edit. Explain fresh-process variables versus stored source and results. Inspect module availability without installing packages, use runtime identity to diagnose an import complaint, and read a first error before changing anything. Finally, describe how optional REPL and Jupyter state differs from a browser Run without being required to install those tools.

Vocabulary and concepts#

  • Source: The text of a program, such as print("Hello"). Saving that text preserves instructions for another execution. A result is what happened when one particular version of those instructions ran.
  • Interpreter: The program that reads Python instructions and carries them out. sys.executable reports its executable path. A screen that merely says Python does not establish which environment supplied that interpreter.
  • Process: One running instance of a program. Its names and temporary values live in memory. A new process starts without variables defined only in an old process, even when both processes read the same saved source.
  • Container: An isolated environment for running processes with prepared tools and a filesystem view. The classroom's worker runs Python in a Linux container. A container is not the same thing as the Python process inside it.
  • Image: Prepared container contents, including the selected interpreter and installed packages. Editing your pad does not edit or rebuild that image. The classroom stores learner source/results separately from prepared images.
  • Module and package: A module is importable Python functionality. A package groups modules, and an installed distribution can supply one or more of them. The standard library comes with Python; third-party distributions need deliberate environment preparation. Day 1 imports only standard-library tools.
  • Virtual environment: A Python interpreter/package environment used to separate dependencies. It is narrower than a container's filesystem/process boundary. A worker can contain a virtual environment internally, but that does not require you to create one on your host machine.
  • Working directory: The process's base directory for relative file names. Path.cwd() reports it. It is neither a universal repository location nor proof of where the classroom stores saved pads. Do not depend on a particular developer's absolute path.
  • REPL: Read-Evaluate-Print Loop, a live interactive interpreter prompt. It evaluates entries and can display expression results automatically. Names persist until that live process ends. >>> is the prompt, not Python source that should be copied into a browser program.
  • Kernel: The live interpreter process connected to a Jupyter notebook. Ordinary cells in that kernel share memory. The course's optional contributor kernel is named Python (ds60sqlpy), but its friendly name alone does not prove the executable path. Browser Runs have a different fresh-process lifetime.
Syntax anatomy before the first program#

print("Hello") calls Python's built-in print function. The parentheses hold its input; quotes make Hello a text value rather than a variable name. Leave the quotes in place. print("Total:", total) supplies two inputs separated by a comma, and print places a space between them. A line starting with # is a comment for a reader. In the classroom pad, a standalone # %% is also a cell boundary understood by the notebook execution adapter.

price = 12 binds the name price to the integer twelve. One equals sign means assignment, not a question about equality. Later price * quantity multiplies the two current values. Names are case sensitive: print and Print are different names. Python normally reads the submitted program from top to bottom, so a name must be defined before it is used.

import sys makes the standard-library sys module available under that name. The dot in sys.executable selects information provided by the module. from pathlib import Path gives this program the name Path from the pathlib module; Path.cwd() asks it for the current directory. These inspected values can vary between processes and machines. Record actual output instead of copying a path from a solution.

Some reference checks use assert condition. A true condition continues; a false condition raises AssertionError. == compares values, whereas = assigns a value. A small assertion checks a particular fact; it is not a completion marker for all the manual browser tasks. A nonempty string counts as true in an assertion; an empty string counts as false.

True and False are Boolean values for yes/no observations. None is a special no-result value. A module specification describes where an interpreter could find a module. In importlib.util.find_spec("math") is not None, the function is asked to look for math, then is not None checks that it returned a specification rather than the no-result value. This reads availability and does not install a package.

Worked example / walkthrough#

Ask the running interpreter for facts#

Before running, predict which lines contain machine-dependent information. Then use this complete program. It needs no third-party import and reads no personal file. Its four labels make the observations easy to match to source.

import platform
import sys
from pathlib import Path

print("Python:", platform.python_version())
print("Implementation:", platform.python_implementation())
print("Interpreter:", sys.executable)
print("Working directory:", Path.cwd())

Expected: Four labelled lines with a Python version, implementation name, nonempty executable path, and current directory. The prepared version should agree with the selected capability. A worker executable can be inside its own prepared environment; it need not contain your host checkout's .venv path. This is a real interpreter observation. It does not reveal an image digest, the entire installed package list, or the browser's storage implementation.

Separate calculation from visible presentation#

Read each assignment in order and predict the two output lines. The first two names hold integers; multiplication calculates a new total. The last lines ask print to show the result and then a marker. They work both as notebook cells and as an ordinary submitted script.

price = 12
quantity = 3
total = price * quantity
print("Total:", total)
print("Ready")

Expected: Total: 36 followed by Ready. Changing quantity to zero would make the first line Total: 0, while the second line stays Ready. Merely writing total as the final expression is an interactive display request in a marked cell, but an ordinary script does not automatically print it. Keep explicit print calls when comparing modes. There is no hidden previous value: the program defines each required name before using it.

Common pitfalls#

If you see NameError for Hello, check whether you omitted the quotes around a text value. If NameError mentions greeting, locate its assignment above the first use. If Print is undefined, fix the capital letter. If a line has an unclosed quote or parenthesis, Python may report SyntaxError before any line runs; compare the indicated punctuation with the small complete examples. Package installation does not repair any of these source errors.

If nothing appears for 7 * 6, inspect the source mode and use print(7 * 6). If a supposedly fresh test still knows visit, check whether Run A remains in an earlier cell of the same submission or you are using a live Jupyter kernel. Do not erase saved work to obtain fresh process memory. Replace only your own submitted experiment source and keep a recoverable note of the earlier text.

If an import works in one tool and not another, compare the actual interpreter and selected dependency profile first. Discovery is a read-only diagnostic, not a package installation. A prepared image, a running Python variable, a saved pad, and a saved result are distinct things; changing one does not imply the others were changed or validated.
