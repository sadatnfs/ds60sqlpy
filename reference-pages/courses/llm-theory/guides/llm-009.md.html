Learning objectives#

You will calculate causal attention for a three-token example, implement an independent prefix check, expose a mask that looks triangular but normalizes incorrectly, reject a fully masked row, and explain why correct attention does not rule out training-data or assessment leakage.

Purpose and mental model#

For one query position, attention forms a weighted combination of value rows. The scores decide how much of each row to use. A causal decoder is allowed to use its current input and earlier inputs, but not later ones. The mask is the information boundary that enforces this rule. A triangle drawn on a screen is not evidence that the implementation enforces it.

A simple independent check is to run the same computation on just a prefix. Earlier outputs in the full sequence should equal outputs computed without any future positions. Changing future-only data should also leave earlier outputs unchanged. These checks exercise the mechanism rather than relying on a plausible-looking loss or generated sentence.

This is one fixed attention head, not a trained language model. Its weighted values are feature vectors, not token probabilities or explanations of why an answer is true. A complete decoder adds other components. Prefix invariance requires those components to preserve the same information boundary too.

Vocabulary and concepts#

A query is the feature vector for the position requesting information. A key is a vector used to score a candidate position. A value is the vector that will be mixed into the output. Here Q, K and V have one token per row. Queries and keys have the same feature width so their dot product is defined; values may have a different feature width.

A score matrix has a query row and a key column. Q @ K.T compares every query with every key. Dividing by sqrt(d) is the attention scaling convention for key width d. Softmax converts finite allowed scores into nonnegative weights that sum to one along the key axis. Subtracting a row maximum avoids unnecessary exponential overflow without changing the distribution.

The boolean allowed mask in this worksheet uses True for a position that may participate. It is lower triangular, including its diagonal. Other APIs can use the inverse boolean meaning; a mask name alone is not a portable contract. Prefix invariance means recomputing any prefix gives the same outputs as the corresponding early rows of the full computation, within a stated numeric tolerance.

Causal mask: an explicit information boundary whose allowed keys for a query are its current position and earlier positions.

Key axis: the column axis of the score matrix; softmax normalizes this axis separately for every query row.

Prefix invariance: agreement between an independently recomputed prefix and the corresponding early rows of the full calculation.

How to run and syntax anatomy#

np.tri(T, dtype=bool) builds the allowed lower triangle. np.where(allowed, scores, -np.inf) removes forbidden positions before normalization. The axis=1 reductions operate over keys for each query. keepdims=True preserves a column shape for broadcasting each row's normalizer back across that row. weights @ v forms the final weighted combinations.

The helper below handles square self-attention, not batched or cross-attention inputs. It rejects an empty sequence, shape disagreements, nonboolean masks, fully masked rows and nonfinite inputs. A fully masked row has no probability distribution to normalize. Silently inventing zeros would hide that contract failure.

Worked example / walkthrough#

Example A: equal scores make the mask visible#

Zero query and key vectors give every allowed key the same score. The first row has one legal value, the second has two, and the third has three. With V=[[2,0],[0,2],[6,6]], the outputs are the value, the first-two mean, and the three-value mean. This makes an off-by-one or wrong-axis error easy to see.

import numpy as np


def attention(q, k, v, allowed):
    q, k, v = (np.asarray(value, dtype=np.float64) for value in (q, k, v))
    allowed = np.asarray(allowed)
    if any(value.ndim != 2 for value in (q, k, v)):
        raise ValueError("q, k and v must be matrices")
    count, width = q.shape
    if count == 0 or width == 0 or v.shape[1] == 0:
        raise ValueError("nonempty token and feature axes required")
    if k.shape != (count, width) or v.shape[0] != count:
        raise ValueError("self-attention shapes do not agree")
    if allowed.dtype != np.bool_:
        raise TypeError("allowed must be boolean")
    if allowed.shape != (count, count):
        raise ValueError("allowed must have shape (tokens, tokens)")
    if not allowed.any(axis=1).all():
        raise ValueError("each query needs at least one key")
    if not all(np.isfinite(value).all() for value in (q, k, v)):
        raise ValueError("finite inputs required")
    scores = (q @ k.T) / np.sqrt(width)
    if not np.isfinite(scores[allowed]).all():
        raise ValueError("finite allowed scores required")
    masked = np.where(allowed, scores, -np.inf)
    shifted = masked - masked.max(axis=1, keepdims=True)
    weights = np.exp(shifted)
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ v, weights


q = np.zeros((3, 2), dtype=np.float64)
k = q.copy()
v = np.array([[2.0, 0.0], [0.0, 2.0], [6.0, 6.0]])
allowed = np.tri(3, dtype=bool)
output, weights = attention(q, k, v, allowed)
expected = np.array([[2.0, 0.0], [1.0, 1.0], [8 / 3, 8 / 3]])
np.testing.assert_allclose(output, expected, rtol=0, atol=1e-12)
np.testing.assert_allclose(weights.sum(axis=1), 1.0, rtol=0, atol=1e-12)
for cut in range(1, 4):
    prefix, _ = attention(q[:cut], k[:cut], v[:cut], np.tri(cut, dtype=bool))
    np.testing.assert_allclose(output[:cut], prefix, rtol=0, atol=1e-12)
print(output)

Expected: rows [2,0], [1,1], [2.6666666666666665, 2.6666666666666665], up to float formatting. The third row's exact values are 8/3. weights.sum(axis=1) is [1,1,1]. The prefix loop is a second check; it does not read an official solution or require a trained model.

Example B: a future value exposes an unmasked computation#

Keep Q and K at zero. Change only the third value row to [100,200] and compare causal attention with an all-allowed mask. Use the attention helper defined in Example A; run the whole scratch file from a fresh process.

future_v = v.copy()
future_v[2] = [100.0, 200.0]
causal, _ = attention(q, k, future_v, np.tri(3, dtype=bool))
unmasked, _ = attention(q, k, future_v, np.ones((3, 3), dtype=bool))
np.testing.assert_allclose(causal[:2], [[2.0, 0.0], [1.0, 1.0]], rtol=0, atol=1e-12)
np.testing.assert_allclose(unmasked, np.tile([34.0, 202 / 3], (3, 1)), rtol=0, atol=1e-12)
print(causal)
print(unmasked)

Expected: the first two causal rows do not change. Its final row becomes [34,202/3]. Every unmasked row becomes that new global mean, including row zero, so a future position affected an earlier query. This is a direct causal failure even if another metric looked good.

Common pitfalls#

If the first output changes when only a future value changes, inspect mask orientation and the key/query axes. If row sums are below one, inspect whether masking happened after softmax. If a row becomes NaN, first ask whether it had any allowed key, then check numeric finiteness and the maximum-subtraction step. If appending padding changes an earlier result, check whether a later component computes statistics across the whole sequence.

An API's boolean mask may mean forbidden rather than allowed. Translate the meaning explicitly instead of copying a mask unchanged between libraries. Allowing the diagonal is correct for shifted next-token targets; feeding the answer at the same position and labeling it as itself is a different objective. Finally, passing the attention checks says nothing about whether the held-out documents leaked into a tokenizer or a prompt-selection process.

Progressive hints#

  • Hint 1: draw a square with query rows and key columns. Mark each row's current and earlier positions before doing any arithmetic.
  • Hint 2: remove future rows from Q, K and V, recompute from scores, and compare with the full computation's matching prefix. A reused full result cannot test the independent computation.
  • Hint 3: inspect the key-axis sum after normalization and ensure forbidden scores are removed before exponentiation. Reject a row with no legal key instead of guessing a probability distribution.
