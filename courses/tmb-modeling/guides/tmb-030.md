# Profile interval roots and boundary cases

Start with: tmb-029.

Outcome: Find confidence endpoints by a stated likelihood-rise equation.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter finds profile-interval roots with `uniroot` and checks them against the exact interval. In the separately prepared [owned project](../projects/tmb-local/README.md), `tests/public_api.R` compares `confint()` of a `TMB::tmbprofile` result and `TMB::tmbroot()` with the exact interval \(3.5\pm1.96\); a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

A profile interval endpoint solves \(f_p(t)-f_p(\hat t)=c\), where \(c\) is a chosen NLL rise. `tmbroot` targets those roots directly. In contrast, `tmbprofile` computes a curve useful for inspection and its confidence method interpolates crossings. Root finding and curve construction serve related but distinct purposes.

The default target is half a 95% chi-square-one quantile. That calibration assumes a regular interior scalar parameter and an appropriate large-sample likelihood-ratio approximation. It is not a universal 95% guarantee for variance boundaries, unidentified mixture components or sparse event data.

## Key terms

- **tmbroot:** The TMB function that solves directly for the parameter values where the profile NLL rises by a stated amount above its minimum.
- **Likelihood-ratio cutoff:** The NLL rise \(c\) defining an endpoint; the default is half the 0.95 quantile of \(\chi^2_1\), about 1.92.
- **Bracketing interval:** A search range whose ends lie on opposite sides of the cutoff, which a root solver needs to return a finite endpoint.
- **Boundary inference:** Inference for a parameter at or near the edge of its domain, where the chi-square calibration can fail and clipped intervals change coverage.

### Worked case A: a known-variance normal mean

For observations with known standard deviation \(\sigma\), the NLL rise is \(n(\mu-\bar y)^2/(2\sigma^2)\). Solving for the cutoff yields endpoints \(\bar y\pm\sigma\sqrt{2c/n}\). The companion compares this formula to `uniroot` results. This is an independent oracle for a small native `tmbroot` test.

A root solver needs an interval that brackets the target. If both ends of the requested parameter range stay below the cutoff, the data and requested range have not supplied a finite endpoint. Increasing an arbitrary range until a number appears is not a substitute for understanding a flat or unbounded likelihood.

### Worked case B: constrained domain

A positive parameter may have a lower boundary at zero. The companion shows a quadratic profile centered near that boundary and identifies when an unconstrained lower endpoint would be negative. Simply truncating that endpoint changes the coverage behavior. The appropriate likelihood-ratio reference distribution can differ at a boundary; explain the inferential method instead of labeling every clipped interval 95%.

`tmbroot` accepts named or linear-combination targets, parameter ranges and continuation controls. Record the target, domain and whether both endpoints converged. Root-finding numerical tolerance is distinct from statistical interval accuracy.

### Answered discussion

**Why inspect a profile if roots are faster?** The profile can expose asymmetry, multiple regions and optimizer failures that two endpoints hide. **Can a root interval cross a different likelihood basin?** It can if the profiling path switches modes. Multiple starts and curve inspection may be necessary. **Does a finite endpoint imply an identified parameter?** No. Check the underlying profile, optimizer and sensitivity to the domain.

See [tmbroot in the TMB manual](https://cran.r-project.org/web/packages/TMB/TMB.pdf). Keep the numerical equation and statistical cutoff visible in every reported interval.

### Worked case C: solving the rise equation by hand

The companion uses \(y=(1,2,4,7)\), \(\sigma=2\) and \(n=4\), so \(\bar y=3.5\). The cutoff is \(c=\tfrac12\chi^2_{1,0.95}=1.920729\). Setting \(4(\mu-3.5)^2/8=1.920729\) gives \(|\mu-3.5|=2\sqrt{2(1.920729)/4}=1.959964\):

```text
              lower      upper      (closed-form values, rounded)
exact         1.540036   5.459964
roots         1.540036   5.459964   agreement to about 1e-4 or better
```

The half-width 1.959964 equals \(1.96\sigma/\sqrt n\), the familiar Wald half-width, because a known-variance normal mean has an exactly quadratic profile. That is why this model is an oracle: any disagreement between `tmbroot` and these endpoints beyond root tolerance indicates a problem in the native call, not in the statistics. The `uniroot` brackets are \([\bar y-10,\bar y]\) and \([\bar y,\bar y+10]\); at the center the rise function equals \(-1.92\), and at each outer end it equals \(50-1.92=48.08\), so each bracket has a sign change. Default `uniroot` tolerance is near \(10^{-4}\), matching the companion's assertion.

A native version would look like this:

```r
dyn.load(file.path(Sys.getenv("TMB_BUILD_DIR"), TMB::dynlib("normal_mean")))
obj <- TMB::MakeADFun(list(y = c(1, 2, 4, 7)), list(mu = 3.5, log_sigma = log(2)),
  map = list(log_sigma = factor(NA)), DLL = "normal_mean"
)
TMB::tmbroot(obj, name = "mu") # expected near 1.540036 and 5.459964
```

Mapping `log_sigma` to `NA` makes \(\sigma\) known, which is what the closed form assumes. Without the map, the profile would reoptimize the scale and the endpoints would differ.

### The boundary line

The last line prints \(0.1-1.96(0.2)=-0.292\) beside the boundary 0. The unconstrained lower endpoint lies 0.292 below a domain where the parameter cannot exist. Reporting \([0, 0.492]\) as a 95% interval would hide that the reference distribution near a boundary is a mixture, often half a point mass at zero and half a chi-square-one, which changes the cutoff to about 1.35 rather than 1.92 for a one-sided test at the 5% level.

### Two endpoints with different statuses

A `tmbroot` call can return one finite endpoint and one missing value when the profile flattens on one side within the searched range. For a scale parameter estimated from four observations, the upper side of a variance profile rises slowly, so the upper root may lie far beyond a modest `parm.range`. Report such a result as a one-sided bound with the range searched, for example "lower 0.62, upper not reached below 8", rather than copying the range limit into the upper cell. The lower endpoint keeps its likelihood-ratio meaning; the missing upper endpoint carries information too, namely that these data do not bound the parameter from above.

### Base-R companion (runs in the classroom)

```r
y <- c(1, 2, 4, 7);sigma <- 2;n <- length(y);center <- mean(y);cutoff <- .5 * qchisq(.95, 1)
rise <- function(mu) n * (mu - center)^2 / (2 * sigma^2) - cutoff
roots <- c(uniroot(rise, c(center - 10, center))$root, uniroot(rise, c(center, center + 10))$root)
exact <- center + c(-1, 1) * sigma * sqrt(2 * cutoff / n)
print(rbind(roots = roots, exact = exact));stopifnot(max(abs(roots - exact)) < 1e-4)
print(c(unconstrained_lower = .1 - 1.96 * .2, positive_domain_boundary = 0))
```
