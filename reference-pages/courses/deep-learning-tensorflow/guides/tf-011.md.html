tf-011: Keras models and explicit training contracts#

Level and prerequisites#

Beginner; approximately 120 minutes. Direct prerequisites: tf-010. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Map compile/fit/evaluate to the explicit forward-loss-gradient-update sequence. The central investigation is concrete: Create a one-Dense-unit model with fixed zero initializer; perform exactly one full-batch SGD step on the pilot points with shuffling disabled. The finish condition is The zero-bias, no-intercept configuration matches tf-008 within 1e-6 in float32; report dtype and reduction before comparing values. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Keras packages the same computation that the earlier tape lesson exposed. Dense computes a matrix product and optionally adds a bias. Compile selects the loss and optimizer but does not itself update weights. Training evaluates the forward function, reduces the loss, differentiates and applies the optimizer. To compare a high-level API with the hand-derived update, every relevant choice must match: no intercept, a zero initial weight, mean squared error, full-batch SGD and the same rate. Otherwise a difference may reflect a different model or objective instead of an API bug. Evaluation must be distinguished from a training call because it should not apply gradients.

Vocabulary and concepts#

Dense: An affine feature transformation with tracked weights.

Compile: Configuration of loss, optimizer and metrics.

Training call: Forward, differentiation and update on current weights.

Syntax anatomy and reasoning sequence#

Input(shape=(1,)) excludes the batch dimension. Dense(1,use_bias=False) creates a single trainable scalar kernel. Reshape the three observations to (3,1), matching targets exactly. Compile uses SGD(.1) with loss='mse'. train_on_batch executes one full-batch step without a data-shuffle dependency. get_weights returns NumPy copies useful for comparison. A new model is required for each independent control.

Connect the Keras abstraction to one scalar calculation#

The no-bias Dense layer represents y_hat=wx. Its single kernel is trainable state; the predictions and loss are activations computed from that state. Building or compiling a model configures those relationships. Training is the later operation that evaluates a gradient and changes the kernel.

For x=[1,2,3]x=[1,2,3]x=[1,2,3], targets 2x and mean squared error, the loss is (14/3)(w-2) squared. Its derivative is 283(w−2)\frac{28}{3}(w-2)328​(w−2). At zero the gradient is −563\frac{-56}{3}3−56​; an SGD step of size 0.1 therefore gives w=2815w=\frac{28}{15}w=1528​. The residual coefficient is then −215\frac{-2}{15}15−2​, making the post-update loss 56675\frac{56}{675}67556​. Those fractions provide an independent check on the layer, loss reduction and optimizer configuration. A smooth training curve alone would not distinguish an unintended sum loss from the intended mean loss.

Keep predictions and targets explicitly shaped as one output per row. A prediction shaped (B,1) and a raw target shaped (B,) can broadcast to a (B,B) matrix in a manually written subtraction. That would compare each prediction with several targets instead of its paired target. Inspect shapes before reducing; reduction can hide the accidental extra axis.

Adding a bias changes the model to wx+b and raises the parameter count from one to two. The intercept is useful when the relationship need not pass through the origin, but it changes the hand calculation and the optimization problem. Evaluation should read the current parameters without performing a training update; distinguish that property from any layer-specific moving state introduced later.

Worked example / walkthrough#

Example A: Construct a scalar model#

Excluding a bias preserves the exact scalar model yhat=w*x. A Dense layer with its default bias would introduce a second parameter and a second gradient, invalidating the direct comparison.

import numpy as np
import tensorflow as tf

model=tf.keras.Sequential([tf.keras.Input(shape=(1,)),tf.keras.layers.Dense(1,use_bias=False,kernel_initializer='zeros')])
x=np.array([[1.],[2.],[3.]],dtype='float32'); y=2*x
assert model.count_params()==1
np.testing.assert_array_equal(model(x).numpy(),np.zeros((3,1)))

Expected: one parameter and all initial predictions0.

Example B: Audit the first update#

The API may report the loss used for the update, rather than the loss at the updated weight. Recompute predictions after the step to distinguish before from after.

import numpy as np
import tensorflow as tf

model=tf.keras.Sequential([tf.keras.Input(shape=(1,)),tf.keras.layers.Dense(1,use_bias=False,kernel_initializer='zeros')])
x=np.array([[1.],[2.],[3.]],dtype='float32'); y=2*x
assert model.count_params()==1
np.testing.assert_array_equal(model(x).numpy(),np.zeros((3,1)))
model.compile(optimizer=tf.keras.optimizers.SGD(.1),loss='mse')
model.train_on_batch(x,y)
np.testing.assert_allclose(model.get_weights()[0],[[28/15]],atol=1e-6,rtol=0)
np.testing.assert_allclose(np.mean((model(x).numpy()-y)**2),56/675,atol=1e-6,rtol=0)

Expected: kernel28/15 and post-update loss56/675 within 1e-6.

Common pitfalls and diagnosis#

A wrong first kernel value points to learning rate, reduction, initialization or target shape before it points to an optimizer mystery. Print the unreduced error shape and the parameter count. If evaluation changes the kernel, inspect whether a training operation was called. If only moving statistics change, investigate training mode rather than assuming all state is an ordinary trainable weight.
