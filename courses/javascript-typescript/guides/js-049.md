# js-049: Time series: dates, sorted lines and visible gaps

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-048`.

## Learning objectives

Draw a UTC time-series line that stays in time order and shows missing observations as gaps. The central exercise is: Build a UTC line chart with a gap.

## Purpose, vocabulary and mental model

A time series associates measurements with times. A JavaScript Date represents an instant, while formatting can use local time or UTC. If the lesson uses UTC dates, use UTC parsing, scales and formatting consistently so a chart does not shift a day in another time zone.

A line connects observations in the supplied order. D3 does not automatically sort your records by time. Connecting unsorted points can produce a zigzag that implies a path the data never took. Sorting a copy preserves the source order when other code owns the original data.

Missing intervals deserve visible treatment. A line generator’s defined predicate can break a path at missing observations. Connecting across a long outage can imply continuous measurement when none exists. Explain whether a gap means missing data, no activity or a deliberate sampling interval.

### Key terms

- **UTC:** Coordinated Universal Time. Using UTC parsing, scales and formatting together keeps a date from shifting a day when the viewer is in another time zone.
- **Time scale:** A `d3.scaleUtc` mapping from Date instants to positions whose ticks fall on calendar boundaries.
- **Line generator:** A `d3.line` function that turns an ordered array of records into SVG path data through x and y accessors. It connects points in the order supplied, so records must be sorted by time first.
- **Defined predicate:** The `.defined` accessor of a line generator; records for which it returns false break the path into separate segments.
- **Missing interval:** A stretch of time with no valid observation, shown as a visible gap rather than a line that implies continuous measurement.

## Syntax anatomy and mechanism

`d3.scaleUtc` maps instants to x positions. A line generator uses x and y accessors to produce an SVG path string. `.defined(d => Number.isFinite(d.value))` controls which records form continuous segments. Set `fill: none` for an ordinary line so the path is not treated as a filled polygon.

A null value must be rejected explicitly because `Number(null)` becomes zero. Sorting and missingness policies are data decisions, not merely chart styling. The reference checks ordering and the number of separate path segments in a small fixture.

## Worked example / walkthrough

### Worked example 1: Use explicit UTC instants

The Z suffix makes the time zone unambiguous.

```javascript
const a = new Date("2024-01-01T00:00:00Z");
const b = new Date("2024-01-02T00:00:00Z");
console.log((b - a) / 86400000);
```

**Expected observation:** 1 day for these two instants.

### Worked example 2: Break a line at missing data

The defined predicate accepts only finite values, so the null observation splits the line.

```javascript
// js-049 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Time series: dates, sorted lines and visible gaps")
  .style("width", "100%")
  .style("max-width", "640px");
const series = [
  { date: new Date("2024-01-01T00:00:00Z"), value: 3 },
  { date: new Date("2024-01-02T00:00:00Z"), value: 5 },
  { date: new Date("2024-01-03T00:00:00Z"), value: null },
  { date: new Date("2024-01-04T00:00:00Z"), value: 4 },
  { date: new Date("2024-01-05T00:00:00Z"), value: 6 },
];
const x = d3
  .scaleUtc()
  .domain(d3.extent(series, (d) => d.date))
  .range([60, 600]);
const y = d3.scaleLinear().domain([0, 8]).range([320, 40]);
const line = d3
  .line()
  .defined((d) => Number.isFinite(d.value))
  .x((d) => x(d.date))
  .y((d) => y(d.value));
const path = svg
  .append("path")
  .attr("d", line(series))
  .attr("fill", "none")
  .attr("stroke", "#2563eb")
  .attr("stroke-width", 3);
check(
  path.attr("d").split("M").length - 1 === 2,
  "The gap should split the line into two segments",
);
output.textContent = "js-049 worked example 2 complete";
```

**Expected observation:** A line with a visible break at January 3: its path starts two separate segments instead of dropping to zero or bridging the gap.

## Six progressive exercises

### Exercise 1: Predict date order after sorting.

**Expected evidence:** Chronological order by numeric instant.

**Progressive hint:** The line generator uses array order.

### Exercise 2: Insert a missing observation.

**Expected evidence:** The path has a visible gap under the stated policy.

**Progressive hint:** A missing value is not a measured zero.

### Exercise 3: Build a UTC line chart with a gap.

**Expected evidence:** Time-ordered points and separate defined segments.

**Progressive hint:** Use matching time parsing, scale and formatting conventions.

### Exercise 4: Diagnose a line that doubles back in time.

**Expected evidence:** Input order is unsorted or dates were parsed incorrectly.

**Progressive hint:** Inspect numeric timestamps before changing interpolation.

### Exercise 5: Handle an empty or all-missing series.

**Expected evidence:** Show an explicit no-data message rather than invalid domains.

**Progressive hint:** Extent on no valid data does not define a meaningful chart scale.

### Exercise 6: Explain interpolation limits for irregular observations.

**Expected evidence:** Connecting samples is a visual assumption, not evidence between measurements.

**Progressive hint:** Label gaps and sampling intervals.

## Debugging and common mistakes

If the line doubles back, check the order of the parsed instants, not the path generator, and sort a copy by `getTime()`. A date-only ISO string parses as UTC, but a date and time without an offset parses as local time. `d3.utcParse('%Y-%m-%d')` rolls `2024-02-30` over to March 1, so validate day ranges yourself. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a line that doubles back in time. Distinguishing evidence: Input order is unsorted or dates were parsed incorrectly.

## Accessibility and interpretation

Describe the span and the gap in text, for example "Daily values from January 1 to 5; no observation on January 3". A visible break or a labeled gap marker helps sighted readers notice missing data, and a table of date and value lets everyone confirm which days were measured. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

A connected line implies values between samples. Use `line.defined` so a missing day becomes a visible break instead of a drop to zero or a straight bridge. State the time zone, the sampling interval and whether points are instants or daily totals, because a UTC midnight can fall on the previous local date. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
