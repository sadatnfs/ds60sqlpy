Purpose, vocabulary and mental model#

Shared memory lets threads in one block communicate through a common scratch array. Communication requires ordering: a consumer must not read a location until its producer has written it. __syncthreads() is a block barrier with memory-ordering effects for participating threads. Put bounds predicates around loads and stores while keeping the required barrier participation uniform. Invalid tail lanes can load a neutral value and still reach the barrier. A barrier does not coordinate ordinary independent blocks, and a memory fence does not force other threads to arrive at the same program point.

Worked example 1: trace the mechanism#

Four threads load [3,6,9,12][3,6,9,12] into a shared tile, synchronize, then thread t reads tile[3-t]. The reversed output is [12,9,6,3][12,9,6,3]. Without the barrier, a consumer could read before another thread loads its value. An apparent success on one execution is not a synchronization proof.

The complete CPU model below intentionally models only the named arithmetic, layout, dependency or capability decision. It does not model GPU scheduling, caches, instruction timing or device memory visibility.

tile = [3, 6, 9, 12]
# A CPU phase boundary models the dependency, not GPU scheduling.
output = [tile[3 - lane] for lane in range(4)]
assert output == [12, 9, 6, 3]
partial = [3, 6, 9, 0]
assert sum(partial) == 18
print({"reversal": output, "neutralized_tail_sum": sum(partial)})

Expected observation: Every assertion succeeds. A representative CPU output is:

{'reversal': [12, 9, 6, 3], 'neutralized_tail_sum': 18}

Tiny floating-point display differences across platforms are acceptable only where the explicit assertions use a tolerance; integers, shapes and ordering must still satisfy their exact contracts. A printed hypothetical duration is a model output, not a measured GPU benchmark.

Worked example 2: change a meaningful condition#

For a three-element tail in a four-thread block, lane three loads a neutral zero and still participates in the barrier. Only valid lanes store output. A conditional if (i<n) { load; barrier; } can violate the barrier contract when some block threads skip it.

Before applying this example to your own program, write down which inputs are read, which result is produced, and the condition that makes the comparison valid. Keep the original case as a regression check when changing a boundary.

Common mistakes and diagnosis#

A tempting but incorrect claim in this chapter is: a memory fence and a barrier are interchangeable.

For the concrete failure exercise, a conditional barrier hangs only on ragged input. What is the smallest repair? Preserve the original input and the stage where behavior diverged. Compare with the CPU model or dependency diagram before changing hardware configuration. A compiler result, synthetic timing model, profiler counter and returned numeric answer support different claims. Record unavailable hardware honestly.
