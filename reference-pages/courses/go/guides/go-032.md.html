go-032: Security boundaries, escaping and input budgets#

Level and prerequisites#

Intermediate. Allow about 120 minutes, then revisit the transfer case later. Prerequisites: go-031

Learning objectives#

By the end, explain trust boundary, contextual escaping, allowlist; implement the six investigations below; and defend the expected result of a changed input before running it. A passing reference is evidence about that program, not a certification of your independent understanding.

Why this mechanism matters#

Security starts by identifying untrusted inputs and operations carrying authority. Validation defines the accepted domain, while escaping protects the syntax of a particular output context. HTML escaping, URL encoding and SQL parameter binding solve different problems. They are not interchangeable. A string replacement is not an authorization policy. Bound input before expensive parsing, reject ambiguous forms and keep secrets out of diagnostics. These harmless examples expose boundary semantics; they do not establish that the local classroom is safe for hosting arbitrary untrusted tenants. Review authority and ownership before connecting code to real files, networks or services.

Vocabulary and concepts#

  • Trust boundary: A point where data from another authority enters an operation.
  • Contextual escaping: Encoding data for the syntax where it will appear.
  • Allowlist: A deliberately limited set of accepted values or operations.

Syntax anatomy and reasoning#

html/template escapes according to HTML context; text/template does not supply that protection. url.QueryEscape encodes one query value rather than an entire URL. filepath.IsLocal checks a lexical property but does not resolve symlinks. subtle.ConstantTimeCompare compares equal-length byte sequences without value-dependent comparison time. Protocol design must still handle length, storage and cryptographic choices.

Worked example / walkthrough#

Worked example 1: Escape HTML data#

Render script-like text with html/template.

package main

import (
	"bytes"
	"fmt"
	"html/template"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Escape HTML data
	{
		var b bytes.Buffer
		t := template.Must(template.New("x").Parse("<p>{{.}}</p>"))
		check(t.Execute(&b, "<script>alert(1)</script>") == nil, "render")
		check(strings.Contains(b.String(), "&lt;script&gt;"), "escape")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: Angle brackets become escaped text.

Marking untrusted input as template.HTML would bypass this boundary. Keep data as data.

Worked example 2: Encode a query value#

Encode a value containing ampersand and equals characters.

package main

import (
	"bytes"
	"fmt"
	"html/template"
	"net/url"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Escape HTML data
	{
		var b bytes.Buffer
		t := template.Must(template.New("x").Parse("<p>{{.}}</p>"))
		check(t.Execute(&b, "<script>alert(1)</script>") == nil, "render")
		check(strings.Contains(b.String(), "&lt;script&gt;"), "escape")
	}

	// Encode a query value
	{
		original := "a&role=admin"
		encoded := url.QueryEscape(original)
		decoded, err := url.QueryUnescape(encoded)
		check(err == nil && decoded == original && encoded != original, "query")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: Decoding recovers the original string.

Encoding prevents data from being interpreted as new query syntax. It does not authorize the resulting request.

Common pitfalls and diagnosis#

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from check identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned error is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
