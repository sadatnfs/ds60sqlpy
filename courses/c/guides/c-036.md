# c-036: POSIX threads and joined object lifetimes

## Level and prerequisites

Advanced, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-035`

## Learning objectives

Explain thread argument lifetime, join, disjoint result storage. Implement the six investigations with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A thread executes concurrently within the process and shares its address space. Passing a pointer to a thread does not extend the target lifetime. Keep the argument object alive until the worker no longer accesses it, normally by joining the worker before leaving its owning scope. Each worker can write to distinct result storage without a mutex when no conflicting access occurs and the parent waits before reading. Shared mutation needs synchronization, taught next. Thread creation and joining can fail, so their return values belong to the resource contract. Detached threads require a different ownership design and are not a shortcut around joining.

## Vocabulary and concepts

- **Thread argument lifetime:** The interval during which a worker may access its supplied data.
- **Join:** Waiting for a specific thread to finish and reclaiming joinable-thread resources.
- **Disjoint result storage:** Separate objects written by separate workers.

## Syntax anatomy and execution trace

pthread_create takes a pointer to a pthread_t, optional attributes, a function void *(*)(void *) and an argument pointer. The worker converts that argument back to its actual type. pthread_join waits for termination and can retrieve a returned pointer, whose lifetime still needs justification. POSIX pthread functions generally return an error number directly rather than setting errno in the same way as read or write.

## Worked example / walkthrough

### Worked example 1: Join one calculation

Start a thread squaring input 7 and join it.

```c
#include <assert.h>
#include <limits.h>
#include <pthread.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Work {
  int input, output;
};
void *square_worker(void *argument) {
  struct Work *work = argument;
  work->output = work->input * work->input;
  return work;
}

int main(void) {
  /* Join one calculation */
  {
    struct Work work = {.input = 7, .output = 0};
    pthread_t thread;
    CHECK(pthread_create(&thread, NULL, square_worker, &work) == 0);
    CHECK(pthread_join(thread, NULL) == 0);
    CHECK(work.output == 49);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The retained result is 49.

The stack argument remains alive until after join. Reading output before synchronization would not have this contract.

### Worked example 2: Keep separate arguments

Start two workers with inputs 2 and 3.

```c
#include <assert.h>
#include <limits.h>
#include <pthread.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Work {
  int input, output;
};
void *square_worker(void *argument) {
  struct Work *work = argument;
  work->output = work->input * work->input;
  return work;
}

int main(void) {
  /* Join one calculation */
  {
    struct Work work = {.input = 7, .output = 0};
    pthread_t thread;
    CHECK(pthread_create(&thread, NULL, square_worker, &work) == 0);
    CHECK(pthread_join(thread, NULL) == 0);
    CHECK(work.output == 49);
  }

  /* Keep separate arguments */
  {
    struct Work work[2] = {{2, 0}, {3, 0}};
    pthread_t threads[2];
    for (size_t i = 0; i < 2; i++)
      CHECK(pthread_create(&threads[i], NULL, square_worker, &work[i]) == 0);
    for (size_t i = 0; i < 2; i++)
      CHECK(pthread_join(threads[i], NULL) == 0);
    CHECK(work[0].output == 4 && work[1].output == 9);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Their independent outputs are 4 and 9.

Each worker receives its own stable object rather than the address of one changing loop variable.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
