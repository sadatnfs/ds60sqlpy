llm-024: KV caches and incremental equivalence#

Level and prerequisites#

Intermediate; approximately 135 minutes. Direct prerequisites: llm-023. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Prove a cache optimization preserves the uncached causal computation. The central investigation is concrete: Run full-prefix and one-token-at-a-time inference on fixed weights, tracking position offsets and cache ownership by request. The finish condition is Per-position logits agree within 1e-6. A fresh request receives an empty cache; a deliberately reused foreign cache fails the isolation check. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Reuse past computation only when its meaning is unchanged#

During generation, the prefix grows one token at a time. A simple implementation can rerun the entire decoder on the full prefix before every next-token choice. That repeats work for earlier positions whose causal representations should not have changed. A key/value cache stores the relevant past attention projections so the new token can use them without recomputing the whole prefix. The optimization is justified by the information boundary, not merely by the fact that arrays can be concatenated.

Follow the literal prefix [2,5,7,3]. A full pass produces logits with shape [1,4,16]. An incremental pass first sends token 2, storing its keys and values at position zero. It then sends token 5 with the one-position cache, so its position embedding uses index one and its query can read keys zero and one. The next calls use offsets two and three. Each call returns [1,1,16] logits; concatenating the four outputs should match the full result within the specified float32 tolerance.

The cache after four tokens contains K and V arrays shaped [1,2,4,16]: one batch row, two heads, four positions and sixteen features per head. Both arrays are needed because keys score relevance while values supply the mixed features. Their raw float32 data occupies 212416*4=1,024 bytes for this single attention layer. That calculation excludes Python metadata, parameters, temporary buffers and any additional layers. It describes stored tensor values, not measured process memory.

Causal masking must use absolute positions in the incremental call. At the fourth call the query has local row index zero but absolute position three. It may attend to all four stored key positions. A naive lower triangle of shape [1,4] would allow only the first column, confusing local tensor coordinates with sequence positions. Correct shape alone cannot reveal this error; comparing with the full-prefix oracle can.

Why are past values reusable? Under the model's causal computation, the representation of an earlier token did not depend on the tokens appended later. Its keys and values are therefore the same ones a fresh full-prefix calculation would produce, assuming the same model, position policy and evaluation behavior. In a multilayer model, each layer needs its own cache because it projects a different hidden representation. Editing an earlier prefix token or changing model weights can invalidate later stored states that depended on them.

Ownership is consequently part of numerical correctness. The fixture binds the cache to request A and model label v1, rejecting request B or label v2. The surrounding application must ensure those labels identify the actual artifacts and context. A cache from another conversation can have perfectly compatible dimensions while representing the wrong information. Starting a new request with an empty cache avoids that accidental context transfer.

Caching removes repeated past projections and hidden-state work, but the new query still compares with the stored keys and mixes stored values. Context length therefore continues to affect work and storage. The detached cache in this lesson is for inference; reusing it while expecting full-prefix training gradients would change the differentiable computation. The exact parity test establishes the local optimization's semantics before any claim about throughput or deployment scale is considered.

Vocabulary and concepts#

KV cache: Stored attention keys and values for prior tokens.

Position offset: Number of previously processed positions in an incremental request.

Cache ownership: Identity policy preventing state reuse across incompatible requests.

Syntax anatomy and reasoning sequence#

TinyDecoder.forward accepts new IDs and optional past K/V. It concatenates along the time dimension, uses offset=old_time for positions, and constructs allowed keys by comparing absolute positions. Returned cache tensors are detached for inference. An owner wrapper binds cache state to request ID and model version; a mismatch is rejected before the forward call.

Follow one incremental token through the cache#

A full four-token pass computes logits [1, 4, 16]. Incremental inference instead supplies one token at a time. The first call stores K/V for position zero. The second call projects the new token at position one, appends its K/V to the stored tensors and forms a query that can read positions zero and one. After four calls, concatenating the four [1, 1, 16] outputs along time should match the full pass.

The positional offset is the existing cached length. Resetting the new token to position zero changes its representation even if key/value concatenation has the expected shape. A correct cache can therefore fail parity through a position mistake rather than a storage-size mistake. Likewise, a correct output shape does not prove that key order matches token order.

Past keys and values are reusable because the causal computation for an earlier token did not depend on later tokens. In a multilayer decoder, each layer stores its own projections of the corresponding hidden representations. If the model weights, adapter, prompt prefix or position policy changes, those stored values may no longer represent the requested computation. Editing an earlier token can invalidate later cached states that depended on it; it is not generally sufficient to replace one isolated cache row.

Cache ownership is part of correctness#

The local ownership record binds the cache to request A and model label v1. acquire rejects a different request or model label. This demonstrates the check, but the caller is responsible for binding that label to the actual model artifact. A string comparison does not automatically notice changed weights if the version label was left unchanged. A serving system also needs a clear tokenizer, prefix and position-policy identity, plus the relevant request/access boundary.

The returned K/V are detached for inference. Reusing them while expecting full-prefix training gradients would change the differentiable computation. The helper checks its declared batch/context conditions, while a complete general cache interface should additionally validate all head, width, dtype, device and mask contracts. The lesson does not claim that its small metadata wrapper is a sandbox for untrusted cache objects.

Caching removes repeated work on past projections and hidden states, but a new query still compares with stored keys and mixes stored values. It does not eliminate all context-length cost or expand the model's declared position range. Changing sampling temperature alone does not change K/V for an identical token prefix and model, but it can change which future tokens are selected, and therefore change the prefix that later cache entries must represent.

Worked example / walkthrough#

Example A: Compute a full-prefix oracle#

The reference recomputes the complete context without relying on cached state. It provides a separate path for checking the incremental implementation.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
torch.manual_seed(7); model=TinyDecoder(); model.eval(); ids=torch.tensor([[2,5,7,3]])
with torch.no_grad(): full,_=model(ids)
assert tuple(full.shape)==(1,4,16)

Expected: logits shape(1,4,16).

Example B: Run one token at a time#

Both key/value history and position offset must be correct. A cache with valid tensor shapes can still produce wrong logits if positions restart at zero.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
torch.manual_seed(7); model=TinyDecoder(); model.eval(); ids=torch.tensor([[2,5,7,3]])
with torch.no_grad(): full,_=model(ids)
assert tuple(full.shape)==(1,4,16)
cache=None; outputs=[]
with torch.no_grad():
    for i in range(4):
        logits,cache=model(ids[:,i:i+1],cache); outputs.append(logits)
incremental=torch.cat(outputs,dim=1)
torch.testing.assert_close(incremental,full,atol=1e-6,rtol=0)

Expected: incremental logits match full within 1e-6.

Common pitfalls and diagnosis#

Check cache shape and token order, then positional offset and actual model identity. Recompute from an empty cache when the prefix or model changes. A request/version string check only enforces the metadata supplied to it. Detached inference caches do not preserve full-prefix training gradients, and matching tensor sizes alone does not establish semantic cache validity.
