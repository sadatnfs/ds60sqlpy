# mle-009: Model evaluation, calibration and decision utility

## Level and prerequisites

Intermediate. Direct prerequisites: `mle-005`, `mle-008`

**Outcome:** Evaluate probabilities, ranking and actions with separately interpreted evidence.

## Question and mechanism

Different metrics describe different properties of a prediction system. Ranking metrics ask whether positive cases tend to receive higher scores. Probability losses evaluate numeric confidence. A threshold turns a probability into an action under a particular cost and benefit structure. These questions should not be collapsed into a single claim that a model is good.

The first case evaluates a fitted model on forty later synthetic decisions after all their labels are mature at cutoff 224. It reports Brier loss, log loss and AUC, then displays a descriptive calibration plot with bin counts and readable values. The plot is intentionally labeled as descriptive: forty observations do not justify a precise population-calibration claim without uncertainty analysis.

The second case applies declared utility values to four fixed labeled examples. The best threshold on this small teaching fixture is not automatically a deployable policy. In a real workflow, select thresholds using an appropriate development design, evaluate the selected procedure independently and distinguish predictive performance from causal effects of the resulting actions.

## Syntax and data contract

predict_proba returns the positive-class scores under the fitted model. The example uses standard metric implementations and checks their domains. Calibration bins retain their counts and mean predictions; empty bins are omitted explicitly. The threshold case computes benefits for true positive actions and costs for false positives, with the cost values stated in the source.

## Worked case 1: Read several kinds of evaluation evidence

The first program computes actual held-out metrics and an accessible Plotly calibration figure. Its table records bin boundaries, counts, mean scores and observed shares. It checks label maturity before interpreting the result.

**Expected evidence:** Forty evaluation rows contribute; all metric values are finite and their descriptive chart retains exact bin counts.

```python
import numpy as np
import pandas as pd


def dataset():
    rng = np.random.default_rng(17)
    n = 120
    usage = rng.uniform(1, 100, n)
    tickets = rng.poisson(2, n)
    region = np.where(np.arange(n) % 2 == 0, "north", "south")
    logit = 0.9 * tickets - 0.035 * usage + (region == "north") * 0.3
    probability = 1 / (1 + np.exp(-logit))
    label = (rng.random(n) < probability).astype(int)
    cutoff = np.arange(n) + 100
    return pd.DataFrame(
        {
            "id": np.arange(n),
            "customer_id": np.arange(n) % 12,
            "cutoff": cutoff,
            "available_at": cutoff - 2,
            "label_available_at": cutoff + 4,
            "usage": usage,
            "tickets": tickets,
            "region": region,
            "label": label,
        }
    )


def fit_pipeline(frame):
    from sklearn.compose import ColumnTransformer
    from sklearn.impute import SimpleImputer
    from sklearn.linear_model import LogisticRegression
    from sklearn.pipeline import Pipeline
    from sklearn.preprocessing import OneHotEncoder, StandardScaler

    numeric = Pipeline([("impute", SimpleImputer(strategy="median")), ("scale", StandardScaler())])
    transform = ColumnTransformer(
        [
            ("numeric", numeric, ["usage", "tickets"]),
            ("region", OneHotEncoder(handle_unknown="ignore", sparse_output=False), ["region"]),
        ]
    )
    model = Pipeline(
        [("features", transform), ("classifier", LogisticRegression(max_iter=200, random_state=17))]
    )
    model.fit(frame[["usage", "tickets", "region"]], frame["label"])
    return model


def example_one():
    from sklearn.metrics import brier_score_loss, log_loss, roc_auc_score

    frame = dataset()
    train = frame[frame.label_available_at <= 180]
    test = frame[frame.cutoff >= 180]
    model = fit_pipeline(train)
    prob = model.predict_proba(test[["usage", "tickets", "region"]])[:, 1]
    metrics = {
        "brier": float(brier_score_loss(test.label, prob)),
        "log_loss": float(log_loss(test.label, prob)),
        "auc": float(roc_auc_score(test.label, prob)),
    }
    assert 0 <= metrics["brier"] <= 1 and metrics["log_loss"] >= 0 and 0 <= metrics["auc"] <= 1
    assert len(np.unique(test.label)) == 2
    assert int(test.label_available_at.max()) <= 224
    import plotly.graph_objects as go

    bins = np.linspace(0, 1, 6)
    table = []
    for i in range(5):
        selected = (prob >= bins[i]) & (prob <= bins[i + 1] if i == 4 else prob < bins[i + 1])
        if selected.any():
            table.append(
                [
                    float(bins[i]),
                    float(bins[i + 1]),
                    int(selected.sum()),
                    float(prob[selected].mean()),
                    float(test.label.to_numpy()[selected].mean()),
                ]
            )
    assert sum(row[2] for row in table) == len(test)
    figure = go.Figure(
        go.Scatter(
            x=[row[3] for row in table],
            y=[row[4] for row in table],
            mode="markers+lines",
            name="Synthetic held-out bins",
        )
    )
    figure.add_trace(
        go.Scatter(
            x=[0, 1], y=[0, 1], mode="lines", line={"dash": "dash"}, name="Equality reference"
        )
    )
    figure.update_layout(
        title="Descriptive calibration after label maturity",
        xaxis_title="Mean predicted probability",
        yaxis_title="Observed positive share",
        meta={
            "description": (
                "Calibration bins for 40 synthetic future rows, all labels "
                "known by cutoff 224. No sampling interval is "
                "claimed."
            ),
            "table": {
                "columns": ["Lower", "Upper", "Rows", "Mean prediction", "Observed share"],
                "rows": table,
            },
        },
    )
    figure.show()
    return {"rows": len(test), "metrics": metrics, "not_a_deployment_decision_alone": True}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Compare actions under a declared utility

The second case uses benefits 5 and false-positive cost 2. Thresholds 0.3,0.5 and 0.8 produce different action sets and utilities. The plotted comparison makes that consequence visible without inferring business costs from data.

**Expected evidence:** Utilities are 8,10 and 5 for the three thresholds.

```python
import numpy as np


def example_two():
    y = np.array([0, 0, 1, 1])
    prob = np.array([0.1, 0.4, 0.6, 0.9])

    def utility(threshold):
        chosen = prob >= threshold
        return int(5 * np.sum(chosen & (y == 1)) - 2 * np.sum(chosen & (y == 0)))

    assert utility(0.3) == 8 and utility(0.5) == 10 and utility(0.8) == 5
    import plotly.graph_objects as go

    values = [[threshold, utility(threshold)] for threshold in (0.3, 0.5, 0.8)]
    figure = go.Figure(
        go.Bar(
            x=[str(row[0]) for row in values], y=[row[1] for row in values], name="Declared utility"
        )
    )
    figure.update_layout(
        title="Threshold utility on a fixed teaching fixture",
        xaxis_title="Decision threshold",
        yaxis_title="Utility units",
        meta={
            "description": (
                "Four labeled examples under benefit 5 and false-positive "
                "cost 2; these are declared teaching costs, not estimated "
                "business effects."
            ),
            "table": {"columns": ["Threshold", "Utility"], "rows": values},
        },
    )
    figure.show()
    return {
        "utilities": {str(t): utility(t) for t in (0.3, 0.5, 0.8)},
        "costs_are_declared_not_inferred": True,
    }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

A metric improvement can come from changed data, labels, thresholds or selection rather than a better model. Inspect cohort identity and maturity before comparing scores. A calibration plot without counts can hide weak evidence, and a utility table without stated costs can hide an undefined decision.
