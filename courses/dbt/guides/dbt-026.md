# dbt-026: Publish a complete validated analytics product

## Level and prerequisites

Advanced. Direct prerequisites: `dbt-009`, `dbt-010`, `dbt-011`, `dbt-014`, `dbt-016`, `dbt-017`, `dbt-018`, `dbt-021`, `dbt-024`, `dbt-025`

**Outcome:** Deliver a complete local analytics product with a reviewable acceptance decision.

## Question and mechanism

The capstone joins the preceding mechanisms into one bounded analytics product. Raw order text is staged under a parsing policy, a customer dimension enriches accepted orders, and a mart summarizes totals at a declared customer/region grain. Tests check source and model identities before an accepted artifact is published. The complete program creates ordinary dbt files and executes the installed tool against an owned DuckDB database.

The fixture contains one malformed amount, so the accepted mart must account for excluded input rather than silently describing itself as the whole source. The valid product totals 21 across three accepted orders. A second fixture duplicates a dimension key, and the build must block publication. This case connects an operational gate to the earlier fanout reasoning.

The final receipt records grain, row count, a data hash and manifest dependencies. Those fields make an accepted artifact identifiable and reviewable. They do not establish authenticity or a deployed service-level objective on their own. A durable environment additionally needs ownership, atomic publication, storage/retention decisions and recovery after an uncertain operation.

## Syntax and data contract

The program writes seed CSVs, model SQL and YAML tests, runs build, inspects actual query results and generates documentation artifacts. Only the accepted path writes published.json. Its hash binds a canonical serialized result for this fixture. The manifest supplies declared model dependencies; the row checks and test outcomes provide separate evidence about the computation.

## Run the lesson

Open this subject in `/classroom`, then show its code and notes. The prepared `data-engineering` worker runs `main.py` in a fresh temporary directory. The examples use installed packages and synthetic local fixtures; no account, cloud service, network request or package download is required. Save source and notes before switching lessons. Temporary databases, project files and tracking artifacts are recreated by each complete program and removed after the job. The classroom retains the submitted source and bounded output, not an indefinitely running external service. The guide distinguishes this local execution from the deployment decisions that need an owned production environment.



## Worked case 1: Build and publish the accepted case

The clean dimension and staged order rules produce two customer summaries. The program reconciles raw and accepted counts, inspects dependency metadata and checks the written receipt. This is a complete local workflow rather than a list of proposed commands.

**Expected evidence:** Customer totals are 12 and 9, overall 21; one raw order is quarantined and a receipt is written.

```python
import hashlib
import json
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def capstone(bad_dimension):
    from ds60sqlpy.plot_artifacts import publish_report

    with tempfile.TemporaryDirectory() as d:
        models = {
            "staging_orders": (
                "select id::integer as order_id,customer::integer as "
                "customer_id,try_cast(amount as integer) as amount from {{ "
                "ref('raw_orders') }} where try_cast(amount as integer) is "
                "not null"
            ),
            "customer_mart": (
                "select o.customer_id,c.region,sum(o.amount)::bigint as "
                "total,count(*)::bigint as orders from {{ "
                "ref('staging_orders') }} o join {{ ref('customers') }} c "
                "on o.customer_id=c.customer_id group by "
                "o.customer_id,c.region"
            ),
        }
        schema = {
            "seeds": [
                {
                    "name": "customers",
                    "columns": [{"name": "customer_id", "data_tests": ["unique", "not_null"]}],
                }
            ],
            "models": [
                {
                    "name": "staging_orders",
                    "columns": [{"name": "order_id", "data_tests": ["unique", "not_null"]}],
                },
                {
                    "name": "customer_mart",
                    "description": "One accepted order total per customer and region.",
                },
            ],
        }
        customers = "customer_id,region\n10,north\n20,south\n" + (
            "10,north\n" if bad_dimension else ""
        )
        p = project(
            d,
            models=models,
            seeds={
                "raw_orders": "id,customer,amount\n1,10,5\n2,10,7\n3,20,9\n4,20,bad\n",
                "customers": customers,
            },
            schema=schema,
        )
        result = invoke(p, "build", succeeds=not bad_dimension)
        if bad_dimension:
            assert not result.success
            assert not (p / "published.json").exists()
            decision = {"published": False, "duplicate_dimension_blocked": True}
            publish_report(decision, description="dbt publication blocked by a failed key contract")
            return decision
        data = rows(
            p, "select customer_id,region,total,orders from customer_mart order by customer_id"
        )
        assert data == [(10, "north", 12, 2), (20, "south", 9, 1)]
        assert rows(p, "select count(*) from raw_orders") == [(4,)]
        assert rows(p, "select count(*) from staging_orders") == [(3,)]
        invoke(p, "docs", "generate")
        serialized = json.dumps(data, separators=(",", ":"))
        receipt = {
            "grain": "customer_id,region",
            "rows": len(data),
            "data_sha256": hashlib.sha256(serialized.encode()).hexdigest(),
            "model_dependencies": artifact(p, "manifest.json")["nodes"][
                "model.classroom.customer_mart"
            ]["depends_on"]["nodes"],
        }
        (p / "published.json").write_text(json.dumps({"data": data, "receipt": receipt}))
        assert json.loads((p / "published.json").read_text())["receipt"] == receipt
        published = {
            "published": True,
            "total": 21,
            "quarantined": 1,
            "receipt": receipt,
            "data": [list(row) for row in data],
        }
        publish_report(published, description="Accepted dbt product and publication receipt")
        return published


def example_one():
    return capstone(False)


if __name__ == "__main__":
    print(example_one())
```

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Change a valid order

Add a new identified paid amount and predict the mart change.

**Check:** Counts and totals reconcile independently.

**Hint:** Calculate the contribution before running.


### 2. Add a conflicting dimension

Use two different regions for one customer key.

**Check:** The contract rejects the ambiguity.

**Hint:** A duplicate is not resolved by arbitrary selection.


### 3. Inspect lineage

Identify both mart dependencies from the manifest.

**Check:** They name staging_orders and customers.

**Hint:** Dependencies are structured metadata.


### 4. Verify the receipt

Read published.json and recompute its data identity.

**Check:** The received content matches the declared hash and grain.

**Hint:** Keep identity separate from correctness.


### 5. Add temporal semantics

Extend the source with event and known timestamps.

**Check:** The resulting product obeys a declared cutoff.

**Hint:** Reuse the two-clock reasoning.


### 6. Write the release decision

Explain why the clean case is accepted and the bad case is blocked.

**Check:** The decision cites concrete checks and remaining boundaries.

**Hint:** A green process is not the entire argument.


## Diagnose errors and misleading results

If the product differs from its expected total, follow the pipeline from raw parsing through key relationships and aggregation. If the build fails, inspect which resources ran and whether publication was prevented. If a receipt is stale, do not update its hash without re-establishing the candidate's source and validation evidence.

Deliver a complete local analytics product with a reviewable acceptance decision.
