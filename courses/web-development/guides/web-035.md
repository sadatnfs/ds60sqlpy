# web-035: Arrays, records, keys and transformations

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-034`

## Learning objectives

Filter and summarize study records without changing the originals. Explain the risk of a lingering foreach reference. Use array, ordered map and key accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

PHP's array is an ordered map: it associates keys with values and preserves an iteration order. It can represent a list or a keyed record, but these are different data contracts. A list of study rows should not accidentally become an object-shaped JSON value because filtered numeric keys were left nonconsecutive. Key coercion can also matter, so avoid treating arbitrary external strings as interchangeable with integer indices.

Transformations are easier to reason about when they do not mutate the original data unexpectedly. Map computes a derived value for each record; filter keeps records satisfying a predicate. Validate expected fields before arithmetic. A missing key is different from a known null field and should be handled according to the record contract.

### Key terms

- **Ordered map:** PHP's array type, which stores key and value pairs in insertion order with integer or string keys.
- **Record:** An array with fixed string keys, such as a name and a score, used to describe one item.
- **Array filter:** The `array_filter()` function, which keeps elements whose callback returns true and preserves their original keys.
- **Array values:** The `array_values()` function, which renumbers keys from zero, often used after filtering to restore a list.
- **Mapping:** Transforming every element with a callback, such as with `array_map()`, to produce a new array of results.

## Syntax anatomy and mechanism

Use explicit string keys for records, such as subject and minutes. `array_filter` preserves keys, so `array_values` is useful when the intended result is a fresh list. `array_map` applies a function to values. PHP 8.4 adds `array_find`, which returns the first matching value or null, and `array_any` and `array_all`, which answer yes-or-no questions without building an intermediate array. A foreach by reference can leave a lingering reference to the last item; avoid it unless mutation is necessary and understood.

## Worked example / walkthrough

### Worked example 1: A small record

Keys name the meaning of each value.

```php
$row = ['subject' => 'CSS', 'minutes' => 55];
echo $row['subject'];
```

**Expected observation:** The named field produces CSS.

### Worked example 2: A filtered list

Reindexing preserves the intended list shape.

```php fragment
$visible = array_values(array_filter($rows, fn(array $row): bool => $row['minutes'] >= 40));
```

**Expected observation:** The result uses consecutive list indices.

## Contrast case: filtered keys leaking into JSON

The filter is correct, but the result is encoded directly. Compare the JSON with and without reindexing.

```php
$minutes = [10, 50, 45];
$kept = array_filter($minutes, fn(int $m): bool => $m >= 40);

echo json_encode($kept), "\n";
echo json_encode(array_values($kept)), "\n";
```

`array_filter` keeps the original keys, so `$kept` holds keys 1 and 2. Because the keys no longer start at 0 and run consecutively, `json_encode` cannot represent the array as a list and produces the object {"1":50,"2":45}. A JavaScript client that calls `.map` on that value then fails, since objects have no `map` method. After `array_values` the keys are 0 and 1 and the output is the list [50,45]. Filtering that keeps the first element would hide this bug, so test with data where an early item is removed.

## Debugging and common mistakes

Do not assume every array is a list. Avoid weakly typed mixed records whose missing fields become warnings during rendering. Keep mutation deliberate and test the original data after transformations.

When json_encode prints an object with numeric keys where you expected an array, the filter kept the original keys; wrap the result in array_values. When the source rows have changed after a transformation, look for a foreach by reference that was never unset.
