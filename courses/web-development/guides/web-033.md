# web-033: Expressions, integer money and deliberate conversion

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-032`

## Learning objectives

Implement a bounded quantity calculation and cents formatter. Explain when integer cents are insufficient. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

An expression produces a value. Arithmetic operators combine numbers, concatenation joins strings, and logical operators combine conditions. Parentheses make intended grouping clear when an expression mixes operations. Do not assume that familiar-looking operators have the same precedence in every language or version. A readable intermediate variable is often safer than a dense one-line formula.

Many decimal fractions cannot be represented exactly by binary floating point. For a small money example, represent amounts as integer cents and define rounding when converting from external decimal text. This avoids accidentally treating a display string as a precise numeric representation. Integer arithmetic still has limits: values outside the supported range need a different numeric representation or library.

## Syntax anatomy and mechanism

Compute subtotal cents as unit cents times quantity, then add a fixed fee. Validate quantity before multiplication. Use intdiv for deliberate integer division and the remainder operator for the remaining cents. This lesson does not accept arbitrary decimal currency strings; that parser would need explicit scale, sign, range and rounding rules.

## Classroom execution and offline inputs

Choose the **PHP CLI** worker in the classroom. The pad is staged as `main.php` and executes as a bounded Linux process, with prepared PHP and PDO SQLite. Write `<?php` at the beginning; a pure PHP file needs no closing tag. Output appears as text. PHP-generated HTML is escaped output here, not automatically injected into a browser. No host PHP installation is required for the Docker route.

The supplied requests, identities, sessions and database fixtures are synthetic local inputs. CLI runs are fresh processes, not persistent HTTP requests. A dictionary that represents a cookie or request is not a real browser cookie. SQLite examples use an in-memory database and do not connect to the classroom PostgreSQL service. Network servers, uploads, mail, Composer downloads and production credentials are outside this pad's contract. Later delivery lessons provide an explicitly separate loopback server lab. A successful function test does not qualify that server integration.

## Worked example / walkthrough

### Worked example 1: Integer minor units

The unit is encoded in the variable name.

```php
$unitCents = 125;
$quantity = 3;
$totalCents = $unitCents * $quantity;
```

**Expected observation:** The total is exactly 375 cents within the integer range.

### Worked example 2: Display without losing the unit

Integer division and remainder produce two decimal digits.

```php
$label = intdiv($totalCents, 100) . '.' . str_pad((string) ($totalCents % 100), 2, '0', STR_PAD_LEFT);
```

**Expected observation:** 375 cents displays as 3.75.

## Six progressive exercises

### Exercise 1: Predict 125 cents times three units.

**Expected evidence:** The result is 375 cents.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Add a fixed 50-cent fee with a named intermediate value.

**Expected evidence:** The new total is 425 cents and the unit remains explicit.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Implement a bounded quantity calculation and cents formatter.

**Expected evidence:** Valid quantities produce exact integer totals and two-digit fractional display.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Diagnose a concatenation expression that hides arithmetic grouping.

**Expected evidence:** Use parentheses or intermediate variables to express the intended computation.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Reject a negative quantity and test zero.

**Expected evidence:** Invalid negative input is rejected; zero follows the declared contract.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Explain when integer cents are insufficient.

**Expected evidence:** Different currency scales, huge ranges, exchange rates or fractional-unit pricing require an explicit broader numeric policy.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

Do not convert a formatted currency label back into a number by deleting random characters. Avoid claiming floating point is universally bad; it is appropriate for many approximate scientific calculations. Define the precision contract first.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

## Retrieval, transfer and next steps

Close the worked answers and explain expression, operator, integer minor units without using their names as definitions. Reconstruct the central example from a blank pad or worksheet. Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation. When a behavior belongs to the browser, observe it in the browser; when it belongs to an HTTP server, keep that evidence separate from a CLI simulation.

Before moving on, keep a short learning record: your prediction, source revision, actual result, explanation and unresolved limitation. Revisit a direct prerequisite if you can reproduce output but cannot explain the mechanism. The path has milestones, not a fixed daily schedule, and a saved completion marker is a personal progress record rather than a professional certification.
