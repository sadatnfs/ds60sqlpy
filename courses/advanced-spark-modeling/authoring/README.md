# Advanced Spark source ownership

The units file owns the 38 stable IDs, direct prerequisites, declared runtime surfaces and each unit's three to five `key_terms`, which the builder renders as a Key terms section after the opening section. Original chapter prose is in chapters/ and complete programs or worked project notebooks are in programs/. Edit those inputs, then run the subject builder. It emits this subject's guides, examples, track, lesson admission and coverage files only; shared HTML, TeX inventories and registry integration belong to the root integration owner.

Every chapter has an explanation, two materially different worked cases, failure diagnosis, answered interview discussion and a concrete next step. Reading/project chapters do not invent a pad execution channel. The public Spark programs use the prepared Spark 4.3.0, Scala 2.13 and JDK 17 contract. The root-owned spark-torch and spark-tmb projects require separate qualification. The Catalyst project is exact-version experimental code, not a stable extension library.

Do not change IDs or other subjects, copy external source without license review, assume pandas/Torch/TMB in the ordinary Spark image, or weaken numerical tests. Preserve learner volumes and project state. No network work happens when a learner opens a chapter.

Each unit also owns a `worked_examples` list. Every entry has exactly `title`, `language` (python, scala, sql, bash, yaml or text), `code`, `interpretation` and an optional `output`. The builder renders each entry as a `## Worked example: <title>` section before Failure diagnosis. It rejects duplicate titles or code anywhere in the track, em and en dashes, triple backticks inside code or output, Python code that does not parse, and an interpretation that is not one paragraph of at least 40 words ending in a period. Only include `output` when it was produced by running the block exactly as written; PySpark, Scala and configuration examples carry no output, and an interpretation must say when pandas, duckdb or numpy stood in for Spark. The builder also fails when a guide has fewer than two fenced code blocks or fewer than 1050 words.
