# go-002: Numeric types, constants and explicit conversions

## Level and prerequisites

## Why this mechanism matters

A type determines which values and operations are valid. int has an implementation-dependent width, while int64 and uint32 declare particular widths. A conversion changes representation; it is not a proof that the original value fits. Untyped numeric constants can retain exact values until context chooses a concrete type. Variables already have concrete types, so mixing integer and floating arithmetic requires an explicit decision. Integer division truncates toward zero. Floating-point values represent a finite set of approximations, and repeated calculations need a tolerance chosen from the domain. Never repair a numerical test with a tolerance large enough to hide a fundamentally wrong algorithm.

## Vocabulary and concepts

- **Concrete type:** The representation and operations attached to a variable.
- **Conversion:** An explicit change to another type.
- **Truncation:** Discarding a fractional component toward zero.

## Syntax anatomy and reasoning

var n int64 fixes the variable's type. float64(n) converts the value; converting after integer division cannot restore a lost fraction. uint8 wraps values during nonconstant conversion modulo its range. A constant that cannot fit its target type is rejected by the compiler. math.Abs gives an absolute difference, and strconv.ParseInt returns both a value and an error when decoding external text.

## Worked example / walkthrough

### Worked example 1: Compare two divisions

Compute 7/2 and float64(7)/2.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Compare two divisions
	{
		a := 7 / 2
		b := float64(7) / 2
		check(a == 3 && b == 3.5, "division")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The results are 3 and 3.5.

Converting before division selects floating arithmetic. float64(7/2) would instead be 3.0 because integer division has already occurred.

### Worked example 2: Expose narrowing

Convert a variable holding 260 to uint8.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Compare two divisions
	{
		a := 7 / 2
		b := float64(7) / 2
		check(a == 3 && b == 3.5, "division")
	}

	// Expose narrowing
	{
		n := 260
		small := uint8(n)
		check(small == 4, "narrowing")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The narrowed value is 4.

The eight-bit unsigned result retains the value modulo 256. A direct constant assignment of 260 to uint8 would be rejected instead of silently accepted.

### Exercise 2: Expose narrowing: debug a regression

**Verify:** Keep the failing and the repaired runs. Explain why the changed token alters the value tested by `small == 4` for this input.

### Exercise 3: Preserve a wide product

Multiply two explicitly int64 values of 50000.

**Expected:** The product is 2500000000.

**Verify:** Keep a check equivalent to `a*b == 2500000000`. As a control, change `check(a*b == 2500000000, "wide product")` to `check(a+b == 2500000000, "wide product")` inside that check: it must panic with `wide product`, which shows the check can fail. Restore it.

### Exercise 4: Check approximate arithmetic

Add floating variables 0.1 and 0.2 and compare with a 1e-15 tolerance.

**Expected:** The absolute difference from 0.3 is below 1e-15.

**Verify:** Keep a check equivalent to `math.Abs((a+b)-0.3) < 1e-15`. As a control, change `check(math.Abs((a+b)-0.3) < 1e-15, "rounding")` to `check(math.Abs((a-b)-0.3) < 1e-15, "rounding")` inside that check: it must panic with `rounding`, which shows the check can fail. Restore it.

### Exercise 5: Reject invalid numeric text

**Expected:** Parsing returns a non-nil error.

**Verify:** Keep a check equivalent to `err != nil`. As a control, change `check(err != nil, "invalid number")` to `check(err == nil, "invalid number")` inside that check: it must panic with `invalid number`, which shows the check can fail. Restore it.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
