C++ from first compilation to complete projects#

Study in the unified classroom: run ./classroom from the repository root, then choose C++ from first compilation to complete projects on /classroom. Python, SQL and all other subjects share this home and workspace. Each subject has its own theme; prerequisites guide your choices and you set the pace. The one-command setup prepares the Docker runtimes and preserves saved work. Native terminal/editor commands below are optional alternatives.

This 42-lesson journey begins with source files, the compiler, the linker and a running process. It develops values and control flow into ownership, standard containers, generic programming, error handling, concurrency and maintainable projects. Every lesson has a guide, a learner worksheet and separate solutions.

Start with cpp-001, then open the course's Journeys page and select the next lesson. The cpp20 Docker worker compiles one C++20 source file with GCC and returns compiler diagnostics, standard output and exit status to the browser. No host C++ installation is required. Use the Docker classroom guide to build and start it.

For multiple source files, headers, CMake, CTest and installed libraries, follow Compile, run and organize a C++ project. Those complete project fixtures use explicit Docker commands and explain which directory is the source, which is the build tree, and which files are generated. The browser pad remains a single-source-file environment.

Read the guide, predict a result, attempt the exercises and request a hint when needed. Inspect compiler messages before changing code. The app saves your pad, notes and job history in its learning volume. Reference programs remain separate and are revealed for comparison; a passing example does not establish mastery.

Validation and limits#

All runnable reference programs have successful local Linux arm64 Docker receipts for their current source bytes. The implementation checkpoint records runtime, test and platform acceptance separately. Reading lessons use reasoning and written evidence. Windows/WSL2 and amd64 configuration support does not by itself establish an observed run on those systems.

Both complete CMake projects and all 76 added worked programs also compiled and ran in the prepared GCC image. New source changes or another toolchain require appropriate new checks. Course fixtures use local authored inputs and do not install dependencies while a lesson runs.
