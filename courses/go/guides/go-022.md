## Why this mechanism matters

HTTP separates method, target, headers, status and body. A handler implements a protocol boundary, not merely a function that returns text. Validate the method and path before applying domain behavior. WriteHeader chooses a response status before the first body write; once a response starts, changing status may be too late. An in-process recorder can test routing and output without opening a socket. This is excellent unit evidence but does not establish real TLS, proxy, timeout or network behavior. Production servers also need bounded request bodies, explicit timeouts, graceful shutdown and safe logging.

## Vocabulary and concepts

- **Handler:** Code implementing the response to one HTTP request.
- **Status code:** A protocol-level classification of the response.
- **Response recorder:** An in-process test object capturing handler output.

## Syntax anatomy and reasoning

http.HandlerFunc adapts a function with ResponseWriter and *Request parameters. httptest.NewRequest creates an inbound request, and httptest.NewRecorder captures status, headers and body. Header().Set changes response metadata before writing. http.Error writes an error response. A handler should return after rejecting a request so it does not accidentally continue into a success path.

## Worked example / walkthrough

### Worked example 1: Serve a health request

Send GET /health to the handler.

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func health(w http.ResponseWriter, r *http.Request) {
	if r.URL.Path != "/health" {
		http.NotFound(w, r)
		return
	}
	if r.Method != "GET" {
		w.Header().Set("Allow", "GET")
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "text/plain; charset=utf-8")
	w.WriteHeader(http.StatusOK)
	fmt.Fprintln(w, "ok")
}

func main() {
	// Serve a health request
	{
		r := httptest.NewRecorder()
		health(r, httptest.NewRequest("GET", "/health", nil))
		check(r.Code == 200 && r.Body.String() == "ok\n", "health")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The status is 200 and the body is ok plus a newline.

The recorder runs the handler directly. This proves the handler contract without making any network availability claim.

### Worked example 2: Reject an unsupported method

Send POST /health.

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func health(w http.ResponseWriter, r *http.Request) {
	if r.URL.Path != "/health" {
		http.NotFound(w, r)
		return
	}
	if r.Method != "GET" {
		w.Header().Set("Allow", "GET")
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "text/plain; charset=utf-8")
	w.WriteHeader(http.StatusOK)
	fmt.Fprintln(w, "ok")
}

func main() {
	// Serve a health request
	{
		r := httptest.NewRecorder()
		health(r, httptest.NewRequest("GET", "/health", nil))
		check(r.Code == 200 && r.Body.String() == "ok\n", "health")
	}

	// Reject an unsupported method
	{
		r := httptest.NewRecorder()
		health(r, httptest.NewRequest("POST", "/health", nil))
		check(r.Code == 405 && r.Header().Get("Allow") == "GET", "method")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The status is 405 and Allow is GET.

The method boundary is explicit. Returning after the error prevents success text from being appended to an already rejected response.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
