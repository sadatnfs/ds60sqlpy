# A nonlinear forecast and uncertainty dossier

Start with: tmb-021, tmb-023, tmb-018.

Outcome: Assemble a reproducible fit, forecast and limitations report for a synthetic panel.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A defensible modeling deliverable is a dossier of linked evidence: the question, observational unit, data identity, model, implementation, optimization diagnostics, uncertainty target, validation and limitations. This capstone combines a nonlinear shared trend with independent latent group intercepts. It builds on the exact Gaussian marginal and derivative checks instead of relying on a large opaque fit.

The model is \(y_{gt}=a e^{-bt}+c+u_g+\epsilon_{gt}\), with independent normal \(u_g\) and observation errors. The original `panel_trend.cpp` integrates the group intercepts using `random="u"`, AD-reports selected same-group predicted means, and retains normalized densities. Given fixed nonlinear trend parameters, its latent integral is Gaussian, so Laplace integration is exact for the latent block. That does not make nonlinear fixed-parameter uncertainty exact.

### Worked case A: reproduce the compiled fit

The prepared project's `tests/acceptance.R` creates four panels across forty time points, fits the model, checks the gradient and requires positive-definite `sdreport` curvature. It also checks derivatives away from the optimum. The deterministic residual fixture is for reproducible numerical acceptance, not a realistic stochastic forecast experiment.

The native acceptance exposed a useful numerical issue: relative-objective stopping left a small but above-threshold absolute gradient in a narrow basin. The API now permits one small Newton refinement only after optimizer success, positive-definite curvature, a bounded relative step, a nonincreasing objective and an improving gradient. It records the original diagnostics. It does not weaken the gradient threshold or change a failed optimizer status into success.

### Worked case B: compare scientific targets

The companion calculates same-group conditional forecasts for two panels, then compares them with the new-group mean. Existing group offsets persist in the conditional mean; a new group's expected offset is zero and its predictive uncertainty includes new group variation. A forecast report must say which target it presents. The current compiled prediction API rejects unknown group IDs rather than silently reusing an existing latent effect.

A larger evaluation would hold out the final time segment, compare with a simple baseline, simulate predictive observations under the full uncertainty policy and record coverage and error by group. Independent per-panel fits answer a different question from a shared-trend fit. Their parameter estimates must not be averaged as a shortcut to the common likelihood.

### Dossier checklist and answered discussion

Record the source checksum, R/TMB/Matrix/compiler/framework/architecture, data schema and seed, exact likelihood, transformed parameter order, starts, objective, gradient, raw optimizer message, any refinement, Hessian diagnostics, forecast horizon and target. Record both successful and failed fits. Separate deterministic fixture agreement, stochastic recovery, browser presentation and actual distributed execution.

**Can this become a forecasting service?** The fixed protocol is a useful boundary, but a service also needs resource limits, model/version rollout, monitoring, state isolation and failure handling. **Can it scale with Spark?** Independent groups or factorized group-marginal contributions can be distributed under the contracts in chapters 16 and 17. Coupled latent states require another algorithm. **What remains uncertain after all checks pass?** Scientific assumptions, extrapolation, real-data calibration and untested deployment conditions. Numerical correctness is necessary and narrower than universal model validity.

Continue to the advanced Spark route for actual partition-level evaluation and the custom PyTorch likelihood route for an independent automatic-differentiation implementation of related objectives.

### Plotting a model without overstating precision

The existing R track teaches base graphics, ggplot2 and Plotly. This project's fitted and forecast tables can feed those tools after their columns are explicitly labeled: observed value, fitted mean, mean interval, predictive interval and horizon. Use different visual marks for training observations and held-out observations, and keep group labels attached after joins. A translucent predictive band should never be drawn from a mean-standard-error column without adding and documenting future process noise.

For a useful diagnostic figure, plot residuals against time and fitted level, then examine within-panel autocorrelation. A shared smooth trend can leave structured residual dependence even when the overall scatterplot looks satisfactory. A second figure should show horizon-specific forecast error and coverage on held-out data. Interactive Plotly presentation helps inspect groups, but interactivity cannot establish calibrated uncertainty or repair data leakage.

### Complete R companion

```r
a <- 3; b <- .6; offset <- 1; future <- c(9, 10, 12)
trend <- a * exp(-b * future) + offset
group_offset <- c(sensor_a = -.4, sensor_b = .4)
forecast <- outer(trend, group_offset, "+")
print(data.frame(time = future, new_group_mean = trend, forecast))
sigma <- .2; tau <- .5
print(c(known_group_noise_sd = sigma, new_group_noise_sd = sqrt(sigma^2 + tau^2)))
stopifnot(all(forecast[, 1] < trend), all(forecast[, 2] > trend), sqrt(sigma^2 + tau^2) > sigma)
```
