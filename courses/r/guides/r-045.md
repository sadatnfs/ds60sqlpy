## Outcome and mechanism

Construct validation procedures whose partitions and preprocessing match the intended transfer claim.

A validation split defines what kind of new information the assessment represents. Randomly splitting rows can be appropriate for some independent-observation questions, but it can leak information when several rows belong to the same person, document family, device or time-linked episode. A new row from a known family is not the same transfer question as a new family.

Keep group identity with the data and enforce the intended separation explicitly. A split can have no duplicate row IDs yet still share all of its source families. Conversely, a group-aware split may be harder because it asks the model to generalize across the units that matter scientifically. Choose the unit from the intended use rather than selecting whichever partition gives the best score.

Preprocessing belongs inside the training portion of each split. A mean, scale, imputation value or feature-selection rule calculated using held-out observations allows assessment data to influence the fitted system. Even when labels are untouched, that information can change the evaluated procedure. Fit the transformation on training rows and apply the retained parameters to validation rows.

Temporal prediction adds an ordering requirement. Features and model choices must use information available by the prediction origin. Random shuffling can move future observations into the training set for an earlier prediction. A rolling-origin evaluation makes those information boundaries visible and can reveal changes in behavior over time.

Cross-validation scores also have an aggregation rule. Unequal folds can be weighted equally or by observation count, and those summaries answer different questions. Retain fold counts and error sums so the chosen summary can be reconstructed. Hyperparameter tuning and final evaluation are separate roles; repeatedly inspecting the final set to choose a method changes the meaning of that final score.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Group-aware split | A partition that keeps all rows from a declared related unit together. |
| Leakage | Information from an assessment target or held-out unit entering the fitted procedure in a way inconsistent with the intended prediction task. |
| Training-only transformation | A preprocessing rule whose estimated parameters are fitted using training rows only. |
| Rolling origin | A temporal evaluation in which each prediction uses only observations available before its origin. |

## Read the syntax

Create train/test indices from stable group IDs or time order, then assert disjointness at the intended unit. Store centering/scaling values before applying them to held-out data. In a fold loop, refit both preprocessing and the estimator inside each training partition. Return error sums and counts rather than only an unlabeled average score.

## Worked examples

### Example 1: Rows can differ while groups leak

```r
d <- data.frame(id = 1:8, group = rep(LETTERS[1:4], each = 2), x = 0:7)
row_train <- c(1, 3, 5, 7)
row_test <- c(2, 4, 6, 8)
stopifnot(length(intersect(d$id[row_train], d$id[row_test])) == 0)
stopifnot(length(intersect(d$group[row_train], d$group[row_test])) == 4)
group_train <- d$group %in% c("A", "B")
stopifnot(length(intersect(d$group[group_train], d$group[!group_train])) == 0)
print(list(row_split_shared_groups = 4, group_split_shared_groups = 0))
```

**Expected observation:** No shared row IDs can coexist with four shared groups; group split has zero shared groups.

The first split has distinct row IDs but shares every family. The second asks a different transfer question by holding out complete families.

### Example 2: Fit preprocessing on the training partition

```r
train <- c(0, 2)
heldout <- c(100, 102)
center <- mean(train)
transformed <- heldout - center
stopifnot(center == 1, identical(transformed, c(99, 101)))
leaked_center <- mean(c(train, heldout))
stopifnot(leaked_center == 51, leaked_center != center)
print(c(training_center = center, leaked_center = leaked_center))
```

**Expected observation:** Training center1; global center51; valid held-out transformed values 99/101.

The transformation parameters are part of the fitted procedure. Including held-out values changes the centering rule even without using labels.

5. Keep every training date earlier than every assessment date.
