llm-017: Shifted batches, padding and token loss#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: llm-016. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Align inputs, targets and ignored padding without changing the evaluation denominator. The central investigation is concrete: Build inputs/labels from fixed token sequences and add ignored padding labels; compare sum/mean cross entropy over active targets. The finish condition is For [2,5,7,3], input=[2,5,7], target=[5,7,3]. Appending ignored targets changes neither the active count of 3 nor the mean loss. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

A batch is storage; the loss must count prediction events#

Neural libraries prefer rectangular arrays, while text sequences often have different lengths. Padding fills the unused storage positions so several examples can share one tensor. Those filler positions are not automatically additional observations. The training objective must retain the distinction between a place in memory and a real target event, or the amount of padding will change both the reported loss and the gradient scale.

Start with the four-token sequence [2,5,7,3]. Shifting it creates three inputs [2,5,7] and targets [5,7,3]. The decoder emits one vocabulary-logit row for each input position. This chapter deliberately uses an eight-token vocabulary and zero logits, so every candidate has probability 1/8. The model's parameters and attention mechanism are irrelevant to this diagnostic: the exact expected loss is known before any training occurs.

The three target events each contribute log(8), giving total 3log(8). The mean over active events is log(8). Append two storage positions with ignored labels and the total should remain 3log(8), while the active count remains three. Dividing by padded width five instead changes the mean to 3*log(8)/5. That is not just misleading reporting. If the resulting scalar is differentiated, every gradient is multiplied by three fifths compared with the intended active-token mean. Two batches with identical real examples but different padding would then receive different effective update scales.

Let z[b,t,v] denote the logit for batch row b, time position t and vocabulary candidate v. The target y[b,t] selects one candidate from that last axis. Flattening the batch and time axes into one event axis gives a matrix [BT,V], paired with BT integer targets. This rearrangement is valid only if both arrays preserve the same event order. It does not mean time has become a class label. Checking a few explicit target/logit-row pairings is a useful defense against a reshape that is legal but semantically wrong.

The ignore value -100 lives in the target array because the loss function has a rule for excluding it. It is not a token ID that may be sent into an embedding table. Nor does ignoring a loss target automatically stop attention from reading an input position. The loss mask controls which predictions are evaluated; an attention mask controls which representations can influence them. Right padding, left padding and position numbering therefore need their own input-side contracts in a complete model.

For one active event, the derivative of summed cross entropy with respect to logits is p minus the one-hot target vector. Under an active-token mean, divide that vector by the active count. At uniform probability 1/8 with three active targets, the target coordinate is -7/24 and each other coordinate is 1/24. The reference uses a summed objective in its masking-gradient probe to inspect zero gradients at ignored positions; it does not silently replace that sum with this mean. The formulas make the reduction choice explicit.

An all-padding batch has no defined active mean. It should trigger a declared rejection or skipped-update policy, not a zero loss interpreted as perfect prediction. PyTorch cross entropy documents the class-index and ignore-index conventions used here.

Vocabulary and concepts#

Active target: A real next-token observation included in the objective.

Ignore index: A sentinel label excluded from loss calculation.

Loss denominator: The count of participating prediction events.

Syntax anatomy and reasoning sequence#

ids[:,:-1] and ids[:,1:] produce shifted input and target tensors. F.cross_entropy expects classes on dimension1, so flatten(batch,time,vocabulary) logits to(-1,vocabulary) and labels to(-1). With ignore_index=-100, ignored targets contribute no loss. reduction='sum' followed by an explicit active count makes the denominator auditable.

Derive the active-token denominator#

The four IDs [2, 5, 7, 3] produce three input/target pairs. Uniform logits over eight classes give each target probability 1/8, so every active token contributes log(8), approximately 2.079442, to negative log likelihood. Total loss over the three targets is 3 log(8). Dividing by three gives the correct token mean. Appending two ignored positions should change neither that numerator nor its active-token denominator.

Dividing the same numerator by padded length five instead gives 3 log(8)/5, approximately 1.247665. That lower number is not a better prediction. It is an accounting change caused by padding. If used for backpropagation, the wrong denominator also rescales the gradient, making the effective update depend on padding density. Comparing losses from batches with different valid-token counts requires consistent weighting rather than an unweighted average of batch means.

Shape and derivative checks#

The model supplies logits [batch, time, vocabulary]. Cross entropy expects the class axis in the position required by its API. Flattening batch and time to [batch*time, vocabulary], with targets flattened in the same row order, preserves the intended event pairing. Treating time as the class dimension can produce a legal tensor call that scores a different problem.

For one active event with softmax probabilities p and target y, the logit derivative of summed cross entropy is p minus the one-hot target vector. Under a mean over three active events, divide that by three. With eight uniform classes, the true-class derivative is -7/24 and each other-class derivative is 1/24. Ignored positions contribute zero gradient under the stated loss masking. An all-ignored batch has no active mean and should be rejected or explicitly skipped under a declared training policy, not reported as successful learning.

The ignore_index value -100 is a label sentinel, not a valid embedding ID. Targets may contain it because the loss handles it; input token IDs must still follow the vocabulary contract. Loss masking also does not automatically create an attention key mask. Right padding may lie beyond valid causal prefixes, while left padding and position IDs require additional care. This fixture proves target accounting and gradient masking, not every padding strategy in a complete decoder.

Worked example / walkthrough#

Example A: Shift the sequence#

The model may see the current input token but not its target at the next position. The diagonal causal mask is consistent with this shifted objective.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

ids=torch.tensor([[2,5,7,3]]); inputs=ids[:,:-1]; targets=ids[:,1:]
assert inputs.tolist()==[[2,5,7]] and targets.tolist()==[[5,7,3]]

Expected: inputs2,5,7 and targets5,7,3.

Example B: Score uniform logits#

Each target has probability one eighth. Target identity does not change the loss under this uniform distribution, which isolates the denominator calculation.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

ids=torch.tensor([[2,5,7,3]]); inputs=ids[:,:-1]; targets=ids[:,1:]
assert inputs.tolist()==[[2,5,7]] and targets.tolist()==[[5,7,3]]
logits=torch.zeros((1,3,8)); loss=F.cross_entropy(logits.reshape(-1,8),targets.reshape(-1))
np.testing.assert_allclose(loss.item(),np.log(8),atol=1e-6,rtol=0)

Expected: mean losslog8 and count3.

Common pitfalls and diagnosis#

Inspect input and target arrays side by side, then count active targets explicitly. The -100 sentinel belongs to the loss labels rather than embedding inputs. Verify the vocabulary axis before flattening, and distinguish target-loss masking from attention visibility. Reject the all-ignored mean instead of interpreting a NaN or fabricated zero as progress.
