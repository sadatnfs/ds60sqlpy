dme-044: Data drift, model quality and delayed labels#

Level: Advanced | Prepared runtime: python-core

Direct prerequisites: dme-014, dme-038, dme-043.

Outcome: Measure a changed input distribution without inferring quality loss automatically.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

A changed input distribution is a question to investigate#

Data drift means an observed distribution differs from a reference distribution under a chosen representation and measure. Model quality concerns how predictions perform against relevant outcomes or decisions. These quantities are related, but they are not interchangeable. A route mix can change while a model performs equally well in every route. Quality can also decline without a large shift in the monitored input fields, for example when the relationship between features and outcomes changes.

It helps to distinguish changes in P(X)P(X)P(X), the feature distribution, from changes in P(Y∣X)P(Y\mid X)P(Y∣X), the conditional outcome relationship. A shift in the class prevalence P(Y)P(Y)P(Y) is another useful observation, though these changes need not occur independently. The terminology organizes investigation; it does not identify a cause automatically. Instrumentation changes, missing data, new populations and altered business behavior can produce similar monitoring signals.

This chapter uses deterministic synthetic observations to separate those concepts. It does not train a model or claim that one drift threshold detects every failure. The earlier evaluation chapters provide actual fitted models and temporal validation. Here the goal is to make production monitoring populations, observation times and missing-label coverage precise enough that a real model-quality report can be trusted.

The measure lies between zero and one for normalized distributions. Zero means the represented categorical distributions match; it does not mean every unmonitored field or relationship is unchanged.

The implementation uses actual category counts and separate denominators for the reference and current populations. It rejects empty populations because no empirical distribution can be formed from them. Unknown categories are included through the union of keys rather than silently discarded. For continuous features, a monitoring design would need another representation or measure, with explicit binning, tails and missingness behavior. A result can depend strongly on those choices.

These are deliberately constructed synthetic observations, not outputs from a fitted classifier. They form a counterexample to the claim that a large input-distribution change necessarily proves quality loss.

The example does not claim drift is harmless. A changed mix can alter business cost, fairness, capacity, calibration or performance in a small subgroup even when aggregate accuracy stays constant. It tells us that input shift alone cannot settle those questions. Investigate affected cohorts, confidence intervals, label availability and the decision metric before choosing remediation. Retraining automatically on every drift alert can introduce new problems if the current labels are biased or incomplete.

Evaluation requires a matured population#

Many outcomes arrive after a prediction. A shipment-delay label may require waiting until a deadline; a churn label may require an observation period. At evaluation cutoff ccc, a prediction made at time ttt is mature under horizon hhh when t+h≤ct+h\leq ct+h≤c. The label must also have been available by ccc. These are different conditions. An early positive outcome may be known before the full horizon, while a mature prediction can still lack a label because ingestion is delayed.

A missing label is not automatically a negative outcome. An inner join that drops missing labels can conceal this limitation by shrinking the denominator before anyone sees it.

Worked case 2: separate maturity from availability#

example_two() creates ten predictions made on days one through ten, all with probability 0.8. The evaluation cutoff is day ten and the outcome horizon is three days. Predictions from days one through seven are mature. Six have labels known by the cutoff; the day-seven label will not be known until day twelve and therefore remains missing at evaluation time.

Among the six observed mature labels, five are correct under the 0.5 decision threshold. Observed-subset accuracy is 5/65/65/6, approximately 0.8333, while coverage is 6/76/76/7, approximately 0.8571. The result table retains all seven eligible predictions and shows an explicit missing value for day seven. This makes the population limitation visible rather than disguising it as a complete score.

A label for the day-eight prediction is already known on day nine, but that prediction has not completed the declared horizon at cutoff ten. The strict matured-cohort policy excludes it. A naive calculation using every currently available label includes this convenient early result and reports 6/76/76/7 accuracy instead. That number answers a different population question. The code prints both calculations and names the immature known and mature unknown records.

Complete worked program#

Use Python Core. The calculation uses bounded synthetic observations and publishes an eligible-population table plus a distribution-shift report. No monitoring endpoint or private labels are accessed.

"""Distribution change and matured-label evaluation are different observed quantities."""

from collections import Counter


def total_variation(reference, current):
    if not reference or not current:
        raise ValueError("Compare two nonempty observed populations")
    before, after = Counter(reference), Counter(current)
    return 0.5 * sum(
        abs(before[key] / len(reference) - after[key] / len(current))
        for key in before.keys() | after.keys()
    )


def evaluate(predictions, labels, cutoff, horizon):
    if type(horizon) is not int or horizon < 1:
        raise ValueError("Use a positive declared outcome horizon")
    if len({row["id"] for row in predictions}) != len(predictions) or len(
        {row["id"] for row in labels}
    ) != len(labels):
        raise ValueError("Evaluation requires unique prediction and label identities")
    available = {row["id"]: row for row in labels if row["known_day"] <= cutoff}
    eligible = [row for row in predictions if row["decision_day"] + horizon <= cutoff]
    joined = [
        {**row, "outcome": available[row["id"]]["outcome"] if row["id"] in available else None}
        for row in eligible
    ]
    observed = [row for row in joined if row["outcome"] is not None]
    correct = sum((row["probability"] >= 0.5) == row["outcome"] for row in observed)
    return {
        "eligible": len(eligible),
        "labelled": len(observed),
        "missing": len(joined) - len(observed),
        "coverage": len(observed) / len(eligible) if eligible else None,
        "accuracy_observed": correct / len(observed) if observed else None,
        "population": joined,
    }


def example_one():
    reference = ["north"] * 50 + ["south"] * 50
    current = ["north"] * 90 + ["south"] * 10
    drift = total_variation(reference, current)
    assert abs(drift - 0.4) < 1e-12
    before_correct = [True] * 90 + [False] * 10
    after_correct = [True] * 90 + [False] * 10
    assert (
        sum(before_correct) / len(before_correct) == sum(after_correct) / len(after_correct) == 0.9
    )
    return {
        "categorical_total_variation": drift,
        "reference_accuracy": 0.9,
        "current_accuracy": 0.9,
        "input_change_alone_does_not_prove_quality_loss": True,
        "labels_are_synthetic_observations_not_a_guarantee_about_future_data": True,
    }


def example_two():
    predictions = [
        {"id": str(day), "decision_day": day, "probability": 0.8} for day in range(1, 11)
    ]
    labels = [{"id": str(day), "known_day": day + 2, "outcome": day != 3} for day in range(1, 7)]
    labels += [
        {"id": "7", "known_day": 12, "outcome": False},
        {"id": "8", "known_day": 9, "outcome": True},
    ]
    result = evaluate(predictions, labels, cutoff=10, horizon=3)
    assert result["eligible"] == 7 and result["labelled"] == 6 and result["missing"] == 1
    assert result["coverage"] == 6 / 7 and result["accuracy_observed"] == 5 / 6
    assert result["population"][-1]["outcome"] is None
    naive = [row for row in labels if row["known_day"] <= 10]
    assert sum(row["outcome"] for row in naive) / len(naive) == 6 / 7
    return {
        "matured_cohort": result,
        "naive_available_label_accuracy": 6 / 7,
        "immature_known_label_excluded": "8",
        "late_unknown_label_retained_as_missing": "7",
    }


def main():
    from ds60sqlpy.plot_artifacts import publish_report, publish_table

    first, second = example_one(), example_two()
    print("Input shift without observed quality loss:", first)
    print("Maturity and missing labels define the evaluation population:", second)
    publish_table(
        ["id", "decision_day", "probability", "outcome"],
        [
            [row[name] for name in ["id", "decision_day", "probability", "outcome"]]
            for row in second["matured_cohort"]["population"]
        ],
        description=(
            "Seven eligible matured predictions retain six known labels and "
            "one explicit missing label; an immature known label is excluded."
        ),
    )
    publish_report(
        first,
        description=(
            "A controlled categorical shift of 0.4 accompanies unchanged "
            "observed accuracy of 0.9; drift is not itself a quality verdict."
        ),
    )


if __name__ == "__main__":
    main()

What to monitor beyond one drift score#

Monitor schema violations, missingness, value ranges, unknown categories, population size and feature availability before interpreting a statistical distance. A sudden shift caused by a unit conversion is a data-contract incident. A change caused by a new supported region may be expected but still require cohort evaluation. Compare the same field definitions and sampling rules across periods; a changed logging policy can manufacture apparent drift.

Model monitoring should also preserve model version, feature definitions, decision thresholds and outcome definitions. Comparing accuracy across a threshold change or a new label definition without recording that change is not a clean temporal comparison. Include uncertainty when sample sizes are small, and avoid treating repeated noisy checks as independent evidence. The statistics and experimentation books develop these inferential issues in more depth.

For regression, ranking or probabilistic forecasts, choose metrics matching the decision and inspect more than one aggregate. Calibration, residual structure, tail errors and group coverage can reveal failures hidden by average performance. A monitoring dashboard should help localize a problem, while the response procedure decides whether to investigate ingestion, change a threshold, roll back or retrain under reviewed evidence.

Failure diagnosis and answered interview discussion#

If accuracy improves while label coverage falls, inspect which records lost labels. If an immature cohort looks excellent, inspect early-outcome selection. If a drift alert fires after a logging deployment, compare instrumentation before assuming user behavior changed. If a model version appears to degrade only in one report, verify that feature and label cutoffs match the report's intended decision time.

An interviewer may ask, “Should drift trigger retraining?” Explain that it triggers investigation, and retraining requires suitable labels, evaluation and an acceptance decision. If asked how to evaluate delayed outcomes, define the matured population, label-availability cutoff and missing-label coverage before computing metrics. If asked whether missing labels can be treated as zero, explain the observation process and why that assumption needs evidence rather than convenience.

For an answered extension, at cutoff twelve the day-seven label becomes available and additional predictions mature. Recompute the eligible population and coverage under the new cutoff; do not simply append one label to yesterday's denominator. A report should name its observation cutoff so later updates can be interpreted as new evidence rather than unexplained changes to history.
