## Learning objectives

The central investigation is concrete: Use all four XOR inputs; compare an affine threshold with h1=ReLU(x1-x2), h2=ReLU(x2-x1), \(\mathrm{output}=h_{1}+h_{2}\) before optional fitting. The finish condition is The nonlinear construction produces labels [0,1,1,0] for [(0,0),(0,1),(1,0),(1,1)]; no affine separator can satisfy all four inequalities. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

Stacking affine layers without an intervening nonlinearity still produces an affine function. XOR asks for opposite labels at the diagonally opposite corners of a square, a pattern one affine threshold cannot separate. Two rectified differences create the needed representation: \(h_{1}=\max(x_{1}-x_{2},0)\), \(h_{2}=\max(x_{2}-x_{1},0)\). Their sum is one exactly when the inputs differ. This hand-built network separates representational capacity from optimization. If the construction works but a fitted model does not, the architecture may be capable while the training procedure failed. Initialization changes the starting state and symmetry of fitting; it cannot repair an architecture that lacks the required function.

## Vocabulary and concepts

**Nonlinearity:** A transformation that cannot be represented by a single affine map.

**ReLU:** The rectified linear function max(z,0).

**Capacity:** The set of functions a model architecture can represent.

## Syntax anatomy and reasoning sequence

A Dense transform computes X@W. The chosen columns of W form x1-x2 and x2-x1. ReLU applies max(z,0) independently, then reduce_sum combines the hidden units. Before fitting, evaluate all four binary inputs. The affine contradiction comes from summing inequalities at the two positive and two negative corners, so it does not depend on testing many random initializations.

## Derive why a hidden nonlinearity matters

Two affine layers without an intervening nonlinearity remain affine:
(XW_1+b_1)W_2+b_2 equals X(W_1W_2)+(b_1W_2+b_2). More such layers do not by themselves
create the curved decision regions that motivate a nonlinear network.
They can still change parameterization and optimization, so equivalence of
the represented function class does not make every training trajectory equal.

The supplied XOR construction uses two ReLU branches. One keeps the positive
part of x_1-x_2; the other keeps the positive part of x_2-x_1. Their sum is the
absolute difference. At the four Boolean corners it equals the XOR labels,
but at (0.2, 0.8) it is 0.6. That extension is determined by the learned or
constructed function, not by the name XOR. Correct corner predictions do not
tell you how an arbitrary network behaves between or beyond those corners.

Initialization also controls whether hidden units can develop different
roles. Identically initialized units receiving identical gradients stay
symmetric under the same deterministic update. Appropriate random variation
breaks that symmetry; its scale matters because excessively large or small
activations can make optimization unstable or uninformative.

For a negative ReLU input the local derivative is zero; for a positive input
it is one. The boundary at exactly zero needs an implementation convention.
Do not confuse a local zero gradient in a closed region with proof that the
whole model has converged. Trace preactivations, active regions and upstream
gradient paths before changing learning rates.

## Worked example / walkthrough

### Example A: Construct XOR

The hidden features encode the two possible directions of disagreement. Their values are never simultaneously positive on the binary fixture, so their sum behaves like XOR.

```python
import numpy as np
import tensorflow as tf

x=tf.constant([[0.,0.],[0.,1.],[1.,0.],[1.,1.]])
w=tf.constant([[1.,-1.],[-1.,1.]])
h=tf.nn.relu(x@w); output=tf.reduce_sum(h,axis=1)
np.testing.assert_array_equal(output.numpy(),[0,1,1,0])
```

**Expected:** outputs[0,1,1,0].

### Example B: Remove the nonlinearity

The columns cancel exactly. The ReLU was the step that prevented the positive and negative differences from cancelling, rather than merely adding an extra layer name.

```python
import numpy as np
import tensorflow as tf

x=tf.constant([[0.,0.],[0.,1.],[1.,0.],[1.,1.]])
w=tf.constant([[1.,-1.],[-1.,1.]])
h=tf.nn.relu(x@w); output=tf.reduce_sum(h,axis=1)
np.testing.assert_array_equal(output.numpy(),[0,1,1,0])
np.testing.assert_array_equal(tf.reduce_sum(x@w,axis=1).numpy(),[0,0,0,0])
```

**Expected:** all four sums0.

## Common pitfalls and diagnosis

If a deeper model behaves like one linear map, check whether its
nonlinearity was omitted. If hidden columns remain identical, inspect their
initial values and gradients. If a ReLU branch never updates, inspect its
preactivation distribution and connectivity. Do not infer a probability
interpretation merely because the XOR corner outputs are zeros and ones.
