  <behavior>
    - Policy validation (`-k policy`): rejects unknown or missing keys, `schema` other than 1, `*` or empty values anywhere, `expires_at` before today (expired), `expires_at` more than 90 days after `reviewed_at`, `reviewed_at` in the future, empty justification, empty reviewer, unknown profile in `images`, duplicate (id, package, image) triples.     - Unresolved rule (`-k unresolved`): unfixed CRITICAL and HIGH block with reason `unaccepted`; a matching live entry moves them to `suppressed` with the entry's `expires_at`; unfixed MEDIUM, LOW and UNKNOWN go to `reported`.
    - Fixed-version rule (`-k fixed_version`): an entry matching a finding that now has a FixedVersion does not suppress it; the finding blocks as `fixable`.
    - Coverage rule (`-k coverage`): a report whose OS family/version Trivy flags as unsupported (for example `Metadata.OS.Name` `forky/sid`, or an OS result with no `Vulnerabilities` key and an unknown EOL status), or a report with zero detected packages, blocks with reason `coverage` unless a `coverage` entry covers that profile.
    - Secret and misconfig (`-k secret`): any secret finding blocks; a misconfig `FAIL` with HIGH or CRITICAL severity blocks unless a `misconfig` entry covers it; lower misconfig failures are reported.
    - Freshness (`-k freshness`): a DB `UpdatedAt` older than 24 hours at scan time blocks every image with reason `stale-db`.
    - Revision (`-k revision`): with `--tested`, a non-empty `org.opencontainers.image.revision` label that differs from the snapshot context revision fails the scan.
    - Reference image (`-k reference`): for the `postgres` reference class only fixable CRITICAL/HIGH block; fixable MEDIUM/LOW and all unfixed findings are reported.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scanner container to host Docker daemon | Trivy reads images through the mounted socket |
| Policy file to gate decision | A committed JSON file can suppress findings |
| Trivy JSON to DS60 decision | Scanner output is parsed and trusted for the verdict |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `TRIVY_IMAGE` constant | high | mitigate | Digest pin, upstream digest and release-date check in Task 3, no `aquasecurity/*` actions |
| T-08-02 | Elevation of Privilege | docker socket mount | medium | mitigate | Socket mounted `:ro`, no registry credentials in the environment, cache path refused inside repo |
| T-08-03 | Repudiation | `docker/cve-policy.json` | high | mitigate | Exact per-finding entries, reviewer field, 90-day max expiry, expired entries fail, fixable findings cannot be accepted |
| T-08-04 | Spoofing | evidence binding | medium | mitigate | Scan by immutable `tested_image_id`, record revision label and report sha256 |
| T-08-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; scanner is a digest-pinned container image |
</threat_model>
