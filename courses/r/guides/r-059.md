## Outcome and mechanism

Translate a supported ggplot to Plotly and verify retained data while identifying the visual and interaction properties that still require review.

ggplotly translates a ggplot object into a Plotly figure. The source graphic and the interactive result use different representations and rendering systems. A successful conversion is therefore a useful starting point, not a guarantee that every geometry, label, facet, scale or theme behaves identically.

One source layer can become several traces, for example when a group mapping separates categories or when an uncertainty region needs additional geometry. Conversely, a simple layer count is not a reliable measure of the amount of data represented after translation. Validate the quantities and group identities that matter to the task rather than assuming a one-to-one layer-to-trace mapping.

The supported scatter fixture below makes coordinate preservation inspectable. Collect the marker-trace coordinates and compare them with the original observations. This checks the data payload, while legend layout, tooltip wording, text clipping and actual interaction remain browser observations. A conversion can retain every coordinate yet still communicate the wrong quantity through a misleading label.

Tooltip selection is part of the user-facing contract. Choose fields that identify the point and its units without adding irrelevant implementation details. If the task needs precise custom interaction, stable metadata or specialized controls that are awkward to translate, constructing Plotly traces directly can be clearer than repeatedly patching an automatic conversion.

Retain the original ggplot as a static baseline and record package versions with the comparison. The prepared ggplot2 and Plotly versions have been checked for these small examples, but that does not qualify every extension geometry or future version. Actual visual parity must be reviewed at the delivered dimensions, with a static alternative for essential information.

## Worked examples

### Example 1: Retain scatter coordinates across translation

```r
d <- data.frame(x = 1:4, y = c(1, 3, 2, 6), group = c("A", "A", "B", "B"))
p <- ggplot2::ggplot(d, ggplot2::aes(x, y, colour = group)) +
  ggplot2::geom_point(size = 3) +
  ggplot2::labs(x = "Input", y = "Response", colour = "Group")
interactive <- plotly::ggplotly(p, tooltip = c("x", "y", "group"))
traces <- Filter(function(trace) identical(trace$type, "scatter") && isTRUE(grepl("markers", trace$mode)), plotly::plotly_build(interactive)$x$data)
xs <- unlist(lapply(traces, function(trace) as.numeric(trace$x)), use.names = FALSE)
ys <- unlist(lapply(traces, function(trace) as.numeric(trace$y)), use.names = FALSE)
stopifnot(length(xs) == 4, max(abs(sort(xs) - sort(d$x))) < 1e-12, max(abs(sort(ys) - sort(d$y))) < 1e-12)
print(p)
print(interactive)
```

**Expected observation:** Four retained source observations, one static figure and one converted figure.

The checks confirm the four source x and y values in the marker payload. A stronger production comparison should also retain paired identities; separate sorted-coordinate checks alone would not detect every permutation bug.

### Example 2: A reference line becomes additional geometry

```r
d <- data.frame(x = 1:4, y = c(1, 3, 2, 6))
p <- ggplot2::ggplot(d, ggplot2::aes(x, y)) +
  ggplot2::geom_point() +
  ggplot2::geom_hline(yintercept = mean(d$y), linetype = "dashed") +
  ggplot2::labs(x = "Input", y = "Response")
interactive <- plotly::ggplotly(p, tooltip = c("x", "y"))
traces <- plotly::plotly_build(interactive)$x$data
stopifnot(length(traces) >= 2)
marker_count <- sum(vapply(traces, function(trace) if (isTRUE(grepl("markers", trace$mode))) length(trace$x) else 0L, integer(1)))
stopifnot(marker_count == 4)
print(interactive)
```

**Expected observation:** Four marker observations plus reference-line geometry.

The converted figure contains both the observations and additional line geometry. A raw trace count is not the same as the number of observations or source layers.
