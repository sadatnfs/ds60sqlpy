dme-049: Capstone: a validated local data product#

Level: Advanced | Prepared runtime: data-engineering

Direct prerequisites: dme-016, dme-018, dme-025, dme-027, dme-031.

Outcome: Connect ingestion, quarantine, real analytical transformation and an accepted publication manifest.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

Connect the boundaries into one accepted answer#

A data product is more than the final SQL query. It has a source contract, validation, transformation, publication identity and consumer readback. The preceding chapters isolated these mechanisms so their assumptions were visible. This capstone connects them: an actual CSV delivery is parsed with Polars, checked at a declared grain, aggregated through DuckDB, written to Parquet and exposed through an accepted pointer only after reconciliation.

The ordinary pad uses owned temporary files and a single publisher. It does not start an HTTP service or preserve state across classroom runs. The separate data-product project provides the complete owned Docker lifecycle, real HTTP ingestion, durable state and process-failure recovery. This program supplies a compact executable reference for the data path and its acceptance rules, which can be compared with the larger project's observations.

The source contains delivery identity, route and positive integer package count. Routes 10 and 20 are known, mapping to north and south. The input declaration includes the expected row population. The accepted output has one row per route and region. The central reconciliation is

with every source delivery belonging to exactly one known route and with unique delivery identities. The total check is necessary but not sufficient; schema, population, key uniqueness and exact result rows are also checked.

Follow the actual data path#

Polars initially reads CSV fields as strings. That keeps conversion policy explicit rather than relying on a sample to infer types. Route and package fields are then cast to integer with invalid conversions represented as null for quality inspection. The valid-row expression requires a bounded identifier pattern, a known route and a positive package count. Null results are treated as invalid. Duplicate delivery identities are a separate whole-dataset failure.

The program records an attempt decision containing the exact input hash, row count, rejected rows and duplicate flag. It withholds publication if any row violates this complete-delivery contract. This is deliberately stricter than publishing a valid subset. Another product could support partial publication, but it would need a visible partial status and a downstream interpretation. Here the consumer promise is a complete declared delivery, so partial acceptance would be misleading.

For an accepted candidate, DuckDB receives the checked Arrow table and joins it with a primary-keyed route dimension. The query groups at the declared route-region grain and returns an Arrow table through the prepared DuckDB API. Arrow writes actual Parquet bytes. The code reads those bytes back and compares the rows before writing a manifest and moving the accepted pointer. Parsing, query execution, serialization and publication are all exercised, not represented by placeholder dictionaries.

Worked case 1: publish and replay a complete delivery#

example_one() supplies A with two packages on route 10, B with three on route 10 and C with one on route 20. The independent expected output is north: five and south: one. The accepted manifest records three input rows, two output rows and six packages, along with input, source-code and Parquet content identities.

The version identity binds the exact source CSV and implementation bytes. Repeating the same publication verifies the existing version and returns a replay result without rewriting its Parquet file. This is useful when a caller repeats a known completed operation. A changed input or source implementation receives a different version identity. Identical logical rows serialized with different source bytes can therefore form a different recorded version, which is conservative but explainable provenance.

The current reader resolves the accepted version, verifies the Parquet digest and reconciles its row count and total with the manifest. A pointer file alone is not enough: the referenced data must still satisfy the accepted content contract. The result table exposes the actual grouped rows so a learner can inspect both identities and totals rather than relying only on a success message.

Worked case 2: a quality failure preserves the previous publication#

The second case first publishes the valid six-package product. It then appends delivery D with four packages on unknown route 99 and declares a four-row delivery. Parsing succeeds and the declared row count matches, but the route contract fails. The candidate decision contains one quarantined row and accepted: false.

The accepted pointer remains byte-for-byte unchanged, and reading the current product still returns north five and south one. Two attempt records exist: the successful source and the rejected source. This preserves diagnostic evidence without exposing an incomplete or invalid new answer as current. A pipeline that simply drops the unknown-route row and publishes the remaining six packages would conceal the fact that a declared four-row delivery was not fully represented.

The failure also shows why aggregate equality alone is weak. The retained old total is six, and a silently filtered candidate could also total six, but those values have different provenance and completeness. The accepted state must identify which source population it represents. An operator can then correct the route mapping or source data and submit a new reviewed candidate rather than treating the rejection as a transient query error.

Complete worked program#

Use data-engineering. The program runs actual Polars, DuckDB and Parquet operations, captures a table and decision report, and creates no network listener. Its temporary state is intentionally separate from the persistent Docker project.

"""Actual CSV validation, Polars/DuckDB transformation, Parquet and accepted publication."""

import hashlib
import json
import tempfile
from pathlib import Path

import duckdb
import polars as pl
import pyarrow.parquet as pq


def digest(path):
    return hashlib.sha256(path.read_bytes()).hexdigest()


def read_version(root, version):
    if len(version) != 64 or any(character not in "0123456789abcdef" for character in version):
        raise ValueError("Invalid accepted version identity")
    directory = root / "versions" / version
    manifest = json.loads((directory / "manifest.json").read_text())
    path = directory / "summary.parquet"
    if digest(path) != manifest["data_sha256"]:
        raise ValueError("Accepted Parquet content changed")
    rows = pq.read_table(path).to_pylist()
    if (
        len(rows) != manifest["output_rows"]
        or sum(row["packages"] for row in rows) != manifest["packages"]
    ):
        raise ValueError("Accepted product reconciliation failed")
    return {"version": version, "rows": rows, "manifest": manifest}


def current(root):
    pointer = json.loads((root / "current.json").read_text())
    return read_version(root, pointer["version"])


def publish(root, source, expected_rows):
    if type(expected_rows) is not int or not 0 <= expected_rows <= 100:
        raise ValueError("Declare a bounded complete source population")
    root.mkdir(exist_ok=True)
    if source.stat().st_size > 10_000:
        raise ValueError("Source fixture exceeds its byte budget")
    frame = pl.read_csv(source, infer_schema=False)
    if set(frame.columns) != {"delivery_id", "route", "packages"} or frame.height != expected_rows:
        raise ValueError("Complete delivery schema or population differs from its declaration")
    checked = frame.with_columns(
        pl.col("route").cast(pl.Int64, strict=False),
        pl.col("packages").cast(pl.Int64, strict=False),
    )
    valid = (
        pl.col("delivery_id").str.contains(r"^[A-Za-z0-9_-]{1,30}$")
        & pl.col("route").is_in([10, 20])
        & (pl.col("packages") > 0)
    ).fill_null(False)
    quarantined = checked.filter(~valid).to_dicts()
    duplicated = checked.select(pl.col("delivery_id").n_unique()).item() != checked.height
    source_sha = digest(source)
    decision = {
        "input_sha256": source_sha,
        "input_rows": frame.height,
        "quarantine_rows": len(quarantined),
        "quarantine": quarantined,
        "duplicated_identity": duplicated,
        "accepted": not quarantined and not duplicated,
    }
    (root / "attempts").mkdir(exist_ok=True)
    (root / "attempts" / (source_sha + ".json")).write_text(json.dumps(decision, sort_keys=True))
    if not decision["accepted"]:
        return decision
    source_code_sha = digest(Path(__file__))
    version = hashlib.sha256((source_sha + source_code_sha).encode()).hexdigest()
    directory = root / "versions" / version
    if directory.exists():
        prior = read_version(root, version)
        if (
            prior["manifest"]["input_sha256"] != source_sha
            or prior["manifest"]["source_sha256"] != source_code_sha
            or prior["manifest"]["input_rows"] != expected_rows
        ):
            raise ValueError("An existing version has inconsistent provenance")
        if current(root)["version"] != version:
            raise ValueError("An older prepared version needs an explicit activation decision")
        return {**decision, "version": version, "rows": prior["rows"], "replayed": True}
    directory.mkdir(parents=True, exist_ok=False)
    with duckdb.connect(":memory:") as connection:
        connection.register("deliveries", checked.to_arrow())
        connection.execute("create table routes(route integer primary key,region varchar)")
        connection.executemany("insert into routes values(?,?)", [(10, "north"), (20, "south")])
        result = connection.sql(
            "select d.route,r.region,sum(d.packages)::BIGINT packages "
            "from deliveries d join routes r using(route) "
            "group by d.route,r.region order by d.route"
        ).to_arrow_table()
    rows = result.to_pylist()
    total = int(checked["packages"].sum())
    if sum(row["packages"] for row in rows) != total:
        raise ValueError("Transformation failed the input-to-output total reconciliation")
    path = directory / "summary.parquet"
    pq.write_table(result, path)
    manifest = {
        "schema_version": 1,
        "input_sha256": source_sha,
        "source_sha256": source_code_sha,
        "data_sha256": digest(path),
        "input_rows": frame.height,
        "output_rows": len(rows),
        "packages": total,
    }
    (directory / "manifest.json").write_text(json.dumps(manifest, sort_keys=True))
    if pq.read_table(path).to_pylist() != rows:
        raise ValueError("Written Parquet differs from the reviewed candidate")
    pending = root / "current.pending"
    pending.write_text(json.dumps({"version": version}))
    pending.replace(root / "current.json")
    accepted = current(root)
    return {**decision, "version": version, "rows": accepted["rows"]}


def fixture(path):
    path.write_text("delivery_id,route,packages\nA,10,2\nB,10,3\nC,20,1\n")


def example_one():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        source = root / "input.csv"
        fixture(source)
        result = publish(root / "product", source, 3)
        assert result["rows"] == [
            {"route": 10, "region": "north", "packages": 5},
            {"route": 20, "region": "south", "packages": 1},
        ]
        assert current(root / "product")["manifest"]["input_rows"] == 3
        assert publish(root / "product", source, 3)["replayed"] is True
        return result


def example_two():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        source = root / "input.csv"
        fixture(source)
        product = root / "product"
        first = publish(product, source, 3)
        before = (product / "current.json").read_bytes()
        source.write_text(source.read_text() + "D,99,4\n")
        rejected = publish(product, source, 4)
        assert rejected["accepted"] is False and rejected["quarantine_rows"] == 1
        assert (product / "current.json").read_bytes() == before
        assert current(product)["rows"] == first["rows"]
        assert len(list((product / "attempts").glob("*.json"))) == 2
        return {
            "rejected_candidate": rejected,
            "accepted_version_retained": first["version"],
            "prior_total": 6,
            "persistent_http_service_is_a_separate_project": True,
        }


def main():
    from ds60sqlpy.plot_artifacts import publish_report, publish_table

    first, second = example_one(), example_two()
    print("Actual complete data product:", first)
    print("Quality failure preserves the accepted publication:", second)
    publish_table(
        ["route", "region", "packages"],
        [[row["route"], row["region"], row["packages"]] for row in first["rows"]],
        description=(
            "Actual CSV to Polars to DuckDB to Parquet publication reconciles "
            "north five and south one packages."
        ),
    )
    publish_report(
        second,
        description=(
            "A source-bound invalid-route candidate is rejected while the "
            "earlier accepted six-package product remains available."
        ),
    )


if __name__ == "__main__":
    main()

What belongs to the persistent project#

A persistent service needs more than this single-run path. It must identify complete source snapshots, accept or reject repeated HTTP deliveries, preserve an ingest ledger, coordinate publication generations and recover uncertain outcomes without replaying an already accepted effect. It also needs an explicit start, stop, resume, replacement and cleanup contract that protects owned state.

The maintained data-product project adds those boundaries using the prepared native Docker image. Its documentation and checker distinguish preparation from startup, retain state outside replaceable containers and exercise actual process exits around pointer publication. Use its own commands and ownership marker rather than adapting this temporary pad into an unbounded background server. The two surfaces share conceptual contracts but have different lifetimes and evidence.

This capstone's atomic local pointer replacement assumes one publisher and the owned filesystem. It is not a remote object-store compare-and-swap operation. It also refuses an older prepared version when it is no longer current rather than silently rolling the product backward. An explicit rollback belongs to a separate reviewed decision, as demonstrated by the full project and later recovery drill.

Review the acceptance chain#

Inspect source identity first: which exact delivery and implementation produced the candidate? Inspect validation next: were rows complete, uniquely identified, typed and mapped? Inspect transformation: did join cardinality and aggregate grain preserve the intended population? Inspect serialization: did the written Parquet read back as expected? Inspect publication: did the accepted pointer change only after those checks? Finally inspect current readback rather than assuming a recorded success still matches the files.

A failure at any stage should retain the earlier accepted product when possible. An incomplete candidate directory is not automatically safe to publish on retry. It needs validation and recovery reasoning. Conversely, a completed matching version can be reused instead of recomputed. The distinction between incomplete preparation, accepted publication and replay drives reliable resume behavior.

Applications and answered interview discussion#

This pattern applies to daily operational aggregates, governed analytical exports and feature snapshots. It keeps the producer's completeness promise visible to consumers and supports reproducible investigation when a result changes. The small fixture is deliberately easy to recompute by hand; a real dataset needs representative tests and scale qualification in addition to the same invariants.

An interviewer may ask, “What makes this a data product rather than a script?” Explain the explicit contract, acceptance boundary, versioned output, diagnostics and consumer behavior. If asked why invalid rows block publication, explain the declared complete-population promise and how a partial policy would need to differ. If asked whether a matching total proves correctness, show the unknown-route case and the need for identity and coverage checks.

For an answered extension, duplicate delivery A under another row. Even if every field parses and the route is known, the unique-delivery grain fails. A duplicate should not become an extra business event merely because it appears twice in the source file. Correct the source or define an explicit event/version interpretation before aggregation.
