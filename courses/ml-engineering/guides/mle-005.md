# mle-005: Validation that matches deployment and time

## Level and prerequisites

Beginner. Direct prerequisites: `mle-002`, `mle-004`

**Outcome:** Design evaluation around the target population and information boundary.

## Question and mechanism

An evaluation split defines which generalization question is being tested. Repeated observations from known entities differ from predictions for unseen entities. A random row split can place the same entity on both sides and make memorization appear useful for a cold-start deployment. The first case demonstrates that mechanism transparently rather than hiding it inside a complicated estimator.

Time adds another boundary. A future evaluation should not use training decisions or labels that were unavailable at the training cutoff. The second case selects mature training rows and later test decisions, then checks identity and clock separation. This is a deployment scenario for returning entities; it is not automatically a test of unseen-customer generalization.

Choose the split before using outcomes to select a model. Keep a validation set for choices such as thresholds or hyperparameters and an appropriately protected evaluation set for the final claim. Repeatedly inspecting a holdout can turn it into part of the selection procedure even if no gradient was computed on it.

## Syntax and data contract

The memorizer is an explicit mapping from entity to observed label, with a declared fallback for unknown entities. The time split uses cutoff and label_available_at separately. Verify identifier overlap, entity overlap and temporal eligibility according to the intended deployment scenario; no single split recipe answers every question.

## Worked case 1: Separate repeat-entity and cold-start questions

The mapping predicts repeated entities perfectly because their labels are already known. On two held-out entities with different labels, its fixed fallback is only half correct. The contrast exposes what the first score actually measured.

**Expected evidence:** Repeated-entity accuracy is 1.0; the chosen unseen-entity case is 0.5.

```python
import numpy as np


def example_one():
    customers = np.arange(6)
    labels = np.array([0, 0, 0, 1, 1, 1])
    memory = dict(zip(customers, labels, strict=True))
    repeated_predictions = np.array([memory[int(c)] for c in customers])
    assert float(np.mean(repeated_predictions == labels)) == 1.0
    held_out = {1, 4}
    training = {int(c): int(y) for c, y in zip(customers, labels, strict=True) if c not in held_out}
    cold = np.array([training.get(c, 1) for c in sorted(held_out)])
    actual = labels[sorted(held_out)]
    assert float(np.mean(cold == actual)) == 0.5
    return {
        "repeated_entity_accuracy": 1.0,
        "unseen_entity_accuracy": 0.5,
        "target_population_changed": True,
    }


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Construct a temporally valid training set

The second case uses only labels mature by 180 and evaluates later decisions. It checks disjoint decision identities and the maximum training label time, preserving the information boundary.

**Expected evidence:** Training has 77 rows, future evaluation 40 rows, with no decision-id overlap.

```python
import numpy as np
import pandas as pd


def dataset():
    rng = np.random.default_rng(17)
    n = 120
    usage = rng.uniform(1, 100, n)
    tickets = rng.poisson(2, n)
    region = np.where(np.arange(n) % 2 == 0, "north", "south")
    logit = 0.9 * tickets - 0.035 * usage + (region == "north") * 0.3
    probability = 1 / (1 + np.exp(-logit))
    label = (rng.random(n) < probability).astype(int)
    cutoff = np.arange(n) + 100
    return pd.DataFrame(
        {
            "id": np.arange(n),
            "customer_id": np.arange(n) % 12,
            "cutoff": cutoff,
            "available_at": cutoff - 2,
            "label_available_at": cutoff + 4,
            "usage": usage,
            "tickets": tickets,
            "region": region,
            "label": label,
        }
    )


def example_two():
    frame = dataset()
    cutoff = 180
    train = frame[(frame.cutoff < cutoff) & (frame.label_available_at <= cutoff)]
    test = frame[frame.cutoff >= cutoff]
    assert set(train.id).isdisjoint(test.id)
    assert train.cutoff.max() < test.cutoff.min()
    assert train.label_available_at.max() <= cutoff
    return {
        "training_rows": len(train),
        "test_rows": len(test),
        "training_label_cutoff": int(train.label_available_at.max()),
    }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

A strong score may reflect repeated entities, future labels or repeated holdout selection. Diagnose the evaluation design before increasing model complexity. A lower score under a more appropriate split can be more useful evidence for the intended deployment.
