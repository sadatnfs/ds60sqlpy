## The question and the mechanism

Derive a YTD measure by enumerating its date boundary and eligible fact rows.

A year-to-date calculation expands a date selection to the start of the relevant year through its current last date. The returned date table becomes a filter for the measure. It does not multiply a current-day value by the number of days, and it does not mean the full calendar year when the anchor is early in that year.

On January 3, 2025 the current day has 20 of revenue, while YTD includes January 2's 27 and January 3's 20, totaling 47. On February 3 the YTD set includes all five 2025 sales lines, totaling 123. These are fixed results for the named reference's anchor dates; the Date fixture's later unused dates do not shift the anchor because the query explicitly supplies it.

Classic time intelligence relies on the marked, complete date-column contract. Keep date roles clear: this lesson uses OrderDate. The same calendar expansion with an explicitly selected shipment relationship would ask a different question. A reproducible YTD result needs its anchor, calendar definition, date role and observation completeness, not just the label YTD.

## Vocabulary and expression anatomy

DATESYTD returns a date table. CALCULATE reevaluates NetRevenue using that date set. The outer CALCULATETABLE establishes the single anchor date. The current-day measure and YTD measure are intentionally shown together so the expansion is visible.

Concepts to explain in your own words: **DATESYTD**, **year to date**, **date filter**, **anchor date**, **reconciliation**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: An early January anchor

**Starting context:** Anchor 2025-01-03; classic Gregorian year; active OrderDate; coverage is available.

```dax
EVALUATE CALCULATETABLE ( ROW ( "CurrentDay", [NetRevenue], "YTD", CALCULATE ( [NetRevenue], DATESYTD ( 'Date'[Date] ) ) ), 'Date'[Date] = DATE ( 2025, 1, 3 ) )
```

**Context trace:**

1. The current date contains S5 and revenue 20.
2. The YTD set begins January 1 and ends January 3.
3. S4 and S 5 contribute 27 +20 =47.

**Hand-derived worked-reference result:**

| CurrentDay | YTD |
| --- | --- |
| 20 | 47 |

An empty January 1 date does not disappear from the calendar set. It simply contributes no fact amount.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: An anchor in February

**Starting context:** Anchor 2025-02-03; same calendar and date role.

```dax
EVALUATE CALCULATETABLE ( ROW ( "CurrentDay", [NetRevenue], "YTD", CALCULATE ( [NetRevenue], DATESYTD ( 'Date'[Date] ) ) ), 'Date'[Date] = DATE ( 2025, 2, 3 ) )
```

**Context trace:**

1. S8 contributes 36 on the current day.
2. The YTD set includes January plus February 1 through 3.
3. S4..S8 sum 27 +20 +20 +20 +36 =123.

**Hand-derived worked-reference result:**

| CurrentDay | YTD |
| --- | --- |
| 36 | 123 |

The measure reevaluates over an expanded set, not over the text currently visible in one table cell.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Only the first 2025 sale is within the period.
2. Exclude S8 on February 3.
3. Name the included-date interval and contributing SaleIDs.
4. Events are not uniformly distributed across dates.
5. Calendar presence does not establish observed outcomes.
6. The expanded dates can be the same while the fact-date role differs.
