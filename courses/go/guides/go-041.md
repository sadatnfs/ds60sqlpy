# go-041: A real client-go project and explicit cluster configuration

## Level and prerequisites

Advanced. Allow about 120 minutes, then revisit the transfer case later. Prerequisites: go-040

## Learning objectives

Configure a client-go project from an explicit, secure cluster configuration and refuse ambient credentials. Along the way, explain clientset, kubeconfig context, dependency pin; implement the six investigations below; and defend the expected result of a changed input before running it.

## Why this mechanism matters

client-go provides typed Kubernetes clients, discovery, watches, caches and work queues. It is a dependency project, not part of the Go standard library. Keep k8s.io/api, apimachinery and client-go on compatible release lines and review the documented compatibility matrix for the target cluster. Configuration carries authority: a kubeconfig can name a cluster, credentials and executable authentication plugins. Do not discover an ambient configuration for a teaching program that is supposed to use a disposable target. The ordinary pad below validates a deliberately constrained connection description and constructs a request without sending it. A separately prepared project fixture shows the actual typed client and explicit-context loading.

## Vocabulary and concepts

- **Clientset:** Typed clients for Kubernetes API resource groups.
- **Kubeconfig context:** A named selection of cluster, identity and namespace.
- **Dependency pin:** An explicit reviewed module version rather than an implicit latest version.

## Syntax anatomy and reasoning

The prepared project uses clientcmd loading rules with one explicit kubeconfig path and a named context override, then kubernetes.NewForConfig. CoreV1().Pods(namespace).List(ctx, metav1.ListOptions{Limit:...}) invokes a typed resource client. Context and request timeout bound work; pagination must be handled rather than assuming one list is complete. The project is read-only and still requires exact disposable target identification, minimal RBAC and deliberate execution.

## Worked example / walkthrough

### Worked example 1: Accept explicit secure configuration

Validate an HTTPS endpoint, lesson namespace and explicit context name.

```go
package main

import (
	"errors"
	"fmt"
	"net/url"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func validateTarget(endpoint, namespace, contextName string) error {
	u, err := url.Parse(endpoint)
	if err != nil || u.Scheme != "https" || u.Host == "" || u.User != nil {
		return errors.New("explicit HTTPS endpoint required")
	}
	if namespace == "" || strings.ContainsAny(namespace, "/\\ ") || contextName == "" {
		return errors.New("explicit namespace and context required")
	}
	return nil
}

func main() {
	// Accept explicit secure configuration
	{
		check(validateTarget("https://cluster.invalid:6443", "lesson", "owned-lesson") == nil, "target")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The configuration is accepted.

The hostname is a nonresolving fixture and no request is sent. Real target ownership requires stronger runtime evidence than these syntax checks.

### Worked example 2: Reject insecure transport

Validate an HTTP endpoint.

```go
package main

import (
	"errors"
	"fmt"
	"net/url"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func validateTarget(endpoint, namespace, contextName string) error {
	u, err := url.Parse(endpoint)
	if err != nil || u.Scheme != "https" || u.Host == "" || u.User != nil {
		return errors.New("explicit HTTPS endpoint required")
	}
	if namespace == "" || strings.ContainsAny(namespace, "/\\ ") || contextName == "" {
		return errors.New("explicit namespace and context required")
	}
	return nil
}

func main() {
	// Accept explicit secure configuration
	{
		check(validateTarget("https://cluster.invalid:6443", "lesson", "owned-lesson") == nil, "target")
	}

	// Reject insecure transport
	{
		check(validateTarget("http://cluster.invalid", "lesson", "owned-lesson") != nil, "TLS")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The configuration is rejected.

TLS policy protects transport identity. Disabling certificate verification is not a reasonable response to a configuration error.

## Exercises

### Exercise 1: Accept explicit secure configuration: predict an edited check

**Expected:** The edited check panics with `target` even though `validateTarget("https://cluster.invalid:6443", "lesson", "owned-lesson") == nil` still holds.

**Verify:** Restoring `check(validateTarget("https://cluster.invalid:6443", "lesson", "owned-lesson") == nil, "target")` makes the check pass again with the worked observation: the configuration is accepted.

### Exercise 2: Reject insecure transport: diagnose an edited check

A careless edit rewrote the check in worked example 2 as `check(validateTarget("http://cluster.invalid", "lesson", "owned-lesson") == nil, "TLS")`. Explain the failure, then restore it.

**Expected:** The defective run panics with `TLS`; after restoring `check(validateTarget("http://cluster.invalid", "lesson", "owned-lesson") != nil, "TLS")`, the configuration is rejected.

**Verify:** The edited check fails with message `TLS` for a state that `validateTarget("http://cluster.invalid", "lesson", "owned-lesson") != nil` accepts.

## Common pitfalls and diagnosis

Letting a program use whatever current-context the local kubeconfig names is how lesson code ends up writing to a production cluster. Require an explicit context and namespace, and reject plain HTTP and credentials embedded in URLs. On the dependency side, mismatched k8s.io/api, apimachinery and client-go versions cause confusing compile errors; pin them together and check the compatibility matrix.

General compiler, panic and error diagnosis is in the [study guide](../STUDY-GUIDE.md#diagnose-a-failure).

## Progressive hints

### Hint for investigation 1: Accept explicit secure configuration: predict an edited check

1. Restate the expected observation: The configuration is accepted.
2. Every rule passes for an HTTPS endpoint with names. What does validateTarget return?
3. The port is now 6443!, so url.Parse fails, validateTarget returns an error and `==nil` is false. The validator is right; the endpoint no longer parses.

### Hint for investigation 2: Reject insecure transport: diagnose an edited check

1. Restate the expected observation: The configuration is rejected.
2. The scheme must be https. What happens to http?
3. An HTTP endpoint is rejected, so validateTarget returns an error and `==nil` is false. Restore `!=nil` so the check asserts rejection.

### Hint for investigation 3: Reject ambient context selection

1. Restate the expected observation: Validation rejects the configuration.
2. An empty context name fails the explicit-name rule. Is it accepted?
3. An explicit context prevents silently inheriting whichever cluster happens to be current in a developer configuration.

### Hint for investigation 4: Constrain a namespace

1. Restate the expected observation: Validation rejects it.
2. The namespace may not contain a slash. Which rule rejects lesson/other?
3. This small validator is deliberately conservative.

### Hint for investigation 5: Construct a bounded request

1. Restate the expected observation: The method and URL path are correct.
2. Building a request does not send it. What are its method and path?
3. Constructing a request proves neither authentication nor authorization nor API availability.

### Hint for investigation 6: Transfer userinfo rejection

1. Restate the expected observation: The embedded credential form is rejected.
2. URL.String writes userinfo into the endpoint. Which rule catches it?
3. Credentials should not be hidden in endpoint strings that might be logged.
