# Plan 11-09: Minimal-CVE R and Swift bases, release 2.1.1

## Objective

The R and Swift workers stop inheriting Ubuntu Noble base findings: Swift
runs on Amazon Linux 2023, and R 4.6.1 is compiled from verified upstream
source on Debian 13 with no fixable vulnerability left in the R, TMB or
Spark/TMB images. Release 2.1.1 ships them from GitHub Actions.

## Tasks

1. Rebuild `docker/workers/Dockerfile.swift` on the official Amazon Linux
   2023 Swift image and refresh the Swift answers whose output depends on
   the platform.
2. Rebuild `docker/workers/Dockerfile.r` in four stages on Debian 13:
   cairo from source without X11, R 4.6.1 from the checksummed tarball,
   builder-only headers, and a runtime that keeps the C, C++ and Fortran
   toolchain from HARD-04. Rebuild tmb-local and spark-tmb on it.
3. Scan the R, tmb-local and Spark/TMB images with the pinned Trivy:
   no fixable findings; the remaining HIGH or CRITICAL pairs are covered
   by the shared Debian 13 policy entries.
4. Bump to 2.1.1, qualify the `r` and `swift` groups on native amd64 and
   arm64 runners, refresh the CVE policy, publish with `[publish-docker]`,
   verify the Hub manifests and publish GitHub release `v2.1.1` as Latest.

## Verification

- `runtime-qualification.yml` passes for `r swift` on both architectures.
- All workflows green on the release commit; `v2.1.1` published with
  multi-architecture tags, and `validate-policy` passes.
