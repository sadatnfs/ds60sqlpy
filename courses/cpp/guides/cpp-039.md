## Learning objectives

Define ownership and error transport across a language/binary boundary.

## Vocabulary and concepts

A C interface exposes stable-shaped calls to clients that may not share a C++ compiler. An opaque handle hides implementation details while preserving a documented owner. A loading boundary introduces version, symbol and cleanup responsibilities. Destroying an object in the wrong allocator or letting an exception cross the boundary can break the contract.

## Syntax and mechanism

Create returns a handle or failure; destroy releases it exactly once; getters validate pointers and report status. extern C controls linkage but the host still needs compatible architecture and calling conventions. Dynamic loading requires a separate platform-specific host test, not the single-file browser example.
