# web-015: Flexbox: one-dimensional layout and resilient navigation

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-014`

## Learning objectives

Build a wrapping navigation bar and flexible card row. Explain when Flexbox fits better than Grid. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

Flexbox distributes space among items primarily along one axis. The main axis follows flex-direction, while the cross axis is perpendicular. justify-content distributes available space along the main axis; align-items aligns items along the cross axis. The names do not permanently mean horizontal and vertical because direction can change.

Flexible items have a basis and rules for growing or shrinking. A row of long labels may overflow if wrapping is disabled or if an item's automatic minimum size prevents shrinking. `min-inline-size:0` is often useful for a flex child that must allow its text to wrap or truncate deliberately. Flexbox is a layout tool, not permission to reorder content into a confusing keyboard sequence.

## Syntax anatomy and mechanism

Use display:flex, gap and flex-wrap:wrap for a simple responsive group. `flex: 1 1 12rem` gives an initial basis and permits growth and shrinkage. Set `align-items:stretch` when equal cross-axis size supports the component. Keep DOM order aligned with intended reading and focus order rather than using order to create a contradictory visual sequence.

## Worked example / walkthrough

### Worked example 1: Wrapping navigation

Wrapping preserves reachable links when space is limited.

```css
nav ul {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
  list-style: none;
  padding: 0;
}
```

**Expected observation:** Items form additional rows rather than overflowing.

### Worked example 2: Flexible cards

The basis expresses a preference rather than an inflexible width.

```css
.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.card {
  flex: 1 1 12rem;
  min-inline-size: 0;
}
```

**Expected observation:** Cards share available space and can wrap.

## Six progressive exercises

### Exercise 1: Name the axes for flex-direction:column.

**Expected evidence:** The main axis is vertical in the usual horizontal writing mode; the cross axis is horizontal.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Add gap between navigation items without per-item margins.

**Expected evidence:** Spacing is owned by the container and stays consistent when wrapping.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Build a wrapping navigation bar and flexible card row.

**Expected evidence:** Long labels stay reachable at narrow widths and DOM order remains logical.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Diagnose a flex child that refuses to shrink.

**Expected evidence:** Inspect its minimum size, long content and flex-basis before forcing overflow hidden.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Test one item, many items and a very long label.

**Expected evidence:** The layout remains readable without relying on exactly three equal strings.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Explain when Flexbox fits better than Grid.

**Expected evidence:** Use Flexbox for distributing items along one primary dimension; use Grid for explicit two-dimensional alignment.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

Do not equate justify-content with horizontal alignment universally. Visual order changes do not necessarily change keyboard order. A perfectly aligned screenshot is insufficient if navigation becomes confusing.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.
