# js-043: D3 and SVG: from a number to a visible mark

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-029`, `js-005`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Create three labeled bars from a saved blank pad. Explain why position and length suit count comparison. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

D3 is a collection of JavaScript tools for transforming data and connecting it to visual output. It does not choose a correct chart or statistical question for you. A visual encoding maps a data property to a perceptual property such as position, length, area or color. Begin by naming the quantity and units before choosing a mark.

SVG is a document tree of vector shapes. A rectangle has x and y coordinates, width and height. In the usual SVG coordinate system x increases to the right and y increases downward. A viewBox describes the internal coordinate system; CSS controls how that system fits the available display area. A shape can be present in the DOM while lying outside the visible viewBox.

The first chart maps three synthetic counts to horizontal bar lengths. A zero-length bar corresponds to zero, making length comparisons interpretable. Labels provide category identity and exact values. The chart is intentionally small enough that you can calculate every coordinate by hand.

## Syntax anatomy and mechanism

`d3.select(host)` wraps one existing DOM element in a selection. `.append('svg')` creates an SVG child and returns a selection containing it. `.attr(name, value)` changes an attribute; a callback receives the bound datum and index. A chain is a sequence of operations, not special chart syntax.

This lesson first uses a simple multiplier rather than a scale to expose the arithmetic. With width equal to count times 20, counts 2, 5 and 8 produce widths 40, 100 and 160. Later lessons replace the literal multiplier with a scale whose domain and range are explicit. Keep text separate from rectangle geometry.

## Worked example / walkthrough

### Worked example 1: Map a count to length

A literal computation exposes the first encoding.

```javascript
const count = 5;
const width = count * 20;
console.log(width);
```

**Expected observation:** 100 SVG coordinate units.

### Worked example 2: Remember SVG vertical direction

These two centers have increasing y downward.

```javascript
const centers = [{x: 40, y: 30}, {x: 40, y: 80}];
console.log(centers[1].y > centers[0].y);
```

**Expected observation:** The second point is lower, even though its y value is larger.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose a rectangle outside the viewBox. Its distinguishing evidence is Its DOM presence differs from its visible intersection. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
