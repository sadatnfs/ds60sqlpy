## The question and the mechanism

Derive an iterator result and explain how blank rows affect its denominator.

An iterator evaluates an expression for each row of a table. SUMX adds those scalar results; AVERAGEX averages the numerical results it includes. The input table therefore determines the weighting unit. Iterating sales lines, products or customers can give different results even when the expression's name contains the same business word.

SUMX is appropriate when the additive amount must be calculated from several row columns. Quantity times UnitPrice minus a line discount is such an expression. A stored NetAmount column can instead be summed directly when its contract is trusted. Neither form is automatically faster for every model; establish semantic equivalence before measuring.

Blank handling changes averages. Product-level [NetRevenue] is blank for Bag, so averaging that measure over Product averages the three nonblank product results. Coalescing Bag's value to zero includes a fourth number and lowers the average. Both computations are valid expressions, but they answer different questions about the catalog population.

## Vocabulary and expression anatomy

Inside SUMX(Sales,...), Sales columns refer to the current line. Inside AVERAGEX(Product,[NetRevenue]), the model measure transitions each Product row before evaluating its sales. COALESCE changes the value supplied to the averaging operation and therefore the effective numerical denominator.

Concepts to explain in your own words: **SUMX**, **AVERAGEX**, **row expression**, **blank exclusion**, **weighting**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Calculate additive row amounts

**Starting context:** All eight Sales rows; Discount is a currency amount per line.

```dax
EVALUATE ROW ( "Gross", SUMX ( Sales, Sales[Quantity] * Sales[UnitPrice] ), "Net", SUMX ( Sales, Sales[Quantity] * Sales[UnitPrice] - Sales[Discount] ) )
```

**Context trace:**

1. The line gross amounts are 20, 5, 40, 30, 20, 20, 20 and 40.
2. Their sum is 195; the line discounts sum to 8.
3. Subtracting each line's discount yields net total 187.

**Hand-derived worked-reference result:**

| Gross | Net |
| --- | --- |
| 195 | 187 |

If Discount represented a percentage or per-unit amount, this expression would be wrong even though its arithmetic is valid. The data dictionary is part of the formula contract.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: Average sold products or the complete catalog

**Starting context:** All four Product rows; Bag has no sales and a blank revenue measure.

```dax
EVALUATE ROW ( "NonblankProducts", AVERAGEX ( Product, [NetRevenue] ), "AllCatalogProducts", AVERAGEX ( Product, COALESCE ( [NetRevenue], 0 ) ) )
```

**Context trace:**

1. Per-product results are 67, 24, 96 and BLANK.
2. AVERAGEX over the nonblank numerical results divides 187 by 3.
3. COALESCE changes Bag to zero, so the average divides 187 by 4.

**Hand-derived worked-reference result:**

| NonblankProducts | AllCatalogProducts |
| --- | --- |
| 62.33333333 | 46.75 |

The lower second average reflects a broader denominator, not worse arithmetic. Label the population as sold products or all catalog products.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.
