# mle-006: Register and retrieve actual Feast historical features

## Level and prerequisites

Beginner. Direct prerequisites: `mle-002`, `mle-003`, `mle-004`

**Outcome:** Qualify a real feature-store retrieval against independent temporal and coverage checks.

## Question and mechanism

A feature store organizes feature definitions and retrieval interfaces. In this lesson Feast uses an actual local Parquet source, registry and SQLite online-store configuration. An entity defines the join identity, a feature view defines fields and a time relationship, and historical retrieval combines those features with an entity/request table.

The normal fixture contains two versions for customer 1 and one for customer 2. Historical requests select values at their own timestamps, within the declared view TTL. Sorting by request_id restores an explicit output comparison order. A successful retrieval is then checked against known values rather than assumed correct because a package imported.

Boundary behavior also needs direct observation. The prepared local backend can omit unmatched or expired request rows. The second case therefore treats the request table as authoritative and left-joins retrieved values back by a validated unique request key. This preserves missing cases explicitly. Neither a point-in-time API name nor a successful process should replace coverage and temporal validation.

## Syntax and data contract

Entity declares the join key and value type. FeatureView supplies a schema, TTL and FileSource timestamp field. FeatureStore.apply registers these owned local definitions. get_historical_features returns actual retrieved data; validate keys and reattach it to the original request population when necessary. The fixture timestamp represents the feature's declared availability/validity point, not arbitrary future knowledge.

## Worked case 1: Observe actual point-in-time values

The first case registers the real view and retrieves three identified requests. Customer 1 receives 10 before its later version and 20 afterward; customer 2 receives 5. The result is sorted by request identity for comparison.

**Expected evidence:** Historical usage is [10,20,5] and one feature view is registered.

```python
import os
import tempfile
from datetime import timedelta
from pathlib import Path

import pandas as pd


def configure_local_tools():
    os.environ.update(
        FEAST_USAGE="False",
        DO_NOT_TRACK="true",
        MLFLOW_ENABLE_TELEMETRY="false",
        MLFLOW_DISABLE_AGENT_HINT="1",
        DBT_SEND_ANONYMOUS_USAGE_STATS="false",
    )


def make_store(directory):
    configure_local_tools()
    from feast import Entity, FeatureStore, FeatureView, Field, FileSource, ValueType
    from feast.types import Float32, Int64

    root = Path(directory)
    root.mkdir(parents=True, exist_ok=True)
    (root / "feature_store.yaml").write_text(
        "project: classroom\nprovider: local\nregistry: "
        "registry.db\nonline_store:\n  type: sqlite\n  path: "
        "online.db\nentity_key_serialization_version: "
        "3\n"
    )
    stamps = pd.to_datetime(["2024-01-01", "2024-01-03", "2024-01-01"], utc=True)
    data = pd.DataFrame(
        {
            "customer_id": [1, 1, 2],
            "feature_time": stamps,
            "usage": [10.0, 20.0, 5.0],
            "tickets": [1, 2, 3],
            "feature_epoch": [int(t.timestamp()) for t in stamps],
        }
    )
    data.to_parquet(root / "features.parquet", index=False)
    customer = Entity(name="customer", join_keys=["customer_id"], value_type=ValueType.INT64)
    view = FeatureView(
        name="customer_features",
        entities=[customer],
        ttl=timedelta(days=30),
        schema=[
            Field(name="usage", dtype=Float32),
            Field(name="tickets", dtype=Int64),
            Field(name="feature_epoch", dtype=Int64),
        ],
        source=FileSource(path=str(root / "features.parquet"), timestamp_field="feature_time"),
    )
    store = FeatureStore(repo_path=str(root))
    store.apply([customer, view])
    return store


def historical(store):
    requests = pd.DataFrame(
        {
            "request_id": [1, 2, 3],
            "customer_id": [1, 1, 2],
            "event_timestamp": pd.to_datetime(["2024-01-02", "2024-01-04", "2024-01-02"], utc=True),
        }
    )
    return (
        store.get_historical_features(
            entity_df=requests, features=["customer_features:usage", "customer_features:tickets"]
        )
        .to_df()
        .sort_values("request_id")
    )


def example_one():
    with tempfile.TemporaryDirectory() as d:
        store = make_store(Path(d) / "features")
        try:
            result = historical(store)
            assert result.usage.tolist() == [10.0, 20.0, 5.0]
            assert result.request_id.tolist() == [1, 2, 3]
            assert len(store.list_feature_views()) == 1
            return {"historical_usage": result.usage.tolist(), "registered_feature_views": 1}
        finally:
            store.teardown()


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Retain unmatched and expired requests

The second case includes a valid request, one before recorded history and one outside TTL. It validates retrieved-key uniqueness and restores all three request rows. The two unavailable values remain missing rather than disappearing from coverage.

**Expected evidence:** The normalized population has 3 rows with values [10,null,null], regardless of whether the backend returned unmatched rows.

```python
import os
import tempfile
from datetime import timedelta
from pathlib import Path

import pandas as pd


def configure_local_tools():
    os.environ.update(
        FEAST_USAGE="False",
        DO_NOT_TRACK="true",
        MLFLOW_ENABLE_TELEMETRY="false",
        MLFLOW_DISABLE_AGENT_HINT="1",
        DBT_SEND_ANONYMOUS_USAGE_STATS="false",
    )


def make_store(directory):
    configure_local_tools()
    from feast import Entity, FeatureStore, FeatureView, Field, FileSource, ValueType
    from feast.types import Float32, Int64

    root = Path(directory)
    root.mkdir(parents=True, exist_ok=True)
    (root / "feature_store.yaml").write_text(
        "project: classroom\nprovider: local\nregistry: "
        "registry.db\nonline_store:\n  type: sqlite\n  path: "
        "online.db\nentity_key_serialization_version: "
        "3\n"
    )
    stamps = pd.to_datetime(["2024-01-01", "2024-01-03", "2024-01-01"], utc=True)
    data = pd.DataFrame(
        {
            "customer_id": [1, 1, 2],
            "feature_time": stamps,
            "usage": [10.0, 20.0, 5.0],
            "tickets": [1, 2, 3],
            "feature_epoch": [int(t.timestamp()) for t in stamps],
        }
    )
    data.to_parquet(root / "features.parquet", index=False)
    customer = Entity(name="customer", join_keys=["customer_id"], value_type=ValueType.INT64)
    view = FeatureView(
        name="customer_features",
        entities=[customer],
        ttl=timedelta(days=30),
        schema=[
            Field(name="usage", dtype=Float32),
            Field(name="tickets", dtype=Int64),
            Field(name="feature_epoch", dtype=Int64),
        ],
        source=FileSource(path=str(root / "features.parquet"), timestamp_field="feature_time"),
    )
    store = FeatureStore(repo_path=str(root))
    store.apply([customer, view])
    return store


def example_two():
    with tempfile.TemporaryDirectory() as d:
        store = make_store(Path(d) / "features")
        try:
            requests = pd.DataFrame(
                {
                    "request_id": [1, 2, 3],
                    "customer_id": [1, 1, 1],
                    "event_timestamp": pd.to_datetime(
                        ["2024-01-02", "2023-12-01", "2024-03-01"], utc=True
                    ),
                }
            )
            retrieved = store.get_historical_features(
                entity_df=requests, features=["customer_features:usage"]
            ).to_df()
            assert retrieved.request_id.is_unique
            assert set(retrieved.request_id) <= set(requests.request_id)
            # Restore the authoritative request population, including unmatched/expired rows.
            result = requests.merge(
                retrieved[["request_id", "usage"]], on="request_id", how="left", validate="1:1"
            ).sort_values("request_id")
            assert len(result) == len(requests) == 3
            assert result.usage.iloc[0] == 10.0 and result.usage.iloc[1:].isna().all()
            return {
                "requested_rows": 3,
                "retrieval_returned_rows": len(retrieved),
                "normalized_rows": 3,
                "nulls_for_unknown_or_expired": int(result.usage.isna().sum()),
                "before_history_or_outside_ttl_missing": True,
            }
        finally:
            store.teardown()


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

If results have fewer rows than requests, investigate coverage instead of fitting on the returned subset silently. If a value is temporally wrong, inspect the declared timestamp, TTL and source history. If registration fails, verify actual field types and owned paths before changing the model.
