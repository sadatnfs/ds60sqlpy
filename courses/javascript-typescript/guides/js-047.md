# js-047: Axes, ticks, labels and numerical formatting

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-046`.

## Learning objectives

Build labeled axes with deliberate ticks and number formats that match the data's representation. The central exercise is: Build a labeled quantitative axis.

## Purpose, vocabulary and mental model

An axis makes a scale interpretable by displaying reference positions and labels. D3 axis generators create SVG elements from a scale; they do not choose the right statistical units or description. The chart author must name the quantity and make tick formatting consistent with the values.

Ticks are selected reference values, not necessarily every data point. A requested tick count is often a hint rather than an exact guarantee. Explicit tick values are useful for small controlled examples. Formatting changes displayed text, not the underlying numeric scale.

Percent data illustrates a common mistake. A formatter expecting fractions displays 0.25 as 25%. If the data is already 25 and you apply that formatter, it displays 2500%. Keep the stored representation, axis label and annotation units aligned. Precision should communicate measurement meaning rather than decorate every value with many decimals.

### Key terms

- **Axis generator:** A function such as `d3.axisBottom(x)` that, when called on an SVG group, draws the domain line, ticks and labels for a scale.
- **Tick:** A selected reference value on an axis, drawn as a short line with a label. A requested tick count is only a hint, while `tickValues` fixes the ticks exactly.
- **Format specifier:** A `d3.format` pattern such as `.0%` that turns numbers into display text without changing the scale. The percent type multiplies by 100, so it expects fractions such as 0.25.
- **Units:** The measurement meaning of a value, such as dollars, counts or percent of a stated denominator, named in the axis title so readers can interpret the ticks.

## Syntax anatomy and mechanism

Call an axis generator on a group: `g.call(d3.axisBottom(x))`. Translate that group to the bottom coordinate, leaving the scale range in the chart’s coordinate system. Recalling the generator on the same group updates its ticks.

Use a visible axis title and a chart description. Avoid assuming that a bare dollar sign, abbreviation or color legend communicates enough context. Units and denominator matter, especially for rates and normalized comparisons.

## Worked example / walkthrough

### Worked example 1: Format fractions as percentages

The number remains a fraction internally.

```javascript
const percent = d3.format(".0%");
console.log(percent(0.25), percent(25));
```

**Expected observation:** 25% and 2500%, revealing the representation mismatch.

### Worked example 2: Use explicit ticks for a teaching chart

The same scale drives the axis and the mark placed above it.

```javascript
// js-047 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Axes, ticks, labels and numerical formatting")
  .style("width", "100%")
  .style("max-width", "640px");
const x = d3.scaleLinear().domain([0, 10]).range([60, 600]);
const axis = svg
  .append("g")
  .attr("transform", "translate(0,300)")
  .call(d3.axisBottom(x).tickValues([0, 5, 10]));
svg.append("circle").attr("cx", x(5)).attr("cy", 250).attr("r", 8).attr("fill", "#dc2626");
const labels = axis
  .selectAll(".tick text")
  .nodes()
  .map((node) => node.textContent);
check(labels.join(",") === "0,5,10", "Expected exactly three explicit tick labels");
output.textContent = "js-047 worked example 2 complete";
```

**Expected observation:** An axis with exactly three labeled ticks, 0, 5 and 10, and a red mark directly above the 5 tick.

**Expected evidence:** 40%.

**Progressive hint:** The format treats the input as a fraction.

### Exercise 2: Change explicit tick values to four named values.

**Expected evidence:** The axis labels match that list and remain aligned with the marks.

**Progressive hint:** Tick selection is a presentation decision.

### Exercise 3: Build a labeled quantitative axis.

**Expected evidence:** Visible quantity, units and correctly formatted tick values.

**Progressive hint:** A reader should understand what a coordinate means without opening the source code.

### Exercise 4: Diagnose 2500% for a value intended as 25%.

**Expected evidence:** The stored percentage was treated as a fraction.

**Progressive hint:** Repair the representation contract at the data boundary or choose a formatter matching stored units.

### Exercise 5: Compare fixed precision and meaningful precision.

**Expected evidence:** Displayed digits reflect measurement and comparison needs.

**Progressive hint:** More decimals are not more accuracy.

### Exercise 6: Design axes for counts and rates side by side.

**Expected evidence:** Separate unit labels and denominators make the comparison explicit.

**Progressive hint:** A count and a rate answer different questions.

## Debugging and common mistakes

When a label reads 2500%, inspect the stored value rather than the formatter: `d3.format('.0%')` multiplies by 100, so it expects 0.25 for 25 percent. A count passed to `ticks` is only a hint, so use `tickValues` when a teaching chart needs exact labels, and check that each tick lines up with a mark at the same value. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose 2500% for a value intended as 25%. Distinguishing evidence: The stored percentage was treated as a fraction.

## Accessibility and interpretation

Put the unit in the axis title, such as "Share of visits (%)", so it survives when color or a legend is unavailable. Tick labels must stay readable at narrow widths; if they overlap, reduce the tick count rather than shrinking the text, and keep a table of the exact values. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Formatting can hide or invent precision. Two decimal places on a survey of 20 people suggest accuracy the data lack, while rounding rates can make different groups look equal. Choose displayed precision from the measurement and the comparison, and give counts and rates separate units and denominators. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
