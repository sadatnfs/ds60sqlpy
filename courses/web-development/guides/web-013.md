# web-013: Color, contrast, focus and accessible states

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-012`

## Learning objectives

Build status cards whose meaning does not depend on color. Compute the contrast of #94a3b8 text on #ffffff and explain why one palette check does not qualify every interaction state. Use contrast, focus-visible and state accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Color can group information, but it cannot be the only carrier of an essential distinction. A failed status should have words or an icon with an accessible name as well as a color. Contrast is the difference in luminance that makes foreground content distinguishable from its background. A pleasing palette does not automatically provide readable text or usable controls. Test the actual foreground-background pair in each state, including hover, focus, disabled and error.

Focus identifies the element receiving keyboard input. Removing the browser's outline without a replacement makes navigation difficult or impossible for many users. The focus-visible pseudo-class lets the browser apply its heuristics for when focus needs a visible indicator. A control can also require an adequately sized target and enough spacing from neighboring controls.

### Key terms

- **Contrast ratio:** The luminance difference between text and background; WCAG 2.2 level AA asks for 4.5 to 1 for normal text and 3 to 1 for large text.
- **Focus-visible:** The `:focus-visible` pseudo-class, which matches when the browser decides focus should be shown, such as after keyboard navigation.
- **Accessible state:** A condition such as checked, expanded or invalid that must be exposed in markup and not only drawn with color.
- **Color independence:** Conveying meaning with text, shape or pattern as well as color, so it survives for readers who cannot distinguish the colors.

## Syntax anatomy and mechanism

Define a small set of tokens for text, background, accent and borders, then inspect their combinations. Use an outline with an offset so it is not hidden by the border. A status element can contain the word Ready or Needs attention; color reinforces that label. Prefer explicit text to a legend that a reader must memorize. WCAG 2.2 level AA gives measurable floors: a contrast ratio of at least 4.5:1 for normal text and 3:1 for large text (success criterion 1.4.3), 3:1 for focus indicators, control boundaries and meaningful graphics against adjacent colors (1.4.11), a focused control that is not entirely hidden by sticky content (2.4.11) and pointer targets of at least 24 by 24 CSS pixels or enough spacing around smaller ones (2.5.8). The contrast ratio is \((L_1+0.05)/(L_2+0.05)\), where \(L_1\) and \(L_2\) are the relative luminances of the lighter and darker colors.

## Worked example / walkthrough

### Worked example 1: Visible keyboard focus

A clear outline remains distinct from the control border.

```css
button:focus-visible {
  outline: 3px solid #9c3200;
  outline-offset: 3px;
}
```

**Expected observation:** Keyboard focus has a visible indicator.

### Worked example 2: A labeled status

Words preserve the information without color.

```html
<p class="status"><strong>Status:</strong> Needs attention</p>
```

**Expected observation:** The status is understandable in monochrome.

## Contrast case: a focus ring removed for looks

A common reset removes outlines everywhere. Compare it with a rule that keeps a visible indicator for keyboard users only.

```css
/* removes the only focus signal */
button:focus {
  outline: none;
}

/* keeps a keyboard signal */
button:focus-visible {
  outline: 3px solid #9c3200;
  outline-offset: 3px;
}
```

With the first rule, pressing Tab still moves focus, but nothing on screen shows where it went, so a keyboard user loses their place. With the second rule, a mouse click usually shows no ring, while keyboard focus draws a 3px outline set 3px away from the border, so the border cannot hide it. The color #9c3200 on a white page is a dark orange-brown with a ratio well above the 3:1 floor for focus indicators. Press Tab through the page with each rule to see the difference directly.

## Debugging and common mistakes

Do not calculate contrast against an assumed background when an overlay or image changes it. A custom focus ring that resembles hover may still confuse users. Automated checks complement real keyboard review.

If the focus ring vanishes, search for outline none and for overflow hidden on a parent, which can clip an outline drawn outside the box. If a status is only red or green, cover the color with your hand or use grayscale and check whether the words still carry the meaning.

The shared [debugging routine](../STUDY-GUIDE.md#debugging-html) covers what to record before each repair.
