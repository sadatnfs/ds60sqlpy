# dbt-017: Temporal data products and late-known facts

## Level and prerequisites

Advanced. Direct prerequisites: `dbt-005`, `dbt-009`, `dbt-010`

**Outcome:** Produce a historical feature relation with explicit entity, time and version semantics.

## Question and mechanism

Historical correctness depends on what was knowable at the decision time. An event can occur before a cutoff but arrive after it. A correction can revise an old event using information discovered later. Selecting only event_time<=cutoff can therefore expose future knowledge to a historical analysis or model.

The example represents both event_at and known_at. It joins requests to eligible feature records and uses row_number to select the latest version after applying both clocks. The counterexample omits the availability condition and returns a strikingly different value for the first request. The program compares the actual model relations, not only the SQL strings.

This small candidate join is designed for inspection, not arbitrary scale. A large implementation needs an appropriate physical strategy, snapshots or source history while preserving the same semantics. The schema must also distinguish unavailable information from a legitimate zero, and requests with no eligible history must remain accounted for.

## Syntax and data contract

The join combines entity identity with event and availability cutoffs. row_number partitions by request identity and orders eligible versions by the declared version keys. Eligibility must be applied before selecting the latest row. The fixture uses integer time keys for transparent arithmetic; a real contract must define timezone and boundary semantics for timestamps.

## Worked case 1: Select only known information

At request cutoff 5, the event at 4 is not known until 7, so the correct result uses the earlier value 10. At cutoff 9, value 30 is eligible. The ordering chooses among already eligible records.

**Expected evidence:** The available feature values are [10,30].

```python
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def temporal_case(available):
    with tempfile.TemporaryDirectory() as d:
        clause = "and f.known_at <= r.cutoff" if available else ""
        sql = (
            (
                "select request_id, value from (select "
                "r.request_id,f.value,row_number() over(partition by "
                "r.request_id order by f.event_at desc,f.known_at desc) as "
                "rank from {{ ref('requests') }} r join {{ ref('features') "
                "}} f on r.customer=f.customer and f.event_at<=r.cutoff "
            )
            + clause
            + ") where rank=1"
        )
        p = project(
            d,
            models={"training_features": sql},
            seeds={
                "requests": "request_id,customer,cutoff\n1,10,5\n2,10,9\n",
                "features": "customer,event_at,known_at,value\n10,2,3,10\n10,4,7,999\n10,8,8,30\n",
            },
        )
        invoke(p, "build")
        result = rows(p, "select request_id,value from training_features order by request_id")
        assert result == ([(1, 10), (2, 30)] if available else [(1, 999), (2, 30)])
        return {"availability_checked": available, "features": result}


def example_one():
    return temporal_case(True)


if __name__ == "__main__":
    print(example_one())
```

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Add an unmatched request

Create a cutoff before any eligible feature.

**Check:** The request is explicitly retained or counted as unmatched.

**Hint:** The example inner join has a coverage limit.


### 2. Change the availability clock

Make the revised event known at 4.

**Check:** It is eligible for cutoff 5.

**Hint:** The two-clock rule remains unchanged.


### 3. Test equal cutoffs

Place an event exactly on the request boundary.

**Check:** Its treatment matches the documented inclusive rule.

**Hint:** Boundary operators are assumptions.


### 4. Add version ties

Create two eligible versions with equal event and known keys.

**Check:** A further deterministic authority rule or rejection is required.

**Hint:** row_number needs a meaningful total ordering.


### 5. Compare with a snapshot

Explain why a periodic snapshot may not capture every intermediate state.

**Check:** The answer distinguishes observed state from complete source history.

**Hint:** A snapshot sees what was present when it ran.


### 6. Validate with an oracle

Recompute the two request values in Python from the tiny rows.

**Check:** The oracle returns 10 and 30.

**Hint:** Use the explicit eligibility inequalities.


## Diagnose errors and misleading results

If a historical score is suspiciously good, inspect availability and label timing before interpreting model quality. If rows disappear, reconcile request coverage. If results vary on rerun, inspect version ties and ordering. Fix the temporal data contract before adjusting the model.
