# tf-028: Restartable training and checkpoint evidence

## Level and prerequisites

Advanced; approximately 135 minutes. Direct prerequisites: `tf-027`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Prove a checkpoint restores the next update rather than only the current predictions. The central investigation is concrete: Train a tiny model for two Adam updates with dropout disabled; save model and optimizer state, restore in a fresh process and compare the next update on the identical batch. The finish condition is Uninterrupted and restored next-step weights agree within declared 1e-6 float32 tolerance. A weights-only restart intentionally exposes missing optimizer state. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

A training checkpoint is more than a weight file. Adam keeps moving estimates of gradients and squared gradients, plus an update counter. Two runs with identical weights but different optimizer state can take different next steps. A restart test therefore compares an uninterrupted next update with a restored next update on the identical batch and dtype. Restoring in a new process tests reconstruction rather than accidental reuse of in-memory objects. Checkpoints are temporary in this lesson and are removed when the context exits. This validates a small deterministic CPU case; it does not promise bitwise reproducibility across hardware, versions or nondeterministic data pipelines.

## Vocabulary and concepts

**Optimizer state:** Accumulated information used to choose the next update.

**Checkpoint:** Saved state sufficient for a declared continuation contract.

**Restart parity:** Agreement between restored and uninterrupted next behavior.

## Syntax anatomy and reasoning sequence

Create the variable and optimizer, then build optimizer slots before restoring. tf.train.Checkpoint tracks both. save writes a numbered checkpoint prefix; restore(...).assert_consumed() detects missing tracked state. The child process constructs fresh objects and takes exactly one further update. Compare float32 weights with tolerance1e-6. A weights-only control resets optimizer history and should diverge on this fixture.

## A restart is a claim about the next operation

Equal model weights do not imply equal training state. Consider a momentum
rule \(v_{\mathrm{next}}=0.9v+g\) and \(w_{\mathrm{next}}=w-0.1v_{\mathrm{next}}\). At the same w and gradient
g = 2, a saved velocity of 1 gives a step of 0.29; a reset velocity of zero
gives a step of 0.2. Adam uses different moment equations, but the same
principle applies: history affects the next update.

The fixture takes two updates before saving, so its Adam moments and update
counter contain nontrivial information. It then computes an uninterrupted
third step as a control. A fresh process constructs new objects, restores
the checkpoint and takes that same third step on the same batch. Comparing
the resulting weight and iteration counter tests continuation behavior.
Merely finding a checkpoint file, or restoring into still-live objects,
would provide weaker evidence.

The restore contract includes model variables and optimizer variables. Slots
must exist under the expected structure for a strict consumed-state check to
be meaningful. A weights-only negative control deliberately loses the Adam
history and should disagree with the uninterrupted control on this fixture.
That disagreement demonstrates why a model file and a training checkpoint
serve different purposes.

The exact continuation state depends on the training process. A shuffled
iterator, stochastic augmentation, random generator, learning-rate schedule
or gradient accumulator adds state beyond this fixed-batch example. The
lesson establishes one bounded CPU continuation with a declared tolerance;
it does not establish exact reproduction across devices or framework
versions. List the state required for the particular next operation you
intend to reproduce.

## Worked example / walkthrough

### Example A: Create nontrivial optimizer state

A checkpoint made before any updates would not test restoration of nonzero moment estimates. Two steps create state that a fresh optimizer does not possess.

```python
import numpy as np
import tensorflow as tf
import tempfile,json,subprocess,sys,textwrap
from pathlib import Path
def make_state():
    w=tf.Variable(0.,dtype=tf.float32); opt=tf.keras.optimizers.Adam(.1); opt.build([w]); return w,opt
def step(w,opt):
    with tf.GradientTape() as tape: loss=(w-2)**2
    opt.apply_gradients([(tape.gradient(loss,w),w)])
w,opt=make_state(); step(w,opt); step(w,opt)
assert int(opt.iterations)==2 and float(w)>0
```

**Expected:** iteration count2 and positive weight.

### Example B: Save both state components

The returned prefix includes a save counter. Keep the exact prefix rather than guessing a filename. Temporary ownership confines the example to disposable local files.

```python
import numpy as np
import tensorflow as tf
import tempfile,json,subprocess,sys,textwrap
from pathlib import Path
def make_state():
    w=tf.Variable(0.,dtype=tf.float32); opt=tf.keras.optimizers.Adam(.1); opt.build([w]); return w,opt
def step(w,opt):
    with tf.GradientTape() as tape: loss=(w-2)**2
    opt.apply_gradients([(tape.gradient(loss,w),w)])
w,opt=make_state(); step(w,opt); step(w,opt)
assert int(opt.iterations)==2 and float(w)>0
temporary=tempfile.TemporaryDirectory(); folder=Path(temporary.name)
checkpoint=tf.train.Checkpoint(weight=w,optimizer=opt); prefix=checkpoint.save(str(folder/'state'))
assert Path(prefix+'.index').is_file()
```

**Expected:** checkpoint index exists; no course source file is written.

## Common pitfalls and diagnosis

When restored predictions match but the next update differs, inspect
optimizer moments and the iteration counter before widening tolerance. If
the fixed-batch proof passes but a larger job diverges, inspect data order,
random generators, schedules and partially accumulated gradients. Keep the
fresh-process control and the weights-only failure case together.
