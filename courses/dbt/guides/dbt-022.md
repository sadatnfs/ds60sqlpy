# dbt-022: Diagnose template, database and semantic failures

## Level and prerequisites

Advanced. Direct prerequisites: `dbt-004`, `dbt-007`, `dbt-011`

**Outcome:** Diagnose failures using the layer that actually rejected the work.

## Question and mechanism

A failed data workflow can fail at different layers. Project parsing and template compilation establish whether definitions can be resolved. Database execution establishes whether the generated SQL can run under the selected schema and privileges. Data tests and independent reconciliation ask whether the resulting values satisfy the intended contract. These layers should be diagnosed separately.

The first case uses a valid template that refers to a nonexistent database column. Compilation produces SQL, but execution fails when DuckDB binds that column. The second case produces a valid but doubled amount. It runs successfully as SQL and is rejected by an independently specified reconciliation test. The difference prevents a common mistake: assuming a compiled or materialized result is correct.

A useful incident record names the source revision, selected resources, target, first relevant error and observed database state. Avoid changing several things at once or weakening a test before understanding its assertion. The goal is to identify which assumption failed and produce new evidence for a specific correction.

## Syntax and data contract

Inspect compiled SQL for a database error and run_results for execution/test outcomes. A singular data test returns failing rows; zero rows mean that particular condition passed. The example uses a fixed independently calculated total 12 rather than deriving the expectation through the same mistaken expression as the model.

## Worked case 1: Compile a template that the database rejects

The first project has a valid ref expression and a prepared input relation, so template compilation succeeds. The generated SQL names a missing column and actual execution fails. This isolates a database-binding issue from dependency preparation.

**Expected evidence:** Compiled SQL exists, but the model result status is error.

```python
import json
import os
import tempfile
from pathlib import Path

import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def example_one():
    with tempfile.TemporaryDirectory() as d:
        p = project(
            d,
            models={"bad": "select missing_column from {{ ref('orders') }}"},
            seeds={"orders": "id,amount\n1,5\n"},
        )
        invoke(p, "seed")
        invoke(p, "compile")
        assert (p / "target/compiled/classroom/models/bad.sql").exists()
        invoke(p, "run", succeeds=False)
        assert artifact(p, "run_results.json")["results"][0]["status"] == "error"
        return {"template_compiled": True, "database_binding_rejected": True}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Reject a wrong quantity after valid execution

The second model doubles a sum and materializes 24. A singular test expecting 12 returns a failing row. Both the result and the failure are inspected, so the diagnosis concerns semantics rather than syntax.

**Expected evidence:** The relation contains 24 and the independent reconciliation test fails.

```python
import json
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def example_two():
    with tempfile.TemporaryDirectory() as d:
        p = project(
            d,
            models={"total": "select sum(amount)*2 as amount from {{ ref('orders') }}"},
            seeds={"orders": "id,amount\n1,5\n2,7\n"},
        )
        (p / "tests").mkdir()
        (p / "tests/reconcile.sql").write_text(
            "select * from {{ ref('total') }} where amount != 12"
        )
        invoke(p, "build", succeeds=False)
        assert rows(p, "select amount from total") == [(24,)]
        assert "fail" in [r["status"] for r in artifact(p, "run_results.json")["results"]]
        return {"sql_executed": True, "wrong_quantity": 24, "independent_expected_quantity": 12}


if __name__ == "__main__":
    print(example_two())
```


## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Classify the first failure

Identify which layer rejects the missing-column model.

**Check:** It is database binding/execution.

**Hint:** The template already compiled.


### 2. Create a template error

Replace a valid ref with an undefined macro.

**Check:** Compilation fails earlier.

**Hint:** Compare with the macro lesson.


### 3. Preserve the wrong result

Inspect the doubled model before repair.

**Check:** The materialized 24 remains evidence of the defect.

**Hint:** Do not delete every artifact immediately.


### 4. Repair one cause

Remove the incorrect factor 2 and rebuild.

**Check:** The independent total becomes 12 and the test passes.

**Hint:** Change the smallest relevant assumption.


### 5. Avoid a circular oracle

Explain why expecting whatever the model outputs is not a test.

**Check:** The expected value is independently justified.

**Hint:** Shared mistakes can produce agreement.


### 6. Write an incident note

Describe trigger, failed assumption, observed state, correction and verification.

**Check:** The note is specific and reproducible.

**Hint:** A stack trace alone is not the explanation.


## Diagnose errors and misleading results

Start with the first relevant diagnostic rather than the last cascade of skipped resources. Inspect actual selected nodes and database state. A model success followed by a test failure calls for semantic investigation, while a missing relation may indicate preparation or routing. Do not report a skipped downstream resource as a passing result.

## Transfer to independent work

Diagnose failures using the layer that actually rejected the work. Preserve bounded before/after evidence and verify a focused correction with an independent oracle. Apply the same method to feature and model pipelines where an apparently healthy process can still produce an invalid product.
