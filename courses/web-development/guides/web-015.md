# web-015: Flexbox: one-dimensional layout and resilient navigation

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-014`

## Learning objectives

Build a wrapping navigation bar and flexible card row. Explain when Flexbox fits better than Grid. Use flex container, main axis and cross axis accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Flexbox distributes space among items primarily along one axis. The main axis follows flex-direction, while the cross axis is perpendicular. justify-content distributes available space along the main axis; align-items aligns items along the cross axis. The names do not permanently mean horizontal and vertical because direction can change.

Flexible items have a basis and rules for growing or shrinking. A row of long labels may overflow if wrapping is disabled or if an item's automatic minimum size prevents shrinking. `min-inline-size:0` is often useful for a flex child that must allow its text to wrap or truncate deliberately. Flexbox is a layout tool, not permission to reorder content into a confusing keyboard sequence.

### Key terms

- **Flex container:** An element with `display: flex` whose direct children become flex items laid out along one axis.
- **Main axis:** The direction in which a flex container places its items, set by `flex-direction`.
- **Cross axis:** The axis perpendicular to the main axis, along which `align-items` positions the items.
- **Flex basis:** An item's starting size along the main axis before free space is distributed or taken away.
- **Flex wrap:** The `flex-wrap: wrap` setting that moves items onto new lines instead of shrinking or overflowing.

## Syntax anatomy and mechanism

Use display:flex, gap and flex-wrap:wrap for a simple responsive group. `flex: 1 1 12rem` gives an initial basis and permits growth and shrinkage. Set `align-items:stretch` when equal cross-axis size supports the component. Keep DOM order aligned with intended reading and focus order rather than using order to create a contradictory visual sequence.

## Worked example / walkthrough

### Worked example 1: Wrapping navigation

Wrapping preserves reachable links when space is limited.

```css
nav ul {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
  list-style: none;
  padding: 0;
}
```

**Expected observation:** Items form additional rows rather than overflowing.

### Worked example 2: Flexible cards

The basis expresses a preference rather than an inflexible width.

```css
.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.card {
  flex: 1 1 12rem;
  min-inline-size: 0;
}
```

**Expected observation:** Cards share available space and can wrap.

## Contrast case: a flex item that refuses to shrink

A card contains one long unbroken identifier. Compare the card before and after setting a minimum size.

```css
.cards {
  display: flex;
  gap: 1rem;
}
.card {
  flex: 1 1 12rem;
}
/* repair */
.card {
  min-inline-size: 0;
  overflow-wrap: anywhere;
}
```

Flex items default to `min-width: auto`, which in practice means they cannot shrink below their longest unbreakable content. A 60-character identifier therefore forces its card wider than the shared space, and the row overflows the container even though `flex-shrink` is 1. Setting `min-inline-size: 0` removes that floor, and `overflow-wrap: anywhere` lets the identifier break so the card can actually use the narrower width. Remove only the first repair line and you will see the card still overflow, because the wrap rule alone cannot beat the automatic minimum.

Exercises 1, 4 and 6 keep their expected answers in the solutions file.

### Exercise 1: Name the axes for flex-direction:column.

**Progressive hint:** The main axis follows flex-direction; the cross axis is perpendicular to it.

### Exercise 2: Add gap between navigation items without per-item margins.

**Expected evidence:** Spacing is owned by the container and stays consistent when wrapping.

**Progressive hint:** Replace the per-item margins with one gap declaration on the container.

### Exercise 3: Build a wrapping navigation bar and flexible card row.

**Expected evidence:** Long labels stay reachable at narrow widths and DOM order remains logical.

**Progressive hint:** Use flex-wrap: wrap and let each item size itself from its content.

### Exercise 4: Diagnose a flex child that refuses to shrink.

**Progressive hint:** Check the item's automatic minimum width and any long unbreakable word.

### Exercise 5: Test one item, many items and a very long label.

**Expected evidence:** The layout remains readable without relying on exactly three equal strings.

**Progressive hint:** Change the number of items and the length of the longest label before calling the layout done.

### Exercise 6: Explain when Flexbox fits better than Grid.

**Progressive hint:** Ask whether you are aligning items along one line or in rows and columns at the same time.

## Debugging and common mistakes

Do not equate justify-content with horizontal alignment universally. Visual order changes do not necessarily change keyboard order. A perfectly aligned screenshot is insufficient if navigation becomes confusing.

When a flex child refuses to shrink, its min-width defaults to auto, so a long word or wide image sets a floor; set min-width 0 on the item. When items overflow instead of wrapping, check that flex-wrap is wrap on the container, not on the children.
