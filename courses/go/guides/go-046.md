## Why this mechanism matters

Admission evaluates an API request after authentication and authorization and before persistence. Mutating admission can change an object; validating admission can accept or reject it. A webhook introduces a network dependency into control-plane writes, so latency, availability and failurePolicy have real consequences. Fail-open can preserve availability while allowing objects that were not checked; fail-closed can enforce policy while blocking writes during an outage. Choose deliberately and test recovery. AdmissionReview responses must correspond to the request UID and use the supported API version. A validation decision is not permission to perform unrelated side effects, especially for dry-run requests.

## Vocabulary and concepts

- **Admission:** Policy evaluation before an API object is persisted.
- **Failure policy:** Whether a failed policy service permits or blocks the API request.
- **Dry run:** A request evaluated without persisting its intended change.

## Syntax anatomy and reasoning

## Worked example / walkthrough

### Worked example 1: Accept a valid range

Validate replica count 3 under maximum 5.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

type Decision struct {
	UID         string
	Allowed     bool
	Reason      string
	SideEffects int
}

func admit(uid string, replicas, maximum int, dryRun bool) Decision {
	d := Decision{UID: uid}
	if uid == "" {
		d.Reason = "request UID required"
		return d
	}
	if replicas < 0 || replicas > maximum {
		d.Reason = "replicas outside allowed range"
		return d
	}
	d.Allowed = true
	return d
}

func main() {
	// Accept a valid range
	{
		d := admit("r1", 3, 5, false)
		check(d.Allowed && d.UID == "r1", "allow")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The decision allows the request.

The pure rule is independently testable. The HTTP adapter still needs protocol and transport validation.

### Worked example 2: Reject a negative value

Validate replica count -1.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

type Decision struct {
	UID         string
	Allowed     bool
	Reason      string
	SideEffects int
}

func admit(uid string, replicas, maximum int, dryRun bool) Decision {
	d := Decision{UID: uid}
	if uid == "" {
		d.Reason = "request UID required"
		return d
	}
	if replicas < 0 || replicas > maximum {
		d.Reason = "replicas outside allowed range"
		return d
	}
	d.Allowed = true
	return d
}

func main() {
	// Accept a valid range
	{
		d := admit("r1", 3, 5, false)
		check(d.Allowed && d.UID == "r1", "allow")
	}

	// Reject a negative value
	{
		d := admit("r2", -1, 5, false)
		check(!d.Allowed && d.Reason != "", "negative")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The decision denies it with a reason.

Field-specific validation gives an actionable failure instead of an unexplained generic denial.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
