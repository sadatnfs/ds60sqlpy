## Outcome and mechanism

Compare numerically equivalent R implementations, collect bounded timing and profiling evidence, and explain its measurement limits.

Optimization starts with a defined computation and a correct reference. Comparing two programs is not meaningful when one ignores missing values, drops groups or performs fewer repetitions. This lesson computes one mean per matrix row using a preallocated R loop and rowMeans on exactly the same finite numeric matrix. The reference values are checked before timing begins, and performance is not asserted as a mathematical invariant.

system.time records CPU and elapsed time for an expression. Elapsed time includes scheduling and other delays; a short expression may be rounded to zero at the available timer resolution. Repeat equivalent work enough to observe a bounded interval, retain the repetition count, and keep fixture generation outside the timed region. A faster result on one run is evidence about that run and workload, not a guarantee for every input size or machine.

Rprof samples the call stack at intervals. summaryRprof aggregates sampled time into inclusive and self-time views. A function can appear expensive because it calls expensive work, so total and self measures answer different questions. Sampling can miss short functions, and profiling itself adds overhead. This example reports the sampled duration and the top entries without asserting an exact profile or requiring every small call to receive a sample.

Memory needs a separate question. object.size estimates the size of an R object, not the process resident set, peak allocation or every shared backing object. Rprofmem records qualifying allocation events when memory profiling is available. The bounded example allocates a known vector inside a temporary profiling session and reports event counts. Those lines are observations of allocation activity, not a complete account of retained memory or garbage-collector behavior.

Repeated c(result,value) can allocate and copy as a vector grows. Preallocation avoids that obvious growth pattern, but it does not make every loop the fastest implementation. A vectorized function can still allocate large intermediates or perform the wrong operation. Prefer a clear implementation that meets the resource bound, then profile the actual bottleneck before adding complexity.

Profiler cleanup matters in a fresh-process lesson as well as a package. The examples register on.exit handlers, stop profiling explicitly, remove only their own temporary files and return data rather than relying on an interactive profiler. They create no persistent benchmark report. Repeated numerical equivalence checks, nonnegative timing values and bounded artifacts are the acceptance evidence; a required speedup would be a brittle and unjustified test.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Elapsed time | Wall-clock duration observed for the timed expression. |
| Sampling profile | Periodic stack observations used to estimate where execution spends time. |
| Self time | Sampled time in a function excluding its called functions. |
| Allocation | Creation of memory storage, distinct from memory retained at the end. |

## Read the syntax

system.time(expr)[["elapsed"]] extracts elapsed seconds. Rprof(path,interval=0.01) begins sampling and Rprof(NULL) stops it. summaryRprof reads the file. Rprofmem and Rprofmem(NULL) separately control allocation logging. on.exit cleanup belongs inside the function that owns those temporary resources.

## Worked examples

### Example 1: Profile two equivalent row-summary implementations

```r
row_means_loop <- function(x) {
  result <- numeric(nrow(x))
  for (i in seq_len(nrow(x))) result[[i]] <- mean(x[i, ])
  result
}
profile_equivalent_work <- function(x) {
  stopifnot(is.matrix(x), is.numeric(x), all(is.finite(x)))
  reference <- row_means_loop(x)
  vectorized <- rowMeans(x)
  stopifnot(isTRUE(all.equal(reference, vectorized, tolerance = 1e-12)))
  slow_time <- system.time(for (i in seq_len(20L)) row_means_loop(x))[["elapsed"]]
  fast_time <- system.time(for (i in seq_len(20L)) rowMeans(x))[["elapsed"]]
  path <- tempfile(fileext = ".Rprof")
  on.exit(unlink(path), add = TRUE)
  utils::Rprof(path, interval = 0.01)
  on.exit(utils::Rprof(NULL), add = TRUE)
  for (i in seq_len(30L)) row_means_loop(x)
  utils::Rprof(NULL)
  profile <- utils::summaryRprof(path)
  list(
    loop_seconds = slow_time, vector_seconds = fast_time,
    sampled_seconds = profile$sampling.time, top = head(profile$by.total, 5L),
    input_bytes = as.numeric(utils::object.size(x))
  )
}

x <- matrix(seq_len(6000) / 100, nrow = 300)
result <- profile_equivalent_work(x)
stopifnot(result$loop_seconds >= 0, result$vector_seconds >= 0, result$input_bytes > 0)
print(result)
```

**Expected observation:** Equivalent results, nonnegative timings, input size and a bounded profile summary.

Both versions compute the same 300 row means over 20 columns. The bounded repeats expose a measurable workload, while exact timings and sampled functions remain environment-dependent observations.

### Example 2: Object size and allocation events answer different questions

```r
inspect_allocation <- function() {
  x <- seq_len(1000) / 10
  bytes <- as.numeric(utils::object.size(x))
  stopifnot(bytes > 0)
  if (!isTRUE(capabilities("profmem"))) return(list(object_bytes = bytes, allocation_events = NA_integer_))
  path <- tempfile(fileext = ".Rprofmem")
  on.exit(unlink(path), add = TRUE)
  utils::Rprofmem(path, threshold = 1000)
  on.exit(utils::Rprofmem(NULL), add = TRUE)
  y <- numeric(10000)
  y[[1]] <- sum(x)
  utils::Rprofmem(NULL)
  events <- readLines(path, warn = FALSE)
  stopifnot(y[[1]] == sum(x))
  list(object_bytes = bytes, allocation_events = length(events))
}
print(inspect_allocation())
```

**Expected observation:** Positive object size; allocation event count or explicit unavailable value.

The object-size estimate describes x, while allocation events come from the later profiling interval. The capability branch reports unavailable memory profiling explicitly rather than inventing a zero event count.
