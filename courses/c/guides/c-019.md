# c-019: Binary formats, byte order and representation boundaries

## Level and prerequisites

## Purpose and mental model

A portable binary format specifies bytes, widths and byte order rather than dumping an in-memory struct. Host representation can differ in endianness, padding, alignment and type sizes. Explicit encoding makes the wire contract inspectable and avoids leaking padding bytes. A decoder must validate the available length before reading fields and reject unsupported versions or values. Use unsigned types for shifts and masks, with shift counts inside the type width. memcpy can safely copy object representation bytes when the destination object and sizes are valid, but interpreting arbitrary bytes as a typed object still requires a representation contract.

## Vocabulary and concepts

- **Endianness:** The byte order used to represent multibyte values.
- **Wire format:** A documented serialized representation independent of host layout.
- **Alignment:** An address requirement for accessing an object through a type.

## Syntax anatomy and execution trace

A big-endian 32-bit encoding stores the most significant byte first. Cast each input byte to uint32_t before shifting so integer promotion does not produce a problematic signed operation. Read four bytes only after checking length. Bitwise OR combines disjoint fields. The format here assumes eight-bit bytes and requires that with _Static_assert because its external definition uses octets.

## Worked example / walkthrough

### Worked example 1: Encode a known word

Encode 0x12345678 in big-endian order.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

_Static_assert(CHAR_BIT == 8, "this octet format requires 8-bit bytes");
void encode_u32(uint32_t value, unsigned char out[4]) {
  out[0] = (unsigned char)(value >> 24);
  out[1] = (unsigned char)(value >> 16);
  out[2] = (unsigned char)(value >> 8);
  out[3] = (unsigned char)value;
}
bool decode_u32(const unsigned char *data, size_t n, uint32_t *out) {
  if (n < 4 || data == NULL || out == NULL)
    return false;
  *out = ((uint32_t)data[0] << 24) | ((uint32_t)data[1] << 16) |
         ((uint32_t)data[2] << 8) | (uint32_t)data[3];
  return true;
}

int main(void) {
  /* Encode a known word */
  {
    unsigned char out[4];
    encode_u32(UINT32_C(0x12345678), out);
    CHECK(out[0] == 0x12 && out[1] == 0x34 && out[2] == 0x56 && out[3] == 0x78);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The bytes are 12, 34, 56, 78 in hexadecimal.

The explicit byte contract does not depend on host endianness.

### Worked example 2: Decode a known word

Decode bytes 00, 00, 01, 00.

```c

  out[0] = (unsigned char)(value >> 24);
  out[1] = (unsigned char)(value >> 16);
  out[2] = (unsigned char)(value >> 8);
  out[3] = (unsigned char)value;
}

    return false;

         ((uint32_t)data[2] << 8) | (uint32_t)data[3];

int main(void) {
  /* Encode a known word */
  {
    unsigned char out[4];
    encode_u32(UINT32_C(0x12345678), out);
    CHECK(out[0] == 0x12 && out[1] == 0x34 && out[2] == 0x56 && out[3] == 0x78);
  }

  /* Decode a known word */
  {
    unsigned char data[] = {0, 0, 1, 0};
    uint32_t value = 0;
    CHECK(decode_u32(data, 4, &value) && value == 256);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The numeric value is 256.

Each byte is promoted to the intended unsigned width before shifting.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
