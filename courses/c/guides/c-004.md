## Purpose and mental model

Control flow chooses which operations execute. A loop invariant describes what remains true before and after each iteration, connecting repeated steps to the intended result. For summation, the accumulator equals the sum of elements already visited. Empty input is then handled by the initial state rather than a special fabricated element. Index-based loops should use a half-open range from zero to length. An off-by-one error in C can access memory outside the array without a guaranteed runtime exception. Prove the bound before access rather than relying on a crash to identify mistakes.

## Vocabulary and concepts

- **Loop invariant:** A property preserved by each iteration.
- **Half-open range:** A range including its start and excluding its end.
- **Fallthrough:** Continuing from one switch case into subsequent statements.

## Syntax anatomy and execution trace

if treats zero as false and nonzero as true. for combines initialization, condition and update. while checks before the body; do-while checks afterward. break exits the nearest loop or switch, while continue skips to the next iteration. switch cases fall through unless control exits explicitly. Use size_t for lengths and indices, and avoid decrement loops that accidentally wrap an unsigned counter below zero.

## Worked example / walkthrough

### Worked example 1: Trace a prefix sum

Sum 2, 4 and 6 with a length-bounded loop.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int main(void) {
  /* Trace a prefix sum */
  {
    int values[] = {2, 4, 6};
    int sum = 0;
    for (size_t i = 0; i < 3; i++) {
      sum += values[i];
    }
    CHECK(sum == 12);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result is 12.

Each iteration adds exactly one valid element. The index is proven less than the declared length before access.

### Worked example 2: Handle zero iterations

Sum zero elements from a valid storage object.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int main(void) {
  /* Trace a prefix sum */
  {
    int values[] = {2, 4, 6};
    int sum = 0;
    for (size_t i = 0; i < 3; i++) {
      sum += values[i];
    }
    CHECK(sum == 12);
  }

  /* Handle zero iterations */
  {
    int values[1] = {9};
    size_t length = 0;
    int sum = 0;
    for (size_t i = 0; i < length; i++) {
      sum += values[i];
    }
    CHECK(sum == 0);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The accumulator remains zero.

The example uses a real array because zero-length arrays are not standard C17. The logical length may still be zero.

## Common pitfalls and diagnosis

Fix diagnostics in the "trace a prefix sum" case and the "handle zero iterations" case one cause at a time, starting with the first warning for branches, loops and invariants; a declaration mismatch in the case code inside `main` cascades. If the CHECK on `sum == 0` in the "handle zero iterations" case fails, compare the actual value with the claim that the accumulator remains zero and find the earliest departing transition. A clean compile, or a run of the "find the first match" case that did not crash, does not rule out undefined behavior.

In the "include an exact threshold" case and the "terminate a switch case" case, give every pointer and index a target, bounds, alignment, lifetime and mutability under the loop invariant, half-open range and fallthrough rules. Check each library result before use and release each owned resource once per path. The "transfer reverse traversal safely" case transfers the mechanism; keep its distinction from the "trace a prefix sum" case instead of replacing a rejected input with a plausible default.
