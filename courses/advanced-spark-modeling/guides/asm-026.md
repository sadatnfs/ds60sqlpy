# asm-026: Preparing a combined Spark and Torch environment

Tutorial mode. Stage: advanced. Direct prerequisites: `asm-018`, `torch-030`.

## Starting point and result

Spark, PyTorch, SciPy, pandas and Arrow must coexist in the same prepared environment before a worker can evaluate a custom differentiable likelihood. Installing each somewhere on the host is insufficient. This chapter introduces the owned `projects/spark-torch` project and the optional `ds60_spark_likelihood` integration package. Ordinary Spark and Torch pads remain distinct environments unless the combined project has actually been prepared.

## Mechanism: local autodiff, global numerical summaries

`SparkObjective` accepts an RDD of validated rows and a declared Torch loss specification. Each evaluation distributes an immutable parameter vector. A worker processes bounded batches, builds local tensors, computes loss and gradients, then returns detached numerical summaries. The driver checks counts and combines summaries before an optimizer proposes the next vector.

For summed loss, \(L=\sum_p L_p\) and \(g=\sum_p g_p\). For a weighted mean, divide the global sums by the global accepted weight, not each partition's weight. Add any model-level penalty once after reduction. The package's explicit `reduction` and `l2_strength` settings encode that distinction. A context manager owns optional persistence and cleanup so cached state is not left indefinitely after a failed fit.

The driver helper `minimize_lbfgsb` reports parameters, optimizer status/message, objective evaluations, raw and projected gradient norms, active bounds and a trace. A convergence flag alone is insufficient. Under active bounds, a nonzero raw gradient can coexist with a valid constrained optimum, so projected stationarity has a different interpretation.

## Worked case: additive logistic likelihood

Run the project's fixed `additive-logistic` case after preparation. Its model uses a stable Torch logits loss and returns partition summaries. Compare both objective and gradient with a serial Torch oracle across unequal partitions and batch sizes. The receipt must retain row count, parameter order, reduction, source/image identity and tolerances.

The integration namespace includes `SparkObjective.from_dataframe` with explicit feature, target and optional weight column names. Do not infer intercept inclusion from a DataFrame's display. The logistic model helper's feature count includes whichever intercept feature the design actually supplies. A schema or feature-order mismatch can produce a valid tensor with the wrong statistical meaning.

## Worked case: nonlinear Gaussian and independent groups

The fixed `nonlinear-gaussian` case evaluates a nonlinear mean with a positive-scale parameterization and compares against serial computation. This demonstrates that additive likelihoods need not be linear. The `independent-groups` case instead fits different parameter vectors to different groups. Its result is a collection of models, not an approximation to the single global model.

Use the objective classification from asm-002 before choosing either case. A shared random effect or global normalizer can invalidate a partition-local loss. No package wrapper can infer the correct factorization from a function name or a tensor shape.

## Failure diagnosis

A missing Torch import on executors is an image-preparation failure. A serialization failure may mean the closure captured a Spark session or an unpicklable optimizer. A gradient mismatch can arise from detached tensors, mean/sum inconsistency, feature order or precision. Diagnose one bounded serial case before scaling workers. Keep thread limits explicit to avoid each task creating a full CPU thread pool.

## Interview discussion

**Is the driver holding the entire dataset?** The intended design returns bounded summaries for a small parameter vector. A tiny serial oracle deliberately uses a small fixture and is not the production data path.

**Does the package make every Torch model distributable?** No. It supports declared additive objectives and a bounded adapter contract. Coupled losses and large training systems require different communication designs.

# Worked reference: Additive Torch objective contract

This is an editable reading/project reference. It has no ordinary pad Run action.

A valid record binds one parameter vector to a complete loss/count/gradient summary. Record reduction `sum` or `weighted_mean`, total accepted weight, feature ordering and whether an intercept column is present.

For unequal partitions with summed gradients 1 and 9 and counts 1 and 3, the global mean gradient is 2.5. Averages of local means give 2.0. The package must preserve the former under its weighted-mean contract. Compare fixed-parameter values before comparing optimized parameters; unchanged minima can conceal scaling errors.
