# llm-021: Document splits and contamination controls

## Level and prerequisites

Intermediate; approximately 120 minutes. Direct prerequisites: `llm-020`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Design a corpus split around the source unit and freeze it before model selection. The central investigation is concrete: Hash and deduplicate a hand-authored local corpus; add near-duplicate examples with known document-family IDs and construct grouped splits. The finish condition is No exact hash or family ID crosses train/validation/test. The original partition manifest is unchanged after evaluation. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

<!-- textbook-foundations-start -->

### Decide what kind of unfamiliar example the test should represent

A train/test split is meaningful only relative to the generalization question. Predicting another paragraph from a document already seen in training is different from predicting a new document, a new author, a new organization or a future policy revision. Randomly assigning rows can produce a formally disjoint list of IDs while leaving the most relevant information shared across the boundary. The split unit should reflect the intended source of novelty.

The fixture has documents a and a2 in family F, b in G and c in H. The policy assigns F to training, G to validation and H to test. Therefore a and a2 both go to training, even if they are separate files or contain different sentences. The family, not the individual row, is the unit of assignment. This prevents the known relationship between a and a2 from appearing on both sides of the chosen boundary.

Moving only a2 into validation creates the deliberate failure. Training still contains family F through a, and validation now contains F through a2. Their family-set intersection is {F}. The important evidence is that shared identity, not the number of rows involved. Audit every pair of partitions: training versus validation, training versus test, and validation versus test. A clean first comparison does not imply the other two are clean.

Exact content identity answers a narrower question. The strings red square and an identical copy produce the same SHA-256 digest of their UTF-8 bytes. The paraphrase square colored red produces a different digest even though its meaning may be related. A trailing space also changes the raw-byte digest. If both strings are stripped first, their normalized digests can agree. The resulting hash is evidence about the particular bytes or normalized representation supplied to it, not a detector of every semantic relationship.

This motivates retaining several identities rather than searching for one perfect ID. A record ID identifies a stored entry. A raw hash identifies its exact bytes. A normalized hash identifies a declared transformation of those bytes. A family ID records a known source relationship. A split assignment records how the experiment permits that information to be used. Each field has a distinct role, and the audit is stronger when it can explain which relationship triggered an exclusion.

The manifest hash in this chapter binds the sorted assignment dictionary. It detects a change in document-to-partition labels under that serialization rule. It does not automatically bind the document text, tokenizer, model weights or family-construction algorithm. Those require their own recorded artifacts or a manifest that explicitly includes them. A stable hash is useful because it makes a specified change detectable; its strength depends on what was actually included.

The test partition contains one authored document here. That is enough to demonstrate whole-family assignment and a deliberate leak, but not enough to estimate deployment reliability. Unknown relationships can remain even after all known family intersections are empty. A defensible report states the grouping policy, normalization rules, audit results and detection limits, then interprets the held-out score within that scope.

## Vocabulary and concepts

**Exact duplicate:** Two documents with identical bytes under the declared policy.

**Family split:** A partition assignment shared by related documents.

**Frozen manifest:** An unchanged record of identities and their partitions.

## Syntax anatomy and reasoning sequence

Hash UTF-8 text with SHA256 under a raw-text policy. Map each family to train,validation or test, then derive document assignments. Compare sets across every pair of partitions. Serialize the manifest with sorted keys for a stable identity receipt. A hash is a content fingerprint, not a claim that two different hashes represent independent documents.

## Different identities catch different problems

A filename is not content identity. Two files named a and a2 can contain the same bytes, and an exact hash can expose that duplication. A paraphrase such as red square versus square colored red has a different hash despite related meaning. A family label adds another relationship: revisions, fragments or templated records can stay together even when their text differs. Neither exact hashing nor known-family metadata proves that every unknown semantic relationship has been detected.

The fixture assigns family F, containing a and a2, wholly to training. Families G and H go to validation and test. Moving only a2 into validation creates a family intersection F even though the document IDs remain distinct. Checking only train-versus-test would miss a train-versus-validation leak, so every partition pair matters. Validation information can influence model or prompt selection long before the final test is read.

## Freeze the transformation policy too

Raw text hashes distinguish red square from red square followed by a space. Hashing stripped text makes those two values equal under a declared normalization policy. That policy may be appropriate for one corpus and destructive for another where whitespace or formatting matters. Record both the normalization version and what the digest actually identifies. Do not quietly change normalization after finding inconvenient duplicates.

The example's manifest hash covers document-to-partition assignments. It does not, by itself, bind every document ID to immutable content bytes. A complete run record should include content hashes, family metadata, preprocessing configuration and split assignments together. A stable split hash with changed source documents would not establish that the experiment used the same corpus.

Repeated documents also change effective weighting. Ten near-copies from one source are not necessarily ten independent observations about deployment performance. When evaluating transfer to new sources, preserve source-family units in both splitting and uncertainty analysis. The correct grouping rule follows the intended deployment question rather than a universal instruction that every task must use the same split granularity.


## Worked example / walkthrough

### Example A: Fingerprint exact text

The paraphrase remains related despite a different hash. This is why content hashing and family metadata address different contamination mechanisms.

```python
import numpy as np

import hashlib, json

hash_text = lambda t: hashlib.sha256(t.encode("utf-8")).hexdigest()
a = hash_text("red square")
copy = hash_text("red square")
para = hash_text("square colored red")
assert a == copy and a != para
```

**Expected:** identical texts share a hash; paraphrase differs.

### Example B: Assign whole families

The assignment is made once per family. Sampling rows independently would permit related versions to cross the boundary.

```python
import numpy as np

import hashlib, json

hash_text = lambda t: hashlib.sha256(t.encode("utf-8")).hexdigest()
a = hash_text("red square")
copy = hash_text("red square")
para = hash_text("square colored red")
assert a == copy and a != para
family = {"a": "F", "a2": "F", "b": "G", "c": "H"}
policy = {"F": "train", "G": "validation", "H": "test"}
manifest = {doc: policy[group] for doc, group in family.items()}
assert manifest == {"a": "train", "a2": "train", "b": "validation", "c": "test"}
```

**Expected:** a and a2 both train.

## Common pitfalls and diagnosis

Distinguish document ID, raw content hash, normalized content hash and family membership. Each checks a different relationship. Audit all partition pairs and freeze normalization rules before scoring. A stable assignment-only hash does not prove that the corpus bytes were unchanged, and an empty exact-hash intersection does not rule out paraphrases or shared provenance.
