Learning objectives#

Preserve leading-zero and literal-NA identifiers while reading CSV, then parse integer-cent text through an exact lexical and range boundary. Distinguish an unknown category from an originally missing observation before casting. Extract structured ASCII codes while retaining invalid and missing states. Finally, write and read real in-memory Parquet using explicit field types, nullability, business identity and category-domain checks.

Vocabulary and concepts#

  • Logical type: The meaning and permitted operations of a field. An identifier is a label even when every character is a digit. Removing its leading zeroes can change identity, while parsing a quantity's leading zeroes may preserve its numeric meaning. Decide the logical type before accepting parser inference.
  • Nullable dtype: A representation that supports known values and a missing marker together. pandas Int64, with a capital I, represents signed integer values and pd.NA. It differs from NumPy int64, which has no equivalent nullable scalar representation in an ordinary integer array.
  • Lexical contract: The accepted spelling of a value at an input boundary. This lesson permits signed ASCII decimal integer text, including leading zeroes and a plus sign for quantities. It rejects fractional text, exponent notation, surrounding whitespace and non-ASCII digit characters. Those are declared choices, not universal rules for every numerical parser.
  • Categorical domain: The declared set of allowed labels and its metadata. Nominal categories have no less-than ranking even if their metadata lists them in a particular order. Internal integer codes refer to that domain; a code alone is not a portable business label across differently configured domains.
  • Schema compatibility: A policy about which fields and representations a consumer accepts. A readable Parquet file is not necessarily compatible with the receiving application. Names, order, logical types, nullability, category values and unique business identity can require separate checks.

Syntax anatomy and exact parsing#

read_csv(..., dtype="string", keep_default_na=False) first reads the declared fields as text and preserves tokens such as NA. It also preserves empty fields as empty strings. The lesson then applies field-specific rules: record IDs and groups cannot be empty, while an empty amount explicitly means unknown. A text amount NA is not an accepted missing-amount token under this contract. The parser does not silently trim or normalize identifiers.

The input contract also requires exactly three fields in every logical CSV record, with no blank records. Check that structure before pandas inference: some ragged inputs can otherwise be interpreted as an implicit row index, shifting values into the wrong named columns without the intended schema error. Use the standard CSV parser to respect quoted commas and embedded newlines; counting physical lines or splitting on commas is not an equivalent check.

Parse valid integer text with Python's exact int before constructing nullable Int64. Check the signed range [−263,263−1][-2^{63},2^{63}-1][−263,263−1] first. Avoid a float intermediate: binary64 cannot represent every consecutive integer beyond 2532^{53}253. Casting a rounded float to an integer does not recover lost digits. Use integer cents for this fixture's stated unit; interpreting a value as dollars instead would still be a semantic error even with a perfectly valid integer dtype.

Worked example / walkthrough#

Worked example 1: Inference can erase identifiers and round quantities#
from io import StringIO
import pandas as pd

text = "record_id,group,amount_cents\n00017,NA,9007199254740993\n00018,red,\n"
inferred = pd.read_csv(StringIO(text))
typed = pd.read_csv(StringIO(text), dtype="string", keep_default_na=False)
assert inferred.record_id.tolist() == [17, 18]
assert pd.isna(inferred.group.iloc[0])
assert int(inferred.amount_cents.iloc[0]) != 9007199254740993
assert typed.record_id.tolist() == ["00017", "00018"]
assert typed.group.iloc[0] == "NA"
assert typed.amount_cents.iloc[0] == "9007199254740993"
print("Preserved IDs:", typed.record_id.tolist())

The first table contains several plausible transformations that violate the producer contract. Numeric ID inference discards leading zeroes. Default missing token handling interprets a literal category label as missing. A missing amount causes floating representation, and the large known integer loses a digit. All of these can happen before later cleaning functions inspect the DataFrame. The second read preserves the original text so each conversion can be deliberate.

Unknown amounts must stay distinguishable from zero-cent amounts. The strict parser maps only its declared empty or missing input to pd.NA, retains an explicit zero, and refuses invalid text rather than converting it to an accepted zero. Negative cents can represent a refund here; an application that forbids negative amounts needs an additional business predicate.

Worked example 2: A categorical cast can conceal a previously unknown label#
labels = pd.Series(["red", "purple", pd.NA], dtype="string")
domain = pd.CategoricalDtype(categories=["red", "blue"], ordered=False)
cast = labels.astype(domain)
unknown_before_cast = labels.notna() & ~labels.isin(domain.categories)
assert cast.isna().tolist() == [False, True, True]
assert unknown_before_cast.tolist() == [False, True, False]
print("Unknown observed labels:", labels[unknown_before_cast].tolist())

After the cast, the unknown purple label and the originally missing observation look alike. The original values are needed to distinguish them. Validate known labels against the declared domain first, then cast. Do not calculate an unknown-label rate only from the cast result. That would mix a domain violation with source missingness and could conceal an upstream vocabulary change.

Retain unused declared categories when the contract requires them. Observing no green rows does not prove green is no longer a valid category. Conversely, a category appearing in a file's metadata does not authorize it in the receiving application. The reader receives the expected domain explicitly and checks the decoded observed labels before restoring the selected categorical representation.

Text validation and Unicode#

The structured-code exercise accepts exactly two ASCII uppercase letters, a hyphen and four ASCII digits. Use a full-match policy and named capture groups, not an unanchored search that accepts a valid substring inside malformed text. The numeric-looking suffix remains a string so 0007 does not become 7. Return valid, invalid and missing states separately while retaining every input row and its original index.

This ASCII code policy is specific to a fictional identifier format. It does not imply that Unicode names or category values are invalid generally. Unicode normalization and case folding can intentionally make distinct spellings equal; they can also merge previously distinct identities. Retain original text and declare any normalization policy before applying it to business keys. Do not silently normalize full-width digit characters merely to make this regex pass.

Real Parquet and a declared compatibility boundary#

The reference writes an actual Arrow table to Parquet bytes using an explicit schema: non-null string record_id, non-null nominal dictionary/string group, and nullable signed-int64 amount_cents. It excludes the pandas row index because the business key is an explicit column. A custom index would not survive this chosen export contract; use an explicit column or a different contract if it carries meaning.

On read, check logical field order, types and nullability before making the expected pandas representations. Validate observed category labels against the consumer's supplied domain before categorical conversion. Recheck record-key uniqueness and missingness after decoding. The complete roundtrip compares all columns, values, dtypes and category metadata, not merely row count or a sum. An intentionally incompatible Parquet schema must be rejected even though the Parquet library can decode it successfully.

This is a strict small-fixture compatibility policy. Other systems deliberately support field additions, nullable widening or identity-based schema evolution. Those behaviors need explicit rules and versioned evidence. They should not emerge accidentally from a permissive cast in a loader.

Only tiny trusted bytes produced by the example are used here. An encoded-byte size limit does not bound a general binary decoder's memory use. Schema checks after decoding are not a sandbox for arbitrary hostile files. The classroom's outer process/resource boundary and deliberate input preparation remain separate.

Common pitfalls#

If an ID loses zeroes, inspect its dtype and raw CSV token before further transformation. If a large integer changes, find the first floating conversion; casting later cannot repair it. If an unknown category disappears, compare the original text with the cast's missing mask. If regex extraction succeeds on a bad string, inspect anchoring and whether a substring rather than the full value was matched.

If Parquet readback has the right row count but different meaning, compare field order/types, category labels, integer values, unknown positions and exact business IDs. Keep parser errors distinct from domain violations. Save the small original fixture and the failed assertion rather than changing expected values to accommodate an accidental conversion.

Exercise 1: Read identity-bearing CSV as text first#

Before that read, standard-library csv.reader validates quoting and exactly three fields per logical record. The reference IDs are 00017, NA and 00019; all three survive exactly. The first amount remains 9007199254740993, the second stays unknown and the third is the signed-int64 maximum. The loader deliberately does not trim ID whitespace or impose an unrelated structured-code format; those would be separate policies.

parts = values.str.extract(pattern)
state = state.mask(values.isna(), "missing").mask(valid, "valid")

The pattern is anchored and has named prefix and number groups. [A-Z] and [0-9] implement this fictional ASCII code specification, while the suffix remains text. AB-0007 therefore yields prefix AB and suffix 0007, without a numeric conversion that would erase zeroes.

Malformed bad, a missing source field and full-width-digit text are retained as separate input rows. Their extraction fields are unknown, but state is invalid, missing and invalid respectively. Without the explicit state column, an all-missing extraction result could conceal why parsing failed. This code format does not prohibit Unicode generally; it merely enforces the declared alphabet for this particular field. Tests also require full-string matching so a valid substring inside extra text cannot pass.

Exercise 5: Write a real Parquet payload with explicit fields#

Inputs: Exactly record_id,group,amount_cents columns: unique nonmissing string IDs, nonmissing nominal categorical groups and nullable Int64 amounts. Input is a small trusted fixture.

Expected: Return actual in-memory Parquet bytes with the explicit non-null string/dictionary fields and nullable signed-int64 amount schema. Exclude the row index, retain business columns, and never mutate the input frame.

Verify: Inspect the real Arrow field schema and compare a deep original frame after writing. Preserve exact large integer and missing amount meanings through the subsequent independently checked readback.

The writer validates the complete three-column table, including unique string IDs, known nominal groups and nullable Int64 amounts. Its Arrow schema fixes the logical field types and nullability before serialization.

table = pa.Table.from_pandas(frame, schema=schema, preserve_index=False, safe=True)
pq.write_table(table, sink, compression="NONE", use_dictionary=["group"])

The business identity is the explicit record ID column. A pandas row index is deliberately excluded from this export, so a custom index would need another declared representation if it carried meaning. Nominal dictionary encoding is a representation of group labels; consumers still need the labels and domain contract. The fixture's bytes are actual Parquet, not a JSON imitation labelled with a Parquet suffix.

The code keeps a deep input copy and compares it after writing. Serialization must not repair the caller's keys, replace missing amounts with zero or mutate its category metadata. Byte equality across different writer versions is not the acceptance criterion. Logical schema and exact meaning are checked by the reader and independent roundtrip comparison.

Exercise 6: Accept only compatible readback meaning#

Inputs: Small trusted Parquet bytes from the exercise and an explicit allowed category tuple. The encoded-byte limit is not a sandbox for arbitrary hostile binary inputs.

Expected: Reject incompatible field order/types/nullability or invalid business identities/domains, then return the declared string/category/Int64 pandas table with a fresh row index. Validate observed labels before casting and restore the consumer-declared category domain.

Verify: Use assert_frame_equal against the explicit original business table, including unknown positions, exact integers and unused category metadata. Reject a readable Parquet file with an incompatible integer-ID schema.

The reader operates on tiny trusted bytes made by the example. It checks the decoded Arrow schema against the expected field order, types and nullability. A valid Parquet file with an incompatible integer record-ID field is rejected.

if not table.schema.equals(expected_schema, check_metadata=False):
    raise ValueError("Parquet logical schema does not match the contract")

Library metadata unrelated to this explicit field contract is not required to be byte-identical. The reader reconstructs string and nullable integer pandas representations only after type compatibility is established. It checks observed group labels against the supplied consumer domain before reapplying categorical metadata, including any declared unused categories. This does not infer domain authority merely from a producer's file metadata.

Finally, the same table boundary checks unique nonmissing IDs, known groups and the declared amount dtype. assert_frame_equal compares complete values, unknown positions, dtypes and categories with the original table after the intentionally excluded row index is reset. A row count or total amount alone would miss changed IDs and rounded integers. Encoded-byte bounds and schema inspection do not make an arbitrary binary parser safe for hostile files; input preparation and process resource containment remain separate from this compatibility exercise.

"""python-pandas-07: exact identity, typed parsing and Parquet references.

Parquet examples use tiny trusted bytes created by this program. Validating a
schema after decoding is not containment for arbitrary untrusted binary files.
"""

from __future__ import annotations

import csv
import re
from io import BytesIO, StringIO

import pandas as pd  # type: ignore[import-untyped]
import pyarrow as pa
import pyarrow.parquet as pq

_INTEGER = re.compile(r"[+-]?[0-9]+\Z")
_CODE = re.compile(r"\A(?P<prefix>[A-Z]{2})-(?P<number>[0-9]{4})\Z")
_COLUMNS = ["record_id", "group", "amount_cents"]
_SCHEMA = pa.schema(
    [
        pa.field("record_id", pa.string(), nullable=False),
        pa.field("group", pa.dictionary(pa.int32(), pa.string()), nullable=False),
        pa.field("amount_cents", pa.int64(), nullable=True),
    ]
)


def _strings(values: pd.Series) -> None:
    if not isinstance(values, pd.Series) or not isinstance(values.dtype, pd.StringDtype):
        raise ValueError("Expected an explicitly typed pandas string Series")


def _domain(allowed: tuple[str, ...]) -> None:
    if (
        not isinstance(allowed, tuple)
        or not allowed
        or any(not isinstance(value, str) or not value for value in allowed)
        or len(set(allowed)) != len(allowed)
    ):
        raise ValueError("Expected a nonempty unique tuple of category strings")


# Exercise 1: Preserve identity and validate CSV structure.
def read_identity_csv(text: str) -> pd.DataFrame:
    """Preserve literal NA and leading-zero IDs; parse amounts without a float stage."""
    if not isinstance(text, str):
        raise ValueError("Expected CSV text")
    try:
        records = list(csv.reader(StringIO(text), strict=True))
    except csv.Error as error:
        raise ValueError("Malformed CSV quoting") from error
    if not records or records[0] != _COLUMNS or any(len(row) != 3 for row in records[1:]):
        raise ValueError("Every CSV record must have the three declared fields")
    frame = pd.read_csv(
        StringIO(text),
        dtype="string",
        keep_default_na=False,
        skip_blank_lines=False,
        index_col=False,
    )
    if (
        list(frame.columns) != _COLUMNS
        or frame["record_id"].eq("").any()
        or frame["record_id"].duplicated().any()
        or frame["group"].eq("").any()
    ):
        raise ValueError("Expected unique known record IDs, known groups and the declared columns")
    frame["amount_cents"] = strict_int64(frame["amount_cents"])
    return frame


# Exercise 2: Parse exact signed integer text.
def strict_int64(values: pd.Series) -> pd.Series:
    """Parse signed ASCII integer text exactly; only empty strings/NA mean missing."""
    _strings(values)
    parsed: list[int | None] = []
    for value in values:
        if value is pd.NA or value == "":
            parsed.append(None)
        elif _INTEGER.fullmatch(value) is None:
            raise ValueError("Expected integer text without decimal, exponent or whitespace")
        else:
            number = int(value)
            if not -(2**63) <= number < 2**63:
                raise ValueError("Integer text is outside signed int64 range")
            parsed.append(number)
    return pd.Series(pd.array(parsed, dtype="Int64"), index=values.index.copy(), name=values.name)


# Exercise 3: Reject unknown labels before categorical conversion.
def known_categories(values: pd.Series, allowed: tuple[str, ...]) -> pd.Series:
    """Reject unknown observed labels before converting to a nominal categorical."""
    _strings(values)
    _domain(allowed)
    if (values.notna() & ~values.isin(allowed)).any():
        raise ValueError("Observed category is outside the declared domain")
    return values.astype(pd.CategoricalDtype(categories=list(allowed), ordered=False))


# Exercise 4: Retain valid, invalid and missing text states.
def extract_codes(values: pd.Series) -> pd.DataFrame:
    """Retain valid/invalid/missing states while extracting exact ASCII code parts."""
    _strings(values)
    valid = values.str.fullmatch(_CODE, na=False)
    parts = values.str.extract(_CODE)
    state = pd.Series("invalid", index=values.index, dtype="string")
    state = state.mask(values.isna(), "missing").mask(valid, "valid")
    parts["state"] = state
    return parts


def _checked_frame(frame: pd.DataFrame) -> None:
    if not isinstance(frame, pd.DataFrame) or list(frame.columns) != _COLUMNS:
        raise ValueError("Expected exactly record_id, group, amount_cents columns")
    _strings(frame["record_id"])
    if (
        frame["record_id"].isna().any()
        or frame["record_id"].eq("").any()
        or frame["record_id"].duplicated().any()
        or not isinstance(frame["group"].dtype, pd.CategoricalDtype)
        or frame["group"].dtype.ordered
        or frame["group"].isna().any()
        or str(frame["amount_cents"].dtype) != "Int64"
    ):
        raise ValueError("Expected unique string IDs, known nominal categories and Int64 amounts")
    _domain(tuple(frame["group"].cat.categories))


# Exercise 5: Serialize real Parquet under an explicit business schema.
def parquet_bytes(frame: pd.DataFrame) -> bytes:
    """Serialize the explicit business columns and nullable schema, without row-index metadata."""
    _checked_frame(frame)
    table = pa.Table.from_pandas(frame, schema=_SCHEMA, preserve_index=False, safe=True)
    sink = BytesIO()
    pq.write_table(table, sink, compression="NONE", use_dictionary=["group"])  # type: ignore[no-untyped-call]
    return sink.getvalue()


# Exercise 6: Enforce logical compatibility and consumer domain.
def read_parquet_payload(payload: bytes, allowed: tuple[str, ...]) -> pd.DataFrame:
    """Validate logical schema/domain and restore declared pandas representations.

    Only use this exercise with tiny trusted bytes. The encoded-byte bound
    below does not bound a general Parquet decoder's memory requirements.
    """
    _domain(allowed)
    if not isinstance(payload, bytes) or not 1 <= len(payload) <= 1_000_000:
        raise ValueError("Expected a small trusted Parquet byte payload")
    table = pq.read_table(BytesIO(payload))  # type: ignore[no-untyped-call]
    if not table.schema.equals(_SCHEMA, check_metadata=False):
        raise ValueError("Parquet logical field order/types/nullability do not match the contract")
    frame = table.to_pandas()
    frame["record_id"] = frame["record_id"].astype("string")
    # Check values against the caller's declared domain before the cast. An
    # unknown category must never disappear into a newly manufactured NA.
    frame["group"] = known_categories(frame["group"].astype("string"), allowed)
    frame["amount_cents"] = frame["amount_cents"].astype("Int64")
    _checked_frame(frame)
    return frame


def verify_examples() -> None:
    source = (
        "record_id,group,amount_cents\n"
        "00017,red,9007199254740993\n"
        "NA,blue,\n"
        "00019,red,9223372036854775807\n"
    )
    frame = read_identity_csv(source)
    assert frame.record_id.tolist() == ["00017", "NA", "00019"]
    assert frame.amount_cents.iloc[0] == 9007199254740993
    assert pd.isna(frame.amount_cents.iloc[1])
    assert frame.amount_cents.iloc[2] == 2**63 - 1
    for bad in [
        "record_id,group,amount_cents\nid,red,2,3\n",
        "record_id,group,amount_cents\nid,red\n",
        "record_id,group,amount_cents\nid,red,2\n\n",
    ]:
        try:
            read_identity_csv(bad)
        except ValueError:
            pass
        else:
            raise AssertionError("A ragged or blank CSV record changed column meaning")
    parsed = strict_int64(pd.Series([str(-(2**63)), "+0002", "", pd.NA], dtype="string"))
    assert parsed.iloc[0] == -(2**63) and parsed.iloc[1] == 2 and parsed.isna().sum() == 2
    for text in ["1.0", "1e3", " 2", "٢", str(2**63), str(-(2**63) - 1)]:
        try:
            strict_int64(pd.Series([text], dtype="string"))
        except ValueError:
            pass
        else:
            raise AssertionError("Invalid or out-of-range integer text was accepted")
    allowed = ("red", "blue", "green")
    frame["group"] = known_categories(frame["group"], allowed)
    assert list(frame.group.cat.categories) == list(allowed)
    try:
        known_categories(pd.Series(["purple", pd.NA], dtype="string"), allowed)
    except ValueError:
        pass
    else:
        raise AssertionError("An unknown category was silently converted to missing")
    codes = extract_codes(pd.Series(["AB-0007", "bad", pd.NA, "AB-０００７"], dtype="string"))
    assert codes.state.tolist() == ["valid", "invalid", "missing", "invalid"]
    assert codes.number.iloc[0] == "0007" and codes.prefix.iloc[0] == "AB"
    assert codes.number.iloc[1:].isna().all()
    original = frame.copy(deep=True)
    payload = parquet_bytes(frame)
    restored = read_parquet_payload(payload, allowed)
    pd.testing.assert_frame_equal(restored, frame.reset_index(drop=True))
    pd.testing.assert_frame_equal(frame, original)
    wrong = BytesIO()
    pq.write_table(pa.table({"record_id": [17]}), wrong)  # type: ignore[no-untyped-call]
    try:
        read_parquet_payload(wrong.getvalue(), allowed)
    except ValueError:
        pass
    else:
        raise AssertionError("An incompatible logical schema was accepted")
    print("python-pandas-07: all six typed-I/O and domain contracts passed")


if __name__ == "__main__":
    verify_examples()
