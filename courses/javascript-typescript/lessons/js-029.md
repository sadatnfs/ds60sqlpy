# js-029: The DOM, events and accessible interaction

Use the browser fixture and record predictions before inspecting solutions.

## Exercises

1. **Use a native button and live result.** Open the complete snippet, activate Add twice by pointer and once by keyboard, then inspect the count.
   **Expected:** count 3; button remains keyboard reachable.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

2. **Trace target and currentTarget through delegation.** Click the nested word inside the list button in the snippet.
   **Expected:** selected A; target SPAN and currentTarget UL.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

3. **Handle a dynamically appended action.** Create a new list item with button B after the listener is installed and activate it.
   **Expected:** the existing ancestor listener reports B without a new per-button listener.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

4. **Implement an accessible disclosure.** Toggle a details region and keep hidden and aria-expanded synchronized.
   **Expected:** opening reveals details and sets true; closing hides it and sets false.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

5. **Remove listeners through their lifecycle signal.** Attach a counter listener with a signal, click once, abort, and click again.
   **Expected:** the count stops increasing after abort.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

6. **Diagnose a missing required element.** Query a deliberately absent id and report the failed startup contract.
   **Expected:** null is detected before accessing a property.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.
