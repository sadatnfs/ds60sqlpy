# c-013: Preprocessing, macros and compile-time contracts

## Purpose and mental model

The preprocessor transforms tokens before the compiler performs ordinary type checking. Header inclusion, conditional compilation and macros can be useful, but a macro is not a normal function. Its arguments may be substituted more than once, and missing parentheses can change expression grouping. Side-effecting arguments such as increments are therefore hazardous in many function-like macros. Prefer typed functions or static inline functions for behavior when possible. Use macros for configuration and declarations that need preprocessing, and keep conditional platform code small and documented. The same source should not silently change semantic contracts because a build flag was forgotten.

## Vocabulary and concepts

- **Macro expansion:** Token replacement before ordinary compilation.
- **Repeated evaluation:** An argument expression being executed multiple times after substitution.
- **Compile-time assertion:** A condition required for successful translation.

## Syntax anatomy and execution trace

#define creates a macro replacement. Parenthesize each expression argument and the full result, but understand that this does not prevent repeated evaluation. #if and #ifdef select tokens before compilation. Include guards prevent repeated header definitions. _Static_assert checks a constant expression during compilation. _Generic can select an expression by type in C11 and later without becoming a runtime type system.

## Worked example / walkthrough

### Worked example 1: Use a parenthesized macro safely

Square the side-effect-free expression 2+3.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

#define SQUARE(x) ((x) * (x))
#define LESSON_CAPACITY 8
#define TYPE_LABEL(x)                                                          \
  _Generic((x), int: "integer", double: "floating", default: "other")
int square_int(int value) { return value * value; }

int main(void) {
  /* Use a parenthesized macro safely */
  {
    CHECK(SQUARE(2 + 3) == 25);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result is 25.

Parentheses preserve grouping. This macro still evaluates its argument twice, so side effects remain inappropriate.

### Worked example 2: Prefer a typed helper for mutation

Pass value++ to a normal square function.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

#define SQUARE(x) ((x) * (x))
#define LESSON_CAPACITY 8
#define TYPE_LABEL(x)                                                          \
  _Generic((x), int: "integer", double: "floating", default: "other")
int square_int(int value) { return value * value; }

int main(void) {
  /* Use a parenthesized macro safely */
  {
    CHECK(SQUARE(2 + 3) == 25);
  }

  /* Prefer a typed helper for mutation */
  {
    int value = 3;
    int result = square_int(value++);
    CHECK(result == 9 && value == 4);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result is 9 and value increments once to 4.

A function argument expression is evaluated once for this call. SQUARE(value++) would create an unsequenced modification hazard.

### Exercise 1: Use a parenthesized macro safely: predict an edited check

In worked example 1, change `CHECK(SQUARE(2 + 3) == 25);` to `CHECK(SQUARE(3 + 3) == 25);`. Predict whether the CHECK still holds and why, then run and restore.

**Expected:** `Check failed`: `CHECK(SQUARE(3 + 3) == 25);` is false, although the result is 25.

**Verify:** Explain which claim `CHECK(SQUARE(3 + 3) == 25);` makes that the state fails; restoring `CHECK(SQUARE(2 + 3) == 25);` passes again.

### Exercise 2: Prefer a typed helper for mutation: debug a regression

**Expected:** `Check failed` at `result == 9 && value == 4` until the line reads `int value = 3;` again.

**Verify:** Explain how `int value = 4;` changes the value `result == 9 && value == 4` tests, using your failing and repaired runs.

**Progressive hints:** First trace `result` and `value` from initialization. Then compare `int value = 4;` with worked example 2's original line.

### Exercise 3: Require a representation fact

Check the language-required char size at translation time.

**Expected:** Compilation accepts the true static assertion.

**Verify:** Keep a CHECK equivalent to `sizeof(char) == 1`. Control edit: `CHECK(sizeof(char) != 1);` must fail; then restore it.

**Progressive hints:** First evaluate `sizeof(char) == 1` by hand. Then recall: A compile-time invariant fails before execution.

### Exercise 4: Read a configuration constant

Use a fixed capacity macro of 8.

**Expected:** The declared buffer has eight elements.

**Verify:** Keep a CHECK equivalent to `sizeof values / sizeof values[0] == 8`. Control edit: `CHECK(sizeof values / sizeof values[0] != 8);` must fail; then restore it.

**Progressive hints:** First trace `values` from initialization. Then recall: Configuration macros can express shared compile-time sizes.

### Exercise 5: Select by a simple type

Use a generic selection for int and double expressions.

**Expected:** The selected labels are integer and floating.

**Verify:** Keep a CHECK equivalent to `strcmp(TYPE_LABEL(3.0), "floating") == 0`. Control edit: `CHECK(strcmp(TYPE_LABEL(3.0), "floating!") == 0);` must fail; then restore it.

**Progressive hints:** First work out what `strcmp` and `TYPE_LABEL` return here. Then recall: _Generic chooses from declared compatible types at translation time.

### Exercise 6: Transfer an inline-style function contract

Square zero and negative three through the typed helper.

**Expected:** The results are 0 and 9.

**Verify:** Keep a CHECK equivalent to `square_int(0) == 0 && square_int(-3) == 9`. Control edit: `CHECK(square_int(1) == 0 && square_int(-3) == 9);` must fail; then restore it.

**Progressive hints:** First work out what `square_int` returns here. Then recall: The helper has ordinary type checking and one evaluation per argument.

## Common pitfalls and diagnosis

Writing `#define SQUARE(x) x * x`: `SQUARE(1 + 2)` expands to `1 + 2 * 1 + 2`, which is 5. Passing `i++` to a macro that names its argument twice increments twice; prefer a typed `static inline` function for anything with side effects.
