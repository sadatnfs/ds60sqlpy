## Reuse past computation only when its meaning is unchanged

During generation, the prefix grows one token at a time. A simple implementation can rerun the entire decoder on the full prefix before every next-token choice. That repeats work for earlier positions whose causal representations should not have changed. A key/value cache stores the relevant past attention projections so the new token can use them without recomputing the whole prefix. The optimization is justified by the information boundary, not merely by the fact that arrays can be concatenated.

Follow the literal prefix [2,5,7,3]. A full pass produces logits with shape [1,4,16]. An incremental pass first sends token 2, storing its keys and values at position zero. It then sends token 5 with the one-position cache, so its position embedding uses index one and its query can read keys zero and one. The next calls use offsets two and three. Each call returns [1,1,16] logits; concatenating the four outputs should match the full result within the specified float32 tolerance.

The cache after four tokens contains K and V arrays shaped [1,2,4,16]: one batch row, two heads, four positions and sixteen features per head. Both arrays are needed because keys score relevance while values supply the mixed features. Their raw float32 data occupies 2*1*2*4*16*4=1,024 bytes for this single attention layer. That calculation excludes Python metadata, parameters, temporary buffers and any additional layers. It describes stored tensor values, not measured process memory.

Causal masking must use absolute positions in the incremental call. At the fourth call the query has local row index zero but absolute position three. It may attend to all four stored key positions. A naive lower triangle of shape [1,4] would allow only the first column, confusing local tensor coordinates with sequence positions. Correct shape alone cannot reveal this error; comparing with the full-prefix oracle can.

Why are past values reusable? Under the model's causal computation, the representation of an earlier token did not depend on the tokens appended later. Its keys and values are therefore the same ones a fresh full-prefix calculation would produce, assuming the same model, position policy and evaluation behavior. In a multilayer model, each layer needs its own cache because it projects a different hidden representation. Editing an earlier prefix token or changing model weights can invalidate later stored states that depended on them.

Ownership is consequently part of numerical correctness. The fixture binds the cache to request A and model label v1, rejecting request B or label v2. The surrounding application must ensure those labels identify the actual artifacts and context. A cache from another conversation can have perfectly compatible dimensions while representing the wrong information. Starting a new request with an empty cache avoids that accidental context transfer.

Caching removes repeated past projections and hidden-state work, but the new query still compares with the stored keys and mixes stored values. Context length therefore continues to affect work and storage. The detached cache in this lesson is for inference; reusing it while expecting full-prefix training gradients would change the differentiable computation. The exact parity test establishes the local optimization's semantics before any claim about throughput or deployment scale is considered.
