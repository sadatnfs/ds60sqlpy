# c-001: Source, compilation, linking and checked execution

## Level and prerequisites

Beginner, approximately 90 minutes plus a later retrieval session. Direct prerequisites: None. Begin with the difference between source text, a compiler and a running process.

## Learning objectives

Compile, link and run a one-file C17 program whose checks fail loudly instead of printing an unchecked result. Along the way, explain translation unit, linker and assertion. Implement the six investigations, from the "check a first value" case to the "transfer a receipt calculation" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

C source is text describing declarations and operations. The preprocessor handles directives, the compiler translates a translation unit, and the linker combines machine-code objects with required libraries. The executable is a separate artifact from main.c. A syntax error prevents compilation; an unresolved symbol prevents linking; an assertion can fail only after execution begins. These stages require different diagnoses. C does not automatically validate every runtime memory operation, so successful compilation is a starting point rather than a safety proof. Begin with independently checked scalar results before learning pointers and resource ownership.

## Vocabulary and concepts

- **Translation unit:** The source after preprocessing, compiled as one unit.
- **Linker:** The tool resolving references among compiled objects and libraries.
- **Assertion:** An explicit runtime check of a claimed property.

## Syntax anatomy and execution trace

#include makes header declarations available. int main(void) is an entrypoint with no parameters; returning zero signals successful termination. Braces form a block and semicolons finish most statements. printf formats values, while puts writes a string plus a newline. assert from assert.h checks a condition when NDEBUG is not defined. %d expects an int, and a mismatched format argument can be undefined behavior.

## Worked example / walkthrough

### Worked example 1: Check a first value

Store 2 plus 3 in an int.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int seven(void) { return 7; }

int main(void) {
  /* Check a first value */
  {
    int total = 2 + 3;
    CHECK(total == 5);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The stored value is 5.

The expectation is known independently of the program. A print statement alone would not reject a wrong calculation.

### Worked example 2: Format a checked result

Format total=5 into a bounded character buffer.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int seven(void) { return 7; }

int main(void) {
  /* Check a first value */
  {
    int total = 2 + 3;
    CHECK(total == 5);
  }

  /* Format a checked result */
  {
    char out[16];
    int n = snprintf(out, sizeof out, "total=%d", 5);
    CHECK(n == 7);
    CHECK(strcmp(out, "total=5") == 0);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result length is 7 and text is total=5.

snprintf returns the length that would be required, excluding the terminating null byte. A caller must compare it with capacity before treating output as complete.

## Prediction before execution

Predict worked example 1: when you store 2 plus 3 in an int, the CHECK on `total == 5` should see that the stored value is 5. For the "format a checked result" case, predict that the result length is 7 and text is total=5. Write down the declared size of `out[16]` before indexing it.

## Exercises

How the hints, control edits and regressions below work: [Work an exercise](../STUDY-GUIDE.md#work-an-exercise).

### Exercise 1: Check a first value: change one input

In worked example 1, change `int total = 2 + 3;` to `int total = 3 + 3;`. Predict which value the CHECK on `total == 5` sees, then run and restore.

**Expected:** `Check failed` at `total == 5`; restoring `int total = 2 + 3;` passes again.

**Verify:** Name the value that made `total == 5` false, where worked example 1 showed that the stored value is 5.

**Progressive hints:** First trace `total` from initialization. Then compute what the CHECK sees with `int total = 3 + 3;` in place.

### Exercise 2: Format a checked result: debug a regression

Worked example 2 now has a line reading `int n = snprintf(out, sizeof out, "total=%d", 6);`. Repair it so that the result length is 7 and text is total=5 again.

**Expected:** `Check failed` at `strcmp(out, "total=5") == 0` until the line reads `int n = snprintf(out, sizeof out, "total=%d", 5);` again.

**Verify:** Explain how `int n = snprintf(out, sizeof out, "total=%d", 6);` changes the value `strcmp(out, "total=5") == 0` tests, using your failing and repaired runs.

**Progressive hints:** First trace `out` from initialization. Then compare `int n = snprintf(out, sizeof out, "total=%d", 6);` with worked example 2's original line.

### Exercise 3: Trace statement order

Start at 1, increment, then multiply by 3.

**Expected:** The result is 6.

**Verify:** Keep a CHECK equivalent to `count == 6`. Control edit: changing `count += 1;` to `count -= 1;` must fail it; then restore it.

**Progressive hints:** First trace `count` from initialization. Then recall: Changing operation order changes the state trajectory.

### Exercise 4: Inspect a boolean condition

Compare 4 with 4 and 4 with 5.

**Expected:** Equality is true and inequality is true.

**Verify:** Keep a CHECK equivalent to `same && different`. Control edit: changing `bool same = (4 == 4);` to `bool same = (4 != 4);` must fail it; then restore it.

**Progressive hints:** First trace `same` and `different` from initialization. Then recall: An equality expression compares values.

### Exercise 5: Use an explicit return contract

Call a helper returning the value 7.

**Expected:** The caller receives 7.

**Verify:** Keep a CHECK equivalent to `seven() == 7`. Control edit: `CHECK(seven() != 7);` must fail; then restore it.

**Progressive hints:** First work out what `seven` returns here. Then recall: The declaration gives the compiler a return-type contract.

### Exercise 6: Transfer a receipt calculation

Multiply 4 items by a unit amount of 6.

**Expected:** The checked amount is 24.

**Verify:** Keep a CHECK equivalent to `amount == 24`. Control edit: changing `int amount = items * unit;` to `int amount = items + unit;` must fail it; then restore it.

**Progressive hints:** First trace `amount` from initialization. Then recall: These small values fit int.

## Common pitfalls and diagnosis

Reading a linker error as a syntax error: `undefined reference to` means every file compiled but no definition was found for a declared name. Fix the missing definition or the missing file on the command line, not the call site.

General diagnosis order and the pointer checklist: [Diagnose failures](../STUDY-GUIDE.md#diagnose-failures).
