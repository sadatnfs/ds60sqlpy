clp-017: Prediction is a distinct estimand#

Tutorial mode. Stage: advanced. Direct prerequisites: clp-006, bayes-011.

Specify what is being predicted#

A fitted mean curve, a new noisy observation from an existing group and an observation from a new group are different estimands. They can share the same point expectation while requiring different uncertainty calculations. A plot with one unlabeled shaded band hides that distinction and can lead a learner to use an interval for the mean as if it covered individual outcomes.

This approximates sampling uncertainty in the fitted mean. If a future observation adds independent noise of variance σ2\sigma^2σ2, its approximate variance adds that term. If a new group additionally contributes an independent random intercept of variance τ2\tau^2τ2, add that term as well. Conditional prediction for an already observed correlated group can require a different mean and variance, as in the capstone.

These are not two numerical approximations to the same target. They are different summaries of a skewed predictive distribution. The program prints both so that a transformed regression prediction cannot silently be labeled an arithmetic mean.

The variance in this identity is the variance of the modeled future log outcome. If a predictive distribution also integrates over uncertain parameters, that integration must be treated explicitly. Simply plugging a coefficient standard error into the lognormal formula is not automatically the correct posterior or frequentist predictive expectation.

Coordinates, assumptions and debugging#

The covariance and Jacobian must use the same parameter coordinates. A covariance for (log⁡a,log⁡b,c)(\log a,\log b,c)(loga,logb,c) cannot be multiplied directly by a Jacobian with respect to (a,b,c)(a,b,c)(a,b,c). Either transform the covariance with the relevant Jacobian or differentiate the prediction in the original optimization coordinates. Unit conversions also transform covariance, not just parameter point values.

The simple variance additions assume independence of the contributing terms. For existing-group predictions, estimated residual histories and fitted parameters can be correlated. A full joint calculation or resampling analysis may be needed. The capstone clearly labels its simplified plug-in band so that these omitted cross terms are visible.

Extrapolation adds model risk that a narrow parameter interval may not represent. A decay model can approach a well-estimated asymptote while being scientifically wrong beyond an intervention or regime change. Assess predictive performance on appropriate held-out times and groups, and report the range over which the model was evaluated.

Answered review questions#

Why is an observation interval wider than a mean interval? A future outcome includes irreducible observation variation in addition to uncertainty in the expected value. More training data can reduce the latter without eliminating the former.

Does a new-group interval always need an extra term? Only under a model with new-group heterogeneity not already included in the other terms. Adding the same random-effect variance twice is as wrong as omitting it.

What should accompany a forecast? State whether it is a mean, median or quantile; the conditioning information; the horizon and units; the uncertainty construction; and which sources of uncertainty remain omitted.

"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json
import math

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def mean_curve(theta, time):
    return theta[0] * torch.exp(-theta[1] * time) + theta[2]


def prediction_components(theta, covariance, time, observation_variance, new_group_variance):
    if observation_variance < 0 or new_group_variance < 0:
        raise ValueError("Variance components must be nonnegative")
    gradient = torch.autograd.functional.jacobian(lambda p: mean_curve(p, time), theta)
    mean_variance = torch.einsum("ij,jk,ik->i", gradient, covariance, gradient)
    if bool((mean_variance < 0).any()):
        raise ValueError("Parameter covariance implies negative forecast variance")
    return (
        mean_variance,
        mean_variance + observation_variance,
        mean_variance + observation_variance + new_group_variance,
    )


def run_cases():
    theta = tensor([2.4, 0.65, 0.7])
    covariance = torch.diag(tensor([0.04, 0.0025, 0.01]))
    time = tensor([0, 2, 6])
    vm, vo, vg = prediction_components(theta, covariance, time, 0.09, 0.16)
    assert bool(torch.all(vm < vo) & torch.all(vo < vg))
    gradient = torch.autograd.functional.jacobian(lambda p: mean_curve(p, time), theta)
    analytic = torch.stack(
        [
            torch.exp(-theta[1] * time),
            -theta[0] * time * torch.exp(-theta[1] * time),
            torch.ones_like(time),
        ],
        dim=1,
    )
    assert torch.allclose(gradient, analytic)
    mean = mean_curve(theta, time)
    rows = [
        {
            "time": float(t),
            "mean": float(m),
            "mean_se": float(a.sqrt()),
            "observation_sd": float(b.sqrt()),
            "new_group_sd": float(c.sqrt()),
        }
        for t, m, a, b, c in zip(time, mean, vm, vo, vg, strict=True)
    ]
    latent_mean, latent_variance = 0.4, 0.36
    median = math.exp(latent_mean)
    expectation = math.exp(latent_mean + latent_variance / 2)
    assert expectation > median
    return {
        "forecast_components": rows,
        "lognormal_median": median,
        "lognormal_mean": expectation,
        "interval_multiplier": 1.96,
        "covariance_is_supplied_for_delta_method_demonstration": True,
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
