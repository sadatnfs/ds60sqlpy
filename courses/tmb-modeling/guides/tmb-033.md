# Normalizing a latent process

Start with: tmb-032, tmb-013.

Outcome: Explain why process normalization depends on parameters and affects estimation.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A latent quadratic penalty is not automatically a normalized density. If \(u\) has precision \(Q(\theta)\), its Gaussian NLL is \(\frac12u^TQu-\frac12\log|Q|+\frac q2\log(2\pi)\). Omitting the determinant changes the objective whenever the precision depends on estimated parameters.

`normalize(obj, flag, value=0)` provides automatic process normalization for a suitable template. The template must have a data flag that disables observation terms, leaving only the unnormalized process contribution. This is a specific interface requirement, not a function that can infer arbitrary missing likelihood terms from source code.

### Worked case A: the missing determinant

The companion evaluates a one-dimensional quadratic process at two scales. Its unnormalized integral depends on scale. Adding the correct normalizer makes the integral one. The difference shows why a parameter-dependent “constant” cannot be dropped merely because it does not involve the latent state.

The process flag must disable every observation contribution while preserving the intended process density. If it also disables part of the prior precision or leaves an observation term active, normalization addresses the wrong function. Test the flag explicitly on a tiny known model before using it for a difficult process.

### Worked case B: an improper process

A random-walk difference penalty without an anchored level can be invariant to adding the same constant to every state. Its precision is singular and the integral over the unconstrained level diverges. The companion demonstrates a zero eigenvalue. No numerical normalizer can turn an improper unrestricted density into a proper one without adding a constraint, boundary distribution or other scientific assumption.

Our existing random-intercept and AR1 templates include their analytic normalizers and do not need this helper. The new API lesson explains when `normalize` would be appropriate rather than wrapping an already normalized model and accidentally changing the target.

### Answered discussion

**Is normalization just subtracting the minimum?** No. A density's integral, not its peak, must equal one. **Does a Laplace normalization become exact for every process?** No. Exactness requires an appropriate special case or independent proof. **Can a singular intrinsic model be used at all?** Yes with explicit constraints or a formulation that accounts for its improper components, but that is a different model contract.

Consult [normalize in the TMB manual](https://cran.r-project.org/web/packages/TMB/TMB.pdf) and validate a new flag-enabled template before advertising its compiled capability.

### Complete R companion

```r
for (tau in c(.5, 2)) {
  raw_integral <- integrate(function(u) exp(-u^2 / (2 * tau^2)), -Inf, Inf)$value
  normalized <- raw_integral / (sqrt(2 * pi) * tau)
  print(c(tau = tau, raw_integral = raw_integral, normalized = normalized));stopifnot(abs(normalized - 1) < 1e-8)
}
D <- matrix(c(-1, 1, 0, 0, -1, 1), 2, 3, byrow = TRUE)
Q <- crossprod(D)
print(eigen(Q, symmetric = TRUE)$values);stopifnot(max(abs(Q %*% rep(1, 3))) < 1e-12)
```
