# dbt-016: Metric contracts and valid denominators

## Level and prerequisites

Advanced. Direct prerequisites: `dbt-004`, `dbt-007`

**Outcome:** Publish a metric with a complete numerator/denominator contract and an independent check.

## Question and mechanism

A metric is a defined quantity, not merely a SQL expression. Its contract names the population, unit of analysis, numerator, denominator, time window and treatment of missing or invalid records. Two expressions can both execute and still answer different questions. The first responsibility is to define the desired quantity.

The worked fixture pools successes and trials by cohort. Cohort A contains rows with very different trial counts, so averaging row-level rates gives a misleading result for the pooled-trial question. This is the same statistical issue seen in the Polars path, now expressed in a tested warehouse model. The transfer matters because a semantic error can survive changes in language or tooling.

The examples use ordinary dbt models and SQL. They do not claim to run a hosted semantic layer or MetricFlow service. A future semantic-layer integration should preserve these contracts and test its actual query semantics. Installing another tool would not decide the correct denominator.

## Syntax and data contract

Aggregate numerator and denominator separately, then divide with a declared zero-denominator policy. Keep the denominator in the output for review and uncertainty calculations. A GROUP BY changes result grain, so identify its keys explicitly. Avoid using an unweighted AVG of precomputed rates unless equal-row weighting is the intended estimand.

## Worked case 1: Compute cohort-level pooled rates

The valid model retains trial counts beside rates. The program checks exact cohort values in the actual DuckDB relation. This makes both the weighting and the evidence amount visible.

**Expected evidence:** Cohort A is 0.1 from 100 trials; cohort B is 0.5 from 2 trials.

```python
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def example_one():
    with tempfile.TemporaryDirectory() as d:
        p = project(
            d,
            models={
                "metrics": (
                    "select cohort, sum(successes)::double/nullif(sum(trials),0"
                    ") as rate, sum(trials) as denominator from {{ "
                    "ref('counts') }} group by cohort"
                )
            },
            seeds={"counts": "cohort,successes,trials\nA,1,1\nA,9,99\nB,1,2\n"},
        )
        invoke(p, "build")
        assert rows(p, "select cohort,rate,denominator from metrics order by cohort") == [
            ("A", 0.1, 100),
            ("B", 0.5, 2),
        ]
        return {"rates": {"A": 0.1, "B": 0.5}, "denominators": {"A": 100, "B": 2}}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Execute a mathematically different metric

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Write the population

Specify which trial records belong in the metric.

**Check:** The inclusion and time rules are explicit.

**Hint:** A WHERE clause should implement a definition.


### 2. Pool across cohorts

Compute the all-trial rate.

**Check:** The rate is 11/102.

**Hint:** Use count weighting.


### 3. Test empty evidence

Add a zero-trial cohort.

**Check:** Its rate follows an explicit undefined-value policy.

**Hint:** No trials do not prove zero success probability.


### 4. Preserve counts

Show numerator and denominator with every rate.

**Check:** The estimate can be independently reconstructed.

**Hint:** A percentage loses sample-size information.


### 5. Prevent join inflation

Add a duplicate descriptive dimension and test reconciliation.

**Check:** The gate detects changed totals or cardinality.

**Hint:** A valid metric can be corrupted by enrichment.


### 6. Review semantic-layer claims

Explain what extra qualification a metric service would need.

**Check:** It includes actual generated queries and equivalent outputs.

**Hint:** A declaration is not execution.


## Diagnose errors and misleading results

A large rate change may come from a changed denominator rather than a changed phenomenon. Inspect grouping, source coverage and join multiplicities. A query that compiles and passes key tests can still implement the wrong estimand. Make the metric definition and independent fixture arithmetic part of review.
