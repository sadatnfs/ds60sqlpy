## Use deliberate memorization to isolate the learning path

Generalization is the eventual objective of most model development, but it is difficult to diagnose a broken training system from a complicated held-out score. A smaller question comes first: can the implementation fit a tiny batch that it sees repeatedly? This deliberately easy experiment removes many sources of variation. If it fails, we can inspect the computation and update path before spending more time on data or scale.

The batch contains one input sequence [1,2,3] and targets [2,3,4]. The decoder has enough flexible parameters to memorize these three cases. The task does not require discovering a transferable grammar. Token and position representations can help distinguish the training positions, so success on this batch is intentionally weaker than language understanding. That weakness is useful because it makes failure suspicious and the expected direction of change straightforward.

Construct two independent models, then copy the first model's state into the second. They should begin with identical numerical parameters, not simply with constructors that happened to receive similar settings. One model will train; the other will remain a control. Independence matters: assigning control=trained would create two names for the same object, so both would change together and the comparison would be meaningless.

The no-update control runs the same batch five times and preserves a cloned state dictionary. In this dropout-free decoder, with no running batch statistics, the predictions and losses remain identical. That establishes the behavior expected when no learning intervention occurs. In a different architecture, training-mode dropout could change outputs without changing weights, and running statistics could change state without an optimizer step. The control must account for the particular model's stochastic and stateful components rather than assuming no_grad makes everything fixed.

The trained model receives thirty Adam updates. Its loss curve is finite and the last recorded training loss is lower than the first. That is evidence that the implemented parameters, objective and optimizer can fit the exposed mapping. It is not evidence that every internal component is necessary: a simpler route through the parameter space may already solve three cases. It also does not show that the final post-update loss equals the last pre-update curve point, a distinction introduced in the previous chapter.

If the trained curve does not improve while the control behaves correctly, inspect the first missing link. Are targets shifted rather than copied? Does the vocabulary axis contain sixteen scores? Do expected parameters receive gradients? Does the optimizer own those parameter objects? Are gradients cleared before, rather than after, backward? Does step actually run? These questions locate a mechanism failure more directly than repeatedly changing random seeds.

Once the diagnostic passes, restore a clean experimental setup for any generalization study. The repeatedly exposed batch is training data, and the report correctly records zero held-out examples. Reusing a model already tuned on a supposed test case would compromise the next comparison. The diagnostic earns confidence in the learning path, while held-out evaluation must earn confidence in transfer.
