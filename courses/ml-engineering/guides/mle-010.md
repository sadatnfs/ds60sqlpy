# mle-010: Actual MLflow tracking and artifact lineage

## Level and prerequisites

Intermediate. Direct prerequisites: `mle-008`, `mle-009`

**Outcome:** Use real tracking APIs to bind parameters, metrics, artifacts and terminal outcomes to an owned run.

## Question and mechanism

Experiment tracking records how a result was produced. Parameters describe choices, metrics describe measured outcomes, tags provide context and artifacts retain files such as contracts or model cards. The tracking record is useful only when those entries refer to the same actual run and source/data versions.

This lesson uses the actual MLflow client with an explicitly local SQLite backend and local artifact directory. It starts no tracking server and selects no ambient cloud workspace. The first case records a metric and a feature/data manifest, then reads both back through MLflow. The second records a failed run that still contains a measured training loss.

A retained metric is not proof that the complete workflow succeeded. Failures can occur after useful observations were produced. Keep the terminal status and the evidence that justified it. Similarly, an artifact named model-card does not establish that someone reviewed its contents; the fields and acceptance decision need their own contract.

## Syntax and data contract

MlflowClient receives explicit local tracking and registry URIs. create_experiment defines an owned experiment and artifact location, create_run obtains its identity, and log_param/log_metric/log_artifact attach evidence. set_terminated records the final status. get_run and list_artifacts establish actual stored readback rather than assuming a logging call was sufficient.

## Worked case 1: Record and retrieve a complete local run

The first case logs a threshold, Brier value and manifest file, marks the run finished and retrieves the stored metadata and artifact path. The manifest identifies feature order and a small data hash.

**Expected evidence:** The run is FINISHED, its metric is 0.2 and the evidence artifact is listed.

```python
import hashlib
import json
import os
import tempfile
from pathlib import Path


def configure_local_tools():
    os.environ.update(
        FEAST_USAGE="False",
        DO_NOT_TRACK="true",
        MLFLOW_ENABLE_TELEMETRY="false",
        MLFLOW_DISABLE_AGENT_HINT="1",
        DBT_SEND_ANONYMOUS_USAGE_STATS="false",
    )


def digest(data):
    return hashlib.sha256(
        json.dumps(data, sort_keys=True, separators=(",", ":"), allow_nan=False).encode()
    ).hexdigest()


def tracker(directory):
    configure_local_tools()
    from mlflow.tracking import MlflowClient

    root = Path(directory)
    root.mkdir(parents=True, exist_ok=True)
    client = MlflowClient(
        tracking_uri="sqlite:///" + str(root / "tracking.db"),
        registry_uri="sqlite:///" + str(root / "tracking.db"),
    )
    experiment = client.create_experiment(
        "local-quality-investigation", artifact_location=(root / "artifacts").as_uri()
    )
    return client, experiment


def example_one():
    with tempfile.TemporaryDirectory() as d:
        client, experiment = tracker(Path(d) / "tracking")
        run = client.create_run(
            experiment, tags={"data_contract": "customer-v1", "source": "synthetic"}
        )
        run_id = run.info.run_id
        client.log_param(run_id, "threshold", "0.5")
        client.log_metric(run_id, "brier", 0.2)
        manifest = {
            "feature_order": ["usage", "tickets", "region"],
            "data_sha256": digest([1, 2, 3]),
        }
        path = Path(d) / "manifest.json"
        path.write_text(json.dumps(manifest))
        client.log_artifact(run_id, str(path), "evidence")
        client.set_terminated(run_id)
        loaded = client.get_run(run_id)
        assert loaded.info.status == "FINISHED" and loaded.data.metrics["brier"] == 0.2
        assert client.list_artifacts(run_id, "evidence")[0].path == "evidence/manifest.json"
        return {
            "status": loaded.info.status,
            "metrics": loaded.data.metrics,
            "artifact_recorded": True,
        }


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Retain observations from a failed workflow

The second case records a training loss but terminates the run as FAILED. The observation remains useful for diagnosis while the status prevents it from being described as a completed accepted workflow.

**Expected evidence:** The failed run retains its 0.1 training-loss observation.

```python
import os
import tempfile
from pathlib import Path


def configure_local_tools():
    os.environ.update(
        FEAST_USAGE="False",
        DO_NOT_TRACK="true",
        MLFLOW_ENABLE_TELEMETRY="false",
        MLFLOW_DISABLE_AGENT_HINT="1",
        DBT_SEND_ANONYMOUS_USAGE_STATS="false",
    )


def tracker(directory):
    configure_local_tools()
    from mlflow.tracking import MlflowClient

    root = Path(directory)
    root.mkdir(parents=True, exist_ok=True)
    client = MlflowClient(
        tracking_uri="sqlite:///" + str(root / "tracking.db"),
        registry_uri="sqlite:///" + str(root / "tracking.db"),
    )
    experiment = client.create_experiment(
        "local-quality-investigation", artifact_location=(root / "artifacts").as_uri()
    )
    return client, experiment


def example_two():
    with tempfile.TemporaryDirectory() as d:
        client, experiment = tracker(Path(d) / "tracking")
        run = client.create_run(experiment)
        client.log_metric(run.info.run_id, "training_loss", 0.1)
        client.set_terminated(run.info.run_id, status="FAILED")
        loaded = client.get_run(run.info.run_id)
        assert loaded.info.status == "FAILED" and loaded.data.metrics["training_loss"] == 0.1
        return {
            "failed_run_retains_observations": True,
            "successful_metric_is_not_successful_workflow": True,
        }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

If expected evidence is missing, inspect the run identifier, destination URI, terminal status and artifact location. Do not infer a successful upload from an old local file. Retain failures and separate a reproducible local fixture from a deployed tracking-service claim.
