<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared working tree to image build context | Uncommitted edits by other agents could enter an image |
| launcher to local Docker engine | Builds can retag shared images used by the learner's projects |
| image labels to release staging | A label is a claim that later gates trust |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Spoofing | revision label | high | mitigate | Label `<sha>-dirty` for dirty trees, empty without own git top level; verifier rejects both; qualification builds only from a clean worktree (Task 1, D-03) |
| T-07-02 | Tampering | build context | medium | mitigate | `.planning` added to `.dockerignore`; worktree builds exclude shared-checkout edits (Task 2) |
| T-07-03 | Tampering | shared tags `ds60sqlpy-lab:1.4.3`, `ds60sqlpy-worker-python-core:1.4.3` | high | mitigate | Tracer verify builds only `-p7<sha8>` tags via `build` action (no containers) and removes exactly those tags (D-04, D-09) |
| T-07-04 | Repudiation | release staging | medium | mitigate | `inspected_image` refuses a revision label that differs from `Context.revision` (Task 3) |
| T-07-05 | Information disclosure | verifier report | low | accept | Report holds labels and image IDs only; no environment values or tokens |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; the RESEARCH Package Legitimacy Audit lists none |
</threat_model>
