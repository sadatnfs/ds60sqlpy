# Kubernetes content authoring

Run `python courses/kubernetes/authoring/complete/build_all.py` from the repository root with the authoring PyYAML dependency already available. The generator writes only k8s-004..007 and k8s-009..042 plus their reviewed fixtures and host-lab guide. It merges those IDs into canonical lessons.json and preserves original k8s-001, k8s-002, k8s-003 and k8s-008 entries. It never starts Docker, contacts Kubernetes, installs tools or edits learner work.

The explicit batch inputs contain the topic explanations, examples, six exercises and separate solution reasoning. enhance.py adds scoped read-only observations and real host-only marker Jobs. Update those inputs alongside generated content. The synthetic signature trust fixture is immutable public material and is not regenerated by this authoring command. No private signing key is stored.

Run tests/test_kubernetes_content_complete.py for plan/artifact parity, offline reference execution, manifest boundaries, marker semantics and actual signature controls. The optional local Kustomize test uses an already prepared tool and never calls an API. Runtime qualification remains separate, as described in [the owned adapter](../../../../docker/kubernetes/README.md)
and [validation](../../../../docs/validation.md).

The final step now invokes `../networking/build.py`, which preserves the original 42 IDs and adds the 24 reading-only networking lessons plus durable depth supplements. See `../networking/README.md`. No new browser cluster operations are admitted by content generation.
