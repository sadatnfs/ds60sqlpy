# nlminb and optimization evidence

Start with: tmb-006, statistics-008.

Outcome: Assess a fit using objective, gradient, status and multiple starting points.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter runs `nlminb` itself, on a base-R Gaussian objective from two starting points. In the separately prepared [owned project](../projects/tmb-local/README.md), `fit_objective()` in `R/api.R` passes TMB's `obj$fn` and `obj$gr` to the same optimizer and records the maximum absolute gradient; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

An optimizer answers a computational question: did its search procedure satisfy its stopping rules? Scientific estimation adds further questions: is the solution an identifiable minimum, does it depend on the initial point, and does the fitted model explain the observations reasonably? Keep those claims separate.

`nlminb(start, objective, gradient)` accepts an initial parameter vector and callable functions. Its result includes `par`, `objective`, `convergence`, `message`, iteration count and evaluations. The project's `fit_objective` records the maximum absolute gradient and a narrow diagnostic flag. That flag is not a guarantee of global optimality or valid uncertainty.

## Key terms

- **nlminb:** R's PORT-library optimizer, called as `nlminb(start, objective, gradient)`, which returns `par`, `objective`, `convergence`, `message`, `iterations` and evaluation counts.
- **Convergence code:** The `convergence` field, where 0 means the stopping rules were satisfied; it says nothing about global optimality, identifiability or valid uncertainty.
- **Multiple starting points:** Refitting from deliberately different initial values to reveal alternative minima, flat directions or path dependence.
- **Parameter scaling:** Centering and rescaling predictors or parameters so that tolerances and gradients are comparable across coordinates, with reported values converted back consistently.

### Worked case A: normal mean from different starts

Fit the normalized normal model from a low mean with a narrow scale and from a high mean with a broad scale. The closed-form answer is known, so compare final coordinates as well as objective values. The companion does this in base R with an analytic gradient. Observe that different paths can take different numbers of evaluations while arriving at the same solution.

Use a relative parameter or objective tolerance consistent with data scale. A gradient of 0.001 may be small or large depending on units and curvature. Reparameterizing predictors can make convergence more stable without changing the underlying scientific model, provided predictions are transformed consistently.

### Worked case B: weakly determined nonlinear decay

The nonlinear model has mean \(a e^{-bt}+c\). If observations cover only early times, \(e^{-bt}\approx1-bt\), so data mainly identify \(a+c\) and \(ab\). Very different values of \(a,b,c\) can therefore give similar fits. The companion compares two such curves on a short interval and on a longer forecast horizon. An optimizer may find a good short-term fit but a poorly determined long-range forecast.

A useful retry changes a diagnosed cause: rescale predictors, choose a physically plausible start, or inspect a likelihood profile. Repeating the same optimization blindly does not add information. Save failed fits with status, message and parameter values; do not silently drop them from simulation summaries.

### Diagnostics and answered discussion

**Is convergence code zero sufficient?** No. Check finite objective and gradient, compare initial and final values, inspect curvature, and evaluate predictive residuals. **Should I simply increase iteration limits?** Only after determining whether the algorithm is progressing toward an identifiable solution. More iterations cannot fix an unbounded likelihood. **Can I average two fitted parameter vectors?** Usually not. Averages can leave constrained parameter spaces or lie in a low-likelihood region; compare fits at their actual objectives.

For latent models, an outer optimizer's success can coexist with a failed inner optimization. Chapter 14 inspects that extra layer explicitly. The [R `nlminb` documentation](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/nlminb.html) explains its stopping and control parameters; retain the package/version context with any saved numerical result.

### Worked case C: auditing one `nlminb` result against the closed form

The companion's objective has a known minimizer, so every field of the result can be audited. The estimate is \(\hat\mu=3.5\) and \(\hat s=\tfrac12\log(21/4)=\tfrac12\log5.25\approx0.829114\), and the minimum value is \(\frac n2\log(2\pi\hat\sigma^2)+\frac n2=2\log(2\pi\cdot5.25)+2\approx8.992210\). The audit below checks the fields that matter rather than printing the whole list.

```r
y <- c(1, 2, 4, 7)
fn <- function(p) -sum(dnorm(y, p[1], exp(p[2]), log = TRUE))
gr <- function(p) c(sum(p[1] - y) / exp(2 * p[2]), length(y) - sum((y - p[1])^2) / exp(2 * p[2]))
fit <- nlminb(c(-2, 0), fn, gr)
target <- c(mean(y), 0.5 * log(mean((y - mean(y))^2)))
audit <- list(
  status = fit$convergence, message = fit$message,
  par_error = max(abs(fit$par - target)),
  objective_error = fit$objective - fn(target),
  gradient_max = max(abs(gr(fit$par))),
  evaluations = fit$evaluations
)
str(audit)
```

The expected shape is a six-element list. `status` should be the integer 0, and `message` is a character string from the PORT routines, typically mentioning relative convergence. `par_error` and `gradient_max` should be small, on the order of the optimizer's tolerance rather than exactly zero. `objective_error` should be zero or a tiny positive number; a negative value larger than rounding would mean the optimizer found a point below the closed-form minimum, which signals a bug in `fn` or in the target. `evaluations` is a named pair counting function and gradient calls; its values depend on the start and are not something to pin in a test.

This audit is the pattern `fit_objective()` follows for compiled models, where no closed form is available: it reevaluates the objective and gradient at the returned `par` instead of trusting the optimizer's last internal state, and only then sets `diagnostic_ok`.

### When the project's Newton correction applies

`fit_objective()` uses `rel.tol = 1e-10`, a relative objective tolerance. On a flat valley, the objective can stop changing by that relative amount while the absolute gradient is still around \(10^{-3}\). The function then tries one Newton step \(-H^{-1}g\) using `stats::optimHess`, but only if the outer status is 0, the gradient is at least \(10^{-4}\), there are at most 32 parameters, the Hessian has a Cholesky factor, and the relative step is below \(10^{-3}\). It keeps the step only if the objective does not increase beyond rounding and the gradient shrinks. The record in `fit$refinement` says whether the step was applied and what the original gradient was. If you see `applied = TRUE` with a large `relative_step`, the conditions above were violated and the code has changed; if you see a failed Cholesky, the Hessian is not positive definite and the next chapter's curvature checks apply before any standard error is reported.

### Base-R companion (runs in the classroom)

```r
y <- c(1, 2, 4, 7)
fn <- function(p) -sum(dnorm(y, p[1], exp(p[2]), log = TRUE))
gr <- function(p) c(sum(p[1] - y) / exp(2 * p[2]), length(y) - sum((y - p[1])^2) / exp(2 * p[2]))
fits <- lapply(list(c(-2, 0), c(8, 2)), function(start) nlminb(start, fn, gr))
for (fit in fits) print(c(fit$par, value = fit$objective, gradient = max(abs(gr(fit$par)))))
stopifnot(max(abs(fits[[1]]$par - fits[[2]]$par)) < 1e-4)
curve <- function(t, a, b, c) a * exp(-b * t) + c
print(data.frame(time = c(0, .1, 8), first = curve(c(0, .1, 8), 3, .6, 1), second = curve(c(0, .1, 8), 6, .3, -2)))
```
