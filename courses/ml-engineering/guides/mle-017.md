# mle-017: Model cards, slice evidence and data minimization

## Level and prerequisites

Advanced. Direct prerequisites: `mle-001`, `mle-005`, `mle-009`, `mle-015`

**Outcome:** Write a model card that is grounded in actual data, metrics and operational decisions.

## Question and mechanism

A model card should make intended use, inputs, evidence, limitations and operational ownership inspectable. It is not a certificate produced by filling a template. A useful card must reflect actual evaluated populations, known failure modes and the decision process used to accept or reject a version.

The first case compares two synthetic slices with different sample sizes and true-positive rates. The counts remain visible, so a rate difference is not presented as a precise population conclusion. One parity metric does not establish fairness, and a model's appropriate use depends on context, harms, alternatives and an adequately designed evaluation.

The second case defines a small input allowlist and rejects an unnecessary email field. Data minimization reduces avoidable exposure and keeps the interface focused on its purpose. It does not establish legal compliance or prove that every allowed feature is appropriate. A real system needs separately qualified governance, access, retention and review processes.

## Syntax and data contract

Compute slice metrics from explicit confusion counts and retain their denominators. The card records purpose, permitted features, excluded fields, owner, limits and a rollback version. Compare incoming fields against the allowlist. Keep governance statements tied to actual evidence rather than treating an artifact's filename as approval.

## Worked case 1: Inspect rate differences with counts

Slice A has twenty observations and true-positive rate 0.8; slice B has ten and rate 0.4. The program reports both counts and rates. Interpretation still requires uncertainty, population and decision context beyond this tiny table.

**Expected evidence:** The two TPRs are 0.8 and 0.4, with different sample sizes.

```python
def example_one():
    groups = {"A": {"tp": 8, "fn": 2, "fp": 1, "tn": 9}, "B": {"tp": 2, "fn": 3, "fp": 1, "tn": 4}}
    report = {}
    for name, c in groups.items():
        n = sum(c.values())
        report[name] = {
            "n": n,
            "tpr": c["tp"] / (c["tp"] + c["fn"]),
            "accuracy": (c["tp"] + c["tn"]) / n,
        }
    assert report["A"]["tpr"] == 0.8 and report["B"]["tpr"] == 0.4
    assert report["A"]["n"] == 20 and report["B"]["n"] == 10
    return {"slice_metrics": report, "metric_parity_alone_is_not_fairness": True}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Reject an unnecessary field

The request includes email even though the declared model interface uses only usage, tickets and region. The program identifies that extra field and retains the card's stated limitations and rollback version.

**Expected evidence:** Email is rejected by the allowlist and the card retains its synthetic-data limit.

```python
def example_two():
    card = {
        "purpose": "optional support prioritization",
        "features": ["usage", "tickets", "region"],
        "excluded": ["email", "free_text"],
        "owner": "learning team",
        "limits": ["synthetic population", "delayed labels"],
        "rollback_version": "v1",
    }
    request = {"usage": 10, "tickets": 2, "region": "north", "email": "learner@example.invalid"}
    allowed = set(card["features"])
    rejected = set(request) - allowed
    assert rejected == {"email"} and card["rollback_version"] == "v1" and card["limits"]
    return {
        "rejected_fields": sorted(rejected),
        "review_card": card,
        "not_a_legal_compliance_certificate": True,
    }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

A clean aggregate metric can hide a weak slice or a changed population. A long model card can still omit the actual decision and evidence. Avoid converting one rate check, a template or an allowlist into a claim of universal fairness, safety or compliance.
