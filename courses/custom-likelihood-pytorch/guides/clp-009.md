# clp-009: Censoring contributes survival probability

Tutorial mode. Stage: intermediate. Direct prerequisites: `clp-004`, `r-048`.

## A censored record is an inequality

If a device is still working when observation ends at time five, the recorded information is that its lifetime exceeds five. Treating time five as a failure adds an event that was never observed. Dropping the record discards five units of survival information. A likelihood should represent the observation actually made.

For an event time \(T\), let \(t_i\) be the observed time and \(d_i\) indicate an observed event. Under noninformative right censoring, the parameter-dependent contribution is

\[
p(t_i,d_i;\theta)\propto f(t_i;\theta)^{d_i}S(t_i;\theta)^{1-d_i},
\]

where \(f\) is event density and \(S(t)=P(T>t)\) is survival. The omitted censoring-process factor must be independent of the event-model parameters under the assumed observation mechanism. Informative dropout may violate this condition and requires a richer model or a defensible sensitivity analysis.

An exponential lifetime has constant hazard \(\lambda>0\), density \(\lambda e^{-\lambda t}\) and survival \(e^{-\lambda t}\). With \(\eta=\log\lambda\), the NLL is

\[
\mathcal L(\eta)=e^\eta\sum_i t_i-\eta\sum_i d_i.
\]

Thus the rate estimate is observed event count divided by total observed time at risk, provided at least one event occurs.

## Worked case 1: distinguish events from censoring

The five observed times are \((1,2,4,5,8)\), and event indicators are \((1,1,0,1,0)\). There are three events over twenty total time units, so \(\widehat\lambda=3/20=0.15\). The program verifies the zero log-rate score and calculates survival at time four as \(e^{-0.6}\), approximately 0.5488.

If every record were incorrectly treated as an event, the estimated rate would be \(5/20=0.25\). That increase is not an optimizer issue; the wrong observation model changed the numerator. Now change the second record from an event to a censoring observation at the same time. The total exposure remains twenty but the event count drops to two, yielding rate 0.1. This controlled change demonstrates exactly which information the event indicator contributes.

## Worked case 2: delayed entry changes the risk set

Suppose records enter observation at times \(a_i\), conditional on having survived until entry. Their conditional contributions divide by \(S(a_i)\). For the exponential model,

\[
\mathcal L(\eta)=e^\eta\sum_i(t_i-a_i)-\eta\sum_i d_i.
\]

Using entries \((0,0.5,1,0,2)\) reduces total observed time at risk from twenty to 16.5. The estimate becomes \(3/16.5\), approximately 0.181818. Delayed entry is also called left truncation in this context. It is different from left censoring, where the event is known to have occurred before a recorded time. The code checks entry precedes exit, so invalid risk intervals cannot silently generate a negative exposure.

The exponential memoryless assumption makes this expression especially simple. For a nonconstant hazard, replacing total lifetime by elapsed observation time in an ordinary density is generally wrong. The survival ratio must be derived from the chosen time origin and event process.

## Debugging and scientific limits

Check time units, event coding, nonnegative finite entries and strictly positive observation intervals. A zero event count produces a boundary MLE at zero hazard; the helper rejects a finite interior estimate rather than manufacturing one. Interval censoring requires a probability such as \(F(u)-F(l)\), not the density at the interval midpoint. Competing risks require specifying which event and which risk process the estimand concerns.

Repeated records from the same subject may represent start-stop intervals, recurrent events or duplicate entries. They are not automatically independent subjects. Decide whether the hazard is conditional on prior history, whether frailty is present and whether a row's risk interval overlaps another row for the same individual. Correct formulas on an incorrect risk table remain incorrect analysis.

## Answered review questions

**Why does a censored observation contribute survival instead of density?** It records a range of possible event times, so the likelihood integrates event density over that range. Survival is exactly that integral for right censoring.

**Is the constant hazard assumption innocuous?** No. It implies the conditional chance of failure in a short future interval does not depend on how long the unit has already survived. Aging mechanisms often violate it. Use this tractable model to learn likelihood construction, then assess whether its assumption is defensible.

**Can a very large dataset remove informative-censoring bias?** No. More observations reduce sampling noise around the wrong target if the observation mechanism is misspecified. Independent uncertainty calculations also need the correct independent unit and risk-set construction.

```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def censored_exponential_nll(log_rate, times, event, entry=None):
    entry = torch.zeros_like(times) if entry is None else entry
    if (
        times.ndim != 1
        or not len(times)
        or event.shape != times.shape
        or entry.shape != times.shape
    ):
        raise ValueError("Use matching duration, event and entry vectors")
    if (
        not bool(torch.isfinite(times).all() & torch.isfinite(entry).all())
        or bool((entry < 0).any())
        or bool((times <= entry).any())
        or not bool(torch.all((event == 0) | (event == 1)))
    ):
        raise ValueError("Require finite 0 <= entry < exit and binary event status")
    return (log_rate.exp() * (times - entry) - event * log_rate).sum()


def mle(times, event, entry=None):
    censored_exponential_nll(tensor(0.0), times, event, entry)
    if float(event.sum()) == 0:
        raise ValueError("No events gives a boundary zero-rate estimate")
    entry = torch.zeros_like(times) if entry is None else entry
    return event.sum() / (times - entry).sum()


def run_cases():
    times, event = tensor([1, 2, 4, 5, 8]), tensor([1, 1, 0, 1, 0])
    rate = mle(times, event)
    changed = event.clone()
    changed[1] = 0
    changed_rate = mle(times, changed)
    delayed = mle(times, event, tensor([0, 0.5, 1, 0, 2]))
    lr = rate.log().detach().requires_grad_()
    score = torch.autograd.grad(censored_exponential_nll(lr, times, event), lr)[0]
    assert float(rate) == 0.15 and float(changed_rate) == 0.1 and abs(float(score)) < 1e-12
    assert abs(float(delayed) - 3 / 16.5) < 1e-12
    survival = float(torch.exp(-rate * tensor(4.0)))
    return {
        "right_censored_rate": float(rate),
        "one_fewer_event_rate": float(changed_rate),
        "incorrect_all_events_rate": len(times) / float(times.sum()),
        "delayed_entry_rate": float(delayed),
        "survival_at_4": survival,
        "score_at_mle": float(score),
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
