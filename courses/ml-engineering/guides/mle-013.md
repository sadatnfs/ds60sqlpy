# mle-013: Orchestration, checkpoints and safe retries

## Level and prerequisites

Advanced. Direct prerequisites: `mle-003`, `mle-008`, `mle-010`

**Outcome:** Define checkpoint and retry behavior using artifact identities.

## Question and mechanism

A workflow coordinator decides which stages can run, what evidence is complete and what should happen after interruption. Repeating a command is not automatically a safe retry. An operation may already have written an artifact before its response was lost, and a changed input may make an old checkpoint invalid.

The local example uses an explicit ledger to expose these mechanisms. It records the input identity, derived features, model state and publication identity. A deliberate interruption occurs after the feature checkpoint. Resuming with the same input reuses that completed stage and reaches the same publication identity on another run.

The second case changes the input and invalidates the prior derived state. This is a small Python workflow model, not a disguised Prefect deployment. The existing Python orchestration lessons introduce actual framework execution. The purpose here is to make the state and retry contract explicit before choosing a scheduler or distributing work.

## Syntax and data contract

The ledger keys represent completed artifacts. A stable input digest identifies which data those artifacts belong to. Publication is created only after model state exists, and repeat execution with the same input returns the same identity. An input change clears derived state under this simple policy; a larger system may invalidate only affected descendants.

## Worked case 1: Resume after a known interruption

The first case fails deliberately after features are recorded. It confirms that publication is absent, then resumes and repeats the same run. The unchanged publication identity is evidence of the fixture's idempotent behavior.

**Expected evidence:** The feature checkpoint survives; resumed model mean is 4 and repeated publication identity is unchanged.

```python
import contextlib
import hashlib
import json


def digest(data):
    return hashlib.sha256(
        json.dumps(data, sort_keys=True, separators=(",", ":"), allow_nan=False).encode()
    ).hexdigest()


def execute_pipeline(ledger, events, fail_after_features=False):
    source_id = digest(events)
    if ledger.get("source_id") != source_id:
        ledger.clear()
        ledger["source_id"] = source_id
    if "features" not in ledger:
        ledger["features"] = [2 * x for x in events]
    if fail_after_features:
        raise RuntimeError("deliberate interruption after checkpoint")
    if "model" not in ledger:
        ledger["model"] = {"mean": sum(ledger["features"]) / len(ledger["features"])}
    if "publication" not in ledger:
        ledger["publication"] = digest(ledger["model"])
    return ledger["publication"]


def example_one():
    ledger = {}
    with contextlib.suppress(RuntimeError):
        execute_pipeline(ledger, [1, 2, 3], True)
    assert "features" in ledger and "publication" not in ledger
    first = execute_pipeline(ledger, [1, 2, 3])
    second = execute_pipeline(ledger, [1, 2, 3])
    assert first == second and ledger["model"]["mean"] == 4
    return {"checkpoint_retained": True, "idempotent_publication": first, "mean": 4}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Invalidate work derived from changed input

The second case changes one source value. Its digest, derived features, model mean and publication identity change. Reusing the old result would violate the dependency contract.

**Expected evidence:** New features are [2,4,8] and the mean is 14/3.

```python
import hashlib
import json


def digest(data):
    return hashlib.sha256(
        json.dumps(data, sort_keys=True, separators=(",", ":"), allow_nan=False).encode()
    ).hexdigest()


def execute_pipeline(ledger, events, fail_after_features=False):
    source_id = digest(events)
    if ledger.get("source_id") != source_id:
        ledger.clear()
        ledger["source_id"] = source_id
    if "features" not in ledger:
        ledger["features"] = [2 * x for x in events]
    if fail_after_features:
        raise RuntimeError("deliberate interruption after checkpoint")
    if "model" not in ledger:
        ledger["model"] = {"mean": sum(ledger["features"]) / len(ledger["features"])}
    if "publication" not in ledger:
        ledger["publication"] = digest(ledger["model"])
    return ledger["publication"]


def example_two():
    ledger = {}
    old = execute_pipeline(ledger, [1, 2, 3])
    new = execute_pipeline(ledger, [1, 2, 4])
    assert old != new and ledger["model"]["mean"] == 14 / 3
    assert ledger["features"] == [2, 4, 8]
    return {"changed_input_invalidates_reuse": True, "new_mean": ledger["model"]["mean"]}


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

If reruns produce duplicated effects, inspect operation identity and publication semantics. If changed inputs reuse old outputs, inspect checkpoint dependencies. If a job outcome is unknown, reconcile it before resubmission. A scheduler's green status does not by itself establish that the correct artifact was published.
