# Reporting and simulation inside the C++ model

Start with: tmb-044, tmb-009, tmb-031.

Outcome: Keep diagnostics, differentiable outputs and simulated observations aligned with the model.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter tabulates residuals and simulates conditional and unconditional group outcomes. In the separately prepared [owned project](../projects/tmb-local/README.md), `models/normal_mean.cpp` contains `REPORT`, `ADREPORT` and a `SIMULATE` block, and `tests/public_api.R` calls `obj$simulate()`; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

`REPORT`, `ADREPORT` and `SIMULATE` are template-authoring macros with different jobs. REPORT makes a value available for ordinary readback. ADREPORT records a derived quantity for derivative-aware uncertainty. SIMULATE encloses generative code executed during simulation requests. None of them adds a likelihood contribution merely by being present.

A template should clearly separate data, parameter transforms, normalized objective terms, output quantities and simulation. Naming a report “prediction_interval” does not make it a calibrated interval; the mathematical construction must support the label.

## Key terms

- **Template sections:** The separated parts of a template: data, parameter transforms, normalized objective terms, output quantities and simulation.
- **REPORT versus ADREPORT:** REPORT exposes plain diagnostic values such as residuals; ADREPORT records estimands such as predicted means for derivative-aware uncertainty.
- **Simulation order:** In a hierarchical generator, drawing group effects before observations; holding fitted modes fixed gives a conditional simulation instead.
- **Generative consistency:** Agreement between what SIMULATE generates and what the likelihood evaluates, which `checkConsistency` can test.

### Worked case A: residual and predicted mean

The companion computes residuals as diagnostics and a fitted mean as an estimand. The residual vector is a natural REPORT target; selected predicted means can be ADREPORT targets when their uncertainty is needed. If prediction covariates change, construct a reviewed objective with the new data rather than silently mutating a report from an old tape.

```cpp
REPORT(residual);
ADREPORT(prediction);
SIMULATE {
  for (int i = 0; i < y.size(); ++i) y(i) = rnorm(mean(i), sigma);
  REPORT(y);
}
```

This fragment assumes matching finite vectors and positive scale already validated. It illustrates the ordinary Gaussian observation generator, not a complete hierarchical generator.

### Worked case B: hierarchical simulation order

For a random-intercept model, unconditional simulation draws group effects first and then observations conditional on those effects. Holding fitted group modes fixed instead produces a conditional simulation. The companion generates both with a fixed seed and explains why their between-group variability differs. Neither should be mislabeled as the other.

If a latent model's SIMULATE block generates only observation noise but `checkConsistency` expects the full joint generator, the score diagnostic can expose a mismatch. Document whether random states are regenerated and whether fixed parameters are conditioned on, resampled or integrated.

### Answered discussion

**Can I generate random values during objective evaluation?** An optimizer expects a deterministic objective for this workflow. Keep stochastic generation inside the intended simulation path, not the likelihood loop. **Can a simulation overwrite learner data?** The numerical model should return generated data to an owned result, not silently replace saved source datasets. **Should every simulated vector be AD-reported?** No. Simulation draws and derivatives of deterministic estimands serve different purposes.

See the [template macro and checkConsistency references](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The original normal template has an actually exercised SIMULATE path; new hierarchical generators need their own consistency checks.

### Worked case C: what each macro returns for the companion data

The deterministic part of the companion is small enough to read by hand. With \(y = (1, 2, 4)\) and fitted means \((1.2, 2.1, 3.8)\), the residuals are \((-0.2, -0.1, 0.2)\), their sum of squares is \(0.04 + 0.01 + 0.04 = 0.09\), and their mean is \(-0.033\) (hand-derived). In a compiled template those three numbers would arrive through `REPORT(residual)` as a plain numeric vector in `obj$report()`, with no standard errors attached. A fitted mean declared through `ADREPORT` arrives through `sdreport` with an estimate and a delta-method standard error. Asking `sdreport` for the residuals instead would compute a full covariance for quantities used only for plotting, which wastes work and invites the reader to treat them as estimands.

```r
rep <- obj$report() # rep$residual: length-3 numeric vector
sdr <- sdreport(obj)
summary(sdr, "report") # rows for ADREPORT targets only: Estimate, Std. Error
sim <- obj$simulate() # sim$y: a new length-3 vector, data untouched
```

The comments describe the expected shapes, not a recorded run.

### Worked case D: the variance the two simulations should show

The random-intercept companion uses \(\tau = 0.8\) and \(\sigma = 0.2\), with four observations in each of three groups. The variance arithmetic predicts what the printed columns should look like before reading them (closed-form values):

```text
                              unconditional         conditional
group effect                  drawn, var 0.64       fixed at -0.2, 0, 0.2
variance of one observation   0.64 + 0.04 = 0.68    0.04
correlation within a group    0.64 / 0.68 = 0.941   0
sample variance of the three  expected 0.64         exactly 0.04
  group effects
```

In the unconditional column, observations in the same group should cluster tightly around a group level, and the three levels should spread by roughly \(\pm 0.8\). In the conditional column, the group levels are pinned at \(1 - 0.2\), \(1\) and \(1 + 0.2\), so the whole column should sit within a band of about \(0.8\) to \(1.2\) plus noise with standard deviation 0.2. Because the draws use seed 4545, the exact values depend on R's generator and are not reproduced here; the comparison of spreads is what the lesson reads.

### A SIMULATE block that skips the latent draw

If the random-intercept template contained only `y(i) = rnorm(mu + u(group(i)), sigma)` inside `SIMULATE`, then each call would reuse the current values of `u` and produce conditional draws. Replicated datasets from that block would show between-group variance near the squared spread of the fitted modes, not near \(\tau^2\), and a parametric bootstrap built on it would understate the uncertainty of \(\tau\). The fix is to draw `u(j) = rnorm(Type(0), tau)` inside the same block, before the observation loop, and to report `u` as well so the replicate is complete.

### Base-R companion (runs in the classroom)

```r
y <- c(1, 2, 4);fitted <- c(1.2, 2.1, 3.8);print(data.frame(y = y, fitted = fitted, residual = y - fitted))
set.seed(4545);group <- rep(1:3, each = 4);sigma <- .2;tau <- .8
new_u <- rnorm(3, 0, tau);unconditional <- 1 + new_u[group] + rnorm(12, 0, sigma)
conditional <- 1 + c(-.2, 0, .2)[group] + rnorm(12, 0, sigma)
print(data.frame(group = group, unconditional = unconditional, conditional = conditional))
stopifnot(length(new_u) == 3, length(unconditional) == length(group))
```
