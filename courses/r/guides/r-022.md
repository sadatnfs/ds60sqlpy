## Outcome and mechanism

Define an S4 measurement with cross-slot invariants and select methods using both argument classes.

S4 defines a formal class with named slots and declared slot classes. This is stronger structural metadata than an S3 class label: a FormalMeasure contains numeric values and a character unit. Slot classes still do not express every domain constraint. A character slot can be empty or have several entries, and numeric values can contain infinities. A validity function checks these additional invariants.

Register the class with setClass, then register a validator with setValidity. The validator returns TRUE when the object is valid and a character vector of diagnostic messages otherwise. A valid prototype supplies sensible default slots. new constructs an instance and performs validity checking. Tests must cover both type incompatibility and domain-invalid values because they arise at different parts of the boundary.

Slot access uses @. A direct replacement can satisfy the slot's type while violating a cross-slot or domain invariant. Do not assume every possible mutation invokes the complete validator. Call validObject before publishing an altered value or provide a constructor-like replacement function that performs the full check. The second example deliberately creates a type-correct but semantically invalid unit to make this boundary visible.

An S4 generic delegates through standardGeneric, and methods have formal signatures. Dispatch can consider several arguments, which is useful when combining two typed measurements. This lesson has one method for two FormalMeasure values and another for FormalMeasure plus numeric. The latter rejects an unlabeled vector instead of guessing a unit. The two typed values must also have equal units; class dispatch alone cannot establish that equality.

Concatenating measurements and adding measurements are different operations. combine_measure concatenates observations while retaining one unit. It does not perform elementwise addition, silently recycle vectors or convert seconds to milliseconds. Tests inspect the resulting observation order, shape and unit as well as the selected rejection path.

Class and generic definitions belong in maintained package code when shared across analyses. This lesson runs definitions in a fresh process to avoid stale registrations from earlier attempts. S4 slots can themselves hold reference objects, so formal classes do not imply universal deep immutability. The useful guarantee here is a checked numeric-vector representation and a small, explicit operation contract.

## Read the syntax

setClass(..., slots=c(values="numeric",unit="character")) declares structure. x@values reads a slot. setValidity accepts a function(object), and validObject(x) requests its checks. setMethod("combine_measure", c(x="FormalMeasure", y="FormalMeasure"), ...) specifies both dispatch arguments.

## Worked examples

### Example 1: Concatenate two compatible formal values

```r
methods::setClass("FormalMeasure",
  slots = c(values = "numeric", unit = "character"),
  prototype = list(values = numeric(0), unit = "ms")
)
methods::setValidity("FormalMeasure", function(object) {
  problems <- character(0)
  if (!is.null(dim(object@values)) || any(!is.finite(object@values))) {
    problems <- c(problems, "values must be a finite vector")
  }
  if (length(object@unit) != 1L || is.na(object@unit) || !nzchar(object@unit)) {
    problems <- c(problems, "unit must be one nonempty string")
  }
  if (length(problems)) problems else TRUE
})
methods::setGeneric("combine_measure", function(x, y) methods::standardGeneric("combine_measure"))
methods::setMethod("combine_measure", c(x = "FormalMeasure", y = "FormalMeasure"), function(x, y) {
  methods::validObject(x)
  methods::validObject(y)
  if (!identical(x@unit, y@unit)) stop("incompatible units", call. = FALSE)
  methods::new("FormalMeasure", values = c(x@values, y@values), unit = x@unit)
})
methods::setMethod("combine_measure", c(x = "FormalMeasure", y = "numeric"), function(x, y) {
  stop("numeric input has no declared unit", call. = FALSE)
})

a <- methods::new("FormalMeasure", values = c(2, 4), unit = "ms")
b <- methods::new("FormalMeasure", values = 6, unit = "ms")
combined <- combine_measure(a, b)
stopifnot(identical(combined@values, c(2, 4, 6)), combined@unit == "ms")
print(combined)
```

**Expected observation:** A FormalMeasure with values 2,4,6 and unit ms.

Both argument classes select the typed-pair method. It checks validity and equality of units before constructing the concatenated result. The original values remain usable.

### Example 2: Type checks and semantic validity are separate

```r
methods::setClass("FormalMeasure",
  slots = c(values = "numeric", unit = "character"),
  prototype = list(values = numeric(0), unit = "ms")
)
methods::setValidity("FormalMeasure", function(object) {
  problems <- character(0)
  if (!is.null(dim(object@values)) || any(!is.finite(object@values))) {
    problems <- c(problems, "values must be a finite vector")
  }
  if (length(object@unit) != 1L || is.na(object@unit) || !nzchar(object@unit)) {
    problems <- c(problems, "unit must be one nonempty string")
  }
  if (length(problems)) problems else TRUE
})
methods::setGeneric("combine_measure", function(x, y) methods::standardGeneric("combine_measure"))
methods::setMethod("combine_measure", c(x = "FormalMeasure", y = "FormalMeasure"), function(x, y) {
  methods::validObject(x)
  methods::validObject(y)
  if (!identical(x@unit, y@unit)) stop("incompatible units", call. = FALSE)
  methods::new("FormalMeasure", values = c(x@values, y@values), unit = x@unit)
})
methods::setMethod("combine_measure", c(x = "FormalMeasure", y = "numeric"), function(x, y) {
  stop("numeric input has no declared unit", call. = FALSE)
})
assert_error <- function(expr, pattern) {
  message <- tryCatch(
    {
      force(expr); NULL
    },
    error = conditionMessage
  )
  stopifnot(is.character(message), length(message) == 1L, grepl(pattern, message))
}

x <- methods::new("FormalMeasure", values = c(2, 4), unit = "ms")
x@unit <- character(0)
assert_error(methods::validObject(x), "nonempty string")
assert_error(methods::new("FormalMeasure", values = Inf, unit = "ms"), "finite vector")
good <- methods::new("FormalMeasure", values = 1, unit = "ms")
assert_error(combine_measure(good, 2), "no declared unit")
cat("Invalid domain values and unlabeled inputs rejected.\n")
```

**Expected observation:** Three expected errors, each matched to its cause.

The empty character vector satisfies the declared character slot class but fails the semantic validator. The numeric second argument dispatches to a different method whose explicit rejection protects the unit boundary.

## Reference review

The reference tests two dispatch paths and two kinds of domain failure. An incompatible unit pair is structurally valid and matches the formal signature, but still fails the operation's compatibility rule. An empty unit passes the slot's character type and fails validObject.

The conversion function makes the scale factor visible and returns a newly validated value. The assertion about the unchanged seconds object separates conversion from in-place mutation. This is a checked local class definition, not an installed package or a claim that every S4 slot mutation automatically runs all invariants.
