## Outcome and mechanism

Run repeatable stochastic calculations without leaking caller RNG state and record a bounded configuration, input digest and software-version ledger.

A seed is one component of a reproducible analysis. Results also depend on the random-number algorithm, the sequence of random calls, input contents and order, configuration, package versions and numerical platform. Setting a seed once does not make arbitrary parallel scheduling or a later changed algorithm produce the same output. The preceding lesson assigned streams to task identities; this lesson makes serial RNG ownership explicit.

with_rng validates one integer seed, saves the caller's RNG kind and state, chooses an explicit generator configuration, evaluates a callback and restores the prior state. The restoration handler also runs when the callback raises an ordinary error. If the caller did not have a .Random.seed, the helper removes the seed it created instead of leaving a new ambient state behind. Tests cover both cases because restoring only an existing seed is an incomplete ownership policy.

The helper's callback is still ordinary code. It can modify files or other global objects, and restoring RNG state does not undo those effects. Keep the calculation pure where possible and return structured results. The public contract says which state the wrapper owns, not that it provides a transaction for the whole R session. Use the prepared package versions when comparing exact outputs, and use numerical tolerances where floating-point algorithms warrant them.

Analysis configuration should be data: seed, sample size, missingness policy, model choice and other declared options. Validate it before computation. Store an explicit representation of the input fixture and a content hash together with that configuration. A hash identifies those bytes; it is not proof that the data are correct, authentic, representative or scientifically suitable. Changing the row order can change the hash and the stochastic result even when a set of values is unchanged.

The metadata example serializes a deliberately ordered local configuration and fixture to JSON, then computes a SHA256 digest with serialize=FALSE over those exact JSON strings. This is an explicit local representation, not a promise that arbitrary JSON producers will generate identical canonical bytes. The ledger records R version, selected package versions and RNG kinds. It avoids dumping the full process environment, credentials or unrelated user state.

A reproducibility ledger helps another analyst reconstruct what was run, but it does not establish statistical validity. A repeated biased estimate remains biased. Keep assumptions, eligibility criteria, uncertainty and interpretation alongside source and configuration. The later analytical-package capstone uses these contracts to distinguish a checked descriptive result from a claim about a population.

## Read the syntax

RNGkind() queries generator choices and set.seed selects an initial state. Save and restore .Random.seed with assign(...,envir=.GlobalEnv), preserving whether it existed. jsonlite::toJSON(...,auto_unbox=TRUE,digits=17) creates the chosen JSON representation; digest::digest(text,algo="sha256",serialize=FALSE) hashes those bytes.

## Worked examples

### Example 1: Repeat a calculation while restoring the caller stream

```r
with_rng <- function(seed, fun) {
  if (!is.numeric(seed) || length(seed) != 1L || !is.finite(seed) ||
    seed != floor(seed) || seed < 0 || seed > .Machine$integer.max) stop("seed must be one valid integer")
  old_kind <- RNGkind()
  had_seed <- exists(".Random.seed", envir = .GlobalEnv, inherits = FALSE)
  if (had_seed) old_seed <- get(".Random.seed", envir = .GlobalEnv)
  on.exit(
    {
      do.call(RNGkind, as.list(old_kind))
      if (had_seed) assign(".Random.seed", old_seed, envir = .GlobalEnv)
      else if (exists(".Random.seed", envir = .GlobalEnv, inherits = FALSE)) rm(".Random.seed", envir = .GlobalEnv)
    },
    add = TRUE
  )
  RNGkind(kind = "Mersenne-Twister", normal.kind = "Inversion", sample.kind = "Rejection")
  set.seed(as.integer(seed))
  fun()
}

set.seed(81)
state_before <- .Random.seed
kind_before <- RNGkind()
a <- with_rng(2026, function() stats::rnorm(5))
b <- with_rng(2026, function() stats::rnorm(5))
stopifnot(identical(a, b), identical(.Random.seed, state_before), identical(RNGkind(), kind_before))
print(a)
```

**Expected observation:** Identical five-value vectors and unchanged caller RNG state.

Two callbacks receive the same explicit generator configuration and seed. Their vectors match, while the caller retains its prior RNG state. The claim is about this declared calculation in the prepared environment.

### Example 2: Create an explicit, bounded analysis ledger

```r
config <- list(seed = 2026L, draws = 5L, missing_policy = "reject")
fixture <- list(id = c("a", "b", "c"), value = c(2, 4, 6), unit = "ms")
config_json <- as.character(jsonlite::toJSON(config, auto_unbox = TRUE, digits = 17))
fixture_json <- as.character(jsonlite::toJSON(fixture, auto_unbox = TRUE, digits = 17))
ledger <- list(
  config = config,
  config_sha256 = digest::digest(config_json, algo = "sha256", serialize = FALSE),
  input_sha256 = digest::digest(fixture_json, algo = "sha256", serialize = FALSE),
  R = R.version.string,
  packages = list(
    jsonlite = as.character(utils::packageVersion("jsonlite")),
    digest = as.character(utils::packageVersion("digest"))
  ),
  rng = RNGkind()
)
stopifnot(nchar(ledger$input_sha256) == 64L, nchar(ledger$config_sha256) == 64L)
print(ledger)
```

**Expected observation:** Configuration, two 64-character digests, R/package versions and RNG kinds.

The hashes identify explicitly serialized local data, and package versions make the serialization context inspectable. No ambient environment variables or credentials are collected.

## Reference review

The reference tests ordinary completion, a deliberately failed callback and an initially absent seed. Each checks a separate restoration obligation. The numeric output is compared within the same explicit generator configuration rather than asserted as an eternal cross-version sequence.

The digest test changes one known value and retains the original object. Metadata is an explicit allowlist of analysis-relevant fields, so the example does not expose unrelated session state. A reproducible ledger supports review but cannot establish unbiasedness or sound experimental design.
