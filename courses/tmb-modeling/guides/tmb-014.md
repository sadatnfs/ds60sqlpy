# Inner and outer convergence

Start with: tmb-013, tmb-007.

Outcome: Diagnose latent-mode failure separately from fixed-parameter convergence.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter takes a Newton step on a quadratic and compares limited and full `nlminb` runs. TMB's inner optimization of latent effects runs only in the separately prepared [owned project](../projects/tmb-local/README.md), for the models built with `random = "u"` (`random_intercept`, `ar1` and `panel_trend`); a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

A latent model has two numerical searches. At each proposed fixed parameter vector \(\theta\), an inner optimizer finds \(\hat u(\theta)\). The outer optimizer then uses the approximate marginal objective and its gradient to update \(\theta\). If the inner search is inaccurate, the outer search is being shown a distorted objective surface.

In a purely quadratic latent problem, one exact Newton step from any start reaches the mode in exact arithmetic. Nonlinear latent models do not generally have this property. The TMB manual exposes `inner.control`, `inner.method` and `random.start`; use them to diagnose a particular model rather than applying a universal setting from an unrelated example.

## Key terms

- **Inner optimization:** The search for the latent mode \(\hat u(\theta)\) at each proposed fixed parameter vector \(\theta\).
- **Outer optimization:** The search over fixed parameters using the approximate marginal objective and gradient that the inner solves produce.
- **Warm start:** Beginning an inner search from the previous latent solution, which saves work but can hide sensitivity to starting modes in nonconvex problems.
- **Inner controls:** The `inner.control`, `inner.method` and `random.start` options of `MakeADFun`, used to diagnose a specific latent model rather than as universal settings.

### Worked case A: exact quadratic latent mode

The companion constructs a positive-definite two-state precision matrix. Its gradient is \(Hu-b\), so a Newton step is \(u-H^{-1}(Hu-b)=H^{-1}b\). Two widely different starts converge to the same answer. This is the reason a known quadratic inner problem can tolerate a one-step policy. It is not permission to use one inner iteration for every TMB model.

Warm starts reuse a previous latent solution and can reduce work as the outer parameters move. They can also hide sensitivity to initial modes in a nonconvex problem. Check a few fresh starts and inspect the inner gradient, especially when a finite-difference derivative comparison is unexpectedly noisy.

### Worked case B: truncating a nonlinear inner solve

For \(f(u)=(u^2-1)^2+0.1u\), multiple stationary points exist. The companion runs a limited optimizer and a fuller search from different starts. The resulting objective and gradient explain more than the exit code alone. This pedagogical objective is intentionally nonconvex; it is not advertised as a normalized density or a reliable random-effect model.

A useful failure record includes outer coordinates, latent start, final inner mode, inner gradient, inner/outer convergence status, and the objective being approximated. Never silently keep the previous successful objective when a new inner evaluation fails. That creates false smoothness and can make the outer optimizer appear more stable than it is.

### Diagnostics and answered discussion

**Can I tell `nlminb` to ignore failed inner evaluations?** Replacing them arbitrarily changes the optimization problem. A bounded invalid-domain policy must be deliberate, and failures should remain visible. **Will a tighter outer tolerance fix a loose inner solve?** No. Inner accuracy must support the precision demanded of the outer function and gradient. **How do I test gradients?** Compare several perturbation sizes, ensure the inner solve converges at every perturbation, and use an exact Gaussian oracle first.

The [MakeADFun documentation](https://cran.r-project.org/web/packages/TMB/TMB.pdf) describes its latent starting-value behavior. Our default project uses TMB's reviewed defaults for the small Gaussian latent cases and qualifies them against exact marginals. More difficult latent models need additional convergence evidence before promotion to ordinary runnable lessons.

### Worked case C: the companion's exact Newton step

The quadratic inner problem has \(H=\begin{pmatrix}3&0.5\\0.5&2\end{pmatrix}\) and \(b=(1,-2)\). With \(|H|=5.75\), the solution is
\[
H^{-1}b=\frac1{5.75}\begin{pmatrix}2&-0.5\\-0.5&3\end{pmatrix}\begin{pmatrix}1\\-2\end{pmatrix}=\frac{(3,\,-6.5)}{5.75}=(0.521739,\,-1.130435).
\]
All three rows of the companion's matrix should print these two numbers, up to rounding. The far start \((10,-7)\) lands on the same point after one step because the gradient \(Hu-b\) is linear, so the Newton model is the objective itself.

The nonconvex objective in the second half has three stationary points, found by solving \(4u^3-4u+0.1=0\):

```text
stationary u   objective   curvature 12u^2 - 4    (closed-form roots, rounded)
-1.012273     -0.100617    8.296                  global minimum
 0.025016      1.001250   -3.992                  local maximum
 0.987257      0.099367    7.696                  local minimum
```

From start \(-2\), a full `nlminb` run should reach the left minimum with `full_value` near \(-0.1006\); from start 2, it should reach the right minimum with value near \(0.0994\). Both report convergence and a tiny `full_gradient`, yet the two objectives differ by about 0.2. An inner solver behaving like this inside TMB would hand the outer optimizer a marginal objective that jumps by that amount whenever the warm start switches basins. The one-iteration `limited_gradient` values are not pinned here; they depend on the PORT step-length logic, but they will be far from zero, which is exactly what an inner-gradient check should flag.

### What to log when the outer fit misbehaves

For a compiled latent model, `obj$env$last.par` holds the most recent fixed and latent values, and `obj$env$random` indexes the latent block. After a suspicious outer step, evaluate `obj$env$f(obj$env$last.par, order = 1)` and look at the entries for `random`: they are the inner gradient. If they are not small, the reported marginal value is not the Laplace objective at that \(\theta\). Two remedies are common for a basin switch: restart the inner search from a fixed, scientifically sensible point instead of the previous mode, or change the model so the latent conditional is log-concave and therefore unimodal.

### Base-R companion (runs in the classroom)

```r
H <- matrix(c(3, .5, .5, 2), 2, 2); b <- c(1, -2)
newton <- function(u) u - solve(H, drop(H %*% u) - b)
print(rbind(from_zero = newton(c(0, 0)), from_far = newton(c(10, -7)), exact = solve(H, b)))
stopifnot(max(abs(newton(c(10, -7)) - solve(H, b))) < 1e-12)
fn <- function(u) (u^2 - 1)^2 + .1 * u
gr <- function(u) 4 * u * (u^2 - 1) + .1
for (start in c(-2, 2)) {
  short <- nlminb(start, fn, gr, control = list(iter.max = 1))
  full <- nlminb(start, fn, gr)
  print(c(start = start, limited_gradient = gr(short$par), full_value = full$objective, full_gradient = gr(full$par)))
}
```
