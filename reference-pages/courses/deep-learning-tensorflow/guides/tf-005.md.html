Purpose and mental model#

A derivative describes how a function changes locally when its input changes. It is neither a new parameter nor a promise that every finite movement will improve a loss. Before asking an automatic-differentiation framework for a number, use a small scalar function whose slope you can derive and independently approximate.

Our reference is f(w)=(w−2)2f(w)=(w-2)^2. Its derivative is 2·(w−2)2\cdot (w-2), so at w=0w=0 the slope is -4. A central finite difference evaluates the function on both sides of the point and divides the change by the total interval. For this quadratic, the symmetric approximation equals the derivative apart from floating-point rounding. A forward-only approximation has a visible step-size bias.

Derivatives also have boundaries. At a kink such as abs(w) at zero, a symmetric difference can return zero even though the ordinary two-sided derivative does not exist. A single plausible-looking finite-difference result therefore is not proof that a function is differentiable. We will distinguish local slope, update direction, finite step and nondifferentiable cases explicitly before the chain rule and tape lessons.

Vocabulary and concepts#

Derivative: the local rate of change of a function with respect to a named input coordinate.

Finite difference: a numerical slope approximation using function values at nearby inputs.

Step size h: the distance used for the numerical probe, distinct from a training learning rate.

Learning rate: the multiplier applied to a gradient during a parameter update.

Kink: a point where the left and right local slopes disagree, so an ordinary two-sided derivative does not exist.

Syntax or reasoning anatomy#

The central expression (f(w+h)-f(w-h))/(2·h2\cdot h) uses two function evaluations and the interval between them. Its numerator subtracts losses, while its denominator is measured in parameter units. A learning update w - rate·gradient\mathrm{rate}\cdot \mathrm{gradient} is a separate operation performed only after a gradient is known. Subtraction of a negative gradient increases w.

The helper validates a positive finite probe size and finite point and function values. It is not a symbolic proof engine. A smaller h can reduce approximation bias but eventually worsens rounding/cancellation, so do not equate smallest with best. Use several scales and an analytic reference where available. At a known kink, explain the one-sided behavior rather than forcing an equality with the central result.

Derive the approximation instead of trusting a small h#

Expanding f(w+h) for f(w) = (w-2) squared gives f(w) + 2(w-2)h + h squared. The forward difference therefore equals 2(w−2)2(w-2) + h. Subtracting the matching expansion at w-h cancels the h-squared terms, so the central difference equals 2(w−2)2(w-2) in exact arithmetic. This exact cancellation is a special convenience of the quadratic fixture, not a promise for every smooth function.

For a general smooth function, a central difference commonly has a truncation error proportional to h squared near a well-behaved point. Floating-point subtraction introduces another error: if h becomes too small, f(w+h) and f(w-h) can round to nearly the same stored value. Smaller h is therefore not always better. Compare several scales and an independent analytic derivative when one is available.

The probe distance h and the learning rate have different jobs. The former estimates a slope; the latter chooses how far to update a parameter. A correct negative slope only describes local behavior. A large enough update can pass the minimum and increase the loss, which the later gradient-step lesson checks explicitly.

Worked example / walkthrough#

Run Examples A and B in order in one scratch file, then run that complete file in a fresh process. Example B may reuse the imports, helpers and fixture state established in Example A. Do not treat an isolated later block as a standalone program.

Example A: A negative local slope#

Compare the derivative and a central probe at zero.

import math

f = lambda w: (w - 2) ** 2
w, h = 0.0, 0.01
central = (f(w + h) - f(w - h)) / (2 * h)
assert math.isclose(central, -4.0, rel_tol=0, abs_tol=1e-10)
updated = w - 0.1 * central
assert math.isclose(updated, 0.4, rel_tol=0, abs_tol=1e-12)
print(central, updated, f(updated))

Expected: The slope is -4, the update is 0.4 and the new loss is approximately 2.56. Three different quantities should be labeled separately.

Example B: A symmetric answer at a kink is not a derivative proof#

Keep the point zero but replace the quadratic with absolute value.

h = 0.01
left_slope = (abs(0.0) - abs(-h)) / h
right_slope = (abs(h) - abs(0.0)) / h
central = (abs(h) - abs(-h)) / (2 * h)
assert (left_slope, right_slope, central) == (-1.0, 1.0, 0.0)
print(left_slope, right_slope, central)

Expected: The one-sided slopes differ. The central zero is an arithmetic average of two incompatible sides, not an ordinary derivative at zero.

Progressive hints#

  • Hint 1: Differentiate the scalar expression before substituting the current weight.
  • Hint 2: For central differences, the two probes are separated by 2·h2\cdot h, not h.
  • Hint 3: At a kink, compare one-sided slopes and state the limitation instead of hiding their disagreement.

Common pitfalls#

If a finite-difference check varies wildly as h shrinks, inspect subtraction of nearly equal floating values and try several sensible scales. If an update moves in the wrong direction, write the sign of the derivative and the subtraction explicitly. If a reported gradient equals a parameter by coincidence, retain separate names and units so the concepts do not collapse together.

At a kink, one-sided probes reveal more than the symmetric average. An automatic system can choose a convention there, but a convention is not a proof of classical differentiability. A local negative slope also cannot guarantee that an excessively large update helps; that finite-step limitation remains important in the later three-point pilot.
