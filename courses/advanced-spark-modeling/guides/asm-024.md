# asm-024: Forward-mode dual numbers inside JVM rows

Tutorial mode. Stage: advanced. Direct prerequisites: `asm-013`, `clp-003`.

## Starting point and result

Automatic differentiation applies the chain rule to a computation built from supported operations. It does not approximate derivatives by perturbing inputs. This chapter implements a tiny forward-mode dual number in Scala and evaluates it in a Spark Dataset. The supported operations are addition, multiplication and exponential, sufficient to differentiate \(f(x)=x^2+e^x\).

## Key terms

- **Automatic differentiation:** Applying the chain rule to a computation built from supported primitives, without perturbing inputs as finite differences do.
- **Forward mode:** The AD mode that propagates one directional derivative alongside each value as the computation runs.
- **Dual number:** A pair a + b epsilon with epsilon squared equal to zero, where a is the value and b is the tangent.
- **Tangent seed:** The initial derivative component of the input, such as one for the derivative with respect to x.
- **Reverse mode:** The AD mode that records a tape and propagates adjoints backward, often cheaper with many parameters and one scalar output.

## Mechanism: carry a value and a tangent

Represent a dual number as \(a+b\varepsilon\), where \(\varepsilon^2=0\). The value a is the ordinary quantity; b is its directional derivative. Addition adds both components. Multiplication follows

\[(a+b\varepsilon)(c+d\varepsilon)=ac+(ad+bc)\varepsilon.\]

For exponential, \(\exp(a+b\varepsilon)=e^a+be^a\varepsilon\). The `Dual` case class implements these rules directly. Seeding the input with tangent one computes the derivative with respect to x. Seeding tangent two computes twice that directional derivative.

This is genuine automatic differentiation for the small supported program. The author supplies derivative rules for primitives, and composed operations propagate tangents automatically. It is not symbolic algebra and does not retain a reverse-mode tape. With many parameters and one scalar output, repeated forward directions can be expensive; reverse mode is often preferable.

## Worked case: differentiate three observations on executors

The Dataset contains x values -1, zero and one. Each task evaluates `f(Dual(x, 1))` and returns x, function value and tangent. The driver compares values with \(x^2+e^x\) and tangents with the analytic derivative \(2x+e^x\). All checks use tight double tolerances.

The computations run within JVM task code. Spark schedules and transports the results; the Dual implementation performs differentiation. This distinction is the answer to whether Spark can “do autodiff natively”: a derivative mechanism can run in JVM tasks, but Spark SQL itself is not thereby a general differentiable programming system.

## Worked case: a non-unit direction

At x=1, the input tangent is changed to two. The output tangent must be \(2(2+e)\). This checks that the implementation carries a direction rather than hard-coding a derivative formula for one seed. If multiplication incorrectly uses only one product-rule term, the square contribution exposes the defect.

For a vector parameter, a direction v produces a Jacobian-vector product. Carrying a full vector tangent can compute all first derivatives in one pass but increases storage and arithmetic. A scalar tangent example does not establish performance for millions of parameters or arbitrary neural-network operations.

## Worked example: a Python Dual with a broken product rule

```python
import math
from dataclasses import dataclass


@dataclass(frozen=True)
class Dual:
    value: float
    tangent: float

    def __add__(self, b):
        return Dual(self.value + b.value, self.tangent + b.tangent)

    def __mul__(self, b):
        return Dual(self.value * b.value, self.tangent * b.value + self.value * b.tangent)

    def exp(self):
        e = math.exp(self.value)
        return Dual(e, e * self.tangent)


class HalfProduct(Dual):
    def __mul__(self, b):
        return HalfProduct(self.value * b.value, self.tangent * b.value)


for kind in (Dual, HalfProduct):
    out = [(x, (lambda d: d * d + d.exp())(kind(x, 1.0)).tangent) for x in (-1.0, 0.0, 1.0)]
    print(kind.__name__, [(x, round(t, 6)) for x, t in out])
print("analytic", [round(2 * x + math.exp(x), 6) for x in (-1.0, 0.0, 1.0)])
d = Dual(1.0, 2.0)
print("direction 2 at x=1:", round((d * d + d.exp()).tangent, 6), round(2 * (2 + math.e), 6))
```

Output from running the block above:

```text
Dual [(-1.0, -1.632121), (0.0, 1.0), (1.0, 4.718282)]
HalfProduct [(-1.0, -0.632121), (0.0, 1.0), (1.0, 3.718282)]
analytic [-1.632121, 1.0, 4.718282]
direction 2 at x=1: 9.436564 9.436564
```

The Python Dual mirrors the Scala case class line for line, so its tangents for f(x) = x squared plus e to the x can be compared with the analytic derivative 2x + e to the x. At -1, 0 and 1 the correct class returns -1.632121, 1.0 and 4.718282, matching the analytic list exactly. The HalfProduct variant keeps only the first product-rule term, so the square contributes x instead of 2x and every tangent away from zero is off by x. At x = 0 both versions agree, which is why a test at the origin alone would pass the defect. With the seed tangent 2 at x = 1 the result is 9.436564, twice the unit-direction derivative.

## Failure diagnosis

A primitive operation missing a derivative rule breaks the supported computation domain. Extracting `.value` early and reconstructing a Dual with zero tangent severs derivative flow. Branches produce the derivative of the executed branch away from discontinuities; they do not magically make a non-smooth function differentiable at its boundary. Exponential overflow remains possible because AD does not eliminate ordinary numerical limits.

## Interview discussion

**Is this finite differencing?** No. The tangent propagates exact chain-rule arithmetic for the implemented primitives, subject to floating-point rounding. There is no step-size parameter.

**Does this differentiate a shuffle or sort?** No. The differentiated program is the per-row function. Distributed aggregation, ordering and optimization are separate layers whose derivative semantics must be designed explicitly.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-scala`.

```scala
import org.apache.spark.sql.{SparkSession, DataFrame, Dataset, Encoder, Encoders}
import org.apache.spark.sql.functions._

case class Dual(value: Double, tangent: Double) {
  def +(b: Dual) = Dual(value + b.value, tangent + b.tangent)
  def *(b: Dual) = Dual(value * b.value, tangent * b.value + value * b.tangent)
  def exp: Dual = { val e = math.exp(value); Dual(e, e * tangent) }
}
object Main {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder
      .master("local[2]")
      .appName("advanced-spark-modeling")
      .config("spark.ui.enabled", "false")
      .config("spark.driver.host", "127.0.0.1")
      .config("spark.driver.bindAddress", "127.0.0.1")
      .config("spark.sql.shuffle.partitions", "2")
      .config("spark.sql.adaptive.enabled", "false")
      .config("spark.sql.ansi.enabled", "true")
      .getOrCreate()
    require(spark.version == "4.3.0", "This example targets Spark 4.3.0")
    spark.sparkContext.setLogLevel("ERROR")
    import spark.implicits._
    try {
      def f(x: Dual): Dual = x * x + x.exp
      val input = Seq(-1.0, 0.0, 1.0).toDS()
      val result = input.map(x => { val d = f(Dual(x, 1.0)); (x, d.value, d.tangent) }).collect()
      result.foreach { case (x, value, derivative) =>
        require(math.abs(value - (x * x + math.exp(x))) < 1e-12)
        require(math.abs(derivative - (2 * x + math.exp(x))) < 1e-12)
      }
      val directional = f(Dual(1.0, 2.0))
      require(math.abs(directional.tangent - 2 * (2 + math.E)) < 1e-12)
      println(result.toSeq.toString)
      println(
        "Original bounded forward-mode implementation; no derivatives through Spark scheduling or arbitrary SQL"
      )
    } finally { spark.stop() }
  }
}
```
