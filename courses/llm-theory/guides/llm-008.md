## Purpose and mental model

An embedding lookup selects feature rows from a table using token IDs. The vocabulary axis and the feature axis have different roles. A table with four token rows and two features can map a three-token input into a three-row, two-feature result. Repeated token IDs select the same learned feature values; they do not create new independent vocabulary entries.

Use the fixed table [[1,0],[0,1],[2,2],[-1,1]] and IDs [2,0,2]. The output is [[2,2],[1,0],[2,2]]. Nothing was trained in this example. The values are supplied parameters so the mechanism can be inspected without claiming that they encode useful semantics.

Token IDs also require a strict domain policy. NumPy normally permits negative indices and wraps them from the end, which is not the desired interpretation of an invalid token ID. Reject negative and out-of-range values, reject fractional IDs, and keep tokenizer/table identity aligned. A vocabulary permutation must be paired with an ID remapping or a syntactically valid lookup will silently choose the wrong features.

## Vocabulary and concepts

**Embedding table:** a matrix with one parameter row per vocabulary ID and a declared feature width.

**Token ID:** an integer selecting a legal row; it is not a feature coordinate or a numeric measure of word meaning.

**Lookup:** selection of table rows in input order, allowing repeated IDs.

**One-hot vector:** a vocabulary-width indicator with one selected coordinate, whose product with the table reproduces a lookup.

**Vocabulary alignment:** the agreement between tokenizer IDs and embedding rows, including model/version identity.

## Syntax or reasoning anatomy

table[ids] uses advanced integer indexing to select rows. For a table shaped (vocabulary,features) and one-dimensional IDs shaped (tokens,), the result is (tokens,features). The same operation can be written as one_hot(ids) @ table, which makes the vocabulary axis explicit without being the preferred memory-efficient implementation.

The reference requires a finite nonempty table and integer rank-one IDs in the legal range. An empty ID list is explicitly accepted and returns shape (0,features); the later attention function separately rejects an empty sequence. Advanced indexing returns independent output storage in this reference, so changing an exercise result must not overwrite the table or another repeated row. State this mutation contract rather than assuming every array view behaves alike.

## Worked example / walkthrough

### Example A: Repeated IDs preserve token order

Inspect rows two, zero and two of the fixed table.

```python
import numpy as np

table = np.array([[1, 0], [0, 1], [2, 2], [-1, 1]], dtype=np.float64)
ids = np.array([2, 0, 2], dtype=np.int64)
output = table[ids]
np.testing.assert_array_equal(output, [[2, 2], [1, 0], [2, 2]])
assert output.shape == (3, 2)
print(output)
```

**Expected:** The first and third outputs match because the same vocabulary row was selected twice. Two is the feature width, not the number of token choices.

### Example B: A legal NumPy index can be an illegal token ID

Show the behavior that the domain guard must reject.

```python
wrapped = table[np.array([-1])]
np.testing.assert_array_equal(wrapped, [[-1, 1]])
assert int(np.array([-1])[0]) < 0
print(wrapped)
```

**Expected:** NumPy interprets -1 as the final row. Our token contract rejects it instead of silently treating an invalid ID as a valid vocabulary member.

## Common pitfalls

If a lookup returns plausible but wrong features, inspect token-ID mapping and vocabulary order before changing the model. Negative indices are especially dangerous because NumPy accepts them. Fractional values must not be rounded into token IDs without a declared tokenizer policy. A shape check cannot detect a vocabulary permutation with the same row count.

If editing a result changes the table, inspect whether another implementation returned a view or shared storage. Keep copies explicit for this learning boundary. Fixed feature vectors are not evidence that a word meaning, factual relationship or causal explanation has been learned. The next attention unit combines these features under an information mask and needs its own shape, empty-input and causal checks.
