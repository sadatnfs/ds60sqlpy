## Outcome and mechanism

Construct a labeled base-R graphic and manage an explicitly owned file device without confusing drawing with browser delivery.

Base graphics draws into the active graphics device. A high-level plot establishes a coordinate system and axes, while lower-level functions such as points, lines, segments and text add marks to that existing plot. Calling another high-level plot usually starts a new plot rather than adding a layer to the current one.

The coordinate system should match the analytic meaning. A scatterplot shows paired observations; connecting points with lines introduces an order relationship. If rows are not sorted by the intended time or predictor, a line can imply transitions that the data do not support. Label axes with quantities and units rather than relying on familiar-looking numbers.

A graphics device is an output target, such as the classroom's captured PNG device or an explicitly opened file. Opening a PNG device and then calling plot is different from merely constructing an object that describes a plot. Closing the owned device flushes its output, after which the file can be inspected. A file existing before closure may not yet represent a complete image.

Device ownership matters in reusable code. A helper should close only the device it opened and clean up only its own temporary files. Closing every device or deleting a broad output directory can interfere with the surrounding classroom or another analysis. Use scoped cleanup and preserve the caller's device when returning.

The default classroom captures base graphics separately from the numerical transcript. The file-device example demonstrates actual PNG creation and signature validation in an owned temporary path. It does not by itself prove that a browser displayed the image, that every text label is readable at the final size, or that a printed export meets publication requirements. Those are additional visual checks.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Device | The active destination for graphical drawing commands. |
| High-level plot | A call establishing a new plot and coordinate system. |
| Overlay | Marks added to the current plot without replacing its coordinate system. |
| Owned output | A file or device created by the current operation and cleaned up within that scope. |

## Read the syntax

Use plot to establish axes and labels, then points or abline to add marks in the same coordinates. xlim/ylim define the intended range; xaxs="i" and yaxs="i" remove default range expansion when exact coordinate checks are needed. For a file, call grDevices::png, retain dev.cur(), draw, then dev.off for that owned device before reading its bytes.

## Worked examples

### Example 1: A labeled plot with an overlay

```r
d <- data.frame(x = 0:4, y = c(0, 2, 4, 6, 8))
plot(d$x, d$y, xlim = c(0, 4), ylim = c(0, 8), xaxs = "i", yaxs = "i", xlab = "Input value", ylab = "Response value", pch = 16, main = "Observed pairs and stated linear rule")
abline(a = 0, b = 2, col = "#1B5E20", lwd = 2)
stopifnot(max(abs(par("usr") - c(0, 4, 0, 8))) < 1e-12)
stopifnot(all(d$y == 2 * d$x))
```

**Expected observation:** One base graphic; coordinate limits 0/4/0/8 and the line through all five points.

The line overlays the same coordinate system as the observations. The exact axis limits are checked without interpreting that software check as a visual readability review.

### Example 2: Write and close an owned PNG

```r
d <- data.frame(x = 1:3, y = c(2, 1, 4))
write_owned <- function() {
  path <- tempfile(fileext = ".png")
  grDevices::png(path, width = 500, height = 350, type = "cairo")
  owned_device <- dev.cur()
  on.exit(
    {
      if (dev.cur() == owned_device) dev.off(); unlink(path)
    },
    add = TRUE
  )
  plot(d$x, d$y, pch = 16, xlab = "Observation", ylab = "Value")
  dev.off()
  signature <- readBin(path, what = "raw", n = 8)
  stopifnot(identical(signature, as.raw(c(137, 80, 78, 71, 13, 10, 26, 10))))
  stopifnot(file.info(path)$size > 0)
  file.info(path)$size
}
print(write_owned())
```

**Expected observation:** A nonempty PNG with the expected signature, followed by owned cleanup.

The function closes its device before reading the signature, then removes only its own tempfile. It returns evidence of file production, not a claim that an external viewer rendered it.
