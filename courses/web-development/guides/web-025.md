# web-025: Connect HTML to JavaScript: DOM, events and safe text

## Level and prerequisites

Advanced; allow about 140 minutes, with extra time for independent practice. Direct prerequisites: `web-024`, `js-029`

## Learning objectives

Build a native-button counter with a reset action and output. Explain why reading state back from formatted text is fragile. Use DOM, event listener and textContent accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

The document object model is the browser's live tree of elements. JavaScript can select a node, observe an event and update content. HTML supplies the structure, CSS supplies presentation, and JavaScript handles behavior. Start with a native button so keyboard activation and focus work without reimplementation. The event listener is a function called when a matching event occurs; it is not the same as calling the function immediately while registering it.

Keep state separate from the text that displays it. A numeric count in a variable is the source of truth; a render function translates it into a label. Reading the current label and repeatedly parsing it back into a number couples business state to presentation. Use textContent for plain user text because it creates text rather than parsing markup.

### Key terms

- **DOM:** The Document Object Model, the live tree of objects the browser builds from HTML, which scripts can read and change.
- **Event listener:** A function registered with `addEventListener` that runs when a named event, such as `click`, reaches an element.
- **TextContent:** The `textContent` property, which reads or sets an element's text without parsing it as HTML, so data cannot become markup.
- **State:** The data a script keeps about the interface, such as a count or a selected item, from which the display is drawn.
- **Deferred script:** A script marked `defer`, or a module script, that runs after the document is parsed, so the elements it needs already exist.

## Syntax anatomy and mechanism

`document.querySelector('#add')` returns a matching element or null. `addEventListener('click', handler)` registers a function. Update the number, then render the new value to an output element. Query elements after they exist, for example with a script at the end of the body. For JavaScript syntax, revisit the JavaScript foundations and browser chapters rather than treating this lesson as a substitute for that route.

A classic inline script runs when the parser reaches it. A script in the head cannot assume that later body elements already exist. Separate classic script tags share the document's global lexical environment, while a module has its own scope and strict semantics. DOMContentLoaded fires after parsing and the relevant deferred script work; it does not mean every image has loaded. The load event describes the later document load boundary. Register a listener before its event occurs, or inspect readyState when code can be loaded at different times.

An external classic script with defer preserves document order and waits for parsing. Async scripts do not provide that same ordering guarantee. Defer does not turn an inline classic script into a deferred one. Inline modules use real module semantics, including top-level this being undefined. The classroom supports inline modules but blocks external script files and imports. Study multi-file loading in a separately prepared local project rather than weakening the preview policy.

## Worked example / walkthrough

### Worked example 1: Update text safely

A name is data even when it contains angle brackets.

```javascript
const label = document.querySelector('#label');
label.textContent = '<new learner>';
```

**Expected observation:** The literal name appears as text, not a new HTML element.

### Worked example 2: A small state transition

The state is numeric and independent of its label.

```javascript
let count = 0;
button.addEventListener('click', () => {
  count += 1;
  output.textContent = String(count);
});
```

**Expected observation:** Each activation increments the stored number and updates the display.

## Contrast case: a script that runs before its button exists

The counter code is unchanged. Only the position of the classic script tag differs between the two documents.

```html
<!-- A: script in head -->
<head>
  <script>
    const button = document.querySelector('#add');
    button.addEventListener('click', () => {});
  </script>
</head>
<body
  ><button id="add" type="button">Add</button></body
>

<!-- B: deferred until parsing ends -->
<head
  ><script defer src="counter.js"></script
></head>
```

A classic inline script runs the moment the parser reaches it. In document A the body has not been parsed yet, so `querySelector('#add')` returns null and the next line throws a TypeError, which stops the rest of that script. The button later appears but has no listener, so clicks do nothing. Document B uses `defer` on an external file, which waits until parsing finishes, so the query finds the button. Placing the inline script at the end of the body has the same effect.

## Debugging and common mistakes

Do not invoke handler() when you meant to pass handler to the listener. Avoid using innerHTML for plain labels. A programmatic click checks logic but does not replace a keyboard interaction test.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
