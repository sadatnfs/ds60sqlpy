Leakage-Resistant Evaluation Across Groups and Time#

Stable ID: python-ml-02

Estimated time: 270 minutes, split across sessions as needed.

Learning objectives#

  • Choose held-out groups or forward time windows from the deployment question.
  • Separate observation time, feature availability, and label availability.
  • Fit preprocessing and baselines only from permitted training records.
  • Audit fold membership, coverage, and error without treating one score as proof of deployment validity.

Vocabulary and concepts#

A test set represents a future decision, not merely a random fraction of rows. If the system must predict for new customers, holding out rows from customers already seen during training can answer the wrong question. If it must operate next month, training on records whose labels arrived after the decision date gives it information unavailable at the time. Start by naming the information a real predictor would possess at its prediction instant.

  • Leakage: information entering training or evaluation that would not have been available under the intended prediction conditions.
  • Group holdout: keeping all records for selected entities outside training, used to study generalization to those unseen entities.
  • Observation time: the instant at which the predictor must make its decision for a record in this lab.
  • Feature availability: the earliest instant an input value is usable, which may be later than its source event time.
  • Label availability: the instant the true target becomes known.
  • Embargo gap: a declared interval before validation during which labels are not allowed into this training fold.
  • Walk-forward evaluation: repeated training on permitted past data and scoring successive future windows.

Each Observation has an event id, entity id, observation instant, feature availability instant, label availability instant, numeric feature, and target. All timestamps must be aware. Features must be available by the observation instant, and labels cannot become available before observation. Numeric values must be finite. Event identities are unique. These are teaching assumptions, not a claim that all applications reveal labels only after prediction.

Group holdout and time holdout answer different questions. The first excludes entities globally; the second may allow returning entities whose past records are legitimate training information. Neither split automatically proves the other policy. If deployment requires both new entities and future time, compose both constraints and audit the resulting smaller training set. Do not claim group independence simply because row identities are disjoint.

Worked example / walkthrough#

Example A: entity overlap can hide behind different row ids#
training = [{"event": "a1", "entity": "A"}, {"event": "b1", "entity": "B"}]
validation = [{"event": "a2", "entity": "A"}]
train_ids = {row["event"] for row in training}
test_ids = {row["event"] for row in validation}
train_entities = {row["entity"] for row in training}
test_entities = {row["entity"] for row in validation}
assert not train_ids & test_ids
assert train_entities & test_entities == {"A"}

Set intersection & reveals shared membership. Different event ids do not guarantee different entities. Expected observation: no row overlap, but entity A appears on both sides. That is a defect for an unseen-entity question and may be allowed for a returning-entity future-time question. The score alone cannot decide which question the experiment actually answers.

Example B: delayed labels change the legal training set#
from datetime import datetime, timedelta, timezone

cutoff = datetime(2026, 1, 5, tzinfo=timezone.utc)
gap = timedelta(days=1)
label_available = datetime(2026, 1, 4, tzinfo=timezone.utc)
assert not (label_available < cutoff - gap)
assert label_available < cutoff

Expected observation: the label is earlier than validation but lies exactly at the embargo boundary, so the declared strict-before training policy excludes it. In this lab, training requires observation before cutoff and label availability strictly before cutoff minus gap. Validation owns observations in [cutoff, end) when an end is supplied. Excluded records are counted, not silently forgotten. The boundary is conservative and explicit; other applications can choose differently if they test and justify their policy.

A baseline makes the experiment inspectable#

Fit the constant prediction as the mean of permitted training targets. Score mean absolute error on validation targets. This baseline is intentionally simple enough to calculate by hand. For training targets zero and zero with a held-out target one hundred, the permitted prediction is zero and the test error is one hundred. Including the held-out target when fitting the mean would improve that same test score, but make the experiment invalid.

The same restriction applies to feature scaling, imputation, feature selection, and threshold tuning. Fit each learned transformation inside its training fold. The reference mean-centering exercise checks feature fitting separately from target fitting so these two uses of a mean are not confused. A final untouched test set is still needed after selecting among modeling policies.

Report coverage beside error#

Each fold report should list training ids, validation ids, excluded count, permitted training target mean, and validation MAE. Empty train or validation sets fail visibly; a zero denominator does not become a fake score of zero. When comparing policies, retain their membership and coverage so different scores cannot conceal different evaluated populations. Repeated walk-forward scores share training history and may share entities, so they are not automatic independent confidence-interval samples. State those limits with the result.

Common pitfalls#

If evaluation looks implausibly good, inspect fitted state and feature availability before trying a more complex model. If one event is scored in two folds, inspect the exclusive end boundary. If a fold unexpectedly empties, report excluded ids and label delays. If the metric returns zero on no rows, repair its preconditions. If entity sets overlap, compare that fact against the declared question before calling it either acceptable or a defect.

Leakage-Resistant Evaluation Across Groups and Time: solution reasoning#

Stable ID: python-ml-02.

Read the guide and attempt the learner artifact first. The executable solution is a comparison implementation. It does not certify your changed program merely because its own demonstration succeeds. Copy the acceptance cases into your attempt, then change one input without changing the intended policy.

The reference separates source validation, split policy, fitted state, and metric calculation. A constant predictor makes it possible to check the entire experiment by hand. There is no estimator dependency and no random split hiding membership. A production model can replace the baseline later without changing the availability questions.

permitted_targets = [0.0, 0.0]
prediction = sum(permitted_targets) / len(permitted_targets)
assert abs(100.0 - prediction) == 100.0

The report retains identities and population sizes beside the score. A score from an empty set is rejected. Group and time splits remain separate because the intended deployment question decides whether both constraints apply. Membership evidence does not establish that the sampled population represents future demand, nor does it prove causal effects.

Exercise 1. Validate availability before splitting#

Validate the whole source before choosing a subset. Event ids must be nonempty trimmed strings and unique; entity ids must be nonempty trimmed strings. Timestamps must have usable offsets and are compared as instants. A feature becoming usable after observation is future information. A label earlier than observation violates the teaching record contract. Equality is permitted at either availability boundary. Reject nonfinite features and targets, including booleans masquerading as numbers. These checks address representation and declared availability, not whether the recorded timestamps are factually accurate.

Exercise 2. Hold out whole entities#

The held-out set names entities, so every record for A enters validation and none enters training. Source ordering is preserved for inspectable comparisons. Requiring both sides to contain data prevents a meaningless score when the requested holdout is absent or includes the entire source. The reference also rejects unknown held-out entities, making a misspelled group visible. Entity intersection is checked independently of event-id intersection. A time split may legitimately retain the same returning entity on both sides, so keep the experiment question beside the membership assertions.

Exercise 3. Enforce delayed-label time policy#

Training requires observation before cutoff and label availability strictly before cutoff minus the nonnegative gap. The optional validation end must follow cutoff and is exclusive. A label exactly at the embargo threshold is excluded under the declared conservative rule; moving it one second earlier makes it eligible if observation also precedes cutoff. Records after the validation end or with unavailable training labels contribute to excluded_count. The source count must equal training plus validation plus excluded. This policy does not guess or backfill labels unavailable at the historical decision point.

Exercise 4. Fit a transformation only on training#

Fit the mean from training feature values two and four, yielding three. Subtract that already-fitted mean from both training and validation values. The validation value one hundred therefore becomes ninety-seven. Including it while fitting yields a different parameter and contaminates the experiment, even though no target was used. This is transformation leakage. Keep the learned state explicit so a test can inspect it. In a larger pipeline, fit imputation, scaling, feature selection, and other learned preprocessing inside each fold rather than once before splitting.

Exercise 5. Calculate a transparent baseline#

The training target mean of zero and zero is zero. Repeating that prediction for the validation target one hundred produces MAE one hundred. The metric validates equal nonzero lengths and finite numeric values before calculating. The report rejects shared event ids so a caller cannot score the exact same record it trained on. It does not require entity disjointness universally because a returning-entity time policy may allow overlap. A metric should report its unit and aggregation; MAE here has the target's units and weights each validation record equally.

Exercise 6. Rehearse walk-forward windows#

Build each forward fold with an explicit cutoff and next boundary. The half-open end prevents a shared-boundary event from appearing in both adjacent validation windows. Refit using the permitted past and the same availability predicate each time. An earlier validation event may later become legal training information once its label is available; that is normal walk-forward behavior rather than leakage. Preserve ids, exclusion counts, and fitted means in each report. These folds share history and may share entities, so treating their scores as independent observations for uncertainty would need additional justification.

Exercise 7. Demonstrate a misleading improvement#

The deliberately leaked training mean includes target one hundred and becomes roughly thirty-three and one third. Its validation absolute error becomes roughly sixty-six and two thirds, appearing better than the permitted error one hundred. That numerical improvement is produced by using the answer during fitting. The exercise is intentionally a scratch comparison, not a recommended implementation. Retain it as a diagnostic demonstration that model-selection pressure can reward invalid experiments. A model should never choose its own availability rules based on which rules produce the best held-out score.

Exercise 8. Transfer to the deployment question#

Returning-customer next-day prediction needs forward-time availability and may use prior records for the same customer. New-customer next-day prediction additionally needs customer-level exclusion so no historical record for that customer enters training. Both need feature availability checks, label delay policy, explicit gap where appropriate, and coverage reporting. A final test set protects against adapting repeatedly to validation results while selecting these policies. It cannot guarantee the future population remains unchanged. State that limitation and monitor deployment inputs rather than presenting a split as permanent acceptance evidence.

"""Inspectable group/time evaluation without an estimator dependency."""
 
from __future__ import annotations
 
import math
from dataclasses import dataclass
from datetime import UTC, datetime, timedelta
from statistics import fmean
 
 
@dataclass(frozen=True)
class Observation:
    event_id: str
    entity_id: str
    observed_at: datetime
    feature_available_at: datetime
    label_available_at: datetime
    feature: float
    target: float
 
 
def _aware(value: datetime) -> datetime:
    if not isinstance(value, datetime) or value.utcoffset() is None:
        raise ValueError("timestamps must be aware")
    return value.astimezone(UTC)
 
 
def _finite(value: float) -> bool:
    return isinstance(value, (int, float)) and not isinstance(value, bool) and math.isfinite(value)
 
 
def validate_observations(rows: list[Observation]) -> None:
    seen: set[str] = set()
    for row in rows:
        if any(
            not isinstance(value, str) or not value or value != value.strip()
            for value in (row.event_id, row.entity_id)
        ):
            raise ValueError("identities must be nonempty trimmed text")
        if row.event_id in seen:
            raise ValueError("duplicate event id")
        seen.add(row.event_id)
        observed, feature_at, label_at = map(
            _aware, (row.observed_at, row.feature_available_at, row.label_available_at)
        )
        if feature_at > observed:
            raise ValueError("feature unavailable at prediction time")
        if label_at < observed:
            raise ValueError("label availability precedes observation")
        if not _finite(row.feature) or not _finite(row.target):
            raise ValueError("features and targets must be finite numbers")
 
 
def group_split(
    rows: list[Observation], held_out: set[str]
) -> tuple[list[Observation], list[Observation]]:
    validate_observations(rows)
    entities = {row.entity_id for row in rows}
    if not held_out or not held_out <= entities:
        raise ValueError("held-out entities must be a nonempty known subset")
    training = [row for row in rows if row.entity_id not in held_out]
    validation = [row for row in rows if row.entity_id in held_out]
    if not training or not validation:
        raise ValueError("training and validation must both be nonempty")
    return training, validation
 
 
def time_split(
    rows: list[Observation],
    cutoff: datetime,
    gap: timedelta = timedelta(0),
    end: datetime | None = None,
) -> tuple[list[Observation], list[Observation], int]:
    validate_observations(rows)
    cutoff = _aware(cutoff)
    end = _aware(end) if end is not None else None
    if gap < timedelta(0) or (end is not None and end <= cutoff):
        raise ValueError("gap must be nonnegative and end must follow cutoff")
    training = [
        row
        for row in rows
        if _aware(row.observed_at) < cutoff and _aware(row.label_available_at) < cutoff - gap
    ]
    validation = [
        row
        for row in rows
        if _aware(row.observed_at) >= cutoff and (end is None or _aware(row.observed_at) < end)
    ]
    if not training or not validation:
        raise ValueError("training and validation must both be nonempty")
    return training, validation, len(rows) - len(training) - len(validation)
 
 
def fit_mean(values: list[float]) -> float:
    if not values or not all(_finite(value) for value in values):
        raise ValueError("mean requires nonempty finite numbers")
    result = fmean(values)
    if not math.isfinite(result):
        raise ValueError("mean overflowed")
    return result
 
 
def mae(actual: list[float], predicted: list[float]) -> float:
    if (
        not actual
        or len(actual) != len(predicted)
        or not all(_finite(value) for value in actual + predicted)
    ):
        raise ValueError("MAE requires equal nonempty finite vectors")
    return fit_mean([abs(a - p) for a, p in zip(actual, predicted, strict=True)])
 
 
def evaluate_baseline(
    training: list[Observation], validation: list[Observation]
) -> dict[str, object]:
    validate_observations(training + validation)
    prediction = fit_mean([row.target for row in training])
    score = mae([row.target for row in validation], [prediction] * len(validation))
    return {
        "train_ids": [row.event_id for row in training],
        "validation_ids": [row.event_id for row in validation],
        "train_count": len(training),
        "validation_count": len(validation),
        "train_target_mean": prediction,
        "mae": score,
    }
 
 
if __name__ == "__main__":
    t = datetime(2026, 1, 1, tzinfo=UTC)
    rows = [
        Observation("A1", "A", t, t, t, 2.0, 0.0),
        Observation("B1", "B", t, t, t, 4.0, 0.0),
        Observation("C1", "C", t + timedelta(days=2), t, t + timedelta(days=3), 100.0, 100.0),
    ]
    training, validation = group_split(rows, {"C"})
    report = evaluate_baseline(training, validation)
    assert report["train_target_mean"] == 0.0 and report["mae"] == 100.0
    print(report)
