js-011: Iterators and generators#

Level and prerequisites#

Beginner, approximately 90 minutes. Direct prerequisites: js-010

Learning objectives#

Explain iterable, iterator, suspension, iterator closing with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. The first investigation is: Create a generator, inspect its trace, then request one value. The final task tests bound the range and validate configuration.

Purpose and mental model#

An iterable describes how to obtain an iterator. An iterator describes how to ask for the next value. A generator function is a convenient state machine implementing this protocol: calling it creates a suspended generator, next() advances execution to a yield, and the result reports value plus done. The generator body does not run merely because the generator object was created.

Laziness allows a consumer to stop before computing every possible value. It does not make an expensive step cheap, and converting a huge iterable with spread still materializes every value in memory. A generator object is usually a one-use cursor; a generator function can create a fresh cursor each time. This matters when a second pass unexpectedly produces no rows.

Early termination is also a resource question. for...of invokes the iterator's return method when a break leaves the loop. A generator's finally block then runs if execution has entered its try block. Code that manually calls next() and abandons the iterator must explicitly close it when it owns resources. The examples record lifecycle events so cleanup is an observed state transition, not a comment promising eventual cleanup.

Vocabulary and concepts#

Iterable: An object with a Symbol.iterator method producing an iterator.

Iterator: An object whose next method returns a value/done record.

Suspension: Preserving local execution state between requests.

Iterator closing: Calling return to terminate an iterator and release owned resources.

Syntax anatomy and execution trace#

The star in function declares a generator; yield produces a value and suspends the local execution state. A return ends iteration and may supply a final result, but that result is not another yielded item. yield delegates to another iterable. Calling next(value) sends a value back into the suspended yield expression. The first next argument has no waiting yield to receive it. for...of reads yielded values and stops on done true.

Worked example / walkthrough#

Example A: Trace lazy execution#

Creating the cursor and executing its body are separate events. The trace distinguishes laziness from eager construction of an array.

import { strict as assert } from 'node:assert';

function* range(length) {
  if (!Number.isInteger(length) || length < 0 || length > 1000) throw new RangeError('length must be an integer from 0 to 1000');
  for (let value = 0; value < length; value += 1) yield value;
}

export async function verify() {
  // Worked example
  {
    const trace = [];
    function* values() { trace.push('started'); yield 2; trace.push('continued'); yield 4; }
    const cursor = values();
    assert.deepEqual(trace, []);
    assert.deepEqual(cursor.next(), { value: 2, done: false });
    assert.deepEqual(trace, ['started']);
    cursor.return();
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));

Expected: trace is empty before next; then started, with value 2.

Example B: Close on an early break#

The loop performs iterator closing when control exits through break. Resource-owning iterators should place cleanup in finally instead of assuming every consumer reaches the end.

import { strict as assert } from 'node:assert';

function* range(length) {
  if (!Number.isInteger(length) || length < 0 || length > 1000) throw new RangeError('length must be an integer from 0 to 1000');
  for (let value = 0; value < length; value += 1) yield value;
}

export async function verify() {
  // Worked example
  {
    const trace = [];
    function* rows() { try { trace.push('opened'); yield 1; yield 2; } finally { trace.push('closed'); } }
    for (const value of rows()) { trace.push(value); break; }
    assert.deepEqual(trace, ['opened', 1, 'closed']);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));

Expected: trace records opened, value 1, closed.

Prediction before your attempt#

Trace the entry point and identify the values that exist before each operation. Distinguish a value from a reference to an object, a returned Promise from its eventual result, and a compile-time type from a runtime check. Write down the first observation that would disprove your explanation. A useful prediction includes an expected value or failure category, not merely a claim that the program should work.

For a loop, write the state before and after one iteration. For a callback, identify the caller and the arguments it supplies. For an asynchronous operation, identify who starts it, who awaits it, and who owns cleanup. These small traces make failures local: you can compare the first incorrect state instead of guessing from a much later symptom.

Exercises#

  1. Trace lazy execution. Create a generator, inspect its trace, then request one value. Expected: trace is empty before next; then started, with value 2. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Close on an early break. Iterate one value from a generator protected by finally, then break. Expected: trace records opened, value 1, closed. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Distinguish a cursor from a fresh iterable. Consume one generator twice, then create a second generator. Expected: first pass is 0,1,2; second is empty; fresh pass repeats 0,1,2. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Inspect the final return value. Read a generator yielding 1 and returning 9, then compare spread. Expected: next records value 1/done false then 9/done true; spread contains only 1. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Send a value into a suspended generator. Suspend at a request, then send 4 to produce its double. Expected: request, then 8. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Bound the range and validate configuration. Produce an empty range and reject negative or fractional lengths. Expected: empty array for 0; RangeError for -1 and 1.5. Verify: Record the observed value, exception or browser state and compare it with that expectation.

Common pitfalls and diagnosis#

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.

Progressive hints#

Start by comparing the actual value with the literal expected result. Next, isolate the expression that transforms it or the boundary where its type or ownership changes. If the discrepancy involves scheduling, replace unrelated work with a small trace array and await the exact completion you intend to observe. Finally, ask for one hint about the first incorrect assumption before opening the reference. Keep one controlled failure that would catch the same mistake returning.
