Scientist and ML engineer learning roadmap#

This is the maintained map from the 25 October 2026 scientist review to the implemented 0.5 and 1.0 learning paths. The earlier review was a planning snapshot: R, JAX, prepared Bayesian tools and several deeper workflows were absent then. They are not a current missing-features list. This page describes checked-in teaching and supported execution contracts, not a claim that every platform or release image has passed qualification.

Start the Docker classroom, choose a subject, and follow its direct prerequisites. Existing projects keep their saved runtime selection. Use ./classroom --all to add the current ordinary set deliberately, or choose specific profiles. ./classroom resume never builds or pulls. Historical day numbers and lesson IDs are stable labels, not a deadline.

Choose a route for your current work#

A first-time programmer should start with Python foundations and the SQL on-ramp (sql-start-01 through sql-start-03), then learn arrays, data frames, joins, probability and model assessment. A different general-purpose language is not a prerequisite for every scientific branch.

  • Experimentation and applied science: statistics foundations, the experiment tutorials, then Applied Science cases relevant to the question. Treat causal identification, prediction and resource decisions as different objectives.
  • Bayesian and numerical modeling: the probability/likelihood material, Bayesian Computing's numerical foundations, actual PyMC workflows, then Stan. JAX and Julia are complementary branches when derivatives or language/runtime semantics are the learning goal.
  • Data and ML engineering: start with the engineering book and its named Python/SQL prerequisites. Use Polars, dbt and the focused ML engineering route for deeper tool practice. Connect event time, availability time, trained state, inference and rollback in the owned projects, then choose relevant platform workshops.
  • Applied LLM science: NLP and Transformer mechanisms, the applied retrieval and adaptation route, then LLM evaluation. Follow dme-057 through dme-072 for the request-to-SSE lifecycle and its actual CPU inference workshop. Keep retrieval quality, factual support, safety policy, preference objectives and held-out task utility distinct.

These are suggested connections, not access gates. Use each lesson's actual prerequisite IDs. Applied Science, Bayesian Computing, Data and ML Engineering and the statistics book are tutorials with complete answers and no required exams. Programming practice routes retain separate attempts, exercises and references. Reading markers and reference executions do not certify expertise.

Boundaries and future additions#

The maintained routes use small synthetic offline data. Short chains, local Spark, single-machine services and tiny policy models teach mechanisms. They do not establish convergence for every posterior, distributed fault tolerance, production capacity or externally useful LLM behavior. GPU correctness, profiling, distributed training, cloud deployment, external model acquisition, Apple SDKs and proprietary DAX engines retain their explicit preparation and qualification boundaries.

Future additions should name a concrete missing outcome, inspect the closest existing guide and update its coverage ledger. Prefer a deeper worked case when the subject already exists. A new language or tool needs a distinct mechanism, prepared runtime, authoring/style support, actual success and failure evidence, and saved-work acceptance. Use the extension playbook and authoring skill. Keep current source registration, local execution, browser/persistence checks and hosted CI as separate evidence; this roadmap is not a release acceptance report.
