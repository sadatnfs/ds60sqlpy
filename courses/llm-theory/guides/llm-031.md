# llm-031: Instruction tuning and loss masks

## Learning objectives

Explain how a supervised objective changes when only answer tokens receive loss. The central investigation is concrete: Use short fixed instruction/answer records with independent literal logits; compare full-sequence and answer-only loss masks and their direct logit gradients. The finish condition is The answer-only denominator equals the number of answer targets, not prompt+answer length. Evaluation tasks are held out by template family. ## Purpose and mental model

### Define what an instruction-tuning example teaches

Pretraining and instruction tuning can use the same next-token prediction machinery while presenting different data and supervision policies. An instruction example often contains a prompt, optional context and an answer. The prompt should influence the answer prediction, but an answer-only objective need not ask the model to predict every prompt token. The loss mask makes that distinction explicit. It selects supervised target events, not the information the model is allowed to read.

Write a complete token sequence as s_0,...,s_T. A next-token decoder receives input positions s_0,...,s_(T-1) and produces logits whose targets are s_1,...,s_T. A mask m_t belongs to those shifted targets. If \(m_{t}=1\), target s_(t+1) contributes a loss; if \(m_{t}=0\), it remains outside the supervised sum and denominator. Misaligning the mask by one position can discard the first answer token or accidentally supervise a prompt token.

#### Put the fixture on a position table

The authored sequence is[1,2,5,6,3]. In this illustration, tokens 1 and 2 form the initial context, tokens 5 and 6 are answer content, and token 3 is the included answer terminator under the fixture's policy. The decoder inputs are[1,2,5,6], while targets are[2,5,6,3]. The answer mask is[False,True,True,True].

| Logit row | Input token at that row | Next-token target | Included in answer loss? |
| --- | ---: | ---: | --- |
| 0 | 1 | 2 | no |
| 1 | 2 | 5 | yes |
| 2 | 5 | 6 | yes |
| 3 | 6 | 3 | yes |

The first answer token 5 is predicted from the state at input token 2. An implementation that starts the mask at the first answer *input* position would begin at row 2 and omit that prediction. The table should be checked before any optimizer result is interpreted. A plausible scalar loss can hide this off-by-one error, especially when the initial logits are uniform.

#### Derive the masked objective and its denominator

For vocabulary size V, let p_t(v) be the softmax probability of token v at row t. The answer-only mean loss is \(L=-\frac{\sum_t m_t\log p_t(y_t)}{\sum_t m_t}\), where y_t is the shifted target. The denominator is the number of active answer targets, not total sequence length and not the number of nonpadding input tokens. If there are no active targets, this empirical mean is undefined and the pipeline must apply an explicit no-target policy.

In the worked example, all logits are zero and \(V=8\), so each target has probability \(\frac{1}{8}\) and loss \(\log(8)\). Three active answer targets give total 3log8 and mean \(\log(8)\). Full-sequence supervision includes four targets, giving total 4log8 and the same mean \(\log(8)\). Equal means here do not mean the objectives are equivalent. Uniform logits made every per-target term identical, concealing the different supervised events and gradient scale.

The gradient makes that difference visible. For an active row under the answer-only mean, dL/dz_tj=(p_tj-1[j=y_t])/3. At uniform probabilities, the correct target coordinate has gradient(\(\frac{1}{8}\)-1)/3=-7/24; every other coordinate has \(\frac{1}{24}\). The ignored row has a zero direct gradient with respect to its logits. Under a four-target full-sequence mean, each correct coordinate has-7/32 and each incorrect coordinate \(\frac{1}{32}\), and row 0 is now supervised too. The same printed initial mean therefore produces a different update objective.

The reference's `ignore_index=-100` encodes target exclusion. The sentinel is not a vocabulary token to embed, and it should not be supplied as a normal model input ID. Flattening logits and labels preserves the row alignment only when the same batch/time order is used for both. Keep the boolean mask or an equivalent target ledger available for inspection instead of debugging only the flattened arrays.

#### Ignoring a prompt loss does not remove prompt influence

A zero direct gradient at the ignored prompt logit is not the same as zero gradient through every prompt representation. An answer state can attend to prompt tokens, so answer loss can backpropagate through their embeddings and earlier transformations. The prompt remains useful context precisely because it can influence the supervised answer prediction.

A simple analytical example shows the distinction. Suppose an answer hidden state is \(h_{\mathrm{answer}}=\frac{e_{\mathrm{prompt}}+e_{\mathrm{answer}}}{2}\) and a scalar answer loss has derivative g with respect to h_answer. The prompt embedding receives derivative \(\frac{g}{2}\) even if no loss is attached to a prompt-position output. Loss participation and computational influence are separate paths. The reference uses independent literal logits to isolate the direct loss-mask gradient; it does not instantiate this full model path in that exercise.

This distinction also prevents a mistaken attempt to mask prompt tokens out of attention. An answer-only loss policy typically leaves the allowed prompt context available. A causal attention mask still prevents access to future answer tokens. The loss mask and attention mask have different shapes and purposes: one selects supervised target rows, while the other selects accessible key positions for each query.

#### Formatting and multi-turn structure are part of the data contract

Real instruction examples may include role markers, separators, retrieved context, several assistant turns and tool results. The training policy must say which spans are supervised and whether terminators or formatting tokens count. A role marker that belongs to the prompt in one serialization can belong to the predicted response format in another. Token-level spans should be derived from the exact serialized/tokenized example rather than guessed from character lengths.

Truncation can change the contract too. If the answer is cut off entirely, the resulting example may contain no active targets. If the prompt is truncated, the answer may no longer be supported by its retained context. If a terminator is removed, the example can teach a different stopping behavior. Validate active-target counts and retained-context adequacy after truncation, not only before it.

For multi-turn data, decide whether to supervise every assistant response or only the final response. Earlier assistant text can be context even when its own loss is ignored. A blanket rule based on one role label may be insufficient if the record includes demonstrations, quoted conversations or tool messages. Keep the span policy explicit and inspect a few fully tokenized examples with their shifted labels.

#### Tune behavior without confusing it with evidence acquisition

Instruction tuning can encourage a model to follow a format, classify an input, extract a field or express a desired interaction style. It does not automatically supply current authoritative evidence for every domain question. RAG supplies selected external context at inference time; supervised fine-tuning changes parameters using training examples. A subject-matter assistant may need both, with independent evaluation of behavior and grounding.

The distinction is useful in data science. An SFT dataset might teach the assistant to return a validated analysis request or to explain a computed result in a specified schema. The actual numerical result should still come from a verified computation against the intended data. Training the assistant to emit plausible statistical prose does not establish that an estimator ran or that its assumptions were satisfied. The [applied SFT-data lesson](../../llm-applied/guides/llm-applied-014.md) develops the corresponding data and mask contract in a more connected workflow.

#### Evaluate beyond the prompt template

Two paraphrased prompts from the same template family can make a row-level split look more independent than it is. A model may memorize the template's answer pattern while failing on a new form of the same task. Keep related templates and source families together when that matches the desired transfer claim. Prompt selection and mask-policy tuning belong on development data, with the final assessment held back from those choices.

## Vocabulary and concepts

**Answer-only mask:** A target participation rule excluding prompt prediction events.

**Template family:** Related prompt forms grouped for evaluation isolation.

## Align the loss mask with the shifted target

The literal sequence is [1, 2, 5, 6, 3]. Feeding [1, 2, 5, 6] into a causal decoder predicts targets [2, 5, 6, 3]. The answer mask [false, true, true, true] therefore excludes prediction of target 2 and includes targets 5, 6, 3. It is a mask over prediction events after shifting. Applying a mask made for the unshifted sequence without checking this alignment can train on a prompt token or omit the first answer token.

Uniform logits over eight vocabulary entries give each target probability \(\frac{1}{8}\) and each active negative log probability \(\log(8)\). The answer-only mean is \(\frac{3\cdot \log(8)}{3}=\log(8)\), while the sum is \(3\cdot \log(8)\). A mean over all four positions would also happen to equal \(\log(8)\) in this uniform fixture, so the mean alone cannot reveal the masking error. Inspect the active count and per-position gradients as well. For the excluded prediction, the logit gradient is zero; for an included prediction, it is (p-one_hot(target))/3 under this mean reduction.

## Ignoring a target does not hide the prompt

The prompt remains an input to the causal computation. Answer tokens can attend to its allowed positions and gradients from answer losses can flow through their use of prompt representations. Loss masking chooses which predictions contribute directly to the objective. An attention mask chooses which input relationships exist. A padding mask and an instruction/answer loss mask therefore have related but distinct jobs.

The EOS decision is part of the task contract. This fixture includes the final3 as an answer target, teaching the modeled sequence to terminate there. A different template might encode turns or end markers differently. For a real tokenizer, verify the rendered chat template and the actual token boundaries, especially around prompt/answer joins. Independently tokenizing two strings and concatenating their IDs need not reproduce tokenizing the combined text under every tokenizer.

An all-false answer mask has denominator zero and must be rejected or handled by an explicit policy before reduction. Returning a plausible zero loss would hide the absence of supervision. Likewise, template variants from one source family should not cross the train/evaluation boundary merely because their strings differ. The code verifies loss and gradient mechanics on literal IDs; it does not demonstrate instruction-following quality. The [applied adaptation route](../../llm-applied/README.md) adds data construction, real tiny updates and an explicitly optional pretrained workflow with template and masking checks.


## Worked example / walkthrough

### Example A: Align the target mask

The first answer token5 is a target at position1 in the shifted array. Masking by unshifted input positions would introduce an off-by-one error.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

sequence=torch.tensor([[1,2,5,6,3]]); targets=sequence[:,1:]; answer=torch.tensor([[False,True,True,True]])
assert targets.tolist()==[[2,5,6,3]] and int(answer.sum())==3
```

**Expected:** targets[2,5,6,3];mask[False,True,True,True].

### Example B: Compute answer-only loss

Uniform logits make each target loss identical. The mean stayslog8, but the active count differs from full-sequence training and affects summed objectives.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

sequence=torch.tensor([[1,2,5,6,3]]); targets=sequence[:,1:]; answer=torch.tensor([[False,True,True,True]])
assert targets.tolist()==[[2,5,6,3]] and int(answer.sum())==3
logits=torch.zeros((1,4,8)); masked=targets.masked_fill(~answer,-100)
loss=F.cross_entropy(logits.reshape(-1,8),masked.reshape(-1),ignore_index=-100)
np.testing.assert_allclose(loss.item(),np.log(8),atol=1e-6,rtol=0)
```

**Expected:** 3 active targets;meanlog8.

## Common pitfalls and diagnosis

Write shifted inputs and targets side by side before applying the answer mask. Inspect active counts and per-position gradients because uniform logits can hide a denominator mistake in the mean. Separate attention visibility from direct loss contribution, and reject an empty answer mask before dividing.
