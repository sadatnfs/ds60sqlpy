## Starting point and result

Automatic differentiation applies the chain rule to a computation built from supported operations. It does not approximate derivatives by perturbing inputs. This chapter implements a tiny forward-mode dual number in Scala and evaluates it in a Spark Dataset. The supported operations are addition, multiplication and exponential, sufficient to differentiate \(f(x)=x^2+e^x\).

## Mechanism: carry a value and a tangent

Represent a dual number as \(a+b\varepsilon\), where \(\varepsilon^2=0\). The value a is the ordinary quantity; b is its directional derivative. Addition adds both components. Multiplication follows

\[(a+b\varepsilon)(c+d\varepsilon)=ac+(ad+bc)\varepsilon.\]

For exponential, \(\exp(a+b\varepsilon)=e^a+be^a\varepsilon\). The `Dual` case class implements these rules directly. Seeding the input with tangent one computes the derivative with respect to x. Seeding tangent two computes twice that directional derivative.

This is genuine automatic differentiation for the small supported program. The author supplies derivative rules for primitives, and composed operations propagate tangents automatically. It is not symbolic algebra and does not retain a reverse-mode tape. With many parameters and one scalar output, repeated forward directions can be expensive; reverse mode is often preferable.

## Worked case: differentiate three observations on executors

The Dataset contains x values -1, zero and one. Each task evaluates `f(Dual(x, 1))` and returns x, function value and tangent. The driver compares values with \(x^2+e^x\) and tangents with the analytic derivative \(2x+e^x\). All checks use tight double tolerances.

The computations run within JVM task code. Spark schedules and transports the results; the Dual implementation performs differentiation. This distinction is the answer to whether Spark can “do autodiff natively”: a derivative mechanism can run in JVM tasks, but Spark SQL itself is not thereby a general differentiable programming system.

## Worked case: a non-unit direction

At x=1, the input tangent is changed to two. The output tangent must be \(2(2+e)\). This checks that the implementation carries a direction rather than hard-coding a derivative formula for one seed. If multiplication incorrectly uses only one product-rule term, the square contribution exposes the defect.

For a vector parameter, a direction v produces a Jacobian-vector product. Carrying a full vector tangent can compute all first derivatives in one pass but increases storage and arithmetic. A scalar tangent example does not establish performance for millions of parameters or arbitrary neural-network operations.

## Failure diagnosis

A primitive operation missing a derivative rule breaks the supported computation domain. Extracting `.value` early and reconstructing a Dual with zero tangent severs derivative flow. Branches produce the derivative of the executed branch away from discontinuities; they do not magically make a non-smooth function differentiable at its boundary. Exponential overflow remains possible because AD does not eliminate ordinary numerical limits.

## Interview discussion

**Is this finite differencing?** No. The tangent propagates exact chain-rule arithmetic for the implemented primitives, subject to floating-point rounding. There is no step-size parameter.

**Does this differentiate a shuffle or sort?** No. The differentiated program is the per-row function. Distributed aggregation, ordering and optimization are separate layers whose derivative semantics must be designed explicitly.
