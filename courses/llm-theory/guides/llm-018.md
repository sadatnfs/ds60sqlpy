## Purpose and mental model

<!-- textbook-foundations-start -->

### Training is a state transition with an observable order

A forward pass answers what the current model predicts. A training step additionally changes the model so that a future forward pass may predict differently. To understand the loop, name its state before and after the update. The parameters hold the current function, gradient buffers hold accumulated derivatives, and Adam holds running estimates derived from earlier gradients. The batch and target policy determine the objective evaluated at that state.

The literal batch contains [1,2,3,4] and [2,3,4,5]. After shifting, inputs have shape [2,3] and there are six target events. The decoder returns [2,3,16] logits, which become six rows of sixteen class scores for cross entropy. The initial loss is measured from the actual initialized model. It is not replaced by \(\log(16)\), because random logits need not be uniform even though sixteen classes are available.

Each iteration begins by clearing prior parameter gradients. It then performs a fresh forward pass, reduces the six event losses to one scalar and calls backward to populate gradients. Only after those derivatives exist does it inspect their norm and call optimizer.step. Swapping the order of clearing and inspection can erase the very evidence the optimizer needs. Calling step without a new gradient calculation, or computing losses without step, describes a different state transition.

The global gradient norm is the square root of the sum of squared entries across all participating parameter gradients. Suppose one parameter has gradient coordinates [3,4] and another has [12]. The combined norm is \(\sqrt{9+16+144}=13\), not the average of 5 and 12. This small derived example explains the reduction used by the reference. A positive norm shows that at least one derivative path is active; it does not establish that every intended module is registered or that every embedding row should have a nonzero gradient.

The reference snapshots the output projection before twelve Adam updates and verifies that it changed. A snapshot must own its values: retaining a view of the live weight would let both the "before" and "after" names observe the updated tensor. detach().clone() removes gradient tracking and copies the data for this comparison. That makes parameter mutation independently observable rather than inferred only from a loss curve.

The recorded loss at iteration k describes the parameters before update k. The final recorded point therefore precedes the twelfth update. To evaluate the final saved weights, run another forward pass afterward with an explicit evaluation mode and the same scoring convention. This timing detail matters when comparing logs, checkpoints or two loops that record at different points. A report should not call a pre-update observation the final model's score by accident.

Twelve updates are a bounded demonstration of a functioning learning path, not a convergence argument. Some steps may increase the objective, and a repeated tiny batch says nothing about unseen text. The useful finish condition here is operational clarity: we know the batch, loss denominator, number of updates, gradient observations and parameter change. Those facts provide a controlled starting point for diagnosing why a real experiment learns or fails to learn.

## Vocabulary and concepts

**Training step:** One gradient calculation followed by one optimizer update.

**Gradient norm:** A magnitude summary used to diagnose update scale.

**Step budget:** A hard upper bound on optimization work.

## Syntax anatomy and reasoning sequence

model.train() declares training behavior. Adam operates on model.parameters(). zero_grad(set_to_none=True) removes previous leaf gradients. Flatten logits and shifted labels for cross entropy. Compute a gradient norm after backward and before step. Snapshot parameters with detach().clone(), because a reference to the same tensor would change with the model and hide updates.

## Follow one update through all mutable state

The two four-token sequences create inputs of shape [2, 3] and six next-token targets. The decoder returns [2, 3, 16] logits, which are reshaped into six rows of sixteen class scores. The objective is a mean over those six target events. The loop clears parameter gradients, computes a fresh forward pass, constructs the loss, backpropagates, records gradient information and applies one Adam update. Moving zero_grad to the wrong side of backward could erase the gradients before the optimizer uses them.

The global gradient norm in this fixture is the square root of the sum of squared entries across every accumulated parameter gradient. It is not an average of per-parameter norms. A finite positive norm shows that some derivative path exists for this batch, but does not prove every expected parameter participates. Unused embedding rows can legitimately have zero gradients; a missing registered module or a detached branch is a different problem requiring a parameter-by-parameter inspection.

Adam owns state in addition to model weights, including moment estimates and an update count. Reconstructing an optimizer after every step would repeatedly reset that history and define a different algorithm. A model snapshot and optimizer state therefore answer different questions when comparing trajectories or resuming a run.

## Interpret the recorded curve correctly

Each loss is recorded before its corresponding optimizer step. The last stored training loss is the objective seen before update twelve, not necessarily the loss of the final post-update weights. To report that final state's loss, perform a separate forward evaluation afterward under a declared mode and reduction. The reference's field name last_training_loss describes its observed pre-update point and does not claim convergence.

The checks establish a twelve-update budget, finite losses and norms, and an actual change in the vocabulary projection. They intentionally do not assert that every step decreases loss or that twelve steps reach an optimum. Optimization can fluctuate, especially under minibatching, stateful optimizers or stochastic layers. A repeated tiny batch is useful for debugging the data and gradient path; held-out task performance remains a separate experiment.

When a curve fails, first verify shifted targets, class axis, active-token denominator, optimizer membership and gradient clearing. Preserve the smallest failed batch before changing learning rate, model width or training budget. Increasing the budget can hide a diagnostic error without explaining it.


## Worked example / walkthrough

### Example A: Prepare a tiny training batch

The fixture is small enough to enumerate every target. The context length and vocabulary remain below the decoder limits.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
torch.manual_seed(7); model=TinyDecoder(); ids=torch.tensor([[1,2,3,4],[2,3,4,5]]); inputs=ids[:,:-1]; targets=ids[:,1:]
assert tuple(inputs.shape)==(2,3) and targets.numel()==6
```

**Expected:** inputs shape(2,3);6 active targets.

## Common pitfalls and diagnosis

Check the first incorrect intermediate state: shifted labels, logits layout, loss denominator, parameter gradients, then optimizer update. Confirm that zero_grad happens before the intended backward and that the optimizer owns the expected parameters. Label recorded losses by whether they were measured before or after an update; finite steps and a positive gradient norm do not establish convergence.
