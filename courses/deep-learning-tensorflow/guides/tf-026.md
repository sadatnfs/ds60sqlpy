# tf-026: Custom layers, residuals and trainable state

## Level and prerequisites

## Learning objectives

Create weights once and keep build/call responsibilities separate. The central investigation is concrete: Implement a tiny residual layer, call it twice with the same feature dimension and inspect its tracked variables. The finish condition is Variable count does not grow on the second call. A residual addition requires matching trailing dimensions; incompatible inputs produce a declared validation failure. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

A custom layer separates construction of persistent parameters from repeated evaluation. Creating a new weight in every call would change the model whenever it sees another batch. Keras tracks weights created through add_weight, typically in build once the feature width is known. A residual connection adds an input to a transformed version of itself. Both operands must have compatible shapes; a projection is required if feature widths differ. This lesson uses a square linear residual with zero initial kernel, so its initial behavior is exactly the identity. The transparent starting function makes tracked-state and gradient tests easy to interpret.

## Vocabulary and concepts

**Tracked variable:** Persistent model state registered with the layer.

**Residual:** An input added to a transformation with matching dimensions.

**Build:** One-time creation of weights for a declared input shape.

## Syntax anatomy and reasoning sequence

build(input_shape) reads the trailing feature width and creates one square kernel. call(x) computes x+x@kernel. The same layer object reuses that kernel on later calls. trainable_variables supplies the variables the optimizer should update. A width mismatch should be reported rather than silently constructing a new parameter set. Batch length may change without changing feature width.

## Separate persistent state from each forward calculation

The residual layer computes Y = X + XW. For a feature width D, its square
kernel has D squared scalar parameters. At W = 0 it is exactly the identity;
at W = I it doubles every input. These two states are useful independent
oracles because neither requires trusting the layer's implementation.

If the loss is the sum of all output elements, the derivative of that loss
with respect to W is X transposed times an all-ones matrix of output shape.
For X with rows [1, 2] and [3, 4], the gradient is [[4, 4], [6, 6]]. The
skip connection contributes to the input gradient but introduces no extra
kernel parameter. A zero initial kernel can therefore still receive a
nonzero gradient and learn a residual correction.

Weights belong to the layer's persistent state. In this shape-dependent
example, build creates the kernel through add_weight after the feature width
is known; call reuses it for each batch. Calling the same layer twice should
leave both the number and identity of its variables unchanged. Two equal
output tensors are a weaker check: a broken implementation could recreate
the same zero kernel on every call and appear correct until training begins.

A residual addition also commits to compatible shapes. If a transformation
changes feature width, a deliberate projection is needed on the skip path
or the architecture must reject the mismatch. Accidental broadcasting is
not a substitute for that design decision. The
[Keras layer contract](https://www.tensorflow.org/api_docs/python/tf/keras/Layer)
describes tracked trainable and nontrainable state; the fixture checks the
particular square-kernel contract used here.

## Worked example / walkthrough

### Example A: Create an identity residual

The zero branch contributes nothing initially. This is a useful reference behavior but does not mean the branch has no gradient or will remain zero during training.

```python
import numpy as np
import tensorflow as tf
class Residual(tf.keras.layers.Layer):
    def build(self,input_shape):
        self.width=int(input_shape[-1])
        self.kernel=self.add_weight(name='kernel',shape=(self.width,self.width),initializer='zeros')
    def call(self,x):
        if x.shape[-1]!=self.width: raise ValueError('feature width mismatch')
        return x+x@self.kernel
layer=Residual(); x=tf.constant([[1.,2.],[3.,4.]]); out=layer(x)
np.testing.assert_array_equal(out.numpy(),x.numpy()); assert len(layer.trainable_variables)==1
```

**Expected:** output equals input; one tracked kernel.

### Example B: Reuse the state

A new batch should change transient activations, not create a new model. Object identity complements a parameter count, since replacing one variable with another could preserve the count.

```python
import numpy as np
import tensorflow as tf
class Residual(tf.keras.layers.Layer):
    def build(self,input_shape):
        self.width=int(input_shape[-1])
        self.kernel=self.add_weight(name='kernel',shape=(self.width,self.width),initializer='zeros')
    def call(self,x):
        if x.shape[-1]!=self.width: raise ValueError('feature width mismatch')
        return x+x@self.kernel
layer=Residual(); x=tf.constant([[1.,2.],[3.,4.]]); out=layer(x)
np.testing.assert_array_equal(out.numpy(),x.numpy()); assert len(layer.trainable_variables)==1
variable=layer.trainable_variables[0]; layer(tf.constant([[9.,8.]]))
assert layer.trainable_variables[0] is variable and len(layer.trainable_variables)==1
```

**Expected:** same variable object and variable count1.

## Common pitfalls and diagnosis

Count variables and compare their identities across repeated calls.
If they grow, inspect state creation in call. If the initial output is wrong,
check the zero-kernel identity before debugging training. If the gradient is
wrong, derive X transposed times ones independently and inspect the reduction
axes. Reject a new feature width with a clear contract error.
