Curriculum map#

DS60 combines the original Python and PostgreSQL cores, the engineering bridge, additional foundational/professional lessons and the full subject library in the front README. Day numbers are stable labels, not deadlines. This map explains the legacy data-science sequence; modern subjects have their own beginner-to-advanced track metadata and classroom journey.

Use the classroom chooser for all subjects. In a prepared contributor environment, inspect the two complementary inventories without executing lessons:

uv run --no-sync python scripts/course.py catalog
uv run --no-sync python scripts/check_modules.py --json

curriculum/catalog.json is generated from legacy artifacts and authoring metadata. Modern module/book admission comes from subject manifests. Do not edit generated catalogs or infer lesson counts from this overview. Windows contributors use WSL 2.

Choose a path#

New to programming and databases#

  1. Complete Python Days 1–15 in catalog order, including the four inserted foundation practice modules.
  2. Start with sql-start-01 through sql-start-03, then complete SQL Days 1–15, beginning with small temporary-table examples.
  3. Continue Python Days 16–30.
  4. Complete sql-found-01 for relational design, then continue SQL Days 16–30.
  5. Add the engineering bridge after Python Day 15 and SQL Day 15 when you want application-oriented integration practice.
  6. After SQL Day 39, complete sql-found-02 for versioned schema evolution before Day 40.
  7. Choose advanced data science, advanced SQL, or alternate both.

Comfortable with another programming language#

Review Python Days 1–9, then focus on testing, tooling, data work, and projects. Begin SQL with sql-start-01 through sql-start-03, then Day 1, unless a placement check demonstrates those foundations. Take the relational-design and migration modules only after their declared catalog prerequisites.

Comfortable with SQL#

Use the SQL companion guides and project lessons as a diagnostic. Do not skip PostgreSQL setup, transaction behavior, or query-plan lessons merely because SELECT syntax is familiar.

Focused on data science#

Follow the Python track in order through Day 45. Days 46–60 introduce larger optional dependencies and production topics; inspect the catalog and environment doctor before installing heavy extras.

Focused on data or backend engineering#

Complete Python Days 1–15 and SQL Days 1–15, then follow the engineering bridge. Continue the main tracks alongside it when a bridge lesson identifies a deeper Python or PostgreSQL prerequisite. Use the professional paths after the shared bridge.

Bridge Day 1 requires python-15 and sql-15; later bridge lessons are sequential. Every lesson includes a learner .py file, companion guide, executable reference solution, and reasoning guide. Default tests use fakes and run offline. Optional live PostgreSQL work uses DS60_DATABASE_URL and the disposable course database.

Five named bridge modules add PostgreSQL notebook magics, migration delivery and observability, AI application boundaries, analytics engineering, and a data-product incident review.

Artifact roles#

  • Plan: broad learning sequence and goals
  • Companion guide: concepts, mental models, pitfalls, and preparation
  • Learner notebook or SQL file: examples and exercises
  • Bridge learner module: application-engineering exercises with testable boundaries and optional live integration
  • Named professional module: a stable-ID foundation, cumulative lab, or elective that does not renumber an established day
  • Solution: worked reasoning after an honest attempt
  • Generated catalog: machine-readable mapping of artifact names plus authoring metadata such as prerequisites, dependency groups, network behavior, and solution availability

Do not infer that a solution format exists because another format exists. Ask the catalog.

Pacing#

A useful lesson rhythm is:

  1. 10–20 minutes: recall prerequisites and read
  2. 20–40 minutes: predict and run examples
  3. 30–60 minutes: exercises
  4. 10 minutes: self-check and notes

Project lessons often need multiple sessions. Heavy machine-learning setup may need a separate connected preparation session.

Readiness checkpoints#

Before moving from a phase:

  • Explain the phase’s core ideas without copying definitions.
  • Recreate one small example from a blank file.
  • Complete the phase project or an equivalent.
  • Review failed exercises after a delay.
  • Run the relevant local validation.

Use the AI tutor for a diagnostic quiz with Learning with an AI tutor, or create your own retrieval questions.

Adding lessons beyond 60#

The repository may grow beyond the historical numbering. New material should close a documented gap, declare prerequisites, and receive a stable catalog ID. Do not renumber established lessons merely to preserve a marketing total.

See Content authoring and the curriculum extension playbook. New tracks register their plan, lessons, topics, and goal targets additively; the app and reading library use that shared metadata rather than a fixed sixty-lesson list.

For the audited gap record and implementation criteria, see the curriculum gap backlog.

The implemented named modules and recommended lanes are in Professional and specialization paths.

Guided routes and the new correctness labs#
