llm-045: Pre/post normalization, RMSNorm and gated feed-forward networks#

Level and prerequisites#

Advanced; approximately 210 minutes. Direct prerequisites: llm-044. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Normalization placement changes the residual network's gradient path. The central investigation is concrete: Normalize vector [3, 4] with unit gain and epsilon 1e-8. The finish condition is RMSNorm mean nonzero; LayerNorm mean approximately 0. LayerNorm shift invariant; RMSNorm changes; both zero cases finite. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Normalize feature geometry without losing track of the residual path#

Position mechanisms change how vectors express location. Normalization changes how their scale and common offsets affect subsequent computation. In a transformer, these choices influence both the forward representation and the gradients that travel through many layers. The names LayerNorm and RMSNorm are not interchangeable labels for "make values small"; their formulas preserve and remove different directions.

Let x be one token's d-dimensional feature vector. A tokenwise LayerNorm computes mean mu=(1/d)sum_i x_i, centered values c=x-mu*1, variance v=(1/d)sum_i c_i², and normalized values c/sqrt(v+epsilon), followed by any learned gain and bias. RMSNorm uses x/sqrt[(1/d)sum_i x_i²+epsilon], typically with learned gain, without subtracting the mean. The reduction axis is the feature axis of one token under this construction.

Calculate the two transformations on a new vector#

For x=[1,2,3], LayerNorm has mean 2, centered values[-1,0,1] and variance 2/3. Ignoring only the tiny epsilon for this hand calculation, the normalized result is approximately[-1.224745,0,1.224745]. RMSNorm has mean square 14/3 and root mean square about 2.160247, giving approximately[.462910,.925820,1.388730]. The latter has nonzero mean because centering was never part of its definition.

Adding 5 to every feature leaves LayerNorm's centered vector unchanged. RMSNorm generally changes because both the raw numerator and root mean square change. Multiplying by a positive constant produces another useful comparison: with epsilon zero and nonzero input, both normalizers remove that positive scale under their respective formulas. With positive epsilon, exact scale invariance no longer holds at every magnitude. Small epsilon is a numerical design parameter, not permission to ignore its effect near zero.

Learned gain and bias can alter the final mean and scale. A unit-gain, zero-bias normalized vector may have zero feature mean under LayerNorm, while an arbitrary learned gain can change that property. State which stage of the formula is being discussed instead of generalizing a property of the standardized intermediate to every final output.

Derive the Jacobian by separating numerator and denominator#

For RMSNorm, write r=sqrt(x^T x/d+epsilon). The derivative of x_i/r with respect to x_j contains a direct numerator term delta_ij/r and a denominator term-x_ix_j/(dr³). This yields J=I/r-xx^T/(d*r³). A learned elementwise gain multiplies the corresponding output rows of this Jacobian.

The geometry becomes clear by testing directions. If u is perpendicular to x, then Ju=u/r. Along x itself, Jx=epsilon*x/r³. When epsilon is zero, a radial scale change has no first-order effect. Near the zero vector, r is approximately sqrt(epsilon), so the Jacobian can have magnitude about 1/sqrt(epsilon). Epsilon makes division defined but does not guarantee small sensitivities.

LayerNorm adds a centering projection. Let P=I-(1/d)11^T, so c=Px and r=sqrt(c^T c/d+epsilon). Its unit-gain Jacobian is P/r-cc^T/(dr³). Because P1=0 and c^T*1=0, the all-ones shift direction is annihilated. This explains the reference's post-normalization Jacobian test directly from the formula, rather than treating the result as an opaque autograd observation.

Place normalization relative to the skip connection#

A residual block adds a transformed branch to a direct path. In pre-norm form, y=x+F(N(x)); in post-norm form, y=N(x+F(x)). Applying the chain rule gives I+J_F J_N for pre-norm and J_N(I+J_F) for post-norm. The location of J_N changes which routes a gradient can follow.

Set F to zero as a controlled case. Pre-norm returns x exactly and has identity Jacobian. Post-norm returns N(x) and still has the normalizer's Jacobian. This isolates placement from the complexity of a learned attention or feed-forward branch. It is a powerful local test because the expected difference can be derived without a long training run.

A direct identity path can help explain optimization behavior, but it is not a complete theorem about training success. Depth, initialization, residual scaling, final normalization, optimizer and data all interact. Moving normalization across an addition changes the function and should be treated as an architectural change, not a harmless code refactor with guaranteed checkpoint equivalence.

A gated feed-forward block has two interacting projections#

A plain feed-forward block can be written phi(XW_1)W_2. A SwiGLU-style block instead forms G=XW_g and U=XW_u, multiplies SiLU(G) elementwise by U, then projects through W_d. SiLU(g)=g*sigmoid(g). The word "gate" describes a multiplicative role; SiLU is not constrained to[0,1] and is not a probability.

For example, g=-1 gives SiLU(g)≈-.268941. With u=2, the scalar product is about-.537883, so the gate can change sign rather than merely attenuate a positive value. At g=0, SiLU is zero but its derivative is 1/2. This is why the reference's output can be zero while the gate receives a nonzero gradient.

Let H=SiLU(G) elementwise_mul U and let R=dL/dY. The gradient reaching H is R W_d^T. Multiplying this by SiLU(G) gives the up-branch derivative; multiplying by U and SiLU'(G) gives the gate-branch derivative. A zero up-branch gradient at a zero gate is therefore a local consequence of the product, not necessarily a disconnected parameter. Inspect both activations and both gradient paths before diagnosing an optimizer failure.

Compare architectures at a stated resource budget#

For input/output width d and hidden width h, a bias-free plain two-matrix FFN has 2dh weights. The gated version has 3dh because it uses gate, up and down matrices. Retaining the same hidden width increases that part of the parameter count by 50 percent. A quality comparison that ignores this change cannot attribute the difference solely to the activation mechanism.

To match this weight count, choose gated hidden width two-thirds of the plain hidden width when the dimensions and implementation permit it. The fixture's d=4, plain h=6 and gated h=4 each give 48 weight entries. This matches one resource measure. It does not automatically equalize activation memory, operation scheduling, kernel efficiency or task quality.

Biases, rounded hardware-friendly widths and additional projections can change the exact count. Write the matrix dimensions and bias policy before using a shorthand ratio. The small model makes this accounting easy; the same habit prevents confusion when comparing larger checkpoints with different feed-forward conventions.

Diagnose numerical differences before drawing training conclusions#

When two implementations disagree, compare the reduction axis, mean subtraction, variance formula, epsilon placement, gain/bias values and dtype. A common-shift case distinguishes centering behavior; a zero vector probes epsilon handling; a nonconstant vector exposes an incorrect variance reduction. Testing only an all-ones vector can hide important differences or collapse the centered variance to zero.

During causal modeling, normalizing independently over features preserves the token information boundary. Accidentally normalizing over token positions can introduce dependence on future positions. A normalization bug can therefore look like an attention-mask bug at the final output. Follow the dependency graph and compare intermediate states to identify the first divergence.

Design decisions and when to use this method#

Use normalization and gating choices as part of a complete architecture and training policy. Pre-norm often offers a direct residual gradient path, but final normalization, initialization, depth and optimizer settings still matter. RMSNorm preserves a different set of invariances than LayerNorm. A swap requires a model-specific evaluation or retraining plan rather than an assumption of numerical equivalence.

For SwiGLU, record the gate activation, projection layouts, bias policy, hidden width and parameter budget. Inspect both gate and up branch gradients when a unit appears inactive. A zero gradient at a particular input can follow directly from the product structure and need not indicate a broken autograd graph. Compare actual held-out task quality and resource use after mechanical checks pass.

Derivation and shape trace#

For a feature vector x in R^d with unit gain, let r=sqrt(mean(x²)+epsilon) and y_i=x_i/r. Differentiating both numerator and denominator gives

\[ \frac{\partial y_i}{\partial x_j}=\frac{\delta_{ij}}{r}-\frac{x_i x_j}{d r^3}. \]

A learned gain g_i multiplies row i of this Jacobian. RMSNorm does not subtract the feature mean, so adding a constant generally changes its output. LayerNorm first subtracts that mean and therefore removes the all-ones shift direction.

For a residual branch F and normalizer N, pre-norm is y=x+F(N(x)), with Jacobian I+J_F J_N. Post-norm is y=N(x+F(x)), with Jacobian J_N(I+J_F). Setting F=0 isolates the placement: the first Jacobian is I, while the second remains J_N. This local identity-path argument is not a complete theorem about every training configuration.

A bias-free plain feed-forward block phi(xW1)W2 has 2dh weights. SwiGLU, [SiLU(xWg) elementwise_mul(xWu)]Wd, has 3dh weights. Equal weight budgets therefore use gated hidden width two-thirds of the plain hidden width when dimensions permit. SiLU(g)=gsigmoid(g), with derivative sigmoid(g)+gsigmoid(g)*(1-sigmoid(g)). At g=0 this derivative is 1/2, which explains the scalar gate-gradient example.

Normalization changes which directions a layer can preserve#

For x in R^d, define r=sqrt[(1/d)sum_j x_j²+epsilon]. RMSNorm with unit gain returns y=x/r. For x=[3,4], the mean square is 12.5 and r is approximately 3.53553, so y is approximately[.848528,1.131371]. The feature mean is not zero. LayerNorm first subtracts the mean 3.5, producing[-.5,.5], and divides by sqrt(.25+epsilon), giving values close to[-1,1]. Confusing the two normalizers would predict the wrong output even before training begins.

The normalizer uses a feature-axis average for each token independently in the ordinary transformer construction. It does not estimate statistics across the sequence or batch. Mixing token positions into the normalizing reduction can introduce dependencies across positions, including future positions in a causal model. A module named "normalization" is not enough to establish the intended axis. Record normalized dimensions, gain/bias shapes and epsilon placement when reproducing a checkpoint.

The RMSNorm Jacobian is J=I/r-xx^T/(d r³). A direction u perpendicular to x satisfies x^T u=0 and therefore Ju=u/r. Along the radial direction x, Jx=epsilon*x/r³. With epsilon exactly zero and nonzero x, changing only the positive scale of x has no first-order effect: normalization removes that radial magnitude. With positive epsilon, the radial sensitivity is small but generally not zero. This is why exact scale invariance must be qualified when an epsilon is present.

At x=0, r=sqrt(epsilon) and J=I/sqrt(epsilon). Epsilon prevents division by zero, but a very small epsilon can still produce large local sensitivity near zero. It is not a universal gradient bound. A learned gain multiplies output coordinates and corresponding Jacobian rows, further changing sensitivities. A learned bias, if present, changes outputs while leaving this derivative with respect to x unaffected. The fixture uses an explicit unit-gain contract to keep the formulas inspectable.

LayerNorm removes a common feature shift because subtracting the mean cancels x+c*1 for any scalar c. Its Jacobian annihilates the all-ones direction under the stated feature reduction. RMSNorm generally does not: adding the same constant changes both the numerator and root mean square without centering it away. A test that shifts every feature by 5 distinguishes them even when both return finite normalized vectors. Do not infer zero mean from a name containing "Norm."

Residual placement changes the route followed by gradients. Pre-norm y=x+F(N(x)) has Jacobian I+J_F J_N. Post-norm y=N(x+F(x)) has J_N(I+J_F). In the zero-branch control F=0, pre-norm leaves both the forward value and derivative equal to the identity, while post-norm still applies N. The direct identity path is a useful local explanation for optimization differences, but a stack also includes initialization, residual scaling, final normalization, optimizer state and depth. The two-line Jacobian comparison is not a theorem that every pre-norm model trains better.

For a gated feed-forward layer, let G=XW_g, U=XW_u, A=SiLU(G), H=A elementwise_mul U and Y=HW_d. If the upstream matrix is R=dL/dY, then dL/dH=R W_d^T. The up-branch derivative is(dL/dH) elementwise_mul A; the gate derivative is(dL/dH) elementwise_mul U elementwise_mul SiLU'(G). Multiplying by X^T accumulates gradients for W_u and W_g. These shapes explain why both projections matter and why a zero local gradient need not indicate a disconnected graph.

The scalar example sets g=0 and u=2. SiLU(0)=0 but SiLU'(0)=1/2, so the output is 0, the derivative with respect to g is 1, and the derivative with respect to u is 0. Changing u to 0 would make both branch derivatives zero at this point. This is a property of the multiplicative gate, not evidence that autograd failed. A large negative gate can also make sigmoid-based activation and derivatives small; inspect actual intermediate values before assuming the optimizer ignored a parameter.

A bias-free plain FFN has matrices d-by-h and h-by-d, totaling2dh weights. A bias-free gated FFN has three such projections totaling3dh. Holding h fixed adds50 percent more FFN weights. Equal weight count requires h_gated=(2/3)h_plain when integer/layout constraints permit: d=4,h_plain=6 and h_gated=4 both yield 48 entries. This equalizes one resource count, not necessarily activation memory, kernel efficiency or task quality.

Interview reasoning: "Can RMSNorm replace LayerNorm without retraining?" The formulas have different invariances and can produce different states under the same weights. Whether a particular conversion works is an empirical model-specific question. First reproduce the existing architecture's axes, epsilon, gains, biases and placement; then evaluate a deliberate change. The RMSNorm paper motivates the alternative, while this chapter's autograd checks test precise local derivatives.

Vocabulary and concepts#

Pre-norm: Normalization inside the transformed residual branch.

Post-norm: Normalization applied after combining residual and branch.

RMSNorm: Normalization by root-mean-square magnitude without mean subtraction.

SwiGLU: A gated feed-forward transformation using aSiLU-activated gate.

Jacobian: The matrix of output sensitivities to input coordinates.

Syntax anatomy and reasoning sequence#

All examples use float64 and small feature widths. RMSNorm computes x/sqrt(mean(x²)+eps) times gain. LayerNorm computes(x-mean(x))/sqrt(mean((x-mean(x))²)+eps). A pre/post comparison uses a zero linear branch so the residual distinction is isolated. SwiGLU uses F.silu for the gate projection and an elementwise product with the up projection. Check the three matrix shapes before counting parameters or requesting gradients.

Worked example / walkthrough#

Example A: Compare RMSNorm and LayerNorm#

The two methods normalize different statistics. Equal output shape does not imply that one is a drop-in numerical replacement for the other.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
def rms_norm(x,eps=1e-8): return x/torch.sqrt(x.square().mean(-1,keepdim=True)+eps)
def layer_norm(x,eps=1e-8):
    centered=x-x.mean(-1,keepdim=True)
    return centered/torch.sqrt(centered.square().mean(-1,keepdim=True)+eps)
x=torch.tensor([3.,4.],dtype=torch.float64)
rms=rms_norm(x); centered=layer_norm(x)
assert abs(rms.mean().item())>.5
np.testing.assert_allclose(centered.mean().item(),0,atol=1e-12,rtol=0)
np.testing.assert_allclose(rms.detach().numpy(),np.array([3.,4.])/np.sqrt(12.5+1e-8),atol=1e-12,rtol=0)

Expected: RMSNorm mean nonzero; LayerNorm mean approximately 0.

Example B: Trace pre/post residual Jacobians#

The zero-branch control isolates placement. LayerNorm removes a common feature shift, so its derivative along the all-ones direction iszero rather than identity.

value=torch.tensor([1.,2.,4.],dtype=torch.float64,requires_grad=True)
pre=torch.autograd.functional.jacobian(lambda z:z+0*layer_norm(z),value)
post=torch.autograd.functional.jacobian(lambda z:layer_norm(z+0*z),value)
torch.testing.assert_close(pre,torch.eye(3,dtype=torch.float64),atol=1e-12,rtol=0)
torch.testing.assert_close(post@torch.ones(3,dtype=torch.float64),torch.zeros(3,dtype=torch.float64),atol=1e-10,rtol=0)

Expected: pre-norm Jacobian is identity; post-norm Jacobian annihilates a constant feature shift.

Example C: Calculate a SwiGLU gate derivative#

At zero, SiLU has derivative one-half. Multiplication by up2 givesgate gradient 1, while the up branch sees the zero gate value. A connected zero gradient is not a missing path.

gate=torch.tensor(0.,dtype=torch.float64,requires_grad=True); up=torch.tensor(2.,dtype=torch.float64,requires_grad=True)
output=F.silu(gate)*up; output.backward()
assert output.item()==0 and gate.grad.item()==1 and up.grad.item()==0

Expected: output 0; gradient with respect to g is 1; with respect to u is 0.

Controlled case study#

A refactor replaces a plain feed-forward block with SwiGLU while retaining the hidden width. The feed-forward parameter count rises by 50 percent, so a quality difference cannot be attributed only to gating. Another refactor moves normalization across the residual addition while keeping the optimizer unchanged. The zero-branch Jacobian and equal-budget calculation separate these changes before a larger training comparison.

Common pitfalls and diagnosis#

For a normalization mismatch, inspect the feature axis, centering, variance convention, epsilon inside or outside the square root, and affine gain/bias before widening tolerances. Use both a nonconstant vector and a zero vector. A zero-branch residual control distinguishes placement independently of a complicated learned branch.

For a gated FFN, inspect gate and up activations and their separate gradients. A connected zero gradient at one point is different from a missing gradient tensor or a parameter absent from the optimizer. This CPU lesson validates explicit float64 formulas and autograd behavior; it does not demonstrate a large-model training run or establish a universally best normalization architecture.
