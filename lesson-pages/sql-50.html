A beginner's mental model for this lesson#

Two tables describe the same months from opposite sides. expenses holds 10,000 individual payments, about 80 per month and category. budgets holds one planned amount per month and category, 125 rows in all. Comparing them row against row is wrong: joining raw expenses to a budget row repeats that budget once per expense. Each side is first summed to one row per (month, category), and only then are the two sides joined.

Variance in this course is actual - budget, so a positive number means overspend. On a fresh load, COGS and Payroll stay under budget in every month, while G&A, Infrastructure and Marketing overspend in almost every month. A budget-only row is a month and category with a plan but no spending; its mirror is spending with no plan. A FULL JOIN keeps both kinds, and the course data happens to contain neither, so you test them by adding rows. A static pivot turns the five known category names into five columns, which only works while that list stays fixed.

The calendar has a trap: the first and last of the 25 months are partial, so comparing them with full months distorts both variance and year-over-year change. Read each query in logical clause order.

Two worked SQL examples#

Both examples build the same two monthly summaries and differ in what they do after the join.

Example 1#
WITH monthly_exp AS (
  SELECT
    date_trunc('month', expense_date)::date AS month,
    category,
    SUM(amount) AS actual
  FROM
    expenses
  GROUP BY
    1,
    2
),
monthly_budget AS (
  SELECT
    period AS month,
    category,
    SUM(amount) AS budget
  FROM
    budgets
  GROUP BY
    1,
    2
)
SELECT
  coalesce(b.category, e.category) AS category,
  coalesce(b.month, e.month) AS month,
  COALESCE(b.budget, 0) AS budget,
  COALESCE(e.actual, 0) AS actual,
  ROUND(COALESCE(e.actual, 0) - COALESCE(b.budget, 0), 2) AS variance,
  ROUND((COALESCE(e.actual, 0) - COALESCE(b.budget, 0)) / NULLIF (b.budget, 0), 4) AS variance_pct
FROM
  monthly_budget b
  FULL OUTER JOIN monthly_exp e ON e.month = b.month
  AND e.category = b.category
ORDER BY
  month DESC,
  category
LIMIT 100;

How to read it: monthly_exp and monthly_budget each return 125 rows, one per month and category. The FULL OUTER JOIN matches them on both keys, COALESCE picks whichever side has the key, and missing amounts display as 0. NULLIF(b.budget, 0) makes the percentage NULL rather than an error if a budget is zero.

Expected result/shape: 100 of the 125 joined rows, newest month first. The top row is COGS for the current partial month: budget 576,000.00, actual 335,159.36, variance -240,840.64 and variance_pct -0.4181 on a fresh load. The columns appear as category, month, budget, actual, variance, variance_pct.

Example 2#
WITH monthly AS (
  SELECT
    date_trunc('month', expense_date)::date AS month,
    category,
    SUM(amount) AS actual
  FROM
    expenses
  GROUP BY
    1,
    2
),
bud AS (
  SELECT
    period AS month,
    category,
    SUM(amount) AS budget
  FROM
    budgets
  GROUP BY
    1,
    2
),
joined AS (
  SELECT
    coalesce(b.category, m.category) AS category,
    coalesce(b.month, m.month) AS month,
    COALESCE(b.budget, 0) AS budget,
    COALESCE(m.actual, 0) AS actual
  FROM
    bud b
    FULL JOIN monthly m ON m.month = b.month
      AND m.category = b.category
)
  SELECT
    category,
    month,
    SUM(actual) OVER (PARTITION BY category ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS actual_ma3,
    SUM(budget) OVER (PARTITION BY category ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS budget_ma3
  FROM
    joined
  ORDER BY
    month DESC,
    category
  LIMIT 100;

How to read it: After the same join, the window ROWS BETWEEN 2 PRECEDING AND CURRENT ROW adds each category's current month to the two before it. Despite the _ma3 names these are three-month totals, not averages; divide by 3 for a mean.

Expected result/shape: 100 rows of category, month, actual_ma3 and budget_ma3. COGS in the latest month shows 1,174,789.21 actual against 1,854,000.00 budget on a fresh load. Each category's two oldest months have fewer than three rows in the frame, so their totals are smaller.

Learning objectives#

  • Align actual and budget values without discarding one-sided periods.
  • Calculate absolute and percentage variance and pivot controlled categories.

Vocabulary and concepts#

  • Variance: actual minus budget under this course's declared convention.
  • Budget-only row: a period/category with budget but no represented actual.
  • Static pivot: fixed output columns for a controlled category domain.

Worked example / walkthrough#

Aggregate actuals and budgets independently at (month, category), full-join those stable relations, and retain both raw values. Derive absolute variance and guard percentage variance with NULLIF(budget, 0); only then pivot the five known categories.

Common mistakes and how to recover#

  • Lesson-specific semantic mistake: Preserve actual-only and budget-only rows before deciding how to display missing values.
  • Budgets about 80 times too large: raw expenses were joined to budgets, so each budget row repeated once per expense. Sum both sides to (month, category) before the join.
  • Year-over-year change of +450% or -16%: the first and last months are partial. Compare full months, or say clearly that the latest month is month-to-date.
  • A pivot row that does not add up: a category spelled differently from the FILTER text, or a sixth category, silently falls out of the pivot. Reconcile each pivot row with the long-form rows from Exercise 3.
  • A "moving average" three times too big: Example 2 sums three months. Divide by the number of rows in the frame if you need a mean.
  • More recovery steps are in the study guide.

Deep dive and reference#

Project focus#

  • Align monthly actual expenses with monthly budgets.
  • Add year-over-year and greater-than-15% overspend indicators.
  • Pivot known expense categories into report columns.

How the learner script uses the current schema#

Actuals come from expenses(expense_date, category, amount). Budgets come from budgets(period, category, amount), where period is the first day of a month. The starter uses a full outer join so months/categories present on only one side remain visible, then demonstrates rolling three-row totals.

The setup categories are COGS, Marketing, Payroll, Infrastructure, and G&A.

Practice map#

Exercise 1 adds year-over-year change and a 15% overspend flag, Exercise 2 pivots variance into one column per category, Exercises 3 and 6 label one-sided and zero-budget rows, and Exercise 4 builds year-to-date totals. Exercise 5 is written: argue for one canonical key before any window. The learner script repeats each prompt unchanged.

Metric semantics#

  • Variance is actual - budget; positive means overspend.
  • Percentage variance uses budget as denominator and must guard zero budgets.
  • A 12-row LAG assumes every category has a complete monthly series. Build a month/category spine when gaps are possible.
  • A static pivot is appropriate only while the category set is controlled.

Validation and limits#

  • Preserve actual-only and budget-only rows before deciding how to display missing values.
  • Reconcile each pivot row to the long-form monthly variance.
  • Do not silently label a missing budget as zero-percent variance.
  • Report both absolute currency variance and percentage; either alone can mislead.

WITH actual AS (
  SELECT
    date_trunc('month', expense_date)::date AS month,
    category,
    SUM(amount) AS actual
  FROM
    expenses
  GROUP BY
    date_trunc('month', expense_date),
    category
),
budget AS (
  SELECT
    period AS month,
    category,
    SUM(amount) AS budget
  FROM
    budgets
  GROUP BY
    period,
    category
),
joined AS (
  SELECT
    COALESCE(a.month, b.month) AS month,
    COALESCE(a.category, b.category) AS category,
    COALESCE(a.actual, 0) AS actual,
    COALESCE(b.budget, 0) AS budget
  FROM
    actual a
    FULL OUTER JOIN budget b USING (month, category)
),
compared AS (
  SELECT
    *,
    LAG(actual, 12) OVER (PARTITION BY category ORDER BY month) AS prior_year_actual
  FROM
    joined
)
SELECT
  month,
  category,
  ROUND(actual, 2) AS actual,
  ROUND(prior_year_actual, 2) AS prior_year_actual,
  ROUND((actual - prior_year_actual) / NULLIF (prior_year_actual, 0), 4) AS year_over_year_variance_pct,
  ROUND((actual - budget) / NULLIF (budget, 0), 4) AS budget_variance_pct,
  actual > budget * 1.15 AS overspent_by_more_than_15_pct
FROM
  compared
ORDER BY
  month DESC,
  category;

Expected grain: one row per month and category, including periods found on only one side of the actual/budget comparison.

Reasoning and verification#
  • Inputs/evidence: For sql-50 Exercise 1, sum the 10,000 expenses rows by date_trunc('month', expense_date) and category in actual, sum the 125 budgets rows by period and category in budget, FULL OUTER JOIN them USING (month, category) with missing amounts set to 0, and take LAG(actual, 12) within each category for the prior year.
  • Expected result/shape: For sql-50 Exercise 1, expected output: 125 rows, one per month and category (25 months from 2024-11-01 to 2026-11-01 times 5 categories), including any period found on only one side of the actual/budget comparison. The final columns are month, category, actual, prior_year_actual, year_over_year_variance_pct, budget_variance_pct, and overspent_by_more_than_15_pct. The final order is month DESC, category.
  • Independent verification: For sql-50 Exercise 1, confirm 125 distinct (month, category) pairs, 71 rows with the flag true, and 65 rows with a prior_year_actual (the first 12 months of each category have none). Recompute the top row by hand: 2026-11 COGS spent 335,159.36 against 398,788.03 in 2025-11 (-0.1596) and a 576,000.00 budget (-0.4181), so the flag is false. Then, in a transaction, insert a Travel expense of 1,000 on 2026-11-15: a 126th row appears with budget_variance_pct NULL but the flag true, because the missing budget became 0; ROLLBACK.
  • Intermediate relation check: actual reduces 10,000 expenses to 125 month-category rows and budget reduces 125 budget rows to 125 groups (the table has no unique key on period and category, so the SUM also absorbs any duplicate plan). joined stays at 125 rows, and compared adds prior_year_actual without changing the count.

  • Alternative/trade-off: Joining compared to itself on month - interval '12 months' finds the prior year by date instead of by row position. It survives a missing month, at the price of a second pass over the data.

Exercise 2: Monthly variance pivot#

SET search_path TO training, public;

WITH actual AS (
  SELECT
    date_trunc('month', expense_date)::date AS month,
    category,
    SUM(amount) AS actual
  FROM
    expenses
  GROUP BY
    date_trunc('month', expense_date),
    category
),
variance AS (
  SELECT
    b.period AS month,
    b.category,
    COALESCE(a.actual, 0) - b.amount AS variance
  FROM
    budgets b
    LEFT JOIN actual a ON a.month = b.period
      AND a.category = b.category
)
  SELECT
    month,
    ROUND(SUM(variance) FILTER (WHERE category = 'COGS'), 2) AS cogs,
    ROUND(SUM(variance) FILTER (WHERE category = 'Marketing'), 2) AS marketing,
    ROUND(SUM(variance) FILTER (WHERE category = 'Payroll'), 2) AS payroll,
    ROUND(SUM(variance) FILTER (WHERE category = 'Infrastructure'), 2) AS infrastructure,
    ROUND(SUM(variance) FILTER (WHERE category = 'G&A'), 2) AS general_admin
  FROM
    variance
GROUP BY
  month
ORDER BY
  month DESC;

Expected shape: one row per budget month and one variance column per known category.

Reasoning and verification#
  • Inputs/evidence: For sql-50 Exercise 2, sum expenses by month and category in actual, start variance from the 125 budgets rows with a LEFT JOIN to actual, compute actual - budget per row, and spread it into one column per category with SUM(variance) FILTER (WHERE category = ...).
  • Expected result/shape: For sql-50 Exercise 2, expected output: 25 rows, one per budget month from 2026-11-01 down to 2024-11-01, with one variance column per known category. The final columns are month, cogs, marketing, payroll, infrastructure, and general_admin. The final order is month DESC.
  • Independent verification: For sql-50 Exercise 2, confirm 25 distinct months and that the five columns of each row add up to that month's total spend minus its total budget: for 2026-11, -240,840.64 + 135,537.59 - 342,178.22 + 41,001.63 + 175,254.25 = -231,225.39, the same as SUM(expenses.amount) - SUM(budgets.amount) for that month. Then, in a transaction, insert a Travel expense of 1,000 on 2026-11-15 and rerun: the pivot is unchanged at 25 rows, so the November reconciliation is now off by exactly 1,000.00, because spending without a budget row never enters variance; ROLLBACK.
  • Intermediate relation check: actual again has 125 rows. variance starts from the 125 budget rows and attaches spending with a LEFT JOIN, then the outer query groups by month, giving 25 rows with five category columns each.
  • Clause check: Each SUM(variance) FILTER (WHERE category = '...') sees one row per month on this data, so the sum just moves that value into its column. The alias general_admin replaces G&A, which is not a convenient column name.
  • Alternative/trade-off: crosstab from the tablefunc extension builds the same layout from a category list, and a BI tool can pivot the long Exercise 3 output itself. Both avoid editing SQL when a category is added.
  • Edge case: Starting from budgets means spending with no budget row never reaches the pivot, and a sixth category would be dropped by every FILTER. Neither happens on the course data, which is why the reconciliation check matters.

Reasoning, safety, and pitfalls#

  • Positive variance means actual spending exceeded budget because the formula is actual - budget.
  • LAG(..., 12) assumes every category has one row for every month. Build a category/month spine when periods can be missing.
  • The pivot is intentionally static. New categories require a new column or a long-form BI result.
  • Treat zero or absent budgets explicitly; NULL percentage is safer than a fabricated infinite or zero rate.

  COALESCE(a.category, b.category) AS category,
  a.actual,
  b.budget,
  CASE WHEN b.category IS NULL THEN
    'missing budget'
  WHEN a.category IS NULL THEN
    'no actual'
  ELSE
    'comparable'
  END AS comparison_status
FROM
  actual a
  FULL JOIN budget b USING (month, category)
ORDER BY
  month DESC,
  category;

-- Exercise 4: first normalize joined keys/values, then apply YTD windows to the
-- single canonical month/category columns.
WITH monthly AS (
  SELECT
    COALESCE(a.month, b.month) AS month,
    COALESCE(a.category, b.category) AS category,
    a.actual,
    b.budget
  FROM (
    SELECT
      date_trunc('month', expense_date)::date AS month,
      category,
      SUM(amount) AS actual
    FROM
      expenses
    GROUP BY
      1,
      2) a
    FULL JOIN (
      SELECT
        period AS month,
        category,
        SUM(amount) AS budget
      FROM
        budgets
      GROUP BY
        1,
        2) b USING (month, category))
SELECT
  month,
  category,
  SUM(actual) OVER (PARTITION BY category, EXTRACT(year FROM month) ORDER BY month) AS actual_ytd,
SUM(budget) OVER (PARTITION BY category, EXTRACT(year FROM month) ORDER BY month) AS budget_ytd,
SUM(actual - budget) OVER (PARTITION BY category, EXTRACT(year FROM month) ORDER BY month) AS variance_ytd
FROM
  monthly
ORDER BY
  month DESC,
  category;

-- Exercise 5 is embodied by the canonical `monthly` CTE above: every later
-- window references its coalesced keys, never one nullable join side.
-- Exercise 6: classify missing plans before applying an overspend threshold.
-- Aggregate each many-row source BEFORE joining. Joining raw expenses to one
-- monthly budget row would repeat that budget once per expense and overstate it.
WITH expense_monthly AS (
  SELECT
    date_trunc('month', expense_date)::date AS month,
    category,
    SUM(amount) AS actual
  FROM
    expenses
  GROUP BY
    1,
    2
),
budget_monthly AS (
  SELECT
    period AS month,
    category,
    SUM(amount) AS budget
  FROM
    budgets
  GROUP BY
    1,
    2
),
monthly AS (
  SELECT
    COALESCE(e.month, b.month) AS month,
    COALESCE(e.category, b.category) AS category,
    e.actual,
    b.budget
  FROM
    expense_monthly e
    FULL JOIN budget_monthly b USING (month, category))
SELECT
  month,
  category,
  actual,
  budget,
  CASE WHEN budget IS NULL THEN
    'unbudgeted spend'
  WHEN actual IS NULL THEN
    'budget without spend'
  WHEN budget = 0 THEN
    'zero budget'
  WHEN actual > budget THEN
    'overspend'
  ELSE
    'within budget'
  END AS status
FROM
  monthly
ORDER BY
  month,
  category;
