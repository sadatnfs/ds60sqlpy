# js-006: Objects, properties and prototypes

## Level and prerequisites

Beginner, approximately 90 minutes. Direct prerequisites: `js-005`

Along the way, explain own property, prototype chain, destructuring, shallow freeze with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. Exercises 1 and 2 start from the worked examples; the authored investigations begin with this task: Read missing count and explicit null count with default 0. The final task tests observe a getter side effect.

## Purpose and mental model

Objects associate property keys with values and can inherit properties through a prototype chain. An own property belongs directly to the object; an inherited property may be found through lookup even when it is absent from the object's own keys. Object.hasOwn checks this distinction without relying on a method that an input object could override. A plain object is useful for records, but Map or a null-prototype dictionary can be clearer for arbitrary external keys.

Destructuring reads properties into bindings, and spread copies enumerable own properties into a new object. Neither automatically deep-copies nested state or validates a schema. Getters can execute code during property access, so an object-shaped value is not always passive data. This lesson uses literal records and controlled prototypes to make lookup, ownership and copying visible.

## Vocabulary and concepts

**Own property:** A property stored directly on an object.

**Prototype chain:** The linked objects consulted during inherited property lookup.

**Destructuring:** Binding selected properties from a value.

**Shallow freeze:** Preventing direct changes without recursively freezing referenced objects.

## Syntax anatomy and execution trace

Object.create(proto) sets a chosen prototype. The in operator checks inherited as well as own properties, while Object.hasOwn checks only own membership. Object.keys enumerates own enumerable string keys. Destructuring defaults apply to undefined values. Object.freeze prevents direct property changes on that object but does not recursively freeze nested objects.

## Worked example / walkthrough

### Example A: Distinguish own and inherited properties

Property lookup and record schema inspection answer different questions. Accepting inherited fields as request data can violate a boundary contract.

```javascript
import { strict as assert } from 'node:assert';

export async function verify() {
  // Worked example
  {
    const parent = { kind: 'record' };
    const child = Object.create(parent);
    child.name = 'sample';
    assert.equal('kind' in child, true);
    assert.equal(Object.hasOwn(child, 'kind'), false);
    assert.equal(Object.hasOwn(child, 'name'), true);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** kind found by in but not hasOwn; name is own.
### Example B: Copy only own enumerable fields

Spread does not reproduce the prototype chain. It copies the declared enumerable own surface, which still may contain mutable nested references.

```javascript
import { strict as assert } from 'node:assert';

export async function verify() {
  // Worked example
  {
    const child = Object.create({ kind: 'record' });
    child.name = 'sample';
    const copy = { ...child };
    assert.deepEqual(Object.keys(copy), ['name']);
    assert.equal(copy.kind, undefined);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** only name copied.

2. **Copy only own enumerable fields: diagnose an edited check.** A careless edit changed a check in Example B so that it reads `assert.deepEqual(Object.keys(copy), ['name!']);`. Run Example B with that line, explain why the edited check now fails for the same program state, and restore it.
   **Expected:** Before the repair the run fails with an `AssertionError` at `assert.deepEqual(Object.keys(copy), ['name!']);`. Restoring `assert.deepEqual(Object.keys(copy), ['name']);` brings back: only name copied.
   **Verify:** Keep the failing and the repaired runs. Explain why the edited check rejects the same program state that `assert.deepEqual(Object.keys(copy), ['name'])` accepts.

3. **Use destructuring defaults carefully.** Read missing count and explicit null count with default 0.
   **Expected:** missing becomes 0; null remains null.
   **Verify:** Keep a check equivalent to `assert.equal(absent, 0)`. As a control, change `const { count: absent = 0 } = {};` to `const { count: absent = 1 } = {};`: the run must fail with an `AssertionError` at that check. Restore the line before continuing.

4. **Use a null-prototype dictionary for arbitrary keys.** Store __proto__ as data in Object.create(null).
   **Expected:** own value preserved; prototype remains null.
   **Verify:** Keep a check equivalent to `assert.equal(Object.hasOwn(dictionary, '__proto__'), true)`. As a control, change `assert.equal(Object.hasOwn(dictionary, '__proto__'), true);` to `assert.equal(Object.hasOwn(dictionary, '__proto__!'), true);` inside it: the run must fail with an `AssertionError`, which shows the check can fail. Restore it.

5. **Expose shallow freeze.** Freeze an outer object and mutate its nested record.
   **Expected:** outer reassignment throws; inner value can change.
   **Verify:** Keep a check equivalent to `assert.equal(value.nested.count, 2)`. As a control, change `value.nested.count = 2;` to `value.nested.count = 3;`: the run must fail with an `AssertionError` at that check. Restore the line before continuing.

6. **Observe a getter side effect.** Read a controlled getter twice and count calls.
   **Expected:** values 1 then 2; getter executed twice.
   **Verify:** Keep a check equivalent to `assert.equal(value.next, 1)`. As a control, change `calls += 1;` to `calls -= 1;`: the run must fail with an `AssertionError` at that check. Restore the line before continuing.

## Common pitfalls and diagnosis

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.
