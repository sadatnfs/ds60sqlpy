## The question and the mechanism

Predict replacement on one column while retaining unrelated filters.

CALCULATE evaluates a scalar expression in a modified filter context. A simple Boolean filter on a column normally replaces an existing filter on that same column. If the column was not filtered, the new filter is added. Other filters are not erased merely because CALCULATE appears in the expression.

This is a precise rule, not a slogan that CALCULATE 'ignores slicers'. An outer Blue filter on Product[Color] can be replaced by an inner Red filter on that column. An outer Paper filter on Product[Category] remains when Blue is added to Color, so the result is the blue Paper product rather than every blue product.

When the business rule requires intersection with an existing selection on the same column, KEEPFILTERS can express it; the next stage examines that alternative. First become comfortable naming the exact modified column. Whole-table filters and expanded-table behavior require additional care, which is why the reference begins with narrow column predicates.

## Vocabulary and expression anatomy

Read the outer CALCULATETABLE as the starting question and the inner CALCULATE as a measure-specific change. A Boolean filter must obey DAX's restrictions, including referencing columns from one table and not referring directly to a measure. The output names distinguish the original and modified contexts.

Concepts to explain in your own words: **CALCULATE**, **Boolean filter**, **replacement**, **added filter**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Replace Blue with Red

**Starting context:** Start with Product.Color = Blue; the inner calculation sets Color = Red.

```dax
EVALUATE CALCULATETABLE ( ROW ( "Original", [NetRevenue], "RedRevenue", CALCULATE ( [NetRevenue], Product[Color] = "Red" ) ), Product[Color] = "Blue" )
```

**Context trace:**

1. The original measure includes Notebook and Mug, totaling 163.
2. The inner predicate replaces the filter on the same Color column.
3. Red admits Pen and produces 24.

**Hand-derived worked-reference result:**

| Original | RedRevenue |
| --- | --- |
| 163 | 24 |

The second result is not a Blue-and-Red intersection. That would have no product rows in this fixture.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: Add Color while retaining Category

**Starting context:** Start with Category = Paper; add Color = Blue on a different column.

```dax
EVALUATE CALCULATETABLE ( ROW ( "PaperRevenue", [NetRevenue], "BluePaperRevenue", CALCULATE ( [NetRevenue], Product[Color] = "Blue" ) ), Product[Category] = "Paper" )
```

**Context trace:**

1. Paper supplies Notebook and Pen: 91.
2. Blue is added while Paper remains active.
3. Only Notebook satisfies both; revenue is 67.

**Hand-derived worked-reference result:**

| PaperRevenue | BluePaperRevenue |
| --- | --- |
| 91 | 67 |

Replacing one column's selection and retaining a different column's selection are compatible behaviors. Always specify which column the expression modifies.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.
