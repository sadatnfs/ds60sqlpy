# web-037: Strings, UTF-8, bytes and contextual encoding

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-036`

## Learning objectives

Build a text inspection report that labels bytes honestly. Explain validation, normalization and output escaping separately. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

A PHP string is a sequence of bytes. UTF-8 is an encoding that represents characters using one or more bytes, so strlen counts bytes rather than user-perceived characters. A visible character can also consist of multiple code points, such as a letter with a combining mark. Code-point count and grapheme count are therefore different concepts. Choose the measure that matches the product requirement.

This worker does not assume every optional internationalization extension. The examples use valid UTF-8 and demonstrate byte-level behavior plus a Unicode-aware regular expression. Production text normalization, locale-aware sorting and grapheme handling need deliberate library and extension choices. Do not truncate arbitrary UTF-8 bytes and then assume the result remains valid text.

## Syntax anatomy and mechanism

Use explicit UTF-8 when escaping HTML output. JSON requires valid Unicode data and can fail on invalid UTF-8. A Unicode regular expression with the u modifier interprets the pattern as UTF-8, but it is not a universal grapheme library. Keep validation, normalization and output encoding separate because they solve different problems.

## Worked example / walkthrough

### Worked example 1: Bytes are not letters

The example's encoding is UTF-8.

```php
$text = 'é';
echo strlen($text);
```

**Expected observation:** The byte length is 2 for this UTF-8 source character.

### Worked example 2: Safe JSON text

The encoder validates its input representation.

```php
$json = json_encode(['label' => 'café'], JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE);
```

**Expected observation:** The result is valid JSON that preserves the readable Unicode label.

## Debugging and common mistakes

Do not promise that a regex character count equals a user's perceived character count. Avoid silently replacing invalid data without a declared policy. Text encoding matters before both rendering and storage.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.
