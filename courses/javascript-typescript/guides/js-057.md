# js-057: Brushing and coordinated views

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-056`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Link a brush to a textual record list. Design a two-chart coordination rule. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

A brush lets a user choose a spatial interval or rectangle. The brush selection is expressed in display coordinates. The analytical selection is usually expressed in data values or record IDs. Convert between those spaces explicitly and decide which boundary values count as selected.

Linked views share application state: selecting a range in one chart changes the records or emphasis in another. If each chart keeps an unrelated hidden selection, the dashboard can contradict itself. A small state object and a pure filter function make coordination easier to inspect.

A drag gesture is not an accessible interface by itself. Provide a reset and a keyboard-friendly way to choose a meaningful preset or numeric interval. Show the selected range and count as text so the effect is understandable without interpreting color alone.

## Syntax anatomy and mechanism

`d3.brushX()` defines a horizontal brush with an explicit extent. Its event selection is null when cleared, otherwise a pair of pixel coordinates. Use `x.invert` to recover data values. Handle null as an intentional full or empty selection according to the documented policy.

The reference uses inclusive data bounds and a preset range from 2 to 4. It calls the same brush move path used by interaction, then asserts selected IDs. Programmatic movement proves state wiring; manual pointer and keyboard checks remain separate.

## Worked example / walkthrough

### Worked example 1: Convert brush pixels to values

A known scale makes the conversion testable.

```javascript
const x = d3.scaleLinear().domain([0, 10]).range([50, 550]);
console.log([x.invert(150), x.invert(250)]);
```

**Expected observation:** [2, 4].

### Worked example 2: Handle clearing explicitly

The policy here treats a cleared brush as all records.

```javascript
function selected(rows, range) {
  return range === null ? rows : rows.filter((d) => d.x >= range[0] && d.x <= range[1]);
}
```

**Expected observation:** Clearing restores the full record set rather than reusing stale bounds.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose filtering with raw pixels against data values. Its distinguishing evidence is The coordinate spaces were mixed. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
