## Why this mechanism matters

Several controller replicas improve availability, but some operations need a single active coordinator. Leader election uses a lease-like coordination record so candidates can observe and renew leadership. It is not a magical exactly-once guarantee. A paused process can continue believing it is leader after another process takes over; external side effects may therefore need fencing tokens or idempotency controls at the destination. Time assumptions, renewal deadlines and shutdown behavior matter. The client-go leader-election package explicitly does not provide fencing by itself. This lesson uses a deterministic logical clock to examine lease policy without sleeping or contacting a cluster.

## Vocabulary and concepts

- **Lease:** A time-bounded claim to coordination authority.
- **Split brain:** Two participants acting as if each has exclusive authority.
- **Fencing:** The destination rejecting operations from an obsolete authority.

## Syntax anatomy and reasoning

A lease model records holder and expiry. A current holder can renew, another candidate must wait until expiry, and a candidate must stop leader-only work when renewal is lost. Real lease acquisition requires optimistic concurrency at the API server, not a local map assignment. A monotonically enforced fencing token belongs at the protected external system; Kubernetes resourceVersion should not be repurposed as a numeric application token.

## Worked example / walkthrough

### Worked example 1: Acquire an empty lease

Let candidate a acquire at logical time 10 for five units.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

type Lease struct {
	Holder  string
	Expires int
}

func acquire(l *Lease, candidate string, now, duration int) bool {
	if candidate == "" || duration <= 0 {
		return false
	}
	if l.Holder != "" && l.Holder != candidate && now < l.Expires {
		return false
	}
	l.Holder = candidate
	l.Expires = now + duration
	return true
}

func main() {
	// Acquire an empty lease
	{
		l := Lease{}
		check(acquire(&l, "a", 10, 5) && l.Holder == "a" && l.Expires == 15, "acquire")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** Holder becomes a and expiry 15.

This local policy model does not implement distributed atomicity. A real update must be protected by the API concurrency contract.

### Worked example 2: Reject a competing candidate

Let b request an unexpired lease held by a.

```go
package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

type Lease struct {
	Holder  string
	Expires int
}

func acquire(l *Lease, candidate string, now, duration int) bool {
	if candidate == "" || duration <= 0 {
		return false
	}
	if l.Holder != "" && l.Holder != candidate && now < l.Expires {
		return false
	}
	l.Holder = candidate
	l.Expires = now + duration
	return true
}

func main() {
	// Acquire an empty lease
	{
		l := Lease{}
		check(acquire(&l, "a", 10, 5) && l.Holder == "a" && l.Expires == 15, "acquire")
	}

	// Reject a competing candidate
	{
		l := Lease{Holder: "a", Expires: 15}
		check(!acquire(&l, "b", 12, 5) && l.Holder == "a", "contender")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The request fails and a remains holder.

The contender waits while the current claim remains valid under this model.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
