Additional likelihoods and uncertainty targets#

Version 0.2 adds eight row likelihoods and one exact complete-group Gaussian likelihood. They use the same prepared native process, distributed reducer and Python/Scala APIs as the original models. No R or Python numerical callback runs on an executor. Read the loaded manifest for the exact field order, parameter names, bounds and model digests; a saved result binds to that particular artifact.

The original gallery still describes its original fourteen models. The additional checks describe independent numerical references and actual Spark check commands for the new registry entries. Preparation, objective evaluation, optimization, prediction and calibration each need their own evidence. A derivative check does not establish successful fitting for every dataset or parameter regime.

All these models provide first and second derivatives of their row objective. The native process checks finite outputs. Near-zero Hessian entries can lose relative precision even when absolute derivative error is small; do not interpret passing absolute numerical checks as uniform relative accuracy at every scale.

The extra variation is within an observation's count distribution. It does not create correlation between different rows. If multiple rows share a latent effect, use an appropriate complete-group model instead of calling independent beta-binomial rows a correlated panel.

Prepare beta_binomial using columns x, trials and y, map observation IDs explicitly, and fit with the ordinary shared interface. Its parameter order is intercept, slope, log_precision. Initial values must respect the descriptor bounds. A prediction frame supplies IDs, x and trials; its tmbad_mean, tmbad_variance and tmbad_sd describe count-scale observation uncertainty at the chosen population parameters. They exclude uncertainty in the estimated parameters.

The implementation evaluates small beta-function increments directly to avoid subtracting nearly equal large log-gamma values. Endpoint count cases, million-trial cases and analytic/independent derivatives are included in the numerical checks. The regularized fit is a different target from an unpenalized likelihood fit; record the selected prior and reduction in any comparison.

Correlated Gaussian random slopes#

gaussian_correlated_random_slope operates on a complete group of x, y rows:

Its coordinates are beta0, beta1, log_sigma, log_tau0, log_tau1 and atanh_correlation, with ρ=tanh⁡(atanh_correlation)\rho=\tanh(\mathrm{atanh\_correlation})ρ=tanh(atanh_correlation). The Gaussian integral is exact. An augmented QR factorization retains the latent prior contribution even when the residual variance is very small or all group covariates coincide. It does not form a rounded normal-equation matrix and then subtract two nearly equal quadratic forms.

Use fit_shared with group columns for one population vector across independent groups. All rows of each group must remain together, within the descriptor's complete-unit bound. A group weight multiplies the whole group's marginal likelihood. Arbitrary row weights would define a different covariance model and are rejected. fit_groups estimates a separate vector per grouping key; that is not a substitute for sharing population information across groups.

Two response-free targets are available:

  • new_group uses the correlated latent prior and observation variance. It rejects supplied history because this target describes an unseen group.
  • existing_group conditions on explicitly supplied complete history and uses exact Gaussian posterior moments of the latent intercept/slope, plus future observation variance.

Future rows in one group remain correlated, although the public output gives each row's marginal moments rather than a dense joint predictive covariance matrix.

The forecast API applies these targets to supplied future covariates. It does not forecast the covariates themselves or introduce an AR process. Use the existing AR(1) models for conditional time-series transitions. No target here includes population-parameter posterior uncertainty.

Priors, fixed coordinates and prepared points#

The extended target API permits Gaussian priors with named means and precisions, selected exact L1 penalties and explicit fixed coordinates. Priors are expressed in the native optimizer coordinates. For example, a Gaussian prior on log_sigma is a prior on a transformed scale, not on sigma; a change of intended probability measure needs the appropriate Jacobian. Optimization of that target is MAP, not posterior sampling.

An L1 target uses the proximal solver and reports KKT stationarity separately from the smooth gradient. A nonzero smooth score at an exact L1 solution is expected. Fixing all coordinates produces an evaluation with explicit all-fixed status, not a fictitious iterative fit. Weighted-mean reduction scales the entire summed target by the same verified weight mass, including the one global prior.

PreparedParameters binds declared simulation truth, a sensitivity point or a separately obtained posterior draw to a prepared model. It can predict and forecast without fabricated convergence metadata. Declaring a posterior draw does not run a posterior sampler. Preserve its source/provenance and distinguish predictive variation across parameter draws from observation variance at one draw.

Boundaries and reproducible checks#

The optional TMB/glmmTMB project supplies real upstream family/covariance examples, custom nonlinear and panel models, and serial reference calculations. Those upstream capabilities are not automatically native registry features. The original nonlinear random-amplitude draft is deliberately not registered: its latent target can have multiple modes, so a zero-start local Laplace solve would not establish the intended marginal likelihood.

Run the numerical and Spark commands in the new-model check guide, then the isolated Compose harness with the matching wheel and native installation. Keep exact source, artifact, input, command and outcome receipts. A local native ARM64 check does not establish AMD64 execution, GPU support, multi-host scale or forecast calibration. Use the simulation studies for explicitly seeded repetitions, retained failures and Monte Carlo uncertainty.
