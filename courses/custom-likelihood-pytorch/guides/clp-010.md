## Model the noise as carefully as the mean

A Gaussian likelihood can let both its mean and its scale depend on covariates. This is useful when measurement precision changes with device type, population segment or the magnitude of an underlying process. It is also easy to implement incorrectly by dividing residuals by an estimated scale while omitting the scale's normalization term.

Let \(m_i=x_i^\top\beta\), let \(s_i=z_i^\top\gamma\) be log standard deviation and define \(\sigma_i=e^{s_i}\). Independent observations have NLL

\[
\mathcal L(\beta,\gamma)=\sum_i\left[s_i+\frac12\log(2\pi)
 +\frac12(y_i-m_i)^2e^{-2s_i}\right].
\]

The first term is essential. Increasing scale reduces standardized squared residuals, but it also spreads the probability density over a wider range of possible observations. The normalization term accounts for that spread. Removing it allows a model to improve its alleged loss by inflating every scale indefinitely.

The log-scale derivative for one observation is \(1-(y_i-m_i)^2/\sigma_i^2\). Under a correctly specified model its expectation is zero, because the expected standardized squared residual is one. This provides a useful diagnostic identity, although observed equality in a fitted sample does not prove out-of-sample calibration.

## Worked case 1: two known noise regimes

The program uses a shared unknown mean and a binary scale covariate \(z\). Group zero has observations \((-1,1,-1,1)\); group one has \((-3,3,-3,3)\). Each group is symmetric around zero, so the mean MLE is zero. Within-group residual squares imply MLE scales one and three. Therefore the exact log-scale coefficients are \(\gamma_0=0\) and \(\gamma_1=\log3\).

L-BFGS estimates the mean and both scale coefficients jointly, and the program compares its result with this independent symmetric-data oracle. It checks the final gradient and the average squared standardized residual in each group. Symmetry was deliberately constructed to make these answers exact; this is not a random sample from which to claim empirical calibration performance.

The scale coefficient is interpreted multiplicatively: moving from group zero to group one multiplies the standard deviation by three, and the variance by nine. Confusing log variance with log standard deviation would change the exponent and score by factors of two. Name the modeled quantity precisely in prose, variable names and output.

## Worked case 2: remove the normalization term

Starting from the fitted parameters, add two to every log standard deviation. The scales multiply by \(e^2\). The residual-only term falls from about four to about 0.0733, falsely suggesting a dramatic improvement. The proper NLL rises from about 15.746 to 27.819 because the observations now occupy only a small portion of an excessively diffuse distribution.

This is a useful negative control: the demonstration intentionally computes a tempting but invalid objective and shows the direction in which it fails. The main fitted objective retains all parameter-dependent terms. Comparing only final residual error would miss this defect, because a scale model is judged on both how it fits residuals and how much probability mass it spreads elsewhere.

## Assumptions, diagnostics and failure modes

An unrestricted scale parameter for every observation can make a Gaussian likelihood degenerate near perfectly fitted points. A covariate scale model shares information, but rich mean and scale networks still need constraints, regularization or a carefully chosen distribution. A positive scale floor is a modeling restriction; document it instead of presenting it as a neutral numerical trick.

Inspect residuals against both mean predictors and scale predictors. A wrong mean can appear as inflated variance in one region. Heavy tails can also make a Gaussian scale estimate sensitive to a few observations. A Student likelihood changes tail behavior but introduces additional parameters and assumptions. Dependence between rows remains a separate issue: heteroskedasticity does not account for within-subject correlation.

The complete helper checks dimensions and finite values. Float64 and modest synthetic values keep this demonstration stable, but a deployment should investigate nonfinite exponentials and near-singular curvature rather than replacing nonfinite losses with arbitrary constants. Such replacements can remove the very gradients needed to detect the problem.

## Answered review questions

**Why can weighted least squares be equivalent only in a special case?** If variances are known and fixed, minimizing residuals weighted by their inverse variances gives the same mean fit as Gaussian MLE. When variances are estimated, their normalization terms cannot be discarded.

**Is fitting the scale enough for calibrated intervals?** No. Distributional shape, dependence, mean correctness and parameter uncertainty all matter. Check interval behavior on relevant held-out populations rather than relying on in-sample standardized residual identities.

**What does the changed case teach about custom neural likelihoods?** A network that outputs a distribution parameter must optimize the complete distributional objective. Learning a variance is a statistical estimation problem, not an opportunity to hide prediction errors behind large uncertainty values.

```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json
import math

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def heteroskedastic_nll(theta, z, y):
    if theta.shape != (3,) or z.ndim != 1 or y.shape != z.shape or not len(y):
        raise ValueError("Use three parameters and matching nonempty covariate/response vectors")
    if not all(bool(torch.isfinite(value).all()) for value in (theta, z, y)):
        raise ValueError("Parameters, scale covariate and observations must be finite")
    mean = theta[0]
    log_sigma = theta[1] + theta[2] * z
    return (
        log_sigma
        + 0.5 * math.log(2 * math.pi)
        + (y - mean).square() * torch.exp(-2 * log_sigma) / 2
    ).sum()


def fit_scales(z, y):
    theta = tensor([0.3, 0.2, 0.2]).requires_grad_()
    optimizer = torch.optim.LBFGS(
        [theta],
        max_iter=100,
        tolerance_grad=1e-10,
        tolerance_change=1e-14,
        line_search_fn="strong_wolfe",
    )

    def closure():
        optimizer.zero_grad()
        value = heteroskedastic_nll(theta, z, y)
        value.backward()
        return value

    optimizer.step(closure)
    gradient = torch.autograd.grad(heteroskedastic_nll(theta, z, y), theta)[0]
    return theta.detach(), float(gradient.abs().max())


def run_cases():
    z = tensor([0, 0, 0, 0, 1, 1, 1, 1])
    y = tensor([-1, 1, -1, 1, -3, 3, -3, 3])
    theta, gradient = fit_scales(z, y)
    assert torch.allclose(theta, tensor([0, 0, math.log(3)]), atol=2e-6, rtol=0)
    log_sigma = theta[1] + theta[2] * z
    residual_only = [
        float(((y - theta[0]).square() * torch.exp(-2 * (log_sigma + shift)) / 2).sum())
        for shift in (0, 2)
    ]
    proper = [float(heteroskedastic_nll(theta + tensor([0, shift, 0]), z, y)) for shift in (0, 2)]
    assert residual_only[1] < residual_only[0] and proper[1] > proper[0]
    standardized = (y - theta[0]) / log_sigma.exp()
    assert torch.allclose(
        standardized.square().reshape(2, 4).mean(1), tensor([1, 1]), atol=2e-6, rtol=0
    )
    return {
        "parameters": theta.tolist(),
        "group_scales": [float(theta[1].exp()), float((theta[1] + theta[2]).exp())],
        "gradient_max_abs": gradient,
        "residual_only_inflation_path": residual_only,
        "proper_nll_inflation_path": proper,
        "fixture": "symmetric synthetic residuals provide an exact scale oracle",
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
