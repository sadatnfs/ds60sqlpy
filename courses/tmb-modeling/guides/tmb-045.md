# Reporting and simulation inside the C++ model

Start with: tmb-044, tmb-009, tmb-031.

Outcome: Keep diagnostics, differentiable outputs and simulated observations aligned with the model.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

`REPORT`, `ADREPORT` and `SIMULATE` are template-authoring macros with different jobs. REPORT makes a value available for ordinary readback. ADREPORT records a derived quantity for derivative-aware uncertainty. SIMULATE encloses generative code executed during simulation requests. None of them adds a likelihood contribution merely by being present.

A template should clearly separate data, parameter transforms, normalized objective terms, output quantities and simulation. Naming a report “prediction_interval” does not make it a calibrated interval; the mathematical construction must support the label.

### Worked case A: residual and predicted mean

The companion computes residuals as diagnostics and a fitted mean as an estimand. The residual vector is a natural REPORT target; selected predicted means can be ADREPORT targets when their uncertainty is needed. If prediction covariates change, construct a reviewed objective with the new data rather than silently mutating a report from an old tape.

```cpp
REPORT(residual);
ADREPORT(prediction);
SIMULATE {
  for (int i = 0; i < y.size(); ++i) y(i) = rnorm(mean(i), sigma);
  REPORT(y);
}
```

This fragment assumes matching finite vectors and positive scale already validated. It illustrates the ordinary Gaussian observation generator, not a complete hierarchical generator.

### Worked case B: hierarchical simulation order

For a random-intercept model, unconditional simulation draws group effects first and then observations conditional on those effects. Holding fitted group modes fixed instead produces a conditional simulation. The companion generates both with a fixed seed and explains why their between-group variability differs. Neither should be mislabeled as the other.

If a latent model's SIMULATE block generates only observation noise but `checkConsistency` expects the full joint generator, the score diagnostic can expose a mismatch. Document whether random states are regenerated and whether fixed parameters are conditioned on, resampled or integrated.

### Answered discussion

**Can I generate random values during objective evaluation?** An optimizer expects a deterministic objective for this workflow. Keep stochastic generation inside the intended simulation path, not the likelihood loop. **Can a simulation overwrite learner data?** The numerical model should return generated data to an owned result, not silently replace saved source datasets. **Should every simulated vector be AD-reported?** No. Simulation draws and derivatives of deterministic estimands serve different purposes.

See the [template macro and checkConsistency references](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The original normal template has an actually exercised SIMULATE path; new hierarchical generators need their own consistency checks.

### Complete R companion

```r
y <- c(1, 2, 4);fitted <- c(1.2, 2.1, 3.8);print(data.frame(y = y, fitted = fitted, residual = y - fitted))
set.seed(4545);group <- rep(1:3, each = 4);sigma <- .2;tau <- .8
new_u <- rnorm(3, 0, tau);unconditional <- 1 + new_u[group] + rnorm(12, 0, sigma)
conditional <- 1 + c(-.2, 0, .2)[group] + rnorm(12, 0, sigma)
print(data.frame(group = group, unconditional = unconditional, conditional = conditional))
stopifnot(length(new_u) == 3, length(unconditional) == length(group))
```
