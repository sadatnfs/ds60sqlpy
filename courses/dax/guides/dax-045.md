## The question and the mechanism

Expand interacting calculation items and distinguish numeric transformation from display selection.

Two reusable transformations can produce different results when their order changes. Adding 10 then multiplying by 0.9 differs from multiplying first then adding 10. Calculation-group precedence defines how item expressions are composed around the selected measure; it is not a suggestion to ignore parentheses and rely on ordinary operator precedence.

For the simple arithmetic groups specified here, the higher-precedence item's expression forms the outer structure, and the lower-precedence expression replaces its SELECTEDMEASURE placeholder. A higher-precedence scale item therefore produces (Revenue +10)*0.9. Reversing the groups' precedence produces Revenue*0.9 +10. Write the expanded tree before calculating.

Dynamic format strings have their own precedence interaction. The highest-precedence applicable calculation-group format string determines presentation in the documented model behavior. A format expression returns a format pattern while leaving the measure numeric. It cannot repair an incorrectly composed numerical expression, and a currency pattern applied to a dimensionless ratio would mislabel the result.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text

                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

### Feature and version boundary

Calculation groups require a supported semantic model and compatibility level 1500 or higher according to the reviewed Microsoft documentation. This lesson teaches definitions and explicitly expanded calculations offline; it does not create a calculation group in an engine.

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Scale has higher precedence

**Starting context:** Specified items: AddTen = SELECTEDMEASURE()+10 at lower precedence; Scale = SELECTEDMEASURE()*0.9 at higher precedence.

```dax
EVALUATE ROW ( "ExpandedValue", ( [NetRevenue] + 10 ) * 0.9 )
```

**Context trace:**

1. The outer Scale expression receives the lower-precedence AddTen expression.
2. The expansion is(187 +10)*0.9.
3. 197 multiplied by 0.9 is 177.3.

**Hand-derived worked-reference result:**

| ExpandedValue |
| --- |
| 177.3 |

The literal 10 represents an illustrative compatible amount for this algebra example. A real fee policy would also define which population and measures receive it.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: Addition has higher precedence

**Starting context:** The same two item definitions with AddTen as the higher-precedence outer expression.

```dax
EVALUATE ROW ( "ExpandedValue", [NetRevenue] * 0.9 + 10 )
```

**Context trace:**

1. The expansion is(187*0.9)+10.
2. The scale first yields 168.3.
3. Adding 10 gives 178.3, one more than the other order.

**Hand-derived worked-reference result:**

| ExpandedValue |
| --- |
| 178.3 |

Passing tests for each group alone does not prove their combined behavior. Include interacting groups in a measure/context regression matrix.

## A deeper model or scope review

For a separately configured dynamic format string, a model can choose a pattern while retaining a numeric measure. A conceptual example for a known margin measure is:

```dax
IF ( ISSELECTEDMEASURE ( [NetMargin] ), "0.0%", SELECTEDMEASUREFORMATSTRING() )
```

The NetMargin definition appears in the measure-composition lesson. This is a format-expression example in the appropriate model scope, not a query or a conversion of units. Actual locale, group selection and format precedence remain part of external model acceptance.

## Progressive hints

1. Keep the parentheses from the expression tree.
2. Some fixtures can hide noncommutativity.
3. Include groups alone, together and an unaffected measure.
4. Presentation does not change the numeric expression's semantics.
5. A percent format scales display of a dimensionless fraction.
6. Conversion and aggregation may occur at different grains.
