# viz-007: Reduce rendering work without hiding important data

## Level and prerequisites

Advanced. Direct prerequisites: `viz-004`, `viz-005`, `viz-006`. This lesson uses bounded SVG traces; it does not require WebGL, a GPU or a remote service.

## Separate analysis from display reduction

A plot can become slow or visually saturated long before its underlying dataset is statistically large. Rendering fewer marks can help, but the reduction method changes what remains visible. Keep the full analysis dataset and its provenance separate from the displayed subset.

The fixture has 5,000 sine-wave samples and a single spike of amplitude twelve at index 2473. Regularly retaining every hundredth point gives 50 marks and misses that spike. A visually smooth line from the subsample could conceal the most consequential event.

## Worked case: a min/max envelope

Partition the source into blocks of 100 indices. Retain the minimum and maximum value in every block, plus the first and last observation. Deduplicate and sort retained indices before plotting. At most 102 points remain, and the spike is preserved because it is its block's maximum.

The algorithm checks the number of selected indices and compares the displayed maximum with the full maximum. This is a numerical preservation property, not a subjective resemblance claim. The source table reports original and reduced counts, maxima and whether the spike survived.

## Contrasting case: what the envelope does not preserve

An envelope preserves extremes within the chosen blocks, but it can distort mean, frequency content, event duration and intermediate shape. Connecting selected extrema with a line can imply slopes that the original signal did not follow. If the decision concerns average load, aggregate means with an appropriate spread summary instead. If it concerns frequency, use a method designed for that analysis and prevent aliasing.

Changing block size changes the representation. Data-dependent selection can preserve anomalies while overemphasizing them visually; the caption should say what was retained and why. A reduced figure is not a replacement dataset for statistical inference.

## Responsiveness and lifecycle

The browser reference asks Plotly to resize responsively and purges its graph when the preview leaves. Measure completed rendering with a timing boundary after the rendering promise, not only the time required to issue `newPlot`. Compare the same source, trace types, dimensions and device/browser when making performance claims.

This reference does not assert a speedup from a host timer. It demonstrates bounded display work and a retained-extrema invariant. Real narrow-screen, zoom, interaction and timing observations remain separate qualification evidence.

## Six progressive exercises

1. **Find the missed spike.** Determine whether index 2473 appears in every-hundredth sampling. Expected evidence: it does not, and the displayed maximum stays near one.
2. **Implement an envelope.** Keep per-block minima/maxima plus endpoints. Expected evidence: no more than 102 unique sorted indices and amplitude twelve retained.
3. **Change the block size.** Use blocks of 250. Expected evidence: at most 42 retained indices and the same global maximum. Hint: reason from 20 blocks plus two endpoints.
4. **Expose a limitation.** Compare the mean of retained values with the full mean. Expected evidence: do not assume equality; explain selection weighting.
5. **Test lifecycle behavior.** Resize, change the source and rerun, then leave the preview. Expected evidence: no stale chart, duplicate controls or asynchronous errors. Hint: creation and cleanup are paired operations.
6. **Transfer the objective.** Propose a display summary for average utilization rather than spike detection. Expected evidence: a defensible aggregation and a caption describing the statistic. Hint: representation follows the decision.
