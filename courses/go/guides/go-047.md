# go-047: Controller tests from pure functions to owned clusters

## Level and prerequisites

Advanced. Allow about 120 minutes, then revisit the transfer case later. Prerequisites: go-046

## Learning objectives

Test controller logic with fakes that count calls and preserve error causes before running against an owned cluster. Along the way, explain fake client, integration evidence, fault injection; implement the six investigations below; and defend the expected result of a changed input before running it.

## Why this mechanism matters

A controller needs several evidence layers. Pure tests check decision rules quickly. Fake-client tests check requested API interactions and local error handling but may omit server defaulting, validation, resourceVersion conflicts and admission behavior. API-server integration tests add those server contracts. An owned disposable cluster adds controllers, scheduling, networking and real cleanup behavior. Passing a fake test is not interchangeable with a successful rollout. Design fault injection around a specific uncertainty: conflict, cancellation, stale cache, forbidden access or unknown outcome. Keep source hashes, exact object identity and cleanup receipts so the evidence can be traced to the program that actually ran.

## Vocabulary and concepts

- **Fake client:** An in-process substitute with deliberately limited server semantics.
- **Integration evidence:** Observed behavior across real component boundaries.
- **Fault injection:** Deliberately producing a specified failure to test recovery.

## Syntax anatomy and reasoning

Use a narrow interface at the application boundary and inject a fake with explicit outcomes. Assert both the result and which calls were made. A forbidden error should not trigger an endless retry loop; a cancellation should stop new calls. For live tests, create a unique owned namespace, retain UIDs, bound all waits and verify cleanup without deleting resources identified only by a reusable name. Do not use production contexts as convenient fixtures.

## Worked example / walkthrough

### Worked example 1: Verify one successful API call

Run a fake client configured to return a value.

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

var ErrForbidden = errors.New("forbidden")

type FakeReader struct {
	Value, Calls int
	Err          error
}

func (f *FakeReader) Read(ctx context.Context) (int, error) { f.Calls++; return f.Value, f.Err }

type Reader interface {
	Read(context.Context) (int, error)
}

func readOnce(ctx context.Context, r Reader) (int, error) {
	if err := ctx.Err(); err != nil {
		return 0, err
	}
	v, err := r.Read(ctx)
	if err != nil {
		return 0, fmt.Errorf("read object: %w", err)
	}
	return v, nil
}

func main() {
	// Verify one successful API call
	{
		f := &FakeReader{Value: 3}
		v, err := readOnce(context.Background(), f)
		check(err == nil && v == 3 && f.Calls == 1, "success")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The result is retained and exactly one call occurs.

Call count is evidence about adapter behavior, while the returned value checks the consuming contract.

### Worked example 2: Preserve a forbidden error

Make the fake return ErrForbidden.

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

var ErrForbidden = errors.New("forbidden")

type FakeReader struct {
	Value, Calls int
	Err          error
}

func (f *FakeReader) Read(ctx context.Context) (int, error) { f.Calls++; return f.Value, f.Err }

type Reader interface {
	Read(context.Context) (int, error)
}

func readOnce(ctx context.Context, r Reader) (int, error) {
	if err := ctx.Err(); err != nil {
		return 0, err
	}
	v, err := r.Read(ctx)
	if err != nil {
		return 0, fmt.Errorf("read object: %w", err)
	}
	return v, nil
}

func main() {
	// Verify one successful API call
	{
		f := &FakeReader{Value: 3}
		v, err := readOnce(context.Background(), f)
		check(err == nil && v == 3 && f.Calls == 1, "success")
	}

	// Preserve a forbidden error
	{
		f := &FakeReader{Err: ErrForbidden}
		_, err := readOnce(context.Background(), f)
		check(errors.Is(err, ErrForbidden) && f.Calls == 1, "forbidden")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The exact cause is visible and only one call occurs.

Authorization failure is not repaired by repeating the same request. Surface the required permission or configuration diagnosis.

## Predict before running

Predict the value and call count when the fake reader returns 3, and when it returns ErrForbidden. For a canceled context, predict whether the fake is called at all. Predict whether a zero value is treated as failure, and whether a wrapped unknown error stays visible to errors.Is. Then decide what the receipt digest proves.

## Exercises

### Exercise 1: Verify one successful API call: change one input

Copy worked example 1, change `f := &FakeReader{Value: 3}` to `f := &FakeReader{Value: 4}` and predict the failure before running; then restore the line.

**Expected:** The edited run panics with `success` because `err == nil && v == 3 && f.Calls == 1` no longer holds.

**Verify:** Restoring `f := &FakeReader{Value: 3}` makes the check pass again with the worked observation: the result is retained and exactly one call occurs.

### Exercise 2: Preserve a forbidden error: diagnose an edited check

A careless edit rewrote the check in worked example 2 as `check(errors.Is(err, ErrForbidden) && f.Calls != 1, "forbidden")`. Explain the failure, then restore it.

**Expected:** The defective run panics with `forbidden`; after restoring `check(errors.Is(err, ErrForbidden) && f.Calls == 1, "forbidden")`, the exact cause is visible and only one call occurs.

**Verify:** The edited check fails with message `forbidden` for a state that `errors.Is(err, ErrForbidden) && f.Calls == 1` accepts.

### Exercise 3: Stop before a canceled call

Cancel context before invoking the adapter.

**Expected:** No API call is made.

**Verify:** Your solution must keep `errors.Is(err, context.Canceled) && f.Calls == 0` true. Control: changing `check(errors.Is(err, context.Canceled) && f.Calls == 0, "cancel")` to `check(errors.Is(err, context.Canceled) && f.Calls != 0, "cancel")` panics with message `cancel`; revert it.

### Exercise 4: Distinguish returned zero from failure

Return a successful zero from the fake.

**Expected:** The zero is accepted with nil error.

**Verify:** Your solution must keep `err == nil && v == 0` true. Control: changing `f := &FakeReader{Value: 0}` to `f := &FakeReader{Value: 1}` panics with message `zero success`; revert it.

### Exercise 5: Retain an unknown failure

Return an unexpected error cause.

**Expected:** The cause remains inspectable.

**Verify:** Your solution must keep `errors.Is(err, cause)` true. Control: an input that falsifies it fails with message `unknown cause`; revert it.

### Exercise 6: Transfer source-bound evidence

Bind a synthetic receipt to its lesson ID and the SHA-256 digest of the exact source text, then compare it with a source that has one extra byte.

**Expected:** The receipt matches the exact source and rejects the changed source.

**Verify:** Your solution must keep `receipt["lesson"] == "go-047" && receipt["source"] == digest(source) && receipt["source"] != digest(source+" ")` true. Control: changing `receipt := map[string]string{"lesson": "go-047", "source": digest(source)}` to `receipt := map[string]string{"lesson": "go-48", "source": digest(source)}` panics with message `receipt identity`; revert it.

## Common pitfalls and diagnosis

Trusting fake-client tests as cluster evidence is the main error: a fake accepts objects a real API server would reject, never applies defaults or admission and returns no conflicts unless told to. Use fakes for decision logic and error paths, envtest or an API server for contracts, and an owned disposable cluster for end-to-end behavior. Count calls to catch hidden retries.

General compiler, panic and error diagnosis is in the [study guide](../STUDY-GUIDE.md#diagnose-a-failure).

## Progressive hints

### Hint for investigation 1: Verify one successful API call: change one input

1. Restate the expected observation: The result is retained and exactly one call occurs.
2. readOnce calls the fake once. What do v and Calls hold?
3. The fake now returns 4, so `v==3` fails while the error is nil and Calls is 1. The adapter works; the fake's value changed.

### Hint for investigation 2: Preserve a forbidden error: diagnose an edited check

1. Restate the expected observation: The exact cause is visible and only one call occurs.
2. The error is wrapped with %w. Can errors.Is still find ErrForbidden?
3. readOnce calls the fake exactly once, so `f.Calls!=1` is false and the check fails. Restore `==1`; the call count is part of the evidence.

### Hint for investigation 3: Stop before a canceled call

1. Restate the expected observation: No API call is made.
2. readOnce checks the context first. How many calls reach the fake?
3. The test verifies absence of a side effect, not merely the final error text.

### Hint for investigation 4: Distinguish returned zero from failure

1. Restate the expected observation: The zero is accepted with nil error.
2. A zero value with a nil error is a success. What does readOnce return?
3. Result value and operation status are separate channels.

### Hint for investigation 5: Retain an unknown failure

1. Restate the expected observation: The cause remains inspectable.
2. %w keeps the original in the chain. Does errors.Is find the cause?
3. Preserving the cause supports diagnosis.

### Hint for investigation 6: Transfer source-bound evidence

1. Restate the expected observation: The receipt matches the exact source and rejects the changed source.
2. A digest changes when any byte changes. Does the source with an extra space match?
3. Binding evidence to a digest of the exact bytes means a later edit cannot reuse an old result.
