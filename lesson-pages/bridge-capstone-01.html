Learning objectives#

  • Reject an apparently healthy release using independently expected identities and values instead of matching grand totals alone.
  • Repair a data product from source facts without changing the golden answer to fit the implementation.
  • Gate a fake publication, preserve an inspectable review artifact, and explain the difference between a tested repair and an observed production recovery.

Vocabulary and concepts#

Imagine a finance export with three invoice rows. Its release summary says three invoices and 15,000 cents. An independent expected fixture says the same. The controls look reassuring, but the release understates invoice B, omits zero-valued invoice C, and invents invoice D. One error cancels another in the grand total. Your job is to make that failure visible, repair the transform, and write a review whose claims stay within the available evidence.

Data product: A dataset delivered under a declared contract, including its grain, identities, field meanings, and allowed values. Here one row represents one invoice identified by invoice_id, and money is nonnegative integer cents in one synthetic currency. Missing invoices differ from zero-valued invoices.

Golden fixture: A small independently specified expected result. It is checked in separately from the implementation. Rebuilding it by calling the same transformer under test would destroy that independence. A golden fixture is only evidence for the cases and domain assumptions it actually covers.

Reconciliation: A comparison that reports changed matched identities, missing expected identities, and unexpected actual identities. Check both directions. Validate unique identities first; a dictionary silently discarding a duplicated invoice is a hidden policy decision, not reconciliation.

Canonical fingerprint: A digest of a declared deterministic encoding of the contract version and validated rows. Sorting identities makes row presentation order irrelevant to this product's equality. A digest identifies encoded content; it does not make the content correct, establish who produced it, or provide a signature or trusted custody chain.

Publication gate: The point before an external effect at which required evidence is checked. In this lesson the effect is an injected fake publisher. The gate controls whether that fake is called; it does not simulate a database commit, message broker acknowledgement, or actual consumer delivery.

Incident review: A record that separates observations, impact, causal claims, corrective action, verification, and unresolved questions. A plausible historical explanation is still a hypothesis when the source release code and timeline are absent. No person or service should be blamed based on these synthetic snapshots.

Syntax anatomy and ownership#

The supplied frozen dataclasses describe values: ProductRow is an invoice, SourceLine is a line item with its own identity, and Difference records one invoice-level mismatch. None in a diagnostic means one side lacks that invoice. It is not an unknown amount inside a valid product; the product contract requires an integer amount. type(value) is int deliberately rejects Boolean values because Python otherwise treats True as an integer.

Sequence[ProductRow] permits caller-owned input collections. Validate and take an immutable tuple snapshot before review and publication so later caller mutation cannot change what is emitted. A Publisher Protocol describes a method the caller supplies. It does not create an external connection. Tests provide an implementation that records calls, allowing you to inspect the exact release ID, reviewed rows, and digest without a service.

Keep effects at the boundary. Parsing reads a caller-named file; transformation and reconciliation return values; publication calls the injected adapter only after exact checks. The report writer receives a caller-supplied path and uses exclusive creation. It refuses an existing path rather than overwriting learner work. Exclusive creation protects existing bytes; it is not an atomic multi-file publication protocol and a process crash can leave an incomplete new report. Detect and investigate a partial artifact rather than trusting its filename as proof of completion.

Worked example / walkthrough#

Example 1: A passing total with a failing keyed result#

This complete example needs only Python. Predict both prints first:

expected = {"X": 100, "Y": 50}
observed = {"X": 90, "Y": 60}
print(sum(expected.values()), sum(observed.values()))
changed = [key for key in sorted(expected) if expected[key] != observed[key]]
print(changed)
assert sum(expected.values()) == sum(observed.values())
assert changed == ["X", "Y"]

Expected: The first print is 150 150; the second is ['X', 'Y']. The input grain is one amount per invoice key. Summing removes identity, so equal sums cannot prove invoice equality. This tiny example assumes identical key sets. The capstone must additionally handle missing and unexpected keys, validate input uniqueness before dictionary conversion, and keep zero distinct from an absent invoice.

Example 2: Evidence controls an injected effect#

This complete toy model uses only lists and dictionaries:

journal = []


def checked_record(expected, candidate):
    if expected != candidate:
        return False
    journal.append(tuple(sorted(candidate.items())))
    return True


assert checked_record({"X": 100}, {"X": 90}) is False
assert journal == []
assert checked_record({"X": 100}, {"X": 100}) is True
assert journal == [(("X", 100),)]
print(len(journal))

Expected: It prints 1. Rejection happens before the fake effect, and a passing comparison records the reviewed value exactly once. This toy is purposefully narrower than the capstone: it has no file parsing, duplicate validation, release identity, fingerprint, or failure-after-effect behavior. The full exercise makes those boundaries explicit. A fake journal is evidence of call ordering, not proof of a real release or exactly-once delivery.

Exercises#

Keep predictions and actual test results in your attempt. The three files in bridge/professional/fixtures/capstone/ are synthetic course data. Do not edit the golden fixture to make a failing implementation pass. Start with literal assertions whose expected values are written independently of your function.

  1. Validate the product boundary. Implement normalize and load_product. Require exactly invoice_id and amount_cents per JSON row, unique nonempty invoice IDs without outer whitespace, and nonnegative integer cents. Reject Boolean amounts, fractional values, missing/extra fields, and duplicate IDs.

Expected: Golden rows are (A,10000),(B,5000),(C,0), sorted by ID. Each malformed fixture raises ValueError. Empty input yields an empty tuple; a zero-valued invoice remains present. Hint: validate before constructing an identity dictionary so duplicates cannot disappear silently.

  1. Retain controls without overstating them. Implement summarize for both product fixtures. Write the strongest statement the two controls support, then one equality claim they do not support.

Expected: Both inputs yield Summary(3,15000). The expected and incident row collections are unequal. Your test must show both matching summaries and unequal keyed rows. Hint: a counterexample needs a passing control and a failing stronger claim on the same input.

  1. Reconcile identities and values. Implement reconcile and the evidence accepted property. Validate both inputs, inspect the union of their keys, and return deterministic changed, missing, and unexpected diagnostics. Keep absent-side amounts as None, never zero.

Expected: Exactly three diagnostics, ordered by invoice ID: B changed 5000 -> 4000, C missing 0 -> None, D unexpected None -> 1000. reconcile((), ()) accepts; golden versus golden accepts. Hint: test key presence before comparing the associated amount.

  1. Repair from source facts. Implement load_source_lines and build_product using the independent source-lines fixture and complete invoice manifest ('A','B','C'). Reject repeated line IDs, orphan lines, repeated manifest IDs, and invalid cents. Preserve zero-line invoices.

Expected: Repaired rows equal the unchanged golden rows exactly, and source inputs remain unchanged. Two A lines sum to 10000, B is 5000, and C is 0. A duplicate L1 or a line for absent invoice Z raises ValueError. Hint: the manifest defines all parent identities; line facts supply amounts.

  1. Fingerprint the declared contract. Implement canonical_digest using SHA-256 of UTF-8 canonical JSON containing contract_version: 1 and sorted validated rows. Use sorted object keys, compact separators, and ASCII-safe JSON encoding. Explain why this identifies content without proving truth.

Expected: Reordering valid rows preserves the 64-hex digest; changing any amount changes it. The golden digest is fddc2c8909fee69e1b96661b9e11a1e87c7212bfe2d5f731a9f45ed2ae868fc3. Repeated invoice identities fail before hashing. Hint: define the bytes before selecting a hash function.

  1. Gate a fake publication. Implement publish_checked. Validate the release ID, snapshot actual rows once, reconcile with the independent expected rows, and call the injected Publisher only after acceptance. Let publication failures propagate without automatic retries.

Expected: Incident input raises ReleaseRejected with zero recorded calls. Repaired input records one (release_id, sorted_rows, digest) call. A fake that records and then raises still records only once; the caller receives the exception and cannot claim acknowledged publication. Hint: distinguish a rejected precondition from an unknown external outcome.

  1. Preserve an inspectable artifact. Implement write_evidence to create a caller-named JSON report exclusively. Record the contract version, verdict, both summaries, both digests, and ordered diagnostics. Use a temporary test directory, not a fixed learner output path.

Expected: The report round-trips with accepted: false and C's absent actual amount as JSON null. A second write to the same path raises FileExistsError, leaving the first report's bytes unchanged. Hint: exclusive creation protects existing work without a prior existence check.

  1. Write an evidence-bounded incident review. Implement incident_review and prepare a short handoff with observations, impact, causal uncertainty, repair, verification, and unresolved questions. Require a rejected before and accepted after that both use the same golden digest.

Expected: The review names all three mismatches, explains matching summaries, marks the historical cause unproven, and states that consumer delivery and production recovery remain unknown. Passing a different golden dataset as the repair is rejected. Hint: a working repair can be verified even when the original failure mechanism has not been established.

Self-check#

  • What information disappears when an invoice relation becomes a grand total?
  • Which fixture independently specifies expected behavior, and what would make that independence circular?
  • Why are None and zero different in the C diagnostic?
  • Which evidence proves a tested repair, a fake publication call, and actual consumer recovery respectively? Which is absent here?
  • Without reading the implementation, describe the next negative fixture you would add for a new domain requirement.

Common pitfalls#

  • A summary passes while the release is wrong. Inspect identity-level differences for B, C, and D. Do not change the total or the golden fixture to hide the discrepancy.
  • Duplicate rows vanish. Look for a dictionary comprehension before key validation. Add two rows with the same ID and require an explicit failure.
  • C disappears because it has no lines. Check whether the transform starts from child lines instead of the complete invoice manifest. A zero-valued parent is still a required row.
  • A publication error triggers a second call. Use the fake that records before raising. Its first effect may already have happened, so a generic retry is not safe evidence of exactly-once behavior.
  • All tests pass without an attempt. Inspect the test import. The supplied suite exercises the reference; point your own test at the learner copy.
  • The review invents a root cause. Compare each claim with the supplied snapshots and source fixture. Label a hypothesis when no release code or deployment timeline proves it.

Exercise solutions#

Exercise 1: Validate before losing information#
def normalize(rows: Sequence[ProductRow]) -> tuple[ProductRow, ...]:
    """Validate the keyed contract before sorting or comparing attributes."""
    identities: set[str] = set()
    for row in rows:
        _identity(row.invoice_id, "invoice_id")
        _amount(row.amount_cents)
        if row.invoice_id in identities:
            raise ValueError("duplicate invoice_id")
        identities.add(row.invoice_id)
    return tuple(sorted(rows, key=lambda row: row.invoice_id))


def load_product(path: Path) -> tuple[ProductRow, ...]:
    raw = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(raw, list):
        raise ValueError("product JSON must be a list")
    rows: list[ProductRow] = []
    for item in raw:
        if not isinstance(item, dict) or set(item) != {"invoice_id", "amount_cents"}:
            raise ValueError("product row must contain exactly invoice_id and amount_cents")
        rows.append(
            ProductRow(_identity(item["invoice_id"], "invoice_id"), _amount(item["amount_cents"]))
        )
    return normalize(rows)

The loader first requires a JSON list and exactly the two declared fields on each row. Identity validation rejects blank values and outer whitespace rather than silently normalizing potentially different business keys. Amounts are nonnegative integer cents; Python bool must be rejected explicitly because it is an int subclass. The typed ProductRow does not itself enforce annotations at runtime, so normalize validates direct in-memory callers as well as files.

Uniqueness is checked before constructing a dictionary. A dictionary would otherwise keep one value per key and could hide either exact or conflicting duplicates. Sorted output supplies a deterministic presentation under exact, case-sensitive identity comparison. No trimming, currency conversion, or duplicate-winner rule is invented. Empty input is valid and returns an empty tuple. Golden invoice C's zero is a present amount, so it stays in the result.

Expected: Golden IDs are A,B,C with amounts 10000,5000,0. Malformed, Boolean, negative, fractional, extra-field and duplicate fixtures raise ValueError.

Verify: Run the malformed-boundary cases plus the literal GOLDEN fixture assertion in the focused test; each invalid input must fail before reconciliation.

Exercise 2: Keep the summary claim narrow#
def summarize(rows: Sequence[ProductRow]) -> Summary:
    checked = normalize(rows)
    return Summary(len(checked), sum(row.amount_cents for row in checked))

Normalize before summarizing so an invalid keyed product does not acquire an apparently authoritative control total. Summary contains row_count and amount_total_cents. Both incident and golden inputs produce three rows and 15,000 cents, which is the deliberately deceptive normal-looking result. Summation projects away identity and individual amount distribution, allowing two defects to cancel.

The correct conclusion is that these two summaries match. It is not that the invoice relations match, that the release was delivered, or that recovery succeeded. Retain summary checks because they detect other failure classes cheaply. Combine them with independent keyed diagnostics instead of replacing one weak proof with another. The test records both equal summaries and unequal literal ProductRow collections on the same input, so the claimed counterexample cannot accidentally become a case where the summary already reveals the fault. The empty collection has zero rows and a zero total.

Expected: Both summaries equal Summary(3,15000), yet the literal expected and incident tuples differ.

Verify: Inspect the test that asserts all three facts together: expected summary, actual summary, and unequal keyed inputs.

Exercise 3: Reconcile the union of keys#
def reconcile(expected: Sequence[ProductRow], actual: Sequence[ProductRow]) -> Evidence:
    expected_rows, actual_rows = normalize(expected), normalize(actual)
    left = {row.invoice_id: row.amount_cents for row in expected_rows}
    right = {row.invoice_id: row.amount_cents for row in actual_rows}
    differences: list[Difference] = []
    for invoice_id in sorted(left.keys() | right.keys()):
        if invoice_id not in left:
            kind = "unexpected"
        elif invoice_id not in right:
            kind = "missing"
        elif left[invoice_id] != right[invoice_id]:
            kind = "changed"
        else:
            continue
        differences.append(
            Difference(invoice_id, left.get(invoice_id), right.get(invoice_id), kind)
        )
    return Evidence(
        summarize(expected_rows),
        summarize(actual_rows),
        canonical_digest(expected_rows),
        canonical_digest(actual_rows),
        tuple(differences),
    )


class Evidence:
    expected_summary: Summary
    actual_summary: Summary
    expected_digest: str
    actual_digest: str
    differences: tuple[Difference, ...]

    @property
    def accepted(self) -> bool:
        return not self.differences

Each side is independently normalized before its keyed dictionary is built. The union of keys covers expected-only and actual-only identities. Sorting that union produces deterministic diagnostics without assuming a particular input row order. Presence checks come before amount comparison, so missing C is distinct from a known amount of zero. The three categories are mutually exclusive for a unique identity: unexpected, missing, or changed.

Evidence contains summaries, canonical digests, and the complete difference tuple. The accepted property means no differences remain under this exact keyed contract. It does not mean a publisher was called or that a consumer received data. Equal empty inputs are accepted because the contract permits an empty product; a domain requiring at least one invoice would need another independently tested rule. The tests compare complete Difference records, including None placement, rather than only counting three diagnostic rows.

Expected: B changed 5000 to 4000, C missing 0 to None, and D unexpected None to 1000, in that identity order. Golden/Golden and empty/empty accept.

Verify: Compare exact diagnostic tuples and test a standalone zero-valued missing invoice to ensure zero is never treated as absent.

Exercise 4: Reconstruct the complete parent relation#
def load_source_lines(path: Path) -> tuple[SourceLine, ...]:
    raw = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(raw, list):
        raise ValueError("source JSON must be a list")
    rows: list[SourceLine] = []
    for item in raw:
        if not isinstance(item, dict) or set(item) != {"line_id", "invoice_id", "amount_cents"}:
            raise ValueError("source row has unexpected fields")
        rows.append(
            SourceLine(
                _identity(item["line_id"], "line_id"),
                _identity(item["invoice_id"], "invoice_id"),
                _amount(item["amount_cents"]),
            )
        )
    return tuple(rows)


def build_product(
    invoice_ids: Sequence[str], lines: Sequence[SourceLine]
) -> tuple[ProductRow, ...]:
    """Aggregate validated source lines while preserving zero-line invoices."""
    totals: dict[str, int] = {}
    for invoice_id in invoice_ids:
        checked = _identity(invoice_id, "invoice_id")
        if checked in totals:
            raise ValueError("duplicate invoice identity in manifest")
        totals[checked] = 0
    seen: set[str] = set()
    for line in lines:
        line_id = _identity(line.line_id, "line_id")
        if line_id in seen:
            raise ValueError("duplicate line_id")
        seen.add(line_id)
        invoice_id = _identity(line.invoice_id, "invoice_id")
        if invoice_id not in totals:
            raise ValueError("line references an invoice absent from the manifest")
        totals[invoice_id] += _amount(line.amount_cents)
    return normalize([ProductRow(invoice_id, amount) for invoice_id, amount in totals.items()])

The invoice manifest creates the complete set of parent identities before any line is processed. Initializing their totals to zero preserves C even though C has no source line. Each line must have a unique line_id, refer to an existing parent, and carry a valid exact amount. Duplicate line IDs are rejected even when their values match: the lesson has no approved replay or deduplication policy, so silently choosing a winner would hide uncertainty.

The transformer allocates its own dictionary and returns new immutable ProductRow values. It does not mutate the caller's list or the checked-in fixtures. Sorting happens only after aggregation. A repaired result is compared with the unchanged independent golden file, never with an expected result generated by this same function. Tests separately cover empty input, a zero-line parent, orphans, duplicate parents, duplicate lines, and invalid cents. These negative controls target information loss and overcounting, which a single passing total would not expose.

Expected: The complete repaired tuple is A=10000, B=5000, C=0. The source list remains byte-for-byte equivalent as values, and malformed line relations are rejected.

Verify: Use literal ProductRow expectations, a copied input list, and separate orphan/duplicate cases; do not call build_product to manufacture the expected answer.

Exercise 5: Define bytes before computing a digest#
def canonical_digest(rows: Sequence[ProductRow]) -> str:
    payload = {"contract_version": 1, "rows": [asdict(row) for row in normalize(rows)]}
    encoded = json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=True)
    return hashlib.sha256(encoded.encode("utf-8")).hexdigest()

Canonicalization explicitly includes contract_version 1 and the validated, identity-sorted rows. Dataclass conversion provides named fields, JSON sorts object keys, compact separators remove formatting variability, and ASCII-safe encoding plus UTF-8 defines repeatable bytes. SHA-256 then fingerprints those bytes. Reversing presentation order cannot change this product's digest, while a changed identity or amount changes the encoded content.

The fixture digest is pinned independently in the tests. That check detects an accidental encoding change as well as an amount change. A deliberate new schema or encoding needs a new contract version and reviewed fixture update; do not merely replace the pinned digest to silence a failing test. The hash supplies content identification under the encoding, not source authenticity, semantic correctness, or historical custody. Invalid duplicates fail before encoding, and the separate golden reconciliation supplies the semantic evidence the fingerprint alone cannot provide.

Expected: Golden digest is fddc2c8909fee69e1b96661b9e11a1e87c7212bfe2d5f731a9f45ed2ae868fc3; row reordering preserves it and incident amounts change it.

Verify: Run the pinned digest, reversed input, changed amount, and duplicate-key cases as separate controls.

Exercise 6: Place the effect behind the gate#
def publish_checked(
    release_id: str,
    expected: Sequence[ProductRow],
    actual: Sequence[ProductRow],
    publisher: Publisher,
) -> Evidence:
    checked_id = _identity(release_id, "release_id")
    # Snapshot caller input once so the reviewed data and emitted data agree.
    rows = normalize(actual)
    evidence = reconcile(expected, rows)
    if not evidence.accepted:
        raise ReleaseRejected("invoice identities or amounts differ from the golden contract")
    publisher.publish(checked_id, rows, evidence.actual_digest)
    return evidence

The function validates release identity, snapshots and normalizes actual rows once, computes evidence against expected rows, and rejects mismatches before invoking the supplied adapter. The exact tuple used in review is passed to the publisher with its digest, so later mutation of the caller's list cannot change emitted data. The fake records the full call, making ordering and payload review possible without any external system.

The function performs no automatic retry. If an adapter records an effect and then loses its acknowledgement, an exception cannot prove that no effect occurred. The test fake reproduces that boundary by appending one record before raising. The caller receives the error and the call count remains one. A real system would need an idempotency and outcome-reconciliation contract before retrying. This reference does not claim atomicity between a local report, a database, and an external publisher.

Expected: Rejected incident produces ReleaseRejected and zero fake calls. Repaired rows produce one sorted reviewed call. Failure after recording propagates after one call.

Verify: Inspect the zero-call test, exact recorded payload/digest, mutable-input snapshot test, and record-then-raise negative control.

def write_evidence(evidence: Evidence, path: Path) -> None:
    """Create a deterministic review artifact without overwriting existing work."""
    payload = {"contract_version": 1, "accepted": evidence.accepted, **asdict(evidence)}
    with path.open("x", encoding="utf-8", newline="\n") as output:

        output.write("\n")

The writer serializes the evidence value with an explicit contract version and accepted verdict. Dataclass conversion preserves the ordered diagnostic list, including None as JSON null. Sorted keys and a final newline make the output deterministic and readable. The caller owns the path and decides where an artifact belongs; main does not create any file by default.

Opening in exclusive mode x combines creation and existence checking in the filesystem operation. A second attempt raises FileExistsError without truncating the original file. Checking exists first and then using write mode would introduce a race and an overwrite hazard. Exclusive creation is still not a transactional artifact publication protocol: a crash can leave a partial newly created report. Keep that limitation explicit. The focused test uses a temporary directory, reads the report back as JSON, checks the missing-zero diagnostic, and verifies that a failed overwrite leaves the original bytes unchanged.

Expected: A report contains contract_version, accepted, both summaries, both digests, and ordered differences. Rewriting the same path raises FileExistsError and preserves its bytes.

Verify: Round-trip the JSON and compare pre/post bytes around the rejected second write; a filename existing is not evidence of complete content.

The review requires a rejected before state and accepted after state under the identical expected digest. That prevents a repair from passing merely because someone changed the golden answer. The observed statement and impact are derived from diagnostic evidence rather than assuming every incident has the fixture's particular invoice names. A mismatch can be described precisely without pretending to know the historical source-code defect.

Cause status remains unproven because the original transform and deployment timeline are absent. Repair is a verified reconstruction from supplied source facts; production delivery and consumer recovery remain unresolved. The narrative does not blame an actor or claim a live operation occurred. Tests reject already-accepted before states, still-rejected repairs, and a passing result against a different golden dataset. A useful handoff pairs this narrative with actual attempted code, test output, rejected evidence, and accepted repair evidence so another reviewer can reproduce its bounded conclusions.

Expected: The review names changed, missing, and unexpected invoices, reports causal uncertainty, and retains consumer delivery and production recovery as unknown.

Verify: Check same-golden rejection and both verdict boundaries, then read the note for any unsupported historical or production claim.

Limits of the evidence#

The synthetic fixture fixes the domain to one currency, nonnegative integer cents, exact case-sensitive invoice identity, and an immutable complete parent manifest. It does not cover multi-currency conversion, partial refunds, authorization, database isolation, real idempotent delivery, or production acceptance. Adding any of those requires a new explicit contract and independent cases. A correct local repair is a meaningful result even while the historical cause remains unknown. Do not trade that precision for a more confident story.

"""Offline data-product review with independent golden evidence and fake effects."""

from __future__ import annotations

import hashlib
import json
from collections.abc import Sequence
from dataclasses import asdict, dataclass
from pathlib import Path
from typing import Protocol

LESSON_ID = "bridge-capstone-01"
PREREQUISITES = ("bridge-08", "sql-quality-01", "python-pro-03")
LEVEL = "advanced"
FIXTURES = Path(__file__).resolve().parents[1] / "fixtures" / "capstone"


@dataclass(frozen=True)
class ProductRow:
    invoice_id: str
    amount_cents: int


@dataclass(frozen=True)
class SourceLine:
    line_id: str
    invoice_id: str
    amount_cents: int


@dataclass(frozen=True)
class Summary:
    row_count: int
    amount_total_cents: int


@dataclass(frozen=True)
class Difference:
    invoice_id: str
    expected_cents: int | None
    actual_cents: int | None
    kind: str


@dataclass(frozen=True)
class Evidence:
    expected_summary: Summary
    actual_summary: Summary
    expected_digest: str
    actual_digest: str
    differences: tuple[Difference, ...]

    @property
    def accepted(self) -> bool:
        return not self.differences


@dataclass(frozen=True)
class IncidentReview:
    observed: str
    impact: str
    cause_status: str
    repair: str
    verification: str
    unresolved: tuple[str, ...]


class Publisher(Protocol):
    """Caller-owned side effect; failures propagate without an automatic retry."""

    def publish(self, release_id: str, rows: tuple[ProductRow, ...], digest: str) -> None: ...


class ReleaseRejected(ValueError):
    """Data failed the declared independent golden contract before publication."""


def _identity(value: object, label: str) -> str:
    if not isinstance(value, str) or not value or value != value.strip():
        raise ValueError(f"{label} must be nonempty text without outer whitespace")
    return value


def _amount(value: object) -> int:
    if type(value) is not int or value < 0:
        raise ValueError("amount_cents must be a nonnegative integer, excluding bool")
    return value


def normalize(rows: Sequence[ProductRow]) -> tuple[ProductRow, ...]:
    """Validate the keyed contract before sorting or comparing attributes."""
    identities: set[str] = set()
    for row in rows:
        _identity(row.invoice_id, "invoice_id")
        _amount(row.amount_cents)
        if row.invoice_id in identities:
            raise ValueError("duplicate invoice_id")
        identities.add(row.invoice_id)
    return tuple(sorted(rows, key=lambda row: row.invoice_id))


def load_product(path: Path) -> tuple[ProductRow, ...]:
    raw = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(raw, list):
        raise ValueError("product JSON must be a list")
    rows: list[ProductRow] = []
    for item in raw:
        if not isinstance(item, dict) or set(item) != {"invoice_id", "amount_cents"}:
            raise ValueError("product row must contain exactly invoice_id and amount_cents")
        rows.append(
            ProductRow(_identity(item["invoice_id"], "invoice_id"), _amount(item["amount_cents"]))
        )
    return normalize(rows)


def load_source_lines(path: Path) -> tuple[SourceLine, ...]:
    raw = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(raw, list):
        raise ValueError("source JSON must be a list")
    rows: list[SourceLine] = []
    for item in raw:
        if not isinstance(item, dict) or set(item) != {"line_id", "invoice_id", "amount_cents"}:
            raise ValueError("source row has unexpected fields")
        rows.append(
            SourceLine(
                _identity(item["line_id"], "line_id"),
                _identity(item["invoice_id"], "invoice_id"),
                _amount(item["amount_cents"]),
            )
        )
    return tuple(rows)


def summarize(rows: Sequence[ProductRow]) -> Summary:
    checked = normalize(rows)
    return Summary(len(checked), sum(row.amount_cents for row in checked))


def canonical_digest(rows: Sequence[ProductRow]) -> str:
    payload = {"contract_version": 1, "rows": [asdict(row) for row in normalize(rows)]}
    encoded = json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=True)
    return hashlib.sha256(encoded.encode("utf-8")).hexdigest()


def reconcile(expected: Sequence[ProductRow], actual: Sequence[ProductRow]) -> Evidence:
    expected_rows, actual_rows = normalize(expected), normalize(actual)
    left = {row.invoice_id: row.amount_cents for row in expected_rows}
    right = {row.invoice_id: row.amount_cents for row in actual_rows}
    differences: list[Difference] = []
    for invoice_id in sorted(left.keys() | right.keys()):
        if invoice_id not in left:
            kind = "unexpected"
        elif invoice_id not in right:
            kind = "missing"
        elif left[invoice_id] != right[invoice_id]:
            kind = "changed"
        else:
            continue
        differences.append(
            Difference(invoice_id, left.get(invoice_id), right.get(invoice_id), kind)
        )
    return Evidence(
        summarize(expected_rows),
        summarize(actual_rows),
        canonical_digest(expected_rows),
        canonical_digest(actual_rows),
        tuple(differences),
    )


def build_product(
    invoice_ids: Sequence[str], lines: Sequence[SourceLine]
) -> tuple[ProductRow, ...]:
    """Aggregate validated source lines while preserving zero-line invoices."""
    totals: dict[str, int] = {}
    for invoice_id in invoice_ids:
        checked = _identity(invoice_id, "invoice_id")
        if checked in totals:
            raise ValueError("duplicate invoice identity in manifest")
        totals[checked] = 0
    seen: set[str] = set()
    for line in lines:
        line_id = _identity(line.line_id, "line_id")
        if line_id in seen:
            raise ValueError("duplicate line_id")
        seen.add(line_id)
        invoice_id = _identity(line.invoice_id, "invoice_id")
        if invoice_id not in totals:
            raise ValueError("line references an invoice absent from the manifest")
        totals[invoice_id] += _amount(line.amount_cents)
    return normalize([ProductRow(invoice_id, amount) for invoice_id, amount in totals.items()])


def publish_checked(
    release_id: str,
    expected: Sequence[ProductRow],
    actual: Sequence[ProductRow],
    publisher: Publisher,
) -> Evidence:
    checked_id = _identity(release_id, "release_id")
    # Snapshot caller input once so the reviewed data and emitted data agree.
    rows = normalize(actual)
    evidence = reconcile(expected, rows)
    if not evidence.accepted:
        raise ReleaseRejected("invoice identities or amounts differ from the golden contract")
    publisher.publish(checked_id, rows, evidence.actual_digest)
    return evidence


def write_evidence(evidence: Evidence, path: Path) -> None:

    with path.open("x", encoding="utf-8", newline="\n") as output:

        output.write("\n")


def incident_review(before: Evidence, after: Evidence) -> IncidentReview:
    if before.accepted or not after.accepted:
        raise ValueError("review requires rejected before evidence and accepted repair evidence")
    if before.expected_digest != after.expected_digest:
        raise ValueError("repair must use the same independent golden contract")
    summary_note = (
        "matching row count and total cents"
        if before.expected_summary == before.actual_summary
        else "different summary controls"
    )
    impact = "; ".join(
        f"{difference.invoice_id}: {difference.kind}, "
        f"expected_cents={difference.expected_cents}, actual_cents={difference.actual_cents}"
        for difference in before.differences
    )
    return IncidentReview(
        observed=f"{len(before.differences)} keyed differences exist alongside {summary_note}.",
        impact=impact,
        cause_status=(
            "Unproven: the supplied snapshots do not identify the historical defect or actor."
        ),
        repair="Rebuild from validated source lines and the complete invoice manifest.",
        verification=(
            "The repaired keyed relation matches the unchanged independent golden fixture."
        ),
        unresolved=(
            "Whether a real consumer received the incident release is unknown.",
            "The original transform and deployment timeline are not supplied.",
            "Fake publication evidence does not prove production recovery.",
        ),
    )


def main() -> None:
    golden = load_product(FIXTURES / "golden_product.json")
    broken = load_product(FIXTURES / "incident_product.json")
    before = reconcile(golden, broken)
    repaired = build_product(("A", "B", "C"), load_source_lines(FIXTURES / "source_lines.json"))
    after = reconcile(golden, repaired)
    print(
        json.dumps(

                "incident": {"accepted": before.accepted, **asdict(before)},
                "repair": {"accepted": after.accepted, **asdict(after)},
                "review": asdict(incident_review(before, after)),
            },
            indent=2,
            sort_keys=True,
        )
    )

    main()
