## Build one connected local ML workflow

This capstone connects actual implementations rather than replacing them with diagrams. Feast retrieves historical features under event-time and availability cutoffs. A reviewed snapshot is materialized into Feast's real local SQLite online store. Scikit-learn fits a preprocessing and classification pipeline. MLflow records an experiment, stores the model with its sklearn flavor, registers a version and resolves an accepted alias. The model is reloaded from its actual artifact and invoked through a FastAPI application that retrieves online features.

The whole workflow remains bounded and local. The ASGI client exercises application requests in process; it does not start a persistent HTTP listener. The feature registry, online store, tracking database and model artifacts live in owned temporary directories and are removed after the run. The persistent local ML service project provides the separate Docker lifecycle for retained state and real network requests. A run ID printed by this pad describes its local execution, not a hosted tracking server that remains available afterward.

The synthetic task predicts whether a dimensionless signal exceeds a threshold. It is intentionally simple so the engineering boundaries can be verified independently. A high validation score on this fixture is not evidence that a useful real-world model has been trained. The preceding ML chapters explain evaluation design, uncertainty and acceptance; here those mechanisms are connected to feature and serving infrastructure.

## Establish feature and evaluation populations

There are 40 synthetic accounts. Twenty training accounts have signals from zero through 19, observed on January 1 and available shortly afterward. Twenty validation accounts have signals from 0.25 through 19.25, observed on January 3 and available before their January 4 decisions. The label is one when the signal is at least 12. The account populations are disjoint and the validation decision period is later.

An additional record changes account zero's January 1 signal to 99, but that correction is not known until January 5. It must not enter a January 2 training decision or the accepted January 4 online snapshot. Historical eligibility requires both clocks:

\[
t_{\mathrm{feature}}\leq t_{\mathrm{decision}},\qquad
 t_{\mathrm{known}}\leq t_{\mathrm{decision}},
\]

with the declared seven-day feature TTL also respected. Feast's actual `filter_by_created_timestamp=True` option enforces the availability cutoff for this prepared FileSource path. A separate hand-calculated list of expected signals checks the retrieved values. The code merges results back to request identities with one-to-one validation and preserves all 40 requests, preventing missing retrieval rows from silently shrinking the training population.

## Publish online features deliberately

An online feature store usually serves the currently materialized value for an entity. It does not automatically reconstruct every historical decision. The program therefore creates a separate accepted feature file containing only records known by the January 4 publication cutoff, registers a serving view over that file and materializes only that view. It does not materialize the unfiltered history and assume late-known corrections will be harmless.

This separation makes the publication policy visible. Historical training retrieval and current online retrieval have different time contracts, but both derive from reviewed source information. The online store is actual SQLite managed by Feast. Querying account zero returns zero, not the future-known correction 99. Querying validation accounts 20 and 39 returns 0.25 and 19.25. The code checks those exact values before treating the model's response as meaningful.

## Worked case 1: train, register, reload and serve

`example_one()` builds the feature store, retrieves the full historical population and fits a pipeline containing `StandardScaler` and `LogisticRegression` on the 20 training rows. It evaluates the 20 later validation rows separately. The prepared execution obtains accuracy 1.0 on this deterministic synthetic boundary and passes the illustrative local acceptance threshold of 0.9.

MLflow creates a real SQLite-backed experiment and run. The run records feature-contract identity, population counts, validation accuracy and exact source-code identity. The sklearn model is logged with an input example, signature and dependency versions, then registered. The program reloads the stored model and confirms that its validation class predictions match the original fitted pipeline. This exercises actual serialization and loading, not merely a dictionary labelled “model artifact.”

After acceptance, the setup explicitly assigns the registry alias. The ASGI `/predict` route receives an account identity and expected feature/model contracts, retrieves the account's signal from Feast's online store and calls the reloaded model's probability method. Three actual responses preserve account identity and model version. Their probabilities are extremely close to zero for the two low-signal accounts and close to one for the high-signal account. Those extremes reflect the easy synthetic task and are not a calibration guarantee.

## Worked case 2: reject incompatible requests without moving acceptance

The second case constructs the complete workflow again in a fresh owned state directory. It submits a request whose feature contract changes the unit from dimensionless to kilograms. The service returns 409 rather than scoring a numerically plausible value under the wrong meaning. It also rejects an unavailable expected model version with 409.

An unknown account returns 404 because no accepted online feature exists. Missing features are not silently converted to zero, which would make an unknown entity resemble a real low-signal account. A valid request still returns 200 after these failures. The registry alias remains on the accepted version. There is no request endpoint that lets a caller activate another model by naming it.

This case demonstrates compatibility at the serving boundary. It does not evaluate a second trained challenger; the dedicated registry chapter covers that acceptance comparison. Keeping the evidence scopes distinct matters: request rejection, model registration, evaluation and activation are separate operations even when they are connected in one product.

```python
"""Actual Feast historical/online features, fitted pipeline, MLflow model and ASGI inference."""

import hashlib
import importlib.metadata
import io
import json
import os
import re
import tempfile
from contextlib import redirect_stdout
from datetime import UTC, datetime, timedelta
from pathlib import Path

import mlflow
import mlflow.sklearn
import pandas as pd
from fastapi import FastAPI, HTTPException
from fastapi.testclient import TestClient
from feast import Entity, FeatureStore, FeatureView, Field, FileSource, ValueType
from feast.types import Float32
from mlflow import MlflowClient
from mlflow.models import infer_signature
from pydantic import BaseModel, ConfigDict
from pydantic import Field as InputField
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

CONTRACT = {"feature": "signal", "unit": "dimensionless", "population": "synthetic-accounts-v1"}
MODEL_NAME = "dme-connected-model"


def contract_digest(contract):
    return hashlib.sha256(json.dumps(contract, sort_keys=True).encode()).hexdigest()


def fixtures():
    records = []
    requests = []
    for account in range(40):
        validation = account >= 20
        value = float(account % 20) + (0.25 if validation else 0)
        day = 3 if validation else 1
        records.append(
            {
                "account_id": account,
                "event_time": datetime(2024, 1, day, tzinfo=UTC),
                "known_at": datetime(2024, 1, day, 1, tzinfo=UTC),
                "signal": value,
            }
        )
        requests.append(
            {
                "request_id": account,
                "account_id": account,
                "event_timestamp": datetime(2024, 1, day + 1, tzinfo=UTC),
                "label": int(value >= 12),
                "validation": validation,
            }
        )
    records.append(
        {
            "account_id": 0,
            "event_time": datetime(2024, 1, 1, tzinfo=UTC),
            "known_at": datetime(2024, 1, 5, tzinfo=UTC),
            "signal": 99.0,
        }
    )
    return pd.DataFrame(records), pd.DataFrame(requests)


def feature_store(root):
    directory = root / "features"
    directory.mkdir()
    (directory / "feature_store.yaml").write_text(
        "project: dme_connected\nprovider: local\nregistry: registry.db\n"
        "online_store:\n  type: sqlite\n  path: online.db\nentity_key_serialization_version: 3\n"
    )
    features, requests = fixtures()
    history_path = directory / "history.parquet"
    features.to_parquet(history_path, index=False)
    cutoff = datetime(2024, 1, 4, tzinfo=UTC)
    accepted = features.loc[features.known_at <= cutoff].copy()
    accepted_path = directory / "accepted.parquet"
    accepted.to_parquet(accepted_path, index=False)
    entity = Entity(name="account", join_keys=["account_id"], value_type=ValueType.INT64)
    views = [
        FeatureView(
            name=name,
            entities=[entity],
            ttl=timedelta(days=7),
            schema=[Field(name="signal", dtype=Float32)],
            source=FileSource(
                path=str(path), timestamp_field="event_time", created_timestamp_column="known_at"
            ),
        )
        for name, path in [("history_signal", history_path), ("serving_signal", accepted_path)]
    ]
    store = FeatureStore(repo_path=str(directory))
    store.apply([entity, *views])
    historical = store.get_historical_features(
        entity_df=requests[["request_id", "account_id", "event_timestamp"]],
        features=["history_signal:signal"],
        filter_by_created_timestamp=True,
    ).to_df()
    joined = requests.merge(
        historical[["request_id", "signal"]], on="request_id", how="left", validate="1:1"
    ).sort_values("request_id")
    expected = [float(account % 20) + (0.25 if account >= 20 else 0) for account in range(40)]
    assert len(joined) == 40 and joined.signal.tolist() == expected and joined.signal.iloc[0] == 0
    progress = io.StringIO()
    with redirect_stdout(progress):
        store.materialize(
            start_date=datetime(2023, 12, 31, tzinfo=UTC),
            end_date=cutoff,
            feature_views=["serving_signal"],
        )
    print(re.sub(r"\x1b\[[0-9;]*m", "", progress.getvalue()), end="")
    return store, joined


def train_register_reload(root, rows):
    os.environ["GIT_PYTHON_REFRESH"] = "quiet"
    uri = "sqlite:///" + str(root / "tracking.db")
    mlflow.set_tracking_uri(uri)
    mlflow.set_registry_uri(uri)
    client = MlflowClient(tracking_uri=uri, registry_uri=uri)
    experiment = client.create_experiment(
        "connected-capstone", artifact_location=(root / "artifacts").as_uri()
    )
    train, validation = rows.loc[~rows.validation], rows.loc[rows.validation]
    model = make_pipeline(StandardScaler(), LogisticRegression(C=1000, random_state=51)).fit(
        train[["signal"]], train.label
    )
    accuracy = float(accuracy_score(validation.label, model.predict(validation[["signal"]])))
    assert accuracy >= 0.9
    requirements = [
        f"{name}=={importlib.metadata.version(name)}"
        for name in ("scikit-learn", "numpy", "pandas", "cloudpickle", "skops")
    ]
    created = client.create_run(experiment)
    with mlflow.start_run(run_id=created.info.run_id) as run:
        mlflow.log_params(
            {
                "feature_contract": contract_digest(CONTRACT),
                "training_rows": len(train),
                "validation_rows": len(validation),
            }
        )
        mlflow.log_metric("validation_accuracy", accuracy)
        mlflow.set_tag("source_sha256", hashlib.sha256(Path(__file__).read_bytes()).hexdigest())
        info = mlflow.sklearn.log_model(
            sk_model=model,
            name="candidate",
            input_example=train[["signal"]].iloc[:2],
            signature=infer_signature(train[["signal"]], model.predict(train[["signal"]])),
            pip_requirements=requirements,
        )
        registered = mlflow.register_model(info.model_uri, MODEL_NAME, await_registration_for=10)
        run_id = run.info.run_id
    loaded = mlflow.sklearn.load_model(info.model_uri)
    assert (
        loaded.predict(validation[["signal"]]).tolist()
        == model.predict(validation[["signal"]]).tolist()
    )
    client.set_registered_model_alias(MODEL_NAME, "accepted", str(registered.version))
    selected = client.get_model_version_by_alias(MODEL_NAME, "accepted")
    assert selected.run_id == run_id
    return (
        client,
        loaded,
        {
            "run_id": run_id,
            "model_version": str(registered.version),
            "validation_accuracy": accuracy,
            "training_rows": len(train),
            "validation_rows": len(validation),
            "feature_contract": contract_digest(CONTRACT),
        },
    )


class ScoringRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    account_id: int = InputField(ge=0)
    feature_contract: str
    expected_model: str


def application(store, model, card):
    app = FastAPI(docs_url=None, redoc_url=None, openapi_url=None)

    @app.post("/predict")
    def predict(request: ScoringRequest):
        if (
            request.feature_contract != card["feature_contract"]
            or request.expected_model != card["model_version"]
        ):
            raise HTTPException(409, "Requested feature/model contract is not accepted")
        result = store.get_online_features(
            features=["serving_signal:signal"], entity_rows=[{"account_id": request.account_id}]
        ).to_dict()
        value = result["signal"][0]
        if value is None:
            raise HTTPException(404, "No accepted online feature exists for this account")
        probability = float(model.predict_proba(pd.DataFrame({"signal": [float(value)]}))[0, 1])
        return {
            "account_id": request.account_id,
            "signal": float(value),
            "probability": probability,
            "model_version": card["model_version"],
        }

    return app


def example_one():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        store, rows = feature_store(root)
        try:
            _, model, card = train_register_reload(root, rows)
            with TestClient(application(store, model, card)) as client:
                responses = [
                    client.post(
                        "/predict",
                        json={
                            "account_id": identity,
                            "feature_contract": card["feature_contract"],
                            "expected_model": card["model_version"],
                        },
                    )
                    for identity in [0, 20, 39]
                ]
            assert all(response.status_code == 200 for response in responses)
            predictions = [response.json() for response in responses]
            assert [row["signal"] for row in predictions] == [0.0, 0.25, 19.25]
            assert predictions[0]["probability"] < 0.5 < predictions[-1]["probability"]
            return {
                "model_card": card,
                "predictions": predictions,
                "historical_rows_preserved": 40,
                "future_known_correction_excluded": True,
                "actual_online_store": "local SQLite",
            }
        finally:
            store.teardown()


def example_two():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        store, rows = feature_store(root)
        try:
            registry, model, card = train_register_reload(root, rows)
            baseline = {
                "account_id": 20,
                "feature_contract": card["feature_contract"],
                "expected_model": card["model_version"],
            }
            with TestClient(application(store, model, card)) as client:
                wrong_feature = client.post(
                    "/predict",
                    json={
                        **baseline,
                        "feature_contract": contract_digest({**CONTRACT, "unit": "kilograms"}),
                    },
                )
                wrong_model = client.post(
                    "/predict", json={**baseline, "expected_model": "unavailable"}
                )
                unknown = client.post("/predict", json={**baseline, "account_id": 999})
                valid = client.post("/predict", json=baseline)
            assert [
                wrong_feature.status_code,
                wrong_model.status_code,
                unknown.status_code,
                valid.status_code,
            ] == [409, 409, 404, 200]
            selected = registry.get_model_version_by_alias(MODEL_NAME, "accepted")
            assert str(selected.version) == card["model_version"]
            return {
                "rejected_feature_and_model_statuses": [409, 409],
                "unknown_entity_status": 404,
                "retained_registry_version": str(selected.version),
                "valid_request_status": 200,
                "persistent_network_service_requires_the_owned_project": True,
            }
        finally:
            store.teardown()


def main():
    from ds60sqlpy.plot_artifacts import publish_report, publish_table

    first, second = example_one(), example_two()
    print("Actual local feature/training/registry/inference workflow:", first)
    print("Contract rejection preserves the accepted model:", second)
    publish_table(
        ["account_id", "signal", "probability", "model_version"],
        [
            [row[key] for key in ["account_id", "signal", "probability", "model_version"]]
            for row in first["predictions"]
        ],
        description=(
            "Actual Feast SQLite online features feed the reloaded MLflow "
            "sklearn model through ASGI for three synthetic accounts."
        ),
    )
    publish_report(
        {"model_card": first["model_card"], "rejections": second},
        description=(
            "A real local MLflow model card and observed feature/model "
            "contract failures; no external service was deployed."
        ),
    )


if __name__ == "__main__":
    main()
```

## Interpret the stored evidence correctly

The model artifact records dependencies needed for its fitted sklearn pipeline. The full serving stack also requires Feast, FastAPI and the prepared runtime configuration, which belong to the image and project environment. A model requirements file alone does not reproduce the entire service. Preserve source, data and feature definitions, model identity, runtime locks and activation decisions together.

The logged model signature describes its native prediction interface; the HTTP route has a separate probability-response contract. Do not assume one metadata object fully specifies every consumer-facing behavior. A deployed service should document which method is called, which class probability is returned and which threshold, if any, converts that probability into a decision.

The online snapshot is fixed for this demonstration. A real system needs a refresh cadence, freshness checks, handling of unknown entities and a policy for corrections. Materialization success does not prove every requested entity has a usable current feature. Preserve coverage and validate the actual values consumed by inference, particularly when offline and online stores use different data paths.

## Failure diagnosis and answered interview discussion

If account zero becomes 99 in historical training, inspect the known-time cutoff. If historical values are correct but online values differ, inspect the accepted materialization source and selected feature view. If loaded-model predictions differ from the original, inspect serialization, dependency versions and feature order. If requests fail only for new entities, inspect feature coverage before blaming the classifier.

If an experiment is registered but not accepted, inspect the evaluation gate rather than treating registry existence as approval. If a request names an unavailable model, return a clear compatibility failure or apply an explicitly documented routing policy. Silently selecting another version makes reproducibility and incident investigation harder.

An interviewer may ask, “What does a feature store solve, and what remains your responsibility?” Explain retrieval and serving mechanisms alongside time semantics, quality, coverage and publication policy. If asked how to prove train/serve consistency, compare exact feature definitions and values as well as model bytes. If asked whether this local run proves production readiness, identify the separate persistent-service, network, load, recovery and operational gates.
