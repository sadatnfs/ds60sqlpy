# dbt-018: Local packages and reusable project dependencies

## Level and prerequisites

Advanced. Direct prerequisites: `dbt-007`

**Outcome:** Prepare and inspect a real reusable dbt dependency with an explicit source boundary.

## Question and mechanism

A dbt package is another project that contributes resources such as macros or models. Declaring a package and preparing it are separate steps. A model can reference a package namespace only after the dependency is available under the project's configured package installation location. This is a project dependency boundary, not a reason to download arbitrary code during a learner run.

The example uses a local package created inside the owned temporary project. Its macro adds one to a supplied SQL expression. The deps command prepares that local dependency and writes a lock artifact; the subsequent build resolves the namespace and executes the emitted SQL in DuckDB. No registry or network request is needed.

A package name or lockfile is not a trust certificate. Review source, license, versions and transitive requirements before adopting an external package. A local path dependency can change without an external release number, so a reproducible project also needs its source identity. Keep authored local packages separate from generated installation directories and never treat copied build output as the maintained source.

## Syntax and data contract

packages.yml declares a local package path. The package has its own dbt_project.yml, name and macros directory. A namespace-qualified call such as classroom_utils.add_one identifies the package that supplies the macro. Run deps before compile/build, then inspect package-lock.yml and the manifest macro entry. Local dependencies are the only package preparation performed in these offline examples.

## Run the lesson

Open this subject in `/classroom`, then show its code and notes. The prepared `data-engineering` worker runs `main.py` in a fresh temporary directory. The examples use installed packages and synthetic local fixtures; no account, cloud service, network request or package download is required. Save source and notes before switching lessons. Temporary databases, project files and tracking artifacts are recreated by each complete program and removed after the job. The classroom retains the submitted source and bounded output, not an indefinitely running external service. The guide distinguishes this local execution from the deployment decisions that need an owned production environment.



## Worked case 1: Use a prepared local package

The first case writes a real local package and prepares it with dbt deps. Its macro appears in the manifest, the lock artifact exists, and the resulting model returns 42. Each observation comes from the actual toolchain.

**Expected evidence:** The macro is registered, the lockfile is written and the model returns 42.

```python
import json
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def package_project(directory):
    p = project(
        directory, models={"answer": "select {{ classroom_utils.add_one('41') }} as answer"}
    )
    local = p / "local_packages/classroom_utils"
    (local / "macros").mkdir(parents=True)
    (local / "dbt_project.yml").write_text(
        "name: classroom_utils\nversion: '1.0'\nconfig-version: 2\nmacro-paths: [macros]\n"
    )
    (local / "macros/add_one.sql").write_text(
        "{% macro add_one(value) %} (({{ value }}) + 1) {% endmacro %}"
    )
    (p / "packages.yml").write_text("packages:\n  - local: local_packages/classroom_utils\n")
    return p


def example_one():
    with tempfile.TemporaryDirectory() as d:
        p = package_project(d)
        invoke(p, "deps")
        invoke(p, "build")
        assert rows(p, "select answer from answer") == [(42,)]
        assert (p / "package-lock.yml").exists()
        assert "macro.classroom_utils.add_one" in artifact(p, "manifest.json")["macros"]
        return {"local_package_used": True, "answer": 42, "lock_written": True}


if __name__ == "__main__":
    print(example_one())
```

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Inspect package identity

Find the package name and macro namespace.

**Check:** They identify classroom_utils and add_one.

**Hint:** Project names determine namespaces.


### 2. Change package logic

Change the local macro to add 2 and rebuild.

**Check:** The output becomes 43.

**Hint:** The dependency source changed.


### 3. Read the lock artifact

Inspect package-lock.yml after deps.

**Check:** The prepared dependency is recorded.

**Hint:** A lock supports reproducibility only for its declared semantics.


### 4. Keep generated paths separate

Identify the authored local package and installed package directory.

**Check:** Their maintenance roles differ.

**Hint:** Do not edit a generated copy as the source.


### 5. Review an external package

List evidence needed before adding a registry dependency.

**Check:** It includes source, version, license and required capabilities.

**Hint:** A package can execute templating logic during compilation.


### 6. Test namespace failure

Use an incorrect package namespace and observe compilation.

**Check:** The undefined macro is rejected.

**Hint:** Check discovery before changing SQL arithmetic.


## Diagnose errors and misleading results

An undefined package macro can result from missing preparation, a wrong package name or an unavailable resource. Check the dependency declaration, installed paths and manifest before modifying the consumer's SQL. Do not solve a local preparation problem by enabling unrelated network access inside the classroom.

## Transfer to independent work

Prepare and inspect a real reusable dbt dependency with an explicit source boundary. Demonstrate its missing-dependency failure and a reviewed source change. Extend the same discipline to external packages only in a deliberately prepared project with suitable version and trust controls.
