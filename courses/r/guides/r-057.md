## Outcome and mechanism

Construct and inspect a small Plotly figure whose trace data and layout correspond to a declared analytical view.

A Plotly figure contains data traces and layout instructions. A trace describes a set of marks with a type, coordinates and styling. Layout describes axes, titles, legends and other figure-level choices. Keeping these responsibilities separate makes the serialized figure inspectable rather than treating an interactive chart as an opaque object.

A scatter trace can draw markers, lines or both. Lines connect supplied coordinates according to their order; they do not infer a meaningful temporal or scientific sequence automatically. A reference line should be labeled as a model, rule or comparison rather than being visually indistinguishable from observed measurements.

In the R interface, plot_ly constructs a figure and add_trace or convenience functions add traces. Formula mappings such as ~x refer to columns in the supplied data. plotly_build resolves the object into trace and layout structures that can be checked numerically. A bar trace uses the supplied heights; it is not automatically a grouped statistical count of arbitrary raw records.

Scripts should call print(p) explicitly. The classroom captures that printed Plotly specification and renders it through its offline figure path. Bare construction of p is not a rendered result. Conversely, a correct captured specification is not proof that hover, zoom, clipping or keyboard behavior worked in a browser.

All data in these examples is inline and synthetic. The figures do not use an external tile service, remote dataset, account or live application server. The small trace grammar is useful before adding interaction because it makes the values, category identity and coordinate order independently checkable.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Trace | A figure component describing one set of marks and its data attributes. |
| Layout | Figure-level settings such as axes, titles and legends. |
| Scatter mode | The choice to display markers, lines or both for a scatter trace. |
| Figure specification | The serializable data and layout consumed by the chart renderer. |

## Read the syntax

Use plotly::plot_ly(data,x=~x,y=~y,type="scatter",mode="markers") for explicit points, then add_lines for a separately named rule. Apply layout for axis titles. Inspect plotly_build(p)$x$data and its layout, then print(p) to emit the widget through the classroom capture path.

## Worked examples

### Example 1: Observed points and a labeled rule

```r
d <- data.frame(x = 1:3, observed = c(2, 4, 3), rule = c(2, 4, 6))
p <- plotly::plot_ly(d, x = ~x, y = ~observed, type = "scatter", mode = "markers", name = "Observed")
p <- plotly::add_lines(p, y = ~rule, name = "Rule: 2x")
p <- plotly::layout(p, xaxis = list(title = "Input"), yaxis = list(title = "Response"), title = "Observations and an explicit comparison rule")
built <- plotly::plotly_build(p)
stopifnot(length(built$x$data) == 2)
stopifnot(max(abs(as.numeric(built$x$data[[1]]$y) - c(2, 4, 3))) < 1e-12)
stopifnot(max(abs(as.numeric(built$x$data[[2]]$y) - c(2, 4, 6))) < 1e-12)
print(p)
```

**Expected observation:** Two traces with observed 2/4/3 and rule2/4/6 values.

Two trace names distinguish observations from the authored rule. The checks inspect the exact y values in both traces before the object is printed.

### Example 2: Bars represent supplied summaries

```r
d <- data.frame(category = c("A", "B", "C"), count = c(2, 1, 3))
p <- plotly::plot_ly(d, x = ~category, y = ~count, type = "bar", name = "Observation count")
p <- plotly::layout(p, xaxis = list(type = "category", title = "Category"), yaxis = list(title = "Count", rangemode = "tozero"))
built <- plotly::plotly_build(p)$x$data[[1]]
stopifnot(identical(as.character(built$x), d$category), identical(as.numeric(built$y), d$count))
print(p)
```

**Expected observation:** Three bars with named categories and supplied heights2/1/3.

The input is already a count table. Plotly draws those values; the analysis that produced the counts remains a separate responsibility.
