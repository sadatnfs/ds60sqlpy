# js-058: Zoom, pan and rescaled axes

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-057`.

## Learning objectives

Implement zoom and pan that rescale axes from the transform and restore the original view on reset. The central exercise is: Implement linked mark and axis zooming.

## Purpose, vocabulary and mental model

Zoom changes the mapping between data space and the visible viewport. A transform typically contains a scale factor and translation. Panning changes which portion of the data is visible; it does not change the underlying observations. Keep the original scale and data separate from the transformed view.

Simply scaling an SVG group can also enlarge text and marker sizes, which may or may not be intended. Rescaling an axis from the zoom transform can preserve readable labels while changing the displayed data domain. Clipping keeps marks within the intended plot region.

A usable zoom interface needs bounds and a reset. Pointer gestures can conflict with page scrolling, so test the actual browser behavior. Keyboard controls or preset views provide an alternative to wheel and drag gestures. Never use zoom to conceal a misleading initial domain.

### Key terms

- **Zoom transform:** The object from a `d3.zoom` event holding a scale factor `k` and translation `x` and `y` between the base view and the current viewport.
- **rescaleX:** The method `transform.rescaleX(baseScale)`, which returns a copy of the base scale whose domain matches the visible region while the base scale stays unchanged.
- **Viewport:** The visible part of the data space inside the plot area, usually bounded with a clip path so panned marks do not cover the axes.
- **Scale extent:** The `zoom.scaleExtent([min, max])` limit on how far a user can zoom out or in.
- **Reset:** Returning the zoom to `d3.zoomIdentity` so the view matches the original base scale again.

## Syntax anatomy and mechanism

`event.transform.rescaleX(baseScale)` creates a scale for the transformed horizontal view. Use that same scale for marks and axis ticks. The base scale remains unchanged so reset has a stable reference.

Set explicit extent and scaleExtent for predictable behavior. The reference applies a known transform programmatically, checks the visible domain narrows and then resets. This establishes the transformation logic; manual interaction acceptance still includes pointer and keyboard behavior.

## Worked example / walkthrough

### Worked example 1: Inspect a known transform

A transform modifies visual coordinates.

```javascript
const t = d3.zoomIdentity.translate(-100, 0).scale(2);
console.log(t.applyX(100));
```

**Expected observation:** 100 because scale and translation combine as 2*100-100.

### Worked example 2: Derive an axis from the view

The zoom transform rescales a copy of the base scale; the original remains available for reset.

```javascript
// js-058 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Zoom, pan and rescaled axes")
  .style("width", "100%")
  .style("max-width", "640px");
const base = d3.scaleLinear().domain([0, 10]).range([0, 600]);
const transform = d3.zoomIdentity.translate(-300, 0).scale(2);
const view = transform.rescaleX(base);
svg.append("g").attr("transform", "translate(20,300)").call(d3.axisBottom(view).ticks(5));
svg
  .append("circle")
  .attr("cx", 20 + view(5))
  .attr("cy", 200)
  .attr("r", 8)
  .attr("fill", "#dc2626");
check(view.domain().join(",") === "2.5,7.5", "The zoomed view shows 2.5 to 7.5");
check(base.domain().join(",") === "0,10", "The base scale is unchanged for reset");
output.textContent = "js-058 worked example 2 complete";
```

**Expected observation:** An axis whose ticks run from 2.5 to 7.5, with the mark for 5 at its center, while the base scale still spans 0 to 10.

## Debugging and common mistakes

If labels grow when zooming, the code is transforming the whole group, which scales text along with geometry. Derive a view scale with `event.transform.rescaleX(x)` instead and redraw marks and axis from it. Check that the base scale's domain is unchanged and that reset applies `d3.zoomIdentity` to restore the original domain. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose enlarged labels after scaling the whole group. Distinguishing evidence: Geometry and text were transformed together.

## Accessibility and interpretation

Wheel and drag gestures are not available to every user, so add native buttons for zoom in, zoom out and reset that call `zoom.transform`. State the visible domain in text, such as "Showing 2.5 to 7.5 of 0 to 10", so readers know part of the data is off screen. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Zooming changes what is visible, not what is true, but a narrow window can make noise look like a trend. Keep the full extent available, show the current domain on the axis, and bound zooming with `scaleExtent` and `translateExtent` so readers cannot drift into empty regions without noticing. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
