## The question and the mechanism

Separate a full-period comparison from an as-of comparison and explain the sign change.

A growth calculation needs comparable populations in time. Comparing a partial current month with a complete prior month can produce a misleading decline even when the formula is syntactically valid. The date set, availability watermark and seasonal calendar policy should be written before calculating a percentage.

Full January 2025 revenue is 67 and January 2024 is 64, giving growth 3/64. Through January 3, 2025 the current amount is 47, while the corresponding prior-year dates contain 64, giving-17/64. These signs differ because the included current facts differ. The prior fixture happens to have no later January sales, so its partial and full totals coincide; that coincidence must not become a rule in the model.

SAMEPERIODLASTYEAR shifts a date set, not a business guarantee about equivalent working days or leap-day treatment. Other comparisons may require fiscal periods, week definitions or a comparable-day policy. Preserve a date-level reconciliation and label an as-of result rather than letting a report title imply completed months.

## Vocabulary and expression anatomy

The first case filters a complete January month. The second uses DATESBETWEEN to define an explicit January 1-through 3 interval. Prior revenue is reevaluated over SAMEPERIODLASTYEAR of the selected dates. DIVIDE expresses relative change against the prior amount and preserves an undefined comparison when that denominator is unavailable.

Concepts to explain in your own words: **SAMEPERIODLASTYEAR**, **year-over-year**, **period completeness**, **comparison denominator**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Completed January versus completed January

**Starting context:** Full January 2025 versus the shifted January 2024 date set; both periods are within available data.

```dax
EVALUATE CALCULATETABLE ( VAR CurrentRevenue = [NetRevenue] VAR PriorRevenue = CALCULATE ( [NetRevenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) ) RETURN ROW ( "Current", CurrentRevenue, "Prior", PriorRevenue, "Growth", DIVIDE ( CurrentRevenue - PriorRevenue, PriorRevenue ) ), 'Date'[Year] = 2025, 'Date'[MonthNumber] = 1 )
```

**Context trace:**

1. Current January contains S4,S5,S6, totaling 67.
2. Prior January contains S1,S2,S3, totaling 64.
3. The difference 3 divided by prior 64 is 0.046875.

**Hand-derived worked-reference result:**

| Current | Prior | Growth |
| --- | --- | --- |
| 67 | 64 | 0.046875 |

That is approximately 4.69 percent growth for this defined monthly population, not a universal growth rate across every date role.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: An explicit as-of comparison

**Starting context:** January 1..3,2025 compared with January 1..3,2024; explicitly as-of rather than full-month.

```dax
EVALUATE CALCULATETABLE ( VAR CurrentRevenue = [NetRevenue] VAR PriorRevenue = CALCULATE ( [NetRevenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) ) RETURN ROW ( "Current", CurrentRevenue, "Prior", PriorRevenue, "Growth", DIVIDE ( CurrentRevenue - PriorRevenue, PriorRevenue ) ), DATESBETWEEN ( 'Date'[Date], DATE ( 2025, 1, 1 ), DATE ( 2025, 1, 3 ) ) )
```

**Context trace:**

1. The current interval excludes S6 on January 5, leaving 47.
2. The prior interval still contains all three prior-year fixture lines, totaling 64.
3. The difference-17 divided by 64 is-0.265625.

**Hand-derived worked-reference result:**

| Current | Prior | Growth |
| --- | --- | --- |
| 47 | 64 | -0.265625 |

The changed result is explained by the period definition. Do not repair it by choosing the more attractive percentage.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Include S6 on the fifth day.
2. It belongs to the full-month case but not the January 1..3 comparison.
3. Include the date interval and the comparable prior interval.
4. The analysis definition must precede the observed result.
5. An absolute difference can exist without a defined relative growth rate.
6. Cohorts can have unequal follow-up opportunity.
