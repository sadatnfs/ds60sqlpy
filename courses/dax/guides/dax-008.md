## The question and the mechanism

Explain coercion and choose a deliberate missing-value display policy.

BLANK is a semantic value in DAX, not the word blank and not a universal synonym for zero. It can describe an absent measure result, an empty aggregation, a missing value or an unknown relationship member. Those causes have different business meanings even when a visual hides them in the same way. Preserve the reason in your model and notes before deciding how to display the result.

Ordinary equality can coerce BLANK to a value such as zero in a numeric comparison. Strict equality with == distinguishes BLANK from zero. Arithmetic also depends on the operator: adding five to BLANK yields five, while multiplying it by five preserves BLANK. Therefore a single remembered rule such as 'blank always acts as zero' is unsafe.

The unsold Bag product gives a concrete empty-population case. Its Product row exists, but no Sales row survives its key filter. SUM(Sales[NetAmount]) is BLANK. Showing zero may be useful for a complete catalog, but COALESCE is a presentation or business-policy decision, not evidence that a transaction of zero occurred. The distinction becomes essential in retention and incomplete-period analysis.

## Vocabulary and expression anatomy

ISBLANK directly tests the value. The two equality operators answer different questions under coercion. COALESCE chooses the first nonblank argument. COUNTROWS over an empty table returns BLANK, while COUNTROWS over the visible Bag dimension returns one. The row and the absence of matching events are separate facts.

Concepts to explain in your own words: **BLANK**, **ISBLANK**, **strict equality**, **COALESCE**, **empty population**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Blank coercion is operator-specific

**Starting context:** Literal BLANK operations; no model context.

```dax
EVALUATE ROW ( "LooseZero", BLANK() = 0, "StrictZero", BLANK() == 0, "PlusFive", BLANK() + 5, "TimesFive", BLANK() * 5 )
```

**Context trace:**

1. Ordinary numeric equality coerces BLANK for the comparison with zero.
2. Strict equality does not identify BLANK with numeric zero.
3. Addition and multiplication have different blank behavior: 5 versus BLANK.

**Hand-derived worked-reference result:**

| LooseZero | StrictZero | PlusFive | TimesFive |
| --- | --- | --- | --- |
| TRUE | FALSE | 5 | BLANK |

A predicate written with = 0 may include missing results that the author intended to exclude. Test the intended missingness condition explicitly.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: An existing product with no sales

**Starting context:** ProductKey 4, Bag; no matching Sales rows.

```dax
EVALUATE CALCULATETABLE ( ROW ( "Products", COUNTROWS ( Product ), "SalesRows", COUNTROWS ( Sales ), "Revenue", [NetRevenue], "DisplayRevenue", COALESCE ( [NetRevenue], 0 ) ), Product[ProductKey] = 4 )
```

**Context trace:**

1. One dimension member remains.
2. The related fact table is empty, so COUNTROWS and SUM return BLANK.
3. COALESCE deliberately displays zero while the original measure remains blank.

**Hand-derived worked-reference result:**

| Products | SalesRows | Revenue | DisplayRevenue |
| --- | --- | --- | --- |
| 1 | BLANK | BLANK | 0 |

A zero-filled display can be appropriate if unsold products are in scope. Retain a separate eligibility or availability signal when zero could otherwise mean an observed failure.
