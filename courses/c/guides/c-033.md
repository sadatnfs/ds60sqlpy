# c-033: Flexible array members and single-allocation records

## Purpose and mental model

A flexible array member lets a struct end with a variable-sized trailing region. It must be the final member and does not contribute ordinary array elements to sizeof the base struct. Allocate enough storage for both the header and payload, with overflow checks before addition and multiplication. Keeping related data in one allocation can simplify ownership and improve locality, but every accessor must still respect the recorded payload length. Copying only sizeof the header does not clone the trailing payload. C struct assignment and generic serialization need special care for this layout.

## Vocabulary and concepts

- **Flexible array member:** A final struct array member whose storage is supplied by a larger allocation.
- **Header size:** The fixed storage occupied by the struct before its variable payload.
- **Contiguous ownership:** One allocation containing metadata and related data.

## Syntax anatomy and execution trace

struct Packet { size_t length; unsigned char data[]; } declares a flexible member. Allocate sizeof(struct Packet)+length bytes after proving length<=SIZE_MAX-sizeof(struct Packet). The member may have alignment-related placement details, so access it through the declared member rather than guessing an offset. One free releases the entire owned record. This fixture stores bytes, avoiding additional element-alignment arithmetic.

## Worked example / walkthrough

### Worked example 1: Create a trailing payload

Create a packet containing bytes 1, 2, 3.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Packet {
  size_t length;
  unsigned char data[];
};
struct Packet *packet_create(const unsigned char *data, size_t length) {
  if (length > SIZE_MAX - sizeof(struct Packet) || (length > 0 && data == NULL))
    return NULL;
  struct Packet *p = malloc(sizeof *p + length);
  if (p == NULL)
    return NULL;
  p->length = length;
  if (length > 0)
    memcpy(p->data, data, length);
  return p;
}

int main(void) {
  /* Create a trailing payload */
  {
    unsigned char data[] = {1, 2, 3};
    struct Packet *p = packet_create(data, 3);
    CHECK(p != NULL && p->length == 3 && p->data[0] == 1 && p->data[2] == 3);
    free(p);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Length and all three bytes are retained.

One owner releases header and payload together.

**Observe:** The header exists and records zero length.

The helper avoids calling memcpy on absent payload pointers when no bytes are requested.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
