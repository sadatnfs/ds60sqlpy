# mle-008: One fitted transformation for training and serving

## Level and prerequisites

Intermediate. Direct prerequisites: `mle-004`, `mle-005`

**Outcome:** Package and use a single fitted preprocessing/model interface.

## Question and mechanism

A model's effective input includes its preprocessing. Imputation values, scaling parameters, category encodings and feature order are part of the fitted state. Reimplementing those operations separately for serving can change predictions even when the classifier coefficients are unchanged. A coherent bundle should use the same fitted transformation at both boundaries.

The first case fits a scikit-learn Pipeline on the eligible training data. It compares batch predictions with predictions from individual request records. The equality check is about transformation and inference consistency on the fixture; it does not prove the model generalizes or that an external service is reliable.

The second case shows why preprocessing must respect the training boundary. A scaler fitted on values 0 and 2 transforms a held-out value 100 very differently from a scaler that includes 100 in its fitting population. Including held-out information changes the representation before the model even sees it. This is leakage even though the preprocessing step does not use target labels.

## Syntax and data contract

The Pipeline contains a ColumnTransformer with numeric imputation/scaling and categorical encoding, followed by logistic regression. fit learns state from training rows; predict_proba applies that state. Construct serving inputs with the declared fields and preserve their meaning. A separate StandardScaler example makes the fitting-population difference visible numerically.

## Worked case 1: Verify batch and request parity

The model predicts two held-out rows both as a batch and as individual dictionaries converted back into frames. Their probabilities must agree within a stated numerical tolerance. This tests the actual fitted pipeline.

**Expected evidence:** Single-request and batch probabilities match and remain between 0 and 1.

```python
import numpy as np
import pandas as pd


def dataset():
    rng = np.random.default_rng(17)
    n = 120
    usage = rng.uniform(1, 100, n)
    tickets = rng.poisson(2, n)
    region = np.where(np.arange(n) % 2 == 0, "north", "south")
    logit = 0.9 * tickets - 0.035 * usage + (region == "north") * 0.3
    probability = 1 / (1 + np.exp(-logit))
    label = (rng.random(n) < probability).astype(int)
    cutoff = np.arange(n) + 100
    return pd.DataFrame(
        {
            "id": np.arange(n),
            "customer_id": np.arange(n) % 12,
            "cutoff": cutoff,
            "available_at": cutoff - 2,
            "label_available_at": cutoff + 4,
            "usage": usage,
            "tickets": tickets,
            "region": region,
            "label": label,
        }
    )


def fit_pipeline(frame):
    from sklearn.compose import ColumnTransformer
    from sklearn.impute import SimpleImputer
    from sklearn.linear_model import LogisticRegression
    from sklearn.pipeline import Pipeline
    from sklearn.preprocessing import OneHotEncoder, StandardScaler

    numeric = Pipeline([("impute", SimpleImputer(strategy="median")), ("scale", StandardScaler())])
    transform = ColumnTransformer(
        [
            ("numeric", numeric, ["usage", "tickets"]),
            ("region", OneHotEncoder(handle_unknown="ignore", sparse_output=False), ["region"]),
        ]
    )
    model = Pipeline(
        [("features", transform), ("classifier", LogisticRegression(max_iter=200, random_state=17))]
    )
    model.fit(frame[["usage", "tickets", "region"]], frame["label"])
    return model


def example_one():
    frame = dataset()
    train = frame[frame.label_available_at <= 180]
    sample = frame.iloc[[90, 91]]
    model = fit_pipeline(train)
    batch = model.predict_proba(sample[["usage", "tickets", "region"]])[:, 1]
    online = np.array(
        [
            model.predict_proba(pd.DataFrame([r]))[0, 1]
            for r in sample[["usage", "tickets", "region"]].to_dict("records")
        ]
    )
    assert np.allclose(batch, online, atol=1e-12)
    assert np.all((batch >= 0) & (batch <= 1))
    return {"batch_probabilities": batch.tolist(), "single_request_parity": True}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Expose preprocessing leakage

The second case fits a scaler on the training values and contrasts it with a scaler fitted on training plus the extreme held-out value. Both produce numbers, but only the first follows the declared training boundary.

**Expected evidence:** The proper transformed value is 99; the leaking result differs by more than 90.

```python
import numpy as np


def example_two():
    from sklearn.preprocessing import StandardScaler

    training = np.array([[0.0], [2.0]])
    heldout = np.array([[100.0]])
    fitted = StandardScaler().fit(training)
    correct = fitted.transform(heldout).item()
    leaking = StandardScaler().fit(np.vstack([training, heldout])).transform(heldout).item()
    assert correct == 99.0 and abs(leaking - correct) > 90
    return {
        "training_mean": 1.0,
        "proper_transformed_value": correct,
        "leaking_transformed_value": leaking,
    }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

If batch and serving disagree, inspect field order, units, missingness, category handling and fitted-state versions before changing model weights. If evaluation is suspiciously strong, check whether preprocessing was fitted on held-out or future rows.
