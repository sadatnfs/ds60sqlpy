## Starting point and result

“Fit a model on Spark” can describe two very different operations. You might want one independent model per product, with separate parameter vectors. Or you might want one shared parameter vector fit to all products. This chapter makes the distinction observable before any complicated optimization enters the picture.

The example fits Gaussian means for a two-record group and a six-record group. It computes separate group MLEs, the pooled global MLE, and an unweighted average of group MLEs. All three are sensible numbers, but they answer different questions. You will also change the group sizes to see when two of the formulas happen to coincide.

## Mechanism: the parameter definition comes first

Suppose group \(g\) contains observations \(y_{gi}\), each with known variance \(\sigma^2\). If every group has its own mean \(\mu_g\), the joint objective is

\[
L(\mu_1,\ldots,\mu_G)=
\sum_g\left[\frac{n_g}{2}\log(2\pi\sigma^2)
+\frac{1}{2\sigma^2}\sum_i(y_{gi}-\mu_g)^2\right].
\]

Each \(\mu_g\) appears in only one term, so optimization separates. The fitted value is \(\hat\mu_g=s_g/n_g\), where \(s_g=\sum_i y_{gi}\). Running those independent fits in parallel is legitimate. The output contains \(G\) fitted models.

If the scientific model instead asserts one common mean \(\mu\), differentiation gives

\[
\frac{\partial L}{\partial\mu}
=\frac{n\mu-\sum_gs_g}{\sigma^2},
\qquad
\hat\mu=\frac{\sum_gs_g}{\sum_gn_g}.
\]

The driver can reconstruct that estimate from tiny \((n_g,s_g)\) summaries. It does not need raw rows and does not need to average independent optimizers. The common mean is the count-weighted average of group means when all groups share the same variance. With known unequal variances, precision weighting changes the formula again.

An unweighted average \(G^{-1}\sum_g\hat\mu_g\) estimates an equal-group descriptive average. It is not generally the common-mean MLE under equal row variance. Calling either answer “the distributed average” hides the estimand.

## Worked case 1: unequal groups

Group A has values \(1,3\), so its independent estimate is \(2\). Group B has six values with sum \(60\), so its estimate is \(10\). The pooled estimate is \((4+60)/(2+6)=8\). An unweighted average of the two group estimates is \(6\).

Spark computes a grouped count, sum and mean. The reference then combines only the count and sum fields to obtain the pooled MLE. It checks the estimate against the direct serial mean and evaluates the global squared error at both \(6\) and \(8\). The pooled optimum has the smaller common-mean objective, as the derivative predicts.

This does not say the value \(6\) is “bad” in every context. If the question is the average of the two products' typical outcomes with equal product importance, it can be the intended descriptive quantity. The model and target, not the distributed API, determine the correct weighting.

## Worked case 2: change the amount of data, not the formula

Replicate every B observation twice. The separate A and B means remain \(2\) and \(10\), but the pooled common-mean fit moves toward B because the shared-mean model now contains more B observations. The unweighted average of the separate means stays at \(6\). This changed-data experiment distinguishes the two objectives without any numerical optimizer.

Now compare equal-size groups \(A=(1,3)\) and \(B=(9,11)\). Both the count-weighted combination and the unweighted group average produce \(6\). That agreement is a special case caused by equal \(n_g\), not a proof that averaging fitted parameters is valid generally.

For a nonlinear model, even count weighting of group-specific fitted coefficients usually does not recover the global optimum. The optimization map is nonlinear in the data, different groups can have different feature designs, and a shared parameter enters every term jointly. Carry loss and gradient summaries at the *same* trial parameter if the goal is one shared model.

## Failure diagnosis

A grouped fit with tiny groups may produce an undefined variance or unidentifiable coefficients. Report group count, design rank and convergence diagnostics with every fit. Do not quietly replace a failed group by zeros and then summarize those zeros as estimates.

If results change when the number of executor partitions changes but group membership does not, inspect whether a function fits one model per physical partition rather than one per scientific group. A repartition can mix or split groups. Only explicit complete-group ownership or sufficient-statistic aggregation provides the intended contract.

Group labels are keys, not ordering guarantees. The program sorts the small output before checking it. Production code should write a keyed result table and join it back by validated keys rather than trusting collection order.

## Interview discussion

**Can I average coefficients from models fit on each partition?** Usually no. For the simple shared Gaussian mean, count and sum are sufficient and count-weighted means happen to work. A generic model does not inherit that property. Derive the global score equation or use a justified distributed optimization method.

**What does an independent per-customer fit require?** Each customer's complete relevant data, enough observations and a clearly defined parameter set. Customers can run independently only if the objective has no shared parameters or coupled latent effects.

**Why not collect each group to Python?** You may do so for a bounded small group, but a large or skewed group can exhaust one worker's memory. This particular Gaussian model only needs count and sum; built-in distributed aggregates are a better representation of its mathematics.
