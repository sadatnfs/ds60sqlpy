## Outcome and mechanism

Validate a small ingestion boundary without silently coercing, dropping or repairing invalid records.

An ingestion boundary turns external representations into an analytical table. A successful file read only establishes that the bytes were parsed; it does not establish valid identifiers, ranges, dates or relationships. Separate structural validation from record-level admission. A missing required column can invalidate the entire batch, while an invalid measurement might be quarantined under a documented policy.

Reason codes make rejection auditable. A row with a missing ID and a negative amount may violate more than one rule. Retain all relevant flags or state a deliberate precedence for the reported primary reason. Do not let the arbitrary order of if statements become an undocumented data-quality policy.

Coercion is not repair. Turning a malformed numeric string into NA, then replacing NA with zero, creates a measured value the source never supplied. Preserve the original field and parse status where debugging requires them. A rejection report can retain only the bounded synthetic fields necessary for the lesson; a real system should also apply its privacy and retention policy.

Admission counts should reconcile. Input rows equal admitted plus quarantined rows when the sets are disjoint and exhaustive. That invariant catches accidental loss or duplication. Batch validity is still scoped to the implemented rules: a table can satisfy local range checks and remain biased, stale or scientifically unsuitable. Validation is one layer of evidence, not a guarantee of truth.

## Worked examples

### Example 1: Retain multiple failure flags

```r
raw <- data.frame(id = c("A", "", "C", "D"), amount = c(2, 3, -1, NA_real_))
flags <- data.frame(missing_id = is.na(raw$id) | raw$id == "", invalid_amount = !is.finite(raw$amount) | raw$amount < 0)
admitted <- !flags$missing_id & !flags$invalid_amount
stopifnot(identical(admitted, c(TRUE, FALSE, FALSE, FALSE)))
stopifnot(sum(admitted) + sum(!admitted) == nrow(raw))
print(cbind(raw, flags))
```

**Expected observation:** One admitted row, three rejected rows.

The negative and missing amounts remain distinct original inputs, even though both violate the same finite-nonnegative amount rule.

### Example 2: A structural error rejects the batch

```r
validate_columns <- function(data) {
  required <- c("id", "amount")
  if (!all(required %in% names(data))) stop("missing required columns", call. = FALSE)
  if (!is.character(data$id) || !is.numeric(data$amount)) stop("invalid column types", call. = FALSE)
  TRUE
}
stopifnot(validate_columns(data.frame(id = "A", amount = 2)))
bad <- tryCatch(
  {
    validate_columns(data.frame(id = "A", value = 2)); FALSE
  },
  error = function(e) TRUE
)
stopifnot(bad)
print(bad)
```

**Expected observation:** The malformed batch is rejected.

The validator does not silently rename an unexpected field or guess that value must mean amount. Structural drift gets an explicit failure.
