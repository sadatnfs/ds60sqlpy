# c-012: Const-correct views and mutation boundaries

## Purpose and mental model

const describes permitted access through a type-qualified expression. A pointer to const int prevents modifying the target through that pointer, while a const pointer prevents changing which target the pointer designates. These are different guarantees. A mutable object can be observed through a const view and changed through another valid mutable path. An object originally defined const must not be modified by casting away qualification. Const-correct APIs communicate read-only intent and let callers pass immutable data safely, but they do not automatically provide deep immutability, ownership or synchronization.

## Vocabulary and concepts

- **Const-qualified view:** An access path that forbids mutation through that path.
- **Const pointer:** A pointer object that cannot be reassigned after initialization.
- **Deep immutability:** A policy preventing mutation throughout a reachable object graph.

## Syntax anatomy and execution trace

const int *p reads as a pointer to a const-qualified int. int *const p is a const pointer to a mutable int. const int *const p combines both restrictions. Function parameters can use const for borrowed read-only arrays. A struct containing a pointer can still reference mutable storage even if the outer struct is accessed through a const pointer; deep ownership requires a broader design.

## Worked example / walkthrough

### Worked example 1: Read through a const view

Observe a mutable integer through const int pointer.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int read_sum(const int *values, size_t n) {
  int sum = 0;
  for (size_t i = 0; i < n; i++)
    sum += values[i];
  return sum;
}

int main(void) {
  /* Read through a const view */
  {
    int value = 4;
    const int *view = &value;
    CHECK(*view == 4);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** The read yields 4.

The view is read-only, but the underlying object was not defined const.

### Worked example 2: Observe another valid mutation

Change the mutable object through its original name.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int read_sum(const int *values, size_t n) {
  int sum = 0;
  for (size_t i = 0; i < n; i++)
    sum += values[i];
  return sum;
}

int main(void) {
  /* Read through a const view */
  {
    int value = 4;
    const int *view = &value;
    CHECK(*view == 4);
  }

  /* Observe another valid mutation */
  {
    int value = 4;
    const int *view = &value;
    value = 7;
    CHECK(*view == 7);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** The const view now reads 7.

Const access does not freeze a shared mutable object or create a snapshot.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
