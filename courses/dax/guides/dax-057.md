## The question and the mechanism

Reason about a dynamic region policy, including unmapped identities and policy-table exposure.

Dynamic RLS can derive permitted rows from an identity-to-domain mapping. Our synthetic Access table maps north.learner@example.test to North and south.learner@example.test to South. The Customer role predicate tests whether its Region belongs to the allowed set for USERPRINCIPALNAME. The strings are fictional teaching principals, not actual accounts.

An unmapped identity should have an explicitly defined outcome. The supplied policy uses an empty allowed-region set, so no Customer rows are permitted. Do not replace a missing mapping with unrestricted access or infer permission from an ordinary slicer. Mapping uniqueness, valid region names, identity normalization and assignment governance are part of the design.

Restricting Customer does not automatically protect the Access table itself or every other disconnected fact. A real model needs a review of all exposed tables and supported identity/relationship behavior. The offline reference makes the intended rule inspectable, but actual enforcement requires a separately prepared engine and applicable Viewer-role tests.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

### Case A: A mapped synthetic principal

**Starting context:** Assume the declared dynamic Customer policy is enforced for north.learner@example.test in a role-restricted Viewer context.

```dax
EVALUATE ROW ( "VisibleCustomers", COUNTROWS ( Customer ), "VisibleRevenue", [NetRevenue] )
```

**Context trace:**

1. The Access mapping supplies North.
2. Customer 10 and 30 are allowed.
3. Their revenues 51 and 56 total 107.

**Hand-derived worked-reference result:**

| VisibleCustomers | VisibleRevenue |
| --- | --- |
| 2 | 107 |

The identity string selects an expected mapping in this teaching specification. No external account was authenticated and no role-test result is being claimed.

Hand-derived expectation for a fictional principal and declared dynamic policy; not live security evidence.

### Case B: An unmapped principal is denied by the declared policy

**Starting context:** Assume the same enforced policy for unmapped.learner@example.test; its allowed-region set is empty.

```dax
EVALUATE ROW ( "VisibleCustomers", COUNTROWS ( Customer ), "VisibleRevenue", [NetRevenue], "HasVisibleRows", COUNTROWS ( Customer ) > 0 )
```

**Context trace:**

1. No Access row matches that principal.
2. The policy's allowed Region set is empty and no Customer row qualifies.
3. COUNTROWS and SUM are BLANK on their empty populations; the positive-row comparison is FALSE.

**Hand-derived worked-reference result:**

| VisibleCustomers | VisibleRevenue | HasVisibleRows |
| --- | --- | --- |
| BLANK | BLANK | FALSE |

This is an explicit deny expectation, not a fallback to all regions. Test it under an actual applicable role before relying on a deployed model.

Hand-derived default-deny expectation. No authentication or live RLS enforcement occurred.

## A deeper model or scope review

The following is a role predicate on Customer in the specified external model scope, not a complete query:

```dax
Customer[Region] IN
    SELECTCOLUMNS ( FILTER ( Access, Access[Principal] = USERPRINCIPALNAME() ),
        "AllowedRegion", Access[Region] )
```
