llm-042: Capstone: a defensible language-system decision#

Level and prerequisites#

Advanced; approximately 270 minutes. Direct prerequisites: llm-040. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Recommend a bounded system only when its evidence and operating limits support the intended use. The central investigation is concrete: Compare the tiny transformer, count baseline and a local retrieval variant on frozen questions; deliver reproducible artifacts, trust-boundary tests and a reviewer-facing decision. The finish condition is Acceptance requires lineage/split hashes, paired held-out results, mask/cache tests, latency/token budgets, failure examples and an explicit go/no-go with limitations. A no-go is a valid evidence-based result. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Assemble a decision whose claims can be traced to observations#

A defensible language-system decision connects several kinds of evidence without pretending they are the same. A model can pass a numerical cache check while answering a domain question incorrectly. A saved answer table can have correct arithmetic without proving which model generated the answers. A resource budget can be written in metadata without being enforced by an execution loop. The capstone's purpose is to make those distinctions visible in one review packet.

The reference intentionally combines hand-authored candidate outcome records with a separate real tiny-decoder mechanism probe. It is a decision-report template, not an end-to-end generation experiment comparing trained assistants. Reading the code with this boundary in mind is part of the lesson: every claim should be tied to the artifact or operation that actually produced it.

Freeze the question and answerability contract first#

The three question IDs are q1,q2,q3, with families shape,color,astronomy. The first two are answerable under the fixture's evidence policy, while q3 lacks the needed evidence and should be handled by the declared abstention rule. A correct response to q3 can therefore be an appropriate refusal to answer, not a fabricated fact.

The fixture hash is computed from a stable serialization of these records. It identifies the particular question/answerability table used by the demonstration. The hash does not prove that the labels were independently validated, that the families represent a population, or that the table remained unseen during system development. Those require additional evidence about the study design.

Before a real comparison, freeze the questions, permitted source versions, output contract, correctness and support rubric, and any severe-failure criteria. If the scoring rule changes after seeing a preferred candidate's output, the comparison has changed. Preserve the earlier rule and explain the revision rather than silently rewriting history.

Reconstruct the saved candidate comparison#

The supplied correctness records give the tiny candidate[1,0,0], the count candidate[0,0,0], and the retrieval candidate[1,1,1] over q1,q2,q3. Their totals are 1,0,3 out of three. These are deterministic input records for the bookkeeping exercise. The newly instantiated TinyDecoder does not generate those answers, and the count/retrieval candidates are not run by this capstone to produce the table.

A paired difference can still be calculated correctly from supplied records. Retrieval minus tiny correctness is[0,1,1], with mean 23\frac{2}{3}32​. That arithmetic describes the illustrative table, not an empirical effect established by executing the three systems. A report should use wording such as "the saved fixture records show" rather than "the experiment demonstrated" when no corresponding candidate run occurred.

The distinction is especially important for q3. The report labels the tiny candidate's answer without evidence as a failure. That label is part of the authored review scenario. To establish it in a real study, retain the actual answer, the evidence supplied, the abstention policy and the scoring rationale. A failure message written into a report cannot substitute for the underlying observation.

Identify what the real decoder probe proves#

The code creates a small decoder under a fixed seed, runs tokens[2,5,7] as a complete prefix, then runs the same tokens incrementally with a cache. It compares concatenated incremental logits with the full-prefix logits within a stated tolerance. This is an actual numerical mechanism check on that model and input.

Passing the check supports the claim that the two evaluated execution paths agree for the supplied case. It does not establish that the model knows facts about shapes, colors or astronomy. The model is not trained on the candidate question task here. It also does not prove universal cache correctness across all shapes, versions or malformed states; additional tests would be needed for those domains.

The parameter-count bound and elapsed-time observation answer separate resource questions. A finite measured duration for one CPU call is useful context but not a serving throughput benchmark. The generated_cap=4 field is declared metadata in this record. There is no generation loop in the capstone that emits and limits four answer tokens, so the field must not be described as an enforced runtime cap.

Bind each claim to the right artifact#

A useful evidence table can distinguish four columns: claim, supporting artifact, acceptance rule and limitation. For cache parity, the support is actual full/incremental logits under a fixed model and tolerance. For question identity, it is the serialized fixture and digest. For candidate quality, it should be actual answer artifacts and independent scoring, which this template deliberately does not generate. For an operational budget, it should include the code path that enforces the limit and its observed boundary behavior.

A hash cannot automatically join unrelated experiments. Hashing model parameters beside a saved correctness table does not prove that those parameters produced that table. The relationship needs an execution record binding input, model/configuration, output and scoring. Similarly, a digest of raw parameter bytes under known code is narrower than a complete portable model artifact identity containing names, shapes, dtypes, architecture, tokenizer and relevant versions.

This is a general data-science lesson. A chart can be correctly rendered from an incorrect table, and a narrative can accurately describe numbers that were computed from the wrong dataset. Trace the chain from source data through execution to result and interpretation. Each link needs its own evidence instead of relying on the presence of a final report file.

Apply required gates without collapsing unknown into pass#

The fixture's gate dictionary contains mechanism=True, trust_boundary=True, population_evidence=None and severe_failures_absent=False. Its decision rule accepts only when every required value is exactly True. The result is therefore no-go. None means a required observation is missing or unresolved; False means a declared condition failed. Neither can be replaced by a favorable average score.

The nonmechanism gate values are supplied review inputs in this exercise. They are not automatically inferred by the cache probe. A real decision process would identify who or what checked each condition and retain the corresponding evidence. Exact boolean logic makes the decision reproducible only after the gate inputs themselves have justified meanings.

A no-go should identify the next useful action. Here the report points to the unsupported q3 behavior and missing independent held-out families. Repairing abstention and collecting a fresh frozen evaluation are different tasks: the first changes the system, while the second supplies new evidence about the revised system. Reusing the same known failure as the only final assessment after repeated tuning would leave the generalization question unresolved.

Design the end-to-end study that would fill the template#

A real study would run each candidate on the same permitted question/evidence cases under a frozen policy. It would save actual answers and abstentions, source/version identities, tool results where applicable, token/resource observations and errors. A scorer would evaluate correctness, claim support and required boundaries under the declared rubric. Paired and family-aware summaries would then be computed from those records.

Use development data for choosing prompts, retrieval settings and adaptation parameters. Reserve final families for the decision claim, and report coverage and uncertainty with their denominators. If a severe failure appears, retain it even if other metrics improve. If a runtime is unavailable, record the missing operation rather than filling the table with expected outputs.

The applied assistant capstone provides a more connected local pipeline. The theory capstone supplies the reasoning discipline needed to read its evidence: generated text, retrieved evidence, executed calculations, mechanism checks and decision gates must remain distinguishable.

Carry the evidence discipline into architectural choices#

The final chapters examine encoder/decoder information flow, positional mechanisms, normalization, grouped attention, sparse experts and speculative decoding. Each introduces a different way to change a model or its execution. The same review question will recur: is the claim algebraic, numerical, empirical or operational, and what exactly was tested?

A strong capstone conclusion does not need to say that the system is ready. It needs to explain what the current evidence supports, what failed, what remains unknown and which controlled next experiment would reduce that uncertainty. That is a complete technical result, even when the decision is no-go.

Vocabulary and concepts#

Common evaluation contract: The same questions,units and scoring rules used for every candidate.

Go/no-go: A decision applying declared acceptance gates to observed evidence.

Unknown gate: A required check lacking an execution or review receipt.

Syntax anatomy and reasoning sequence#

Keep result tables keyed by question ID and grouped by family. Compare paired errors, not unaligned averages. A release dictionary records each required gate as True,False or None for unexecuted. Only True satisfies a required gate. Hash the literal fixture and model state, retain exact token budgets, and keep measured latency as an observation rather than a universal performance promise. The cache oracle compares one-token execution with full-prefix output.

The three questions cover shape, color and an astronomy question with missing evidence. The candidate correctness records give the tiny candidate 13\frac{1}{3}31​, count candidate 03\frac{0}{3}30​ and retrieval candidate 33\frac{3}{3}33​, with the last retrieval success meaning correct abstention. These are hand-authored saved decision records used to demonstrate comparison logic. They are not answers newly generated by the model in this program and must not be reported as measured benchmark quality for a trained system.

This is an actual numerical mechanism check with an untrained random model. It establishes neither subject knowledge nor the correctness of the hand-authored answer ledger. A complete decision can honestly be no-go#

The declared generated-token cap is metadata in this record; there is no generation loop here enforcing that cap against a live assistant. A full system would bind the policy to actual inference and preserve the resulting answers, citations, token counts and failure observations. Similarly, hashing raw parameter bytes under a known architecture is useful, but a reusable artifact identity should include names, shapes, dtypes, configuration, tokenizer and version information.

The gate dictionary contains mechanism=True, trust_boundary=True, population_evidence=None and severe_failures_absent=False. The rule accepts only if every required value is exactly True, so the observed result is no-go. The latter three values are supplied review inputs in this teaching exercise, not findings inferred by the decoder test. An unknown required result and a declared failed condition both block the decision.

To turn the template into a real study, freeze the evaluation families and scoring rubric, run each candidate on the same permitted evidence, preserve actual answers, independently score supported claims and abstention, then apply the predeclared gates. The applied assistant capstone develops a more connected local pipeline. Keep the distinction between mechanism execution and answer-quality evidence throughout: a useful review record can explain exactly what failed and what observation is needed next without claiming readiness.

Worked example / walkthrough#

Example A: Freeze common questions#

The task contract is frozen before comparing systems. The unanswerable case tests abstention rather than rewarding a fabricated response.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F


class TinyDecoder(nn.Module):
    def __init__(self, vocab=16, width=32, heads=2, context=32):
        super().__init__()
        self.vocab, self.width, self.heads, self.context = vocab, width, heads, context
        self.token = nn.Embedding(vocab, width)
        self.position = nn.Embedding(context, width)
        self.norm1 = nn.LayerNorm(width)
        self.qkv = nn.Linear(width, 3 * width, bias=False)
        self.projection = nn.Linear(width, width, bias=False)
        self.norm2 = nn.LayerNorm(width)
        self.feed = nn.Sequential(
            nn.Linear(width, 2 * width), nn.ReLU(), nn.Linear(2 * width, width)
        )
        self.output = nn.Linear(width, vocab, bias=False)

    def forward(self, ids, cache=None):
        if ids.ndim != 2 or ids.dtype != torch.long or ids.shape[1] == 0:
            raise ValueError("nonempty long batch,time IDs")
        offset = 0 if cache is None else cache["k"].shape[2]
        batch, time = ids.shape
        if offset + time > self.context or torch.any(ids < 0) or torch.any(ids >= self.vocab):
            raise ValueError("context or vocabulary limit")
        x = self.token(ids) + self.position(torch.arange(offset, offset + time))
        q, k, v = self.qkv(self.norm1(x)).chunk(3, dim=-1)

        def split(t):
            return t.reshape(batch, time, self.heads, self.width // self.heads).transpose(1, 2)

        q, k, v = map(split, (q, k, v))
        if cache is not None:
            if cache["k"].shape[0] != batch:
                raise ValueError("cache batch mismatch")
            k = torch.cat([cache["k"], k], dim=2)
            v = torch.cat([cache["v"], v], dim=2)
        allowed = torch.arange(k.shape[2])[None, :] <= torch.arange(offset, offset + time)[:, None]
        scores = q @ k.transpose(-2, -1) / (self.width // self.heads) ** 0.5
        weights = torch.softmax(scores.masked_fill(~allowed, float("-inf")), dim=-1)
        mixed = (weights @ v).transpose(1, 2).contiguous().reshape(batch, time, self.width)
        x = x + self.projection(mixed)
        x = x + self.feed(self.norm2(x))
        return self.output(x), {"k": k.detach(), "v": v.detach()}

Common pitfalls and diagnosis#

Trace every claim to the artifact that actually produced it. The saved answer ledger and the random decoder parity test are separate experiments. A hash does not join them automatically. Preserve unknown and failed gates, distinguish a declared budget from an enforced generation loop, and require actual candidate answers before reporting system quality.
