## Replace symbolic IDs with trainable feature vectors

A tokenizer gives the model integer IDs, but ordinary arithmetic on those IDs would impose an arbitrary geometry. If cat has ID 10 and dog ID 11, that numbering does not establish that they are one unit apart in meaning. Renumbering the vocabulary would change the arithmetic without changing the text. An embedding layer instead treats an ID as an address: retrieve the vector stored in that vocabulary row.

Let E be an embedding table with V rows and D columns. V is the number of token identities and D is the feature width. For token ID i, the lookup returns row E_i, a D-dimensional vector. A sequence of T IDs produces T such vectors in the same order, giving shape [T,D]. These symbols name different axes: T counts occurrences in this input, V counts possible token identities, and D counts numeric features in each representation. Increasing any one of them has a different memory and modeling effect.

Example A uses four vocabulary rows and two features per row. The input IDs [2,0,2] select [2,2], then [1,0], then [2,2]. The first and third vectors agree because they read the same parameter row, not because the first and third positions have become the same occurrence. They remain separate positions in the sequence. A later contextual operation can transform them differently because their surrounding information or positions differ.

One-hot multiplication expresses the same lookup algebraically. A one-hot vector has V entries, with one at the selected vocabulary coordinate and zero elsewhere. Multiplying it by E sums all rows weighted by those entries, so only the chosen row remains. Stacking one-hot vectors for the sequence reproduces the lookup output. This is useful for deriving gradients and shapes, although materializing a large one-hot matrix is usually wasteful when direct indexing can do the same selection.

During training, repeated occurrences share a parameter row, so their gradient contributions accumulate there. If two uses of ID 2 contribute upstream vectors g_1 and g_3, the row's gradient includes g_1+g_3. The IDs themselves are discrete selectors; we do not differentiate their integer values as though moving from ID 2 to ID 2.1 were a meaningful token change. The table is fixed literal data in this NumPy example, so the lesson demonstrates lookup and storage behavior before later chapters perform actual automatic differentiation.

The negative-index example separates a general array feature from the model's domain contract. NumPy accepts -1 as an address relative to the end of an array. The tokenizer contract here defines valid IDs from zero through V-1, so -1 must be rejected. A language library may legally execute an operation that is invalid for the application. The same principle applies to a tokenizer/model mismatch: two models can share a vocabulary size while assigning different meanings to the same row numbers, producing no shape error at all.

Embeddings are useful because training can organize reusable numeric features under an objective. The lookup itself supplies no guarantee of semantic similarity, knowledge or contextual understanding. It creates the parameterized representation on which attention and other transformations can operate.
