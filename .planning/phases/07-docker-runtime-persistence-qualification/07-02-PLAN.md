## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness to shared Docker engine | The engine also hosts the user's classroom, MCP containers and unrelated containers |
| harness to lab HTTP API | The harness writes learner data and runs SQL through the API |
| harness report to repository workspace | Reports are read later by agents and humans |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06 | Tampering | `down -v` on the wrong project | critical | mitigate | Name regex `^ds60-p7-`, protected-name denylist, preexisting-resource refusal, ownership marker with run_id checked before any `down`; unit tests assert order (Task 1, D-04, D-09) |
| T-07-07 | Denial of service | shared image tags and protected volumes | high | mitigate | p7-only tags, image removal limited to recorded references, before/after protected snapshot fails on change (Task 1, Task 3) |
| T-07-08 | Information disclosure | worker token and learner data in reports | medium | mitigate | Token and progress read inside the container and only sha256 digests leave it; sentinel token stored as a digest (Task 1, Task 2, D-10) |
| T-07-09 | Tampering | SQL sentinel injection | low | mitigate | NAME and TOKEN validated by strict regexes before SQL is built (Task 2) |
| T-07-10 | Elevation of privilege | subprocess execution | low | mitigate | argv lists only, no shell strings; environment from `clean_environment` strips registry and GitHub credentials |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan |
