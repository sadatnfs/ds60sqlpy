llm-044: RoPE, relative positions, ALiBi and long-context limits#

Learning objectives#

Position mechanisms tell attention how token order or distance should influence a comparison. The central investigation is concrete: Rotate[1, 0] by π2\frac{\pi}{2}2π​ and check length preservation. The finish condition is approximately[0, 1]; norm 1. finite vector; long_context_quality_verified=False; odd width rejected. Purpose and mental model#

Give attention a coordinate system that survives incremental execution#

Attention compares vectors, but a language task often depends on where those vectors occur. "A follows B" and "B follows A" can contain the same token identities while expressing different relationships. Positional mechanisms give the computation information about order or distance. They must remain consistent between full-prefix training/evaluation and incremental cached execution, or the model will compute a different function after a cache boundary.

Without positional information and with an all-allowed mask, a shared self-attention operation is permutation-equivariant: permuting input rows permutes the corresponding output rows. If P is a permutation matrix, the score matrix transforms as P S PT{P}^{T}PT and the output as P O under the matching permutation. A fixed causal mask already imposes an ordered access pattern, so the broad slogan "attention knows no order" needs that qualification. The complete information graph, not attention alone, determines which order information is available.

Compare three ways to introduce position#

A learned absolute embedding adds a position-specific vector to each token representation. Its table has an explicit range of trained indices. Sinusoidal or rotary formulas compute position-dependent transformations rather than selecting an arbitrary learned row. Relative score methods add or otherwise encode a relationship between query and key positions. These choices can be combined with different architectures, and each changes the function a checkpoint expects.

RoPE rotates paired query/key coordinates. ALiBi adds a linear distance bias to attention scores. The first changes the geometry of the dot product through position-dependent rotations; the second changes the score after the content comparison. Neither mechanism is interchangeable with a causal mask. A positional preference says how strongly to weight an available key; an access mask says whether the key is available at all.

Frequencies and layout are part of the checkpoint contract#

A head of even width d can be divided into d2\frac{d}{2}2d​ pairs. The fixture uses adjacent pairs and frequencies ωi=base−2i/d\omega_i=\mathrm{base}^{-2i/d}ωi​=base−2i/d. At width 4 and base 10000, the two frequencies are 1 and .01. A position p rotates the first pair by p radians and the second by .01p radians. The slow pair changes phase more gradually across positions.

Another implementation may arrange paired coordinates differently, such as pairing a first half with a second half. Both layouts can represent the same abstract idea, but projection weights and cache coordinates must be translated consistently. Copying weights between layouts without that conversion changes the computation while preserving shapes. Record pairing convention, frequency schedule, base, scaling policy and dtype with the model artifact.

A frequency has a periodic phase. For one pair, positions separated by 2⋅πω\frac{2\cdot \pi}{\omega}ω2⋅π​ have the same ideal rotation, though integer token positions do not generally land exactly on that period. Multiple frequencies create a richer pattern. This does not mean that a trained model is guaranteed to distinguish or use every distant position correctly. The representation formula and learned task behavior remain separate objects of study.

Cache offsets are a state invariant#

If a prefix contains positions 0 and 1, the next key must be encoded at position 2. Encoding it at 0 treats it as a new beginning. Rotating a key twice applies the sum of the rotations and is another different function. A cache must therefore record whether keys are stored before or after positional transformation and which absolute positions they represent.

The full-prefix versus incremental test should hold token IDs, weights, masks and position policy fixed. Compare the appended key with the corresponding row from a full encoding before comparing final logits. If the key already differs, the defect is in state/position handling rather than the softmax or output projection. This staged diagnosis is more efficient than changing several model components at once.

Cache compaction or a sliding window adds another coordinate decision. Dropping old physical entries need not reset the logical absolute position of the remaining tokens. Some models intentionally use a relative or rescaled convention, but that must be the trained computation's contract. A storage index and a semantic position are not automatically the same number.

Read ALiBi as a ratio of unnormalized masses#

For a causal query at i and available key j<=i, an ALiBi-style bias can be-a(i-j) for positive slope a. When content scores are equal and a=log⁡(2)a=\log(2)a=log(2), moving one position farther into the past halves the exponential mass. At query 2, keys 0,1,2 have masses 14\frac{1}{4}41​,12\frac{1}{2}21​,1 and normalized weights 17\frac{1}{7}71​,27\frac{2}{7}72​,47\frac{4}{7}74​. The current key receives the largest weight under this illustrative slope.

A finite recency penalty is not a hard context window. A sufficiently large content score can overcome it. A hard window instead forbids keys outside the chosen range regardless of their content. If future key 3 were accidentally admitted, the same signed-distance formula would give it positive bias log⁡(2)\log(2)log(2), rewarding an unavailable position. The causal mask must remain separate.

Different heads can use different slopes, creating different distance preferences. The single slope in the fixture is chosen for exact arithmetic, not to reproduce every published head-slope schedule. When comparing methods, record the actual policy rather than assuming that the name ALiBi fully specifies every implementation detail.

Distinguish a long index from long-context competence#

A sine/cosine formula may return finite numbers at position one million. That establishes that a particular calculation completed under its dtype and inputs. It does not establish that the model was trained on useful patterns at that range, that nearby positions remain numerically distinct, or that a distant source fact influences the answer correctly.

Position precision can fail before the trigonometric function itself does. A limited-precision floating type eventually cannot represent every consecutive large integer, so two logical positions may be rounded to the same stored value. Frequency multiplication and angle reduction add further numerical considerations. These facts motivate explicit dtype and offset tests, not an automatic conclusion that every long-context use is invalid.

Behavioral evaluation should require information at controlled distances and include distractors, missing evidence and tasks that cannot be solved from the final few tokens alone. Increasing prompt length by adding irrelevant text is not the same as demonstrating reliable long-range use. Changing a rotary base or scaling recipe also changes the model's computation and needs model-specific evidence.

Design decisions and when to use this method#

Use positional mechanisms according to the architecture and its training contract. Learned absolute tables impose an explicit index range unless extended; rotary and bias formulas can be evaluated beyond the training length but still need empirical validation. Compare methods on tasks requiring information at different distances, not merely a longer prompt that can be answered from its final sentence.

Do not claim that changing a RoPE base or applying a scaling recipe preserves quality without a measured model-specific study. Check dtype precision, position offsets, cache layout and masking first. For ALiBi, record the actual per-head slope policy; the single slope here is a hand-checkable fixture rather than a claim to reproduce every paper configuration.

Relative geometry depends on consistent coordinates#

A rotary pair is a two-dimensional subspace. With q=(q_0,q_1), rotation by angle theta gives(q_0 cos theta-q_1 sin theta, q_0 sin theta+q_1 cos theta). Squaring and adding cancels the cross terms, leaving q_0²+q_1². Norm preservation is therefore an exact algebraic property before floating-point rounding. It does not mean that the query-key similarity is unchanged, because the query and key can rotate by different angles.

For q=k=[1,0]q=k=[1,0]q=k=[1,0], their rotated dot product is cos(n-m), where m and n are their respective angles. Equal positions give1; a relative angle π2\frac{\pi}{2}2π​ gives 0; a relative angle pi gives-1. This example makes the distinction clear: each vector keeps unit length while their relative orientation changes. If both positions receive the same offset c and use the same frequency rule, R(m+c)TR(n+c)=R(n−m)R(m+c)^{\mathsf T}R(n+c)=R(n-m)R(m+c)TR(n+c)=R(n−m), so the pairwise score is unchanged. Resetting only the new query's position is not a common shift and breaks that relation.

A width-d head applies this construction in multiple paired subspaces. The fixture uses adjacent pairs(0,1),(2,3),... and ωi=base−2i/d\omega_i=\mathrm{base}^{-2i/d}ωi​=base−2i/d. For d=4d=4d=4 and base 10000, the frequencies 1 and.01 give a rapidly changing first pair and a slower second pair. Another implementation may pair the first half of coordinates with the second half. Both conventions can be mathematically valid, but their projection weights and rotary layout must be converted together. Identical tensor shapes do not establish layout compatibility.

The usual rotary application transforms Q and K before their dot product. It does not automatically transform V or add a new vector to the residual stream. Consequently, a cached key needs to retain the position at which it was rotated. If positions 0,1,2 were processed together, incremental processing of the third key must rotate it at 2. Rotating that new key at 0, or rotating an already rotated cached key again, changes the scores. Compare full-prefix and incremental outputs while holding weights, masks and token IDs fixed to isolate this state error.

ALiBi changes a score by an additive distance penalty. For positive slope a and causal key j<=i, the bias is-a(i-j). With a=log 2, moving a key one position further into the past halves its exponential weight before normalization when content scores are equal. At query 2 the three masses are 14\frac{1}{4}41​,12\frac{1}{2}21​,1, so weights are 17\frac{1}{7}71​,27\frac{2}{7}72​,47\frac{4}{7}74​. If a future key3 were accidentally admitted, the same expression would give a positive log 2 bias and mass2, favoring precisely the unavailable position. A distance bias is therefore not a substitute for a causal access mask.

A recency bias changes relative preference rather than imposing a fixed window. A sufficiently favorable content score can overcome a finite distance penalty. Conversely, a hard sliding window sets older positions to forbidden regardless of their content score. These mechanisms answer different design questions. If a task requires exact retrieval from a distant passage, test distance and distractor effects explicitly instead of assuming that a method's ability to evaluate a long index proves useful access to that passage.

There are at least three different long-context checks. Algebraic validity asks whether rotations and masks obey their formulas. Numerical validity asks whether positions, angles and trigonometric calculations retain enough precision at the intended scale. Behavioral validity asks whether a trained model uses information correctly across the required distances. Float32 cannot represent every consecutive integer once the magnitude grows beyond its precision, so assigning very large positions in a narrow dtype can collapse distinct coordinates even before sine/cosine evaluation. The fixture uses float64, but successful evaluation at one million still establishes no trained-model quality result.

Frequency or position scaling changes the computation seen by a trained model. A conversion can preserve output shape while altering phase relationships. Treat such a change as a model configuration requiring controlled evaluation, with distance-stratified retrieval, reasoning and failure cases. Record training context length, tested lengths, tokenizer policy, cache offsets and precision. A prompt that grows by adding irrelevant padding can be long without requiring long-distance reasoning.

Interview reasoning: "Why does relative-position algebra not guarantee extrapolation?" The identity determines how the chosen vectors' scores depend on coordinates. It says nothing about which vectors training learned, whether unseen phase combinations are useful, or whether a downstream task needs the relevant information. RoPE and ALiBi describe different mechanisms with empirical studies; this lesson separately checks their small geometric contracts.

Vocabulary and concepts#

RoPE: Rotary position embedding applied to query/key feature pairs.

Relative offset: The difference between two token positions.

ALiBi: Attention with linear distance biases added to scores.

Position offset: The absolute index of a newly appended cached token.

Length extrapolation: Using context lengths beyond those supported by the training/evaluation evidence.

Syntax anatomy and reasoning sequence#

The RoPE helper pairs adjacent features and uses inverse frequencies base**(-2i/d) for pair index i. For each position p, it applies a 2D rotation by pfrequency to the corresponding query or key pair. Head width must be positive and even. ALiBi scores add -slope*(query_position-key_position) for legal past/current keys, then apply the causal mask before softmax. Cached keys retain the position assigned when they were created; do not rotate an already rotated key again or restart offsets for a new token.

Worked example / walkthrough#

Example A: Rotate a two-dimensional vector#

A rotation changes direction while preserving the Euclidean norm. This separates position encoding from arbitrary magnitude scaling.

import numpy as np
def rotate(vector,angle):
    c,s=np.cos(angle),np.sin(angle); return np.array([[c,-s],[s,c]])@np.asarray(vector,dtype=float)
def rope(values,positions,base=10000.):
    values=np.asarray(values,dtype=np.float64); positions=np.asarray(positions,dtype=np.float64)
    if values.ndim!=2 or values.shape[1]==0 or values.shape[1]%2 or positions.shape!=(len(values),): raise ValueError('even feature width and one position per row required')
    if not np.isfinite(values).all() or not np.isfinite(positions).all() or not np.isfinite(base) or base<=0: raise ValueError('finite rotary inputs required')
    width=values.shape[1]; pairs=values.reshape(len(values),width//2,2); angles=positions[:,None]*base**(-2*np.arange(width//2)/width)
    c,s=np.cos(angles),np.sin(angles); result=np.empty_like(pairs)
    result[...,0]=pairs[...,0]*c-pairs[...,1]*s; result[...,1]=pairs[...,0]*s+pairs[...,1]*c
    return result.reshape(values.shape)
vector=np.array([1.,0.]); rotated=rotate(vector,np.pi/2)
np.testing.assert_allclose(rotated,[0,1],atol=1e-12,rtol=0)
np.testing.assert_allclose(np.linalg.norm(rotated),1,atol=1e-12,rtol=0)

Expected: approximately[0, 1]; norm 1.

Example B: Verify the relative dot-product identity#

The transpose of a rotation is its inverse, so the absolute angles combine into their difference. This is an algebraic property, not a measured long-context quality result.

q=np.array([1.,2.]); k=np.array([3.,-1.]); m=.3; n=1.1
left=rotate(q,m)@rotate(k,n); right=q@rotate(k,n-m)
np.testing.assert_allclose(left,right,atol=1e-12,rtol=0)

Expected: dot(Rm q, Rn k)=dot(q, R(n-m)k) within 1e-12.

Controlled case study#

An incremental decoder passes short-prefix tests but diverges after cache reuse. Its weights are unchanged. Each new key was rotated at position zero instead of at the accumulated cache offset. Encoding the key at the correct position restores parity. A second failure rotates already-rotated cached keys again. These are state and layout errors, not evidence about long-context model quality. Resolve them before attempting an extrapolation study.

Common pitfalls and diagnosis#

If incremental and full-prefix outputs disagree, compare token IDs, position offsets and pairing layout before changing weights. Check whether cached keys are already rotated, whether only Q/K receive the intended transformation, and whether the mask still excludes future positions after adding a bias. Norm preservation alone will not detect a wrong angle: every wrong rotation can still preserve length.

Inspect long-context behavior by distance and task, not only by array shape or successful sine/cosine evaluation. Record the dtype used to form positions and angles. This fixture validates local algebra and cache bookkeeping; it does not implement a published context-extension training recipe or measure production long-context reliability.
