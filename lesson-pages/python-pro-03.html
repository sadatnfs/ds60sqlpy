Restartable File Pipelines and Honest Durability Guarantees#

Stable ID: python-pro-03

Estimated time: 270 minutes, split across sessions as needed.

Level and prerequisites#

Advanced. Direct catalog prerequisites: python-23, python-10.

You can process records in batches, work with files and JSON, and test failure behavior. This lab adds restart semantics and local publication boundaries using only the standard library. One writer owns each checkpoint. It does not introduce distributed coordination or promise power-loss durability on every filesystem.

Learning objectives#

  • Pin exact source bytes before processing and reject a changed source on resume.
  • Store progress and aggregate results together behind one atomic publication boundary.
  • Deduplicate replayed identities while rejecting conflicting duplicates.
  • Inject a failure before replacement, resume, and compare with a clean run.
  • Separate process-restart correctness from concurrency and power-loss guarantees.

Vocabulary and concepts#

A pipeline can crash after doing work but before recording that it finished. On restart, it must know which input and committed result belong together. Treat the checkpoint as a sealed receipt containing both progress and the result at that progress. If the receipt and result lived in independent files, replacing one successfully would not make the pair an atomic transaction. This lab keeps them in the same JSON document and replaces that one file.

  • Checkpoint: persisted progress plus enough state to resume the declared computation from an inspected boundary.
  • Snapshot identity: a hash of the exact source bytes used by this run, including encoding and line endings.
  • Replay: processing an input again after uncertain or repeated delivery.
  • Idempotency: repeating an operation with the same identity and content has the same externally visible result as performing it once.
  • Atomic replacement: a successful name replacement exposes a complete old or complete new file rather than a partially rewritten target.
  • Durability: survival of committed state across a stated failure model; process failure and power loss are different models.

The input is UTF-8 JSON Lines: one JSON object per nonempty physical line. Blank lines and duplicate JSON field names are rejected so offset counting and field meaning remain explicit. Each record contains exactly id and quantity. Id is nonempty trimmed text; quantity is a nonnegative integer, excluding bool. Repeating an id with the same quantity is an idempotent replay. Repeating it with a different quantity is a conflict and rejects the whole snapshot before publication. A correction needs an explicit version or event identity; last-write-wins is not silently assumed.

The checkpoint contains version, source SHA-256, source byte size, next row, unique quantities by id, total quantity, and completion status. Next row is the number of source records already accounted for, including identical replays. The unique count and total only count each identity once. State is recomputed for the committed prefix when loading, catching invalid progress, unexpected keys, or inconsistent totals rather than trusting arbitrary JSON.

Worked example / walkthrough#

Example A: keep related state in one publication#
state = {"next_row": 3, "quantities": {"A": 2, "B": 5}, "total_quantity": 7, "complete": False}
assert state["next_row"] == 3
assert sum(state["quantities"].values()) == state["total_quantity"]

Expected observation: three processed source rows can represent two unique identities when one row was a replay. The mapping and total travel with the offset. Publishing an offset of three while retaining a total from only one record would be inconsistent. JSON is just a format; putting values in JSON does not automatically validate or transactionally coordinate several files.

Example B: inspect exact input identity#
import hashlib

first = b'{"id":"A","quantity":2}\n'
same_meaning_new_bytes = b'{"id": "A", "quantity": 2}\n'
assert hashlib.sha256(first).hexdigest() != hashlib.sha256(same_meaning_new_bytes).hexdigest()

Expected observation: spacing changes the byte hash even though the parsed record has the same meaning. This lab pins byte identity deliberately so a resume cannot quietly reinterpret a different source. A semantic content hash is another legitimate design, but needs canonicalization and its own versioned contract. SHA-256 detects content differences; without a trusted signature or key it does not prove who created the source.

Replacement sequence and its limits#

Create a temporary file in the target directory so replacement stays on the same filesystem. Write complete UTF-8 JSON, flush Python's buffer, fsync the file, close it, then call os.replace. Closing before replacement is important for Windows file-handle behavior. Remove only the temporary file created by this attempt when an exception occurs. Preserve the old checkpoint and every learner-owned file. A test hook raises before replacement so a test can observe that the old published checkpoint is unchanged.

This sequence prevents partial target contents for the stated single-writer process-restart model. It does not establish directory-entry persistence after sudden power loss on every platform, nor protect against concurrent writers, network filesystem behavior, disk failure, or malicious state modification. File fsync and atomic rename solve different parts of the problem. State those limits beside the evidence instead of calling the design universally crash-proof or exactly-once.

Replay without pretending work executes once#

Each committed batch publishes a new prefix state. If the next candidate fails before replacement, the old prefix remains authoritative and the next run can repeat uncommitted computation. Because the aggregate derives from source identities and committed prefix together, replay does not double-count the result. The computation may execute more than once. That differs from a claim that each instruction or external side effect happens exactly once.

The reference re-derives state from a small source prefix for transparent validation. That is intentionally simple and can do repeated work across many batches. Measure and redesign for large sources only after preserving the same state invariants. This lab also validates the entire snapshot before the first write, so it is a bounded-file design rather than an unbounded streaming reader. It demonstrates restart reasoning, not a universal high-throughput ingestion engine.

Common pitfalls#

If totals double after retry, inspect replay identity and the committed prefix. If a changed source resumes, check the hash before processing. If Windows replacement fails, inspect open temporary/target handles before changing paths. If state parses but results disagree, re-derive its prefix and compare all fields. If tests remove every nearby temp file, narrow cleanup to the one path owned by this attempt so learner work is preserved.

Before adding concurrent writers or external side effects, define ownership, conflict detection, and the exact failure model rather than reusing this single-writer file design unchanged.

Restartable File Pipelines and Honest Durability Guarantees: solution reasoning#

Stable ID: python-pro-03.

Read the guide and attempt the learner artifact first. The executable solution is a comparison implementation. It does not certify your changed program merely because its own demonstration succeeds. Copy the acceptance cases into your attempt, then change one input without changing the intended policy.

The checkpoint is also the published result. That single-file boundary is the central design choice. A temporary candidate can be discarded without changing the old state. A completed state can be read repeatedly without rewriting it. Source identity and a re-derived prefix make resumption explicit instead of treating any parseable JSON as trusted progress.

quantities = {"A": 2, "B": 5}
assert len(quantities) == 2
assert sum(quantities.values()) == 7

The reference intentionally reads a bounded snapshot and validates all rows before committing progress. It uses one writer, small deterministic data, and same-directory replacement. Its failure injection tests a process boundary, not a physical power loss. Never run this demonstration against another learner's state or remove files you did not create.

Exercise 1. Pin and validate a snapshot#

Read bytes once, decode as UTF-8, and parse each physical line as one JSON object. The exact key set, trimmed nonempty text id, and nonnegative integer quantity form a small inspectable schema. Booleans are rejected despite Python considering bool an int subclass. Blank lines are rejected so a source-row offset has one unambiguous meaning. Parsing the whole snapshot before publication means an invalid suffix cannot leave a partially accepted source. This trades streaming scale for transparent teaching behavior and should be stated as a bounded-file assumption.

Exercise 2. Declare replay and conflict behavior#

Track the first quantity for each id while validating the snapshot. A repeated equal quantity is an idempotent replay and does not add units again. A differing quantity is a conflict that requires a source correction or explicit version policy. Reject it before creating or replacing a checkpoint. Three source rows A/2, A/2, B/5 therefore represent two unique identities and seven units. This does not prove the original quantities are true, nor does it make an external side effect idempotent merely because the in-memory sum is.

Exercise 3. Derive inspectable prefix state#

A prefix state counts every processed source row in next_row, including replays. Its unique mapping and sum represent the accepted identities in that prefix. At offset two in the replay example, only A contributes and total is two; after the third row B contributes five and total is seven. Completion means offset equals source row count. Validate offset type and range so a negative value cannot invoke Python's slice-from-end behavior. The persisted source hash and byte size identify exactly which snapshot the offset belongs to.

Exercise 4. Publish one complete state#

Write the full candidate into a temporary file in the target directory, flush buffered text, fsync the underlying file, close it, and then replace the target name. Injecting an error before replace demonstrates that old target bytes remain authoritative. Clean up only the candidate path created in this attempt, including on exceptions. Closing before replace avoids a common Windows handle problem. These steps do not prove parent-directory persistence after sudden power loss on every filesystem; document that boundary instead of calling the implementation unconditionally durable.

Exercise 5. Resume after a failed candidate#

With batches of two, the first committed state has offset two. The next candidate reaches offset four in memory, but the injected pre-replace error prevents publication, leaving offset two on disk. A fresh invocation loads that state and repeats the uncommitted work from the same pinned source. The final offset five and unique-id sum match a clean run. Compare complete state content, not only total, because an accidental offset change could otherwise go unnoticed. No external side effects exist in this lab beyond the single checkpoint publication.

Exercise 6. Reject stale or corrupt state#

A changed source produces a different snapshot identity, even when its parsed meaning happens to be similar. Refuse resume rather than silently resetting the checkpoint. A tampered total or offset also fails comparison with the expected prefix state. Parsing JSON verifies syntax only; state validation checks relationships among progress, source, aggregate, and completion. Preserve invalid state for inspection. Automatically deleting it would remove failure evidence and could cause replay under the wrong assumptions. The hash is an identity check, not a signature proving a trusted author.

Exercise 7. Prove repeat and empty behavior#

Once completion is true and the entire state matches its expected prefix, return it without rewriting. Byte-for-byte equality before and after a rerun makes that external idempotency visible. An empty source still needs a complete zero-row state so a caller can distinguish finished-empty from never-started. Reject bool, zero, and negative batch sizes before any write. Batch size changes how work is checkpointed, not the final aggregate. Try a different positive size on a fresh temporary checkpoint and compare its final state with the original.

Exercise 8. Write an honest guarantee#

The runbook should name the exact source identity, checkpoint location, ownership, resume command, next_row, completion flag, and aggregate checks. It should describe the injected failure and observed retained prefix. It must also say that concurrent writers, network filesystem semantics, directory fsync portability, physical disk loss, and external side effects were not tested or promised. That is not a weakness hidden in footnotes; it is the meaning of the evidence. Before broader deployment, choose mechanisms whose guarantees cover the actual failure and coordination model.

"""Single-writer, bounded-snapshot restart lab for python-pro-03."""
 
from __future__ import annotations
 
import hashlib
import json
import os
from collections.abc import Callable
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory
 
 
def _unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("duplicate JSON field")
        result[key] = value
    return result
 
 
def read_snapshot(source: Path) -> tuple[bytes, list[dict[str, object]]]:
    raw = source.read_bytes()
    records: list[dict[str, object]] = []
    seen: dict[str, int] = {}
    try:
        text = raw.decode("utf-8")
    except UnicodeDecodeError as exc:
        raise ValueError("source must be UTF-8") from exc
    for number, line in enumerate(text.splitlines(), start=1):
        if not line.strip():
            raise ValueError(f"blank source row {number}")
        try:
            record = json.loads(line, object_pairs_hook=_unique_object)
        except json.JSONDecodeError as exc:
            raise ValueError(f"invalid JSON at source row {number}") from exc
        if not isinstance(record, dict) or set(record) != {"id", "quantity"}:
            raise ValueError(f"unexpected schema at source row {number}")
        identifier, quantity = record["id"], record["quantity"]
        if not isinstance(identifier, str) or not identifier or identifier != identifier.strip():
            raise ValueError(f"invalid id at source row {number}")
        if not isinstance(quantity, int) or isinstance(quantity, bool) or quantity < 0:
            raise ValueError(f"invalid quantity at source row {number}")
        if identifier in seen and seen[identifier] != quantity:
            raise ValueError(f"conflicting id at source row {number}")
        seen[identifier] = quantity
        records.append(record)
    return raw, records
 
 
def state_for_prefix(
    raw: bytes, records: list[dict[str, object]], next_row: object
) -> dict[str, object]:
    if (
        not isinstance(next_row, int)
        or isinstance(next_row, bool)
        or not 0 <= next_row <= len(records)
    ):
        raise ValueError("invalid next_row")
    quantities: dict[str, int] = {}
    for row in records[:next_row]:
        identifier, quantity = row["id"], row["quantity"]
        if not isinstance(identifier, str) or not isinstance(quantity, int):
            raise ValueError("prefix requires validated records")
        quantities[identifier] = quantity
    return {
        "version": 1,
        "source_sha256": hashlib.sha256(raw).hexdigest(),
        "source_bytes": len(raw),
        "next_row": next_row,
        "quantities": dict(sorted(quantities.items())),
        "total_quantity": sum(quantities.values()),
        "complete": next_row == len(records),
    }
 
 
def atomic_write_state(
    path: Path, state: dict[str, object], before_replace: Callable[[], None] | None = None
) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary: Path | None = None
    try:
        with NamedTemporaryFile(
            mode="w",
            encoding="utf-8",
            newline="\n",
            dir=path.parent,
            prefix=f".{path.name}.",
            suffix=".tmp",
            delete=False,
        ) as handle:
            temporary = Path(handle.name)
            json.dump(state, handle, sort_keys=True, indent=2)
            handle.write("\n")
            handle.flush()
            os.fsync(handle.fileno())
        if before_replace is not None:
            before_replace()
        temporary.replace(path)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)
 
 
def run_pipeline(
    source: Path, checkpoint: Path, batch_size: int = 2, fail_before_commit_at: int | None = None
) -> dict[str, object]:
    if not isinstance(batch_size, int) or isinstance(batch_size, bool) or batch_size <= 0:
        raise ValueError("batch_size must be a positive integer")
    if source.resolve() == checkpoint.resolve():
        raise ValueError("source and checkpoint must differ")
    raw, records = read_snapshot(source)
    state: dict[str, object]
    if checkpoint.exists():
        try:
            loaded = json.loads(
                checkpoint.read_text(encoding="utf-8"), object_pairs_hook=_unique_object
            )
        except (json.JSONDecodeError, UnicodeDecodeError) as exc:
            raise ValueError("invalid checkpoint encoding or JSON") from exc
        if not isinstance(loaded, dict):
            raise ValueError("checkpoint must be an object")
        expected = state_for_prefix(raw, records, loaded.get("next_row"))
        # Canonical JSON distinguishes booleans from integers and integers from floats.
        if json.dumps(loaded, sort_keys=True) != json.dumps(expected, sort_keys=True):
            raise ValueError("checkpoint does not match this source and prefix")
        state = expected
    else:
        state = state_for_prefix(raw, records, 0)
        atomic_write_state(checkpoint, state)
    raw_offset = state["next_row"]
    assert isinstance(raw_offset, int)
    offset: int = raw_offset
    while offset < len(records):
        offset = min(offset + batch_size, len(records))
        candidate = state_for_prefix(raw, records, offset)
 
        def before_replace(target_offset: int = offset) -> None:
            if fail_before_commit_at == target_offset:
                raise RuntimeError(f"injected failure before committing row {target_offset}")
 
        atomic_write_state(checkpoint, candidate, before_replace)
        state = candidate
    return state
 
 
if __name__ == "__main__":
    with TemporaryDirectory() as directory:
        root = Path(directory)
        source = root / "source.jsonl"
        source.write_text(
            "".join(json.dumps({"id": str(i), "quantity": i}) + "\n" for i in range(5)),
            encoding="utf-8",
        )
        checkpoint = root / "checkpoint.json"
        try:
            run_pipeline(source, checkpoint, fail_before_commit_at=4)
        except RuntimeError:
            assert (
                json.loads(
                    checkpoint.read_text(encoding="utf-8"), object_pairs_hook=_unique_object
                )["next_row"]
                == 2
            )
        result = run_pipeline(source, checkpoint)
        assert (
            result["next_row"] == 5
            and result["total_quantity"] == 10
            and result["complete"] is True
        )
        print(result)
