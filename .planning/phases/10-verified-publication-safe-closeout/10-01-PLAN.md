# Plan 10-01: publish and verify release 2.0.0

## Objective

Publish DS60 2.0.0 only after its source, tests, images, scans, registry
target and tags are verified, then pull and smoke-test the published artifact
and publish a matching GitHub release (REL-01, the release half of REL-03).

## Tasks

1. Bump every DS60 `1.4.3` release reference to `2.0.0`, following the 1.4.3
   release commit `c46e6ad4` (pyproject, `src/ds60sqlpy/__init__.py`,
   `uv.lock` project entry, Dockerfiles, compose files, launchers, project
   READMEs and scripts, docs). Rewrite the `docs/dockerhub.md` "next version"
   example and the `1.4.4` examples in `classroom.html` and
   `tests/test_image_scan.py` by hand. Do not touch third-party versions that
   happen to read `1.4.3` or `1.4.4` (the Julia Manifest, `mako==1.4.3` locks,
   Go module sums) or test fixtures that model older tags. Run `make generate`
   so the reference pages follow.
2. Rerun the Phase 9 repository gate on the bumped tree.
3. Commit `Release DS60 2.0.0 [publish-docker]`, push to `main`, then dispatch
   `verify-torch-package.yml` for that exact commit.
4. Watch `Publish images`: qualification, the Phase 8 scan gate, staging and
   promotion. On a transient failure use Re-run failed jobs; never bypass the
   scan gate.
5. After promotion, confirm the native AMD64 and ARM64 pull jobs passed, then
   pull `sadatnfs/ds60sqlpy:2.0.0` locally into a disposable project
   `ds60-p10-smoke`, start App and Core, open a lesson, run Python and SQL, and
   tear it down with `down -v`.
6. Tag the release commit `v2.0.0` and publish the GitHub release with
   `gh release create v2.0.0 --target <sha> --title "DS60 2.0.0"`. Write the
   notes from the phase summaries, listing the image tags and the publish run.
   Confirm with `gh release view v2.0.0` that the release is not a draft and
   that its tag resolves to the published commit.
7. Update `docs/dockerhub.md` and the README with the 2.0.0 evidence in a
   follow-up commit without release markers.

## Verification

- Publish run green with 2.0.0 version indexes and latest aliases; pull jobs
  green; GitHub release `v2.0.0` published at the release commit; local smoke
  receipt recorded in `10-VERIFICATION.md`.
