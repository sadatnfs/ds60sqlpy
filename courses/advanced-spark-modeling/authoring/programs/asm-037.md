# Worked reference: Measurement ledger

This is an editable reading/project reference. It has no ordinary pad Run action.

Record preparation time, first evaluation, warm evaluation distribution, total optimizer time, objective-evaluation count, peak memory, spill and transfer/conversion costs. Bind them to rows, features, parameters, partition count, precision, CPU/thread limits and image/source identity.

If a serial fit takes 0.2 seconds and ten Spark actions each incur 0.1 seconds of scheduling before arithmetic, parallelism cannot remove that one-second overhead. This is an illustrative cost arithmetic, not a measured benchmark. A real speedup claim needs equivalent targets and tolerances on representative data.
