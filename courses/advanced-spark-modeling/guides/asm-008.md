# asm-008: Merge precision, unequal partitions and one penalty

Tutorial mode. Stage: intermediate. Direct prerequisites: `asm-007`, `clp-013`.

## Starting point and result

Repartitioning should change execution, not the statistical objective. Three common violations are averaging partition means equally, applying a penalty once per partition, and assuming floating-point addition is exact. This program makes all three visible with four values and two deliberately unequal partitions.

## Mechanism: count and sum form the merge contract

For partition \(p\), return \((n_p,s_p)\), where \(s_p=\sum_{i\in p}\ell_i\). Merge by addition. The global mean is

\[\bar\ell=\frac{\sum_p s_p}{\sum_p n_p}.\]

The unweighted average of partition means instead assigns equal influence to each nonempty partition. That matches the global mean only under special conditions, such as equal partition sizes. Empty partitions need an identity summary \((0,0)\), not a division by zero. The example uses explicit keyed partitioning so the unequal sizes are intentional, not an accident of a scheduler.

For ridge regularization under the summed-loss convention, \(J(\beta)=\sum_i\ell_i(\beta)+\lambda\|\beta\|^2/2\). The penalty belongs to the model objective, not to a partition. Add it once after reduction. Equivalently, a carefully weighted distributed allocation could sum to the same value, but distributing it equally among an assumed partition count is fragile when partitions are empty or execution changes.

## Worked case: one row versus three

Partition zero contains one loss value, 1. Partition one contains three values, all 3. The summaries are \((1,1)\) and \((3,9)\). The correct mean is 10/4, or 2.5. The mean of the two partition means is (1+3)/2, or 2. The program asserts both numbers so the wrong estimator is explicitly reproduced rather than merely warned about.

At beta 2 and lambda 0.5, the ridge penalty is one. The correct penalized summed objective is 11. Adding the same penalty to each partition gives 12. Increasing partitions would silently strengthen regularization. The same mistake affects gradients through duplicated \(\lambda\beta\).

## Worked case: arithmetic order changes the last bits

The sequence \([10^{16},1,-10^{16}]\) sums to one in exact arithmetic. A naive left-to-right double-precision sum can return zero because adding one to \(10^{16}\) rounds back to \(10^{16}\). Python's `math.fsum` returns one by retaining additional summation information. The program records both results.

Using `fsum` inside each partition cannot recover information already lost in input quantization or a previous rounded reduction. Likewise, merging partition totals with `fsum` does not recreate every original term. For sensitive objectives consider compensated summaries, scale-aware data transformations, pairwise reductions and explicit tolerances. None promises bitwise reproducibility under arbitrary partition changes.

## Failure diagnosis

If fitted parameters change materially when only partition count changes, inspect normalization before tuning the optimizer. If only the final few bits change, compare the error with your convergence tolerance and the conditioning of the model. A tolerance far below attainable summation precision can cause unnecessary iterations or inconsistent stop decisions.

## Interview discussion

**Should I multiply lambda by the number of rows?** Only when translating between explicitly defined sum and mean conventions. Derive the full objective on paper, including its denominator, before changing lambda.

**Does Spark provide an exact real-number reduction?** Ordinary double arithmetic does not. SQL decimals can represent some fixed-precision quantities exactly but have bounded range and do not solve arbitrary nonlinear floating-point computation.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-python`.

```python
from __future__ import annotations

import json
import math


def session(name):
    from pyspark.sql import SparkSession

    spark = (
        SparkSession.builder.master("local[2]")
        .appName(name)
        .config("spark.ui.enabled", "false")
        .config("spark.driver.host", "127.0.0.1")
        .config("spark.driver.bindAddress", "127.0.0.1")
        .config("spark.sql.shuffle.partitions", "2")
        .config("spark.sql.adaptive.enabled", "false")
        .config("spark.sql.ansi.enabled", "true")
        .config("spark.sql.session.timeZone", "UTC")
        .getOrCreate()
    )
    if spark.version != "4.0.1":
        spark.stop()
        raise RuntimeError("This worked reference is qualified for Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    return spark


def run(spark):
    keyed = [(0, 1.0), (1, 3.0), (1, 3.0), (1, 3.0)]
    rdd = spark.sparkContext.parallelize(keyed, 2).partitionBy(2)

    def summary(iterator):
        values = [value for _, value in iterator]
        yield (len(values), math.fsum(values))

    summaries = rdd.mapPartitions(summary).collect()
    n = sum(x[0] for x in summaries)
    total = math.fsum(x[1] for x in summaries)
    mean = total / n
    bad = math.fsum(loss / count for count, loss in summaries if count) / len(
        [1 for count, _ in summaries if count]
    )
    assert sorted(count for count, _ in summaries) == [1, 3]
    assert mean == 2.5 and bad == 2.0
    beta, lam = 2.0, 0.5
    once = total + lam * beta * beta / 2
    repeated = math.fsum(loss + lam * beta * beta / 2 for _, loss in summaries)
    assert once == 11.0 and repeated == 12.0
    terms = [1e16, 1.0, -1e16]
    naive = 0.0
    for term in terms:
        naive += term
    assert naive == 0.0 and math.fsum(terms) == 1.0
    print(
        json.dumps(
            {
                "summaries": summaries,
                "global_mean": mean,
                "wrong_mean_of_means": bad,
                "penalty_once": once,
                "penalty_per_partition": repeated,
                "naive_sum": naive,
                "accurate_sum": math.fsum(terms),
            }
        )
    )


if __name__ == "__main__":
    spark = session("asm-008")
    try:
        run(spark)
    finally:
        spark.stop()
```
