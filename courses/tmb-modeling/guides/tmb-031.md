# Simulation APIs and score consistency

Start with: tmb-030, tmb-019.

Outcome: Distinguish generative consistency, estimation bias and approximation bias.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A model's simulation method should generate observations according to the same probability distribution that its likelihood evaluates. A `SIMULATE` block provides that generative code. TMB's `checkConsistency` compares simulation-based score behavior with identities implied by normalized densities and can inspect marginal approximation effects.

Under suitable regularity conditions, the expectation of the score is zero. For NLL \(f_\theta\), this means \(E_\theta[\nabla_\theta f_\theta(Y)]=0\). A missing normalizer can violate this identity even when a fitted curve looks plausible. With random effects, joint score checks and approximate marginal score checks answer different questions.

### Worked case A: centered Gaussian score

The companion simulates datasets from a known normal distribution and computes the mean score at the generating mean. Its average should be close to zero relative to Monte Carlo uncertainty, not literally zero. Increasing replicates reduces simulation error but does not change the model.

In the prepared project, the normal template's `obj$simulate` returns generated `y`; `checkConsistency(obj, n=...)` builds a bounded diagnostic object. `print` and `summary` methods display different levels of detail. Keep the number of simulated datasets and whether each was refitted in the receipt.

### Worked case B: omit a scale normalizer

For a flawed objective containing only squared standardized residuals, the log-scale derivative has negative expectation rather than zero. The companion compares this with the full normal log-scale score \(n-\sum_i r_i^2/\sigma^2\). This is a specific diagnostic failure, not a generic p-value exercise.

The manual cautions that a sufficiently large marginal-score experiment can detect approximation error even for a useful Laplace approximation. `summary.checkConsistency` expresses part of this on parameter-bias scales. A formal rejection is evidence to interpret, not permission to hide failures or widen tolerances until green.

### Answered discussion

**Does `estimate=TRUE` merely print extra output?** It requests repeated fitting and can be much more expensive. **Can a deterministic fixture establish generative consistency?** No. It establishes exact arithmetic on chosen values; simulation tests another layer. **Do print and summary methods rerun estimation?** They summarize an existing diagnostic object; preserve that object and its settings for reproducibility.

The [checkConsistency manual](https://cran.r-project.org/web/packages/TMB/TMB.pdf) documents its beta status. Pin the API and avoid unbounded replicate counts in ordinary learner runs.

### Complete R companion

```r
set.seed(3131);n <- 20;B <- 100;mu <- 1;sigma <- 2
scores <- replicate(B, {
  y <- rnorm(n, mu, sigma);c(mean_score = sum(mu - y) / sigma^2, scale_score = n - sum((y - mu)^2) / sigma^2, missing_normalizer = -sum((y - mu)^2) / sigma^2)
})
print(rowMeans(scores));print(apply(scores, 1, sd) / sqrt(B))
stopifnot(mean(scores[3, ]) < -10)
```
