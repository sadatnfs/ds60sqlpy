asm-009: Retry-safe evaluation and external side effects#

Tutorial mode. Stage: intermediate. Direct prerequisites: asm-008, spark-035.

Starting point and result#

Spark may recompute a partition after failure or run speculative attempts. An objective evaluation must not count those attempts as additional observations. This lesson performs two real bounded evaluations and separately models duplicate external deliveries. It does not claim to have injected a real executor failure or qualified speculative execution.

Mechanism: logical work differs from attempts#

A pure task maps immutable inputs and parameters to a summary. Spark owns the selection of successful task results in the ordinary RDD action. A task that appends to an external database, increments a remote counter or sends a message creates effects outside that result protocol. Re-execution may repeat those effects even when Spark returns one logical result.

For an external summary store, an identity must bind the data version, parameter version and logical chunk identity. A result also needs a content check. Identical retries can be accepted idempotently; conflicting content for the same immutable identity is an error. A physical partition number is meaningful only within a particular immutable partition plan. Repartitioning or changing input discovery invalidates a scheme that treats that number as a durable global key.

A dictionary in this program illustrates the rule. It is not a production transactional store. Real concurrent writers require an atomic unique key or compare-and-set operation, persistence, access controls and a defined cleanup policy. An in-memory “seen” set inside each executor does not coordinate all executors or survive a process restart.

Worked case: repeated pure evaluation#

Four values are split across two partitions. Each task emits a count and sum, with no outside writes. Running the action twice returns identical sorted summaries. This demonstrates deterministic results for the tiny fixture and current code. It does not guarantee deterministic results for a nondeterministic source, unseeded random numbers or mutable external files.

The driver may intentionally evaluate the same parameter twice during a line search. Such repetitions cost time but should not alter the mathematical answer. Cache keys must include the parameter vector and every relevant model setting. Caching by iteration number alone is insufficient when the optimizer evaluates several candidates within an iteration.

Worked case: duplicated and conflicting deliveries#

The program wraps both evaluations in the same immutable evaluation identity. Naively summing every delivered attempt counts eight rows, even though the dataset has four. Reconciliation accepts one identical summary per key and restores the correct four-row total. Then an intentionally conflicting summary with count 999 is delivered under an existing key. The function raises instead of silently choosing whichever attempt happened to arrive last.

Rejecting a conflict is essential. Last-writer-wins may hide a stale parameter, changed data or corrupted summary. Compare explicit fields and use a documented numeric tolerance only when legitimate reduction variability is expected. A tolerance should not excuse changes in counts, IDs, schema or parameter hashes.

Failure diagnosis#

An inflated likelihood after a worker retry points toward external side effects or duplicated source ingestion. A random seed derived from task attempt number changes simulated likelihoods between retries. Use logical observation or simulation identities when repeatability matters. Accumulators are useful operational counters but should not become the authoritative optimizer objective.

Interview discussion#

Does Spark give exactly-once side effects in arbitrary user code? No. Its result and storage contracts do not automatically extend to your external service. Explain the service's transaction and deduplication behavior separately.

Can retries change wall time without changing the model? Yes. Pure evaluation preserves semantics while repeated computation increases cost. Report attempts and resource time as execution diagnostics, not extra data.

Next step#

Apply the same immutable-evaluation idea to a nonlinear model. Keep the serial oracle small enough that it can diagnose whether a failure is numerical, statistical or distributed.

Complete reproducible program#

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: spark-local-python.

from __future__ import annotations

import json
import math


def session(name):
    from pyspark.sql import SparkSession

    spark = (
        SparkSession.builder.master("local[2]")
        .appName(name)
        .config("spark.ui.enabled", "false")
        .config("spark.driver.host", "127.0.0.1")
        .config("spark.driver.bindAddress", "127.0.0.1")
        .config("spark.sql.shuffle.partitions", "2")
        .config("spark.sql.adaptive.enabled", "false")
        .config("spark.sql.ansi.enabled", "true")
        .config("spark.sql.session.timeZone", "UTC")
        .getOrCreate()
    )
    if spark.version != "4.0.1":
        spark.stop()
        raise RuntimeError("This worked reference is qualified for Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    return spark


def summary(values):
    return {"count": len(values), "sum": math.fsum(values)}


def reconcile(attempts):
    accepted = {}
    for identity, value in attempts:
        if identity in accepted and accepted[identity] != value:
            raise ValueError("Attempt content disagrees for the same immutable evaluation identity")
        accepted[identity] = value
    return accepted


def run(spark):
    data = [1.0, 2.0, 3.0, 4.0]
    rdd = spark.sparkContext.parallelize(data, 2)

    def evaluate(index, iterator):
        yield str(index), summary(list(iterator))

    first = sorted(rdd.mapPartitionsWithIndex(evaluate).collect())
    second = sorted(rdd.mapPartitionsWithIndex(evaluate).collect())
    assert first == second
    attempts = [(("fixture-v1", "beta-zero", key), value) for key, value in first + second]
    accepted = reconcile(attempts)
    assert sum(value["count"] for value in accepted.values()) == 4
    assert sum(value["count"] for _, value in attempts) == 8
    try:
        reconcile(attempts + [(attempts[0][0], {"count": 999, "sum": 0.0})])
    except ValueError:
        rejected = True
    else:
        rejected = False
    assert rejected
    print(
        json.dumps(
            {
                "two_actual_evaluations": 2,
                "accepted_rows": 4,
                "naive_attempt_rows": 8,
                "conflict_rejected": rejected,
                "fault_injection": False,
            }
        )
    )


if __name__ == "__main__":
    spark = session("asm-009")
    try:
        run(spark)
    finally:
        spark.stop()
