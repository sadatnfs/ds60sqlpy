# Python to a compiled TMB boundary

Start with: tmb-022, tmb-007.

Outcome: Design a narrow request to a prepared compiled model that keeps execution, data and native pointers isolated.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter checks a request's parameter order and row identity. In the separately prepared [owned project](../projects/tmb-local/README.md), `python/bridge.py` sends such requests to the compiled models through rpy2, and `tests/bridge_acceptance.py` checks the round trip; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

A useful integration boundary is narrow. The Python caller should select a documented model and typed data, then receive numerical results and diagnostics. It should not construct shell commands containing arbitrary C++ text, accept unrestricted library paths from untrusted input, or pretend that an R external pointer can be serialized to another worker.

The owned project provides two paths. `R/evaluate.R` accepts a bounded JSON request for one allowlisted model and evaluates a specified parameter vector. `python/bridge.py` uses embedded R and scoped pandas conversion to fit the original regression model. Both use already prepared libraries. Neither installs packages or compiles a model during a normal evaluation.

## Key terms

- **Fixed protocol:** A bounded request format that names one allowlisted prepared model, typed data and a parameter vector, with no arbitrary source or library paths.
- **Embedded R:** An R interpreter running inside the Python process through rpy2, used by the bridge to fit the prepared regression model.
- **Library identity rejection:** Refusing to evaluate when a same-named model is already loaded from another directory, and asking for a fresh R process instead.
- **Detached result:** Plain numerical values, gradients and diagnostics returned to the caller without R external pointers, which cannot be serialized to another worker.

### Worked case A: an explicit evaluation request

```json
{
  "schema_version": 1,
  "model": "normal_mean",
  "data": { "y": [1, 2, 4, 7] },
  "parameters": { "mu": 0, "log_sigma": 0 },
  "theta": [2.2, 0.3],
  "random": null
}
```

`parameters` determines declared shapes and initial coordinates. `theta` determines the evaluation point. The response contains the value, gradient, parameter names, row count and software/source identity. This separation supports a Spark driver that changes a shared parameter vector and asks workers for fresh additive contributions. It does not claim to optimize anything merely because an evaluation succeeded.

### Worked case B: stale-library and invalid-data rejection

If a model with the same name is already loaded from another directory, the API rejects it and asks for a fresh R process. If a dataframe contains duplicate IDs, non-finite values or a constant predictor, the Python bridge rejects it before fitting. A caller should retain these failures as explicit results keyed by the attempted input, rather than substituting an older successful fit.

The base-R companion models the fixed flattened coordinate and row-identity checks. Actual bridge acceptance must additionally execute the prepared rpy2 path and compare estimates with an independent least-squares oracle. Test a non-monotonic row-ID order, because an accidental sort can otherwise pass unnoticed.

### Lifecycle and answered discussion

**Can I reuse a process?** Yes with careful ownership, but native objects must remain inside that process and loaded-model identities must match. A fresh bounded process is easier to reason about for isolated examples. **Can I use Spark `mapPartitions`?** It can host a prepared R/TMB boundary when data groups and environment are compatible. Spark supplies scheduling; it does not differentiate through R or its serialization boundary. **Why return gradients rather than an R object?** Plain numerical arrays have an explicit order and can be reduced safely. Native pointers cannot.

See `projects/tmb-local/PROTOCOL.md` for exact request semantics. The Spark/TMB project handles its own group decomposition, retry behavior and numerical parity. A successful local bridge is a prerequisite, not proof of distributed scale or production fault tolerance.

### Worked case C: the response for the protocol's example request

`R/evaluate.R` builds its output from `evaluate_objective()`, which returns `value` and `gradient`, and then adds `schema_version`, `model`, `parameter_names`, `nobs` and `provenance`. For the documented `normal_mean` request at \(\theta=(2.2,0.3)\), the objective and gradient have a closed form. With \(e^{2(0.3)}=1.822119\) and \(S=\sum(y_i-2.2)^2=27.76\):

\[
\text{value}=4(0.3)+2\log(2\pi)+\frac{27.76}{2(1.822119)}=1.2+3.675754+7.617506=12.493260,
\]
\[
\frac{\partial}{\partial\mu}=-\frac{5.2}{1.822119}=-2.853821,\qquad
\frac{\partial}{\partial\log\sigma}=4-\frac{27.76}{1.822119}=-11.235011.
\]

```json
{
  "value": 12.49326,
  "gradient": [-2.853821, -11.235011],
  "schema_version": 1,
  "model": "normal_mean",
  "parameter_names": ["mu", "log_sigma"],
  "nobs": 4,
  "provenance": {
    "R": "<R version>",
    "TMB": "<TMB version>",
    "architecture": "<platform>",
    "source_md5": "<md5 of models/normal_mean.cpp>"
  }
}
```

The numbers above are rounded closed-form values; the driver prints 17 significant digits, so a real response carries more. Angle-bracket fields are placeholders for whatever the prepared environment reports. Both gradient components are negative, so a driver taking a descent step would raise \(\mu\) toward 3.5 and raise \(\log\sigma\) toward 0.829. The `parameter_names` array is what makes the gradient usable: a Spark driver that summed gradients from several workers must check that every worker returned the same names in the same order before adding element-wise.

### Failure responses a caller should expect

A `theta` of length 3 stops with "Theta dimension mismatch". A request with `schema_version` 2 stops with "Unsupported request schema". A request file above 10 MB stops before parsing. An evaluation point where the objective or gradient is not finite, for example a `log_sigma` so negative that the residual term overflows, stops with "Non-finite objective or gradient" rather than returning `Inf`. Each failure ends the R process with a nonzero status and no JSON, so a caller should treat a missing or unparseable response as a failed evaluation keyed by its request, not retry silently with a different `theta`.

### Base-R companion (runs in the classroom)

```r
request <- list(schema_version = 1L, model = "normal_mean", data = list(y = c(1, 2, 4, 7)), parameters = list(mu = 0, log_sigma = 0), theta = c(2.2, .3))
expected_order <- c("mu", "log_sigma")
stopifnot(identical(names(request$parameters), expected_order), length(request$theta) == 2)
print(setNames(request$theta, expected_order))
ids <- c("r3", "r1", "r2")
returned <- ids
stopifnot(identical(ids, returned))
print(list(correct_order = identical(ids, returned), detect_accidental_sort = !identical(ids, sort(returned))))
```
