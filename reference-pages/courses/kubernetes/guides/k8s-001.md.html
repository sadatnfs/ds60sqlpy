Vocabulary and concepts#

A terminal displays requests and observations. A YAML file is saved desired-state text; it is not a running workload. Before a request changes a cluster, identify which owned disposable resource the request can affect. A context name is a convenient label for connection settings, not proof that the remote server or namespace still has the identity you expect.

The examples below are fictional reading fixtures, not real authorization receipts. The explicit host preparation operation issues an actual private lease and records cluster identity, namespace UID, ownership markers and expiry. The browser must not select an ambient current-context when that evidence is missing. A kubeconfig can contain credentials, so keep it outside source, portable learning notes and exports. Kubernetes contexts describe connection selection; course ownership requires additional evidence.

  • terminal: an interface to commands and their output streams
  • manifest: saved desired-state text such as a YAML API request
  • context: a named connection/user/namespace selection, not an ownership proof
  • UID: a server-assigned immutable identity for one object instance
  • lease: time-bounded permission to use explicitly owned lab resources

Preparation timing and expiry#

Prepare the private fifteen-minute session immediately before running the lab, after image/tool preparation. An expired lease is correctly refused. Stop the broker, release the exact owned session and prepare a fresh one while preserving learner source. The host-lab guide explains the expiry and UID-aware release workflow; no ambient credential fallback is used.

Common pitfalls#

Never paste the fictional receipt into an actual authorization path. Matching a context or namespace name alone is insufficient. An expired lease is not repaired by switching identities, and a cleanup button must not select a default cluster.
