## Purpose and mental model

### Accelerate a sampling procedure without changing its target law

Ordinary autoregressive sampling asks the target model for the next-token distribution, draws one token, appends it and repeats. Speculative decoding introduces a cheaper draft model that proposes several tokens before the target verifies them. The central challenge is statistical correctness: proposals from the draft distribution must be accepted or corrected so that the emitted sequence still follows the declared target distribution.

This is different from greedy agreement. Two models can share an argmax while assigning very different probabilities to the remaining tokens. Accepting every matching top choice would generally change a sampling law. The exact algorithm accounts for probability mass token by token. It can change the random-number schedule and individual sampled text while preserving the target distribution under its assumptions.

#### Begin at one fixed prefix

Let p_i be the target probability of token i and q_i the draft probability at the same prefix. Both vectors refer to the same vocabulary identities and include the intended temperature or filtering policy. A draft proposal X is sampled from q. If X=i, accept it with probability \(a_{i}=\min(1,\frac{p_{i}}{q_{i}})\) when \(q_{i}>0\).

The probability mass emitted through acceptance at i is \(q_{i}\cdot a_{i}=\min(p_{i},q_{i})\). Where the draft overallocates mass relative to the target, some proposals are rejected. Where the target has more mass, correction must restore the difference. Define positive residual mass \(r_{\mathrm{raw\_i}}=\max(p_{i}-q_{i},0)\), with total \(R=\sum_i r_{\mathrm{raw},i}\). For \(R>0\), sample a correction from \(r_{i}=\frac{r_{\mathrm{raw\_i}}}{R}\) after rejection.

Because p and q both sum to one, R also equals \(1-\sum_i\min(p_i,q_i)\), the overall rejection probability. The final emitted mass is \(\min(p_{i},q_{i})+R\cdot r_{i}=p_{i}\). This equation is the core proof. It is stronger than observing roughly matching frequencies in a small random simulation, though implementation tests are still needed to ensure the code follows it.

#### Work through the mismatch in the supplied distributions

For \(p=[0.5,0.3,0.2]\) and \(q=[0.2,0.5,0.3]\), acceptance probabilities are[1,.6,2/3]. Accepted mass is[.2,.3,.2], totaling .7. The remaining .3 belongs entirely to token 0 because \(p-q=[0.3,-0.2,-0.1]\). The correction distribution is therefore[1,0,0].

If draft token 1 is proposed with acceptance draw .8, it is rejected because .8 is not below .6, and the correction produces token 0. If token 2 is proposed with draw .5, it is accepted because \(0.5<\frac{2}{3}\). These deterministic draw choices make both branches inspectable without relying on a large Monte Carlo sample.

A tempting fallback is to sample directly from p after rejection. That would yield accepted mass[.2,.3,.2] plus \(0.3\cdot p\), giving[.35,.39,.26]. The result is not p. The residual is essential because some target mass has already been delivered through accepted proposals. Correction must fill only the remaining deficit, not draw from the whole target law again.

#### Interpret overlap through total variation

The rejection probability R equals one half of the L1 distance between p and q. It measures their mass mismatch at this particular prefix. If \(p=q\), \(R=0\) and every valid proposal is accepted. If their supports are disjoint, \(R=1\) and every proposal is rejected before correction samples from the target's support.

A token with \(q_{i}=0\) cannot be proposed by a valid draw from q, so its acceptance ratio need not be evaluated. If \(p_{i}>0\) there, that mass can still appear through correction. The implementation must avoid turning a division by zero into a valid proposal path. It also must preserve zero-probability intervals when drawing from cumulative probabilities.

Floating-point cumulative sums need their own support check. The sampler constructs its cumulative distribution only over positive-probability token IDs, caps rounded cumulative values at 1, and assigns the terminal boundary 1 to the final positive-support entry. It then maps the chosen support index back to the original token ID. Otherwise, setting only the last array entry to1 can accidentally give a trailing zero-probability token a tiny interval near 1. Interior and leading zero entries are excluded by the same mapping, while half-open interval boundaries retain their stated behavior.

When distributions are equal, the residual has zero total mass and is not a usable distribution. The correct control flow never requests it. Returning an arbitrary uniform residual to avoid handling this case would conceal an impossible-branch error. Boundary behavior belongs in the algorithm's contract, not merely in a numerical tolerance.

#### Extend the argument to a proposal block

The draft proposes a sequence by conditioning each proposal on the previous draft proposals. The target verifies in order. Before the first rejection, the accepted prefix matches the prefix under which each saved draft distribution was computed, allowing the one-step correction argument to apply. At the first rejection, later proposals were conditioned on a token that was not committed and must be discarded.

If all gamma proposals are accepted and output budget remains, the algorithm can draw a bonus token from the target's next distribution. The bonus is not drawn from a zero-mass residual. An accepted EOS ends the sequence immediately and suppresses further proposals or a bonus. A hard output cap also limits the round, defining a truncated generation process under the chosen policy.

This conditional-prefix reasoning is why verifying tokens independently out of order is not enough. A distribution attached to the wrong prefix can have valid nonnegative entries summing to one and still be the wrong distribution for the current event. Preserve the prefix relationship as carefully as the probability vector itself.

#### Restore caches to the committed sequence

Suppose a committed prefix has length 5 and three draft tokens have been processed speculatively. If two are accepted and the third is rejected, keep state for length 7, remove the rejected position, and append the correction at logical position 7. The final committed length is 8. If only one proposal had been accepted, the retained length before correction would be 6. Cache lengths must follow the accepted prefix, not the original proposal count.

The rollback concerns token IDs, keys, values and positions together. Leaving a rejected key in the target cache changes the next attention context. Reusing its position for the correction incorrectly can change rotary or learned-position behavior. The lesson's TinyCache stores actual NumPy K/V arrays so these differences can be checked against a fresh reconstruction from committed tokens.

Draft and target caches belong to different models. Matching token IDs do not make their K/V vectors interchangeable. Each model must update or rebuild its own state from the same committed prefix under its own projections and layout. A shared request identity does not authorize copying raw internal tensors between architectures.

#### Estimate when speculation could help, then measure it

Assume for one simplified calculation that each proposal is accepted independently with probability a, that gamma proposals are attempted, and that neither EOS nor an output cap binds. Expected emitted tokens per round are \(1+a+a^2+\cdots+a^\gamma\). With \(a=0.8\) and \(\gamma=3\), the value is 2.952. The terms represent the successive opportunities to extend the accepted prefix, together with the correction or bonus event.

If target verification costs C_v, each draft step costs C_d and cache/coordination work costs C_o, a rough time per emitted token is(C_v+gamma*C_d+C_o)/2.952 under those assumptions. Compare that with an actual ordinary target-decode measurement. A high acceptance rate alone does not establish speedup if the draft or coordination is expensive, if verification does not exploit parallelism, or if batching changes the critical path.

Real acceptance depends on the prefix and can be correlated across positions. Device kernels, memory bandwidth, request length and batch occupancy affect latency. The tiny probability-table program does not measure those effects. Its exactness proof and cache tests establish algorithmic ingredients; a serving benchmark must supply the performance evidence separately.

## Design decisions and when to use this method

Use speculative decoding when a cheaper draft model achieves enough agreement with the target and the serving stack can exploit parallel verification. Measure acceptance length, draft cost, target verification cost, cache work, batch effects and end-to-end latency. A high acceptance rate alone does not prove a speedup if draft or coordination overhead dominates.

Do not replace the exact correction rule with argmax agreement or sample-from-target fallback while claiming distribution preservation. Keep token vocabularies and effective sampling policies aligned. Exact distribution preservation does not mean identical random samples under a different RNG schedule. This CPU reference establishes algebra and cache-state behavior only; it does not measure GPU kernels, distributed serving or production quality.

## Derivation and shape trace

At one fixed prefix, sample a draft token X from q. Its accepted mass at token i is \(q_{i}\cdot \min(1,\frac{p_{i}}{q_{i}})=\min(p_{i},q_{i})\). Define \(R=1-\sum_i\min(p_i,q_i)\). Since both distributions sum to one, \(R=\sum_i\max(p_i-q_i,0)\). For \(R>0\), use residual \(r_{i}=\frac{\max(p_{i}-q_{i},0)}{R}\). Then

\[
P(\text{emitted}=i)=\min(p_i,q_i)+Rr_i=p_i.
\]

For \(p=(0.5,0.3,0.2)\) and \(q=(0.2,0.5,0.3)\), accepted mass is (.2,.3,.2), rejection mass is .3, and the residual is (1,0,0). Sampling directly from p after rejection would instead produce (.35,.39,.26), which is not p. The residual correction is essential.

For gamma proposals, every draft and target distribution must refer to the same accepted prefix at that position. Stop verification at the first rejection. If all gamma proposals are accepted, sample the extra token from the next target distribution, not from a zero-mass residual. The target can verify causal logits for a proposed block in an appropriately batched forward pass; this reference evaluates tiny probability tables individually for clarity.

Exactness concerns the declared target sampling distribution, including its temperature or filtering policy. It does not promise identical individual samples under a different random-number schedule. Numerical precision, vocabulary alignment, termination and cache state remain implementation contracts that require tests.

## Preserve the target law while changing the execution schedule

At one fixed prefix, let p be the target distribution and q the draft distribution over the same token identities. A draft token i is proposed with probability q_i and accepted with probability \(\min(1,\frac{p_{i}}{q_{i}})\). The resulting accepted mass is min(p_i,q_i). A token with \(q_{i}=0\) cannot be proposed by a valid draw from q, so the acceptance ratio need not be evaluated there. If \(p_{i}>0\) while \(q_{i}=0\), that target mass can still be produced by the correction distribution after rejecting another draft proposal.

Let \(R=\sum_i\max(p_i-q_i,0)\). Because both distributions have unit mass, the total positive difference equals the total negative difference in magnitude, so \(R=\frac12\sum_i|p_i-q_i|\), their total variation distance. Accepted probability is 1-R. When \(p=q\), \(R=0\) and every valid draft proposal is accepted. The residual distribution is undefined in that case because its total mass is zero; it is never needed on a valid rejection branch. Creating an arbitrary residual for equal distributions would conceal a control-flow mistake.

For \(p=[0.5,0.3,0.2]\) and \(q=[0.2,0.5,0.3]\), accepted mass is[.2,.3,.2]. Rejection mass is.3 and the residual places all its mass on token 0. Combining accepted mass with.3 times that residual recovers p exactly. If rejection instead sampled directly from p, the result would be[.2,.3,.2]+.3*[.5,.3,.2]=[.35,.39,.26], which differs from the target. An acceptance check followed by an intuitive "fallback to target" is therefore not the exact algorithm.

The random-draw contract matters at boundaries. Sampling from cumulative probabilities uses half-open intervals, so a draw exactly on one cumulative boundary belongs to the next interval. A zero-probability token must never be chosen merely because two adjacent cumulative values coincide. Likewise, acceptance uses a uniform draw in[0,1) and the strict comparison \(u<a_{i}\). Floating-point normalization and cumulative rounding need deliberate treatment, but a tolerance must not silently admit a negative probability or change token identity.

A block round proposes several tokens under successive draft prefixes. Verification accepts a contiguous prefix. Before the first rejection, the accepted prefix matches the proposal prefix used to compute each stored q distribution, so the one-step correction applies at that position. At the first rejection, later draft proposals were conditioned on an uncommitted token and are discarded. Continuing to accept that suffix would compare probabilities under the wrong context. If the whole proposal block is accepted and budget remains, a bonus token comes from the target's next conditional distribution.

A simple latency calculation illustrates why acceptance alone is insufficient. Assume, only for this calculation, that each proposal has the same independent acceptance probability a and that at most gamma proposals are made. Ignoring EOS and a binding token cap, expected emitted tokens per round are \(1+a+a^2+\cdots+a^\gamma\): the mandatory correction/bonus contribution and the successive accepted-prefix opportunities. With \(a=0.8\) and \(\gamma=3\) this is 2.952. If target verification cost is C_v, each draft step costs C_d and coordination/cache work costs C_o, a rough per-token time is(C_v+gamma*C_d+C_o)/2.952. Compare that with measured ordinary target decode cost, not with an assumed cost of zero for the draft. Real acceptance is prefix-dependent, and batch/device effects can violate this simplified cost model.

Cache state must match committed tokens exactly. Suppose an old prefix has length5, three draft tokens were appended speculatively, and only the first was accepted before a correction. Keep the first6 positions, discard the unaccepted two, then append the correction at position 6. The resulting committed length is 7. Keeping rejected K/V entries, retaining their position offsets or appending the correction after the discarded suffix changes the next attention context. A correct probability formula cannot repair that state error.

Target and draft caches belong to different models. Even when their token vocabularies match, their layer counts, projected keys, values, positional layouts and dtypes may differ. They should each be restored or rebuilt from the same committed token prefix using their own model computation. Copying raw target K/V tensors into the draft cache is not justified by shared token IDs. The tiny cache in this lesson makes token/position-dependent values observable, but it does not implement a production multilayer decoder cache.

Termination is part of the distribution contract. An accepted EOS ends the sequence and prevents a bonus token. A hard output cap can stop a round even without EOS and defines truncation of the generation process. Both target and draft probabilities must already include the intended temperature and filtering policy at the same prefix. Using raw logits for one and a top-p filtered distribution for the other while claiming to preserve a different target sampling policy is a mismatch of laws.

**Interview reasoning:** "Does exact speculative sampling return exactly the same text as ordinary sampling with the same seed?" It preserves the target distribution under its assumptions, not necessarily a draw-for-draw sequence from a different random-number schedule. Compare exact probability decomposition and state transitions first. Frequency experiments can supplement those checks, while a speed claim requires measured serving behavior. The [speculative decoding](https://arxiv.org/abs/2211.17192) and [speculative sampling](https://arxiv.org/abs/2302.01318) papers establish the algorithmic context; this fixture verifies the small numerical and cache contracts.

## Vocabulary and concepts

**Draft distribution:** The proposal model's next-token probabilities at a specific prefix.

**Acceptance probability:** The correction rulemin(1,p_i/q_i) for a sampled draft token.

**Residual distribution:** Normalized positive mass from p-q used after rejection.

**Bonus token:** A target-sampled next token after an entirely accepted proposal block.

**Cache rollback:** Removing state for unaccepted speculative positions before continuing.

## Syntax anatomy and reasoning sequence

Validate finite nonnegative probability vectors with unit mass. Sample using an explicit draw in[0, 1), with half-open cumulative intervals. Compute acceptance ratios only where q is positive; a zero-q token cannot be a valid draft sample. The round helper stores the draft distributions at their proposal prefixes, then verifies in order and stops at the first rejection or accepted EOS. A TinyCache stores position-dependent key vectors and value vectors so rollback can be checked against a fresh reconstruction.

Sampling builds the cumulative distribution on positive-support entries only, then maps the selected index back to the original token ID. The final cumulative boundary is assigned to the last positive entry, so floating-point rounding cannot create a tail interval for a zero-probability token. Half-open interval behavior is retained at internal boundaries.

## Worked example / walkthrough

### Example A: Prove one-step distribution preservation

The equality is an exact probability decomposition up to floating-point arithmetic. It is stronger than observing approximate frequencies in a finite simulation.

```python
import numpy as np
def probabilities(value):
    value=np.asarray(value,dtype=np.float64)
    if value.ndim!=1 or not len(value) or not np.isfinite(value).all() or (value<0).any() or not np.isclose(value.sum(),1,rtol=0,atol=1e-12): raise ValueError('finite nonnegative unit probability vector required')
    return value/value.sum()
def draw(probability,uniform):
    probability=probabilities(probability)
    if not np.isfinite(uniform) or not 0<=uniform<1: raise ValueError('draw must be in [0,1)')
    support=np.flatnonzero(probability>0)
    cumulative=np.minimum(np.cumsum(probability[support]),1.)
    cumulative[-1]=1.
    selected=np.searchsorted(cumulative,uniform,side='right')
    return int(support[selected])
def correction(p,q):
    p,q=probabilities(p),probabilities(q)
    if p.shape!=q.shape: raise ValueError('matching vocabulary required')
    ratio=np.divide(p,q,out=np.zeros_like(p),where=q>0); acceptance=np.minimum(1.,ratio)
    positive=np.maximum(p-q,0.); rejection=float(positive.sum())
    return acceptance,None if rejection==0 else positive/rejection,rejection
def one_step(p,q,token,acceptance_draw,residual_draw):
    p,q=probabilities(p),probabilities(q)
    if p.shape!=q.shape or type(token) is not int or not 0<=token<len(q) or q[token]<=0: raise ValueError('token must have draft support')
    if not 0<=acceptance_draw<1: raise ValueError('acceptance draw in [0,1) required')
    acceptance,residual,rejection=correction(p,q)
    if acceptance_draw<acceptance[token]: return {'token':token,'accepted':True}
    if residual is None: raise ValueError('rejection impossible for equal distributions')
    return {'token':draw(residual,residual_draw),'accepted':False}
def speculative_round(prefix,target,draft,draft_draws,acceptance_draws,extra_draw,budget,eos=None):
    if type(budget) is not int or budget<=0 or not draft_draws: raise ValueError('positive budget and proposals required')
    proposals=[]; distributions=[]
    for uniform in draft_draws[:budget]:
        distribution=probabilities(draft(list(prefix)+proposals)); token=draw(distribution,uniform); distributions.append(distribution); proposals.append(token)
        if token==eos: break
    if len(acceptance_draws)<len(proposals): raise ValueError('one acceptance draw per proposal required')
    accepted=[]
    for index,token in enumerate(proposals):
        p=probabilities(target(list(prefix)+accepted)); result=one_step(p,distributions[index],token,acceptance_draws[index],extra_draw)
        if not result['accepted']: return {'tokens':accepted+[result['token']],'accepted_count':len(accepted),'rejected':True,'proposals':proposals}
        accepted.append(token)
        if token==eos: return {'tokens':accepted,'accepted_count':len(accepted),'rejected':False,'proposals':proposals}
    count=len(accepted)
    if count<budget: accepted.append(draw(target(list(prefix)+accepted),extra_draw))
    return {'tokens':accepted,'accepted_count':count,'rejected':False,'proposals':proposals}
class TinyCache:
    table=np.array([[1.,0.],[0.,1.],[1.,1.]])
    def __init__(self,tokens):
        self.tokens=[]; self.keys=np.empty((0,2)); self.values=np.empty((0,2))
        for token in tokens: self.append(token)
    def append(self,token):
        if type(token) is not int or not 0<=token<len(self.table): raise ValueError('token outside fixture vocabulary')
        position=len(self.tokens); value=self.table[token]; key=value+position*np.array([.2,-.1]); self.tokens.append(token); self.keys=np.vstack([self.keys,key]); self.values=np.vstack([self.values,value])
    def truncate(self,length):
        if type(length) is not int or not 0<=length<=len(self.tokens): raise ValueError('invalid cache rollback length')
        self.tokens=self.tokens[:length]; self.keys=self.keys[:length].copy(); self.values=self.values[:length].copy()
    def output(self):
        if not self.tokens: raise ValueError('nonempty cache required')
        score=self.keys@self.keys[-1]/np.sqrt(2); mass=np.exp(score-score.max()); return mass/mass.sum()@self.values
def apply_round(cache,old_length,result):
    cache.truncate(old_length+result['accepted_count'])
    for token in result['tokens'][result['accepted_count']:]: cache.append(token)
p=np.array([.5,.3,.2]); q=np.array([.2,.5,.3]); acceptance,residual,rejection=correction(p,q)
accepted_mass=q*acceptance
np.testing.assert_allclose(accepted_mass,[.2,.3,.2],atol=1e-12,rtol=0)
np.testing.assert_allclose(rejection,.3,atol=1e-12,rtol=0); np.testing.assert_allclose(residual,[1,0,0],atol=1e-12,rtol=0)
np.testing.assert_allclose(accepted_mass+rejection*residual,p,atol=1e-12,rtol=0)
```

**Expected:** accepted mass[.2, .3, .2]; rejection .3; residual[1, 0, 0]; combined mass p.

## Controlled case study

A decoder uses the correct acceptance formula but diverges after a rejection. Its target cache still contains the rejected proposal and a later draft token, so the next query sees the wrong prefix and position. Rebuilding a fresh cache from committed tokens exposes the error. Roll both model caches back to old_prefix_length+accepted_count, then process the correction token through each model independently. Raw K/V tensors from different models are not interchangeable.

## Common pitfalls and diagnosis

For a distribution mismatch, compare accepted mass and corrected rejection mass per token before examining long generated strings. Check vocabulary identity, effective temperature/filtering, q-support and the prefix attached to every saved proposal distribution. A same-seed string mismatch is not by itself evidence of a changed law.

For divergence after rejection, compare committed token IDs, cache length, positions, keys, values and the next attention output against a fresh reconstruction. Check EOS and the remaining token budget before producing a bonus. The fixture demonstrates exact small-distribution arithmetic and a concrete cache rollback; it does not run an optimized target/draft serving stack or establish hardware speedup.
