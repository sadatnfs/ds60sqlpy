# The inner Newton solver and its controls

Start with: tmb-034, tmb-014.

Outcome: Relate inner-optimizer controls to curvature and numerical failure modes.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter takes one Newton step on a quadratic and shifts an indefinite Hessian. In the separately prepared [owned project](../projects/tmb-local/README.md), `tests/public_api.R` solves a sparse quadratic with `TMB::newton` and reads a model's controls with `TMB::newtonOption(obj)`; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

TMB exports `newton`, the generalized Newton optimizer used for its inner problem, and `newtonOption` to inspect or change inner controls for an objective. Their many arguments serve different purposes: iteration and gradient tolerances, step-size controls, trace behavior and modified-curvature search. They are not interchangeable ways to demand “more accuracy.”

An ordinary Newton update solves \(H d=g\) and sets \(u_{new}=u-\alpha d\). For a positive-definite quadratic with an exact solve and \(\alpha=1\), one step reaches the minimum. For an indefinite Hessian, that direction need not decrease the objective. The documented smart-search approach modifies curvature using a quadratic penalty around the current expansion point.

## Key terms

- **Newton step:** The update that solves \(Hd=g\) and moves \(u\) to \(u-\alpha d\); for a positive-definite quadratic with \(\alpha=1\) it reaches the minimum in one step.
- **newton:** TMB's exported generalized Newton optimizer for the inner problem, which expects compatible gradient and sparse Hessian functions.
- **newtonOption:** The function that inspects or changes one objective's inner-optimizer controls, which should be saved with the fit record.
- **Smart search:** A strategy that adds a quadratic penalty, effectively a diagonal shift, to an indefinite Hessian so the local step decreases the objective.

### Worked case A: a stable quadratic step

The companion solves a two-dimensional positive-definite quadratic from a distant start. It prints the original gradient, step and exact optimum. A bounded local refinement after a successful outer fit, as used in our panel example, is justified by this kind of curvature calculation and strict acceptance checks, not by replacing the original optimizer status.

### Worked case B: indefinite curvature

The companion constructs a Hessian with one negative eigenvalue and shows how adding a diagonal shift can make it positive definite. This only stabilizes a local numerical step; it does not prove the unmodified objective has a useful global minimum. Inspect the original function and repeat the numerical analysis after any proposed move.

`newtonOption(obj, ...)` changes the particular model object's inner controls. Save the configuration with the fit records. The raw `newton` API expects compatible gradient and Hessian functions, often sparse matrices; a teaching wrapper should not pass arbitrary dense or misshaped values and assume the optimizer repairs them.

The native API probe also exposed a representation detail: a diagonal Matrix object did not provide the sparse Cholesky methods expected by the raw helper. The corrected probe uses a symmetric compressed sparse matrix created by `Matrix::sparseMatrix(..., symmetric=TRUE)` and checks the known optimum. Matrix dimensions alone do not establish the required native sparse representation.

### Answered discussion

**Should I set `maxit=1` for speed?** Only for a proven quadratic inner objective with sufficiently accurate linear algebra, not for every latent model. **Can tracing be disabled without losing evidence?** Yes during a routine run if final diagnostics remain recorded; retain detailed traces when diagnosing a failure. **Does a small step imply convergence?** A solver can take small steps because of poor scaling, clipping or an indefinite basin. Check gradient, curvature and actual objective change.

Read [newton and newtonOption](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The function's broad control surface is documented in the inventory; the current project uses a deliberately narrow subset with explicit evidence.

### Worked case C: one Newton step on the quadratic

The companion's objective is \(\tfrac12u^\top Hu-b^\top u\) with \(H=\begin{pmatrix}3&0.5\\0.5&2\end{pmatrix}\), \(b=(1,-2)\) and start \(u=(8,-7)\). The gradient is \(Hu-b\):

\[
g=(3\cdot8-0.5\cdot7-1,\;0.5\cdot8-2\cdot7+2)=(19.5,\,-8).
\]

```text
gradient  19.5        -8
step       7.478261   -5.869565
updated    0.521739   -1.130435
exact      0.521739   -1.130435    (closed-form values, rounded)
```

The exact optimum is \(H^{-1}b=(12,-26)/23\), because \(\det H=5.75\). A single full step lands on it, and the companion asserts agreement to \(10^{-12}\). This is the property that justifies `maxit=1` for a Gaussian inner problem: when the joint objective is exactly quadratic in \(u\), the first Newton step is the last. For a Poisson or binomial latent model, the same step would only approximate the mode, and the gradient after one step would remain nonzero.

The indefinite matrix \(\begin{pmatrix}1&2\\2&1\end{pmatrix}\) has eigenvalues \(-1\) and 3. Along \((1,-1)/\sqrt2\), the curvature is \(-1\), so a Newton step moves toward a saddle rather than a minimum. Adding \(2I\) shifts both eigenvalues by 2, giving 1 and 5, and the shifted system is positive definite. The shifted step is shorter and points downhill, but it is no longer the Newton step of the original function; a solver that keeps needing a shift at the reported optimum is reporting a saddle or a flat direction, not a minimum.

### What to record from `newtonOption`

A reproducible fit should store the inner settings next to the outer result:

```r prelude=../projects/tmb-local/R/api.R
obj <- make_objective("random_intercept",
  list(y = c(1.2, 0.8, 2.1, 2.5), group = c(0, 0, 1, 1)),
  list(beta = 0, log_sigma = 0, log_tau = 0, u = c(0, 0)),
  random = "u"
)
inner <- TMB::newtonOption(obj) # inspect current inner controls
TMB::newtonOption(obj, maxit = 1) # only for a proven Gaussian inner problem
str(inner[c("maxit", "tol", "tol10")])
```

The listed names are illustrative selections; inspect the returned list in the prepared R session and save whichever controls it contains. If a later run changes `maxit` and the fitted variance components move, the saved configuration lets a reviewer see that the change was in the inner solver rather than in the data.

### Base-R companion (runs in the classroom)

```r
H <- matrix(c(3, .5, .5, 2), 2, 2);b <- c(1, -2);u <- c(8, -7)
g <- drop(H %*% u) - b;step <- solve(H, g);updated <- u - step
print(list(gradient = g, step = step, updated = updated, exact = solve(H, b)));stopifnot(max(abs(updated - solve(H, b))) < 1e-12)
bad <- matrix(c(1, 2, 2, 1), 2, 2)
print(list(original = eigen(bad, symmetric = TRUE)$values, shifted = eigen(bad + 2 * diag(2), symmetric = TRUE)$values))
```
