# AFModel as a historical design case

Start with: tmb-016, statistics-026.

Outcome: Translate a historical modeling architecture into an original, inspectable panel example.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter tabulates a decaying trend with panel offsets and AR(1) residual forecasts. The separately prepared [owned project](../projects/tmb-local/README.md) compiles the trend and autoregressive pieces as `models/panel_trend.cpp` and `models/ar1.cpp`; no AFModel code is compiled; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

The open-source [AFModel repository](https://github.com/sadatnfs/AFModel) illustrates an important idea: a forecasting system can combine structural trends, explanatory variables, group effects and autoregressive residual behavior in a custom TMB objective. Its public source includes choices for differencing, fixed effects, group intercepts, random coefficients and autoregression. Understanding those mechanisms is more useful than copying a large historical implementation unchanged.

This course uses independently written synthetic models and neutral sensor-panel labels. It does not import historical datasets, environment paths, organization metadata or source routines. AFModel's published `AFModel/LICENSE.md` identifies MIT terms; TMB and the other cited projects have their own licenses. Scholarly and design attribution remain separate from code reuse.

## Key terms

- **Forecasting components:** The structural trend, explanatory variables, group effects and autoregressive residuals that a forecasting objective combines.
- **Historical model review:** Studying an older system such as AFModel for its design ideas while writing new code and data instead of copying its implementation.
- **Temporal validation:** Fitting on earlier periods and scoring on later held-out periods so evaluation mimics real forecasting.
- **Leakage:** Letting information from the evaluation period influence fitting, which makes forecast accuracy look better than it is.

### Worked case A: decompose a forecast

Write \(y_{gt}=m(t;\theta)+b_g+r_{gt}+\epsilon_{gt}\). The structural mean explains the common trend. The group effect represents a persistent offset. The residual state represents temporally evolving deviations. Observation noise represents remaining measurement variation. The companion constructs these components explicitly and prints their sum for two original synthetic panels.

This decomposition makes assumptions visible. A persistent group offset and an AR process with correlation near one can compete to explain the same low-frequency pattern. A large parameter set is not automatically a richer scientific explanation if the observed history cannot distinguish its components.

### Worked case B: forecasting residuals without leakage

At the final training time, an AR(1) residual forecast is \(\phi^h r_{gT}\). It depends on residuals computed from the fitted structural model using training data. Recomputing that model with future observations before assessing the forecast leaks information. The companion predicts three future residual means for each group using only its last training residual.

The owned compiled capstone currently uses a nonlinear trend plus independent group intercepts. The separate AR1 template studies latent residual dependence. Combining both structures into one larger model is an extension that requires new identifiability and integration checks; the course does not claim the current panel template silently includes every historical AFModel option.

### Diagnostics and answered discussion

**Why not automatically port all old flags?** Each flag expands the model space and can create incompatible combinations. Start with explicit statistical targets and qualified examples. **Does a lagged observed outcome equal a latent autoregressive residual?** No. A regression on lagged outcomes can have different measurement-error and initial-condition assumptions. **Can a model with many groups be split by group?** Only if the latent and parameter ownership contract permits it; shared fixed parameters still require one coherent objective.

Neal Marquez's [ar.matrix](https://github.com/nmmarquez/ar.matrix) offers another historical perspective on precision-based autoregressive simulation. Chapter 15 derives its relevant mathematical ideas independently. The next chapters modernize the Python-to-R boundary without copying the older PyMB implementation.

### Worked case C: reading the companion's component table

The structural trend is \(3e^{-0.5t}+1\), so the first frame's `trend` column runs from 4 at time 0 through 2.819592, 2.103638, 1.669390 and 1.406006 to 1.246255 at time 5. Panel A subtracts 0.4 and adds its residuals; panel B adds 0.4 and its residuals:

```text
time  trend      panel_a    panel_b     (closed-form values, rounded)
0     4.000000   3.900000   4.200000
1     2.819592   2.619592   3.119592
2     2.103638   1.603638   2.603638
3     1.669390   1.369390   2.269390
4     1.406006   1.056006   1.906006
5     1.246255   0.866255   1.686255
```

The gap between the panels is 0.8 plus the residual difference, so it is 0.3 at time 0 and 0.82 at time 5. A model with only a group intercept would see this gap move by half a unit over six times and could explain it only through residual noise. A model with an AR residual near one could instead absorb most of the 0.8 offset as a persistent residual, leaving a smaller fitted intercept. Panel A's residuals average 0.095 and panel B's average 0.023, so over this short window some of the residual signal is indistinguishable from an offset. That competition is the AFModel lesson in miniature: offsets and slow residual dynamics need longer histories or priors to separate.

### The three-step residual forecast

The second frame scales each panel's last training residual by \(0.6^h\). Panel A's 0.02 becomes 0.012, 0.0072 and 0.00432; panel B's 0.04 becomes 0.024, 0.0144 and 0.00864. Both residual forecasts decay geometrically toward zero, so by the third step each panel's forecast is essentially trend plus offset. In a compiled version that combined `panel_trend.cpp` with the AR1 latent block, the last residual would be a latent state with its own uncertainty, and the forecast uncertainty would include both \(\tau^2(1-\phi^{2h})\) from future innovations and the posterior variance of that last state. Using the observed last residual as if it were known exactly understates forecast uncertainty at short horizons, where its weight \(\phi^h\) is largest.

### Base-R companion (runs in the classroom)

```r
time <- 0:5; trend <- 3 * exp(-.5 * time) + 1
residual_a <- c(.3, .2, -.1, .1, .05, .02)
residual_b <- c(-.2, -.1, .1, .2, .1, .04)
print(data.frame(time = time, trend = trend, panel_a = trend - .4 + residual_a, panel_b = trend + .4 + residual_b))
phi <- .6; horizon <- 1:3
print(data.frame(horizon = horizon, panel_a_residual = phi^horizon * tail(residual_a, 1), panel_b_residual = phi^horizon * tail(residual_b, 1)))
stopifnot(all(abs(phi^horizon * tail(residual_a, 1)) < abs(tail(residual_a, 1))))
```
