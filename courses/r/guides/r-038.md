## Outcome and mechanism

Compute and reconcile conditional probabilities from a finite original table without confusing the conditioning direction.

A finite probability table makes the population and denominator visible. The joint cells describe combinations of two variables, such as segment and alert status. Marginal probabilities sum over one variable. A conditional probability restricts the population first, then renormalizes within that selected event.

Conditioning direction matters. The fraction of alerted records within segment A is not generally the fraction of segment A among alerted records. The first denominator counts all A records; the second counts all alerted records. This difference is often hidden when both quantities are described vaguely as an accuracy or likelihood.

Bayes rule follows from the same joint table: P(A given alert) equals P(alert given A) times P(A), divided by P(alert), when the alert event has positive probability. It is not a separate source of evidence. A changed base rate can change the reverse conditional probability even when segment-specific alert rates remain fixed.

These synthetic counts describe the admitted population. Interpreting them as estimates for another population requires sampling and stability assumptions. A zero denominator makes a conditional probability undefined, not automatically zero. Keep exact counts beside proportions and use an explicit missing result or rejection for an impossible conditioning event.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Joint probability | Probability assigned to a combination of outcomes. |
| Marginal probability | Probability after summing over another variable. |
| Conditional probability | Probability within an explicitly selected event. |
| Bayes rule | A relationship reversing conditioning through joint and marginal probabilities. |

## Read the syntax

Use matrix row/column names to state event meaning, rowSums/colSums for margins, and an explicit selected total for a conditional denominator. In math, \(P(A\mid B)=P(A\cap B)/P(B)\) when \(P(B)>0\).

## Worked examples

### Example 1: Reverse conditionals use different denominators

```r
counts <- matrix(c(30, 70, 10, 90), nrow = 2, byrow = TRUE, dimnames = list(segment = c("A", "B"), alert = c("yes", "no")))
alert_given_a <- counts["A", "yes"] / sum(counts["A", ])
a_given_alert <- counts["A", "yes"] / sum(counts[, "yes"])
stopifnot(alert_given_a == 0.3, a_given_alert == 0.75)
print(c(alert_given_a = alert_given_a, a_given_alert = a_given_alert))
```

**Expected observation:** 0.3 versus 0.75.

Thirty of one hundred A records are alerted, while thirty of forty alerted records are A. Both calculations are correct for different questions.

### Example 2: Reconstruct the reverse conditional

```r
p_a <- 0.5
p_alert_a <- 0.3
p_alert_b <- 0.1
p_alert <- p_alert_a * p_a + p_alert_b * (1 - p_a)
posterior <- p_alert_a * p_a / p_alert
stopifnot(isTRUE(all.equal(p_alert, 0.2)), isTRUE(all.equal(posterior, 0.75)))
print(c(alert_probability = p_alert, a_given_alert = posterior))
```

**Expected observation:** Alert probability 0.2; reverse conditional 0.75.

The total alert probability combines both segments. Bayes rule reconstructs the same finite-table conditional rather than introducing new observations.
