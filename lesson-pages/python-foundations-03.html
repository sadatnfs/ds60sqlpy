Turn Messy Text into Trustworthy Records#

Vocabulary and concepts#

A CSV reader gives you text, even when a column is supposed to represent a quantity. Cleaning is the translation from raw representation to a declared meaning. It should be possible to explain what changed and what was rejected. Imagine a receiving desk: every incoming parcel gets either an acceptance receipt or a reason for rejection. A parcel must never disappear simply because it looked inconvenient.

  • Raw record: the original field values before any cleaning decision.
  • Normalization: a permitted representation change, such as trimming spaces around an identifier.
  • Validation: checking whether a value satisfies a declared rule.
  • Identity: the field used to decide whether two records describe the same entity or event. Here it is a case-sensitive trimmed id string.
  • Rejection: a record retained separately with a specific failed rule.
  • Reconciliation: an independent accounting check across pipeline stages.

Our input contract is a dictionary containing string fields id and quantity. Identifiers must remain nonempty after stripping outer whitespace. Quantities may contain outer whitespace and an optional leading plus sign, but must parse as integers greater than or equal to zero. Decimal text, missing fields, non-string fields, and negative values are rejected. This is a bounded teaching policy; other domains may legitimately allow negatives. The first valid record for an identifier wins. Invalid earlier rows do not reserve that identifier, because they never became accepted records.

Zero means a known count of none. Empty text means no usable representation was supplied. Invalid text such as many is a third state. Mapping all three to zero makes an aggregate look complete while losing the reason for missing information. Preserve those distinctions in both returned data and tests.

Worked example / walkthrough#

Example A: parse only the boundary that can fail#
def parse_quantity(raw):
    if not isinstance(raw, str) or not raw.strip():
        raise ValueError("quantity is missing or not text")
    try:
        quantity = int(raw.strip())
    except ValueError as exc:
        raise ValueError("quantity is not an integer") from exc
    if quantity < 0:
        raise ValueError("quantity is negative")
    return quantity


assert parse_quantity(" 0 ") == 0
assert parse_quantity("+4") == 4

raw is the function parameter. isinstance checks the representation before calling a string method. The narrow try block wraps only conversion; raise ... from exc keeps the original cause for diagnosis. Returning zero is correct for the text zero, but not a fallback for a failed conversion. Expected observation: both assertions pass; parse_quantity("4.5") raises ValueError instead of quietly rounding.

Example B: copy before changing representation#
raw = {"id": " A-1 ", "quantity": "2"}
cleaned = {"id": raw["id"].strip(), "quantity": int(raw["quantity"])}
assert raw["id"] == " A-1 "
assert cleaned == {"id": "A-1", "quantity": 2}
print(raw, cleaned)

Expected observation: the raw dictionary retains its spaces while cleaned contains a normalized identifier and integer. Creating a new dictionary preserves original evidence. Assigning cleaned = raw would make both names refer to the same mutable dictionary; a later edit would change your evidence. This differs from the immutable integer reassignment in the first on-ramp.

Make rejection actionable#

Use a one-based source row number and a stable reason such as duplicate id or quantity is negative. A row number is a location in this input, not a permanent identity across reordered files. Preserve a shallow copy of the raw dictionary here because the input values are simple strings. If nested lists were allowed, shallow copying would not isolate changes inside those lists. Document the actual data shape instead of promising universal deep copying.

Only add an identifier to seen after all validation succeeds. That order makes first-valid-wins precise and avoids rejecting a good replacement for an invalid earlier row. Keep accepted rows in source order. Rejection order also follows source order, which makes a report easier to compare with its input. The count check input_count == accepted_count + rejected_count catches lost rows, but cannot prove each accepted quantity is correct. Add value checks and input-unchanged checks as separate evidence.

Self-check#

Explain why zero differs from missing and invalid input. Reconstruct the first-valid-wins sequence using a new identifier. Show why count reconciliation alone cannot detect accidentally changing quantity two into twenty. Give a second assertion that would catch that defect without opening the solution.

Common pitfalls#

If raw evidence changes after cleaning, compare object identities and inspect assignments that reuse dictionaries. If a valid replacement is called a duplicate, locate the point where seen is updated. If counts reconcile but totals are wrong, inspect accepted integer values and compare with a manual small-case calculation. If None causes AttributeError, validate the field type before calling .strip(). Do not catch that programming mistake globally.

Next step#

Use these boundaries in the first independent data investigation, then carry the same reasoning into pandas cleaning and schema validation. A library may make conversion faster; it cannot choose your missing-value or identity policy.

Turn Messy Text into Trustworthy Records: solution reasoning#

Stable ID: python-foundations-03.

Read the guide and attempt the learner artifact first. The executable solution is a comparison implementation. It does not certify your changed program merely because its own demonstration succeeds. Copy the acceptance cases into your attempt, then change one input without changing the intended policy.

The reference separates parsing, record validation, and batch policy. That makes a failed rule visible and lets each layer have a small test. The first two functions raise ValueError for an input that violates the declared contract. The batch layer catches that specific signal and records the failed row instead of losing the entire batch. Unexpected errors still escape.

rows = [{"id": "A", "quantity": "2"}, {"id": "B", "quantity": "many"}]
# After cleaning: accepted count 1, rejected count 1, accepted total 2.
# Independent accounting: 2 == 1 + 1.

Record order is preserved. The solution copies raw dictionaries into rejection records and creates fresh canonical dictionaries for accepted rows. It makes no claim that mutable nested data would be fully isolated by a shallow copy.

Exercise 1. Define the policy before coding#

The parser first checks that the supplied object is a nonempty string after whitespace removal. Conversion then distinguishes integer text from decimal or arbitrary words. A negative integer is syntactically valid but violates the quantity rule, so it gets a different reason. Zero is valid and is returned as zero. The reference deliberately accepts a leading plus sign because Python integer conversion accepts it and our contract discloses it. If a stricter external format is required later, add a lexical rule and tests rather than assuming this parser enforces one.

Exercise 2. Keep raw records unchanged#

Normalize the identifier with strip and parse the quantity into a new dictionary. Keep the original object untouched. The input contains the only direct evidence that surrounding spaces existed, so mutating it would remove information useful for troubleshooting. Compare both canonical values and original values in a test; checking only the returned result would miss unwanted mutation. These records contain simple text fields, which is why a shallow dictionary copy is enough for rejection evidence. That argument must be reconsidered if the record schema changes.

Exercise 3. Make missing identity visible#

Absent keys are inspected with get, then validated as text with nonempty content. An absent key returns None and is rejected instead of becoming the displayed string "None". Case-sensitive identity means A and a remain distinct. That is a policy choice, not a universal rule for identifiers. Trimming normalizes outer spaces without changing internal characters or case. If a future source uses case-insensitive identities, treat that as a deliberate migration because previously separate records may collide. Preserve the original values while investigating those collisions.

Exercise 4. Account for every row#

For each source row, use enumerate with start one to record a human-readable row number. A valid canonical record goes into accepted; a validation failure goes into rejected with its raw copy and reason. Quantities two and zero sum to two, while many is rejected at row two. The three-way evidence checks count conservation, value correctness, and reject location independently. A program that copies one row twice could accidentally pass a total-only check, so preserve row counts and identities as well as aggregate values.

Exercise 5. Enforce first valid wins#

The seen set is updated only after a valid record passes all checks. A/many fails conversion and therefore never reserves A. A/2 becomes the first valid record and is accepted. A/3 is then rejected as a duplicate. This explicitly implements first-valid-wins, which differs from first-row-wins and last-row-wins. The original third row stays visible in rejected evidence. If the two valid rows disagree, the policy does not claim the first is factually correct; it provides deterministic behavior and enough evidence to review the conflict.

Exercise 6. Reject wrong field types#

A None quantity violates the text representation boundary. A numeric identifier violates the identifier representation boundary. Converting arbitrary values with str would hide those distinctions, and int(True) would create another surprising coercion if booleans were accepted. The reference uses explicit string checks so its numeric policy only operates on declared text input. Tests should assert that both invalid records are rejected and that raw values remain None and integer three, respectively. That catches accidental coercion even if the final counts still reconcile.

Exercise 7. Check empty and all-invalid batches#

An empty input has zero accepted rows and zero rejected rows. A batch containing two invalid rows has zero accepted rows and two rejected rows. Both accepted totals are zero, but they describe different situations and must retain different counts. Summing with a zero start makes the intended identity element explicit and avoids a reduction that crashes on empty input. A report should show counts beside totals so a reader cannot mistake a zero quantity after total rejection for a successfully observed zero quantity.

Exercise 8. Transfer to stock adjustments#

A signed adjustment stream models a different meaning: negative quantities can be legitimate returns. Keep a separate parser or explicit policy parameter instead of quietly changing the shared nonnegative contract. Both versions should still reject missing input and decimal text when exact integers are required. Write normal, zero, negative, and invalid cases for each policy. The key learning is that validation follows meaning. There is no single universal cleaning rule that correctly handles inventory counts, financial adjustments, temperatures, and event counters without domain-specific decisions.

If it is, the duplicate policy must change, perhaps to reject every conflicting identity or require an explicit version. Do not describe deterministic order-sensitive behavior as evidence of order independence.

"""Non-mutating text-record boundaries for python-foundations-03."""

from __future__ import annotations


def parse_quantity(raw: object) -> int:
    if not isinstance(raw, str) or not raw.strip():
        raise ValueError("quantity is missing or not text")
    try:
        quantity = int(raw.strip())
    except ValueError as exc:
        raise ValueError("quantity is not an integer") from exc
    if quantity < 0:
        raise ValueError("quantity is negative")
    return quantity


def normalize_record(raw: dict[str, object]) -> dict[str, object]:
    identifier = raw.get("id")
    if not isinstance(identifier, str) or not identifier.strip():
        raise ValueError("id is missing or not text")
    return {"id": identifier.strip(), "quantity": parse_quantity(raw.get("quantity"))}


def clean_rows(
    rows: list[dict[str, object]],
) -> tuple[list[dict[str, object]], list[dict[str, object]]]:
    accepted: list[dict[str, object]] = []
    rejected: list[dict[str, object]] = []
    seen: set[str] = set()
    for row_number, raw in enumerate(rows, start=1):
        try:
            cleaned = normalize_record(raw)
            identifier = str(cleaned["id"])
            if identifier in seen:
                raise ValueError("duplicate id")
            seen.add(identifier)
            accepted.append(cleaned)
        except ValueError as exc:
            rejected.append({"row_number": row_number, "reason": str(exc), "raw": raw.copy()})
    assert len(rows) == len(accepted) + len(rejected)
    return accepted, rejected


if __name__ == "__main__":
    sample: list[dict[str, object]] = [
        {"id": "A", "quantity": "many"},
        {"id": " A ", "quantity": "2"},
        {"id": "A", "quantity": "3"},
        {"id": "B", "quantity": "0"},
    ]
    accepted, rejected = clean_rows(sample)
    assert accepted == [{"id": "A", "quantity": 2}, {"id": "B", "quantity": 0}]
    assert [r["row_number"] for r in rejected] == [1, 3]
    assert sample[1]["id"] == " A "
    print({"accepted": accepted, "rejected": rejected})
