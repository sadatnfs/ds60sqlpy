# js-055: Transitions, interruption and reduced-motion design

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-054`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Implement a bounded transition with completion checks. Defend when to use a static update. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

A transition changes attributes over time rather than setting the final state immediately. Interpolation computes intermediate values, while easing controls the pace along the timeline. Motion can help a reader follow identity through a change, but it can also distract, delay access or imply a continuous process that the data does not represent.

Transitions are asynchronous. Starting one does not mean its final geometry exists on the next line. A newer update may interrupt an earlier transition, so a component must decide whether to finish, replace or cancel work. Awaiting a transition’s completion can reject when it is interrupted; handling that rejection is part of lifecycle correctness.

Reduced-motion preferences should lead to a useful static or immediate update. Do not make animation the only way to discover a value or state change. The reference uses a short bounded transition, respects the media preference and checks the final state after completion.

## Syntax anatomy and mechanism

Name transitions when a component needs a clear interruption channel. Call `.interrupt(name)` before replacing obsolete work. A named transition’s `.end()` returns a promise for completion. The final data state should be stored independently of a partly animated attribute.

For deterministic testing, assert the final value after awaiting the promise, not after guessing a sleep duration. Timing varies across machines and background tabs. The reference does not run an infinite animation loop.

## Worked example / walkthrough

### Worked example 1: Await the actual completion

The mark is already selected.

```javascript
await mark.transition("update").duration(120).attr("cx",300).end();
console.log(mark.attr("cx"));
```

**Expected observation:** 300 after successful completion, rather than an intermediate coordinate.

### Worked example 2: Respect reduced motion

The data update still happens.

```javascript
const reduced=matchMedia("(prefers-reduced-motion: reduce)").matches;
const duration=reduced?0:120;
```

**Expected observation:** The same final chart state with motion disabled when requested.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose a rejected end promise after a new update. Its distinguishing evidence is The earlier transition may have been interrupted. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
