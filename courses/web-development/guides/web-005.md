# web-005: Lists, quotations, code and meaningful text

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-004`

## Learning objectives

Build a study checklist with a code example and glossary. Explain the difference between preserving whitespace and preserving meaning. Use ordered list, unordered list and description list accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Lists express relationships that paragraphs do not. An ordered list describes a sequence where position matters. An unordered list groups peers without requiring order. A description list pairs terms with explanations. These structures help reading tools announce item counts and relationships. A row of hyphens in plain text may look like a list but does not expose that structure.

A quotation identifies borrowed language and should have a source when appropriate. Code identifies literal program text, while pre preserves whitespace. The combination pre and code is useful for multiline snippets. Long lines still need an overflow policy. Never use a quotation element simply to indent text or a list merely to create a visual column.

### Key terms

- **Ordered list:** An `ol` list whose items have a meaningful sequence, such as steps, and are numbered by the browser.
- **Unordered list:** A `ul` list whose items form a set in which changing the order does not change the meaning.
- **Description list:** A `dl` list that pairs terms in `dt` elements with their descriptions in `dd` elements.
- **Quotation:** Words from another source, marked with `blockquote` for a block or `q` for a short inline phrase.
- **Code element:** The `code` element marks a fragment of computer code, and a surrounding `pre` keeps its spaces and line breaks.

## Syntax anatomy and mechanism

A list contains li elements; nested lists belong inside the parent li they elaborate. A description list contains dt terms and dd explanations. A short inline token uses code without pre. Literal less-than signs in displayed code must be escaped because the containing HTML still has to parse correctly.

## Worked example / walkthrough

### Worked example 1: A meaningful sequence

The order is part of the instructions.

```html
<ol>
  <li>Write a prediction.</li>
  <li>Run the example.</li>
  <li>Compare evidence.</li>
</ol>
```

**Expected observation:** A numbered sequence exposes three ordered steps.

### Worked example 2: Code as data

Escaping prevents the example from becoming live markup.

```html
<pre><code>&lt;p&gt;Hello&lt;/p&gt;</code></pre>
```

**Expected observation:** The displayed code contains literal paragraph tags.

## Contrast case: a nested list placed beside its parent item

Both versions indent the same way in the editor, but only one produces the structure the indentation suggests.

```html
<!-- broken -->
<ul>
  <li>Tools</li>
  <ul
    ><li>Editor</li></ul
  >
</ul>

<!-- repaired -->
<ul>
  <li
    >Tools
    <ul
      ><li>Editor</li></ul
    >
  </li>
</ul>
```

In the broken version, the inner `ul` is a direct child of the outer `ul`, which only permits `li` children. Browsers still draw it indented, so the defect hides on screen, but the outer list now has one item plus a stray list, and assistive technology reports one item instead of an item with a sublist. In the repaired version Editor belongs to Tools. The check is `document.querySelector('ul > ul')`, which returns an element for the broken markup and null for the repair.

## Six progressive exercises

Exercises 1 and 6 keep their expected answers in the solutions file.

### Exercise 3: Build a study checklist with a code example and glossary.

**Expected evidence:** The page exposes list, code and definition structures without relying on spacing.

**Progressive hint:** Use a list for the checklist, code inside pre for the example and a description list for the glossary.

### Exercise 4: Repair a nested list placed as a sibling of its parent item.

**Expected evidence:** The nested list belongs inside the associated li.

**Progressive hint:** Move the inner list inside the li that it belongs to.

### Exercise 5: Test a long code line in a narrow preview.

**Expected evidence:** The code region can scroll without making the entire page horizontally overflow.

**Progressive hint:** Give the pre block its own horizontal overflow rule instead of shrinking the whole page.

### Exercise 6: Explain the difference between preserving whitespace and preserving meaning.

**Progressive hint:** Compare what pre changes on screen with what code or ol tells a screen reader.

## Debugging and common mistakes

Do not use nonbreaking spaces to build layout columns. Avoid unescaped code snippets that accidentally create real tags. A screenshot can hide these structural errors, so inspect the tree.

If a sublist renders but screen readers report the wrong item count, open the Elements panel and confirm the inner ul is a child of an li, not a sibling. If code shows formatted output instead of tags, the angle brackets were not escaped inside the code element.

The shared [debugging routine](../STUDY-GUIDE.md#debugging-html) covers what to record before each repair.
