## Purpose and mental model

A language model assigns scores to possible continuations. A fluent continuation can still be false, unsupported by a source or inappropriate for an intended use. Before learning a tokenizer or transformer, distinguish a statement about how a component works from a measurement on a fixed set and from a claim the available evidence cannot support.

This distinction is practical. A report saying accuracy is high leaves unanswered which questions were asked, how related questions were grouped, whether the answers were already present in training and what counted as correct. Three paraphrases from one document can look like three independent successes while measuring one narrow family. A score does not choose its own evaluation unit.

Use a local written worksheet in this lesson. There is no endpoint to call and no model installation. The examples are authored records whose truth can be inspected directly. They prepare you to ask better questions when later code produces probabilities or generated text. The goal is not to distrust every result; it is to state precisely what a result supports and what further evidence would change a decision.

## Vocabulary and concepts

**Mechanism claim:** a statement about a specified computation or information boundary, checked against that implementation and its assumptions.

**Empirical claim:** a statement about observed behavior on a named evaluation set, metric and unit.

**Unsupported claim:** a conclusion extending beyond the evidence or conditions actually checked.

**Evaluation unit:** the item weighted by a metric, such as token, question, source document or question family.

**Counterexample:** a concrete case contradicting a universal statement; one fluent false answer is enough to refute fluency always means truth.

## Syntax or reasoning anatomy

Read an evidence statement as subject, conditions, observation, unit and limitation. For example, on these three question records, two answers match the supplied references reports a count and a denominator. It does not claim two-thirds of all future questions will be correct. Architecture or code inspection may support a mask property, but that property does not establish factuality.

A worksheet should retain question ID, source family, reference answer, observed answer, correctness rule and result. A family-weighted score first aggregates within each family and then gives each family equal weight. A record-weighted score gives every record equal weight. Both can be valid, but they answer different questions. Decide the unit before seeing which score looks better.

## Worked example / walkthrough

### Example A: One table, two declared units

There are three authored questions. Two near-paraphrases belong to family A and are correct; one question from family B is incorrect.

```text
ID   Family   Correct
q1   A        yes
q2   A        yes
q3   B        no
Record-weighted accuracy: 2/3
Family means: A=1, B=0
Equal-family accuracy: (1+0)/2 = 1/2
```

**Expected:** Neither number is fabricated, but reporting one without its unit hides the weighting policy. The table also cannot estimate performance across a broad population.

### Example B: A fluent answer can be wrong

Use an arithmetic question so no remote fact lookup or model is needed.

```text
Question: What is 7 + 8?
Reference: 15
Observed answer: The result of adding seven and eight is thirteen.
Fluent wording: yes
Correct by the arithmetic reference: no
```

**Expected:** A polished sentence is not a correctness test. Conversely, one incorrect answer does not prove every answer is wrong; it refutes a universal fluency-implies-truth claim.

## Prediction before your attempt

Before executing or calculating, write the result you expect from the normal
fixture and which changed condition would invalidate it. Save that prediction.
Afterward, name the first observation that supported or contradicted it rather
than rewriting your original answer to match the reference.

## Exercises

1. **Classify six claims.** Classify these: a fixed mask blocks later keys; a table has 2/3 correct records; all future outputs are true; this fixture has no observed failures; no observed failures means zero risk; a supplied score matrix has one row per query.
   **Expected:** Mechanism, empirical, unsupported, empirical, unsupported, mechanism, in that order.
   **Verify:** Write the evidence type and a test or counterexample next to all six statements; do not substitute a single reliability label.

2. **Compute two accuracies.** Use q1=A/correct, q2=A/correct, q3=B/incorrect and compute record-weighted versus equal-family accuracy.
   **Expected:** Record-weighted 2/3 and equal-family 1/2.
   **Verify:** Inspect the three correctness values and the two separate family means before calculating the final averages.

3. **Challenge fluent correctness.** Use the 7+8 answer in the walkthrough. State which universal claim it contradicts and which broad negative claim it does not establish.
   **Expected:** It contradicts fluent answers are always correct; it does not show that every answer is false.
   **Verify:** Record reference 15, observed 13 and the single failed equality as the counterexample.

4. **Detect repeated evidence.** Duplicate q1 using the same ID and family. Decide whether the duplicate should count as another independent question.
   **Expected:** A repeated question ID is rejected; related but distinct IDs must remain in their family for grouped evaluation.
   **Verify:** Capture the duplicate-ID ValueError in the optional reference checker or identify the repeated row explicitly in writing.

5. **Refuse an empty accuracy.** Evaluate no questions and decide whether accuracy is zero, one, or undefined.
   **Expected:** The mean is undefined; the reference raises ValueError for an empty evaluation.
   **Verify:** Retain the empty-set diagnosis and then recompute the original 2/3 table to show the valid result remains available.

6. **Transfer to a new family balance.** Use three correct questions from family A and one incorrect question from family B. Compare record and family weighting, then write a bounded report.
   **Expected:** Record-weighted accuracy 3/4; equal-family accuracy 1/2. The report names four records and two families.
   **Verify:** Inspect a four-row table, both denominators and a statement that unseen families remain untested.

## Progressive hints

- **Hint 1:** Underline what is being claimed: code behavior, a finite observation, or a universal conclusion.
- **Hint 2:** Write each denominator in words before doing division.
- **Hint 3:** Keep repeated question IDs distinct from different IDs in the same family; both affect how evidence should be counted.

## Common pitfalls

If two reports disagree, inspect the evaluation unit before deciding one model is better. A token-weighted metric, question accuracy and equal-family average need not match. If a result improves after adding paraphrases of an easy question, check whether the report is measuring repeated evidence rather than broader coverage.

If a component test passes, retain the exact property it checked. Causal attention can be correct while a tokenizer was fit on validation text or an answer cites unsupported material. If zero failures are observed, record how many cases were tested and which conditions were missing. A finite result is useful; describing it as zero possible risk discards the limitation that makes the result interpretable.

## Self-check

Without the examples, distinguish a mechanism claim from an empirical claim using one new sentence each. Then explain how a family-weighted metric can differ from a record-weighted one without either calculation being arithmetically wrong.

## Evidence review

Use a 0, 1 or 2 score for each of five dimensions: the declared data/observation
contract, a correct normal-case derivation, diagnosis of the changed fixture,
explicit handling of the invalid case, and a fresh explanation of the evidence
boundary. Normally seek 8/10 with no zero for the contract or claim boundary,
then require a new transfer example. This is a human learning rubric, not an
automatic certification or completion awarded by a single successful Run.
