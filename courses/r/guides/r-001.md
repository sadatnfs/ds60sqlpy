## Outcome and mechanism

Run a self-contained calculation and distinguish printed output, saved source and a successful check.

R evaluates expressions and associates names with objects. In a classroom script, each run starts a new R process. A name created in yesterday's run is not a hidden input available today. Put every required input and definition in the pad so the submitted source explains its result. Saving that source preserves a draft; it does not keep a live R session in memory.

Use <- to bind a value and print to display it deliberately. An interactive R console often prints the result of a bare expression automatically. Rscript does not promise the same convenient display for every nested expression or object, so explicit print calls make a lesson's observable output clear. Comments begin with # and describe intent without changing the calculation.

A successful exit means the script reached its end without an uncaught error. It does not establish that the calculation answered the intended question. A small assertion such as stopifnot(total == 18) states a separate expected property. Later lessons will develop checks for approximate numerical equality and failure cases. Here, the arithmetic uses small exact integers represented as R numbers.

The classroom provides R and prepared packages inside Linux Docker. Windows uses WSL 2 to run that same container. There is no need to install R or an IDE on the learner's host, and lessons do not download packages or data. Output, plots and saved run receipts are separate from the editable source. Reading an old receipt should not recreate variables or rerun a script.

| Term | Meaning |

| Binding | A name associated with an object in an environment. |

## Read the syntax

Assignment puts the computed right-hand value under the left-hand name. Parentheses supply arguments to print or stopifnot. A quoted string is text; the unquoted name total asks R to look up its value. Use "Total" as a label and total as data. R is case-sensitive: quantity and Quantity are different names. A syntax error points to source that could not be parsed; retain its message and check quotes, parentheses and the indicated line before rerunning.

## Worked examples

### Example 1: Calculate a small invoice

```r
quantity <- 3
unit_price <- 6
total <- quantity * unit_price
print(total)
stopifnot(total == 18)
```

**Expected observation:** 18

Both inputs are present in the script. The printed 18 is the computed total, while stopifnot states the expected arithmetic result.

### Example 2: Rebinding does not rewrite a prior calculation

```r
quantity <- 3
unit_price <- 6
total <- quantity * unit_price
quantity <- 4
print(c(saved_total = total, recalculated = quantity * unit_price))
stopifnot(total == 18, quantity * unit_price == 24)
```

**Expected observation:** saved_total 18; recalculated 24.

total contains the earlier result. Changing quantity does not convert total into a spreadsheet formula that reevaluates itself.
