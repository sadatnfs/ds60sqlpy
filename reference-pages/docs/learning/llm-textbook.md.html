Language models: a textbook reading route#

This route joins 48 chapters on how language models work with 24 chapters on building and evaluating subject-matter assistants. Read it as a connected book, then use the coding pad to inspect the small experiments. The browser opens these two journeys in a wide reading view; Show code and notes brings back the experiment panel. Your layout preference is remembered for each journey.

Start the whole classroom with ./classroom. The one-command guide covers macOS, Linux and Windows through WSL 2. The lessons below use the prepared Core or PyTorch CPU worker. Default examples use small local fixtures without API keys, model downloads or GPU requirements. The optional pretrained recipe is identified explicitly.

What you will be able to explain#

A language model assigns probabilities to possible next tokens given a prefix. A useful assistant is a larger system: it chooses context, controls access to information, may retrieve documents or call defined tools, produces a proposal, and checks that proposal against the intended task. Learning both levels matters. A correct attention implementation is not evidence that a generated business answer is supported, and a fluent answer does not establish that a calculation used the correct denominator.

The mechanism chapters build from concrete sequences and counts into embeddings, attention, Transformer blocks, objectives and optimization. The later chapters connect the same mathematical objects to caching, inference budgets, adaptation, quantization, routing and evaluation. The applied route carries a running Methods Desk case: an assistant helping analysts answer questions from versioned subject-matter material and structured data. It makes the transitions between data preparation, retrieval, generation, tools and measurement visible.

Each chapter starts with an explanation of the problem the mechanism solves. Notation and assumptions appear before they are used in derivations. Numerical traces connect equations to the existing code and show which intermediate value should change. Counterexamples explain where an attractive shortcut fails. Chapter bridges identify the new idea needed next, so the route does not reduce to a list of library calls.

A small notation map#

Symbol or word Meaning to establish before using it
Token A vocabulary item produced by a particular tokenizer; its boundaries need not match words
Vocabulary size V The number of token IDs the output distribution can assign probability to
Sequence length T The number of token positions participating in the particular computation
Batch size B The number of sequences processed together, not their total active-token count
Feature width D The number of representation coordinates at a token position
Embedding A vector looked up or computed for a token; it is not a stored dictionary definition
Logit An unnormalized score, distinct from the probability obtained after normalization
Q, K and V in attention Query, key and value matrices; this V means values, not vocabulary size
Mask A declaration of permitted information or participating loss positions; the exact meaning depends on the API and operation
Parameter Learned persistent state, such as a projection matrix
Activation An intermediate value computed for particular inputs and parameters
Gradient A local derivative of the declared objective with respect to a chosen quantity
Cache Retained computation state whose correctness depends on model, sequence and position identity
Evaluation unit The observation, customer, document family or other unit to which a reported metric applies

For a decoder, one common representation layout is (B, T, D). Attention heads introduce another axis, so an implementation might reshape to (B, H, T, d) with D = H*d. That equality belongs to a particular architecture. Grouped-query attention, cross-attention and different framework APIs need their own dimension contracts. Keep the axis names beside an equation rather than guessing from a square example that happens to multiply successfully.

Similarly, distinguish the causal attention mask from the loss mask. The first limits which positions can influence a prediction. The second determines which target positions contribute to an objective. Excluding a prompt token from loss does not necessarily make it invisible as context. Several chapters derive this separation using exact logits and gradients.

How to read equations and experiments together#

First identify the inputs and their units. Write the operation in words, then name the axes it preserves or reduces. Follow one small numerical case from input to output before relying on a final scalar. Only then run the code and compare the intermediate quantities with your calculation.

A program's boundary is as important as its happy path. Ask what happens for an empty candidate set, an all-masked row, a different feature width, an unseen identity or a nonfinite intermediate. A check that rejects an undefined quantity can be more informative than a program that always prints a number. Preserve a counterexample that distinguishes the intended mechanism from a plausible wrong implementation.

The chapters label whether worked blocks are complete standalone programs or a sequential A/B/C experiment. A sequential experiment shares explicitly introduced state inside one fresh process. It does not rely on hidden variables in an old notebook. Save your own pad before replacing it with an example. Ordinary practice sections and separately revealed solutions remain available after the exposition.

Small examples make a mechanism inspectable. They do not replace the evidence needed for a deployment decision. Track four different questions: whether the algebra is right, whether this implementation executes, whether the measurement matches its stated unit, and whether the resulting system is useful on new work. The final question requires data and evaluation beyond a published toy fixture.

Part I: mechanisms, training and inference#

Begin with chapters 001-009 if token probability, vector shapes or gradients are unfamiliar. Chapters 010-024 assemble the Transformer and examine training, masking, decoding and state. Chapters 025-042 connect resource use, adaptation, evaluation and a complete bounded system. Chapters 043-048 examine architecture families, positional rotations, normalization and gated feed-forward networks, grouped and blockwise attention, sparse experts, and exact speculative decoding. The exact prerequisites remain in each guide.

For an additional connected architectural walkthrough, read Inside a Transformer. Its NumPy program traces a full small decoder forward pass and independently checks an output-head gradient. It explicitly distinguishes the untrained forward mechanism from full-model learning. The primary Transformer paper is background reading; the checked-in chapters supply the explanation locally.

Part II: subject assistants and data-science work#

The applied route starts by defining the decision, analytical unit and evidence policy. It then follows documents through ingestion, chunking, indexing, retrieval, ranking and answer construction. Evaluation separates missing evidence, unsupported generation, inappropriate abstention and calculation errors. Access control and provenance apply before a convenient answer is assembled, not after it has already exposed information.

The adaptation chapters explain why changing model weights and supplying current retrieved context solve different parts of the problem. Fine-tuning is not an automatic substitute for a maintained source of facts. RAG does not guarantee that the selected evidence is relevant or that a generated answer follows it. The original RAG paper and LoRA paper support the mechanism references; the course derives concrete local examples and their limits.

For data-science use, keep structured computation separate from prose generation. Define the population and time window, run the authorized calculation, retain its units and denominator, then explain the result with the available evidence. The Methods Desk chapters show why an assistant can quote the correct document and still answer the wrong analytical question.

Companion routes#

Use NLP for a broader treatment of text processing, representation, classification, sequence tasks and language evaluation. PyTorch and TensorFlow explain the tensor, training, state and export machinery in comparable depth. The statistics book develops the sampling, modeling, experimentation and causal reasoning needed to judge a data-science assistant's outputs.

These are connected learning resources, not a certification that reading alone creates expertise. Reconstruct a mechanism, run the experiment, explain a failure case, and then apply it to a new question with its assumptions made explicit.
