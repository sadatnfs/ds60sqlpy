## Outcome and mechanism

Inspect numeric types and choose an equality check that matches the numerical contract.

A printed number does not reveal all of its representation. In R, 2 is usually a double and 2L is an integer. Both can participate in arithmetic, but their storage types differ. typeof inspects that storage distinction, while class describes the class used by higher-level behavior. Do not infer a type solely from the way print rounds a value for display.

Floating-point arithmetic stores many decimal fractions approximately. The expression 0.1 + 0.2 need not be exactly equal to the stored representation of 0.3. This is a representation issue rather than evidence that arithmetic is arbitrary. For a numerical result, specify a sensible scale-aware tolerance. isTRUE(all.equal(actual, expected, tolerance=...)) converts the comparison's success or explanatory text into one logical answer.

Coercion can change both type and meaning. Combining a number with text in one atomic vector creates character data. as.numeric can parse an ordinary numeric string, but identifiers with leading zeros should usually remain text. Turning "0017" into 17 loses a representational distinction that might matter for a customer code.

Integer division and remainders answer another pair of questions. For nonnegative items, 17 %/% 5 counts complete groups and 17 %% 5 counts the remainder. Ordinary / computes a ratio. Keep those operations distinct when translating a business rule into source, and define the intended behavior for negative quantities before generalizing the example.

## Read the syntax

Use typeof(2L) versus typeof(2), / for a ratio, %/% for integer quotient and %% for remainder. identical checks exact value and attributes, so identical(2L, 2) is false even when 2L == 2 is true.

## Worked examples

### Example 1: Same displayed value, different storage

```r
stopifnot(typeof(2L) == "integer", typeof(2) == "double")
stopifnot(2L == 2, !identical(2L, 2))
print(c(integer_type = typeof(2L), double_type = typeof(2)))
```

**Expected observation:** integer and double.

Numeric equality and exact object identity make different claims. The storage difference is intentional.

### Example 2: A decimal result and a grouping rule

```r
decimal <- 0.1 + 0.2
stopifnot(isTRUE(all.equal(decimal, 0.3, tolerance = 1e-12)))
stopifnot(17 %/% 5 == 3, 17 %% 5 == 2)
print(c(decimal = decimal, groups = 17 %/% 5, remainder = 17 %% 5))
```

**Expected observation:** Approximately 0.3; three groups and two remaining.

The decimal check allows a tiny representation error. Grouping uses exact small integer arithmetic and keeps quotient separate from remainder.
