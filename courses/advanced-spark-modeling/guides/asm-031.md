# asm-031: Independent TMB fits on complete Spark groups

Tutorial mode. Stage: advanced. Direct prerequisites: `asm-003`, `tmb-016`.

## Starting point and result

TMB evaluates a C++ objective and its automatic derivatives through R. Spark can distribute independent modeling work that invokes this prepared R/TMB environment. The useful question is not whether Spark “supports TMB” as a built-in estimator, but whether the model and runtime admit a correct, bounded integration. The owned `projects/spark-tmb` project provides that explicit boundary.

## Mechanism: independent models need independent state

For groups g with distinct parameters \(\theta_g\), an objective \(L=\sum_g L_g(\theta_g)\) can be minimized group by group. Each worker receives complete group data, creates its own process-local TMB objective and optimizer state, and returns parameters plus diagnostics. The outputs are many fitted models. They are not automatically the fit of one parameter vector shared across groups.

TMB's `MakeADFun` result contains functions and native state associated with a loaded compiled model. Do not create it on the Spark driver and serialize it as though it were a plain table. Load the compatible shared library and build the objective in the worker process that will evaluate it. Native pointers and AD tapes are process-local resources.

The fixed `partition-normal` project case establishes a bounded compiled normal-model path. The broader group-fitting pattern uses the same preparation principles. `failure-contracts` checks invalid inputs and subprocess failures. Read the project's concrete receipt to distinguish which cases actually ran from general design discussion.

## Worked case: two independent means

Group A has observations one and three; group B has eight, ten, ten, twelve, nine and eleven. Separate normal-mean MLEs are two and ten. The pooled mean is eight. A TMB objective for each complete group can reproduce the separate estimates, while the serial closed forms provide an oracle.

Return group ID, row count, estimated parameters, objective, optimizer convergence/message and gradient diagnostics. Preserve failed groups as explicit failures rather than dropping them from the output table. Otherwise a successful-looking dataset of estimates may hide the difficult groups.

## Worked case: one shared mean is a different computation

If both groups share one mean, fitting separately and averaging two and ten gives six, which is wrong for the pooled row-weighted objective. Combining count and sum gives eight. More generally, shared nonlinear parameters need a driver-controlled objective or another valid distributed optimization scheme, not a mean of independently optimized coefficients.

This is why group-by parallelism is powerful but not a universal answer. The model determines whether group parameters are independent, partially pooled through hyperparameters or fully shared. Hierarchical random effects add another layer addressed in later chapters.

## Failure diagnosis

A worker that cannot load the model library has a runtime or ABI failure. An optimizer that returns a nonzero status has a numerical or model issue requiring diagnostics. A group too large for memory is a data-layout failure. Keep these categories visible in results and retry policies. Repeating an invalid group indefinitely is not fault recovery.

## Interview discussion

**Can TMB run under Spark at all?** Yes, through a deliberately prepared worker process and a valid decomposition, as the owned project is designed to demonstrate. Spark does not need to understand the internal C++ tape to schedule independent computations.

**Why not ship one live TMB object to every executor?** Its native state belongs to the process and library that created it. Ship versioned data and model artifacts, then construct process-local state.

# Worked reference: Independent normal group fits

This is an editable reading/project reference. It has no ordinary pad Run action.

Group A values `[1,3]` have mean 2. Group B values `[8,10,10,12,9,11]` have mean 10. Independent fits return two models. A single shared mean is `(4+60)/(2+6)=8`, not the unweighted average 6 of the fitted group means.

A compiled TMB process must return its own objective/gradient and optimizer diagnostics with the group identity. Native objective objects are constructed inside the owning process. Do not serialize an existing MakeADFun closure as ordinary model data. The project's receipt defines which concrete evaluation/fitting case was executed.
