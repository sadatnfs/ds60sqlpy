# web-045: Templates and context-specific output escaping

## Level and prerequisites

Advanced; allow about 140 minutes, with extra time for independent practice. Direct prerequisites: `web-002`, `web-037`, `web-044`

## Learning objectives

Render a study-card template from synthetic untrusted labels. Explain why validated text still needs output escaping. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

A template combines trusted structure with data. If a visitor's text is inserted directly into HTML, the browser may interpret it as elements or script-capable attributes. Output escaping represents the data so it remains data in a particular destination context. It is not a one-time cleanup that makes a value safe everywhere. Keep the original validated value and encode it when crossing the output boundary.

For HTML text and ordinary quoted attribute values, htmlspecialchars with explicit flags and UTF-8 is a useful primitive. It is not a JavaScript-string encoder, a CSS sanitizer or a URL policy. A URL in an href needs a separate scheme and destination decision before attribute escaping. Avoid dynamic inline scripts and styles when a simpler data boundary is available.

## Syntax anatomy and mechanism

Define a small e function that calls htmlspecialchars with ENT_QUOTES, ENT_SUBSTITUTE and UTF-8. Use it only for the contexts described by its contract. The CLI reference prints an HTML string as text so you can inspect the escaped bytes; it does not execute that string in a browser. A server template later uses the same contextual boundary before returning a response.

## Classroom execution and offline inputs

Choose the **PHP CLI** worker in the classroom. The pad is staged as `main.php` and executes as a bounded Linux process, with prepared PHP and PDO SQLite. No host PHP installation is required for the Docker route.

## Worked example / walkthrough

### Worked example 1: HTML text escaping

The angle brackets must remain visitor data.

```php
$name = '<Ada & Bea>';
echo htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
```

**Expected observation:** The output contains &lt;, &amp; and &gt; references rather than live tags.

### Worked example 2: A bounded template

Only the fixed structure is authored markup.

```php
$html = '<p>Hello, ' . e($name) . '</p>';
```

**Expected observation:** The greeting structure is fixed and the name stays text.

## Debugging and common mistakes

Do not escape data once on input and assume it is safe for SQL, JavaScript and HTML alike. Double escaping can corrupt display while still failing another context. Never label an arbitrary strip-tags operation a complete XSS defense.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.
