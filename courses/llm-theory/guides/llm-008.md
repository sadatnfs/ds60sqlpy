## Purpose and mental model

<!-- textbook-foundations-start -->

### Replace symbolic IDs with trainable feature vectors

A tokenizer gives the model integer IDs, but ordinary arithmetic on those IDs would impose an arbitrary geometry. If cat has ID 10 and dog ID 11, that numbering does not establish that they are one unit apart in meaning. Renumbering the vocabulary would change the arithmetic without changing the text. An embedding layer instead treats an ID as an address: retrieve the vector stored in that vocabulary row.

Let E be an embedding table with V rows and D columns. V is the number of token identities and D is the feature width. For token ID i, the lookup returns row E_i, a D-dimensional vector. A sequence of T IDs produces T such vectors in the same order, giving shape [T,D]. These symbols name different axes: T counts occurrences in this input, V counts possible token identities, and D counts numeric features in each representation. Increasing any one of them has a different memory and modeling effect.

Example A uses four vocabulary rows and two features per row. The input IDs [2,0,2] select [2,2], then [1,0], then [2,2]. The first and third vectors agree because they read the same parameter row, not because the first and third positions have become the same occurrence. They remain separate positions in the sequence. A later contextual operation can transform them differently because their surrounding information or positions differ.

One-hot multiplication expresses the same lookup algebraically. A one-hot vector has V entries, with one at the selected vocabulary coordinate and zero elsewhere. Multiplying it by E sums all rows weighted by those entries, so only the chosen row remains. Stacking one-hot vectors for the sequence reproduces the lookup output. This is useful for deriving gradients and shapes, although materializing a large one-hot matrix is usually wasteful when direct indexing can do the same selection.

During training, repeated occurrences share a parameter row, so their gradient contributions accumulate there. If two uses of ID 2 contribute upstream vectors g_1 and g_3, the row's gradient includes g_1+g_3. The IDs themselves are discrete selectors; we do not differentiate their integer values as though moving from ID 2 to ID 2.1 were a meaningful token change. The table is fixed literal data in this NumPy example, so the lesson demonstrates lookup and storage behavior before later chapters perform actual automatic differentiation.

The negative-index example separates a general array feature from the model's domain contract. NumPy accepts -1 as an address relative to the end of an array. The tokenizer contract here defines valid IDs from zero through V-1, so -1 must be rejected. A language library may legally execute an operation that is invalid for the application. The same principle applies to a tokenizer/model mismatch: two models can share a vocabulary size while assigning different meanings to the same row numbers, producing no shape error at all.

Embeddings are useful because training can organize reusable numeric features under an objective. The lookup itself supplies no guarantee of semantic similarity, knowledge or contextual understanding. It creates the parameterized representation on which attention and other transformations can operate.

## A lookup selects parameters and accumulates their gradients

Let E have shape(V,D), where V is vocabulary size and D is feature width. For token IDs t_1 through t_T, the output row i is X_i=E_(t_i). A one-hot selection matrix S with shape(T,V) gives the same operation as \(X=\mathrm{SE}\). Each row of S contains one1. This algebra explains why lookup preserves token order and why repeated IDs select the same parameter row. An implementation need not materialize S; direct indexing avoids allocating \(T\cdot V\) mostly-zero entries.

For the fixture IDs[2,0,2], S selects vocabulary row2 twice and row0 once. The output is a three-position sequence with feature width 2. There are still only four vocabulary parameters rows in the table. Token ID2 is an address into that table; it is not a magnitude that should be interpreted as "twice token 1." Interpolating between integer IDs or averaging them before lookup therefore has no justified semantic meaning under this representation.

The backward relation follows directly: if \(G=\frac{\partial L}{\partial X}\) has shape(T,D), then \(\frac{\partial L}{\partial E}=S^{\mathsf T}G\). In coordinates, the gradient of row r is the sum of G_i over positions whose ID equals r. Take upstream rows \(G=[[1,2],[3,4],[5,6]]\) for the three fixture positions. Row0 receives[3,4]; row2 receives[6,8]; rows1 and 3 receive[0,0]. The two appearances of token 2 accumulate into the same parameter. Assigning rather than adding the second occurrence's gradient would lose one contribution. The current NumPy lookup example does not execute this backward update; this is an independent derivation of what a differentiable embedding layer must do.

That gradient statement assumes the loss depends on E through the input lookup alone. If the table is also tied to the output classifier, logits for hidden state h may be E h, and the softmax loss supplies additional gradients through output-vocabulary rows. With weight tying, a row absent from the input sequence can still receive an output-side gradient. This is why "unused input IDs never change" is too broad unless all paths and optimizer behavior have been specified.

Padding has similarly separate contracts. An embedding layer may suppress gradient accumulation for a designated padding row, but that does not automatically prevent padding positions from participating in attention, pooling or loss. Nor does it prove that optimizer weight decay or another shared use cannot alter that row. A model needs an input padding convention, an attention mask where appropriate, and a supervised-target inclusion rule. These controls operate on different axes and should be checked independently.

A vocabulary permutation can produce a silent failure while all shapes remain valid. Suppose a new tokenizer swaps IDs0 and 2, but the old table is kept unchanged. The new ID0 now means the token formerly represented by row2, yet lookup returns[1,0] instead of[2,2]. No index error occurs because both IDs are legal. Correct migration would remap every affected input ID and the corresponding input/output vocabulary parameters consistently. Keeping vocabulary size and file format unchanged is not a compatibility proof.

The NumPy storage behavior in this lesson is also deliberate. Advanced integer indexing creates a separate result array. Editing output[0] does not update E or output[2], despite both having originally selected row2. Parameter sharing describes which source parameter a computation reads and which gradients accumulate; it does not require all returned activation rows to alias the same memory. In an automatic-differentiation framework, mutation rules and gradient tracking add further constraints, so inspect that framework's documented semantics before translating a NumPy mutation experiment.

**Interview reasoning:** "Where is meaning stored in an embedding?" The lookup mechanism itself only associates IDs with vectors. Useful structure can emerge from the training objective, data and downstream transformations. The supplied table has no such training history. A similarity between two hand-authored rows demonstrates a geometric relation in this fixture, not a validated semantic relation between words. Also distinguish this context-independent token table from a contextual representation produced after attention layers process the whole allowed prefix.

## Vocabulary and concepts

**Embedding table:** a matrix with one parameter row per vocabulary ID and a declared feature width.

**Token ID:** an integer selecting a legal row; it is not a feature coordinate or a numeric measure of word meaning.

**Lookup:** selection of table rows in input order, allowing repeated IDs.

**One-hot vector:** a vocabulary-width indicator with one selected coordinate, whose product with the table reproduces a lookup.

**Vocabulary alignment:** the agreement between tokenizer IDs and embedding rows, including model/version identity.

## Syntax or reasoning anatomy

table[ids] uses advanced integer indexing to select rows. For a table shaped (vocabulary,features) and one-dimensional IDs shaped (tokens,), the result is (tokens,features). The same operation can be written as one_hot(ids) @ table, which makes the vocabulary axis explicit without being the preferred memory-efficient implementation.

The reference requires a finite nonempty table and integer rank-one IDs in the legal range. An empty ID list is explicitly accepted and returns shape (0,features); the later attention function separately rejects an empty sequence. Advanced indexing returns independent output storage in this reference, so changing an exercise result must not overwrite the table or another repeated row. State this mutation contract rather than assuming every array view behaves alike.

## Worked example / walkthrough

Run Examples A and B in order in one scratch file, then run that complete file in a fresh process. Example B may reuse the imports, helpers and fixture state established in Example A. Do not treat an isolated later block as a standalone program.

### Example A: Repeated IDs preserve token order

Inspect rows two, zero and two of the fixed table.

```python
import numpy as np

table = np.array([[1, 0], [0, 1], [2, 2], [-1, 1]], dtype=np.float64)
ids = np.array([2, 0, 2], dtype=np.int64)
output = table[ids]
np.testing.assert_array_equal(output, [[2, 2], [1, 0], [2, 2]])
assert output.shape == (3, 2)
print(output)
```

**Expected:** The first and third outputs match because the same vocabulary row was selected twice. Two is the feature width, not the number of token choices.

### Example B: A legal NumPy index can be an illegal token ID

Show the behavior that the domain guard must reject.

```python
wrapped = table[np.array([-1])]
np.testing.assert_array_equal(wrapped, [[-1, 1]])
assert int(np.array([-1])[0]) < 0
print(wrapped)
```

**Expected:** NumPy interprets -1 as the final row. Our token contract rejects it instead of silently treating an invalid ID as a valid vocabulary member.

## Common pitfalls

If a lookup returns plausible but wrong features, inspect token-ID mapping and vocabulary order before changing the model. Negative indices are especially dangerous because NumPy accepts them. Fractional values must not be rounded into token IDs without a declared tokenizer policy. A shape check cannot detect a vocabulary permutation with the same row count.

If editing a result changes the table, inspect whether another implementation returned a view or shared storage. Keep copies explicit for this learning boundary. Fixed feature vectors are not evidence that a word meaning, factual relationship or causal explanation has been learned. The next attention unit combines these features under an information mask and needs its own shape, empty-input and causal checks.
