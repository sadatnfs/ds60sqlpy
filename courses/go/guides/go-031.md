## Why this mechanism matters

Logs describe events; stable fields let operators inspect them without parsing prose. A correlation ID connects related work, a level indicates severity and numeric counts support diagnosis. Logging does not replace returning an error or checking an invariant. Avoid credentials, raw tokens, complete user payloads and unbounded identifiers. Structured output can still leak data if its fields are chosen badly. Tests should control timestamps and parse records instead of comparing incidental field order. Metrics describe aggregates, logs describe events and traces connect distributed spans. Choose which evidence answers the question rather than emitting everything indiscriminately.

## Vocabulary and concepts

- **Structured attribute:** A named value attached to a log event.
- **Correlation ID:** A bounded identifier linking related events.
- **Redaction:** Removing sensitive values before output.

## Syntax anatomy and reasoning

log/slog builds records from key/value attributes. JSONHandler writes to an io.Writer. HandlerOptions.ReplaceAttr can remove timestamps in deterministic tests. Logger.With attaches common attributes to a derived logger. A logged status is a report, while the actual operation and durable receipt remain separate evidence.

## Worked example / walkthrough

### Worked example 1: Emit a structured event

Log processed with count 3 and parse its JSON.

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"log/slog"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func logRecord(message string, args ...any) map[string]any {
	var b bytes.Buffer
	handler := slog.NewJSONHandler(&b, &slog.HandlerOptions{ReplaceAttr: func(groups []string, a slog.Attr) slog.Attr {
		if a.Key == slog.TimeKey {
			return slog.Attr{}
		}
		return a
	}})
	slog.New(handler).Info(message, args...)
	var value map[string]any
	if err := json.Unmarshal(b.Bytes(), &value); err != nil {
		panic(err)
	}
	return value
}

func main() {
	// Emit a structured event
	{
		v := logRecord("processed", "count", 3)
		check(v["msg"] == "processed" && v["count"] == float64(3), "fields")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The record has message processed and numeric count 3.

The check inspects meaning rather than serialized field order.

	// Emit a structured event
	{
		v := logRecord("processed", "count", 3)
		check(v["msg"] == "processed" && v["count"] == float64(3), "fields")
	}

	// Retain correlation
	{
		v := logRecord("read", "request_id", "lesson-7")

**Observe:** The ID is retained exactly.

A bounded synthetic ID is sufficient. Secrets and complete payloads are inappropriate correlation fields.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
