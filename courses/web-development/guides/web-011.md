# web-011: The box model, sizing and overflow

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-010`

## Learning objectives

Build a readable card that contains a long identifier. Explain which dimensions margin does and does not affect. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

Every rendered box has content, optional padding, a border and an outside margin. With the default content-box sizing, a declared width describes the content, so padding and borders add to the outer width. With border-box sizing, the declared width includes the content, padding and borders. Margins remain outside either calculation. This distinction explains many layouts that unexpectedly exceed a parent.

Overflow occurs when content needs more room than the available box. Hiding overflow can conceal essential information; scrolling or wrapping may preserve it. Long unbroken strings and images are frequent sources of overflow. A fixed height can clip translated text, enlarged fonts or error messages, so prefer content-driven height unless the interaction truly requires a bounded region.

## Syntax anatomy and mechanism

For a 200px content-box with 20px left and right padding and 2px borders, outer width is 244px. For a 200px border-box, the content width becomes 156px. Set a consistent box-sizing rule on all elements and pseudo-elements. Use max-inline-size to constrain readable width without assuming the writing direction.

## Worked example / walkthrough

### Worked example 1: Content-box arithmetic

The declared content width excludes padding and border.

```css
.card {
  width: 200px;
  padding: 20px;
  border: 2px solid;
}
```

**Expected observation:** The border box is 244px wide.

### Worked example 2: A predictable border box

The declared width now contains the interior spacing.

```css
.card {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 2px solid;
}
```

**Expected observation:** The border box is 200px wide.

## Six progressive exercises

### Exercise 1: Calculate outer widths for the two examples.

**Expected evidence:** They are 244px and 200px, before margins.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Add border-box sizing to a document and inspect one card.

**Expected evidence:** The declared width matches the border-box width.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Build a readable card that contains a long identifier.

**Expected evidence:** The identifier wraps or scrolls locally without overflowing the page.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Repair a fixed height that clips a validation message.

**Expected evidence:** Use content-driven height or an explicitly accessible bounded scroll region.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Increase text size and inspect overflow.

**Expected evidence:** Essential text remains visible and controls remain reachable.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Explain which dimensions margin does and does not affect.

**Expected evidence:** Margins add external separation but are not included in either box-sizing width.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

Do not use overflow:hidden to hide a layout bug without checking lost content. Vertical margins can collapse in ordinary block layout, while flex and grid layout have different rules. Inspect box measurements directly.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

## Retrieval, transfer and next steps

Close the worked answers and explain content box, padding, border without using their names as definitions. Reconstruct the central example from a blank pad or worksheet. Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation. When a behavior belongs to the browser, observe it in the browser; when it belongs to an HTTP server, keep that evidence separate from a CLI simulation.

Before moving on, keep a short learning record: your prediction, source revision, actual result, explanation and unresolved limitation. Revisit a direct prerequisite if you can reproduce output but cannot explain the mechanism.
