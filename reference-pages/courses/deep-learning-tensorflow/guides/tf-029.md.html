tf-029: Precision, overflow and stable objectives#

Level and prerequisites#

Advanced; approximately 120 minutes. Direct prerequisites: tf-028. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Locate overflow before it becomes a misleading training conclusion. The central investigation is concrete: Compare naive exp/log cross entropy with a stable logits-based form at logits [1000,999]; inspect finite values and gradients. The finish condition is The naive exponential path overflows; the stable positive-first-class loss is log(1+exp(−1))\log(1+\exp(-1)) within 1e-6. Mixed precision is an optional hardware study, not a default speed claim. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Floating-point arithmetic has a finite representable range. The probabilities implied by logits[1000,999] are well defined, but exponentiating those scores directly overflows ordinary floating-point types. Subtracting the maximum leaves the softmax unchanged because a common multiplicative factor cancels between numerator and denominator. A stable cross entropy works with shifted logits or a log-sum-exp expression, avoiding an unnecessary probability round trip. Numeric precision is a separate concern from objective correctness: a stable implementation can still optimize the wrong labels or denominator. Mixed precision may improve performance on some hardware, but this CPU fixture makes no speed claim.

Vocabulary and concepts#

Overflow: A finite mathematical result exceeds the numeric representation.

Log-sum-exp: A stable way to calculate the logarithm of a sum of exponentials.

Precision: The resolution of representable values, distinct from range.

Syntax anatomy and reasoning sequence#

Use tf.nn.sparse_softmax_cross_entropy_with_logits for the combined stable calculation. In NumPy, logaddexp(0,-1) gives the positive-first-class loss. finite checks should include gradients as well as forward outputs. float16 overflows at much smaller exponent arguments than float64. Compare using absolute tolerances appropriate to the dtype instead of exact equality for transcendental functions.

Stable algebra and sufficient precision solve different problems#

For logits z, log-sum-exp can be evaluated as m+log∑jezj−mm+\log\sum_j e^{z_j-m}, where m is the largest logit. The exponentials then have nonpositive inputs, avoiding overflow from unnecessarily large intermediate exponentials. For logits [1000, 1001] with the second class correct, the loss is log(1+e−1)\log(1+e^{-1}), about 0.3133. Computing exp(1001)\exp(1001) first is unnecessary.

Softmax probabilities are mathematically unchanged by adding one common constant to all logits. Floating-point computation has another boundary: if a low-precision representation rounds two distinct logits to the same stored number, subtracting the maximum cannot recover their lost difference. Test shift invariance only where the chosen dtype still represents the relevant differences. A stable operation is not a repair for already corrupted inputs.

Float16 has a much narrower representable range than float32. Squaring a representable input can overflow, and a small gradient can round to zero. Mixed precision deliberately assigns different dtypes to suitable operations and state. Loss scaling multiplies the loss before differentiation to help represent small gradients, then removes that scale before an ordinary optimizer update. If clipping is part of a custom implementation, it must operate under the intended unscaled-gradient convention. Otherwise changing the scale also changes the effective clipping threshold.

The TensorFlow mixed-precision guide explains the framework mechanism. This CPU lesson demonstrates numerical boundaries and stable formulas. It does not benchmark accelerator speedups or claim that lower precision is beneficial for every operator or dataset. Inspect forward values and gradients separately when diagnosing precision.

Worked example / walkthrough#

Example A: Expose naive overflow#

The warning is intentionally scoped to a counterexample. Silencing all numerical warnings in a training program would hide unrelated failures.

import numpy as np
import tensorflow as tf

z=np.array([1000.,999.])
with np.errstate(over='ignore'): naive=np.exp(z)
assert np.isinf(naive).all()

Expected: both exponentials are infinite.

Example B: Calculate stable loss#

The meaningful quantity is the difference between scores, not their shared offset. The stable form keeps that difference available without constructing enormous exponentials.

import numpy as np
import tensorflow as tf

z=np.array([1000.,999.])
with np.errstate(over='ignore'): naive=np.exp(z)
assert np.isinf(naive).all()
loss=tf.nn.sparse_softmax_cross_entropy_with_logits(labels=[0],logits=tf.constant([[1000.,999.]]))
np.testing.assert_allclose(loss.numpy(),[np.logaddexp(0,-1)],atol=1e-6,rtol=0)

Expected: loss log(1+e−1)\log(1+e^{-1}) within 1e-6.

Common pitfalls and diagnosis#

Locate the first nonfinite intermediate, then distinguish overflow from a loss of small differences. Compare a stable float32 calculation with the same input before any low-precision cast. If gradients are finite but updates depend unexpectedly on loss scale, inspect unscaling and clipping. Do not replace NaNs with zeros and call the training result repaired.
