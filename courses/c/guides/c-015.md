# c-015: Dynamic allocation and single-owner release

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-014`

## Learning objectives

Explain allocation owner, dangling pointer, size overflow. Implement the six investigations with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

Allocated storage lets a program choose capacity at runtime. malloc returns uninitialized storage or a null pointer on failure; calloc also initializes its bytes to zero. The caller must establish an owner responsible for exactly one release after the last use. free ends the allocation lifetime, so every pointer into that allocation becomes invalid even if its numeric address still looks familiar. Setting one pointer to NULL does not repair other aliases. Calculate allocation sizes without overflowing size_t before calling an allocator. A successful allocation says storage exists, not that application fields have been initialized meaningfully.

## Vocabulary and concepts

- **Allocation owner:** The component responsible for releasing dynamic storage.
- **Dangling pointer:** A pointer whose target lifetime has ended.
- **Size overflow:** An allocation-size calculation wrapping to an insufficient value.

## Syntax anatomy and execution trace

malloc(count * sizeof *items) avoids repeating the element type, but multiplication needs a prior bound check. Check the returned pointer before use. calloc(count,sizeof *items) accepts element count and size separately, while still requiring an application resource budget. free(NULL) is defined and harmless. The helper here returns NULL for a zero count by its own contract and refuses multiplication overflow before allocation.

## Worked example / walkthrough

### Worked example 1: Allocate and initialize

Allocate three ints, assign 2, 4, 6 and sum them.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int *allocate_ints(size_t count) {
  if (count == 0 || count > SIZE_MAX / sizeof(int))
    return NULL;
  return malloc(count * sizeof(int));
}

int main(void) {
  /* Allocate and initialize */
  {
    int *p = allocate_ints(3);
    CHECK(p != NULL);
    p[0] = 2;
    p[1] = 4;
    p[2] = 6;
    CHECK(p[0] + p[1] + p[2] == 12);
    free(p);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** The sum is 12 before release.

malloc storage must be initialized before reading. The owner releases it after the final valid access.

### Worked example 2: Inspect zero-initialized integers

Allocate three ints with calloc and read them.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int *allocate_ints(size_t count) {
  if (count == 0 || count > SIZE_MAX / sizeof(int))
    return NULL;
  return malloc(count * sizeof(int));
}

int main(void) {
  /* Allocate and initialize */
  {
    int *p = allocate_ints(3);
    CHECK(p != NULL);
    p[0] = 2;
    p[1] = 4;
    p[2] = 6;
    CHECK(p[0] + p[1] + p[2] == 12);
    free(p);
  }

  /* Inspect zero-initialized integers */
  {
    int *p = calloc(3, sizeof *p);
    CHECK(p != NULL);
    CHECK(p[0] == 0 && p[1] == 0 && p[2] == 0);
    free(p);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** All three values are zero.

For integer objects, all-bits-zero represents zero. Do not generalize that claim blindly to every possible pointer or floating representation.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path.
