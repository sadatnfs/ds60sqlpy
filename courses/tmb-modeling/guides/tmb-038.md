# Debugging compiler and native failures

Start with: tmb-037.

Outcome: Separate R validation errors, compiler failures and native crashes during diagnosis.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

Not all failures occur at the same layer. A missing column can be rejected in R before native evaluation. A malformed C++ expression fails compilation. An invalid native index can crash an R process. An optimization failure can arise from a valid program evaluating a scientifically unsuitable or numerically ill-conditioned model. Diagnose the layer before changing the model or environment.

`gdbsource(file, interactive=FALSE)` runs an R script under a debugger and can provide a native backtrace. Its `print.backtrace` method formats the result. A debugger executable and useful debug symbols must be prepared; importing TMB does not guarantee that the environment contains gdb or that container permissions allow every debugging operation.

### Worked case A: fail before C++

The companion implements an explicit zero-based group-index check. An out-of-range value is rejected with a clear domain error instead of being allowed to index an Eigen vector. The project's R API performs this kind of validation and native compilation retains bounds checking. Input validation and compiler bounds checks complement each other.

### Worked case B: a deliberate compile error without stale-library fallback

In an owned scratch directory, copy one original template and introduce a missing token. Require a nonzero compile result and confirm that the wrapper does not load an old library as if the new compilation succeeded. Do not edit the good source or overwrite a library used by another process. The companion models the state machine explicitly: a failed build cannot advance to “load new library.” Actual compiler-error acceptance requires the prepared native project.

For a real crash, preserve a minimal reproducer, source identity, exact command, data shapes and version receipt. Recompile the reproducer with suitable debug information and lower optimization in a disposable environment. Avoid publishing raw dumps containing learner data or unrelated environment secrets.

### Answered discussion

**Should I disable bounds checks to make a crash disappear?** No. That can turn a visible defect into silent memory corruption. **Does a backtrace identify the scientific error?** It identifies an execution path; interpreting the model still requires domain and numerical analysis. **Should every ordinary lesson require a debugger?** No. Keep debugging preparation optional and explicit, while making ordinary failures readable.

Read [gdbsource and compile documentation](https://cran.r-project.org/web/packages/TMB/TMB.pdf). This chapter teaches the complete process while honestly distinguishing its mathematical/state companion from an actual gdb session.

```r
validate_group <- function(group, n) {
  if (any(!is.finite(group)) || any(group != floor(group)) || any(group < 0 | group >= n)) stop("invalid group index");TRUE
}
stopifnot(validate_group(c(0, 1, 0), 2))
rejected <- tryCatch(validate_group(c(0, 2), 2), error = function(e) conditionMessage(e));print(rejected)
next_state <- function(compile_status) if (compile_status == 0L) "fresh-load-check" else "failed-build-no-load"
print(c(success = next_state(0L), failure = next_state(1L)));stopifnot(next_state(1L) == "failed-build-no-load")
```
