js-066: D3 capstone: an accessible, tested analytical dashboard#

Level and prerequisites#

Advanced; about 110 minutes plus independent practice. Direct prerequisites: js-065. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

Learning objectives#

Build a complete accessible dashboard from a blank pad. Defend the finished analysis and its evidence limits. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

Purpose, vocabulary and mental model#

The final D3 project combines a validated dataset, explicit transformations, consistent scales, keyed rendering and accessible controls. Its goal is an analytical explanation that a reader can inspect, not merely an attractive screenshot. Every visible claim should have a named source row grain, unit and aggregation policy.

Testing a visualization has several layers. Pure data tests verify filters and summaries. DOM or Canvas checks verify mark count and geometry. Interaction tests verify state changes and keyboard routes. Visual review catches clipping, illegible labels and misleading emphasis. No single screenshot or assertion covers all of these.

The reference is a small category dashboard with a filter, sorted bars, exact text values and a total summary. It uses no network input and offers a deterministic completion marker. Your independent project should change the dataset and question, then defend the encoding and limitations without copying the reference blindly.

Syntax anatomy and mechanism#

Keep the chart’s source data, derived data and view state separate. This capstone measures its container width and uses that width in its viewBox, keeping labels at a readable 14-pixel logical size instead of shrinking a fixed 640-unit chart. A ResizeObserver schedules geometry writes on a guarded animation frame when the container changes width. Keeping writes outside the observer callback avoids a resize-notification feedback loop. It disconnects and cancels pending animation work when the preview page leaves. The table adds explicit cell padding and alignment so headers and values remain distinct. Validate IDs and finite nonnegative values before rendering. Reconcile marks by stable ID. Add a native group selector and reset. Provide a text table that remains useful without interpreting color.

The reference asserts baseline totals, filtered totals, mark counts, reset behavior and source preservation. It intentionally does not claim to automate screen-reader usability or statistical validity. Perform the manual narrow-screen, keyboard and interpretation checks before calling your own project complete.

Debugging and common mistakes#

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Introduce a duplicate-ID failure and repair the input. Its distinguishing evidence is Validation refuses ambiguous identity before rendering. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

Accessibility and interpretation#

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.

Retrieval and transfer#

Close the solution and explain acceptance, accessibility, data provenance using a new small dataset. Reconstruct one example from a blank pad. Predict the effect of one missing value, empty input or reordered record before execution. Retain the source and observation separately from the explanation so a future reader can reproduce the case.
