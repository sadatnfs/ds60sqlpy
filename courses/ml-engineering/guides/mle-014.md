# mle-014: Shadow comparison and stable rollout cohorts

## Level and prerequisites

Advanced. Direct prerequisites: `mle-009`, `mle-012`

**Outcome:** Design stable routing and shadow comparisons with bounded conclusions.

## Question and mechanism

A rollout changes which model participates in a decision. Shadow evaluation can compare predictions without changing user actions. A canary or ramp routes an explicit portion of traffic to a candidate. These mechanisms provide operational evidence, but a prediction difference or a successful router is not automatically evidence of a beneficial causal effect.

Stable assignment is useful when repeated requests from one entity should remain in the same cohort. The first case hashes a declared entity identity into a bounded bucket. Increasing the threshold creates a nested larger cohort. This is a deterministic assignment mechanism, not a guarantee of balance or an analysis of an experiment.

The second case compares scores from two small candidate outputs. Their thresholded decisions agree even though probabilities differ. A single disagreement count would therefore miss a change in confidence. A real rollout policy should consider input compatibility, output behavior, service errors, latency, monitoring and appropriately designed outcome evidence.

## Syntax and data contract

The hash bucket is computed from a stable namespaced identity and a fixed rule. Keep the rule and salt/version with the rollout contract. Shadow comparison inspects both numeric score changes and derived actions. The fixture's acceptance limit is a declared illustrative threshold, not an estimated business-value rule.

## Worked case 1: Use a stable nested cohort

The first case assigns one hundred synthetic entities and verifies that a ten-percent bucket range is contained within the twenty-five-percent range. It checks deterministic assignment rather than assuming every small sample has an exact percentage count.

**Expected evidence:** The smaller selected set is a nonempty subset of the larger set, and assignments repeat exactly.

```python
import hashlib


def example_one():
    assignments = [
        int(hashlib.sha256(f"entity:{i}".encode()).hexdigest()[:8], 16) % 100 for i in range(100)
    ]
    small = {i for i, bucket in enumerate(assignments) if bucket < 10}
    larger = {i for i, bucket in enumerate(assignments) if bucket < 25}
    assert small <= larger and len(small) > 0 and len(larger) < 100
    assert assignments == [
        int(hashlib.sha256(f"entity:{i}".encode()).hexdigest()[:8], 16) % 100 for i in range(100)
    ]
    return {
        "stable_cohort": True,
        "nested_ramp": True,
        "small_n": len(small),
        "larger_n": len(larger),
    }


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Observe score changes without action changes

The second case has zero decision disagreements at threshold 0.5 but nonzero probability differences. This demonstrates why monitoring only labels can hide a meaningful interface change.

**Expected evidence:** All thresholded decisions agree, while the probabilities have changed.

```python
import numpy as np


def example_two():
    old = np.array([0.1, 0.3, 0.6, 0.9])
    candidate = np.array([0.2, 0.4, 0.7, 0.8])
    disagreement = int(np.sum((old >= 0.5) != (candidate >= 0.5)))
    assert disagreement == 0 and np.max(np.abs(old - candidate)) > 0
    accepted = bool(np.max(np.abs(old - candidate)) <= 0.15)
    assert accepted
    return {
        "shadow_disagreement": disagreement,
        "prediction_change_exists": True,
        "no_causal_effect_claim": True,
    }


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

Unstable cohorts can produce confusing comparisons and repeated exposure changes. Zero disagreement can conceal probability changes. A rollout that meets latency limits can still harm an outcome. Diagnose these separately and connect each decision to the evidence it actually requires.
