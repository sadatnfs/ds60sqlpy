# asm-016: A custom Transformer and durable parameters

Tutorial mode. Stage: intermediate. Direct prerequisites: `asm-015`, `spark-012`.

## Starting point and result

A Transformer applies an already specified operation to a DataFrame. It does not learn parameters from training data. Our `Shift` stage adds a configurable finite offset to a double column. Although the arithmetic is simple, the example implements schema checks, parameter validation, copying and saved-state round trips, which are essential parts of a reusable pipeline stage.

## Mechanism: parameters are named, owned state

The stage extends `Transformer`, `HasInputCol`, `HasOutputCol` and `DefaultParamsWritable`. Each stage has a UID that distinguishes parameter ownership in a pipeline. A `DoubleParam` stores the offset and validates finiteness. `setDefault` provides a default without silently overwriting an explicitly configured value.

`transformSchema` checks the input type and rejects an output-column collision. This allows pipeline construction and execution to fail with a meaningful contract before replacing existing data. `transform` validates the schema and returns a new DataFrame with a native addition expression. Nullability follows the input because adding a finite offset preserves null.

Persistence works here because all required state is represented by supported Params. The companion object extends `DefaultParamsReadable[Shift]`, and the class supplies the constructor shape needed for restoration. This pattern does not automatically serialize arbitrary external connections, anonymous closures or large learned tensors. Such state needs a reviewed custom writer/reader and format version.

## Worked case: save and restore an offset

The input values are one, two and null. A shift of three creates four, five and null. The stage is written to a newly created temporary model directory and loaded through `Shift.load`. The restored stage must produce identical rows and retain its UID. This checks behavior, not merely the existence of metadata files.

The temporary directory exists inside the disposable execution environment. An ordinary classroom run does not make that filesystem artifact a durable learner model download. The example teaches the persistence API; a real project must define an explicit artifact export location and checksum. Do not claim saved model availability after container deletion without a mounted, governed destination.

## Worked case: reject accidental replacement

A second input already contains the output column. The stage must throw `IllegalArgumentException` rather than silently overwrite it. This matters in a multi-stage pipeline: a typo in an output name could otherwise replace a feature or label and produce plausible but incorrect downstream predictions.

The finite-parameter validator similarly rejects NaN or infinity at configuration time. The stage does not promise to cleanse arbitrary nonfinite input values. A feature-quality stage can handle that separately, with explicit accounting rather than an invisible coercion.

## Failure diagnosis

A model that works before saving but fails after loading may depend on unpersisted fields, a missing class on the executor classpath or incompatible code. Save/load tests should run from the same public loading entrypoint a user will invoke. A class that exists only in an interactive notebook scope can be difficult to resolve in another application.

## Interview discussion

**Why preserve the UID?** Parameter maps refer to stage identity and parameter names. Stable restoration preserves the expected ownership relationship, especially when pipelines contain several instances of the same class.

**Is a Transformer allowed to launch Spark actions?** It can, but that often violates expectations of a cheap lazy transformation. Learning data-dependent values generally belongs in an Estimator's `fit` method.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-scala`.

```scala
import org.apache.spark.sql.{SparkSession, DataFrame, Dataset, Encoder, Encoders}
import org.apache.spark.sql.functions._

import org.apache.spark.ml.{Estimator, Model, Transformer}
import org.apache.spark.ml.param.{ParamMap, DoubleParam}
import org.apache.spark.ml.param.shared.{HasInputCol, HasOutputCol}
import org.apache.spark.ml.util.{DefaultParamsWritable, DefaultParamsReadable, Identifiable}
import org.apache.spark.sql.types.{StructType, StructField, DoubleType}

class Shift(override val uid: String)
    extends Transformer
    with HasInputCol
    with HasOutputCol
    with DefaultParamsWritable {
  def this() = this(Identifiable.randomUID("shift"))
  val amount = new DoubleParam(this, "amount", "finite offset", (x: Double) => x.isFinite)
  setDefault(amount -> 0.0)
  def setInputCol(value: String): this.type = set(inputCol, value)
  def setOutputCol(value: String): this.type = set(outputCol, value)
  def setAmount(value: Double): this.type = set(amount, value)
  override def transformSchema(schema: StructType): StructType = {
    require(schema($(inputCol)).dataType == DoubleType, "input must be double")
    require(!schema.fieldNames.contains($(outputCol)), "output already exists")
    schema.add(StructField($(outputCol), DoubleType, schema($(inputCol)).nullable))
  }
  override def transform(data: Dataset[_]): DataFrame = {
    transformSchema(data.schema); data.withColumn($(outputCol), col($(inputCol)) + lit($(amount)))
  }
  override def copy(extra: ParamMap): Shift = defaultCopy(extra)
}
object Shift extends DefaultParamsReadable[Shift]
object Main {
  def main(args: Array[String]): Unit = {
    val spark = SparkSession.builder
      .master("local[2]")
      .appName("advanced-spark-modeling")
      .config("spark.ui.enabled", "false")
      .config("spark.driver.host", "127.0.0.1")
      .config("spark.driver.bindAddress", "127.0.0.1")
      .config("spark.sql.shuffle.partitions", "2")
      .config("spark.sql.adaptive.enabled", "false")
      .config("spark.sql.ansi.enabled", "true")
      .getOrCreate()
    require(spark.version == "4.0.1", "This example targets Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    import spark.implicits._
    try {
      val input = Seq[java.lang.Double](1.0, 2.0, null).toDF("x")
      val transform = new Shift().setInputCol("x").setOutputCol("shifted").setAmount(3.0)
      val directory =
        java.nio.file.Files.createTempDirectory("asm-shift-").resolve("model").toString
      transform.write.save(directory)
      val restored = Shift.load(directory)
      val expected = transform.transform(input).collect().toSeq
      require(restored.transform(input).collect().toSeq == expected)
      require(restored.uid == transform.uid)
      require(expected.head.getDouble(1) == 4.0 && expected.last.isNullAt(1))
      val invalid = try { restored.transform(input.withColumn("shifted", lit(0.0))); false }
      catch { case _: IllegalArgumentException => true }
      require(invalid)
      println("Saved/restored offset, UID, null preservation and collision rejection passed")
    } finally { spark.stop() }
  }
}
```
