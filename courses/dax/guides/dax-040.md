## The question and the mechanism

Separate enrolled members, active members and unavailable follow-up periods.

A cohort groups units by an entry event or date. Retention compares later activity with a specified eligible cohort population. It is not automatically a count of events divided by another event count. Repeated activity must not turn one member into several retained units, and inactive but eligible members must not disappear from the denominator.

CohortMember contains two January entrants and two February entrants. January members 100 and 200 are both active at entry; only 100 is active in February, so one-month retention is 1/2. In the February cohort, only 300 is active at entry while 400 is not, giving entry-month activity 1/2 under the full-enrollment denominator.

March is beyond the available activity window in this fixture. February's month-one retention is therefore unavailable, not zero. A cohort matrix that fills those future cells with zero can falsely imply that newer cohorts perform worse. Define calendar month versus elapsed-day age, eligibility and observation coverage separately before comparing cohorts.

## Vocabulary and expression anatomy

The CohortMember-to-Activity relationship restricts the activity fact to the selected cohort. DISTINCTCOUNT counts active member identities, not activity rows. A declared LastObservedMonth guards an unavailable future result. The examples use literal month keys; do not implement month arithmetic by adding one to a YYYYMM integer across December.

Concepts to explain in your own words: **cohort**, **retention**, **eligibility**, **observation age**, **censoring**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    VAR LastObservedMonth = 202502
```

### Case A: January cohort at one-month age

**Starting context:** Analytics cohort population; January entrants 100/200; activity observed through February 2025.

```dax
EVALUATE CALCULATETABLE ( ROW ( "EligibleMembers", COUNTROWS ( CohortMember ), "ActiveAtEntry", CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202501 ), "ActiveAtAgeOne", CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202502 ), "RetentionAtAgeOne", DIVIDE ( CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202502 ), COUNTROWS ( CohortMember ) ) ), CohortMember[CohortMonth] = 202501 )
```

**Context trace:**

1. Both January members remain in the eligible denominator.
2. Both are active in January, but only 100 is active in February.
3. One-month retention is 1/2, regardless of how many events member 100 generated.

**Hand-derived worked-reference result:**

| EligibleMembers | ActiveAtEntry | ActiveAtAgeOne | RetentionAtAgeOne |
| --- | --- | --- | --- |
| 2 | 2 | 1 | 0.5 |

This denominator is the entry cohort, not the subset observed active in a later month. Filtering to active members before counting eligibility would inflate retention.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: A newer cohort has unavailable follow-up

**Starting context:** February entrants 300/400; March follow-up is outside the declared observed months.

```dax
EVALUATE CALCULATETABLE ( ROW ( "EligibleMembers", COUNTROWS ( CohortMember ), "ActiveAtEntry", CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202502 ), "EntryActivityRate", DIVIDE ( CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202502 ), COUNTROWS ( CohortMember ) ), "RetentionAtAgeOne", IF ( 202503 > LastObservedMonth, BLANK(), DIVIDE ( CALCULATE ( DISTINCTCOUNT ( Activity[MemberKey] ), Activity[MonthKey] = 202503 ), COUNTROWS ( CohortMember ) ) ) ), CohortMember[CohortMonth] = 202502 )
```

**Context trace:**

1. Both members are enrolled, but only 300 has February activity.
2. Entry activity is 1/2.
3. Month-one retention asks about March, so the coverage guard returns BLANK rather than an invented zero.

**Hand-derived worked-reference result:**

| EligibleMembers | ActiveAtEntry | EntryActivityRate | RetentionAtAgeOne |
| --- | --- | --- | --- |
| 2 | 1 | 0.5 | BLANK |

The two 50-percent values in the lesson have different ages and meanings. A matrix must expose both cohort month and observation age.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Count retained identities, not event rows.
2. The January eligible population is unchanged.
3. State entry rule, eligible denominator, activity criterion and observed age.
4. The denominator would become conditional on the outcome.
5. YYYYMM is a label, not a continuous month counter.
6. Incomplete follow-up is not automatically a failure event.
