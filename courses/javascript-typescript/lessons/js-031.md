# js-031: Safe browser rendering and security boundaries

Use the browser fixture and record predictions before inspecting solutions.

## Exercises

1. **Render a markup-looking title as literal text: change one input.** Save the snippet and inspect the resulting DOM and visible title. Then change one attribute, label or handler in your copy and predict the visible difference before reloading.
   **Expected:** The rebuild reproduces the observation: the angle-bracket text is visible; no img element is created. The changed copy differs as you predicted.
   **Verify:** Record the browser observation, then explain it: The suspicious-looking string is a local inert test value. textContent preserves it as characters, so the browser does not create the image or interpret its event attribute.

2. **Validate a URL before creating a link: debug a regression.** Use a same-origin relative link and reject a javascript URL under the shown policy. Then break one selector or attribute in a copy, predict which behavior exposes it, and repair it.
   **Expected:** The broken copy no longer shows that local help is accepted; javascript: is rejected. The repair restores it.
   **Verify:** Record the first browser observation that differed, then explain the repair: The policy acts on parsed components rather than textual resemblance.

3. **Install the complete fixture CSP.** Inspect the reference HTML and load its external script and stylesheet under the meta policy.
   **Expected:** local resources load; no inline handlers or eval are needed.
   **Verify:** Record the browser observation that shows it, then explain why: The policy permits only the local resource categories the fixture requires.

4. **Reject origin and credential tricks.** Try a different port, an external origin, a data URL and embedded credentials.
   **Expected:** every candidate is rejected by the local-link policy.
   **Verify:** Record the browser observation that shows it, then explain why: Changing the port changes origin.

5. **Inspect dynamic text without changing policy.** Enter strong-tag-looking text, render it, then inspect child element count.
   **Expected:** text remains literal and child element count stays zero.
   **Verify:** Record the browser observation that shows it, then explain why: An allowlisted script can still be unsafe if it uses an injection sink.

6. **Explain the actual policy boundary.** Record what the meta policy proves and what needs headers or server authorization.
   **Expected:** no claim that CSP authenticates callers, CORS authorizes actions, or meta implements frame-ancestors.
   **Verify:** Record the browser observation that shows it, then explain why: Browser restrictions and server decisions solve different problems.
