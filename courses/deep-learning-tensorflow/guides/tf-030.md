# tf-030: Distributed gradient semantics on one CPU

## Level and prerequisites

Advanced; approximately 120 minutes. Direct prerequisites: `tf-029`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Distinguish a mean over examples from an unweighted mean over unequal shards. The central investigation is concrete: Simulate shards of sizes 1 and 3 with fixed gradients; compare naive shard averaging with example-weighted aggregation and gradient accumulation. The finish condition is Shard means 2 and 6 combine to 5 when weighted 1:3, not 4. A microbatch accumulator matches the full-batch mean before any optional distributed runtime. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

A distributed or accumulated gradient must represent the intended global objective. If shards have different numbers of examples, averaging shard means equally weights shards rather than observations. A one-example shard with mean gradient2 and a three-example shard with mean6 combine to5 under an example mean, not4. Gradient accumulation has the same issue when microbatches differ in size. Accumulate gradient sums and counts, divide once, then apply one optimizer update. Applying an update after each microbatch is a different trajectory because later gradients use changed parameters. This lesson simulates all shards on one CPU and does not claim a distributed runtime was exercised.

## Vocabulary and concepts

**Shard:** A subset of observations processed as one partition.

**Gradient accumulation:** Combining gradients before one optimizer update.

**Global denominator:** The total participating example count across partitions.

## Syntax anatomy and reasoning sequence

The identity global_mean=sum(count*local_mean)/sum(count) is independent of a communication library. tf.reduce_sum exposes numerators. Hold weights fixed while accumulating gradients, then assign once. A regularization term needs a deliberate global scaling convention so it is not accidentally multiplied by the number of shards. The examples distinguish mathematical reduction from runtime placement.

## Derive the global objective before combining workers

For N examples, an example-weighted objective is the sum of individual losses
divided by N, plus any separately defined regularization term. A shard with
one example and mean gradient 2 contributes numerator 2. A shard with three
examples and mean gradient 6 contributes numerator 18. The combined gradient
is (2 + 18)/4 = 5. Averaging the two means gives 4 and silently assigns more
weight to each example in the smaller shard.

Microbatch accumulation follows the same arithmetic. Hold the parameters
fixed while computing gradient sums for all contributing microbatches, add
the sums and divide by the total count before one update. Applying an update
after the first microbatch changes the parameters at which the second
gradient is evaluated. That creates a different optimization trajectory,
even if the final reporting denominator is correct.

An empty shard contributes a zero numerator and count zero. Its local mean
is undefined, so forming that mean and multiplying a NaN by zero is not a
valid repair. If every shard is empty, there is no example mean at all.
Similarly, a token-weighted objective uses the number of participating tokens,
not automatically the number of sequences. Choose the unit before reduction.

Regularization needs its own scaling convention. If the intended global
objective adds lambda times R(w) once, adding that full term on every shard
and summing multiplies it by the number of shards. TensorFlow documents
[global loss and regularization scaling](https://www.tensorflow.org/tutorials/distribute/custom_training)
for distributed custom loops. This lesson verifies the arithmetic on one
CPU. Communication, device placement and distributed failure recovery need
separate runtime evidence.

## Worked example / walkthrough

### Example A: Weight shard means

Multiplying each local mean by its count restores the gradient numerator. The final division then gives each example equal weight.

```python
import numpy as np
import tensorflow as tf

means=np.array([2.,6.]); counts=np.array([1,3])
assert np.average(means,weights=counts)==5 and means.mean()==4
```

**Expected:** global5; naive4.

### Example B: Recover a full-batch mean

The explicit per-example values are an independent oracle for the shard calculation. A test that compares two formulas using the same wrong weights would miss the error.

```python
import numpy as np
import tensorflow as tf

means=np.array([2.,6.]); counts=np.array([1,3])
assert np.average(means,weights=counts)==5 and means.mean()==4
g=np.array([2.,4.,6.,8.]); parts=[g[:1],g[1:]]
recombined=sum(p.sum() for p in parts)/sum(len(p) for p in parts)
assert recombined==g.mean()==5
```

**Expected:** both full and reconstructed means5.

## Common pitfalls and diagnosis

Write each numerator and its contributing count before inspecting
an average. Unequal and empty shards expose assumptions that equal-sized
batches conceal. If accumulated and full-batch updates disagree, check whether
weights moved during accumulation, whether regularization was duplicated,
and whether the denominator counts examples or active tokens.
