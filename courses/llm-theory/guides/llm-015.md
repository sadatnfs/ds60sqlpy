## Purpose and mental model

<!-- textbook-foundations-start -->

### Automatic differentiation follows a computation you already understand

A trainable neural model has parameters that influence its outputs, and a scalar objective that evaluates those outputs. Training needs to know how a small change in each parameter would change that objective. A gradient supplies this local sensitivity. Automatic differentiation computes it by applying the chain rule through the operations that actually ran; it is not a separate model guessing a useful update and it does not optimize a parameter merely because backward was called.

The scalar fixture makes each role visible. The parameter is w, the target value in the objective is 2, and the loss is L(w)=(w-2)^2. At w=0, the loss is 4. Differentiating gives dL/dw=2(w-2)=-4. A negative derivative means increasing w slightly would reduce the loss locally. PyTorch records the subtraction and square when w requires gradients, then backward accumulates their chain-rule result in w.grad. The value of w remains zero until a separate update operation changes it.

If an optimizer used learning rate eta=0.1, a gradient-descent step would compute w_new=w-eta*dL/dw=0.4. That would reduce the quadratic loss to 2.56. This update is a derived illustration, not an extra operation secretly performed by the reference's first exercise. Separating sensitivity from mutation helps diagnose a common failure: correct gradients can exist while the wrong optimizer parameter list leaves the intended weights unchanged.

The second backward call in the fixture creates another computation at the same unchanged parameter and adds another -4 to the stored gradient, giving -8. This is accumulation, not a new derivative formula. Accumulation is useful when several microbatches should contribute to one update, provided their weighting is correct. It becomes a bug when a training loop intends independent updates but forgets to clear old gradient state. Resetting grad to None makes the next backward begin from an absent accumulator.

A finite-difference calculation offers an independent check. Evaluate the objective at w+h and w-h, subtract and divide by 2h. For this quadratic, the exact arithmetic matches -4 at w=0; floating-point subtraction still limits extremely small h. The method is useful for a tiny diagnostic because it does not reuse the autograd implementation. It is expensive as a general training method because checking every parameter separately requires many objective evaluations.

Language-model embeddings add shared parameters to the same story. IDs [2,0,2] read row two twice, so both occurrences can contribute gradients to that row. The integer IDs are fixed selectors; gradients update the table values, not the token numbering. Detaching a tensor can intentionally end a gradient path for reporting or inference, but placing that detachment inside a trainable forward path changes which parameters the objective can affect. [PyTorch's autograd notes](https://docs.pytorch.org/docs/2.9/notes/autograd.html) describe the recording and accumulation semantics used here.

## Vocabulary and concepts

**Autograd:** Automatic differentiation through recorded tensor operations.

**Leaf gradient:** Accumulated derivative stored on an input or parameter tensor.

**Detach:** Remove a tensor value from its existing gradient graph.

## Syntax anatomy and reasoning sequence

torch.tensor(...,requires_grad=True) creates a leaf whose .grad is populated after backward. Clear gradients before a new independent step because backward accumulates by default. detach returns a value with requires_grad=False. nn.Embedding.from_pretrained(...,freeze=False) wraps a fixed literal table as trainable state. IDs use torch.long and select rows along the vocabulary axis.

## The gradient is a local calculation, not an update

For L(w)=(w-2)^2, the derivative is 2(w-2). At w=0 the loss is 4 and the gradient is -4. backward computes and accumulates that derivative into the leaf tensor's grad field; it does not change w. An optimizer or an explicit update rule would still need to apply w_new=w-learning_rate*gradient. With learning rate 0.1, that rule would move w to 0.4, but the current derivative fixture deliberately keeps the parameter fixed while inspecting gradient state.

A central finite difference compares L(h) and L(-h), divided by 2h. For this quadratic the real-arithmetic expression equals -4 for any nonzero h, while floating-point subtraction can still introduce error. More general nonlinear functions have truncation error as well, so a useful check balances a sufficiently small step against cancellation. Float64 makes this small diagnostic easier to inspect than an unnecessarily low-precision calculation.

## Accumulation, detachment and snapshots

Two separate backward calls at the same unchanged w add two copies of -4, producing grad=-8. Setting grad=None clears accumulated state so the next backward produces -4 again. This is intentional accumulation behavior, not evidence that the derivative formula changed. A training loop must choose whether several microbatches contribute to one update or whether each update begins with cleared gradients.

A detached tensor keeps the value but removes the autograd connection. Detach is not a deep copy: storage may still be shared. Use detach().clone() when an independent snapshot is required. Converting a tensor to a Python scalar with item also leaves the differentiable tensor path. Such operations are useful for reports, but putting them into the computation that should produce a training loss can disconnect parameters.

Embedding lookup is differentiable with respect to table entries, not the integer token IDs. Looking up IDs [2, 0, 2] returns rows two, zero and two. If an objective sums all six returned coordinates, the table-row derivative would count those uses: row two receives [2, 2], row zero [1, 1], and untouched rows receive zero under the dense-gradient default. Repeated token identity therefore accumulates evidence into one shared learned row. This connects the simple scalar accumulation example to language-model parameter sharing.


## Worked example / walkthrough

### Example A: Derive a scalar gradient

The analytic derivative2(w-2) supplies an independent oracle. A correct loss alone would not show that the gradient graph was connected.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

w=torch.tensor(0.,dtype=torch.float64,requires_grad=True); loss=(w-2)**2; loss.backward()
assert w.grad.item()==-4 and loss.item()==4
```

**Expected:** gradient-4 and loss4.

### Example B: Compare finite differences

Finite differences perturb the function value rather than reading autograd internals. Agreement away from a nondifferentiable point supports the derivative calculation.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

w=torch.tensor(0.,dtype=torch.float64,requires_grad=True); loss=(w-2)**2; loss.backward()
assert w.grad.item()==-4 and loss.item()==4
h=.001; numeric=(((h-2)**2)-((-h-2)**2))/(2*h)
np.testing.assert_allclose(numeric,-4,atol=1e-10,rtol=0)
```

**Expected:** finite difference approximately-4 within1e-10.

## Common pitfalls and diagnosis

Separate parameter value, requires_grad, accumulated grad and graph connectivity. A second backward on a new loss can accumulate another derivative without moving the parameter. Zero and None gradients have different meanings. Detach removes a gradient path but may retain shared storage; a snapshot intended for comparison needs an independent copy.
