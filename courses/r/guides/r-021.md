## Outcome and mechanism

Build a validated S3 measurement value, dispatch a domain-specific generic and reject malformed objects at the public boundary.

An S3 object is an ordinary R value with a class attribute. A numeric vector, list or other underlying representation can carry that attribute. Assigning a class does not install a schema or prove an invariant. For an analytical measurement, the contract must state what the values represent, which units accompany them and how missing or infinite values are handled.

This lesson uses a list with a finite numeric vector and one nonempty unit string. An empty vector is allowed and its total is zero in the declared unit. Missing values, matrices and complex numbers are rejected. A low-level constructor assembles the representation; a validator checks the invariant; the public constructor combines both. Keeping these roles visible explains why a fast internal constructor must not become an unchecked public input boundary.

A generic describes an operation. UseMethod chooses a method from the object's class and the generic name. measurement_total.measurement is a method for one class; measurement_total.default makes unsupported input fail explicitly. The method validates again because a caller can forge a class attribute or modify a list field after construction. In a package, exported generics and registered methods need NAMESPACE declarations, which the later package lesson explains.

For these list and numeric components, assignment has value semantics: changing the copied list's values leaves the original observable value unchanged. This does not mean every S3 object is deeply immutable. A list can contain an environment or another reference object, and that component can still be shared. The later R6 lesson isolates that difference with actual mutable objects.

Choose domain operations deliberately. A total of measurements retains the unit; adding milliseconds to seconds without conversion would silently change meaning. Implementing every base arithmetic method is unnecessary for a small public interface and creates additional recycling, missingness and compatibility obligations. This lesson exposes only one total operation and tests the boundary with forged and unsupported inputs.

A method's printed representation is separate from its returned value. Downstream analysis should receive a named numeric total, not parse console text. Tests inspect the numeric result, name and unchanged input. A class label is useful for dispatch, while validation and tests supply evidence about this particular contract.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Constructor | A function that creates the chosen internal representation. |
| Validator | A function that checks and rejects violations of an object invariant. |
| Generic | An operation whose implementation is selected from an object class. |
| S3 method | A function conventionally named generic.class and selected by S3 dispatch. |
| Value semantics | Changes to a copied value do not mutate another observable value under the stated representation. |

## Read the syntax

structure(..., class="measurement") labels a list. UseMethod("measurement_total") dispatches to measurement_total.measurement. The validator returns x when valid and raises stop(..., call.=FALSE) otherwise. A named scalar such as c(ms=6) preserves the total unit without inventing arithmetic for incompatible objects.

## Worked examples

### Example 1: Construct a unit-bearing value and dispatch its total

```r
new_measurement <- function(values, unit) {
  structure(list(values = values, unit = unit), class = "measurement")
}
validate_measurement <- function(x) {
  if (!inherits(x, "measurement") || !is.list(x) ||
    !is.numeric(x$values) || is.complex(x$values) ||
    !is.null(dim(x$values)) || any(!is.finite(x$values))) {
    stop("values must be a finite numeric vector", call. = FALSE)
  }
  if (!is.character(x$unit) || length(x$unit) != 1L ||
    is.na(x$unit) || !nzchar(x$unit)) {
    stop("unit must be one nonempty string", call. = FALSE)
  }
  x
}
measurement <- function(values, unit) {
  validate_measurement(new_measurement(values, unit))
}
measurement_total <- function(x, ...) UseMethod("measurement_total")
measurement_total.measurement <- function(x, ...) {
  x <- validate_measurement(x)
  setNames(sum(x$values), x$unit)
}
measurement_total.default <- function(x, ...) {
  stop("measurement_total requires a measurement", call. = FALSE)
}

x <- measurement(c(2, 4), "ms")
result <- measurement_total(x)
stopifnot(identical(result, c(ms = 6)))
print(result)
```

**Expected observation:** A named numeric total ms=6.

The generic receives the complete object. Dispatch selects the measurement method, which checks the fields and returns six milliseconds. The class controls selection; it does not replace the explicit checks.

### Example 2: A copied list and a forged class

```r
new_measurement <- function(values, unit) {
  structure(list(values = values, unit = unit), class = "measurement")
}
validate_measurement <- function(x) {
  if (!inherits(x, "measurement") || !is.list(x) ||
    !is.numeric(x$values) || is.complex(x$values) ||
    !is.null(dim(x$values)) || any(!is.finite(x$values))) {
    stop("values must be a finite numeric vector", call. = FALSE)
  }
  if (!is.character(x$unit) || length(x$unit) != 1L ||
    is.na(x$unit) || !nzchar(x$unit)) {
    stop("unit must be one nonempty string", call. = FALSE)
  }
  x
}
measurement <- function(values, unit) {
  validate_measurement(new_measurement(values, unit))
}
measurement_total <- function(x, ...) UseMethod("measurement_total")
measurement_total.measurement <- function(x, ...) {
  x <- validate_measurement(x)
  setNames(sum(x$values), x$unit)
}
measurement_total.default <- function(x, ...) {
  stop("measurement_total requires a measurement", call. = FALSE)
}
assert_error <- function(expr, pattern) {
  message <- tryCatch(
    {
      force(expr); NULL
    },
    error = conditionMessage
  )
  stopifnot(is.character(message), length(message) == 1L, grepl(pattern, message))
}

a <- measurement(c(2, 4), "ms")
b <- a
b$values[[1]] <- 100
stopifnot(a$values[[1]] == 2, measurement_total(b)[[1]] == 104)
forged <- new_measurement(c(2, Inf), "ms")
assert_error(measurement_total(forged), "finite numeric vector")
assert_error(measurement_total(c(2, 4)), "requires a measurement")
print(c(original = measurement_total(a)[[1]], copy = measurement_total(b)[[1]]))
```

**Expected observation:** Original total 6, copied total 104; forged and unsupported inputs rejected.

The copy can change without changing a. A forged class gets as far as dispatch but fails validation inside the method. Unsupported plain numeric input reaches the deliberately defined default method.

## Reference review

The reference separates assembly, validation and dispatch, so each failed input has a stated cause. The matrix case is numeric but has a shape that the vector contract excludes. The NA case demonstrates a declared policy rather than accidental na.rm behavior.

The count generic is an independent operation with the same object invariant. Its default rejection prevents unrelated values from silently acquiring domain meaning. Copy assertions establish behavior for the actual numeric-list representation. They are not a proof that all S3 objects are immutable or that package registration has already occurred.

Compare your implementation with the reference only after retaining your own attempt. Different readable implementations can satisfy the same behavioral contract. Inspect type, shape, missingness and boundary behavior alongside printed numbers.
