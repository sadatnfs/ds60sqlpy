go-003: Decisions, loops and invariants#

Level and prerequisites#

Beginner. Allow about 90 minutes, then revisit the transfer case later. Prerequisites: go-002

Learning objectives#

By the end, explain invariant, short circuit, half-open interval; implement the six investigations below; and defend the expected result of a changed input before running it. A passing reference is evidence about that program, not a certification of your independent understanding.

Why this mechanism matters#

Control flow determines which statements execute. A condition is a boolean expression, not a number used as a truth value. Go's for statement covers counting loops, condition-controlled loops and collection iteration. The safest way to reason about a loop is to name an invariant: a statement true before the first iteration and preserved by every iteration. In a prefix sum, the accumulator contains exactly the elements already visited. Empty input is therefore not an exceptional accident; the initial accumulator already represents its result. Short-circuit operators also affect execution, which makes a guard before a potentially unsafe operation meaningful.

Vocabulary and concepts#

  • Invariant: A property maintained across every loop iteration.
  • Short circuit: Skipping an operand after the result is determined.
  • Half-open interval: A range including its start and excluding its end.

Syntax anatomy and reasoning#

if condition { ... } selects a branch. && skips the right operand when the left is false. for i := 0; i < len(items); i++ visits a half-open index interval. break leaves the innermost loop; continue skips to its next iteration. switch compares one expression against alternatives and does not fall through by default. A boundary using <= instead of < often attempts one extra iteration.

Worked example / walkthrough#

Worked example 1: Trace a prefix sum#

Sum 2, 4 and 6 while checking every visited prefix.

package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Trace a prefix sum
	{
		items := []int{2, 4, 6}
		sum := 0
		for _, x := range items {
			sum += x
		}
		check(sum == 12 && len(items) == 3, "sum")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: The final sum is 12 and three elements were visited.

The accumulator starts at the additive identity. Each iteration includes exactly one new value; double addition or a skipped element breaks the independently known total.

Worked example 2: Handle empty data#

Apply the same summation to an empty slice.

package main

import (
	"fmt"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Trace a prefix sum
	{
		items := []int{2, 4, 6}
		sum := 0
		for _, x := range items {
			sum += x
		}
		check(sum == 12 && len(items) == 3, "sum")
	}

	// Handle empty data
	{
		sum := 0
		for _, x := range []int{} {
			sum += x
		}
		check(sum == 0, "empty sum")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: The result is 0 with no special invented element.

The loop body never runs. A correct initial state makes the empty case follow from the same algorithm rather than a separate patch.

Common pitfalls and diagnosis#

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from check identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned error is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
