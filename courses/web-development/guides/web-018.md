# web-018: Custom properties, tokens and component themes

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-017`

## Learning objectives

Build two themed cards using one component rule. Explain a token name that survives a palette change. Use custom property, design token and fallback accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

A design token names a recurring design decision such as a spacing step, text color or border radius. CSS custom properties store values that participate in the cascade and can be scoped to a component. A variable name should communicate its purpose, such as --surface or --space-small, rather than merely its current value. That allows the value to change while the role remains stable.

Custom properties are resolved where they are used and usually inherit. A card can override a small set of tokens while retaining the same component rules. A fallback in var supplies a value when a variable is missing or invalid in the relevant way, but a custom property can still produce an invalid declaration at computed-value time. Test the final computed result instead of assuming any string is suitable for any property.

### Key terms

- **Custom property:** A property whose name starts with two hyphens, such as `--space-2`, read with `var()` and inherited by descendants.
- **Design token:** A named design decision, such as a color or spacing step, defined once and reused across components.
- **Var fallback:** The second argument of `var()`, used when the referenced custom property is not defined.
- **Theme:** A set of token values, often scoped to a class or attribute, that changes a component's appearance without changing its rules.

## Syntax anatomy and mechanism

Define shared defaults at :root and override them on a component class. `background:var(--surface,white)` uses the current scope's value. Keep semantic text labels independent of theme color. A theme change must preserve contrast and focus behavior, not merely update an accent swatch.

## Worked example / walkthrough

### Worked example 1: Named decisions

The variable names describe their roles.

```css
:root {
  --surface: #ffffff;
  --ink: #172033;
  --space: 1rem;
}
.card {
  background: var(--surface);
  color: var(--ink);
  padding: var(--space);
}
```

**Expected observation:** One component consumes three reusable tokens.

### Worked example 2: A scoped variation

Only descendants of this component inherit the override.

```css
.card.featured {
  --surface: #e0f2fe;
  --space: 1.5rem;
}
```

**Expected observation:** The featured card changes without copying its full rule set.

## Contrast case: a token holding the wrong kind of value

Custom properties accept almost anything, so the error appears only where the token is used. Inspect the card's padding.

```css
:root {
  --space: blue;
}
.card {
  padding: 2rem;
  padding: var(--space);
}
```

Defining `--space: blue` is valid, because a custom property holds any token sequence. The problem appears at computed-value time: `padding: blue` is invalid, and because the declaration used `var()`, the browser cannot fall back to the earlier `padding: 2rem` line. Instead padding behaves as if it were unset, which for padding means 0. The Computed panel shows padding 0px while `--space` still appears as a defined variable, which is why checking that the token exists is not enough.

**Progressive hint:** Inspect the computed value of the property that uses var().

**Expected evidence:** The component remains usable with its declared fallback.

**Progressive hint:** Delete the variable definition and give var() a second argument.

**Progressive hint:** Rename a color token by what it does rather than how it looks.

## Debugging and common mistakes

Do not treat a token system as a substitute for a content design. Overly granular tokens can make simple changes harder. A dark theme needs a full state review, not a global invert filter.

When a token seems ignored, check the computed value of the custom property on the element itself, since custom properties inherit and the nearest declaration wins. When a declaration using var() is dropped, the token holds a value of the wrong type, such as a color used as a length.
