Outcome and mechanism#

Choose a statistic and grouping contract that matches whether the input contains raw observations or precomputed summaries.

A ggplot layer may transform data before drawing marks. geom_bar normally counts observations by category, while geom_col uses supplied heights. They can look similar when both happen to produce the same bars, but they expect different data contracts. Confusing raw records with preaggregated counts can count groups twice or discard the intended values.

Grouping determines which observations belong to a connected object or statistical calculation. A line for each person needs a person grouping variable. A single line through all rows can connect unrelated trajectories, especially when several entities share the same x values. Colour mappings can sometimes imply grouping, but an explicit group mapping is clearer when identity matters independently of styling.

Histograms introduce a binning policy. Bin width, boundaries and closure determine which observations enter each bin. A different setting can alter the visual pattern without changing the underlying data. Retain that configuration and distinguish counts from density or other normalized quantities.

Inspect the data after the layer's statistic when validating the calculation. A correct bar height, histogram total or number of line groups provides evidence about the chosen transformation. It does not show that the statistic is appropriate for the scientific question or that the displayed plot is readable.

Use the smallest synthetic counterexample that exposes the mistaken contract. Raw category rows versus a three-row count table distinguish count and identity statistics. Two opposing trajectories distinguish entity grouping from row order. Those controls are more informative than a large chart whose transformation choices are difficult to reconstruct.

Vocabulary#

Term Meaning
Statistic A layer transformation such as counting or binning before geometry is drawn.
Identity statistic Using supplied values directly rather than estimating a new summary.
Group mapping An assignment of observations to a shared geometric or statistical object.
Bin policy The width, boundary and inclusion convention defining histogram membership.

Read the syntax#

Use geom_bar for raw category records and geom_col for an already summarized height column. Inspect ggplot_build(p)$data[[1]]$count or y to verify the resulting values. For trajectories, map group explicitly and keep the time/order variable defined. Specify histogram binwidth and boundary when the comparison depends on them.

Worked examples#

Example 1: Raw counts and supplied heights#

d <- data.frame(category = factor(c("A", "A", "B", "C", "C", "C"), levels = c("A", "B", "C")))
counts <- data.frame(category = factor(c("A", "B", "C"), levels = c("A", "B", "C")), n = c(2, 1, 3))
p_count <- ggplot2::ggplot(d, ggplot2::aes(category)) +
  ggplot2::geom_bar() +
  ggplot2::labs(y = "Observation count")
p_identity <- ggplot2::ggplot(counts, ggplot2::aes(category, n)) +
  ggplot2::geom_col() +
  ggplot2::labs(y = "Supplied count")
stopifnot(identical(as.numeric(ggplot2::ggplot_build(p_count)$data[[1]]$y), c(2, 1, 3)))
stopifnot(identical(as.numeric(ggplot2::ggplot_build(p_identity)$data[[1]]$y), c(2, 1, 3)))
print(p_count)
print(p_identity)

Expected observation: Both plots have heights2/1/3, from different declared data representations.

The bars match because the summarized table correctly represents the raw records. Their identical appearance does not make the input contracts interchangeable.

Example 2: Two separate trajectories#

d <- data.frame(time = rep(1:3, 2), value = c(1, 2, 3, 3, 2, 1), person = rep(c("A", "B"), each = 3))
p <- ggplot2::ggplot(d, ggplot2::aes(time, value, group = person, colour = person)) +
  ggplot2::geom_line(linewidth = 1) +
  ggplot2::geom_point() +
  ggplot2::labs(x = "Time", y = "Value", colour = "Person")
built <- ggplot2::ggplot_build(p)$data[[1]]
stopifnot(length(unique(built$group)) == 2, nrow(built) == 6)
print(p)

Expected observation: Six observations arranged into two line groups.

The group mapping preserves entity identity even where trajectories share time coordinates. A line connecting all rows would answer a different and misleading question.

Progressive hints#

  1. Do not supply a precomputed y height to the count statistic.
  2. Use its n column as the identity height.
  3. Check the count statistic's input contract.
  4. Map group to person explicitly.
  5. Inspect the post-statistic count column.
  6. Separate data from the layer transformation.
