# Why a C++ objective is called from R

Start with: r-012, cpp-001.

Outcome: Trace an observation through the objective, optimizer and returned estimate.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A model is a probability statement. Its implementation evaluates a scalar objective for a candidate parameter vector. An optimizer repeatedly asks for that value and its derivatives, and a reporting step converts the final parameter vector into scientific quantities. TMB, Template Model Builder, connects these steps: you describe the objective in templated C++, compile a shared library, and use R to supply data, construct derivatives, optimize and interpret results. It does not choose a defensible likelihood or an identifiable parameterization for you.

Start with \(f(\mu)=\frac12\sum_i(y_i-\mu)^2\). The data \(y\) stay fixed during optimization. The parameter \(\mu\) changes. Its derivative is \(f'(\mu)=n\mu-\sum_i y_i\), so its minimum is the sample mean. The factor one half simplifies differentiation. This is a least-squares objective; calling it a full Gaussian negative log likelihood also requires a variance assumption and its normalizing terms.

### Worked case A: follow the calls

With observations 1, 2 and 6, the value at zero is 20.5 and the derivative is -9. A positive step in the mean lowers the objective. At the optimum 3, the derivative is zero and the value is 7. The companion prints this trace using base R. An actual TMB run replaces the hand-written gradient with `obj$gr`, but the mathematics stays the same.

```r
obj <- make_objective("normal_mean", list(y = c(1, 2, 6)),
                      list(mu = 0, log_sigma = 0))
fit <- fit_objective(obj)
```

This project fragment uses two functions from `projects/tmb-local/R/api.R`; it needs the compiled project and estimates the scale as well. `list` constructs a named collection, `$` extracts a field, and `<-` assigns an R object. The optimizer receives functions, not C++ source text. The ordinary R classroom pad runs the base-R companion; it does not compile this project fragment.

### Worked case B: change an observation

Replace 6 by 9. The optimum becomes 4, not a cached previous result. The new objective must contain the new data. Reusing the old objective while displaying a new table is a dangerous integration error because the optimizer can converge perfectly on stale observations. Our fixed JSON interface constructs a fresh objective per request and returns the observation count and model identity.

Compilation converts template source into machine code for one architecture and R installation. `MakeADFun` then constructs an automatic-differentiation representation for data shapes and parameter declarations. These are different preparation stages. An R object holding native pointers is valid only in its process. Saving it with a generic serializer or shipping it to another Spark executor does not transport a working model.

### Diagnostics and answered discussion

**Does C++ make a wrong model correct?** No. It can evaluate a wrong objective and its exact derivative very quickly. First validate tiny values against independently written formulas. **Is automatic differentiation symbolic algebra?** It applies chain rules to executed elementary operations; it is neither finite differencing nor a general proof system. **What should a fit report contain?** Data identity, objective definition, parameterization, software versions, final objective, gradient, convergence status and scientific interpretation. Later chapters add uncertainty and predictive validation.

Read [the TMB introduction](https://kaskr.github.io/adcomp/Introduction.html) for the architecture. Continue by learning the exact C++ data and parameter contract before changing model families.

### Complete R companion

```r
y <- c(1, 2, 6)
trace_objective <- function(y) {
  mu <- mean(y)
  data.frame(
    mu = c(0, mu),
    value = vapply(c(0, mu), function(m) sum((y - m)^2) / 2, numeric(1)),
    gradient = vapply(c(0, mu), function(m) length(y) * m - sum(y), numeric(1))
  )
}
print(trace_objective(y))
print(trace_objective(c(1, 2, 9)))
stopifnot(mean(y) == 3, mean(c(1, 2, 9)) == 4)
```
