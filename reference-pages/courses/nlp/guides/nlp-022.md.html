nlp-022: Retrieval pipelines and ranking evaluation#

Level and prerequisites#

Advanced; about 120 minutes plus discussion. Direct prerequisites: nlp-021. Read the preceding guide if its notation or information boundaries are unfamiliar.

Purpose and mental model#

Retrieval finds candidate evidence from a corpus, and ranking orders those candidates for a query. A reliable pipeline preserves the distinction between locating related text and proving that it answers a question. The index must also respect which documents are current and permitted before passages reach a model or user.

This lesson implements an inverted index, a specified BM25 formula, reciprocal-rank fusion and exact ranking metrics over three authored documents. It is a real lexical retrieval calculation, with a separate demonstration of combining two supplied rankings. The second ranking is not falsely described as output from a trained dense model. You will see how to compare candidates, fuse ranks and interpret task-level evidence.

Candidate generation places a ceiling on the final system. If a required document never enters the candidate set, a reranker cannot recover it. If a document is retrieved but contradicts or fails to support the question, a high score does not turn it into a valid answer. Evaluate candidate coverage, order and final evidence use separately.

Build an inverted index and derive BM25#

An inverted index maps each term to the document IDs containing it. It avoids scanning every document for every query term and provides document-frequency counts. A posting can later include positions or term frequencies, but the simple index here stores sets of IDs. Term frequency remains in each document's Counter, so repeated router occurrences do not count twice toward document frequency.

The chosen BM25 term score is IDF⁡(q)tf(k1+1)tf+k1(1−b+b length/average_length)\operatorname{IDF}(q)\frac{\mathrm{tf}(k_1+1)}{\mathrm{tf}+k_1(1-b+b\,\mathrm{length}/\mathrm{average\_length})}IDF(q)tf+k1​(1−b+blength/average_length)tf(k1​+1)​, with IDF=log⁡(1+N−∂f+0.5∂f+0.5)\mathrm{IDF}=\log(1+\frac{N-\partial f+0.5}{\partial f+0.5})IDF=log(1+∂f+0.5N−∂f+0.5​). k1 controls term-frequency saturation and b controls length normalization. These conventions should be recorded because variants exist. Query terms are treated as a set here, so repeated query words do not receive an extra query-frequency factor.

For the three documents, N=3N=3N=3 and average length is eight-thirds. Router and reset each occur in two documents, giving the same IDF log⁡(1+1.52.5)\log(1+\frac{1.5}{2.5})log(1+2.51.5​). The shorter router reset document gets two equal contributions. The longer document repeats router but incurs a length adjustment; extra repetition is not rewarded linearly forever.

Fuse candidates without pretending raw scores share units#

A lexical score and an embedding similarity generally have different scales. Adding them directly with arbitrary weights can make one system dominate for numerical reasons. Reciprocal-rank fusion instead gives a document contribution 1k+rank\frac{1}{k+\mathrm{rank}}k+rank1​ from each ranked list, using one-based ranks and a chosen constant k.

With lists [a,b,c] and [b,c,a], document b receives 162+161\frac{1}{62}+\frac{1}{61}621​+611​ when k=60k=60k=60 and ranks first in the fused list. This is a deterministic aggregation policy, not a calibrated probability. The constant affects how much top-rank differences matter, and missing candidates receive no contribution from that list.

Hybrid retrieval should be compared with each component alone on the same held-out queries. It can improve coverage when methods find complementary evidence, but it also adds latency and may introduce irrelevant candidates. A later reranker requires its own training and evaluation boundary.

Interpret ranking metrics and evidence requirements#

MRR uses the reciprocal rank of the first relevant result and suits tasks where one relevant hit is enough. nDCG supports graded relevance and discounts lower positions, normalized by the ideal ordering under a stated gain convention. This reference uses exponential gains 2relevance−12^{\mathrm{relevance}}-12relevance−1 and log⁡2(rank+1)\log_2(\mathrm{rank}+1)log2​(rank+1) discount. An all-zero ideal score returns zero by convention.

A question may require two separate sources, such as a policy and a runtime observation. MRR can be one even if the second required source is missing. Add recall over the required evidence set and inspect whether the passage version and scope support the claim. Evaluation judgments should identify useful evidence rather than merely documents sharing query words.

Use query families, temporal snapshots and permissions representative of deployment. Negative queries with no answer are important: returning a ranked list of zero scores should not imply that the top arbitrary ID is meaningful evidence. An application should distinguish no-known-terms, no-relevant-candidate and insufficient-answer-support cases.

Access filtering is an input boundary#

Filter documents according to authorized scope before generating a context packet for a model. Retrieving private text and hoping the final answer omits it is not the same boundary. The fixture restricts the searchable dictionary to d0 and verifies that only d0 can appear in its score results.

A production system also needs version-aware indexing, tombstones for removed documents, freshness policy and a record of which source chunks entered an answer. A search score is not an authorization decision. Keep access logic deterministic and independently tested, then evaluate relevance inside the permitted corpus.

Worked examples#

Worked example 1: Inspect postings and a numeric score#

Router maps to document IDs d0 and d1, regardless of its repeated occurrence in d1. The hand formula for d0 sums two identical term contributions using length two and average length eight-thirds. The reference compares this exact expression with the implementation before checking the ranking d0,d1,d2.

Worked example 2: Fuse two supplied rankings#

Lists [a,b,c] and [b,c,a] put b at ranks two and one, so it receives 162+161\frac{1}{62}+\frac{1}{61}621​+611​. The fused order begins with b. No neural retrieval model is run here; the example isolates the fusion arithmetic and rejects duplicate IDs within one input ranking.

Worked example 3: Evaluate a delayed first hit#

For ranking [d2,d0,d1] with relevance {d0:3,d1:2,d2:0}, the first relevant result is at rank two, giving reciprocal rank 0.5. Exponential-gain nDCG compares the discounted [0,7,3] gains with ideal [7,3,0]. These numbers describe the judged order, not final answer correctness.

Interview reasoning#

Interview: Why can a dense and lexical score not simply be added? Their scales and distributions differ. Calibrated weighting or a rank-based fusion policy needs validation under the same candidate/evaluation setup.

Interview: What does high MRR miss in a multi-source question? It can reward the first useful document while required additional evidence remains absent. Measure the complete evidence set and final support.

Interview: Where should access filtering occur? Before unauthorized source text enters the retrieval context or downstream model. A final-output filter is a weaker and different boundary.
