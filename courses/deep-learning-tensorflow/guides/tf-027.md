# tf-027: Transfer learning without a model download

## Level and prerequisites

Advanced; approximately 120 minutes. Direct prerequisites: `tf-026`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Freeze and adapt a locally trained feature extractor with an explicit gradient boundary. The central investigation is concrete: Reuse the small classifier from tf-024, freeze its base, train a new head for a relabeled local task and compare gradient/weight changes. The finish condition is Frozen-base weights remain byte-identical while at least one head weight changes; an unfreeze phase uses a new, declared optimizer policy. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

Transfer learning reuses a representation for a related task. Freezing a base means its parameters should not receive optimizer updates while a new head learns from its outputs. The base can still perform computation; frozen does not mean bypassed. Normalization and dropout also have mode-dependent behavior, so a frozen base should be called with a deliberate training flag. Here a small deterministic two-feature transform stands in for the locally trained base from the classifier capstone. No pretrained weights are downloaded. A relabelled target tests whether the new head can change without altering the base. Unfreezing is a new phase with an explicit optimizer policy.

## Vocabulary and concepts

**Base:** The reused representation-producing part of a model.

**Head:** A task-specific output mapping trained on that representation.

**Freeze:** Exclude a parameter set from optimizer updates.

## Syntax anatomy and reasoning sequence

Set base.trainable=False before constructing the training variable list. Use base(x,training=False) to preserve its inference behavior. Train only head.trainable_variables. Snapshot all base weights before the update and compare arrays afterward. When unfreezing, use a new optimizer or explicitly build optimizer state for the newly trainable variables rather than assuming an old optimizer knows them.

## Freezing answers which state may change

This lesson's local base is an identity transformation chosen for inspection.
It has not learned reusable features from a large external dataset. Freezing
it demonstrates parameter selection and state boundaries, not the empirical
benefit of pretrained representations. A real transfer-learning claim would
need a documented source model, suitable target data and a comparison against
training from scratch or a simpler baseline.

During head-only training, the optimizer should receive the head's selected
variables. Check the base weights before and after an update, and separately
check that the head changed. A falling loss is insufficient: the model could
improve by changing a base that was supposed to remain fixed.

Unfreezing creates a new optimization phase. The optimizer must know about
the newly trainable variables and any state it maintains for them. With Keras
fit, changing trainable flags calls for recompilation so the training setup
reflects the new set. Decide whether to carry or restart optimizer state and
record the learning rate for the new phase. Those choices change the next
updates even when the initial weights are identical.

Trainability and forward-pass mode are separate concepts. Dropout changes
its behavior with training mode despite having no learned kernel. Batch
normalization has trainable affine parameters and moving statistics; its
Keras-specific frozen behavior also needs attention during fine-tuning.
Read the [Keras transfer-learning guide](https://keras.io/guides/transfer_learning/)
before adapting that layer. State which parameters and buffers may change
instead of using the word frozen as an ambiguous promise about all behavior.

## Worked example / walkthrough

### Example A: Construct the local base

The identity fixture keeps transfer semantics visible. In the earlier capstone the base may be learned, but freezing should obey the same state contract.

```python
import numpy as np
import tensorflow as tf

base = tf.keras.layers.Dense(2, use_bias=False, kernel_initializer=tf.keras.initializers.Identity())
x = tf.constant([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]])
base(x)
base.trainable = False
np.testing.assert_array_equal(base(x).numpy(), x.numpy())
assert not base.trainable_variables
```

**Expected:** base output equals input; no trainable base variables.

### Example B: Train a new head

Zero initial outputs give nonzero residuals, so this fixture has an observable update. A trainable flag alone would not prove that an optimizer actually changed the head.

```python
import numpy as np
import tensorflow as tf

base = tf.keras.layers.Dense(2, use_bias=False, kernel_initializer=tf.keras.initializers.Identity())
x = tf.constant([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]])
base(x)
base.trainable = False
np.testing.assert_array_equal(base(x).numpy(), x.numpy())
assert not base.trainable_variables
head = tf.keras.layers.Dense(1, use_bias=False, kernel_initializer="zeros")
features = base(x, training=False)
head(features)
before = head.get_weights()[0].copy()
target = tf.constant([[1.0], [2.0], [3.0]])
with tf.GradientTape() as tape:
    loss = tf.reduce_mean((head(features) - target) ** 2)
g = tape.gradient(loss, head.trainable_variables)
tf.keras.optimizers.SGD(0.1).apply_gradients(zip(g, head.trainable_variables))
assert not np.array_equal(before, head.get_weights()[0])
```

**Expected:** at least one head coefficient changes.

## Common pitfalls and diagnosis

Compare snapshots of the base and head separately. If an unfrozen
variable never changes, inspect the optimizer's variable set and compilation
boundary. If weights stay fixed but outputs vary, inspect dropout, batch
statistics and evaluation mode. Keep the identity-base demonstration separate
from claims about useful pretrained features.
