# Separable arrays and scalar or vector scales

Start with: tmb-043, tmb-041.

Outcome: Compose normalized densities while preserving axis order and scale Jacobians.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter checks the scaled-density identity and a Kronecker covariance. The separately prepared [C++ API probes](../projects/tmb-cpp-api/README.md) compile `models/separable_array.cpp`, and `check.R` compares its `SEPARABLE` value and every correlation and scale gradient direction with a dense oracle; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

Density composition lets a model express structure without manually expanding every covariance entry. `SCALE` applies a common scale to a base density. `VECSCALE` applies coordinate-specific scales. `SEPARABLE` combines compatible density structures across array dimensions, often yielding a Kronecker covariance. The transformations must include their normalizing Jacobians, not only divide residuals by a scale.

If \(u=Dz\), with positive diagonal entries \(s_i\), the NLL becomes \(f_z(D^{-1}u)+\sum_i\log s_i\). For a common scale \(s\), the correction is \(q\log s\). These terms affect scale estimation.

## Key terms

- **SCALE:** A density modifier that applies one common scale \(s\) to a \(q\)-dimensional base density, adding \(q\log s\) to the NLL.
- **VECSCALE:** A modifier that applies coordinate-specific scales \(s_i\), adding \(\sum_i\log s_i\) to the NLL as the Jacobian term.
- **SEPARABLE:** A combinator that joins compatible densities across array dimensions, often yielding a Kronecker covariance whose axis order must be checked.
- **Kronecker covariance:** A covariance such as \(\Sigma_{time}\otimes\Sigma_{space}\), which assumes cross-axis covariance factors into products and depends on axis order.

### Worked case A: vector scaling

The companion starts from a correlated two-dimensional standard-scale covariance and applies distinct scales. It checks the direct covariance \(D\Sigma D\) against the transformed-state NLL plus log-Jacobian. Swapping the scales changes which variable has which uncertainty, even if the determinant stays the same.

```cpp
Type nll = density::VECSCALE(density::MVNORM(correlation), scales)(state);
```

The correlation matrix must have the intended interpretation and scales must be valid. An arbitrary covariance supplied as “correlation” can double-count scaling.

### Worked case B: two array axes

For an array with rows indexing space and columns indexing time, a separable covariance can be \(\Sigma_{time}\otimes\Sigma_{space}\) under column-major vectorization. The companion constructs a two-by-three example and checks selected covariance entries. `SEPARABLE(f,g)` applies its first component to the outer dimensions in the reviewed implementation, so axis ordering must be verified against a tiny dense oracle.

```cpp
Type nll = density::SCALE(
    density::SEPARABLE(density::AR1(phi_time), density::AR1(phi_space)),
    tau)(state_array);
```

This pattern states a separability assumption: cross-axis covariance factors into products. Real systems can violate it. More computationally convenient structure is not automatically a better scientific model.

### Answered discussion

**Can I transpose an array without changing the density composition?** Not unless the corresponding components and dimension interpretation are transposed consistently. **Does SCALE change correlation?** A single common scale changes variance, while the base correlation structure remains. **Can VECSCALE replace an arbitrary cross-covariance model?** It changes marginal scales but does not create every possible correlation pattern.

The [density composition source and documentation](https://github.com/kaskr/adcomp/blob/master/TMB/inst/include/tmbutils/density.hpp) is the primary reference. Array-order and normalizer tests are essential before publishing a new composed template.

### Worked case C: when the Jacobian check is too easy

The companion uses scales \((2, 0.5)\), so \(D R D = \begin{pmatrix}4 & 0.4\\ 0.4 & 0.25\end{pmatrix}\) with determinant \(1 - 0.16 = 0.84\), equal to \(|R| \times (2 \times 0.5)^2\). The transformed state is \(z = (0.3/2, -0.4/0.5) = (0.15, -0.8)\). Both printed columns equal 2.202188 (closed-form values, rounded):

```text
log(2 pi)                         1.837877
0.5 * log|R| = 0.5 * log(0.84)   -0.087177
0.5 * z' R^{-1} z                 0.451488
sum(log(scales)) = log 2 + log 0.5  0.000000
NLL                               2.202188
```

The last line is the lesson. The two scales multiply to 1, so the Jacobian term is exactly zero, and an implementation that forgot it would still pass this check. A stronger oracle uses scales whose product is not 1:

```r
scales2 <- c(2, 1)
D2 <- diag(scales2)
missing_jacobian <- nll(u, D2 %*% R %*% D2) - nll(u / scales2, R)
stopifnot(abs(missing_jacobian - log(2)) < 1e-12)
```

Here the gap equals \(\log 2 = 0.693147\) by construction, so a template that drops the correction would fail. Swapping the companion's scales to \((0.5, 2)\) keeps the determinant at 0.84 but changes the quadratic term: the NLL becomes 2.045938, lower by 0.15625 (closed-form values, rounded). A wrong axis assignment can therefore look like a better fit.

### Worked case D: reading the Kronecker entries

The companion's `S` is six by six, ordered as (space 1, time 1), (space 2, time 1), (space 1, time 2), and so on. Each entry is a time correlation times a space correlation:

```text
entry     space lag  time lag  value
S[1, 2]   1          0         0.3
S[1, 3]   0          1         0.7
S[1, 4]   1          1         0.3 x 0.7  = 0.21
S[1, 6]   1          2         0.3 x 0.49 = 0.147
```

If the arguments to `kronecker` were reversed, `S[1, 2]` would become 0.7: neighboring storage positions would be treated as adjacent times rather than adjacent sites. In TMB the same reversal is swapping the two components of `SEPARABLE` relative to the array's dimension order, which is why the tiny dense oracle should index specific cells rather than compare only a total NLL.

### Separability as a testable claim

The product structure means the time correlation at lag 1 is 0.7 for every pair of sites, and the cross-correlation between site 1 at time 1 and site 2 at time 2 is fixed at 0.21. If empirical residual correlations at that space-time lag are clearly higher or lower than the product of the marginal lag correlations, separability is misspecified, and a better optimizer will not repair it.

### Base-R companion (runs in the classroom)

```r
R <- matrix(c(1, .4, .4, 1), 2, 2);scales <- c(2, .5);D <- diag(scales);u <- c(.3, -.4)
nll <- function(x, S) length(x) * log(2 * pi) / 2 + as.numeric(determinant(S, logarithm = TRUE)$modulus) / 2 + sum(x * solve(S, x)) / 2
print(c(direct = nll(u, D %*% R %*% D), transformed = nll(u / scales, R) + sum(log(scales))))
stopifnot(abs(nll(u, D %*% R %*% D) - nll(u / scales, R) - sum(log(scales))) < 1e-12)
space <- .3^abs(outer(1:2, 1:2, "-"));time <- .7^abs(outer(1:3, 1:3, "-"));S <- kronecker(time, space)
print(S);stopifnot(S[1, 2] == .3, S[1, 3] == .7, abs(S[1, 4] - .21) < 1e-12)
```
