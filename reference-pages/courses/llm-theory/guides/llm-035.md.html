llm-035: Inference scheduling and cache isolation#

Status: authored beta content. The manifest inventories complete teaching files; runtime readiness remains a separate, measured property.

Level and prerequisites#

Advanced; approximately 120 minutes. Direct prerequisites: llm-034. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Keep request ownership and stop conditions correct when batching inference. The central investigation is concrete: Interleave two tiny requests with different prefix lengths; compare batched output with independent inference and invalidate caches on model/tokenizer version changes. The finish condition is Each request matches its independent logits within 1e-6 and retains its own token cap. Cache keys include model, tokenizer and request identity. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Inference scheduling interleaves work from multiple requests while preserving each request's context and budget. A batch dimension is a storage arrangement, not permission to mix caches. Requests with different prefix lengths have different position offsets, so a simple shared batch cache is insufficient unless padding and masks are handled deliberately. This lesson uses separate caches and round-robin single-token work, then compares each result with independent full-prefix inference. Model, tokenizer and request identities form the cache key. A change to any component invalidates the state even if tensor shapes still match.

Vocabulary and concepts#

Scheduler: A policy deciding which request performs the next unit of work.

Request isolation: One request cannot inherit another context state.

Versioned cache key: Identity binding between cache, model, tokenizer and request.

Syntax anatomy and reasoning sequence#

Maintain a dictionary from(request,model_version,tokenizer_version) to K/V state. For each scheduled token, look up only that request cache and append one position. Track generated or consumed token counts separately per request. Compare concatenated per-request logits to a full-prefix oracle; never compare only aggregate tensor norms, which could hide cross-request swaps.

Worked example / walkthrough#

Example A: Define unequal requests#

Different request lengths require different offsets. A shared cache tensor without per-request bookkeeping would confuse the next position.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
torch.manual_seed(7); model=TinyDecoder(); model.eval(); requests={'A':[2,5,7],'B':[1,3]}; keys={r:(r,'model-v1','tokens-v1') for r in requests}
assert len(set(keys.values()))==2 and [len(requests[r]) for r in ['A','B']]==[3,2]

Expected: lengths3 and2;distinct keys.

Example B: Interleave bounded work#

Each scheduling action advances one request only. The final cache lengths are conservation checks on the work assigned to each request.

import torch
from torch import nn
from torch.nn import functional as F

        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
