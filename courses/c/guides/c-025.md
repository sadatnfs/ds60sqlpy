# c-025: Recursion, trees and depth budgets

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-024`

## Learning objectives

## Purpose and mental model

Recursion solves a problem by invoking the same mechanism on smaller subproblems. A base case stops the process, and a progress measure explains why each step approaches it. A binary tree naturally decomposes into a root and subtrees, but an unbalanced tree can have depth proportional to its node count. Recursive traversal therefore consumes stack space according to depth, not just total work. For untrusted or very large structures, impose a depth budget or use an explicit stack. This lesson uses fixed stack-allocated nodes with no cycles and no ownership ambiguity, separating traversal reasoning from allocation mechanics.

## Vocabulary and concepts

- **Base case:** The condition ending recursive descent.
- **Progress measure:** A quantity that decreases toward termination.
- **Depth budget:** A bound on nested traversal steps.

## Syntax anatomy and execution trace

A node stores value, left and right pointers. NULL represents an empty subtree. A sum traversal combines the root value with both subtree sums. A depth function returns zero for empty and one plus the greater child depth otherwise. The bounded search checks its remaining depth before descending. General graph traversal also needs visited-state handling because a cycle is not a valid finite tree.

## Worked example / walkthrough

### Worked example 1: Traverse a small tree

Sum a root 2 with children 1 and 3.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Tree {
  int value;
  const struct Tree *left, *right;
};
int tree_sum(const struct Tree *node) {
  if (node == NULL)
    return 0;
  return node->value + tree_sum(node->left) + tree_sum(node->right);
}
size_t tree_depth(const struct Tree *node) {
  if (node == NULL)
    return 0;
  size_t a = tree_depth(node->left), b = tree_depth(node->right);
  return 1 + (a > b ? a : b);
}
bool tree_contains(const struct Tree *node, int target, size_t budget) {
  if (node == NULL || budget == 0)
    return false;
  if (node->value == target)
    return true;
  return tree_contains(node->left, target, budget - 1) ||
         tree_contains(node->right, target, budget - 1);
}

int main(void) {
  /* Traverse a small tree */
  {
    struct Tree left = {1, NULL, NULL}, right = {3, NULL, NULL},
                root = {2, &left, &right};
    CHECK(tree_sum(&root) == 6);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** The total is 6.

Each node contributes once under the acyclic tree assumption.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
