Learning objectives#

Vocabulary and concepts#

  • Scope: The region in which a name is resolved. Within a function, Python first considers local names, then enclosing function scopes, the module, and builtins. This lookup order describes names, not a permanent snapshot of all objects visible when the function was defined.
  • Binding: The association between a name and an object. Assigning a new dictionary to config changes that binding; mutating config["limit"] changes the existing dictionary. Those are observably different operations.
  • Closure: A function that retains access to bindings in an enclosing function after that outer call returns. Each outer call can create a new private binding. Several functions made within one call can share one binding.
  • Late binding: A free name is looked up when the function runs. A loop usually updates one binding repeatedly, so closures made during that loop can all observe its final value. A new factory call supplies a separate scope; a default parameter can instead store the current object during definition.
  • Rebinding with nonlocal: nonlocal total tells an inner function that assignment should change an existing enclosing binding. Reading total does not need this declaration. Assigning to it without the declaration makes it local and can produce UnboundLocalError when it is read first.
  • Decorator: A callable that receives a function and returns its replacement. Writing @decorate above def calculate is equivalent to rebinding calculate = decorate(calculate) after definition. Decoration happens once; the replacement wrapper runs on every later call.

A function and a callable object are related but distinct. For this lesson the decorators accept ordinary synchronous functions with names and docstrings. *args collects positional arguments in a tuple, and **kwargs collects named arguments in a dictionary. Passing function(*args, **kwargs) forwards those arguments. It does not make a copy of the objects referenced by them.

functools.wraps(function) copies useful metadata and installs __wrapped__. Tools such as inspect.signature follow that link by default. Metadata helps inspection, but does not itself enforce a call's domain. A wrapper still needs to reject a negative integer before the body executes if that is its contract. Type annotations likewise describe intended types without checking them.

The integer policy here excludes bool, even though Python makes it an integer subclass. Use that policy consistently when comparing the valid input zero with the invalid input False. This boundary is an exercise choice appropriate to a numerical counter; another API could choose a different policy explicitly.

Worked example / walkthrough#

A loop stores functions before their calls happen#

Predict both lists before running the following example. The loop name label belongs to the same enclosing call on both iterations. In the second list, saved=label is evaluated when each lambda is created. Strings are immutable, so keeping that string object gives the two expected labels. The default technique would retain a reference to a mutable object, not clone its contents. A factory is often clearer once the behavior needs validation or several local names.

def worked_binding() -> None:
    late = []
    early = []
    for label in ("red", "blue"):
        late.append(lambda: label)  # noqa: B023 - deliberate late-binding contrast
        early.append(lambda saved=label: saved)
    assert [read() for read in late] == ["blue", "blue"]
    assert [read() for read in early] == ["red", "blue"]
    print("Late binding:", [read() for read in late])
    print("Definition defaults:", [read() for read in early])

A wrapper observes both the success and failure route#

The wrapper below forwards arguments and uses finally for an observation that must occur on either route. return inside try does not bypass finally. The division error propagates to the caller, where this small demonstration expects it. There is no broad fallback returning zero, so an invalid operation cannot look like a valid numerical answer. This example observes entry/exit; the independent tracing task asks you to distinguish success from failure.

from functools import wraps

events = []


def announce(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        events.append("before")
        try:
            return function(*args, **kwargs)
        finally:
            events.append("after")

    return wrapper


@announce
def reciprocal(value):
    """Return one divided by value."""
    return 1 / value


assert reciprocal(2) == 0.5
try:
    reciprocal(0)
except ZeroDivisionError:
    pass
else:
    raise AssertionError("The wrapper hid the failure")
assert events == ["before", "after", "before", "after"]
assert reciprocal.__name__ == "reciprocal"
print("Decorator events:", events)

Expected: The first call returns 0.5; the second raises ZeroDivisionError. Both produce a balanced before/after pair and the wrapper retains the name reciprocal. The final print contains four strings. Remove wraps experimentally and compare the name, docstring, and inspected signature; restore it before evaluating the exercise contracts.

Two stacked decorators apply from the bottom upward during definition, while calls enter the outer wrapper first. For @trace above @validate, tracing receives the validated replacement and observes its rejection. Reversing the lines means validation rejects before tracing begins. Neither arrangement should invoke the mathematical body for rejected input. Separate body calls from trace events when investigating this difference.

Common pitfalls#

If every callback adds the final offset, inspect its free names and when it is called. Create a separate enclosing call per offset or deliberately bind a default. If UnboundLocalError mentions total, look for an assignment in the inner function and decide whether the intended state is enclosing or local. Do not fix the error by introducing a module global shared by all accumulators.

If an invalid increment changes the next valid total, validation happened too late. Move the check before the state transition. If changing a configuration value has no effect, inspect whether you captured the value or copied the whole dictionary instead of retaining the specified live object. If a wrapper hides a failure, check for an unintended return in finally or a broad exception handler that returns a substitute value.

If logs are missing, compare decorator order before adding another logging layer. If a pipeline changes after the original list is cleared, identify its ownership boundary: the stage sequence needs a snapshot, while the callable objects themselves remain shared references. This lesson does not promise thread-safe counters, immutable callable internals, or safe remote retry.

python-lang-02: Explained solutions#

The executable reference implements the six contracts and contains independent expected-value, failure, and lifetime assertions. Read the learner guide for the complete run workflow and attempt each learner function before comparing. The reference runs entirely offline in the prepared Docker Python classroom; its assertions are behavioral evidence for these fixtures, not a claim about unseen learner work or external system acceptance.

Exercise 1: Bind independent offsets#

Inputs: A tuple of exact integers such as (2, -1, 0); bool is not an integer for these contracts.

Expected: Return one function per offset in input order. Each function adds its own offset to an exact integer argument. Empty input returns (). Reject invalid offsets before returning functions, and invalid call arguments, with ValueError.

Verify: Calling all three functions with 10 returns (12, 9, 10). Call them again in reverse order to expose accidental shared late binding.

The reference first validates every offset, so a malformed later entry does not leave the caller holding a partially accepted collection of functions. It then calls a small factory once per offset. Each factory call creates a separate local binding named offset, and its inner add function reads that binding later. The closure therefore remembers the selected offset through an independent enclosing scope. Testing only the final callback would miss the loop-binding defect; calling all callbacks and then reversing the call order distinguishes independent capture from shared state. An empty tuple has no callbacks and produces an empty result tuple. A default argument could also bind the current integer, but it would appear in the function's signature and would need care to prevent callers from overriding an implementation detail.

Exercise 2: Keep private accumulated state#

Inputs: An exact integer start and later exact integer increments, including negative increments.

Expected: Return a closure with private running state. Calls add the increment and return the new total. Separate factory calls never share state. Reject a malformed start or increment with ValueError; a rejected increment must not change the stored total.

Verify: A total starting at 5 returns 7 then 4 for increments 2 and -3. After rejecting True, increment 0 still returns 4; a second factory starting at 5 still returns 5.

The accumulator's total lives in the factory invocation. nonlocal is necessary because the inner function reassigns that enclosing name, rather than merely reading an integer object. The increment is validated before changing total. This sequencing gives rejection a precise guarantee: a bad input leaves the next valid observation unchanged. Integer addition creates a new integer object and rebinds total; it does not mutate an integer in place. The executable fixture starts at five, adds two, subtracts three, rejects True, and then adds zero. The last observation must still be four. A separately constructed accumulator still returns five. A module-level counter or a mutable default list would create accidental sharing across factory calls and violate this contract even if one test sequence happened to pass.

Exercise 3: Read a live configuration binding#

Inputs: A caller-owned dictionary whose keys are nonempty strings and values exact integers, plus an existing nonempty key.

Expected: Validate the initial dictionary without copying or modifying it. Return a closure that reads the current value of the selected key on each call. A missing key raises KeyError, including after later deletion; a malformed current value raises ValueError. Replacing a separate caller variable with a new dictionary does not replace the captured dictionary.

Verify: A captured limit initially 3 becomes 8 after config["limit"] = 8. Deleting limit raises KeyError; reinserting a string raises ValueError. Record the caller dictionary before and after construction to prove no mutation.

The live lookup captures the original dictionary object and the selected key binding. It deliberately does not cache config[key] at construction. Looking up the key again on every call exposes later updates and deletion, with normal KeyError on absence. The validator checks all initial key/value entries without altering them. Later reads validate the selected current value, because a caller can mutate the shared dictionary after construction. Other later dictionary edits are outside the selected read contract. Reassigning the caller's variable config to a different dictionary leaves the closure's original reference intact. The reference keeps an old_config name solely to make that object identity visible in the test. Copying the dictionary would be a reasonable snapshot API, but it would answer a different question and would fail the required change from three to eight.

Exercise 4: Trace a call without changing its result#

Inputs: A list for observation and an ordinary synchronous callable to decorate. Calls may use positional and keyword arguments or raise an Exception.

Expected: Return a decorator that preserves metadata with functools.wraps. Append call:NAME before invocation, then return:NAME on success or raise:NAME:TYPE on an Exception. Return the original result and re-raise the same exception object. Do not catch BaseException control signals.

Verify: For a function named divide, division by zero yields ["call:divide", "raise:divide:ZeroDivisionError"]. Inspect name, doc, wrapped, and inspect.signature; assert an injected exception is the identical object.

The decorator factory captures the caller's observation list. Decoration creates a wrapper with wraps applied, so the wrapper retains the original name, docstring, and wrapped link. The wrapper accepts arbitrary positional and keyword arguments and forwards them unchanged. It records entry first, then separates ordinary success from an Exception. A bare raise inside the handler re-raises the original exception object and traceback rather than constructing a replacement with the same message. The reference checks object identity with an injected RuntimeError; comparing only its text would miss a replacement error. BaseException subclasses remain control signals and are not converted into ordinary failure log entries. Metadata preservation does not make the wrapper statically typed for every possible callable; the runtime contract here is specifically ordinary synchronous functions.

Exercise 5: Make decorator order observable#

Inputs: An ordinary one-integer function. The wrapper accepts one exact integer that must be at least zero.

Expected: Preserve function metadata. Reject negative integers, bool, and nonintegers with ValueError before calling the wrapped function. Otherwise return its result unchanged. Compare tracing outside validation with validation outside tracing; neither order may call the body for invalid input.

Verify: A traced outer wrapper records call and raise for -1. An outer validator records no trace for -1. On 0 both call the body once and return its actual result.

Validation is its own wrapper and happens before invocation of the function it wraps. The exact integer test distinguishes zero from False, and the nonnegative test rejects negative integers without running the body. When tracing is outermost, its call entry occurs before the validator rejects and its handler records the resulting ValueError. When validation is outermost, the rejected call never reaches the tracing wrapper. Both arrangements therefore protect the body but produce different trace evidence. The body-call list is empty after the two invalid calls, which is stronger evidence than inspecting only logs. Both zero calls then return the body's true result and each adds one entry to the body list. Reversing decorator order to obtain desired observability is a policy decision, not a general rule that either order is always superior.

Exercise 6: Snapshot and compose a pipeline#

Inputs: A finite caller-owned sequence of callables. Each stage accepts and returns an integer. Input stage storage may be changed after construction.

Expected: Snapshot the stage sequence and reject a noncallable stage with ValueError at construction. Return a function applying stages from left to right. Empty stages return their input unchanged. Forward a stage exception immediately without calling later stages; never mutate the supplied sequence.

Verify: For add-two then multiply-three, input 4 gives 18, while reversed stages give 14. Clearing the original list afterward does not change the first pipeline; record that a later stage was not called after a deliberate error.

The pipeline converts the stage sequence to a tuple before returning its closure. This snapshots which callable objects participate and their order, so clearing the original list has no effect. It does not deep-copy callable internals: a stage that closes over mutable configuration can still observe that configuration. The reference applies stages in supplied order, so add-two followed by multiply-three transforms four into eighteen. Reversing those stages gives fourteen and exposes an implementation that guessed conventional right-to-left composition. Empty composition is the identity operation. Stage validation happens at construction, while stage exceptions propagate during invocation. A deliberate first-stage error plus an independent later-stage observation list proves short-circuiting. Catching the error and continuing would return a plausible number while violating the pipeline's control-flow contract. No global pipeline registry or external package is needed.

The following compact check runs in the executable reference namespace after its function definitions:

callbacks = bind_offsets((2, -1, 0))
assert tuple(callback(10) for callback in callbacks) == (12, 9, 10)

"""Executable references for python-lang-02, with behavioral assertions."""

from __future__ import annotations

import inspect
from collections.abc import Callable, Sequence
from functools import wraps
from typing import Any


def _integer(value: object) -> int:
    if type(value) is not int:
        raise ValueError("Expected an exact integer")
    return value


# Exercise 1: Bind independent offsets.
def bind_offsets(offsets: tuple[int, ...]) -> tuple[Callable[[int], int], ...]:
    for offset in offsets:
        _integer(offset)

    def bind(offset: int) -> Callable[[int], int]:
        def add(value: int) -> int:
            return _integer(value) + offset

        return add

    return tuple(bind(offset) for offset in offsets)


# Exercise 2: Keep private accumulated state.
def make_running_total(start: int = 0) -> Callable[[int], int]:
    total = _integer(start)

    def increment(value: int) -> int:
        nonlocal total
        checked = _integer(value)
        total += checked
        return total

    return increment


# Exercise 3: Read a live configuration binding.
def make_live_lookup(config: dict[str, int], key: str) -> Callable[[], int]:
    if (
        not isinstance(config, dict)
        or not isinstance(key, str)
        or not key
        or any(not isinstance(name, str) or not name for name in config)
    ):
        raise ValueError("Expected a dictionary with nonempty string keys")
    for value in config.values():
        _integer(value)
    _integer(config[key])

    def lookup() -> int:
        return _integer(config[key])

    return lookup


# Exercise 4: Trace a call without changing its result.
def trace_calls(events: list[str]) -> Callable[[Callable[..., Any]], Callable[..., Any]]:
    def decorate(function: Callable[..., Any]) -> Callable[..., Any]:
        @wraps(function)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            events.append(f"call:{function.__name__}")
            try:
                result = function(*args, **kwargs)
            except Exception as error:
                events.append(f"raise:{function.__name__}:{type(error).__name__}")
                raise
            events.append(f"return:{function.__name__}")
            return result

        return wrapper

    return decorate


# Exercise 5: Make decorator order observable.
def require_nonnegative(function: Callable[[int], int]) -> Callable[[int], int]:
    @wraps(function)
    def wrapper(value: int) -> int:
        checked = _integer(value)
        if checked < 0:
            raise ValueError("Expected a nonnegative integer")
        return function(checked)

    return wrapper


# Exercise 6: Snapshot and compose a pipeline.
def compose_stages(stages: Sequence[Callable[[int], int]]) -> Callable[[int], int]:
    frozen = tuple(stages)
    if not all(callable(stage) for stage in frozen):
        raise ValueError("Each stage must be callable")

    def pipeline(value: int) -> int:
        for stage in frozen:
            value = stage(value)
        return value

    return pipeline


def _raises(kind: type[Exception], action: Callable[[], Any]) -> Exception:
    try:
        action()
    except kind as error:
        return error
    raise AssertionError(f"Expected {kind.__name__}")


def verify_examples() -> None:
    adders = bind_offsets((2, -1, 0))
    assert tuple(add(10) for add in adders) == (12, 9, 10)
    assert tuple(add(10) for add in adders[::-1]) == (10, 9, 12)
    assert bind_offsets(()) == ()
    _raises(ValueError, lambda: bind_offsets((True,)))
    _raises(ValueError, lambda: adders[0](True))
    running = make_running_total(5)
    separate = make_running_total(5)
    assert (running(2), running(-3)) == (7, 4)
    _raises(ValueError, lambda: running(True))
    assert running(0) == 4 and separate(0) == 5
    _raises(ValueError, lambda: make_running_total("5"))  # type: ignore[arg-type]  # Deliberately invalid input.
    config = {"limit": 3}
    before = config.copy()
    lookup = make_live_lookup(config, "limit")
    assert config == before and lookup() == 3
    config["limit"] = 8
    assert lookup() == 8
    old_config = config
    config = {"limit": 99}
    assert lookup() == 8 and old_config == {"limit": 8}
    del old_config["limit"]
    _raises(KeyError, lookup)
    old_config["limit"] = "invalid"  # type: ignore[assignment]  # Probe runtime validation.
    _raises(ValueError, lookup)
    _raises(ValueError, lambda: make_live_lookup({"": 1}, ""))
    events: list[str] = []
    failure = RuntimeError("original")

    def divide(value: int, *, divisor: int = 1) -> float:
        """Divide a value by a supplied divisor."""
        if divisor == -1:
            raise failure
        return value / divisor

    wrapped = trace_calls(events)(divide)
    assert wrapped(8, divisor=2) == 4
    assert events == ["call:divide", "return:divide"]
    assert _raises(RuntimeError, lambda: wrapped(8, divisor=-1)) is failure
    assert events[-2:] == ["call:divide", "raise:divide:RuntimeError"]
    assert wrapped.__name__ == divide.__name__ and wrapped.__doc__ == divide.__doc__
    # Callable describes calls; wraps also attaches this runtime metadata.
    assert wrapped.__wrapped__ is divide  # type: ignore[attr-defined]
    assert inspect.signature(wrapped) == inspect.signature(divide)
    body: list[int] = []

    def square(value: int) -> int:
        body.append(value)
        return value * value

    outer_trace: list[str] = []
    inner_trace: list[str] = []
    traced_validator = trace_calls(outer_trace)(require_nonnegative(square))
    validated_trace = require_nonnegative(trace_calls(inner_trace)(square))
    _raises(ValueError, lambda: traced_validator(-1))
    _raises(ValueError, lambda: validated_trace(-1))
    assert body == [] and inner_trace == []
    assert outer_trace == ["call:square", "raise:square:ValueError"]
    assert traced_validator(0) == 0 and validated_trace(0) == 0
    assert body == [0, 0]
    stages = [lambda value: value + 2, lambda value: value * 3]
    pipeline = compose_stages(stages)
    assert pipeline(4) == 18 and compose_stages(stages[::-1])(4) == 14
    stages.clear()
    assert pipeline(4) == 18 and compose_stages([])(4) == 4
    _raises(ValueError, lambda: compose_stages([None]))  # type: ignore[list-item]  # Deliberately invalid stage.
    later: list[int] = []

    def broken(value: int) -> int:
        raise failure

    def observe(value: int) -> int:
        later.append(value)
        return value

    assert _raises(RuntimeError, lambda: compose_stages([broken, observe])(1)) is failure
    assert later == []
    print("All six scope, closure, and decorator contracts passed.")


if __name__ == "__main__":
    verify_examples()
