<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scan job step to Docker Hub credentials | The scan step must not see push credentials |
| Receipt artifact to promote job | Receipts cross jobs as artifacts and authorize public writes |
| Workflow definitions to third-party actions | Any action reference runs code with job permissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-05 | Information Disclosure | candidate tags | high | mitigate | Scan precedes `stage` in all four staging jobs; `stage` validates evidence before any tag or push |
| T-08-06 | Spoofing | receipt scan block | high | mitigate | Evidence bound to tested_image_id, architecture and context; strict key sets; schema 2 rejects old receipts |
| T-08-07 | Tampering | stale DB or expired suppressions | medium | mitigate | 24-hour DB bound at stage and promote; expiry rechecked at promote against the committed policy hash |
| T-08-08 | Elevation of Privilege | `actions/cache`, scanner step | high | mitigate | Full-SHA pin, contract test forbids `aquasecurity/` actions, no `secrets.` in scan steps |
| T-08-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan |
</threat_model>
