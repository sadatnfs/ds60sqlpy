# One-step-ahead predictive residuals

Start with: tmb-031, tmb-015.

Outcome: Construct diagnostics that respect observation ordering and conditioning.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter computes probability-integral-transform and randomized quantile residuals. No file in the separately prepared [owned project](../projects/tmb-local/README.md) calls `oneStepPredict`, so this chapter's TMB usage is explanatory; the [API reference](../API-REFERENCE.md) gives the pinned signature; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

An ordinary fitted residual uses a model estimated with all available observations. A one-step-ahead residual instead evaluates the next observation using an appropriate conditional distribution given earlier observations. That distinction matters for latent time series and sequential model criticism.

For a continuous conditional CDF \(F_t\), the probability integral transform \(U_t=F_t(Y_t\mid Y_{1:t-1})\) is uniform under the correctly specified model, and \(Z_t=\Phi^{-1}(U_t)\) is standard normal. Parameters estimated from the same finite data can alter the ideal reference behavior, so simulation-based calibration remains useful.

## Key terms

- **One-step-ahead residual:** A residual for each observation computed from its conditional distribution given only earlier observations.
- **Probability integral transform:** \(U=F(Y)\) for a continuous conditional CDF \(F\), which is uniform when the model is correct; applying \(\Phi^{-1}\) then gives a standard normal value.
- **Randomized residual:** For discrete data, \(F(y)-V\,p(y)\) with \(V\) uniform on \((0,1)\), which spreads the CDF jump so the transform is continuous.
- **oneStepPredict:** The TMB function that builds one-step-ahead residuals; its observation name, data-term indicator and method must match the template.

### Worked case A: known Gaussian forecasts

The companion transforms a few observations using specified forecast means and standard deviations. It verifies that the resulting standardized residual equals the normal-CDF transform. The means are supplied as prior forecasts, not fitted retrospectively using each target observation.

`oneStepPredict` supports several Gaussian and generic methods and requires model-specific observation and indicator conventions. Its `observation.name`, `data.term.indicator`, `subset`, `conditional`, `reverse` and method settings must match the actual template. The current nine-model project does not claim full OSA support merely because the function is exported.

### Worked case B: discrete randomized residuals

A Poisson CDF jumps at integer values, so directly applying its CDF does not produce a continuous uniform variable. A randomized transform samples within the observed probability mass interval: \(F(y)-V p(y)\), with \(V\sim U(0,1)\). The companion implements this on seeded count observations and records the seed.

A different randomized residual seed changes individual residuals without changing the fitted model. Diagnose distributions and patterns, not the visual appeal of one chosen seed. Do not search seeds until a normality plot looks better.

### Answered discussion

**Can observations be reordered freely?** The joint factorization may remain valid, but conditional questions and diagnostic patterns change. Time-series order should follow the scientific forecasting task. **Does `parallel=TRUE` make all methods efficient?** It changes execution and needs its own resource and equivalence check. **Is OSA a forecast benchmark?** It is a model diagnostic. A held-out forecast evaluation still needs a defined training/validation separation and horizon.

Read [oneStepPredict's complete arguments and beta-status note](https://cran.r-project.org/web/packages/TMB/TMB.pdf) before preparing a template-specific native example.

### Worked case C: the continuous and discrete transforms

For the three continuous observations, the standardized residuals are \((-0.2-0)/1=-0.2\), \((0.5-0.2)/0.5=0.6\) and \((1.4-1)/0.8=0.5\) (hand-derived). The companion computes them through `qnorm(pnorm(...))`, which must agree to \(10^{-12}\) because, for a normal forecast, the PIT followed by \(\Phi^{-1}\) is the standardization. The middle observation is the most surprising relative to its forecast, even though its raw error 0.3 is smaller than the third observation's 0.4, because its forecast standard deviation is smaller.

For the counts, the Poisson(2) CDF defines one probability interval per observation, and the randomized value falls uniformly inside it:

```text
count   lower F(y-1)   upper F(y)   residual range qnorm(lower) to qnorm(upper)
0       0.000000       0.135335     -Inf to -1.102
1       0.135335       0.406006     -1.102 to -0.238
3       0.676676       0.857123      0.458 to  1.067
5       0.947347       0.983436      1.620 to  2.131
(closed-form values, rounded; the seeded draw places each residual inside its range)
```

Whatever `runif` returns under seed 3232, each printed residual must lie in its row's range. A count of 0 can produce a very negative residual if its uniform draw is near 1, which is why the companion asserts \(0<u<1\) strictly. The count of 5 is in the upper 5.3% tail for \(\lambda=2\), and its residual will be between 1.62 and 2.13 regardless of seed: the conclusion that 5 is unusual does not depend on randomization, while the exact plotted point does.

### Matching `oneStepPredict` to a template

For the `ar1` model in the project, a one-step diagnostic would need the observation vector declared with `DATA_VECTOR_INDICATOR(keep, y)` so TMB can remove one observation at a time from the likelihood. Without that declaration, `oneStepPredict(obj, observation.name = "y", data.term.indicator = "keep", method = "oneStepGaussian")` has no indicator to toggle. The current project templates do not declare it, which is one concrete reason the course does not claim OSA support. Adding the indicator changes the template source and its MD5 identity, so the acceptance record would need a fresh run.

### Why retrospective residuals look too good

If the forecast mean for the third observation had been refit using that observation, for instance by averaging it in, the mean would move toward 1.4 and the residual would shrink below 0.5. Repeating that for every point pulls all residuals toward zero, so their spread falls below 1 and a normality check passes too easily. One-step residuals avoid this by conditioning only on \(Y_{1:t-1}\). With the companion's three forecasts treated as fixed in advance, the residuals \(-0.2\), 0.6 and 0.5 have sample standard deviation 0.44, a reminder that three values cannot test calibration by themselves.

### Base-R companion (runs in the classroom)

```r
y <- c(-.2, .5, 1.4);forecast_mean <- c(0, .2, 1);forecast_sd <- c(1, .5, .8)
z <- qnorm(pnorm(y, forecast_mean, forecast_sd))
print(z);stopifnot(max(abs(z - (y - forecast_mean) / forecast_sd)) < 1e-12)
set.seed(3232);counts <- c(0, 1, 3, 5);lambda <- 2
u <- ppois(counts, lambda) - runif(length(counts)) * dpois(counts, lambda)
print(data.frame(counts = counts, randomized_quantile = u, residual = qnorm(u)))
stopifnot(all(u > 0 & u < 1))
```
