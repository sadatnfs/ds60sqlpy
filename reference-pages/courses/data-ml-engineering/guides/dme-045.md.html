dme-045: Security boundaries, secrets and shared systems#

Level: Advanced | Prepared runtime: python-core

Direct prerequisites: dme-028, dme-032, dme-040, dme-042.

Outcome: Enforce a synthetic resource-authorization contract and safe request validation.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

A valid request is not necessarily an authorized request#

Validation asks whether a request has an acceptable shape and value range. Authentication establishes the caller's identity. Authorization decides whether that caller may perform an action on a particular resource. These checks address different failure modes. A perfectly formatted request for another tenant's report should still be denied. A trusted user can also submit malformed or oversized content that must be rejected before it reaches a sensitive operation.

A shared data or ML platform has many boundaries: browser to application, application to worker, worker to filesystem, service to database and operator to deployment controls. Each boundary should expose only the operations and resources it needs. Giving a code execution worker broad host access because it is “inside Docker” would ignore the actual isolation design. Containerization is one mechanism; mounts, users, network access, capabilities and exposed APIs determine much of its effective scope.

This chapter uses synthetic principals and reports in owned temporary directories. It performs actual POSIX file operations under the Linux classroom runtime. It does not authenticate a real user or inspect private files. The principal object is a trusted fixture supplied by the example, not a role string accepted from an untrusted HTTP header. The purpose is to show how resource authorization and safe file access form separate, testable layers.

Bind resource identity to a reviewed path#

The application exposes logical resource IDs report-a and report-b. A maintained mapping associates each ID with its tenant and a fixed basename. The caller never supplies an arbitrary filesystem path. read_report first checks that the principal belongs to the resource's tenant and has the analyst role. Unknown resources and unauthorized resources both produce the same permission error in this fixture.

The decision can be written as

This is an illustrative policy, not a complete role hierarchy. Real systems may need resource ownership, project membership, purpose, environment or time restrictions. The important design property is that the decision binds the trusted principal to the particular resource action. A global “logged in” check is not enough to protect every object in a shared system.

After authorization, the code opens the owned directory and then the fixed file relative to that directory descriptor. O_NOFOLLOW rejects a symlink at the opened boundary. fstat verifies the opened object is a regular file and enforces a byte limit. Reading at most 4,097 bytes detects an oversized report against the 4,096-byte budget. The JSON parser rejects duplicate field names, and the schema requires exactly one nonnegative integer package count. A Boolean is deliberately not accepted as an integer count even though Python's Boolean type is related to integers.

Worked case 1: permit one tenant and deny another#

example_one() creates a north report with six packages and a south report with nine. The synthetic principal is an analyst for north. Reading report-a returns the six-package object. Reading report-b is denied even though the file exists and contains valid JSON.

The case also submits a path-looking string and an unlisted resource ID. Both are denied before filesystem access because neither is a registered logical resource available to the caller. The program does not normalize ../b.json into a path and then hope a later check catches the escape. The public operation accepts resource identities, and the mapping controls which files those identities can reach.

The result reports a denied-request count rather than printing another tenant's contents. A production audit should similarly record enough context to investigate access decisions without copying sensitive resource payloads into a broadly readable log. The fixture contains only synthetic values, but the habit matters when the same design is applied to real reports or model features.

Worked case 2: an authorized name can still point to an unsafe object#

The second case creates a report directory and another file elsewhere within the owned temporary fixture. It then places a symlink at the authorized report basename pointing to that other file. The principal is still authorized for the logical north report, but the file-opening layer rejects the symlink. Authorization did not eliminate the need to validate the actual object being opened.

The case replaces the symlink with a regular JSON file containing true as the package count. The file boundary now passes, but the numeric schema rejects the payload. This demonstrates another independent layer: an authorized regular file can still contain invalid data. The other owned fixture remains unchanged throughout the case.

These are actual kernel and parser observations in the Linux runtime. They do not establish security against every attacker or filesystem race. The example assumes the owned directory and reviewed resource mapping are controlled by the application. A system allowing hostile mutation of directory ancestors, mounts or trusted metadata needs a broader threat model and stronger isolation. State those assumptions explicitly instead of calling a path helper universally secure.

Complete worked program#

Run in Python Core inside the Linux classroom. The symlink target is another synthetic file created by the example, never a private host path. Every opened descriptor is closed in a finally block.

"""Synthetic resource authorization and actual bounded POSIX file reads inside owned fixtures."""

import json
import os
import stat
import tempfile
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class Principal:
    name: str
    tenant: str
    roles: frozenset[str]


RESOURCES = {
    "report-a": {"tenant": "north", "file": "a.json"},
    "report-b": {"tenant": "south", "file": "b.json"},
}


def unique_fields(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("Duplicated JSON field is ambiguous")
        result[key] = value
    return result


def read_report(root, principal, resource_id):
    resource = RESOURCES.get(resource_id)
    if (
        resource is None
        or principal.tenant != resource["tenant"]
        or "analyst" not in principal.roles
    ):
        raise PermissionError("Resource action is not authorized")
    directory = os.open(root, os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW)
    try:
        descriptor = os.open(resource["file"], os.O_RDONLY | os.O_NOFOLLOW, dir_fd=directory)
        try:
            information = os.fstat(descriptor)
            if not stat.S_ISREG(information.st_mode) or information.st_size > 4096:
                raise ValueError("Expected a bounded regular report file")
            content = os.read(descriptor, 4097)
            if len(content) > 4096:
                raise ValueError("Report grew beyond its byte budget")
        finally:
            os.close(descriptor)
    finally:
        os.close(directory)
    value = json.loads(content, object_pairs_hook=unique_fields)
    if (
        not isinstance(value, dict)
        or set(value) != {"packages"}
        or type(value["packages"]) is not int
        or value["packages"] < 0
    ):
        raise ValueError("Report content violates the reviewed numeric schema")
    return value


def example_one():
    with tempfile.TemporaryDirectory() as directory:
        root = Path(directory)
        (root / "a.json").write_text('{"packages":6}')
        (root / "b.json").write_text('{"packages":9}')
        principal = Principal("synthetic-reader", "north", frozenset({"analyst"}))
        assert read_report(root, principal, "report-a") == {"packages": 6}
        denied = []
        for resource in ["report-b", "../b.json", "unlisted"]:
            try:
                read_report(root, principal, resource)
            except PermissionError:
                denied.append(resource)
            else:
                raise AssertionError("Unauthorized resource was returned")
        return {
            "own_resource": {"packages": 6},
            "denied_request_count": len(denied),
            "principal_is_a_trusted_fixture_not_user_supplied_authentication": True,
        }


def example_two():
    with tempfile.TemporaryDirectory() as directory:
        parent = Path(directory)
        root = parent / "reports"
        root.mkdir()
        outside = parent / "other-fixture.json"
        outside.write_text('{"packages":999}')
        (root / "a.json").symlink_to(outside)
        principal = Principal("synthetic-reader", "north", frozenset({"analyst"}))
        try:
            read_report(root, principal, "report-a")
        except OSError:
            linked = True
        else:
            raise AssertionError("A report symlink escaped the fixed file boundary")
        (root / "a.json").unlink()
        (root / "a.json").write_text('{"packages":true}')
        try:
            read_report(root, principal, "report-a")
        except ValueError:
            typed = True
        else:
            raise AssertionError("A Boolean was accepted as a package count")
        return {
            "symlink_rejected": linked,
            "boolean_count_rejected": typed,
            "outside_owned_fixture_unchanged": json.loads(outside.read_text()) == {"packages": 999},
        }


def main():
    print("Authorization precedes resource access:", example_one())
    print("File and payload validation enforce a separate boundary:", example_two())


if __name__ == "__main__":
    main()

Secrets belong outside source and outputs#

Credentials authorize access and should not become ordinary teaching data, logs or model features. Use an appropriate secret delivery mechanism for a deployed service, minimize the process environment and avoid including credentials in command arguments or exception messages. A container image is not a secret store merely because its filesystem is packaged. Anyone able to inspect the image layers may recover embedded values.

A public repository should use clearly synthetic fixtures and document required secret names without including real values. Configuration examples should distinguish non-sensitive defaults from credentials. When a diagnostic needs to show an endpoint, redact signed query strings or authorization headers rather than storing them in retained evidence. The classroom's own release and workshop scripts apply separate rules for these boundaries.

Least privilege also applies to service identities. A read-only prediction process should not automatically be able to activate models, rewrite training data or control the Docker engine. A maintenance command may need a broader capability, but that capability should be explicit and separate from ordinary requests. This separation reduces the consequences of a request-handling defect and makes operational review easier.

Validate content before interpreting it#

Safe file access does not make arbitrary serialization safe. Loading an executable object format from an untrusted source can run code during deserialization. Prefer a reviewed bounded representation when the model or configuration can be expressed as numeric arrays and explicit metadata, and verify schema and integrity before use. The artifact chapter develops that distinction in more detail.

JSON is data-oriented, but its values still need a contract. Duplicate keys can make different parsers interpret the same text differently. Huge inputs can exhaust memory. Non-finite numbers and unexpected fields can break downstream assumptions. The program's exact package schema is intentionally small enough to validate completely. A larger model schema needs similarly explicit limits and interpretation rather than a generic “JSON parsed successfully” acceptance rule.

Failure diagnosis and answered interview discussion#

If one tenant can access another's object, inspect whether authorization checks the requested resource rather than only a global role. If a path escape succeeds, inspect whether callers control paths or only logical IDs and whether symlinks are followed. If malformed content reaches a computation, inspect the schema after the file-open boundary. If credentials appear in logs, trace the specific serialization or error path that copied them; changing a README alone will not repair the source of exposure.

An interviewer may ask, “Does input validation prevent unauthorized access?” Explain the distinction between shape and permission. If asked whether Docker makes arbitrary code safe, discuss mounts, network, users and privileged interfaces. If asked why use a directory descriptor, explain anchoring the file lookup to the reviewed directory and validating the opened object rather than trusting a string check alone.
