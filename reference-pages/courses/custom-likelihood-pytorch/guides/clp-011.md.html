Worked case 2: labels and scale collapse#

Swap both component means and their corresponding logits. Every observation has the same marginal probability. This label invariance means that component-specific parameter estimates are not identified without a labeling convention or other constraints. A numerical optimizer can return equivalent solutions with opposite labels, so comparing raw coefficient vectors can incorrectly flag a change even when the distribution is identical.

The code then holds one component mean at an observation equal to zero and decreases that component's scale from one to 0.1 to 0.01. Its density at zero grows without bound, so the log-likelihood increases. Ordinary unconstrained Gaussian-mixture likelihood can therefore be unbounded as a component collapses around a data point. Stable logsumexp evaluates this failure accurately; it does not cure the statistical degeneracy.

A minimum scale, a prior, a constrained covariance model or a different estimation criterion can address particular degeneracies, but each changes the allowed model or objective. Record that choice and assess sensitivity. A tiny component scale and a spectacularly improved training likelihood are reasons to inspect a fit, not automatic reasons to celebrate it.

Debugging and uncertainty#

Validate positive component scales, finite values and component dimension agreement. Keep the component dimension separate from the observation dimension; summing the wrong axis can produce plausible scalars with no valid likelihood interpretation. Use log weights directly instead of repeatedly converting between probabilities and logits.

Classical inverse-Hessian uncertainty is delicate near overlapping components, disappearing weights and collapsed scales. Label symmetry and boundary parameters violate simple regularity assumptions. A positive Hessian at one local solution does not establish global uniqueness or justify ordinary Wald intervals. Multiple initializations, predictive checks and model-specific inference are necessary for substantive use.

Answered review questions#

Why can two different parameter vectors describe the same model? Permuting mixture labels preserves the marginal density when weights and component parameters are permuted together. Identification concerns the data distribution, not the optimizer's variable order.

Does a mixture need sampling to differentiate its likelihood? A finite component sum can be marginalized exactly and differentiated directly. Sampling a discrete label is unnecessary for the small finite mixture here and would introduce different estimator considerations.

Can one average per-component losses and call it mixture likelihood? No. The mixture sums probabilities before taking a log. The weighted average of logs is related to other constructions and bounds, but it is not the marginal mixture log-likelihood.

"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def mixture_log_prob(y, logits, means, scales):
    if (
        y.ndim != 1
        or logits.ndim != 1
        or means.shape != logits.shape
        or scales.shape != logits.shape
        or not len(logits)
    ):
        raise ValueError("Use observations and matching component vectors")
    if not bool(
        torch.isfinite(y).all()
        & torch.isfinite(logits).all()
        & torch.isfinite(means).all()
        & torch.isfinite(scales).all()
    ) or bool((scales <= 0).any()):
        raise ValueError("All mixture inputs must be finite, with positive scales")
    component = torch.distributions.Normal(means, scales).log_prob(y[:, None])
    return torch.logsumexp(torch.log_softmax(logits, dim=0) + component, dim=1)


def run_cases():
    logits, means, scales = tensor([0.3, -0.2]), tensor([-2, 2]), tensor([1, 1])
    y = tensor([-1, 0, 2.5, 100])
    stable = mixture_log_prob(y, logits, means, scales)
    library = torch.distributions.MixtureSameFamily(
        torch.distributions.Categorical(logits=logits), torch.distributions.Normal(means, scales)
    ).log_prob(y)
    swapped = mixture_log_prob(y, logits.flip(0), means.flip(0), scales.flip(0))
    assert torch.allclose(stable, library, atol=1e-12, rtol=0) and torch.allclose(
        stable, swapped, atol=1e-12, rtol=0
    )
    direct = (
        torch.softmax(logits, dim=0)
        * torch.exp(torch.distributions.Normal(means, scales).log_prob(y[-1]))
    ).sum()
    assert float(direct) == 0 and bool(torch.isfinite(stable).all())
    collapse = [
        float(mixture_log_prob(tensor([0]), tensor([0, 0]), tensor([0, 3]), tensor([s, 1]))[0])
        for s in (1, 0.1, 0.01)
    ]
    assert collapse[0] < collapse[1] < collapse[2]
    return {
        "stable_log_probabilities": stable.tolist(),
        "direct_probability_underflowed": float(direct) == 0,
        "label_swap_invariant": True,
        "single_point_collapse_log_likelihood": collapse,
        "scale_collapse_is_not_model_success": True,
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
