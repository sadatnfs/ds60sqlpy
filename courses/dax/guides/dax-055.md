## The question and the mechanism

Separate a metric's definition from data freshness, storage mode and external capability.

Import stores a processed copy of data in the semantic model. DirectQuery leaves data in the source and issues queries through supported connectors at report time. Composite models combine storage choices and can introduce additional relationship and query constraints. Direct Lake is a Fabric-specific mode over supported lake data with its own framing, identity and fallback behavior. None of these modes is provided by the offline DAX classroom.

The same revenue definition should return 187 when two models expose the same eight facts and compatible semantics. That numerical agreement does not establish identical refresh behavior, function support, security, latency or transaction consistency. Some DAX functions have specific DirectQuery restrictions in calculated columns or RLS rules; check the exact use, not merely the function's name.

Freshness is an explicit input. If a hypothetical source gains a valid ten-dollar sale after an Import refresh, the stored snapshot can still report 187 while a later source view has 197. DirectQuery is not a universal guarantee of immediate, uncached or transactionally consistent observation; its actual behavior depends on the source, connector, caching and workload. A mode label does not replace a freshness contract.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: Same data, same defined amount

**Starting context:** The same fixed data and compatible semantics; no actual storage-mode execution.

```dax
EVALUATE ROW ( "FixedFixtureRevenue", [NetRevenue], "EquivalentSnapshotRevenue", SUMX ( Sales, Sales[NetAmount] ) )
```

**Context trace:**

1. Both expressions include the same eight line amounts.
2. Each totals 187.
3. This parity condition says nothing about refresh latency or external function support.

**Hand-derived worked-reference result:**

| FixedFixtureRevenue | EquivalentSnapshotRevenue |
| --- | --- |
| 187 | 187 |

A release should compare actual model outputs after any storage-mode change rather than assuming the mode preserves every detail.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: A refresh boundary can explain a difference

**Starting context:** Illustrative scenario: an additional valid 10 USD event arrives after the stored snapshot; it is not added to the checked-in Sales fixture.

```dax
EVALUATE ROW ( "StoredSnapshot", [NetRevenue], "HypotheticalLaterSource", [NetRevenue] + 10 )
```

**Context trace:**

1. The snapshot still contains 187.
2. The hypothetical later source adds exactly 10 under the same metric policy.
3. Its intended amount is 197; an observed difference would need provenance and freshness checks.

**Hand-derived worked-reference result:**

| StoredSnapshot | HypotheticalLaterSource |
| --- | --- |
| 187 | 197 |

The additional event is scenario data, not evidence of a connected source or live DirectQuery result.

Hand-derived freshness scenario only. No source connection, refresh, DirectQuery or Direct Lake operation occurred.

## Progressive hints

1. Source identity and observation time matter as well as the formula.
2. An update is not necessarily an append.
3. Check the exact formula context and relationship type.
4. Caching, source transactions and connector behavior remain relevant.
5. Conceptual understanding and operating an external service are separate.
6. Stored data and source data can represent different versions.
