# mle-002: Event time, knowledge time and label maturity

## Level and prerequisites

Beginner. Direct prerequisites: `mle-001`

**Outcome:** Construct an eligible training cohort from explicit feature and label clocks.

## Question and mechanism

A historical model must use information eligible at its decision time. Event time describes when something happened; knowledge or availability time describes when the system could use it. A backfilled event can have an old event time and a later known time. A row that looks historical can therefore contain future knowledge.

The shared dataset uses integer hours relative to a synthetic epoch. Features become available two hours before each prediction cutoff, while labels become available four hours afterward. At training cutoff 180, the most recent decisions do not all have mature labels. Selecting every decision before 180 would include three outcomes that were not yet available.

The worked cases make both boundaries explicit. The first chooses a feature using event and known clocks. The second separates decision eligibility from label maturity. These rules should be part of the data-generation and evaluation process, not comments added after a score has already been selected.

## Syntax and data contract

Feature eligibility uses both event_at<=cutoff and known_at<=cutoff in the first fixture. Training eligibility additionally requires label_available_at<=training_cutoff. The example keeps the original decision identifier so every excluded record can be explained. Use explicit timestamp units and boundary operators when adapting the integer-clock illustration.

## Worked case 1: Reject late-known information

At cutoff 5, the event at 4 is not known until 7. The eligible value is 10, while an event-only selection would incorrectly use 999. At cutoff 9, value 30 is eligible under both clocks.

**Expected evidence:** Correct feature values are [10,30]; the leaking event-only result includes 999.

```python
def example_one():
    records = [
        {"id": 1, "event_at": 2, "known_at": 3, "value": 10},
        {"id": 2, "event_at": 4, "known_at": 7, "value": 999},
        {"id": 3, "event_at": 8, "known_at": 8, "value": 30},
    ]

    def select(cutoff):
        valid = [r for r in records if r["event_at"] <= cutoff and r["known_at"] <= cutoff]
        return max(valid, key=lambda r: (r["event_at"], r["known_at"]))["value"]

    assert [select(5), select(9)] == [10, 30]
    assert (
        max([r for r in records if r["event_at"] <= 5], key=lambda r: r["event_at"])["value"] == 999
    )
    return {"eligible": [10, 30], "event_only_leak": 999}


if __name__ == "__main__":
    print(example_one())
```


## Worked case 2: Wait for mature training labels

The shared data has 80 decisions before cutoff 180, but only 77 labels available by that time. The three excluded identifiers are preserved as an explicit set. This distinguishes unavailable outcomes from ordinary missing-value imputation.

**Expected evidence:** Training uses 77 rows; decisions 77,78 and 79 have labels that are not yet mature.

```python
import numpy as np
import pandas as pd


def dataset():
    rng = np.random.default_rng(17)
    n = 120
    usage = rng.uniform(1, 100, n)
    tickets = rng.poisson(2, n)
    region = np.where(np.arange(n) % 2 == 0, "north", "south")
    logit = 0.9 * tickets - 0.035 * usage + (region == "north") * 0.3
    probability = 1 / (1 + np.exp(-logit))
    label = (rng.random(n) < probability).astype(int)
    cutoff = np.arange(n) + 100
    return pd.DataFrame(
        {
            "id": np.arange(n),
            "customer_id": np.arange(n) % 12,
            "cutoff": cutoff,
            "available_at": cutoff - 2,
            "label_available_at": cutoff + 4,
            "usage": usage,
            "tickets": tickets,
            "region": region,
            "label": label,
        }
    )


def example_two():
    frame = dataset()
    training_cutoff = 180
    mature = frame[(frame.cutoff < training_cutoff) & (frame.label_available_at <= training_cutoff)]
    premature = frame[frame.cutoff < training_cutoff]
    assert len(mature) == 77 and len(premature) == 80
    assert set(premature.id) - set(mature.id) == {77, 78, 79}
    return {"mature_training_rows": 77, "not_yet_known_labels": [77, 78, 79]}


if __name__ == "__main__":
    print(example_two())
```

## Diagnose errors and misleading results

Do not diagnose every missing label as random missingness. Delays can depend on the outcome or workflow. Check known-time history, maturity windows and included identifiers before fitting or comparing models. A data warehouse's latest state is not automatically a valid historical training view.
