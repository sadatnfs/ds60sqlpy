# js-043: D3 and SVG: from a number to a visible mark

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-029`, `js-005`.

## Learning objectives

Map a count to the length of an SVG bar, place marks in a viewBox and label each mark with its value. The central exercise is: Create three labeled bars from a saved blank pad.

## Purpose, vocabulary and mental model

D3 is a collection of JavaScript tools for transforming data and connecting it to visual output. It does not choose a correct chart or statistical question for you. A visual encoding maps a data property to a perceptual property such as position, length, area or color. Begin by naming the quantity and units before choosing a mark.

SVG is a document tree of vector shapes. A rectangle has x and y coordinates, width and height. In the usual SVG coordinate system x increases to the right and y increases downward. A viewBox describes the internal coordinate system; CSS controls how that system fits the available display area. A shape can be present in the DOM while lying outside the visible viewBox.

The first chart maps three synthetic counts to horizontal bar lengths. A zero-length bar corresponds to zero, making length comparisons interpretable. Labels provide category identity and exact values. The chart is intentionally small enough that you can calculate every coordinate by hand.

### Key terms

- **SVG:** Scalable Vector Graphics, a document tree of vector shapes such as `rect` and `text` whose geometry is set through attributes. In its usual coordinate system x grows to the right and y grows downward.
- **viewBox:** The SVG attribute that declares the internal coordinate system as min-x, min-y, width and height. CSS scales that system to the display area, and a shape outside it stays in the DOM but is not visible.
- **Selection:** A D3 wrapper around existing DOM elements, created with `d3.select`, whose methods such as `.append` and `.attr` act on the wrapped elements and return a selection for chaining.
- **Visual encoding:** A mapping from a data property, such as a count, to a perceptual property, such as bar length, position or color.

## Syntax anatomy and mechanism

`d3.select(host)` wraps one existing DOM element in a selection. `.append('svg')` creates an SVG child and returns a selection containing it. `.attr(name, value)` changes an attribute; a callback receives the bound datum and index. A chain is a sequence of operations, not special chart syntax.

This lesson first uses a simple multiplier rather than a scale to expose the arithmetic. With width equal to count times 20, counts 2, 5 and 8 produce widths of 40 units, 100 units and 160 units. Later lessons replace the literal multiplier with a scale whose domain and range are explicit. Keep text separate from rectangle geometry.

## Worked example / walkthrough

### Worked example 1: Map a count to length

A literal computation exposes the first encoding.

```javascript
const count = 5;
const width = count * 20;
console.log(width);
```

**Expected observation:** 100 SVG coordinate units.

### Worked example 2: Remember SVG vertical direction

These two circles share x; the second has the larger y value.

```javascript
// js-043 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "D3 and SVG: from a number to a visible mark")
  .style("width", "100%")
  .style("max-width", "640px");
const centers = [
  { label: "first", x: 120, y: 90 },
  { label: "second", x: 120, y: 240 },
];
svg
  .selectAll("circle")
  .data(centers)
  .join("circle")
  .attr("cx", (d) => d.x)
  .attr("cy", (d) => d.y)
  .attr("r", 18)
  .attr("fill", "#2563eb");
svg
  .selectAll("text")
  .data(centers)
  .join("text")
  .attr("x", (d) => d.x + 30)
  .attr("y", (d) => d.y + 5)
  .text((d) => `${d.label}: y = ${d.y}`);
const [firstTop, secondTop] = svg
  .selectAll("circle")
  .nodes()
  .map((node) => node.getBoundingClientRect().top);
check(secondTop > firstTop, "A larger y value should be drawn lower");
output.textContent = "js-043 worked example 2 complete";
```

**Expected observation:** Two labeled circles appear in #chart; the second, with the larger y value 240, is drawn below the first.

## Six progressive exercises

### Exercise 1: Predict the three bar widths.

**Expected evidence:** widths of 40 units, 100 units and 160 units.

**Progressive hint:** The same linear multiplier maps all counts.

### Exercise 2: Change the multiplier to 10.

**Expected evidence:** All widths halve while category values remain unchanged.

**Progressive hint:** This changes display geometry, not the data.

### Exercise 3: Create three labeled bars from a saved blank pad.

**Expected evidence:** Exactly three rectangles with matching labels and counts.

**Progressive hint:** Use a small input array and inspect mark count before styling.

### Exercise 4: Diagnose a rectangle outside the viewBox.

**Expected evidence:** Its DOM presence differs from its visible intersection.

**Progressive hint:** Inspect coordinates and viewBox bounds.

### Exercise 5: Add a zero-count category.

**Expected evidence:** A zero-length bar with a visible category/value label.

**Progressive hint:** Zero is data, not missingness.

### Exercise 6: Explain why position and length suit count comparison.

**Expected evidence:** A common baseline supports meaningful magnitude comparison.

**Progressive hint:** Choose the encoding to match the task.

## Debugging and common mistakes

When a bar is missing, inspect its attributes before its color. A rectangle placed at x = 700 inside a 640-unit `viewBox` is present in the DOM yet not visible, and a negative width draws nothing. Log each count, multiplier and computed width, then check that every width equals its count times the multiplier. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a rectangle outside the viewBox. Distinguishing evidence: Its DOM presence differs from its visible intersection.

## Accessibility and interpretation

Each bar needs its category and count as visible text, not only a length, and the `svg` should carry `role="img"` with a title naming the comparison. A short list of category and count gives screen-reader users the exact values and doubles as a check that the labels match the data. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Bar length is honest only when every bar starts at the same zero baseline and uses the same multiplier. Say what was counted and over what period; three synthetic counts demonstrate length encoding, not a finding. A zero-count category should stay visible as a labeled empty bar rather than vanish from the comparison. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
