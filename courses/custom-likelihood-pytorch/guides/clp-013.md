# clp-013: Penalty, prior and objective placement

Tutorial mode. Stage: intermediate. Direct prerequisites: `clp-005`, `bayes-003`.

## Name the objective before interpreting the estimate

Maximum likelihood minimizes the negative log probability of the observed data. Penalized likelihood adds a chosen regularizer. Maximum a posteriori estimation adds a negative log prior in a specified parameterization. These constructions can share algebra, but their interpretation and uncertainty are not interchangeable.

For independent Normal observations with known variance one and a common mean \(\mu\), consider

\[
\mathcal L(\mu)=\frac12\sum_i(y_i-\mu)^2+\frac n2\log(2\pi),\qquad
Q(\mu)=\mathcal L(\mu)+\frac\lambda2\mu^2.
\]

The MLE is \(\sum_i y_i/n\), while the penalized estimate is \(\sum_i y_i/(n+\lambda)\). The penalty shrinks the estimate toward zero. Its strength depends on the data-loss scale. If the data term changes from a sum to a mean while the penalty stays unchanged, the same numerical \(\lambda\) represents a different amount of shrinkage.

A zero-centered Gaussian prior with variance \(1/\lambda\) has negative log density \(\lambda\mu^2/2\) plus a parameter-independent normalizing constant. Its MAP therefore equals this penalized estimate in the \(\mu\) coordinate. MAP is a point summary; it is not the full posterior distribution.

## Worked case 1: one penalty for one parameter

Use observations \((1,2,4)\) and \(\lambda=2\). The unpenalized estimate is \(7/3\), whereas the penalized estimate is \(7/5=1.4\). The program evaluates the objective and gradient at \(\mu=0.8\), then compares the regularized expression with a Normal prior density. The gradients agree and the objective difference is the prior's constant normalization term.

That comparison establishes an algebraic equivalence for this particular parameterization and prior. It does not mean that every optimizer weight-decay option implements the same statistical regularizer. Adaptive optimizer update rules can distinguish decoupled weight decay from adding an L2 term to the loss. For a scientific estimator, write the intended objective explicitly and verify the optimizer actually minimizes it.

## Worked case 2: duplicate the penalty across partitions

Split the three observations into two chunks. Their data NLL contributions sum to the full NLL. Add the global penalty once after summing those contributions, and the answer matches the original objective. If each chunk adds the entire penalty before its result is summed, the effective penalty becomes \(2\lambda\), yielding estimate \(7/(3+4)=1\).

This defect can make parameter estimates depend on the number of Spark partitions or workers. The underlying data did not change; only the execution layout changed. A result that shifts with arbitrary repartitioning should immediately trigger an audit of loss reduction, penalty placement and repeated observations.

There are two valid implementation strategies. Sum only data terms on workers and add the global penalty once on the coordinator, or distribute explicitly scaled shares of the penalty whose total is exactly one copy. The latter must account for the aggregation operation. A reduction that averages gradients instead of summing them requires different local scaling, discussed in Chapter 19.

## Assumptions, uncertainty and model selection

A penalty can stabilize a rank-deficient optimization problem, but it does not mean the data identify the formerly ambiguous parameter. Some information now comes from the penalty or prior. Report that dependence and examine sensitivity. If the prior is centered at a scientifically justified nonzero value, the shrinkage target changes. If coefficient units change, a penalty on raw coefficient magnitudes can also change its meaning unless transformed appropriately.

The inverse Hessian of a penalized objective is not automatically a frequentist covariance estimator for the penalized estimator. It can participate in a local posterior approximation under a declared prior and regularity conditions. Frequentist sampling variance requires an estimator-specific derivation or resampling procedure. Selecting the penalty using the same data adds further uncertainty and should be part of a documented validation design.

## Answered review questions

**Can a prior be placed on a transformed positive parameter?** Yes, but specify whether the prior is on the physical parameter or its log coordinate. Density transformations require the appropriate Jacobian, and MAP values may depend on coordinates.

**Should the penalty be added once per observation?** Only if that is the explicitly chosen objective with corresponding scaling. A global parameter prior ordinarily appears once for the whole dataset, regardless of how observations are batched or partitioned.

**What is the decisive distributed regression test?** Compare objective, gradient and fitted estimate after several repartitionings of identical data. Agreement within floating-point tolerance is necessary for a partition-invariant declared estimator. This chapter performs serial chunk arithmetic to establish that oracle before distributed execution.

```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json
import math

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def data_nll(mu, y):
    return ((y - mu).square() / 2 + 0.5 * math.log(2 * math.pi)).sum()


def penalized(mu, y, precision):
    if precision < 0:
        raise ValueError("Penalty precision must be nonnegative")
    return data_nll(mu, y) + precision * mu.square() / 2


def run_cases():
    y = tensor([1, 2, 4])
    precision = 2.0
    mu = tensor(0.8).requires_grad_()
    full = penalized(mu, y, precision)
    once = data_nll(mu, y[:1]) + data_nll(mu, y[1:]) + precision * mu.square() / 2
    duplicated = penalized(mu, y[:1], precision) + penalized(mu, y[1:], precision)
    prior = torch.distributions.Normal(tensor(0), tensor(1 / math.sqrt(precision)))
    map_objective = data_nll(mu, y) - prior.log_prob(mu)
    grad_full = torch.autograd.grad(full, mu)[0]
    grad_map = torch.autograd.grad(map_objective, mu)[0]
    assert torch.allclose(full, once) and torch.allclose(grad_full, grad_map, atol=1e-12, rtol=0)
    assert torch.allclose(duplicated - full, precision * mu.square() / 2)
    mle = float(y.mean())
    penalized_fit = float(y.sum() / (len(y) + precision))
    duplicate_fit = float(y.sum() / (len(y) + 2 * precision))
    assert duplicate_fit < penalized_fit < mle
    return {
        "mle": mle,
        "penalized_mean": penalized_fit,
        "duplicated_penalty_mean": duplicate_fit,
        "penalty_count": 1,
        "map_minus_penalized_constant": float((map_objective - full).detach()),
        "gradient_equivalence": float(grad_full),
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
