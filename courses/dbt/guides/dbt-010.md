# dbt-010: Snapshots and observed historical state

## Level and prerequisites

Intermediate. Direct prerequisites: `dbt-003`, `dbt-004`, `dbt-005`

**Outcome:** Explain what a snapshot actually observed and what it cannot reconstruct.

## Question and mechanism

A snapshot records changes in a mutable source as observed by successive snapshot runs. It can support slowly changing dimension history, but it cannot recover states that were never observed between runs. Its validity intervals describe the snapshot's chosen strategy and clock. Those intervals should not automatically be treated as the true business-effective time of every change.

The example uses the check strategy to detect a change in region for a stable customer identifier. dbt stores a closed historical version and a current version. The second case also removes a customer from the source and uses hard_deletes='invalidate' so the previously current record is closed. Without a declared deletion policy, consumers can misinterpret missing source records.

History is meaningful only with a stable identity and clear column choices. A changed display name, a corrected attribute and a genuinely new entity are different events. Decide which changes create new versions and which time interpretation the downstream consumer requires.

## Syntax and data contract

The modern YAML snapshot declares a relation, unique_key, strategy, check_cols and deletion policy. The example obtains the actual relation name from the generated manifest because custom schema naming can depend on the adapter/profile. dbt_valid_to is null for current versions under this contract. Query both all historical rows and the active subset.

## Worked case 1: Observe an attribute change

The first case snapshots two customers, changes one region, and snapshots again. The history has three versions in total, with two current customers. The old region remains observable rather than being overwritten.

**Expected evidence:** There are 3 history rows; current regions are west and south.

```python
import json
import os
import tempfile
from pathlib import Path

import duckdb
import yaml


def project(directory, models=None, seeds=None, schema=None, snapshots=None, macros=None):
    os.environ["DBT_SEND_ANONYMOUS_USAGE_STATS"] = "false"
    os.environ["DBT_USE_COLORS"] = "false"
    os.environ["DO_NOT_TRACK"] = "true"
    root = Path(directory) / "project"
    root.mkdir(parents=True)
    for folder in ("models", "seeds", "snapshots", "macros"):
        (root / folder).mkdir()
    config = {
        "name": "classroom",
        "version": "1.0",
        "config-version": 2,
        "profile": "classroom",
        "model-paths": ["models"],
        "seed-paths": ["seeds"],
        "snapshot-paths": ["snapshots"],
        "macro-paths": ["macros"],
    }
    (root / "dbt_project.yml").write_text(yaml.safe_dump(config))
    output = {
        "type": "duckdb",
        "path": str(root / "warehouse.duckdb"),
        "schema": "main",
        "threads": 1,
        "settings": {"threads": 2, "memory_limit": "256MB"},
    }
    (root / "profiles.yml").write_text(
        yaml.safe_dump({"classroom": {"target": "dev", "outputs": {"dev": output}}})
    )
    for name, sql in (models or {"answer": "select 42::integer as answer"}).items():
        (root / "models" / (name + ".sql")).write_text(sql)
    for name, csv in (seeds or {}).items():
        (root / "seeds" / (name + ".csv")).write_text(csv)
    if schema:
        (root / "models/schema.yml").write_text(yaml.safe_dump({"version": 2, **schema}))
    if snapshots:
        (root / "snapshots/snapshots.yml").write_text(
            yaml.safe_dump({"version": 2, "snapshots": snapshots})
        )
    for name, sql in (macros or {}).items():
        (root / "macros" / (name + ".sql")).write_text(sql)
    return root


def invoke(root, *arguments, succeeds=True):
    from dbt.cli.main import dbtRunner

    result = dbtRunner().invoke(
        [
            "--quiet",
            "--no-use-colors",
            "--no-send-anonymous-usage-stats",
            *arguments,
            "--project-dir",
            str(root),
            "--profiles-dir",
            str(root),
            "--no-partial-parse",
        ]
    )
    if succeeds:
        assert result.success, str(result.exception)
    else:
        assert not result.success, "The deliberately invalid fixture was accepted."
    return result


def rows(root, sql):
    with duckdb.connect(str(root / "warehouse.duckdb"), read_only=False) as connection:
        return connection.execute(sql).fetchall()


def artifact(root, name):
    return json.loads((root / "target" / name).read_text())


def relation(root, unique_id):
    return artifact(root, "manifest.json")["nodes"][unique_id]["relation_name"]


def snapshot_case(delete):
    with tempfile.TemporaryDirectory() as d:
        snapshots = [
            {
                "name": "customer_history",
                "relation": "ref('customers')",
                "config": {
                    "schema": "history",
                    "unique_key": "customer_id",
                    "strategy": "check",
                    "check_cols": ["region"],
                    "hard_deletes": "invalidate",
                },
            }
        ]
        p = project(
            d,
            models={"dummy": "select 1 as value"},
            seeds={"customers": "customer_id,region\n1,north\n2,south\n"},
            snapshots=snapshots,
        )
        invoke(p, "seed")
        invoke(p, "snapshot")
        (p / "seeds/customers.csv").write_text(
            "customer_id,region\n1,west\n" if delete else "customer_id,region\n1,west\n2,south\n"
        )
        invoke(p, "seed")
        invoke(p, "snapshot")
        table = relation(p, "snapshot.classroom.customer_history")
        assert rows(p, f"select count(*) from {table}") == [(3,)]
        active = rows(
            p,
            f"select customer_id,region from {table} "
            "where dbt_valid_to is null order by customer_id",
        )
        assert active == ([(1, "west")] if delete else [(1, "west"), (2, "south")])
        return {"history_rows": 3, "active_rows": active, "delete_invalidation": delete}


def example_one():
    return snapshot_case(False)


if __name__ == "__main__":
    print(example_one())
```

## Practice

Make each requested change in a saved copy. Compare both the expected result and the deliberately changed assumption. The separate reference explains the answers.


### 1. Inspect a closed version

Query the old region and its validity endpoint.

**Check:** The changed version has a non-null dbt_valid_to.

**Hint:** Current and historical predicates differ.


### 2. Change a tracked column

Add another attribute to check_cols.

**Check:** Its changes can create new versions under the revised policy.

**Hint:** The tracked column set is part of the contract.


### 3. Explain unobserved changes

Describe a source that changes twice between snapshot runs.

**Check:** The intermediate state may never appear in the snapshot.

**Hint:** Observation frequency limits evidence.


### 4. Compare deletion policies

Explain the effect of ignoring source deletions.

**Check:** A formerly current record can remain open.

**Hint:** Missing source data needs interpretation.


### 5. Review temporal meaning

Distinguish snapshot observation time from business-effective time.

**Check:** The explanation keeps the clocks separate.

**Hint:** The check strategy observes changes when it runs.


### 6. Verify identity

Add a source uniqueness test on customer_id.

**Check:** Conflicting identity is detected before trusting history.

**Hint:** A stable key is required.


## Diagnose errors and misleading results

Unexpected history growth may come from unstable keys or noisy tracked columns. Unexpected open records may come from the deletion policy. A historical result can also be temporally wrong even when its interval columns are well-formed. Inspect source completeness and time semantics before changing snapshot configuration.
