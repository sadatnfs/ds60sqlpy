## The question and the mechanism

Interpret a supplied timing scenario while separating it from an actual DAX execution receipt.

Performance evidence needs provenance: exact source, model, engine/version, hardware, workload filters, cache state and repeated measurements. Cold and warm queries can measure different work. Comparing one cold result with another warm result is not a fair formula comparison. A screenshot of a small duration without its context cannot establish a general speedup.

The numbers in this lesson are explicitly fabricated teaching observations embedded in DATATABLE. No DAX engine produced them. They let you practice summarizing supplied records and spotting misleading claims without requiring an external tool or fabricating a runtime receipt. Their means and medians are hand-derived arithmetic, just like the other reference tables.

A candidate can have a lower best observed time yet a worse average because of a slow trial. That does not automatically condemn it either: investigate noise, workload differences, contention and repeatability. Keep semantic parity and representative workload coverage ahead of choosing the most attractive timing statistic.

## Vocabulary and expression anatomy

AVERAGEX, MINX and MEDIANX summarize literal trial tables. These functions are used to analyze provided values, not to time the current query. A real Performance Analyzer or server-timing trace would need its own recorded provenance and distinction between visual rendering, query time and other work.

Concepts to explain in your own words: **cache state**, **repeated trials**, **median**, **variance**, **synthetic evidence**.

## Worked cases

### Case A: Cold and warm are different conditions

**Starting context:** Original synthetic trial scenario, not measured engine output; three supplied values per cache-state label.

```dax
EVALUATE
VAR Cold = DATATABLE ( "DurationMs", INTEGER, { { 100 }, { 120 }, { 110 } } )
VAR Warm = DATATABLE ( "DurationMs", INTEGER, { { 20 }, { 25 }, { 21 } } )
RETURN ROW ( "SyntheticColdMeanMs", AVERAGEX ( Cold, [DurationMs] ), "SyntheticWarmMeanMs", AVERAGEX ( Warm, [DurationMs] ) )
```

**Context trace:**

1. The synthetic cold values sum to 330 and average 110.
2. The synthetic warm values sum to 66 and average 22.
3. The different conditions must not be presented as proof that one formula is five times faster.

**Hand-derived worked-reference result:**

| SyntheticColdMeanMs | SyntheticWarmMeanMs |
| --- | --- |
| 110 | 22 |

Cache-state labels are part of a benchmark's design. These invented values teach the comparison issue but establish no performance property of this course or a DAX engine.

Arithmetic over explicitly synthetic timing data. No timing measurement or engine execution occurred.

### Case B: Best trial and average can disagree

**Starting context:** Two synthetic three-trial candidates under a hypothetical comparable condition; no real benchmark claim.

```dax
EVALUATE
VAR A = DATATABLE ( "DurationMs", INTEGER, { { 20 }, { 21 }, { 19 } } )
VAR B = DATATABLE ( "DurationMs", INTEGER, { { 18 }, { 60 }, { 18 } } )
RETURN ROW ( "MeanA", AVERAGEX ( A, [DurationMs] ), "MedianA", MEDIANX ( A, [DurationMs] ), "BestA", MINX ( A, [DurationMs] ), "MeanB", AVERAGEX ( B, [DurationMs] ), "MedianB", MEDIANX ( B, [DurationMs] ), "BestB", MINX ( B, [DurationMs] ) )
```

**Context trace:**

1. CandidateA has mean 20, median 20 and best 19.
2. CandidateB has mean 32, median 18 and best 18 because one supplied trial is 60.
3. Selecting only the best trial hides the variability shown by the complete record.

**Hand-derived worked-reference result:**

| MeanA | MedianA | BestA | MeanB | MedianB | BestB |
| --- | --- | --- | --- | --- | --- |
| 20 | 20 | 19 | 32 | 18 | 18 |

Three invented trials cannot estimate production tail latency. The point is to inspect the full evidence and design an adequate real measurement procedure.

Synthetic scenario summary only; these values are not DS60 runtime performance receipts.

## Progressive hints

1. Recompute the same statistic rather than selecting a favorable trial.
2. The cache condition is confounded with the candidate.
3. Include semantic parity and workload identity before time.
4. One synthetic best value has neither real provenance nor tail coverage.
5. Physical plans, memory and contention can change with scale.
6. Separate model loading, compilation, warmup, batch size and synchronization.
