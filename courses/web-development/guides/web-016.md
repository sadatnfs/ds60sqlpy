# web-016: Grid: tracks, gaps and two-dimensional alignment

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-015`

## Learning objectives

Build an adaptive topic grid that survives a narrow container. Explain auto-fit versus auto-fill at a high level. Use grid, track and fr accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Grid arranges items along rows and columns. A track is the space between two adjacent grid lines. Fractional fr units share remaining space after fixed sizes and gaps have been considered. They are not a fixed percentage of the full container. An item's minimum content contribution can still affect track size, which explains why a long unbroken value may widen an apparently equal grid.

Grid is useful when rows and columns must align across a collection. An auto-fit repeat with minmax can create as many columns as fit a preferred minimum, then distribute remaining room. The minimum must still fit a narrow viewport. A layout should adapt to its content, not depend on one device model or a fixed card count.

### Key terms

- **Grid container:** An element with `display: grid` that places its children into rows and columns.
- **Track:** One row or column of a grid, sized by `grid-template-columns` or `grid-template-rows`.
- **Fr unit:** A flexible length that shares a grid container's free space among tracks in proportion to their fr values.
- **Minmax:** The `minmax()` function that gives a track a minimum and a maximum size, such as `minmax(12rem, 1fr)`.
- **Auto-fit:** The `repeat()` keyword that creates as many tracks as fit and collapses empty ones so the filled tracks stretch.

## Syntax anatomy and mechanism

Use `grid-template-columns:repeat(auto-fit,minmax(min(100%,14rem),1fr))` for a resilient card collection. The inner min permits a track to fit a container narrower than the preferred minimum. `gap` adds separation without changing source order. Named grid areas are useful for a page shell, but the source order must remain understandable when the layout collapses.

## Worked example / walkthrough

### Worked example 1: Two equal tracks

The remaining width is shared after the gap.

```css
.grid {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1rem;
}
```

**Expected observation:** Two tracks share the available width without an automatic min-content floor.

### Worked example 2: Adaptive cards

The preferred minimum is bounded by the available width.

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
  gap: 1rem;
}
```

**Expected observation:** The column count adapts to available space.

## Contrast case: a 1fr track widened by a long value

The first rule looks equivalent to worked example 1 but omits `minmax(0, 1fr)`. Place a long URL in the first cell.

```css
.grid-a {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 1rem;
}
.grid-b {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1rem;
}
```

A plain `1fr` track has an automatic minimum equal to its min-content size, so a long unbroken URL makes the first column wider than the second and can push the grid past its container. In `.grid-b` the minimum is 0, so both columns stay equal and the URL overflows inside its own cell, where you can add `overflow-wrap: anywhere` to keep it readable. With short words both grids look identical, which is why this difference only appears when you test with long content.

## Debugging and common mistakes

Do not use visual grid placement to conceal an incoherent document order. Avoid a minimum track width larger than the smallest intended container. Fr units are space-sharing rules, not magic overflow prevention.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
