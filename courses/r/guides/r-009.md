## Outcome and mechanism

Read and update nested records while preserving heterogeneous fields and validating required components.

A list can contain a character ID, a numeric vector and another list without coercing them into one atomic type. It is therefore useful for structured records, model outputs and configuration. The structure itself is not a validated schema: fields can be absent, misspelled, duplicated or contain an unexpected object. Validate the pieces a function actually requires.

The operators [ and [[ have different container behavior. record["values"] returns a one-element list, while record[["values"]] returns the contained numeric vector. The $ syntax is convenient for literal field names, but exact double-bracket indexing is preferable when a name comes from a variable. Avoid relying on partial matching of a misspelled field.

NULL has a special role in list updates. Assigning record$note <- NULL removes that component. To retain a component whose value is NULL, use single-bracket replacement with list(NULL). This is useful when a schema distinguishes an explicitly absent value from a completely missing field. The difference affects later names and length checks.

Flattening with unlist can discard structural distinctions and coerce values. It is appropriate only when the flattened representation is the actual intended output. A model result containing coefficients, diagnostics and labels should usually remain structured so each part can retain its type and meaning. Inspect str before writing extraction code around an unfamiliar return object.

## Read the syntax

Use record[[key]] for an exact variable field name, names(record) to inspect fields and is.list/is.numeric to validate structure. Nested extraction can be staged into named intermediate values for clear errors.

## Worked examples

### Example 1: Container versus contained value

```r
record <- list(id = "A", values = c(2, 4), metadata = list(unit = "kg"))
stopifnot(is.list(record["values"]), is.numeric(record[["values"]]))
stopifnot(record[["metadata"]][["unit"]] == "kg")
print(record[["values"]])
```

**Expected observation:** 2,4.

The one-element list and the numeric measurement vector are different objects. Exact nested names retain the unit contract.

### Example 2: Retain or remove a NULL component

```r
record <- list(id = "A", note = "draft")
record["note"] <- list(NULL)
stopifnot("note" %in% names(record), is.null(record[["note"]]))
record$note <- NULL
stopifnot(!("note" %in% names(record)))
print(names(record))
```

**Expected observation:** Only id remains after deletion.

Single-bracket replacement retains the field with a NULL value; dollar replacement by NULL deletes the field.
