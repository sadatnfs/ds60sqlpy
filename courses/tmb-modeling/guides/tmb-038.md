# Debugging compiler and native failures

Start with: tmb-037.

Outcome: Separate R validation errors, compiler failures and native crashes during diagnosis.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter validates group indices before evaluation and models the build-failure decision. No file in the separately prepared [owned project](../projects/tmb-local/README.md) calls `gdbsource`; its failure handling is input validation in `validate_inputs()` (`R/api.R`) and a stop on a nonzero `TMB::compile` status in `R/compile.R`; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

Not all failures occur at the same layer. A missing column can be rejected in R before native evaluation. A malformed C++ expression fails compilation. An invalid native index can crash an R process. An optimization failure can arise from a valid program evaluating a scientifically unsuitable or numerically ill-conditioned model. Diagnose the layer before changing the model or environment.

`gdbsource(file, interactive=FALSE)` runs an R script under a debugger and can provide a native backtrace. Its `print.backtrace` method formats the result. A debugger executable and useful debug symbols must be prepared; importing TMB does not guarantee that the environment contains gdb or that container permissions allow every debugging operation.

## Key terms

- **Failure layer:** Where an error originates: R input validation, C++ compilation, native execution or numerical optimization.
- **gdbsource:** The TMB function `gdbsource(file, interactive=FALSE)` that runs an R script under gdb to capture a native backtrace.
- **Backtrace:** The chain of native function calls active at a crash, formatted by the `print.backtrace` method.
- **Bounds checking:** Runtime checks that reject out-of-range vector indices, complementing R-side validation of inputs such as group indices.

### Worked case A: fail before C++

The companion implements an explicit zero-based group-index check. An out-of-range value is rejected with a clear domain error instead of being allowed to index an Eigen vector. The project's R API performs this kind of validation and native compilation retains bounds checking. Input validation and compiler bounds checks complement each other.

### Worked case B: a deliberate compile error without stale-library fallback

In an owned scratch directory, copy one original template and introduce a missing token. Require a nonzero compile result and confirm that the wrapper does not load an old library as if the new compilation succeeded. Do not edit the good source or overwrite a library used by another process. The companion models the state machine explicitly: a failed build cannot advance to “load new library.” Actual compiler-error acceptance requires the prepared native project.

For a real crash, preserve a minimal reproducer, source identity, exact command, data shapes and version record. Recompile the reproducer with suitable debug information and lower optimization in a disposable environment. Avoid publishing raw dumps containing learner data or unrelated environment secrets.

### Answered discussion

**Should I disable bounds checks to make a crash disappear?** No. That can turn a visible defect into silent memory corruption. **Does a backtrace identify the scientific error?** It identifies an execution path; interpreting the model still requires domain and numerical analysis. **Should every ordinary lesson require a debugger?** No. Keep debugging preparation optional and explicit, while making ordinary failures readable.

Read [gdbsource and compile documentation](https://cran.r-project.org/web/packages/TMB/TMB.pdf). This chapter teaches the complete process while honestly distinguishing its mathematical/state companion from an actual gdb session.

### Worked case C: classifying each companion outcome

The companion's validator rejects four kinds of bad group index before anything reaches C++. For two groups (\(n=2\)), the valid values are 0 and 1:

```text
input        finite  integer  in [0, 2)   result
c(0, 1, 0)   yes     yes      yes         TRUE
c(0, 2)      yes     yes      no          "invalid group index"
c(0, 1.5)    yes     no       yes         "invalid group index"
c(0, NA)     no      (not reached)         "invalid group index"
c(-1, 0)     yes     yes      no          "invalid group index"
```

Only the first two rows appear in the companion; the others follow from the same expression and are worth adding as local tests. The `NA` row is subtle: `is.finite(NA)` is `FALSE`, so `any(!is.finite(group))` is `TRUE` and the `||` short-circuits before the comparisons, which would otherwise return `NA` and make `if` fail with a less helpful "missing value where TRUE/FALSE needed" error. That ordering is the reason the finiteness check comes first. A one-based index from an R factor, `c(1, 2)`, fails for the same reason as `c(0, 2)`: the group 2 does not exist when \(n=2\). In C++, `u(group(i))` with `group(i)=2` would read past the end of a length-2 vector; with `safebounds = TRUE`, as `R/compile.R` sets, TMB's vector access checks the index and aborts instead of reading neighboring memory.

### The build state machine in practice

The second half maps a compile status to the next action: status 0 leads to `"fresh-load-check"`, anything else to `"failed-build-no-load"`. `R/compile.R` implements the same rule with `if (status != 0L) stop(paste("Compilation failed:", model))`, so a failed model halts the loop before any later model or receipt is written. A deliberate failure test in a scratch copy could look like this:

```r external
file.copy("models/normal_mean.cpp", "scratch/broken.cpp")
src <- readLines("scratch/broken.cpp")
writeLines(sub("nll -= dnorm", "nll -= dnorm(", src), "scratch/broken.cpp")
status <- try(TMB::compile("scratch/broken.cpp"), silent = TRUE)
stopifnot(inherits(status, "try-error") || status != 0L)
stopifnot(!file.exists(file.path("scratch", TMB::dynlib("broken"))))
```

The unbalanced parenthesis guarantees a compiler error. The last assertion checks that no shared library with the new name exists, so nothing can be loaded by accident. Depending on the TMB version, `compile` may signal an R error rather than return a nonzero status, which is why the test accepts either.

### Telling an optimizer failure from a native fault

The four layers leave different traces. A validation failure produces an R error message such as "invalid group index" and a normal exit. A compile failure produces compiler diagnostics naming a file and line in the staged `.cpp`. A native crash ends the R process with a signal and no R-level message, so a wrapping Python bridge sees a nonzero exit code and an empty response. An optimizer failure produces a complete, finite result with a nonzero `convergence` code or a large final gradient. Only the third kind calls for `gdbsource`; the fourth calls for chapter 35's curvature checks instead.

### Base-R companion (runs in the classroom)

```r
validate_group <- function(group, n) {
  if (any(!is.finite(group)) || any(group != floor(group)) || any(group < 0 | group >= n)) stop("invalid group index");TRUE
}
stopifnot(validate_group(c(0, 1, 0), 2))
rejected <- tryCatch(validate_group(c(0, 2), 2), error = function(e) conditionMessage(e));print(rejected)
next_state <- function(compile_status) if (compile_status == 0L) "fresh-load-check" else "failed-build-no-load"
print(c(success = next_state(0L), failure = next_state(1L)));stopifnot(next_state(1L) == "failed-build-no-load")
```
