# c-023: Hash tables, collisions and explicit occupancy

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-022`

## Learning objectives

Implement an open-addressing hash table that resolves collisions and distinguishes an absent key from a stored zero. Along the way, explain collision, probe sequence and load factor. Implement the six investigations, from the "insert and retrieve" case to the "transfer replacement while full" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A hash table maps a key to a candidate storage position. Different keys can collide, so a hash value is not proof of key equality. Open addressing resolves collisions by probing alternative slots under a bounded policy. Each slot needs occupancy information separate from its stored key and value, because zero may be a legitimate key or value. Deletion in an open-addressed table requires care: clearing a slot can break the search chain for later colliding entries. This small fixed table supports insertion, replacement and lookup, and deliberately does not pretend that naive clearing implements deletion.

## Vocabulary and concepts

- **Collision:** Different keys selecting the same initial hash position.
- **Probe sequence:** The ordered candidate positions searched after a collision.
- **Load factor:** The fraction of table capacity occupied by entries.

## Syntax anatomy and execution trace

The fixture uses unsigned integer keys and linear probing across eight slots. Every probe checks used and then compares the actual key. A probe loop has a capacity bound so a full table cannot cause an infinite search. Inserting an existing key replaces its value without consuming another slot. Production designs choose a load factor, resizing policy, hash function and collision-resistance requirements from their input threat model.

## Worked example / walkthrough

### Worked example 1: Insert and retrieve

Store key 1 with value 7.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

enum { TABLE_CAPACITY = 8 };
struct Entry {
  bool used;
  unsigned key;
  int value;
};
struct Table {
  struct Entry entries[TABLE_CAPACITY];
};
bool table_put(struct Table *t, unsigned key, int value) {
  for (size_t step = 0; step < TABLE_CAPACITY; step++) {
    size_t i = (key % TABLE_CAPACITY + step) % TABLE_CAPACITY;
    struct Entry *e = &t->entries[i];
    if (!e->used || e->key == key) {
      e->used = true;
      e->key = key;
      e->value = value;
      return true;
    }
  }
  return false;
}
bool table_get(const struct Table *t, unsigned key, int *out) {
  for (size_t step = 0; step < TABLE_CAPACITY; step++) {
    size_t i = (key % TABLE_CAPACITY + step) % TABLE_CAPACITY;
    const struct Entry *e = &t->entries[i];
    if (!e->used)
      return false;
    if (e->key == key) {
      *out = e->value;
      return true;
    }
  }
  return false;
}

int main(void) {
  /* Insert and retrieve */
  {
    struct Table t = {0};
    int out = 0;
    CHECK(table_put(&t, 1, 7) && table_get(&t, 1, &out) && out == 7);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Lookup succeeds with 7.

Lookup checks the actual key rather than trusting the initial slot alone.

### Worked example 2: Resolve a collision

Insert keys 1 and 9, which share the initial slot.

```c

int main(void) {
  /* Insert and retrieve */
  {
    struct Table t = {0};
    int out = 0;
    CHECK(table_put(&t, 1, 7) && table_get(&t, 1, &out) && out == 7);
  }

  /* Resolve a collision */
  {
    struct Table t = {0};
    int out = 0;
    CHECK(table_put(&t, 1, 10) && table_put(&t, 9, 90));
    CHECK(table_get(&t, 1, &out) && out == 10);
    CHECK(table_get(&t, 9, &out) && out == 90);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Both values remain retrievable.

Linear probing finds another free slot while preserving the key distinction.

### Exercise 3: Replace an existing key

Write key 2 twice with different values.

**Expected:** The latest value is 8.

**Verify:** Keep a CHECK equivalent to `table_get(&t, 2, &out) && out == 8`. Control edit: `CHECK(table_put(&t, 2, 3) && table_put(&t, 3, 8));` must fail; then restore it.

**Progressive hints:** First trace `t` and `out` from initialization. Then recall: Replacement does not create duplicate logical keys.

### Exercise 4: Distinguish absent from zero

Store key zero with value zero and query a missing key.

**Expected:** The stored zero succeeds; the missing key fails.

**Verify:** Keep a CHECK equivalent to `!table_get(&t, 3, &out) && out == 9`. Control edit: changing `out = 9;` to `out = 10;` must fail it; then restore it.

**Progressive hints:** First trace `t` and `out` from initialization. Then recall: Occupancy and return status preserve information that a zero sentinel would lose.

### Exercise 5: Reject a full-table insertion

Fill all eight slots and insert a new ninth key.

**Expected:** The operation returns false without looping forever.

**Verify:** Keep a CHECK equivalent to `!table_put(&t, 99, 99)`. Control edit: changing `for (unsigned i = 0; i < 8; i++)` to `for (unsigned i = 1; i < 8; i++)` must fail it; then restore it.

**Progressive hints:** First trace `t` from initialization. Then recall: Every probe sequence is bounded by capacity.

### Exercise 6: Transfer replacement while full

Replace an existing key after filling the table.

**Expected:** Replacement still succeeds.

**Verify:** Keep a CHECK equivalent to `table_put(&t, 3, 30) && table_get(&t, 3, &out) && out == 30`. Control edit: `CHECK(table_put(&t, 4, 30) && table_get(&t, 3, &out) && out == 30);` must fail; then restore it.

**Progressive hints:** First trace `t` and `out` from initialization. Then recall: Full storage prevents new keys, not an update to an already present key.

## Common pitfalls and diagnosis

Stopping a probe at the first slot whose key differs loses entries placed after a collision; only an empty slot ends the search. Returning 0 for a missing key confuses absence with a stored zero.
