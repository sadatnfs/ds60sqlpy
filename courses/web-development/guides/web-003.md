# web-003: Semantic structure, headings and landmarks

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-002`

## Learning objectives

Build a study page with landmarks and a working skip link. Explain when a div is more appropriate than section. Use semantics, heading hierarchy and landmark accurately when you explain a normal case and a failure case.

## Purpose, vocabulary and mental model

Semantic markup tells the browser and reader what a piece of content is. A main region contains the page's primary content. Navigation groups major navigation links; a header introduces a page or section; a footer provides related closing information. These elements are not a promise of any particular position on screen. A header can appear inside an article and need not be a fixed top bar.

Headings provide a hierarchy that a screen reader and a visual reader can use to scan. Use the main topic as h1 and its major subdivisions as h2, with h3 for nested detail. Choose levels for structure, not because the browser's default font size looks attractive. A section normally benefits from a heading; a generic div is appropriate when there is no additional semantic meaning.

## Syntax anatomy and mechanism

Draw the content outline before assigning tags. Use one visible main region for the primary task. Give repeated navigation regions distinct accessible labels such as `aria-label="Course"`. A skip link points to the main region's id and lets a keyboard user bypass repeated controls. Native HTML supplies roles automatically; redundant roles rarely add value.

## Worked example / walkthrough

### Worked example 1: A useful outline

Topic relationships determine heading levels.

```html
<main>
  <h1>Study notes</h1>
  <section>
    <h2>HTML</h2>
    <p>Structure first.</p>
  </section>
</main>
```

**Expected observation:** HTML is a subsection of Study notes.

### Worked example 2: Skip repeated navigation

The fragment targets a real unique element.

```html
<a href="#content">Skip to content</a>
<main id="content" tabindex="-1"><h1>Notes</h1></main>
```

**Expected observation:** The link moves to the main content target without a network request.

## Six progressive exercises

Exercises that ask you to predict, explain, compare or diagnose keep their answers in the solutions file. The others show the evidence to look for.

### Exercise 1: Draw the heading outline of the first example.

**Progressive hint:** Write each heading with its level number and indent by level.

### Exercise 2: Add a sibling CSS section at the correct level.

**Expected evidence:** CSS and HTML both use h2 because they have the same parent topic.

**Progressive hint:** Find the level of the HTML heading and use the same level for its sibling.

### Exercise 3: Build a study page with landmarks and a working skip link.

**Expected evidence:** Header, labeled navigation, one main and footer have meaningful content; the skip target exists.

**Progressive hint:** Give main an id and point the first link at it with a matching fragment.

### Exercise 4: Replace a heading used only for large text with an appropriate element.

**Expected evidence:** A visual callout uses CSS without corrupting the document outline.

**Progressive hint:** Ask whether the large text introduces a section. If it does not, style a p or div instead.

### Exercise 5: Check the document with CSS disabled or unavailable.

**Expected evidence:** The reading order and heading relationships remain coherent.

**Progressive hint:** Remove or rename the style element and read the remaining order.

### Exercise 6: Explain when a div is more appropriate than section.

**Progressive hint:** Ask whether the group would deserve its own heading in an outline.

## Debugging and common mistakes

A semantic element cannot compensate for misleading content. Avoid h1-h4 jumps that merely chase font sizes. Do not create dozens of named landmarks for tiny fragments because navigation becomes noisy.

Keep the failing source, the viewport width and what you observed, then repair one cause at a time. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order, so inspect the element and its computed styles in the browser's developer tools instead of trusting the rendering alone.
