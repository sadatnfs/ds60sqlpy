# A nonlinear trend likelihood

Start with: tmb-007, clp-006.

Outcome: Fit and interpret a nonlinear mean without confusing interpolation and extrapolation.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

Consider a sensor whose expected reading approaches a long-run background level:
\[
y_i\sim N(m(t_i),\sigma^2),\qquad m(t)=a e^{-bt}+c,\quad a>0,\ b>0.
\]
The amplitude \(a\) controls the initial excess, \(b\) controls its decay rate, and \(c\) is the limiting level. The half-life is \(\log(2)/b\). The model does not imply that every observed sequence decreases: noisy observations can rise even when the conditional mean decreases.

The original `nonlinear.cpp` optimizes log amplitude, log rate, offset and log scale. Its complete normal density separates mean structure from residual variation. Nonlinear regression is not restricted to a built-in formula once the scalar likelihood can be written and differentiated.

### Worked case A: enough time coverage

The companion constructs forty observations over eight time units with a small deterministic residual pattern. It fits the log-parameterized model using `nlminb`, prints amplitude, rate and offset, and predicts at times nine and ten. The deterministic pattern makes the worked output reproducible; it is not presented as a random sample for a coverage claim. The prepared project performs the corresponding compiled fit and checks its derivatives.

```cpp
Type mean = exp(log_a) * exp(-exp(log_b) * time(i)) + offset;
nll -= dnorm(y(i), mean, exp(log_sigma), true);
```

Each occurrence of `exp` acts on a typed parameter and remains in the derivative graph. If the sensor response were constrained to be strictly positive with proportional noise, a lognormal likelihood might be more appropriate. Merely logging observed values while retaining the same likelihood changes the model and requires care about transformed density normalizers.

### Worked case B: short history, uncertain horizon

Restrict the observations to a short early window. The Taylor approximation is \(m(t)\approx(a+c)-ab t\), so data distinguish the intercept and initial slope more readily than all three original parameters. Curves can be nearly indistinguishable now and strongly different at time ten. The companion prints such a pair without claiming both are reliable forecasts.

Forecasting requires more than optimizer convergence. Check whether the modeled mechanism should persist, whether time is measured consistently, whether a regime change is plausible and whether the forecast is inside the observed covariate domain. Hold out later times when evaluating forecasts. Random row splitting leaks nearby temporal information into training and answers a different question.

### Diagnostics and answered discussion

**Can I compare this model with a linear trend using training residual error alone?** Additional flexibility normally improves training fit. Compare held-out forecasts and, where appropriate, penalized likelihood criteria with consistent likelihood definitions. **Is the half-life standard error just the rate standard error?** No. Apply the derivative of \(\log(2)/b\) or use simulation/profile intervals. **Should the offset be positive?** Only when the scientific measurement requires it; the current model leaves it unconstrained and documents that assumption.

For a cross-library comparison, match parameterization, normalization, data and precision before comparing TMB and PyTorch. Matching optimizer labels alone does not make two fits equivalent.

### Complete R companion

```r
t <- seq(0, 8, length.out = 40)
y <- 3 * exp(-.6 * t) + 1 + rep(c(-.03, .01, .02, -.01, .01), 8)
fn <- function(p) -sum(dnorm(y, exp(p[1]) * exp(-exp(p[2]) * t) + p[3], exp(p[4]), log = TRUE))
fit <- nlminb(c(log(2.5), log(.5), .9, log(.1)), fn)
print(c(amplitude = exp(fit$par[1]), rate = exp(fit$par[2]), offset = fit$par[3], half_life = log(2) / exp(fit$par[2])))
stopifnot(fit$convergence == 0, abs(exp(fit$par[2]) - .6) < .03)
short_and_long <- c(0, .1, 10)
print(data.frame(time = short_and_long, curve_a = 3 * exp(-.6 * short_and_long) + 1, curve_b = 6 * exp(-.3 * short_and_long) - 2))
```
