# web-012: Typography, units and readable content

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-011`

## Learning objectives

Build a reading page with bounded measure and scalable headings. Explain why ch is a useful approximation rather than a word-count guarantee. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

Typography controls the effort required to read. A font stack lists preferred fonts followed by a generic fallback, so text remains usable when a particular font is absent. This course uses system fonts and makes no external font request. Relative units allow the design to respond to user settings. A rem is relative to the root font size; em often depends on the current element's font size, with property-specific details.

Line length, line height and spacing interact. Very long lines make it difficult to find the next line; very short lines create constant interruptions. A max-width expressed in ch can approximate a readable character measure, though it is based on the zero glyph width rather than an exact count of all characters. A unitless line-height scales naturally with the element's font size.

## Syntax anatomy and mechanism

Use `font: 1rem/1.6 system-ui, sans-serif` to set size, unitless line-height and family. Avoid fixing the root to a tiny pixel size to make arithmetic convenient. Preserve user zoom. Headings can use a bounded fluid size with clamp, while body text should remain comfortable and predictable. Text alignment is content-sensitive; full justification can create distracting gaps in narrow columns.

## Classroom execution and offline inputs

Choose **HTML browser preview** in the classroom. The pad is one complete HTML document with embedded CSS and, where taught, embedded JavaScript. Its preview is isolated from the classroom and recreated on each run. It does not contact a server, submit real forms, read cookies, fetch assets or load a CDN. All fixtures are inline and synthetic. The browser uses its native HTML parser, so classic-script ordering, shared lexical bindings, inline modules and real DOMContentLoaded/load events keep their browser semantics. External module imports remain blocked. Navigation metadata such as base and meta http-equiv is rejected explicitly. On any supported host, the browser renders the document while Docker serves the classroom. No host compiler is needed.

Run your own source after implementing the task. A reference's checks inspect only the named initial conditions. Its success message is not a full accessibility audit, proof of responsive behavior at every size, or evidence that you implemented the solution yourself. Inspect actual output after keyboard input, resizing and changes. Save your source before comparing with a reference. The document and its CSS share one saved pad; HTML and CSS remain different languages within that artifact.

## Worked example / walkthrough

### Worked example 1: A reading column

The column stays bounded even on a large monitor.

```css
.prose { max-inline-size: 65ch; font-size: 1rem; line-height: 1.6; }
```

**Expected observation:** Paragraphs have a bounded measure and relative text size.

### Worked example 2: A bounded heading

Clamp supplies a minimum, preferred fluid size and maximum.

```css
h1 { font-size: clamp(1.75rem, 4vw, 3rem); }
```

**Expected observation:** The heading grows with width within the given bounds.

## Debugging and common mistakes

Do not disable pinch zoom or set user-scalable=no. A brand font is optional; readable content is not. Test actual enlargement because a screenshot at one size cannot expose clipping.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation.
