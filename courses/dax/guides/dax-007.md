## The question and the mechanism

Keep a numeric measure numeric and explain why its display label is a separate concern.

DAX expressions have types, even when a report formats several types to look similar. A whole number can represent a count, a decimal can represent an amount or ratio, a Boolean expresses a logical condition, and a date identifies a calendar value. Text that looks like a number is still text until an explicit or implicit conversion occurs. Do not design a model around hoping that every consumer makes the conversion you intended.

Operators also carry meaning. The plus sign adds numeric values; an ampersand concatenates text. Parentheses make grouping visible. Multiplication before subtraction matters in the line formula Quantity * UnitPrice - Discount, because Discount is defined for the entire line. If the discount were per unit, the correct formula and data dictionary would differ.

A unit is not enforced merely because a column is numeric. Revenue in USD, units sold and the number of orders are all numbers with different interpretations. FORMAT produces text for presentation; it is not a substitute for a numeric measure with a format property. Preserve the numeric value when later visuals need sorting, aggregation or numerical comparison.

## Vocabulary and expression anatomy

ROW can hold differently typed columns in one result. DATE constructs a date from year, month and day. DIVIDE returns the ratio of two numeric expressions. FORMAT's explicit en-US locale makes this example's decimal and currency characters reproducible; it still returns text. The classroom records an ISO date string in the worked table rather than pretending to emulate a report's regional display settings.

Concepts to explain in your own words: **scalar**, **number**, **text**, **Boolean**, **date**, **format**.

## Model and context contract

The ordinary star follows Product → Sales, Customer → Sales and Date → Sales through OrderDate. The ShipDate relationship is inactive unless a case explicitly activates it. Filters flow from the one side to the many side. Additional analytical tables have only the relationships declared in their named model; a similar column name does not create a relationship.

```text
Product (one)  --> Sales (many) <-- Customer (one)
                       ^
                       | active OrderDate
                    Date (one)
                       | inactive ShipDate
                       +------> Sales
```

All amounts in ordinary Sales are USD after the line discount, before tax and returns. The Date fixture is complete for 2024 and 2025; a short result table is a selected slice, not the whole calendar. JSON `null` in the worked-results sidecar means DAX BLANK, not the text "null".

## Worked cases

The following query-local declarations are shared by these cases. They do not create persisted measures in this classroom.

```dax
DEFINE
    MEASURE Sales[NetRevenue] = SUM ( Sales[NetAmount] )
```

### Case A: A row of distinct types

**Starting context:** Literal expressions; no model filter is needed.

```dax
EVALUATE ROW ( "Count", 3, "Ratio", DIVIDE ( 3, 2 ), "Larger", 3 > 2, "Day", DATE ( 2025, 1, 2 ) )
```

**Context trace:**

1. The whole-number literal is 3.
2. Three divided by two is 1.5, while the comparison is TRUE.
3. DATE constructs 2025-01-02; a different display format would not change that date.

**Hand-derived worked-reference result:**

| Count | Ratio | Larger | Day |
| --- | --- | --- | --- |
| 3 | 1.5 | TRUE | 2025-01-02 |

Putting values in the same row does not make them interchangeable. The ratio is not a count of one and a half transactions; its unit depends on its numerator and denominator.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

### Case B: A number and its text label

**Starting context:** All retail sales; a numeric result and an explicitly formatted text representation.

```dax
EVALUATE ROW ( "NumericRevenue", [NetRevenue], "DisplayText", FORMAT ( [NetRevenue], "$0.00", "en-US" ) )
```

**Context trace:**

1. The measure evaluates to numeric 187.
2. FORMAT renders the same amount as the text $187.00.
3. The original number remains available for later arithmetic.

**Hand-derived worked-reference result:**

| NumericRevenue | DisplayText |
| --- | --- |
| 187 | $187.00 |

Replacing every revenue measure with FORMAT can break numerical behavior even when the report looks correct. Numeric measures and display policy should remain separate.

Hand-derived for the named reference and fixture. Editing a draft does not recalculate this table.

## Progressive hints

1. Apply the multiplication grouping before addition.
2. Change presentation, not the fact table.
3. Give each output its own name and unit.
4. Compare text beginning with 9 and text beginning with 1.
5. A fraction is dimensionless; a displayed percent includes a scale convention.
6. A string's appearance does not declare seconds, minutes or a clock time.
