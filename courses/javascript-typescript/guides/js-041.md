# js-041: A typed analytics pipeline

## Level and prerequisites

Advanced, approximately 120 minutes. Direct prerequisites: `js-040`

## Learning objectives

Explain framing, quarantine, aggregation state, resource budget with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. The first investigation is: Decode rows for groups A and B from three-byte chunks and aggregate their values. The final task tests expose incomplete-data counts and empty input.

## Purpose and mental model

An analytics pipeline combines framing, parsing, validation and aggregation. Each layer has a different failure mode. Bytes can split UTF-8 characters, chunks can split lines, JSON can be malformed, and syntax-valid rows can violate a domain schema. Treating every line as a trusted typed record skips several independent boundaries. A useful diagnostic identifies the physical line and category without copying sensitive raw data into logs.

This fixture accepts newline-delimited JSON rows containing a group and a bounded integer value. A StringDecoder retains incomplete UTF-8 sequences across byte chunks. A line buffer retains incomplete records. The parser validates exact fields and returns a typed record or a compact diagnostic. Aggregation stores a count and sum per group. Invalid rows are quarantined as diagnostics; their values do not contribute to accepted totals.

The quarantine policy is a deliberate choice. A financial reconciliation or release gate might instead reject the entire input on any invalid row. This example returns accepted and rejected counts so a partial aggregate cannot be confused with a complete clean dataset. It does not infer that rejected data is statistically ignorable: missingness can bias the aggregate, so the downstream interpretation must consider why rows failed.

Streaming does not automatically mean bounded memory. The fixture caps total input bytes, line bytes and record lengths, and its tiny group set is controlled by the authored input. A production pipeline with unbounded unique groups needs a cardinality limit, spill strategy or external aggregation. The code demonstrates actual incremental decoding and validation, not a claim of constant memory for arbitrary datasets.

## Vocabulary and concepts

**Framing:** Separating a byte/text stream into logical records.

**Quarantine:** Retaining failure diagnostics while excluding invalid rows from accepted aggregates.

**Aggregation state:** The per-group statistics retained while scanning records.

**Resource budget:** An explicit bound on input, records or retained state.

## Syntax anatomy and execution trace

The byte source is an AsyncIterable<Uint8Array>. StringDecoder.write handles split characters, while end flushes remaining decoder state. A pending text buffer is split at newline characters and strips an optional preceding carriage return. Each physical line receives a one-based number. JSON.parse returns unknown at the boundary, and the validator checks its shape before constructing a fresh Row. Map aggregation updates only accepted rows and returns a separate diagnostics list.

## Worked example / walkthrough

### Example A: Aggregate valid split-byte input

Chunk boundaries are independent of JSON record boundaries. The pipeline carries partial decoder and line state instead of parsing each chunk as a complete row.

```typescript
import { strict as assert } from 'node:assert';
import { StringDecoder } from 'node:string_decoder';

type Row = { group: string; value: number };
type Diagnostic = { line: number; code: 'json' | 'schema' };
function row(value: unknown): Row | undefined {
  if (typeof value !== 'object' || value === null || Array.isArray(value)) return undefined;
  if (
    Object.keys(value).sort().join(',') !== 'group,value' ||
    !('group' in value) ||
    !('value' in value)
  )
    return undefined;
  if (
    typeof value.group !== 'string' ||
    value.group.length === 0 ||
    value.group.length > 40 ||
    typeof value.value !== 'number' ||
    !Number.isSafeInteger(value.value) ||
    Math.abs(value.value) > 1000
  )
    return undefined;
  return { group: value.group, value: value.value };
}
async function* chunks(text: string, size: number): AsyncGenerator<Uint8Array> {
  const bytes = Buffer.from(text, 'utf8');
  for (let index = 0; index < bytes.length; index += size)
    yield bytes.subarray(index, index + size);
}
async function* lines(
  source: AsyncIterable<Uint8Array>,
): AsyncGenerator<{ line: number; text: string }> {
  const decoder = new StringDecoder('utf8');
  let pending = '';
  let total = 0;
  let line = 0;
  for await (const chunk of source) {
    total += chunk.byteLength;
    if (total > 16384) throw new RangeError('input byte budget exceeded');
    pending += decoder.write(Buffer.from(chunk));
    let boundary: number;
    while ((boundary = pending.indexOf('\n')) >= 0) {
      const text = pending.slice(0, boundary).replace(/\r$/u, '');
      pending = pending.slice(boundary + 1);
      if (Buffer.byteLength(text) > 1024) throw new RangeError('line byte budget exceeded');
      yield { line: ++line, text };
    }
    if (Buffer.byteLength(pending) > 1024) throw new RangeError('line byte budget exceeded');
  }
  pending += decoder.end();
  if (pending !== '') yield { line: ++line, text: pending.replace(/\r$/u, '') };
}
async function analyze(source: AsyncIterable<Uint8Array>): Promise<{
  groups: Map<string, { count: number; sum: number }>;
  accepted: number;
  rejected: Diagnostic[];
}> {
  const groups = new Map<string, { count: number; sum: number }>();
  const rejected: Diagnostic[] = [];
  let accepted = 0;
  for await (const entry of lines(source)) {
    if (entry.text.trim() === '') continue;
    let value: unknown;
    try {
      value = JSON.parse(entry.text);
    } catch {
      rejected.push({ line: entry.line, code: 'json' });
      continue;
    }
    const parsed = row(value);
    if (!parsed) {
      rejected.push({ line: entry.line, code: 'schema' });
      continue;
    }
    const previous = groups.get(parsed.group) ?? { count: 0, sum: 0 };
    groups.set(parsed.group, { count: previous.count + 1, sum: previous.sum + parsed.value });
    accepted += 1;
  }
  return { groups, accepted, rejected };
}

export async function verify(): Promise<{ checks: number; status: string }> {
  // Worked example
  {
    const text = [
      { group: 'A', value: 2 },
      { group: 'B', value: 4 },
      { group: 'A', value: 3 },
    ]
      .map((row) => JSON.stringify(row))
      .join('\n');
    const result = await analyze(chunks(text, 3));
    assert.deepEqual(
      [...result.groups],
      [
        ['A', { count: 2, sum: 5 }],
        ['B', { count: 1, sum: 4 }],
      ],
    );
    assert.equal(result.accepted, 3);
    assert.deepEqual(result.rejected, []);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** A count 2 sum 5; B count 1 sum 4; zero rejected.
### Example B: Quarantine syntax and domain failures with physical line numbers

Rejected values never enter the aggregate. The diagnostic identifies where and why the row failed without reproducing the entire source payload.

      { line: 2, code: 'json' },

**Expected:** one accepted row; diagnostics at lines 2 and 3 with json/schema categories.

## Prediction before your attempt

Trace the entry point and identify the values that exist before each operation. Distinguish a value from a reference to an object, a returned Promise from its eventual result, and a compile-time type from a runtime check. Write down the first observation that would disprove your explanation. A useful prediction includes an expected value or failure category, not merely a claim that the program should work.

For a loop, write the state before and after one iteration. For a callback, identify the caller and the arguments it supplies. For an asynchronous operation, identify who starts it, who awaits it, and who owns cleanup. These small traces make failures local: you can compare the first incorrect state instead of guessing from a much later symptom.

## Common pitfalls and diagnosis

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.

## Progressive hints

Start by comparing the actual value with the literal expected result. Next, isolate the expression that transforms it or the boundary where its type or ownership changes. If the discrepancy involves scheduling, replace unrelated work with a small trace array and await the exact completion you intend to observe. Finally, ask for one hint about the first incorrect assumption before opening the reference. Keep one controlled failure that would catch the same mistake returning.
