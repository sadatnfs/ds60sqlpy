# Apache and open data platform authoring

Read the root guidance and repository Add a learning path skill. This subject owns
apache-001 through apache-088 and the projects beneath this directory. Use tutorial
mode, complete worked answers and no compulsory exams. Do not use em dashes.

`authoring/chapter-map.json` and `DESIGN.md` are design inputs, not admission
manifests. Admit only developed guides, source and verified runtime contracts.
Maintain two distinct explained worked cases, mechanism-level prose, mistakes,
answered interview discussions, primary citations and explicit mathematical
notation. Never copy a generic paragraph across chapters to satisfy a count.

Ordinary examples use prepared actual libraries. Distributed services belong to
owned project workshops with no Docker socket inside ordinary workers. Mark their
main classroom artifacts as reading/Markdown, with full commands and observations.
No simulated broker, catalog, scheduler or server counts as real-product evidence.

Keep Arrow, DataFusion and PyIceberg API compatibility separate from Ballista and
Delta Sharing client dependencies. Use official upstream releases and digest or
source checksums. Delta Sharing belongs to the Delta Lake/Linux Foundation
ecosystem, not the Apache Software Foundation. Use Rust, Java, Scala and Python
where the actual product APIs justify them.

Projects have bounded resources, loopback ports, exact ownership checks, persistent
state, explicit lifecycle and deletion commands, and positive, negative and restart
checks. Prefer upstream service images and build custom clients inside Docker.
Record AMD64/ARM64 availability separately from actual native runtime acceptance.
Do not publish images, run global prune, touch other projects or change shared
runtime/UI/CI code from this tree. Coordinate integration with the parent owner.
