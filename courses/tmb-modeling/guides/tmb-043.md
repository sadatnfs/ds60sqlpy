# Multivariate normals and Gaussian Markov fields

Start with: tmb-042, tmb-015.

Outcome: Choose covariance or precision interfaces and verify equivalent tiny densities.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter compares covariance and precision forms of a bivariate normal density and inspects an intrinsic precision. The separately prepared [C++ API probes](../projects/tmb-cpp-api/README.md) compile `models/density_forms.cpp`, and `check.R` compares its `MVNORM`, `GMRF`, `SCALE` and `VECSCALE` densities with dense formulas; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

A multivariate normal can be represented by covariance \(\Sigma\) or precision \(Q=\Sigma^{-1}\). These interfaces are not interchangeable arguments. The normalized NLL is
\[
\tfrac q2\log(2\pi)+\tfrac12\log|\Sigma|+\tfrac12u^T\Sigma^{-1}u
=\tfrac q2\log(2\pi)-\tfrac12\log|Q|+\tfrac12u^TQu.
\]

TMB's `density::MVNORM` family uses a covariance matrix and is intended for manageable dense problems. `density::GMRF` uses a sparse precision representation and supports structured Gaussian fields. Passing a precision matrix where a covariance is expected changes both the quadratic form and normalizer.

## Key terms

- **Covariance and precision:** Two representations of a multivariate normal, \(\Sigma\) and its inverse \(Q\); they enter the quadratic form and log determinant with opposite roles.
- **MVNORM:** TMB's `density::MVNORM` family, which takes a covariance matrix and suits manageable dense problems.
- **GMRF:** A Gaussian Markov random field; `density::GMRF` takes a sparse precision matrix for structured latent fields.
- **Singular precision:** A precision matrix with a null direction, such as an unanchored random walk, which defines no normalized density without a constraint.

### Worked case A: two representations, one density

The companion evaluates the same two-dimensional normal using covariance and precision formulas and verifies agreement. It also prints the incorrect result obtained by interpreting precision as covariance. This small oracle should precede a large sparse model.

```cpp fragment
Type dense_nll = density::MVNORM(covariance)(state);
Type sparse_nll = density::GMRF(precision)(state);
```

These are API patterns, not a suggestion to add both terms for the same state. Adding both would double-model that state. A comparison variant should select one representation at a time or report their difference as a diagnostic.

### Worked case B: a singular precision

A difference-only random-walk precision has a null direction. Without a constraint or a proper initial-level distribution, it does not define a normalized Gaussian density over every coordinate. The companion compares the singular matrix with a properly anchored one. A sparse Cholesky failure can be a correct indication of an improper model rather than a library installation problem.

`GMRF` options involving normalization or powers/order affect the model and computational path. Do not disable normalization merely to avoid an expensive determinant when estimating precision parameters. If a constant is truly parameter-independent for a narrowly defined target, document that derivation and keep normalized references for integration checks.

### Answered discussion

**Can any positive diagonal matrix be treated as a covariance?** It must be symmetric positive definite as a whole. **Does sparse precision imply sparse covariance?** Usually not; conditional dependence can be local while marginal dependence is widespread. **When should I avoid explicit inversion?** For large matrices, use factorization and solves. Our explicit inverse is only a tiny pedagogical oracle.

See the [MVNORM and GMRF density-family implementation](https://github.com/kaskr/adcomp/blob/master/TMB/inst/include/tmbutils/density.hpp). Hardware scale claims require actual memory and factorization measurements on the intended graph.

### Worked case C: the three printed densities

The companion's covariance has determinant \(2 \times 1 - 0.5^2 = 1.75\), so the precision is \(Q = \frac{1}{1.75}\begin{pmatrix}1 & -0.5\\ -0.5 & 2\end{pmatrix}\). With \(u = (0.3, -0.4)\) the pieces are (closed-form values, rounded):

```text
constant              = log(2 pi)                    = 1.837877
u' Sigma^{-1} u       = (0.09 + 0.12 + 0.32) / 1.75  = 0.302857
u' Sigma u            = 0.18 - 0.12 + 0.16           = 0.220000
covariance_form       = 1.837877 + 0.279808 + 0.151429 = 2.269114
precision_form        = 1.837877 - (-0.279808) + 0.151429 = 2.269114
wrong_precision_as_covariance
                      = 1.837877 - 0.279808 + 0.110000 = 1.668069
```

The first two agree because \(\log|Q| = -\log|\Sigma|\). The wrong value is lower by 0.601, so a model that confused the two interfaces would not merely be slightly off: it would report a better fit for this state, and when \(\Sigma\) contains estimated scale parameters the optimizer would move them in the opposite direction. The companion's threshold of 0.1 is well inside that gap.

The eigenvalue list explains Worked case B. The intrinsic matrix `crossprod(D)` is \(\begin{pmatrix}1&-1&0\\-1&2&-1\\0&-1&1\end{pmatrix}\) with eigenvalues 0, 1 and 3. The zero belongs to the direction \((1,1,1)\): adding a constant to every state leaves every difference, and so the quadratic form, unchanged. Anchoring adds 1 to the first diagonal entry and gives eigenvalues 0.198062, 1.554958 and 3.246980 (numerical values, rounded). Their product is exactly 1, which can be checked by hand: the anchored precision is the density of \(x_1 \sim N(0,1)\), \(x_2 - x_1 \sim N(0,1)\), \(x_3 - x_2 \sim N(0,1)\), a triangular change of variables with unit Jacobian, so \(\log|Q| = 0\).

In a template, the anchored form is a sparse precision passed to `GMRF`:

```cpp fragment
DATA_SPARSE_MATRIX(Q); // anchored random-walk precision
PARAMETER_VECTOR(x);
Type nll = density::GMRF(Q)(x);
```

### Why the precision route scales

For a random walk of length \(q\) the anchored precision is tridiagonal, with \(3q - 2\) nonzeros. Its Cholesky factor is bidiagonal, so factorization costs work proportional to \(q\). The covariance of the same walk is dense: entry \((i, j)\) equals \(\min(i, j)\) for the anchored walk, so every entry is nonzero, and a dense Cholesky costs about \(q^3/3\) operations, roughly \(3.3 \times 10^8\) at \(q = 1000\) (hand-derived). This is the practical reason Gaussian Markov fields are written with precision matrices. Inside a Laplace approximation the sparse factorization is repeated at every outer step, so the difference compounds over an entire fit.

### Base-R companion (runs in the classroom)

```r
Sigma <- matrix(c(2, .5, .5, 1), 2, 2);Q <- solve(Sigma);u <- c(.3, -.4);constant <- length(u) * log(2 * pi) / 2
ld <- function(M) as.numeric(determinant(M, logarithm = TRUE)$modulus)
a <- constant + ld(Sigma) / 2 + drop(t(u) %*% solve(Sigma, u)) / 2
b <- constant - ld(Q) / 2 + drop(t(u) %*% Q %*% u) / 2
wrong_precision_as_covariance <- constant + ld(Q) / 2 + drop(t(u) %*% solve(Q, u)) / 2
print(c(covariance_form = a, precision_form = b, wrong_precision_as_covariance = wrong_precision_as_covariance))
stopifnot(abs(a - b) < 1e-12, abs(wrong_precision_as_covariance - a) > .1)
D <- matrix(c(-1, 1, 0, 0, -1, 1), 2, 3, byrow = TRUE);intrinsic <- crossprod(D);proper <- intrinsic;proper[1, 1] <- proper[1, 1] + 1
print(list(intrinsic = eigen(intrinsic, symmetric = TRUE)$values, anchored = eigen(proper, symmetric = TRUE)$values))
```
