llm-033: Preference objectives and what they do not prove#

Level and prerequisites#

Advanced; approximately 120 minutes. Direct prerequisites: llm-032. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Compute a preference loss and separate preference evidence from factual correctness. The central investigation is concrete: Calculate a DPO-style logistic loss from fixed policy/reference log probabilities; reverse chosen/rejected labels and inspect the change. The finish condition is Equal preference margins produce log⁡(2)\log(2)log(2); swapping labels reverses the margin. No online RL, reward model service or factuality guarantee is claimed. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Learn from a comparison without confusing preference with truth#

Supervised instruction tuning provides a desired response to imitate. Preference data instead compares responses under a stated criterion: for the same prompt, one response is labeled chosen and another rejected. A preference objective turns that comparison into a learning signal. The criterion might concern usefulness, format, completeness or another property, and the label collection process determines what it actually means. A chosen label is not automatically an independently verified factual answer.

Let x be a prompt, y_w the chosen response and y_l the rejected response. Write pi_theta(y|x) for the current policy's sequence probability and pi_ref(y|x) for a fixed reference policy. A sequence log probability is a sum of conditional token log probabilities under the declared tokenization and termination policy. The lesson uses those log probabilities as supplied scalar values so the objective can be inspected without sampling or training a model.

Understand where the reference correction comes from#

One motivation considers a policy optimized for expected reward while penalizing divergence from a reference distribution. Under the relevant fixed-prompt, support and normalization assumptions, the optimum has the form π∗(y∣x)∝πref(y∣x)exp⁡ ⁣(r(x,y)β)\pi_*(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)\exp\!\left(\frac{r(x,y)}{\beta}\right)π∗​(y∣x)∝πref​(y∣x)exp(βr(x,y)​). Rearranging expresses reward as βlog⁡π∗(y∣x)πref(y∣x)\beta\log\frac{\pi_*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}βlogπref​(y∣x)π∗​(y∣x)​ plus a prompt-dependent normalization term.

If pairwise preferences are modeled through a logistic function of reward differences, that prompt-only normalization term cancels between two responses to the same prompt. This yields the relative log-probability comparison used by the DPO-style objective. The derivation relies on the preference model and regularized-policy assumptions; it is not a statement that arbitrary human choices reveal an exact universal reward function. The DPO paper develops this connection in full, while the course isolates the resulting scalar objective.

The reference policy is normally fixed for the stated comparison. If its parameters or scoring convention change, the same current-policy scores can produce a different margin. Store the reference identity alongside the data and objective configuration. Using a variable called reference does not establish that it remained frozen or that its tokenization matched the current policy.

Follow the gradient to see what is rewarded#

The derivative ∂L∂m\frac{\partial L}{\partial m}∂m∂L​ is −σ(−m)-\sigma(-m)−σ(−m). Applying the chain rule gives derivative −βsigmoid⁡(−m)-\beta\operatorname{sigmoid}(-m)−βsigmoid(−m) with respect to the chosen response's current log probability and +βsigmoid⁡(−m)+\beta\operatorname{sigmoid}(-m)+βsigmoid(−m) with respect to the rejected response's. Gradient descent therefore pushes the chosen log probability upward relative to the rejected one through the model's parameterization. At β=0.5\beta=0.5β=0.5 and m=1m=1m=1, the magnitudes are approximately .13447.

For a very positive margin, the gradient becomes small because the pair is already strongly ordered as desired. For a very negative margin, its magnitude with respect to m approaches 1. The stable implementation uses logaddexp(0,-m) rather than forming exp⁡(−m)\exp(-m)exp(−m) directly. At m=−1000m=-1000m=−1000, direct exponentiation can overflow even though the loss is approximately 1000 and can be represented. Numerical stability preserves the intended objective; it does not correct bad labels or a mismatched reference.

An improved margin need not mean that the chosen response's absolute probability increased. Suppose the current difference changes from(-2)-(-3)=1 to(-3)-(-5)=2. The chosen response became less probable, but the rejected response declined even more, so the relative preference improved. This counterexample explains why a margin alone is not a complete description of the policy change. Inspect sequence probabilities, task outcomes and reference divergence when those quantities matter to the experiment.

Token and response conventions change the event being compared#

A sequence log probability is usually a sum over response tokens conditioned on the prompt and previous response tokens. Prompt tokens can be context without belonging to the response score. Including an EOS token, masking formatting tokens or normalizing by response length changes the comparison. A mean token log probability is not algebraically interchangeable with the sequence log probability in the stated objective.

Length can affect sums because a longer response contains more factors below one. The reference correction can account for aspects of baseline preference, but it does not make every length-related data bias disappear. If annotators consistently prefer verbose answers or the rejected responses are systematically shorter, the dataset may teach a style preference alongside the intended quality criterion. Preserve response lengths and annotation rationale so that a gain can be interpreted.

The prompt must also be the same contextual event for the pair. Comparing one response generated with extra retrieval evidence to another generated without it can mix evidence availability with response quality. Such a comparison may be meaningful for a system-level study, but it is a different experimental question from changing only the policy under fixed context. Record the actual input artifacts used to produce each candidate.

Preference data is a measurement process#

A label can be inconsistent, ambiguous or affected by presentation order, domain knowledge and the rubric. Multiple annotators may disagree for substantive reasons. A dataset should retain the prompt family, candidate identities, rubric, available evidence and relevant collection conditions. Pair counts alone do not establish independent coverage if many comparisons are variations of the same underlying task.

Train/development/test separation must follow the intended unit of generalization. If the same source answer or prompt template appears in both adaptation and assessment, a favorable score may reflect familiarity with that family. Choosing beta or a stopping point after repeatedly examining final assessment preferences similarly converts that set into development data. The presence of a reference policy does not solve data leakage.

A useful application evaluation separates the behavior rewarded by preference labels from other required properties. Better preferred-response rate can coexist with worse citation support, more unsupported detail or a regression on a small but important task family. Those outcomes need their own checks. This does not make preference learning useless; it makes its objective precise enough to combine with other evidence.

Know what the local exercise actually executes#

The reference computes fixed margins, stable losses and controlled changes. It does not fit a reward model, sample a rollout, run an online reinforcement-learning loop or train a production assistant. Describing it as a full RLHF pipeline would attribute work to the code that it never performs. Its contribution is the ability to derive and debug a preference objective before using one in a larger adaptation experiment.

Vocabulary and concepts#

Preference pair: Two candidate responses labelled chosen and rejected.

Reference policy: A fixed comparison distribution in the objective.

Preference margin: The adjusted log-probability advantage of the chosen response.

Syntax anatomy and reasoning sequence#

Let margin=beta*((policy_chosen-policy_rejected)-(reference_chosen-reference_rejected)). The negative log sigmoid equals logaddexp(0,-margin), which is stable for large magnitudes. Log probabilities are sequence scores under a declared tokenization and length policy. Keep those conventions fixed when comparing pairs, because length changes can affect sequence log probability.

What the preference margin measures#

For a common prompt x and chosen/rejected answers, let delta_policy=log p_policy(chosen|x)-log p_policy(rejected|x), with an analogous delta_reference. The objective used here is L=log⁡(1+exp⁡(−m))L=\log(1+\exp(-m))L=log(1+exp(−m)), where m=β⋅(δpolicy−δreference)m=\beta\cdot (\delta_{\mathrm{policy}}-\delta_{\mathrm{reference}})m=β⋅(δpolicy​−δreference​). A positive margin means the policy favors the chosen answer more than the reference does under this sequence-scoring convention. It does not mean the chosen answer has high absolute probability or that its factual claims are true.

In the first case, policy scores-2 and-3 give δpolicy=1\delta_{\mathrm{policy}}=1δpolicy​=1, while reference scores-4 and-5 also give δreference=1\delta_{\mathrm{reference}}=1δreference​=1. Their difference is zero, so the loss is log⁡(2)\log(2)log(2), about 0.693147, even though both systems prefer the chosen answer. In the second case the supplied differences are2 and 0 with beta0.5, yielding margin 1 and loss about 0.313262. Reversing the preference gives margin-1 and loss about 1.313262. The objective rewards a change in relative preference against the reference.

The derivative with respect to the margin is −σ(−m)-\sigma(-m)−σ(−m). For a large positive margin it approaches zero; for a very negative margin it approaches-1. Computing logaddexp(0, -m) avoids directly exponentiating a huge positive number. At margins1000 and-1000 the stable losses are approximately 0 and1000, rather than an overflow in the latter case.

Objective, optimization and preference quality are separate#

The DPO formulation connects a preference objective to a reference policy. This chapter evaluates the scalar objective and its counterexamples. It does not train a policy, fit a reward model, collect online rollouts or implement an RLHF pipeline. The applied preference lesson supplies actual small gradient updates and discusses the distinct workflows.

A practical comparison needs paired answers for the same prompt, a declared label collection procedure and consistent sequence likelihood accounting. A sum of token log probabilities and a length-normalized score are different quantities; changing the reduction changes the objective. Preference labels can reflect style, brevity or annotation error. They require separate factual, task-specific and held-out evaluation. Reusing the final evaluation answers to choose beta or prompts would also contaminate the reported result. A decreasing preference loss is evidence about the fitted comparison objective, not a universal reliability certificate.

Worked example / walkthrough#

Example A: Evaluate equal margins#

Equal relative preferences cancel even though absolute sequence log probabilities differ. The objective compares a change in preference relative to the reference.

import numpy as np

margin=.1*((-2-(-3))-(-4-(-5))); loss=np.logaddexp(0,-margin)
assert margin==0; np.testing.assert_allclose(loss,np.log(2),atol=1e-12,rtol=0)

Expected: margin0 and loss log 2.

Example B: Favor the chosen response#

A positive adjusted margin reduces the logistic loss. This expresses agreement with the supplied preference label, not independent correctness.

import numpy as np

margin=.1*((-2-(-3))-(-4-(-5))); loss=np.logaddexp(0,-margin)
assert margin==0; np.testing.assert_allclose(loss,np.log(2),atol=1e-12,rtol=0)
margin=.5*(2-0); loss=np.logaddexp(0,-margin)
np.testing.assert_allclose(loss,np.log1p(np.exp(-1)),atol=1e-12,rtol=0)

Expected: margin1;loss log⁡(1+e−1)\log(1+e^{-1})log(1+e−1).

Common pitfalls and diagnosis#

Compute the policy and reference log-ratios separately, then subtract and scale. Use a stable logistic loss for extreme margins. Inspect prompt pairing, token reduction and label quality before treating a lower preference loss as a better task outcome. This program calculates the objective rather than training an RLHF system.
