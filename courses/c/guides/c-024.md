# c-024: Sorting, binary search and complexity evidence

## Purpose and mental model

An algorithm contract includes input assumptions and output meaning. Binary search requires sorted data and a comparison relation consistent with that ordering. A lower-bound search returns the first position whose value is at least a target, including an insertion position when no element matches. Using a half-open interval makes empty input and one-past results natural. Midpoint arithmetic should avoid overflowing low+high. Complexity explains growth in operations, while runtime performance depends on constants, memory access and input distribution. Preserve exact boundary tests when optimizing rather than trusting a faster-looking implementation.

## Vocabulary and concepts

- **Lower bound:** The first index whose value is not less than a target.
- **Search invariant:** A statement preserving where the answer can lie.
- **Asymptotic growth:** How required work changes as input grows.

## Syntax anatomy and execution trace

Maintain an interval [low, high) containing the answer. Compute middle as low+(high-low)/2. If values[middle] is below the target, advance low to middle+1; otherwise set high to middle. The interval strictly shrinks until both bounds meet. Never dereference the returned index before checking it is below length. Sorting and deduplication are different operations.

## Worked example / walkthrough

### Worked example 1: Find an interior boundary

Search 2, 4, 6, 8 for target 5.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

size_t lower_bound(const int *values, size_t n, int target) {
  size_t low = 0, high = n;
  while (low < high) {
    size_t middle = low + (high - low) / 2;
    if (values[middle] < target)
      low = middle + 1;
    else
      high = middle;
  }
  return low;
}

int main(void) {
  /* Find an interior boundary */
  {
    int values[] = {2, 4, 6, 8};
    CHECK(lower_bound(values, 4, 5) == 2);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The lower-bound index is 2.

The result is an insertion position, not a claim that 5 exists.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
