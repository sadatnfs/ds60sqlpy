## Outcome and mechanism

Validate a small ingestion boundary without silently coercing, dropping or repairing invalid records.

An ingestion boundary turns external representations into an analytical table. A successful file read only establishes that the bytes were parsed; it does not establish valid identifiers, ranges, dates or relationships. Separate structural validation from record-level admission. A missing required column can invalidate the entire batch, while an invalid measurement might be quarantined under a documented policy.

Reason codes make rejection auditable. A row with a missing ID and a negative amount may violate more than one rule. Retain all relevant flags or state a deliberate precedence for the reported primary reason. Do not let the arbitrary order of if statements become an undocumented data-quality policy.

Coercion is not repair. Turning a malformed numeric string into NA, then replacing NA with zero, creates a measured value the source never supplied. Preserve the original field and parse status where debugging requires them. A rejection report can retain only the bounded synthetic fields necessary for the lesson; a real system should also apply its privacy and retention policy.

Admission counts should reconcile. Input rows equal admitted plus quarantined rows when the sets are disjoint and exhaustive. That invariant catches accidental loss or duplication. Batch validity is still scoped to the implemented rules: a table can satisfy local range checks and remain biased, stale or scientifically unsuitable. Validation is one layer of evidence, not a guarantee of truth.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Validation rule | An explicit predicate describing an admissible record. |
| Quarantine | A retained diagnostic set of records that fail admission. |
| Reason code | A stable explanation of a validation failure. |
| Schema drift | An unexpected change in fields, types or meaning. |

## Read the syntax

Build separate logical rule flags, then a complete admitted mask. Return data and diagnostics as named fields. Require declared column names/types before evaluating row expressions, and check the input=admitted+rejected reconciliation.

## Worked examples

### Example 1: Retain multiple failure flags

```r
raw <- data.frame(id = c("A", "", "C", "D"), amount = c(2, 3, -1, NA_real_))
flags <- data.frame(missing_id = is.na(raw$id) | raw$id == "", invalid_amount = !is.finite(raw$amount) | raw$amount < 0)
admitted <- !flags$missing_id & !flags$invalid_amount
stopifnot(identical(admitted, c(TRUE, FALSE, FALSE, FALSE)))
stopifnot(sum(admitted) + sum(!admitted) == nrow(raw))
print(cbind(raw, flags))
```

**Expected observation:** One admitted row, three rejected rows.

The negative and missing amounts remain distinct original inputs, even though both violate the same finite-nonnegative amount rule.

### Example 2: A structural error rejects the batch

```r
validate_columns <- function(data) {
  required <- c("id", "amount")
  if (!all(required %in% names(data))) stop("missing required columns", call. = FALSE)
  if (!is.character(data$id) || !is.numeric(data$amount)) stop("invalid column types", call. = FALSE)
  TRUE
}
stopifnot(validate_columns(data.frame(id = "A", amount = 2)))
bad <- tryCatch(
  {
    validate_columns(data.frame(id = "A", value = 2)); FALSE
  },
  error = function(e) TRUE
)
stopifnot(bad)
print(bad)
```

**Expected observation:** The malformed batch is rejected.

The validator does not silently rename an unexpected field or guess that value must mean amount. Structural drift gets an explicit failure.

### Example 3: A parse failure is not a measured zero

```r
text <- c("12.5", "", "1,5", "7")
parsed <- suppressWarnings(as.numeric(text))
zeroed <- ifelse(is.na(parsed), 0, parsed)
stopifnot(mean(zeroed) == 4.875)
blank <- trimws(text) == ""
parse_failed <- is.na(parsed) & !blank
stopifnot(identical(blank, c(FALSE, TRUE, FALSE, FALSE)))
stopifnot(identical(parse_failed, c(FALSE, FALSE, TRUE, FALSE)))
admitted <- !blank & !parse_failed
stopifnot(sum(admitted) == 2L, mean(parsed[admitted]) == 9.75)
print(data.frame(text, parsed, blank, parse_failed))
```

**Expected observation:** Four rows; blank is TRUE only for the empty string, parse_failed only for 1,5, and the admitted mean is 9.75 rather than the zero filled 4.875.

as.numeric turns both the empty string and the decimal comma value 1,5 into NA, so after parsing the two problems look identical. Filling every NA with 0 then averages 12.5, 0, 0 and 7 to 4.875, and both zeros would pass a rule that rejects negative amounts. Comparing the parsed result with the original text separates the cases: a blank field is missing, while a nonblank field that failed to parse is a format error the source must fix. Each gets its own flag, and the admitted mean, 9.75, uses only the two values that were actually read.

## Reading the rejected table

For the reference input, `result$rejected` prints three rows:

```text
  id amount missing_id invalid_amount
2        -3       TRUE           TRUE
3  C     -1      FALSE           TRUE
4  D     NA      FALSE           TRUE
```

The row names 2, 3 and 4 are the positions in `raw`, and for the first rejected record they are the only identifier, because its id is empty. A quarantine file written without them, or with `row.names = FALSE`, leaves no way to point the source owner at that line. Keeping an explicit source row column is safer than relying on row names surviving later steps.

D's flag deserves a second look. `NA < 0` is NA, but `!is.finite(NA)` is TRUE, and `TRUE | NA` is TRUE, so invalid_amount is a plain TRUE. Without the is.finite term the flag would be NA, `keep` would contain NA, and indexing with it would add a row of NA values to the admitted table. The first rejected row also shows both flags at once, so one resubmission can fix the id and the amount together.

## Progressive hints

1. Every rule must pass for admission.
2. Both rule flags should remain visible.
3. Keep disjoint sets and the original reason flags.
4. An unparseable value is not a measured zero.
5. Schema and row validity are separate.
6. Scientific suitability requires broader evidence.
