# c-037: Mutexes, condition variables and predicate loops

## Level and prerequisites

Advanced, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-036`

## Learning objectives

## Purpose and mental model

A mutex protects shared state only when every relevant reader and writer follows the same locking protocol. A condition variable lets a thread wait for a state predicate to become true while releasing the mutex atomically during the wait. Notifications are not stored as durable messages, and waking does not prove the predicate is true. Always recheck it in a loop to handle spurious wakeups and other consumers. Change the predicate under the same mutex used by waiters. Keep lock ownership and destruction explicit, and do not destroy a mutex or condition variable while another thread can still use it.

## Vocabulary and concepts

- **Predicate:** The shared-state condition a waiting thread actually needs.
- **Condition variable:** A mechanism for waiting while atomically releasing and reacquiring a mutex.
- **Spurious wakeup:** A return from waiting that still requires predicate rechecking.

## Syntax anatomy and execution trace

pthread_mutex_lock and unlock delimit the protected region. pthread_cond_wait expects the mutex to be locked, releases it while waiting, and reacquires it before returning. while(!ready) wait is the correct shape for this fixture. Signal after updating the protected state. Join the worker before destroying synchronization objects. A sleep cannot replace the predicate protocol.

## Worked example / walkthrough

### Worked example 1: Protect a shared count

Run four threads doing one hundred locked increments each.

```c
#include <assert.h>
#include <limits.h>
#include <pthread.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct CounterState {
  pthread_mutex_t mutex;
  int count, iterations;
};
void *increment_worker(void *argument) {
  struct CounterState *s = argument;
  for (int i = 0; i < s->iterations; i++) {
    CHECK(pthread_mutex_lock(&s->mutex) == 0);
    s->count++;
    CHECK(pthread_mutex_unlock(&s->mutex) == 0);
  }
  return NULL;
}
int locked_total(size_t workers, int iterations) {
  CHECK(workers <= 5);
  struct CounterState s = {.count = 0, .iterations = iterations};
  CHECK(pthread_mutex_init(&s.mutex, NULL) == 0);
  pthread_t threads[5];
  for (size_t i = 0; i < workers; i++)
    CHECK(pthread_create(&threads[i], NULL, increment_worker, &s) == 0);
  for (size_t i = 0; i < workers; i++)
    CHECK(pthread_join(threads[i], NULL) == 0);
  int result = s.count;
  CHECK(pthread_mutex_destroy(&s.mutex) == 0);
  return result;
}
struct ReadyState {
  pthread_mutex_t mutex;
  pthread_cond_t condition;
  bool ready;
  int value;
};
void *publish_worker(void *argument) {
  struct ReadyState *s = argument;
  CHECK(pthread_mutex_lock(&s->mutex) == 0);
  s->value = 42;
  s->ready = true;
  CHECK(pthread_cond_signal(&s->condition) == 0);
  CHECK(pthread_mutex_unlock(&s->mutex) == 0);
  return NULL;
}
int wait_for_value(void) {
  struct ReadyState s = {.ready = false, .value = 0};
  CHECK(pthread_mutex_init(&s.mutex, NULL) == 0);
  CHECK(pthread_cond_init(&s.condition, NULL) == 0);
  pthread_t worker;
  CHECK(pthread_create(&worker, NULL, publish_worker, &s) == 0);
  CHECK(pthread_mutex_lock(&s.mutex) == 0);
  while (!s.ready)
    CHECK(pthread_cond_wait(&s.condition, &s.mutex) == 0);
  int result = s.value;
  CHECK(pthread_mutex_unlock(&s.mutex) == 0);
  CHECK(pthread_join(worker, NULL) == 0);
  CHECK(pthread_cond_destroy(&s.condition) == 0);
  CHECK(pthread_mutex_destroy(&s.mutex) == 0);
  return result;
}

int main(void) {
  /* Protect a shared count */
  {
    CHECK(locked_total(4, 100) == 400);
  }
  puts("Worked example checks passed.");
  return 0;
}

```

**Observe:** The final count is 400.

Every increment is inside the same critical section, and the parent joins all writers before reading the final value.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
