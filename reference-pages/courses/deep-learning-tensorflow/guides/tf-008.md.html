tf-008: one gradient step you can audit#

Level and prerequisites#

Beginner within the TensorFlow track; estimated time: 120 minutes, split across sessions if useful. Direct prerequisite: tf-007, which includes the preceding loss, derivative and shape units. The active entry foundation is python-16. You need arrays, a mean, a scalar derivative and the meaning of a fresh Python process. Keras training APIs, GPU tools and model downloads are not prerequisites.

Learning objectives#

After this lesson, you can derive and inspect a scalar loss, its gradient and the resulting update; explain why a constant input still permits a gradient with respect to a Variable; distinguish a missing gradient from a zero one; and detect a wrong target shape even when the initial loss looks correct. You will also state why this arithmetic check is not evidence that a model will generalize.

Why one small update matters#

A training loop is a sequence of state transitions. At the old weight, a forward computation produces predictions and a loss. A gradient describes how that old loss changes when the weight changes. An optimizer applies an update; a new forward computation is needed to observe the new loss. Treating these as separate events makes a silent bug inspectable.

Use three fixed observations, x=[1,2,3] and y=[2,4,6], and the hypothesis prediction=w*x. The intended slope is visibly 2, but the experiment begins at 0. The target values are supplied labels, not values that an optimizer may change. There is no bias in the first model, no shuffle, no stochastic layer and no held-out-quality claim. A deliberately tiny example gives us a second way to check the framework's answer.

Vocabulary and concepts#

A tensor is an array with a shape and a dtype. Here x and y are vectors of shape (3,); each position refers to the same observation in both vectors. A Variable is mutable TensorFlow state. The scalar w is the only state the first experiment updates. Float64 is the numeric dtype chosen to make a tight arithmetic comparison reasonable on CPU; it is not a requirement for all later models.

A residual is prediction minus target. Mean squared error, or MSE, sums the squared residuals and divides by the number of observations. If a target has physical units, this loss has squared target units. A gradient is the local sensitivity of loss to a parameter. A learning rate multiplies that sensitivity before an update; it is not itself a gradient or a guarantee of improvement.

GradientTape records operations executed within its context. By default it watches trainable Variables such as w. It does not need to make x trainable to compute a gradient with respect to w. A disconnected result can produce None: there was no recorded path. A connected function at a flat point can produce a numeric zero. Those observations require different diagnoses.

Gradient: a derivative with respect to a chosen parameter, evaluated at its current value; it is a local sensitivity, not an updated parameter.

Tape: the recording scope that connects the loss calculation to watched Variables; a later scope cannot recover operations already performed.

Pairing: the agreement that prediction row i and target row i refer to the same observation; equal scalar losses do not prove this agreement.

Syntax anatomy#

with tf.GradientTape() as tape: defines the recording region. Put the forward prediction and loss calculation inside it. tape.gradient(loss, w) asks for the derivative with respect to that exact Variable after recording finishes. The ordinary tape is consumed by this gradient query; use a fresh tape and forward calculation for a new training step.

w.assign_sub(learning_rate * gradient) changes the Variable by subtracting a scaled gradient. Python w = ... would instead rebind a Python name and is a different operation. tf.reduce_mean(...) chooses the denominator. The square is elementwise, not a matrix multiplication. The exact matching vector shapes are part of the paired-record contract, not a cosmetic formatting choice.

Derive when this learning rate contracts the error#

For this three-point model, L(w)=143(w−2)2L(w)=\frac{14}{3}(w-2)^2L(w)=314​(w−2)2 and its derivative is L′(w)=283(w−2)L'(w)=\frac{28}{3}(w-2)L′(w)=328​(w−2). Write the parameter error as e=w−2e=w-2e=w−2. One gradient update with learning rate η\etaη gives enext=(1−28η3)ee_{\mathrm{next}}=\left(1-\frac{28\eta}{3}\right)eenext​=(1−328η​)e. Repeated updates contract this scalar error precisely when the absolute value of that multiplier is less than one, giving 0<η<3140<\eta<\frac{3}{14}0<η<143​.

At η=0.1\eta=0.1η=0.1, the multiplier is 115\frac{1}{15}151​, so the squared-loss ratio is 1225\frac{1}{225}2251​. At η=0.25\eta=0.25η=0.25, the multiplier is −43\frac{-4}{3}3−4​: the update crosses the optimum and increases squared error by 169\frac{16}{9}916​. This derives the larger-step failure in the exercise from the objective instead of treating it as mysterious optimizer behavior. A multiplier between -1 and zero would cross the optimum while still contracting the error.

This bound belongs to this scalar quadratic and its chosen loss reduction. Changing feature scale, adding a bias, changing from mean to sum, or using a nonlinear network changes the curvature and may change the useful update range. The derivation gives a method of reasoning about one transparent problem, not a universal learning-rate prescription.

Example A: derive the result, then ask the tape#

At w=0, the residuals are [-2,-4,-6]. Their squares sum to 56, so the mean loss is 56/3. Differentiating each square gives 2*x*(w*x-y). At zero, their mean is -56/3. With learning rate 1/10, subtraction moves the weight to 28/15. The new residuals are [-2/15,-4/15,-6/15], giving a new mean loss of 56/675. The sign has a concrete interpretation: increasing a weight that is below 2 reduces the loss locally.

import math
import tensorflow as tf

# A CPU-only arithmetic experiment, not a model-quality benchmark.
with tf.device("/CPU:0"):
    x = tf.constant([1.0, 2.0, 3.0], dtype=tf.float64)
    y = tf.constant([2.0, 4.0, 6.0], dtype=tf.float64)
    w = tf.Variable(0.0, dtype=tf.float64)
    learning_rate = tf.constant(0.1, dtype=tf.float64)

    with tf.GradientTape() as tape:
        prediction = w * x
        loss = tf.reduce_mean(tf.square(prediction - y))
    gradient = tape.gradient(loss, w)
    if gradient is None:
        raise ValueError("The loss is disconnected from w")
    before = float(loss.numpy())
    grad = float(gradient.numpy())
    w.assign_sub(learning_rate * gradient)
    after = float(tf.reduce_mean(tf.square(w * x - y)).numpy())

assert math.isclose(before, 56 / 3, rel_tol=0, abs_tol=1e-12)
assert math.isclose(grad, -56 / 3, rel_tol=0, abs_tol=1e-12)
assert math.isclose(float(w.numpy()), 28 / 15, rel_tol=0, abs_tol=1e-12)
assert math.isclose(after, 56 / 675, rel_tol=0, abs_tol=1e-12)
print(
    {"loss_before": before, "gradient": grad, "weight_after": float(w.numpy()), "loss_after": after}
)

Expected: old loss approximately 18.666666666666668, gradient approximately -18.666666666666668, new weight approximately 1.8666666666666667, and new loss approximately 0.08296296296296296. Floating-point text may differ in its last digits. The four absolute-tolerance assertions, rather than the printed formatting, are the checks.

Running the whole file starts again from zero. Running only the assignment line twice would reuse a stale gradient; it is not two correctly computed training steps.

Example B: a shape bug with a plausible scalar loss#

A column target has shape (3,1). Subtracting it from a vector prediction of shape (3,) creates all nine combinations, with shape (3,3). At zero every prediction is zero, so this incorrect objective accidentally has the same initial MSE. Its gradient exposes the changed pairing.

import math
import tensorflow as tf

with tf.device("/CPU:0"):
    x = tf.constant([1.0, 2.0, 3.0], dtype=tf.float64)
    y_column = tf.constant([[2.0], [4.0], [6.0]], dtype=tf.float64)
    bad_w = tf.Variable(0.0, dtype=tf.float64)
    with tf.GradientTape() as tape:
        residual_grid = bad_w * x - y_column
        bad_loss = tf.reduce_mean(tf.square(residual_grid))
    bad_gradient = tape.gradient(bad_loss, bad_w)

assert tuple(residual_grid.shape) == (3, 3)
assert math.isclose(float(bad_loss.numpy()), 56 / 3, rel_tol=0, abs_tol=1e-12)
assert math.isclose(float(bad_gradient.numpy()), -16.0, rel_tol=0, abs_tol=1e-12)
print(residual_grid.shape, float(bad_gradient.numpy()))

Expected: (3, 3) and -16.0. The intended gradient is -56/3, so a matching initial loss was insufficient evidence. The wrong objective uses averages over all input/target combinations instead of paired observations. An appropriate first repair is an explicit equal-vector-shape contract, before optimization.

  1. Reject a broken pairing. Write an eager helper that accepts only equal, nonempty vector shapes for x and y. It should reject the column target from Example B before calculating an MSE.   1. Diagnose missing versus zero. Compute prediction=w*x outside a tape, then use that precomputed tensor inside a new tape's loss. Inspect the gradient at w=0. Repair the recording boundary and separately test w=2. Expected: disconnected gradient is None; repaired gradient at zero is -56/3; the connected gradient at two is numeric zero. Expected: initial gradients are -68/3 and -10; new weight 34/15, new bias 1, training MSE 224/675; held-out prediction 151/15 and squared error 256/225. Common pitfalls#

If the gradient is None, inspect the first point at which a Variable-dependent calculation happened outside the tape or became a NumPy/Python value. If the loss agrees but the gradient does not, inspect the residual shape and target pairing before changing the optimizer. If the loss increases, verify update sign and rate independently; a correct derivative permits an overly large step. If a second step looks identical, inspect whether the gradient was recomputed rather than cached.

If an integer Variable yields an unsupported or absent derivative, identify the dtype rather than treating the framework as numerically unreliable. If a CPU import is slow, record the actual runtime boundary; do not infer that a GPU is necessary for three numbers. Preserve a failing transcript and the smallest case before trying a repair.

Progressive hints#

Ask for these one at a time, only after an attempt:

  • Hint 1: write the residual for each paired observation at the current weight. Check the vector shape before taking a mean.
  • Hint 2: the derivative of a squared residual includes its input x and the same observation denominator as the loss. Trace the Variable through every recorded operation.
  • Hint 3: update means subtracting a scaled gradient, then doing a new forward pass. For the second step, the old gradient no longer describes the new state.
