# clp-004: Constraints and density transformations

Tutorial mode. Stage: beginner. Direct prerequisites: `clp-003`, `bayes-004`.

## Two different meanings of transformation

Statistical code uses transformations for at least two reasons. We can represent a constrained parameter through an unconstrained optimization coordinate, or we can describe a transformed random variable. Only the second operation automatically changes the probability density with respect to the observation's measurement scale. Confusing these operations produces an objective that optimizes successfully but estimates the wrong model.

For a positive standard deviation, write \(\sigma=\exp(s)\), with real-valued optimizer coordinate \(s\). The likelihood for the original observations becomes \(L(\exp(s);y)\). Since this is the same likelihood evaluated at another parameter coordinate, there is no additional Jacobian term. AD already applies the chain rule to derivatives with respect to \(s\).

By contrast, if \(Z=\log X\) is Normal and observations are recorded as positive \(X\), the density with respect to \(dx\) is

\[
p_X(x)=p_Z(\log x)\left|\frac{d\log x}{dx}\right|
       =\frac{p_Z(\log x)}{x},\quad x>0.
\]

Consequently \(\log p_X(x)=\log p_Z(\log x)-\log x\). This is the change-of-variable formula for an observed random variable, not a correction for selecting a convenient optimizer coordinate.

## Worked case 1: estimating a positive scale

For fixed residuals \(r=(-1,1)\), the Normal NLL in log-scale coordinates is

\[
\mathcal L(s)=ns+\frac12e^{-2s}\sum_i r_i^2+\frac n2\log(2\pi).
\]

Its derivative is \(n-e^{-2s}\sum_i r_i^2\), which vanishes at \(s=0\), or \(\sigma=1\). The program checks that AD gives zero at this known optimum. It then deliberately adds the wrong term \(-s\), as if the parameter coordinate change required a density Jacobian. The derivative becomes -1 at the actual MLE, exposing a changed estimator.

A Bayesian density over \(\sigma\) is a separate situation. If a prior density \(p_\sigma(\sigma)\) is represented as a density over \(s=\log\sigma\), then \(p_s(s)=p_\sigma(e^s)e^s\). That Jacobian belongs to the parameter-density transformation. Moreover, posterior modes depend on parameterization, so maximizing a density in one coordinate system and transforming its mode is not generally equivalent to maximizing the transformed density. State whether you seek an MLE, a MAP in a declared coordinate, or samples from a posterior.

## Worked case 2: a lognormal observation density

The code evaluates lognormal observations using the explicit Normal-on-log-scale expression and compares with Torch's `LogNormal.log_prob`. It also integrates the resulting density numerically on a broad positive grid obtained by exponentiating an evenly spaced log grid. The trapezoidal integration is performed over the actual positive \(x\) values, yielding a value close to one. This catches an omitted \(1/x\) factor in a way that derivative-only tests would not.

Integration over a finite grid is an approximation. The tolerance reflects truncation and discretization, not an exact proof that every possible parameter value is normalized. The formula is the proof; this independent numerical check helps catch coding mistakes in the formula's implementation. Positive observations are required. A zero caused by a detection limit needs a censoring model, not an arbitrary small replacement before taking logs.

## Correlation coordinates and numerical limits

A stationary AR(1) correlation can be represented as \(\rho=\tanh(r)\). Its derivative is \(1-\rho^2\), checked in the program. Near \(|\rho|=1\), that derivative becomes small, and the covariance matrix may become poorly conditioned. A bounded transform prevents an invalid mathematical domain but does not guarantee good optimization or precise inference.

Similarly, exponentiation can overflow at large positive coordinates or underflow at very negative ones. Center predictors, select plausible initial scales and diagnose nonfinite objectives rather than silently clipping parameters and pretending the clipped function is the original likelihood. A softplus scale can be useful, but a chosen positive floor changes the allowed model and must be stated.

## Answered review questions

**Does every transformation need a Jacobian?** No. Ask which density is being expressed with respect to which random variable. Reparameterizing an ordinary likelihood's unknown parameter needs chain-rule derivatives but no likelihood Jacobian.

**Does fitting log outcomes estimate the mean on the original scale?** Not directly. For a lognormal model, \(E[X]=\exp(\mu+\sigma^2/2)\), whereas \(\exp(\mu)\) is the median. Chapter 17 separates these prediction targets.

**Can a transform cure weak identification?** It can improve numerical geometry, but it cannot create information absent from the data. A flat likelihood remains scientifically weak even when a transformed optimizer returns finite numbers.

```python
"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json
import math

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def scale_objective(log_sigma, residuals, *, false_parameter_jacobian=False):
    sigma = torch.exp(log_sigma)
    loss = (
        log_sigma + 0.5 * math.log(2 * math.pi) + residuals.square() / (2 * sigma.square())
    ).sum()
    return loss - log_sigma if false_parameter_jacobian else loss


def lognormal_log_density(x, mu, sigma):
    if bool((x <= 0).any()):
        raise ValueError("A lognormal observation must be positive")
    return torch.distributions.Normal(mu, sigma).log_prob(torch.log(x)) - torch.log(x)


def run_cases():
    residuals = tensor([-1, 1])
    s = tensor(0.0).requires_grad_()
    correct = torch.autograd.grad(scale_objective(s, residuals), s)[0]
    incorrect = torch.autograd.grad(
        scale_objective(s, residuals, false_parameter_jacobian=True), s
    )[0]
    assert float(correct) == 0 and float(incorrect) == -1
    x, mu, sigma = tensor([0.5, 2, 3]), tensor(0.3), tensor(0.7)
    manual = lognormal_log_density(x, mu, sigma)
    library = torch.distributions.LogNormal(mu, sigma).log_prob(x)
    assert torch.allclose(manual, library, atol=1e-12, rtol=0)
    grid = torch.exp(torch.linspace(-7, 7, 6001, dtype=DTYPE))
    integral = torch.trapezoid(torch.exp(lognormal_log_density(grid, mu, sigma)), grid)
    assert abs(float(integral) - 1) < 1e-5
    raw_rho = tensor(1.2).requires_grad_()
    rho = torch.tanh(raw_rho)
    dr = torch.autograd.grad(rho, raw_rho)[0]
    assert -1 < float(rho.detach()) < 1
    assert abs(float(dr) - (1 - float(rho.detach()) ** 2)) < 1e-12
    return {
        "correct_scale_gradient_at_mle": float(correct),
        "false_jacobian_gradient": float(incorrect),
        "lognormal_density_integral": float(integral),
        "rho": float(rho.detach()),
        "density_jacobian_needed_only_for_random_variable_change": True,
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
```
