Purpose and mental model#

Build a model whose entire memory fits on the page#

Before introducing neural weights, we can build a language model by counting what follows what. The vocabulary in this lesson contains A, B and C. Each symbol gets a row describing the next-symbol choices after it. This makes the model a small conditional-probability machine: look up the last symbol, read its row and use that distribution to score or choose the next symbol.

Walk through the two training sequences without joining them. The first, [A,B,A], contributes A to B and B to A. The second, [A,A], contributes A to A. There are three observed transitions in total. A's row therefore records one A, one B and no C; B's row records one A; C's row records nothing. The table is the model's learned state. Fitting means constructing it from the training records, while inference means consulting it without changing it.

A raw frequency model would give C zero probability after A. That is a strong conclusion from only two observations. Add-one smoothing changes the assumption: before normalization, place one pseudo-observation on every possible continuation. A's three masses become [2,2,1], with total five, and its probabilities become [0.4,0.4,0.2]. The pseudo-observations are a declared estimation rule, not additional training examples that were actually collected. They prevent a missing event in a small sample from automatically becoming an impossible event in the model.

The row shape clarifies an important compatibility requirement. A three-column table means the candidates are the three vocabulary entries in their frozen order. Adding a fourth candidate changes not only the new column but also the smoothing denominator of every existing row. Reordering columns changes which token each number represents. A saved matrix without its vocabulary mapping is therefore not a complete language model. The tokenizer and embedding lessons will revisit the same identity problem in neural form.

What information does the model retain? Only the immediately preceding token. Prefixes [C,A] and [B,B,A] both end in A, so both receive the same next-token row [0.4,0.4,0.2]. If the correct continuation depends on the earlier part of the prefix, this model cannot express that distinction no matter how carefully its counts are implemented. This is a representational limitation, separate from a coding error or lack of training observations. Longer-context models enlarge the set of distinctions that can influence a prediction.

The baseline remains useful because its failure modes are transparent. It can catch accidental boundary transitions, scoring mismatches or a neural training loop that is not improving beyond local frequency information. It is also inexpensive to fit and inspect. Its simplicity is not a reason to declare its held-out score invalid; the comparison becomes informative when both baseline and neural model predict the same target events. What would be invalid is changing the vocabulary, observation set or metric between them and calling the difference an architectural improvement.

What the count table assumes, and what smoothing changes#

Let C_uv count how often context token u is followed by candidate v within the training documents, and let Cu=∑vCuvC_u=\sum_v C_{uv}Cu​=∑v​Cuv​. The unsmoothed estimate is CuvCu\frac{C_{uv}}{C_{u}}Cu​Cuv​​ when C_u is positive. A bigram model uses one preceding token, so two long prefixes ending in the same u receive the same next-token distribution. This deliberately discards information before u. A transparent weak baseline is valuable precisely because its limitations are visible and its likelihood can be independently reconstructed.

With vocabulary size V and a positive smoothing coefficient alpha, the additive estimate is (C_uv+alpha)/(C_u+alpha V). The lesson uses α=1\alpha=1α=1. The denominator must include alpha once per candidate, not merely once for the whole row. For context A, counts [1,1,0] and V=3V=3V=3 yield [2,2,1]5\frac{[2,2,1]}{5}5[2,2,1]​. Dividing by Cu+1=3C_{u}+1=3Cu​+1=3 would make the row sum5/3, which is not a probability distribution. For B, [1,0,0] becomes [2,1,1]4\frac{[2,1,1]}{4}4[2,1,1]​. For C, the zero row becomes uniform [1,1,1]3\frac{[1,1,1]}{3}3[1,1,1]​.

When Cu>0C_{u}>0Cu​>0, rewrite the estimate as a mixture: [C_u/(C_u+alpha V)] times the empirical row plus [alpha V/(C_u+alpha V)] times the uniform row. This makes the tradeoff concrete: with only two observed transitions, three pseudo-counts have substantial influence. A huge vocabulary with α=1\alpha=1α=1 can dominate sparse observations. More smoothing avoids zero assigned probability but can flatten real preferences; tune the policy using designated validation data, then freeze it before final evaluation.

The zero-count context and an unknown context string are distinct situations. C is inside the declared vocabulary but has no observed outgoing transition. A token outside [A,B,C] has no allocated row. The reference explicitly chooses a uniform known-candidate fallback for an unseen scoring context. That is an application policy, not an inference that all continuations of an arbitrary new symbol are equally plausible. Unknown training tokens are rejected so fitting cannot silently change the candidate domain. A richer system could reserve an UNK ID, but it would need an explicit mapping and a corresponding count row/column.

Document boundaries determine which observations exist. The sequences [A,B,A] and [A,A] contain two and one transitions, for three total. Concatenating them would introduce an extra A→A transition across the boundary, incorrectly changing A's row to [2,1,0]. Its smoothed distribution would become [3,2,1]6\frac{[3,2,1]}{6}6[3,2,1]​ instead of [2,2,1]5\frac{[2,2,1]}{5}5[2,2,1]​. The arithmetic would still normalize, so a row-sum test would miss the semantic defect. Counting the expected number of transitions, ∑dmax⁡(lengthd−1,0)\sum_d\max(\mathrm{length}_d-1,0)∑d​max(lengthd​−1,0), supplies an independent boundary oracle.

This baseline does not model a start distribution or stopping probability unless BOS/EOS are explicitly added. It scores transitions conditioned on each document's supplied first token. Scoring the transition path A→B→A gives 0.4⋅0.5=0.20.4\cdot 0.5=0.20.4⋅0.5=0.2, with total loss log 5 over two targets. Calling that the unconditional probability of the complete string A,B,A would omit the start and termination contracts. State exactly what is conditioned on when comparing it with a neural next-token model.

Fit-on-train-only covers more than the count values. It includes vocabulary selection, normalization, document segmentation, smoothing selection and any fallback policy learned from data. Merely freezing the final count matrix after examining validation failures does not undo that information use. Compare systems using the same held-out target events and compatible representations. If the neural model beats this baseline, that establishes improvement on the measured score and split; it does not independently prove grounded answering or reasoning.

Interview reasoning: "Why keep a model we know ignores long context?" It provides a cheap reproducible floor, exposes dataset and scoring mistakes, and shows whether a more expensive model captures useful structure beyond local frequencies. If a complex model fails to beat it, inspect training, leakage and evaluation alignment before adding architectural complexity.

Vocabulary and concepts#

Bigram: an ordered pair of neighboring tokens inside one sequence.

Context row: the counts or probabilities for next-token candidates after one preceding token.

Vocabulary: the fixed candidate set and its order; it is frozen before evaluation.

Add-one smoothing: adding one pseudo-count to every vocabulary candidate before normalization.

Fallback: the declared behavior for a context without training observations, rather than an undocumented default.

Syntax or reasoning anatomy#

A count matrix has one context row and one next-token column, both ordered by the vocabulary. For A, counts [1,1,0] become smoothed masses [2,2,1], whose denominator is five. For B, [1,0,0] becomes [2,1,1], denominator four. A context with no observations receives [1,1,1], denominator three.

Count transitions by zipping each sequence with its one-position suffix. This creates no pair after the final token and no pair across documents. A dictionary maps token strings to fixed row/column indices. Reject unknown training tokens instead of silently changing the declared vocabulary. For an unseen scoring context, the reference explicitly chooses a uniform known-vocabulary fallback; it does not pretend that this estimates a rich semantic relationship.

Example A: Recover smoothed rows#

Read the three raw rows before adding pseudo-counts.

import numpy as np

counts = np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=np.int64)
mass = counts + 1
probabilities = mass / mass.sum(axis=1, keepdims=True)
np.testing.assert_allclose(probabilities[0], [2 / 5, 2 / 5, 1 / 5], rtol=0, atol=1e-12)
np.testing.assert_allclose(probabilities.sum(axis=1), 1.0, rtol=0, atol=1e-12)
print(probabilities)

Expected: Each row sums to one under the same three-candidate vocabulary. Smoothing changes the model; disclose it rather than labeling it raw frequency.

Example B: Do not invent a document-boundary transition#

Count two single-token documents independently and contrast concatenation.

documents = [["A"], ["B"]]
pairs = [pair for document in documents for pair in zip(document, document[1:])]
concatenated = ["A", "B"]
wrong_pairs = list(zip(concatenated, concatenated[1:]))
assert pairs == []
assert wrong_pairs == [("A", "B")]
print(pairs, wrong_pairs)

Progressive hints#

  • Hint 1: List pairs inside each sequence before adding them to a shared matrix.
  • Hint 2: Add one to every known candidate, including zero-count candidates, before summing the denominator.
  • Hint 3: Treat validation as a lookup-only path and compare the original table afterward.

Common pitfalls#

If validation text changes a probability, inspect whether the scoring path increments counts or adds vocabulary entries. If a boundary pair appears unexpectedly, print the per-document transition list before aggregating. If a row sums above or below one, inspect its smoothed denominator and candidate order.

Smoothing is not evidence that an unseen word or context is well modeled; it is a declared nonzero fallback over known candidates. A bigram model's limited context can be useful as a baseline while still missing long dependencies. A later transformer should be compared on the same frozen split and scoring units, not against a baseline accidentally deprived of preprocessing information that the neural model received.
