# viz-001: Data, traces and honest visual encodings

## Level and prerequisites

Beginner. Direct prerequisites: `python-16`. JavaScript readers should also review `js-005` and `js-029` for arrays and the browser DOM; they are language bridges rather than additional prerequisites for the Python route.

## Learning objectives and environment

Build a chart whose records, labels, units and table agree. The canonical Python pad uses prepared Plotly and `fig.show()`, which the classroom captures as a bounded interactive figure. The JavaScript variant uses the browser preview's `window.Plotly`, `#chart` and `#output`. Node is not the browser host. Neither variant imports a CDN, fetches data, starts a server or needs a Plotly account.

## Mental model and vocabulary

A record is one measured entity. A trace is a collection of marks with a shared encoding, such as bars whose heights represent elapsed hours. Layout describes axes, titles and other content; configuration describes display behavior such as responsiveness. A figure is a serializable specification that a renderer turns into pixels and interactive elements. Valid JSON can still describe a scientifically misleading chart.

Use the records (u1,Alpha,2), (u2,Beta,5), (u3,Gamma,3). The unit is elapsed hours per team record. This is not a sample-size-weighted mean, a confidence interval or a causal comparison.

## Worked case: preserve identity while sorting

Sort whole records by value, giving Beta,Gamma,Alpha and heights 5,3,2. Keep IDs in `customdata` so hover text can identify the same record after sorting. Sorting labels and values independently would produce a plausible chart with incorrect associations.

```python
ordered = sorted(records, key=lambda row: row[2], reverse=True)
fig = go.Figure(go.Bar(x=[r[1] for r in ordered], y=[r[2] for r in ordered]))
```

In JavaScript, copy before sorting with `[...records].sort(...)`; otherwise `sort` mutates the original array. `Plotly.newPlot` returns a promise. Wait for completion before checking rendered SVG or announcing the completion marker.

## Contrasting case: a truncated baseline

Starting a bar chart's y axis at 1.9 makes two hours look almost negligible beside five, exaggerating the encoded length ratio. A zero baseline preserves the intended length comparison. A point chart can use a restricted axis for a different task if the axis and purpose are explicit. No single axis rule applies to every chart type.

The full reference adds an axis unit, readable values, a caption, native table in JavaScript and structured table metadata in Python. Text and table provide exact values without relying on color or hover access.

## Six progressive exercises

1. **Trace identity.** Write the sorted IDs, labels and values together. Expected evidence: u2/Beta/5 stays one record, total ten. Hint: sort tuples or objects, not separate columns.
2. **Build the figure.** Add a three-bar trace, hours axis and descriptive title. Expected evidence: three marks, correct unit and zero baseline. Hint: data arrays live in the trace; titles live in layout.
3. **Change the measurement.** Replace Gamma's value three with four and update the table. Expected evidence: total eleven and unchanged record identity. Hint: derive both chart and table from one record collection.
4. **Diagnose a mismatch.** Deliberately alphabetize only the labels. Explain the wrong mapping before repairing it. Expected evidence: the recovered label/value map matches the records. Hint: a visual resemblance test will not catch identity loss.
5. **Handle empty input.** Show a plain no-observations message and an empty table rather than inventing zero-valued teams. Expected evidence: no fabricated data marks. Hint: an absent observation is not a measured zero.
6. **Transfer the encoding.** Plot distances 1.5,2.0,2.5 kilometers with new IDs. Expected evidence: updated axis, hover unit, caption and table, with total six. Hint: change the measurement contract as well as the numbers.

## Diagnosis and interpretation

Inspect records first, trace arrays second, and rendered marks last. Wrong data can render perfectly. A missing `window.Plotly` means the prepared browser capability is unavailable; installing a package from learner code is not the remedy. A Python figure captured successfully proves this figure was produced, not that every interaction or accessibility requirement has been reviewed.
