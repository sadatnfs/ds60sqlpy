llm-011: Multiple heads, residuals and a decoder block#

Level and prerequisites#

Beginner; approximately 120 minutes. Direct prerequisites: llm-010. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Trace every dimension through a small decoder block and keep residual paths valid. The central investigation is concrete: Split a width 4 vector into two heads, rejoin it, apply a fixed feed-forward transformation and residual addition. The finish condition is Split/rejoin is an exact round trip; head width=2\mathrm{width}=2. Residual operands have the same shape, and every operation is tokenwise or causally masked. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Several views of the same permitted context#

One attention head produces one normalized mixture of the allowed values for each query. A second head can produce a different mixture because it uses different projected features. This makes multiple heads useful when several relationships matter at once. For example, a trained layer might use different numerical features to connect a token with an earlier subject or with nearby punctuation. That is a possible learned behavior, not a built-in assignment of one linguistic job to each head. The literal arrays here demonstrate the mechanism without making semantic claims about trained heads.

Let D be the total feature width, H the number of heads and d=DHd=\frac{D}{H} the width of each head in this simple layout. For T tokens, a [T,D] array is reorganized into [H,T,d]. Every head still has T token positions. Splitting heads does not give half the tokens to one head and half to another. It distributes feature coordinates while each head receives its own complete allowed context.

The smallest layout fixture uses two token rows [0,1,2,3] and [4,5,6,7]. With two heads, head zero receives [0,1] and [4,5], while head one receives [2,3] and [6,7]. Those memberships are the meaning of the reshape-plus-transpose sequence. Simply reshaping the head-major result back to two rows yields [0,1,4,5] and [2,3,6,7], which has the right final shape but the wrong token/feature membership. Undoing the transpose before the reshape restores the original array. Tracking distinctive values is more informative than inspecting shape alone.

Within each head, scores are normalized separately over allowed key positions. The output vectors are then concatenated along the feature axis. A learned output projection can mix information from those head-specific vectors into the next representation. Keeping D fixed while changing H does not automatically multiply the main projection parameter count by H, because each head becomes narrower. It can still change score-tensor storage and the kinds of separate mixtures the architecture can express. Later head-sharing designs change the key/value projections themselves and require different accounting.

The residual connection then combines an input x with a learned update F(x), producing x+F(x). It gives the block a direct route to preserve x when the update is zero. It does not promise that x always survives unchanged: an update equal to -x cancels it. This matters when explaining residuals as an optimization aid rather than a guarantee that information cannot be lost. The feed-forward sublayer applies learned nonlinear feature transformations to each token independently; attention supplies cross-token mixing, while this sublayer changes how features are represented at each position.

A decoder block becomes understandable when these responsibilities remain separate: rearrange features into heads, compute permitted mixtures, rejoin features correctly, combine a residual update and apply tokenwise nonlinear transformations. The chapter's exact-value tests isolate each responsibility before the later PyTorch decoder puts them into one trainable module.

Vocabulary and concepts#

Attention head: A separately normalized query/key/value computation over permitted token positions.

Head width: The feature dimension assigned to one head under a declared layout.

Concatenation: Joining head features while preserving each token row.

Residual addition: Adding a shape-compatible branch output back to its input.

Tokenwise feed-forward network: Shared nonlinear feature processing applied independently at each token.

Syntax anatomy and reasoning sequence#

Trace the split and inverse#

For X:[T,D] with T=2,D=4,H=2, the head width is d=DH=2d=\frac{D}{H}=2. Reshape [2,4] to [2,2,2] interpreted as [token,head,head_feature], then transpose to [head,token,head_feature]. These dimensions happen to have the same sizes, making axis names more informative than the printed shape alone.

With rows [0,1,2,3] and [4,5,6,7], head zero contains [[0,1],[4,5]], while head one contains [[2,3],[6,7]]. The inverse must first transpose [head,token,feature] back to [token,head,feature], then merge the last two axes. Flattening the head-major tensor directly instead creates rows [0,1,4,5] and [2,3,6,7]. Both arrays have shape [2,4], but the wrong version mixes features from different tokens.

Compute attention within each head#

The batched multiplication Q_h KhT{K_{h}}^{T} produces [H,T,T], one query-by-key matrix for each head. The normalization axis is the final key axis. For a width-two head the scale is 2\sqrt{2}, and a causal Boolean triangle [T,T] broadcasts across the head axis. Multiplying weights [H,T,T] by V [H,T,2] returns [H,T,2]. Rejoining produces [T,4], preserving the width needed by a residual path.

For the three-token identity-projection fixture, head zero contains [1,0],[0,1],[1,1], while head one contains [1,1],[1,0],[0,1]. At query row one, the causal mask permits keys zero and one. Head zero has scores [0,12][0,\frac{1}{\sqrt{2}}] and weights [11+a,a1+a][\frac{1}{1+a},\frac{a}{1+a}] with a=exp(12)a=\exp(\frac{1}{\sqrt{2}}). Head one has equal allowed scores [12,12][\frac{1}{\sqrt{2}},\frac{1}{\sqrt{2}}] and weights [12,12][\frac{1}{2},\frac{1}{2}]. Their mixtures are therefore approximately [0.33023845,0.66976155] and exactly [1,0.5]. Concatenation gives [0.33023845,0.66976155,1,0.5] before any learned output projection.

Residual and feed-forward equations#

A residual computes R(x)=x+F(x). If F(x)=2x, R(x)=3x and its Jacobian is 3I. If F(x)=0, the residual is the identity. If F(x)=-x, the sum is zero and the Jacobian is zero. Thus the identity contribution can improve the available path, but a residual connection is not a universal proof against vanishing, exploding or cancelled gradients.

A usual feed-forward branch has F(x_t)=activation(x_t W1+b1) W2+b2, using the same weights at every token t. W1 can expand the hidden feature width and W2 return it to D for residual addition. The teaching fixture chooses identity weights and b1=−2b_{1}=-2 so the first row [0,1,2,3] becomes [0,0,0,1]. This isolates nonlinearity and tokenwise independence. A pair of affine maps without a nonlinearity collapses to one affine map; adding width alone would not create that nonlinear behavior.

Why several heads can help, and what they do not guarantee#

A single head returns one normalized mixture of its value vectors for each query. Several heads can compute several mixtures before their results are combined. The output projection can then mix feature contributions across heads, rather than treating each head output as an isolated final answer. This expands the available computation, but it does not guarantee that every head learns a distinct useful role. Redundant or weak heads are possible, and interpreting one head as a particular linguistic relation requires evidence beyond an attractive attention plot.

At fixed model width D, the usual Q/K/V projections still contain about 3D squared weight entries and the output projection about D squared, regardless of how D is divided among heads. The per-head feature dimension becomes D/H, so total projected width remains D. Scores require H·T·TH\cdot T\cdot T entries if materialized for full self-attention. More heads can therefore change the attention-state layout and its storage even when projection parameter count remains fixed. The efficient attention chapter later distinguishes these algebraic dimensions from a specific GPU kernel's memory traffic.

Causal visibility is applied independently in every head. Rejoining does not repair a head that read the future. Conversely, a correct head mask does not repair a feed-forward operation that accidentally reduces over time or a normalization step with the wrong axes. A complete decoder's prefix test must include every branch. This chapter's identity projections and simple feed-forward weights make the mechanisms inspectable; the learned, normalized full decoder appears in llm-016.

An output projection must return a compatible width before residual addition. If a residual uses a different width, a learned projection on the skip path can make dimensions compatible, but that is no longer an unchanged identity skip. The original Transformer block and many later variants choose the model width consistently so the addition has a clear interpretation. The normalization and gated-block chapter develops pre/post normalization and SwiGLU; the head-sharing chapter distinguishes ordinary multi-head attention from MQA and GQA.

Worked example / walkthrough#

Example A: Split and rejoin#

Axis membership is the actual contract. Here every dimension has size two, so shape checks alone cannot distinguish a correct transpose from an incorrect one. Exact element placement supplies the missing evidence.

import numpy as np
def split_heads(values, heads):
    values = np.asarray(values)
    if values.ndim != 2 or min(values.shape) == 0:
        raise ValueError('nonempty token-by-feature input required')
    if type(heads) is not int or heads <= 0 or values.shape[1] % heads != 0:
        raise ValueError('positive head count must divide feature width')
    time, width = values.shape
    head_width = width // heads
    return values.reshape(time, heads, head_width).transpose(1, 0, 2)


def join_heads(values):
    values = np.asarray(values)
    if values.ndim != 3 or min(values.shape) == 0:
        raise ValueError('nonempty head-by-token-by-feature input required')
    heads, time, head_width = values.shape
    return values.transpose(1, 0, 2).reshape(time, heads * head_width)


def multihead(values, heads=2, causal=True):
    values = np.asarray(values, dtype=np.float64)
    if not np.isfinite(values).all():
        raise ValueError('finite values required')
    projected = split_heads(values, heads)
    head_width = projected.shape[-1]
    scores = projected @ projected.transpose(0, 2, 1) / np.sqrt(head_width)
    time = values.shape[0]
    allowed = np.tri(time, dtype=bool) if causal else np.ones((time, time), dtype=bool)
    masked = np.where(allowed[None, :, :], scores, -np.inf)
    mass = np.exp(masked - masked.max(axis=-1, keepdims=True))
    weights = mass / mass.sum(axis=-1, keepdims=True)
    head_outputs = weights @ projected
    return join_heads(head_outputs), weights


def tokenwise_feed_forward(values):
    values = np.asarray(values, dtype=np.float64)
    width = values.shape[-1]
    first_weight = np.eye(width)
    first_bias = np.full(width, -2.0)
    second_weight = np.eye(width)
    hidden = np.maximum(values @ first_weight + first_bias, 0)
    return hidden @ second_weight
values = np.arange(8).reshape(2, 4)
heads = split_heads(values, 2)
np.testing.assert_array_equal(heads[0], [[0, 1], [4, 5]])
np.testing.assert_array_equal(heads[1], [[2, 3], [6, 7]])
np.testing.assert_array_equal(join_heads(heads), values)
assert heads.shape == (2, 2, 2)

Expected: head zero is [[0,1],[4,5]], head one is [[2,3],[6,7]], and rejoining restores X exactly.

Example B: Test actual head mixtures and causal prefixes#

This check exercises real score normalization and value mixing, extending the earlier tokenwise-only prefix check. The analytic row-one expectation is an independent oracle for head identity and the softmax axis. Prefix equality then checks the visibility boundary.

for length in [1, 2, 3]:

Common pitfalls and diagnosis#

If a split/rejoin test passes shapes but fails values, write an index label for every element before reshaping. Check that token index remains the outer row after joining. A contiguous array can still have the wrong semantic axis order; contiguity alone is not a correctness test.

If two heads unexpectedly have identical weights, inspect their projected inputs and the fixture symmetry before assuming a bug. In this chapter the chosen row-one distributions intentionally differ and have a hand-derived oracle. In a learned model, identical or nearly identical heads may be a real outcome. If weights do not sum to one over allowed keys, inspect the softmax reduction axis and masking order.

If a causal prefix fails, recompute the full sequence of transformations on the prefix. Inspect each head's forbidden weights and any token-coupling operation outside attention. If a feed-forward prefix changes when a later row changes, inspect whether a reduction or matrix multiplication is accidentally using the time dimension. Finally, distinguish residual addition from concatenation and avoid claiming that a skip connection proves healthy gradients under every branch function.
