clp-003: Analytic, finite-difference and AD gradients#

Tutorial mode. Stage: beginner. Direct prerequisites: clp-002, torch-005.

Three routes to a derivative#

Automatic differentiation applies chain-rule operations to a recorded computation. It does not infer the intended statistical formula from variable names. A handwritten derivative can expose the wrong formula; a finite-difference derivative can expose a broken graph; and a distribution implementation can expose a missing normalization constant. Agreement between these independent routes is a much stronger starting point than a loss that merely decreases.

Reverse-mode differentiation is particularly useful when a scalar objective depends on many parameters. The forward computation creates intermediate quantities and the reverse computation propagates sensitivities back to parameters. The calculation differentiates the executed operations, including their current branches. It does not automatically differentiate through data-dependent discrete choices such as an argmax selection.

Debugging a broken graph#

detach, a NumPy round trip and rebuilding a tensor from Python scalar values can sever a derivative path. A program can still produce the correct forward objective while returning the wrong gradient. If you need a diagnostic number, convert a detached result only after constructing and differentiating the objective. Conversely, retaining every graph between optimizer iterations can consume unnecessary memory. Build a fresh objective on each iteration and retain higher-order graphs only when computing higher derivatives requires them.

Check derivatives away from nonsmooth points. A central difference at an absolute-value cusp averages two one-sided slopes, while AD follows its defined local rule. Their disagreement is then a mathematical boundary issue rather than necessarily an implementation bug. Also check several scientifically relevant parameter values: a derivative test at zero can miss entire terms whose local contribution vanishes.

Answered review questions#

Does AD estimate derivatives by perturbation? No. It composes derivatives of primitive operations along the executed graph, subject to floating-point arithmetic. Finite differences are a separate approximation used here as an audit.

Why not trust a falling loss? The wrong gradient can accidentally improve an objective, and an incorrect objective can be optimized very effectively. Test the probability formula, the gradient and the optimizer separately.

Does this prove a model will scale on Spark? No. It proves tiny local derivative arithmetic. A distributed implementation must additionally preserve complete independent units, parameter versions, reduction weights and retry behavior. Those are separate execution contracts.

"""Complete float64 CPU likelihood investigation with original synthetic data."""

from __future__ import annotations

import json
import math

import torch

DTYPE = torch.float64
torch.set_num_threads(1)


def tensor(values):
    return torch.as_tensor(values, dtype=DTYPE)


def normal_mean_nll(mu, y, sigma):
    mu, y, sigma = tensor(mu), tensor(y), tensor(sigma)
    if sigma.ndim != 0 or float(sigma) <= 0:
        raise ValueError("Use a positive known scale")
    return (
        torch.log(sigma) + 0.5 * math.log(2 * math.pi) + (y - mu).square() / (2 * sigma.square())
    ).sum()


def decay_nll(theta, time, y):
    mean = theta[0] * torch.exp(-theta[1] * time)
    return ((y - mean).square() / 2).sum()


def central_difference(function, theta, step):
    if not 0 < step < 1:
        raise ValueError("Use a positive small finite-difference step")
    basis = torch.eye(theta.numel(), dtype=DTYPE)
    return torch.stack(
        [
            (function(theta + step * row) - function(theta - step * row)) / (2 * step)
            for row in basis
        ]
    )


def run_cases():
    mu = tensor(0.3).requires_grad_()
    y = tensor([-1, 0.5, 2])
    loss = normal_mean_nll(mu, y, 1.5)
    derivative = torch.autograd.grad(loss, mu)[0]
    analytic = (mu.detach() - y).sum() / 1.5**2
    assert torch.allclose(derivative, analytic, atol=1e-12, rtol=0)
    theta = tensor([2.0, 0.7]).requires_grad_()
    time, observed = tensor([0, 1, 2]), tensor([1.9, 1.1, 0.4])

    def objective(value):
        return decay_nll(value, time, observed)

    ad = torch.autograd.grad(objective(theta), theta)[0]
    exponent = torch.exp(-theta.detach()[1] * time)
    residual = theta.detach()[0] * exponent - observed
    expected = torch.stack(
        [(residual * exponent).sum(), (residual * -theta.detach()[0] * time * exponent).sum()]
    )
    errors = {
        str(h): float((central_difference(objective, theta.detach(), h) - ad).abs().max())
        for h in (1e-3, 1e-5, 1e-7)
    }
    assert torch.allclose(ad, expected, atol=1e-12, rtol=0)
    assert min(errors.values()) < 1e-8
    return {
        "normal_mean_gradient": float(derivative),
        "nonlinear_gradient": ad.tolist(),
        "finite_difference_max_errors": errors,
        "precision": "float64",
    }


if __name__ == "__main__":
    print(json.dumps(run_cases(), sort_keys=True, allow_nan=False))
