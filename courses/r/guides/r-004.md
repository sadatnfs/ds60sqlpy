## Outcome and mechanism

Build explicit selection predicates and handle unknown values without turning them into false evidence.

Comparisons produce logical values. A vector such as amount >= 10 describes one predicate result per amount. Combining conditions with & or | works element by element. This is useful for constructing a row mask, but it differs from a single control-flow decision about the entire vector. The functions any and all reduce a logical vector to a question about at least one or every entry.

Missing data introduces an unknown truth value. NA > 10 is NA, not FALSE. TRUE | NA is TRUE because one known true branch suffices, while FALSE | NA stays unknown. Similarly FALSE & NA is FALSE, but TRUE & NA remains unknown. Treating all unknowns as false may be an intentional eligibility rule, but that rule should be expressed and explained.

Use is.na rather than x == NA to detect missingness. An ordinary equality comparison with NA cannot establish which values are missing. A complete numeric eligibility mask can combine !is.na(x) with x >= 10, retaining only known qualifying values. Keep the count of excluded unknowns available for reporting.

Scalar control flow uses a length-one condition. The short-circuit operators && and || evaluate their right-hand side only when needed; they are useful for a guard such as length(x) > 0 && x[[1]] > 0. They are not replacements for vector & and |. Confusing those roles can silently change a row selection into one scalar decision.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Logical vector | Values TRUE, FALSE or NA used to state predicates. |
| Elementwise conjunction | The & operation combining corresponding logical entries. |
| Short-circuit condition | The scalar && or || operation that can skip a second expression. |
| Unknown predicate | An NA comparison result whose truth is not established. |

## Read the syntax

Use parentheses to make a combined predicate readable. ! negates a logical value, & and | combine vectors, and any/all reduce them. isTRUE produces FALSE for an unknown scalar, so use it only when that explicit policy fits.

## Worked examples

### Example 1: Retain known qualifying observations

```r
amount <- c(5, 12, NA_real_, 20)
keep <- !is.na(amount) & amount >= 10
stopifnot(identical(keep, c(FALSE, TRUE, FALSE, TRUE)))
stopifnot(identical(amount[keep], c(12, 20)))
print(keep)
```

**Expected observation:** FALSE, TRUE, FALSE, TRUE.

The mask explicitly excludes missing amounts and separately tests the threshold. Unknown values are counted, not interpreted as measured failures.

### Example 2: Unknown truth and short-circuit guards

```r
stopifnot(isTRUE(TRUE | NA), identical(FALSE & NA, FALSE))
stopifnot(is.na(FALSE | NA), is.na(TRUE & NA))
x <- numeric(0)
first_positive <- length(x) > 0 && x[[1]] > 0
stopifnot(identical(first_positive, FALSE))
print(first_positive)
```

**Expected observation:** FALSE; no empty-vector extraction error.

The first condition prevents an invalid extraction from an empty vector. The truth-table checks explain when uncertainty does and does not affect the combined answer.
