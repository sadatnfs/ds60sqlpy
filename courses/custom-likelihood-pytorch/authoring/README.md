# Likelihood tutorial authoring

`units.json` defines the twenty stable teaching units; `chapters/` contains original prose and `programs/` contains complete independent CPU programs. `build.py` checks these inputs and emits the course guides, examples, metadata and README deterministically using the standard library. `--check` compares exact UTF-8 bytes. It does not run PyTorch or claim native acceptance. Each unit's `key_terms` object lists three to five lesson-specific terms with one- or two-sentence definitions; the builder validates them and renders a `## Key terms` section before the first worked case.

Every program exposes `run_cases()` with finite JSON evidence and a main block that prints it. Each guide embeds the exact program bytes after its mathematical and worked-case explanation. Change the durable program and chapter together, regenerate, and run tests/test_custom_likelihood_pytorch.py. Numerical tests require the prepared Torch environment and are distinct from source checks. No model or dataset download is allowed during a lesson.

Root integrates the track into the shared directory, compiles TeX and regenerates shared HTML after all authors freeze. Source manifests are emitted only after all twenty complete chapters/programs exist.

Each unit's `worked_examples` list holds one or more objects with `title`, `language`, `code`, an optional `output` and an `interpretation`. The code is a short snippet that was actually executed, `output` is its observed stdout copied verbatim, and the interpretation reads specific values from that output. The builder requires every field except `output` to be non-empty, rejects em and en dashes, requires titles, code and interpretations to be unique across the track, and requires at least two treatments per lesson counting the chapter's worked cases. It renders each entry as a `## Worked example:` section after the chapter prose and before the complete program. Rerun a snippet and update its `output` whenever its code changes; never edit output by hand. The snippets are NumPy and SciPy cross-checks of the likelihood mathematics, written so they run without PyTorch; they serve as independent oracles for the PyTorch programs, not as replacements.
