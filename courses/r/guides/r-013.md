## Outcome and mechanism

Explain captured configuration and lazy argument timing without relying on hidden global state.

A function's environment influences where it finds names not defined locally. R uses lexical scope: the search follows the function's enclosing environment rather than simply using the caller's local variables. A closure combines executable function code with this environment. That makes it possible to construct a reusable function with a private configured value.

A function factory returns another function. For example, a multiplier factory can bind one factor and return a function that multiplies future inputs by it. Creating two factories gives two separate enclosing environments, so a factor of two in one closure need not affect a factor of three in another. Avoid shared global assignments when ordinary captured configuration is enough.

R arguments are lazy promises. The argument expression is normally evaluated when the function first needs it, and its value is then retained. This can surprise a factory that returns before using an argument referring to a changing outer variable. force evaluates that argument during factory construction, making the capture time explicit.

Lazy evaluation is useful, but it is not a reason to hide time-dependent behavior. Decide whether a returned function should capture today's configuration or reevaluate an external object later. Test the chosen behavior by changing the caller's binding between construction and invocation. Keep mutation and lexical lookup separate: the existence of a closure does not mean every captured value should be updated with <<-.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Lexical scope | Name lookup through the environment where a function was created. |
| Closure | A function paired with its enclosing environment. |
| Promise | An argument expression evaluated when its value is needed. |
| Forced value | An argument evaluated deliberately before later use. |

## Read the syntax

A function can return function(x) ... directly. force(argument) evaluates its promise at that point. environment(fn) identifies the enclosing environment for inspection, but routine analytical code should expose a clear interface rather than editing it externally.

## Worked examples

### Example 1: Two independent configured closures

```r
make_multiplier <- function(factor) {
  force(factor)
  function(x) x * factor
}
double <- make_multiplier(2)
triple <- make_multiplier(3)
stopifnot(double(4) == 8, triple(4) == 12)
print(c(double = double(4), triple = triple(4)))
```

**Expected observation:** 8 and 12.

Each returned function retains its own configured factor. No global factor is needed at call time.

### Example 2: Capture time is observable

```r
lazy_factory <- function(factor) function(x) x * factor
fixed_factory <- function(factor) {
  force(factor); function(x) x * factor
}
rate <- 2
lazy <- lazy_factory(rate)
fixed <- fixed_factory(rate)
rate <- 5
stopifnot(lazy(3) == 15, fixed(3) == 6)
print(c(lazy = lazy(3), fixed = fixed(3)))
```

**Expected observation:** Lazy 15; fixed 6.

The unforced promise looks up rate on first use after the change. The forced closure retained the value two during construction.
