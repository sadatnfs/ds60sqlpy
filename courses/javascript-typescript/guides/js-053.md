# js-053: Grouped and stacked bars: totals, composition and denominators

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-052`.

## Learning objectives

Build stacked and grouped bar charts and keep totals, shares and denominators explicit. The central exercise is: Build a two-series stacked chart.

## Purpose, vocabulary and mental model

Grouped bars support comparison of categories within several groups using a shared baseline for each bar. Stacked bars emphasize totals and composition, but interior segments do not share a common baseline. The choice depends on whether the reader needs precise subgroup comparisons or an overview of parts and whole.

A stack layout computes interval endpoints for each series in each row. The rectangle represents the distance between the lower and upper endpoints, not the upper endpoint alone. A normalized stack transforms each row to shares, which can hide differences in total magnitude.

A zero total has no meaningful fraction composition unless a policy is stated. Missing components also differ from known zeros. Preserve the original totals alongside a 100% chart so the reader can see whether a large-looking share represents two observations or two million.

### Key terms

- **Stack layout:** The `d3.stack().keys(...)` layout that returns, for each series and row, a `[lower, upper]` pair of cumulative endpoints. A segment's height is the distance between the two endpoints.
- **Grouped bars:** Subgroup bars placed side by side within each group so every bar shares a common baseline for precise comparison.
- **Normalization:** Rescaling each row so its components sum to one, as `d3.stackOffsetExpand` does. It shows shares but hides differences in totals.
- **Denominator:** The total that a share is computed against. A zero total makes a composition undefined and requires an explicit policy.

## Syntax anatomy and mechanism

`d3.stack().keys(['a','b'])` reads the named components from each record and returns one series for each key. A point is `[lower, upper]` and retains its original row in `.data`. Use y(lower)-y(upper) for positive vertical height.

`stackOffsetExpand` normalizes each row to unit total when appropriate. Validate finite nonnegative components for this introductory positive stack. Signed values need a different design, such as a diverging stack with explicit positive and negative baselines.

## Worked example / walkthrough

### Worked example 1: Read stack endpoints

The second component begins where the first ends.

```javascript
const series = d3.stack().keys(["a", "b"])([{ group: "X", a: 2, b: 3 }]);
console.log(series[0][0].slice(), series[1][0].slice());
```

**Expected observation:** [0, 2] and [2, 5].

### Worked example 2: Compare counts and shares

The same share can represent very different totals, so the labels keep the counts visible.

```javascript
// js-053 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Grouped and stacked bars: totals, composition and denominators")
  .style("width", "100%")
  .style("max-width", "640px");
const rows = [
  { label: "small", a: 2, b: 3 },
  { label: "large", a: 20, b: 30 },
];
const shares = rows.map((d) => d.a / (d.a + d.b));
check(shares.join(",") === "0.4,0.4", "Both rows have the same share");
const x = d3.scaleLinear().domain([0, 1]).range([160, 600]);
svg
  .selectAll("rect")
  .data(rows)
  .join("rect")
  .attr("x", x(0))
  .attr("y", (d, i) => 80 + i * 120)
  .attr("height", 50)
  .attr("width", (d) => x(d.a / (d.a + d.b)) - x(0))
  .attr("fill", "#2563eb");
svg
  .selectAll("text")
  .data(rows)
  .join("text")
  .attr("x", 20)
  .attr("y", (d, i) => 112 + i * 120)
  .text((d) => `${d.label}: ${d.a} of ${d.a + d.b}`);
output.textContent = "js-053 worked example 2 complete";
```

**Expected observation:** Two equally long share bars, 40 percent each, whose labels show different totals: 2 of 5 and 20 of 50.

## Six progressive exercises

### Exercise 1: Predict the stack endpoints.

**Expected evidence:** First segment 0..2, second 2..5.

**Progressive hint:** Endpoints are cumulative positions.

### Exercise 2: Normalize two proportional rows.

**Expected evidence:** Both have 40% and 60% shares despite different totals.

**Progressive hint:** Normalization removes absolute scale.

### Exercise 3: Build a two-series stacked chart.

**Expected evidence:** Segment heights match component values and total heights match row sums.

**Progressive hint:** Check both component and total invariants.

### Exercise 4: Diagnose using upper endpoint as segment height.

**Expected evidence:** Later segments are exaggerated because the lower endpoint was ignored.

**Progressive hint:** Compute the interval length in scale coordinates.

### Exercise 5: Handle a zero-total group.

**Expected evidence:** Show an explicit no-composition state or documented zero representation.

**Progressive hint:** Dividing by zero does not produce an interpretable percentage.

### Exercise 6: Choose grouped or stacked bars for subgroup comparison.

**Expected evidence:** Use shared baselines when precise subgroup comparison is the primary task.

**Progressive hint:** A stack can still be useful for total composition, but the tradeoff should be explicit.

## Debugging and common mistakes

When later segments look too tall, check how height is computed. Each `d3.stack` point is a pair [y0, y1], so a segment's height is `y(y0) - y(y1)`, not `y(y1)`. Compare the top of each stack with its row total. With `stackOffsetExpand`, an all-zero group stays at 0 and draws no segments, so show that state explicitly. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose using upper endpoint as segment height. Distinguishing evidence: Later segments are exaggerated because the lower endpoint was ignored.

## Accessibility and interpretation

Interior segments are hard to compare, so label each segment with its series name and value or share, and include the row total. Do not rely on two colors alone to separate series; use direct labels or a text legend, and offer the table of component values. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

A share of 40 percent means little without its denominator: 2 of 5 and 20 of 50 look identical once normalized, so label totals beside normalized bars. Choose grouped bars when readers must compare one subgroup across groups, because only grouped bars give every subgroup a common baseline. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
