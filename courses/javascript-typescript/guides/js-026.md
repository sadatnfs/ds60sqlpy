# js-026: Classes, composition and private state

## Level and prerequisites

Advanced, approximately 120 minutes. Direct prerequisites: `js-025`

## Learning objectives

Design classes with private state, injected collaborators and invariants that reject invalid transitions.

By the end you can maintain balance through methods, inject a deterministic clock, reject invalid transitions without mutation, guard derived overflow, reject an incompatible collaborator, and distinguish private storage from a lookalike property.

## Purpose and mental model

Classes combine state with operations that preserve invariants. A typed number can still be negative, fractional, infinite or too large for exact integer arithmetic. A balance object therefore checks values before assigning new state. Constructor and method annotations document accepted checked calls, while runtime checks protect the actual numeric domain.

JavaScript #private fields enforce privacy at runtime. TypeScript private is primarily a checking restriction and should not be confused with a security boundary around ordinary emitted properties. Encapsulation is useful when callers should request an operation rather than directly assign arbitrary state. A getter returning a number supplies a value; a getter returning a mutable object would need a separate ownership policy.

Composition supplies a collaborator through a small interface, such as a clock. A test can provide a deterministic clock without changing global time or subclassing a large framework. The interface describes the capability required by the consumer. Inheritance is appropriate when substitutability is real, but reusing a few implementation lines does not prove that every subclass preserves its parent's contract.

## Vocabulary and concepts

**Encapsulation:** Restricting state changes to invariant-preserving operations.

**Private field:** A JavaScript # field with runtime-enforced access.

**Composition:** Building behavior from explicit collaborators.

**Interface:** A static capability contract for compatible values.

## Syntax anatomy and execution trace

A constructor establishes initial state. #balance names a runtime private field, while the cents getter exposes a primitive observation. implements would check an interface without generating methods. Constructor parameter properties create fields as part of TypeScript emission. A readonly dependency reference prevents reassignment through that class; it does not guarantee the collaborator itself is immutable. Validate derived results before committing a state transition.

## Worked example / walkthrough

### Example A: Maintain balance through methods

The public API exposes observations and controlled mutations. A caller cannot directly assign the private field by an ordinary property name.

```typescript
import { strict as assert } from 'node:assert';

function validCents(value: number): void {
  if (!Number.isSafeInteger(value) || value < 0)
    throw new RangeError('nonnegative safe integer cents required');
}
class Wallet {
  #balance: number;
  constructor(initial: number) {
    validCents(initial);
    this.#balance = initial;
  }
  get cents(): number {
    return this.#balance;
  }
  deposit(amount: number): void {
    validCents(amount);
    const next = this.#balance + amount;
    validCents(next);
    this.#balance = next;
  }
  withdraw(amount: number): void {
    validCents(amount);
    if (amount > this.#balance) throw new RangeError('insufficient balance');
    this.#balance -= amount;
  }
}
interface Clock {
  now(): Date;
}
class ReceiptService {
  constructor(private readonly clock: Clock) {}
  create(id: string): { id: string; createdAt: string } {
    if (id === '') throw new TypeError('id required');
    return { id, createdAt: this.clock.now().toISOString() };
  }
}

export async function verify(): Promise<{ checks: number; status: string }> {
  // Worked example
  {
    const wallet = new Wallet(100);
    wallet.deposit(50);
    wallet.withdraw(30);
    assert.equal(wallet.cents, 120);
    assert.equal(Object.hasOwn(wallet, 'balance'), false);
    assert.deepEqual(Object.keys(wallet), []);
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** balance 120; no enumerable balance field.
### Example B: Inject a deterministic clock

The time dependency is explicit and replaceable. The test does not mutate global time or rely on a fragile elapsed-time tolerance.

```typescript
import { strict as assert } from 'node:assert';

function validCents(value: number): void {
  if (!Number.isSafeInteger(value) || value < 0)
    throw new RangeError('nonnegative safe integer cents required');
}
class Wallet {
  #balance: number;
  constructor(initial: number) {
    validCents(initial);
    this.#balance = initial;
  }
  get cents(): number {
    return this.#balance;
  }
  deposit(amount: number): void {
    validCents(amount);
    const next = this.#balance + amount;
    validCents(next);
    this.#balance = next;
  }
  withdraw(amount: number): void {
    validCents(amount);
    if (amount > this.#balance) throw new RangeError('insufficient balance');
    this.#balance -= amount;
  }
}
interface Clock {
  now(): Date;
}
class ReceiptService {
  constructor(private readonly clock: Clock) {}
  create(id: string): { id: string; createdAt: string } {
    if (id === '') throw new TypeError('id required');
    return { id, createdAt: this.clock.now().toISOString() };
  }
}

export async function verify(): Promise<{ checks: number; status: string }> {
  // Worked example
  {
    const service = new ReceiptService({ now: () => new Date('2026-01-01T00:00:00.000Z') });
    assert.deepEqual(service.create('A'), { id: 'A', createdAt: '2026-01-01T00:00:00.000Z' });
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** timestamp 2026-01-01T00:00:00.000Z.

## Prediction before your attempt

Predict `Object.keys(wallet)` after deposits and withdrawals. A `#cents` private field is not a property at all, so it never appears, and adding an ordinary `balance` property creates a separate public value that the methods ignore. ## Exercises

1. **Maintain balance through methods: change one input.** In a scratch copy of Example A, change `const wallet = new Wallet(100);` to `const wallet = new Wallet(101);`. Which check fails, and what value does it see?
   **Expected:** The edited run fails with an `AssertionError` at `assert.equal(wallet.cents, 120)`. Restoring `const wallet = new Wallet(100);` brings back: balance 120; no enumerable balance field.
   **Verify:** The public API exposes observations and controlled mutations. Use that rule to account for the actual and expected values in the `AssertionError`.

2. **Inject a deterministic clock: debug a regression.** A regression made one Example B line read `const service = new ReceiptService({ now: () => new Date('2027-01-01T00:00:00.000Z') });`. Locate and repair it without editing the check.
   **Expected:** Before the repair the run fails with an `AssertionError` at `assert.deepEqual(service.create('A'), { id: 'A', createdAt: '2026-01-01T00:00:00.000Z' })`. Restoring `const service = new ReceiptService({ now: () => new Date('2026-01-01T00:00:00.000Z') });` brings back: timestamp 2026-01-01T00:00:00.000Z.
   **Verify:** The time dependency is explicit and replaceable. Keep the failing and repaired runs and compare the values each one reports.

3. **Reject invalid transitions without mutation.** Try a negative deposit and an overdraw.
   **Expected:** both throw; balance stays 100.
   **Verify:** Keep `assert.throws(() => wallet.withdraw(101), RangeError)`. Control: changing `const wallet = new Wallet(100);` to `const wallet = new Wallet(101);` must make that check fail; then restore it.

4. **Guard derived overflow.** Deposit one cent into the maximum safe balance.
   **Expected:** RangeError; original balance preserved.
   **Verify:** Keep the check `assert.equal(wallet.cents, Number.MAX_SAFE_INTEGER)`; name an input that would make it fail and the value that changes.

5. **Reject an incompatible collaborator.** Pass a clock returning text in an uncalled negative type check.
   **Expected:** expected compiler error; valid Date clock works.
   **Verify:** Keep `assert.equal(new ReceiptService({ now: () => new Date(0) }).create('B').createdAt, '1970-01-01T00:00:00.000Z')`. Control: editing it to `new ReceiptService({ now: () => new Date(1) }).create('B').createdAt,` must make the check fail; then restore it.

6. **Distinguish private storage from a lookalike property.** Add an ordinary balance property to the wallet.
   **Expected:** ordinary property 999; private cents remain 2.
   **Verify:** Keep `assert.equal(wallet.cents, 2)`. Control: changing `const wallet = new Wallet(2);` to `const wallet = new Wallet(3);` must make that check fail; then restore it.

## Common pitfalls and diagnosis

Changing the balance before the overdraft check leaves the wallet invalid when the method throws. Validate the amount and compute the new balance first, then assign. A typed `number` parameter still admits negative, fractional and infinite values. ([Diagnosing a failure](../STUDY-GUIDE.md#diagnosing-a-failure).)
