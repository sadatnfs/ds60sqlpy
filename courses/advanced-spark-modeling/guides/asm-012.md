# asm-012: State-space boundaries and complete-series ownership

Tutorial mode. Stage: intermediate. Direct prerequisites: `asm-011`, `r-049`.

## Starting point and result

An autoregressive process connects adjacent observations. For a stationary AR(1), \(y_t=\phi y_{t-1}+\epsilon_t\), with independent \(\epsilon_t\sim N(0,\sigma^2)\) and \(|\phi|<1\). A correct likelihood includes both an initial-state density and every transition. This chapter demonstrates repartition invariance when the logical series and time order are retained.

## Mechanism: initial condition plus transitions

Stationarity implies \(y_0\sim N(0,\sigma^2/(1-\phi^2))\). The likelihood for one complete series factors as \(p(y_0)\prod_{t=1}^{T-1}p(y_t\mid y_{t-1})\). Consequently,

\[L=\tfrac12[\log(2\pi v_0)+y_0^2/v_0]+\tfrac12\sum_{t=1}^{T-1}[\log(2\pi\sigma^2)+(y_t-\phi y_{t-1})^2/\sigma^2],\quad v_0=\frac{\sigma^2}{1-\phi^2}.\]

Spark's window specification partitions by the logical series key and orders by time. `lag` supplies the previous observation. This may require a shuffle and sort. It does not mean an arbitrary physical partition is an independent process. The first row per series receives the stationary initial term, and all later rows receive transition terms.

The fixture has unique, contiguous integer times and no missing y values. Before using real data, verify those conditions. Duplicate times make order ambiguous. A gap of several intervals requires the corresponding multi-step transition distribution, not the one-step formula used here. Null y values cannot serve as a harmless first-row marker.

## Worked case: two complete series

Two four-point series are evaluated at phi 0.7 and sigma 0.5. The serial oracle walks each complete list in order. Spark evaluates the same observations after repartitioning to one and then three partitions. Both aggregate losses agree with the oracle. The logical window boundary remains the series key, so changing physical placement does not create extra initial states.

The result is a fixed-parameter likelihood evaluation. It is not an estimated forecast model, a state-space filter or evidence of cluster-scale throughput. Those are useful extensions after this contract is correct.

## Worked case: resetting every chunk is a different model

The program splits each series into two chunks and incorrectly gives each chunk its own stationary initial density. The likelihood differs from the complete-series calculation. The transition connecting the second and third observations has disappeared and a second initial term has appeared. This is exactly the kind of error that can be hidden by partition-local loops.

A distributed scan could retain boundary state or use an associative transition representation in suitable models. That requires an explicit algorithm and ordering contract. Alternatively, assigning each manageable complete series to one worker preserves its local recurrence. The choice depends on series length, number of series and memory, not on a wish to avoid communication.

## Failure diagnosis

Unexpected initial-term counts often indicate missing values, duplicate keys or an incorrect window partition. If the objective changes when input row order changes, verify the time ordering and tie policy. Near \(|\phi|=1\), the stationary variance becomes large and the model approaches a boundary where this parameterization is poorly conditioned. A nonstationary model needs different initial assumptions.

## Interview discussion

**Are AR(1) observations independent?** They are not marginally independent. Their conditional transition factorization makes a sum of conditional log densities possible when the previous state is available.

**Is dropping the initial density always wrong?** Conditional likelihood can deliberately condition on the first observation. That is a different declared objective. The error is silently changing between conditional and stationary likelihood as partitions change.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-python`.

```python
from __future__ import annotations

import json
import math


def session(name):
    from pyspark.sql import SparkSession

    spark = (
        SparkSession.builder.master("local[2]")
        .appName(name)
        .config("spark.ui.enabled", "false")
        .config("spark.driver.host", "127.0.0.1")
        .config("spark.driver.bindAddress", "127.0.0.1")
        .config("spark.sql.shuffle.partitions", "2")
        .config("spark.sql.adaptive.enabled", "false")
        .config("spark.sql.ansi.enabled", "true")
        .config("spark.sql.session.timeZone", "UTC")
        .getOrCreate()
    )
    if spark.version != "4.0.1":
        spark.stop()
        raise RuntimeError("This worked reference is qualified for Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    return spark


def series_nll(values, phi, sigma):
    if abs(phi) >= 1 or sigma <= 0:
        raise ValueError("Stationary AR(1) needs abs(phi)<1 and sigma>0")
    v = sigma * sigma / (1 - phi * phi)
    loss = 0.5 * (math.log(2 * math.pi * v) + values[0] * values[0] / v)
    for prior, current in zip(values, values[1:], strict=False):
        loss += 0.5 * (
            math.log(2 * math.pi * sigma * sigma) + (current - phi * prior) ** 2 / (sigma * sigma)
        )
    return loss


def run(spark):
    from pyspark.sql import Window
    from pyspark.sql import functions as F

    sequences = {"a": [1.0, 0.9, 0.6, 0.5], "b": [-1.0, -0.7, -0.2, 0.1]}
    phi, sigma = 0.7, 0.5
    rows = [(key, t, value) for key, values in sequences.items() for t, value in enumerate(values)]
    df = spark.createDataFrame(rows, "series string,t long,y double")
    oracle = math.fsum(series_nll(values, phi, sigma) for values in sequences.values())
    evidence = []
    for partitions in (1, 3):
        ordered = df.repartition(partitions).withColumn(
            "prior", F.lag("y").over(Window.partitionBy("series").orderBy("t"))
        )
        v = sigma * sigma / (1 - phi * phi)
        initial = 0.5 * (math.log(2 * math.pi * v) + F.col("y") ** 2 / v)
        transition = 0.5 * (
            math.log(2 * math.pi * sigma * sigma)
            + (F.col("y") - phi * F.col("prior")) ** 2 / (sigma * sigma)
        )
        actual = (
            ordered.agg(
                F.sum(F.when(F.col("prior").isNull(), initial).otherwise(transition)).alias("loss")
            )
            .first()
            .loss
        )
        assert math.isclose(actual, oracle, abs_tol=1e-12)
        evidence.append({"partitions": partitions, "loss": actual})
    reset = math.fsum(
        series_nll(v[:2], phi, sigma) + series_nll(v[2:], phi, sigma) for v in sequences.values()
    )
    assert abs(reset - oracle) > 0.01
    print(
        json.dumps(
            {
                "complete_series_loss": oracle,
                "wrong_chunk_reset": reset,
                "cases": evidence,
                "fixture_times_unique_and_contiguous": True,
            }
        )
    )


if __name__ == "__main__":
    spark = session("asm-012")
    try:
        run(spark)
    finally:
        spark.stop()
```
