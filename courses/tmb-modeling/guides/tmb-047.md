# Atomic functions and custom derivative contracts

Start with: tmb-046, tmb-006.

Outcome: Design and test a custom derivative boundary without silently truncating derivatives.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

An atomic function packages an operation behind a derivative-aware boundary. It can reduce tape size or expose an efficient algorithm whose derivatives are known. It also moves responsibility to the author: a wrong reverse rule makes the entire model's gradient wrong even when forward values look perfect.

TMB provides `TMB_ATOMIC_VECTOR_FUNCTION` and framework-specific implementation support. The pinned macro takes a name, output dimension, forward calculation and reverse calculation. It is a low-level extension mechanism, not a routine requirement for ordinary likelihood code. Prefer ordinary typed operations or reviewed built-in atomics when they already meet the need.

### Worked case A: derive the reverse rule

For \(y=x^4\), an incoming output adjoint \(\bar y\) produces input adjoint \(\bar x=4x^3\bar y\). For a vector function, the reverse rule computes \(J^T\bar y\), not the full Jacobian unless that is explicitly needed. The companion checks this rule with two different incoming adjoints and finite differences of the scalar composition.

A custom macro implementation must account for every input and output component, including zeros and unused coordinates. Its forward code may run on ordinary doubles while reverse code runs in a typed AD context. Casting reverse intermediates to double can make first derivatives appear plausible while breaking higher-order derivatives.

### Worked case B: a derivative that passes one point and fails elsewhere

A deliberately wrong derivative \(4x^3+0.1(x-1)\) agrees with the true derivative at x=1. The companion checks additional points and exposes the error. A derivative test only at the fitted optimum can likewise miss a broken implementation. Use a grid, random but seeded points, domain edges and incoming-adjoint variations.

Laplace gradients and Hessians can require derivatives beyond the first level. A custom atomic accepted for a fixed-effect first derivative is not automatically accepted for a latent model's higher-order requirements. Test the exact required derivative order under the chosen CppAD/TMBad build and report unsupported orders explicitly.

### Answered discussion

**Are atomics always faster?** No. They can reduce recording overhead but introduce their own call, memory and derivative costs. Benchmark only after numerical qualification. **Can a finite-difference reverse rule be used?** It changes accuracy and performance guarantees and needs a carefully stated approximation policy; it is not exact AD. **Should learners edit the library's internal atomic implementation?** Keep experiments in owned source with a clear boundary instead of modifying installed dependency internals.

Read the [TMB atomic macro interface](https://github.com/kaskr/adcomp/blob/master/TMB/inst/include/atomic_macro.hpp) and its [TMBad counterpart](https://github.com/kaskr/adcomp/blob/master/TMB/inst/include/tmbad_atomic_macro.hpp). This chapter's companion validates the derivative contract mathematically. The separate original quartic atomic in `projects/tmb-cpp-api` also compiled and passed value, gradient and Hessian oracles at three points on native Linux ARM64 with CppAD. This narrow receipt does not qualify every custom atomic or TMBad variant.

### Complete R companion

```r
f <- function(x) x^4;h <- 1e-6
for (adjoint in c(.3, 2)) for (x in c(-.7, .4, 1.3)) {
  reverse <- 4 * x^3 * adjoint;numeric <- (adjoint * f(x + h) - adjoint * f(x - h)) / (2 * h)
  stopifnot(abs(reverse - numeric) < 1e-7)
}
x <- c(-1, 0, 1, 2);wrong <- 4 * x^3 + .1 * (x - 1)
print(data.frame(x = x, true = 4 * x^3, wrong = wrong, error = wrong - 4 * x^3));stopifnot(wrong[3] == 4, any(abs(wrong - 4 * x^3) > .05))
```
