# web-051: PDO, prepared statements and the value-query boundary

## Level and prerequisites

Advanced; allow about 140 minutes, with extra time for independent practice. Direct prerequisites: `web-035`, `web-044`, `web-047`

## Learning objectives

Build a local PDO note store with prepared insert and lookup. Explain which checks must be repeated when moving to PostgreSQL. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

PDO is a database access interface with drivers for particular engines. The classroom prepares PDO SQLite so examples can use an in-memory database without credentials or network access. PostgreSQL and SQLite differ in types, SQL features and concurrency, so a SQLite pass does not prove PostgreSQL behavior. Revisit the SQL route for relational design and engine-specific queries.

A prepared statement separates the fixed query structure from parameter values. A value containing a quote or SQL-looking text remains a value when bound correctly. Parameters cannot stand in for arbitrary identifiers, keywords or sort directions. Dynamic column selection needs an explicit allowlist that maps a choice to trusted SQL structure. Escaping HTML output is a separate boundary after fetching data.

## Syntax anatomy and mechanism

Create a PDO connection with exception error mode, create a tiny schema and prepare an INSERT. Execute it with a parameter map, then prepare a SELECT using a value predicate. Keep the database handle local to this run. The example's table is disposable in-memory state, not the learner's persistent classroom database.

## Classroom execution and offline inputs

Choose the **PHP CLI** worker in the classroom. The pad is staged as `main.php` and executes as a bounded Linux process, with prepared PHP and PDO SQLite. Write `<?php` at the beginning; a pure PHP file needs no closing tag. Output appears as text. PHP-generated HTML is escaped output here, not automatically injected into a browser. No host PHP installation is required for the Docker route.

The supplied requests, identities, sessions and database fixtures are synthetic local inputs. CLI runs are fresh processes, not persistent HTTP requests. A dictionary that represents a cookie or request is not a real browser cookie. SQLite examples use an in-memory database and do not connect to the classroom PostgreSQL service. Network servers, uploads, mail, Composer downloads and production credentials are outside this pad's contract. Later delivery lessons provide an explicitly separate loopback server lab. A successful function test does not qualify that server integration.

## Worked example / walkthrough

### Worked example 1: A value parameter

The SQL structure is fixed before the name is supplied.

```php
$stmt = $db->prepare('INSERT INTO notes (title) VALUES (:title)');
$stmt->execute(['title' => "Ada's notes"]);
```

**Expected observation:** The apostrophe is stored as data rather than breaking the query.

### Worked example 2: An allowlisted identifier

Parameters do not replace column names.

```php
$columns = ['title' => 'title', 'created' => 'id'];
$orderBy = $columns[$requested] ?? 'id';
```

**Expected observation:** Only reviewed column names can enter a dynamic query structure.

## Debugging and common mistakes

Do not concatenate values into SQL and call the result prepared merely because prepare() is used afterward. Avoid copying SQLite-specific assumptions into PostgreSQL without checking them. Database binding does not make fetched text safe for HTML.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.
