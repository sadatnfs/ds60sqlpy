# c-006: Arrays, bounds and element counts

## Purpose and mental model

An array owns a fixed number of elements of one type. Its valid indices run from zero through length minus one. C does not attach a runtime bounds check to each subscript. In many expressions an array converts to a pointer to its first element, which loses the length information. A function receiving an array-like parameter therefore normally needs a separate element count. sizeof applied to an actual array measures the whole array, but sizeof applied to a pointer measures the pointer object. Confusing these contexts is a common source of incomplete loops and out-of-bounds access.

## Vocabulary and concepts

- **Array extent:** The number of elements in an array object.
- **Array-to-pointer conversion:** Conversion to a pointer to the first element in most expressions.
- **Logical length:** The number of elements an operation is allowed to use.

## Syntax anatomy and execution trace

`int values[3]` allocates three integers. A partial initializer fills remaining elements with zero. `sizeof values / sizeof values[0]` derives an element count only where `values` is still an array. A parameter written `int values[]` is adjusted to a pointer parameter. Pass the logical length explicitly and document whether a null pointer is permitted for length zero. Never dereference the one-past position.

## Worked example / walkthrough

### Worked example 1: Derive a local element count

Create a three-element array and calculate its count with sizeof.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int sum_items(const int *values, size_t n) {
  int out = 0;
  for (size_t i = 0; i < n; i++)
    out += values[i];
  return out;
}

int main(void) {
  /* Derive a local element count */
  {
    int values[] = {2, 4, 6};
    size_t n = sizeof values / sizeof values[0];
    CHECK(n == 3);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The count is 3.

The expression works because values is an array in this scope. Moving it unchanged into a pointer-taking helper would change its meaning.

### Worked example 2: Pass an explicit length

Sum three elements through a pointer-and-length API.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int sum_items(const int *values, size_t n) {
  int out = 0;
  for (size_t i = 0; i < n; i++)
    out += values[i];
  return out;
}

int main(void) {
  /* Derive a local element count */
  {
    int values[] = {2, 4, 6};
    size_t n = sizeof values / sizeof values[0];
    CHECK(n == 3);
  }

  /* Pass an explicit length */
  {
    int values[] = {2, 4, 6};
    CHECK(sum_items(values, 3) == 12);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The result is 12.

The API relies on the caller providing at least three live elements. The pointer alone cannot prove that extent.

### Exercise 3: Inspect partial initialization

Initialize only the first element of a three-element array.

**Expected:** The remaining two elements are zero.

**Verify:** Keep a CHECK equivalent to `values[0] == 7 && values[1] == 0 && values[2] == 0`. Control edit: changing `int values[3] = {7};` to `int values[3] = {8};` must fail it; then restore it.

**Progressive hints:** First trace `values` from initialization. Then recall: This initialization rule differs from an uninitialized automatic array, whose elements must not be read before assignment.

### Exercise 4: Use a logical prefix

Sum only the first two elements of a three-element array.

**Expected:** The result is 6.

**Verify:** Keep a CHECK equivalent to `sum_items(values, 2) == 6`. Control edit: changing `int values[] = {2, 4, 99};` to `int values[] = {3, 4, 99};` must fail it; then restore it.

**Progressive hints:** First trace `values` from initialization. Then recall: Physical capacity and logical length are separate.

### Exercise 5: Handle an empty logical view

Call the sum contract with null and length zero.

**Expected:** The sum is zero and no access occurs.

**Verify:** Keep a CHECK equivalent to `sum_items(NULL, 0) == 0`. Control edit: `CHECK(sum_items(NULL, 0) != 0);` must fail; then restore it.

**Progressive hints:** First work out what `sum_items` returns here. Then recall: This particular helper accepts an empty null view because its loop performs no access.

### Exercise 6: Transfer independent array storage

Copy elements into a distinct array and mutate the copy.

**Expected:** The original first element remains 1.

**Verify:** Keep a CHECK equivalent to `a[0] == 1 && b[0] == 9`. Control edit: changing `int a[] = {1, 2};` to `int a[] = {2, 2};` must fail it; then restore it.

**Progressive hints:** First trace `a` and `b` from initialization. Then recall: C arrays cannot be assigned as whole arrays with =.

## Common pitfalls and diagnosis

Applying `sizeof arr / sizeof arr[0]` to a parameter declared `int arr[]`: the parameter is a pointer, so the result is a ratio of pointer size to element size, not the element count. Pass the length explicitly.
