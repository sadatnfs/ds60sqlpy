# js-052: Statistical summaries, box plots and uncertainty intervals

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-051`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Draw a labeled box and median. Design a comparison of two estimated effects. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

A summary reduces a distribution to selected quantities. The median is a central order statistic; quartiles describe the middle part of the distribution. A box plot communicates chosen quantiles and whisker rules, which must be stated because conventions differ. It does not preserve every feature of the raw observations.

An uncertainty interval describes uncertainty about a parameter under a statistical procedure and assumptions. It is not the same as the spread of individual observations. A box showing sample quartiles and an interval around a mean answer different questions. Label both the statistic and the interval method when presenting estimates.

The lesson uses tiny synthetic samples to make quartiles and interval endpoints inspectable. It does not claim a confidence interval from an arbitrary pair of numbers. A visualization may render a supplied estimate and bounds correctly while the upstream statistical method is invalid; those checks remain separate.

## Syntax anatomy and mechanism

Sort numerical values before using a function that assumes sorted input. `d3.quantileSorted` computes a quantile of an ordered array. For `[1, 2, 3, 4, 5]`, median is 3 and the first and third quartiles are 2 and 4. A simple box can map those values to x positions, with a median line inside.

For a supplied interval, check lower <= estimate <= upper before drawing a segment and point. If the interval spans zero, that visual fact should not be hidden by a truncated axis. The statistical interpretation still depends on the stated estimator and procedure.

## Worked example / walkthrough

### Worked example 1: Compute transparent quartiles

The input is explicitly sorted.

```javascript
const v=[1,2,3,4,5];
console.log(d3.quantileSorted(v,0.25),d3.quantileSorted(v,0.5),d3.quantileSorted(v,0.75));
```

**Expected observation:** 2, 3 and 4.

### Worked example 2: Validate an interval before rendering

This does not calculate the interval statistically.

```javascript
const estimate={value:0.2,lower:-0.1,upper:0.5};
console.log(estimate.lower<=estimate.value && estimate.value<=estimate.upper);
```

**Expected observation:** true; the supplied interval crosses zero.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose calling an unsorted-only contract incorrectly. Its distinguishing evidence is Sort a copy before quantileSorted. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
