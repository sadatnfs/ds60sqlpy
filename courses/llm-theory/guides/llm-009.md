## Purpose and mental model

<!-- textbook-foundations-start -->

### Contextual information is a weighted computation

An embedding gives a token occurrence an initial vector, but understanding its role often requires other tokens. Attention is one way to construct a context-dependent vector. For a selected position, it compares a query with candidate keys, converts those comparisons into weights and uses the weights to mix candidate value vectors. The query and key determine where information is taken from; the values determine what numerical information is combined. These are roles in a computation, not literal questions, dictionary keys or human explanations.

It helps to separate the three steps before reading the compact matrix expression. First form one score for each query/key pair. Next normalize each query's allowed scores into a probability row. Finally multiply that row by the value matrix, obtaining one weighted average of value vectors. With T query positions and T key positions, the weight matrix has T squared entries. If each value has D_v features, the output has T rows and D_v columns. The weights range over positions, not vocabulary tokens. An attention probability of 0.7 therefore means a mixing coefficient for a particular value row, not a 70 percent probability that a word or claim is correct.

The equal-score fixture deliberately removes complicated content matching. Every query and key is zero, so all allowed scores are zero. The causal mask makes the first query see one value, the second see two and the third see three. With values [2,0], [0,2] and [6,6], the first output must be [2,0]. The second is their first-two average, [1,1]. The third is the three-way average, \([\frac{8}{3},\frac{8}{3}]\). We can predict these outputs without any exponentials because equal legal scores imply equal weights.

Now change only the third value to [100,200]. The first two outputs should be identical to their previous values, because the changed row is in their future. The final output changes to \([34,\frac{202}{3}]\). This test translates the abstract word "causal" into an observable condition. An unmasked computation instead makes every output that global average, immediately exposing future information in the first row. The test is stronger than inspecting whether the mask has a triangular shape: it checks the result of the whole operation.

The equal-score case is easy to understand but deliberately incomplete. A function that ignores queries and keys could pass it, so the following derivation also uses unequal dot products. This is a general testing principle: one controlled fixture isolates a particular mechanism, while a second fixture must challenge assumptions that the first one makes invisible. Exact weighted outputs, row sums, forbidden zeros and independent prefix recomputation test different properties.

Attention is useful when the relevance of an earlier representation depends on the current representation. It still needs projected features, positional information, residual paths and training to become part of a useful model. The [Transformer architecture](https://arxiv.org/abs/1706.03762) combines these pieces; this chapter isolates one small head so that its information flow can be understood without hiding inside a framework call.

## Trace one attention row beyond the equal-score control

For query i, score \(s_{ij}={q_{i}}^{T}\) \(\frac{k_{j}}{\sqrt{d_{k}}}\) compares it with key j. The allowed mask removes unavailable keys, softmax normalizes the remaining row, and \(o_i=\sum_j a_{ij}v_j\) mixes values. Query/key width d_k controls the dot product and scaling. Value width d_v controls the output width and need not equal d_k. The score matrix carries query and key positions, while the output carries query positions and value features. A dimension match alone cannot establish that these semantic axes were arranged correctly.

The equal-score fixture is an excellent mask control because every legal key receives equal weight. It cannot test whether Q and K are actually used or whether division by \(\sqrt{d_{k}}\) is present: zero dot products stay zero under either correct or incorrect scaling. Consider instead a second query q_1=[1,0], allowed keys k_0=[1,0], k_1=[0,1], and \(d_{k}=2\). Its two scores are[1/sqrt2,0], giving weights approximately[.66976155,.33023845]. With values[2,0] and[0,2], the output is approximately[1.33952310,.66047690]. Omitting the scaling gives weights about[.73105858,.26894142], so the output changes despite preserving the causal triangle and unit row sum.

Scaling has a statistical motivation, not a universal exact variance guarantee. If independent query/key components have zero mean and unit variance, a width-d dot product has variance d because it sums d product terms. Dividing by \(\sqrt{d}\) keeps that variance near one under those assumptions. Learned features can violate independence or unit variance, and a model can use other architectural conventions. For this worksheet, the explicit formula is the contract to test, regardless of whether a particular literal vector resembles the motivating assumptions.

Masking after softmax breaks normalization. With three equal scores, unconstrained weights are[1/3,1/3,1/3]. Zeroing future entries in the first row leaves[1/3,0,0], so its output is one third of the first value instead of that value. Renormalizing allowed mass afterward can recover the algebra in benign finite cases, but forming the distribution over forbidden extreme scores first can lose allowed mass numerically. Removing forbidden scores before maximum subtraction gives a clearer and safer computation. A fully masked query has no categorical distribution under this contract and is refused.

A backward trace helps distinguish the roles of Q,K,V. For one query, let \(g=\frac{\partial L}{\partial o}\) be the upstream value-width vector. Then \(\frac{\partial L}{\partial v_{j}}=a_{j}\) g, and \(\frac{\partial L}{\partial s_{j}}=a_{j}\) \(g^{\mathsf T}(v_j-o)\). The latter term compares each value with the current mixture. Gradients then flow to the query through \(\sum_j\frac{\partial L}{\partial s_j}\frac{k_j}{\sqrt{d_k}}\), and to each key through(dL/ds_j) \(\frac{q}{\sqrt{d_{k}}}\). A hard forbidden key has no contribution through this row. These equations describe the fixed attention operation; the reference does not train the projected Q/K/V matrices or a complete model.

Prefix invariance is a whole-path property. A residual addition and a positionwise feed-forward transformation preserve it if their own inputs are causal. A normalization that mixes statistics across all token positions could violate it even when the attention mask is correct. So could a preprocessing step that inspects future targets or a batch construction that appends the answer unshifted. For teacher-forced next-token prediction, a diagonal attention entry is legal because input position i contains the previous target under the shifted convention. If it contains the current label instead, the same triangular mask leaks the answer.

Cached decoding changes mask coordinates. With three cached keys and one newly appended key, a single new query at absolute position 3 may attend to all four keys. A naive lower triangle constructed with shape(1,4) allows only column0, because its query row index is 0 rather than absolute position 3. The worksheet intentionally handles square self-attention; later cached/cross-attention implementations need an explicit absolute-position or cache-offset rule. Shape compatibility should never silently decide causal meaning.

**Interview reasoning:** "Does prefix invariance prove correct attention?" It proves a useful information boundary for the checked inputs, but a function that always returns zeros could also satisfy it. Combine independent properties: exact nonuniform outputs, allowed-row sums, forbidden zeros, shape/type/domain guards, prefix recomputation and future perturbations. Even all of those checks establish a computation, not factuality or data-split independence. The [original Transformer paper](https://arxiv.org/abs/1706.03762) provides the architectural context; the numerical cases here isolate individual mechanisms.

## Vocabulary and concepts

A **query** is the feature vector for the position requesting information. A
**key** is a vector used to score a candidate position. A **value** is the
vector that will be mixed into the output. Here `Q`, `K` and `V` have one token
per row. Queries and keys have the same feature width so their dot product is
defined; values may have a different feature width.

A **score matrix** has a query row and a key column. `Q @ K.T` compares every
query with every key. Dividing by `sqrt(d)` is the attention scaling convention
for key width `d`. **Softmax** converts finite allowed scores into nonnegative
weights that sum to one along the key axis. Subtracting a row maximum avoids
unnecessary exponential overflow without changing the distribution.

The boolean **allowed mask** in this worksheet uses `True` for a position that
may participate. It is lower triangular, including its diagonal. Other APIs
can use the inverse boolean meaning; a mask name alone is not a portable
contract. **Prefix invariance** means recomputing any prefix gives the same
outputs as the corresponding early rows of the full computation, within a
stated numeric tolerance.

**Causal mask:** an explicit information boundary whose allowed keys for a
query are its current position and earlier positions.

**Key axis:** the column axis of the score matrix; softmax normalizes this
axis separately for every query row.

**Prefix invariance:** agreement between an independently recomputed prefix
and the corresponding early rows of the full calculation.

### Example A: equal scores make the mask visible

Zero query and key vectors give every allowed key the same score. The first
row has one legal value, the second has two, and the third has three. With
`V=[[2,0],[0,2],[6,6]]`, the outputs are the value, the first-two mean, and the
three-value mean. This makes an off-by-one or wrong-axis error easy to see.

```python
import numpy as np


def attention(q, k, v, allowed):
    q, k, v = (np.asarray(value, dtype=np.float64) for value in (q, k, v))
    allowed = np.asarray(allowed)
    if any(value.ndim != 2 for value in (q, k, v)):
        raise ValueError("q, k and v must be matrices")
    count, width = q.shape
    if count == 0 or width == 0 or v.shape[1] == 0:
        raise ValueError("nonempty token and feature axes required")
    if k.shape != (count, width) or v.shape[0] != count:
        raise ValueError("self-attention shapes do not agree")
    if allowed.dtype != np.bool_:
        raise TypeError("allowed must be boolean")
    if allowed.shape != (count, count):
        raise ValueError("allowed must have shape (tokens, tokens)")
    if not allowed.any(axis=1).all():
        raise ValueError("each query needs at least one key")
    if not all(np.isfinite(value).all() for value in (q, k, v)):
        raise ValueError("finite inputs required")
    scores = (q @ k.T) / np.sqrt(width)
    if not np.isfinite(scores[allowed]).all():
        raise ValueError("finite allowed scores required")
    masked = np.where(allowed, scores, -np.inf)
    shifted = masked - masked.max(axis=1, keepdims=True)
    weights = np.exp(shifted)
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ v, weights


q = np.zeros((3, 2), dtype=np.float64)
k = q.copy()
v = np.array([[2.0, 0.0], [0.0, 2.0], [6.0, 6.0]])
allowed = np.tri(3, dtype=bool)
output, weights = attention(q, k, v, allowed)
expected = np.array([[2.0, 0.0], [1.0, 1.0], [8 / 3, 8 / 3]])
np.testing.assert_allclose(output, expected, rtol=0, atol=1e-12)
np.testing.assert_allclose(weights.sum(axis=1), 1.0, rtol=0, atol=1e-12)
for cut in range(1, 4):
    prefix, _ = attention(q[:cut], k[:cut], v[:cut], np.tri(cut, dtype=bool))
    np.testing.assert_allclose(output[:cut], prefix, rtol=0, atol=1e-12)
print(output)
```

**Expected:** rows `[2,0]`, `[1,1]`, `[2.6666666666666665,
2.6666666666666665]`, up to float formatting. The third row's exact values are
`8/3`. `weights.sum(axis=1)` is `[1,1,1]`. The prefix loop is a second check;
it does not read an official solution or require a trained model.

### Example B: a future value exposes an unmasked computation

Keep Q and K at zero. Change only the third value row to `[100,200]` and compare
causal attention with an all-allowed mask. Use the `attention` helper defined
in Example A; run the whole scratch file from a fresh process.

```python
future_v = v.copy()
future_v[2] = [100.0, 200.0]
causal, _ = attention(q, k, future_v, np.tri(3, dtype=bool))
unmasked, _ = attention(q, k, future_v, np.ones((3, 3), dtype=bool))
np.testing.assert_allclose(causal[:2], [[2.0, 0.0], [1.0, 1.0]], rtol=0, atol=1e-12)
np.testing.assert_allclose(unmasked, np.tile([34.0, 202 / 3], (3, 1)), rtol=0, atol=1e-12)
print(causal)
print(unmasked)
```

**Expected:** the first two causal rows do not change. Its final row becomes
`[34,202/3]`. Every unmasked row becomes that new global mean, including row
zero, so a future position affected an earlier query. This is a direct causal
failure even if another metric looked good.

## Common pitfalls

If the first output changes when only a future value changes, inspect mask
orientation and the key/query axes. If row sums are below one, inspect whether
masking happened after softmax. If a row becomes NaN, first ask whether it had
any allowed key, then check numeric finiteness and the maximum-subtraction
step. If appending padding changes an earlier result, check whether a later
component computes statistics across the whole sequence.

An API's boolean mask may mean forbidden rather than allowed. Translate the
meaning explicitly instead of copying a mask unchanged between libraries.
Allowing the diagonal is correct for shifted next-token targets; feeding the
answer at the same position and labeling it as itself is a different objective.
Finally, passing the attention checks says nothing about whether the held-out
documents leaked into a tokenizer or a prompt-selection process.

## Progressive hints

- **Hint 1:** draw a square with query rows and key columns. Mark each row's
  current and earlier positions before doing any arithmetic.
- **Hint 2:** remove future rows from Q, K and V, recompute from scores, and
  compare with the full computation's matching prefix. A reused full result
  cannot test the independent computation.
- **Hint 3:** inspect the key-axis sum after normalization and ensure forbidden
  scores are removed before exponentiation. Reject a row with no legal key
  instead of guessing a probability distribution.
