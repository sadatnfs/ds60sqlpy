# js-022: Generic functions and constraints

## Level and prerequisites

Intermediate, approximately 90 minutes. Direct prerequisites: `js-021`

## Learning objectives

Write generic functions whose constraints connect inputs to precise result types without unsafe casts.

By the end you can preserve identity type and object identity, connect a key to its exact result type, expose absence in a generic first function, use only the constrained length property, transform while preserving output element type, and avoid pretending a constraint is the exact caller type.

## Purpose and mental model

Generics express a relationship between types across a reusable operation. An identity function returning any loses information about the relationship between input and output. A generic identity function returns the same type T supplied by its caller. The parameter is not a runtime argument or a request to create a new specialized JavaScript function for every type; it is a compile-time relation checked against one implementation.

A constraint gives the implementation only the operations known to exist. T extends {length: number} permits reading length, but does not permit replacing the input with an arbitrary object containing length and claiming it is still the caller's exact T. The caller may have supplied an array, a string or a richer record with additional invariants.

keyof and indexed access types connect property keys to property result types. A generic getProperty<T,K extends keyof T> returns T[K], preserving whether the chosen field is a string or a number. This is useful when the relationship is real. Overly elaborate generics can make an API harder to understand; prefer a concrete parameter type when only one domain shape is needed. Generics cannot validate unknown JSON or prove that an external service honored a claimed schema.

## Vocabulary and concepts

**Type parameter:** A placeholder describing a relationship selected at a call site.

**Constraint:** The minimum structure a generic implementation may rely on.

**Keyof:** A type operator producing the known keys of a type.

**Indexed access type:** A type expression selecting the type associated with a key.

## Syntax anatomy and execution trace

Declare type parameters in angle brackets on the function. T names a caller-selected type; extends constrains its allowed structure. K extends keyof T restricts a key to known properties, and T[K] gives the corresponding value type. A generic function returning the first element should expose T | undefined for an empty input even when the project's indexed-access checking is less strict. Runtime control flow must implement the same absence policy.

## Worked example / walkthrough

### Example A: Preserve identity type and object identity

The generic relationship preserves static information without copying data. Runtime identity is still a separate observation checked by the assertion.

```typescript
import { strict as assert } from 'node:assert';

function identity<T>(value: T): T {
  return value;
}
function getProperty<T, K extends keyof T>(value: T, key: K): T[K] {
  return value[key];
}
function first<T>(values: readonly T[]): T | undefined {
  return values.length === 0 ? undefined : values[0];
}
function measuredLength<T extends { length: number }>(value: T): number {
  return value.length;
}
function mapValues<T, U>(values: readonly T[], convert: (value: T) => U): U[] {
  return values.map(convert);
}

export async function verify(): Promise<{ checks: number; status: string }> {
  // Worked example
  {
    const value: number = identity(7);
    const record = { id: 'A' };
    assert.equal(value, 7);
    assert.equal(identity(record), record);
    function negativeTypeCheck(): void {
      // @ts-expect-error identity preserves number rather than inventing string.
      const text: string = identity(7);
      void text;
    }
    void negativeTypeCheck;
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** number remains 7; object is the same reference.
### Example B: Connect a key to its exact result type

Returning a broad string|number union would lose the connection between the selected key and its payload. T[K] preserves that correlation.

```typescript
import { strict as assert } from 'node:assert';

function identity<T>(value: T): T {
  return value;
}
function getProperty<T, K extends keyof T>(value: T, key: K): T[K] {
  return value[key];
}
function first<T>(values: readonly T[]): T | undefined {
  return values.length === 0 ? undefined : values[0];
}
function measuredLength<T extends { length: number }>(value: T): number {
  return value.length;
}
function mapValues<T, U>(values: readonly T[], convert: (value: T) => U): U[] {
  return values.map(convert);
}

export async function verify(): Promise<{ checks: number; status: string }> {
  // Worked example
  {
    const row = { id: 'A', count: 2 };
    const id: string = getProperty(row, 'id');
    const count: number = getProperty(row, 'count');
    assert.equal(id, 'A');
    assert.equal(count, 2);
    function negativeTypeCheck(): void {
      // @ts-expect-error missing is not a key of this record.
      getProperty(row, 'missing');
    }
    void negativeTypeCheck;
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));
```

**Expected:** id is string A; count is number 2.

## Prediction before your attempt

Predict the type inferred for `getProperty(record, 'count')`. With `K extends keyof T` and a return type of `T[K]`, it is `number`, not the union of every property type. Then predict the type of `first([])` for an empty array. ([Predicting before you run](../STUDY-GUIDE.md#predicting-before-you-run).)

## Exercises

1. **Preserve identity type and object identity: change one input.** In a scratch copy of Example A, change `const value: number = identity(7);` to `const value: number = identity(8);`. Which check fails, and what value does it see?
   **Expected:** The edited run fails with an `AssertionError` at `assert.equal(value, 7)`. Restoring `const value: number = identity(7);` brings back: number remains 7; object is the same reference.
   **Verify:** The generic relationship preserves static information without copying data. Use that rule to account for the actual and expected values in the `AssertionError`.

2. **Connect a key to its exact result type: debug a regression.** A regression made one Example B line read `const row = { id: 'A', count: 3 };`. Locate and repair it without editing the check.
   **Expected:** Before the repair the run fails with an `AssertionError` at `assert.equal(count, 2)`. Restoring `const row = { id: 'A', count: 2 };` brings back: id is string A; count is number 2.
   **Verify:** Returning a broad string|number union would lose the connection between the selected key and its payload. Keep the failing and repaired runs and compare the values each one reports.

3. **Expose absence in a generic first function.** Read the first item from a nonempty and an empty readonly array.
   **Expected:** 4 and undefined.
   **Verify:** Keep `assert.equal(first([4, 5]), 4)`. Control: editing it to `assert.equal(first([5, 5]), 4);` must make the check fail; then restore it.

4. **Use only the constrained length property.** Apply a length operation to a string and an array; reject a number at compile time.
   **Expected:** lengths 3 and 2.
   **Verify:** Keep `assert.equal(measuredLength('abc'), 3)`. Control: editing it to `assert.equal(measuredLength('abc!'), 3);` must make the check fail; then restore it.

5. **Transform while preserving output element type.** Map numbers to labels through a generic map function.
   **Expected:** string array `['item:2', 'item:4']`; input unchanged.
   **Verify:** Keep `assert.deepEqual(labels, ['item:2', 'item:4'])`. Control: changing `const values = [2, 4];` to `const values = [3, 4];` must make that check fail; then restore it.

6. **Avoid pretending a constraint is the exact caller type.** Show that a replacement object cannot be returned as arbitrary T even if it meets the constraint.
   **Expected:** expected compile error for returning a fabricated length-only object.
   **Verify:** Keep `assert.equal(measuredLength({ length: 5, id: 'A' }), 5)`. Control: editing it to `assert.equal(measuredLength({ length: 6, id: 'A' }), 5);` must make the check fail; then restore it.

## Common pitfalls and diagnosis

Returning `any` from a generic helper discards the link between input and output types, and a fabricated object that only satisfies the constraint is not a valid `T`. When the compiler rejects a return, check whether you return the caller's value or a new one. ([Diagnosing a failure](../STUDY-GUIDE.md#diagnosing-a-failure).)

Reveal one hint at a time ([using the hints](../STUDY-GUIDE.md#using-the-hints)).

- **Exercise 1:** Compute the checked value with `const value: number = identity(8);` in place before running it.
- **Exercise 2:** Compare `const row = { id: 'A', count: 3 };` with the original line and state the claim each version makes.
- **Exercise 3:** The signature deliberately includes undefined. Trace each value that `assert.equal(first([4, 5]), 4)` reads.
- **Exercise 4:** A constraint permits one shared capability across otherwise different types. Trace each value that `assert.equal(measuredLength('abc'), 3)` reads.
- **Exercise 5:** Two type parameters represent the input element and output element. Trace each value that `assert.deepEqual(labels, ['item:2', 'item:4'])` reads.
- **Exercise 6:** A constraint is a lower bound on required capabilities, not the full identity of every allowed type. Trace each value that `assert.equal(measuredLength({ length: 5, id: 'A' }), 5)` reads.
