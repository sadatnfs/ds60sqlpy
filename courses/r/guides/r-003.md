## Outcome and mechanism

Write vectorized calculations while rejecting accidental recycling and unintended coercion.

The c function combines values into an atomic vector when their types can be made compatible. Arithmetic on two equal-length numeric vectors generally pairs their elements by position. A scalar is a length-one vector, so adding one fee to every amount uses the same mechanism. Vectorized syntax is concise, but it does not automatically align records by a customer or product key.

R recycles a shorter vector when its length is smaller than the other operand. A two-element pattern added to four values repeats twice without a warning. If the longer length is not a multiple of the shorter length, R commonly warns, but the operation still produces a result. That warning is not a dependable substitute for a shape contract: some incorrect lengths recycle silently.

State the intended sizes before the operation. If every amount needs its own fee, require equal lengths. If one fee applies to all amounts, allow exactly one fee deliberately. The rule belongs to the calculation's interface, not to a later visual inspection of plausible output. A length-zero input also needs an explicit policy because it often propagates to a length-zero result.

An atomic vector has one storage type. c(1, TRUE) is numeric, while c(1, "two") is character. A list, introduced later, can retain different object types. These choices matter when reading heterogeneous records: putting a label beside measurements in a single atomic vector can silently turn all the measurements into text.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Atomic vector | A sequence whose elements share one underlying type. |
| Elementwise operation | An operation applied to aligned vector elements. |
| Recycling | Reuse of a shorter vector during compatible elementwise operations. |
| Length contract | A declared relationship between input sizes. |

## Read the syntax

Use length(x) to inspect size, seq_along(x) to create valid positions even for empty x, and rep to create a deliberate repeated pattern. The expression x + fee pairs positions; it is not a join on names.

## Worked examples

### Example 1: One declared scalar fee

```r
amount <- c(10, 20, 30)
fee <- 2
stopifnot(length(fee) == 1)
result <- amount + fee
stopifnot(identical(result, c(12, 22, 32)))
print(result)
```

**Expected observation:** 12, 22, 32.

Length one is an intentional broadcast in this calculation. Each input receives the same fee.

### Example 2: A silent pattern can be the wrong contract

```r
amount <- c(10, 20, 30, 40)
fees <- c(1, 2)
recycled <- amount + fees
stopifnot(identical(recycled, c(11, 22, 31, 42)))
valid_per_row <- length(amount) == length(fees)
stopifnot(!valid_per_row)
print(recycled)
```

**Expected observation:** 11, 22, 31, 42; per-row lengths are invalid.

No warning is needed because four is a multiple of two. The separate per-row length rule still rejects the input.
