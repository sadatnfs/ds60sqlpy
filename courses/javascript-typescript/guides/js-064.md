# js-064: Canvas, rendering cost and spatial hit testing

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-063`.

## Learning objectives

Draw many points on a canvas at the right pixel ratio and hit-test them with a quadtree. The central exercise is: Draw 100 bounded points and a textual summary.

## Purpose, vocabulary and mental model

SVG keeps a DOM node for each mark, making styling and interaction convenient. Canvas draws pixels into one bitmap, which can reduce DOM overhead for many simple marks. Canvas does not automatically provide a separate accessible or interactive element for each point. The author must supply semantics and hit testing.

A Canvas has a backing resolution and a CSS display size. Device pixel ratio can make a one-to-one backing bitmap look blurry on high-density screens. Scale the backing dimensions and drawing context deliberately while keeping analytical coordinates in the documented logical space.

Performance depends on data size, transformations, layout, rendering and interactions. Switching to Canvas does not fix an expensive quadratic data algorithm. Measure the slow stage, avoid repeated allocations where appropriate and preserve an accessible data summary or table.

### Key terms

- **Canvas:** An HTML element that draws into a single pixel bitmap through a 2D context. Its marks are not DOM nodes, so the author must supply semantics and hit testing.
- **Device pixel ratio:** The value of `window.devicePixelRatio`, the number of physical pixels per CSS pixel. Scaling the backing bitmap by it keeps Canvas drawing sharp on dense screens.
- **Hit testing:** Finding which mark lies under a pointer position, computed in the same coordinate space used to draw the marks.
- **Quadtree:** A `d3.quadtree` spatial index that recursively divides two-dimensional space so `find(x, y)` locates the nearest point without scanning every point.

## Syntax anatomy and mechanism

Set canvas.width and height for the backing bitmap, set CSS width and height for display, then transform the context by the device pixel ratio. Draw circles with beginPath, arc and fill. A quadtree can search nearby points efficiently, but its coordinates must match the pointer coordinate space.

The reference draws a bounded grid of 100 points and performs a known nearest-point lookup. It does not benchmark a million records or claim universal Canvas superiority. The SVG is hidden for this lesson because the output is the Canvas plus a textual summary.

## Worked example / walkthrough

### Worked example 1: Separate display and backing dimensions

Logical size remains 320 by 180. This snippet creates its own canvas.

```javascript
const canvas = d3.select("#chart").append("canvas").node();
const context = canvas.getContext("2d");
const ratio = Math.min(devicePixelRatio || 1, 2);
canvas.width = 320 * ratio;
canvas.height = 180 * ratio;
canvas.style.width = "320px";
canvas.style.height = "180px";
context.setTransform(ratio, 0, 0, ratio, 0, 0);
console.log(canvas.width / ratio, canvas.height / ratio);
```

**Expected observation:** 320 180: drawing coordinates stay logical while the backing bitmap gains resolution.

### Worked example 2: Find a nearby point

The quadtree query uses the same coordinate system as the points drawn on the canvas.

```javascript
// js-064 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Canvas, rendering cost and spatial hit testing")
  .style("width", "100%")
  .style("max-width", "640px");
const points = [
  { id: "A", x: 10, y: 10 },
  { id: "B", x: 90, y: 90 },
];
const canvas = d3.select(host).append("canvas").attr("width", 320).attr("height", 180).node();
const context = canvas.getContext("2d");
context.fillStyle = "#2563eb";
for (const point of points) {
  context.beginPath();
  context.arc(point.x, point.y, 6, 0, 2 * Math.PI);
  context.fill();
}
const tree = d3
  .quadtree()
  .x((d) => d.x)
  .y((d) => d.y)
  .addAll(points);
const hit = tree.find(12, 11);
check(hit.id === "A", "The query near (12, 11) finds A");
context.strokeStyle = "#dc2626";
context.strokeRect(hit.x - 10, hit.y - 10, 20, 20);
check(tree.find(50, 50, 5) === undefined, "A small search radius rejects distant queries");
output.textContent = "js-064 worked example 2 complete";
```

**Expected observation:** Two dots on a canvas; A is outlined in red because the query at (12, 11) returns it, while a query at (50, 50) with radius 5 returns nothing.

## Debugging and common mistakes

If points look blurry, check the backing size: set `canvas.width` to the CSS width times `devicePixelRatio` and call `ctx.scale(ratio, ratio)` so drawing coordinates stay logical. If a hit test selects the wrong point, compare pointer and indexed coordinate spaces. `quadtree.find(x, y, radius)` returns `undefined` when nothing lies within the radius. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a hit test that selects the wrong point after scaling. Distinguishing evidence: Pointer and indexed coordinates use different spaces.

## Accessibility and interpretation

Canvas pixels have no DOM nodes, so assistive technology sees a single image. Give the canvas an accessible name and a text summary with the point count, and provide a keyboard-operable filter or list for exact records. The selected point's values should appear as text, not only as an outline. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Switching to Canvas changes rendering cost, not the data; the same scales and grain apply. Measure which stage is slow, transformation or drawing, before replacing SVG. With thousands of points overplotting returns, so state how density is shown and keep the record count visible. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
