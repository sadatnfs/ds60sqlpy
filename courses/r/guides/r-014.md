## Outcome and mechanism

Map a validated computation over records and retain predictable output types with readable data flow.

Functional iteration separates the operation on one element from the traversal over a collection. lapply applies a function to each input element and returns a list, retaining heterogeneous results when necessary. This is useful when each group produces a structured summary rather than one number.

Simplification needs a contract. sapply may simplify a result into a vector, matrix or list depending on what it receives. That convenience can make edge cases surprising. vapply asks for an expected result prototype, such as numeric(1), and rejects an incompatible output. A pipeline using one numeric scalar per group should make that requirement explicit.

The base pipe |> makes a sequence of calls readable by passing the left-hand value to the next call. It does not make an operation lazy, distributed or automatically vectorized. A function still receives and returns ordinary R objects. Anonymous functions can adapt argument order or perform a short named step when a simple first-argument call does not fit.

Avoid mapping solely to hide a complex stateful loop. If each iteration depends on prior mutation, a clear bounded loop may communicate the algorithm better. For independent group summaries, a small pure function and an explicit output contract make testing easier. Include empty collections and groups with missing observations in the interface rather than assuming every group resembles the first.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Mapping | Applying a function to each element of a collection. |
| lapply | Mapping that returns a list. |
| vapply | Mapping with an explicit expected result type and length. |
| Pipe | Syntax passing an intermediate result into the next call. |

## Read the syntax

lapply(groups, summarize) returns one object per group. vapply(groups, function(x) sum(x), numeric(1)) requires one double-compatible scalar per group. The base pipe sends the left value into the first argument of a normal call unless explicitly adapted.

## Worked examples

### Example 1: One typed total per group

```r
groups <- list(A = c(1, 2), B = c(4, 6))
totals <- vapply(groups, sum, numeric(1))
stopifnot(identical(totals, c(A = 3, B = 10)))
print(totals)
```

**Expected observation:** A3, B10.

The prototype states that every group produces one numeric total. Group names remain available for interpretation.

### Example 2: Structured mapping and a readable pipeline

```r
groups <- list(A = c(1, 2), B = c(4, 6))
summaries <- lapply(groups, function(x) list(n = length(x), total = sum(x)))
stopifnot(summaries$B$n == 2L, summaries$B$total == 10)
result <- c(3, 1, 2) |>
  sort() |>
  head(2)
stopifnot(identical(result, c(1, 2)))
print(result)
```

**Expected observation:** 1,2.

A list is appropriate for structured group outputs. The pipe is ordinary sequential evaluation with an inspectable intermediate order.
