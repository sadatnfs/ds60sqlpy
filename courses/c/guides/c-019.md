# c-019: Binary formats, byte order and representation boundaries

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-018`

## Learning objectives

Implement the six investigations, from the "encode a known word" case to the "transfer a framed payload" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A portable binary format specifies bytes, widths and byte order rather than dumping an in-memory struct. Host representation can differ in endianness, padding, alignment and type sizes. Explicit encoding makes the wire contract inspectable and avoids leaking padding bytes. A decoder must validate the available length before reading fields and reject unsupported versions or values. Use unsigned types for shifts and masks, with shift counts inside the type width. memcpy can safely copy object representation bytes when the destination object and sizes are valid, but interpreting arbitrary bytes as a typed object still requires a representation contract.

## Vocabulary and concepts

- **Endianness:** The byte order used to represent multibyte values.
- **Wire format:** A documented serialized representation independent of host layout.
- **Alignment:** An address requirement for accessing an object through a type.

## Syntax anatomy and execution trace

A big-endian 32-bit encoding stores the most significant byte first. Cast each input byte to uint32_t before shifting. Without the cast, integer promotion (introduced in c-003) turns the unsigned char into an int, and shifting a byte value of 128 or more left by 24 overflows int, which is undefined behavior. Read four bytes only after checking length. Bitwise OR combines disjoint fields. The format here assumes eight-bit bytes and requires that with _Static_assert because its external definition uses octets.

## Worked example / walkthrough

### Worked example 1: Encode a known word

Encode 0x12345678 in big-endian order.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

_Static_assert(CHAR_BIT == 8, "this octet format requires 8-bit bytes");
void encode_u32(uint32_t value, unsigned char out[4]) {
  out[0] = (unsigned char)(value >> 24);
  out[1] = (unsigned char)(value >> 16);
  out[2] = (unsigned char)(value >> 8);
  out[3] = (unsigned char)value;
}
bool decode_u32(const unsigned char *data, size_t n, uint32_t *out) {
  if (n < 4 || data == NULL || out == NULL)
    return false;
  *out = ((uint32_t)data[0] << 24) | ((uint32_t)data[1] << 16) |
         ((uint32_t)data[2] << 8) | (uint32_t)data[3];
  return true;
}

int main(void) {
  /* Encode a known word */
  {
    unsigned char out[4];
    encode_u32(UINT32_C(0x12345678), out);
    CHECK(out[0] == 0x12 && out[1] == 0x34 && out[2] == 0x56 && out[3] == 0x78);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The bytes are 12, 34, 56, 78 in hexadecimal.

The explicit byte contract does not depend on host endianness.

### Worked example 2: Decode a known word

Decode bytes 00, 00, 01, 00.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

_Static_assert(CHAR_BIT == 8, "this octet format requires 8-bit bytes");
void encode_u32(uint32_t value, unsigned char out[4]) {
  out[0] = (unsigned char)(value >> 24);
  out[1] = (unsigned char)(value >> 16);
  out[2] = (unsigned char)(value >> 8);
  out[3] = (unsigned char)value;
}
bool decode_u32(const unsigned char *data, size_t n, uint32_t *out) {
  if (n < 4 || data == NULL || out == NULL)
    return false;
  *out = ((uint32_t)data[0] << 24) | ((uint32_t)data[1] << 16) |
         ((uint32_t)data[2] << 8) | (uint32_t)data[3];
  return true;
}

int main(void) {
  /* Encode a known word */
  {
    unsigned char out[4];
    encode_u32(UINT32_C(0x12345678), out);
    CHECK(out[0] == 0x12 && out[1] == 0x34 && out[2] == 0x56 && out[3] == 0x78);
  }

  /* Decode a known word */
  {
    unsigned char data[] = {0, 0, 1, 0};
    uint32_t value = 0;
    CHECK(decode_u32(data, 4, &value) && value == 256);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The numeric value is 256.

Each byte is promoted to the intended unsigned width before shifting.

**Expected:** The decoder fails and preserves output.

**Verify:** Keep a CHECK equivalent to `!decode_u32(data, 3, &value) && value == 9`. Control edit: changing `uint32_t value = 9;` to `uint32_t value = 10;` must fail it; then restore it.

### Exercise 4: Round-trip zero

Encode and decode numeric zero.

**Expected:** The result is zero.

**Verify:** Keep a CHECK equivalent to `decode_u32(out, 4, &value) && value == 0`. Control edit: changing `encode_u32(0, out);` to `encode_u32(1, out);` must fail it; then restore it.

**Progressive hints:** First trace `out` and `value` from initialization. Then recall: Zero is a valid payload, not an absent field or string terminator in this format.

### Exercise 5: Round-trip the maximum

Encode and decode UINT32_MAX.

**Expected:** All bits survive.

**Verify:** Keep a CHECK equivalent to `decode_u32(out, 4, &value) && value == UINT32_MAX`. Control edit: `CHECK(decode_u32(out, 4, &value) && value != UINT32_MAX);` must fail; then restore it.

**Progressive hints:** First trace `out` and `value` from initialization. Then recall: The boundary case exercises every high bit and catches signed intermediate mistakes.

### Exercise 6: Transfer a framed payload

Decode the four bytes after a one-byte version field.

**Expected:** Version 1 and payload 7 are interpreted separately.

**Verify:** Keep a CHECK equivalent to `frame[0] == 1 && decode_u32(frame + 1, sizeof frame - 1, &value) && value == 7`. Control edit: changing `unsigned char frame[] = {1, 0, 0, 0, 7};` to `unsigned char frame[] = {2, 0, 0, 0, 7};` must fail it; then restore it.

**Progressive hints:** First trace `frame` and `value` from initialization. Then recall: A format should reject unsupported versions before interpreting fields under the wrong schema.

## Common pitfalls and diagnosis

Copying wire bytes straight into a `uint32_t` with `memcpy` adopts the host's byte order, so the value differs between little- and big-endian machines. Casting an arbitrary `unsigned char *` to `uint32_t *` can also violate alignment.
