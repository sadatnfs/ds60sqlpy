tf-002: Tensors, axes, dtypes and units#

Learning objectives#

Trace each axis and unit through vector arithmetic without accidental broadcasting. By the end, you can produce the exact observations below, explain one plausible wrong result and transfer the reasoning to a new fixed fixture without copying a solution. Keep your first prediction alongside the actual evidence so a changed conclusion remains visible.

Purpose and mental model#

An array has values and a shape. Its shape states how many entries belong on each axis. A vector containing three predictions has shape (3,), while a column containing three targets has shape (3,1). Both displays can look like three numbers, but subtracting them asks NumPy to align different axes. NumPy follows its broadcasting rules instead of guessing that the rows represent paired observations.

This lesson teaches you to trace that alignment before interpreting a loss. With x=[1,2,3]x=[1,2,3] and y=[2,4,6]y=[2,4,6], paired subtraction yields three residuals. Reshaping y into a column creates nine combinations. Neither result is random and neither requires a framework bug. The shapes describe different mathematical questions.

A second contract is dtype, the representation used for each scalar. Integer storage is suitable for counts but cannot silently store every fractional update. Float64 is our small arithmetic reference, not a promise of exact real-number mathematics. A third contract is units: an array does not know whether 100 means centimeters, dollars or a count. Make shape, representation and units explicit together so a plausible-looking number does not hide the wrong calculation.

Vocabulary and concepts#

Shape: a tuple giving the length of every axis; (3,) and (3,1) describe different layouts.

Axis: one independently indexed dimension; name the observation axis before a reduction.

Broadcasting: NumPy alignment that conceptually repeats compatible singleton axes without understanding record identities.

Dtype: the scalar storage/operation representation, such as int64 or float64.

Unit: the physical or semantic meaning of a value, which NumPy does not infer from dtype.

Syntax or reasoning anatomy#

In np.asarray(values, dtype=np.float64), values supplies the data and dtype requests an explicit floating representation. A shape comparison inspects the layout before subtraction. The expression left - right is elementwise only after NumPy has aligned axes; it does not imply one-to-one observations. A rank-one vector has one axis, whereas a matrix has two, even if one axis has length one.

For the small paired helper, require both arrays to be nonempty rank-one vectors of the same shape, then reject nonfinite values before calculating a residual. This is deliberately narrower than NumPy's complete arithmetic API. A strict domain helper prevents an automatic broadcast that is legal for arrays but wrong for our observation meaning. Do not flatten an arbitrary column unless you have established its intended row order.

A scalar reduction can conceal an axis mistake#

For the correct residual vector [-1, -2, -3], the mean square is 143\frac{14}{3}. The wrongly broadcast 3 by 3 grid contains squares with total 66 and mean 223\frac{22}{3}. Dividing each by its own array size produces a valid scalar, yet the second value describes nine cross-record comparisons. The reduction has no knowledge of which pairs were intended.

Even agreement of scalar values would not establish correct pairing. If all predictions happen to be zero, repeating each target across several columns can leave the mean square unchanged. A later gradient or a changed prediction can expose the error. Check rank, shape and record identity before reduction; then use a fixture with distinct predictions and targets so a mistaken axis cannot hide behind symmetry.

Units create a similar silent failure. A length stored as 100 centimeters and one stored as 1 meter describe the same quantity. Subtracting the raw numbers reports 99 because arithmetic knows representations, not physical meaning. Convert to a shared unit before pairing, and record that unit alongside the dtype and feature name.

Worked example / walkthrough#

Run Examples A and B in order in one scratch file, then run that complete file in a fresh process. Example B may reuse the imports, helpers and fixture state established in Example A. Do not treat an isolated later block as a standalone program.

Example A: Three actual pairs#

Use explicit float64 vectors. Read the shape tuple before reading values.

import numpy as np

x = np.array([1, 2, 3], dtype=np.float64)
y = np.array([2, 4, 6], dtype=np.float64)
residual = x - y
assert residual.shape == (3,)
np.testing.assert_array_equal(residual, [-1, -2, -3])
print(residual)

Expected: There are three residuals because the two observation vectors share one axis of length three.

Example B: A valid array operation with the wrong pairing#

Change only the target layout. This is a diagnosis example, not a recommended repair.

column = y.reshape(3, 1)
grid = x - column
assert grid.shape == (3, 3)
np.testing.assert_array_equal(grid, [[-1, 0, 1], [-3, -2, -1], [-5, -4, -3]])
print(grid)

Expected: The rightmost axes align first: (1,3) and (3,1) expand to (3,3). Every target is compared with every input. A later scalar mean cannot restore the lost pairing.

Progressive hints#

  • Hint 1: Write both shape tuples with their rightmost axes aligned.
  • Hint 2: Check rank, equal shape and nonempty count before performing arithmetic.
  • Hint 3: Keep representation and units separate: float64 enables fractions but does not convert centimeters into meters.

Common pitfalls#

If subtraction returns a square matrix where you expected a vector, print both operand shapes first. Looking only at length is insufficient because len(column) and len(vector) can both be three. If an update raises a casting error, inspect the target array's dtype rather than changing the learning rule. Create an explicit floating copy when fractional arithmetic is intended.

If a mean is NaN, inspect emptiness and finiteness before tuning a model. If a comparison fails only in the last digit, use a stated tolerance for the intended numeric check. A tolerance cannot repair a wrong axis, record order or unit. Multiplying a centimeter value by a meter-trained weight is a different model even when the array shapes match.
