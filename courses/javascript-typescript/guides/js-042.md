# js-042: Release, observability and maintenance

## Level and prerequisites

Advanced, approximately 120 minutes. Direct prerequisites: `js-041`

## Learning objectives

Explain release artifact, smoke test, artifact verification, compatibility gate with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. The first investigation is: Create the authored bundle, verify hashes and run its self-test in a child. The final task tests gate an observed runtime against explicit policy.

## Purpose and mental model

A release is a specific artifact with a reproducible behavior contract, not merely a folder that once worked during development. A small release manifest can name the exact files, record their digests and declare a schema version. Verification should reject unexpected paths before reading files, compare expected byte identities and then execute a bounded smoke test in a fresh process. These checks answer different questions: identity, admissible layout and behavior.

The fixture builds a tiny command-line bundle in an owned temporary directory. Its application has a self-test command and a generic usage failure. The manifest names only app.mjs and package.json, so an altered manifest cannot make the verifier read an arbitrary path. The app's self-test checks real arithmetic behavior and reports the actual Node version. A compatibility gate accepts an explicitly supplied required major version; the course's prepared execution profile remains Node 24. Production policy may pin a full version and image digest rather than only a major.

Observability is part of the output contract. The application emits one result object to stdout and a small completion or failure event to stderr. It does not echo arbitrary command-line values in its error. The caller preserves those channels separately and includes them when a smoke test fails. A successful self-test proves only its covered cases, so the manifest and receipt must not be advertised as production acceptance or exhaustive compatibility.

Maintenance means keeping source, docs, tests, packaged bytes and runtime assumptions aligned. A source edit invalidates a digest and should trigger new execution evidence. Rollback requires retaining a known artifact and its compatible state assumptions; renaming a version label is not a rollback procedure. This lesson performs local packaging and smoke checks only. It does not publish a registry package, deploy a service or change learner state.

## Vocabulary and concepts

**Release artifact:** The exact files intended to be distributed or executed.

**Smoke test:** A small fresh-process check of essential behavior.

**Artifact verification:** Checking allowed layout and expected byte identities.

**Compatibility gate:** An explicit rule comparing observed runtime evidence with release requirements.

## Syntax anatomy and execution trace

The manifest uses an explicit filename allowlist and SHA-256 digests. Paths are rejected before joining them to the bundle directory. The hash list excludes the manifest itself to avoid a self-reference. spawnSync runs the current Node executable with a fixed source path and argument list, bounded timeout and output size. stdout and stderr remain separate. Runtime qualification compares a reported actual major version with a caller-supplied policy rather than trusting package metadata alone.

## Worked example / walkthrough

### Example A: Build, verify and execute a fresh bundle

The child executes the packaged bytes rather than an already imported development function. The receipt records the runtime that actually ran.

```javascript
import { strict as assert } from 'node:assert';
import { mkdtemp, writeFile, readFile, appendFile, rm } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { createHash } from 'node:crypto';
import { spawnSync } from 'node:child_process';

const APP = String.raw`import { strict as assert } from 'node:assert';
const args = process.argv.slice(2);
if (args.length !== 1 || args[0] !== '--self-test') {
  process.stderr.write(JSON.stringify({ event: 'usage_error', message: 'Use --self-test' }) + '\n');
  process.exitCode = 2;
} else {
  assert.equal(2 + 3, 5);
  assert.equal([].reduce((sum, value) => sum + value, 0), 0);
  assert.equal(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1), false);
  process.stdout.write(JSON.stringify({ status: 'passed', checks: 3, node: process.versions.node }) + '\n');
  process.stderr.write(JSON.stringify({ event: 'self_test_complete', checks: 3 }) + '\n');
}
`;
function hash(bytes) { return createHash('sha256').update(bytes).digest('hex'); }
async function withBundle(use) {
  const directory = await mkdtemp(join(tmpdir(), 'course-release-'));
  try {
    await writeFile(join(directory, 'app.mjs'), APP);
    await writeFile(join(directory, 'package.json'), JSON.stringify({ name: 'course-release', version: '1.0.0', type: 'module', private: true }));
    const files = [];
    for (const path of ['app.mjs', 'package.json']) files.push({ path, sha256: hash(await readFile(join(directory, path))) });
    await writeFile(join(directory, 'manifest.json'), JSON.stringify({ version: 1, files }));
    return await use(directory);
  } finally { await rm(directory, { recursive: true, force: true }); }
}
async function verifyBundle(directory) {
  const manifest = JSON.parse(await readFile(join(directory, 'manifest.json'), 'utf8'));
  if (manifest.version !== 1 || !Array.isArray(manifest.files) || manifest.files.length !== 2) throw new Error('invalid manifest');
  const allowed = new Set(['app.mjs', 'package.json']);
  const seen = new Set();
  for (const file of manifest.files) {
    if (!allowed.has(file.path) || seen.has(file.path)) throw new Error('unapproved artifact path');
    seen.add(file.path);
    if (hash(await readFile(join(directory, file.path))) !== file.sha256) throw new Error('digest mismatch');
  }
}
function runBundle(directory, args) {
  const result = spawnSync(process.execPath, [join(directory, 'app.mjs'), ...args], { encoding: 'utf8', timeout: 10000, maxBuffer: 1024 * 1024 });
  if (result.error) throw result.error;
  if (result.signal) throw new Error(`child terminated by ${result.signal}`);
  return result;
}
function qualifyRuntime(receipt, requiredMajor) {
  if (receipt.status !== 'passed' || Number(receipt.node.split('.')[0]) !== requiredMajor) throw new Error('runtime mismatch');
  return true;
}

export async function verify() {
  // Worked example
  {
    await withBundle(async directory => {
      await verifyBundle(directory);
      const result = runBundle(directory, ['--self-test']);
      assert.equal(result.status, 0, result.stderr);
      const receipt = JSON.parse(result.stdout);
      assert.equal(receipt.checks, 3);
      assert.equal(receipt.status, 'passed');
      assert.equal(receipt.node, process.versions.node);
    });
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));

```

**Expected:** three checks passed; actual Node version reported.
### Example B: Reject altered application bytes before execution

Even a behavior-preserving edit changes artifact identity. The correct repair is to create a new reviewed manifest and rerun evidence, not ignore the mismatch.

## Prediction before your attempt

Trace the entry point and identify the values that exist before each operation. Distinguish a value from a reference to an object, a returned Promise from its eventual result, and a compile-time type from a runtime check. Write down the first observation that would disprove your explanation. A useful prediction includes an expected value or failure category, not merely a claim that the program should work.

For a loop, write the state before and after one iteration. For a callback, identify the caller and the arguments it supplies. For an asynchronous operation, identify who starts it, who awaits it, and who owns cleanup. These small traces make failures local: you can compare the first incorrect state instead of guessing from a much later symptom.

## Exercises

1. **Build, verify and execute a fresh bundle.** Create the authored bundle, verify hashes and run its self-test in a child.
   **Expected:** three checks passed; actual Node version reported.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

2. **Reject altered application bytes before execution.** Append a harmless comment to the owned application after manifest creation.
   **Expected:** digest verification fails.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

3. **Reject a manifest path outside the allowlist.** Replace one file entry with ../outside.txt.
   **Expected:** path is rejected before any outside file is read.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

4. **Preserve result and diagnostic channels on failure.** Invoke an unsupported argument containing a fake secret-like value.
   **Expected:** nonzero child exit; stdout empty; generic stderr without the value.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

5. **Derive stable content identity from unchanged files.** Read and hash the same app twice and compare with its manifest entry.
   **Expected:** equal digests and an unchanged manifest match.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

6. **Gate an observed runtime against explicit policy.** Accept the current runtime major for the fixture and reject a different required major.
   **Expected:** matching policy passes; mismatched policy throws.
   **Verify:** Record the observed value, exception or browser state and compare it with that expectation.

## Common pitfalls and diagnosis

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.

## Progressive hints

Start by comparing the actual value with the literal expected result. Next, isolate the expression that transforms it or the boundary where its type or ownership changes. If the discrepancy involves scheduling, replace unrelated work with a small trace array and await the exact completion you intend to observe. Finally, ask for one hint about the first incorrect assumption before opening the reference. Keep one controlled failure that would catch the same mistake returning.
