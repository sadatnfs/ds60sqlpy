## Outcome and mechanism

Use the pinned S7 property and method API to construct valid values, reject invalid replacement and dispatch across two typed arguments.

S7 provides class definitions with declared properties and an explicit generic-method system. It aims to support interoperability with existing R object systems while offering more regular interfaces. It is not a spelling change for either S3 or S4. This lesson targets the prepared S7 0.2.2 API and uses method(generic, class) <- function(...) replacement syntax. Newer development documentation can show syntax not present in this pinned environment.

new_class returns a class object that is also callable as a constructor. Named properties specify expected classes such as class_numeric and class_character. A class validator expresses constraints that property types cannot state: the numeric values must form a finite vector, and the unit must contain exactly one nonempty string. An S7 validator returns NULL on success or a character vector of failures, which differs from the TRUE success result used by the S4 validity function.

Property access uses @. Construction and ordinary property replacement are validated by the S7 interface. An attempted invalid replacement should raise an error instead of installing an invalid value. Tests verify both the diagnostic and the value retained after failure. Low-level bypasses or arbitrary attribute editing are outside the public interface and should not be used as an analytical shortcut.

A new_generic declares the names of the arguments involved in dispatch. A single-argument total uses the Series class. A two-argument join uses list(Series,Series), so the method is selected from both argument classes. The method still checks equality of units because dispatch selects by type, not by every possible property value. Concatenation is explicit and does not silently convert incompatible units.

S7 properties and S4 slots share @ notation, but notation alone does not establish that an object is an S4 instance or that S4 method registrations apply. Inspect the public class interfaces and write adapters when crossing object-system boundaries. The next lesson uses an ordinary validated data contract so one analytical calculation can consume S3, S4, R6 and S7 values without depending on their private layouts.

Version-aware examples should test behavior against the actual prepared package and cite the relevant API. A package upgrade can change dispatch details, diagnostics or helper syntax. The bounded checks here establish construction, property validation and two generic operations on a small fixture. They do not establish compatibility with every historical S3 generic or every future S7 release.

## Read the syntax

Series <- S7::new_class(...) defines properties and a validator. Series(values=c(2,4),unit="ms") constructs a value and x@values reads its property. S7::new_generic("join_series",c("x","y")) declares multiple dispatch; S7::method(join_series,list(Series,Series)) <- function(x,y) installs the pinned-version method.

## Worked examples

### Example 1: Single and multiple dispatch on validated properties

```r
Series <- S7::new_class("Series",
  properties = list(
    values = S7::class_numeric, unit = S7::class_character
  ),
  validator = function(self) {
    problems <- character(0)
    if (!is.null(dim(self@values)) || any(!is.finite(self@values))) {
      problems <- c(problems, "values must be a finite vector")
    }
    if (length(self@unit) != 1L || is.na(self@unit) || !nzchar(self@unit)) {
      problems <- c(problems, "unit must be one nonempty string")
    }
    if (length(problems)) problems else NULL
  }
)
series_total <- S7::new_generic("series_total", "x")
S7::method(series_total, Series) <- function(x) setNames(sum(x@values), x@unit)
join_series <- S7::new_generic("join_series", c("x", "y"))
S7::method(join_series, list(Series, Series)) <- function(x, y) {
  if (!identical(x@unit, y@unit)) stop("incompatible series units")
  Series(values = c(x@values, y@values), unit = x@unit)
}

a <- Series(values = c(2, 4), unit = "ms")
b <- Series(values = 6, unit = "ms")
result <- join_series(a, b)
stopifnot(identical(result@values, c(2, 4, 6)))
stopifnot(identical(series_total(result), c(ms = 12)))
print(series_total(result))
```

**Expected observation:** A joined vector 2,4,6 and total ms=12.

The class object builds both inputs and the join result. The join method receives two Series values and preserves their unit. The total generic then returns a named scalar.

### Example 2: A property type does not express all domain constraints

```r
Series <- S7::new_class("Series",
  properties = list(
    values = S7::class_numeric, unit = S7::class_character
  ),
  validator = function(self) {
    problems <- character(0)
    if (!is.null(dim(self@values)) || any(!is.finite(self@values))) {
      problems <- c(problems, "values must be a finite vector")
    }
    if (length(self@unit) != 1L || is.na(self@unit) || !nzchar(self@unit)) {
      problems <- c(problems, "unit must be one nonempty string")
    }
    if (length(problems)) problems else NULL
  }
)
series_total <- S7::new_generic("series_total", "x")
S7::method(series_total, Series) <- function(x) setNames(sum(x@values), x@unit)
join_series <- S7::new_generic("join_series", c("x", "y"))
S7::method(join_series, list(Series, Series)) <- function(x, y) {
  if (!identical(x@unit, y@unit)) stop("incompatible series units")
  Series(values = c(x@values, y@values), unit = x@unit)
}
assert_error <- function(expr, pattern) {
  message <- tryCatch(
    {
      force(expr); NULL
    },
    error = conditionMessage
  )
  stopifnot(is.character(message), length(message) == 1L, grepl(pattern, message))
}

x <- Series(values = c(2, 4), unit = "ms")
assert_error(Series(values = Inf, unit = "ms"), "finite vector")
assert_error(
  {
    x@unit <- character(0)
  },
  "nonempty string"
)
stopifnot(identical(x@unit, "ms"), identical(x@values, c(2, 4)))
seconds <- Series(values = 1, unit = "s")
assert_error(join_series(x, seconds), "incompatible series units")
cat("Invalid construction, replacement and combination rejected.\n")
```

**Expected observation:** Three expected failures; the original value remains valid.

Infinity is numeric and an empty character vector is character, so the domain validator must add information beyond the property declarations. The failed replacement preserves the previous unit.

The implementation uses the pinned replacement-method syntax and the S7 NULL validator convention. It separately tests constructor validation, property replacement and a compatibility check inside a multi-argument method. These are different sources of guarantees.

The count operation demonstrates an independent generic with the same public class. The all-empty case is deliberate and preserves units. Class-system interoperability is deferred to explicit adapters; the shared @ notation is not used as evidence of S4 inheritance.
