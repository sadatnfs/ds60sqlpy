js-062: Geographic data, GeoJSON and projection choices#

Level and prerequisites#

Advanced; about 110 minutes plus independent practice. Direct prerequisites: js-061. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

Learning objectives#

Render the synthetic point collection. Plan a real boundary-data integration. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

Purpose, vocabulary and mental model#

GeoJSON represents geographic features using geometry and properties. Geographic coordinates conventionally use longitude then latitude in degrees. Swapping them can produce plausible but incorrect locations. A map projection converts positions on the globe into a flat display, introducing distortion because a sphere cannot be flattened without tradeoffs.

Different projections preserve different properties locally or globally. A map for comparing area should not casually use a projection that strongly distorts area. A map for route direction has another purpose. State the geographic scope and the projection’s relevance to the analytical question.

The reference uses a tiny original synthetic point collection, so it needs no external map download or geographic dataset license. It demonstrates coordinate conversion and path creation without pretending that dots alone are a detailed basemap. Real geographic boundaries also require source, date and topology review.

Syntax anatomy and mechanism#

A FeatureCollection contains Feature objects with geometry and properties. d3.geoMercator returns a projection callable on [longitude,latitude]. d3.geoPath(projection) converts GeoJSON into SVG path data. Fitting a projection to data chooses scale and translation for a view, not an analytical normalization of values.

Check that all projected coordinates are finite and within the intended view. A coordinate can be valid globally yet outside your chosen region. Handle antimeridian crossings and polygon winding deliberately for actual region datasets; those cases are not solved by swapping arbitrary signs until a map looks right.

Worked example / walkthrough#

Worked example 1: Respect coordinate order#

Longitude is first.

const point={type:"Point",coordinates:[10,45]};
console.log(point.coordinates[0]);

Expected observation: 10 degrees longitude, not latitude.

Worked example 2: Project the origin#

A known center provides a useful anchor.

const projection=d3.geoMercator().center([0,0]).scale(100).translate([320,180]);
console.log(projection([0,0]));

Expected observation: Approximately[320, 180].

Debugging and common mistakes#

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose a misplaced but numerically valid point. Its distinguishing evidence is Check coordinate order, units, projection and source reference system. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

Accessibility and interpretation#

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
