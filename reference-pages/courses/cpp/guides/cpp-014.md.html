Learning objectives#

Deliver a deterministic small CLI from source and explain its failure behavior.

Vocabulary and concepts#

An auditable CLI is a command-line program whose inputs, accepted values, rejected records and output can be reconciled. Parsing and business validation are separate steps. Integer cents avoid decimal rounding ambiguity. The ledger keeps every input accounted for instead of silently discarding bad text.

Syntax and mechanism#

Parse each complete field with from_chars, require the entire string to be consumed, then add only valid nonnegative values. Maintain accepted and rejected counts independently from the sum. Returning nonzero is appropriate for a fatal file failure; per-row rejection can be a documented partial-report policy.

Trace the mechanism#

Reconciliation is a conservation rule: input_count equals accepted_count plus rejected_count. The total alone is too weak because losing a valid zero changes count without changing money. Keep one ledger row for every raw input before grouping. The malformed suffix 25x is a useful negative control because a convenient prefix parser produces an apparently reasonable but incorrect amount. The capstone succeeds only when another learner can repeat both the normal result and the rejected shortcut.

Worked example / walkthrough#

Worked example 1#

for (auto raw : {"10","0","bad","-2","25"}) { /* classify once */ }

Expected: Three accepted, two rejected, total 35.

Worked example 2#

assert(parse_reading("0")==0); assert(!parse_reading("10x"));

Expected: Zero remains valid, while a numeric prefix with trailing junk is rejected.

File-driven reference handoff#

The separate reference also accepts --input FILE. It reads at most 100 lines of at most 32 characters each, reports accepted/rejected counts and exact total, and rejects fatal open/read/budget failures with status 2. Copy the five-line input to an owned local directory. After compiling the reference as analyzer, POSIX runs ./analyzer --input readings.txt; PowerShell runs & .\analyzer.exe --input .\readings.txt. Expected output: accepted=3 rejected=2 total=35. The browser executes the embedded fixture without command-line arguments. Supplying a missing file must produce nonzero status, not an empty successful report.
