## Outcome and mechanism

Parse dates and timestamps with explicit formats and zones, distinguishing calendar labels from elapsed time.

A Date describes a calendar date, while a POSIXct object describes an instant with date-time behavior. The same instant can have different displayed clock times in different time zones. Conversely, a local clock label without a time zone may be ambiguous or nonexistent during daylight-saving transitions. Do not silently treat these as interchangeable representations.

Parsing is part of the data contract. Use a known format and a declared time zone rather than relying on the host's defaults. These lessons use UTC for deterministic instant examples. A source that supplies local civil time needs its source zone and an explicit ambiguity policy before it can be converted into reliable instants.

Calendar arithmetic and elapsed durations answer different questions. Subtracting Dates counts calendar days. Subtracting date-time instants yields a difftime object whose units should be stated explicitly. A local day can have a different elapsed-hour length around a daylight-saving transition, so adding one day on a calendar is not universally equivalent to adding 24 hours to an instant.

Retain the original timestamp text and parsing diagnostics when ingesting data. Invalid or incomplete text can become NA. A successful parse does not prove that the source zone was correct. Downstream grouping by local date should use a declared display/business zone and should not overwrite the canonical instant used for ordering and elapsed-time calculations.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Date | A calendar date without a time-of-day or time zone. |
| POSIXct | An instant represented numerically with date-time behavior. |
| Time zone | Rules for displaying and interpreting local civil time. |
| Elapsed duration | A difference between instants with explicit units. |

## Read the syntax

as.Date parses calendar dates, as.POSIXct(..., format=..., tz="UTC") parses instants, format(..., tz=...) chooses a display zone, and as.numeric(difftime(a, b, units="hours")) states elapsed units.

## Worked examples

### Example 1: Leap-day calendar arithmetic

```r
start <- as.Date("2024-02-28")
end <- as.Date("2024-03-01")
stopifnot(as.numeric(end - start) == 2)
stopifnot(format(start + 1, "%Y-%m-%d") == "2024-02-29")
print(seq(start, end, by = "day"))
```

**Expected observation:** February 28, February 29, March 1.

The calendar contains leap day. Counting date labels across the boundary therefore gives two days.

### Example 2: One instant, two clock displays

```r
instant <- as.POSIXct("2025-01-15 12:00:00", format = "%Y-%m-%d %H:%M:%S", tz = "UTC")
later <- instant + 90 * 60
stopifnot(as.numeric(difftime(later, instant, units = "mins")) == 90)
stopifnot(format(instant, "%H:%M", tz = "UTC") == "12:00")
stopifnot(format(instant, "%H:%M", tz = "America/New_York") == "07:00")
print(c(utc = format(instant, tz = "UTC"), new_york = format(instant, tz = "America/New_York")))
```

**Expected observation:** 12:00 UTC and 07:00 NewYork; elapsed 90 minutes.

Changing the display zone does not change the underlying instant. The elapsed interval is calculated between instants, not by subtracting printed clock strings.
