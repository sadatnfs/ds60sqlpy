# web-014: Normal flow, display and positioning

## Level and prerequisites

Intermediate; allow about 110 minutes, with extra time for independent practice. Direct prerequisites: `web-013`

## Learning objectives

Build a card with an intentional positioned badge and flowing content. Explain the containing block used by an absolute element. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

Normal flow is the browser's default arrangement of content. Block boxes generally stack in the block direction and inline content flows within lines. Understanding this default prevents unnecessary positioning. Display changes how an element participates in layout; it does not change its underlying HTML meaning. A paragraph made display:flex remains a paragraph semantically.

Positioning modifies placement relative to a containing block or scroll container. Relative positioning keeps the element's original space while offsetting its painted position. Absolute positioning removes it from ordinary flow and uses a containing block, often the nearest positioned ancestor. Fixed positioning is often tied to the viewport but transformed ancestors can affect that behavior. Sticky positioning depends on a scroll container and an inset threshold.

## Syntax anatomy and mechanism

Use position:relative on a card only when it intentionally establishes the containing block for an absolute badge. Keep the main article content in flow. A sticky section label needs an inset such as top:0 and sufficient scroll space. Avoid putting every element at exact pixel coordinates; content length and viewport width will change.

## Classroom execution and offline inputs

Choose **HTML browser preview** in the classroom. The pad is one complete HTML document with embedded CSS and, where taught, embedded JavaScript. Its preview is isolated from the classroom and recreated on each run. It does not contact a server, submit real forms, read cookies, fetch assets or load a CDN. All fixtures are inline and synthetic. The browser uses its native HTML parser, so classic-script ordering, shared lexical bindings, inline modules and real DOMContentLoaded/load events keep their browser semantics. External module imports remain blocked. Navigation metadata such as base and meta http-equiv is rejected explicitly. On any supported host, the browser renders the document while Docker serves the classroom. No host compiler is needed.

Run your own source after implementing the task. A reference's checks inspect only the named initial conditions. Its success message is not a full accessibility audit, proof of responsive behavior at every size, or evidence that you implemented the solution yourself. Inspect actual output after keyboard input, resizing and changes. Save your source before comparing with a reference. The document and its CSS share one saved pad; HTML and CSS remain different languages within that artifact.

## Worked example / walkthrough

### Worked example 1: Ordinary flow

Blocks stack without special positioning.

```html
<p>First paragraph.</p><p>Second paragraph.</p>
```

**Expected observation:** The second paragraph follows the first in normal flow.

### Worked example 2: A contained badge

Only the badge is taken out of flow.

```css
.card { position: relative; padding: 2rem; }
.badge { position: absolute; inset-block-start: .5rem; inset-inline-end: .5rem; }
```

**Expected observation:** The badge is positioned relative to the card.

## Six progressive exercises

### Exercise 1: Predict whether relative positioning frees the original space.

**Expected evidence:** It does not; the original layout space remains.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Turn a group of inline links into a block navigation list.

**Expected evidence:** Display changes the arrangement without changing navigation semantics.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Build a card with an intentional positioned badge and flowing content.

**Expected evidence:** Long body text expands the card while the badge stays in its reserved corner.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Diagnose an absolute label overlapping enlarged text.

**Expected evidence:** Provide sufficient reserved space or return the label to normal flow.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Add a long paragraph and narrow the preview.

**Expected evidence:** Content remains readable and the badge does not obscure it.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Explain the containing block used by an absolute element.

**Expected evidence:** Identify the actual ancestor that establishes it, rather than assuming it is always the viewport.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

Sticky positioning can fail because an ancestor creates an unexpected scroll container. Z-index does not repair an incorrect containing block. Keep the reading order in the source meaningful.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation.
