# Sparse symbolic analysis and factorization accuracy

Start with: tmb-035, tmb-015.

Outcome: Distinguish sparse structure, ordering and numerical solve accuracy.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter solves a tridiagonal system, checks a permuted solve and measures the error of dropping coupling. No file in the separately prepared [owned project](../projects/tmb-local/README.md) calls `runSymbolicAnalysis`; sparse factorizations occur inside TMB's Laplace approximation for its latent models; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

A sparse Hessian stores few nonzero entries, but its factorization can introduce additional nonzeros called fill-in. Symbolic analysis chooses or analyzes an elimination structure before numerical factorization. A good ordering can reduce memory and work without changing the mathematical matrix; an approximate factorization changes the numerical calculation and needs an accuracy policy.

`runSymbolicAnalysis(obj, method=...)` exposes advanced options. The manual describes a CHOLMOD path with specialized-installation and historical compatibility context, and an experimental incomplete-factorization path with drop tolerances, iterative refinement, ordering and parallel controls. These are specialized capabilities, not requirements for ordinary small TMB examples.

## Key terms

- **Fill-in:** Nonzero entries created during factorization of a sparse matrix in positions that were zero in the original.
- **Symbolic analysis:** The step that chooses or analyzes an elimination ordering and sparsity structure before numerical factorization.
- **CHOLMOD:** A sparse Cholesky library offered as an advanced `runSymbolicAnalysis` path whose availability and features depend on the package and system build.
- **Incomplete factorization:** An approximate factorization that drops small entries, which changes the solve and needs an accuracy policy such as iterative refinement.

### Worked case A: sparse precision still couples states

The companion builds a tridiagonal chain precision and compares solving a linear system with multiplying by an explicit inverse. The solutions agree on a tiny problem. For a large problem, explicitly constructing the inverse would often destroy the sparse memory advantage. Use solves for the quantities actually required.

Permutation reorders variables and equations consistently. If \(P\) is a permutation matrix, solve \((PQP^T)z=Pb\) and then recover \(x=P^Tz\). Reordering the matrix without reordering the right-hand side silently solves the wrong problem.

### Worked case B: dropping entries changes the solve

The companion drops an off-diagonal coupling and measures the residual under the original matrix. A small residual is a concrete linear-algebra diagnostic; a small change in a displayed coefficient alone can be misleading. In an iterative refinement scheme, tolerances and iteration limits control whether the approximate factor is adequate for the current solve.

For Laplace gradients, inaccurate sparse solves can affect both the latent mode and curvature derivatives. A fast approximate factorization should be compared with an exact small reference, then checked across difficult parameter regions, not only at a convenient initial point.

### Answered discussion

**Does sparse mean independent?** No. It often encodes conditional rather than marginal independence. **Can a drop tolerance be selected from a runtime target alone?** It also needs an error target tied to the resulting objective and gradient. **Is CHOLMOD always available with the same features?** No. Package/system builds and optional orderings differ. Report the actual prepared libraries and avoid claiming a specialized path ran merely because its function name exists.

See [runSymbolicAnalysis documentation](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The native course acceptance currently qualifies the ordinary sparse operations used by its small latent models, not every experimental factorization option.

### Worked case C: exact solve versus dropped coupling

The companion's precision has 3 on the diagonal and \(-0.7\) on both neighbors, a chain over four states. Its eigenvalues are \(3-1.4\cos(k\pi/5)\) for \(k=1,\dots,4\): 1.867376, 2.567376, 3.432624 and 4.132624, all positive, so a Cholesky factor exists. That factor is lower bidiagonal:

```text
L = [ 1.732051   0          0          0        ]
    [-0.404145   1.684241   0          0        ]
    [ 0         -0.415618   1.681446   0        ]
    [ 0          0         -0.416308   1.681276 ]   (closed-form values, rounded)
```

A tridiagonal matrix in natural chain order factors with no fill-in: every nonzero of \(L\) sits where \(Q\) already had one. The exact solution for \(b=(1,2,-1,0.5)\) is approximately \((0.509858, 0.756535, -0.124709, 0.137568)\). The explicit inverse, by contrast, is dense: all 16 entries are nonzero, which is the memory cost the guide warns about once the chain has thousands of states.

The diagonal-only approximation gives \(x_a=b/3=(0.333333,0.666667,-0.333333,0.166667)\). Under the original matrix its residual is \(Qx_a-b=(-0.466667,0,-0.583333,0.233333)\), so the companion prints a maximum residual of 0.583333 (hand-derived). The second entry happens to be zero because \(-0.7(1/3)-0.7(-1/3)=0\). A reviewer looking at only that coefficient would conclude that dropping the coupling was harmless. The maximum residual shows otherwise: it is more than half the size of the largest right-hand-side entry. The approximate solution for the third state even has the wrong magnitude by a factor of about 2.7 relative to the exact \(-0.124709\).

### The permutation check

The order \((4,2,1,3)\) scrambles the chain. The companion solves \(Q_{PP}z=b_P\) and writes each \(z_i\) back to position \(P_i\), which recovers the same \(x\) to \(10^{-12}\). A bug that permuted the matrix but passed the original \(b\) would instead solve a different system and return a vector with no error message. Under this ordering, a Cholesky factorization would also create fill-in, because states 1 and 2 are no longer adjacent in the elimination order. That is a small illustration of why ordering choices affect cost but must never change the answer.

### Where a drop tolerance would bite in a Laplace fit

In a latent model, the inner solve finds the mode \(\hat u\) and the outer objective uses \(\tfrac12\log|H|\). An incomplete factor affects both. The mode error behaves like the residual above, and the log determinant is the sum of \(2\log L_{ii}\) over the diagonal of the factor. For this chain, the exact sum is \(2\log(1.732051\cdot1.684241\cdot1.681446\cdot1.681276)=4.220\) (hand-derived), while the diagonal-only approximation gives \(4\log 3=4.394\). The log determinant is off by 0.175, so the objective's \(\tfrac12\log|H|\) term is off by 0.087. That error moves with the coupling strength, so it would bias any parameter that controls the \(-0.7\) entries.

### Base-R companion (runs in the classroom)

```r
Q <- diag(4) * 3;Q[row(Q) == col(Q) + 1 | row(Q) == col(Q) - 1] <- -.7;b <- c(1, 2, -1, .5)
x <- solve(Q, b);print(c(solve_residual = max(abs(Q %*% x - b)), inverse_difference = max(abs(x - solve(Q) %*% b))))
permutation <- c(4, 2, 1, 3);z <- solve(Q[permutation, permutation], b[permutation]);restored <- numeric(4);restored[permutation] <- z
stopifnot(max(abs(restored - x)) < 1e-12)
approximate <- diag(diag(Q));xa <- solve(approximate, b)
print(c(dropped_coupling_residual = max(abs(Q %*% xa - b))))
```
