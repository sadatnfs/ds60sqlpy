# js-055: Transitions, interruption and reduced-motion design

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-054`.

## Learning objectives

Animate updates with bounded, interruptible transitions that await completion and respect reduced motion. The central exercise is: Implement a bounded transition with completion checks.

## Purpose, vocabulary and mental model

A transition changes attributes over time rather than setting the final state immediately. Interpolation computes intermediate values, while easing controls the pace along the timeline. Motion can help a reader follow identity through a change, but it can also distract, delay access or imply a continuous process that the data does not represent.

Transitions are asynchronous. Starting one does not mean its final geometry exists on the next line. A newer update may interrupt an earlier transition, so a component must decide whether to finish, replace or cancel work. Awaiting a transition’s completion can reject when it is interrupted; handling that rejection is part of lifecycle correctness.

Reduced-motion preferences should lead to a useful static or immediate update. Do not make animation the only way to discover a value or state change. The reference uses a short bounded transition, respects the media preference and checks the final state after completion.

### Key terms

- **Transition:** A D3 object created with `selection.transition()` that moves attributes from their current values to targets over a duration instead of setting them immediately.
- **Interpolation:** Computing intermediate values between a start state and an end state, while easing controls the pace along the timeline.
- **Interruption:** Cancelling an active transition, either with `.interrupt(name)` or by starting a newer transition with the same name on the element. The interrupted transition's `.end()` promise rejects.
- **Reduced motion:** The user preference reported by `matchMedia('(prefers-reduced-motion: reduce)')`, which should lead to an immediate or static update rather than animation.

## Syntax anatomy and mechanism

Name transitions when a component needs a clear interruption channel. Call `.interrupt(name)` before replacing obsolete work. A named transition’s `.end()` returns a promise for completion. The final data state should be stored independently of a partly animated attribute.

For deterministic testing, assert the final value after awaiting the promise, not after guessing a sleep duration. Timing varies across machines and background tabs. The reference does not run an infinite animation loop.

## Worked example / walkthrough

### Worked example 1: Await the actual completion

This snippet creates its own mark, then awaits the named transition's end.

```javascript
const svg = d3.select("#chart").append("svg").attr("viewBox", "0 0 640 360");
const mark = svg.append("circle").attr("cx", 80).attr("cy", 180).attr("r", 20);
await mark.transition("update").duration(120).attr("cx", 300).end();
console.log(mark.attr("cx"));
```

**Expected observation:** 300 after successful completion, rather than an intermediate coordinate.

### Worked example 2: Respect reduced motion

The data update still happens; only its animation depends on the user's preference.

```javascript
// js-055 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Transitions, interruption and reduced-motion design")
  .style("width", "100%")
  .style("max-width", "640px");
const reduced = matchMedia("(prefers-reduced-motion: reduce)").matches;
const mark = svg
  .append("circle")
  .attr("cx", 320)
  .attr("cy", 180)
  .attr("r", 12)
  .attr("fill", "#7c3aed");
await mark
  .transition("grow")
  .duration(reduced ? 0 : 120)
  .attr("r", 48)
  .end();
svg
  .append("text")
  .attr("x", 40)
  .attr("y", 320)
  .text(reduced ? "Reduced motion: updated without animation" : "Animated for 120 ms");
check(+mark.attr("r") === 48, "Both paths must reach the same final radius");
output.textContent = "js-055 worked example 2 complete";
```

**Expected observation:** The circle ends with radius 48 either way; with reduced motion requested it changes at once and the caption says so.

## Six progressive exercises

### Exercise 1: Predict an attribute read immediately after starting a transition.

**Expected evidence:** It can still be the initial or intermediate value.

**Progressive hint:** Starting asynchronous work is not completion.

### Exercise 2: Set duration to zero under reduced motion.

**Expected evidence:** The final value remains available without movement.

**Progressive hint:** Accessibility should preserve information and control, not remove the update entirely.

### Exercise 3: Implement a bounded transition with completion checks.

**Expected evidence:** Final geometry is asserted only after the transition ends.

**Progressive hint:** A guessed timeout can be flaky under load.

### Exercise 4: Diagnose a rejected end promise after a new update.

**Expected evidence:** The earlier transition may have been interrupted.

**Progressive hint:** Interruption is a meaningful lifecycle result.

### Exercise 5: Replace an obsolete transition by name.

**Expected evidence:** Only the component-owned update channel is interrupted.

**Progressive hint:** Named ownership avoids canceling unrelated animations.

### Exercise 6: Defend when to use a static update.

**Expected evidence:** Prefer immediate clarity when motion adds no explanatory value.

**Progressive hint:** Animation is a design choice, not a requirement of a polished chart.

## Debugging and common mistakes

If a final-coordinate check fails, read the attribute only after `await transition.end()`; reading right after starting returns the initial or an intermediate value. That promise rejects when a newer transition interrupts the old one, so catch the rejection where a replacement is expected. Name transitions so `interrupt` stops only the component's own channel. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a rejected end promise after a new update. Distinguishing evidence: The earlier transition may have been interrupted.

## Accessibility and interpretation

Check `matchMedia('(prefers-reduced-motion: reduce)')` and use a zero duration when it matches, so the final state appears at once. Motion should never be the only cue: a caption or label should state the new value, and animations should finish quickly enough not to delay keyboard users. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Animation can suggest a path between two states that the data never visited. Growing a bar from 10 to 50 is harmless, but interpolating between unrelated categories or reordered entities implies a false continuity. Use a static update when motion adds no explanation, and keep the final values identical either way. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
