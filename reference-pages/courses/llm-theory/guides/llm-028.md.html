llm-028: Capstone: train and audit a tiny transformer#

Level and prerequisites#

Intermediate; approximately 240 minutes. Direct prerequisites: llm-027. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Defend a bounded local training run with a frozen corpus and diagnostic evidence. The central investigation is concrete: Train a decoder with fewer than 50000 parameters, context at most 32 and at most 200 updates; compare held-out loss with the count baseline and submit failure analysis. The finish condition is Tokenizer/split/model hashes, masks, loss denominator, seed/profile and exact step count are recorded. Any quality conclusion names the held-out unit and uncertainty. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Treat a tiny training run as a complete experiment#

The earlier chapters built the pieces of a decoder and explained how to inspect their shapes, losses and cache behavior. This capstone puts those pieces into one bounded experiment. Its purpose is to make a whole training-and-evaluation workflow understandable, including the possibility that the neural model does not beat a simple baseline. A completed optimizer loop is an observation about computation; an improvement on a frozen holdout is an observation about that particular prediction problem.

The authored training documents are[1,2,3,4] and[1,2,4,3]. The held-out document is[1,3,2,4]. Token IDs come from a fixed vocabulary of size 16. Each length-four document supplies three next-token targets, so the training batch contains six target events and the holdout contains three. There is no implicit EOS target in this fixture. These counts define the loss denominator and the count model's transition observations.

Follow the forward path from IDs to logits#

The training input batch has shape(2,3): the first three IDs from each document. Labels are the last three IDs, also shaped(2,3). A token embedding and learned position embedding each contribute width 32 features, producing a hidden array shaped(2,3,32). Adding them combines lexical identity and position at the same token coordinates; it does not concatenate them into width 64.

The first LayerNorm acts over each token's 32 features. A single bias-free QKV projection maps width 32 to width 96, then splits into three width 32 arrays. With two heads, each head has width 16. Reshaping and transposing gives Q,K,V shapes(2,2,3,16): batch, head, token, head-feature. The score array is(2,2,3,3), and its lower-triangular access rule prevents a query from using later input positions.

The weighted values return to shape(2,3,32), pass through an output projection and join the first residual path. A second LayerNorm and a feed-forward transformation 32→64→32 form the second residual branch. The final vocabulary projection produces logits shaped(2,3,16). These are unnormalized scores for each next-token target. Flattening to(6,16) and flattening labels to(6,) merely presents the same six events to cross entropy; it does not create six independent documents.

This shape trace also gives a parameter audit. Token embeddings contribute 1632=512 entries and position embeddings 3232=1024. Two LayerNorms each have 32 gains and 32 biases, totaling 128. QKV contributes 3296=3072 and its output projection 3232=1024. The feed-forward layers contribute 3264+64 plus 6432+32, totaling 4192. The vocabulary projection contributes 32*16=512. Altogether the model has 10,464 parameters under the exact bias choices in the reference, comfortably below the declared 50,000 cap. The count is a structural fact, not a claim that the model has enough data to estimate all those parameters reliably.

Understand what one optimizer step changes#

Every update clears previous gradients, computes logits on the same six training targets, forms mean cross entropy, differentiates that scalar, and applies an Adam update. The loop performs 20 such updates. Because the dataset is tiny, these updates repeatedly revisit the same authored transitions. Repeated exposure can reduce training loss without adding new information about unseen document families.

The loss stored in curve is computed before that iteration's parameter update. The final recorded curve point therefore describes the parameters entering the twentieth step, while a later evaluation uses parameters after it. This distinction matters when reproducing an exact training trace. The test requires 20 finite values and the parameter bound; it does not require a particular monotonic curve or claim that every update improves the loss.

The seed fixes initialization for this runtime's random-number sequence. It helps reproduce the small experiment, but one seed does not establish robustness across initializations or implementations. Optimizer version, dtype, operation order and platform can matter to exact numeric output. For the lesson's conclusion, retain the runtime and source identity with the measured losses rather than turning a seed into a universal reproducibility guarantee.

Reconstruct the count baseline independently#

The count model observes transitions within each training document. Token 1 is followed by 2 twice. Token 2 is followed by 3 once and 4 once. Token 3 is followed by 4 once, and token 4 is followed by 3 once. These six observations match the target count. No transition is invented between the end of one document and the start of another.

Add-one smoothing over 16 candidates gives P(v|u)=(C_uv+1)/(C_u+16). The held-out path contains 1→3,3→2 and 2→4. Their probabilities are 1/18,1/17 and 2/18=1/9. The baseline's held-out mean negative log likelihood is therefore[log(18)+log(17)+log(9)]/3=log(2754)/3, approximately 2.6403 nats per target. This number can be derived without training a neural network, making it a useful independent oracle for the evaluation pipeline.

Why can a uniform predictor over 16 candidates have loss log(16)≈2.7726 while this smoothed model is slightly better on the holdout despite missing two transitions? The known 2→4 transition receives probability 1/9, above the uniform 1/16. That improvement partly compensates for the two unseen transitions receiving smaller probabilities. This is a concrete example of an aggregate log score combining benefits and failures rather than simply counting how many transitions were previously observed.

Score the same target events under both models#

The neural model receives[1,3,2] as context positions and predicts[3,2,4]. Evaluation mode and no-grad prevent the scoring call from intentionally performing a training update or retaining a backward graph. The mean is over exactly three targets. The count baseline scores the same transitions. This alignment matters more than the fact that both results are called "loss."

A fair comparison also keeps preprocessing, vocabulary, target inclusion and holdout identity fixed. If the baseline were allowed to fit the held-out transitions, or the neural model were scored only on an easy subset, the resulting numbers would answer different questions. Likewise, choosing the 20-update budget after repeatedly viewing this final holdout would use it for model selection. In the authored demonstration, the budget is fixed beforehand.

The reference asserts that both held-out losses are finite. It deliberately does not assert that the neural loss is lower. A model with more parameters and a more expressive architecture can overfit, optimize poorly, or fail to generalize from two tiny documents. Reporting that outcome accurately is a successful experiment, not an error to repair by adding the holdout to training.

Retest the information boundary after fitting#

Parameter updates should change learned preferences while preserving the causal access rule. The capstone recomputes the first two positions separately and compares their logits with the corresponding prefix of the full input. Agreement within the stated tolerance supports prefix invariance for the trained model and checked sequence. It is different evidence from the holdout loss.

A model can pass this causal test and still have seen the evaluation answers during data construction. It can also have a valid split but an incorrect loss denominator. Use independent checks for independent failure modes: transition counts and label shifting for the scoring contract, family identities for the split, prefix recomputation for information flow, and actual held-out losses for the measured comparison. One passing assertion should not stand in for all four.

Read hashes as identities, not endorsements#

The split hash records the serialized partition mapping. The model hash records parameter bytes under the known code and ordering used by this fixture. A matching hash helps identify which artifact was evaluated. It does not authenticate a publisher, prove that the split is independent, or show that a metric was computed correctly. A reusable production artifact would also need architecture, tokenizer, names, shapes, dtypes and relevant version/configuration information bound into its identity.

Vocabulary and concepts#

Capstone evidence: A combined record of mechanics, data lineage and held-out observations.

Count baseline: A smoothed transition model fitted on the same training data.

Frozen test: Assessment data excluded from model and prompt selection.

Syntax anatomy and reasoning sequence#

Use the provided TinyDecoder with seed11. Train on shifted local sequences for exactly20 updates. Count bigram transitions without crossing document boundaries, apply add-one smoothing and evaluate the same held-out pairs. Hash canonical integer sequences and detached model parameter bytes separately. Open the heldout split only after freezing the update budget and model choice.

Compare models under one frozen prediction task#

The two training sequences create six within-document next-token events. Their count baseline observes 1 to 2 twice, and 2 to 3, 3 to 4, 2 to 4, 4 to 3 once each. Add-one smoothing uses the same sixteen-token vocabulary as the neural model, so every row denominator includes sixteen pseudocounts. Changing that vocabulary would change the baseline and the comparison.

The held-out sequence [1, 3, 2, 4] has three events. The smoothed probabilities are 1/18 for 1 to 3, 1/17 for 3 to 2, and 1/9 for 2 to 4. Its baseline mean loss is (log(18)+log(17)+log(9))/3, approximately 2.640270. The neural score is measured from the trained model after its twenty updates. The reference intentionally does not require the neural model to beat the baseline; a fair comparison can reveal that a simpler method is adequate or that more investigation is needed.

The training curve stores pre-update objectives, while the held-out score is computed afterward in evaluation mode without gradient recording. These values describe different states and data. A lower training loss is not itself a better held-out result. Rechecking causal prefixes after training confirms that updating weights did not invalidate the declared information boundary, but does not substitute for contamination checks.

Bind the report to its actual artifacts#

The split digest identifies the recorded assignment dictionary. The parameter digest hashes the ordered parameter bytes under this known architecture. A robust reusable artifact manifest would additionally bind parameter names, shapes, dtypes, model configuration, corpus contents, tokenizer and software versions. A hash does not establish that an unlabeled sequence of bytes can reconstruct a model without those contracts.

The holdout contains one authored document and three correlated token predictions. Three targets are the loss denominator, not necessarily three independent experimental units for uncertainty estimation. The capstone therefore produces a reproducible small-model decision record rather than a production-quality claim. Preserve both model scores, the active count, the trained state identity, the split policy and a clear statement of what remains untested. A no-go conclusion is informative when it follows from those observations rather than from a preferred model narrative.

Worked example / walkthrough#

Example A: Freeze corpus identity#

The literal corpus prevents hidden downloads and makes every target visible. Document identity is separate from token identity because repeated tokens are expected across splits.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context
        self.token=nn.Embedding(vocab,width); self.position=nn.Embedding(context,width)
        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)
    def forward(self,ids,cache=None):
        if ids.ndim!=2 or ids.dtype!=torch.long or ids.shape[1]==0: raise ValueError('nonempty long batch,time IDs')
        offset=0 if cache is None else cache['k'].shape[2]
        batch,time=ids.shape
        if offset+time>self.context or torch.any(ids<0) or torch.any(ids>=self.vocab): raise ValueError('context or vocabulary limit')
        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)
        def split(t): return t.reshape(batch,time,self.heads,self.width//self.heads).transpose(1,2)
        q,k,v=map(split,(q,k,v))
        if cache is not None:
            if cache['k'].shape[0]!=batch: raise ValueError('cache batch mismatch')
            k=torch.cat([cache['k'],k],dim=2); v=torch.cat([cache['v'],v],dim=2)
        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]
        scores=q@k.transpose(-2,-1)/(self.width//self.heads)**.5
        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)
        mixed=(weights@v).transpose(1,2).contiguous().reshape(batch,time,self.width)
        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))
        return self.output(x),{'k':k.detach(),'v':v.detach()}
import hashlib,json
docs=[[1,2,3,4],[1,2,4,3]]; held=[1,3,2,4]; split={'train':['a','b'],'test':['c']}; digest=hashlib.sha256(json.dumps(split,sort_keys=True).encode()).hexdigest()
assert len(docs)==2 and len(held)-1==3 and len(digest)==64

Expected: train2 documents;holdout1;context3.

Example B: Train a bounded decoder#

The budget and architecture are fixed before held-out evaluation. Training loss is retained as diagnostic evidence rather than a substitute for a test score.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
class TinyDecoder(nn.Module):
    def __init__(self,vocab=16,width=32,heads=2,context=32):
        super().__init__()
        self.vocab,self.width,self.heads,self.context=vocab,width,heads,context

        self.norm1=nn.LayerNorm(width); self.qkv=nn.Linear(width,3*width,bias=False)
        self.projection=nn.Linear(width,width,bias=False); self.norm2=nn.LayerNorm(width)
        self.feed=nn.Sequential(nn.Linear(width,2*width),nn.ReLU(),nn.Linear(2*width,width))
        self.output=nn.Linear(width,vocab,bias=False)

        x=self.token(ids)+self.position(torch.arange(offset,offset+time))
        q,k,v=self.qkv(self.norm1(x)).chunk(3,dim=-1)

        q,k,v=map(split,(q,k,v))
        if cache is not None:

        allowed=torch.arange(k.shape[2])[None,:]<=torch.arange(offset,offset+time)[:,None]

        weights=torch.softmax(scores.masked_fill(~allowed,float('-inf')),dim=-1)

        x=x+self.projection(mixed); x=x+self.feed(self.norm2(x))

import hashlib,json
docs=[[1,2,3,4],[1,2,4,3]]; held=[1,3,2,4]; split={'train':['a','b'],'test':['c']}; digest=hashlib.sha256(json.dumps(split,sort_keys=True).encode()).hexdigest()
assert len(docs)==2 and len(held)-1==3 and len(digest)==64
torch.manual_seed(11); model=TinyDecoder(); opt=torch.optim.Adam(model.parameters(),lr=.01); batch=torch.tensor(docs); curve=[]
for _ in range(20):
    opt.zero_grad(set_to_none=True); logits,_=model(batch[:,:-1]); loss=F.cross_entropy(logits.reshape(-1,16),batch[:,1:].reshape(-1)); loss.backward(); opt.step(); curve.append(loss.item())
assert len(curve)==20 and np.isfinite(curve).all() and sum(p.numel() for p in model.parameters())<50000

Common pitfalls and diagnosis#

Verify document boundaries and the common vocabulary before comparing baseline and neural scores. Keep pre-update training points separate from post-training held-out evaluation. Bind hashes to their actual scope, and report the one-document holdout limitation rather than treating three token targets as three independent studies.
