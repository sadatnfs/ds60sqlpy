# go-007: Strings, bytes, runes and Unicode boundaries

## Level and prerequisites

Beginner. Allow about 90 minutes, then revisit the transfer case later. Prerequisites: go-006

## Learning objectives

Count and slice text by bytes or runes deliberately and reject malformed UTF-8 instead of guessing. Along the way, explain byte, rune, utf-8; implement the six investigations below; and defend the expected result of a changed input before running it.

## Why this mechanism matters

A Go string is an immutable sequence of bytes, not necessarily valid Unicode text. Source string literals are commonly UTF-8, but strings can contain arbitrary bytes. Indexing a string returns one byte. Ranging over a string decodes runes, which are Unicode code points; malformed encodings produce replacement runes. A user-perceived character can contain multiple code points, such as a letter plus combining accent. Byte length, rune count and displayed-character count therefore answer different questions. Choose a unit before slicing, counting or truncating text. Immutability protects a string value, while conversion to a mutable byte slice creates a separate editing representation.

## Vocabulary and concepts

- **Byte:** An eight-bit storage unit.
- **Rune:** Go alias for int32, commonly representing a Unicode code point.
- **UTF-8:** A variable-width encoding of Unicode code points.

## Syntax anatomy and reasoning

len(text) counts bytes. []byte(text) and []rune(text) choose different element units. utf8.RuneCountInString counts decoded code points, while utf8.ValidString checks encoding validity. strings.TrimSpace removes surrounding Unicode whitespace and returns a string. A rune literal uses single quotes and has a numeric code-point value; a string literal uses double quotes.

## Worked example / walkthrough

### Worked example 1: Count two units

Inspect A followed by a smiling face.

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Count two units
	{
		text := "A🙂"
		check(len(text) == 5 && utf8.RuneCountInString(text) == 2, "text units")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** There are 5 bytes and 2 runes.

The ASCII letter occupies one byte and this emoji occupies four. Neither count is a general grapheme-cluster algorithm.

### Worked example 2: Edit a copied byte slice

Convert cat to bytes, replace c with b and retain the original.

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Count two units
	{
		text := "A🙂"
		check(len(text) == 5 && utf8.RuneCountInString(text) == 2, "text units")
	}

	// Edit a copied byte slice
	{
		original := "cat"
		data := []byte(original)
		data[0] = 'b'
		check(original == "cat" && string(data) == "bat", "copy edit")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The original is cat and the new string is bat.

The mutable byte slice provides an explicit editing boundary. This example uses ASCII so replacing one byte does not split a multibyte encoding.

## Common pitfalls and diagnosis

Treating `len(s)` as a character count, or slicing a string at a byte index, works on ASCII test data and breaks on the first emoji or accented name. Choose the unit first: bytes for storage and protocols, runes for code points, and a segmentation library for user-perceived characters. Remember also that a string can hold invalid UTF-8, so validate input instead of assuming the encoding.

## Progressive hints

### Hint for investigation 1: Count two units: change one input

1. Restate the expected observation: There are 5 bytes and 2 runes.
2. UTF-8 uses one byte for A and four for this emoji. Which function counts runes instead of bytes?
3. Adding ! adds one byte and one rune, so `len(text)` is 6 and `len(text)==5` fails first. The units are still counted correctly; the text changed.

### Hint for investigation 2: Edit a copied byte slice: debug a regression

1. Restate the expected observation: The original is cat and the new string is bat.
2. `[]byte(original)` copies the bytes. Does changing `data[0]` reach the original string?
3. The edit writes `data[1]`, producing cbt instead of bat. The copy still protects original; restore index 0 so the first byte changes.

### Hint for investigation 3: Reject malformed encoding

1. Restate the expected observation: UTF-8 validation returns false.
2. 0xff can never begin a valid UTF-8 sequence. Which utf8 function reports that?
3. A string can exist without being valid UTF-8.

### Hint for investigation 4: Slice by rune position

1. Restate the expected observation: The resulting string is the intact emoji.
2. Converting to `[]rune` decodes code points. What does `r[1:]` hold when r has two elements?
3. The conversion makes code-point indexing explicit.

### Hint for investigation 5: Separate combining forms

1. Restate the expected observation: There are 2 runes even though it can display as one character.
2. \u0301 is its own combining code point. How many runes does the string contain?
3. A code point is not always a complete displayed character.

### Hint for investigation 6: Transfer a whitespace policy
