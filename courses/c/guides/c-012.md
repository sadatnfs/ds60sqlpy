# c-012: Const-correct views and mutation boundaries

## Purpose and mental model

const describes permitted access through a type-qualified expression. A pointer to const int prevents modifying the target through that pointer, while a const pointer prevents changing which target the pointer designates. These are different guarantees. A mutable object can be observed through a const view and changed through another valid mutable path. An object originally defined const must not be modified by casting away qualification. Const-correct APIs communicate read-only intent and let callers pass immutable data safely, but they do not automatically provide deep immutability, ownership or synchronization.

## Vocabulary and concepts

- **Const-qualified view:** An access path that forbids mutation through that path.
- **Const pointer:** A pointer object that cannot be reassigned after initialization.
- **Deep immutability:** A policy preventing mutation throughout a reachable object graph.

## Syntax anatomy and execution trace

const int *p reads as a pointer to a const-qualified int. int *const p is a const pointer to a mutable int. const int *const p combines both restrictions. Function parameters can use const for borrowed read-only arrays. A struct containing a pointer can still reference mutable storage even if the outer struct is accessed through a const pointer; deep ownership requires a broader design.

## Worked example / walkthrough

### Worked example 1: Read through a const view

Observe a mutable integer through const int pointer.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int read_sum(const int *values, size_t n) {
  int sum = 0;
  for (size_t i = 0; i < n; i++)
    sum += values[i];
  return sum;
}

int main(void) {
  /* Read through a const view */
  {
    int value = 4;
    const int *view = &value;
    CHECK(*view == 4);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The read yields 4.

The view is read-only, but the underlying object was not defined const.

### Worked example 2: Observe another valid mutation

Change the mutable object through its original name.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

int read_sum(const int *values, size_t n) {
  int sum = 0;
  for (size_t i = 0; i < n; i++)
    sum += values[i];
  return sum;
}

int main(void) {
  /* Read through a const view */
  {
    int value = 4;
    const int *view = &value;
    CHECK(*view == 4);
  }

  /* Observe another valid mutation */
  {
    int value = 4;
    const int *view = &value;
    value = 7;
    CHECK(*view == 7);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The const view now reads 7.

Const access does not freeze a shared mutable object or create a snapshot.

### Exercise 1: Read through a const view: change one input

In worked example 1, change `int value = 4;` to `int value = 5;`. Predict which value the CHECK on `*view == 4` sees, then run and restore.

**Expected:** `Check failed` at `*view == 4`; restoring `int value = 4;` passes again.

**Verify:** Name the value that made `*view == 4` false, where worked example 1 showed that the read yields 4.

**Progressive hints:** First trace `view` from initialization. Then compute what the CHECK sees with `int value = 5;` in place.

### Exercise 2: Observe another valid mutation: debug a regression

Worked example 2 now has a line reading `value = 8;`. Repair it so that the const view now reads 7 again.

**Expected:** `Check failed` at `*view == 7` until the line reads `value = 7;` again.

**Verify:** Explain how `value = 8;` changes the value `*view == 7` tests, using your failing and repaired runs.

**Progressive hints:** First trace `view` from initialization. Then compare `value = 8;` with worked example 2's original line.

### Exercise 3: Use a fixed pointer target

Create an int pointer that cannot be reassigned, then update its target.

**Expected:** The target becomes 8.

**Verify:** Keep a CHECK equivalent to `value == 8`. Control edit: changing `*fixed = 8;` to `*fixed = 9;` must fail it; then restore it.

**Progressive hints:** First trace `value` from initialization. Then recall: The pointer object is fixed while the designated int remains writable.

### Exercise 4: Read an immutable object

Declare a const integer and access it through a const pointer.

**Expected:** The value is 9.

**Verify:** Keep a CHECK equivalent to `*p == 9`. Control edit: changing `const int value = 9;` to `const int value = 10;` must fail it; then restore it.

**Progressive hints:** First trace `p` from initialization. Then recall: No cast is used to bypass the qualification.

### Exercise 5: Pass a read-only array contract

Sum a const array using a const pointer parameter.

**Expected:** The sum is 6.

**Verify:** Keep a CHECK equivalent to `read_sum(values, 3) == 6`. Control edit: changing `const int values[] = {1, 2, 3};` to `const int values[] = {2, 2, 3};` must fail it; then restore it.

**Progressive hints:** First trace `values` from initialization. Then recall: A read-only parameter accepts both const and mutable inputs while promising not to change elements through that path.

### Exercise 6: Transfer snapshot independence

Copy the scalar observed through a const view and then mutate the original.

**Expected:** The snapshot remains 2 while the view reads 5.

**Verify:** Keep a CHECK equivalent to `snapshot == 2 && *view == 5`. Control edit: changing `int value = 2;` to `int value = 3;` must fail it; then restore it.

**Progressive hints:** First trace `snapshot` and `view` from initialization. Then recall: A value copy establishes an independent snapshot; qualification alone does not.

## Common pitfalls and diagnosis

Assuming `const int *p` makes the target immutable everywhere: it only forbids writes through `p`, so another non-const path may still change the value. Casting away `const` to write an object defined `const` is undefined.
