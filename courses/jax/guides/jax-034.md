# jax-034: Optional kernels, FFI and an independent engineering review

## Starting point and outcome

Advanced. Direct prerequisites: `jax-033`

Decide when a lower-level extension is justified and specify the numerical, transformation and hardware evidence it must produce.


## Mechanism and purpose

A high-level JAX expression is often the clearest implementation of a numerical operation. A custom kernel or foreign-function interface can be justified when a measured limitation or external capability requires it. The decision should start with an observed problem and a correct baseline, not the assumption that lower-level code is automatically faster.

Pallas and FFI expose additional contracts: layouts, memory ownership, indexing, synchronization, supported devices, compiler/runtime versions and transformation rules. An operation with correct forward values may still have an incorrect gradient, incompatible batching behavior or unsafe handling of noncontiguous inputs. These are separate acceptance questions.

A custom derivative must correspond to the implemented mathematical function and its domain. For an affine operation y=ax+b, an input derivative of one is wrong when a is three, even if the forward result passes. Non-unit upstream sensitivities are important because a backward rule that returns only the local derivative can miss the chain-rule multiplier.

Performance qualification follows correctness. Compare completed equivalent work, include required transfers and account for allocation or launch overhead. Profile actual supported hardware rather than borrowing timings from another system. A CPU oracle can validate mathematics; it cannot qualify a GPU kernel's memory behavior, race freedom or device recovery.

The final review also integrates the rest of the course. A numerical component should have a shape/dtype/domain contract, explicit state and key policy, independent derivatives, transformation checks, bounded runtime evidence and an interpretation proportional to that evidence. An advanced learner should be able to identify which layer failed and propose a discriminating next observation.

## Key terms

- **Pallas:** The JAX extension for writing custom kernels with explicit control over memory access and indexing on supported devices.
- **FFI:** The foreign function interface that lets JAX call compiled external code under a declared buffer, layout and device contract.
- **Memory layout:** The order and strides in which array elements are stored, which a kernel must handle explicitly, including noncontiguous inputs.
- **Backward rule:** The derivative a custom operation supplies, which must scale the upstream gradient, such as a times G for y = ax + b.
- **Reference baseline:** A trusted high-level implementation kept as the oracle for values, gradients and a fair performance comparison.

## Derivation and shape contract

For \(Y=AX+B\) with scalar A=a, \(\partial L/\partial X=aG\), where \(G=\partial L/\partial Y\). At a=3 and G=4, the input gradient is 12, not three or one. For matrix operations, orientation and layout must be translated explicitly. A forward-only comparison cannot establish the derivative or memory-access contract.

## Worked investigations

### Worked example 1: Review a proposed custom operator

A hypothetical affine GPU operator returns correct values for contiguous float32 inputs but has no backward or stride tests. Assess its status.

The correct observed case should be retained without extending its claim to untested interfaces.

**Expected:** One narrow forward case only; derivative, layout, dtype and broader execution remain unqualified.

**Review table:** forward contiguous float32 observed; noncontiguous input untested; dtype rejection untested; gradient untested; synchronization/error handling untested; performance unmeasured.

**Evidence record sketch:**

```text
custom affine operator review
forward, contiguous float32 ...... observed correct
forward, transposed input ........ untested
unsupported dtype rejection ...... untested
backward rule .................... untested
synchronization and errors ....... untested
performance ...................... unmeasured
current claim .................... one narrow forward case
```

### Worked example 2: Find a backward-rule defect

For y=3x+1, a custom backward returns the incoming cotangent unchanged. Test incoming cotangent four.

The backward omitted the local derivative three. A unit or identity-scale fixture could hide the defect.

**Expected:** Expected input sensitivity 12; returned four is incorrect.

**Independent calculation:** local derivative three times upstream four equals twelve. Repeat with a changed scale and non-unit upstream value before considering a kernel implementation.

**Evidence record sketch:**

```text
backward rule check for y = 3x + 1
local derivative dy/dx ........... 3
incoming cotangent ............... 4
required input cotangent ......... 3 * 4 = 12
defective rule returns ........... 4, the cotangent unchanged
why unit fixtures hide it ........ cotangent 1 and scale 1 give equal answers
next fixture ..................... change the scale and use a non-unit cotangent
```

## Exercises

### Exercise 1: Justify the extension

List evidence needed before replacing a correct high-level operation with a custom kernel.

**Expected:** A measured limitation, equivalent work definition, supported target and independent numerical oracle.

**Verify:** Complexity is justified by a concrete benefit and an acceptance plan, not by the API's lower level.

**Hint:** Measure before choosing the optimization.

### Exercise 2: Define input layout

Specify how an operator handles transposed or strided inputs.

**Expected:** Either correct support or an explicit validated refusal/copy policy.

**Verify:** A shape alone does not describe memory layout. Silently assuming contiguity can return wrong values or access invalid memory.

**Hint:** Translate both dimensions and strides.

### Exercise 3: Qualify transformation composition

A custom operation has a VJP. Decide whether JVP, vmap and higher derivatives are automatically accepted.

**Expected:** No; each required transformation needs its own supported rule and evidence.

**Verify:** A valid reverse rule does not imply every other transformation mode is implemented.

**Hint:** Use the custom_jvp/custom_vjp distinction from jax-022.

### Exercise 4: Design a fair kernel benchmark

Compare a fused operator with a sequence of high-level operations.

**Expected:** Matched inputs/outputs, synchronization, warmup, transfers, allocation policy and actual hardware identity.

**Verify:** A faster dispatch-only measurement or omitted transfer is not a valid completed-work speedup.

**Hint:** Ensure fusion has not changed the requested result or precision.

### Exercise 5: Preserve a CPU oracle

A GPU backend is unavailable. Define what useful work can still be completed.

**Expected:** Mathematical derivation, small CPU reference, interface review and planned failure cases, with GPU acceptance pending.

**Verify:** Unavailable hardware limits execution evidence but does not prevent rigorous source and numerical preparation.

**Hint:** Keep missing evidence explicit without discarding completed analysis.

### Exercise 6: Defend the final result

Prepare a concise review of an independently built JAX component using the course's evidence layers.

**Expected:** A reproducible artifact and argument covering purpose, assumptions, source, tests, runtime observations, limits and unresolved risks.

**Verify:** The reviewer should be able to challenge a concrete claim and identify the observation supporting it. A lesson-completion count is not the evidence.

**Hint:** Demonstrate transfer and judgment rather than repeating the reference.

## Diagnosis and boundaries

Do not advertise unsupported dtype/layout/transform combinations. A successful source build is not device correctness, and a correct value is not a valid backward rule. Preserve resource ownership and the high-level oracle throughout optimization.

## Transfer and review

Select one optional extension only after identifying an actual need. Produce a scoped design and qualification matrix before preparing the external toolchain. The default JAX CPU course remains complete without custom kernels, paid services or accelerator access.
