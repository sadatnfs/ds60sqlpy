# Tutorial source ownership

`units.json` owns stable IDs, prerequisites and runtime contracts. `chapters/` owns original teaching prose; `programs/` owns complete executable examples. Edit those sources, then run `python courses/applied-science/authoring/build.py` and its `--check` mode. The builder does not execute code. Guides embed the exact complete program, and every admitted source is standalone. Each unit's `key_terms` object lists three to five lesson-specific terms with one- or two-sentence definitions; the builder validates them and renders a `## Key terms` section before the first worked case.

Do not edit generated guides, examples, track.json, lessons.json or the course README directly. Preserve existing IDs and program/data meaning when formatting. Keep all answers visible in tutorial mode. Independent numerical and runtime checks remain separate from generated-byte checks. Shared TeX/readers and runtime registration belong to the integration owner.

Each unit's `worked_examples` list holds one or more objects with `title`, `language`, `code`, an optional `output` and an `interpretation`. The code is a short snippet that was actually executed, `output` is its observed stdout copied verbatim, and the interpretation reads specific values from that output. The builder requires every field except `output` to be non-empty, rejects em and en dashes, requires titles, code and interpretations to be unique across the track, and requires at least two treatments per lesson counting the chapter's worked cases. It renders each entry as a `## Worked example:` section after the chapter prose and before the complete program. Rerun a snippet and update its `output` whenever its code changes; never edit output by hand.
