# MakeADFun maps, profiles and safe data changes

Start with: tmb-025, tmb-004, tmb-014.

Outcome: Explain which construction options change parameter dimension, target or recorded operations.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

`MakeADFun` is the central construction API. `data` supplies observations and fixed inputs; `parameters` supplies named coordinates and shapes. `map` fixes or ties components. `random` asks for latent integration, normally using Laplace approximation. `profile` profiles selected nuisance components without the corresponding Laplace volume correction. These switches do not merely tune speed: some change the inferential target.

A profile likelihood at a fixed target value minimizes over nuisance parameters. A marginal likelihood integrates over latent variables with their specified density. Both may call an inner optimizer, but their mathematical results differ.

### Worked case A: fixed and tied coordinates

A vector \(\beta=(\beta_1,\beta_2,\beta_3)\) mapped with `factor(c(1,1,NA))` has one free coordinate: the first two components are tied and the third stays at its supplied value. The companion reconstructs this rule explicitly. In a direct native construction:

```r
obj <- TMB::MakeADFun(data, parameters,
  map = list(beta = factor(c(1, 1, NA))),
  DLL = "reviewed_model"
)
names(obj$par)
```

Check the resulting `par` rather than sending a vector with the old dimension. A tied intercept and slope would generally be an odd scientific assumption even if the code allows it.

### Worked case B: changing data and reconstructing the objective

If a data value changes from positive to negative and controls a C++ branch, recorded operations may change. Changing vector length or category count changes shapes too. The safe public workflow is to construct a fresh objective from the new validated data and current intended parameter starts. The companion shows that two equal-length datasets still have different objective values and identities.

Internal object-environment helpers such as retaping are implementation details, not separately exported public APIs in this pinned namespace. Do not build a stable classroom feature around undocumented mutation of `obj$env$data` or an assumed tape cache. If a specialized workflow deliberately uses internals, pin the source version and test changed values, shapes and branches separately.

### Answered discussion

**Can `checkParameterOrder=FALSE` fix mismatched names?** Suppressing a check does not repair the model contract. **Does `hessian=TRUE` mean every latent/Hessian mode is interchangeable?** No; derivative availability depends on construction and framework. **Can profiling a latent variable replace integrating it?** Only if that different target is what the analysis intends. Keep the distinction in result labels and comparisons.

The [MakeADFun manual](https://cran.r-project.org/web/packages/TMB/TMB.pdf) includes `atomic`, `ADreport`, `intern`, `integrate` and advanced controls. Use the ordinary reviewed settings until a concrete derivative or integration need justifies changing them.

### Complete R companion

```r
start <- c(2, 2, 7); mapping <- factor(c(1, 1, NA))
reconstruct <- function(free) {
  result <- start; result[!is.na(mapping)] <- free[as.integer(mapping[!is.na(mapping)])]; result
}
print(reconstruct(3));stopifnot(identical(reconstruct(3), c(3, 3, 7)))
a <- c(1, 2, 3);b <- c(1, 2, 9)
print(c(same_length = length(a) == length(b), objective_a = sum(a^2) / 2, objective_b = sum(b^2) / 2))
```
