go-018: Filesystems, paths and owned cleanup#

Level and prerequisites#

Intermediate. Allow about 120 minutes, then revisit the transfer case later. Prerequisites: go-017

Learning objectives#

By the end, explain filesystem interface, path confinement, owned resource; implement the six investigations below; and defend the expected result of a changed input before running it. A passing reference is evidence about that program, not a certification of your independent understanding.

Why this mechanism matters#

A filesystem path is a name interpreted by a filesystem, not proof of ownership or permission. Logical path cleaning removes redundant components but does not prevent symlink escapes or authorize deletion. The io/fs interfaces let programs consume files without depending on a particular disk layout. A deterministic in-memory filesystem makes success, missing-file and malformed-path behavior easy to inspect. When real temporary files are needed, create a unique owned directory, defer its cleanup and never infer ownership from a familiar filename. Persistent learner work belongs in the classroom storage layer; a worker scratch file is temporary and should not be treated as saved progress.

Vocabulary and concepts#

  • Filesystem interface: An abstraction for relative file operations.
  • Path confinement: Restricting access to an explicitly allowed tree.
  • Owned resource: A resource whose creation and cleanup responsibility are known.

Syntax anatomy and reasoning#

fs.ReadFile accepts an fs.FS and a slash-separated relative path. fs.ValidPath rejects empty paths, leading slashes and dot-dot components under the logical contract. fstest.MapFS provides test files in memory. errors.Is(err, fs.ErrNotExist) detects a missing-file cause across wrapping. filepath.Clean alone is normalization, not a containment security boundary.

Worked example / walkthrough#

Worked example 1: Read an in-memory file#

Read data/input.txt containing red and a newline.

package main

import (
	"fmt"
	"io/fs"
	"testing/fstest"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Read an in-memory file
	{
		files := fstest.MapFS{"data/input.txt": &fstest.MapFile{Data: []byte("red\n")}}
		v, err := fs.ReadFile(files, "data/input.txt")
		check(err == nil && string(v) == "red\n", "file read")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: The bytes decode to red followed by a newline.

The algorithm uses the same filesystem interface without reaching the host disk. That isolates content behavior from permissions and mount configuration.

Worked example 2: Observe a missing file#

Read absent.txt from an empty filesystem.

package main

import (
	"errors"
	"fmt"
	"io/fs"
	"testing/fstest"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Read an in-memory file
	{
		files := fstest.MapFS{"data/input.txt": &fstest.MapFile{Data: []byte("red\n")}}
		v, err := fs.ReadFile(files, "data/input.txt")
		check(err == nil && string(v) == "red\n", "file read")
	}

	// Observe a missing file
	{
		_, err := fs.ReadFile(fstest.MapFS{}, "absent.txt")
		check(errors.Is(err, fs.ErrNotExist), "missing file")
	}
	fmt.Println("Worked example checks passed.")
}

Observe: The error matches fs.ErrNotExist.

Preserving a typed cause lets a caller distinguish optional absence from unreadable or malformed content.

Common pitfalls and diagnosis#

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from check identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned error is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
