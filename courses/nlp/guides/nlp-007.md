# nlp-007: Counts, TF-IDF and sparse representations

## Level and prerequisites

Beginner; about 120 minutes plus discussion. Direct prerequisites: `nlp-006`. Read the preceding guide if its notation or information boundaries are unfamiliar.

## Purpose and mental model

Bag-of-words representations turn documents into vectors whose coordinates correspond to a fixed vocabulary. A count says how often a term appears in one document. Document frequency says in how many training documents it appears. TF-IDF combines within-document frequency with a corpus-level rarity weight, providing a useful sparse baseline for classification and retrieval.

The unit is one document, not one token or one customer. Repeated occurrences of tea in a document increase term frequency but count only once toward document frequency. Changing the document boundaries therefore changes IDF even if the concatenated text is unchanged. Preserve the corpus definition and fit the vocabulary/IDF only on the training or indexed collection appropriate to the evaluation claim.

This lesson derives the exact smoothing and normalization convention used by a real scikit-learn TfidfVectorizer. TF-IDF is a family of weighting choices, so an undocumented formula can produce a valid-looking vector different from a library's result. We compare every coordinate against a hand-built oracle before using cosine scores.

## Derive the chosen weighting convention

Let n be the number of training documents and df_j the number containing term j. With smooth_idf=True, the implementation used here assigns \(\mathrm{idf}_{j}=\log(\frac{1+n}{1+\partial f_{j}})+1\). The natural logarithm and final plus one matter. Raw term frequency multiplies that weight by the count tf_ij; optional sublinear frequency instead uses \(1+\log(\mathrm{tf}_{ij})\) for positive counts.

The two training documents are tea tea cup and coffee cup. Sorted vocabulary order is [coffee,cup,tea]. Coffee and tea each occur in one document, while cup occurs in both. Thus the rare-term weight a is \(\log(\frac{3}{2})+1\), and cup has weight one. Before normalization the rows are [0,1,2a] and [a,1,0].

L2 normalization divides each nonzero row by its Euclidean norm. It removes overall magnitude from cosine comparisons while retaining relative term weighting. The first row norm is \(\sqrt{1+4a^2}\). A repeated term still changes direction relative to other terms, so normalization does not erase every effect of document length or repetition.

## Read the sparse matrix and API

fit_transform learns the vocabulary and IDF from TRAIN and returns a sparse matrix. transform applies those frozen values to a query or held-out document. get_feature_names_out supplies the column mapping. Never interpret coefficient or vector position zero as a particular word without checking that mapping.

A sparse matrix stores nonzero entries rather than a full dense rectangle. This matters when thousands of documents use only a small fraction of a large vocabulary. The worked fixture can safely call `toarray()` because it is only two by three. Converting a real corpus matrix to dense can exhaust memory, so use sparse multiplication and bounded inspection in production.

For normalized nonzero vectors, cosine equals their dot product. The expression X @ query.T produces one score per document. A query with no known terms becomes a zero vector. The computed dot products are all zero, but that is an absence-of-representation case, not evidence that every document is equally irrelevant. A retrieval system should recognize it and choose an explicit fallback or abstention.

## Representation limitations and diagnosis

A unigram representation ignores order, so dog bites person and person bites dog share the same counts. It can also lose negation, domain synonyms and spelling variants. Character n-grams, word n-grams or other representations may address some failures, but each changes the vocabulary and evaluation contract. A dense embedding is another candidate, not an automatic replacement for a useful lexical baseline.

IDF is not a truth or importance score. A rare typo can get a high weight, while a common domain term can be essential to the task. Inspect tokenization, stopwords and minimum-frequency policies rather than treating every high-IDF term as meaningful. Fitting IDF on an evaluation collection can be appropriate for a clearly transductive retrieval setup, but it cannot be silently described as a training-only inductive experiment.

The reference checks raw counts, IDF values, normalized vectors, cosine, sublinear TF and frozen unknown-token behavior separately. This decomposition helps locate a mismatch: a wrong document frequency differs from a right vector with the wrong normalization or vocabulary order.

## Worked examples

### Worked example 1: Compute DF and IDF

For the two authored documents, df(coffee)=1, df(cup)=2 and df(tea)=1. With the chosen smoothed formula, IDF is [a,1,a] where \(a=\log(1.5)+1\), about 1.40547. Counting the two tea occurrences as \(\partial f=2\) would incorrectly reduce its IDF.

### Worked example 2: Normalize and retrieve

The first raw weighted row [0,1,2a] becomes that row divided by \(\sqrt{1+4a^2}\). Query tea becomes [0,0,1]. Their dot product is \(\frac{2a}{\sqrt{1+4a^2}}\), while the coffee document has score zero. The score follows the declared lexical representation and does not claim semantic understanding of tea.

### Worked example 3: Observe an unsupported query

Both matcha and an empty query produce zero stored entries under the frozen vocabulary. The vocabulary remains unchanged. A production search endpoint should report or handle this boundary explicitly rather than returning a seemingly meaningful ranking based only on arbitrary tie order.

### Executable worked traces

Run these two small blocks in order. They reproduce the numerical or structural observations above; the full reference additionally checks the exercise changes and failure cases.

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
v=TfidfVectorizer().fit(['tea tea cup','coffee cup'])
print(v.get_feature_names_out(),v.idf_)
a=np.log(3/2)+1
assert np.allclose(v.idf_,[a,1,a])
```

```python
x=v.transform(['tea tea cup','coffee cup']);q=v.transform(['tea'])
scores=(x@q.T).toarray().ravel()
print(scores)
assert np.isclose(scores[0],2*a/np.sqrt(1+4*a*a)) and scores[1]==0
```

## Interview reasoning

**Interview: Why can TF-IDF remain useful beside dense embeddings?** It provides an efficient lexical baseline that preserves exact rare terms and is easy to inspect. Domain names and identifiers can favor lexical matching; compare or combine representations using task evidence.

**Interview: Is IDF fitted on test text always leakage?** The answer depends on the declared setup. A fixed indexed corpus can be part of a transductive retrieval task, while an inductive classification claim requires train-only fitting. The information boundary must be explicit.

**Interview: Why avoid `toarray()` on a real corpus?** Sparse matrices save memory by storing nonzero values. Densifying can allocate documents times vocabulary entries even when almost all are zero. Inspect bounded slices or use sparse operations.
