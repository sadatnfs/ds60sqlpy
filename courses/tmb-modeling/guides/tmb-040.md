# An API-complete workflow and qualification map

Start with: tmb-039, tmb-024.

Outcome: Navigate every pinned public TMB API without overstating untested features.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A comprehensive course needs a map of the actual public package, not an unbounded promise to cover every implementation symbol. The pinned TMB 1.9.25 NAMESPACE declares 30 explicit exports. It also registers S3 methods, including `confint` for profile objects and `as.list` for uncertainty reports. The manual documents `GK`, which is not an explicit export in that namespace. The maintained [API reference](../API-REFERENCE.md) lists exact signatures, purpose, cautions and chapter placement for these distinct surfaces.

The workflow begins with a scientific observation model and ends with a qualified result. Authoring helpers create scaffolds; compile and native-lifetime helpers prepare execution; `MakeADFun` constructs the target; optimizers find parameters; reporting and profile functions quantify selected uncertainty; simulation and OSA tools criticize the model; parallel and sparse controls change execution details. Each step has a separate failure mode and receipt.

### Worked case A: a small fully qualified model

For the original normal model, derive its full density, validate input, compile a source-identified library, compare values and derivatives, recover known MLEs, inspect curvature, use report methods and compare a profile/root interval to an independent formula. The companion assembles these evidence layers as a table with explicit statuses. A source file and a successful import are not replacements for the execution rows.

### Worked case B: an advanced prepared-only capability

Suppose you add a custom latent process requiring automatic normalization and one-step predictive residuals. The existing normal model's receipt does not qualify those features. Define the required flag/indicator template conventions, prepare the new source, test a tiny oracle and record actual runtime results. Until then, mark the API explanation as taught and its particular project implementation as prepared or untested.

This distinction lets learners study the entire API now while keeping product capability claims precise. The course covers all public function families, but does not claim that every combination of framework, specialized sparse build, integration method, debugger and hardware is exercised in the ordinary classroom runtime.

### Answered discussion

**Is API coverage the same as mastery?** No. Learners must connect each tool to a statistical question and diagnose its limitations. **How should a future TMB upgrade be handled?** Compare exports and signatures against the maintained inventory, inspect behavior changes, rebuild native models and rerun exact numerical and failure checks. **Should undocumented internals be forbidden?** Research sometimes needs them, but they require explicit source pinning and cannot silently become a stable learner-facing contract.

The companion is an honest evidence map. The owned project's qualification ledger and release receipts supply actual statuses. Continue to the advanced Spark integration only after the local compiled model and process boundary are trustworthy.
