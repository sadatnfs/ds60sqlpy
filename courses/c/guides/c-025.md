# c-025: Recursion, trees and depth budgets

## Level and prerequisites

Intermediate, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-024`

## Learning objectives

Traverse a binary tree recursively with an explicit depth budget and correct empty-tree behavior. Along the way, explain base case, progress measure and depth budget. Implement the six investigations, from the "traverse a small tree" case to the "transfer a singleton" case, with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

Recursion solves a problem by invoking the same mechanism on smaller subproblems. A base case stops the process, and a progress measure explains why each step approaches it. A binary tree naturally decomposes into a root and subtrees, but an unbalanced tree can have depth proportional to its node count. Recursive traversal therefore consumes stack space according to depth, not just total work. For untrusted or very large structures, impose a depth budget or use an explicit stack. This lesson uses fixed stack-allocated nodes with no cycles and no ownership ambiguity, separating traversal reasoning from allocation mechanics.

## Vocabulary and concepts

- **Base case:** The condition ending recursive descent.
- **Progress measure:** A quantity that decreases toward termination.
- **Depth budget:** A bound on nested traversal steps.

## Syntax anatomy and execution trace

A node stores value, left and right pointers. NULL represents an empty subtree. A sum traversal combines the root value with both subtree sums. A depth function returns zero for empty and one plus the greater child depth otherwise. The bounded search checks its remaining depth before descending. General graph traversal also needs visited-state handling because a cycle is not a valid finite tree.

## Worked example / walkthrough

### Worked example 1: Traverse a small tree

Sum a root 2 with children 1 and 3.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

struct Tree {
  int value;
  const struct Tree *left, *right;
};
int tree_sum(const struct Tree *node) {
  if (node == NULL)
    return 0;
  return node->value + tree_sum(node->left) + tree_sum(node->right);
}
size_t tree_depth(const struct Tree *node) {
  if (node == NULL)
    return 0;
  size_t a = tree_depth(node->left), b = tree_depth(node->right);
  return 1 + (a > b ? a : b);
}
bool tree_contains(const struct Tree *node, int target, size_t budget) {
  if (node == NULL || budget == 0)
    return false;
  if (node->value == target)
    return true;
  return tree_contains(node->left, target, budget - 1) ||
         tree_contains(node->right, target, budget - 1);
}

int main(void) {
  /* Traverse a small tree */
  {
    struct Tree left = {1, NULL, NULL}, right = {3, NULL, NULL},
                root = {2, &left, &right};
    CHECK(tree_sum(&root) == 6);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** The total is 6.

Each node contributes once under the acyclic tree assumption.

### Worked example 2: Handle an empty tree

Sum NULL.

```c
    struct Tree left = {1, NULL, NULL}, right = {3, NULL, NULL},
                root = {2, &left, &right};

  /* Handle an empty tree */
  {
    CHECK(tree_sum(NULL) == 0);
  }

```

**Observe:** The result is zero.

The empty subtree contributes the additive identity and ends recursion.

### Exercise 1: Traverse a small tree: change one input

In worked example 1, change `struct Tree left = {1, NULL, NULL}, right = {3, NULL, NULL},` to `struct Tree left = {2, NULL, NULL}, right = {3, NULL, NULL},`. Predict which value the CHECK on `tree_sum(&root) == 6` sees, then run and restore.

**Expected:** `Check failed` at `tree_sum(&root) == 6`; restoring `struct Tree left = {1, NULL, NULL}, right = {3, NULL, NULL},` passes again.

**Verify:** Name the value that made `tree_sum(&root) == 6` false, where worked example 1 showed that the total is 6.

**Progressive hints:** First trace `root` from initialization. Then compute what the CHECK sees with `struct Tree left = {2, NULL, NULL}, right = {3, NULL, NULL},` in place.

### Exercise 2: Handle an empty tree: diagnose an edited check

Worked example 2's CHECK now reads `CHECK(tree_sum(NULL) != 0);`. Explain why it fails although the result is zero, then restore it.

**Expected:** `Check failed` until the CHECK reads `CHECK(tree_sum(NULL) == 0);` again, though the result is zero.

**Verify:** Explain why `CHECK(tree_sum(NULL) != 0);` rejects a state that `tree_sum(NULL) == 0` accepts, using your failing and repaired runs.

**Progressive hints:** First work out what `tree_sum` returns here. Then compare `CHECK(tree_sum(NULL) != 0);` with worked example 2's original line.

### Exercise 3: Measure structural depth

Measure the root and two children.

**Expected:** The depth is 2.

**Verify:** Keep a CHECK equivalent to `tree_depth(&root) == 2`. Control edit: `CHECK(tree_depth(&root) != 2);` must fail; then restore it.

**Progressive hints:** First trace `root` from initialization. Then recall: Depth counts nested levels, not the three total nodes.

### Exercise 4: Find an existing value

Search the tree for 3 with sufficient budget.

**Expected:** The value is found.

**Verify:** Keep a CHECK equivalent to `tree_contains(&root, 3, 2)`. Control edit: changing `struct Tree leaf = {3, NULL, NULL}, root = {2, NULL, &leaf};` to `struct Tree leaf = {4, NULL, NULL}, root = {2, NULL, &leaf};` must fail it; then restore it.

**Progressive hints:** First trace `root` from initialization. Then recall: The budget permits visiting root and child.

### Exercise 5: Respect a depth limit

Search for the child value with only one level allowed.

**Expected:** The bounded search does not descend to the child.

**Verify:** Keep a CHECK equivalent to `!tree_contains(&root, 3, 1)`. Control edit: changing `struct Tree leaf = {3, NULL, NULL}, root = {2, NULL, &leaf};` to `struct Tree leaf = {3, NULL, NULL}, root = {3, NULL, &leaf};` must fail it; then restore it.

**Progressive hints:** First trace `root` from initialization. Then recall: This bool API conflates not-found-within-budget and absent.

### Exercise 6: Transfer a singleton

Measure and sum one node containing 7.

**Expected:** Depth is 1 and sum is 7.

**Verify:** Keep a CHECK equivalent to `tree_depth(&root) == 1 && tree_sum(&root) == 7`. Control edit: changing `struct Tree root = {7, NULL, NULL};` to `struct Tree root = {8, NULL, NULL};` must fail it; then restore it.

**Progressive hints:** First trace `root` from initialization. Then recall: The singleton verifies that both empty-child base cases combine correctly.

## Common pitfalls and diagnosis

Recursing without a base case for the empty tree dereferences NULL. Assuming the call stack is unlimited is the other trap: a degenerate tree as deep as its input can exhaust it, which is why this lesson enforces a depth budget.
