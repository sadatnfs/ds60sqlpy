# DAX curriculum guidance

Read the root guidance and [authoring contract](authoring/README.md) before editing.
The subject is offline source editing and analytical reasoning. Its profile is
`dax-offline`; it has no worker, compiler, connector, account or execution receipt.

Keep stable `dax-001` through `dax-060` identities and the real prerequisite graph.
Preserve learner drafts, named references and worked results as different artifacts.
A source match or completion marker never certifies execution or mastery. Do not
add a simulated Run button or describe hand-derived tables as executed results.

Edit `authoring/part01.py` through `part10.py`, `progression.py`, `fixtures.py` and
`build.py`. Regenerate this subject only, then check drift and focused contracts.
Root shared HTML generation is a separate coordinated step. Do not hand-edit
rendered readers or the generated sidecar hashes.

Every case needs an explicit model, filter/row context, trace and result units.
Only the unknown-member model deliberately has an unmatched Product key. Cases
with hypothetical roles, metadata or performance numbers must state that boundary.
Newer DAX features require a dated primary source and explicit scope/version note.
Keep source literals exact, write prose math in LaTeX, and use no em dashes.

Verification checks source/model bytes, typed fixtures and independent arithmetic.
It does not parse or execute DAX. Optional external engine validation needs its own
named model/version/role and genuine observed record. Never manufacture such proof.
