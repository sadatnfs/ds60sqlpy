# Typed vectors, matrices, arrays and sparse inputs

Start with: tmb-040, tmb-002.

Outcome: Design a C++ data contract that preserves dimensions, indices and scientific meaning.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

The R export list does not describe all model-authoring interfaces. A TMB template also uses C++ macros, typed containers and density helpers supplied by its headers. The [C++ family map](../CPP-API-FAMILIES.md) covers the supported teaching families without claiming every Eigen, CppAD or TMBad implementation symbol is part of this course.

`DATA_SCALAR`, `DATA_VECTOR`, `DATA_MATRIX` and `DATA_ARRAY` read fixed numerical inputs. Integer and category interfaces include `DATA_INTEGER`, `DATA_IVECTOR` and `DATA_FACTOR`. `DATA_SPARSE_MATRIX` reads a compatible sparse matrix. Parameter declarations include scalar, vector, matrix and array forms. Their shapes define the free coordinate layout that `MakeADFun` records.

### Worked case A: array orientation is part of the model

R arrays use column-major storage. A two-by-three array stores the first column's two elements before the second column. `PARAMETER_ARRAY(u)` preserves dimensions, while `PARAMETER_VECTOR(u)` only preserves a flat sequence. The companion labels each position and verifies the flattening order. An array transpose with unchanged coefficient interpretation can fit a different model even though every value is finite.

```cpp
DATA_ARRAY(observed);
PARAMETER_ARRAY(latent);
Type residual = observed(0, 1) - latent(0, 1);
```

This fragment assumes a two-dimensional array and a validated matching shape. A generic loop should inspect dimensions or flatten consistently. Do not index a three-dimensional array using a two-dimensional scientific interpretation.

### Worked case B: sparse design and factor keys

A group design matrix \(Z\) has one nonzero per row for a simple random intercept. The companion builds an explicit small design and verifies \(Zu\) agrees with group-index lookup. A large sparse representation stores the nonzero coordinates and dimensions rather than every zero. Validate indices and compatible sparse class on the R side before entering C++.

R factor levels are categorical labels; their numerical codes are an implementation detail. `DATA_FACTOR` and explicit zero-based integer-index interfaces need careful conversion and a stable training vocabulary. The existing project uses explicit zero-based `DATA_IVECTOR(group)` and rejects out-of-range groups. Adding new factor levels requires a new objective shape and potentially a new scientific prediction target.

### Answered discussion

**Should parameter-dependent values be converted to double for speed?** That can remove derivative dependence. Keep them in `Type` arithmetic unless a reviewed atomic operation supplies the derivative boundary. **Can integer identifiers be passed as floating-point measurements?** Large keys can lose exactness and should remain explicit strings outside the numerical template. **Are sparse matrices automatically symmetric?** No. Symmetry, definiteness, dimensions and storage representation are separate properties.

See the [template macro reference](https://cran.r-project.org/web/packages/TMB/TMB.pdf) and [typed density source](https://github.com/kaskr/adcomp/blob/master/TMB/inst/include/tmbutils/density.hpp). The course's pinned source hashes identify the actual version reviewed.
