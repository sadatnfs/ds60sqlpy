Brad Bell's work, automatic differentiation and distributed likelihoods#

This review supports the separate Spark likelihood package. The primary implementation evaluates custom PyTorch likelihoods on Spark executors and returns bounded objective/gradient summaries. It does not require R or the classroom server. The completed R/TMB integration remains a separately prepared reference, rather than the main package dependency.

The research covers all 26 repositories publicly listed under Brad Bell's account at inspection, plus upstream and publicly indexed contribution repositories. In total, 36 repository heads were recorded and 35 root README files were read at those immutable revisions. The remaining repository, test_sphinx, had no README at the checked names. The versioned source index retains the exact scope and revisions. GitHub's contributed-repository index is a recent public index, not a complete lifetime authorship record.

Can adcomp support an R-free C++ calculation?#

Yes, for the AD core we actually exercised. The standalone native experiment compiles an original likelihood functor with the TMBad component from the checksum-pinned TMB 1.9.25 source archive. Its configuration adapter supplies standard C++ diagnostic streams and assertions. R is not installed in the test image, and the executable links neither libR nor libpython.

The experiment compares values, gradients and Hessians with independent Gaussian formulas at six data/parameter combinations. On native Linux ARM64, maximum absolute error was about 1.14×10−131.14\times10^{-13}1.14×10−13. Its source-bound receipt records exactly what ran.

This is not drop-in loading of an arbitrary TMB model library. The usual TMB interface includes R headers, R data objects, template input macros, model construction and reporting. A portable C++ functor using TMBad is a different interface. The research example does not qualify all TMB distributions, random-effect integration, concurrent JNI calls or a multi-node Spark connector. TMB interface source, TMBad function-object source

The bundled TMB-modified CppAD headers also exposed standalone-build assumptions during a separate exploratory attempt. That failed attempt is not evidence that upstream CppAD cannot run independently; upstream CppAD is specifically a C++ AD library with its own supported configuration. It is evidence that copying a nested vendor directory without its configuration is not a complete integration.

TMBad contains forward/reverse code-generation machinery as well. Inspection of the pinned implementation found an experimental helper using fixed temporary filenames and an unchecked compiler-failure branch before attempting to load a shared library. We did not use that helper for the accepted experiment. A future code-generation backend needs owned build directories, checked compiler exits, source/binary identities and independent numerical acceptance. Code-generation implementation

The distributed estimator's mathematical boundary#

Let θ∈Rd\theta\in\mathbb R^dθ∈Rd be the shared parameter vector and IpI_pIp​ the observations assigned to partition ppp. For a row-additive objective,

Each executor returns LpL_pLp​, ∇Lp\nabla L_p∇Lp​, counts, weight totals and identity evidence. The driver combines these summaries, adds the shared penalty once and chooses the next parameter vector. Its numerical payload grows with PdPdPd, rather than with the full observation table. Spark scheduling and local differentiation have separate responsibilities.

For a complete independent group ggg, replace the row sum with a scalar group objective ℓg(θ;yg)\ell_g(\theta;y_g)ℓg​(θ;yg​). All observations needed by that group must reach the same bounded evaluation unit. The current package includes an exact Gaussian random-intercept marginal and an original Gamma-Poisson custom example. The latter integrates a shared latent rate analytically, rather than pretending that an AD engine automatically performs statistical integration.

Three operations must remain distinct:

  1. One shared fit, obtained by summing compatible contributions at the same parameter vector.
  2. Independent fits with a different parameter vector for each group.
  3. A coupled model whose covariance or latent state spans multiple units.

Averaging independently fitted coefficients does not generally recover the shared MLE. Splitting a coupled likelihood can change the model. Neither native C++ nor a faster derivative engine changes those facts.

For large neural parameter sets, use an appropriate distributed training strategy rather than collecting a separate full gradient from every Spark partition into a small-parameter driver optimizer. The package's opt-in TorchDistributor/Lightning examples teach rank scaling and exact observation coverage separately from the MLE interface.

Numerical stability is part of the model interface#

A finite result can still be wrong. Review found that a naive Gamma-Poisson formula could cancel to zero when shape and rate were both very large. The example was rewritten with stable ratio/rising-factorial algebra and an explicit supported-count regime. Zero- and nonzero-count Poisson-limit checks now test the value and score, rather than merely testing that neither is NaN.

A model's source identity must also distinguish meaningful callables and configuration. Same-file anonymous functions and changed defaults were concrete review findings. Registration now has a stricter named-source/configuration contract; this is compatibility evidence, not a digital signature certifying scientific correctness.

Benchmark the complete path#

Measure derivative correctness first, then separate model preparation, tape recording, compilation, warm evaluation, serialization, Spark scheduling and optimizer passes. Keep dtype, threads, parameter dimension and observation counts comparable. A fast isolated kernel does not establish a faster end-to-end distributed fit. The comparison structure in cmpad is useful for designing such experiments. cmpad
