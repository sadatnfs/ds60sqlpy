# js-062: Geographic data, GeoJSON and projection choices

## Level and prerequisites

Advanced; about 110 minutes plus independent practice. Direct prerequisites: `js-061`.

## Learning objectives

Project GeoJSON points with an explicit projection and check longitude-latitude order and distortion. The central exercise is: Render the synthetic point collection.

## Purpose, vocabulary and mental model

GeoJSON represents geographic features using geometry and properties. Geographic coordinates conventionally use longitude then latitude in degrees. Swapping them can produce plausible but incorrect locations. A map projection converts positions on the globe into a flat display, introducing distortion because a sphere cannot be flattened without tradeoffs.

Different projections preserve different properties locally or globally. A map for comparing area should not casually use a projection that strongly distorts area. A map for route direction has another purpose. State the geographic scope and the projection’s relevance to the analytical question.

The reference uses a tiny original synthetic point collection, so it needs no external map download or geographic dataset license. It demonstrates coordinate conversion and path creation without pretending that dots alone are a detailed basemap. Real geographic boundaries also require source, date and topology review.

### Key terms

- **GeoJSON:** A JSON format for geographic features. A FeatureCollection holds Feature objects, each with a geometry and a properties object.
- **Longitude:** The angle east or west of the prime meridian in degrees. GeoJSON lists it first in each position, so swapping it with latitude yields plausible but wrong locations.
- **Projection:** A function such as `d3.geoMercator()` that maps `[longitude, latitude]` on the globe to flat `[x, y]` coordinates. Every projection distorts area, shape, distance or direction in some way.
- **geoPath:** The generator returned by `d3.geoPath(projection)` that converts GeoJSON geometry into SVG path data.

## Syntax anatomy and mechanism

A FeatureCollection contains Feature objects with geometry and properties. `d3.geoMercator` returns a projection callable on `[longitude,latitude]`. `d3.geoPath(projection)` converts GeoJSON into SVG path data. Fitting a projection to data chooses scale and translation for a view, not an analytical normalization of values.

Check that all projected coordinates are finite and within the intended view. A coordinate can be valid globally yet outside your chosen region. Handle antimeridian crossings and polygon winding deliberately for actual region datasets; those cases are not solved by swapping arbitrary signs until a map looks right.

## Worked example / walkthrough

### Worked example 1: Respect coordinate order

Longitude is first.

```javascript
const point = { type: "Point", coordinates: [10, 45] };
console.log(point.coordinates[0]);
```

**Expected observation:** 10 degrees longitude, not latitude.

### Worked example 2: Project the origin

A known center provides a useful anchor for the projection.

```javascript
// js-062 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Geographic data, GeoJSON and projection choices")
  .style("width", "100%")
  .style("max-width", "640px");
const projection = d3.geoMercator().center([0, 0]).scale(100).translate([320, 180]);
const origin = projection([0, 0]);
check(
  Math.abs(origin[0] - 320) < 1e-9 && Math.abs(origin[1] - 180) < 1e-9,
  "The center projects to the translate point",
);
svg
  .append("path")
  .attr("d", d3.geoPath(projection)(d3.geoGraticule10()))
  .attr("fill", "none")
  .attr("stroke", "#d1d5db");
svg
  .append("circle")
  .attr("cx", origin[0])
  .attr("cy", origin[1])
  .attr("r", 6)
  .attr("fill", "#dc2626");
svg
  .append("text")
  .attr("x", origin[0] + 10)
  .attr("y", origin[1] - 10)
  .text("longitude 0, latitude 0");
output.textContent = "js-062 worked example 2 complete";
```

**Expected observation:** A Mercator graticule with a red point at longitude 0, latitude 0, drawn at `(320, 180)` as configured by center and translate.

## Six progressive exercises

### Exercise 1: Identify longitude and latitude positions.

**Expected evidence:** The first coordinate is longitude and the second latitude.

**Progressive hint:** GeoJSON order is part of the data contract.

### Exercise 2: Change a longitude while holding latitude fixed.

**Expected evidence:** The projected horizontal location changes under this projection.

**Progressive hint:** Use a known anchor to reason about direction before interpreting an unfamiliar region.

### Exercise 3: Render the synthetic point collection.

**Expected evidence:** One finite path per feature with descriptive labels.

**Progressive hint:** Keep feature identity and geometry separate from visual styling.

### Exercise 4: Diagnose a misplaced but numerically valid point.

**Expected evidence:** Check coordinate order, units, projection and source reference system.

**Progressive hint:** Visual plausibility is not enough.

### Exercise 5: Explain projection distortion.

**Expected evidence:** A flat map cannot preserve every geographic property simultaneously.

**Progressive hint:** Choose the property relevant to the task and state the tradeoff.

### Exercise 6: Plan a real boundary-data integration.

**Expected evidence:** Source/license, date, stable IDs, topology and projection checks.

**Progressive hint:** The map must be reproducible and legally distributable.

## Debugging and common mistakes

When a point lands in the wrong place with valid numbers, check coordinate order first: GeoJSON uses [longitude, latitude]. Then check that units are degrees, the projection's center, scale and translate, and the source's reference system. With center [0, 0] and translate [320, 180], the origin should project exactly to (320, 180). ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose a misplaced but numerically valid point. Distinguishing evidence: Check coordinate order, units, projection and source reference system.

## Accessibility and interpretation

A map's positions are inaccessible without a text equivalent. Name each feature with its place and coordinates in an accessible label, and add a list sorted by the variable of interest. A graticule or labeled reference points help sighted readers orient themselves. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Every flat projection distorts area, shape, distance or direction. Mercator stretches areas toward the poles, so latitude 89.9 projects hundreds of units beyond latitude 85. Choose the projection for the question, such as an equal-area projection when comparing region sizes, and record the source, date and license of real boundaries. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
