# js-048: Data cleaning: CSV parsing, missing values and aggregation

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-047`.

## Learning objectives

Parse inline CSV, separate missing from invalid values and aggregate at an explicit grain before charting. The central exercise is: Parse and aggregate the inline fixture.

## Purpose, vocabulary and mental model

CSV is a text format whose cells do not automatically have the domain types your analysis needs. Parsing a file into rows and interpreting strings as numbers or dates are separate steps. Empty strings, malformed values and duplicate IDs require explicit policies before visual encoding.

A missing measurement is not necessarily zero. Replacing absence with zero can distort averages, totals and visual trends. Reject invalid rows with a reason, retain a count of excluded rows, and make the policy visible to the chart reader. Trimming text and checking finite numeric values are small but important boundary operations.

Aggregation changes the row grain. A transaction table has one row per event; a category summary may have one row per group. The correct denominator and missing-value policy depend on that grain. A data scientist should be able to reconstruct the aggregate from the small source rows before rendering it.

### Key terms

- **CSV parsing:** Converting comma-separated text into row objects with `d3.csvParse`; every cell arrives as a string until a row accessor converts it.
- **Row accessor:** A function passed to `d3.csvParse` that returns a cleaned object for each row, or null to omit the row.
- **Missingness:** The absence of a measurement, such as a blank cell, which is not the same as zero. Because `Number('')` is 0, the blank check must come before numeric conversion.
- **Validation:** Checking each parsed row against explicit rules, such as finite numbers and trimmed categories, and counting rejected rows with a reason.
- **Rollup:** The `d3.rollup` operation that groups rows by a key and reduces each group, for example with `d3.sum`, returning a Map at a coarser row grain.

## Syntax anatomy and mechanism

`d3.csvParse` parses inline CSV without a network request. A row accessor can return a cleaned object or null to omit a row, but an omission should be counted and explained. `Number('')` is zero, which is why a blank-string check must precede numeric conversion.

`d3.rollup(rows, group => d3.sum(group, d => d.value), d => d.category)` returns a Map keyed by category. The grouping key should be normalized intentionally. Case-sensitive category names may be genuinely distinct or accidental inconsistencies; do not merge them without a domain decision.

## Worked example / walkthrough

### Worked example 1: Reject blank and malformed numbers

This function separates missingness from numeric conversion.

```javascript
function numberOrNull(text) {
  if (text.trim() === "") return null;
  const n = Number(text);
  return Number.isFinite(n) ? n : null;
}
console.log(numberOrNull(""), numberOrNull("3"), numberOrNull("oops"));
```

**Expected observation:** null, 3, null.

### Worked example 2: Aggregate a known grain

Each input row is one event, so a group total is a sum over its events.

```javascript
// js-048 worked example 2: a complete program for the classroom preview.
const host = document.querySelector("#chart");
const output = document.querySelector("#output");
host.replaceChildren();
const check = (condition, message) => {
  if (!condition) throw new Error(message);
};
const svg = d3
  .select(host)
  .append("svg")
  .attr("viewBox", "0 0 640 360")
  .attr("role", "img")
  .attr("aria-label", "Data cleaning: CSV parsing, missing values and aggregation")
  .style("width", "100%")
  .style("max-width", "640px");
const events = [
  { g: "A", v: 2 },
  { g: "A", v: 3 },
  { g: "B", v: 4 },
];
const totals = d3.rollup(
  events,
  (rows) => d3.sum(rows, (d) => d.v),
  (d) => d.g,
);
check(totals.get("A") === 5 && totals.get("B") === 4, "Each group total sums its own events");
const x = d3.scaleLinear().domain([0, 6]).range([0, 480]);
const groups = [...totals.keys()];
svg
  .selectAll("rect")
  .data(groups)
  .join("rect")
  .attr("x", 100)
  .attr("y", (d, i) => 80 + i * 100)
  .attr("height", 50)
  .attr("width", (d) => x(totals.get(d)))
  .attr("fill", "#7c3aed");
svg
  .selectAll("text")
  .data(groups)
  .join("text")
  .attr("x", 20)
  .attr("y", (d, i) => 112 + i * 100)
  .text((d) => `${d}: ${totals.get(d)}`);
output.textContent = "js-048 worked example 2 complete";
```

**Expected observation:** Two bars labeled A: 5 and B: 4; the A total comes from exactly two events.

## Six progressive exercises

### Exercise 1: Predict blank-string numeric conversion.

**Expected evidence:** Number of an empty string is 0, so prevalidation is required.

**Progressive hint:** Blind conversion silently changes missingness into a measured zero.

### Exercise 2: Count rejected rows with reasons.

**Expected evidence:** Every omitted row is accounted for as blank or malformed.

**Progressive hint:** A chart should not silently shrink its sample.

### Exercise 3: Parse and aggregate the inline fixture.

**Expected evidence:** A totals to 5 and B totals to 4 from valid rows.

**Progressive hint:** Check the row-level interpretation before grouping.

### Exercise 4: Diagnose treating a blank value as zero.

**Expected evidence:** The chart includes an invented measurement.

**Progressive hint:** Repair the cleaning rule and compare the resulting counts or means.

### Exercise 5: Handle a category with only missing rows.

**Expected evidence:** Its absence or missing state is documented rather than called zero.

**Progressive hint:** Whether to retain an empty category depends on the analytical universe.

### Exercise 6: Transfer the pipeline to a rate metric.

**Expected evidence:** Validate numerator and denominator at a defined grain before division.

**Progressive hint:** Averaging percentages can differ from a ratio of sums.

## Debugging and common mistakes

When a total looks wrong, count rows at each stage: raw lines, parsed rows, valid rows and rejected rows with reasons. `Number('')` is 0, so a blank cell silently becomes a measurement, while `d3.autoType` turns a blank into `null` but leaves text such as `x` as a string. Check that valid plus rejected equals parsed. ([checkpoints](../STUDY-GUIDE.md#d3-debugging-checkpoints))

Exercise 4 is the controlled failure: Diagnose treating a blank value as zero. Distinguishing evidence: The chart includes an invented measurement.

## Accessibility and interpretation

Report rejected rows in text next to the chart, for example "2 rows omitted: 1 blank, 1 malformed", so readers who cannot see a missing bar still learn that data were excluded. A table of aggregated values by category makes the exact totals available to everyone. ([accessibility review](../STUDY-GUIDE.md#d3-accessibility-review))

Aggregation needs a stated grain: one bar per category summing event rows is a different claim from one bar per day. A category whose rows are all missing has an unknown total, not zero. Declare the missing-value policy in the caption so a reader can judge whether excluded rows could change the comparison. ([statistical meaning](../STUDY-GUIDE.md#d3-statistical-meaning))
