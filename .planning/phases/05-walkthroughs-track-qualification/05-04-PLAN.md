How to choose and author each walkthrough (apply to every track):
1. List candidates per stage from the matrix: `.venv/bin/python -c "import json; rows=json.load(open('curriculum/coverage-matrix.json'))['lessons']; [print(r['id'], r['stage'], r['runtime'], r['learning_mode'], r['paths']['solutions'] or r['paths']['lesson']) for r in rows if r['track']=='TRACK']"`. Use only rows whose runtime is an ordinary profile (listed as a case, not an exclusion, by `check_module_references.py --list-only`).
2. Read `courses/<track>/AGENTS.md` for track rules, then the executable reference (tutorial track: the lesson source; practice track: the single non-Markdown solution file) and its guide.
3. Prefer a lesson whose reference prints a stable, deterministic line (a check marker, a label, an integer count, a schema or column list). Never use floating values, timings, paths, random draws, library version strings or warnings as expected_output. If a reference prints nothing deterministic, pick another lesson in the same stage. If no eligible lesson in a stage prints deterministic text, STOP and report the track and stage in the summary; do not edit course sources to add output.
4. Write 3 to 8 steps in program order with `lines` `[start, end]`, byte-exact `excerpt`, `title`, `explanation` (why, in plain American English for a newcomer) and `observe` (what the learner would see or which value now exists). Do not say "trace", "executed" or "live".
5. Compute `source_sha256` with `.venv/bin/python -c "import hashlib,sys; print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" PATH`.
6. Validate with `.venv/bin/python scripts/check_walkthroughs.py --track TRACK` and confirm three stages are listed.
