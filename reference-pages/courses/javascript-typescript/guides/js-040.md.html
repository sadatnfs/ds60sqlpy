js-040: A tested local JavaScript service#

Level and prerequisites#

Advanced, approximately 120 minutes. Direct prerequisites: js-039

Learning objectives#

Explain transport integration, repository lifetime, conflict, structured event with a concrete program. Trace how the values change, identify the assumptions, and make a boundary or invalid case observable. The first investigation is: POST item A with value 2, then GET the list. The final task tests correlate safe events and prove listener cleanup.

Purpose and mental model#

A local service combines transport handling with domain state and resource ownership. The HTTP handler should parse and validate a request before changing state, return a documented status, and finish every response. The domain operation here stores a small item with a unique id and bounded integer value. Duplicate creation returns a conflict without replacing the original item. This in-memory repository is lost when the process stops; it is not a database or a durable transaction system.

The fixture creates an actual HTTP server on an ephemeral 127.0.0.1 port and sends real fetch requests. Each exercise gets a fresh repository and server, preventing one scenario from making another pass through leftover state. The accepted body is JSON with an exact schema. A byte limit bounds retained request data, and unexpected media types or unsupported methods receive distinct errors. Client timeouts bound waiting, while finally closes active connections and the owned listener.

Observability records the operation's outcome without copying the full request. A generated request id is returned in a header and appears in a small event record with a normalized route and status. Unknown routes are logged as unknown rather than preserving arbitrary path text. This makes the evidence useful for correlating a request and its result while avoiding a second uncontrolled payload store in logs.

The service is an offline teaching fixture with no authentication, TLS, durable storage or public deployment claim. Loopback binding reduces exposure but does not establish a security sandbox. A production service would need those operational boundaries in addition to the contract and cleanup mechanisms demonstrated here. The reference's actual socket exchanges establish more than a pure handler unit test, but still only for the bounded local scenarios.

Vocabulary and concepts#

Transport integration: Testing actual request and response exchange through sockets.

Repository lifetime: The persistence scope of the state backing domain operations.

Conflict: A request that would violate an existing-state invariant.

Structured event: A bounded diagnostic record with named, intentionally selected fields.

How to run this lesson#

Use the prepared Node 24.22.1 profile. The classroom saves an ES module as main.mjs and executes it with Node. Only built-in Node or ECMAScript APIs are used. For a prepared native environment, node main.mjs is the same command on PowerShell and POSIX. Browser APIs have separate host requirements.

Save your own learner copy under ignored .learning/expansion/js-040/ or use a saved classroom pad. Record predictions before execution. Each worked program includes its helper definitions. The reference puts the six exercises in separate scopes, so a task cannot silently rely on a variable from a previous task. A successful assertion is silent; the final JSON receipt reports how many exercise blocks completed. A failing assertion must produce a failed process, not a generic success message.

Syntax anatomy and execution trace#

createServer delegates to an async dispatcher and captures unexpected rejections. Request bodies are read incrementally; only bytes within the configured cap are retained. JSON parsing and exact-field checks occur before Map insertion. Responses set application/json and an x-request-id header. The context tracks metrics after choosing a status. withService closes connections and awaits server.close in finally, even when a client assertion fails.

Worked example / walkthrough#

Example A: Create and retrieve an item over real HTTP#

The assertions cross the real transport boundary. A typed or pure handler result alone would not check serialization, headers, routing or socket cleanup.

import { strict as assert } from 'node:assert';
import { createServer } from 'node:http';

async function readBody(request) {
  const chunks = [];
  let bytes = 0;
  for await (const chunk of request) {
    bytes += chunk.length;
    if (bytes <= 512) chunks.push(chunk);
  }
  if (bytes > 512) throw Object.assign(new Error('body too large'), { status: 413 });
  return Buffer.concat(chunks).toString('utf8');
}
async function withService(use) {
  const items = new Map();
  const events = [];
  let sequence = 0;
  const server = createServer((incoming, response) => {
    const requestId = `R${++sequence}`;
    const path = new URL(incoming.url, 'http://127.0.0.1').pathname;
    const route = ['/items', '/health'].includes(path) ? path : 'unknown';
    function send(status, body) {
      events.push({ requestId, method: incoming.method, route, status });
      response.writeHead(status, { 'content-type': 'application/json; charset=utf-8', 'x-request-id': requestId });
      response.end(JSON.stringify(body));
    }
    async function dispatch() {
      if (route === 'unknown') { incoming.resume(); send(404, { error: 'not_found' }); return; }
      if (path === '/health' && incoming.method === 'GET') { send(200, { status: 'ready' }); return; }
      if (path === '/items' && incoming.method === 'GET') { send(200, [...items.values()].sort((a, b) => a.id.localeCompare(b.id))); return; }
      if (path !== '/items' || incoming.method !== 'POST') { incoming.resume(); send(405, { error: 'method_not_allowed' }); return; }
      if (incoming.headers['content-type']?.split(';')[0] !== 'application/json') { incoming.resume(); send(415, { error: 'json_required' }); return; }
      let value;
      try { value = JSON.parse(await readBody(incoming)); }
      catch (error) { send(error.status === 413 ? 413 : 400, { error: error.status === 413 ? 'body_too_large' : 'invalid_json' }); return; }
      if (value === null || typeof value !== 'object' || Array.isArray(value) || Object.keys(value).sort().join(',') !== 'id,value' || typeof value.id !== 'string' || !/^[A-Z]{1,8}$/u.test(value.id) || !Number.isSafeInteger(value.value) || Math.abs(value.value) > 1000) { send(400, { error: 'invalid_item' }); return; }
      if (items.has(value.id)) { send(409, { error: 'duplicate_id' }); return; }
      const accepted = { id: value.id, value: value.value };
      items.set(value.id, accepted);
      send(201, accepted);
    }
    dispatch().catch(() => { if (!response.headersSent) send(500, { error: 'internal_error' }); else response.destroy(); });
  });
  server.requestTimeout = 3000;
  await new Promise((resolve, reject) => { server.once('error', reject); server.listen(0, '127.0.0.1', resolve); });
  try {
    const address = server.address();
    if (address === null || typeof address === 'string') throw new Error('TCP address required');
    return await use({ base: `http://127.0.0.1:${address.port}`, server, events });
  } finally {
    server.closeAllConnections();
    await new Promise((resolve, reject) => server.close(error => error ? reject(error) : resolve()));
  }
}
function request(context, path, options = {}) {
  return fetch(new URL(path, context.base), { ...options, headers: { 'content-type': 'application/json', ...options.headers }, signal: AbortSignal.timeout(2000) });
}

export async function verify() {
  // Worked example
  {
    await withService(async context => {
      const created = await request(context, '/items', { method: 'POST', body: JSON.stringify({ id: 'A', value: 2 }) });
      assert.equal(created.status, 201);
      assert.deepEqual(await created.json(), { id: 'A', value: 2 });
      const listed = await request(context, '/items');
      assert.equal(listed.status, 200);
      assert.deepEqual(await listed.json(), [{ id: 'A', value: 2 }]);
    });
  }

  return { checks: 1, status: "passed" };
}

console.log(JSON.stringify(await verify()));

Expected: 201 created; subsequent 200 list contains exactly A.

Prediction before your attempt#

Trace the entry point and identify the values that exist before each operation. Distinguish a value from a reference to an object, a returned Promise from its eventual result, and a compile-time type from a runtime check. Write down the first observation that would disprove your explanation. A useful prediction includes an expected value or failure category, not merely a claim that the program should work.

For a loop, write the state before and after one iteration. For a callback, identify the caller and the arguments it supplies. For an asynchronous operation, identify who starts it, who awaits it, and who owns cleanup. These small traces make failures local: you can compare the first incorrect state instead of guessing from a much later symptom.

Exercises#

  1. Create and retrieve an item over real HTTP. POST item A with value 2, then GET the list. Expected: 201 created; subsequent 200 list contains exactly A. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Reject malformed data before changing state. Send malformed JSON and a wrong-shaped object, then inspect the repository through GET. Expected: both 400; list remains empty. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Preserve original state on duplicate creation. Create A with value 2, then try A with value 9. Expected: second request 409; stored value remains 2. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Enforce body and media-type contracts. Send 513 body bytes, then a text/plain payload. Expected: 413 for size and 415 for media type. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Distinguish unknown routes and unsupported methods. Request an absent path and DELETE on the item route. Expected: 404 and 405 respectively. Verify: Record the observed value, exception or browser state and compare it with that expectation.
  1. Correlate safe events and prove listener cleanup. Request health, inspect its request id and event keys, then check the server after the helper exits. Expected: matching id and status; server no longer listening. Verify: Record the observed value, exception or browser state and compare it with that expectation.

Common pitfalls and diagnosis#

Keep the smallest fixture that distinguishes the intended behavior from a tempting alternative. Read the assertion message and inspect the input, return value and state at that point. Do not remove a failing check just to reach the success receipt. Preserve the original failure, repair the responsible assumption, then check the normal path and the negative case again.

If a host API is absent, confirm the actual host and version before changing the algorithm. A successful parse does not prove that an API exists. Compiler success does not prove that external data satisfies a type. A browser interaction requires browser evidence. For resource-owning examples, inspect cleanup after failure as carefully as the happy path. The separate explanations discuss the specific mistaken inference in each exercise.

Progressive hints#

Start by comparing the actual value with the literal expected result. Next, isolate the expression that transforms it or the boundary where its type or ownership changes. If the discrepancy involves scheduling, replace unrelated work with a small trace array and await the exact completion you intend to observe. Finally, ask for one hint about the first incorrect assumption before opening the reference. Keep one controlled failure that would catch the same mistake returning.
