llm-032: Low-rank adaptation without a package download#

Level and prerequisites#

Advanced; approximately 135 minutes. Direct prerequisites: llm-031. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Derive and test a low-rank update while keeping base weights frozen. The central investigation is concrete: Use base W=I8, x=ones(8), target=zeros(8), A=ones((8,2))/8 and B=zeros((2,8)); form W+A@B and take one squared-loss SGD update of the adapter only. The finish condition is A and B have 32 parameters versus 64 in W. At initialization, zero delta matches the base. On the first step B changes, A may have zero gradient, and frozen W stays unchanged. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Change a model through a restricted update space#

Full fine-tuning allows a selected weight matrix to change entry by entry. Low-rank adaptation instead freezes a base matrix and learns an additive update represented by two smaller factors. The reduction concerns trainable state and the family of permitted updates. It does not mean that the base computation disappears, and it does not guarantee that every task can be solved as well as with unrestricted fine-tuning.

This lesson uses row-vector notation. Inputs X have shape(N,d_in), the frozen base W has shape(d_in,d_out), factor A has shape(d_in,r), and factor B has shape(r,d_out). The output is Y=X(W+A B). Rank r is the intermediate dimension of the update. Some libraries store transposed weight layouts or name the factors in the opposite order; the matrix equation is the reliable specification.

Count the restriction before discussing quality#

The full base matrix has d_ind_out entries. The two adapter factors have r(d_in+d_out). For the fixture d_in=d_out=8 and r=2, the base has 64 entries and the adapter 32. This is a 50 percent trainable-parameter reduction for this one tiny matrix, not the many-orders-of-magnitude reduction possible for different dimensions and selected layers. The number must be calculated from the actual shapes being adapted.

The update A B has rank at most r. It can change many visible entries while remaining constrained to a lower-dimensional matrix family. A rank-one outer product can be dense, so counting nonzero entries does not measure rank. Conversely, a nominal rank-two parameterization may realize an update of rank zero or one because its factors are zero or linearly dependent. The rank bound is an upper bound, not a promise that every degree of freedom is being used.

Many practical LoRA formulations multiply the update by a scale alpha/r. The current fixture omits that extra factor, effectively using scale 1. When translating the derivation to another implementation, include the scale in both the forward equation and gradients. Rank, scale, target modules, dropout and bias policy are configuration choices that belong in the adapter artifact.

Derive why zero initialization preserves the base function#

The reference initializes W as the 8-by-8 identity, every entry of A as 1/8, and B as zero. Because A B is zero, the initial adapted output equals XW exactly. This gives a useful starting contract: adding the adapter has not already changed the base prediction before any optimization step.

Both factors should not be initialized to zero under an ordinary differentiable product update. If A=0 and B=0, the gradients through each factor contain the other zero factor and can remain zero at initialization. Initializing one factor nonzero and the other zero preserves the initial function while leaving a path for one factor's first gradient. The fixture chooses nonzero A and zero B to make that path easy to inspect.

For the all-ones input row X, X A=[1,1] because each adapter column sums eight copies of 1/8. The initial output has eight ones. The objective is the mean squared output, L=(1/8)sum_j Y_j², so its initial value is 1. This objective is a constructed mechanism test; it does not represent a real instruction-following task.

Trace every matrix in the first backward pass#

Let G=dL/dY with shape(N,d_out). Differentiating Y=XW+(X A)B gives dL/dB=(X A)^T G and dL/dA=X^T G B^T. The frozen W is not included in the optimizer. These equations explain the first-step asymmetry without relying on a framework's printed tensor names.

At the fixture's initial state, each component of G is 2/8=1/4. Since X A=[1,1], every entry of dL/dB is 1/4. Since B=0, dL/dA is zero. The zero A gradient is mathematically expected; it is not evidence that A is disconnected from the graph. After B changes, the next backward pass can give A a nonzero gradient.

With SGD learning rate .1, the first update sets every B entry to-.025 while A remains unchanged. Each entry of A B becomes 2(1/8)(-.025)=-.00625. Multiplying by the all-ones X sums eight such entries, giving an adapter output of-.05 in every output coordinate. The new prediction is therefore .95 in all eight coordinates and the new objective is .95²=.9025. This independently derived value explains why the reference's post-step loss must be lower than the initial loss.

Because both columns of the initialized A are identical and both rows of B receive the same first update, this particular update is actually rank one despite the allowed rank-two parameterization. The reference correctly checks rank<=2 rather than equality. A useful explanation should distinguish the architecture's maximum rank from the rank realized by this data and initialization.

Freezing and optimizer membership are separate checks#

A frozen base should not receive an update through the selected training path. In this fixture, W is an ordinary tensor and the optimizer is constructed only from A and B. The saved base copy remains equal after the step. In a larger model, inspect both requires_grad and optimizer parameter groups, and consider buffers or stochastic modes that can change behavior without a parameter update.

A stale gradient left on a parameter can also be misleading when changing which parts are trainable. Clearing or rebuilding the intended optimizer state is part of a deliberate transition. The small lesson avoids those complications by constructing a fresh adapter optimizer, but it supplies the conceptual check: identify the trainable parameter set, the gradient paths and the actual post-step state separately.

Reducing trainable parameters can reduce their gradients and optimizer states. It does not remove the need to store or read the frozen base, and it does not automatically remove all activations needed for backward through the adapted network. The memory savings depend on the chosen layers, optimizer, precision and implementation. Quantized-base adaptation introduces another approximation contract, which the following precision chapter will examine.

Merge and reuse only under a bound artifact identity#

For inference, one can form a merged matrix W_merged=W+A B under the same layout and scale, then evaluate XW_merged. In exact arithmetic this equals the unmerged formula. Floating-point rounding can differ depending on dtype and operation order, so compare actual outputs under the intended tolerance before declaring a conversion correct. A merged adapter is not another independent update to add a second time.

An adapter must be paired with the base model and tokenizer it was trained against, along with target-module names, dimensions, rank, scale and any additional trainable components. Loading factors into a different base with compatible shapes can silently change the function in an unintended way. Cache identity must also change when adapted weights change, because cached K/V states were computed under previous parameters.

A useful task comparison evaluates the frozen base, the adapted model and, when relevant, another adaptation strategy on the same held-out families and scoring contract. It reports both task outcomes and resource changes. The original LoRA study supplies the broader method, while this lesson derives a tiny actual update. It does not establish pretrained-model quality or domain expertise from a matrix-rank check.

Vocabulary and concepts#

Low-rank update: A matrix change represented as the product of two smaller matrices.

Frozen base: Parameters excluded from the adaptation optimizer.

Zero-delta initialization: An adapter starting with no change to the base function.

Syntax anatomy and reasoning sequence#

Keep W as a tensor without requires_grad. Wrap A and B as Parameters and pass only those to SGD. The row-vector convention differs from frameworks that store Linear weights as(out,in), so record the orientation before transplanting equations. Compute delta=A@B and compare its shape with W. Snapshot the base bytes and assert exact preservation after the adapter update.

Derive the first low-rank update exactly#

This lesson uses row vectors and the convention y=x(W+AB), with W[8, 8], A[8, 2] and B[2, 8]. There is no additional alpha/r multiplier here, so the effective scale is one. The frozen W is the identity, every element of A is 1/8, B starts at zero and x is an all-ones row. Thus x*A=[1, 1], the adapter output is zero, y is all ones and mean(y squared)=1.

For this loss, the gradient G=dL/dy has eight entries equal to 2/8=0.25. Matrix differentiation gives dL/dB=(xA).TG, so every B gradient is 0.25. It also gives dL/dA=x.TGB.T, which is zero at this first step because B is zero. Zero initial dA is therefore expected, not evidence that autograd is broken. If both A and B started at zero, both adapter gradients would vanish for this bilinear path.

SGD at learning rate 0.1 changes every B entry to-0.025. Each entry of AB is then2(1/8)*(-0.025)=-0.00625. Multiplying by the eight ones in x changes each output by-0.05, giving y=0.95 and loss 0.9025. The update has rank at most two, but these identical columns and rows make its actual rank one. A rank bound is not a promise that optimization uses every available direction.

Frozen weights still participate in the computation#

Freezing W prevents optimizer updates to that parameter; it does not remove its contribution to the output or necessarily stop gradients to earlier layers. For a trainable input, dL/dx=G(W+AB).T still includes W. Distinguish a frozen parameter from detaching an entire activation path. Confirm which tensors the optimizer receives and inspect both parameter changes and gradients.

The LoRA paper motivates learning a low-rank change to a frozen base. The arithmetic above is an original small illustration, not a replication of large-model quality or memory measurements. Trainable parameter count here is 82+28=32 rather than 64 for a full W update. The frozen base still occupies memory; activations and optimizer states also matter. Merging W+A*B can remove the extra adapter operations for this linear layer, but changing dtype or quantization can change numerical parity. Compare with applied LoRA, whose explicitly stated scale is two and whose first-step numbers therefore differ.

Worked example / walkthrough#

Example A: Count adapter parameters#

The parameter reduction comes from the factorization rank2. Increasing rank increases trainable state and changes the set of possible updates.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

w=torch.eye(8); a=nn.Parameter(torch.ones((8,2))/8); b=nn.Parameter(torch.zeros((2,8))); x=torch.ones((1,8))
assert a.numel()+b.numel()==32 and w.numel()==64

Expected: adapter32 parameters versus base64.

Example B: Check zero initial delta#

ZeroB eliminates the product while retaining a connected path forB through A. The base prediction is preserved exactly at initialization.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

w=torch.eye(8); a=nn.Parameter(torch.ones((8,2))/8); b=nn.Parameter(torch.zeros((2,8))); x=torch.ones((1,8))
assert a.numel()+b.numel()==32 and w.numel()==64
delta=a@b; initial=x@(w+delta)
assert torch.equal(delta,torch.zeros((8,8))); assert torch.equal(initial,x@w)

Expected: both equal ones(1,8).

Common pitfalls and diagnosis#

Confirm the matrix orientation and adapter scale before copying numerical results from another implementation. Zero initial A gradient is expected when B starts at zero; zeroing both factors stalls the bilinear path. Check actual parameter changes, rank and merge parity separately from parameter-count or memory estimates.
