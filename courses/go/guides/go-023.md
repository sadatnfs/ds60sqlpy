## Why this mechanism matters

An HTTP client owns a request lifecycle that can fail before any response exists or return a valid HTTP response describing an application failure. A 404 is usually not a transport error. Callers must inspect status, bound response bodies and close every acquired response body. Context cancellation propagates an explicit stop signal, while a client timeout bounds the overall operation. Reuse clients and transports in real services rather than constructing an unbounded pool of connections. This lesson injects a RoundTripper fake so the real client logic can be exercised without DNS, ports or external services.

## Vocabulary and concepts

- **Transport error:** Failure to obtain a valid HTTP response.
- **Response ownership:** The obligation to consume or close an acquired body.
- **Cancellation:** An explicit request to stop bounded work.

## Syntax anatomy and reasoning

RoundTrip(*http.Request) returns a response or a transport error. A function adapter can implement that interface for tests. NewRequestWithContext binds a request to cancellation. Client.Do follows client policy, including status-independent transport success. Read at most limit+1 bytes to detect oversized bodies. A response body must be closed even when its status is not accepted.

## Worked example / walkthrough

### Worked example 1: Read a successful response

Use a fake transport returning status 200 and body ready.

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"io"
	"net/http"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

type roundTripFunc func(*http.Request) (*http.Response, error)

func (f roundTripFunc) RoundTrip(r *http.Request) (*http.Response, error) { return f(r) }
func fetch(ctx context.Context, status int, body string, limit int64) (string, error) {
	client := &http.Client{Transport: roundTripFunc(func(r *http.Request) (*http.Response, error) {
		if err := r.Context().Err(); err != nil {
			return nil, err
		}
		return &http.Response{StatusCode: status, Header: make(http.Header), Body: io.NopCloser(strings.NewReader(body)), Request: r}, nil
	})}
	req, err := http.NewRequestWithContext(ctx, "GET", "http://lesson.invalid/resource", nil)
	if err != nil {
		return "", err
	}
	response, err := client.Do(req)
	if err != nil {
		return "", err
	}
	defer response.Body.Close()
	if response.StatusCode != 200 {
		return "", fmt.Errorf("status %d", response.StatusCode)
	}
	data, err := io.ReadAll(io.LimitReader(response.Body, limit+1))
	if err != nil {
		return "", err
	}
	if int64(len(data)) > limit {
		return "", errors.New("response too large")
	}
	return string(data), nil
}

func main() {
	// Read a successful response
	{
		v, err := fetch(context.Background(), 200, "ready", 8)
		check(err == nil && v == "ready", "client success")
	}
	fmt.Println("Worked example checks passed.")
}

```

**Observe:** The client helper returns ready without error.

The fake isolates policy from the network. A live connection test would establish additional behavior and requires a separate owned target.


**Observe:** The helper returns an error despite transport success.

Client.Do does not classify every non-2xx response as a transport failure. Application status policy belongs in the consuming code.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
