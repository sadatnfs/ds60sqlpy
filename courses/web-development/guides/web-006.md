# web-006: Images, SVG, alternatives and media decisions

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-005`

## Learning objectives

Create an offline SVG progress illustration with a textual equivalent. Plan an accessible video lesson without autoplay. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

Alternative text communicates an image's purpose in its context. A decorative image may use empty alt text so it does not add noise. An informative image needs a concise equivalent; a complex chart usually needs surrounding explanation or a data table as well. A filename is rarely useful alternative text. The same picture can need different alternatives in different contexts because the task differs.

A figure groups self-contained media with a caption. A caption is visible to everyone, while an alternative serves when the image is unavailable or not visually perceived. SVG describes vector geometry and can be written inline, which keeps our fixtures offline. A viewBox defines internal coordinates; CSS controls the displayed dimensions. Width and height reserve space and reduce unexpected layout movement.

## Syntax anatomy and mechanism

For inline SVG, connect a title and description using `aria-labelledby`, and use `role="img"` for a meaningful standalone illustration. Decorative SVG can be hidden from assistive technology. Use a textual list when exact values matter. Audio and video require captions or transcripts, appropriate controls and deliberate autoplay decisions; no media downloads are required by this lesson.

## Classroom execution and offline inputs

Choose **HTML browser preview** in the classroom. The pad is one complete HTML document with embedded CSS and, where taught, embedded JavaScript. Its preview is isolated from the classroom and recreated on each run. It does not contact a server, submit real forms, read cookies, fetch assets or load a CDN. All fixtures are inline and synthetic. The browser uses its native HTML parser, so classic-script ordering, shared lexical bindings, inline modules and real DOMContentLoaded/load events keep their browser semantics. External module imports remain blocked. Navigation metadata such as base and meta http-equiv is rejected explicitly. On any supported host, the browser renders the document while Docker serves the classroom. No host compiler is needed.

Run your own source after implementing the task. A reference's checks inspect only the named initial conditions. Its success message is not a full accessibility audit, proof of responsive behavior at every size, or evidence that you implemented the solution yourself. Inspect actual output after keyboard input, resizing and changes. Save your source before comparing with a reference. The document and its CSS share one saved pad; HTML and CSS remain different languages within that artifact.

## Worked example / walkthrough

### Worked example 1: Informative image

The alternative describes the information relevant to this page.

```html
<img src="local-map.svg" alt="Library entrance is on the east side" width="400" height="240">
```

**Expected observation:** The dimensions reserve space; the alternative conveys a useful location.

### Worked example 2: Inline SVG labeling

The named title is inside the vector image.

```html
<svg viewBox="0 0 100 30" role="img" aria-labelledby="label"><title id="label">Three completed lessons</title><rect width="60" height="20"/></svg>
```

**Expected observation:** A vector shape has a textual accessible name.

## Six progressive exercises

### Exercise 1: Choose alternatives for decorative and informative images.

**Expected evidence:** Decorative images have empty alternatives; informative ones convey task-relevant meaning.

**Progressive hint:** Trace the smallest example before editing. Name which values are source and which are observations.

### Exercise 2: Add a visible caption without repeating a verbose alternative.

**Expected evidence:** Caption and alternative serve complementary roles.

**Progressive hint:** Change only the named feature. Compare with the unchanged example and explain any unaffected behavior.

### Exercise 3: Create an offline SVG progress illustration with a textual equivalent.

**Expected evidence:** The image has an accessible name and the numeric progress is visible as text.

**Progressive hint:** Sketch the structure or data contract first. Reuse the mechanism from the examples without copying the reference.

### Exercise 4: Explain why chart alt text saying chart is insufficient.

**Expected evidence:** It names the object but omits the information the reader needs.

**Progressive hint:** Keep the failing input. Identify the first layer where the observed result differs from the intended contract.

### Exercise 5: Shrink the preview and preserve the SVG aspect ratio.

**Expected evidence:** The illustration scales while labels and the textual equivalent remain readable.

**Progressive hint:** Predict the boundary before running it. Add an explicit check or manual observation that would detect a regression.

### Exercise 6: Plan an accessible video lesson without autoplay.

**Expected evidence:** Provide controls, captions and a transcript, with deliberate download size and motion choices.

**Progressive hint:** Explain your choice to someone who has not seen the code. Include one limitation and the evidence needed to remove it.

## Debugging and common mistakes

An image loading successfully says nothing about its alternative. Avoid remote placeholders in offline examples. Do not convert all useful text into an image just to control typography.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

## Retrieval, transfer and next steps

Close the worked answers and explain alternative text, figure, caption without using their names as definitions. Reconstruct the central example from a blank pad or worksheet. Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation. When a behavior belongs to the browser, observe it in the browser; when it belongs to an HTTP server, keep that evidence separate from a CLI simulation.

Before moving on, keep a short learning record: your prediction, source revision, actual result, explanation and unresolved limitation. Revisit a direct prerequisite if you can reproduce output but cannot explain the mechanism. The path has milestones, not a fixed daily schedule, and a saved completion marker is a personal progress record rather than a professional certification.
