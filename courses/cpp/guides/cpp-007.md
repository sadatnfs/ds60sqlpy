# cpp-007: Vectors and standard algorithms

## Learning objectives

Use an owning sequence and choose an algorithm with a clear order contract.

## Vocabulary and concepts

A vector owns a contiguous sequence and knows its current size. An iterator identifies a position for a standard algorithm. Algorithms separate traversal from intent: sorting orders values, counting measures a predicate, and accumulation combines values. Sorting a copy preserves the original evidence.

<!-- terms:start -->

- **`std::vector`:** an owning container that stores its elements in contiguous memory.
- **size and capacity:** size counts constructed elements the program may access; capacity counts how many elements fit before another allocation.
- **iterator:** an object that identifies a position in a sequence for a standard algorithm.
- **reallocation:** moving elements into a new buffer when capacity runs out, which invalidates every pointer, reference and iterator into the old storage.
- **predicate:** a function that returns true or false and tells an algorithm such as a count which elements match.

<!-- terms:end -->

## Syntax and mechanism

`std::sort(xs.begin(),xs.end())` sorts the half-open range in place. `std::accumulate(...,0LL)` chooses a long long accumulator from its initial value. A sorted vector still contains duplicate elements unless a separate operation removes them.

## Trace the mechanism

A vector is a bag of ordered elements, not a set. The two threes in [3, 1, 3, 0] occupy separate positions after sorting. Erasing duplicates is a new semantic decision. The common sort/unique/erase sequence has two phases after sorting: unique rearranges the retained prefix and returns a new logical end, while erase changes vector size. Inspect both the values and size so a stale tail cannot masquerade as a unique result.

## Vector ownership, capacity and iterator validity

A vector has a size and a capacity. Size counts constructed elements that the program may access. Capacity describes how many elements the current storage can accommodate before another allocation is needed. reserve(4) requests capacity for at least four elements but leaves an empty vector at size 0. Writing `xs[0]` after reserve alone is invalid because no element has been constructed there. push_back creates a new element and increases size; resize changes size and constructs or destroys elements as needed.

Contiguous storage means the elements occupy adjacent positions, which makes indexed access and many algorithms efficient. It also explains reallocation. If growth requires a new buffer, the vector moves or copies elements into that buffer and releases the old storage. Every pointer, reference and iterator into the old element storage is then invalid. Do not demonstrate this by dereferencing a stale pointer: that is undefined behavior, so even an apparently correct printed value is not evidence of safety.

The second program forces a capacity increase with reserve(capacity()+1) after adding one element. It retains an index, not an element pointer, and reacquires access as xs[index] after the operation. This is safe for that example because reallocation preserves the sequence and index 0 still names the same element. It is not a general fix for erase or insert before an index, which can change what a position means. Stable business identity may need an ID lookup rather than a remembered position.

begin and end define a half-open range. begin names the first element when one exists; end names the position after the last and must not be dereferenced. Empty vectors have begin==end, so algorithms can handle them without a special invalid first-element access. Sorting rearranges values within the range. It preserves multiplicity: the two threes remain two elements. Copying original before sorting gives a separate owner, so the original order remains available for comparison.

accumulate uses its initial value both as the starting total and to determine the accumulator type. Starting with 0LL selects long long and the additive identity. Starting with 10LL adds an unwanted ten even though the element traversal is otherwise correct. Starting with int 0 can introduce a narrower intermediate accumulator for large values. A wider accumulator reduces some overflow risks but is not an unlimited arithmetic guarantee.

The sort/unique/erase idiom has separate contracts. sort brings equal values together. unique rearranges a retained prefix and returns its logical end; it does not shrink the vector. erase removes the tail and changes size. Code that prints the whole vector after unique but before erase can show unspecified leftover tail values and mistakenly believe deduplication failed. Inspect the retained range and final size, not just one displayed element.

Insertion and erasure have their own invalidation rules even when no reallocation occurs. Erasing shifts later elements left, invalidating positions at or after the erased point. The safe iteration pattern uses the iterator returned by erase rather than incrementing an invalid old iterator. These rules matter because a vector is a sequence with ownership and position semantics, not a set or a permanently stable collection of element addresses.

## Worked example / walkthrough

Example 1 sorts a copy of `{3, 1, 3, 0}`: the copy becomes `{0, 1, 3, 3}` with both threes kept, while the original keeps its order. Example 2 calls `reserve(4)`, appends 8, then forces a reallocation with a larger `reserve` and reads through an index. The index survives the move to new storage where an old iterator or pointer would not, and the program prints `size=1 value=8`. Build rules: [study guide](../STUDY-GUIDE.md#worked-examples).

### Worked example 1

[Complete program 1](../examples/cpp-007-example-1.cpp)

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>
#include <numeric>
#include <vector>

int main() {
  std::vector<int> original{3, 1, 3, 0};
  auto sorted = original;
  std::sort(sorted.begin(), sorted.end());
  assert((sorted == std::vector<int>{0, 1, 3, 3}));
  assert((original == std::vector<int>{3, 1, 3, 0}));
  std::cout << "sorted:";
  for (int value : sorted)
    std::cout << " " << value;
  std::cout << "\nsum=" << std::accumulate(sorted.begin(), sorted.end(), 0LL)
            << "\n";
  std::cout << "cpp-007 example 1 checks passed\n";
  return 0;
}
```

**Expected:** With assertions enabled, the program exits with status 0 and prints:

```text
sorted: 0 1 3 3
sum=7
cpp-007 example 1 checks passed
```

### Worked example 2

[Complete program 2](../examples/cpp-007-example-2.cpp)

```cpp
#include <cassert>
#include <cstddef>
#include <iostream>
#include <numeric>
#include <vector>

int main() {
  std::vector<int> xs;
  xs.reserve(4);
  assert(xs.size() == 0 && xs.capacity() >= 4);
  assert(xs.begin() == xs.end());
  assert(std::accumulate(xs.begin(), xs.end(), 0LL) == 0);
  xs.push_back(8);
  const auto index = std::size_t{0};
  xs.reserve(xs.capacity() + 1);
  // Any old element pointer or iterator is invalid after this reallocation.
  assert(xs[index] == 8);
  std::cout << "size=" << xs.size() << " value=" << xs[index] << "\n";
  std::cout << "cpp-007 example 2 checks passed\n";
  return 0;
}
```

**Expected:** With assertions enabled, the program exits with status 0 and prints:

```text
size=1 value=8
cpp-007 example 2 checks passed
```

## Exercises

### Exercise 1: Predict sorting

Sort [3, 1, 3, 0] on paper.

**Expected result/shape:** [0, 1, 3, 3], size 4.

**Verify:** Compare your paper result with the `sorted:` line printed by Worked example 1, element by element, and confirm the duplicate 3 appears twice.

**Progressive hints:** Ordering does not remove multiplicity.

### Exercise 2: Preserve evidence

Sort a copy and compare the original.

**Expected result/shape:** Original remains [3, 1, 3, 0].

**Verify:** Assert `original == std::vector<int>{3, 1, 3, 0}` after sorting the copy, and assert `std::ranges::is_sorted(copy)`.

**Progressive hints:** Copying creates a separately owned buffer.

### Exercise 3: Count a boundary

Use count_if to count >=3.

**Expected result/shape:** 2 matching elements.

**Verify:** Assert the `std::count_if` result with the predicate `x >= 3` is 2 on `{3, 1, 3, 0}`; changing the predicate to `x > 3` must give 0.

**Progressive hints:** Both equal-valued rows count.

### Exercise 4: Repair a wrong total

Replace accumulate start 0LL with 10LL, then repair.

**Expected result/shape:** Wrong total 17; correct total 7.

**Verify:** Run the scratch copy and confirm it prints `sum=17`, exactly 10 more than the data; after restoring `0LL` the `sum=7` line must return.

**Progressive hints:** The initial value participates in the fold.

### Exercise 5: Check an empty vector

Sort, count and sum an empty vector.

**Expected result/shape:** Size 0, count 0, sum 0; no dereference.

**Verify:** Assert `xs.size() == 0`, a count of 0 and `std::accumulate(xs.begin(), xs.end(), 0LL) == 0` in one program, with no `front()` or `[0]` call.

**Progressive hints:** Algorithms accept an empty half-open range.

### Exercise 6: Transfer to ordered unique values

Sort [3, 1, 3, 0], then erase the unique tail.

**Expected result/shape:** [0, 1, 3], size 3.

**Verify:** Assert `xs == std::vector<int>{0, 1, 3}` after `xs.erase(std::unique(xs.begin(), xs.end()), xs.end())`; run `std::unique` once without sorting to see the non-adjacent 3 survive.

**Progressive hints:** unique moves survivors but erase actually changes vector size.

## Self-check

Why does sorting keep both threes, and what would `std::unique` plus `erase` change? For Example 2, explain why the stored index still reads 8 after the second `reserve`, while an iterator taken before it would be invalid.

## Common pitfalls

A capacity of 4 with size 0 is not four accessible integers. Use at(index) for a checked diagnostic while learning, and remember that operator[] requires a valid index. If a bug appears only after growth, inspect every retained pointer/reference/iterator across push_back or reserve. If a deduplicated result still has size 4, check whether erase was omitted. If a total differs by ten, inspect the accumulate identity before blaming sort.

## Retrieval and transfer

Close the source and redo Exercise 6: sort `[3, 1, 3, 0]`, then erase the duplicate tail that `std::unique` leaves, giving `[0, 1, 3]`. Explain why forgetting `erase` keeps the old size. Then say how the cost changes for a million values and whether a set would be a better structure.
