# js-047: Axes, ticks, labels and numerical formatting

## Level and prerequisites

Intermediate; about 110 minutes plus independent practice. Direct prerequisites: `js-046`. This is the D3.js specialization within the JavaScript path. Use the original language and browser lessons whenever syntax or DOM behavior is unfamiliar.

## Learning objectives

Build a labeled quantitative axis. Design axes for counts and rates side by side. Produce a chart whose data transformation, visual encoding and interaction can be explained and checked independently.

## Purpose, vocabulary and mental model

An axis makes a scale interpretable by displaying reference positions and labels. D3 axis generators create SVG elements from a scale; they do not choose the right statistical units or description. The chart author must name the quantity and make tick formatting consistent with the values.

Ticks are selected reference values, not necessarily every data point. A requested tick count is often a hint rather than an exact guarantee. Explicit tick values are useful for small controlled examples. Formatting changes displayed text, not the underlying numeric scale.

Percent data illustrates a common mistake. A formatter expecting fractions displays 0.25 as 25%. If the data is already 25 and you apply that formatter, it displays 2500%. Keep the stored representation, axis label and annotation units aligned. Precision should communicate measurement meaning rather than decorate every value with many decimals.

## Syntax anatomy and mechanism

Call an axis generator on a group: `g.call(d3.axisBottom(x))`. Translate that group to the bottom coordinate, leaving the scale range in the chart’s coordinate system. Recalling the generator on the same group updates its ticks.

Use a visible axis title and a chart description. Avoid assuming that a bare dollar sign, abbreviation or color legend communicates enough context. Units and denominator matter, especially for rates and normalized comparisons.

## Worked example / walkthrough

### Worked example 1: Format fractions as percentages

The number remains a fraction internally.

```javascript
const percent=d3.format(".0%");
console.log(percent(0.25), percent(25));
```

**Expected observation:** 25% and 2500%, revealing the representation mismatch.

### Worked example 2: Use explicit ticks for a teaching chart

The same scale drives marks and axis.

```javascript
const x=d3.scaleLinear().domain([0,10]).range([60,600]);
svg.append("g").attr("transform","translate(0,300)").call(d3.axisBottom(x).tickValues([0,5,10]));
```

**Expected observation:** Three labeled tick positions align with the scale endpoints and midpoint.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose 2500% for a value intended as 25%. Its distinguishing evidence is The stored percentage was treated as a fraction. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
