Documentation map#

DS60 has one Docker classroom and one maintained source tree. Historical day numbers identify lessons; they do not limit your pace or the number of subjects.

Learn or return to saved work#

  1. Read the front README for supported hosts and the subject directory.
  2. Follow one-command setup, then first success.
  3. Use the classroom guide for pads, live previews, results and language switching.
  4. Choose a route with placement and pacing, lesson prerequisites and subject READMEs.
  5. Consult troubleshooting for an observed failure and storage boundaries before cleanup.

Windows uses WSL 2; macOS and Linux use the same Linux-container product. Docker basics explains prerequisites. Manual Compose and backup covers transfer. Normal startup is ./classroom; strict return is ./classroom resume.

Learn with a coding assistant#

Start with AI tutoring. The repository's learning skill guides placement, explanation, progressive hints and review across all subjects. MCP tutoring provides read-only curriculum tools by default. It does not execute code or implicitly read private Docker pads. Tutorial books expose worked explanations; practice lessons keep attempts and reference solutions separate.

Develop or add a subject#

Start with CONTRIBUTING.md, AGENTS.md and the repository tour. The checkpoint describes current architecture. Validation lists exact local and CI gates and distinguishes source checks, execution and platform qualification.

Use the authoring skill, extension playbook, module contract and content contract for progression, durable sources, registration, runtime preparation and browser acceptance. Read the closest subject AGENTS file and authoring README. Derive IDs/counts from loaders, not another list.

The curriculum map, gap backlog and design references support teaching decisions. Generated practice coverage and depth reports are maintained outputs. The founding subject plans remain active metadata; the former prototype application has been removed.
