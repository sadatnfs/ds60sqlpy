Contributor formatting toolchain#

This directory is the build context for the Ubuntu formatting and linting image. R uses a separate image to retain its compatible R system libraries. Its Dockerfile.r builds from the repository root and copies only the existing hash-locked R package list and installer; the root Docker ignore policy excludes private state and Git history. No course files are copied into either image. The host wrapper mounts the checkout and runs both prepared tools without network access or an engine socket inside the containers.

The image supports Linux amd64 and arm64. Windows contributors run the same Linux image through WSL 2 and their Docker engine. It does not start classroom services or change learner volumes.

Shared entrypoints#

Run from the repository root with a local Linux-container engine:

./scripts/format-repo
./scripts/format-repo --check
./scripts/lint-repo
./scripts/format-repo --list

The wrapper derives a local ds60-formatting image tag from its tool context, excluding the separately owned R Dockerfile. ds60-formatting-r depends only on that R Dockerfile and the shared R lock/installer, not lesson or runtime source files. First use builds selected tools with visible logs; unchanged preparation reuses them. --build explicitly rebuilds selected tools. The unfiltered pass runs R first, then the remaining formatters, then refreshes its owned generated views. A failed R pass stops that chain. Shared regeneration compiles the lesson TeX before building readers; --language NAME narrows source adapters and omits shared reader refresh. Check/list/lint modes mount source read-only. Listing uses the existing inventory without preparing the R image. --language r uses only the R image and does not refresh shared readers. Mixed language selections run the relevant isolated passes without duplicating R checks. The wrapper requires a local Unix-socket context because a remote engine cannot safely interpret this checkout's bind path. It never mounts an engine socket inside the tool container.

This README is excluded from the image build context and fingerprint. Updating instructions therefore reuses the same tools. Dockerfile, locks, wrappers and .dockerignore remain fingerprinted; a tool-input change selects a new image.

Reuse an explicitly reviewed local tool image#

A retained image can be selected without a registry connection:

DS60_FORMAT_IMAGE=reviewed-main-tools:local \
  DS60_FORMAT_R_IMAGE=reviewed-r-tools:local \
  DS60_FORMAT_JULIA_IMAGE=reviewed-julia-tools:local \
  ./scripts/format-repo --check

Use actual prepared image names or immutable IDs available on the machine. Overrides require Linux images matching both the local engine and host native architecture. The wrapper inspects every selected override before any source edit, pins its immutable ID, prints that identity, selects the tooling entrypoint and uses --pull=never. It refuses missing images, architecture mismatches and --build together with an override. Ordinary default fingerprint selection is unchanged. An override never retags an old image as a new build and does not prove that changed Docker inputs have been rebuilt. Verify the locked tool versions and retain the actual image identities with the resulting checks.

Fenced code and authoring containers#

Markdown prose remains outside Prettier. The shared formatting pass uses format_inline_code.py for supported language-tagged fenced programs. The fence scanner distinguishes backticks and tildes, opening/closing lengths, up to three spaces of CommonMark indentation, closed versus unclosed blocks and LF/CRLF input. It replaces only admitted body spans. Prose, TeX, headings, links, fence delimiters and technical identifier code spans remain byte-for-byte unchanged.

Every public language family in the standalone formatter has explicit fence aliases. Python, R, Julia, Stan, SQL/dbt, JavaScript/TypeScript, JSON/YAML, HTML/CSS, Java, C/C++/CUDA, C#, Go, Rust, Swift, Scala, PHP, TOML, XML, CMake and Dockerfile snippets use their pinned existing adapter. Python uses an AST and comment signature; SQL retains its PostgreSQL/psql guard; R and Julia compare native parsed expressions; other families use typed values or syntax trees with protected literal spans. XML permits indentation between element-only children, while mixed content, leaf text and xml:space="preserve" remain exact. Formatter output must parse, preserve the admitted structure and values, and be idempotent. No example is executed, compiled to run, or permitted to download dependencies. Java statement and member excerpts use temporary parsed method/class contexts; the wrapper is removed and the original excerpt structure is checked again. Optional separators and arrow parameter parentheses are normalized only in reviewed grammar positions. JavaScript array holes, Rust tuple arity and typed parameters remain significant. Scala 2.13 wrapped chains may have a single expression indentation node. HTML void-tag delimiters may differ, while quoted attribute values, text, scripts and styles remain exact. Docker mount values, shell bodies and heredocs remain protected. C++ fences disable automatic namespace comments, and Python comment bytes, including cell markers, are restored. Rust macro token trees remain verbatim because an arbitrary macro can distinguish punctuation that ordinary Rust expressions treat as optional. Each such region is reported explicitly while surrounding Rust source can still be formatted. TypeScript union formatting preserves its ordered member list and parenthesized type groups, including an optional leading union separator.

The same body-only contract applies to complete fences inside static Python and JSON authoring prose strings. An independent enclosing-file check allows only those approved prose constants to change. Known prose assignments/fields such as guide, introduction, body, explanation and worked_examples are admitted; expected outputs, executable source fields, replacement needles and unknown roles remain unchanged with a recorded reason. The reviewed NLP author() example argument has an explicit positional contract. Identical JSON string values in prose and expected output are tracked by their distinct field paths. Notebook Markdown cells are supported; code cells, outputs, execution counters and metadata values are preserved. Python authoring f-strings and concatenated literals are inventoried explicitly when their source cannot be rewritten safely without interpreting templates.

Generated Markdown is checked but never rewritten directly by the source formatter. Owner renderers can call canonical_markdown(text, root=repo_root, path=relative_output) from scripts.format_inline_code before their normal Markdown write. The hook admits only explicitly generator-owned paths in the formatting policy, formats in memory through the same guards, and reports preserved regions. It never writes a file, runs a generator, executes an example or installs dependencies. Run such generators in the documented prepared formatter environment. Required tools for supported fences must be available; missing tools fail explicitly rather than producing a silently noncanonical output. The owner's normal command and publication assertions remain authoritative.

A differing checked-in generated fence reports needs-regeneration, with matching authored source candidates when available. Repair its durable program/prose input, run the subject's documented generator, then repeat the formatting and generation checks. Existing publication assertions remain in place. The statistics-book synchronizer retains its declared complete-example relationships and independent AST equivalence proof. Shared HTML is regenerated only after successful source checks.

Untyped/text/output blocks, interactive prompts, nested Markdown containers, unknown language labels, R Markdown/Quarto documents and fragments rejected by the declared parser are retained with explicit reasons and positions. Unquoted <your-...> shell placeholders are inventoried as templates rather than commands. DAX and PowerShell labels currently have no standalone formatter adapter and are listed as unsupported. These entries are not reported as formatted or executed. A missing prepared tool, unexpected formatter failure or changed literal/structure fails the check. Restoring exact authored literals can affect a later line-wrap choice, so at most three additional guarded passes may find a fixed point. Output must then be byte-idempotent; continued changes or oscillation fail the check. ./scripts/format-repo --list includes the complete inventory; normal runs show preservation counts and all actionable drift/errors.

For a machine-readable inventory inside a prepared tools environment:

python3 scripts/format_inline_code.py --list --report /tmp/inline-inventory.json

The report records source positions, language, status, reason and hashes without copying entire programs. It does not replace compiler, runtime or scientific qualification. Language-only passes cover only that selection and still require the other toolchain shards for a full repository result.

R source checks use Rscript --vanilla and stdin. Formatting uses styler's line-break scope and independently compares parsed expressions before any write, preserving executable meaning and literal values. Invalid syntax or a changed parse fails without replacing the source. Lint uses fixed lexical lintr rules plus R's parser, with cache and ambient .lintr settings disabled. It does not evaluate learner expressions, load .Rprofile, install packages, or infer that an R model is statistically valid. R Markdown and Quarto prose are not silently executed or reformatted by this source adapter.

The isolated image can run python3 docker/formatting/smoke.py --r-only with the repository mounted. This checks idempotence, protected literal spacing, valid and invalid parsing, lint and a source-side-effect sentinel without executing the supplied source. The ordinary smoke command remains specific to the Ubuntu toolchain.

JavaScript and TypeScript linting uses ESLint 9.39.1, typescript-eslint 8.47.0, TypeScript 5.9.3 and globals 16.5.0. ShellCheck is supplied by Ubuntu 24.04. Offline source parsing uses tree-sitter-language-pack 0.13.0 with its exact compatible grammar dependencies. PostgreSQL parsing uses pglast 7.21. These syntax checks do not compile, execute or type-check every language. PHP parsing and CUDA C++ formatting do not qualify an HTTP server or a GPU. Use actual profile checks for those execution claims.

The image also includes the source reader's locked latex2mathml and Pygments versions so the formatting script can regenerate published readers. See the root contributor documentation for the public commands and generated-file policy.

Deliberate upgrades#

Language image references include release digests. npm uses package-lock.json and disables package install scripts. Python uses exact versions and --require-hashes; requirements.lock covers the supported Linux wheel architectures. The pinned Go module versions are verified through Go's checksum database. install-downloads.py verifies SHA-256 before installing the exact Scalafmt and pgFormatter archives. Do not disable TLS verification or add local proxy credentials or certificates to this directory.

To change a tool version, update its pin and applicable lockfile, run the cross-language smoke check in the newly built image, apply the formatter, then run formatting and lint checks again. Review semantic changes and regenerate readers before committing. An operating-system security update can change base utilities without changing formatter versions; the image is not claimed to be bit-for-bit reproducible across all build dates.

The final image copies only the formatter and necessary Swift/Rust shared libraries. Full build SDKs remain in discarded build stages. You can select a public npm mirror with the Docker build argument NPM_REGISTRY; default builds use the public npm registry. Registry overrides must still retain TLS and lockfile integrity verification.

Tool smoke check#

After preparing the image, run the smoke script with the checkout mounted at /workspace and the container network disabled:

docker run --rm --network none --read-only --tmpfs /tmp \
  --mount "type=bind,src=$PWD,dst=/workspace,readonly" \
  <your-formatting-image> python3 docker/formatting/smoke.py

It exercises the configured syntax formatters, checks that a second pass is unchanged, and checks SQL literal and psql directive boundaries. Prose rendering, guarded fence formatting and owned-fence synchronization have separate repository gates. Replace <your-formatting-image> with the actual ds60-formatting tag prepared by the wrapper and shown in the local image inventory; do not guess a version. The public root script manages that fingerprinted tag. Use the smoke command when changing the toolchain itself, alongside the repository checks.
