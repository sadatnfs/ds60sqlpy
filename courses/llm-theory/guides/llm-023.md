## Purpose and mental model

<!-- textbook-foundations-start -->

### Bound both the candidate set and the generation process

A language model may assign a small amount of probability to many possible continuations. Sampling from the entire distribution can select unlikely alternatives, while always taking the maximum removes variation. Nucleus sampling offers a different policy: retain enough of the highest-probability candidates to cover a chosen amount of the original mass, then sample within that set. Its support size adapts to how concentrated the current distribution is.

The example distribution is [0.5,0.3,0.2], already in descending order. With threshold 0.6, the first candidate alone covers only 0.5, so it is insufficient. Adding the second reaches 0.8, which crosses the threshold. The smallest qualifying prefix contains two candidates. The threshold is a minimum covered mass, not a requirement that the retained mass equal exactly 0.6. Discrete candidate probabilities generally prevent exact equality.

After selection, divide the retained masses by 0.8 to obtain [0.625,0.375]. The omitted candidate gets probability zero under this policy. The sampling distribution has changed deliberately; it is not the original model distribution with an unused row hidden from display. Top-k would keep a fixed number of candidates even if their probabilities changed, while top-p chooses the count from the mass. If a single candidate had probability 0.9, threshold 0.6 could retain only that candidate.

The order of policy operations matters. Temperature changes probabilities, which can change which candidates are needed to cross a top-p threshold even when their ranking stays the same. Stable tie handling also matters when equally probable candidates straddle a boundary. Preserve the original vocabulary IDs when sorting: a sampled position in the retained array must be mapped back to the token it represents. In this fixture, the retained positions happen to be IDs zero and one, which makes the mapping easy to overlook.

A generation loop needs a stopping contract independently of its sampler. The literal token stream [2,3,9,4] stops at EOS token 9, leaving stored output [2,3,9]. The next token 4 is never appended. Another loop with no EOS stops after three generated tokens because of its explicit cap. The first outcome means the designated termination token was observed; the second means the budget was exhausted. A caller may need to distinguish them, especially if truncated JSON or an incomplete calculation is not an acceptable answer.

The cap counts newly generated tokens, while the model's total context also includes the prompt and any retained history. Hitting neither the output cap nor EOS does not make an arbitrarily long context valid. Position limits and cache capacity remain separate constraints. Likewise, hiding EOS from displayed text does not change whether it was stored or counted by the generation process.

Two local generators seeded identically produce the same draws in the tested runtime because they use the same support and call sequence. Changing earlier calls or the policy can alter later outputs. Treat a generation result as the product of model state, prefix, sampling configuration, random state and stopping rules. None of these mechanisms independently establishes that the resulting answer is supported by evidence.

## Syntax anatomy and reasoning sequence

Sort probabilities descending with a stable tie policy, compute cumulative sums and retain each token whose preceding cumulative mass is belowp. This formulation keeps the crossing token. torch.Generator(device='cpu') with a fixed seed makes repeated sampling locally reproducible. Generation loops check EOS after appending a chosen token and before requesting another token.

## Why nucleus sampling keeps the crossing token

Sort the probability vector [0.5, 0.3, 0.2] in descending order. With a top-p threshold of 0.6, the first candidate supplies only 0.5 mass, so stopping there would miss the threshold. Including the second candidate reaches 0.8, which crosses it. The minimum retained prefix is therefore tokens zero and one, not just token zero. The implementation tests mass before the candidate, equivalent to keeping the crossing candidate under the stated positive-threshold policy.

The retained probabilities must be normalized: [0.5, 0.3]/0.8 gives [0.625, 0.375]. Top-p is not top-k with a different name. It chooses a support size according to the distribution: a highly concentrated distribution may retain one candidate, while a nearly uniform distribution can require many. The threshold domain must be declared; zero would produce an empty support under the literal previous-mass rule, so a general sampler needs an explicit validation or special-case policy.

Stable sorting makes the tie behavior reproducible for this fixture. When the cutoff falls among equal probabilities, index order can affect which tied candidate is retained. That is an implementation policy, not evidence that one tied token is more correct. Also distinguish a sampled index into the retained vector from the original vocabulary ID. If retained vocabulary IDs were [5, 2], retained index one would mean vocabulary token two. The current [0, 1] fixture makes those numbers coincide, so a general implementation must preserve the mapping explicitly.

## Sampling and termination have different contracts

Two local generators initialized identically produce matching draws for the same ordered support in the same prepared runtime. This does not imply that changing earlier calls, filtering or runtime versions preserves the entire generated sequence. Reproducibility needs the policy and RNG state, not merely a seed written somewhere in a report.

The termination fixture appends EOS before stopping, so its stored token list includes the EOS ID. A text presentation may choose not to display that token; the storage and display policies should not be confused. The maximum-new-token cap counts generated tokens, not prompt tokens. Total model context must still respect its positional and cache limits. Hitting a cap without EOS is a truncation outcome, not proof of a complete answer or valid structured output. A downstream parser should verify its own contract rather than assume a stopped generator finished the requested task.


## Worked example / walkthrough

### Example A: Retain the crossing token

Testing the cumulative mass before each token keeps the first token that crosses the threshold. Filtering on cumulative<=p would incorrectly drop it.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

p = torch.tensor([0.5, 0.3, 0.2])
sorted_p, order = torch.sort(p, descending=True, stable=True)
previous = torch.cumsum(sorted_p, 0) - sorted_p
keep = previous < 0.6
assert order[keep].tolist() == [0, 1]
np.testing.assert_allclose(sorted_p[keep].sum().item(), 0.8, atol=1e-6, rtol=0)
```

**Expected:** retained IDs0,1 with original mass.8.

### Example B: Renormalize retained mass

The discarded mass is removed from the candidate set. The remaining entries must sum to one to define the sampling distribution.

```python
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

p = torch.tensor([0.5, 0.3, 0.2])
sorted_p, order = torch.sort(p, descending=True, stable=True)
previous = torch.cumsum(sorted_p, 0) - sorted_p
keep = previous < 0.6
assert order[keep].tolist() == [0, 1]
np.testing.assert_allclose(sorted_p[keep].sum().item(), 0.8, atol=1e-6, rtol=0)
mass = sorted_p[keep]
normalized = mass / mass.sum()
np.testing.assert_allclose(normalized.numpy(), [0.625, 0.375], atol=1e-6, rtol=0)
```

**Expected:** probabilities.625,.375.

## Common pitfalls and diagnosis

If top-p retains too little mass, check whether the crossing candidate was discarded. Validate a nonempty support and renormalize it, then map sampled retained indices back to vocabulary IDs. Keep EOS inclusion, generated-token cap and total context budget separate. A truncated sequence should not be silently reported as a completed structured answer.
