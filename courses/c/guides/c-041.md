# c-041: State-machine parsing and bounded input grammars

## Level and prerequisites

Advanced, approximately 120 minutes plus a later retrieval session. Direct prerequisites: `c-040`

## Learning objectives

Explain grammar, parser state, staged output. Implement the six investigations with explicit checks, identify a plausible defect and defend a fresh boundary case before execution. Completing a reference is not evidence of independent mastery.

## Purpose and mental model

A parser should define the language it accepts before processing bytes. A small state machine makes separator, digit and termination rules visible. It is safer than repeatedly guessing with partial conversions and ignoring leftovers. This lesson parses a deliberately narrow grammar: one or more unsigned decimal integers separated by single commas, with no spaces, signs or quoted fields. It is not a general CSV parser. Each digit update checks for overflow before multiplying by ten, and the output count is bounded by caller capacity. Invalid input preserves the caller output by parsing into a bounded temporary array first.

## Vocabulary and concepts

- **Grammar:** The exact forms of input a parser accepts.
- **Parser state:** The information needed to interpret the next byte.
- **Staged output:** Temporary results committed only after complete validation.

## Syntax anatomy and execution trace

The parser alternates between expecting a digit and accepting further digits or a comma. A comma requires a completed number and another number afterward. End-of-input commits the last value only if a digit was seen. The accumulator bound uses value>(UINT_MAX-digit)/10 before value*10+digit. A temporary staging array makes the final output update failure-atomic for the declared maximum of eight numbers.

## Worked example / walkthrough

### Worked example 1: Parse a valid list

Parse 1,20,3 into capacity three.

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void lesson_check(bool condition, const char *file, int line) {
  if (!condition) {
    fprintf(stderr, "Check failed at %s:%d\n", file, line);
    abort();
  }
}
#define CHECK(condition) lesson_check((condition), __FILE__, __LINE__)

bool parse_list(const char *text, unsigned *out, size_t capacity,
                size_t *count) {
  if (text == NULL || out == NULL || count == NULL)
    return false;
  unsigned temporary[8];
  size_t used = 0;
  unsigned value = 0;
  bool digit_seen = false;
  for (const unsigned char *p = (const unsigned char *)text;; p++) {
    unsigned char c = *p;
    if (c >= '0' && c <= '9') {
      unsigned digit = (unsigned)(c - '0');
      if (value > (UINT_MAX - digit) / 10U)
        return false;
      value = value * 10U + digit;
      digit_seen = true;
    } else if (c == ',' || c == '\0') {
      if (!digit_seen || used >= 8 || used >= capacity)
        return false;
      temporary[used++] = value;
      if (c == '\0')
        break;
      value = 0;
      digit_seen = false;
    } else {
      return false;
    }
  }
  memcpy(out, temporary, used * sizeof temporary[0]);
  *count = used;
  return true;
}

int main(void) {
  /* Parse a valid list */
  {
    unsigned out[3] = {0};
    size_t count = 0;
    CHECK(parse_list("1,20,3", out, 3, &count) && count == 3 && out[0] == 1 &&
          out[1] == 20 && out[2] == 3);
  }
  puts("Worked example checks passed.");
  return 0;
}
```

**Observe:** Three values are returned in order.

The parser validates the entire grammar before publishing output.

**Observe:** The parse fails and prior output is unchanged.

Two separators in a row violate the required-digit state.

## Common pitfalls and diagnosis

Begin with the first relevant compiler warning or error. A declaration mismatch can cause many later diagnostics, so fix one cause at a time. If a check fails, compare actual and expected values and identify the earliest state transition that differs from the intended invariant. A program that compiles can still contain undefined behavior. A program that ran once without crashing can still access invalid memory.

For every pointer, identify its target object, bounds, alignment, lifetime and whether mutation is permitted. For every library call, inspect its return value before using output. For every owned resource, identify one release on each completed path. The worked examples and solutions explain the lesson-specific counterexamples; keep those distinctions rather than replacing a rejected input with a plausible default.
