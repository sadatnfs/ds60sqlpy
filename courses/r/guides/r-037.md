## Outcome and mechanism

Use a small simulation to investigate a probability while separating simulation error from model uncertainty.

Simulation begins with a model, not a random-number call. State the outcome space, probabilities and independence assumptions. Drawing four independent fair coin flips is a specific mechanism; drawing four correlated user events is a different one. A simulation can be internally correct and still answer the wrong real-world question if its generative assumptions do not fit.

A Monte Carlo probability estimate is the fraction of simulated repetitions satisfying an event. More repetitions generally reduce numerical sampling variation, but they do not repair a misspecified model. For independent Bernoulli event indicators with probability p, the estimator's standard error is approximately \(\sqrt{p(1-p)/B}\), where B is the number of repetitions. The estimated p can provide a practical approximation when its limitations are understood.

Set a seed for reproducibility, then report the number of repetitions and the generator context. Do not keep trying seeds until a preferred result appears. A deterministic reference should test a broad justified approximation bound or compare with an exact small-case calculation, rather than asserting one arbitrary simulated decimal as a scientific truth.

Simulation output also has a unit. A repetition may represent a trial, a user, a whole experiment or a time series. Accidentally treating every internal draw as an independent replication changes the uncertainty calculation. Keep repetitions and within-repetition observations separate in array dimensions and summaries. Later bootstrap and resampling chapters build on this distinction.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Simulation model | An explicit mechanism generating synthetic outcomes. |
| Monte Carlo estimate | A numerical estimate obtained by repeated simulated draws. |
| Monte Carlo standard error | Variation from finite simulation repetitions under a stated model. |
| Seeded stream | A reproducible pseudorandom sequence under a declared generator configuration. |

## Read the syntax

Use rbinom(B, size, prob) for B binomial outcomes under the stated independent-trial model. Compute event indicators, their mean and a Monte Carlo error estimate. The mathematical standard error is \(\sqrt{p(1-p)/B}\) for independent indicators.

## Worked examples

### Example 1: Compare a simulated event with an exact probability

```r
set.seed(41)
repetitions <- 20000L
heads <- rbinom(repetitions, size = 4, prob = 0.5)
estimate <- mean(heads >= 3)
exact <- 5 / 16
mcse <- sqrt(estimate * (1 - estimate) / repetitions)
stopifnot(abs(estimate - exact) < 0.02, mcse < 0.005)
print(c(estimate = estimate, exact = exact, mcse = mcse))
```

**Expected observation:** Estimate near 0.3125 with finite simulation error.

There are four ways to obtain exactly three heads and one way to obtain four, among sixteen equally likely sequences. The simulation approximates that model probability.

### Example 2: Repetition size and estimator precision

```r
p <- 0.3
small <- sqrt(p * (1 - p) / 100)
large <- sqrt(p * (1 - p) / 400)
stopifnot(isTRUE(all.equal(large, small / 2)))
print(c(repetitions100 = small, repetitions400 = large))
```

**Expected observation:** Approximately 0.0458 and 0.0229.

Quadrupling independent repetitions halves this standard error. It does not imply that a biased real-world model becomes correct.

### Example 3: At least three is not more than three

```r
flips <- expand.grid(a = 0:1, b = 0:1, c = 0:1, d = 0:1)
heads <- rowSums(flips)
stopifnot(nrow(flips) == 16L, sum(heads >= 3) == 5L, sum(heads > 3) == 1L)
upper_wrong <- pbinom(3, 4, 0.5, lower.tail = FALSE)
upper_right <- pbinom(2, 4, 0.5, lower.tail = FALSE)
stopifnot(isTRUE(all.equal(upper_wrong, 1 / 16)), isTRUE(all.equal(upper_right, 5 / 16)))
stopifnot(isTRUE(all.equal(sum(dbinom(3:4, 4, 0.5)), 5 / 16)))
print(table(heads))
```

**Expected observation:** The table shows 1, 4, 6, 4 and 1 sequences with 0 to 4 heads; five sequences have three or more heads.

Listing all 16 equally likely sequences gives an exact answer that needs no random draws, and the head counts follow the 1, 4, 6, 4, 1 pattern. The event in this lesson is three or more heads, which is 4 plus 1 sequences. With lower.tail = FALSE, pbinom returns the probability of exceeding its first argument, so pbinom(3, ...) gives only the four head case, 1/16. The correct call uses 2. A simulation that tests heads > 3 makes the same mistake and settles near 0.0625, and no number of repetitions would reveal it, because the simulated answer is precise for the wrong event.

## How large the simulation error is here

The first worked example prints three numbers. Two can be worked out before running it:

```text
quantity    value           source
exact       0.3125          5 of 16 sequences
mcse        about 0.0033    sqrt(0.3125 * 0.6875 / 20000)
tolerance   0.02            about 6 times the mcse
estimate    near 0.3125     depends on the draws after set.seed(41)
```

Because the tolerance is about six standard errors, the check `abs(estimate - exact) < 0.02` would pass for almost any seed, not only 41. That is the right design for a test: it confirms the simulation targets the right quantity without depending on lucky draws. A tolerance of 0.001, about a third of a standard error, would fail for most seeds, and a seed that happened to pass would hide that fragility.

The mcse formula uses the estimate itself. If an event is rare and no draw produces it, the estimate is 0 and the formula reports an error of 0, which says nothing about how rare the event really is. Record `RNGkind()` with the seed, since the same seed under a different generator gives different draws.

## Progressive hints

1. Count three-head and four-head sequences.
2. Monte Carlo standard error scales with inverse square root.
3. Separate the event indicator from internal draws.
4. The seed is a reproducibility control, not an optimization target.
5. The Bernoulli event has no variation under that exact model.
6. Numerical precision and model validity are different.
