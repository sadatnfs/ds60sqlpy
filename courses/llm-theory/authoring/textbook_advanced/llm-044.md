## Give attention a coordinate system that survives incremental execution

Attention compares vectors, but a language task often depends on where those vectors occur. "A follows B" and "B follows A" can contain the same token identities while expressing different relationships. Positional mechanisms give the computation information about order or distance. They must remain consistent between full-prefix training/evaluation and incremental cached execution, or the model will compute a different function after a cache boundary.

Without positional information and with an all-allowed mask, a shared self-attention operation is permutation-equivariant: permuting input rows permutes the corresponding output rows. If P is a permutation matrix, the score matrix transforms as P S P^T and the output as P O under the matching permutation. A fixed causal mask already imposes an ordered access pattern, so the broad slogan "attention knows no order" needs that qualification. The complete information graph, not attention alone, determines which order information is available.

### Compare three ways to introduce position

A learned absolute embedding adds a position-specific vector to each token representation. Its table has an explicit range of trained indices. Sinusoidal or rotary formulas compute position-dependent transformations rather than selecting an arbitrary learned row. Relative score methods add or otherwise encode a relationship between query and key positions. These choices can be combined with different architectures, and each changes the function a checkpoint expects.

RoPE rotates paired query/key coordinates. ALiBi adds a linear distance bias to attention scores. The first changes the geometry of the dot product through position-dependent rotations; the second changes the score after the content comparison. Neither mechanism is interchangeable with a causal mask. A positional preference says how strongly to weight an available key; an access mask says whether the key is available at all.

### Expand one rotary dot product by hand

For a two-dimensional pair q=(a,b), k=(c,d), define R(theta) as the usual rotation matrix. Rotating query at angle m and key at angle n gives(R(m)q)^T(R(n)k)=q^T R(n-m)k. Let delta=n-m. Expanding the coordinates yields(ac+bd)cos(delta)+(bc-ad)sin(delta). The relative offset enters through two content-dependent coefficients.

For q=[1,2] and k=[3,-1], the coefficients are 1 and 7, so the rotated dot product is cos(delta)+7sin(delta). Equal angles give delta 0 and recover the original dot product 1. A common offset added to both angles cancels, while changing only one angle changes the score. This explains why a cached key and a new query must share the same position convention.

Each rotation preserves the length of its own vector because R(theta)^T R(theta)=I. But equal vector norms do not imply equal attention scores: relative direction matters. A wrong offset can preserve every pair norm and still produce an incorrect output. Norm tests and relative-dot-product tests therefore check different properties.

### Frequencies and layout are part of the checkpoint contract

A head of even width d can be divided into d/2 pairs. The fixture uses adjacent pairs and frequencies omega_i=base^(-2i/d). At width 4 and base 10000, the two frequencies are 1 and .01. A position p rotates the first pair by p radians and the second by .01p radians. The slow pair changes phase more gradually across positions.

Another implementation may arrange paired coordinates differently, such as pairing a first half with a second half. Both layouts can represent the same abstract idea, but projection weights and cache coordinates must be translated consistently. Copying weights between layouts without that conversion changes the computation while preserving shapes. Record pairing convention, frequency schedule, base, scaling policy and dtype with the model artifact.

A frequency has a periodic phase. For one pair, positions separated by 2*pi/omega have the same ideal rotation, though integer token positions do not generally land exactly on that period. Multiple frequencies create a richer pattern. This does not mean that a trained model is guaranteed to distinguish or use every distant position correctly. The representation formula and learned task behavior remain separate objects of study.

### Cache offsets are a state invariant

If a prefix contains positions 0 and 1, the next key must be encoded at position 2. Encoding it at 0 treats it as a new beginning. Rotating a key twice applies the sum of the rotations and is another different function. A cache must therefore record whether keys are stored before or after positional transformation and which absolute positions they represent.

The full-prefix versus incremental test should hold token IDs, weights, masks and position policy fixed. Compare the appended key with the corresponding row from a full encoding before comparing final logits. If the key already differs, the defect is in state/position handling rather than the softmax or output projection. This staged diagnosis is more efficient than changing several model components at once.

Cache compaction or a sliding window adds another coordinate decision. Dropping old physical entries need not reset the logical absolute position of the remaining tokens. Some models intentionally use a relative or rescaled convention, but that must be the trained computation's contract. A storage index and a semantic position are not automatically the same number.

### Read ALiBi as a ratio of unnormalized masses

For a causal query at i and available key j<=i, an ALiBi-style bias can be-a(i-j) for positive slope a. When content scores are equal and a=log(2), moving one position farther into the past halves the exponential mass. At query 2, keys 0,1,2 have masses 1/4,1/2,1 and normalized weights 1/7,2/7,4/7. The current key receives the largest weight under this illustrative slope.

A finite recency penalty is not a hard context window. A sufficiently large content score can overcome it. A hard window instead forbids keys outside the chosen range regardless of their content. If future key 3 were accidentally admitted, the same signed-distance formula would give it positive bias log(2), rewarding an unavailable position. The causal mask must remain separate.

Different heads can use different slopes, creating different distance preferences. The single slope in the fixture is chosen for exact arithmetic, not to reproduce every published head-slope schedule. When comparing methods, record the actual policy rather than assuming that the name ALiBi fully specifies every implementation detail.

### Distinguish a long index from long-context competence

A sine/cosine formula may return finite numbers at position one million. That establishes that a particular calculation completed under its dtype and inputs. It does not establish that the model was trained on useful patterns at that range, that nearby positions remain numerically distinct, or that a distant source fact influences the answer correctly.

Position precision can fail before the trigonometric function itself does. A limited-precision floating type eventually cannot represent every consecutive large integer, so two logical positions may be rounded to the same stored value. Frequency multiplication and angle reduction add further numerical considerations. These facts motivate explicit dtype and offset tests, not an automatic conclusion that every long-context use is invalid.

Behavioral evaluation should require information at controlled distances and include distractors, missing evidence and tasks that cannot be solved from the final few tokens alone. Increasing prompt length by adding irrelevant text is not the same as demonstrating reliable long-range use. Changing a rotary base or scaling recipe also changes the model's computation and needs model-specific evidence.
