llm-032: Low-rank adaptation without a package download#

Status: authored beta content. The manifest inventories complete teaching files; runtime readiness remains a separate, measured property.

Level and prerequisites#

Advanced; approximately 135 minutes. Direct prerequisites: llm-031. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Derive and test a low-rank update while keeping base weights frozen. The central investigation is concrete: Use base W=I8, x=ones(8), target=zeros(8), A=ones((8,2))/8 and B=zeros((2,8)); form W+A@B and take one squared-loss SGD update of the adapter only. The finish condition is A and B have 32 parameters versus 64 in W. At initialization, zero delta matches the base. On the first step B changes, A may have zero gradient, and frozen W stays unchanged. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Low-rank adaptation freezes a base matrix and learns an additive product of two smaller matrices. Here row-vector inputs multiply W+A@B, with W shaped8x8,A8x2 andB2x8. The adapter has32 trainable scalars compared with64 in the base. InitializingB to zero makes the initial adapter contribution exactly zero, preserving base behavior. On the first update, the gradient ofA can be zero because it is multiplied byB, whileB receives a nonzero gradient throughA. This is expected under the stated initialization, not a disconnected graph. Low rank limits the update space; it is not a universal guarantee of equal quality to full fine-tuning.

Vocabulary and concepts#

Low-rank update: A matrix change represented as the product of two smaller matrices.

Frozen base: Parameters excluded from the adaptation optimizer.

Zero-delta initialization: An adapter starting with no change to the base function.

Syntax anatomy and reasoning sequence#

Keep W as a tensor without requires_grad. Wrap A andB as Parameters and pass only those to SGD. The row-vector convention differs from frameworks that store Linear weights as(out,in), so record the orientation before transplanting equations. Compute delta=A@B and compare its shape withW. Snapshot the base bytes and assert exact preservation after the adapter update.

Worked example / walkthrough#

Example A: Count adapter parameters#

The parameter reduction comes from the factorization rank2. Increasing rank increases trainable state and changes the set of possible updates.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

w=torch.eye(8); a=nn.Parameter(torch.ones((8,2))/8); b=nn.Parameter(torch.zeros((2,8))); x=torch.ones((1,8))
assert a.numel()+b.numel()==32 and w.numel()==64

Expected: adapter32 parameters versus base64.

Example B: Check zero initial delta#

ZeroB eliminates the product while retaining a connected path forB throughA. The base prediction is preserved exactly at initialization.

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F

delta=a@b; initial=x@(w+delta)
assert torch.equal(delta,torch.zeros((8,8))); assert torch.equal(initial,x@w)

Expected: both equal ones(1,8).
