tf-013: Binary logits, probabilities and thresholds#

Level and prerequisites#

Intermediate; approximately 105 minutes. Direct prerequisites: tf-012. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Use a binary loss with the correct logit/probability convention. The central investigation is concrete: Compare logits [-2,0,2], sigmoid probabilities and thresholds 0.5 versus 0.8 on fixed labels; deliberately mismatch from_logits. The finish condition is At logit 0 the probability is 0.5 and positive-label BCE is log(2)\log(2) within 1e-6. Threshold changes predictions, not the already fitted logits. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

A binary logit is an unrestricted score whose sigmoid is a probability under the chosen model. It is not already a probability. Binary cross entropy compares that probability with a zero-or-one target. A logits-aware implementation combines the sigmoid and logarithms into a stable calculation. The decision threshold is a separate policy: moving it changes predicted classes without changing the fitted scores. This distinction matters when false positives and false negatives have different costs. The three-point fixture is designed to make the boundary at probability one half explicit. It cannot show that the probabilities are calibrated on real observations.

Vocabulary and concepts#

Logit: An unrestricted binary score before the sigmoid transformation.

Threshold: A probability boundary used to choose a class.

Binary cross entropy: Negative log probability assigned to the observed binary label.

Syntax anatomy and reasoning sequence#

tf.math.sigmoid converts each score independently. sigmoid_cross_entropy_with_logits requires labels and logits of equal shape and computes a loss per entry. reduce_mean chooses the example denominator. Compare probability>=threshold for a declared tie policy. Do not apply sigmoid twice or feed a probability to a function that expects a logit; both can produce finite but incorrectly interpreted losses.

Separate the probability model from the action rule#

A logit z represents log odds. Its sigmoid p=11+exp(−z)p=\frac{1}{1+\exp(-z)} lies between zero and one. A zero logit therefore represents probability 0.5, not probability zero. For a binary target y, the logits form of cross entropy is log(1+exp(z))−yz\log(1+\exp(z))-yz; a stable implementation avoids directly exponentiating a very large positive z. Its derivative with respect to z is p-y.

The from_logits setting is a contract about the supplied numbers. Feeding probability 0.5 as if it were a logit applies another sigmoid, producing about 0.622 rather than 0.5. For target 1 the corresponding loss is about 0.474 instead of log(2)\log(2), about 0.693. The calculation remains finite, so a NaN check cannot detect this semantic mismatch.

A decision threshold adds a policy on top of probabilities. With false-positive cost C_FP and false-negative cost C_FN, zero cost for correct decisions and calibrated probabilities for the decision population, predicting positive has expected cost C_FP(1-p), while predicting negative costs C_FN p. The resulting threshold is CFPCFP+CFN\frac{C_{\mathrm{FP}}}{C_{\mathrm{FP}}+C_{\mathrm{FN}}}. Costs 1 and 4 give 0.2. Those assumptions matter: class weighting during fitting can change how a score should be interpreted.

Specify the equality convention at the threshold. This lesson includes p=0.5p=0.5, so greater-than and greater-than-or-equal rules differ on an actual fixture row. Moving a threshold changes decisions and error counts without changing the fitted logits, ranking or probability-loss calculation.

Worked example / walkthrough#

Example A: Convert scores#

The sigmoid is monotonic, so ordering survives. A score of zero lies at the probability midpoint, which makes it a useful exact boundary fixture.

import numpy as np
import tensorflow as tf

z=tf.constant([-2.,0.,2.]); p=tf.math.sigmoid(z).numpy()
assert p[1]==.5 and np.all(np.diff(p)>0)

Expected: middle probability 0.5; probabilities increase.

Example B: Check the midpoint loss#

A fifty-fifty prediction assigns probability one half to either outcome. Its negative logarithm provides an independent reference that does not depend on a trained model.

import numpy as np
import tensorflow as tf

z=tf.constant([-2.,0.,2.]); p=tf.math.sigmoid(z).numpy()
assert p[1]==.5 and np.all(np.diff(p)>0)
loss=tf.nn.sigmoid_cross_entropy_with_logits(labels=tf.constant([1.]),logits=tf.constant([0.]))
np.testing.assert_allclose(loss.numpy(),[np.log(2)],atol=1e-6,rtol=0)

Expected: loss log(2)\log(2) within 1e-6.

Common pitfalls and diagnosis#

Check whether the loss expects logits before adding sigmoid. Compare the zero-logit case with log(2)\log(2), then inspect large positive and negative scores using the stable operation. If probability loss is correct but classification counts differ, inspect the threshold and its equality rule. A three-row success does not establish population calibration.
