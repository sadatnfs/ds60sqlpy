# Sparse symbolic analysis and factorization accuracy

Start with: tmb-035, tmb-015.

Outcome: Distinguish sparse structure, ordering and numerical solve accuracy.

The classroom companion runs in the prepared R statistics runtime. It uses base R to expose the mathematics or data contract. Compiling and executing TMB uses the separate [owned project](../projects/tmb-local/README.md); a companion run is not a TMB compiler or rpy2 receipt.

A sparse Hessian stores few nonzero entries, but its factorization can introduce additional nonzeros called fill-in. Symbolic analysis chooses or analyzes an elimination structure before numerical factorization. A good ordering can reduce memory and work without changing the mathematical matrix; an approximate factorization changes the numerical calculation and needs an accuracy policy.

`runSymbolicAnalysis(obj, method=...)` exposes advanced options. The manual describes a CHOLMOD path with specialized-installation and historical compatibility context, and an experimental incomplete-factorization path with drop tolerances, iterative refinement, ordering and parallel controls. These are specialized capabilities, not requirements for ordinary small TMB examples.

### Worked case A: sparse precision still couples states

The companion builds a tridiagonal chain precision and compares solving a linear system with multiplying by an explicit inverse. The solutions agree on a tiny problem. For a large problem, explicitly constructing the inverse would often destroy the sparse memory advantage. Use solves for the quantities actually required.

Permutation reorders variables and equations consistently. If \(P\) is a permutation matrix, solve \((PQP^T)z=Pb\) and then recover \(x=P^Tz\). Reordering the matrix without reordering the right-hand side silently solves the wrong problem.

### Worked case B: dropping entries changes the solve

The companion drops an off-diagonal coupling and measures the residual under the original matrix. A small residual is a concrete linear-algebra diagnostic; a small change in a displayed coefficient alone can be misleading. In an iterative refinement scheme, tolerances and iteration limits control whether the approximate factor is adequate for the current solve.

For Laplace gradients, inaccurate sparse solves can affect both the latent mode and curvature derivatives. A fast approximate factorization should be compared with an exact small reference, then checked across difficult parameter regions, not only at a convenient initial point.

### Answered discussion

**Does sparse mean independent?** No. It often encodes conditional rather than marginal independence. **Can a drop tolerance be selected from a runtime target alone?** It also needs an error target tied to the resulting objective and gradient. **Is CHOLMOD always available with the same features?** No. Package/system builds and optional orderings differ. Report the actual prepared libraries and avoid claiming a specialized path ran merely because its function name exists.

See [runSymbolicAnalysis documentation](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The native course acceptance currently qualifies the ordinary sparse operations used by its small latent models, not every experimental factorization option.

### Complete R companion

```r
Q <- diag(4) * 3;Q[row(Q) == col(Q) + 1 | row(Q) == col(Q) - 1] <- -.7;b <- c(1, 2, -1, .5)
x <- solve(Q, b);print(c(solve_residual = max(abs(Q %*% x - b)), inverse_difference = max(abs(x - solve(Q) %*% b))))
permutation <- c(4, 2, 1, 3);z <- solve(Q[permutation, permutation], b[permutation]);restored <- numeric(4);restored[permutation] <- z
stopifnot(max(abs(restored - x)) < 1e-12)
approximate <- diag(diag(Q));xa <- solve(approximate, b)
print(c(dropped_coupling_residual = max(abs(Q %*% xa - b))))
```
