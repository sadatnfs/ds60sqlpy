llm-027: Calibration and comparable evaluation#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: llm-026. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Report predictive confidence under an explicit scoring and grouping policy. The central investigation is concrete: Compute token-weighted loss, a small calibration table and paired errors for fixed saved predictions; contrast a tokenizer change. The finish condition is Bins report counts, confidence and observed frequency; empty bins are explicit. Token losses across incompatible vocabularies are not directly ranked. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Make confidence, loss and correctness answer the same declared question#

A model can assign a valid probability distribution and still be wrong. It can also be accurate while expressing confidence that does not match observed success rates. Calibration connects a probability statement to repeated outcomes: among predictions assigned a given confidence, how often does the corresponding event occur? This is different from asking whether the most likely class was correct, and different again from measuring the log probability assigned to target tokens.

Let c_i be the reported confidence for a declared event and a_i be 1 if that event occurs and 0 otherwise. For answer confidence, the event might be "this answer satisfies the stated correctness rule." For a binary classifier, it might be "the label is positive." These definitions are not interchangeable. A next-token maximum probability is not automatically the probability that a multi-sentence answer is supported by evidence. Define the event before calculating a calibration statistic.

Start with the four-record fixture#

The supplied confidences are[.6,.8,.8,1.0] and observed correctness indicators are[1,1,0,1]. Mean confidence is .8 and observed accuracy is .75. Their difference is .05 for this one aggregated group. The sample is too small to establish a stable relationship across confidence levels, but it is enough to show that confidence and outcome are distinct columns.

A confidence of 1.0 in the final row means the forecaster assigned certainty to that declared event. The observed success in this one row does not validate certainty for all similar rows. If a future row assigned confidence 1.0 fails, a binary log score for that event would be infinite. Practical systems sometimes clip probabilities for numerical reasons, but clipping changes the scored forecast and must be explicit. Confidence should not acquire a stronger interpretation merely because it is displayed with many decimal places.

A calibration bin groups predictions with comparable confidence. Its record should include the lower/upper bounds, boundary convention, count, average confidence and observed event frequency. An empty bin has count 0 and no observed frequency. Writing accuracy 0 for an empty bin invents a failed observation where none exists; writing accuracy 1 invents a success. The reference uses None to retain this absence of evidence.

Trace how binning changes a summary#

Use two bins: [.5,.8) and [.8,1]. The first contains only the .6 prediction, which succeeded. Its confidence is .6, accuracy 1 and absolute gap .4. The second contains .8,.8,1, with two successes. Its mean confidence is 1315\frac{13}{15}≈.8667 and accuracy 23\frac{2}{3}≈.6667, giving gap .2. An expected calibration error using sample-weighted absolute bin gaps is(1/4).4+(3/4).2=.25.

If all four records are placed in a single bin, the same formula gives|.8-.75|=.05. Neither calculation changed any prediction. Combining the bins allowed overconfidence in one range and underconfidence in another to cancel before taking the absolute value. This is why bin count and boundary choice are part of the method, not harmless plotting options. A small ECE under one coarse partition is not a proof of well-calibrated probabilities everywhere.

There is also a bias/variance tradeoff in the display. Many narrow bins can reveal local structure but have noisy frequencies when few records fall into each bin. Few wide bins stabilize counts while hiding variation. Equal-width and equal-count bins answer slightly different practical needs. Preserve the raw prediction/outcome records so a reader can inspect the chosen partition rather than relying solely on one final scalar.

A bin-free score can provide complementary evidence. For this declared binary correctness event, the Brier score is the mean squared probability error, 1N∑i(ci−ai)2\frac1N\sum_i(c_i-a_i)^2. The four squared errors are .16,.04,.64,0, giving .21. It evaluates probabilistic forecasts directly, while an accuracy score would discard the confidence magnitudes. No single scalar fully describes discrimination, calibration, subgroup behavior and task costs, so choose a small set of metrics with clearly stated purposes.

Loss aggregation is another weighting decision#

The first worked example supplies document means[1,3] and target counts[1,3]. Token-weighted mean loss is(11+33)/(1+3)=2.5, while equal-document mean is(1+3)/2=2. A long, difficult document contributes more token events under the first policy and the same document weight under the second. Neither arithmetic expression is wrong. The report becomes misleading when it switches policies without naming the unit.

Suppose model A has lower loss on the longer document while model B has lower loss on several short documents. The ranking may change between token and document weighting. Decide which population or workload the summary should represent before examining which result makes a preferred model look better. Retain per-document losses and active-target counts so the aggregate can be independently reconstructed.

Per-token perplexity adds a representation dependency. A tokenizer that splits a word into several targets changes the event count. Two systems can assign the same probability to a complete string and produce different per-token perplexities. Matching the label "token" in a report is insufficient when the tokenizers differ. A comparable evaluation needs aligned strings, context and stopping policies, and a justified common normalization unit. The lesson's metadata comparison refuses to treat tokenizer v1 and v2 as automatically interchangeable.

Compare models by aligned identities#

Model A's saved errors are{q1:0,q2:1}; model B's are{q2:0,q1:1}. The dictionaries list rows in different orders, but pairing by stable question ID gives differences[-1,1] and mean 0. Pairing by incidental storage order could incorrectly compare unrelated cases. IDs are part of the statistical design because they define which observations belong together.

Even a zero mean difference can hide important exchanges. One model improves q1 and regresses q2. Inspect whether those questions belong to different families, severities or evidence conditions. If a rare severe case regresses, an unchanged average is not enough to satisfy a policy that forbids that failure. Paired summaries should preserve the individual differences and the grouping structure rather than only printing a win/loss count.

Calibration is fitted and evaluated under a population contract#

A calibration method can transform scores using designated calibration data. Temperature scaling, for example, fits a positive temperature for logits under a chosen probabilistic objective. This can change confidence without changing the ranking of unequal class logits. It is not the same operation as choosing a generation temperature because a user prefers creative text, and it does not establish factual truth for arbitrary answers.

If the calibration population changes, the relationship between confidence and correctness can change too. A document assistant may be evaluated on familiar policy questions and deployed on rare technical exceptions. The same score range can have different error rates. Report domain, task, time window, answerability and subgroup counts alongside the calibration method. Repeatedly retuning on the final test set turns it into development data.

A useful diagnostic sequence asks: Are the event labels correct? Are predictions paired with the right IDs? Is the confidence attached to the event being scored? Are empty bins represented as unknown? Are denominators active targets, questions or families? Only after these contracts hold should a discrepancy be attributed to the model's probability quality.

Vocabulary and concepts#

Calibration: Agreement between predicted confidence and observed frequency.

Bin count: Number of observations supporting a calibration summary.

Comparable unit: An event definition shared by the quantities being compared.

Syntax anatomy and reasoning sequence#

Store per-event confidence and a boolean correctness outcome. Use explicit half-open bin boundaries, with the final bin including1. Compute each bin count, mean confidence and observed accuracy separately. For loss, retain sums and counts until the final division. Join model comparisons by stable event IDs rather than relying on array order.

Metric weighting changes the question#

Document mean losses 1 and 3 with token counts 1 and 3 produce a token-weighted mean 1·1+3·34=2.5\frac{1\cdot 1+3\cdot 3}{4}=2.5. An equal-document mean is 2. Both are valid summaries of different units, but reporting one as the other changes the interpretation. Comparing language-model scores requires the same tokenizer and event definition; a token under vocabulary v1 need not represent the same amount or kind of text as a token under v2.

For confidences [0.6, 0.8, 0.8, 1.0] and correctness [1, 1, 0, 1], one combined bin has mean confidence 0.8 and accuracy 0.75. Its absolute gap is 0.05. If the bins are [0.5, 0.8) and [0.8, 1], the first contains one correct event at confidence 0.6, while the second has average confidence about 0.8667 and accuracy 23\frac{2}{3}. Under the common count-weighted absolute-bin-gap definition, these bins give 0.25 rather than 0.05. The underlying predictions did not change; the binning changed the summary.

This small example shows why calibration bin boundaries and event definitions should be fixed and reported. Empty bins have no observed accuracy and should remain explicitly empty, not be assigned a fabricated zero or one. A model token probability is also not automatically the probability that an entire cited answer is correct. Define the event being calibrated before assigning meaning to a confidence number.

Pairing preserves information hidden by equal averages#

Model A's errors are q1=0q_{1}=0, q2=1q_{2}=1, while B's are q1=1q_{1}=1, q2=0q_{2}=0. Correct ID alignment gives paired differences [-1, 1], with mean zero. Iterating their dictionaries in different orders can incorrectly pair [0, 1] with [0, 1], producing [0, 0]. The mean still happens to be zero, so an aggregate-only check misses the error, while the variability and per-question tradeoffs are destroyed.

Keep stable IDs and relevant family/group membership when comparing systems. Confidence intervals or paired resampling depend on the actual observation unit, not merely the number of tokens printed by an evaluator. A similar average can conceal different failure types, so preserve the question-level outcomes as well as the overall metric.

Worked example / walkthrough#

Example A: Weight token losses#

The two statistics answer different questions. Neither should be labelled average loss without naming its weighting unit.

import numpy as np

means=np.array([1.,3.]); counts=np.array([1,3])
assert np.average(means,weights=counts)==2.5 and means.mean()==2

Expected: token mean 2.5; document mean 2.

Example B: Build a calibration bin#

The gap between confidence and frequency is observable for this small sample. Its sampling uncertainty remains large, so the bin is not a population guarantee.

import numpy as np

means=np.array([1.,3.]); counts=np.array([1,3])
assert np.average(means,weights=counts)==2.5 and means.mean()==2
confidence=np.array([.6,.8,.8,1.]); correct=np.array([1,1,0,1])
assert len(confidence)==4; np.testing.assert_allclose(confidence.mean(),.8,atol=1e-12,rtol=0); assert correct.mean()==.75

Expected: count4,mean confidence.8,accuracy.75.

Common pitfalls and diagnosis#

Name the averaging unit and tokenizer before comparing losses. Preserve empty calibration bins and fixed boundary conventions. Align paired outcomes by stable ID even when overall means happen to match; a mistaken pairing can leave the average unchanged while destroying the variance and failure interpretation.
