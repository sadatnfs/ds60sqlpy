Vocabulary and concepts#

A schema can say decimal, string, and timestamp while still leaving critical meaning undecided. What rounding is allowed? Do two visually identical labels denote one identity? Which side owns an event exactly at midnight? These are boundary policies, not formatting preferences. Think of the boundary as a translator that must declare which representations it accepts and how it preserves meaning. Reject ambiguity before calculating a polished result.

  • Binary floating point: an approximate representation of many decimal fractions, useful for scientific calculations but not exact currency units.
  • Decimal: a base-ten number representation; constructing it from text preserves the supplied decimal digits instead of a prior float approximation.
  • Quantization: mapping a number to a fixed decimal exponent, potentially requiring rounding if the input has finer precision.
  • Unicode normalization: conversion of equivalent character sequences to a chosen canonical representation, such as NFC.
  • Case folding: a language-independent Unicode operation for caseless matching; it can merge labels that a domain considers distinct.
  • Aware datetime: a datetime with a usable offset from UTC; it identifies an instant rather than only a wall-clock reading.
  • Half-open interval: a window that includes its start and excludes its end, written [start, end).

The money parser accepts stripped ASCII decimal text with one to twelve integer digits and zero, one, or two fractional digits. Amounts are nonnegative, have no exponent notation, and represent one declared currency. It rejects excess precision instead of rounding it. A real multicurrency system must also carry currency identity; adding two amounts with different currencies is outside this lab's contract. Use integer cents to reconcile a batch, avoiding dependence on a caller's Decimal precision context.

For labels, NFC addresses canonical character equivalence. Casefold is a separate, explicit caseless-matching choice. Neither is a complete identity solution: normalization can reveal collisions that need review. Keep every raw spelling in the collision report. Do not claim that this eliminates homoglyphs, resolves languages, or makes untrusted paths safe.

Worked example / walkthrough#

Example A: preserve source decimal meaning#
from decimal import Decimal

assert Decimal("0.10") + Decimal("0.20") == Decimal("0.30")
assert Decimal(0.1) != Decimal("0.1")
assert int(Decimal("12.34") * 100) == 1234

Decimal("0.10") reads text directly. Decimal(0.1) instead captures the existing binary float value, including its approximation. The integer-cent conversion is safe here because the contract already limits precision to cents. Truncating arbitrary Decimal input first would hide an invalid third fractional digit. Expected observation: all three assertions pass, and the last amount has exactly 1234 cents.

Example B: compare instants, then decide window ownership#
from datetime import datetime, timezone

local = datetime.fromisoformat("2026-01-02T00:30:00+02:00")
utc = local.astimezone(timezone.utc)
start = datetime.fromisoformat("2026-01-01T22:00:00+00:00")
end = datetime.fromisoformat("2026-01-01T23:00:00+00:00")
assert utc.isoformat() == "2026-01-01T22:30:00+00:00"
assert start <= utc < end
assert not (start <= end < end)

fromisoformat parses a supplied offset; astimezone changes representation while preserving the instant. It does not relabel the wall clock. Expected observation: a local January 2 event belongs to the UTC January 1 window. The final assertion excludes the exact end, so adjacent windows cannot both own that instant. Replacing timezone information with replace(tzinfo=...) would assign a meaning rather than convert an already-known instant.

Wall-clock ambiguity needs more information#

A timestamp without an offset cannot tell this lab which instant occurred. Reject it instead of assuming the executing machine's timezone. A named zone also has historical and seasonal rules; a fixed offset does not teach those rules or resolve repeated daylight-saving clock times. This offline lab uses explicit offsets so Windows, macOS, and Linux agree without an external zone database. In real zoned data, preserve the zone, disambiguation policy, and timezone-data version when they matter to reproduction.

Validate every source record before filtering its window. An invalid record outside the desired window still violates the input contract and must be reported instead of hidden by filtering. The reference raises ValueError for such a record. A quarantine pipeline could retain it separately, but would need count and rejected-value accounting of its own.

Exact Values, Unicode Identity, and Calendar Boundaries: solution reasoning#

Stable ID: python-data-02.

Read the guide and attempt the learner artifact first. The executable solution is a comparison implementation. It does not certify your changed program merely because its own demonstration succeeds. Copy the acceptance cases into your attempt, then change one input without changing the intended policy.

The reference makes representation decisions before arithmetic or selection. A lexical money rule accepts one documented format; a separate Unicode pipeline preserves raw collisions; timestamp parsing requires an offset and normalizes the representation to UTC. The functions reject invalid inputs instead of consulting machine locale or silently rounding.

from decimal import Decimal

assert Decimal("0.10") + Decimal("0.20") == Decimal("0.30")

Whole-batch totals use integer cents, so an unrelated caller changing the Decimal arithmetic context cannot silently round a large sum. The format is intentionally bounded; this is not a general financial ledger, language-aware identity service, or named-timezone resolver. Those broader systems require additional contracts and evidence.

Exercise 1. Parse exact cents#

The money parser checks type before stripping and matches a small ASCII decimal grammar. It then constructs Decimal from text and quantizes to a cent exponent. Because the grammar already rules out a third fractional digit, quantization only standardizes representation; it never decides a rounding policy. A local Decimal context protects the small conversion from a caller's unexpectedly low precision setting. Check both numeric equality and exponent, since Decimal("12.3") equals Decimal("12.30") numerically while representing different displayed precision. The chosen contract requires the cent exponent explicitly.

Exercise 2. Reject ambiguous numeric forms#

NaN and Infinity are valid Decimal spellings but not accepted monetary amounts here. Exponent notation, signs, extra precision, and overlong integer parts also fail the lexical contract. Rejecting those forms early makes the accepted representation inspectable and bounds work on unreasonable input. A float is rejected even if it appears to contain a clean decimal value, because it has already crossed an approximate representation boundary. These decisions are domain policy rather than claims that those representations are invalid for all Python calculations.

Exercise 3. Expose Unicode collisions#

NFC makes canonically equivalent accents comparable. Casefold then supports the explicitly chosen caseless match and can turn the German sharp s into ss. A final NFC normalizes any resulting character sequence again. Collision reporting groups distinct raw spellings under their canonical key and retains insertion order for review. Repeating exactly the same raw spelling twice does not count as a distinct-spelling collision. The report does not prove that the spellings denote the same person, account, or product. A consumer must choose a merge or rejection rule separately.

Exercise 4. Parse and convert an instant#

Parse the source text with datetime.fromisoformat and reject any result whose utcoffset is None. Convert the aware result with astimezone(timezone.utc). The local timestamp at 00:30 with offset plus two hours becomes 22:30 UTC on the previous date, and compares equal to that UTC representation. Replacing tzinfo would incorrectly change the identified instant. The reference accepts explicit offsets; it does not use the machine timezone or a downloaded zone database. Missing-offset input raises a visible ValueError so no implicit assumption enters the result.

Exercise 5. Own an exact boundary once#

Validate the start, end, and candidate datetime as aware values, normalize them to UTC, and require end strictly greater than start. Include a candidate when start is less than or equal to it and it is strictly less than end. The exact endpoint belongs only to the next adjacent interval. Rejecting empty windows instead of returning an empty result makes an accidental swapped or equal bound visible. Comparing aware instants also prevents misleading comparisons between equal wall-clock strings from different offsets. Keep endpoint tests alongside normal mid-window examples.

Exercise 6. Reconcile a window total#

Validate each amount and timestamp, then select by the half-open UTC interval. The two selected amounts contribute ten and twenty integer cents, giving thirty cents and count two. The record at the exact end contributes neither count nor money. Conversion back to a two-decimal Decimal occurs once after integer summation. A separate manually written integer calculation provides an oracle for this tiny case. Count alone would not catch an amount defect, and total alone could miss swapping equal-value records, so preserve both observations.

Exercise 7. Prevent filter-hidden invalid data#

Whole-source validation is a deliberate ordering guarantee. The malformed out-of-window amount fails before the selection can conceal it. This prevents a pipeline from claiming its source boundary passed while merely ignoring inconvenient records. A different system might quarantine invalid records and continue, but it must report rejected rows and limits on completeness. Do not silently change between these policies to make a test pass. The reference raises ValueError for the bad amount and performs no partial publication or report write, so callers see a clear failed boundary.

Exercise 8. Transfer to local-day reporting#

A local business day is defined by a named zone's calendar rules and may not last exactly twenty-four hours during seasonal changes. Require the zone identity, applicable timezone rules or version, and a policy for ambiguous or nonexistent wall-clock times. Test both seasonal transition directions and an event at the local boundary. Fixed-offset examples cannot establish those behaviors. The current lab deliberately uses aware offset timestamps for a portable offline core. A future zoned extension should make its database dependency explicit and preserve the same instant and interval reasoning.

"""Explicit money, Unicode, and instant boundaries for python-data-02."""

from __future__ import annotations

import re
import unicodedata
from datetime import UTC, datetime
from decimal import Decimal, localcontext

MONEY = re.compile(r"[0-9]{1,12}(?:\.[0-9]{1,2})?")


def parse_money(raw: object) -> Decimal:
    if not isinstance(raw, str) or MONEY.fullmatch(raw.strip()) is None:
        raise ValueError(
            "expected nonnegative decimal text with at most "
            "12 integer digits and 2 fractional digits"
        )
    with localcontext() as context:
        context.prec = 32
        return Decimal(raw.strip()).quantize(Decimal("0.01"))


def canonical_label(raw: str) -> str:
    if not isinstance(raw, str) or not raw.strip():
        raise ValueError("label must be nonempty text")
    return unicodedata.normalize("NFC", unicodedata.normalize("NFC", raw.strip()).casefold())


def collision_groups(labels: list[str]) -> dict[str, list[str]]:
    groups: dict[str, list[str]] = {}
    for raw in labels:
        group = groups.setdefault(canonical_label(raw), [])
        if raw not in group:
            group.append(raw)
    return {key: values for key, values in groups.items() if len(values) > 1}


def _as_utc(value: datetime) -> datetime:
    if not isinstance(value, datetime) or value.utcoffset() is None:
        raise ValueError("timestamp must have an explicit UTC offset")
    return value.astimezone(UTC)


def parse_instant(raw: str) -> datetime:
    if not isinstance(raw, str):
        raise ValueError("timestamp must be text")
    try:
        parsed = datetime.fromisoformat(raw)
    except ValueError as exc:
        raise ValueError("invalid ISO timestamp") from exc
    return _as_utc(parsed)


def in_window(instant: datetime, start: datetime, end: datetime) -> bool:
    start, end, instant = _as_utc(start), _as_utc(end), _as_utc(instant)
    if end <= start:
        raise ValueError("window end must follow start")
    return start <= instant < end


def window_total(
    records: list[dict[str, str]], start: datetime, end: datetime
) -> tuple[int, Decimal]:
    # Validate the bounds even when there are no source records.
    in_window(start, start, end)
    parsed = [
        (parse_money(record["amount"]), parse_instant(record["occurred_at"])) for record in records
    ]
    cents = 0
    count = 0
    with localcontext() as context:
        context.prec = 32
        for amount, instant in parsed:
            if in_window(instant, start, end):
                cents += int(amount * 100)
                count += 1
        context.prec = max(32, len(str(abs(cents))) + 4)
        total = Decimal(cents).scaleb(-2).quantize(Decimal("0.01"))
    return count, total


if __name__ == "__main__":
    start = parse_instant("2026-01-01T00:00:00+00:00")
    end = parse_instant("2026-01-02T00:00:00+00:00")
    rows = [
        {"amount": "0.10", "occurred_at": start.isoformat()},
        {"amount": "0.20", "occurred_at": "2026-01-01T12:00:00+00:00"},
        {"amount": "9.00", "occurred_at": end.isoformat()},
    ]
    assert window_total(rows, start, end) == (2, Decimal("0.30"))
    assert canonical_label("Café") == canonical_label("Cafe\u0301")
    print("Exact window total:", window_total(rows, start, end))
    print("Raw collision evidence:", collision_groups(["Straße", "STRASSE"]))
