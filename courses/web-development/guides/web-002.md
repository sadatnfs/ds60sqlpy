# web-002: Elements, attributes, nesting and text escaping

## Level and prerequisites

Beginner; allow about 90 minutes, with extra time for independent practice. Direct prerequisites: `web-001`

## Learning objectives

Build a notes paragraph with nested importance and literal angle brackets. Explain escaping versus validation with a text and URL example. Explain the mechanism, a normal case and a failure case in your own words, then retain source and observations separately.

## Purpose, vocabulary and mental model

An attribute adds information to an opening tag. In `<html lang="en">`, the attribute name is lang and its value identifies the document language. Attribute values should be quoted consistently. Nesting means one element's content contains another element; the resulting parent-child relationship matters to styling, accessibility and scripts. A paragraph can contain emphasized text, but a list does not belong inside that paragraph.

HTML has special syntax characters. A less-than sign begins markup, so literal comparison text may need `&lt;`. An ampersand begins a character reference and is commonly represented as `&amp;`. Escaping means representing text so a parser treats it as data. It is different from deleting characters and different from making an unsafe URL safe.

## Syntax anatomy and mechanism

Close nested elements in reverse order: open paragraph, open strong, close strong, close paragraph. Void elements such as `br` and `img` have no closing tag. A `data-*` attribute stores page-specific metadata; it does not create a visible label. `id` must uniquely identify an element in the document. Class names may repeat because they group related elements.

## Classroom execution and offline inputs

Choose **HTML browser preview** in the classroom. The pad is one complete HTML document with embedded CSS and, where taught, embedded JavaScript. Its preview is isolated from the classroom and recreated on each run. It does not contact a server, submit real forms, read cookies, fetch assets or load a CDN. All fixtures are inline and synthetic. The browser uses its native HTML parser, so classic-script ordering, shared lexical bindings, inline modules and real DOMContentLoaded/load events keep their browser semantics. External module imports remain blocked. Navigation metadata such as base and meta http-equiv is rejected explicitly. On any supported host, the browser renders the document while Docker serves the classroom. No host compiler is needed.

Run your own source after implementing the task. A reference's checks inspect only the named initial conditions. Its success message is not a full accessibility audit, proof of responsive behavior at every size, or evidence that you implemented the solution yourself. Inspect actual output after keyboard input, resizing and changes. Save your source before comparing with a reference. The document and its CSS share one saved pad; HTML and CSS remain different languages within that artifact.

## Worked example / walkthrough

### Worked example 1: Nested emphasis

The strong element identifies importance within the paragraph.

```html
<p>Save <strong>before</strong> closing.</p>
```

**Expected observation:** The word before has semantic importance and typically bold styling.

### Worked example 2: Literal comparison

Character references preserve the intended data.

```html
<p>2 &lt; 3 &amp; 3 &gt; 2</p>
```

**Expected observation:** The reader sees 2 < 3 & 3 > 2.

## Debugging and common mistakes

A page that looks correct can still contain an unintended parser repair. Inspect the Elements tree rather than relying only on View Source. Never teach `innerHTML` as a general way to insert untrusted text.

Keep the source that produced the failure, the relevant input or viewport, and the actual observation. Repair one cause and repeat the original case before adding a new one. A browser can recover malformed HTML, silently ignore a CSS declaration or display a plausible layout with the wrong reading order. PHP can produce correct-looking text while missing an invalid-input branch. A successful parse or an initial reference marker therefore answers a narrower question than the full lesson objective.

## Retrieval, transfer and next steps

Close the worked answers and explain element, attribute, nesting without using their names as definitions. Reconstruct the central example from a blank pad or worksheet. Use one new value, one empty or missing case and one adversarial or unusual boundary. State which result would disprove your explanation. When a behavior belongs to the browser, observe it in the browser; when it belongs to an HTTP server, keep that evidence separate from a CLI simulation.

Before moving on, keep a short learning record: your prediction, source revision, actual result, explanation and unresolved limitation. Revisit a direct prerequisite if you can reproduce output but cannot explain the mechanism. The path has milestones, not a fixed daily schedule, and a saved completion marker is a personal progress record rather than a professional certification.
