## Purpose and mental model

Automatic differentiation follows a recorded computation from a watched variable to a chosen output. TensorFlow's GradientTape is a recording scope. It does not infer dependencies merely because two values have a familiar name or because an unrecorded forward result happens to equal a recorded one.

Use \(\mathrm{loss}={\left(w-2\right)}^{2}\) with a float64 Variable. At zero the connected gradient is -4; at two it is numeric zero. If the forward loss was computed before the tape began, the tape has no recorded route from that loss to w, so its gradient is None. Missing and zero therefore report different facts. Treating every missing path as a zero update hides a broken experiment.

Variables also have identity and mutable state. assign_sub updates the existing Variable; rebinding a Python name to a calculated Tensor creates a different object. This unit inspects those boundaries using scalar CPU fixtures, before the three-point gradient pilot introduces paired observations. A qualified TensorFlow runtime is required for execution; reading the trace remains useful when that profile is unavailable.

## Vocabulary and concepts

**Tensor:** a TensorFlow value with shape and dtype, which need not be a trainable mutable parameter.

**Variable:** a mutable TensorFlow object whose identity and value can persist across updates.

**GradientTape:** the scope that records relevant operations for a later differentiation query.

**Watched value:** an input tracked for differentiation; trainable Variables are watched automatically when read inside the scope.

**Disconnected gradient:** None when the recorded graph has no path from the requested output to the requested input, unlike numeric zero on a connected path.

## Syntax or reasoning anatomy

The with statement starts a recording scope and indentation identifies its forward operations. Compute the loss from the Variable inside that scope. Calling tape.gradient afterward queries the recorded dependency. An ordinary nonpersistent tape supports one gradient query, so use a fresh tape and forward computation for another update. A constant can be watched explicitly, while a constant input feature does not need to be trainable for a separate Variable's derivative to exist.

Use float64 for these scalar checks and CPU placement explicitly. Integer tensors are not ordinary differentiable parameters. Never repair a disconnected path by substituting zero without diagnosing its origin. Updating a Variable uses its assignment method, whereas the Python assignment operator changes what a name refers to.

## Follow object identity and the recording interval

A variable's Python name is not its mathematical dependency. The tape records
operations involving the watched object during its scope. Copying a value
computed before recording does not reconstruct the missing history. Likewise,
converting a result to a Python number and then making a new tensor can preserve
the numerical value while discarding the recorded path needed for a gradient.

The constant feature in loss = (2w - 4) squared does not need to be trainable.
Its value still contributes the chain factor 2 when differentiating with
respect to w. At w = 0, the derivative is 2 times -4 times 2, or -16. The
question is which object receives the derivative, not whether every object
in the calculation is mutable.

A zero gradient at one point also needs interpretation. It can indicate a
minimum in this convex scalar example, but other functions have stationary
maxima, saddles or locally flat regions. A connected zero and a missing path
are different observations; neither should be replaced by a conclusion about
general model quality. Keep the forward value, recording boundary and requested
variable together when diagnosing an update.

## Worked example / walkthrough

Run Examples A and B in order in one scratch file, then run that complete file in a fresh process. Example B may reuse the imports, helpers and fixture state established in Example A. Do not treat an isolated later block as a standalone program.

### Example A: A recorded scalar loss

The multiplication and subtraction depend on w inside the recording region.

```python
import tensorflow as tf

with tf.device("/CPU:0"):
    w = tf.Variable(0.0, dtype=tf.float64)
    with tf.GradientTape() as tape:
        loss = tf.square(w - 2.0)
    gradient = tape.gradient(loss, w)
assert gradient is not None
assert float(gradient.numpy()) == -4.0
print(float(loss.numpy()), float(gradient.numpy()))
```

**Expected:** The output is loss 4 and gradient -4. A watched mutable Variable and a connected forward path produce an ordinary numeric gradient.

### Example B: A value formed before recording

Keep the same numerical loss but move its calculation outside the scope.

```python
with tf.device("/CPU:0"):
    precomputed = tf.square(w - 2.0)
    with tf.GradientTape() as tape:
        copied_loss = tf.identity(precomputed)
    missing = tape.gradient(copied_loss, w)
assert missing is None
print(missing)
```

**Expected:** The scalar can still equal 4, but the Variable-dependent operations were not recorded. Starting another scope afterward cannot reconstruct them.

## Exercises

1. **Trace a recorded path.** Reproduce the connected scalar example and name which forward operations depend on w.
   **Expected:** Loss 4 and gradient -4 at \(w=0\), dtype float64.
   **Verify:** Assert the scalar values and inspect that subtraction and square both occur inside the tape indentation.

2. **Distinguish a true zero.** Create a fresh Variable at \(w=2\) and record the same loss computation.
   **Expected:** Connected loss 0 and numeric gradient 0, not None.
   **Verify:** Use is not None before comparing the gradient value to 0.

3. **Repair a missing path.** Reproduce the outside-scope calculation, then recompute the forward path inside a new tape.
   **Expected:** Outside path gives None; repaired path at zero gives -4.
   **Verify:** Retain both results and assert their different types/values rather than converting None to zero.

4. **Watch a constant deliberately.** Differentiate square(c-2) for a float64 constant \(c=0\) with and without tape.watch(c).
   **Expected:** Unwatched constant gives None; explicitly watched constant gives -4.
   **Verify:** Assert both outcomes and explain why this does not make all input features trainable parameters.

5. **Preserve Variable identity.** Compare name rebinding after \(w-0.1\cdot \mathrm{gradient}\) with w.assign_sub on a fresh Variable.
   **Expected:** Rebinding yields a Tensor at 0.4 while the old Variable remains 0; assign_sub preserves the Variable object and changes its value to 0.4.
   **Verify:** Inspect isinstance(...,tf.Variable), object identity and both old/new numeric values.

6. **Use a fresh recording.** Query an ordinary tape twice, then repeat the operation using a new tape. Also use constant feature \(x=2\) with \(\mathrm{loss}={\left(w\cdot x-4\right)}^{2}\) at \(w=0\).
   **Expected:** Second use of the consumed tape raises RuntimeError; a fresh scalar tape gives -4, and the constant-feature loss gives gradient -16.
   **Verify:** Capture the consumed-tape exception and assert the two fresh-path gradients separately.

## Common pitfalls

If gradient is None, trace the earliest Variable-dependent operation and check whether it occurred before the tape or became a Python/NumPy value. Explicitly watching a constant cannot restore an operation performed earlier. If a second gradient query fails, inspect whether an ordinary tape has already been consumed instead of swallowing the RuntimeError.

If a parameter stops behaving like a Variable after an update, inspect whether Python name rebinding replaced it with a Tensor. A correct printed weight alone does not establish the state contract needed by another step. Keep CPU placement and dtype explicit; a missing TensorFlow import is an unavailable runtime, not a mathematical failure or a prompt to install packages inside this file.
