tf-018: Normalization state and batch dependence#

Level and prerequisites#

Intermediate; approximately 120 minutes. Direct prerequisites: tf-017. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

Learning objectives#

Distinguish BatchNorm moving statistics from per-example LayerNorm. The central investigation is concrete: Use momentum 0.5 and a fixed batch mean [2,4]; inspect the first BatchNorm moving-mean update and compare per-row normalization. The finish condition is Starting from zeros, moving mean becomes [1,2]. Evaluation does not update it. Adding an unrelated batch row cannot alter another row under LayerNorm. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

Purpose and mental model#

Normalization has three distinct contracts: which values share statistics, which state changes during training, and which affine parameters are learned. BatchNorm and LayerNorm can use similar arithmetic while differing on all three. A layer name or an axis number is not enough to infer the dependency structure.

For BatchNormalization(axis=-1) on input [N,C], the final axis identifies separate channels whose statistics are retained. The reduction happens over the other axis N. On channels-last images [N,H,W,C], separate channel statistics reduce over N,H,W. In contrast, LayerNormalization(axis=-1) reduces the final feature axis itself. On [N,T,D] it computes a distinct mean and variance for every [N,T] token, reducing D and preserving the token positions. These opposite roles for the axis argument are a common source of plausible-looking but incorrect comparisons.

BatchNorm uses current-batch statistics during a training call and updates moving statistics for later inference. Its scale gamma and offset beta are trainable parameters, while moving mean and variance are nontrainable state updated by the layer. Inference uses the stored state and should not update it. LayerNorm uses the current row's feature statistics in both ordinary training and inference, without maintaining running batch statistics. Its learned affine parameters still matter.

The main fixture keeps the familiar Keras momentum 0.5 example, then adds momentum 0.8 so the update convention becomes visible. Keras momentum is the retention weight of the old statistic. PyTorch BatchNorm momentum is the weight of the new statistic. Equal numerical arguments usually describe different updates; the value 0.5 happens to hide that distinction. Matching moving means alone also does not establish full cross-framework parity, because epsilon, variance-state conventions, layout and mode behavior must be matched explicitly.

Vocabulary and concepts#

Channel axis: For BatchNorm, the dimension whose distinct channel statistics are retained while other axes are reduced.

Reduction axis: A dimension whose values are combined to compute a statistic; LayerNorm axis=-1 reduces the feature dimension.

Moving statistics: Nontrainable state accumulated across training calls and used during BatchNorm inference.

Affine parameters: Learned scale gamma and offset beta applied after normalization.

Momentum convention: The meaning of the coefficient in a moving-statistic update, which differs between Keras and PyTorch.

Syntax anatomy and reasoning sequence#

Reduction axes and statistic shapes#

Layer and input Axis argument means Reduction axes Statistic shape before broadcasting
BatchNorm on [N,C] retain C distinct channels N [C]
BatchNorm on [N,H,W,C] retain C distinct channels N,H,W [C]
LayerNorm on [N,T,D] reduce D features D [N,T,1]
LayerNorm on [N,H,W,C] with axis=-1 reduce channels at each location C [N,H,W,1]

The last row is not whole-image normalization. Likewise, PyTorch's common channels-first convolution layout requires its own axis reasoning. Translate tensor layout before comparing framework calls. A statistical reduction can preserve the final output shape while changing which observations influence one another.

Calculate current and moving statistics#

For batch [[1,3],[3,5]], the per-channel mean is [2,4]. Each channel has centered values [-1,1] and population variance 1. With initial moving mean [0,0] and Keras momentum m=0.5, the update mold+(1-m)batch gives [1,2]. A second identical batch gives [1.5,3]. With a constant batch mean and zero initial mean, the value after t updates is (1-m^t) times that batch mean. Early inference statistics still reflect their initialization.

The initial moving variance is one. The main batch's variance is also one, so that state would not visibly change. A separate probe [[0,0],[4,4]] has population variance four per channel. The Keras update with m=0.5 gives 0.51+0.54=2.5. PyTorch's documented running-variance update uses the unbiased batch estimate, which is eight for those two observations, so matching its new-batch weight to 0.5 gives 4.5 instead. The TensorFlow fixture executes the Keras result; the paired PyTorch chapter separately exercises that framework's state convention.

Training output is not inference output#

With gamma=1, beta=0 and explicit epsilon=0.001, the training output of the main batch is [[-1,-1],[1,1]]/sqrt(1.001). After one moving-state update, inference instead subtracts [1,2] and divides by sqrt(1.001), giving [[0,1],[2,3]]/sqrt(1.001). It need not be centered on the new inference batch. Using inference mode on unrepresentative or barely initialized state can therefore produce a different result even when no trainable weight changed.

LayerNorm on row [1,3] uses row mean 2 and variance 1. Appending [100,200] as another row does not change those statistics. Learned gamma/beta are omitted from this hand arithmetic by using their default initial values. After affine parameters are learned, the final output need not retain zero mean even though the normalized internal values are centered.

Comparing frameworks and choosing the normalization contract#

For the same moving-mean update, translate Keras retention momentum m to PyTorch new-statistic momentum 1-m. Do not stop there: PyTorch documents a population variance for its training normalization but an unbiased estimate for its running-variance update. The Keras fixture above checks its moving-variance rule directly. Epsilon and affine parameters also affect outputs. The paired PyTorch chapter gives that framework's actual state checks; matching one printed mean is not a complete equivalence argument.

BatchNorm can be useful when its batch/statistical assumptions fit the task and data pipeline, but small, unusual or changing batches can make training and inference behavior diverge. Evaluation must avoid accidentally updating state using held-out examples. For sequence models, a reduction that includes future time positions can violate an autoregressive boundary even if attention is masked. Tokenwise LayerNorm avoids that particular cross-token dependency, although it does not prevent unrelated leakage elsewhere in a model.

Keras BatchNorm's trainable=False behavior is special: a direct call uses moving statistics even if training=True is supplied. For a compiled Keras training workflow, changing trainable after compilation requires recompilation for the changed setting to take effect as documented. These exercises use direct layer calls, so they do not claim a compiled-fit reconfiguration was tested. PyTorch separates parameter gradient flags from module mode, and its track_running_stats option introduces another distinct policy. Always name the state and mode contract being compared.

Primary API references: Keras BatchNormalization, Keras LayerNormalization, and PyTorch2.9 BatchNorm1d. The formulas and fixtures here use small literal CPU arrays; they do not establish distributed synchronization or deployment behavior.

Worked example / walkthrough#

Example A: Update and inspect moving state#

The mean update reveals old-versus-new weighting. The separate variance probe is necessary because a batch variance equal to the initial moving variance would hide whether an update occurred. The output expectation uses current-batch statistics, not the newly updated moving mean.

import numpy as np
import tensorflow as tf

epsilon = 1e-3
values = tf.constant([[1., 3.], [3., 5.]])
bn = tf.keras.layers.BatchNormalization(axis=-1, momentum=0.5, epsilon=epsilon)
training_output = bn(values, training=True)
np.testing.assert_allclose(bn.moving_mean.numpy(), [1, 2], atol=1e-6, rtol=0)
np.testing.assert_allclose(bn.moving_variance.numpy(), [1, 1], atol=1e-6, rtol=0)
expected = np.array([[-1., -1.], [1., 1.]]) / np.sqrt(1 + epsilon)
np.testing.assert_allclose(training_output.numpy(), expected, atol=1e-6, rtol=0)
probe = tf.keras.layers.BatchNormalization(axis=-1, momentum=0.5, epsilon=epsilon)
probe(tf.constant([[0., 0.], [4., 4.]]), training=True)
np.testing.assert_allclose(probe.moving_variance.numpy(), [2.5, 2.5], atol=1e-6, rtol=0)

Expected: moving mean [1,2]; main variance stays [1,1]; variance-four probe updates moving variance to [2.5,2.5].

Example B: Repeat updates and translate asymmetric momentum#

At 0.5 the coefficients are equal, hiding the convention difference. The asymmetric example identifies which coefficient belongs to the new batch. The Torch values here are an arithmetic comparison from its documented formula, not a claim that a Torch layer ran inside the TensorFlow profile.

import numpy as np
import tensorflow as tf

values = tf.constant([[1., 3.], [3., 5.]])
bn = tf.keras.layers.BatchNormalization(momentum=0.5)
bn(values, training=True)
bn(values, training=True)
np.testing.assert_allclose(bn.moving_mean.numpy(), [1.5, 3], atol=1e-6, rtol=0)
asymmetric = tf.keras.layers.BatchNormalization(momentum=0.8)
asymmetric(values, training=True)
np.testing.assert_allclose(asymmetric.moving_mean.numpy(), [0.4, 0.8], atol=1e-6, rtol=0)
asymmetric(values, training=True)
np.testing.assert_allclose(asymmetric.moving_mean.numpy(), [0.72, 1.44], atol=1e-6, rtol=0)
batch_mean = np.array([2., 4.])
keras_first = (1 - 0.8) * batch_mean
torch_same_number_formula = 0.8 * batch_mean
torch_matched_formula = 0.2 * batch_mean
assert not np.allclose(keras_first, torch_same_number_formula)
np.testing.assert_allclose(keras_first, torch_matched_formula, atol=1e-12, rtol=0)

Expected: 0.5 repeat gives [1.5,3]; Keras0.8 first/second means are [0.4,0.8] and [0.72,1.44]; matching Torch new-batch weight is 0.2.

Example C: Compare channel retention with feature reduction#

Both calls specify axis=-1 and return the same shape, but they reduce different axes. The independent NumPy formulas identify the distinction directly. This protects against a misleading axis label or a shape-only comparison.

import numpy as np
import tensorflow as tf

values = np.arange(8, dtype=np.float32).reshape(1, 2, 2, 2)
epsilon = 1e-3
bn = tf.keras.layers.BatchNormalization(axis=-1, momentum=0.8, epsilon=epsilon)
bn_output = bn(tf.constant(values), training=True).numpy()
channel_mean = values.mean(axis=(0, 1, 2), keepdims=True)
channel_variance = values.var(axis=(0, 1, 2), keepdims=True)
np.testing.assert_array_equal(channel_mean.reshape(-1), [3, 4])
np.testing.assert_array_equal(channel_variance.reshape(-1), [5, 5])
np.testing.assert_allclose(bn_output, (values - channel_mean) / np.sqrt(channel_variance + epsilon), atol=1e-6, rtol=0)
np.testing.assert_allclose(bn.moving_mean.numpy(), [0.6, 0.8], atol=1e-6, rtol=0)
np.testing.assert_allclose(bn.moving_variance.numpy(), [1.8, 1.8], atol=1e-6, rtol=0)
ln = tf.keras.layers.LayerNormalization(axis=-1, epsilon=epsilon)
ln_output = ln(tf.constant(values)).numpy()
local_mean = values.mean(axis=-1, keepdims=True)
local_variance = values.var(axis=-1, keepdims=True)
np.testing.assert_allclose(ln_output, (values - local_mean) / np.sqrt(local_variance + epsilon), atol=1e-6, rtol=0)
assert not np.allclose(bn_output, ln_output)

Expected: BN uses channel means [3,4] and variances [5,5]; LN reduces each location's two features.

Common pitfalls and diagnosis#

If changing another record changes an output, first ask which layer and mode are being tested. It is expected for training BatchNorm and unexpected for feature-only LayerNorm under fixed affine parameters. Write the reduced axes and statistic shapes explicitly. BatchNorm axis=-1 retains channel identities; LayerNorm axis=-1 reduces those feature values within each record.

If moving state does not match, expand one update numerically and check which coefficient weights the old statistic. The value 0.5 can hide reversed conventions. A variance probe equal to its initializer can also hide whether the state updated, so use the separate variance-four fixture. If inference output is not centered on a new batch, inspect the stored statistics rather than assuming the inference implementation is broken.

If state changes during evaluation, check the training argument, layer mode and any unexpected calls from preprocessing or validation. If freezing behaves differently across frameworks, separate affine-gradient control from moving-statistic updates and inference mode. Finally, keep epsilon and variance-estimator choices explicit before adjusting numerical tolerances; an API-convention mismatch is not floating-point noise.
