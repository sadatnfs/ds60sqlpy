# asm-011: When a likelihood is not separable

Tutorial mode. Stage: intermediate. Direct prerequisites: `asm-010`, `clp-012`.

## Starting point and result

Some objectives couple observations through covariance, normalization or shared latent variables. Splitting their rows and summing independent losses changes the model. This chapter uses a two-dimensional Gaussian to expose the missing cross term and log determinant. Complete pairs remain independent units, so Spark can still distribute work across pairs.

## Mechanism: covariance defines the indivisible unit

For a zero-mean pair \(y=(y_1,y_2)^\mathsf{T}\) with unit marginal variances and correlation rho, \(\Sigma=\begin{bmatrix}1&\rho\\\rho&1\end{bmatrix}\). Positive definiteness requires \(|\rho|<1\). Its negative log likelihood is

\[\ell(y;\rho)=\log(2\pi)+\tfrac12\log(1-\rho^2)+\frac{y_1^2-2\rho y_1y_2+y_2^2}{2(1-\rho^2)}.\]

The cross product is not expressible as two independent functions of y1 and y2 unless rho is zero. The determinant also depends on rho. Omitting it changes the optimizer's preference for covariance. The SQL expression evaluates each intact pair; the final sum is justified by independence between pairs, not between the two coordinates inside each pair.

This distinction generalizes to time series, spatial models and random effects. An algebraic reduction may exist without a row-wise factorization. For example, a structured covariance can permit sparse factorization or state-space recursion. That is a specialized algorithm, not permission to replace the joint distribution with independent marginals.

## Worked case: zero correlation recovers independence

The program evaluates three pairs with rho zero. The determinant is one, the cross term disappears and each pair's quadratic term is \((y_1^2+y_2^2)/2\). The joint expression equals the sum of two unit-normal losses exactly up to numerical reduction behavior. The serial oracle and Spark aggregate must agree.

This limiting case is valuable because it checks both the constant term and the quadratic contribution. Comparing only fitted parameters could miss a wrong additive constant, which matters for likelihood comparisons when model dimension or observation counts change.

## Worked case: correlation 0.8 changes the answer

At rho 0.8, same-sign pairs such as (1,1) are more consistent with the correlation structure than a discordant pair such as (0.2,-0.3). The program evaluates the correct joint loss and the incorrect independent-marginal loss on the same rows, and asserts a material difference. It does not estimate rho; it compares two objective implementations at a declared parameter.

If the pair coordinates were stored on different physical partitions, preparing complete pair records would require a join or another communication step. The communication is not merely an optimization detail: it supplies the information needed for the cross product. A missing partner must be rejected or modeled explicitly rather than replaced by zero.

## Failure diagnosis

A negative determinant indicates an invalid correlation or covariance parameterization. Use constrained transforms, such as a suitable bounded parameter map, while checking behavior near the boundary. An apparently excellent loss obtained by dropping unmatched rows is a coverage defect. Count complete pairs, missing partners and duplicate keys before trusting the reduction.

## Interview discussion

**Does a coupled objective make Spark useless?** No. Spark can prepare data, distribute independent blocks, compute matrix products or orchestrate specialized solvers. The valid decomposition must follow the model's structure.

**Can we sum arbitrary partition-local log determinants?** Only if the relevant matrix is block diagonal in those partitions, or if a mathematically justified decomposition accounts for the coupling. A storage partition boundary alone establishes neither.

## Complete reproducible program

Run this complete source in its declared prepared Spark profile. The fixture is tiny, deterministic and offline. Scala sources are compiled before execution; Python sources use the prepared PySpark environment. These are worked tutorials with no hidden solutions or exams. Runtime: `spark-local-python`.

```python
from __future__ import annotations

import json
import math


def session(name):
    from pyspark.sql import SparkSession

    spark = (
        SparkSession.builder.master("local[2]")
        .appName(name)
        .config("spark.ui.enabled", "false")
        .config("spark.driver.host", "127.0.0.1")
        .config("spark.driver.bindAddress", "127.0.0.1")
        .config("spark.sql.shuffle.partitions", "2")
        .config("spark.sql.adaptive.enabled", "false")
        .config("spark.sql.ansi.enabled", "true")
        .config("spark.sql.session.timeZone", "UTC")
        .getOrCreate()
    )
    if spark.version != "4.0.1":
        spark.stop()
        raise RuntimeError("This worked reference is qualified for Spark 4.0.1")
    spark.sparkContext.setLogLevel("ERROR")
    return spark


def pair_nll(y1, y2, rho):
    if abs(rho) >= 1:
        raise ValueError("Correlation must lie strictly between -1 and 1")
    return (
        math.log(2 * math.pi)
        + 0.5 * math.log1p(-rho * rho)
        + (y1 * y1 - 2 * rho * y1 * y2 + y2 * y2) / (2 * (1 - rho * rho))
    )


def run(spark):
    from pyspark.sql import functions as F

    pairs = [(1.0, 1.0), (-1.0, -0.5), (0.2, -0.3)]
    df = spark.createDataFrame(pairs, "a double,b double")
    evidence = []
    for rho in (0.0, 0.8):
        loss = (
            math.log(2 * math.pi)
            + 0.5 * math.log1p(-rho * rho)
            + (F.col("a") ** 2 - 2 * rho * F.col("a") * F.col("b") + F.col("b") ** 2)
            / (2 * (1 - rho * rho))
        )
        actual = df.agg(F.sum(loss).alias("loss")).first().loss
        oracle = math.fsum(pair_nll(a, b, rho) for a, b in pairs)
        assert math.isclose(actual, oracle, abs_tol=1e-12)
        independent = math.fsum(pair_nll(a, b, 0) for a, b in pairs)
        assert rho != 0 or math.isclose(actual, independent, abs_tol=1e-12)
        assert rho == 0 or abs(actual - independent) > 0.1
        evidence.append(
            {"rho": rho, "joint_loss": actual, "incorrect_independent_loss": independent}
        )
    print(json.dumps({"independent_units": "complete pairs", "cases": evidence}))


if __name__ == "__main__":
    spark = session("asm-011")
    try:
        run(spark)
    finally:
        spark.stop()
```
