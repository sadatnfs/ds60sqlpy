## Several views of the same permitted context

One attention head produces one normalized mixture of the allowed values for each query. A second head can produce a different mixture because it uses different projected features. This makes multiple heads useful when several relationships matter at once. For example, a trained layer might use different numerical features to connect a token with an earlier subject or with nearby punctuation. That is a possible learned behavior, not a built-in assignment of one linguistic job to each head. The literal arrays here demonstrate the mechanism without making semantic claims about trained heads.

Let D be the total feature width, H the number of heads and d=D/H the width of each head in this simple layout. For T tokens, a [T,D] array is reorganized into [H,T,d]. Every head still has T token positions. Splitting heads does not give half the tokens to one head and half to another. It distributes feature coordinates while each head receives its own complete allowed context.

The smallest layout fixture uses two token rows [0,1,2,3] and [4,5,6,7]. With two heads, head zero receives [0,1] and [4,5], while head one receives [2,3] and [6,7]. Those memberships are the meaning of the reshape-plus-transpose sequence. Simply reshaping the head-major result back to two rows yields [0,1,4,5] and [2,3,6,7], which has the right final shape but the wrong token/feature membership. Undoing the transpose before the reshape restores the original array. Tracking distinctive values is more informative than inspecting shape alone.

Within each head, scores are normalized separately over allowed key positions. The output vectors are then concatenated along the feature axis. A learned output projection can mix information from those head-specific vectors into the next representation. Keeping D fixed while changing H does not automatically multiply the main projection parameter count by H, because each head becomes narrower. It can still change score-tensor storage and the kinds of separate mixtures the architecture can express. Later head-sharing designs change the key/value projections themselves and require different accounting.

The residual connection then combines an input x with a learned update F(x), producing x+F(x). It gives the block a direct route to preserve x when the update is zero. It does not promise that x always survives unchanged: an update equal to -x cancels it. This matters when explaining residuals as an optimization aid rather than a guarantee that information cannot be lost. The feed-forward sublayer applies learned nonlinear feature transformations to each token independently; attention supplies cross-token mixing, while this sublayer changes how features are represented at each position.

A decoder block becomes understandable when these responsibilities remain separate: rearrange features into heads, compute permitted mixtures, rejoin features correctly, combine a residual update and apply tokenwise nonlinear transformations. The chapter's exact-value tests isolate each responsibility before the later PyTorch decoder puts them into one trainable module.
