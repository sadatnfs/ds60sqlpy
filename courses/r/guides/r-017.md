## Outcome and mechanism

Represent categories explicitly and avoid interpreting internal factor codes as measurements.

A factor stores category membership through integer codes and a levels attribute. The codes are an implementation representation, not the original category values. Calling as.numeric on a factor returns those codes. If categories happen to look numeric, that conversion can silently produce the wrong quantities. Decide first whether the field is a category or a numeric measurement.

Declared levels can outlive a selected subset. This is useful when a report must retain a stable category universe, including categories with zero observed rows. droplevels removes unused categories deliberately. The choice affects tables, plots and modeling contrasts, so it should follow a stated reporting or modeling contract rather than happen accidentally.

An ordered factor adds an ordering interpretation, such as low, medium and high. That does not establish equal numeric spacing between categories. A model may use different default contrasts for ordered versus unordered factors, changing the design matrix. Inspect model.matrix rather than assuming a factor becomes one simple numeric predictor.

For an unordered categorical predictor under ordinary treatment contrasts, the reference level defines the baseline interpretation. relevel can choose it explicitly. A coefficient then compares one category with that baseline while other modeled variables are held according to the model. The later regression lessons develop this fully; here the goal is to inspect and preserve the category contract before fitting anything.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Factor | A categorical vector with integer codes and declared levels. |
| Unused level | A declared category with no current observation. |
| Ordered factor | A categorical vector whose order is explicitly meaningful. |
| Reference level | A baseline category used by a chosen model contrast coding. |

## Read the syntax

factor(x, levels=...) declares the category universe and order. levels exposes labels, as.character recovers them, table(..., useNA=...) counts categories and missing values, and droplevels changes the retained universe deliberately.

## Worked examples

### Example 1: Codes are not numeric labels

```r
category <- factor(c("10", "20", "10"), levels = c("10", "20"))
stopifnot(identical(as.numeric(category), c(1, 2, 1)))
stopifnot(identical(as.numeric(as.character(category)), c(10, 20, 10)))
print(data.frame(label = as.character(category), code = as.integer(category)))
```

**Expected observation:** Labels 10,20,10; codes 1,2,1.

The intermediate character conversion retrieves the labels before numeric parsing. It is appropriate only if those labels genuinely represent measurements.

### Example 2: A retained category universe

```r
group <- factor(c("A", "B", "A"), levels = c("A", "B", "C"))
subset <- group[group == "A"]
stopifnot(identical(levels(subset), c("A", "B", "C")))
stopifnot(identical(levels(droplevels(subset)), "A"))
print(table(subset))
```

**Expected observation:** A2, B0, C0.

Subsetting retains the declared levels. Zero counts for B and C can be useful evidence rather than categories that should automatically disappear.
