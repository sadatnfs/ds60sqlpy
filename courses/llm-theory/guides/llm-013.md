# llm-013: A leakage audit before a model score

Status: authored beta content. The manifest inventories complete teaching files; runtime readiness remains a separate, measured property.

## Level and prerequisites

Beginner; approximately 105 minutes. Direct prerequisites: `llm-012`. The prerequisite sequence introduces the notation used here; revisit its worked examples if an axis, probability or gradient is unfamiliar.

## Learning objectives

Identify target leakage, duplicate documents and test-set reuse independently of mask correctness. The central investigation is concrete: Split a fixed corpus by source document; compare shifted labels with copying the input as its own target and introduce one duplicate document. The finish condition is Inputs [2,5,7] pair with labels [5,7,3]; document sets are disjoint and the injected duplicate is detected. Prefix invariance alone does not establish these conditions. A useful explanation connects the calculation to the reason it is needed, rather than treating a function name as a definition.

## Purpose and mental model

A decoder can have perfect causal attention and still be evaluated on leaked data. Next-token training pairs each input position with the following token; copying the input as its own label creates an easier identity task. A split must also keep document families together and exclude duplicates across partitions. Tokenizer fitting, prompt selection and preprocessing can consume evaluation information before model training begins. The fixture separates these failure modes so a passing mask test is not mistaken for a complete experiment audit. Stable document identity and explicit shifted arrays provide stronger evidence than a plausible loss curve.

## Vocabulary and concepts

**Shifted target:** The next token paired with the current input position.

**Contamination:** Assessment information entering training or selection.

**Document family:** Related records treated as one split unit.

## Worked example / walkthrough

### Example A: Construct next-token pairs

There are three target events in a four-token sequence. The final token has no next token unless an explicit end marker is included in the original sequence.

```python
import numpy as np

ids=np.array([2,5,7,3]); inputs=ids[:-1]; labels=ids[1:]
np.testing.assert_array_equal(inputs,[2,5,7]); np.testing.assert_array_equal(labels,[5,7,3])
```

**Expected:** inputs[2,5,7],labels[5,7,3].

### Example B: Expose identity labels

A model trained to reproduce its current token is not being tested on next-token prediction. A causal mask allows the current input, so it cannot detect this objective error.

```python
import numpy as np

copied=inputs.copy(); assert np.count_nonzero(copied!=labels)==3
```

**Expected:** all three copied labels differ from the target fixture.
