Outcome and mechanism#

Trace shared R6 identity, protect state through methods and distinguish shallow from nested-R6 deep cloning.

R6 creates objects with reference semantics. Assigning an existing R6 object to another name creates an alias to the same instance. A method that changes its private state is visible through both names. That behavior is useful for a controlled cache, iterator or running accumulator, but it differs from the numeric-list value in the S3 lesson. An analysis that assumes assignment always isolates state can therefore change earlier results accidentally.

An R6Class call creates a generator. Calling Counter$new constructs an instance, and object$method() invokes one of its public methods. The example stores value in the private environment and exposes read and add operations. Validation occurs before mutation, so a rejected negative, missing or infinite increment leaves the previous state intact. The method returns invisible(self), allowing explicit chaining without using printed output as data.

Private members express an interface boundary for ordinary use. They are not a security boundary against arbitrary R reflection in the same process. The purpose is to keep callers from depending on internal representation and to concentrate state changes in methods that preserve the invariant. A reusable method should document whether it mutates the object and what it returns.

clone creates a new instance, but shallow and deep cloning have different reach. A shallow clone copies the outer R6 object while retaining references to nested R6 objects. A deep clone automatically clones those nested R6 objects. The boxed-counter example makes this distinction measurable: a change through a shallow box affects the original counter, while a change through the deep box does not.

Deep cloning is not a universal recursive snapshot of every possible object graph. Arbitrary environments and external resources need an explicitly designed deep_clone policy, and file connections or external pointers may not have a meaningful copy. This lesson tests nested R6 members only. When independent analytical values are sufficient, a plain validated value object often has a smaller behavioral contract.

Reference objects make test order and ownership important. Each example starts in a fresh process and constructs fresh counters. Tests check aliases, clones, unchanged state after rejection and returned values independently. A mutable accumulator should not be reused across folds or simulations unless that reuse is intentional and reset behavior is part of the interface.

Vocabulary#

Term Meaning
Alias Another name referring to the same mutable object instance.
Encapsulation Keeping state changes behind a stated public interface.
Shallow clone A new outer instance that can retain referenced inner objects.
Deep clone An R6 clone that also clones nested R6 objects, with limits for other reference types.

Read the syntax#

R6::R6Class returns a generator; Counter$new(initial=2) makes an instance. Public methods use self and private to access object state. b <- a aliases a, while a$clone() creates a new outer instance. a$clone(deep=TRUE) also clones nested R6 members under the default R6 policy.

Worked examples#

Example 1: Aliases observe the same counter#

Counter <- R6::R6Class("Counter", private = list(value = 0), public = list(
  initialize = function(initial = 0) {
    if (!is.numeric(initial) || length(initial) != 1L || !is.finite(initial) || initial < 0) {
      stop("initial must be one nonnegative finite number")
    }
    private$value <- initial
  },
  add = function(amount) {
    if (!is.numeric(amount) || length(amount) != 1L || !is.finite(amount) || amount < 0) {
      stop("amount must be one nonnegative finite number")
    }
    if (!is.finite(private$value + amount)) stop("counter overflow")
    private$value <- private$value + amount
    invisible(self)
  },
  read = function() private$value
))

a <- Counter$new(2)
b <- a
b$add(3)
stopifnot(a$read() == 5, b$read() == 5, identical(a, b))
copy <- a$clone()
copy$add(4)
stopifnot(a$read() == 5, copy$read() == 9)
print(c(original = a$read(), copy = copy$read()))

Expected observation: Alias reads 5; independent clone reads 9.

Assignment shares the same reference; cloning the simple scalar counter creates independent private state. The returned numeric readings are suitable for later calculations.

Example 2: Nested R6 members expose shallow-clone sharing#

Counter <- R6::R6Class("Counter", private = list(value = 0), public = list(
  initialize = function(initial = 0) {
    if (!is.numeric(initial) || length(initial) != 1L || !is.finite(initial) || initial < 0) {
      stop("initial must be one nonnegative finite number")
    }
    private$value <- initial
  },
  add = function(amount) {
    if (!is.numeric(amount) || length(amount) != 1L || !is.finite(amount) || amount < 0) {
      stop("amount must be one nonnegative finite number")
    }
    if (!is.finite(private$value + amount)) stop("counter overflow")
    private$value <- private$value + amount
    invisible(self)
  },
  read = function() private$value
))

Box <- R6::R6Class("Box", public = list(
  counter = NULL,
  initialize = function(counter) {
    stopifnot(inherits(counter, "Counter"))
    self$counter <- counter
  }
))
original <- Box$new(Counter$new(1))
shallow <- original$clone()
deep <- original$clone(deep = TRUE)
shallow$counter$add(2)
deep$counter$add(5)
stopifnot(original$counter$read() == 3, shallow$counter$read() == 3, deep$counter$read() == 6)
print(c(original = original$counter$read(), shallow = shallow$counter$read(), deep = deep$counter$read()))

Expected observation: Original 3, shallow 3, deep 6.

The shallow box and original share the same nested counter. The deep box owns a cloned counter that started at one. This demonstrates the supported nested-R6 policy without claiming to duplicate arbitrary resources.

Progressive hints#

  2. Clone before mutating.
  3. Read before and after catching the specific validation error.
  4. The outer box can differ while its inner counter is shared.
  5. A prior fold may leave state for the next.
  6. R6 members and all reference types are not interchangeable.

Reference review#

The alias test establishes reference identity directly with identical, then tests observable mutation. The scalar clone and nested box tests isolate two different depths of copying. Validation tests check that rejection happens before mutation, rather than merely checking that some error occurs.

Fresh counters within the fold function demonstrate one ownership policy for independent analytical tasks. The example makes no claim that default deep cloning duplicates every environment, file handle or external resource. Those need their own lifecycle and copying rules.
