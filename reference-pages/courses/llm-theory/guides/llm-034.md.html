llm-034: Precision and quantization error budgets#

Purpose and mental model#

Quantization is an approximation with a specified reconstruction rule#

A floating-point weight can take many representable values. Quantization maps it to one of a smaller set of codes, along with information needed to reconstruct an approximation. The integer code by itself is not the original weight. The scale, zero-point convention, grouping and rounding rule are part of the representation. Changing any of them can change the dequantized function even when the stored integer array has the same shape.

This chapter uses symmetric signed int8 codes from-127 to 127 and a zero-centered scale s. For a nonzero tensor with maximum absolute value a, s=a127s=\frac{a}{127}. A weight w is mapped to q=clip(round(w/s),-127,127), then reconstructed as w^=s·q\widehat{w}=s\cdot q. The reference uses NumPy's nearest-even rounding. It is one explicit scheme, not a claim that all int8 or low-bit implementations use the same endpoints or metadata.

Preserve a full-precision oracle#

The fixture weight matrix is[[.1,-.9],[1.7,-.2]] and the input is[1,-2]. The full-precision output is[.1+1.8,1.7+.4]=[1.9,2.1]. Save this result from the original matrix before quantizing. If the supposed reference were recomputed from reconstructed weights, the comparison would hide the approximation by making both paths share it.

With one scale for the whole matrix, s=1.7127s=\frac{1.7}{127}≈.01338583. Dividing by that scale and rounding produces integer codes[[7,-67],[127,-15]]. Reconstructing them gives approximately[[.09370079,-.89685039],[1.7,-.20078740]]. The new output is approximately[1.88740157,2.10157480], so the two output errors are about[-.01259843,.00157480]. The first output suffers more because its row shares a scale set by the larger magnitude in another row.

The integer array looks compact and plausible, but its correctness is inseparable from the scale and reconstruction formula. Treating q directly as a floating-point matrix would compute a completely different function. Loading the correct q with a scale from another tensor is another silent compatibility error that shape checks alone cannot catch.

Derive a useful error bound and its assumptions#

For nearest rounding without clipping, the reconstruction error of one scalar satisfies |w^−w|≤s2|\widehat w-w|\le\frac{s}{2}. For a matrix row and input x, output error is δy=∑jδw,jxj\delta_y=\sum_j\delta_{w,j}x_j. The triangle inequality gives |δy|≤∑j|δw,j||xj||\delta_y|\le\sum_j|\delta_{w,j}|\,|x_j|, and with one row-wide scale this is at most s2∑j|xj|\frac{s}{2}\sum_j|x_j|. The input's L1 magnitude matters: small weight errors can be amplified by large input coordinates.

For x=[1,−2]x=[1,-2], the L1 sum is 3. With the shared scale 1.7127\frac{1.7}{127}, the simple row bound is 1.5·s1.5\cdot s≈.02007874. The observed first-row error magnitude .01259843 lies below that bound. The bound is not an equality prediction and does not account for cancellation signs. It is useful as a sanity check because an error much larger than the stated unclipped bound suggests a different operation, scale or clipping event.

Clipping breaks the simple s2\frac{s}{2} guarantee relative to an arbitrary original value. If a scale was calibrated from one dataset and a later value exceeds its representable range, the clipped code can be far from the original. Quantization policies therefore distinguish rounding error within range from saturation outside range. Counting clipped values and inspecting their task context can reveal a failure that a mean weight error hides.

Compare per-tensor and per-row scales#

A per-row scheme gives the first row scale 0.9127\frac{0.9}{127}≈.00708661 and the second row scale 1.7127\frac{1.7}{127}. The first row's codes become[14,-127], reconstructing approximately[.09921260,-.9]. Its output becomes 1.89921260, much closer to 1.9 than under the shared scale. The second row's scale and result remain as before. In this fixture, the maximum output error falls from about .01259843 to .00157480.

This is an example, not a universal theorem that a particular grouping always improves every downstream output. Finer groups often offer better local resolution but require more scales, different kernels and additional indexing. A scale policy can interact with activation distributions and accumulation precision. Compare the reconstructed function on representative inputs, not only the maximum weight error or one favorable vector.

The all-zero tensor is an important boundary. Its maximum magnitude is zero, so the naive scale formula gives s=0s=0 and division by zero. A complete implementation needs a declared convention, such as storing zero codes with a harmless nonzero scale. The code and tests should state that convention rather than relying on accidental NaNs or a later cast. The lesson's positive matrix does not establish every boundary of every quantizer.

Storage savings include metadata and actual format#

Four float32 weights occupy 16 raw bytes. Four int8 codes occupy 4 bytes. But one float32 scale adds 4 more bytes, making 8 raw bytes under this minimal per-tensor accounting. Two row scales add 8 bytes, making 12. On this tiny matrix, scale metadata is a large fraction of the result. Headers, alignment, tensor names and serialization overhead can dominate a saved file even more.

For a large matrix, metadata amortizes differently, but it still belongs in the count. A low-bit representation may pack several codes into a byte and require unpacking; an int8 dtype does not demonstrate four-bit storage. A saved file's size, an in-memory tensor's numeric bytes and runtime peak memory are distinct measurements. Report which one was actually observed.

A quantized representation also does not prove that the matrix multiplication executes using a fast integer kernel. The reference reconstructs values and uses ordinary local arithmetic to inspect error. Real kernels choose accumulation dtypes, layouts, scale application and hardware instructions. A speed claim requires a measured implementation on representative shapes, with appropriate synchronization and warmup. File compression alone cannot establish it.

Follow approximation through the larger computation#

A transformer contains many operations, so local quantization error can interact with nonlinearities, residual paths, normalization and attention. An error that is small under one input can matter near a decision boundary or change an argmax when two logits are close. Conversely, a visible weight difference can have little effect for a particular input direction. Output and task-level tests answer questions that weight-distance metrics cannot settle alone.

Suppose two final logits are[1.001,1.000]. A perturbation of only-.002 to the first can reverse the chosen token, even though the absolute error looks tiny. If the logits are[10,0], the same perturbation leaves the top choice unchanged. The operational significance of an error depends on margins, downstream policy and the task, not merely on the number of decimal places.

When quantization is combined with an adapter, keep the base representation and adapter computation explicit. A frozen quantized base plus trainable factors is not identical to the full-precision base unless the approximation happens to preserve the relevant function. The adapter may learn to compensate for some errors under its training distribution, but a successful local loss reduction does not prove universal compensation.

Build an error report that can guide a decision#

Retain the original weights or their identity, quantization grouping, scale metadata, rounding/clipping rules, reconstructed weights, input cases, output errors and any observed saturation. Separate mechanism checks from task evaluation and measured runtime behavior. If an error threshold fails, inspect which row and input direction caused it before increasing tolerances or changing the metric.

Vocabulary and concepts#

Scale: The real-valued spacing represented by one integer quantization step.

Saturation: A value clipped to the allowed integer boundary.

Error budget: A declared tolerance for the effect of approximation.

Syntax anatomy and reasoning sequence#

For a nonzero block, scale=max(|W|)127\mathrm{scale}=\frac{\max(\left|W\right|)}{127}. Quantize with rint(W/scale), clip and cast to int8. Dequantize by multiplying the integer array by its scale. Row scales use keepdims=True to preserve broadcasting along columns. A zero block needs an explicit nonzero scale convention. Compare against full precision W@x for x[1,-2].

Quantization changes values before the matrix product#

The full-precision fixture has W=[[0.1, -0.9], [1.7, -0.2]] and x=[1, -2], giving W*x=[1.9, 2.1]. A symmetric shared scale s=1.7127s=\frac{1.7}{127} maps the weights to integer codes round(W/s)=[[7, -67], [127, -15]]. Dequantization multiplies these codes by s. The resulting output is approximately[1.887401575, 2.101574803], so the maximum absolute output error is about 0.012598425.

The largest magnitude1.7 sets the shared scale. With a separate scale per row, the first row can use0 0.9127\frac{0.9}{127}, yielding codes[14, -127] and output1.899212598. The second row is unchanged. The maximum error then becomes approximately 0.001574803. This improvement is specific to the supplied weights and input, and costs an additional scale. More granular scales can reduce some representation errors while increasing metadata and implementation complexity.

For nearest rounding without clipping, each weight error has magnitude at most s2\frac{s}{2}. Writing E=Wrestored−WE=W_{\mathrm{restored}}-W, the output error in row i obeys |(Ex)i|≤∑j|Eij||xj|≤s2‖x‖1|(Ex)_i|\le\sum_j|E_{ij}|\,|x_j|\le\frac{s}{2}\lVert x\rVert_1. Here the bound is approximately 0.02007874 because ||x||_1=3. It is a worst-case bound for these assumptions, not the observed error. Clipping an out-of-range value can exceed the half-step bound. A zero-valued block also needs an explicit scale convention to avoid division by zero in a general implementation.

Count the intended storage and the actual operations#

Four int8 codes and one float32 scale would use8 raw data bytes; two float32 scales would use12. Those are layout calculations for the proposed representation. This NumPy program uses float64 for its analysis scales and dequantized arithmetic, plus array metadata and intermediates. It does not demonstrate an eight-byte process allocation or an integer matrix-multiplication kernel.

The code restores floating values before multiplying. Therefore it measures numerical error from a specified quantizer, not inference speed, GPU memory savings or a full low-bit model. It also declares NumPy's ties-to-even rounding:0.5 goes to 0, 1.5 to 2 and2.5 to 2. Quantization comparisons should state code range, scale shape, rounding, clipping, accumulation dtype and the calibration data used to set ranges. Evaluate downstream outputs under a representative task; a small weight error alone need not imply a small decision change near a classification boundary.

Worked example / walkthrough#

Example A: Compute the full-precision reference#

The reference keeps the original floating-point values. It must not be recomputed from dequantized weights, which would erase the approximation being measured.

import numpy as np

w=np.array([[.1,-.9],[1.7,-.2]]); x=np.array([1.,-2.]); reference=w@x
np.testing.assert_allclose(reference,[1.9,2.1],atol=1e-12,rtol=0)

Expected: output[1.9,2.1].

Example B: Quantize one shared scale#

The smaller first row uses the scale set by the largest value in the second row. Its values therefore receive coarser relative resolution.

import numpy as np

w=np.array([[.1,-.9],[1.7,-.2]]); x=np.array([1.,-2.]); reference=w@x
np.testing.assert_allclose(reference,[1.9,2.1],atol=1e-12,rtol=0)
scale=np.abs(w).max()/127; raw=np.rint(w/scale); q=np.clip(raw,-127,127).astype(np.int8)
np.testing.assert_array_equal(q,[[7,-67],[127,-15]]); assert scale==1.7/127

Expected: scale1.7/127;integer array[[7,-67],[127,-15]].

Common pitfalls and diagnosis#

Inspect integer codes, scale shape and clipping before measuring the final output error. The half-step bound assumes unclipped nearest rounding. Raw proposed layout bytes are not the actual NumPy allocation, and dequantize-then-multiply is not an integer kernel benchmark. Report the input and task whose error was measured.
