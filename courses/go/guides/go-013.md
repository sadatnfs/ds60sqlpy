# go-013: Packages, modules and reproducible project boundaries

## Level and prerequisites

Beginner. Allow about 90 minutes, then revisit the transfer case later. Prerequisites: go-012

## Learning objectives

Use standard-library packages through their exported API and read the module, go and toolchain directives in go.mod. Along the way, explain module, exported name, import path; implement the six investigations below; and defend the expected result of a changed input before running it.

## Why this mechanism matters

A package is a compilation and visibility boundary; a module is a versioned collection of packages described by go.mod. An import path identifies a package, not an operating-system filename. Capitalized declarations are exported to other packages. The main package creates an executable, while reusable packages expose focused APIs. go.sum records module-content checksums but is not a substitute for reviewing dependency changes. An offline classroom pad cannot become a multi-file dependency project by containing a go.mod string. This lesson executes standard-library boundary examples and separately teaches the real project layout. Keep generated outputs, dependency selection and application source under distinct review.

## Vocabulary and concepts

- **Module:** A versioned group of Go packages rooted at go.mod.
- **Exported name:** A declaration visible outside its package because its name begins uppercase.
- **Import path:** The logical identity used to select a package.

## Syntax anatomy and reasoning

The standard library already contains packages such as path, strings and strconv. An alias in an import declaration changes the local selector name, not the dependency's identity. For a real project, run go mod init example.org/learning/report in a prepared directory, place reusable code under a package folder, and use go test ./... plus go build ./cmd/report. Pin reviewed dependency versions with go get and commit go.mod and go.sum. Dependency retrieval is explicit setup, never a side effect of opening a lesson. A go.mod file starts with the module path, then a go line such as go 1.27 that states the minimum Go version the module needs, and optionally a toolchain line such as toolchain go1.27.3 that names a suggested newer toolchain. The GOTOOLCHAIN environment variable decides whether the go command may switch to another toolchain; local means it never does.

## Worked example / walkthrough

### Worked example 1: Use a package boundary

Join logical slash-separated path segments with path.Join.

```go
package main

import (
	"fmt"
	"path"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Use a package boundary
	{
		check(path.Join("reports", "daily.json") == "reports/daily.json", "path package")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The result is reports/daily.json.

path works with slash-separated logical paths. filepath is a different package whose behavior follows the host operating system.

### Worked example 2: Compose standard-library APIs

Trim and parse the text containing spaces around 12.

```go
package main

import (
	"fmt"
	"path"
	"strconv"
	"strings"
)

func check(ok bool, message string) {
	if !ok {
		panic(message)
	}
}

func main() {
	// Use a package boundary
	{
		check(path.Join("reports", "daily.json") == "reports/daily.json", "path package")
	}

	// Compose standard-library APIs
	{
		v, err := strconv.Atoi(strings.TrimSpace(" 12 "))
		check(err == nil && v == 12, "package composition")
	}
	fmt.Println("Worked example checks passed.")
}
```

**Observe:** The parsed value is 12.

Each package contributes a small contract. Trimming is an explicit input policy, while numeric parsing remains independently fallible.

## Exercises

### Exercise 1: Use a package boundary: predict an edited check

Copy worked example 1 into a scratch pad and change `check(path.Join("reports", "daily.json") == "reports/daily.json", "path package")` to `check(path.Join("reports!", "daily.json") == "reports/daily.json", "path package")` inside its check. Before running, predict whether the check still passes and explain why; then restore it.

**Expected:** The changed run panics with `path package` because the edited check no longer holds. Restoring the original line brings back the worked observation: the result is reports/daily.json.

**Verify:** Compare your written prediction with the panic message `path package` and name the value that made `path.Join("reports", "daily.json") == "reports/daily.json"` false. After restoring the input, the program must print its success line again.

### Exercise 2: Compose standard-library APIs: debug a regression

A regression changed one token in worked example 2, so one line now reads `v, err := strconv.Atoi(strings.TrimSpace(" 13 "))`. Run worked example 2 with that line, use the failure to locate the defect and repair it without changing the check.

**Expected:** Before the repair the program panics with `package composition`; after it the line reads `v, err := strconv.Atoi(strings.TrimSpace(" 12 "))` again and the parsed value is 12.

**Verify:** Keep the failing and the repaired runs. Explain why the changed token alters the value tested by `err == nil && v == 12` for this input.

### Exercise 3: Inspect exported spelling

Classify ParseInt, parseInt and an empty name with one rule: a name is exported when its first rune is an uppercase letter.

**Expected:** Only ParseInt is exported.

**Verify:** Keep a check equivalent to `exported("ParseInt") && !exported("parseInt") && !exported("")`. As a control, change `exported := func(name string) bool { return name != "" && unicode.IsUpper([]rune(name)[0]) }` to `exported := func(name string) bool { return name == "" && unicode.IsUpper([]rune(name)[0]) }`: the run must panic with `export convention`. Restore the line before continuing.

### Exercise 4: Read the go and toolchain directives

Extract the module, go and toolchain lines from a small go.mod text.

**Expected:** The module requires Go 1.27 and suggests toolchain go1.27.3.

**Verify:** Keep a check equivalent to `directives["module"] == "example.org/learning/report" && directives["go"] == "1.27" && directives["toolchain"] == "go1.27.3"`. As a control, change `if len(fields) == 2 {` to `if len(fields) == 3 {`: the run must panic with `directives`. Restore the line before continuing.

### Exercise 5: Reject malformed input at an API boundary

Parse a nonnumeric public input after trimming.

**Expected:** The numeric error remains non-nil.

**Verify:** Keep a check equivalent to `err != nil`. As a control, change `check(err != nil, "boundary error")` to `check(err == nil, "boundary error")` inside that check: it must panic with `boundary error`, which shows the check can fail. Restore it.

### Exercise 6: Transfer an API contract

Build a deterministic report name from a validated positive integer.

**Expected:** The resulting logical name is reports/day-3.json.

**Verify:** Keep a check equivalent to `name == "reports/day-3.json"`. As a control, change `day, err := strconv.Atoi("3")` to `day, err := strconv.Atoi("4")`: the run must panic with `report name`. Restore the line before continuing.

## Common pitfalls and diagnosis

Read a compiler error from the first location in your source, then fix one cause at a time. Unused imports and variables are errors in Go; add an import when its use exists, rather than copying a large unused import list. A panic from `check` identifies a violated example contract. Compare the actual value with the expected value and inspect the state transition that produced it. A returned `error` is a value that the caller must handle; an ignored error can make later output look plausible while the original operation failed.

The lesson-specific explanations in the two examples identify the important counterexamples. Extend that reasoning to every investigation: explain why a plausible alternative would fail, and preserve a tiny input that distinguishes it. Treat empty data, missing values and cancellation as domain cases with explicit policies. In concurrent work, replace sleeps used as synchronization with channels, mutexes or an explicit ownership protocol.
