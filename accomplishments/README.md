# Accomplishment index implementation draft

This work-only directory is a copy-ready prototype. It reads maintained
repository JSON, TOML, Python export syntax and the native C++ registration
source as text. It does not import Torch, Spark or R or execute lessons. No
main repository file changed when this prototype was built. Relative links in
the generated landing page resolve after the directory is placed at the
repository root as `accomplishments/`.

`inventory.json` is generated lookup data. `INDEX.md` is its human landing
page. `manual-capabilities.json` is an edited set of cross-cutting entries.
`RUNNING.md` is a separately maintained dated accomplishment log and is never
rewritten by `build` or `check`.

## Rebuild, check and search

From this directory:

```sh
python index.py build --repo /path/to/ds60sqlpy
python index.py check --repo /path/to/ds60sqlpy
python index.py search 'SparkTMBad' --kind api --limit 5
python index.py search 'sim-028' --kind study
DS60_INDEX_REPO=/path/to/ds60sqlpy python -m unittest -v test_index.py
```

The generated inventory has 2,267 entries: 40 tracks, 2,074 lessons and
variants, two independent packages, 27 root API exports, six registered
Spark/PyTorch likelihood models, seven named model factories, 23 native models,
14 primary Scala facade operations, four optional R reference models,
24 option-expanded R reference cases, 37 simulation study IDs, and nine
cross-cutting capabilities. Legacy lesson
records come from `curriculum/catalog.json`, whose maintained builder is
`src/ds60sqlpy/catalog_builder.py`. Modern track and lesson records come from
the 31 `courses/*/track.json` plans, five founding plans in
`docs/expansion/plans/`, 36 authored `courses/*/lessons.json` manifests, and
the special statistics book manifest and tutorial extension index. The parity
test compares all lesson IDs against the actual `Catalog` and `ModuleCatalog`
loaders. This test confirmed 201 legacy plus 1,873 module lessons/variants
without loading Torch, PySpark or R bindings.

Native model IDs are resolved from each `prepared_models()` call to its
descriptor definition, including parameterized and custom extension calls.
The current registry yields 23 IDs. If a call or descriptor is unparsed, the
rebuild fails rather than silently omitting a model. The existing Python
likelihood registry, named TorchLoss/TorchUnitLoss factories and primary
Scala `PythonBridge` facade are indexed from source declarations.
Optional R option leaves must match the 24 hash-bound cases in the ARM64 v2
reference index. Planned lessons remain planned until authored files are
registered; manifest variants have a separate authored-variant status.
Simulation entries retain the design file's exact status
statement; normalized labels distinguish design/source, historical local
partial scope and incomplete historical runs. Neither a generated row nor a
running log entry is current hosted acceptance by itself.

## Recommended repository placement and maintained links

After review and the release source gate, copy this directory to
`accomplishments/` at the repository root. Keep the source, manual and generated
files together so
`index.py` can find the manual and generated files. Add a short row to root
`AGENTS.md` under **Maintained sources**:

```md
| Accomplishments and lookup | [running log](accomplishments/RUNNING.md), [index](accomplishments/INDEX.md), generated `accomplishments/inventory.json`, [rebuild tool](accomplishments/index.py) |
```

Add this link and rule in `.agents/skills/add-learning-path/SKILL.md` after
the existing catalog/lesson regeneration step:

```md
Rebuild the [accomplishment index](../../../accomplishments/INDEX.md) after
track, lesson, variant, package, model, reference or study registry changes.
Use `python accomplishments/index.py build --repo .` and
`python accomplishments/index.py check --repo .`. Append to RUNNING.md only
when the evidence tier changes; do not auto-generate dated accomplishments.
```

Add a link in `.agents/skills/guide-ds60sqlpy-learning/SKILL.md` for discovery:

```md
Use [the accomplishment lookup](../../../accomplishments/INDEX.md) to find a
registered lesson or package API. Its status is source/evidence metadata,
not learner progress or proof that an optional runtime is installed.
```

Add a source gate row in `docs/validation.md`, linking to
`../accomplishments/INDEX.md`, and use these read-only commands in the
repository source CI after the build output is committed:

```sh
python accomplishments/index.py check --repo .
DS60_INDEX_REPO="$PWD" python -m unittest -v accomplishments/test_index.py
```

The index check must run after curriculum/catalog and authored reader checks.
It verifies exact generated bytes, safe repository-relative paths, unique IDs,
resolved relationships and reference receipt hashes. A changed registry
requires a deliberate rebuild and review of the generated diff. The running
log is reviewed as an editorial source and stays outside generated output.

## Review boundaries

- The optional R v2 index is historical local ARM64 evidence. It does not
  establish hosted recurrence or availability of a current base image.
- Simulation IDs are reserved study identities, not classroom lessons.
  Several are designs only; partial fit runs remain explicitly partial.
- The independent Torch executor-training draft is described in RUNNING.md
  but has no generated repository API entry yet. Once its sibling namespace
  and setuptools discovery are in the independent package, the lookup verifies
  and adds named program, data, launch and checkpoint entrypoints as source
  entries. Installed-wheel and runtime acceptance remain separate gates.
- Source and workflow entries distinguish implementation from exact release
  publication, fresh Hub pull, browser acceptance and recurrence.
