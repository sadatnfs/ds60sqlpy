Production worker boundary#

Each service runs one operation at a time. Source is bounded to 256 KiB, logs to 128000 bytes, disposable files to 32 MiB / 1024 files, and the total deadline to 15, 60 or 120 seconds. Compile has its own maximum 60-second phase within that total. Worker terminal history retains at most 32 snapshots. The service never accepts shell commands, image references, host mounts or learner-supplied tool flags.

Production readiness requires a Linux container supervisor, an actual UID/GID 65534 privilege drop, inability of that child to read the private token, and the ability of the supervisor to kill that different-UID child. The supervisor requires CHOWN, SETUID, SETGID, DAC_OVERRIDE and KILL. Its private token is outside portable .learning, inside image-owned root mode 0700 /run/ds60; expanded Windows-sharing file modes are accepted only under that exact protected parent and still need the child-read probe to fail as intended.

A fixed backend smoke then runs with a 45-second total startup bound. Health returns the cached result and a stable-for-process random instance_id. Worker ports are unexposed on an internal project network. No Docker socket, repository, learner home, cloud credentials or external model endpoints are mounted. This personal trusted-code environment is not a hostile multi-user sandbox or a tamper-resistant examination service.

Dependency resolution evidence#

Metadata resolution selected 38 TensorFlow packages and 11 CPU PyTorch packages for Python 3.12 Linux amd64/arm64. It installed no framework and downloaded no model. The resolver fetched a 1.2 MiB setuptools metadata helper. Docker installs use exact versions, --require-hashes and binary wheels only. TensorFlow uses its common tensorflow package without a CUDA extra because the 2.20.0 tensorflow_cpu package lacks an ARM64 wheel.

The root integration agent found the engine mounts worker tmpfs noexec by default. The overlay now explicitly enables exec for private /tmp, which is necessary to run compiled C++ and may be needed for framework/JVM native code. Root also observed apt CMake 3.25 in Bookworm; the C++ image now adds a separate hash-locked CMake 3.28.4 environment to meet the authored project minimum. No host tool was installed.

Actual image IDs, startup/UID/process tests, framework imports, Spark JVM jobs, Windows host mount behavior, amd64 execution and Kubernetes lease qualification must be recorded by the integration owner. No configuration-only claim fills those evidence gaps. Kubernetes uses a separately injected lease-aware adapter; the generic operation explicitly refuses cluster work without that adapter.

Qualification-driven process-budget repair#

The integration owner observed a Spark JVM exhausting the 128-task limit, preventing a thread-per-request server from starting its HTTP control thread. The worker now keeps health/poll/cancel on an existing synchronous control loop, with the single job in the background. A regression forces all further thread creation to fail while confirming health, polling and cancellation still work. Child JVMs receive a fixed ActiveProcessorCount=2 and bounded GC worker counts. Only the Spark services increase their task ceiling to 384; other profiles retain 128. Actual JVM peak usage and successful runtime jobs remain in the integration owner's image ledger.

The same pressure review reproduced a child-process leak when an output-reader thread could not start after Popen. Reader setup now belongs to the complete process cleanup try/finally; a real-child regression confirms termination and wait. Job-controller thread admission failure also becomes an explicit failed receipt instead of a permanently queued job. Unexpected infrastructure errors make readiness false and do not claim cancellation cleanup was confirmed.
