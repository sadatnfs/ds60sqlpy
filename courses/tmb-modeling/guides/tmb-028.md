# Reporting objects and uncertainty controls

Start with: tmb-027, tmb-009, tmb-018.

Outcome: Read report objects without losing shape, estimand or uncertainty assumptions.

**Where this runs.** In the classroom, the base-R companion at the end of this chapter computes a contrast standard error and compares a transformed mean with a mean of transforms. In the separately prepared [owned project](../projects/tmb-local/README.md), `tests/public_api.R` calls `TMB::sdreport(..., getReportCovariance = FALSE)` and prints its `summary`, `as.list` and `print` forms; a companion run is not a TMB compiler or rpy2 receipt, so its output is not evidence that a compiled model or the rpy2 bridge ran.

`sdreport` returns an object with methods for printing, summaries and restoration of parameter shapes. `print.sdreport` provides a compact display. `summary.sdreport` can select fixed, random or AD-reported quantities. The registered `as.list.sdreport` method reconstructs shaped lists, reducing the temptation to guess which unnamed vector element corresponds to a scientific quantity.

Call these through R's generic functions: `print(report)`, `summary(report, select="report")` and `as.list(report, what="Estimate", report=TRUE)`. The method name need not be a directly exported function to be available through dispatch. The API inventory records that distinction.

## Key terms

- **summary.sdreport:** The summary method for an sdreport object, which selects fixed, random or AD-reported rows, as in `summary(report, select="report")`.
- **as.list.sdreport:** The registered method that rebuilds named, shaped lists of estimates or standard errors, so values are not picked by row position.
- **Bias correction:** The `sdreport(bias.correct=TRUE)` machinery that adjusts expectations of nonlinear functions of latent variables; for \(Z\sim N(m,v)\), \(E[e^Z]=e^{m+v/2}\) rather than \(e^m\).
- **Report covariance:** The covariance among AD-reported quantities; `getReportCovariance=FALSE` skips the dense matrix but does not make standard errors exact.

### Worked case A: preserve shape and covariance

The companion constructs a two-parameter estimate and its covariance, derives a contrast and calculates its standard error with the full covariance. Reordering displayed rows does not permit reordering a covariance matrix independently. For a real TMB report, select by inspected names and keep the original mapping to the template.

`getReportCovariance=FALSE` avoids requesting a dense covariance among every AD-reported quantity. It does not mean standard errors are exact or free. `skip.delta.method=TRUE` deliberately skips delta calculations; absence of a standard error must not be converted into zero uncertainty.

### Worked case B: nonlinear transformation bias

If \(Z\sim N(m,v)\), then \(E[e^Z]=e^{m+v/2}\), while exponentiating the mean gives \(e^m\). The companion compares the two. This is a simple example of transformation bias, not proof that every arbitrary prediction should receive the same correction. `sdreport(bias.correct=TRUE)` applies its documented correction machinery and has resource controls such as split groups. Choose it for a specified estimand and assess approximation quality.

`ignore.parm.uncertainty=TRUE` intentionally conditions on estimated fixed parameters for some calculations. Such a result can be useful for isolating one component of uncertainty, but must be labeled. The default fitted-parameter covariance and a posterior covariance are not interchangeable claims.

### Answered discussion

**Why not request p-values for every output?** A p-value needs a meaningful null and valid regular approximation. Derived scales at boundaries and weakly identified latent components often violate simple assumptions. **Can the printed table be treated as the full result?** Printing omits object structure and provenance. Save typed values, diagnostics and the exact report configuration. **Are formatting methods separate fitting algorithms?** No. They expose an existing result and should not be counted as independent model validation.

See [sdreport and its S3 methods](https://cran.r-project.org/web/packages/TMB/TMB.pdf). The chapter companion is a transparent numerical illustration, while the prepared API probe exercises the actual report methods when available.

### Worked case C: the contrast and the covariance it needs

The companion's estimate is intercept 1 and slope 0.4, with variances 0.04 and 0.09 and covariance 0.01. The contrast \(c=(-1,2)\) estimates \(2\beta_1-\beta_0\):

\[
c^\top\hat\beta=-1+2(0.4)=-0.2,\qquad
c^\top Vc=0.04+4(0.09)+2(-1)(2)(0.01)=0.04+0.36-0.04=0.36,
\]

so the standard error is 0.6 (hand-derived). Dropping the covariance term would give \(\sqrt{0.40}=0.632\), a slight overstatement here because the positive covariance enters with a negative sign. With a negative covariance, ignoring it would understate the error. In a real report, the covariance comes from the fitted object, and the same contrast can be computed as an `ADREPORT` quantity so that `sdreport` applies the delta method with the full joint covariance:

```r fragment
rep <- TMB::sdreport(obj)
s <- summary(rep, select = "report")
s["contrast", c("Estimate", "Std. Error")] # select by name, never by row position
as.list(rep, what = "Estimate", report = TRUE)$contrast
```

The row name `"contrast"` assumes the template contains `ADREPORT(contrast)`. Selecting by name protects against reordering when another reported quantity is added later.

### Reading the transformation-bias numbers

With \(m=0.5\) and \(v=0.3\), the companion prints \(e^{0.5}=1.648721\) for the transform of the mean and \(e^{0.65}=1.915541\) for the mean of the transform (closed-form values, rounded). The ratio \(e^{v/2}=1.161834\) shows that the back-transformed mean is about 16% higher. For a log-normal response, the first number is the median and the second is the mean; both are valid estimands, and the choice depends on whether a reader wants a typical value or an expected total. Summed over 100 sites with these settings, the two choices would differ by about 26.7 units (100 times 0.266820), which is large enough to change a capacity decision. The `sdreport` standard error for the log-scale prediction, 0.548 here (\(\sqrt{0.3}\)), describes spread on the log scale; exponentiating its interval endpoints gives an interval for the median, not a symmetric interval around the mean. A report that applies `bias.correct=TRUE` addresses the mean of a nonlinear function of random effects; it does not decide which estimand a forecast table should show. Record that choice next to the number.

### When a standard error is missing

A report produced with `skip.delta.method=TRUE` still contains estimates for each `ADREPORT` quantity, but its standard-error column holds no delta-method values. A table writer that formats missing values as blanks, and a downstream reader that treats blanks as zero, would turn the contrast above into \(-0.2\pm0\) instead of \(-0.2\pm0.6\). The interval would then exclude zero by construction. Write the configuration flags beside every exported table, and make the formatter print an explicit `not computed` marker rather than an empty cell.

```r
estimate <- c(intercept = 1, slope = .4);V <- matrix(c(.04, .01, .01, .09), 2, 2)

```
