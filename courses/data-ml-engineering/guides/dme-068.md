# dme-068: Quantization and speculative decoding without exaggerated claims

**Level:** Advanced | **Prepared runtime:** `python-core`

**Direct prerequisites:** `dme-067`.

**Outcome:** Bound quantization error and prove a speculative acceptance correction reconstructs its target distribution.

Open the worked program in the classroom code pad. This tutorial exposes complete examples and answered discussions without an exam gate. The pad has fresh temporary state; separately documented projects use their own owned lifecycle.

Serving optimizations can change storage, arithmetic or the number of expensive model passes. Quantization uses lower-precision representations. Speculative decoding uses a cheaper proposal process and a verification rule to reduce expensive sequential work under suitable conditions. Both require careful correctness reasoning, and neither guarantees a speedup merely because an algorithm is implemented.

This chapter runs two explicit NumPy mechanisms. The first quantizes a small weight matrix and bounds its output error. The second derives a one-step speculative acceptance distribution exactly. The live workshop does not implement a quantized integer kernel or a multi-token speculative scheduler. Its ordinary float32 Transformer remains the reference service.

## Quantization represents values with codes and scales

For symmetric per-row quantization, choose a positive scale \(s_r\) for row \(r\), then encode weight \(w_{rj}\) as

\[
q_{rj}=\operatorname{clip}\left(\operatorname{round}(w_{rj}/s_r),-127,127\right),
\qquad
\widehat w_{rj}=s_rq_{rj}.
\]

The fixture selects \(s_r=\max_j|w_{rj}|/127\), so its largest magnitude fits the signed code range. A zero row needs an explicit convention to avoid division by zero; a general implementation must handle it. The worked matrix has no zero row so the primary error argument remains visible.

When values are not clipped and rounding is to the nearest code, absolute reconstruction error is at most half a scale step. For a row-vector product with input \(x\), the triangle inequality gives

\[
|(w_r-\widehat w_r)^\top x|\leq \frac{s_r}{2}\sum_j|x_j|.
\]

This is a local numerical bound under the stated representation. It does not bound an entire deep model's semantic quality, where errors propagate through nonlinear operations and may change a near-tied token selection.

Per-tensor, per-channel and grouped quantization have different scale overhead and error behavior. Outliers can force a large scale and erase small values. Activation quantization introduces a separate calibration problem. Weight-only quantization can reduce stored bytes while still converting values into a higher precision for computation. An actual speed benefit depends on the available kernel and data movement.

The program reconstructs weights in floating point and performs NumPy multiplication. That demonstrates quantization error, not accelerated int8 inference. Reporting an “int8 speedup” from this code would be incorrect because the multiply does not use a specialized integer kernel.

## Speculation proposes, then corrects

Autoregressive target-model generation is sequential across tokens. A cheaper draft model can propose candidates that a target model verifies. Under an appropriate acceptance and correction rule, speculation can preserve the target distribution rather than simply trusting the draft.

Consider one categorical step. Let \(p_j\) be the target probability and \(q_j\) the draft probability. For a proposed token \(j\sim q\), accept it with probability

\[
a_j=\min\left(1,\frac{p_j}{q_j}\right)
\]

for draft entries with positive mass. The accepted mass for token \(j\) is \(q_ja_j=\min(p_j,q_j)\). If the proposal is rejected, sample from the normalized positive residual \((p-q)_+\). The rejection mass exactly fills the target probability that acceptance did not supply.

When target and draft distributions are identical, every proposal is accepted and the residual branch is unused. When a draft entry has zero probability, it cannot be proposed; implementation must avoid blindly dividing by zero. Support mismatches and degenerate residuals need explicit branches, not small arbitrary epsilons that quietly alter the distribution.

A multi-token speculative algorithm also needs correct target conditionals for proposed prefixes, handling of the first rejection, retained accepted tokens, cache rollback or extension, stopping rules and random state. The one-step proof is a foundation, not a complete serving engine.

## Worked case 1: quantized weights and an output-error bound

The first case uses two rows with different magnitude ranges. Each gets its own scale. Values are rounded into signed int8 codes and reconstructed. The program verifies a maximum per-entry error bound and then multiplies by `[2,-1,3]`, checking each row's output error against half its scale times the input's absolute sum.

The second row contains a large value five alongside small values negative 0.01 and 0.03. The scale needed for five makes the small entries particularly informative: some precision is lost even though the largest entry is well represented. This is the kind of outlier effect that motivates finer grouping or specialized treatment in larger models.

The expected result is an inequality, not an invented universal accuracy percentage. Inspect the actual codes, reconstruction error and stated bound. A later model evaluation must test outputs and downstream task metrics on representative inputs, including cases near decision boundaries.

## Worked case 2: reconstruct the exact target distribution

The second case sets target probabilities to `[0.6,0.3,0.1]` and draft probabilities to `[0.2,0.5,0.3]`. Acceptance probabilities are `[1,0.6,1/3]`. The resulting accepted mass is `[0.2,0.3,0.1]`, totaling 0.6. Rejection occurs with probability 0.4, and the positive residual places all its mass on the first entry.

Adding that rejected-and-corrected mass reconstructs `[0.6,0.3,0.1]` exactly within numerical tolerance. The code checks the full distribution rather than relying on a small random sample that might look approximately right. This independent accounting is a useful oracle before implementing a stochastic sampler.

```python
"""Numerical quantization error and exact speculative acceptance accounting."""

import numpy as np


def example_one():
    weights = np.array([[0.1, -0.6, 1.0], [5.0, -0.01, 0.03]], dtype=np.float64)
    scale = np.max(np.abs(weights), axis=1, keepdims=True) / 127
    quantized = np.clip(np.rint(weights / scale), -127, 127).astype(np.int8)
    reconstructed = quantized.astype(float) * scale
    assert np.max(np.abs(weights - reconstructed)) <= float(scale.max() / 2 + 1e-12)
    vector = np.array([2.0, -1.0, 3.0])
    error = np.abs((weights - reconstructed) @ vector)
    bound = scale[:, 0] / 2 * np.abs(vector).sum()
    assert np.all(error <= bound + 1e-12)
    print("Weight codes", quantized, "output error", error, "bound", bound)
    print("Dequantized NumPy multiplication is not an accelerated integer kernel.")


def example_two():
    target = np.array([0.6, 0.3, 0.1])
    draft = np.array([0.2, 0.5, 0.3])
    acceptance = np.minimum(1.0, target / draft)
    accepted_mass = draft * acceptance
    rejection = 1 - float(accepted_mass.sum())
    residual = np.maximum(target - draft, 0.0)
    residual /= residual.sum()
    total = accepted_mass + rejection * residual
    np.testing.assert_allclose(acceptance, [1.0, 0.6, 1 / 3])
    np.testing.assert_allclose(total, target)
    np.testing.assert_allclose(accepted_mass, [0.2, 0.3, 0.1])
    assert abs(rejection - 0.4) < 1e-12
    print("Accepted mass", accepted_mass, "rejection", rejection, "corrected distribution", total)
    print("Exact one-step distribution proof does not establish a wall-clock speedup.")


def main():
    example_one()
    example_two()


if __name__ == "__main__":
    main()
```

## When speculation may help or hurt

Speculation has costs: running the draft, verifying proposals, managing two cache states and assembling accepted output. It helps when enough proposals are accepted and the target verification can use hardware more efficiently than separate sequential target steps. A draft that is too expensive or too different from the target can remove the benefit.

Measure acceptance length, total target and draft work, memory, first-token latency, per-token gaps and end-to-end throughput under the same output policy. If the optimized system changes temperature, truncation or stopping behavior, it may be performing a different task. Compare distributions or deterministic outputs under an appropriate contract rather than only comparing speed.

Quantization and speculation can interact. A quantized target is a different numerical model from its full-precision reference unless equivalence has been established under a stated tolerance or task criterion. Preserving the quantized target's sampling distribution does not prove preservation of the original full-precision distribution. Name which target the acceptance rule uses.

## Interview discussion

**Does lower stored precision automatically reduce latency?** No. Kernel support, dequantization overhead, memory traffic, batch size and bottlenecks determine the actual effect. Smaller weights can help capacity even when a particular implementation does not run faster.

**Why does speculative rejection need a residual distribution?** Replacing a rejected draft token with an arbitrary target sample would generally distort the target mass already supplied by accepted proposals. The residual corrects exactly the missing probability.

**What does the one-step proof leave untested?** Multi-token conditional verification, cache management, stopping behavior, device kernels, scheduling and real performance. Those require an implemented system and independent runtime checks.
