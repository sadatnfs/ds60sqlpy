# nlp-008: Naive Bayes as a text baseline

## Level and prerequisites

## Purpose and mental model

Multinomial Naive Bayes is a compact probabilistic baseline for nonnegative text counts. It models the class prior and the distribution of token events within each class, then combines those pieces with Bayes' rule. Its conditional-independence assumption is strong, but the resulting classifier can be useful even when the language is not actually generated independently word by word.

The feature order is [urgent,thanks]. Four documents have count rows [2,1],[1,0],[0,2],[0,1] and labels [1,1,0,0]. We derive the fitted probabilities by hand and compare them with a real scikit-learn MultinomialNB. This establishes implementation parity on a known fixture, not a claim of calibrated confidence or deployment accuracy.

Separate the prior probability of a class from the likelihood of tokens under that class. A word can favor an urgent class while a strong nonurgent prior still makes the posterior nonurgent. Class imbalance and the target population therefore matter to the decision, not just the presence of a distinctive keyword.

## Derive the multinomial likelihood and posterior

For class c and vocabulary term j, estimate theta_cj=(N_cj+alpha)/(sum_j N_cj+alpha*V), where N_cj is the total training count in that class and V is vocabulary size. The class prior pi_c can come from document frequencies or a specified target prior. The log score for document counts x is log pi_c+sum_j x_j*log theta_cj. A multinomial coefficient common to all classes cancels when comparing posterior classes for the same document.

Class zero contains total counts [0,3], while class one contains [3,1]. With alpha one and V two, their token probabilities are [1/5,4/5] and [4/6,2/6]. There are two documents in each class, so priors are one-half each. For probe [1,0], unnormalized posterior weights are 0.1 and 1/3. Dividing by their sum yields [3/13,10/13].

The prior counts documents, while likelihood counts token events. Mixing these denominators is a common implementation error. The normalization of each theta row provides an independent check before any posterior is calculated.

## Use logs and verify the actual estimator

The model multiplies token probabilities repeatedly, so log-space addition avoids numerical underflow. To normalize scores, subtract logsumexp across classes before exponentiating. logsumexp evaluates the logarithm of the sum of exponentials stably; directly exponentiating very negative log scores can turn every class weight into zero.

In the reference, model.feature_log_prob_ is compared with the hand-computed matrix, and predict_proba is compared with [3/13,10/13]. The class order is checked explicitly as [0,1]. Never assume the first probability column means urgent without reading model.classes_. A classifier can return perfectly valid numbers attached to the wrong labels if the consumer assumes a different order.

An all-zero feature vector has no token evidence, so its posterior equals the prior under this formulation. This can arise from empty text or a completely out-of-vocabulary message. It is not a confident semantic judgment. A production pipeline should identify the no-evidence condition separately from ordinary classification.

## Why naive does not mean harmless

Conditional independence assumes token events are independent given the class in the modeled likelihood. Real phrases violate this through grammar, repetition and correlated vocabulary. The assumption can overcount related evidence, producing overconfident probabilities even when the decision boundary is useful. Evaluate probability calibration separately from classification accuracy.

A fixed vocabulary lacking not gives urgent and not urgent the same feature vector. Naive Bayes cannot recover information absent from the representation. Adding bigrams or a richer encoder can help only if training labels and evaluation cover the distinction. The model name is not a substitute for an error analysis.

Changing the class prior to [0.9,0.1] flips the stated urgent-only probe toward class zero, even though the token likelihoods stay fixed. Such a change is a model of a different population or decision setting, not a free accuracy trick. If label prevalence shifts, consider whether the conditional feature distributions also changed before applying a prior adjustment.

## Worked examples

### Worked example 1: Calculate class-conditional word probabilities

Summing the first two urgent rows gives [3,1], and summing the other rows gives [0,3]. Laplace smoothing adds one to each coordinate. The resulting likelihood rows are [0.2,0.8] for class zero and [2/3,1/3] for class one. Each sums to one.

### Worked example 2: Normalize a posterior

For a single urgent token, prior-times-likelihood is [0.5*0.2,0.5*(2/3)]=[0.1,1/3]. Their normalized values are [3/13,10/13]. The actual library fit must match these values and the intermediate log likelihoods within numerical tolerance.

### Worked example 3: Change the prior and expose missing context

With prior [0.9,0.1], weights become [0.18,1/15], so the same token evidence favors class zero overall. Separately, urgent and not urgent remain indistinguishable if not is outside the feature vocabulary. These are different failure mechanisms: population assumptions versus missing representation.

import numpy as np

```

weights=np.array([.5,.5])*likelihood[:,0]
posterior=weights/weights.sum()
print(posterior)
assert np.allclose(posterior,[3/13,10/13])
```

## Interview reasoning

**Interview: Why can Naive Bayes classify well despite false independence assumptions?** A useful decision boundary can survive imperfect probability modeling. That does not imply its confidence values are calibrated, so evaluate ranking, decisions and probabilities separately.

**Interview: Does Laplace smoothing add real observations?** It is a statistical regularization/pseudocount convention. It allocates mass to unseen token events under an assumption, rather than creating new empirical evidence.

**Interview: Why inspect class order?** Probability columns follow the estimator's class inventory. Misinterpreting the order can reverse a correct prediction without any numerical error in the fitted model.
