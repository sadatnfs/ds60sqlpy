## Purpose, vocabulary and mental model

SVG keeps a DOM node for each mark, making styling and interaction convenient. Canvas draws pixels into one bitmap, which can reduce DOM overhead for many simple marks. Canvas does not automatically provide a separate accessible or interactive element for each point. The author must supply semantics and hit testing.

A Canvas has a backing resolution and a CSS display size. Device pixel ratio can make a one-to-one backing bitmap look blurry on high-density screens. Scale the backing dimensions and drawing context deliberately while keeping analytical coordinates in the documented logical space.

Performance depends on data size, transformations, layout, rendering and interactions. Switching to Canvas does not fix an expensive quadratic data algorithm. Measure the slow stage, avoid repeated allocations where appropriate and preserve an accessible data summary or table.

## Syntax anatomy and mechanism

Set canvas.width and height for the backing bitmap, set CSS width and height for display, then transform the context by the device pixel ratio. Draw circles with beginPath, arc and fill. A quadtree can search nearby points efficiently, but its coordinates must match the pointer coordinate space.

The reference draws a bounded grid of 100 points and performs a known nearest-point lookup. It does not benchmark a million records or claim universal Canvas superiority. The SVG is hidden for this lesson because the output is the Canvas plus a textual summary.

## Worked example / walkthrough

### Worked example 1: Separate display and backing dimensions

Logical size remains 320 by 180.

```javascript
const ratio=Math.min(devicePixelRatio||1,2);
canvas.width=320*ratio; canvas.height=180*ratio;
canvas.style.width="320px"; canvas.style.height="180px";
context.setTransform(ratio,0,0,ratio,0,0);
```

**Expected observation:** Drawing coordinates stay logical while the backing bitmap gains resolution.

### Worked example 2: Find a nearby point

The query is in the same coordinate system as the data.

```javascript
const tree=d3.quadtree().x(d=>d.x).y(d=>d.y).addAll([{id:"A",x:10,y:10},{id:"B",x:90,y:90}]);
console.log(tree.find(12,11).id);
```

**Expected observation:** A.

## Debugging and common mistakes

Keep three checkpoints separate: the records after parsing, the domain and geometry after transformation, and the visible marks after rendering. A chart can look plausible while silently dropping records or assigning the wrong scale. Inspect counts, IDs, finite coordinates and meaningful expected values before adjusting colors. A missing mark may come from invalid input, a missing selection, an undefined scale result or clipping outside the viewBox.

The controlled failure for this lesson is: Diagnose a hit test that selects the wrong point after scaling. Its distinguishing evidence is Pointer and indexed coordinates use different spaces. Preserve that failing case when repairing your program. Do not remove an assertion or broaden a scale merely to hide a wrong input. Explain whether a changed value should affect the data, an encoding, a layout or only presentation.

## Accessibility and interpretation

Give the visualization a descriptive title and a short textual summary of the main result. Keep a table or list when exact values matter. Do not encode a critical category only through color; use labels, shapes or position as appropriate. Interactive controls need keyboard operation and clear focus, and motion should respect the user's reduced-motion preference. Automated DOM checks support, but do not replace, a real keyboard and assistive-technology review.

A data scientist must also defend the statistical meaning. State the population, units, aggregation, missing-value policy and uncertainty where relevant. Synthetic points illustrate a mechanism and do not establish a real-world finding. A beautiful visualization should make a valid claim easier to inspect, not make a weak claim appear certain.
